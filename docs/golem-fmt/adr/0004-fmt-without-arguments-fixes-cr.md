# ADR 0004: 引数なしの `golem fmt` で、CR を含む原稿も整形できるようにする

ステータス: 採択

## 文脈

原稿に CR があると、構文の段階で G01003 のエラーになり、その diagnostic には修正案「golem fmt で LF に直す」が付く（docs/diagnostics.md）。
[ADR 0003](0003-lone-cr-to-lf.md) で、`golem fmt` は CRLF の CR も単独の CR も LF に直すようになった。

ところが、引数なしの `golem fmt` は CR を直せない。
引数なしのときは、整形するファイルの一覧を得るために、まず `Golem.Project.loadProject` でプロジェクトを読み込む（golem-cli の `formatFiles`）。
読み込みは `@import` をたどってファイルを集めるので、原稿を構文として読み、CR があると G01003 で止まる。
そのため、`golem fmt` は一つのファイルも整形せずに終わる。
CRLF でも同じであり、[ADR 0003](0003-lone-cr-to-lf.md) の前からの振る舞いである。
ファイルを引数に渡せば直せるが、G01003 の修正案のとおりに引数なしで実行した書き手は直せない。

## 実装すること

### 読み込みが CR だけで止まったら、直した中身で読み込み直す

引数なしの `golem fmt` は、整形するファイルの一覧を次のように求める。

1. `loadProjectWith` でプロジェクトを読み込む。
2. 読み込みが失敗し、エラーの diagnostic がすべて原稿のファイル（章と import したファイル）の G01003 であれば、そのファイルの中身を `golem fmt` の前処理（`Golem.Fmt.preprocess`）にかけたものを、`loadProjectWith` の差し替え（overlay）に加えて、1 から読み込み直す。
3. 読み込めたら、そのソースの一覧を整形の対象にする。整形はディスクの中身から行うので、前処理が CR を直したうえで、今のとおり整形して書き戻す。
4. G01003 のほかのエラーで失敗したら、今のとおり diagnostic を出して、何も書き換えずに終了コード 1 とする。

- 読み込み直すたびに、差し替えるファイルが少なくとも一つ増えるので、繰り返しはプロジェクトのファイルの数で終わる。同じファイルの G01003 が差し替えた後も出れば、それ以上は繰り返さずに失敗とする。
- 差し替えは、LSP が未保存の編集を渡すのに使っている仕組み（`loadProjectWith` の overlay）をそのまま使う。golem-project と golem-parser は変えず、モジュールのあいだの依存も変えない。golem-cli は、すでに golem-fmt と golem-project に依存している。
- `--check` のときも同じ手順で一覧を求め、CR を含むファイルを、整形が必要なファイルとして示す。

### 整形しないもの

- `manifest.toml` と `style.toml` の CR は、今のとおり直さない。`golem fmt` は TOML を整形しないからである。`manifest.toml` の CR で読み込みが止まった場合は、G01003 を出して終了コード 1 とする（手順 4）。G01003 の修正案も、今のとおり原稿のファイルにだけ付く。

### ドキュメント

- 仕様書の fmt の節と、使い手のマニュアルの `golem fmt` の説明に、引数なしでも CR を含む原稿を直せることを書く。
- [ADR 0001](0001-formatter.md) と [ADR 0003](0003-lone-cr-to-lf.md) のステータスの行に、「、引数なしの `golem fmt` が CR を含む原稿を読む手順は [ADR 0004](0004-fmt-without-arguments-fixes-cr.md)」を足す。

## 実装しないこと

- `golem check` や `golem build` が、CR を黙って LF とみなして読むこと。CR は今のとおり G01003 のエラーとする（仕様書の「緩い規則より厳しい規則」）。
- `manifest.toml` と `style.toml` の CR を直すこと。

## テスト設計

テストを先に書き、今の実装で失敗することを確かめる。

golem-cli の `test/Main.hs` に、次を足す。

- 章のファイルに単独の CR を含むプロジェクトで、引数なしの `golem fmt` が終了コード 0 で終わり、その章が LF だけになり、続く `golem check` が G01003 を出さないこと。今は書き換えずに終了コード 1 なので失敗する。
- 二つの章（一方が他方を `@import` しない）がどちらも CRLF を含むプロジェクトで、引数なしの `golem fmt` が両方を直すこと。
- `@import` で読むファイルだけが CR を含み、章はそのファイルを import するプロジェクトで、import されたファイルも直ること（読み込み直しで初めて見つかるファイル）。
- `manifest.toml` に CR があるプロジェクトで、引数なしの `golem fmt` が G01003 を出し、終了コード 1 で、どのファイルも書き換えないこと。
- 章に CR と、CR 以外の構文エラーの両方があるプロジェクトで、今のとおり何も書き換えずに終了コード 1 になること。
- `golem fmt --check` が、CR を含む章を整形が必要なファイルとして示し、書き換えないこと。

## トレードオフ

- 読み込みを繰り返すので、CR を含むファイルが多いプロジェクトでは、読み込みの回数が増える。CR を直すのは一度きりの作業であり、問題にならない。
- 差し替えの仕組みを `golem fmt` の中でも使うので、LSP と `golem fmt` が同じ読み込みの口を共有する。読み込みの規則が一つのままで済む。
