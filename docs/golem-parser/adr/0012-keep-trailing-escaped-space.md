# ADR 0012: keep の段落の行末のエスケープした空白を除き、お知らせを出す

ステータス: 採択

## 文脈

ロードマップの「keep の段落の行末のエスケープした空白」は、`line-breaks = "keep"` の段落の行末に書いた `\ ` が、行の末尾の空白とともに除かれているように読めると書いている。
コードを読んだだけで、出力では確かめていなかった項目である。

### 仕様の文言

docs/markup.md は、エスケープした空白について三か所で述べている。

- 「空白の扱い」は、行末の空白、表のセルの両端の空白、散文スロットの末尾の空白を無視し、これらの位置に空白を置きたい場合は `\ ` とエスケープして書く、と定める。
- 「韻文」は、`keep` の段落で各行の先頭と末尾の空白とタブを無視し、エスケープした空白も行の先頭では無視する、と定める。行の末尾のエスケープした空白には触れていない。
- 「強制改行」は、`\` の前の空白とタブを無視すると定める。

韻文の記法を決めた [docs/adr/0003](../../adr/0003-verse-line-breaks.md) も、「エスケープした空白（`\ `）も行の先頭では無視する」と書き、手順では「各行の先頭の `Text` の先頭の空白とタブを取り除き」としている。
行末のエスケープした空白を除くとは、どの文書も書いていない。
「空白の扱い」の一般の規則に従えば、行末の `\ ` は空白として残る。

### コードの振る舞い

golem-eval の `Golem.Eval.File` の `styledParagraph` は、`keep` の段落の各行に `trimLine (A.plainEscapes l)` を掛ける。
`plainEscapes` が `Escaped ' '` を `Text " "` に戻して隣の `Text` とつなぎ、その後で `trimLine` の `trimEnd` が行末の空白とタブを除く。
エスケープした空白は、戻した時点で地の文の空白と区別できなくなるので、行末でも除かれる。

[golem-parser ADR 0010](0010-ruby-slash-escape-and-table-cell-breaks.md) は、エスケープを AST に `Escaped` として残すと決めたときに、「`plainEscapes` を掛けてから `trimLine` で行頭の空白を除くので、エスケープした空白は今と同じく無視される」と書いた。
行頭について述べた文であり、行末が同じく除かれることには触れていない。
`Escaped` を AST に残す前から、エスケープは評価の前に地の文になっていたので、行末の `\ ` はそのころから除かれていたと考えられる。

### 実験

main（e3e19da）と同じ `Golem.Eval.File` から作った `golem` で、次の原稿を `golem inspect --as ir` と `golem build --target text` にかけた。
`␣` は U+0020、`⇥` は U+0009 を表す。

```
@style verse
ab\␣
cd\␣\␣
ef\⇥
\␣gh

ij\␣
kl
```

| 原稿の行 | IR の文字列 | 期待（markup.md の「空白の扱い」） |
| --- | --- | --- |
| `ab\␣`（`keep`） | `ab` | `ab␣` |
| `cd\␣\␣`（`keep`） | `cd` | `cd␣␣` |
| `ef\⇥`（`keep`） | `ef` | `ef⇥` |
| `\␣gh`（`keep`） | `gh`、G0264 | `gh`、G0264 |
| `ij\␣` と `kl`（`join`） | `ij␣kl` | `ij␣kl` |

続けて、ほかの位置も確かめた。

| 原稿 | IR の文字列 |
| --- | --- |
| `ab\␣\` と `cd`（`join` の段落の強制改行） | `ab␣`、強制改行、`cd` |
| `ef\␣␣␣`（`keep`、エスケープの後に地の文の空白） | `ef` |
| `gh␣[bold:␣x\␣]`（`keep` の行末の散文スロット） | `gh␣` と `[bold]` の `x␣` |

`keep` の段落の行末だけが、エスケープした空白を除いている。
`join` の段落の強制改行の前と、散文スロットの末尾では残る。
`keep` の段落の行末の扱いは、どの文書にも書かれていないまま、コードだけが決めていた。

実験では、もう一つの誤りも見つかった。
`trimLine` が切り詰めた `Text` の位置は、文字の数の差で縮めている。
`plainEscapes` がつないだ `Text` は、原稿では一字が二バイト（`\` と空白）なので、位置が一バイトずれる。
`ab\␣` の `ab` の位置は `ab\` を、`\␣gh` の `gh` の位置は `␣gh` を覆っていた。
位置は IR の `Text` の位置であり、診断（G0501 などの lint）や LSP の位置に使われる。

### 決めること

行末のエスケープした空白を残すか、除くかを決める。

- **残す**：markup.md の「空白の扱い」の一般の規則に合わせる。`join` の段落の強制改行の前、散文スロットの末尾と同じ扱いになる。
- **除く**：今のコードの振る舞いを仕様とし、markup.md に書く。行頭と同じくお知らせ（G0264 にならうもの）を出す。

### メンテナーが決めたこと

起草の後、メンテナーが「除く」を選んだ。
`keep` の段落の行末のエスケープした空白は除き、除いたことをお知らせで知らせる。
お知らせには新しいコードを設け、`noticeCodes` に加える。

起草の段階では「残す」を案としていたが、この ADR はそれを覆す。

## 実装すること

### 規則

`keep` の段落の各行で、次のとおりに空白を扱う。

- 行頭の地の文の空白とタブ、エスケープした空白とタブは、今と同じく無視する。エスケープした空白かタブが行の最初の要素なら、今と同じく G0264 を出す。
- 行末の地の文の空白とタブは、今と同じく無視する。
- 行末のエスケープした空白とタブも、今と同じく無視する。行末の空白とタブの並びにエスケープしたものが一つでもあれば、その行に G0279 を一つ出す。

行の途中のエスケープした空白（`a\ b`）は、今と同じく空白として残る。
行の末尾にあたるかどうかは、行の最後の要素から前へ、地の文の空白とタブだけの部分と、エスケープした空白とタブをたどって決める。
`ab\␣␣␣` の `\␣` も、後ろが地の文の空白だけなので行末にあたる。

### 診断

評価の段階のお知らせ G0279 を加える。

| コード | 重大度 | 条件 | メッセージ | 位置 |
| --- | --- | --- | --- | --- |
| G0279 | お知らせ | `keep` の段落の行の末尾の空白とタブの並びに、エスケープした空白かタブがある | `行末のエスケープした空白は無視されます` | 並びの中の最初のエスケープの `\`（一バイト） |

- golem-syntax の `noticeCodes` に `"G0279"` を加える。`manifest.toml` の `silence-notices` で抑えられる。
- 一行に一つだけ出す。行末に `\␣\␣` と書いても一つである。
- `golem build --profile prod` でも、G0264 と同じくお知らせのままとする。
- G0279 は、02 の区分で草稿の ADR が使う番号（G0270 から G0276）と、草稿の [`**[式]` をキーワード引数と同じ位置に書けるようにする](0013-splat-after-keyword-arguments.md) の G0277、草稿の [数の糖衣構文 `##…##`](0011-number-shorthand.md) の G0278 の次である。並行する草稿が同じ番号を取っていれば、実装の順にずらす。

行頭の G0264 と対になるお知らせである。
行頭では字下げを全角の空白で書かせる目的があり、行末では、書き手が残したつもりの空白が残らないことを知らせる目的がある。

### 評価（golem-eval）

`styledParagraph` の `keep` の枝で、`trimLine` を `plainEscapes` の前に掛ける。

```haskell
evalInlines ctx False (A.plainEscapes (trimLine l))
```

`trimLine` は `Escaped` を含む列を受け取り、次のように切り詰める。

- **行頭**：列の先頭から、空白とタブだけの `Text`、`Escaped ' '`、`Escaped '\t'` を取り除く。最初に残った要素が `Text` なら、その先頭の空白とタブを除く。行頭の `\␣\␣` や `\␣␣\␣` は、全体が無視される。
- **行末**：列の末尾から、空白とタブだけの `Text`、`Escaped ' '`、`Escaped '\t'` を取り除く。最後に残った要素が `Text` なら、その末尾の空白とタブを除く。

`trimLine` が切り詰めるのは、`Escaped` を含まない `Text` だけになる。
その `Text` の文字列の長さと位置の幅は、取り除いた空白とタブ（どれも一バイト）の分だけ同じに縮むので、「実験」で見つけた位置のずれもなくなる。

G0279 は、G0264 の `escapedIndent` と同じく、`plainEscapes` を掛ける前の行を見て出す。
行の末尾から前へ、空白とタブだけの `Text` と、エスケープした空白とタブをたどり、その中のエスケープのうち最も前のものの位置に出す。

`trimLine` を使うのは `keep` の段落だけである。
`join` の段落と強制改行（`hardLines`）は変えない。

### データ構造

意味論 IR と AST は変えない。
`keep` の段落の IR の行の文字列は、今と同じになる。
変わるのは、切り詰めた `Text` の位置と、G0279 の診断だけである。

### 出力

IR の文字列が変わらないので、どの出力も変わらない。

### ドキュメント

- docs/markup.md の「韻文」の「各行の先頭と末尾の空白とタブは無視する。」の項を、「各行の先頭と末尾の空白とタブは、エスケープした空白（`\ `）も含めて無視する。行末のエスケープした空白にはお知らせ（G0279）を出す。」と改め、この ADR へリンクする。「空白の扱い」の、行末の空白を `\ ` で残せるという文に、`keep` の段落の行末は除くことを添える。
- docs/specifications.md の「お知らせ」の一覧に G0279 を加える。
- docs/diagnostics.md に G0279 の節を加える。「主な原因」は、行末に空白を残すつもりで `\ ` を書いたこと、「直し方」は、`\ ` を消すこと、見える空きが要るなら全角の空白を使うこととする。
- docs/roadmap.md の「記法と設定」から「keep の段落の行末のエスケープした空白」の項を除く。
- 使い手のマニュアル（`manual/`）の `manual/chapters/03-markup.gm` の `verse` の節に、行末の `\ ` は行頭と同じく無視されることを一文で加える。付録A（`manual/appendices/a-markup.gm`）の「行末に残したい半角の空白（`\ `）」の項に、`verse` の段落の行末では残らないことを添える。付録E（`manual/appendices/e-errors.gm`）に G0279 の項を加える。
- [golem-syntax ADR 0002](../../golem-syntax/adr/0002-notice-severity.md) のステータスの行を、「採択→G0279 は [golem-parser ADR 0012](0012-keep-trailing-escaped-space.md)」とする。
- [docs/adr/0003](../../adr/0003-verse-line-breaks.md) と [golem-parser ADR 0010](0010-ruby-slash-escape-and-table-cell-breaks.md) のステータスの行は変えない。どちらも行末のエスケープした空白の扱いを定めておらず、この ADR は定めていなかった振る舞いを書き足すだけだからである。

## 実装しないこと

- 行末のエスケープした空白を残すこと（「メンテナーが決めたこと」）。
- 行頭のエスケープした空白を字下げとして残すこと。全角の空白で書く、という [docs/adr/0003](../../adr/0003-verse-line-breaks.md) と G0264 の方針を変えない。
- `join` の段落、強制改行、散文スロットの空白の扱いの変更。どれも行末の `\ ` を残しており、`keep` の段落の行末だけが例外になる。
- 行末の地の文の空白とタブにお知らせを出すこと。今と同じく黙って無視する。
- G0264 のメッセージと条件の変更。

### 自動テストにしない確かめ方

二つのマニュアルと、fixture の十冊の PDF を組み、出力のバイト列が変わらないことを確かめる。
IR の文字列は変わらないので、変われば規則の実装が意図より広く効いている。
同じ組版で、G0279 が出ないことも確かめる。
出れば、マニュアルの原稿の行末に `\ ` があり、その箇所を直す。

## トレードオフ

除くことを選ぶと、`\ ` の意味が段落の様式によって変わる。
`join` の段落では行末の `\ ` が空白として残り、`keep` の段落では除かれる。
書き手は、`keep` の段落の行頭と行末では空白を残せない、と覚える必要がある。
G0279 は、この例外に書き手が出会ったときに知らせるためのものである。

残す側を選べば、`\ ` を「この空白は文字である」という一つの意味に保てた。
しかし、残しても PDF と HTML の見た目はほぼ変わらず、行末の空白はプレーンテキストと正規表現スタイルにしか効かない。
`keep` の段落の行は、行頭と行末を対称に切り詰めるほうが、規則として説明しやすい。
今のコードの振る舞いのままなので、出力も変わらない。

`trimLine` を `plainEscapes` の前に移すと、`trimLine` は `Escaped` を知る必要がある。
代わりに、位置のずれも同時に直る。
`plainEscapes` の後で、エスケープだった空白を位置の幅から見分ける方法もあるが、[golem-parser ADR 0010](0010-ruby-slash-escape-and-table-cell-breaks.md) が G0264 で廃した推し量りを、別の箇所に戻すことになるので採らない。
