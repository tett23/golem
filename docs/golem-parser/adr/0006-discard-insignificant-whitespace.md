# ADR 0006: 地の文の端の空白を捨てる

ステータス: 採択

## 文脈

整形（golem-fmt ADR 0001）は、行末の空白を取り除き、表の `|` の前後と散文スロットの `|` の前後に空白を一つ置くと定めた。
同じ ADR は、整形の前後で AST が一致することを不変条件にしている。

ところが、CST から AST への変換（ADR 0005）は、これらの空白を地の文としてそのまま残す。
`| a|b |` のセルは `" a"` と `"b "` になり、行末の空白も段落の `Text` に入る。
整形の規則を適用すると AST が変わるので、整形器はこれらの規則を適用できずにいる。

どちらかを改めるしかない。
空白に意味を持たせ続けるなら、整形の規則を削ることになる。
しかし、行末の空白やセルの端の空白は、書き手が意図して書くものではない。
改行は文字を生まない規則（markup.md）なので、行末の空白は改行の後の欧文とつながって見えるだけで、出力の見た目を不安定にする。
そこで、変換の側で捨てる。

## 実装すること

CST から AST への変換で、次の空白（空白とタブ）を捨てる。

- 段落、見出し、リストの項目、定義リストの用語の地の文で、改行の直前にある空白。ブロックの最後の行の行末の空白も含む。
- 表のセルの先頭と末尾の空白。
- 散文スロットの末尾の空白（`|` と `]` の直前）。スロットの先頭の空白は、すでにトリビアとして捨てている。

捨てるのは地の文の端の空白だけである。
地の文の途中の空白、コードブロックの中身、文字列のリテラル、コメントの中身は変えない。
エスケープした空白（`\ `）は地の文として残す。行末やセルの端に意図して空白を置きたい場合は、これを使う。

整形（golem-fmt ADR 0001）は、この変換を前提に、行末の空白の除去と、表と散文スロットの `|` の前後の空白の規則を適用する。
不変条件（整形の前後で AST が一致すること）は変えない。

markup.md の地の文の節に、行末と表のセルの端と散文スロットの端の空白は無視される、と書き加える。

## 実装しないこと

- 地の文の途中の連続した空白を一つにまとめること。欧文の語間の扱いは組版の側で決める。
- 全角の空白（U+3000）を捨てること。和文の字下げなどで意図して使うためである。

## テスト設計

- 行末に空白のある段落と、空白のない段落の AST が一致することを確かめる。
- `| a|b |` と `| a | b |` の表の AST が一致することを確かめる。
- `[ruby 漢字: かん | じ]` と `[ruby 漢字: かん|じ]` の AST が一致することを確かめる。
- エスケープした空白と全角の空白が、行末やセルの端でも残ることを確かめる。
- 整形の規則をすべて適用した結果が AST を変えないことを、golem-fmt のプロパティテストで確かめる。

## トレードオフ

行末の空白を地の文として使っていた原稿は、出力が変わる。
Golem はまだ配布しておらず、そうした原稿はない。
意図した空白はエスケープで書けるので、表現できることは減らない。
