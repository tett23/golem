# ADR 0003: ブロック層の文法

ステータス: 採択

## 文脈

原稿はブロックの並びであり、ブロックの種類は行頭の文字で決まる（docs/markup.md）。
この ADR は、ブロック層の記法を peg-hs の文法としてどう書くか、どこにエラーからの回復のラベルを付けるかを定める。
インライン層（段落の中身、式文脈、命令文脈）は [ADR 0004](0004-inline-grammar.md) で扱う。

文法はコマンドの定義表に依存してはならない。
プラグインを追加しても既存の原稿の構文解釈が変わらないことを保証するためである。
そのため、どのブロックコマンドが属性（`@label` など）で、どれが独立したブロック（`@set` など）かは、文法では区別せず、評価の段階で判定する。

## 実装すること

### ブロックの区切り

- ブロックは一つ以上の空行で区切る。空白だけの行も空行とみなす。
- ファイルの末尾の改行の有無は問わない。

### ブロックの種類と行頭の文字

| 行頭 | ブロック | CST のノード |
|---|---|---|
| `#`、`##`、`###` と空白 | 見出し | `NHeading` |
| `-` と空白 | 箇条書きのリスト | `NBulletList` |
| `+` と空白 | 番号付きのリスト | `NOrderedList` |
| `=` と空白、`=:` | 定義リスト | `NDefList` |
| `\|` | 表 | `NTable` |
| ```` ``` ```` | コードブロック | `NCodeBlock` |
| `@` と識別子 | ブロックコマンド | `NBlockCommand` |
| それ以外 | 段落 | `NParagraph` |

- 見出しの階層は 1 から 3 までとする。`####` 以上で始まる行は構文エラーとする。
- 行頭で上の文字を本文として書く場合は、`\` でエスケープする。エスケープした行は段落になる。

### インデント

- リストの入れ子、定義リストの説明、ブロックコマンドの本体は、2 つの空白のインデントで表す。
- インデントにタブを使った場合は構文エラーとする。タブの幅は環境によって解釈が異なり、構造が揺れるためである。
- インデントが 2 の倍数でない行は構文エラーとする。

### リスト

- 項目の続きの行と入れ子のリストは、項目の行頭の記号より 2 つ深くインデントする。
- 箇条書きと番号付きの項目を同じリストの中で混ぜた場合は、別のリストとして扱う。

### 定義リスト

- `=` の行は用語であり、`=` の行が連続すると次の説明を共有する。
- 用語の直後の、2 つ深くインデントしたブロックの並びが説明であり、説明には任意のブロックを置ける。
- `=:` の行は、直前の用語を引き継いで新しい説明を始める。
- 用語のない `=:` は構文エラーとする。

### 表

- 行頭が `|` で始まる連続した行が一つの表である。
- 2 行目は区切りの行（`|---|:---:|` の形）でなければならない。区切りの行の `:` が列の揃えを表す。
- 行ごとのセルの数が見出しの行と異なる場合は構文エラーとする。
- セルの中身はインライン層として解析する。

### コードブロック

- ```` ``` ```` で始まる行から、同じインデントの ```` ``` ```` だけの行までがコードブロックである。開始の行の ```` ``` ```` の後に言語の名前を書ける。
- 中身はインライン層として解析せず、一つのトークンとして保持する。コメントとエスケープも解釈しない。
- 閉じる行のないコードブロックは、ファイルの終わりまでを中身とする構文エラーとする。

### ブロックコマンドと属性

- `@` に識別子が続く行がブロックコマンドである。識別子の後の引数は、インライン層の命令文脈と同じ規則で解析する（[ADR 0004](0004-inline-grammar.md)）。
- ブロックコマンドの行の直後に、2 つ深くインデントしたブロックの並びを本体として置ける（`@figure` のキャプションなど）。
- 空行を挟まずに連続したブロックコマンドの行と、その直後のブロックを、一つのまとまり（`NAttributed`）として解析する。まとまりの最後がブロックコマンドである場合（後ろにブロックがない場合）も、文法では受理する。どのコマンドが属性として付けられるかの判定と、後ろにブロックがないことのエラーは、評価の段階で行う。

### 段落

- 上のどれにも当たらない行から、空行までが段落である。
- 段落の中身は [ADR 0004](0004-inline-grammar.md) のインライン層として解析する。
- コメントだけからなる段落も段落として解析する。中身が空になる段落を捨てるのは AST への変換（[ADR 0005](0005-cst-to-ast.md)）の役割とする。

### 回復のラベル

[peg-hs ADR 0021](https://github.com/tett23/peg-hs/blob/main/docs/adr/0021-error-recovery.md) の記法で、次のラベルと回復の規則を書く。

| ラベル | 付ける位置 | 回復 |
|---|---|---|
| `block` | ブロックの選択の全体 | 次の空行まで読み飛ばす |
| `heading-level` | `#` の数の検査 | 次の空行まで読み飛ばす |
| `indent` | インデントの検査 | 次の空行まで読み飛ばす |
| `table-delimiter` | 表の 2 行目 | 表の終わりまで読み飛ばす |
| `table-cells` | 行ごとのセルの数の検査 | その行を読み飛ばす |
| `code-close` | コードブロックの閉じる行 | ファイルの終わりまでを中身とする |
| `def-orphan` | 用語のない `=:` | 次の空行まで読み飛ばす |

各ラベルの診断コードとメッセージは、[ADR 0002](0002-parser-on-peg-hs.md) の対応表に加える。

## 実装しないこと

- インライン層の文法。[ADR 0004](0004-inline-grammar.md) で扱う。
- 属性として付けられるコマンドの判定。評価の段階で行う。
- 番号付きリストの番号の計算。評価と文書構造の段階で行う。

## テスト設計

- docs/markup.md のすべての例が、構文エラーなしで期待した CST になることを golden テストで確かめる。
- 行頭の各文字をエスケープした行が段落になることを確かめる。
- タブのインデント、奇数のインデント、`####`、区切りの行のない表、セルの数の合わない行、閉じていないコードブロック、用語のない `=:` が、それぞれ対応する診断と `NErrorNode` になり、次のブロックが正しく解析されることを確かめる。
- 連続したブロックコマンドとその直後のブロックが一つの `NAttributed` になり、空行を挟んだ場合は別のブロックになることを確かめる。
- コードブロックの中の `[`、`%%`、`\` が解釈されないことを確かめる。

## トレードオフ

見出しを 3 階層に限ると、4 段目以下の細かい見出しは書けない。
書籍の構造は章、節、項で足りることが多く、階層を増やす必要が生じたら ADR で上限を変える。

タブのインデントをエラーにすると、エディタの設定によっては原稿が書きにくくなる。
`golem fmt` がタブを空白に直す修正案を出すことで、手間を減らす。
