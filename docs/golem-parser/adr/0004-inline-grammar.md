# ADR 0004: インライン層の文法

ステータス: 採択

## 文脈

段落、見出し、表のセル、散文スロットの中身はインライン層である。
インライン層には、地の文、エスケープ、コメント、式文脈 `[= ...]`、命令文脈 `[name ...]` がある（docs/markup.md）。
`[` の直後の一文字で文脈が決まり、文脈の判定はコマンドの定義表に依存しない。
この ADR は、インライン層と式の言語の文法を定める。

ルビの `/` による区切りや、コマンドごとの引数の意味は、文法では扱わない。
文法がコマンドの意味を知ると、プラグインの追加が構文解釈を変えうるためである。

## 実装すること

### 地の文とエスケープ

- 地の文は、`[`、`\`、`%%`、改行以外の文字の並びである。散文スロットの中では、`|` と `]` も地の文から除く。
- `\` の後の一文字はエスケープであり、`EscapeToken` として保持する。エスケープの解除は AST への変換で行う。
- 改行はトリビアではなく `KNewline` のトークンとして保持する。段落内の改行が文字を生まないという規則は、AST への変換で適用する。

### コメント

- `%%` から次の `%%` までがコメントであり、`%%=` で始まるものは校正用のコメントとする。どちらもトリビアのトークンにする。
- 段落の境界（空行）までに閉じないコメントは構文エラーとする。

### 式文脈

`[=` から対応する `]` までが式文脈である。
式の文法は [golem-eval ADR 0001](../../golem-eval/adr/0001-expression-language-and-numerics.md) の優先順位表に従い、左再帰で書く。

- 整数のリテラル：数字の並び。
- 浮動小数点数のリテラル：数字の並び、`.`、数字の並び。指数表記は v1 では持たない。
- 文字列のリテラル：`"` で囲み、`\"` と `\\` のエスケープを持つ。
- 真偽値と `nil`：`true`、`false`、`nil`。予約語であり、識別子に使えない。
- 配列：`[` 式 `,` ... `]`。式文脈の中の `[` は常に配列の開始である。
- 連想配列：`{` キー `:` 式 `,` ... `}`。キーは識別子か文字列のリテラルとする。
- 識別子と名前空間の参照：`a`、`a.b`。
- 関数の呼び出し：`f(式, ...)`。
- 式の中の空白と改行はトリビアとする。

### 命令文脈

```
[name 引数... : 散文 | 散文 ...]
```

- `[` の直後が識別子であれば命令文脈である。識別子は、英小文字で始まり、英小文字、数字、`-` からなる。
- 引数は空白で区切る。引数の種類は次のとおりである。
  - 裸の語：空白、`]`、`:`、`|`、`=`、`[`、`"` を含まない文字の並び（`intro`、`images/arch.pdf`、`10` など）。
  - 文字列：`"` で囲んだもの。
  - キーワード引数：裸の語、`=`、値（裸の語、文字列、式文脈、命令文脈）。
  - 式文脈と、入れ子の命令文脈。
  - 展開：`*[式]` と `**[式]`。
- 位置引数の後にキーワード引数を置く規則は、文法で強制する。順序が混ざった場合は構文エラーとする。
- `:` 以降が散文スロットであり、`|` で区切って複数のスロットを書ける。散文スロットの中身はインライン層であり、命令文脈を入れ子にできる。
- 散文スロットの中の `|` と `]` を地の文として書く場合は、エスケープする。

### ブロックコマンドの引数

ブロックコマンド（[ADR 0003](0003-block-grammar.md)）の識別子の後は、命令文脈の引数と同じ規則で解析する。
ブロックコマンドは散文スロットを持たず、行末までが引数である。
`@set name = 式` は例外とし、`=` の後を式文脈の式として解析する。

### 回復のラベル

| ラベル | 付ける位置 | 回復 |
|---|---|---|
| `close` | 式文脈と命令文脈の `]` | 入力を消費せず、段落の終わりで閉じたとみなす |
| `comment-close` | コメントの閉じる `%%` | 段落の終わりまでをコメントとみなす |
| `arg-order` | キーワード引数の後の位置引数 | その引数を読み飛ばす |
| `expr` | 式文脈の式 | `]` の直前まで読み飛ばす |

`close` の回復は、閉じ括弧を段落の終わりに挿入したものとして扱う。
エラーの影響は、その段落の中に閉じる。

## 実装しないこと

- コマンドごとの引数の検査（必須の引数、引数の型、ルビのセグメントの数など）。評価の段階で行う。
- エスケープの解除と、改行の除去。AST への変換で行う。
- 浮動小数点数の指数表記と、ユーザー定義の関数。

## テスト設計

- docs/markup.md のインラインの例のすべてが、期待した CST になることを golden テストで確かめる。
- 式の優先順位と結合（`2 ** 3 ** 2`、`-2 ** 2`、`1 - 2 - 3`、`a < b < c` の構文エラー）を確かめる。
- 式文脈の中の `[` が配列になり、命令文脈にならないことを確かめる。
- 散文スロットの中の入れ子の命令文脈、エスケープした `|` と `]` を確かめる。
- 閉じていない `[`、閉じていないコメント、位置引数とキーワード引数の順序の誤りが、診断になり、次の段落に影響しないことを確かめる。
- 未知のコマンド名を含む原稿が、構文エラーなしで解析されることを確かめる。未知の名前の検出は評価の段階の役割である。

## トレードオフ

裸の語に `:` を含められないので、URL を引数に書く場合は文字列のリテラルで囲む必要がある。
散文スロットの開始の `:` と区別するための制約であり、引数に URL を書く場面は少ない。

浮動小数点数の指数表記を持たないので、非常に大きい数や小さい数は桁をすべて書く必要がある。
書籍の原稿の計算で指数表記が要る場面は少なく、必要になったら ADR で追加する。
