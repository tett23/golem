# ADR 0003: golem new の雛形に版面とフォントを入れる

ステータス: 採択→雛形の `preflight.toml` は[ADR 0006](0006-preflight.md)

## 文脈

`golem new` が作る `style.toml` は、見出しの番号と強調の設定しか持たない。
[ADR 0002](0002-build-all-targets-by-default.md) で `golem build` が既定ですべてのターゲットを作るようになったため、雛形のままビルドすると、PDF が `[page]` の不足（G07001）でエラーになり、終了コードが 1 になる。
`[page]` を足しても、次はフォントの不足（G08002）で止まる。

フォントは設定だけでは足りず、ファイルそのものが要る。
Golem はフォントのファイルを持たないので、`golem new` がどこかから用意する必要がある。
実行ファイルに埋め込むと大きさが数 MB 増えるので、`golem new` の時点で配布元から取得し、プロジェクトの中に置く。

雛形の言語も一つに決まっていない。
今の雛形は日本語（`language = "ja"`、「第{n:kanji}章」）に固定されているが、英語の本では判型も組み方向もフォントも変わる。

## 実装すること

### 言語の選択

- `golem new <dir> [--language ja|en]` とし、既定は `ja` とする。
- 言語ごとに、マニフェストの `language` と `title`、見出しの番号の書式、最初の章の内容、版面、フォントを変える。

### 版面

| 項目 | ja | en |
|---|---|---|
| 判型 | `A6`（文庫判） | `mass-market`（[golem-project ADR 0003](../../golem-project/adr/0003-mass-market-paperback-size.md)） |
| 綴じ | 右 | 左 |
| 組み方向 | 縦 | 横 |
| 文字の大きさ | 12.5Q | 9.5pt |
| 字数 × 行数 | 38 字 × 16 行 | 24 字 × 33 行 |
| 行送り | 20H | 12pt |
| 版面の位置 | 天 14mm、のど 14mm | 天 16mm、のど 15mm |
| ノンブル | 下の小口側、算用数字 | 下の小口側、算用数字 |

### フォント

| 言語 | フォント | `[fonts.body]` |
|---|---|---|
| ja | Noto Serif JP Regular（Noto Serif CJK 2.003 の Subset OTF） | `ja = "fonts/NotoSerifJP-Regular.otf"` |
| en | Source Serif 4 Regular（OTF） | `latin = "fonts/SourceSerif4-Regular.otf"` |

- どちらも SIL Open Font License 1.1 であり、ライセンスの文書を `fonts/` に一緒に置く。
- フォントとライセンスの文書は、GitHub の配布元のリポジトリの、タグで固定した版のファイルから取得する。URL と SHA-256 は Golem のソースに固定する。
- 取得には、プラグインの取得と同じ HTTPS の取得の仕組み（[golem-plugin ADR 0002](../../golem-plugin/adr/0002-distribution-and-lock.md)）を使う。
- 取得したファイルのハッシュが固定した値と一致しなければエラーとする。
- 取得はファイルを書く前に行う。取得かハッシュの検査に失敗したら、プロジェクトのファイルを一つも書かず、終了コードを 1 にする。
- `--no-fonts` を付けると取得しない。`style.toml` には同じフォントのパスを書き、置くべきファイルを標準エラー出力に示す。

### モジュールの分担

- 雛形の内容と作成の処理は golem-driver に移し、取得の関数を引数で受け取る形にする。golem-cli は引数を解釈して呼ぶだけにする（[ADR 0001](0001-command-line-interface.md) の方針）。
- テストでは、取得の関数を偽物に差し替えて、ネットワークに接続しない。

### ドキュメント

- 仕様書と README の `golem new` の説明に、`--language` と `--no-fonts`、フォントの取得を加える。

## 実装しないこと

- 日本語と英語以外の言語の雛形。
- フォントを選ぶオプション。雛形のあとで `style.toml` を書き換えればよい。
- フォントの実行ファイルへの埋め込みと、取得したフォントのキャッシュ。
- 既存のプロジェクトにフォントを後から取得するコマンド。`--no-fonts` で作ったプロジェクトには、利用者がファイルを置く。
- 和文の雛形に欧文フォントを加えること。Noto Serif JP は欧文の字形も持つので、一つのフォントで組める。

## テスト設計

golem-driver のテストに加える。

- 言語ごとに、`id` を除いたマニフェスト、`style.toml`、最初の章を golden テストで固定する。
- 偽の取得の関数が正しいバイト列を返すとき、フォントとライセンスの文書が `fonts/` に書かれること。
- 偽の取得の関数がハッシュの合わないバイト列を返すとき、および失敗を返すときに、エラーになり、ディレクトリにファイルが一つも作られないこと。
- `--no-fonts` に当たる指定では、取得の関数が呼ばれず、`style.toml` にはフォントのパスがあること。
- 偽のフォントを置いた雛形を言語ごとに読み込み、`style.toml` が診断なしで読めて、版面が判型に収まること（G07001 にならないこと）。

ネットワークからの実際の取得は自動テストにしない。
実装のあとで、`golem new` を言語ごとに実行し、続けて `golem build` が終了コード 0 で四つのターゲットを作ることを確かめる。

## トレードオフ

`golem new` がネットワークに接続するようになる。
ビルドはネットワークに接続しないという原則は保つが、プロジェクトの作成には接続が要る。
接続できない環境のために `--no-fonts` を用意する。

配布元のファイルが消えるか移ると、`golem new` はフォントを取得できなくなる。
タグで固定した版のファイルは通常は変わらないが、変わった場合はハッシュの検査で止まり、別のフォントを黙って置くことはない。

フォントは各プロジェクトに複製され、和文では一つのプロジェクトにつき約 6MB になる。
プロジェクトだけでビルドが完結し、フォントの版も固定されるので、この大きさは受け入れる。
