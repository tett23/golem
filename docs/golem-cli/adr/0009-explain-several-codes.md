# ADR 0009: golem explain に複数のコードを渡す

ステータス: 採択

## 文脈

`golem explain` は、一度に一つのコードの説明しか表示できない（[ADR 0005](0005-explain-diagnostic-codes.md)）。
CI のログに十種類のコードが並んでいれば、利用者は `golem explain` を十回実行することになる。
JSON の形式の diagnostics からコードを抜き出して `xargs golem explain` に流す、という使い方も今はできない。

今の実装は次のとおりである。
引用はすべて origin/main の 466884da のものである。

- コマンドの引数は `optional (argument codeArg (metavar "CODE"))` であり、位置引数を高々一つ受け付ける（[app/Main.hs の 171 行め](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-cli/app/Main.hs#L171)）。
- コードの検査は、引数の解釈の段階の `ReadM`（`codeArg`）で行う（[138〜146 行め](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-cli/app/Main.hs#L138-L146)）。大文字に直してから、`G` と 5 桁の数字の形であることと、`catalog` にあることを確かめる。形の誤りは `診断のコードは G と 5 桁の数字です: <値>`、文書にないコードは `未知の診断のコードです: <値>。…` とし、どちらも使い方の誤り（終了コード 2）になる（[ADR 0004](0004-usage-error-exit-code.md)）。4 桁のコードも形の誤りとして扱う（[docs/adr/0061](../../adr/0061-five-digit-diagnostic-codes.md)）。
- `explain` は、コードがあれば `exBody` を `putStrLn` で書き、なければすべてのコードと題を一行ずつ書く（[221〜229 行め](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-cli/app/Main.hs#L221-L229)）。`exBody` は、節の見出しの行から次の節の直前までを、末尾の空行を除いて持つ（`Golem.Driver.Explain.Catalog`）。
- docs/diagnostics.md の節と節のあいだは、空行一つである。

手元の `golem`（`~/.local/bin/golem`）で `golem explain G01017 G01002` を実行すると、`未知の引数です: G01002` と使い方を標準エラー出力に書き、終了コード 2 で終わった。
二つめの位置引数を受け付ける口がないので、optparse-applicative がそれを未知の引数として扱う。

複数のコードを受け付けるには、四つのことを決める必要がある。
説明を並べる順、節と節の区切り、誤ったコードが混じった場合の振る舞い、ほかのオプションとの関係である。

誤ったコードの扱いには、引数の解釈の仕組みが関わる。
optparse-applicative 0.19.0.0 は、位置引数の `ReadM` が失敗すると、その場で解釈全体を失敗させる（`Options.Applicative.Common` の `searchArg` は、`ArgReader` の結果を `runReadM` でそのまま返す）。
`many (argument codeArg …)` にすると、コマンドラインの順で最初に誤ったコードだけが報告され、残りの引数は読まれない。
正しいコードの説明も書かれない。
メンテナーは、誤ったコードがあってもコマンドを止めず、正しいコードの説明を書き、誤ったコードをすべて報告すると決めた。
これには、コードの検査を `ReadM` の外に出す必要がある。

[ADR 0001](0001-command-line-interface.md) と [ADR 0004](0004-usage-error-exit-code.md) は、終了コードを、成功が 0、diagnostic によるエラー（原稿の誤り）が 1、コマンドの使い方の誤りが 2 と定めた。
CI の利用者が「原稿の誤り」と「呼び出し方の誤り」を見分けられるようにするためである。
[ADR 0005](0005-explain-diagnostic-codes.md) は、誤ったコードを使い方の誤りとし、終了コードを 2 とした。

## 実装すること

### 引数

- `golem explain [CODE...]` とし、コードを 0 個以上受け付ける。引数は `many (strArgument (metavar "CODE..."))` とし、引数の解釈の段階ではコードを検査しない。使い方の行は `golem explain [CODE...]` になる。optparse-applicative の例（`tests/Examples/LongSub.hs` の `metavar "TARGET..."`）の使い方の行は `[TARGET...]` である。
- `-` で始まる引数は、今と同じく optparse-applicative がオプションとして読み、未知のオプションは使い方の誤り（終了コード 2）になる。`golem explain G01017 --format json` もこれに当たる。
- コードを省いた場合は、今と同じく一覧を書く。
- コードが一つで、それが正しい場合の出力は、今とバイト列まで同じにする。
- ヘルプのコマンドの説明は今の `診断のコードの説明を表示する` のままとする。

### 検査を移す先

`codeArg` の検査を、`ReadM` から純粋な関数に移す。

```haskell
-- 大文字に直したコードか、誤りの文。文は今の codeArg と同じ
checkCode :: T.Text -> Either T.Text T.Text
```

`explain` は、受け取った引数の列のすべてに `checkCode` を当ててから、出力を書く。
`ReadM` の中では最初の誤りで解釈が止まるが、実行の段階で列を検査すれば、すべての誤りを集められる。
誤りの文は今の `codeArg` の文と同じにし、`codeArg` は消す。

### 並べる順と重複

- 説明は、コマンドラインに書いた順に並べる。
- 大文字に直した後に同じになる引数は、最初に現れたものだけを扱う。`golem explain G01017 g01017 G01002 G01017` は、G01017 と G01002 の二つの節を書く。誤ったコードの重複も同じく一度だけ報告する。

並べ直さないのは、利用者が書いた順を、利用者の意図として保つためである。
昇順に並べたければ、`sort -u` を通してから渡せば足りる。
重複を除くのは、`jq -r '.[].code'` で抜き出したコードには同じコードが何度も現れ、同じ節を何度も書いても読み手に得がないからである。
重複を除いても、出力は引数の列だけで決まる。

### 節の区切り

- 節と節のあいだに空行を一つ置く。出力は、各節の `exBody` を空行一つでつなぎ、最後に改行を一つ書いたものになる。
- 区切りの記号（`---` など）は置かない。

各節は `## G01017` の見出しの行で始まるので、見出しが節の境を示す。
空行一つでつなげば、docs/diagnostics.md と同じ並べ方の Markdown になり、Markdown のビューアーにそのまま渡せる。
コードが一つの場合は区切りがなく、今の出力と変わらない。
区切りは、使ってみて読みにくければ別の ADR で改める。

### 誤ったコードが混じった場合

- 正しいコードの節は、誤ったコードを除いた順のまま、標準出力に書く。
- 誤ったコード（形の誤り、文書にないコード、4 桁のコード）は、一つずつ一行で、コマンドラインの順に標準エラー出力に書く。文は今の `codeArg` の文と同じにする。
- 標準出力をすべて書いてから、標準エラー出力を書く。
- 誤ったコードが一つでもあれば、終了コードを 2 とする。正しいコードが一つもなければ、標準出力には何も書かない。
- 使い方の表示（`使い方: golem explain [CODE...]` の行）は書かない。引数の並べ方は正しく、誤っているのは値だからである。
- 4 桁のコードは、今と同じく形の誤りとする（[docs/adr/0061](../../adr/0061-five-digit-diagnostic-codes.md)）。読み替えの案内は加えない。

```
$ golem explain G01017 G99999 G0101
## G01017
…（G01017 の節）
未知の診断のコードです: G99999。プラグインが出す診断は、プラグインの文書を参照してください
診断のコードは G と 5 桁の数字です: G0101
$ echo $?
2
```

終了コードを 0 でないものにするのは、スクリプトが誤りに気付けるようにするためである。
0 にすると、`xargs golem explain` に誤ったコードが混じっても、スクリプトは成功として扱う。

0 でない値のうち、1 ではなく 2 を選ぶ。
1 は、[ADR 0001](0001-command-line-interface.md) の表で「診断によるエラー」、つまり原稿の誤りを表す。
誤ったコードを渡したのは原稿の誤りではなく、コマンドの呼び出し方の誤りであり、[ADR 0004](0004-usage-error-exit-code.md) が 1 と 2 を分けた目的（CI で原稿の誤りと呼び出し方の誤りを見分ける）に照らすと 2 に当たる。
検査する段階が引数の解釈から実行に移っても、誤りの種類は変わらない。
[ADR 0005](0005-explain-diagnostic-codes.md) の「誤ったコードは使い方の誤り（2）」も、そのまま保たれる。
コードが一つで誤っている場合も、今と同じ 2 で終わる。

一方で、[ADR 0004](0004-usage-error-exit-code.md) の使い方の誤りは、解釈に失敗して何もしないものだった。
この ADR の後は、終了コードが 2 でも、標準出力に正しいコードの説明が書かれていることがある。
`golem explain` の出力は説明の文書であり、一部が書かれていても、それを使って何かが壊れることはない。
終了コードが 0 なら、渡したコードの説明はすべてそろっている。

### ほかのオプション

- `--format json` は設けない。ほかのオプションも加えない。
- `--no-notices` などのほかのコマンドのオプションは、今と同じく使い方の誤りとする。

`golem explain` が書くのは docs/diagnostics.md の節そのものであり、diagnostic ではない。
`golem explain` は人が読むためのコマンドであり、プログラムで説明を読むなら、docs/diagnostics.md の形（[ADR 0005](0005-explain-diagnostic-codes.md) の「説明の文書」）を読める。
JSON の形を設けると、その形が CLI の互換の対象に加わる。

### diagnostics の後の案内の行

`コードの説明は golem explain <コード> で表示できます（例: golem explain G01017）` の一行（[ADR 0005](0005-explain-diagnostic-codes.md)）は変えない。

### データ構造

```haskell
data Command = … | Explain [T.Text]

explain :: [T.Text] -> IO ExitCode
-- [] は一覧。それ以外は nubOrd で重複を除き、checkCode で正しいものと誤ったものに分け、
-- 正しいものの節を標準出力に、誤ったものの文を標準エラー出力に書く
```

`Data.Containers.ListUtils` の `nubOrd` は、app/Main.hs がすでに import している（[7 行め](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-cli/app/Main.hs#L7)）。
パッケージの依存は変えない。

### ドキュメント

- 仕様書の「CLI」の表の `golem explain [CODE]` を `golem explain [CODE...]` にし、複数のコードの順、重複、区切り、誤ったコードの報告と終了コードを書く。
- README のコマンドの表の行を同じく改める。
- 開発者のマニュアルの CLI の章（`manual-dev/part1/01-cli.gm`）と diagnostics の章の `golem explain` の例（`manual-dev/part1/02-diagnostics.gm`）に、複数のコードを渡す例と、誤ったコードが混じった場合の例を足す。
- [ADR 0005](0005-explain-diagnostic-codes.md) のステータスの行に「、複数のコードと、コードを実行の段階で検査することは [ADR 0009](0009-explain-several-codes.md)」を足す。

## 実装しないこと

- `--format json` と、そのほかの新しいオプション。
- 誤ったコードが一つでもあれば、正しいコードの説明も書かずに止めること。
- 説明を昇順に並べ直すこと。
- 標準入力からコードを読むこと。`xargs` で足りる。
- diagnostics の後の案内の行に、出したコードをすべて並べること。
- 4 桁のコードの読み替えの案内。

## テスト設計

golem-cli のテスト（`modules/golem-cli/test/Main.hs` の `explainTests`）に、次のテストを先に書き、今の実装で失敗することを確かめる。
今の実装では二つめのコードが未知の引数になるので、二つ以上のコードを渡すテストは、どれも終了コード 2 と、`未知の引数です:` で始まる標準エラー出力で失敗する。
一つの誤ったコードのテストは、今は使い方の表示を含むので失敗する。
4 桁のコードと `--format json` のテストは今も通るが、作りを変えた後も誤りであり続けることを確かめるために置く。

- `golem explain G01017 G01002` が終了コード 0 で終わり、標準出力が「`golem explain G01017` の標準出力」、改行一つ、「`golem explain G01002` の標準出力」をつないだものに等しく、標準エラー出力が空であること。
- `golem explain G01002 G01017` が、上と逆の順に書くこと。
- `golem explain G01017 g01017 G01002 G01017` の標準出力が、`golem explain G01017 G01002` と等しいこと。
- `golem explain G01017 G99999 G01002` が終了コード 2 で終わり、標準出力が `golem explain G01017 G01002` の標準出力と等しく、標準エラー出力が `未知の診断のコードです: G99999。プラグインが出す診断は、プラグインの文書を参照してください` の一行であること。
- `golem explain G01017 G0101 nope G0101` が終了コード 2 で終わり、標準出力が `golem explain G01017` の標準出力と等しく、標準エラー出力が `診断のコードは G と 5 桁の数字です: G0101` と `診断のコードは G と 5 桁の数字です: nope` の二行だけであること（すべての誤りを報告し、重複は一度だけ）。
- `golem explain G0258` が終了コード 2 で終わり、標準出力が空で、標準エラー出力が形の誤りの一行だけであること（4 桁のコード、使い方の表示なし）。
- `golem explain G01017 --format json` が終了コード 2 で終わり、標準出力が空であること（未知のオプションは今と同じく解釈の誤り）。

既存のテストのうち、一つの正しいコード、小文字、廃止したコード、一覧、`--no-notices` のテストは変えずに通ること。
golden の `explain-help` は、使い方の行が `golem explain [CODE...]` に変わるので更新する。
golden の `explain-unknown-code` と `explain-bad-code` は、使い方の表示がなくなり、誤りの一行だけになるので更新する。

## トレードオフ

- 終了コードが 2 でも、標準出力に一部の説明が書かれていることがある。[ADR 0004](0004-usage-error-exit-code.md) の使い方の誤りは何もしないものだったので、2 の意味が少し広がる。誤りの種類（呼び出し方の誤り）を終了コードで示すことを優先した。
- 検査が引数の解釈の段階から実行の段階に移り、ほかのコマンドの値の誤り（`--profile nope` など）と作りが分かれる。すべての誤りを一度に報告し、正しいコードの説明を書くことと引き換えにする。
- 一つの誤ったコードの標準エラー出力から、使い方の表示がなくなる。引数の並べ方を誤ったわけではないので、使い方を見せても直し方の助けにならない。
- 重複を除くので、出力の節の数は引数の数と一致しない。一致させたい利用者はいないと見込む。
- 書いた順を保つので、同じコードの集合でも、渡す順によって出力が変わる。並べ直しは `sort` に任せる。
- 区切りを空行だけにしたので、端末で読むときに節の境は見出しの行でしか見分けられない。一つの節の中にも `###` の小見出しがあり、`##` と `###` の違いで節の境を見ることになる。

## 決めたことの記録

草案で開いていた点を、次のとおりに決めた。

- **区切り、`--format json` を設けないこと、一つのコードの出力をバイト列まで変えないこと**：メンテナーが草案のとおりに承認した。区切りは使ってみて変えてもよいとされた。
- **誤ったコードの扱い**：メンテナーが、コマンドを止めず、正しいコードの節を順に標準出力へ書き、誤ったコード（4 桁を含む）を一つずつ標準エラー出力へ書くと決めた。
- **終了コード**：メンテナーは 0 でない値（例として 1）を示した。この版では 2 を選んだ。呼び出し方の誤りを 2 とする [ADR 0004](0004-usage-error-exit-code.md) と [ADR 0005](0005-explain-diagnostic-codes.md) の区別を保つためである。
- **検査の移し方**：`ReadM` の `codeArg` を純粋な `checkCode` に置き換え、実行の段階で引数の列のすべてに当てる形を、この版で決めた。
- **並べる順と重複**：メンテナーの指示はなく、草案の案（書いた順、重複は最初だけ）を保った。誤ったコードの重複も一度だけ報告するのは、この版で足した。
