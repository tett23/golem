# ADR 0004: TSV の表、表のファイルの誤りの位置、表の列の揃え

ステータス: 採択

## 文脈

ロードマップの v0.1.0-rc3 の「TSV の表」は、タブで区切った TSV のファイルからも `@table` で表を作れるようにする項目である。
今の `@table` は、CSV のファイルからしか表を作れない。
表計算のソフトからデータを書き出すとき、セルにカンマを含むデータでは TSV のほうが扱いやすい。
InDesign も、タブで区切ったテキストを「テキストを表に変換」で表にでき、タブ区切りは組版の現場で表のデータを受け渡す普通の形である。

この ADR は、TSV に加えて、メンテナーの判断（下の「メンテナーが決めたこと」）により、次の三つも扱う。
CSV と TSV の誤りをファイルの中の位置で報告すること、`@table` で列の揃えを指定すること、LSP が表のファイルの保存を受けて評価し直すことである。

### 今のコード

コードで確かめると、`@table` は次のように動く。

- 評価（golem-eval の `Golem.Eval.File` の `csvTable`）は、キーワード引数 `src` のパスだけを受け付ける。位置引数のパスは受け付けない（G0234）。`src` のほかのキーワード引数は黙って無視する。
- ファイルの形式を見分けない。拡張子によらず、どのファイルも `parseCsv` で RFC 4180 の CSV として読む。
- `parseCsv` は CRLF を LF に直し、空の行（セルが一つで空のもの）を捨てる。単独の CR は、セルの中の文字として残る。引用符を閉じずにファイルが終わると、黙ってそこまでを一つのセルにする。セルの前後の空白は除かない。
- 一行目が見出しの行になる。列の揃えは、すべて `AlignDefault` である。
- セルは地の文として扱い、インラインの記法を解釈しない（[golem-eval ADR 0002](0002-file-evaluation.md)）。セルの `Text` の位置は、`@table` のコマンド全体である。
- 誤りは G0235 の一つのコードに二つの文言（`CSV が空です`、`CSV の行ごとのセルの数が一致しません`）を持ち、どちらも `@table` のコマンドを指す。CSV のファイルには `FileId` がなく、診断の位置として表せないためである（[golem-eval ADR 0003](0003-evaluation-diagnostic-codes.md)）。
- ファイルは golem-driver の `loadAssets` が読み、`ctxAssets` の `AssetText` として評価に渡す。読み方は `decodeUtf8Lenient` であり、UTF-8 として不正なバイトは黙って U+FFFD になる。BOM も検査せず、BOM は見出しの行の最初のセルの先頭の文字として残る。
- 原稿（`.gm`）、`manifest.toml`、`style.toml` には、読み込みの段階の検査（G0101 の UTF-8、G0102 の BOM、G0103 の CR）がある（golem-parser の `Golem.Parser.Read` の `readSourceFile`）。G0103 は CRLF の CR も誤りにする。
- 意味論 IR の表は `Table [Alignment] [[Inline]] [[[Inline]]]` であり、`Alignment` は `AlignDefault`、`AlignLeft`、`AlignCenter`、`AlignRight` の四つである。どこから作った表かは持たない。
- PDF（[golem-driver ADR 0008](../../golem-driver/adr/0008-pdf-tables.md)）は揃えを列の幅との差で組み、縦組みでは `AlignLeft` を天寄せ、`AlignRight` を地寄せにする。HTML と EPUB は揃えを `align-left` などのクラスで出す。テキストの出力は、セルをタブで区切って出し、揃えを持たない。原稿の `|` の表の揃えは、この経路ですでにすべての出力に届いている。
- LSP（golem-lsp の `Golem.Lsp.Server`）は、`textDocument/didOpen`、`didChange`、`didClose` で評価し直す。`didSave` と `workspace/didChangeWatchedFiles` は扱わない。表のファイルを保存しても、原稿を編集するまで診断は古いままである。

### TSV の規則の候補

TSV には、広く使われる規則が二つある。

- **IANA の `text/tab-separated-values`**：一行が一つのレコードで、フィールドはタブで区切る。一行目はフィールドの名前である。すべての行が同じ数のフィールドを持つ。フィールドの中にタブと改行は書けず、引用符もエスケープもない。
- **PostgreSQL の `COPY` のテキスト形式**：IANA の形に、`\t`、`\n`、`\r`、`\\` などのバックスラッシュのエスケープを加える。`\N` は NULL を表す。

Golem の表のセルは、もともと改行を持てない。
原稿の `|` の表では、セルの中の行末の `\` は G0124 である（[docs/adr/0016](../../adr/0016-hard-line-breaks.md)、[golem-parser ADR 0010](../../golem-parser/adr/0010-ruby-slash-escape-and-table-cell-breaks.md)）。
セルの中のタブも、組んだ結果では空白と見分けられない。
このため、エスケープで書ける文字が増えても、表に組めるものは増えない。
一方、バックスラッシュのエスケープがあると、`C:\new` のような Windows のパスや正規表現のデータが書き換わり、Golem の原稿の `\` のエスケープとも意味が食い違う。

### `@table` の位置引数のパスとの関係

ロードマップの v0.1.0-rc4 には、「`@table` の位置引数のパス」がある。
`@table` のパスを、`src=` でなく最初の引数として書けるようにするかを検討する項目である。
この ADR は、パスをどう書くかに関わらない形で形式を決める。
形式の見分けは、パスの文字列と `format` のキーワード引数だけを見る。
rc4 の項目で位置引数のパスを加えても、この ADR の規則はそのまま当てはまる。

### メンテナーが決めたこと

草稿の未決に対して、メンテナーは次のように決めた。

- **CR**：TSV も CSV と同じく CRLF を受け付ける。単独の CR は、CSV と揃えて決める。UTF-8 だけを受け付けることと BOM の規則は、CRLF を受け付けることで変える必要がなければ保つ。この ADR は、CSV と TSV のどちらでも、単独の CR を誤り（G0282）にすることにした（実装することの「表のファイルの読み込み」とトレードオフの節）。
- **列の揃え**：`@table` に `align` のキーワード引数を、この ADR で加える。CSV と TSV の両方に効く。
- **セルの中のインラインの記法**：将来セルをインラインの記法として読めるように、引数の名前と値の空間をいま決める。実装はしない。この ADR は `cells` のキーワード引数を予約し、`cells=text` だけを受け付けることにした。
- **CSV の誤りの位置**：CSV の誤りも、この ADR でファイルの中の行と列を指すようにする。
- **LSP**：保存した表のファイルの変更を受けて、LSP が評価し直すことを、この ADR で扱う。
- **BOM**：表のファイル（CSV と TSV）に限り、先頭の BOM を読み飛ばし、G0102 にしない。原稿、`manifest.toml`、`style.toml` は今のとおり G0102 にする。Excel の「CSV UTF-8」の書き出しが先頭に BOM を書くためである。
- **G0235**：G0235 の条件と位置を改めない。表のファイルの中を指す誤り（空の表と、行のセルの数の不一致）には、新しいコード G0285 を割り当てる。G0235 を出す箇所が残らなければ、[docs/diagnostics.md](../../diagnostics.md) で廃止にする。この ADR の後、CSV の誤りもすべて G0285 で報告するので、G0235 を出す箇所は残らない。G0235 は廃止にし、番号を使い回さない。

### 未決

- **コードの番号**：G0280 から G0285 は、この草稿を書き直した時点で、rc3 のほかの草稿が使っていない番号である（G0277 から G0279 はほかの草稿が使う）。草稿をまとめて採択するときに、ほかの草稿と重ならないか確かめる必要がある。

## 実装すること

### 記法

`@table` は、CSV か TSV のファイルから表を作る。
キーワード引数は次の四つである。

| 引数 | 値 | 既定 |
|---|---|---|
| `src` | 表のファイルのパス | なし（G0234） |
| `format` | `csv` か `tsv` | パスの拡張子で決める |
| `align` | 揃えの並び（下の「列の揃え」） | すべての列が既定の揃え |
| `cells` | `text` | `text` |

形式は次の順で決める。

1. `format` のキーワード引数があれば、その値で決める。値は `csv` か `tsv` である。どちらでもなければ G0280 とし、表を作らない。
2. `format` がなければ、パスの拡張子で決める。拡張子が `.tsv` なら TSV とする。大文字と小文字は区別しない（`.TSV` も TSV）。
3. それ以外は CSV とする。

```
@table src=data/sizes.tsv align=left,right,right
@table src=data/export.txt format=tsv
```

拡張子が `.tsv` でないファイルを CSV として読む今の振る舞いは変えない。
`.txt` のファイルを CSV として読んでいる今のプロジェクトは、そのまま同じ表になる。
`src`、`format`、`align`、`cells` のほかのキーワード引数は、今と同じく無視する。

### 列の揃え

`align` は、列の揃えを左の列から順にカンマで区切って並べる。
値は `Word` か文字列リテラル（`align="left,right"`）で書く。
式（`[= ...]`）は受け付けない。

| 値 | 意味論 IR | 原稿の `\|` の表の区切りの行 |
|---|---|---|
| `left` | `AlignLeft` | `:---` |
| `center` | `AlignCenter` | `:---:` |
| `right` | `AlignRight` | `---:` |
| `default` | `AlignDefault` | `---` |

- 値の数が一つなら、すべての列に同じ揃えを当てる（`align=right`）。
- 値の数が二つ以上なら、表の列の数と同じでなければならない。違えば G0281 とし、表を作らない。
- 空の値（`align=left,,right` の真ん中）も、上の四つ以外の値も G0281 とし、表を作らない。
- 値の前後の空白は除く（`align="left, right"` は `left` と `right`）。大文字と小文字は区別する（`Left` は G0281）。
- `align` がなければ、すべての列が `AlignDefault` である。今の CSV の表と同じ結果になる。

揃えの名前は、意味論 IR と原稿の `|` の表の揃えに合わせて `left`、`center`、`right` とする。
縦組みでは、[golem-driver ADR 0008](../../golem-driver/adr/0008-pdf-tables.md) のとおり `left` が天寄せ、`right` が地寄せになる。
`@figure` の `wrap` のように `start` と `end` にしないのは、原稿の `|` の表の揃えと、HTML の出力のクラスの名前（`align-left` など）が、すでに左右の名前で縦組みを扱っているからである。

出力は、揃えを意味論 IR の `Table` の `[Alignment]` に入れるだけで、原稿の `|` の表と同じ経路を通る。
PDF は列の幅との差で揃え、HTML と EPUB は `align-left`、`align-center`、`align-right` のクラスを出す。
テキストの出力は、今と同じく揃えを持たない。
出力のモジュールに変更は要らない。

### セルの読み方の予約

`cells` は、セルの中身をどう読むかを決める引数として予約する。
この ADR が実装する値は `text`（今と同じく地の文として読む）だけである。

- `cells=text` は、書かないのと同じである。
- `cells=markup` は G0284 の「まだ実装していません」とし、表を作らない。将来、セルを原稿のインラインの記法として読む値として、名前だけを決めておく。
- ほかの値は G0284 とし、表を作らない。

未実装の値を黙って `text` として読まず、誤りにする。
`cells=markup` を書いた原稿が、実装の後に意味を変えないためである。
組版の型は広く、実装は狭くし、未実装の場合は誤りで止めるという Golem の方針（仕様書の「[設計原則](../../specifications.md#設計原則)」の節と、「[意図的に採用しなかったもの](../../specifications.md#意図的に採用しなかったもの)」の節のレイアウトエンジンの項）に合わせる。

### TSV の読み方

TSV は、IANA の `text/tab-separated-values` の規則で読む。

- 行の終わりは LF か CRLF である。一つのファイルに両方が混ざってもよい。
- ファイルが行の終わりで終わるときは、その後の空の行を一つだけ捨てる。ファイルの末尾の行の終わりはなくてもよい。
- 行をタブ（U+0009）で区切ってセルにする。タブと行の終わりのほかに特別な文字はない。
- 引用符（`"`）もバックスラッシュ（`\`）も、書いたままの文字である。エスケープはない。
- セルの前後の空白は除かない。CSV と同じく、セルの中身は書いたままのテキストである。
- 空のセル（`a<TAB><TAB>b` の真ん中）は、インラインを持たないセル（`[]`）にする。原稿の `|` の表の空のセルと同じである。
- 一行目が見出しの行である。見出しの行だけのファイルは、本体の行のない表にする。
- 途中の空の行は捨てず、一つの空のセルを持つ行として扱う。列が一つの表では空のセルの行になり、列が二つ以上の表では G0285 になる。
- すべての行のセルの数は、一行目と同じでなければならない。違う行があれば、最初のその行で G0285 とし、表を作らない。
- 最後の行の終わりを捨てた後に行が一つもなければ（空のファイル、または行の終わりだけのファイル）、G0285 とし、表を作らない。

### CSV の読み方

CSV の読み方は今の規則（RFC 4180）を保ち、位置を持つ形に書き直す。
変わるのは次の点である。

- 行の終わりは LF か CRLF である。今と同じく CRLF を受け付ける。引用符の中の LF と CRLF は、今と同じくセルの中の文字として残す。
- 単独の CR は、引用符の中でも外でも G0282 とする（下の「表のファイルの読み込み」）。
- 引用符を閉じずにファイルが終わったら、G0283 とし、表を作らない。位置は開いた引用符である。
- 空の行（セルが一つで空のもの）を捨てることは変えない。今のプロジェクトの表を変えないためである。
- 空のセルは、今と同じく `[Text sp ""]` にする。
- 今の G0235 のかわりに、ファイルの中を指す G0285 で報告する（下の「診断の位置」）。G0235 は廃止にする。

引用符の外の `"`（`a"b`）は、今と同じく書いたままの文字とする。
RFC 4180 の形に厳密に合わせて誤りにすると、今のプロジェクトの表が失敗するからである。

### 表のファイルの読み込み

`@table` で読むファイル（CSV と TSV）には、表のファイルのための読み込みの段階の検査を行う。
原稿の `readSourceFile` は CRLF の CR を誤りにするので、そのままは使わない。
UTF-8 の検査は `readSourceFile` と同じ関数を使い、BOM と CR の扱いを表のファイルのために分ける。

- UTF-8 として不正なバイト列は G0101 とする。文字コードは UTF-8 だけを受け付ける。
- 先頭の BOM（U+FEFF）は読み飛ばし、G0102 にしない。読み飛ばした BOM は見出しの行の最初のセルに入れない。位置はファイルの先頭からのバイトのまま数え、BOM の 3 バイトを引かない。先頭以外の U+FEFF は、原稿と同じく書いたままの文字として残す。
- LF の前にない CR（単独の CR）は G0282 とする。位置は最初の単独の CR である。
- CRLF は誤りにしない。CRLF の CR は、行の終わりの一部として読み、セルに入れない。

単独の CR を誤りにするのは、次の理由による。
CSV（RFC 4180）の行の終わりは CRLF であり、単独の CR を行の終わりとは定めていない。
TSV（IANA）の行の終わりも、単独の CR を含まない。
単独の CR を受け付けると、古い Mac の改行（CR だけ）のファイルが、黙って一行だけの表か、CR を含む一つの大きなセルになる。
CR を含むセルは、どの出力でも組めない。
G0103 にしないのは、G0103 の文言「改行は LF に限ります」が、CRLF を受け付ける表のファイルには当てはまらないからである。

検査に通らないファイルからは表を作らない。
同じファイルを複数の `@table` から参照しても、読み込みの段階の診断は一つのファイルに一度だけ出す。
同じファイルを `@listing` からも参照する場合、`@listing` の読み方は今のまま変えない（`decodeUtf8Lenient`）。

### 診断の位置

表のファイルに `FileId` を与え、CSV と TSV の中の誤りをファイルの位置で報告する。

- golem-driver の `loadAssets` は、テキストとして読むファイル（CSV、TSV、`@listing` のファイル）ごとに `FileId` を割り当てる。番号は `plugins.lock` の `FileId`（`lockFileId`）の次から、パスの順（`Map` の順）に振る。パスの順はファイルの一覧の取得の順によらないので、決定性を保つ（[docs/adr/0002](../../adr/0002-determinism.md)）。
- 読んだファイルの `SourceInfo`（パスと行の索引）を、`Evaluated` に加え、`golem build`、`golem check`、`golem lint`、`golem preflight` の表示に使う位置の表（`brSources` など）に入れる。人の読む表示は `data/sizes.tsv:3:1: error[G0285]: ...` の形になり、JSON の表示もそのファイルのパスを持つ。
- 位置はバイトで持ち、表示のときに行と列にする。原稿と同じである。
- LSP は、位置の指すファイルに診断を載せる今の規則のまま、表のファイルに診断を載せる。エディタで表のファイルを開いていれば、`loadAssets` はディスクのかわりにエディタの内容（`wsOverlay`）を読む。
- セルの `Text` の位置は、今と同じく `@table` のコマンド全体とする。表のファイルの中の位置は、読み込みと表の形の診断にだけ使う（トレードオフの節）。

| コード | 条件 | メッセージ | 位置 |
|---|---|---|---|
| G0101 | 表のファイルに UTF-8 として不正なバイト列がある | `UTF-8 として不正なバイト列があります` | ファイルの最初の不正なバイト |
| G0285 | 最後の行の終わりを捨てた後（CSV では空の行を除いた後）に行が一つもない | `CSV が空です`、`TSV が空です` | ファイルのバイト 0 から 0 |
| G0285 | 行のセルの数が一行目のセルの数と違う | `CSV の行のセルの数が見出しの行と違います（見出しの行は <m>、この行は <n>）`（TSV では `TSV の`） | ファイルのその行（行頭から行の終わりの前まで。CSV では引用符の中の改行をまたぐレコードの全体） |
| G0280 | `@table` の `format` が `csv` でも `tsv` でもない | `format は csv か tsv です: <値>` | `format` の引数の全体 |
| G0281 | `align` の値が `left`、`center`、`right`、`default` のどれでもない | `align の値は left、center、right、default のどれかです: <値>` | `align` の引数の全体 |
| G0281 | `align` の値の数が、一つでなく、表の列の数とも違う | `align の値の数が表の列の数と違います（列は <m>、align は <n>）` | `align` の引数の全体 |
| G0282 | 表のファイルに単独の CR がある | `単独の CR があります。表のファイルの改行は LF か CRLF に限ります` | ファイルの最初の単独の CR |
| G0283 | CSV の引用符を閉じずにファイルが終わる | `CSV の引用符が閉じていません` | 開いた引用符 |
| G0284 | `cells` が `markup` である | `cells=markup はまだ実装していません` | `cells` の引数の全体 |
| G0284 | `cells` が `text` でも `markup` でもない | `cells は text です: <値>` | `cells` の引数の全体 |

G0285 は、今の G0235 と同じ「ファイルの形が表にならない」という条件を、ファイルの中の位置で報告するコードである。
CSV と TSV で位置がファイルの中に揃うので、一つのコードにまとめる。
G0235 はコマンドを指すコードとして定めたので、条件と位置を改めずに廃止にする（トレードオフの節）。
G0285 の読み込みの段階の検査を通った後のファイルを読む段階は評価なので、02 の区分に置く。
G0234、G0280、G0281、G0284 は原稿の引数の誤りなので、原稿の位置を指す。
G0101 は、新しいコードにせず、原稿と同じコードを使う。
条件（ファイルの読み込みの段階の検査）と直し方（UTF-8 で保存し直す）が原稿と同じだからである。
G0281 と G0284 は、引数の検査であり、ファイルを読む前に行う。
G0281 の値の数の検査だけは、列の数が要るので、ファイルを読んで見出しの行を得た後に行う。

### LSP の評価し直し

LSP は、表のファイルの変更を受けて評価し直す。

- 初期化の後（`initialized`）、クライアントが `workspace.didChangeWatchedFiles.dynamicRegistration` を持てば、`client/registerCapability` で `workspace/didChangeWatchedFiles` を登録する。
- 監視する対象は、最後の評価で `@table` が参照した表のファイルのパスである。パスごとに、プロジェクトのルートを基準にした `RelativePattern` を作り、作成、変更、削除のすべてを受ける。
- 評価し直して、参照する表のファイルの集合が変わったら、前の登録を `client/unregisterCapability` で外し、新しい集合で登録し直す。集合が変わらなければ登録し直さない。
- `workspace/didChangeWatchedFiles` の通知が、監視している表のファイルを含めば、プロジェクトを評価し直し、診断を公開し直す。エディタで開いている表のファイル（`wsOverlay` にあるもの）の通知は無視する。開いているあいだは、エディタの内容が正だからである。
- 動的な登録ができないクライアントでは、監視しない。今と同じく、原稿を編集したときに評価し直す。
- 図版と `@listing` のファイルは、この ADR では監視しない。

監視する対象を `**/*` にせず、参照しているパスに絞るのは、`build/` の下の出力の書き込みのたびに通知が来て評価し直すのを避けるためである。
`**/*.csv` と `**/*.tsv` のように拡張子で絞ると、`format` で読む `.txt` のファイルが漏れる。

### golem fmt、golem lint

- `golem fmt` は表のファイルを整形しない。原稿の `@table` の行は、今のとおりほかのブロックコマンドと同じく整形する。
- `golem lint` に表のための規則を加えない。`golem lint` は評価の診断も出すので、この ADR のコードはすべて `golem lint` にも出る。
- LSP の補完に、`format`、`align`、`cells` の値と表のファイルのパスは加えない。

### データ構造

golem-eval の `Asset` の `AssetText` に、そのファイルの `FileId` を持たせる。

```haskell
data Asset
  = -- | read as text, for a table or a listing, with the file it was read from (golem-eval ADR 0004)
    AssetText !FileId !Text
  | AssetPresent
  | AssetInvalid !PathError
```

`FileId` は、`@listing` のファイルにも振る。
`@listing` は当面これを使わず、今のとおり G0237 などはコマンドを指す。
型を先に広げておけば、`@listing` の診断をファイルの中で報告する変更が、型を変えずに済む。

表のファイルは、`loadAssets` が表のための読み込みの検査で読み、失敗したファイルは `AssetText` にしない。
そのため、`loadAssets` が返すものに、読み込みの段階の診断と、ファイルごとの `SourceInfo` を加える。

```haskell
data LoadedAssets = LoadedAssets
  { laAssets :: !(Map FilePath Asset),
    laSources :: !(Map FileId SourceInfo),
    laDiagnostics :: ![Diagnostic],
    -- | the table files the last evaluation read, for the LSP to watch (golem-eval ADR 0004)
    laTableFiles :: !(Set FilePath)
  }
```

表として読むかどうかを `loadAssets` が知るために、`assetRefs` は `@table` の参照と、`@listing` の参照を分けて返す。

```haskell
data AssetUse = UseImage | UseTable | UseListing
```

形式の決め方、揃えの読み方、セルの読み方は、`Golem.Eval.File` に置く純粋な関数とする。

```haskell
data TableFormat = TableCsv | TableTsv

-- | the reserved cells= values; only CellsText is implemented (golem-eval ADR 0004)
data CellReading = CellsText | CellsMarkup

tableFormat :: Maybe Text -> Text -> Either Text TableFormat
tableAlign :: Text -> Either AlignError [Alignment]

-- | the rows of a table file, each cell with its span; Left is G0285, G0282 or G0283 (golem-eval ADR 0004)
parseCsv :: FileId -> Text -> Either Diagnostic [[Text]]
parseTsv :: FileId -> Text -> Either Diagnostic [[Text]]
```

`tableAlign` は、値の並びを `[Alignment]` に直す。
値の数が一つのときに列の数だけ複製するのは、見出しの行を得た後の評価で行う。

意味論 IR の `Table` は変えない。
PDF、HTML、EPUB、テキストの出力は、原稿の `|` の表と同じく IR だけを見るので、変更は要らない。

LSP の `Workspace` に、監視を登録している表のファイルの集合を持たせる。

```haskell
wsWatchedTables :: !(Set FilePath)
```

## 実装しないこと

- セルをインラインの記法として読むこと（`cells=markup`）。名前を予約し、誤り（G0284）にするだけである。読み方（`|` の表のセルと同じ文法で読むか、エスケープをどうするか、誤りの位置を表のファイルの中にどう写すか）は、実装する ADR で決める。
- バックスラッシュのエスケープ（PostgreSQL の `COPY` の形）。セルに改行もタブも組めないので、書ける文字が増えても表は変わらない。`\` を書いたままの文字にしておくほうが、パスや正規表現のデータを壊さない。
- 引用符で囲んだセル（RFC 4180 の形の TSV）。TSV の引用符は書いたままの文字である。
- ファイルの中の揃えの行（`:---` の形）。表計算のソフトとやりとりできる TSV と CSV でなくなるので、揃えは `align` の引数だけで書く。
- `align` を式（`[= ...]`）やリストで書くこと。
- 列ごとの揃えを見出しの行と本体の行で分けること。
- 見出しの行のない表（`header=false` など）。今の CSV と同じく、一行目を常に見出しの行とする。
- UTF-8 でない文字コード（Shift_JIS、UTF-16）の表のファイル。表計算のソフトの「Unicode テキスト」の書き出しは UTF-16 なので、UTF-8 に変換してから使う。
- 拡張子が `.tsv` でも `.csv` でもないファイルを誤りにすること。今のプロジェクトの表を壊さないためである。
- 引用符の外の `"` を CSV の誤りにすること。
- CSV の空の行を表の行にすること。
- `@listing` のファイルの読み込みの検査、誤りの位置、LSP での監視。
- 図版のファイルの LSP での監視。
- LSP での `format`、`align`、`cells` の値と表のファイルのパスの補完。
- `@table` の位置引数のパス。v0.1.0-rc4 の項目で扱う。

## トレードオフ

### エスケープを持たない IANA の規則

IANA の規則は、セルにタブと改行を書けない。
PostgreSQL の形を選べば書けるが、Golem の表のセルは改行を持てず、タブは空白と見分けがつかないので、組める表は増えない。
バックスラッシュを書いたままの文字にすることで、パスや正規表現をそのまま表にできる。
将来、セルの中で改行したい表が出てきたら、そのときは `cells=markup` で原稿の記法として読むほうが、TSV の方言を増やすより筋がよい。

### 拡張子と `format`

拡張子だけで決めれば引数は要らないが、`.txt` で書き出されたタブ区切りのファイルを使うには、名前を変える必要がある。
`format` だけで決めれば見分けは明示的になるが、`.tsv` のファイルに毎回 `format=tsv` を書くのは冗長である。
両方を持ち、`format` を優先する。
拡張子が `.tsv` でないファイルを CSV として読む既定は、今の振る舞いを保つためであり、新しい形式を加えるときにも既定は CSV のままとする。

### CRLF を受け付け、単独の CR を誤りにすること

原稿は CR をすべて誤りにするが、表のファイルは CRLF を受け付ける。
表のファイルは、原稿と違って表計算のソフトが書き出すものであり、Windows の書き出しは CRLF のことが多い。
原稿は `golem fmt` で LF に直せるが、表のファイルは `golem fmt` の対象でなく、利用者に変換を求めることになる。
CRLF の CR は行の終わりの一部であり、セルにも位置の計算にも混ざらないので、受け付けても決定性は崩れない。
単独の CR は、CSV と TSV のどちらの規則でも行の終わりではなく、組めない文字なので、誤りにして利用者に知らせる。
代わりに、原稿と表のファイルで改行の規則が分かれ、G0103 と G0282 の二つのコードができる。

### 表のファイルに限り BOM を読み飛ばすこと

BOM は、表のファイルの規則（RFC 4180、IANA）のどちらにも書かれていない。
しかし、Excel の「CSV UTF-8」の書き出しは先頭に BOM を書く。
誤りにすると、Excel から書き出した CSV がそのままでは使えず、今の CSV の表が失敗することもある。
表のファイルは原稿と違い `golem fmt` の対象でもないので、BOM を除く手段を Golem が用意できない。
先頭の BOM は文字の中身を持たないので、読み飛ばしても表の中身は変わらず、決定性も崩れない。
代わりに、原稿と表のファイルで BOM の規則が分かれる。

### `align` の書き方

列ごとの揃えを、原稿の `|` の表の区切りの行の記号（`:---:`）で書く案もある。
しかし、`@table align=:---,:---:,---:` は読みにくく、引数の値としても `:` の扱いが要る。
名前で書けば、`golem explain` の説明と誤りの文言で値を挙げやすい。
一つの値をすべての列に当てるのは、数の表で列がすべて右寄せのことが多いからである。
二つ以上で数が合わないものを誤りにし、足りない列を既定で埋めないのは、列を足したときの揃えのずれを黙って許さないためである。

### `cells` を予約して誤りにすること

`cells` をいま予約しなければ、将来の名前が今の原稿の無視される引数と衝突しうる。
今の `@table` は知らないキーワード引数を無視するので、利用者が別の意味で `cells` を書いている可能性はある。
予約したうえで、未実装の値を誤りにすれば、将来 `cells=markup` を実装したときに、すでに書かれた原稿の意味が黙って変わることはない。

### 空の行と空のセル

CSV の読み方は空の行を捨てるが、TSV は捨てない。
列が一つの表では、空の行が空のセルを表すからである。
CSV で空の行を捨てることを変えないのは、今のプロジェクトの表を変えないためである。
表のファイルの誤りはファイルの行を指すので、余分な空の行があっても、利用者はその行をすぐに見つけられる。
TSV の空のセルを `[]` にし、CSV の `[Text sp ""]` と揃えなかったのは、原稿の `|` の表の空のセルに合わせるためである。
出力はどちらも空のセルになる。

### セルの位置をコマンドに置くこと

表のファイルの中の位置を持つので、セルの `Text` の位置を表のファイルの中のセルにすることもできる。
そうすれば、組版の段階の診断（書体にない字など）がセルを指せる。
しかし、意味論 IR の位置が `.gm` 以外のファイルを指すと、章の判定やラベルなど、位置からファイルを引く箇所が `.gm` だけを前提にしているかを一つずつ確かめる必要がある。
この ADR では、表のファイルの中の位置を読み込みと表の形の診断に限り、セルの位置は今と同じくコマンドに置く。

### G0235 を廃止にして G0285 を加えること

G0235 の位置をコマンドからファイルの中に移せば、コードの数は増えない。
しかし、同じコードの位置が版によって変わると、診断の出力を読む CI の設定や、`golem explain` の説明を前提にした手順が、気づかないうちにずれる。
位置の変わる誤りを新しいコードにすれば、変わったことがコードで見える。
代わりに、G0235 は節を残したまま廃止になり、番号が一つ使われずに残る。

### LSP の監視を参照するパスに絞ること

`**/*` を監視すれば登録し直しは要らないが、出力の書き込みのたびに通知が来る。
参照するパスに絞ると、原稿を変えて参照が変わるたびに登録し直す必要がある。
登録し直しは参照の集合が変わったときだけで、その頻度は原稿の編集の回数よりずっと少ない。
