# ADR 0003: 評価の診断コード G0201 から G0243

ステータス: 採択

## 文脈

golem-eval は、式の評価とファイル内評価（S0）の誤りを `G02xx` の診断として返す（[golem-eval ADR 0001](0001-expression-language-and-numerics.md)、[golem-eval ADR 0002](0002-file-evaluation.md)）。
しかし、G0201 から G0243 の番号と条件とメッセージを定めた ADR はない。
前者は `G02xx` とだけ書き、後者は検査の内容を表にしたが、コードには触れていない。
[docs/diagnostics.md](../../diagnostics.md) は、これらのコードの節に「ADR なし」と書いている。

コードの体系は [golem-syntax ADR 0001](../../golem-syntax/adr/0001-source-spans-and-diagnostics.md) が決めている。
上 2 桁が段階を表し、一度割り当てた番号はほかの意味に使い回さない。
この ADR は、その体系の上で、G0201 から G0243 の一つずつについて、出す条件、重大度、メッセージ、位置、出すモジュールを定める。
今のソースの挙動を追認する部分と、ソースを読んで見つけた問題を直す部分を分けて書く。

ソースを読んで見つけた問題は次のとおりである。
いずれも「実装すること」の「変更すること」で扱いを決める。

- G0233 が、ファイルがない場合と、パスが絶対パス、URL、プロジェクトのルートの外を指す場合の両方に出る。後者でもメッセージは `ファイルがありません` である。
- 同じパスを `@figure` と `@table` か `@listing` の両方から参照すると、golem-driver の `loadAssets` が後の参照の種類で上書きし、テキストとして読むべきファイルが `ファイルがありません` になることがある。
- G0207 が、組み込みの関数への誤った引数と、存在しない関数の呼び出しという別の条件に出る。メッセージの一つ `引数がありません` は、`min` と `max` の引数のパターンのせいで出ることがない。
- G0212 が、重複した属性の行ではなく、属性のまとまり全体を指す。重複が二つあっても一つしか出ない。
- G0223 の位置が、`@set` では変数の名前を指すが、`@import` ではコマンド全体を指す。
- G0215 が、対象を `/` で区切らず読みだけを `/` で区切った場合に出ない。このとき読みの `/` がそのまま読みの文字になる。[docs/markup.md](../../markup.md) の「セグメントの数が一致しない場合はコンパイルエラー」と食い違う。
- G0217、G0218、G0221 で、位置引数が `[= ...]` やコマンドのとき、名前が空のメッセージ（`style.toml にないスウォッチです: `）になる。
- G0219 のメッセージ `number-text には数を一つ書きます` は、整数しか受け付けないのに「数」と書いている。
- G0226 のメッセージは、名前に使える文字を示さない。`@label Intro` のように大文字を使った場合に、名前を書いたのに「名前を一つ書きます」と言われる。
- `number-text`、`ref-number`、`ref-title`、`ref-page`、`cite` に散文スロットを書くと、診断なしにスロットを捨てる。
- 属性のまとまりに対象のブロックがあって G0211 を出す場合に、まとまりの中の属性でないコマンド（`@set` など）を評価せずに捨てる。対象のブロックがない場合は評価する。捨てた `@set` の変数を後で参照すると、G0202 が続けて出る。
- G0208 の位置が、S0 では `[= ...]` のインラインを指し、S1 の `doc` を参照する式では `[= ...]` の中の式を指す。
- 次のコードにテストがない：G0223、G0225、G0226、G0227、G0230、G0232、G0234、G0235、G0236、G0238、G0239、G0240、G0241、G0243。テストのあるコードも、コードだけを確かめ、メッセージと位置は確かめていない。

段階の範囲の外の番号は見つからなかった。
G0201 から G0243 はすべて golem-eval が出し、G0222 だけはプラグインのコマンドの呼び出しで golem-driver も出す。
一つの箇所に同じコードを二度出す箇所も見つからなかった。

## 実装すること

### 共通の規則

- G0205 を除くすべてのコードは、重大度がエラーである。プロファイルによって重大度は変わらず、`profileDependentCodes` には含めない。
- G0205 は警告であり、prod のプロファイルでだけ出る。dev では出さない。
- 位置について、この ADR では次の語を使う。
  - **式の位置**：診断の原因になった部分式の `Located Expr` の範囲。二項演算なら演算全体、関数の呼び出しなら呼び出し全体、変数なら変数の参照全体である。
  - **コマンド全体**：ブロックコマンドなら `@` から本体の終わりまで、インラインのコマンドなら `[` から `]` までの範囲。
  - **名前の位置**：コマンドの名前の語だけの範囲。
  - **属性の行**：属性のまとまりの中の、一つの属性のブロックコマンドの範囲。
  - **まとまり全体**：属性のまとまり（`A.Attributed`）の範囲。
- メッセージの `<型>` は `typeName` の返す語（`整数`、`浮動小数点数`、`文字列`、`真偽値`、`nil`、`配列`、`連想配列`）である。
- 引数の `<名前>`、`<値>`、`<パス>` は、引数が語か文字列のリテラルであればその文字列であり、それ以外（`[= ...]` やコマンド）では空文字列になる（`argText`）。

### 既存の挙動の追認

この節は、今のソースの挙動をそのまま定める。
次の節「変更すること」で変える点は、ここでは今の挙動を書き、変更の番号を添える。

#### 式（`Golem.Eval.Expr`）

G0201 から G0208 は、`evalExpr` と `embedValue` が出す。
`[= ...]`、`@set` の右辺、コマンドの引数の式で出る。
`doc` を参照する式は S0 では評価せず、S1 で golem-driver の `evalDeferred` が同じ `evalExpr` と `embedValue` で評価する。
このため、`doc` を参照する式の G0201 から G0208 は S1 で出る。
どれも、最初の誤りで式の評価を止め、一つの式につき一つだけ出す。

| コード | 条件 | メッセージ | 位置 |
|---|---|---|---|

| G0201 | `+`、`-`、`*`、`/`、`**`、比較の演算子の両辺が、その演算子の受け付ける型の組でない | `<型> と <型> にこの演算子は使えません` | 式の位置 |
| G0201 | `%` の両辺の一方が整数でない（右辺が整数の 0 の場合は G0203 が先） | `% は整数にだけ使えます` | 式の位置 |

#### 図版、表、ソースコードのリスト（`Golem.Eval.File`）

ファイルの存在は、golem-driver の `loadAssets` が読み込んだ `ctxAssets` で判定する。
パスはプロジェクトのルートからの相対パスである。

`@figure` は次の順に検査し、最初に当たった一つを出して図版を作らない。
ただし G0233 は、画像と `web` の両方について先に検査し、ほかの検査と並べて出す。
キャプションの評価の診断も、ほかの検査の結果によらず出す。

1. 位置引数が一つでなければ G0232。
2. 画像と `web` のファイルがなければ、それぞれ G0233。
3. `alt` がなければ G0228。空の `alt=""` は受け付ける。
4. 画像のパスが `.pdf` で終わり（大文字と小文字を区別しない）、`web` がなければ G0229。
5. G0233 を出していれば、ここで止める。
6. `wrap` が `start` でも `end` でもなければ G0230。
7. `wrap` があって `width` がなければ G0231。

| コード | 条件 | メッセージ | 位置 |
|---|---|---|---|
| G0228 | `@figure` に `alt` のキーワード引数がない | `図版には alt の代替テキストが必要です` | コマンド全体 |
| G0229 | PDF の画像を使う `@figure` に `web` のキーワード引数がない | `PDF の図版には web の代替画像が必要です` | コマンド全体 |
| G0230 | `@figure` の `wrap` が `start` でも `end` でもない | `wrap は start か end です: <値>` | コマンド全体 |
| G0231 | `wrap` のある `@figure` に `width` がない | `回り込む図版には width が必要です` | コマンド全体 |
| G0232 | `@figure` の位置引数が一つでない | `@figure には画像のパスを一つ書きます` | コマンド全体 |
| G0233 | `@figure` の画像か `web`、`@table` の `src`、`@listing` のファイルが `ctxAssets` にない（変更 1 で条件を分ける） | `ファイルがありません: <パス>` | コマンド全体 |
| G0234 | `@table` に `src` のキーワード引数がない。位置引数のパスは受け付けない | `@table には src が必要です` | コマンド全体 |
| G0235 | `@table` の CSV から空の行を除くと行が一つもない | `CSV が空です` | コマンド全体 |
| G0235 | `@table` の CSV の行のセルの数が、最初の行のセルの数と違う | `CSV の行ごとのセルの数が一致しません` | コマンド全体 |
| G0236 | `@listing` に位置引数も `src` のキーワード引数もない。両方あれば位置引数を使う | `@listing にはファイルのパスが必要です` | コマンド全体 |
| G0237 | `@listing` の `lines` が `開始-終了` の二つの 10 進数の形でないか、開始が 1 未満か、終了が開始より小さいか、終了がファイルの行数を超える | `lines の範囲が不正です: <値>` | コマンド全体 |

G0235 は、CSV のファイルの中の行を指さず、`@table` のコマンドを指す。
CSV のファイルには `FileId` がなく、診断の位置として表せないためである。
CSV の不正を二つの文言で一つのコードにまとめるのは、どちらも「CSV の形が表にならない」という一つの条件だからである。

### 変更すること

#### 変更 1：G0233 からパスの誤りを分け、G0260 を割り当てる

`@figure`、`@table`、`@listing` のパスが、絶対パス、URL、またはプロジェクトのルートの外（`..` やシンボリックリンクで外に出るもの）を指す場合は、G0260 とする。
G0233 は、パスとして正しく、ファイルがない場合だけに出す。

| コード | 条件 | メッセージ | 位置 |
|---|---|---|---|
| G0260 | パスが絶対パス | `絶対パスは使えません: <パス>` | コマンド全体 |
| G0260 | パスが URL | `URL は使えません: <パス>` | コマンド全体 |
| G0260 | パスがプロジェクトのルートの外を指す | `プロジェクトルートの外を指しています: <パス>` | コマンド全体 |

メッセージの前半は、golem-project の `pathErrorMessage` をそのまま使う。
章と `@import` のパスの誤り（G0303）と文言をそろえるためである。
番号を G0303 と共有しないのは、G0303 がプロジェクトの段階（`G03xx`）のコードであり、図版などのファイルの参照は評価の段階のものだからである。

実装では、golem-driver の `loadAssets` が `resolveInRoot` の `PathError` を捨てずに `ctxAssets` に渡し、golem-eval がそれを見て G0233 か G0260 を選ぶ。
`ctxAssets` の型は、ファイルの中身（テキストか、テキストでないが存在する）か、パスの誤りかを表すものに変える。

あわせて、同じパスを `@figure` と、`@table` か `@listing` の両方から参照した場合は、テキストとして読む。
`loadAssets` は、参照のどれかがテキストを求めていれば、そのパスをテキストとして読む。
今は後の参照の種類で上書きするので、`@listing` が `ファイルがありません` になることがある。

#### 変更 2：存在しない関数を G0261 に分け、出ない枝を消す

`builtinNames` にない関数の呼び出しは、G0207 でなく G0261 とする。

| コード | 条件 | メッセージ | 位置 |
|---|---|---|---|
| G0261 | 式の中で、`builtinNames` にない名前の関数を呼んだ | `未定義の関数 <関数> です` | 式の位置 |

G0207 は、組み込みの関数への誤った数か型の引数だけに出す。
綴りの誤りと引数の誤りは直し方が違い、`golem explain` で別の説明を引けるようにするためである。
G0202（未定義の名前）に含めないのは、変数と関数は名前の空間が別で、`@set` で関数を定義することもできないからである。

`min` と `max` の `extreme _ []` の枝（`引数がありません`）は出ないので消す。
引数のない `min()` と `max()` は、今と同じく `min の引数が不正です` の G0207 になる。

#### 変更 3：G0212 は重複した属性の行を指す

G0212 の位置を、まとまり全体から、重複した属性の二つ目以降の行に変える。
重複が複数あれば、二つ目以降の行のそれぞれに一つずつ出す。
同じ名前の属性が三つあれば、二つ目と三つ目に出す。
直すべき行を位置が直接示すようにするためである。

#### 変更 4：`@import` の G0223 は名前空間の語を指す

`@import` の名前空間が予約語の場合の G0223 の位置を、コマンド全体から、名前空間の位置引数の範囲に変える。
`@set` の G0223 が変数の名前を指すのとそろえる。

#### 変更 5：G0211 のとき、まとまりの中の属性でないものも評価する

対象のブロックがある属性のまとまりで G0211 を出す場合も、まとまりの中の属性でないもの（`@set` など）を書いた順に評価してから、属性を対象に適用する。
対象のブロックがない場合と同じ扱いにし、捨てた `@set` の変数への参照が G0202 を続けて出すのを防ぐ。

#### 変更 6：読みだけを `/` で区切ったルビも G0215 にする

`ruby` の対象が一つのセグメントで、読みを `/` で区切ると二つ以上のセグメントになる場合も、G0215 とする。
メッセージと位置は今の G0215 と同じである。
[docs/markup.md](../../markup.md) の「`/` で対象と読みを同じ数のセグメントに区切る」「一致しない場合はコンパイルエラー」に実装を合わせる。
読みに `/` の文字そのものを入れる書き方は、v1 では用意しない。

#### 変更 7：S1 の G0208 も `[= ...]` のインラインを指す

`doc` を参照する式を S1 で評価して G0208 になった場合も、位置を `[= ...]` のインライン（`Deferred` の範囲）にする。
golem-doc の `assemble` が `evalDeferred` に `Deferred` の範囲を渡すか、`evalDeferred` の返した G0208 の範囲を `Deferred` の範囲に置き換える。
G0201 から G0207 は、S0 と同じく式の位置のままにする。

#### 変更 8：G0219 のメッセージ

`number-text には数を一つ書きます` を `number-text には整数を一つ書きます` に改める。

#### 変更 9：G0226 のメッセージに名前の規則を書く

G0226 の二つのメッセージを次に改める。

- `@label にはラベルの名前を一つ書きます。名前は英小文字、数字、-、_ で書きます`
- `参照にはラベルの名前を一つ書きます。名前は英小文字、数字、-、_ で書きます`

条件と位置は変えない。

#### 変更 10：名前でない位置引数への G0217、G0218、G0221

`color`、`style`、`cite` の位置引数が一つで、それが語でも文字列のリテラルでもない（`[= ...]` やコマンド）場合は、名前のないメッセージ（`style.toml にないスウォッチです: `）でなく、「一つ書きます」の側のメッセージを出す。

- G0218：`style には文字スタイルの名前を一つ書きます`

#### 変更 11：散文スロットを取らないコマンドのスロットを G0238 にする

`number-text`、`ref-number`、`ref-title`、`ref-page`、`cite` に散文スロットを書いた場合は、G0238 とし、コマンドを出力しない。

## トレードオフ

今の挙動を追認する部分と変える部分を一つの ADR にまとめたので、ADR が長い。
コードごとに ADR を分けると、G0201 から G0243 の 43 のコードの条件が散らばり、`golem explain` の文書を書くときに引きにくい。
変更は番号を付けて分け、実装のコミットを変更ごとに分けられるようにした。

G0233 と G0207 を分けると、番号が二つ増える。
番号を使い回さない規則（[golem-syntax ADR 0001](../../golem-syntax/adr/0001-source-spans-and-diagnostics.md)）のもとでは、番号は減らない。
それでも分けるのは、一つのコードに直し方の違う条件が混ざると、コードから直し方を引くという診断のコードの目的が果たせないからである。

一方、G0210、G0213、G0214、G0219、G0235、G0238 のように、一つのコードに複数のメッセージがあるものは分けない。
これらは、メッセージは違っても条件の種類と直し方が同じだからである。

変更 6 は、読みに `/` を含むグループルビを書けなくする。
今の実装でこれを書いた原稿は、ビルドが失敗するようになる。
記法の文書がすでにエラーと定めているので、実装の誤りを直すものとして扱う。

変更 11 も、今は通っている原稿（スロットを書いた `cite` など）のビルドを失敗させる。
スロットを黙って捨てると、書いた本文が出力から消えたことに気づけないので、エラーにするほうを選ぶ。
