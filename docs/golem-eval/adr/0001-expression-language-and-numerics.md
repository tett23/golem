# ADR 0001: 式の言語と数の規則

ステータス: 採択

## 文脈

原稿の式文脈 `[= ...]` と `@set` は、コンパイル時に評価される式の言語で書く。
言語仕様（docs/markup.md）は、リテラル、演算子、組み込み関数、数の規則を定めている。
この ADR は、それを評価器としてどう実装し、どう検証するかを定める。

式の評価は、決定性が最も崩れやすい場所の一つである。
浮動小数点数の計算、超越関数、数値の文字列化は、実装によって最後の桁が変わりうる。
言語仕様はこれを避ける規則を定めており、評価器はその規則を一つの例外もなく実装する必要がある。

## 実装すること

### 値

```haskell
data Value
  = VInt !Integer
  | VFloat !Double     -- NaN、無限大、負のゼロを含まない
  | VString !Text
  | VBool !Bool
  | VNil
  | VArray !(Vector Value)
  | VHash !(Map Text Value)
```

`VFloat` を作る箇所はすべて一つの関数を通し、NaN と無限大はエラーに、負のゼロは正のゼロにする。

### 演算子の優先順位

高い順に次のとおりとする。

| 優先順位 | 演算子 | 結合 |
|---|---|---|
| 1 | 関数呼び出し、名前空間の参照（`a.b`） | 左 |
| 2 | `**` | 右 |
| 3 | 単項の `-` | |
| 4 | `*`、`/`、`%` | 左 |
| 5 | `+`、`-` | 左 |
| 6 | `==`、`!=`、`<`、`<=`、`>`、`>=` | 結合しない |

### 数の規則

言語仕様の「数の規則」をそのまま実装する。
実装上の要点は次のとおりである。

- 浮動小数点数のリテラルの読み取りは、十進の文字列から最も近い倍精度の値への正しい丸めで行う。
- `**` は、指数が整数のときだけ、二乗の繰り返しで計算する。指数が浮動小数点数ならエラーとする。
- `div` と `%` は整数専用とし、負の無限大の方向への切り捨てで実装する（Haskell の `div` と `mod`）。
- `round(x, n)` と `fixed(x, n)` は、`x` を最短の十進表記に直し、その十進数を 0 から遠い方向への四捨五入で丸める。浮動小数点数のまま 10 の累乗を掛けて丸める実装は使わない。
- 本文に埋め込む浮動小数点数の表記は、最短の往復表記の数字列から、指数表記を使わずに組み立てる。整数値なら小数点以下を付けない。

### 組み込み関数と定数

`pi`、`e`、`sqrt`、`floor`、`ceil`、`round`、`fixed`、`abs`、`min`、`max`、`len`、`div` を実装する。
`pi` と `e` は、それぞれ倍精度で最も近い値の定数とする。

### 評価とエラー

- 評価は純粋な関数とし、入出力を一切行わない。
- 型の誤り、未定義の名前、0 での割り算、NaN と無限大を作る演算、浮動小数点数の指数は、式の位置を指す診断として返す（`G02xx`）。
- 本文への埋め込みでは、数と文字列だけを受け付け、それ以外は型エラーとする。

## 実装しないこと

- 超越関数（三角関数、指数関数、対数関数）と、浮動小数点数の指数による累乗。決定性を保つ実装方法を v2 で決める。
- ユーザー定義の関数、条件式、繰り返し。
- 文字列の連結などの文字列の演算子。
- `[number-text ...]` の表記の解決。これは評価ではなく、書字方向が決まった後の段階で行う。

## テスト設計

- **境界の値**：`round(2.675, 2) = 2.68`、`round(-2.5) = -3`、`fixed(1.5, 2) = "1.50"`、`[= 10 / 2]` が「5」、`0.01` が「0.01」、`1e21` 相当の値が位取りで書かれること、負のゼロが「0」になることを確かめる。
- **エラー**：`1 / 0`、`sqrt(-1)`、`2 ** 0.5`、`div(1.5, 1)`、オーバーフローが、それぞれ診断になることを確かめる。
- **代数的性質**：任意の整数 `a` と 0 でない `b` について `a == div(a, b) * b + a % b` が成り立つことをプロパティテストする。
- **往復**：任意の有限の倍精度の値について、本文への表記を読み直すと元の値に戻ることをプロパティテストする。
- **アーキテクチャ間の一致**：固定した式の集合の評価結果を、x86-64 と aarch64 の CI で比較する。

## トレードオフ

`round` を十進表記の上で行うと、二進数の値をそのまま丸める方式より計算は遅くなる。
原稿に現れる式の数は少なく、書き手の期待に合うことのほうが重要なので、この遅さは受け入れる。

比較演算子と真偽値は、条件式を持たない v1 では使い道が限られる。
将来条件式を加えるときに演算子の優先順位と値の型を作り直さずに済むよう、言語仕様と評価器に最初から含めておく。
