# ADR 0006: 累乗の計算の上限を範囲より先に正確に判定する

ステータス: 採択→累乗の判定の順序と G02095 は [docs/adr ADR 0101](../../adr/0101-rational-numbers-in-expressions.md)

## 文脈

[golem-eval ADR 0005](0005-float-overflow.md) は、整数の底と負の指数の `**` と、浮動小数点数の底の `**` を、正確な値を最も近い倍精度の値に一度だけ丸めて求めると決めた。
正確な計算が大きくなりすぎないように、同じ ADR は計算の前に結果の大きさを倍精度の掛け算で見積もり、次の順に判定する。

1. 見積もった結果の絶対値の log2 を `E` とし、`E ≥ 1025` なら G02004 とする。
2. `E ≤ -1076` なら、計算せずに 0 とする（コードの条件は `E < -1076`）。
3. 底を `±m × 2^f`（`m` は正の奇数）と分け、`(m のビットの数 - 1) × |k|` が 2^20 を超えれば G02086 とする。メッセージは `累乗の計算が大きすぎます` である。
4. ほかは正確に計算して丸め、丸めた結果が無限大なら G02004 とする。

PR #264 で入った `modules/golem-eval/src/Golem/Eval/Expr.hs` の `powRounded` は、この順のとおりに作られている。
上限の定数は `maxExactBits`、見積もりの関数は `estimatePow` である。

見積もりには誤差がある。
底の仮数を倍精度に丸めるときの相対誤差（最大 2^-53）は、`|k|` 乗するとおよそ `|k| × 2^-53` の相対誤差になり、二乗の繰り返しの丸めも同じ程度の誤差を足す。
[ADR 0005](0005-float-overflow.md) は「見積もった log2 の誤りは 1 より十分に小さい」と書いたが、誤差は `|k|` に比例して増え、指数の大きさには整数の上限（2^4096）しかない。
このため、真の値が範囲の境界の近くにある式では、判定 1 と判定 2 の結果が真の値と食い違い、判定 3 に進むかどうかが入れ替わる。

main（e69e6848）の `powRounded` と同じ関数を手元で組み、次を確かめた。
真の値の log2 は `bc -l` で 40 桁まで計算した。
二つの底は、倍精度の値 1 + 7 × 2^-24 と 1 - 2^-26 を、十進で正確に書いたものである。

| 式 | 真の値の log2 | main の結果 | [ADR 0005](0005-float-overflow.md) の規則を真の値に当てた結果 |
| --- | --- | --- | --- |
| `1.000000417232513427734375 ** 1702829922` | 1025.0000000076 | G02086 | G02004 |
| `1.000000417232513427734375 ** 1702829923` | 1025.0000006095 | G02004 | G02004 |
| `0.99999998509883880615234375 ** 50051559810` | -1076.0000000096 | G02086 | 0 |
| `0.99999998509883880615234375 ** 50051559811` | -1076.0000000311 | 0 | 0 |

一つめの組では、指数を 1 増やすと G02086 が G02004 に変わる。
二つの式の真の値はどちらも 2^1025 以上であり、コードを分けたのは見積もりの丸めの誤差である。
二つめの組では、エラーと値（0）が入れ替わる。
アンダーフローの境界の近くでは、diagnostic が出るかどうか、つまりビルドが失敗するか成功するかまでを、見積もりの誤差が決めている。

見積もりは倍精度の掛け算と 2 での割り算だけを使うので、同じバージョンの Golem なら、マシンが違っても同じ結果になる。
出力のバイト列についての決定性（[docs/adr/0002](../../adr/0002-determinism.md)）は、この意味では破れていない。
破れているのは、どの diagnostic になるかを仕様の言葉で書けないことである。
仕様が判定に使うのは「見積もった log2」であり、その値は見積もりの手順（掛け算の順序、仮数の丸め方）に依存する。
手順を変えれば誤差が変わり、同じ式の diagnostic のコードが変わる。
[ADR 0005](0005-float-overflow.md) の「上限を v2 で広げる余地」のとおりに正確な計算を Ziv の方式に置き換えるときも、同じことが起きる。

メンテナーは、diagnostic のコードが揺れることを受け入れないと判断した。
Golem の土台は決定性である。
決定性はバイト列についての約束だが、それは diagnostic のコードが揺れてよいことを意味せず、揺れは決定性の原則に反する。

コードの割り当てにも問題がある。
G02086 は、[docs/adr/0035](../../adr/0035-security-hardening.md) が整数の絶対値の上限（2^4096）と、`round` と `fixed` の桁数の上限に割り当てたコードである。
[ADR 0005](0005-float-overflow.md) は、これに `累乗の計算が大きすぎます` を加えた。
整数の上限は結果の値についての制限だが、累乗の計算の上限は計算の手間についての制限であり、結果が倍精度に収まる式にも出る。
意味の違う条件に一つのコードを使うと、コードから原因を引けない。

## 実装すること

### 判定の順序

整数の底と負の指数の `**` と、浮動小数点数の底の `**` を、次の順に判定する。
整数の底と 0 以上の指数の `**` は変えず、[docs/adr/0035](../../adr/0035-security-hardening.md) の G02086 のままとする。

底 `a` は 0 でない整数か、0 でない有限の倍精度の値である。
倍精度の値の分母は 2 の累乗なので、`|a|` はいつも `m × 2^f`（`m` は正の奇数、`f` は整数）と一意に分けられる。
指数を `k`（0 でない整数）とする。

1. **計算の上限**：`(m のビットの数 - 1) × |k|` が `maxExactBits`（2^20）を超えれば、新しいコード G02095 のエラーとする。結果が倍精度の範囲の内か外かは問わない。判定は整数の演算だけで行う。
2. **正確な値**：`P = m^|k|` を整数で計算する。`F = f × k` とすると、結果の絶対値は、`k > 0` なら `P × 2^F`、`k < 0` なら `2^F / P` である。
3. **あふれ**：結果の絶対値が 2^1024 以上と決まれば、G02004 の `結果が NaN か無限大になる演算です` とする。
4. **アンダーフロー**：結果の絶対値が 2^-1075 以下と決まれば、0 とする。2^-1075 は 0 と最小の非正規化数の中間であり、偶数の側の 0 に丸まる。
5. **丸め**：ほかは正確な有理数を `fromRational` で一度だけ丸める。丸めた結果が無限大なら G02004 とする。

符号と負のゼロの扱いは [ADR 0005](0005-float-overflow.md) のまま変えない。
底が負で `k` が奇数なら結果を負にし、負のゼロは正のゼロにする。

判定 3 と判定 4 は、`P` のビットの数 `L` と `F` から整数で決める。
`k > 0` なら、結果の絶対値は 2^(L - 1 + F) 以上 2^(L + F) 未満である。
`k < 0` なら、結果の絶対値は 2^(F - L) より大きく 2^(F - L + 1) 以下である。
下の端が 2^1024 以上なら判定 3 に、上の端が 2^-1075 以下なら判定 4 に当たる。
どちらでもない場合は `|F| ≤ L + 1076` なので、判定 5 で `2^F` を作っても大きくならない。

### 計算の大きさの上界

判定 1 を通った式では、正確な計算はいつも小さい。
`m ≥ 3` なら `m のビットの数 - 1 ≥ 1` なので `|k| ≤ 2^20` であり、`P` のビットの数は `(m のビットの数) × |k| ≤ 2^20 + |k| ≤ 2^21` 以下になる。
`m = 1`（底が 2 の累乗）なら `P = 1` であり、指数がいくつでも判定 3 と判定 4 は整数 `F` の比較で終わる。
手元の試作では、上限に近い `1.0000001 ** 20164`（`52 × 20164 = 1048528`）の丸めが約 8 ミリ秒、`1.5 ** 1048576` のあふれの判定が約 3 ミリ秒、`2.0 ** 1000000000000000000` の判定が 1 ミリ秒未満で終わった。

### 倍精度の見積もりを消す

`estimatePow` と `split` を消し、判定に倍精度の値を使わない。
見積もりを計算を省く近道として残すには、どの入力でも判定の結果を変えないことを示す誤差の上界が要る。
その上界は `|k|` に比例し、[ADR 0005](0005-float-overflow.md) はそれを小さく見積もった。
一方で、上の上界のとおり、判定 1 を通った式の正確な計算は数ミリ秒で終わる。
近道を残しても速さの利点はなく、判定の正しさを示す手間だけが残るので、消す。

### 新しいコード G02095

- G02095 は、累乗を正確に計算すると大きくなりすぎることを表す。重大度はエラーで、メッセージは `累乗の計算が大きすぎます（正確な計算に要るビットの数 <n> が、上限の 1048576（2 の 20 乗）を超えます）` とする。<n> は `(m のビットの数 - 1) × |k|` の値である。何が大きいのかを書き手が迷わないよう、要る量と上限を数で示す。
- 位置は `**` の式の全体とし、今の G02086 の `累乗の計算が大きすぎます` と同じにする。
- G02086 から `累乗の計算が大きすぎます` を除く。G02086 は、整数の絶対値の上限と、小数の桁数の上限だけを表す。
- 番号は、評価の段階（上 2 桁が 02）の空いている番号から選んだ。G02087 から G02094 は、採択済みの ADR と下書きの ADR が使っている。

### diagnostics の決定性の原則

仕様書の「設計原則」に、diagnostics の決定性を加える。
同じ入力からは、出力のバイト列に加えて、同じ diagnostics（コード、メッセージ、位置、並びの順）を得る。
どの diagnostic になるかは入力だけで決まり、近似の誤差や計算の順序に左右されない。
判定に近似を使ってよいのは、近似が判定の結果を変えないことを示せる場合に限る。

## アルゴリズム

```haskell
-- 底 a（0 でない整数か有限の倍精度の値を有理数にしたもの）、指数 k（0 でない整数）
-- integerLog2 n は n のビットの数から 1 を引いた値
pow a k
  | integerLog2 m * abs k > maxExactBits = G02095
  | lo >= 1024                            = G02004
  | hi <= -1075                           = 0
  | otherwise                             = finiteOrG02004 (withSign (fromRational exact))
  where
    (m, f) = oddAndPowerOfTwo (abs a)   -- |a| = m * 2^f、m は正の奇数
    p = m ^ abs k
    big = f * k
    l = integerLog2 p + 1
    (lo, hi)
      | k > 0 = (l - 1 + big, l + big)  -- 2^lo ≤ |結果| < 2^hi
      | otherwise = (big - l, big - l + 1)  -- 2^lo < |結果| ≤ 2^hi
    exact
      | k > 0 = fromInteger p * 2 ^^ big
      | otherwise = 2 ^^ big / fromInteger p
```

## 実装しないこと

- 上限 `maxExactBits` の値を変えること。上限を広げるのは [ADR 0005](0005-float-overflow.md) のとおり v2 以降である。
- 上限を超える式に、結果が範囲の外であることも合わせて知らせること。範囲の判定には正確な計算が要るので、上限を超える式の範囲は判定しない。
- 整数の底と 0 以上の指数の判定（[docs/adr/0035](../../adr/0035-security-hardening.md)）を変えること。この判定は整数の演算だけで行っており、近似を使っていない。
- アンダーフローを diagnostic で知らせること。[ADR 0005](0005-float-overflow.md) のとおり 0 とする。
- ほかの diagnostics の判定に近似が使われていないかを、全モジュールにわたって調べること。原則に反する箇所が見つかれば、仕様書の「既知の不具合」に載せ、個別の ADR で直す。この監査は v1.0.0 で行う（ロードマップの「diagnostics の判定の近似の監査」）。

## テスト設計

先に次のテストを書き、main で失敗することを確かめてから直す。
結果の値は、[ADR 0005](0005-float-overflow.md) と同じく倍精度のビットの並び（`castDoubleToWord64`）で比べる。

- **見積もりの揺れの再現**：「文脈」の表の四つの式が、どれも G02095（`累乗の計算が大きすぎます（正確な計算に要るビットの数 <n> が、上限の 1048576（2 の 20 乗）を超えます）`）になる。main では、指数を 1 だけ変えた組で G02086 と G02004、G02086 と 0 に分かれるので失敗する。
- **上限による分類（プロパティテスト）**：0 でない任意の倍精度の値 `a` と、上限の前後に偏らせて生成した整数 `k` について、結果が G02095 になることと `(m のビットの数 - 1) × |k| > 2^20` が同値である。生成する `|k|` は 2^40 までとし、範囲の外の結果になる組を含める。main では `1.5 ** 100000000` のような範囲の外の組が G02004 になるので失敗する。
- **入力だけで決まること（プロパティテスト）**：任意の `a` と `k` について、`a ** k` を単独で評価した場合と、ほかの式の後に評価した場合と、同じファイルで二度評価した場合で、diagnostic のコードとメッセージが一致する。同じ値を違う書き方にした底（`1.5`、`1.50`、`15e-1`）でも、コードとメッセージが一致する。同じソースを二度評価した diagnostics の列（コード、メッセージ、位置、順序）が一致する。
- **正確な丸めとの一致（プロパティテスト）**：[ADR 0005](0005-float-overflow.md) の性質（`|k| ≤ 64` で、結果が `fromRational (toRational a ^^ k)` と一致するか、それが無限大のとき G02004）を残す。加えて、底が 2 の累乗の値（`m = 1`）と `|k| ≤ 2^4000` の任意の組について、結果が 2^(f × k) を直接丸めた値か G02004 か 0 と一致する。
- **あふれの境界**：`2.0 ** 1023` が 2^1023、`2.0 ** 1024` と `0.5 ** -1024` が G02004 になる。判定 5 に進む組として、`3.0 ** 646` が `1.6608505280233425e308`、`3.0 ** 647` が G02004 になる。
- **アンダーフローの境界**：`2.0 ** -1074` と `2 ** -1074` が 2^-1074、`2.0 ** -1075` と `(-2) ** -1075` が 0（負のゼロでない）になる。判定 5 に進む組として、`3.0 ** -678` が 2^-1074 に丸まり、`3 ** -679` が 0 になる。
- **上限の境界**：`1.0000001 ** 20164` が値になり、`1.0000001 ** 20165`（`52 × 20165 = 1048580`）が G02095 になる。`1.5 ** 1048576` が G02004、`1.5 ** 1048577` が G02095、`1.5 ** -1048576` が 0、`1.5 ** -1048577` が G02095、`3 ** -1048576` が 0、`3 ** -1048577` が G02095 になる。
- **底が 2 の累乗で指数が大きい式**：`2.0 ** 100000000000` が G02004、`0.5 ** 100000000000` と `2 ** -100000000000` が 0 になる。
- **時間**：上の式は、どれも 1 秒以内に終わる。
- **既存のテストの更新**：[ADR 0005](0005-float-overflow.md) のテストのうち、`1.5 ** 100000000` と `0.75 ** -100000000` の G02004 を G02095 に、`1.0000001 ** 100000` の G02086 を G02095 に改める。`0.5 ** 100000000` の 0 は変わらない。
- **diagnostic の一覧**：golem-driver のテスト（`modules/golem-driver/test/Main.hs`）で、G02095 が `docs/diagnostics.md` に状態「使用中」で載り、ソースで使われていることを確かめる。
- **アーキテクチャ間の一致**：上の境界の式を、[golem-eval ADR 0001](0001-expression-language-and-numerics.md) の x86-64 と aarch64 の比較の式の集合に加える。

## トレードオフ

上限を範囲より先に判定するので、明らかに範囲の外にある式も G02095 になる。
`1.5 ** 100000000` は今は G02004 だが、G02095 になる。
整数の演算だけで「確実に範囲の外」と言える場合（`|a|` の log2 の整数の上下の端と `k` の積で判定する場合）に G02004 を先に出す案もあった。
しかし、その案では G02004 と G02095 の境界が、log2 の端の取り方という仕様の外の事情で決まり、今と同じく、値が近い二つの式でコードが分かれる。
メンテナーは、上限を超える式はいつも G02095 とすると決めた。
上限を超える式は、範囲の内でも外でも同じ直し方（指数を小さくするか、底を変える）になるので、コードを一つにまとめても利用者の手間は増えない。

G02086 を分けると、[ADR 0005](0005-float-overflow.md) の後に `累乗の計算が大きすぎます` の G02086 を前提にした CI やスクリプトが、G02095 を見落とす。
[ADR 0005](0005-float-overflow.md) は v0.1.0 のリリースの前に入り、このコードを含むリリースはまだないので、影響はリリース前の作業中のバージョンに限られる。

倍精度の見積もりを消すので、上限の内で範囲の外にある式（`1.5 ** 1048576` など）は、`P` を計算してから判定する。
見積もりなら計算せずに済むが、`P` のビットの数は 2^21 以下であり、手元の試作で数ミリ秒だった。

## ドキュメント

- `docs/diagnostics.md` に G02095 の節を足す。題は `累乗の計算が大きすぎます` とし、メッセージには要るビットの数と上限を書き、意味（底の奇数の部分のビットの数から 1 を引いた値と指数の絶対値の積が 2^20 を超えること、範囲の内か外かを問わないこと）、メッセージ、段階とモジュール（評価、golem-eval の `Golem.Eval.Expr`）、ADR（[golem-eval ADR 0005](0005-float-overflow.md) とこの ADR）、主な原因（`1.0000001 ** 100000`、`1.5 ** 100000000`）、直し方を書く。
- `docs/diagnostics.md` の G02086 の節から、累乗の計算の上限の文と、メッセージ `累乗の計算が大きすぎます` と、主な原因の `1.0000001 ** 100000` を除き、ADR の欄にこの ADR を加える。
- `docs/markup.md` の「数の規則」の累乗の段落を、この ADR の判定の順序に書き換える。「計算の前に結果の大きさを見積もり」の文を消し、上限の判定を先に置き、コードを G02095 に改める。
- 仕様書の「設計原則」に、diagnostics の決定性の原則を加える。決定性の規則を述べる段落（「メタデータ」の「識別子」の後）にも、diagnostics が決定性の対象であることを書く。
- 仕様書の「既知の不具合」から、累乗の diagnostic が見積もりの誤差で決まる項目を消す。
- [golem-eval ADR 0005](0005-float-overflow.md) のステータスの行を `採択→累乗の判定の順序と G02086 の累乗の上限は golem-eval ADR 0006` に改め、この ADR へのリンクを付ける。
- 利用者向けマニュアルの式の章（`manual/appendices/a-markup.gm`）と diagnostic の付録（`manual/appendices/e-errors.gm`）、開発者のマニュアルの純粋さの章（`manual-dev/part2/12-purity.gm`）の、見積もりと G02086 の記述を直す。
