# ADR 0005: 浮動小数点数の桁あふれ

ステータス: 採択→累乗の判定の順序と G0286 の累乗の上限は [golem-eval ADR 0006](0006-exact-power-limit-before-range.md)

## 文脈

式の言語は、任意精度の整数と倍精度の浮動小数点数を持つ（[docs/markup.md](../../markup.md) の「数の規則」、[golem-eval ADR 0001](0001-expression-language-and-numerics.md)）。
整数は絶対値が 2 の 4096 乗未満まで作れる（[docs/adr/0035](../../adr/0035-security-hardening.md)）。
倍精度で表せる有限の値は、絶対値が約 1.8 × 10^308 未満と、2^-1074 以上の非正規化数である。
二つの型の範囲が違うので、整数を浮動小数点数に変える箇所と、途中の値が倍精度に収まらない箇所で、結果が仕様と合わなくなる。

v0.1.0-rc4 の作業中のコード（a2b6106e）で、次を確かめた。

| 式 | 今の結果 | 正しい値 |
| --- | --- | --- |
| `2.0 ** -1074` | `0` | 2^-1074（最小の非正規化数） |
| `2 ** -1074` | `0` | 同上 |
| `10 ** 309 + 0.5` | G0204 | 倍精度で表せない |
| `10 ** 309 / 10 ** 308` | G0204 | `10` |
| `max(10 ** 309, 10 ** 310)` | 10^309 | 10^310 |
| `max(2 ** 53, 2 ** 53 + 1)` | 2^53 | 2^53 + 1 |
| `max(2 ** 53 + 1, 9007199254740992.0)` と引数を入れ替えた式 | 引数の順で 2^53 + 1 と 2^53 が入れ替わる | どちらも 2^53 + 1 |
| `1.1 ** 10` | `2.593742460100002` | 最も近い倍精度の値は `2.5937424601000023` |

原因は `modules/golem-eval/src/Golem/Eval/Expr.hs` にある。

- **負の指数の `**`**：`binary` の `Pow` は、負の指数 `k` を `1 / powInt (*) 1 a (negate k)` で計算する。`powInt` は二乗の繰り返しを倍精度で行うので、`2.0 ** 1074` の途中で無限大になり、その逆数が 0 になる。0 は有限なので `mkFloat` を通り、誤りにならない。整数の底も `fromInteger a` で倍精度にしてから同じ計算をする。
- **整数と浮動小数点数の比較**：`compareV` と `equal` は、`asDouble` で両方を倍精度にしてから比べる。2^53 を超える整数は丸められ、2^1024 付近より大きい整数は無限大になる。`10 ** 309 > 1.0` が真になるのは、無限大と 1.0 を比べた結果であり、正しく比べたからではない。
- **`min` と `max`**：`lessThan` も `asDouble` を通すので、整数どうしでも倍精度で比べる。等しいと判定した値は、先の引数を残す。
- **整数どうしの `/`**：`Div` は両方を `asDouble` で倍精度にしてから割る。10^309 は無限大になり、無限大どうしの割り算は NaN になる。
- **浮動小数点数の底の `**`**：二乗の繰り返しは掛け算のたびに丸めるので、結果は最も近い倍精度の値とは限らない。言語仕様は「決まった順序の掛け算で計算する」としか定めておらず、決定的ではあるが、どの値になるかは計算の順序に依存する。

`10 ** 309 + 0.5` の G0204 は、仕様の「整数と浮動小数点数の演算では、整数を浮動小数点数に変換する」と「結果が無限大になる演算はエラー」から導ける。
ただし、仕様は変換の丸め方と、変換があふれた場合を書いていない。
メッセージの `結果が NaN か無限大になる演算です` も、原因が整数の変換にあることを伝えない。

この ADR は [golem-eval ADR 0001](0001-expression-language-and-numerics.md) の「数の規則」の、累乗、比較、整数の変換の規則を改める。

## 実装すること

### 整数から浮動小数点数への変換

- 整数を浮動小数点数に変えるときは、最も近い倍精度の値に丸め、等距離なら偶数の側に丸める。GHC の `fromInteger :: Integer -> Double` はこの丸めを行う。
- 変換した値が無限大になる整数（絶対値が 2^1024 - 2^970 以上）は、その演算の位置で G0204 とする。メッセージは `整数が大きすぎて浮動小数点数に変換できません` とする。
- この変換は、整数と浮動小数点数の `+`、`-`、`*`、`/` と、`sqrt`、`round`、`fixed` の引数の整数で行う。

### 整数どうしの `/`

整数どうしの `/` は、商を有理数のまま計算し、最も近い倍精度の値に一度だけ丸める（Haskell の `fromRational`）。
結果が無限大に丸まる場合は、今と同じく G0204 の `結果が NaN か無限大になる演算です` とする。
絶対値が 2^53 以下の整数どうしでは、今の結果と変わらない。

### 累乗

`**` の指数は、今と同じく整数に限る。

- **整数の底、0 以上の指数**：今と同じく整数で計算し、上限は [docs/adr/0035](../../adr/0035-security-hardening.md) の G0286 に従う。
- **整数の底、負の指数**：`1 / a^|k|` を有理数として計算し、最も近い倍精度の値に一度だけ丸める。底が 0 なら、今と同じく G0203 とする。
- **浮動小数点数の底**：底を有理数（`toRational`）にして `a^k` を正確に計算し、最も近い倍精度の値に一度だけ丸める。指数の符号は問わない。底が 0 で指数が負なら G0203 とする。

正確な計算が大きくなりすぎないように、計算の前に結果の大きさを見積もる。
見積もりは、結果の絶対値を、仮数（1 以上 2 未満の倍精度の値）と整数の指数の組で表し、二乗の繰り返しで計算する。
掛け算のたびに仮数を 1 以上 2 未満に戻し、はみ出た分を整数の指数に移すので、途中で無限大や 0 にならない。
倍精度の掛け算だけを使うので、見積もりも決定的である（`log` は使わない）。
掛け算の回数は指数のビットの数の 2 倍以下なので、見積もった log2 の誤りは 1 より十分に小さい。
見積もった結果の絶対値の log2 を `E` とする。

1. `E ≥ 1025` なら、結果は無限大に丸まるので G0204 とする。
2. `E ≤ -1076` なら、結果は 0 に丸まるので、計算せずに 0 とする。
3. ほかは正確に計算する。底を `±m × 2^e`（`m` は正の奇数）としたとき、`(m のビットの数 - 1) × |k|` が 2^20 を超えれば G0286 とし、メッセージは `累乗の計算が大きすぎます` とする。底が 2 の累乗（`m = 1`）なら、指数がいくつでも計算は小さい。この条件に当たるのは、底の絶対値が 1 に近く、指数の絶対値が大きい式（`1.0000001 ** 100000` など）に限られる。
4. 正確な値を丸めた結果が無限大なら G0204 とする。

結果が非正規化数の範囲や 0 に丸まることは、誤りにしない。
十進のリテラルの読み取り（`1e-400` は 0）と同じく、IEEE 754 の丸めの結果として扱う。
負のゼロは、今と同じく正のゼロにする。

### 比較

- `==`、`!=`、`<`、`<=`、`>`、`>=` で整数と浮動小数点数を比べるときは、浮動小数点数を有理数（`toRational`）にして、整数と正確に比べる。浮動小数点数は有限なので、有理数にできる。
- `min` と `max` も同じ規則で比べる。整数どうしは整数のまま比べる。
- 等しい値が複数あるときに先の引数を残す規則は変えない。

### メッセージ

G0204 のメッセージに `整数が大きすぎて浮動小数点数に変換できません` を、G0286 のメッセージに `累乗の計算が大きすぎます` を加える。
コードは増やさない。

### 上限を v2 で広げる余地

2^20 ビットの上限は v0.1.0 の値であり、非常に大きな数や精度の高い計算は v2 以降で扱う。
そのときに上限と数の表し方を広げられるように、次のように作る。

- 上限は `Golem.Eval.Expr` の一つの名前の付いた定数（`maxExactBits`）とし、判定はこの定数だけを見る。上限を変えても、上限の内側の結果は変わらない。結果は「正確な値を一度丸めた値」と定義しており、計算の方法に依存しないためである。
- 累乗は、`(底, 指数) -> 正確な値の丸め` を返す一つの関数に閉じ込め、見積もりと正確な計算を分けておく。v2 で上限を外すときは、正確な計算を、精度を段階的に上げながら丸めが決まるまで計算する方式（Ziv の方式）に置き換えられる。整数の指数の累乗は、有限の精度の区間で包めるので、この方式で丸められる。ただし、結果がちょうど二つの倍精度の値の中間にある場合は精度を上げても丸めが決まらないので、その判定（底の仮数の奇数の部分と指数から決まる）と正確な計算を残す。
- 倍精度に収まらない大きな浮動小数点数を値として持つには、`Value` に新しい数の型を足す必要がある。今の `VFloat` の意味（倍精度）は変えず、型を足す ADR で、演算の規則と本文への表記を決める。この ADR の比較と変換の規則は、型が増えても「正確に比べ、結果の型の値に一度だけ丸める」の形で引き継げる。

## アルゴリズム

累乗の手順を次に示す。
`fromRational` は、有理数を最も近い倍精度の値に丸める（等距離なら偶数の側）。

```haskell
-- 底 a（有理数として正確）、指数 k（0 でない整数）
-- e は、仮数と整数の指数の組で見積もった |a ^^ k| の log2
pow a k
  | e >= 1025                       = G0204
  | e <= -1076                      = 0
  | (bitLength m - 1) * |k| > 2^20  = G0286   -- m は a の仮数の奇数の部分
  | otherwise                       = finiteOrG0204 (fromRational (a ^^ k))
```

## 実装しないこと

- 整数と浮動小数点数の `+`、`-`、`*` を有理数で正確に計算すること。結果は浮動小数点数なので、整数を変換してから IEEE 754 で演算する今の規則を残す。Python も同じく、混ざった演算では整数を変換し、比較だけを正確に行う。
- 浮動小数点数の指数による累乗と超越関数。[golem-eval ADR 0001](0001-expression-language-and-numerics.md) のとおり v2 で扱う。
- 0 に丸まる結果（アンダーフロー）を diagnostic で知らせること。

## テスト設計

先に次のテストを書き、今のコードで失敗することを確かめてから直す。
結果の値は、倍精度のビットの並び（`castDoubleToWord64`）で比べる。

- **負の指数**：`2.0 ** -1074` と `2 ** -1074` が 2^-1074、`2 ** -1075` と `2.0 ** -1075` が 0（等距離なので偶数の側）、`3 ** -2` が `1 / 9` の倍精度の値、`(-2.0) ** -1075` が 0（負のゼロでない）になる。
- **浮動小数点数の底**：`1.1 ** 10` が `2.5937424601000023`、`0.5 ** 1074` が 2^-1074、`2.0 ** 1023` が 2^1023、`2.0 ** 1024` と `(1e200) ** 2` が G0204、`0.1 ** 400` が 0 になる。
- **大きさの見積もり**：`1.5 ** 100000000` が G0204、`0.75 ** -100000000` が G0204、`0.5 ** 100000000` が 0、`1.0000001 ** 100000` が G0286（`累乗の計算が大きすぎます`）になり、どれも 1 秒以内に終わる。`1.0 ** 100000000` は 1、`0.5 ** -1000` は 2^1000 になる（底が 2 の累乗なので正確な計算が小さい）。
- **性質**：任意の倍精度の値 `a`（0 でない）と `|k| ≤ 64` の整数 `k` について、結果が `fromRational (toRational a ^^ k)` と一致するか、それが無限大のとき G0204 になることをプロパティテストする。
- **整数どうしの `/`**：`10 ** 309 / 10 ** 308` が 10、`(2 ** 53 + 1) / 1` が 2^53（等距離なので偶数の側）、`10 ** 400 / 3` が G0204 になる。絶対値が 2^53 以下の整数の組で、今の `/` と結果が一致することをプロパティテストする。
- **変換**：`10 ** 309 + 0.5` と `sqrt(10 ** 309)` が G0204 の `整数が大きすぎて浮動小数点数に変換できません` になる。`(2 ** 54 + 3) + 0.0` が 2^54 + 4 になる。
- **比較**：`10 ** 309 > 1.0`、`2 ** 53 + 1 > 9007199254740992.0`、`2 ** 53 + 1 != 9007199254740992.0` が真、`2 ** 53 == 9007199254740992.0` が真、`10 ** 400 < 1e308` が偽になる。真偽値は本文に埋め込めないので、評価器の単体のテストで確かめる。
- **`min` と `max`**：`max(10 ** 309, 10 ** 310)` が 10^310、`max(2 ** 53, 2 ** 53 + 1)` が 2^53 + 1、`max(2 ** 53 + 1, 9007199254740992.0)` と引数を入れ替えた式がどちらも 2^53 + 1、`min(1, 1.0)` が整数の 1（先の引数）になる。
- **アーキテクチャ間の一致**：上の式を、[golem-eval ADR 0001](0001-expression-language-and-numerics.md) の x86-64 と aarch64 の比較の式の集合に加える。

## トレードオフ

浮動小数点数の底の `**` を一度だけ丸めると、`1.1 ** 10` のように、今の原稿の出力が最後の桁で変わる式がある。
今の値も決定的なので、互換を優先して二乗の繰り返しを残す案もあった。
しかし、二乗の繰り返しのままでは、負の指数で途中の値があふれる問題を、指数の符号で計算の方法を分けずに直せない。
負の指数だけを正確に計算すると、`a ** -k` と `1 / a ** k` が別の値になりうる。
正確な値を一度丸める規則なら、十進のリテラルの読み取りと同じ「最も近い倍精度の値」という一つの言葉で仕様を書ける。
v0.1.0 のリリースの前なので、出力の変化は受け入れる（メンテナーの判断）。

正確な計算の大きさに 2^20 ビットの上限を設けたので、`1.0000001 ** 100000` のように今は値を返す式が G0286 になる。
組版の原稿で、1 に近い数を何万回も掛ける計算は少ないと判断した。
上限は、上の「上限を v2 で広げる余地」のとおり、結果を変えずに v2 で広げられる。

比較だけを正確にし、混ざった演算は変換のままにしたので、`2 ** 53 + 1 > 9007199254740992.0` が真なのに、`(2 ** 53 + 1) - 9007199254740992.0` は 0 になる。
後者は結果が浮動小数点数であり、IEEE 754 の演算として正しい。

## ドキュメント

- `docs/markup.md` の「数の規則」と「式文脈」の節を、この ADR の規則（変換の丸めとあふれ、正確な比較、累乗の一度の丸めと上限、アンダーフロー）に書き換える。今の「整数と浮動小数点数を比べるときは、整数を浮動小数点数に変換する」と「整数の指数による累乗は、決まった順序の掛け算で計算する」は消す。
- `docs/diagnostics.md` の G0204 と G0286 に、メッセージと原因を加える。
- 仕様書の「既知の不具合」から「浮動小数点数の桁あふれ」を、`docs/roadmap.md` の「既知の不具合の修正」から同じ項目を消す。
- 利用者向けマニュアルの式の章と diagnostic の付録を直す。
