# ADR 0002: ファイル内評価（S0）

ステータス: 採択

## 文脈

評価は三つの階層に分かれる（specifications.md）。
ファイル内評価（S0）は、ソースファイルを一つずつ、そのファイルと import 先だけを見て評価し、意味論 IR（[golem-doc ADR 0001](../../golem-doc/adr/0001-semantic-ir-in-cddl.md)）を作る段階である。
章ファイルの独立性（単独での検査、並列のビルド、LSP）は、S0 がファイルの外を見ないことに依拠する。

S0 のうちに決まらない値が二種類ある。
文書構造（S1）の値（`doc` の名前空間、章の番号と題への参照）と、レイアウト後（S2）の値（ページ番号）である。
意味論 IR は評価済みの値だけを持つと決めているが、S1 と S2 の値は S0 の時点では評価できない。
この ADR は、それらを意味論 IR の中でどう表すかも定める。

## 実装すること

### 入力と出力

```haskell
evalFile
  :: EvalContext          -- マニフェスト、style.toml、import 先の評価結果、プラグイン、プロファイル
  -> AST.File
  -> (Doc.Document, FileIndex, [Diagnostic])
```

`FileIndex` は、S1 が集める情報（見出し、ラベル、チャネルへの項目、属性）をファイルの順で並べたものである。

### 変数と import

- `@set` の変数はファイル単位で有効であり、定義は上から順に評価する。定義より前で参照した場合と、同じ名前を二度定義した場合はコンパイルエラーとする。
- `@import path as ns` は、取り込み先のファイルのすべての `@set` の変数を、名前空間 `ns` の下に束縛する。取り込み先の評価結果は golem-project の import のグラフに従って共有する。
- `meta` の名前空間は、マニフェストの `[metadata]` から作る読み取り専用の値である。
- `doc`、`meta`、`true`、`false`、`nil` を `@import` の名前空間や `@set` の名前に使った場合はコンパイルエラーとする。

### 評価を遅らせる値

- `doc` の名前空間を参照する式は、S0 では評価せず、`DeferredExpr` のインラインとして意味論 IR に残す。このとき、式の中の S0 の変数はすべて値に置き換え、式に残る自由な名前は `doc` だけにする。
- `[ref-number ...]` と `[ref-title ...]` は、ラベルを持つ `DeferredRef` のインラインになる。
- ページ番号への参照は、ラベルを持つ `DeferredRef` のインラインになり、S2 で Number に解決される。
- 見出しの中にこれらの値が現れた場合はコンパイルエラーとする。

`DeferredExpr` は意味論 IR の CDDL に加える。
プラグインは `DeferredExpr` を受け取って出力にそのまま含めることはできるが、新しく作ることはできない（[golem-plugin ADR 0001](../../golem-plugin/adr/0001-wasm-host-and-abi.md)）。

### コマンドの解決

コマンドの名前は、上書きを宣言したプラグインのコマンド、組み込みのコマンド、プラグインのコマンドの順に探す。
どれにもない名前はコンパイルエラーとする。

プラグインは、マニフェストで宣言した場合に限り、組み込みのインラインのコマンドを上書きできる（[golem-plugin ADR 0002](../../golem-plugin/adr/0002-distribution-and-lock.md)）。
上書きできるのは、表示だけに関わる次のコマンドである。

- `strong`、`bold`、`italic`、`ruby`、`kenten`、`color`、`style`、`tcy`、`number-text`

ブロックコマンドと、文書構造や注、チャネルに関わるインラインのコマンド（`ref-number`、`ref-title`、`note`、`sidenote`、`index`、`cite`）は上書きできない。
これらは S1 の集約が前提にする情報を作るので、プラグインが置き換えると、番号やチャネルの不変条件を処理系が保証できなくなるためである。

上書きを宣言せずに組み込みのコマンドと同じ名前を提供するプラグインがある場合と、二つのプラグインが同じ名前を提供する場合は、プロジェクトの読み込みの時点でエラーとする。
宣言を必須にするのは、プラグインを追加しただけで既存の原稿の意味が黙って変わるのを防ぐためである。

### 組み込みのインラインのコマンド

| コマンド | 検査と結果 |
|---|---|
| `strong`、`bold`、`italic` | 散文スロットが一つ |
| `ruby` | 散文スロットが二つ。対象と読みの地の文を `/` で分け、セグメントの数が一致しなければエラー。ルビの中のルビはエラー |
| `kenten` | 散文スロットが一つ。`shape` は style.toml の圏点の形の集合に含まれること |
| `color` | 位置引数がスウォッチの名前であり、style.toml に定義されていること |
| `style` | 位置引数が文字スタイルの名前であり、style.toml に定義されていること |
| `tcy` | 散文スロットが一つで、中身が地の文だけであること |
| `number-text` | 位置引数が整数であること。`style` は `kanji`、`kanji-digits`、`tcy` のいずれか。結果は Number |
| `ref-number`、`ref-title` | 位置引数がラベルの名前であること。結果は `DeferredRef` |
| `note` | 散文スロットが一つ。注の番号をファイルの中の出現順で振り、注の印のインラインと、注のチャネルへの項目を作る |
| `sidenote` | 散文スロットが一つ。傍注の番号を、脚注とは別にファイルの中の出現順で振り、傍注の印と本文を持つインラインを作る。縦組みでの使用の検査は、書字方向が決まるレイアウトの段階で行う |
| `index` | `reading` が必須。対象と読みを `/` で分け、階層は二段まで、段の数が一致すること |
| `cite` | 位置引数が書誌データのキーとして存在すること |

### 組み込みのブロックコマンド

| コマンド | 検査と結果 |
|---|---|
| `set`、`import` | 上記のとおり。属性のまとまりの中に置いた場合はエラー |
| `label` | 属性。名前の文字の規則は識別子と同じ |
| `toc-title`、`number`、`nonumber`、`notoc` | 属性。見出しに付けた場合だけ有効（`number` は番号付きリストの項目にも付けられる） |
| `toc`、`index`、`bibliography` | チャネルを出力するブロック |
| `figure` | 画像のファイルが存在すること、`alt` が必須、PDF の画像には `web` が必須、`wrap` は `start` か `end` で、`wrap` を指定した場合は `width` が必須 |
| `table` | `src` の CSV を RFC 4180 に従って読み、表にする。セルは地の文として扱う |
| `listing` | `src` のファイルを UTF-8 として読み、`lines` の範囲をコードブロックにする |

### 属性のまとまり

- まとまりの中のコマンドは、すべて属性でなければならない。属性でないコマンドが含まれる場合はエラーとする。
- まとまりの後ろにブロックがない場合はエラーとする。
- 同じ属性を一つのまとまりに二度書いた場合はエラーとする。

### プラグインとフィルタ

- プラグインのコマンドは、評価済みの引数と散文スロットを渡して golem-plugin で呼び出し、返された断片を検証してから IR に入れる。
- ファイル全体の評価が終わったら、マニフェストでそのファイルに宣言したフィルタを宣言の順に適用する。

### 校正用のコメント

AST の `ProofComment` は、意味論 IR の校正用のコメントのインラインにする。
prod のプロファイルでは、出力には含めず、警告の診断を作る。

## 実装しないこと

- S1 の集約と、`DeferredExpr` と `DeferredRef` の解決。[golem-doc ADR 0002](../../golem-doc/adr/0002-document-assembly.md) で扱う。
- lint の規則（使われていない変数など）。golem-lint の ADR で扱う。
- プラグインの呼び出しの仕組み。[golem-plugin ADR 0001](../../golem-plugin/adr/0001-wasm-host-and-abi.md) で扱う。

## テスト設計

- 組み込みのコマンドごとに、正しい用例と、表に挙げた検査の違反のそれぞれを用意し、結果の IR と診断を golden テストで固定する。
- `doc` を参照する式が `DeferredExpr` になり、式の中の S0 の変数が値に置き換わっていることを確かめる。
- 見出しの中の `doc`、`ref-number`、ページ番号への参照がエラーになることを確かめる。
- 注の番号が、ファイルごとに 1 から振られることを確かめる。
- import 先の変数が名前空間を通して参照でき、名前空間なしでは参照できないことを確かめる。
- 同じファイルを二回評価した結果が一致することを確かめる。

## トレードオフ

`doc` を参照する式を `DeferredExpr` として IR に残すと、意味論 IR が評価前の式を持たないという原則に例外ができる。
例外を `doc` だけを自由な名前に持つ式に限り、プラグインには新しく作らせないことで、原則が守ろうとしていたもの（プラグインによるコードの注入の防止と、評価の階層の保持）は保つ。
