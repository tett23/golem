# golem-color の仕様

`golem-color` は、ファイル形式、描画、ICC プロファイルを扱わない、色成分の純粋な計算モジュールである（[root ADR 0474](../adr/0474-centralize-color-conversions-with-a-fixed-approximation.md)）。
実行時の依存は `base` だけである。
RGB、CMYK、グレースケール、8-bit と 16-bit の符号化成分を別の型とし、0 から 1 の成分と整数成分の範囲外を構築時に拒む。
各変換の途中では成分を丸めない。

## 固定の RGB から CMYK への近似

入力の符号化済み RGB 成分 `r,g,b` は 0 から 1 の有理数とし、`v=max(r,g,b)`、`k=1-v` とする。
`v=0` なら `c=m=y=0`、それ以外は `c=(v-r)/v`、`m=(v-g)/v`、`y=(v-b)/v` とする。
黒は `(0,0,0,1)`、白は `(0,0,0,0)` になる。
この式は [CSS Color 5 §6.1](https://www.w3.org/TR/2026/WD-css-color-5-20261116/#cmyk-rgb) の単純な逆変換で、ガンマを解除せず、RGB の ICC プロファイルを解釈しない。
元の RGB の ICC を、結果の CMYK のプロファイルとして付けない。

8-bit と 16-bit の整数入力には同じ式の整数実装を用いる。
最大値を `M`（255 または 65535）、`V=max(R,G,B)`、`K=M-V` とする。
`V=0` なら `C=Magenta=Y=0`、それ以外は `C=roundEven(M*(V-R)/V)` とし、`Magenta,Y` も対応する入力成分で同じ計算をする。
`roundEven` は最も近い整数、同距離なら偶数を選ぶ。
積は 64-bit の符号なし整数で計算するため、整数実装は有理数の式を最後に偶数丸めした結果に一致する。

CMYK から RGB への近似は、`r=(1-c)*(1-k)`、`g=(1-m)*(1-k)`、`b=(1-y)*(1-k)` とする。
整数成分を出す必要がある呼出側でだけ 8-bit または 16-bit に量子化する。
旧来のスウォッチ百分率を画面表示する API は最後に 8-bit へ偶数丸めし、PDF の Decode 範囲には既存どおり半切り上げを使う。
中性の CMYK（`c=m=y`）の明るさは `(1-c)*(1-k)` である。

透明度はこのモジュールの変換対象に含めず、呼出側が元の値を保つ。
式は印刷条件に応じた色の一致、総インク量の制限、元の CMYK 分版の復元を保証しない。
厳密な色管理が必要なら、Golem の外で変換した CMYK データを入力する。
色指定のない図版は元の色成分と ICC の扱いを保ち、CMYK 出力インテントだけを理由にこの近似を呼ばない。
明示したスウォッチへの図版の色置換は、元図版の濃淡と指定した CMYK を使う既存の処理であり、元 RGB を CMYK に近似しない。

## 既存の成分計算

スウォッチへの濃淡適用、灰色からインク量への換算、色成分の量子化、PDF の Decode 範囲と shading の成分計算、JPEG の YCbCr と YCCK の成分変換もここで計算する。
JPEG の固定小数点の係数と丸めは JuicyPixels 3.3.9 の既存結果に合わせる。
JPEG と PDF の復号、走査、色指定の解決、ICC の付与と保持、CSS や PDF の生成は各呼出側に残す。
