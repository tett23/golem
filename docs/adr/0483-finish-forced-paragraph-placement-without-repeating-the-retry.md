# ADR 0483: 行数を減らせない強制配置を採用し、同じ再試行を繰り返さない

Status: accepted-pending

## 文脈

回り込みを含む段落のページ付けでは、段を移した後の行幅に合わせて残りを改行し直す。
末尾に必要な行数を残せない場合は、現在の段で採用する行数の上限を減らして試し直す。
しかし、空の段で行保持を緩めて配置する経路では、その上限より多くの行を返すことがある。
呼び出し側が同じ状態で再試行を続け、検証時間内に PDF 生成が終わらない入力が見つかった。

root [ADR 0261](0261-keep-options-of-paragraph-styles.md) は、空の段と見出しだけの段で保持条件を満たせなければ、入るだけ置いて `ShortPart` を記録すると定める。
root [ADR 0397](0397-paragraph-line-pitch-and-dimensional-spacing.md) も、この保持の規則と進捗の条件を保つ。
この ADR は、その強制配置を呼び出し側が採用して前進することを定める。
公開の試し置き API の強制配置を、上限に合わせて変更する案は採らない。

## 調査した事項

コミット `0aa78f65ac691cdd8d1a3bd5fc4c8bffb1feabdb` の CLI で、試験用の「あ」49 文字と回り込み図版を含む原稿を検証した。
自由な配置、10 pt、12 字、4 行、15 pt の行送りで、先頭の保持行数は 2 である。
末尾の保持行数だけを 2 から 4 へ変えた。

末尾 2 行の原稿は通常の `build --target pdf --profile dev --format json` が終了コード 0 で終わり、PDF を生成した。
末尾 4 行の原稿は 15 秒で終わらず、検証側で起動した子プロセスだけを終了した。
この観測だけで無限実行を証明したとは扱わない。

`trialParagraphPartLimit` の公開 API では、5 行、3 行分の容量、先頭 2 行と末尾 4 行の保持を指定した場合、上限なし、上限 2、上限 1 のいずれも 3 行を採用した。
空の段では、通常の分割規則が採用行数 0 を返すと、入るだけ強制配置するためである。
この経路は、見出しだけの段にも適用する既存の規則である。

`Flow.hs` の `paragraph.parts` は、残りが末尾の保持行数に足りず、現在の採用行数が先頭の最低行数より多ければ、採用行数から 1 を引いた上限で試し直す。
そのため、上限 2 でも 3 行を返すと、同じ上限 2 での再試行が続く。
独立した Lean の具体例でも、上限なし、2、1 で採用 3 となり、再試行の減少条件が成り立たないことを kernel の検査で確認した。
これは具体例の検査であり、全入力の終了証明の代わりではない。

## 実装すること

`paragraph.parts` は、正の再試行上限を指定した後に、その上限より多い採用数が返った場合、同じ状態で行数を減らす再試行をやめる。
試し置き側が既存の規則に従って返した強制配置を採用し、未処理の原稿を進める。
通常の分割結果では採用数は指定上限以下なので、この判定は強制配置の結果だけを対象にする。

採用する内容、配置済みの状態、緩めた保持設定、`ShortPart` などの未達情報は、試し置きが返したものを保つ。
残りの原稿は既存の段送りと再改行の経路へ渡す。
空の段かどうかを呼び出し側が狭い条件で判定し直し、見出しだけの段を不必要に送ることはしない。

上限以下の結果が返る正常な再試行では、既存の行数を減らす処理を保つ。
`trialParagraphPartLimit` と、上限を指定しない通常のページ付けの決定は変えない。
新しいエラー、原稿の削除、固定回数の打ち切り、時間切れによる製品側の中止は追加しない。

Lean モデルの呼び出し側も同じ規則に合わせる。
上限を無視する試し置きの具体例を消さず、それでも呼び出し側が内容を消費して進むことを検証する。
旧モデルの反例のソースの版と由来を research に残し、同じ入力を修正後の呼び出し側の正常な消費を確かめる回帰試験へ切り替える。
root [ADR 0352](0352-prove-pagination-in-lean.md) の既存の未証明範囲と区別し、この局所修正だけで全ページ付けの終了証明を完成扱いしない。
仕様書、README、開発者向けマニュアルも同時に更新する。

## 実装しないこと

先頭と末尾の保持行数、全行保持、空の段と見出しだけの段で制約を緩める既存の優先順は変えない。
公開 API の上限を絶対的な制約へ変更する案は採らない。
図版の縮小、注の配置、文献の未決事項、CI の時間上限は変えない。

## 不変条件

- I1: 正の上限を超える採用数を返した再試行は、同じ未処理位置と段のまま同じ上限で再び試さない。
- I2: 強制配置を採用する場合、試し置きの行、配置状態、保持設定、未達情報を保つ。
- I3: 消費した元ソースの範囲と未消費の接尾部で全入力を分割し、glue などを描画から除く既存の消費規則を保つ。
- I4: 上限以下の結果を返す既存の再試行と、再試行が不要な入力の配置は変えない。
- I5: 公開の試し置き API は、空の段と見出しだけの段の既存の強制配置を保つ。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 5行、容量3、先頭2行と末尾4行保持、試行上限2で採用3 | 強制配置を採用して原稿を消費 | I1, I2, I3 |
| 同じ公開APIに上限なし、2、1 | 従来どおり、それぞれ採用3 | I5 |
| 見出しだけの段で同じ強制配置 | 見出しを孤立させず、既存の未達情報を保つ | I1, I2, I5 |
| 上限を減らすと採用数も減る | 既存の再試行を維持 | I4 |
| 再試行せず全体が収まる | 修正前と同じ出力 | I4 |
| 空の原稿 | 内容を作らず終了 | I3, I4 |

## 受けいれ条件

A1: 49 文字の通常 CLI の反例で、末尾保持 2 と 4 の両方の PDF 生成が終了する。
検証側だけに短い停止上限を設け、終了コード、diagnostics、PDF の画像、原稿の欠落と重複を確認する。
末尾保持を満たせない場合の注意は、実際に採用した配置と一致させる。

A2: 空の段、見出しだけの段、途中の段、先頭と継続部分、回り込みの有無を含む境界で、既存の試し置きと修正した呼び出し側を照合する。
試し置きの上限超過の具体例は維持し、修正後の再帰が原稿を消費することを Lean で確認する。

A3: 既存のページ付け、図版、脚注、段送り、行保持の試験を通す。
影響がある PDF は前後を視認し、無関係な画像参照や時間上限を変更しない。
root [ADR 0352](0352-prove-pagination-in-lean.md) の残る証明は未完了のまま明記する。

## テスト設計

I1 から I5 の番号を持つ試験を先に書き、通常 CLI の時間切れと、同じ再試行上限を繰り返すモデルの失敗を確認する。
公開 API の 5 行と容量 3 の試験は、修正後も上限なし、2、1 で採用 3 を期待する。
呼び出し側では消費した元ソースの範囲と未消費の接尾部を比較し、glue の消費と見出しだけの段の対照を含める。
通常 CLI の再現は、この作業が起動した子プロセスだけに時間上限を設ける。
Lean の具体例と再帰の減少を検証し、古い無条件の再試行へ戻す変異を拒否する。

## トレードオフ

不可能な行保持を強制的に満たす代わりに、既存の注意を伴って配置を進める。
これは既存の空の段の緩和規則を保つ選択である。
行数を減らす正常な再試行を残し、上限を絶対的な制約に変える範囲の広い修正を避ける。
