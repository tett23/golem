# ADR 0042: 制御文字と glob のメタ文字の扱い

ステータス: 採択

## 文脈

2026-10-18 のセキュリティ監査（[docs/audits/2026-10-18-security-audit.md](../audits/2026-10-18-security-audit.md)）で、原稿のリポジトリの作者が書ける文字列が、そのまま端末、XML、glob に流れる箇所が見つかった。

- C13：diagnostic の人間向けの描画（`renderHuman`）は、パス、メッセージ、ソース行の制御文字をそのまま端末に書く。ESC で始まるエスケープシーケンスで端末の表示を書き換えられ、BEL で音を鳴らせる。JSON の描画はエスケープしている。
- T2：同じ描画は、ソース行の長さを限らずに書く。10 MB の 1 行のファイルでは、diagnostic が 10 MB を標準エラー出力に書く。
- C15：golem-pdf の XMP と golem-html の XHTML、EPUB の OPF と nav の `escapeXml` は、`<`、`>`、`&`、`"` だけを置き換える。XML 1.0 がどこにも許さない C0 制御文字（タブ、改行、復帰を除く）が、`manifest.toml` のタイトル（`\u0001` のエスケープで書ける）や原稿の本文から XML に通り、PDF/X-4 と EPUB の検証で誤りになる。
- C14：LSP は、評価が読んだ表のファイルのパスをそのまま glob にして監視を登録する。`*`、`?`、`{`、`[` を含む名前は、その名前のファイルより多くに一致する。

どれも、読む人の環境でコードが動くものではないので低としたが、端末の種類によっては危険が増す。

直し方は、Golem の開発の方針に従う。
出力が入力と違うものになる場所では、黙って変えずに diagnostic で報告する。
C15 の制御文字は、出力の側で置き換えれば XML は正しくなるが、入力と出力が黙って食い違う。
そこで、読み込みの段階でエラーにする。
一方、C13 と T2 の人間向けの描画は表示だけの問題で、出力のファイルには関わらないので、描画の側で置き換える。
C14 の glob のエスケープも、監視の対象をファイルの名前どおりにするだけで、出力には関わらない。

## 実装すること

### 人間向けの描画の制御文字

- `renderHuman` は、パス、メッセージ、ソース行、関連する位置のメッセージの中の制御文字を、見える形に置き換える。
- 置き換える文字は、U+0000 から U+001F（タブ U+0009 を除く）、U+007F、U+0080 から U+009F である。
- 置き換えの形は `\x` に続く小文字の 16 進数 2 桁とする（ESC は `\x1b`）。JSON の描画と見た目をそろえた形である。
- タブはそのまま書く。改行はソース行には含まれない。メッセージの中の改行は今までどおりである。
- JSON の描画（`renderJson`）は変えない。
- LSP に送る diagnostic も変えない。エディタは文字列として受け取り、自分で描く。
- この置き換えは表示だけのものであり、diagnostic の値も出力のファイルも変えない。

### 長いソース行の省略

- ソース行は、diagnostic の位置の桁を中心に、最大 200 文字を書く。
- 行がそれより長いときは、位置の前を最大 60 文字、後ろを残りの文字数とし、切った端に `…`（U+2026）を置く。
- 省いた文字数は書かない。
- 行の長さは、制御文字を置き換えた後の文字数で数える。

### 出力に書けない文字（G0328、G0289）

XML 1.0 の `Char` に当たらない文字を、**出力に書けない文字**と呼ぶ。
U+0000 から U+001F のうちタブ、改行、復帰以外、U+FFFE、U+FFFF、サロゲートの符号位置である。
U+007F と C1 制御文字（U+0080 から U+009F）は XML が許すので、含めない。
出力に書けない文字は、出力の側で置き換えず、読み込みの段階でエラーにする。

- `manifest.toml` の文字列の値（`title`、`title-reading`、`publisher`、`creators`、`contributors`、`publisher-person` など、`[metadata]` のすべての文字列と、ほかのテーブルの文字列）に出力に書けない文字があれば、新しいエラー G0328 を出す。位置は、その値の TOML の位置である。メッセージは、キーの名前と、文字の符号位置（`U+0001` の形）を述べる。TOML の文字列に生の制御文字は書けないので、これに当たるのは `\u0001` のようなエスケープである。
- 原稿の本文、見出し、表のファイルのセル、取り込んだコード（`@listing`）とテキスト（`@import`）の文字列に出力に書けない文字があれば、新しいエラー G0289 を出す。位置は、その文字を含む文字列の `SrcSpan` である。メッセージは、文字の符号位置を述べる。
- G0289 は評価の段階で出し、golem-doc の IR の文字列を作るときに検査する。ターゲットを問わず、プレーンテキストと PDF でも出す。XML の出力だけで拒むと、ターゲットによって同じ原稿が通ったり止まったりする。メンテナーは、この揺らぎを不要なものとして、すべてのターゲットで誤りにすると決めた。
- 一つの文字列に複数あれば、最初の一つを報告する。文字列ごとに一つ出す。
- G0328 と G0289 は dev と prod の両方でエラーである。LSP も同じく出す。
- `escapeXml` は変えない。読み込みで拒むので、XML に出力に書けない文字が届くことはない。

### LSP の監視の glob

- 表のファイルの監視の glob は、ファイルのパスの `*`、`?`、`[`、`]`、`{`、`}` を、角括弧の 1 文字の集合（`[*]` など）に置き換えて登録する。
- `[` と `]` も同じく `[[]` と `[]]` にする。
- 置き換えは LSP の `Pattern` の glob の文法（`*`、`?`、`**`、`{}`、`[]`）に従う。
- 監視の基準（プロジェクトのルートの `RelativePattern`）は変えない。

### ドキュメント

- `docs/diagnostics.md` に G0328 と G0289 の節を足す。
- 仕様書の diagnostic の節に、人間向けの描画の制御文字の置き換えとソース行の省略を書く。
- 仕様書の `manifest.toml` の節と原稿の文字の節に、出力に書けない文字を書く。
- golem-syntax の仕様書に、置き換える文字の範囲と形を書く。
- golem-project と golem-eval の仕様書に、出力に書けない文字の検査の場所を書く。
- golem-lsp の仕様書に、監視の glob のエスケープを書く。
- 利用者向けマニュアルの diagnostic の付録に、ソース行は 200 文字までであることと、G0328 と G0289 を書く。

## 実装しないこと

- 出力に書けない文字を、出力の側で U+FFFD などに置き換えること。入力と出力が黙って食い違うので、開発の方針に反する。
- U+007F と C1 制御文字を拒むこと。XML 1.0 はこれらを許し、組版にも害がない。
- 人間向けの描画の色づけや、端末の幅に合わせた折り返し。
- JSON の描画と LSP の diagnostic の変更。
- LSP の監視を、ファイルのディレクトリを基準にして名前だけを登録する形に変えること。エスケープで足りる。

## テスト設計

ブランチ `security-audit-rc3-tests` のテストが、修正の前に失敗し、修正の後に通ることを確かめる。
C15 のテストは、`escapeXml` の置き換えではなく読み込みのエラーで通るように、断言を書き換える。

- golem-syntax RenderSpec：ソース行の ESC が `\x1b` になり、ESC そのものが出力にない。パスとメッセージの ESC と BEL も同じ。
- golem-pdf SecuritySpec（C15）：出力に書けない文字を含むタイトルは `manifest.toml` の読み込みで G0328 になるので、XMP のパケットを作る関数には届かない。テストは golem-project に移し、`title = "t\u0001t"` の `manifest.toml` が G0328 になり、位置が `title` の値を指すことを確かめる。
- golem-epub PackageSpec（C15）：同じ理由で golem-project のテストに移す。
- golem-lsp TableWatchSpec（C14）：`a*b?.tsv` という名前の表のファイルが、`a[*]b[?].tsv` の glob で登録される。

これに加えて、次を足す。

- golem-syntax：長さ 1000 の行の桁 500 の diagnostic で、ソース行が 200 文字と両端の `…` になり、桁の文字が含まれる。長さ 100 の行はそのまま書かれる。
- golem-syntax：タブはそのまま、U+007F と U+0085 は置き換えられる。
- golem-project：`creators` の要素の `\u0000`、`publisher` の `￾` が G0328 になり、タブと改行を含むタイトルは通る。
- golem-eval：本文の段落に U+0001 を含む原稿が G0289 になり、位置がその段落の文字列を指す。表のファイルのセルの U+0002、`@listing` のファイルの U+0003 も G0289 になる。タブと改行は通る。
- golem-driver：U+0001 を含む原稿で、`golem build --target text` と `--target pdf` も G0289 で止まる。
- golem-lsp：`[` と `{` を含む名前がエスケープされ、メタ文字のない名前は変わらない。
- `docs/diagnostics.md` の G0328 と G0289 の節は、golem-driver の既存のテストが確かめる。

## トレードオフ

- 人間向けの描画の出力が、制御文字を含む場合と 200 文字を超える行で変わる。diagnostic の出力を比べるテストや道具があれば、更新が要る。制御文字と長い行を含まない出力は変わらない。
- 出力に書けない文字を含む原稿は、プレーンテキストと PDF でも組めなくなる。これらの出力は制御文字を書けるが、ターゲットによって原稿の可否が変わることを避けた。制御文字を本文に置く理由は組版にはなく、失うものは小さい。
- 置き換えではなく拒むので、既存の原稿に制御文字が混ざっていれば、この変更でビルドが止まる。位置を示すので、直す場所はわかる。
- glob のエスケープは LSP の仕様の文法に従うが、エディタの実装によっては `[*]` を解釈しないものがありうる。その場合は監視が外れるだけで、評価の結果は変わらない。
