# ADR 0218: コードブロックの途中で始まるページの `pages.json` に、そのページの最初の行の位置を書く

ステータス: 採択

## 文脈

[ADR 0195](0195-page-start-positions-of-pdf.md) は、`golem build` が PDF の横に `pages.json` を書き、各ページの最初の行が原稿のどこから始まるかを出すと決めた。
目的は、エディタの Aleph が改ページの位置の印を原稿に出すことである。
ADR は「そのページの最初の行が原稿のどのファイルの何行何列から始まるか」と書き、コードブロックを例外にしていない。

実装は、コードブロックの行を例外にした。
仕様書の「ページの始まりの原稿の位置」の節は、「コードブロックの行は、コードブロックの始まりを位置とする」と書く（`docs/specifications.md` の 2894 行）。
2026-11-08 のレビューは、これを [ADR 0195](0195-page-start-positions-of-pdf.md) からの逸脱とした。

### 再現

一段で 5 行の横組みの版面に、1 行の段落と、9 行のコードブロックを置いて組んだ（origin/main の `f366145c` を組んだ `golem`、2026-11-08）。

````
あ。

```
いち
にい
（略、9 行）
```
````

`pages.json` は次のとおりだった。

```json
[{"page":1,"file":"chapters/01.gm","line":0,"character":0},{"page":2,"file":"chapters/01.gm","line":2,"character":0},{"page":3,"file":"chapters/01.gm","line":2,"character":0}]
```

2 ページと 3 ページが、どちらもコードブロックの開始の行（0 から数えて 2 行め）を指す。
3 ページはコードブロックの途中から始まるのに、エディタは二つの改ページの印を同じ行に出すことになる。
`complex-vertical`（[ADR 0175](0175-complex-typesetting-fixture.md)）でも、23 ページが三章の 17 行のコードブロックの開始の行を指す。
段の行の数は 15 なので、このブロックは二つのページにまたがり、23 ページはその途中から始まる可能性が高い（22 ページの中身は確かめていない）。

### 原因

コードブロックの行の箱は、すべて `bcAt` にブロックの始まりを持つ（[`Flow.hs`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-typeset/src/Golem/Typeset/Flow.hs#L2544-L2555)）。
[`pageStarts`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-typeset/src/Golem/Typeset/Flow.hs#L677-L692) は、ページの最初の行の箱から位置を取るので、コードブロックのどの部分で始まるページも、ブロックの始まりになる。

行ごとの位置は、評価の途中まではある。
原稿のコードブロックは、AST の段階で行ごとの範囲（`A.Located lsp t`）を持ち、評価の `codeOf` に渡る（[`File.hs`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-eval/src/Golem/Eval/File.hs#L483-L489)）。
`codeOf` は差分の印と注釈の印を外した後、範囲を捨てる。
意味論 IR の `CodeLine` は範囲を持たない（[`IR.hs`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-doc/src/Golem/Doc/IR.hs#L220-L232)、CDDL の [`code-line`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-doc/schema/golem-doc.cddl#L41)）。
`@listing` の行は、取り込んだファイルの行で、どの行にも `@listing` の範囲が付く（[`File.hs`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-eval/src/Golem/Eval/File.hs#L1886-L1888)）。
原稿の中に行の位置がない。

### ブロックの範囲から行を探す方法の難点

IR を変えずに、ブロックの範囲の原稿のバイト列と行のテキストを照らす方法もある。
段落のテキストの位置は、今もこの方法（[`sourceAt`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-typeset/src/Golem/Typeset/Pages.hs#L22-L48)）で決めている。
ただ、コードブロックの範囲は開始の行を含むので、```` ```haskell ```` の `h` が、`hello` で始まるコードの最初の字に照らされる。
差分の印 `+` で始まる行の本文が `+` で始まれば、印のほうに照らされる。
避けるには、開始の行を飛ばす、差分の印を飛ばす、という評価の規則を golem-typeset にもう一度書くことになる。

## 実装すること

### 位置の規則

ページの最初の行がコードブロックの行であるとき、`pages.json` の位置を次のように決める。

1. その行が、コードブロックの最初の部分（キャプション、ファイル名の行、最初の行を含む部分）にあれば、今のとおりブロックの始まりとする。
2. 2 番め以後の部分の最初の行で、その行のコードの行が原稿の位置を持てば、その部分の最初の行の最初の字の位置とする。折り返した続きの行なら、続きの行の最初の字である。
3. 2 のコードの行が空の行なら、そのコードの行の範囲の始まりとする。
4. 2 のコードの行が原稿の位置を持たなければ（`@listing`、プラグインが返したコード）、ブロックの始まりとする。

字の位置は、今の `character` と同じく UTF-16 のコード単位で数える。
タブは原稿の一字として数える（組むときに空白の 2 字分ごとまで進めることは位置に影響しない）。
行番号、差分の印、折り返しの印、続きの印（`continued`）は原稿にない字で、飛ばす。

### 意味論 IR

`CodeLine` に、行の本文の原稿の範囲を `Maybe SrcSpan` で加える。
範囲は差分の印の後から、注釈の印を外す前の行の終わりまでとする。
`@listing` の行と、Emet の関数が作ったコードの行は `Nothing` とする。
Emet の IR はほかの要素でも範囲を持たないので、Emet の `CodeLine` の型は変えない。

CDDL の `code-line` の最後に `span: span / null` を加える。
プラグインとの ABI のバージョンは、まだどのリリースにも含まれていない 8 のままとする（[docs/adr/0052](0052-plugin-abi-version-bump-rule.md)）。
`golem-plugin-sdk` は、コードブロックを `BlockBody::Other` として CBOR のまま通す（[`ir.rs`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/plugins/golem-plugin-sdk/src/ir.rs#L142-L144)）ので、型は変わらない。
コードブロックを自分で組み立てるプラグインは、要素を一つ足す必要がある。
5 つの要素の `code-line` は、ほかのスキーマの誤りと同じく、プラグインの出力なら G06009 とする。

### golem-typeset

コードの行の箱の `bcAt` に、その行（折り返した続きなら続き）の最初の字の、原稿のバイトの位置を入れる。
位置は、`CodeLine` の範囲とテキストを `sourceAt` で照らして決める。
範囲は差分の印の後から始まるので、開始の行や印に照らされることはない。
`pageStarts` は、ページの最初の行が `SCode` の 2 番め以後の部分なら、その行の箱の `bcAt` を使う。
最初の部分なら、今のとおりブロックの始まりを使う。
行分割、字形の選択、描画、構造の木は `bcAt` を読まないので、PDF は変わらない。

### 文書

- 仕様書の「ページの始まりの原稿の位置」の節：「コードブロックの行は、コードブロックの始まりを位置とする」を、上の 1 から 4 に改める。
- 仕様書の「意味論 IR」の節と開発者のマニュアルの IR の章（`manual-dev/part1/06-ir.gm`）：`CodeLine` の範囲。
- [ADR 0195](0195-page-start-positions-of-pdf.md) のステータスの行に、コードブロックの途中で始まるページの位置はこの ADR、と足す。

## 実装しないこと

- **`@listing` の行を取り込んだファイルの位置で示すこと**：`pages.json` の `file` は本の原稿（`.gm`）のパスで、エディタが開くのも原稿である（「メンテナーが決めること」の 4）。
- **ページの中の各行の位置**：[ADR 0195](0195-page-start-positions-of-pdf.md) が実装しないとしたとおりである。
- **G07030 などの位置**：折り返したコードの行の notice の位置は、今のとおりブロックの範囲とする。行の範囲を使えば細かくできるが、この ADR の目的の外である。
- **HTML、EPUB、プレーンテキスト**：`CodeLine` の範囲を読まない。出力は変わらない。

## 不変条件

ページ p の最初の行が、原稿の ```` ``` ```` のコードブロック B の行であるとする。
B のコードの行を 0 から数え、i 番めの行の原稿の範囲を R(i) とする。

- **C1**：p の最初の行が B の 2 番め以後の部分の最初の行で、それがコードの行 i の最初の折り返しなら、p の位置は R(i) の中で、テキストの最初の字のバイトの位置である。
- **C2**：その行がコードの行 i の k 番め（k ≥ 1）の折り返しの続きなら、p の位置は、テキストの中でその続きの最初の字の、R(i) の中のバイトの位置である。
- **C3**：コードの行 i が空なら、p の位置は R(i) の始まりである。
- **C4**：p の最初の行が B の最初の部分にあるなら、p の位置は B の始まりである。
- **C5**：`@listing` とプラグインと Emet のコードブロックでは、どの部分で始まるページの位置も、ブロックの始まりである。
- **C6**：一つのコードブロックの中で始まるページの位置は、ページの順に狭義に増える（同じ位置を二つのページが指さない）。
- **C7**：PDF のバイト列は、この ADR の前と同じである。`pages.json` は、C1 から C3 に当たるページのオブジェクトだけが変わる。
- **C8**：同じ入力からは、`optParallel` の有無によらず、同じ `pages.json` を書く。

境界の入力：

| 量 | 調べる値 |
| --- | --- |
| ページが始まる部分 | 最初の部分、2 番めの部分、最後の部分 |
| 部分の最初の行 | コードの行の最初、折り返しの続き（1 番め、2 番め）、空の行 |
| 行の始めの字 | ASCII、BMP の外の字（UTF-16 で 2 単位）、タブ、```` ` ````、開始の行の言語の名前の最初の字と同じ字 |
| 差分の印 | なし、`+` の後の本文が `+` で始まる行、`-` の行（番号なし） |
| 注釈の印 | なし、行末に `<1>` |
| ブロックの置き場所 | 文書の最上位、リストの項目の中（字下げのある行）、`@style` の本体 |
| ブロックの種類 | ```` ``` ````、`@listing`、プラグインが返したコード、Emet の関数が作ったコード |
| キャプションとファイル名 | なし、`@caption`、`file=` |
| 段 | 一段、二段（2 段めがコードの途中で始まる） |
| 組みの向き | 横組み、縦組み |

## テスト設計

テストは実装の前に書き、今の実装で C1 から C3 と C6 が失敗することを確かめる。

- **golem-eval**：```` ``` ```` のコードの行の範囲が、差分の印の後から行の終わりまでであること。リストの項目の中の字下げした行でも同じであること。`@listing` の行は `Nothing` であること。
- **golem-doc**：範囲を持つ `CodeLine` と `Nothing` の `CodeLine` が CBOR で往復し、CDDL の検査を通ること。5 つの要素の `code-line` を、プラグインの出力として G06009 にすること。
- **golem-driver の `PageStartsSpec`**：境界の入力の表の組で、`pages.json` の位置を、原稿の中で一度だけ現れる字から求めた位置（今の `expected` と同じ作り方）と比べ、C1 から C6 を確かめる。「文脈」の再現の入力では、3 ページが三つめの部分の最初のコードの行を指すこと。
- **C7**：今の PDF のゴールデン（`OutputGoldenSpec`）と、`scripts/visual/pages/` の参照が変わらないこと。`complex-vertical` と `complex-horizontal` の `pages.json` の変わったページが、コードブロックの途中で始まるページだけであること。
- **C8**：`PageStartsSpec` の今の並列と逐次の比較に、コードブロックをまたぐ入力を足す。

## トレードオフ

- IR の `CodeLine` に範囲を一つ足すので、CDDL、CBOR の読み書き、コードブロックを組み立てるプラグインが変わる。ABI 8 はまだリリースしていないので、ABI のバージョンは上げずに済む。
- 範囲は `pages.json` のためだけに IR を通る。ただ、インラインのテキストはすでに範囲を持つので、コードの行だけが範囲を持たない今の形のほうが例外である。
- 最初の部分ではブロックの始まりを指し、後の部分では行の位置を指すので、規則が二つになる。最初の部分には、コードの行より前にキャプションとファイル名の行が組まれ、ファイル名の行は原稿の行の位置を持たない。

## メンテナーが決めること

1. **後の部分で始まるページの位置**：推奨は、その部分の最初の行の最初の字の位置である。[ADR 0195](0195-page-start-positions-of-pdf.md) の文のとおりで、二つのページが同じ位置を指さなくなる。
   - 退けた案の一つは、今のブロックの始まりのまま、仕様書の例外を記録として認めることである。長いコードブロックでは、何ページ分もの改ページの印が開始の行に重なり、Aleph が印を出す目的に合わない。
   - 二つめは、コードの行の原稿の行の始め（`character` を 0）とすることである。折り返した続きで始まるページが、その前のページと同じ位置になる。
2. **行の位置の出どころ**：推奨は、評価がすでに持つ行の範囲を IR の `CodeLine` に残すことである。位置を知っている段階が位置を渡す。
   - 退けた案は、IR を変えず、golem-typeset でブロックの範囲と行のテキストを照らすことである。開始の行と差分の印を飛ばす評価の規則を、golem-typeset にもう一度書くことになる（「文脈」）。
3. **最初の部分**：推奨は、今のとおりブロックの始まりとすることである。キャプションとファイル名の行はコードの行より前に組まれ、原稿でも開始の行（```` ``` ````）がコードの行より前にある。
   - 退けた案は、最初の部分でも最初のコードの行を指すことである。そのページに組まれたキャプションより後ろの原稿を指すことになる。
4. **`@listing` の行**：推奨は、今のとおりブロックの始まりとすることである。
   - 退けた案は、取り込んだファイルのパスと行を `file` と `line` に書くことである。`file` に原稿でないファイルが混じり、エディタの改ページの印を出す先が本の原稿でなくなる。
5. **プラグインの古い形の `code-line`**：推奨は、5 つの要素の `code-line` をほかのスキーマの誤りと同じく G06009 とすることである。ABI 8 はまだリリースしていないので、古い形で作られた配布済みのプラグインはない。
   - 退けた案は、5 つの要素の形も読み、範囲を `null` とみなすことである。スキーマに二つの形を残すことになり、ABI の版で互換を判定するという決め方（[docs/adr/0052](0052-plugin-abi-version-bump-rule.md)）に合わない。

## 決めたことの記録

- **「メンテナーが決めること」のすべて**（2026-11-08、メンテナー）：どれも推奨のとおりとした。
