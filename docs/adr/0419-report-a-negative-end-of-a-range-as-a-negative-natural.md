# ADR 0419: 語と文字列で書いた範囲の負の端を、自然数の箇所の負の数（G02103）にする

Status: accepted-pending

## 文脈

[ADR 0342](0342-revise-retire-dash-line-ranges.md) は、行の範囲（`@listing` の `lines` と `highlight` など）の端に負の数を書いたものを、エラーにすると決めた。
コードは決めていない。

今は、同じ「自然数を求める箇所に負の数を書いた」誤りが、書き方によって二つのコードに分かれている。
式で書いた負の端は G02103（自然数を求める箇所に負の数）になる。
語や文字列で書いた負の端は G02110（範囲の端に数を書いていない）になり、メッセージは「範囲の端には数を書きます」である。
数を書いた入力に「数を書きます」と出るので、メッセージも原因と合わない。

tett23 は 2026-11-18 に、単独の負の値は型の誤りとし、型の誤りのコードがあればそれを使うと決めた。
自然数の型の誤りのコードとして、G02103 がすでにある（[ADR 0102](0102-natural-number-type.md)）。

## 調査した事項

`origin/main`（`2ac7fb273`）で確かめた。

- 範囲の項目を読む [`rangeItem`](https://github.com/tett23/golem/blob/2ac7fb273d6e26d3b42d57eef76f8f1ddd0634e2/modules/golem-eval/src/Golem/Eval/File.hs#L3218-L3233) は、先頭が `-` の項目と、`...` の後が `-` で始まる項目を `ItemBadEnd` にする。
  `ItemBadEnd` は [`rangeEndDiagnostic`](https://github.com/tett23/golem/blob/2ac7fb273d6e26d3b42d57eef76f8f1ddd0634e2/modules/golem-eval/src/Golem/Eval/Expr.hs#L176-L178) で G02110 になる。
  `ItemBadEnd` は、数でない端（`a...3`）と、端のない範囲にも使われる。
- 式の値の負の数は、[`naturalDiagnostic`](https://github.com/tett23/golem/blob/2ac7fb273d6e26d3b42d57eef76f8f1ddd0634e2/modules/golem-eval/src/Golem/Eval/Expr.hs#L201-L208) で G02103 になる。
  メッセージは「…には 0 以上の整数を書きます（書かれた値は …）」である。
- テストは、`lines=3--1`、`lines=-1`、`lines="1...-2"`、`lines="1, -2"`、`lines=3...-1` を G02110 と確かめ、`lines=[= 3...0 - 1]` を G02103 と確かめている（golem-eval の `RangeSpec.hs`）。
- `docs/diagnostics.md` の G02103 の項は、「語で書いても式で書いても同じコード」と書き、`lines` と `highlight` だけを G02110 の例外としている。
- 0 は、`lines` では G02037、`highlight` では G02069 になる（[docs/specifications.md](../specifications.md) の 5265 行と 5266 行）。

## 実装すること

- 語と文字列で書いた範囲の端が負の整数のとき、G02103 にする。
  対象は、単独の負の値（`lines=-1`）、範囲の負の端（`3...-1`、`"1...-2"`、`3--1`）、並びの中の負の値（`"1, -2"`）のすべてである。
  `3--1` は、[ADR 0342](0342-revise-retire-dash-line-ranges.md) の表で「負の端の構文エラー」とした入力であり、負の端として扱う。
- メッセージは、式で書いたときと同じく「…には 0 以上の整数を書きます（書かれた値は …）」とする。
  位置は、今の G02110 と同じく引数（式が返した文字列では、その式）とする。
  `docs/diagnostics.md` の G02103 の位置の決まりに、行の範囲の端では引数とすることを足す。
- 一つの項目には diagnostic を一つだけ出す。
  項目の始めの端から読み、最初に見つけた誤りのコードを出す。
  負の小数（`-1.5`）は、負の数として G02103 にする（式で書いたときと同じ）。
  `-0` は 0 として、今の 0 の扱い（G02037、G02069）にする。
  `-a` のように `-` の後が数でない項目は、G02110 のままとする。
- G02110 は、数でない端と、端のない範囲だけに使う。
- `docs/diagnostics.md` の G02103 の項から `lines` と `highlight` の例外を消し、G02110 の項から負の端を消す。
- 仕様書の行の範囲の節を直す。
- 採択したら、[ADR 0342](0342-revise-retire-dash-line-ranges.md) のステータスの行に、部分「負の端のコード」をこの ADR による補足として足す。

## 実装しないこと

- 0 の扱い（G02037、G02069）は変えない。
- 小数の端（G02104）は変えない。
- 範囲を使うほかのコマンドの範囲の読み方は変えない。

## 不変条件

- I1：行の範囲の項目の始めの端か、始めの端が正しい項目の終わりの端に負の数を書いたどの入力でも、その項目の diagnostic は G02103 をちょうど一つだけ含む。
- I2：語、文字列、式のどれで書いても、同じ負の整数の端の diagnostic のコードとメッセージは等しい。
- I3：負の数の端を持たない項目の、数でない端と、端のない範囲の diagnostic は、この ADR の前と同じ G02110 である。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| `lines=-1` | G02103 | I1 |
| `lines=3...-1` | G02103 | I1, I2 |
| `lines=3--1` | G02103 | I1 |
| `lines="1...-2"` | G02103 | I1 |
| `lines="1, -2"` | G02103 | I1 |
| `lines=[= 3...0 - 1]` | G02103（前と同じ） | I2 |
| `lines=a...3` | G02110 | I3 |
| `lines=3...` | G02110 | I3 |
| `lines=-1.5` | G02103 | I1 |
| `lines=-0` | G02037 | I3 |
| `lines=-a` | G02110 | I3 |
| `lines=-1...a` | G02103 だけ | I1 |
| `lines=-1...-2` | G02103 が一つ | I1 |
| `highlight=-1` | G02103 | I1, I2 |
| `lines=0` | G02037（前と同じ） | I3 |

## 受けいれ条件

なし。
この ADR の振る舞いは、不変条件のテストで確かめる。

## テスト設計

- golem-eval の `RangeSpec.hs` に、境界の表の行ごとのテストを置く。
  名前は `root ADR 0419 I<番号>: ...` とする。
- I2 は、`lines` と `highlight` の両方で、-1 から -3 の負の整数を、語、文字列、式で書いた入力のコードとメッセージを比べる。
- G02110 を期待する今のテストのうち、負の端のものは G02103 に書き換える。
- テストは、実装の前に失敗することを確かめてから実装する。

## トレードオフ

負の端を書いた原稿の diagnostic のコードが G02110 から G02103 に変わる。
どちらもエラーで、`silence-notices` では抑えられないので、コードを指す設定の移行は要らない。
