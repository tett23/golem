# ADR 0336: 原稿の変数を set 名前 = 式 で宣言する

ステータス: 採択

## 文脈

現在の原稿でファイル内の変数を宣言するには、行頭に `@set x = "abc"` と書く。
参照はすでに `[= x]` と書ける。
この `@` はブロック指令の開始記号であり、変数名の一部ではない。
現行 CLI では、宣言と参照の間に空行を入れた原稿が成功し、参照を `[= @x]` にすると G01020 になった。
`@x` だけの行は未知のブロック指令として G02009 になり、段落中の `前置 @x` は本文として通った。

## 実装すること

変数に付く `@` を外す対象は、原稿の変数の宣言とする。
次の例の一行目を変数の宣言として読む。

```text
set x = "abc"

[= x]
```

通常の原稿で行の先頭にある `set`、水平空白、既存の変数名、水平空白、単独の `=`、水平空白または行末の並びを宣言の開始として認識する。
右辺は従来と同じ式として読み、空なら構文エラーにする。
コードブロックの内容はそのまま扱う。
見出しや段落の途中から宣言を始めない。
既存の名前の有効範囲、予約名、ファイル間の取り込み、エラーの位置は現行の原稿の規則に従う。

導入時は旧宣言も同じ値を定義する。
旧宣言の先頭の記号に移行用の notice を出し、一字を消す修正を提示する。
旧宣言をエラーにする時期は互換性の手順に従い、別に決める。

## 実装しないこと

`@import` などほかのブロック指令、Emet の構文、原稿の `[vars]` の参照方法は変更対象から外す。
スタイルの値の名前は [Golem ADR 0320](0320-named-layout-values.md) で決める。

## 不変条件

1. 新旧の宣言に同じ名前と右辺を与えると、後続の式が同じ値を返す。
2. 新しい形の先頭に一致しない本文、またはコードブロックに書いた例は変数を定義しない。
3. 旧宣言の先頭一字を消すと移行の notice が消え、予約名と右辺のエラーは残る。

| 入力 | 結果 |
| --- | --- |
| 空行、`set up is easy`、`set x == 3` | 宣言を作らない |
| `set x =` | 右辺の構文エラー |
| `set x = "abc"` の後の `[= x]` | 本文に abc を出す |
| コードブロックの `set x = 3` | そのまま掲載する |
| `[= @x]` | G01020 |

## テスト設計

[現行 CLI の比較](../../experiments/syntax/review/current.jsonl) では、新宣言を現行 CLI に直接渡すと参照が G02002 になった。
[一行用の試作](../../experiments/syntax/review/review.mjs) が新宣言の先頭を変換した同じ原稿は終了 0 になった。
既存の PEG 文法にも新宣言を追加してパーサーを生成し、[変更後の 9 件](../../experiments/syntax/review/declaration-green.log) で AST を比較した。
新旧の宣言はともに SetVar になり、コードブロックの例は CodeBlock、本文は Paragraph のままだった。
正確なソース位置、全種類の変数名、旧宣言の notice と編集、フォーマッターと LSP は採択後に検査する。

## トレードオフ

旧版で行頭に `set x = 3` と書いた本文は、更新後は宣言として読まれる。
この形を例示する原稿ではコードブロックを使える。
新旧の宣言を併用できる期間には、ファイル単位で順に移せる。
