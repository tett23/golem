# ADR 0327: 入稿しない原稿のプリフライト設定と雛形を用意する

ステータス: 採択（未実装）

## 文脈

会議資料などを画面で読むときには、断裁位置の外に塗り足しを付ける必要がない。
現行の `golem preflight` は設定がなければ印刷向けの print を使う。
塗り足しと出力インテントを書かない試作の原稿では、print は G09010 と G09014、basic は G09014、none はエラーなしだった。
none を選ぶと書体にない字や行のはみ出しまで検査しなくなる。

## 実装すること

`preflight.toml` の `based-on = "screen"` で、入稿しない原稿に適した検査を選べるようにする。
screen は現行の basic の設定から PDF/X-4 の検査だけを外す。
したがって塗り足し不足（G09010）、断裁線に近い図版（G09011）、安全域外の文字（G09012）、PDF/X-4 の要件（G09014）が既定で検査対象から外れる。
basic が調べる欠けた字、行のはみ出し、フォントの埋め込みは引き続き調べる。
検査ごとの明示的な設定は、他の組み込み設定と同じように既定値を上書きする。

`golem new DIR --screen` は、日本語と英語のどちらでも、塗り足しを省いた `style.toml` と `based-on = "screen"` を書いた `preflight.toml` を作る。
既存の原稿には `preflight.toml` の一行で同じ設定を選べる。
用途をマニフェストとスタイルにも重ねて書く必要はない。

## 実装しないこと

画面用の原稿でも `--marks japanese` を明示して塗り足しがなければ、指定どおりのトンボを描けないので G07002 を出す。
この設定は検査の選択であり、書き手が指定した版面や明示したトンボは変更しない。

## 不変条件

1. S1：screen で各検査を上書きしなければ、塗り足しがなくても G09010、G09011、G09012 は出ない。
2. S2：`new --screen` は対応する各言語で塗り足しを省き、同じ screen を設定する。
3. S3：screen で塗り足し不足の検査を再び error にした場合、設定した最小値を下回れば G09010 が出る。
4. S4：PDF が対象で版面の設定まで読めた場合は、どの組み込み設定でも、日本式のトンボを明示して塗り足しが 0 なら G07002 になる。

| 設定 | 塗り足し | トンボ | 結果 |
| --- | --- | --- | --- |
| print の既定 | なし | なし | G09010 |
| screen の既定 | なし | なし | G09010 なし |
| screen で最小 3 mm を error に変更 | 2 mm | なし | G09010 |
| screen の既定 | なし | 日本式 | G07002 |

## テスト設計

試作は実際の `preflight` と `new --language ja|en --no-fonts --screen` を呼ぶ。
`experiments/diagnostics/expected.mjs` の S1 と S2 で、diagnostic、生成したスタイル、設定ファイルを照合する。
S3 は塗り足しを省いた原稿で、検査を明示的に error に戻して G09010 を得た。
本実装では断裁線に接する図版と安全域外の文字を含む原稿を作って G09011 と G09012 の有無を検証する。
トンボの検査には `--marks japanese` を付ける。

## トレードオフ

既存の basic を変えると入稿用に使っている原稿の検査内容まで変わる。
screen を一つ足せば、既存の設定を保ったまま原稿ごとに用途を選べる。
`golem new` のオプションは一つ増えるが、生成後の用途は通常の設定ファイルを編集するだけで変更できる。
