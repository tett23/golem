# ADR 0130: 総ルビのプラグイン

ステータス: 採択

## 文脈

児童書や学習書には、本文のすべての漢字にルビを振る**総ルビ**の本がある。
原稿の全ての漢字に手でルビを書くのは現実的でないので、組版の側で振りたい。
ロードマップの v0.1.0-rc4 は、総ルビを見本のプラグインとして作り、読みの決め方、配布の形、Golem の本体に要る変更を ADR で決めるとしている（[docs/roadmap.md](../roadmap.md)）。

総ルビの難しさは、読みを決めることにある。
「一本」は「いっぽん」、「今日」は文脈で「きょう」とも「こんにち」とも読む。
読みをプログラムで決めるには、文を語に分け、語ごとに辞書の読みを引く形態素解析が要る。
形態素解析には数十 MB の辞書が要り、プラグインの実行量とメモリには上限がある（[golem-plugin ADR 0001](../golem-plugin/adr/0001-wasm-host-and-abi.md)）。
この ADR は、形態素解析器を実際に wasm にして Golem の上限の下で動かし、その結果から読みの決め方を選ぶ。

### 読みの決め方の候補

候補は三つである。

1. **形態素解析器と辞書を wasm に埋め込む**：配布物一つで動く。
2. **形態素解析器だけを wasm にし、辞書をデータで渡す**（[docs/adr/0105](0105-plugin-data.md)）：辞書を本ごとに選べる。
3. **利用者の TSV だけを使う**：形態素解析をしない。読みのない漢字は残る。

形態素解析器には、Rust で書かれ、`wasm32-unknown-unknown` に作れるものとして Lindera を選んだ。
Lindera は、IPADIC を組み込む機能（`embed-ipadic`）と、辞書をバイト列から読む関数の両方を持つので、上の 1 と 2 を同じ解析器で比べられる。
Vibrato も Rust で書かれているが、この試しでは Lindera だけを試した。

### 試しに実装して分かったこと

この ADR は、採択の前に実装を試した（ブランチ `plugins-ruby`）。
Lindera 6.2.0 と IPADIC で、1 と 2 の両方の形のプラグインを作り、高野聖の fixture（一章、約 160 KB、本文に原稿のルビを含む）を `golem build` で組んだ。
時間は macOS arm64 の手元で `/usr/bin/time` で測った一回の値であり、比べる目安にとどまる。

**作れたこと**：Lindera は `wasm32-unknown-unknown` に、std ごと import のないモジュールとして作れた。
ホストは import を持つモジュールを拒む（G06005）が、どちらの形も読み込めた。
1 と 2 の出力のバイト列は一致し、同じ入力を二度組んだ PDF も一致した。

**大きさ**は次のとおりだった。

| 形 | wasm | 辞書のデータ |
| --- | --- | --- |
| 1. 埋め込み | 48077266 バイト | なし |
| 2. データ | 355923 バイト | 9 ファイル、合計 47524848 バイト（最大は `dict.words` の 32674733 バイト） |

2 の辞書は [docs/adr/0105](0105-plugin-data.md) の上限（64 MiB）に収まった。

**速度とメモリ**は次のとおりだった（プレーンテキストだけを組んだとき）。

| 本 | 時間 | ピークのメモリ |
| --- | --- | --- |
| プラグインなし | 0.30 秒 | 189 MB |
| 1. 埋め込み、高野聖 | 2.79 秒 | 471 MB |
| 1. 埋め込み、一行の章 | 2.44 秒 | 334 MB |
| 1. 埋め込み、一行の章を十 | 2.33 秒 | 333 MB |
| 2. データ、高野聖 | 1.02 秒 | 459 MB |
| 2. データ、一行の章を十 | 0.79 秒 | 382 MB |

1 では、一行の章でも 2 秒余りかかった。
章を十にしても変わらないので、この時間は呼び出しごとではなく、48 MB のモジュールの読み込みにかかっている。
Golem は評価のたびにプラグインを読み込み直し（[`evaluateProject` の読み込み](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/modules/golem-driver/src/Golem/Driver.hs#L216-L221)）、LSP も評価のたびにこの経路を通る。
埋め込みの形では、LSP で原稿を一文字直すたびに 2 秒の待ちが加わることになる。

2 では、呼び出しのたびに 47 MB のデータを要求に写すが、十の章でも 0.79 秒だった。
四つのターゲットを組むと、プラグインなしの 1.85 秒（304 MB）に対して、2 は 2.74 秒（454 MB）だった。

**実行量の上限**：高野聖（約 160 KB）は上限の内に収まった。
高野聖を二つつないだ章（約 325 KB）と四つつないだ章（約 650 KB）は、1 と 2 のどちらでも、命令の数の上限（10 億、[`defaultFuel`](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/modules/golem-plugin/src/Golem/Plugin.hs#L77-L78)）を超えて G06009 になった。
上限は呼び出しごとに一定で、ファイルの大きさによらない。
コマンドの呼び出しには十分な量でも、ファイル全体を辿るフィルタには、長い章で足りない。
この問題は草稿の [docs/adr/0124](0124-filter-fuel-by-document-size.md) で扱った。
フィルタの上限を文書の大きさに比例させる試しの実装で、二つの章とも上限に収まった。

その草稿のために、使った命令の数を測った。
2 の形は、文書によらず約 2.3 億を使う。
要求の 47.5 MB の辞書を読み、Lindera の構造を作る分である。
残りは文書の CBOR の 1 バイトあたり、英文の章で約 160 から、和文の章で約 3400 までだった。
高野聖は約 7.6 億、四つつないだ章は約 24 億だった。

**読みの質**：IPADIC の読みは、語ごとの辞書の読みであり、文脈による音の変化を扱わない。
高野聖では、「一本」が「一（いち）本（ほん）」、「覚しい」が「覚（さま）しい」、「一人我」が「一（いち）人我（じんが）」になった。
読みを割り当てられなかった漢字は 12 組で、プラグインが警告した（「危」「漬」「泣出」「押」など）。
形態素解析で振った総ルビは、校正を前提にする必要がある。

**ライセンス**は次のとおりである。

- Lindera 6.2.0 は MIT である。2 のプラグインが依存するクレート（手続きマクロと、このリポジトリのクレートを含めて 88 個）は、どれも MIT、Apache-2.0、BSD-3-Clause、Unicode-3.0、Zlib、BSL-1.0、Unlicense のいずれか（またはその選択）である。
- IPADIC（mecab-ipadic 2.7.0）は、NAIST（Nara Institute of Science and Technology）の著作物であり、項目の多くは ICOT Free Software に由来する。
  ICOT の条件は、元の形でも変更した形でも自由に配布してよいとし、そのときは「NO WARRANTY」の節を必ず添えることを求めている。
  Lindera の `lindera-ipadic` は、この条件を `NOTICE.txt` に収めている。
- `lindera-ipadic` が組み込むのは、Lindera のサイトに置かれた `mecab-ipadic-2.7.0-20250920.tar.gz` であり、ビルドのときに取得し、MD5 で確かめる。元の配布物（`mecab-ipadic-2.7.0-20070801`）から何を変えたかは、確かめていない。
- UniDic（unidic-cwj、unidic-csj の 3.1.0）は、GPL v2.0、LGPL v2.1、BSD（New）の三つから選べるライセンスである。UniDic を Lindera の形式にして動かすことは、試していない。

**ABI の欠け**はなかった。
フィルタの要求と応答、データの受け渡しは、[docs/adr/0105](0105-plugin-data.md) のとおりに動いた。
Lindera の辞書は九つのファイルからなるので、データの名前が九つになった。

## 実装すること

### 読みの決め方

読みは、二段で決める。

1. 利用者の TSV（データ `words`）の語を、最も長いものから左に照合する。一致した語は、TSV の読みでルビを振る。
2. TSV の語に一致しなかった部分に漢字があれば、形態素解析器（Lindera）で語に分け、辞書の読み（欄 `reading`）を引く。

利用者の TSV を先にするのは、形態素解析の誤り（上の「読みの質」）を本ごとに直せるようにするためである。
TSV の形式は [docs/adr/0131](0131-first-occurrence-ruby-plugin.md) と同じである（`/` によるモノルビ、部分ルビ、読みを空にした止めの語）。

### 辞書はデータで渡す

辞書は wasm に埋め込まず、データで渡す（上の候補の 2）。

```toml
[plugins.sou-ruby]
url = "https://github.com/tett23/golem/releases/download/v0.1.0-rc4/sou-ruby.wasm"
data = { words = "data/readings.tsv", dict-char-def = "dict/char_def.bin", dict-matrix = "dict/matrix.mtx", dict-metadata = "dict/metadata.json", dict-trie = "dict/dict.trie", dict-unk = "dict/unk.bin", dict-vals = "dict/dict.vals", dict-vals-idx = "dict/dict.valsidx", dict-words = "dict/dict.words", dict-words-idx = "dict/dict.wordsidx" }

[[filters]]
plugin = "sou-ruby"
filter = "sou-ruby"
files = ["chapters/01.gm"]
```

- `dict-*` の九つは、Lindera の辞書の九つのファイルである。
- 九つのどれも渡さなければ、形態素解析をせず、TSV だけで振る（候補の 3）。
- 九つのうち一部だけを渡すと、エラー `sou-ruby-dict`（`辞書のファイルが足りません: <名前>、…`）とする。
- Lindera が読めないファイル、版の合わないファイルは、エラー `sou-ruby-dict`（`辞書のファイルを読めません: <名前>: <Lindera の理由>`）とする。
- 欄 `reading` のない辞書は、エラー `sou-ruby-dict`（`辞書に読み（reading）の欄がありません`）とする。
- TSV も辞書もなければ、エラー `sou-ruby-no-words` とする。

埋め込みを採らない理由は三つある。

- **LSP の速度**：48 MB のモジュールは、読み込むたびに約 2 秒かかり、評価のたびに読み込む今の作りでは LSP が使えない。
- **コミットと配布**：48 MB の wasm は、[docs/adr/0106](0106-sample-plugins-in-rust.md) の「`.wasm` をコミットする」に合わない。355923 バイトならコミットできる。
- **ビルドの再現性**：`embed-ipadic` は、ビルドのたびに Lindera のサイトから辞書を取る。CI のビルドが外部のサイトに依存する。データで渡す形のプラグインのビルドは、crates.io のクレートだけで済む。

### 辞書の入手

利用者は、Lindera の CLI（lindera-cli 6.2.0 の `lindera build`）で辞書を作り、プロジェクトの中に置く。
試しの実装では、CLI を使わず、`lindera-ipadic` のビルドが作った九つのファイルをそのまま渡した。
CLI で作ったファイルが同じバイト列になるかは、確かめていない。
作った辞書のファイルは、Lindera の版（`metadata.json` の `format_version`）に縛られ、プラグインの Lindera と合わなければ `sou-ruby-dict` になる。
Golem のリリースに辞書を添えることはしない（「実装しないこと」）。

### 振り方

- 形態素解析の語ごとに、読みを漢字の連なりに割り当てる。語の中の仮名は読みにそのまま現れるものとし、仮名の位置で読みを切る。「取り扱い」（とりあつかい）は、「取（と）り扱（あつか）い」の二つのルビになる。カタカナの読みはひらがなにする。
- 漢字の連なりの一つ（「東京」）には、一つのグループルビを振る。漢字一字ずつの読みは辞書にないので、モノルビにしない。熟語ルビ（[docs/roadmap.md](../roadmap.md) の「ルビの拡張」）は Golem にまだない。
- 読みのない語、読みを語に割り当てられない語は、ルビなしで残し、警告 `sou-ruby-unread`（`読みの分からない漢字です: <語>`）を出す。警告は、ファイルごとに語ごとに一度で、位置はその語が最初に出たテキストのノードの位置とする。
- 漢字は、CJK 統合漢字（拡張 A、第 2 面と第 3 面を含む）、CJK 互換漢字、`々`、`〆`、`〇`、`ヶ` とする。

### 対象にしない箇所

[docs/adr/0131](0131-first-occurrence-ruby-plugin.md) の辿り方を共有する。
違いは見出しである。

- 見出しにもルビを振る。総ルビの本は、見出しも含めてすべての漢字に読みを振るからである。
- 原稿のルビは、そのまま残す。著者の読みを優先する。
- コード、圏点、縦中横、数、参照、索引の印、チャネルの項目、校正の注記は書き換えない。
- 図版とコードのブロック（キャプションを含む）は辿れない。

### 置き場所と配布

- `plugins/sou-ruby/` に置き、`plugins/wasm/sou-ruby.wasm` をコミットする。
- 依存は `lindera` と `lindera-dictionary` の 6.2.0（`default-features = false`、`embed-*` なし）と、補助のクレートと `ruby-common`（[docs/adr/0131](0131-first-occurrence-ruby-plugin.md)）である。
- Golem の本体（golem-* のパッケージ）は変えない。build-depends も変えない。

## 実装しないこと

- 辞書を wasm に埋め込むこと。上の三つの理由による。
- Golem のリリースに IPADIC の辞書のファイルを添えること。辞書の配布の責任とライセンスの表示を Golem が負うことになる。
- 文脈による読みの選択（「今日」を「きょう」と「こんにち」で振り分けるなど）と、音の変化（「一本」の「いっぽん」）。辞書の語ごとの読みを使う。
- 熟語ルビとモノルビへの分解。
- 実行量の上限の決め方。フィルタの上限は、草稿の [docs/adr/0124](0124-filter-fuel-by-document-size.md) で決める。
- ノードの境をまたぐ語の解析。テキストのノードごとに解析する。

## テスト設計

Rust の単体テスト（`cargo test`）では、次を確かめる。

- `ruby-common` の読みの割り当て：「東京」「引張り」「取り扱い」「大きい」「お茶」「一ヶ月」「カタカナ」と、割り当てられない読み（「書く」と「よむ」、短すぎる読み、空の読み）。漢字の判定とカタカナからひらがなへの変換。
- `sou-ruby`：TSV の語をすべての出現に振ること、TSV にない漢字の連なりをファイルごとに一度警告すること、止めの語に警告を出さないこと、見出しにも振ること、原稿のルビを残すこと、TSV も辞書もなければエラーになること。
- 形態素解析器との組み合わせ：決まった語だけを返す偽の解析器で、TSV を先に照合し、残りを解析器の読みで振り、仮名で読みを切り、読みのない語を警告すること。
- 辞書のデータ：一部のファイルだけでエラーになること、Lindera が読めないファイルでエラーになること、`golem_describe` が十のデータの名前を宣言すること。

golem-driver のテスト（`PluginsSpec`）では、`plugins/wasm/sou-ruby.wasm` で次を確かめる。

- TSV だけで、語にルビが振られ、TSV にない漢字に `sou-ruby-unread` の警告が出ること。ビルドがエラーなしで終わること。
- 辞書のファイルの一部だけで、`sou-ruby-dict` がファイルごとに出ること。

IPADIC はリポジトリに置かないので、形態素解析の結合はテストに入れていない。
手で確かめたことは「試しに実装して分かったこと」に書いた（高野聖の四つのターゲット、二度のビルドの PDF の一致、上限を超える章）。
再現性は、`plugins/` を別のディレクトリに写して `build.sh --check` が通ることを確かめた。

テストは Rust の実装と同時に書いた。
先に失敗させる手順は踏んでいない。

## トレードオフ

辞書をデータで渡すので、利用者は辞書を自分で作り、47 MB のファイルをプロジェクトに置く。
埋め込みなら URL を一行書けば動くが、LSP が使えない速度になる。
LSP の速度を優先した。
評価のたびにプラグインを読み込み直す作りが変われば（コンパイル済みのモジュールの保持など）、埋め込みの形を見直せる。

呼び出しのたびに 47 MB を写すので、メモリのピークは 150 MB ほど増えた。
インスタンスのメモリの上限（256 MiB）の内には収まったが、余裕は測っていない。
UniDic のように大きな辞書は、64 MiB のデータの上限を超えるおそれがある（試していない）。

形態素解析の読みには誤りが残る。
TSV で直せるが、誤りを見つけるのは校正である。
「全ての漢字に正しい読みを振る」ことは、このプラグインでは約束できない。
読みのない漢字は警告するので、黙ってルビが抜けることはない。

依存のクレートが 88 個に増え、`plugins/Cargo.lock` は約 950 行増えた。
ライセンスは上に書いたとおり許容的なものだけだが、クレートの更新のたびに確かめる必要がある。

## 決めたことの記録

- 2026-10-29、メンテナー：総ルビの辞書は、データ（[docs/adr/0105](0105-plugin-data.md)）で渡す。wasm に埋め込まない。この ADR の「辞書はデータで渡す」の節のとおりである。
- 2026-10-29、メンテナー：見出しにも振る（初出ルビは見出しに振らない）。
- 2026-10-29、メンテナー：フィルタの命令数の上限を文書の大きさに比例させる方針を認めた。値は草稿の [docs/adr/0124](0124-filter-fuel-by-document-size.md) で測って決めた。
