# ADR 0446: 同じ名前の成果物が試行をまたいで残るときは、いちばん新しいものを取り寄せる

Status: accepted-pending

## 文脈

[root ADR 0442](0442-download-the-waited-artifacts-with-retries-checked-by-digest.md) は、待った成果物を `scripts/ci/download-artifact.sh` で取り寄せ、`digest` で確かめると決めた。
同じ名前の成果物が二つ以上あるときは、取り寄せずに終了コード 1 で終わる（0442 の I5）。
0442 は、実行の全体を再実行したときに前の試行の同じ名前の成果物が一覧に残るかを確かめておらず、採択の前に確かめ、残る場合は試行の番号で絞る形に直すとしていた。

確かめると、上げる側のジョブを再実行した実行では、前の試行の成果物が同じ名前で残っていた。
一方で、一覧の API は試行の番号を返さず、取り寄せる側だけを再実行した試行には前の試行の成果物しか無いので、試行の番号では絞れない。
今の I5 のままでは、上げる側を再実行した後の試行で取り寄せる側を再実行すると、取り寄せる側が毎回失敗する。
この ADR は、同じ名前の成果物が二つ以上あるときの選び方を決め直す。

## 調査した事項

`gh api` で次のことを確かめた（2026 年 11 月 24 日）。

- 実行 45117806778（試行 2 まで、`head_sha` は b271c4db6）の一覧の API（`actions/runs/45117806778/artifacts?name=visual-pdfs`）は、期限切れでない `visual-pdfs` を二つ返した。
  - id 14793011579、`created_at` は 05:36:53Z、`digest` は `sha256:0311963f…`。
  - id 14792764380、`created_at` は 05:42:25Z、`digest` は `sha256:51114bcc…`。
  - 試行 2 の `run_started_at` は 05:39:40Z である。
    一つめは試行 1、二つめは試行 2 の成果物である。
  - 新しいほうの id が小さいので、id の大小では新しさを決められない。
  - 同じコミットから組んだ成果物でも、`digest` は試行ごとに違った。
- 一覧の API の成果物の `workflow_run` は、`head_branch`、`head_repository_id`、`head_sha`、`id`、`repository_id` だけを持ち、試行の番号を持たない。
- 実行 45099523314 の試行 2（`run_started_at` は 02:31:21Z）で走ったジョブは `editors-lsp` と `ci` で（`caches` は skipped）、上げる側のジョブは走っていない。
  `golem-linux-x86_64` は、試行 1 の 02:22:41Z の一つだけが一覧にあった。
  試行 2 の `editors-lsp` は、試行 1 の成果物を使うことになる。
- `wait-pdfs.sh` は、期限切れでない成果物が一つでもあれば待ち終える（[wait-pdfs.sh#L33-L40](https://github.com/tett23/golem/blob/5dfabfe991b96edaab06c6ecb966c2390497910b/scripts/visual/wait-pdfs.sh#L33-L40)）。
  上げる側を再実行すると、前の試行の成果物を見つけてすぐに待ち終える。
- 実行 45117806778 の二つの試行の成果物の zip の大きさは、`visual-pdfs` が 2 つとも 20245327 バイト、`conformance-pdfs` が 2 つとも 2313723 バイト、`wasm-native-list` が 2 つとも 1077 バイトで、`golem-linux-x86_64` は 40385027 バイトと 40385110 バイトで違った。
  zip を取り寄せて中を比べてはいない。
- 実行の全体を再実行した例では確かめていない。

## 実装すること

### 選び方

`download-artifact.sh` は、名前の一致する期限切れでない成果物のうち、`created_at` がいちばん新しいものを選ぶ。
`created_at` の最大が二つ以上の成果物で等しければ、取り寄せずに終了コード 1 で終わる。
選んだ成果物に `digest` が無ければ、0442 のとおり、間を置いて一覧から問い合わせ直す。
選んだ成果物の zip の SHA-256 が `digest` と一致しなければ、0442 のとおり、展開せず、取り直さずに終了コード 1 で終わる。
選んだ成果物の id と `created_at` と、名前の一致した成果物の数を標準エラーに書く。
この選び方は、0442 の「`digest` があるものの `archive_download_url` から zip を取り寄せる」の選び方を置き換える。

### wait-pdfs.sh

`wait-pdfs.sh` は変えない。
上げる側を再実行した実行で、前の試行の成果物を見つけて待ち終えたときは、取り寄せる側は、そのとき一覧にあるいちばん新しいものを取る。
PDF の成果物は、同じ実行の試行が同じコミットから組むので、Golem の決定性により、中身は試行によらないと見ている（推測で、中を比べてはいない）。
実行ファイル（`golem-linux-x86_64`）は、zip の大きさが試行ごとに違ったので、中身も違う見込みが高い。

## 実装しないこと

成果物を試行の番号で絞ることはしない。
一覧の API が試行の番号を返さないうえ、取り寄せる側だけを再実行した試行では、前の試行の成果物しか無いためである。
同じ理由で、`run_started_at` と `created_at` を比べて今の試行の成果物を選ぶこともしない。
`wait-pdfs.sh` に試行の判定を足すことはしない。

## 不変条件

`download-artifact.sh` を、偽の `gh` で確かめる。

- I1: 名前の一致する期限切れでない成果物が二つ以上あり、`created_at` の最大がただ一つのとき、取り寄せるのはその成果物の `archive_download_url` だけである。
- I2: `created_at` の最大が二つ以上の成果物で等しいとき、取り寄せずに終了コード 1 で終わる。
- I3: 名前の一致する成果物が一つの入力では、0442 の境界の表の各行が同じ期待で通る。
- I4: 選んだ成果物に `digest` が無いときは、ほかの成果物を取り寄せずに問い合わせ直す。
- I5: 選んだ成果物の `digest` と一致しない zip は展開せず、終了コード 1 で終わる。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 成果物が一つ | 0442 と同じ | I3 |
| 試行 1 と試行 2 の二つで、新しいほうの id が小さい | 新しいほうを取り寄せる | I1 |
| 三つで、`created_at` がすべて違う | いちばん新しいものを取り寄せる | I1 |
| 二つで、`created_at` が等しい | 取り寄せず、終了コード 1 | I2 |
| 二つで、新しいほうの `digest` が空で、古いほうにある | 古いほうを取り寄せず、問い合わせ直す | I4 |
| 二つで、新しいほうの zip の `digest` が一致しない | 展開せず、取り直さずに終了コード 1 | I5 |

## 受けいれ条件

- A1: 実装のプルリクエストの CI で、上げる側のジョブを再実行した後に、取り寄せる側の 4 つのジョブを別の試行で再実行すると、取り寄せる側が通り、標準エラーに書いた id が新しいほうの成果物である。

## テスト設計

root ADR 0446 I1 から I5 を名前の先頭に置いたテストを、0442 の実装と同じプルリクエストで `scripts/ci/test.sh` に足す。
偽の `gh` が返す一覧に、`created_at` と `digest` の違う同じ名前の成果物を並べる。
A1 は、実装のプルリクエストの CI で `build` の行列のジョブを再実行し、それが成果物を上げ終えてから `visual`、`verapdf`、`wasm`、`editors-lsp` を再実行して、ログの id と成果物の数を見て確かめる。

## トレードオフ

取り寄せる側が、前の試行の成果物を使うことがある。
PDF の成果物は同じコミットから組むので中身は変わらないと見ているが、実行ファイルは試行ごとに中身が違う見込みが高い。

再実行の上げる側が成果物を上げ始める前に取り寄せる側が走ると、前の試行の成果物を使う。
前の試行の上げる側が壊れた成果物を上げて失敗していた場合も、その成果物を使う。
`digest` は上げた zip の SHA-256 なので、中身が壊れていても一致し、この場合を見分けられない。
