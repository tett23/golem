# ADR 0284: インラインの境目の両側の空白を、一つのグルーにまとめる

ステータス: 採択

## 文脈

### 一つのテキストの中だけでまとめている

一つのテキストの中で続く空白は、一つの語間の空白のグルーになる。
テキストの部品を作るときに、空白の連なりを一つの部品にするからである（[`strippedPieces` の `go`](https://github.com/tett23/golem/blob/5fe4b57f2e2a11f09eaff9497b1956c8477d53a1/modules/golem-layout/src/Golem/Layout/Japanese.hs#L963)）。
部品はテキストごとに作るので、境目の前のテキストの終わりの空白と、後のテキストの頭の空白は、別々の部品になり、二つのグルーになる。
[ADR 0280](0280-breaks-between-latin-word-boxes-follow-the-joined-word.md) の実装（[#827](https://github.com/tett23/golem/pull/827)）は、境目の列挙でこれを見つけ、仕様書の「既知の不具合」に「二つのインラインの空白が、二つのグルーになる」として載せた。
列挙は、空白の隣に境目を置かない（[`spaceAtBoundary`](https://github.com/tett23/golem/blob/5fe4b57f2e2a11f09eaff9497b1956c8477d53a1/modules/golem-layout/test/JoinedWordEnum.hs#L322-L323)）。
[ADR 0280](0280-breaks-between-latin-word-boxes-follow-the-joined-word.md) の前からある振る舞いである。

### 原稿のどこで起きるか

「既知の不具合」の例 `a ` と `[strong:  b]` は、原稿からは作れない。
2026-11-10 に、インストール済みの `golem 0.1.0-rc4` の `golem inspect` で `a [strong:  b] c` の CST を見ると、`:` の後の二つの空白は散文スロットの前の空白（`KWhitespace`）であり、IR の `strong` のテキストは `b` だった。
散文スロットの末尾の空白も無視する（[markup.md](../markup.md) の「空白の扱い」）。
そのため、境目の両側に空白ができるのは、末尾の空白をエスケープした `x [strong: y\ ] z` のような原稿である。
同じ `golem inspect` で、この段落の IR は `Text "x "`、`CharStyle "strong" [Text "y "]`、`Text " z"` だった。
式の値（`[= …]`）とプラグインの返すテキストの端の空白も、同じ形になりうる。

### 今の振る舞い

2026-11-10 に origin/main（`5fe4b57f`）の golem-layout のテストを `cabal repl` で読み込み、境目の列挙の環境（[`envOf`](https://github.com/tett23/golem/blob/5fe4b57f2e2a11f09eaff9497b1956c8477d53a1/modules/golem-layout/test/JoinedWordEnum.hs#L69-L74)）で組んだ。
「境目」は、その位置から後の部品を `[strong: …]` に入れたことを表す。

| 部品 | 境目で分けた段落の項目 | 一つのテキストの項目 | 破る不変条件 |
| --- | --- | --- | --- |
| `あ `、境目、` a` | `あ`、グルー、グルー、`a` | `あ`、グルー、`a` | L11 |
| `a `、境目、` b`（行の幅 4 em） | `a`、グルー、グルー、`b`。一行の中で語間が二倍になる | `a`、グルー、`b` | なし |
| `aa `、境目、` bb`（行の幅 2 em） | 一行目 `aa`、二行目 `bb` | 同じ | なし |

L11 は、和文の字と欧文の語のあいだに語間の空白を書いたとき、そのあいだを語間の空白のグルー一つだけとする（[ADR 0222](0222-line-breaking-points-the-invariants-did-not-decide.md) の D2）。
欧文の語どうしのあいだは、どの不変条件も判定しない。
そのため、二つの欧文の語のあいだの語間が二倍になっても、列挙は気付かない。
行で分ける位置では、分けた後のグルーは行に残らないので、見た目は変わらない。

### 拠るもの

- JLReq は、原稿の空白の連なりの扱いを定めていない。
- InDesign の振る舞いは、Golem の開発の環境で動かせないので確かめていない。
- TeX では、2026-11-10 に手元の TeX Live 2026 の `tex` で `\hbox{a {\bf  b}}` と `\hbox{a\ {\bf\ b}}` を `\showbox` で見た。前者のグルーは一つ（`\tenrm` の空白の幅）で、後者は二つ（`\tenrm` と `\tenbf` の空白の幅）だった。TeX は、入力の行を読むときに続く空白を一つにまとめるが、制御空白 `\ ` はまとめない。
- CSS は、`white-space` が `normal` の要素では、続く空白を一つにまとめ、インラインの要素の境目をまたいでもまとめる。残すのは前の空白である（CSS Text Module Level 3 の 4.1.1）。Golem の HTML と EPUB の本文は、閲覧環境がこの規則で組む。

Golem は、一つのテキストの中では、エスケープした空白（`a\  b`）も一つのグルーにまとめる。
エスケープは散文スロットの末尾の空白を残すための書き方であり、TeX の制御空白のように「この空白を足す」という指定ではない。
この ADR は、境目をまたいでも一つのテキストの中と同じにまとめることにする。

## 実装すること

### 1. 境目の両側の空白

段落の部品の並びで、本文の中のコードでない二つの空白の部品（`PSpace`）が、あいだに項目を作る部品を挟まずに続くとき、後の部品を捨てて一つにする。
項目を作らない部品は、アンカー（索引の印など）とソフトハイフンの部品（`PShy`）である。
三つ以上続くときも、最初の一つだけを残す。

残す部品は前の空白である。
グルーの幅と伸縮は、前の空白の見た目（字の大きさ、字送り）で決まる。
前の空白が上付きか下付きの範囲の空白（[ADR 0269](0269-superscript-and-subscript.md)）なら、残した空白は今のとおり伸び縮みせず、その前で改行しない。
前の空白が引用の印の中の保持した空白（[ADR 0277](0277-keep-the-page-label-of-a-citation-mark-with-its-value.md)）なら、今のとおり改行しない。

実装は、[`composeInlinesTree`](https://github.com/tett23/golem/blob/5fe4b57f2e2a11f09eaff9497b1956c8477d53a1/modules/golem-layout/src/Golem/Layout/Japanese.hs#L320-L368) が `structured` から受け取った部品の並びで後の空白の部品を捨て、捨てた部品の葉（[ADR 0183](0183-tagged-pdf-and-pdf-a.md)）と原稿の位置も一緒に除く形を想定する。
アンカーの位置は、捨てた部品の後の項目の数え方で今のとおりに合わせる。

### 2. 本文の中のコードの空白

本文の中のコードの空白（`lkCode` の空白）は、この規則に当てない。
コードの空白は伸び縮みしない固定の幅であり（[golem-layout ADR 0017](../golem-layout/adr/0017-spaces-inside-inline-code.md)）、コードの外の空白とは別の項目である。
コードの空白とコードの外の空白が続くときは、今のとおり二つのグルーになる。

### 3. 列挙

[ADR 0280](0280-breaks-between-latin-word-boxes-follow-the-joined-word.md) の境目の列挙（W3）で、空白の隣に境目を置かない除外をやめる。
空白を含む並びのすべての境目を調べる。
部品の数は変えないので、プルリクエストの段の時間は除外していた並びの分だけ増える。
実装で時間を測り、範囲ごとの予算 10 秒（[ADR 0208](0208-widen-lightweight-formal-methods.md) の 4）を超えるときは、プルリクエストの段で空白の隣の境目だけを部品 1 個少なく調べ、毎晩の段ではすべてを調べる。

### 4. 文書

- [docs/specifications.md](../specifications.md) の「行分割」の節の語間の空白の段落に、続く空白はインラインの境目をまたいでも一つのグルーにまとめ、前の空白を残すことと、コードの空白はまとめないことを書く。
- 仕様書の「既知の不具合」から、「二つのインラインの空白が、二つのグルーになる」を消す。
- 「行分割」の節の境目の列挙の段落から、「空白の隣には境目を置かず」を消す。

### 5. 出力の変化

境目の両側に空白のある段落の、行の中の語間が狭くなり、行の分け方が変わりうる。
実装のプルリクエストで、決定性のハッシュと見た目の回帰テストの変わったものと、その理由を説明に書く。

## 実装しないこと

- **原稿の段階でまとめること**：IR のテキストからは空白を除かない。HTML と EPUB の出力は変えない。本文の空白は閲覧環境が CSS の規則でまとめる。
- **プレーンテキスト**：この ADR では変えない。続く空白をどう書くかは、プレーンテキストの出力の規則で別に決める。
- **lint の規則**：境目の両側の空白を golem-lint で知らせることは、この ADR では足さない。まとめた結果は書き手の意図（空白一つ）とずれないためである。
- **和文の空白（U+3000）**：語間の空白ではないので、まとめない。
- **コードの空白どうし**：コードの中の続く空白の扱いは [golem-layout ADR 0017](../golem-layout/adr/0017-spaces-inside-inline-code.md) のままとする。

## 不変条件

「境目で分けた段落」と「一つのテキスト」は、[ADR 0283](0283-decide-the-roles-of-characters-of-both-scripts-across-inline-boundaries.md) の不変条件の節のとおりとする。
「語間の空白のグルー」は、コードの外の空白から作ったグルーとする。

- **S1 続くグルーはない**：どの段落の項目の列にも、あいだに箱を挟まずに続く二つの語間の空白のグルーはない（あいだが罰点だけのものも続くとみなす）。
- **S2 一つのテキストと同じ**：境目で分けた段落と一つのテキストとで、語間の空白のグルーの数と、それぞれの位置（段落の字の数え）が等しい。
- **S3 前の空白の幅**：境目の両側の空白の見た目が違うとき、残ったグルーの幅と伸縮は、前の空白の見た目で作ったグルーに等しい。
- **S4 列挙**：空白の隣に境目を置く入力を含む境目の列挙のすべての入力で、[ADR 0209](0209-line-breaking-invariants-by-exhaustive-small-inputs.md) の L1 から L13（[ADR 0222](0222-line-breaking-points-the-invariants-did-not-decide.md) の読み方で）と S1、S2 が成り立つ。
- **S5 コードの空白は変わらない**：コードの空白のグルーの数と幅は、この ADR の前と後で等しい。

境界の入力：

| 量 | 調べる値 |
| --- | --- |
| 空白の置き場所 | 前のテキストの終わり、後のテキストの頭、両方、空白だけのテキスト |
| 続く空白の数 | 二つ、三つ（三つのインライン） |
| あいだの部品 | なし、索引の印、ソフトハイフンだけのテキスト、注の印（箱なのでまとめない） |
| 空白の隣の字 | 欧文の字、和文の字、段落の端（[golem-layout ADR 0032](../golem-layout/adr/0032-drop-word-spaces-before-the-end-of-a-paragraph.md) で捨てる） |
| 見た目 | 同じ、前の空白の字が大きい、後の空白の字が大きい |
| 空白の種類 | 本文の空白どうし、本文の空白とコードの空白、上付きの範囲の空白と本文の空白 |
| 行の位置 | 行の中、行で分ける位置 |

## テスト設計

テストを先に書き、今の実装で失敗することを確かめてから実装する。
テストの名前には、S1 から S5 の番号を入れる。

- **S1**：境界の入力の表の「空白の置き場所」と「続く空白の数」と「あいだの部品」の組で、続く語間の空白のグルーがないこと。今は `a ` と `[strong:  b]` の形（IR で組む）で失敗する。注の印を挟んだ入力では、今のとおり二つのグルーが残ること。
- **S2**：同じ組で、グルーの数と位置が一つのテキストと等しいこと。
- **S3**：前のテキストの字の大きさを 10 pt、後のテキストを 20 pt にした段落で、残ったグルーが 10 pt の空白のグルーであること。逆の大きさでも、前の空白のグルーであること。
- **S4**：境目の列挙を、空白の除外をやめてプルリクエストの上限まで走らせる。今は `あ ` と `[strong:  a]` の L11 で失敗する。
- **S5**：空白で終わるコードと、空白で始まるテキストの段落（IR で組む）で、コードの空白のグルーとコードの外の空白のグルーが今のとおり二つあること。
- **golem-driver**：`x [strong: y\ ] z` の原稿を組み、`y` と `z` のあいだのグルーが一つであること。

## トレードオフ

- 後の空白の見た目は、組み方に現れなくなる。字の大きさを変える文字スタイルの末尾にエスケープした空白を書き、その後のテキストが空白で始まるとき、空白の幅は前の空白で決まる。CSS と同じであり、一つのテキストの中の続く空白が最初の空白の幅になるのとも同じである。
- 上付きの範囲の末尾の空白が残ると、その前で改行しない空白になる。`[sup: a\ ] b` の `a` と `b` のあいだは改行できない。範囲の末尾の空白をエスケープして書く原稿は少ないと見込む。
- TeX の制御空白と違い、書き手が二つの空白を並べる手段がなくなる。一つのテキストの中では今もないので、新しく失うものではない。広い空きは `[aki]` で書く。

## メンテナーが決めること

1. **まとめるか**：推奨は、一つのグルーにまとめることである。一つのテキストの中の規則と、HTML と EPUB の閲覧環境の組み方に合い、L11 を例外なしに保てる。
   - 退けた案の一つは、今のとおり二つのグルーとし、L11 と列挙を二つのグルーを許す形に改めることである。TeX の制御空白と同じ振る舞いだが、Golem のエスケープした空白は一つのテキストの中ではまとめるので、境目の有無で組み方が変わる。
   - 二つめは、IR を作るときに空白を除くことである。HTML の出力も変わり、[ADR 0183](0183-tagged-pdf-and-pdf-a.md) の葉の文字列と原稿の位置の対応も変わる。組版だけの問題を、すべての出力の形式に広げることになる。
2. **残す空白**：推奨は、前の空白とすることである。CSS Text Module Level 3 の 4.1.1 と同じで、一つのテキストの中の連なりとも同じ向きである。
   - 退けた案は、幅の大きいほうを残すことである。見た目の大きさを比べる規則が増え、同じ幅のときの決め方がまた要る。
3. **コードの空白**：推奨は、まとめないことである。コードの空白は書いた字の幅を保つ固定の幅であり（[golem-layout ADR 0017](../golem-layout/adr/0017-spaces-inside-inline-code.md)）、隣の本文の空白と同じ種類の項目ではない。
   - 退けた案は、コードの空白も含めてまとめることである。コードの末尾の空白（エスケープしたもの）が、隣の本文の空白で消えることになる。

## 決めたことの記録

2026-11-10 に、tett23 が「メンテナーが決めること」のすべてを推奨のとおりに決めた。

1. インラインの境目の両側の空白は、一つのグルーにまとめる。
2. 残す空白は前の空白とする。
3. 本文の中のコードの空白は、まとめない。

採択にあたり、「今の振る舞い」と「文脈」のコードの記述が、`main` の `5fe4b57f`（[ADR 0280](0280-breaks-between-latin-word-boxes-follow-the-joined-word.md) の実装のマージ）のコードと仕様書の「既知の不具合」に合うことを確かめた。
