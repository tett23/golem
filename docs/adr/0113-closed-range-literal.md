# ADR 0113: 閉じた範囲のリテラル `1...10` を設け、`..` を予約する

ステータス: 採択

## 文脈

`@listing` の `lines` とコードブロックの `highlight` は、行の範囲を受け取る。
今の範囲は、両端を `-` で区切って書く（`lines=10-20`、`highlight=12,14-15`）。
引用は、断りのないかぎり origin/main の 668ed3ac のものである。

この書き方は、[ADR 0102](0102-natural-number-type.md) で端に負の数を書けるようになってから、読みにくくなった。
[ADR 0102](0102-natural-number-type.md) は、自然数を求める箇所の語を数のリテラルとして読み、先頭の `-` も許すと決めた。
そのため、範囲の区切りの `-` と負の符号の `-` が同じ字になる。
`lines=3--1` は「3 から -1 まで」と読み、後の端が負なので G02103 になる（[docs/markup.md の 1048 行め](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/docs/markup.md#L1048)）。
区切りを探す [`rangeEnds`](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/modules/golem-eval/src/Golem/Eval/File.hs#L2029-L2048) は、指数の `1e-3` の `-` を区切りと取らないために、直前の字が `e` かどうかまで見ている。

メンテナーは、両端を含む閉じた範囲を `a...b` と書き、`..` は予約すると決めた。
`..` を予約するのは、端を省いた範囲や終わりを含まない範囲が、いずれどこかで要るからである。
予約した記法を書いたときの扱いは、マクロの `[!` と同じく、[ADR 0115](0115-reserved-syntax-code.md) の予約された記法のコードに従う。
範囲は式の言語の値（範囲のリテラル）にする。

### 式で書く範囲

[ADR 0102](0102-natural-number-type.md) は「`@listing` の `lines` の両端、コードブロックの `numbers` と `highlight` の両端」を自然数を求める箇所とし、どれも式を受け取るとした。
範囲を式でどう書くかは決めていなかった。
2026-10-28 の監査（[F-08](../audits/2026-10-28-rc4-adr-conformance.md)）がこれを未実装の部分として挙げ、プルリクエスト #459 が ADR を経ずに次の形を入れた。

- 式の値が自然数 `n` なら、`n` だけの範囲とする。
- 式の値が二つの自然数の配列 `[a, b]` なら、`a` から `b` までの範囲とする（`lines=[= [n, n + 4]]`）。
- 式の値が文字列なら、語と同じに読む（`lines=[= "1-2"]`）。
- `highlight` の複数の範囲（`3,5-7`）は、語か文字列でしか書けない。

この配列の形は、配列を「範囲」と「行の並び」のどちらの意味にも取れる。
`highlight=[= [2, 4]]` は 2 から 4 までの範囲になり、2 行めと 4 行めの二行にはならない。
プルリクエストの本文も、これをレビューで判断する点に挙げていた。

### 範囲を受け取る箇所

範囲を受け取るのは、次の二つだけである。

- `@listing` の `lines`。一つの範囲か一つの行を受け取る（[File.hs の 1415〜1423 行め](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/modules/golem-eval/src/Golem/Eval/File.hs#L1415-L1423)）。
- コードブロックと `@listing` の `highlight`。カンマで区切った行と範囲の並びを受け取る（[File.hs の 1455〜1464 行め](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/modules/golem-eval/src/Golem/Eval/File.hs#L1455-L1464)）。

[ADR 0102](0102-natural-number-type.md) が挙げた `numbers` は、範囲ではない。
`true`、`false`、最初の行の番号のどれかを受け取る。
今の実装は `numbers` も範囲の読み取り（[`rangesArg`](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/modules/golem-eval/src/Golem/Eval/File.hs#L1992-L2027)）に通すので、`numbers=5-5` を 5 と読む。
`rg` で `splitOn "-"` と `..` を探し、docs と manual の下で `N-M` の形の例を探したが、ほかに範囲を受け取る引数とキーはなかった。
正規表現の文字クラスの `a-z` は正規表現の記法であり、この ADR の範囲ではない。

### rc3 で出した書き方

v0.1.0-rc3 は、次の書き方を出している。

- `lines` の語と文字列の `N-M`（[rc3 の File.hs の 1394〜1399 行め](https://github.com/tett23/golem/blob/8a90425e5e8119776ec0969b57bf3f9638c4f861/modules/golem-eval/src/Golem/Eval/File.hs#L1394-L1399)、[rc3 の docs/markup.md の 279 行め](https://github.com/tett23/golem/blob/8a90425e5e8119776ec0969b57bf3f9638c4f861/docs/markup.md#L279)）。rc3 の `lines` は式を受け取らない。
- `highlight` の語と文字列の `3`、`3,5-7`。式の値が整数ならその一行、文字列なら語と同じに読む（[rc3 の File.hs の 1440〜1473 行め](https://github.com/tett23/golem/blob/8a90425e5e8119776ec0969b57bf3f9638c4f861/modules/golem-eval/src/Golem/Eval/File.hs#L1440-L1473)）。

`-` の範囲は出した書き方であり、ここで消すと rc3 の原稿が組めなくなる。
廃止の手順（[docs/diagnostics.md の「廃止予定の手順」](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/docs/diagnostics.md#L109-L115)）は、廃止予定の notice を少なくとも一つの minor のバージョンで出し、次の ADR でエラーにすると定める。
プレリリースだけでは数えないので、rc4 で notice を出しても、それだけでは `-` の範囲をエラーにできない。
ロードマップの予定では rc4 の次は v1.0.0 であり、今の手順はそのままでは成り立たない（[ロードマップ](../roadmap.md) の「1.0 で約束すること」）。
廃止の手順は、その項目の ADR で決め直すことになっている。
一方、配列の範囲、`lines=5` の一行、`lines` の式はどれも rc3 の後に入ったもので、まだ出していない。

### 範囲の誤りのコード

今は、範囲の誤りの原因ごとにコードが分かれていない。

- G02037 は `lines` について、範囲の形でないこと、終わりが始めより前であること、ファイルの行を外れることの三つをまとめている（[docs/diagnostics.md の G02037](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/docs/diagnostics.md#L1532-L1557)）。
- `highlight` の同じ三つは、コードブロックの引数のほかの誤りと一緒に G02069 になる。

「一つの原因に一つのコード」の原則に照らすと、範囲の書き方を変えるこの機会に分けるのがよい。

### 式の言語の値とプラグイン

式の値は、自然数、整数、有理数、文字列、真偽値、`nil`、配列、連想配列の八つである（[`Golem.Eval.Value`](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/modules/golem-eval/src/Golem/Eval/Value.hs#L24-L33)）。
評価の前の解析の型も、これに `doc` の型を足したものである（[`StaticType`](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/modules/golem-eval/src/Golem/Eval/Analysis.hs#L22-L23)）。
`==` と `!=` はどの型どうしにも使え、型の違う値は等しくない（[`equal`](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/modules/golem-eval/src/Golem/Eval/Expr.hs#L213-L219)）。
大小の比較は数どうしと文字列どうしにだけ使え、ほかは G02001 になる。
本文に埋め込めない値（配列、連想配列など）は G02008 になる（[Expr.hs の 272 行め](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/modules/golem-eval/src/Golem/Eval/Expr.hs#L272)）。

プラグインのコマンドには、引数の値を CBOR で渡す。
CDDL の `value` は `int64 / rational / tstr / bool / null / [* value]` であり、連想配列は渡せない（[golem-doc.cddl の 103 行め](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/modules/golem-doc/schema/golem-doc.cddl#L103)、[`valueTerm`](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/modules/golem-plugin/src/Golem/Plugin.hs#L238-L247)）。
遅らせた式（S1）は、意味論 IR の `expr` として CBOR に書く（[golem-doc.cddl の 83〜97 行め](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/modules/golem-doc/schema/golem-doc.cddl#L83-L97)）。
`expr` の二項演算子は 0 から 11 の番号で持ち、符号化の [`binopIndex`](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/modules/golem-doc/src/Golem/Doc/Cbor.hs#L183-L187) は、表にない演算子に表の長さ（12）を返す。
`BinaryOp` に演算子を足すと、スキーマの外の 12 を黙って書く経路ができる。
ABI のバージョンは 8 で、rc3 の 7 から rc4 のために上げたものであり、まだどのリリースにも含まれていない（[ADR 0052](0052-plugin-abi-version-bump-rule.md)）。
コードブロックの行は、IR では番号と強調の真偽値（`clNumber`、`clHighlight`）だけを持ち、範囲を持たない。

### 文法と数のリテラル

式の文法（[Golem.hpeg の 398〜468 行め](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/modules/golem-parser/grammar/Golem.hpeg#L398-L468)）に `..` と `...` はない。
数のリテラル、名前の参照、引数の語と衝突しないかを、規則ごとに確かめた。

- 数（`Number <- [0-9]+ ('.' [0-9]+)? ('e' [+\-]? [0-9]+)?`）は、`.` の後に数字がなければ小数部の全体が失敗し、`.` を読まずに戻る。`1...10` は `1`、`...`、`10` に分かれる。`1.5...2` は `1.5`、`...`、`2` に、`1e-3...2` は `1e-3`、`...`、`2` に分かれる。
- `1....2` は、`1` と `...` の後に `.2` が残る。Golem は `.2` を数のリテラルとしないので、後の端が読めない。
- 名前の参照（`VarExpr <- !Keyword ExprIdent (Dot ExprIdent)*`）は、`.` の後に名前がなければ繰り返しを止める。`a...b` は `a`、`...`、`b` に分かれ、`meta.x...meta.y` も `meta.x` で止まる。
- 引数の語（`Word`）は空白、`]`、`:`、`|`、`=`、`[`、`"`、`\` 以外の字の並びなので、`3...5` と `3,5...7` はそのまま一つの語になる。語の文法は変えなくてよい。

## 実装すること

### 範囲のリテラル

範囲は `a...b` と書き、`a` から `b` までを表す。
両端を含む閉じた範囲である。
`5...5` は 5 だけであり、行の範囲としては `5` と書いたのと同じである。
今の `1-10` も両端を含むので、`-` を `...` に置き換えれば意味は変わらない。

- **値**：範囲は式の言語の値であり、両端の整数を持つ。端は負でもよい。行の番号として使うときに、[ADR 0102](0102-natural-number-type.md) のとおり自然数かどうかを確かめる。
- **端の型**：端は整数の値を持つ数とする。数でない値（文字列など）は G02110、整数でない数（`1.5...3`、`1...7 / 2`）は [ADR 0102](0102-natural-number-type.md) の G02104 とする。`4 / 2` のように値が整数の有理数は整数として受け取る。
- **向き**：始めの端が終わりの端より大きい範囲（`7...3`）は、空の範囲とせずに G02106 とする。両端を含むので、始めが終わり以下なら範囲は空にならない。空の範囲を書けるのは逆順の場合だけであり、これをエラーにすれば空の範囲は値として作れない。
- **書ける位置**：式を書けるところならどこにでも書ける。`@set r = 1...3` で名前に束ね、`lines=[= r]` で使ってよい。配列の要素にもなる（`highlight=[= [3, 5...7]]`）。
- **本文への埋め込み**：本文に埋め込むと、配列と同じく G02008（`範囲 は本文に埋め込めません`）とする。原因が「埋め込めない型の値を埋め込んだ」で同じなので、コードを分けない。
- **比較**：`==` と `!=` は、両端がどちらも等しいときに等しい。範囲とほかの型の値は等しくない。大小の比較（`<`、`<=`、`>`、`>=`）は G02001 とする。範囲どうしの大小に、決まった意味がないからである。
- **演算と関数**：算術の演算子は G02001、組み込みの関数に渡すと、今の関数と同じく G02007 とする。`len` も範囲を受け取らない。

### `..` の予約

`..` は、端を省いた範囲や終わりを含まない範囲のために予約し、今は受け付けない。
式でも語でも、`..` を書いたら、[ADR 0115](0115-reserved-syntax-code.md) の予約された記法のコード G01100 とする。
メッセージは [ADR 0115](0115-reserved-syntax-code.md) のメッセージとし、位置は式では `..` から、語では引数とする。
両端を含む範囲を `...` で書くことは、docs/diagnostics.md の G01100 の「直し方」に書く。
この ADR は範囲のための自分のコードを設けない。
原因は「予約された記法を書いた」であり、`[!` や `@!` と同じだからである。
端を省いた形（`[= 5...]`、`[= ...5]`）は、範囲の端がないので G02110 とする（下の「文法」）。

G01100 は [ADR 0115](0115-reserved-syntax-code.md) が定める。
この ADR の実装は、[ADR 0115](0115-reserved-syntax-code.md) の実装の後か、同じプルリクエストで行う。

### 文法

`Golem.hpeg` の式の最上位に、範囲の規則を足す。

```peg
%token RangeOp

Expr :: ()
Expr <- RangeExpr { () }

RangeExpr :: ()
RangeExpr <- &'...' (&{ False } '...')^range_end { () }
           / &'..' (&{ False } '..')^reserved { () }
           / AddExpr ES RangeOp ES (AddExpr)^range_end (!(ES '..'))^range_end { () }
           / CompareExpr { () }

RangeOp :: ()
RangeOp <- '...' { () }
         / &'..' (&{ False } '..')^reserved { () }
```

- 範囲の端がない、または端が式として読めない形は、ラベル `range_end` の失敗にする。式の始めの `...`（`[= ...5]`）、`...` の後に端がない形（`[= 5...]`）、端が読めない形（`[= 1....2]`）、端の後にさらに点が続く形（`[= 1...2...3]`、`[= 1...2..3]`）である。`Golem.Parser.labelCode` は `range_end` を G02110 にし、回復は `SkipExpr`、`%safe range_end` を足す（`expr` と同じ理由）。式の始めの `..`（`[= ..5]`）は `reserved` にする。
- `RangeOp` は `...` を先に試す。逆にすると、`1...2` を `1`、`..`、`.2` と読んでしまう。
- `..` は、[ADR 0115](0115-reserved-syntax-code.md) が定めるラベル `reserved` の失敗にする。ラベルの失敗は後戻りしないので、`1..3` はほかの読み方を試さずに G01100 になる。ラベルの回復と `labelCode` の対応は、[ADR 0115](0115-reserved-syntax-code.md) のとおりである。
- `...` は加減算より弱く結び付く。`n...n + 4` は `n...(n + 4)`、`-1...3` は `(-1)...3` である。
- 端は加減算の式とし、比較の式を端にしない。`1 < 2...3` と `1...2 == 1...2` は構文の誤りになる。範囲どうしを比べるときは括弧で囲む（`(1...2) == (1...2)`）。
- 範囲は連ねられない。`1...2...3` は、後の端の後に点が続くので G02110 になる。
- `RangeExpr` は `Expr` の規則なので、配列の要素、関数の引数、括弧の中にも範囲を書ける。
- `scripts/gen-parser.sh` で `Golem.Parser.Generated` と `StrippedGrammar` を作り直し、ラベルの安全性の検査（[golem-parser ADR 0007](../golem-parser/adr/0007-grammar-label-safety.md)）を通す。

構文木と AST は次のとおりにする。

```haskell
-- golem-parser の Golem.Parser.CST
data NodeKind = ... | NRangeExpr

-- golem-parser の Golem.Parser.AST。BinaryOp には足さない
data Expr = ... | ERange (Located Expr) (Located Expr)
```

- `Golem.Parser.Convert` は、規則 `RangeExpr` を `NRangeExpr` に、字句 `RangeOp` を `KOperator` にする。
- `Golem.Parser.Lower` は、`NRangeExpr` の `[a, 演算子, b]` を `ERange a b` にする。`..` は構文の段階で止まるので、AST に現れない。
- `BinaryOp` に足さないのは、`binopIndex` がスキーマの外の番号を黙って書くのを避けるためである。

式を辿る次の関数に、`ERange` の枝を足す。

- golem-eval：`Golem.Eval.Expr` の `freeNames` と評価、`Golem.Eval.Analysis` の `inferExpr` と `analyse` の子の列挙、`Golem.Eval.File` の `nsRefsOf`、`substitute`、`exprNumbers`
- golem-lsp：`Golem.Lsp.Features` の名前の参照と `usesDoc`

### 値と解析の型

```haskell
-- golem-eval の Golem.Eval.Value。始めは終わり以下
data Value = ... | VRange !Integer !Integer

-- golem-eval の Golem.Eval.Analysis
data StaticType = ... | SRange
```

- `typeName (VRange _ _)` は `範囲` とする。
- 解析は、`ERange a b` の両端の型を推論する。どちらかが `SNum` でないと分かれば G02110 とし、そうでなければ `SRange` を返す。端が `TRat` でも、値が整数かどうかは評価で決まるので、解析では誤りにしない（[ADR 0102](0102-natural-number-type.md) と同じく値で狭める）。
- `@set` の名前の型は、その値の型（`SRange`）になる。

### IR とプラグイン

範囲は値なので、遅らせた式とプラグインの引数に現れる。
CDDL に次の二つを足す。

```cddl
; 閉じた範囲の式（docs/adr ADR 0113）
expr = ...
  / [14, span, expr, expr]

; 閉じた範囲の値。first と last を含む。first は last 以下
range = {"first": int64, "last": int64}
value = int64 / rational / tstr / bool / null / range / [* value]
```

- 範囲の式は、二項演算子の `[10, ...]` ではなく、新しい番号 14 の形にする。`..` は構文の段階で止まるので、IR には現れない。
- 範囲の値は、`first` と `last` の二つのキーを持つ CBOR の map にする。`value` に map の形はほかになく（連想配列は渡せない）、配列（`[* value]`）とも区別できる。CBOR のタグを使わないのは、範囲に当たる登録されたタグを確かめられなかったからである。
- 端が `int64` に収まらない範囲は、今の整数と同じく G02091 とする。
- 復号は、`first` が `last` より大きい map、キーが二つでない map、キーが `first` と `last` でない map をスキーマの誤りとする。プラグインが返す遅らせた式の `[14, ...]` も読めるようにする。
- ABI のバージョンは [ADR 0052](0052-plugin-abi-version-bump-rule.md) の規則による。今の 8 はまだリリースに含まれていないので、8 のままである。

### 範囲を受け取る引数

`rangesArg` と `RangesValue` を、次の型に置き換える。

```haskell
-- 両端を含む行の範囲。始めは終わり以下
data LineRange = LineRange !Natural !Natural

-- 範囲を受け取る引数を読む。誤りは報告して Nothing を返す
lineRanges :: EvalContext -> Text -> SrcSpan -> A.ArgValue -> M (Maybe [LineRange])
```

式の値ごとの扱いは次のとおりである。

| 値 | `lines` | `highlight` |
| --- | --- | --- |
| 範囲 | その範囲 | その範囲 |
| 数 | その一行 | その一行 |
| 配列 | G02107 | 要素ごとに、数は一行、範囲はその範囲。ほかの要素は G02105 |
| 文字列 | 語と同じに読む | 語と同じに読む |
| ほかの値（真偽値、`nil`、連想配列） | G02105 | G02105 |

- 範囲の端と数は、[ADR 0102](0102-natural-number-type.md) の自然数への狭める変換を通す。負の数は G02103、整数でない数は G02104、評価の上限を超える数は G02086 のままである。
- `highlight=[= [2, 4]]` は 2 行めと 4 行めである。プルリクエスト #459 の「二つの自然数の配列は一つの範囲」という読み方は消す。まだ出していない書き方なので、廃止の手順は踏まない。
- 文字列を語と同じに読むのは、rc3 で `highlight=[= "3,5-7"]` を出しているからである。
- `lines` に一行（`lines=5`、`lines=[= 5]`）を書けるのは今のままである。
- `highlight` の行がコードにないときの G02069 は今のままとする（[File.hs の 1515 行め](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/modules/golem-eval/src/Golem/Eval/File.hs#L1515)）。

### 語と文字列の範囲

語と文字列の値は、次のとおりに読む。

1. カンマで項目に分ける。
2. 項目に `...` があれば、最初の `...` で前の端と後の端に分ける。端が空（`1...`、`...3`）か、数のリテラルとして読めない（`a...3`、`1-2...3`、`1....2`、`1...2...3`、`1...2..3`）なら G02110 とする。式の同じ書き間違いと同じコードである。
3. 項目に `...` がなく `..` があれば、[ADR 0115](0115-reserved-syntax-code.md) の G01100 とする（`3..5`）。
4. どちらもなければ、一つの数として読む。読めなければ、`-` の範囲として読む。
5. `-` の範囲（`3-5`）は、今の `rangeEnds` で読み、受け付けたうえで廃止予定の notice（G02108）を出す。notice は引数ごとに一つとする。読めなければ G02105 とする。
6. 端は、[ADR 0102](0102-natural-number-type.md) のとおり数のリテラルとして読み、先頭の `-` を許す。`3...-1` の後の端は -1 であり、G02103 になる。`1...1.5` は G02104 になる。

- `3...5` は 3 から 5 まで、`3,5...7` は 3、5、6、7 である。
- `1....2` は `1` と `.2` に分かれ、`.2` が数でないので G02110 とする。
- `1-2...3` は `1-2` が数でないので G02110 とする。
- `3,,5` の空の項目と、数でも範囲でもない項目（`lines=abc`）は G02105 とする。
- `lines` は一つの項目だけを受け取る。カンマで二つ以上の項目を書くと G02107 とする。

### `numbers`

`numbers` を範囲の読み取りから外し、`true`、`false`、自然数だけを受け取る。
自然数は [ADR 0102](0102-natural-number-type.md) の `naturalArg` で読む。
`numbers=5-5`、`numbers=5...5`、`numbers=[= 1...3]` は、今の「`numbers` の値が正しくない」G02069 にする。
rc3 の `numbers` は数字だけの語を受け取り、`5-5` を拒んでいたので、出した書き方は変わらない。

### diagnostic

| コード | 重大度 | 原因 | メッセージ |
| --- | --- | --- | --- |
| G02105 | エラー | `lines` か `highlight` の値（配列なら要素、語なら項目）が、行の番号でも範囲でもない（`lines=abc`、`3,,5`、`[= true]`、`[= [nil]]`） | `<何> には行の番号か範囲を書きます: <値>` |
| G02106 | エラー | 範囲の始めが終わりより大きい（`7...3`、`[= 7...3]`、`@set r = 7...3`） | `範囲の始め <a> が終わり <b> より大きくなっています` |
| G02107 | エラー | `lines` に二つ以上の項目か配列を書いた（`1,3`、`[= [1...2]]`） | `@listing の lines には範囲を一つだけ書きます: <値>` |
| G02108 | notice | `-` で区切った範囲を書いた | `- で区切った範囲は廃止予定です。<a>...<b> のように ... で区切ります` |
| G02110 | エラー | 範囲の端がない、端が数でない、または読めない（`1...`、`...3`、`a...3`、`1....2`、`1...2...3`、`[= 5...]`、`[= "a"...3]`） | `範囲の端には数を書きます: <値>` |

`<何>` は [ADR 0102](0102-natural-number-type.md) と同じ箇所の名前（`@listing の lines`、`コードブロックの highlight`）である。
G02108 は `noticeCodes` に足し、状態を「使用中」とする。
位置は、G02106 と G02110 は式の中ならその範囲の式（構文の段階のものは `...` から）、語ならその引数とし、ほかは引数とする。
範囲の端が整数でない数（`1.5...3`、`[= 1...7 / 2]`、`@set r = 1.5...3`）は、語でも式でも [ADR 0102](0102-natural-number-type.md) の G02104 とする。
原因は「整数が要るところに整数でない数を書いた」で同じである。
範囲の値を作るときの G02104 のメッセージは `範囲の端には整数を書きます（書かれた値 <値> は整数ではありません）` とする。
G02109 は使わずに空けておく。
予約した `..` は、上のとおり [ADR 0115](0115-reserved-syntax-code.md) の G01100 とする。

今のコードは次のとおりに狭める。

- G02037 は「`lines` の範囲がファイルの行を外れる」だけにする。始めの 0 もここに入る。メッセージは `@listing の lines の範囲がファイルの行（1〜<行数>）を外れています: <値>` とする。
- G02069 から、`highlight` の値の形の誤りと逆順の範囲を外す。`numbers` の値の誤り、コードにない `highlight` の行、ほかのキーの誤りは G02069 のままとする。

[golem-eval ADR 0003](../golem-eval/adr/0003-evaluation-diagnostic-codes.md) の G02037 の行と、[golem-driver ADR 0023](../golem-driver/adr/0023-code-block-book-features.md) の範囲の書き方と G02069 の扱いは、この ADR で置き換える。
採択したら、二つと [ADR 0102](0102-natural-number-type.md) のステータスの行に、置き換えた部分とこの ADR へのリンクを足す。

## 実装しないこと

- `..` を使う範囲。端を省いた範囲（`5..`、`..5`）と、終わりを含まない範囲（半開きの範囲）は、`..` を予約したまま後に回す。メンテナーは、閉じた範囲だけを先に入れると決めた。入れれば問題を起こすのが目に見えているからである。具体的には次のものがある。
  - 終わりを含むかどうかを `..` と `...` の一字の違いで書き分けると、一字の書き違いが黙って一行ずれた出力になり、エラーにならない。
  - 端を省いたときの端の意味が箇所ごとに変わる。`lines` ではファイルの最後の行、`highlight` ではコードの最後の番号であり、`diff=true` で数えない行や `numbers` の最初の番号との関係も決めることになる。
  - 範囲が値になったので、端のない範囲を値として持つと、端の型（無限をどう表すか）、比較、プラグインへの形も決めることになる。

  docs/roadmap.md の未決事項に載せ、要る場面が出たら別の ADR で決める。
- 範囲を回して要素を作ること（範囲から配列を作る関数、繰り返し）。
- 範囲の端を取り出す関数（`first`、`last` など）と、範囲の長さ。
- 整数でない端を持つ範囲と、刻みを持つ範囲。
- `-` の範囲をエラーにすること。次の ADR で扱う。
- golem-fmt で `-` の範囲を `...` に書き換えること。fmt は引数の語を書き換えない。
- G02001 と G02069 に残る、範囲と関係のない原因の分割。
- 正規表現の文字クラスの範囲の書き方。

## テスト設計

先に次のテストを書き、今のコードで失敗することを確かめてから実装する。

### golem-parser

- `[= 1...10]`、`[= 1.5...2]`、`[= 1e-3...2]`、`[= n...n + 4]`、`[= -1...3]`、`[= (1...3)]`、`[= [3, 5...7]]`、`[= (1...2) == (1...2)]` が、`ERange` を持つ期待どおりの AST になること。`n...n + 4` の後の端が `EBinary Add` であること。
- `[= 1..3]`、`[= a..b]`、`@set r = 1..3` が G01100 になり、位置が `..` から始まること。
- `[= a...b]` と `[= meta.x...meta.y]` で、名前の参照が `...` の手前で止まること。
- `[= 1....2]`、`[= 1...2...3]`、`[= 1...2..3]`、`[= 5...]`、`[= ...5]` が G02110 になり、`[= ..5]` と `[= 5..]` が G01100 になること。
- `[= 1 < 2...3]` と `[= 1...2 == 1...2]` が今の構文の誤り（G01017）になること。
- `[= 1.5]`、`[= 1e-3]`、`[= meta.title]` の AST が変わらないこと（`ParserSpec` と `AstShapeSpec` の既存のテスト）。
- ラベルの安全性のテスト（`LabelSafetySpec`）が通ること。

### golem-eval

- 式の値：`@set r = 2...3` の後の `[= r == (2...3)]` が真、`[= (1...2) == (1...3)]` と `[= (1...2) == [1, 2]]` が偽であること。`[= (1...2) < (1...3)]`、`[= (1...2) + 1]` が G02001、`[= len(1...3)]` が G02007、本文の `[= 1...3]` が G02008（`範囲 は本文に埋め込めません`）であること。
- 端：`[= "a"...3]` と `[= true...3]` が G02110、`@set r = 1.5...3` と `@set r = 1...7 / 2` が G02104、`@set r = 1...4 / 2` が 1 から 2 の範囲、`@set r = -2...3` が誤りでないこと。
- 向き：`@set r = 7...3` が G02106 になること。
- 予約：`lines=1..3`、`highlight=3,5..7`、`lines="1..3"` が G01100 になり、位置が引数であること。
- 解析の型：`@set r = 1...3` の `r` の型が `SRange` であり、`[= r]` を本文に書くと G02008 になること。
- `lines`：`lines=2...3`、`lines="2...3"`、`lines=[= 2...3]`、`@set n = 2` の後の `lines=[= n...n + 1]`、`@set r = 2...3` の後の `lines=[= r]` が 2 行めと 3 行めを取り込み、最初の行の番号が 2 であること。`lines=2`、`lines=[= 2]`、`lines=2...2` が同じ結果になること。
- `highlight`：`highlight=3,5...7`、`highlight="3,5...7"`、`highlight=[= [3, 5...7]]` が 3、5、6、7 行めを強調すること。`highlight=[= [2, 4]]` が 2 行めと 4 行めだけを強調すること。
- 自然数：`lines=3...-1`、`lines=[= 3...0 - 1]` が G02103、`lines=1...1.5` が G02104、`lines=1...1e1301` が G02086 になること。
- 端の形：`lines=1...`、`lines=...3`、`lines=1...2...3`、`lines=1...2..3`、`lines=a...3`、`lines=1-2...3`、`lines=1....2`、`lines=[= "a"...3]` が G02110 になること。今は G02037 か G02069 である。
- 行でも範囲でもない値：`lines=abc`、`highlight=3,,5`、`lines=[= true]`、`highlight=[= nil]`、`highlight=[= [true]]` が G02105 になること。
- 整数でない端：`lines=1...1.5` と `lines=[= 1...3 / 2]` が同じ G02104 になること。
- 逆順：`lines=7...3`、`lines=[= 7...3]`、`highlight=7...3` が G02106 になること。
- 複数：`lines=1,3`、`lines=[= [1...2]]`、`lines=[= [1, 2]]` が G02107 になること。
- ファイルの外：`lines=0...2` と、ファイルの行数を超える `lines=2...9` が G02037 になり、新しいメッセージになること。
- 廃止予定：`lines=2-3`、`lines="2-3"`、`highlight=3,5-7`、`highlight=[= "5-7"]` が今と同じ行を取り込みまたは強調し、G02108 を引数ごとに一つ出すこと。`highlight=1-2,4-5` も一つだけであること。`lines=3--1` が G02108 と G02103 の両方を出すこと。
- `numbers`：`numbers=5-5`、`numbers=5...5`、`numbers=[= 1...3]` が G02069 になり、`numbers=5`、`numbers=[= 5]`、`numbers=true` が今と同じであること。

### golem-doc と golem-plugin

- 範囲を含む遅らせた式が `[14, span, expr, expr]` に符号化され、復号して同じ AST に戻ること（CDDL との往復のテスト）。
- 範囲の値をプラグインのコマンドに渡すと、引数が `{"first": a, "last": b}` の map になること。端が `int64` を超える範囲が G02091 になること。
- `first` が `last` より大きい map、キーが一つの map、知らないキーを持つ map が、復号でスキーマの誤りになること。

### golem-syntax と golem-driver

- `noticeCodes` が G02108 を含むこと。
- `DiagnosticsSpec` の `everyNoticeProjects` に `-` の範囲を足し、G02108 を出しても出力のバイト列が変わらないこと（「no notice of noticeCodes changes the outputs of the four targets」）。
- `OutputGoldenSpec` のゴールデンが変わらないこと。原稿を書き換えないので、コードブロックの出力は変わらない。

### 文書と出力

- `scripts/manual/build.sh manual` と `manual-dev` が diagnostic を出さないこと。
- 見た目の回帰テストで変わるページが、マニュアルの記法の説明（第 3 章、付録 A、付録 E）と、開発者のマニュアルの IR とプラグインの章に限られることを、ページの一覧の差分で確かめる。`@listing` の `lines` を `...` に書き換えただけのページ（第 4 章と第 5 章）は、取り込む行が同じなので変わらない。
- `adr-guard links` と textlint が通ること。

## トレードオフ

- `...` は、言語によって終わりを含むかどうかが逆になる。Ruby と CoffeeScript の `...` は終わりを含まず、`..` が含む。Swift の `...` は終わりを含み、Golem と同じである。Rust は `..` が終わりを含まず、`..=` が含む。Ruby に慣れた書き手は `1...10` を 9 までと読むことがありうる。読み違いは黙って一行ずれた出力になるので、読みやすさの危険として受け入れる。今の `1-10` が終わりを含むこと、行番号の範囲を言うときの日常の読み方、`..` を後の開いた範囲のために空けておくことを優先した。
- 範囲を値にしたので、本文、比較、プラグイン、IR のそれぞれで扱いを決め、CDDL を変えた。ABI のバージョンは上がらないが、プラグインの作者は `value` の新しい形を読めるようにすることになる。
- 範囲の値の CBOR の形を map にした。CBOR のタグなら型の意味を示せるが、範囲に当たる登録されたタグを確かめられなかった。
- `-` の範囲をエラーにするまで受け付けるので、読み取りの規則が二つ（`...` と `-`）並ぶ。`rangeEnds` の指数の扱いも、次の ADR まで残る。
- 範囲の誤りのコードを五つ（G02105 から G02108 と G02110）足し、G02037 の意味を狭める。G02037 を受け取っていた書き手の原稿のうち、形の誤りと逆順のものは別のコードになる。1.0.0 の前であり、[ADR 0102](0102-natural-number-type.md) が G02037 から負の数を移したのと同じ扱いとする。
- `highlight=[= [2, 4]]` の意味が、main のビルドを使っていた書き手にとっては変わる。出していない書き方であり、配列が二つの意味を持つより、要素の並びという一つの意味に固定するほうを選んだ。

## 決めたことの記録

草案で開いていた点を、次のとおりに決めた。

- **範囲の記号**：最初の草案は `1..10` とした。メンテナーが考え直し、閉じた範囲を `1...10` と書き、`..` を端を省いた範囲と終わりを含まない範囲のために予約すると決めた。`..` は、マクロの `[!` と同じく予約された記法のコードで拒むと、メンテナーが決めた。そのコードは [ADR 0115](0115-reserved-syntax-code.md) で定め、この ADR は自分のコードを設けない。
- **`..` と `...` の割り当て**：閉じた範囲に `...`、端を省いた範囲と終わりを含まない範囲に `..` を割り当てた。メンテナーの理由は、開いた範囲のほうが長い記法を持つのは見た目がおかしい、というものである。
- **範囲の形**：メンテナーが、閉じた範囲だけを先に入れると決めた。端を省いた範囲と半開きの範囲は、問題を起こすのが目に見えているので後に回し、ロードマップの未決事項に載せる。
- **範囲を値にするか**：最初の草案は値にしないとした。メンテナーが、範囲を式の言語の値（範囲のリテラル）にすると決めた。ABI は rc4 の前に上げているので、IR と CBOR の新しい形を足してよいとした。解析の型、書ける位置、埋め込み、比較、CBOR の形は、この版で決めた。
- **新しいコード**：メンテナーが G02105 から G02109 の五つを承認した。範囲を値にし、`..` を [ADR 0115](0115-reserved-syntax-code.md) のコードで拒むことにしたので、番号を詰め直した。G02105（行の番号でも範囲でもない値）、G02106（逆順）、G02107（`lines` に二つ以上）、G02108（`-` の範囲の notice）である。
- **一つの原因に一つのコード**：草案は、範囲の端が整数でない数を、語では G02104、式では新しいコードとしていた。メンテナーが、原則はつねに優先するとして、語でも式でも既存の G02104（整数が要るところに整数でない数）にすると決めた。新しいコードは取り下げ、G02109 は空けておき、ほかの番号は変えない。
  同じ見方で語と式の経路を見直し、次のものを一つのコードにそろえた。
  - 範囲の端がない、端が数でない、端が読めない：語では G02105、式では G02001 か構文の誤り（G01017、G01020）に分かれていた。新しい G02110 にそろえ、式の側は文法のラベル `range_end` と解析で出す。
  - 行の番号でも範囲でもない値：語の `abc` と式の `true` を G02105 にそろえた。G02105 から範囲の端の誤りを外し、この原因だけにした。
  - 負の端（G02103）、逆順（G02106）、`lines` の二つ以上の項目（G02107）、`..`（G01100）は、もともと語と式で同じコードである。
  - 語の `3,,5` の空の項目は G02105、式の `[3,,5]` は配列の構文の誤り（G01020）のまま残した。式の誤りは範囲と関係なく、どの配列でも起きる配列の書き方の誤りであり、語の空の項目（行の番号がない）とは原因が違うと判断した。
- **確かめてほしい点の一つめ**（範囲を値にしないことで `@set` に束ねられないこと）：メンテナーが了承した。その後、範囲を値にすると決めたので、この制限はなくなった。
- **フォントと構文のパッケージ**：メンテナーは、golem-font が golem-syntax に依存することを決して認めないとした（[ADR 0114](0114-sp-in-a-length-package.md)）。
