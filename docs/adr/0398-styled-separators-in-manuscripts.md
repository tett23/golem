# ADR 0398: 原稿の区切りをプロジェクトのスタイルで組む

Status: accepted-pending

## 文脈

原稿の `---` を、場面や内容の区切りとして使いたい。
区切りの見た目は本や台本によって異なり、二行や三行のアキ、罫線を置く一行、約物を置く一行とその前後のアキを選びたい。
原稿には区切りを表す記号だけを書き、プロジェクトの `style.toml` で見た目を変更する。
Emet で生成する本文にも、同じ区切りを挿入できるようにする。
行アキ、罫線、約物は用途の例であり、処理系が用意した見た目だけに限定しない。
著者はプロジェクトの style または Emet で区切りの内容を書き換えられる。

## 調査した事項

調査した版は `dc8bf92ec33549ae2cd3b1cbf43487d451b1071a` である。
以下は定義を読んだ結果であり、新しい構文の実行確認ではない。

- [ブロックの文法](https://github.com/tett23/golem/blob/dc8bf92ec33549ae2cd3b1cbf43487d451b1071a/modules/golem-parser/grammar/Golem.hpeg#L169-L182) には段落、リスト、表、コードとブロックコマンドがあり、独立した区切りの規則はない。
- [原稿の仕様](../markup.md) の「行アキ」では、`@blank-line N` が整数行のアキを表す。段の先頭では捨て、段落間隔と加算しない。
- [意味論 IR](https://github.com/tett23/golem/blob/dc8bf92ec33549ae2cd3b1cbf43487d451b1071a/modules/golem-doc/src/Golem/Doc/IR.hs#L115-L138) と [Emet の組み込み定義](https://github.com/tett23/golem/blob/dc8bf92ec33549ae2cd3b1cbf43487d451b1071a/modules/golem-emet/src/Golem/Emet/Builtins.hs#L140-L154) には `BlankLines` があるが、名前で見た目を選ぶ区切りはない。
- [Emet のブロック結果の検査](https://github.com/tett23/golem/blob/dc8bf92ec33549ae2cd3b1cbf43487d451b1071a/modules/golem-emet/src/Golem/Emet/Gm.hs#L135-L154) は、現状では行アキの返却を拒否する。新しい区切りは型の追加だけでなく、この検査の変更も要る。
- [罫線の共通指定](../specifications.md#罫線の指定) には、太さ、長さ、色、線の種類がある。区切り専用に同じ属性の別仕様を作る必要はない。

文法の `Block`、IR の `BlockBody`、Emet の `blockSource` を通読し、`rg -n 'BlankLines|FSpace|UGap' modules/golem-doc/src modules/golem-emet/src modules/golem-typeset/src` で処理箇所を確認した。

## 実装すること

### 原稿の構文

ブロックの始まりで、ASCII のハイフン三つだけからなる `---` の行を区切りとして読む。
行末の空白とタブは許す。
前後の空行は不要で、空行で段落を分ける様式と改行で分ける様式の両方で、段落をそこで終える。
原稿の文字列として三つのハイフンを書くときは `\---` とする。

この提案では `----`、`- - -`、`***`、`___` を区切りとして扱わない。
Markdown 全体の構文互換を導入せず、`---` の綴りだけを追加する。
コードブロックの内部、インラインの文字列、表の区切り行では、この規則を適用しない。
`- 本文` の箇条書きの規則も変えない。

`---` は、区切りスタイル `default` を指定した `@separator default` と同じ意味とする。
`@separator 名前` で別の区切りスタイルを選べる。
引数は名前一つとし、本体、キーワード引数、散文スロットは受け取らない。

区切りは独立したブロックであり、後続の段落への属性ではない。
文書の最上位と、最上位に展開される Emet のブロック命令の結果で使える。
リストの項目、定義リストの説明、注、図版のキャプション、`@style` の本体では使えない。
`@label`、`@style`、`@lang` の付与対象にはせず、これらの属性を直前に置いて区切りを対象にするとエラーにする。
Emet とプラグインの展開後にも検査し、属性の付いた命令の結果に区切りが含まれる場合は、その命令の位置でエラーにする。
フィルタの返す区切りにラベルか言語が付いている場合も、IR の妥当性検査で拒否する。
採択時には、[root ADR 0187](0187-inline-language-switch.md) の結果への言語付与の規則に、この制限を記録する。
 diagnostic の追加時には原因ごとのコードを割り当て、 diagnostics の一覧に記録する。

### プロジェクトごとの区切りスタイル

`style.toml` の `[separators.<名前>]` に区切りを定義する。
名前の規則は段落スタイルと同じとする。
名前空間は段落スタイルと分け、`default` は `---` が参照する区切りの名前とする。
`default` の定義がなければ、組み込みの一行アキを使う。
区切りの定義には、以下の style のキーによる指定か、「Emet による区切りの定義」の関数指定のどちらかを使う。
利用者の定義があれば、その定義で全体を置き換える。
スタイル間の継承とファイル内の `@style-def` による区切り定義は、この提案には含めない。

| キー | 値と意味 |
| --- | --- |
| `kind` | 必須。`"blank"`、`"rule"`、`"text"` のいずれか |
| `lines` | `blank` だけ。必須の正の整数。空ける行数 |
| `space-before`、`space-after` | `rule` と `text` だけ。0以上の整数で、既定は0。前後に空ける行数 |
| `text` | `text` だけ。必須の空でない一行の文字列。原稿の記法としては評価しない |
| `character-style` | `text` だけ。任意の文字スタイル名。省略時は本文の文字の設定 |
| `align` | `rule` と `text` だけ。`"start"`、`"center"`、`"end"`。既定は `"center"` |
| `rule` | `rule` だけ。省略時は空の表と同じ。下記の罫線指定 |

`rule` の表では、既存の罫線指定の `length`、`weight`、`color`、`style`、`dash`、`gap` を使い、値の検査と既定値を引き継ぐ。
`length` の省略時は段の行長いっぱいに引く。
区切りの罫線の `zw` は、版面の `[page.grid].font-size` を一字として解決する。
前後のアキは区切り側の整数行で決めるため、罫線の表の `space-before` と `space-after` は受け付けない。
`start-indent`、`end-indent`、`keep-in-column` も受け付けない。
罫線の長さが行長を超える場合は設定のエラーにする。

次はプロジェクトごとの設定例であり、処理系に固定する台本の規則ではない。

```toml
# --- を二行アキにする。三行なら lines = 3 に変える。
[separators.default]
kind = "blank"
lines = 2

# @separator scene で約物を置き、前後を一行ずつ空ける。
[separators.scene]
kind = "text"
text = "＊　＊　＊"
space-before = 1
space-after = 1

# @separator rule で一行分の領域に罫線を置く。
[separators.rule]
kind = "rule"
space-before = 1
space-after = 1
```

`---` を約物や罫線にする場合も、`separators.default` の内容を変更するだけでよい。
約物の種類、文字スタイル、罫線の見た目、行数はプロジェクトに属し、台本用の固定値を導入しない。
不明なキー、種類と合わないキー、不正な行数、存在しない文字スタイル、改行を含む `text` は G03006 とし、設定位置を示す。
未定義の区切りスタイルを原稿や Emet から参照した場合は、呼び出しの位置でエラーにする。

### Emet による区切りの定義

style のキーだけでは足りない区切りは、プロジェクトの Emet の関数で定義する。
`[separators.<名前>]` に `function` と `command` を書き、`kind` とそのほかの見た目のキーとは併用しない。
`function` はプロジェクトのルートからの `.emet` の相対パス、`command` はそのファイルが公開する引数のない `pub block` 関数のコマンド名である。
ファイルの読み込み、要求の解決、型検査、評価の手数の上限は既存の Emet の規則を使う。
本体、位置引数、可変長引数、キーワード引数を持つ関数は指定できない。

```toml
[separators.default]
function = "functions/layout.emet"
command = "scene-break"
```

関数は `Blocks` を返し、文字スタイル付きの約物、段落スタイル付きの段落、行アキを自由に組み合わせる。
前後一行のアキと約物の例は次のとおりである。
`scene-mark` は著者が `style.toml` に定義する段落スタイルであり、組み込みではない。

```haskell
pub block "scene-break" sceneBreak :: Blocks
sceneBreak =
  [Block.BlankLines 1]
  ++ Block.styled "scene-mark" (Inline.text "＊　＊　＊")
  ++ [Block.BlankLines 1]
```

この関数の結果には、通常の公開ブロック関数が返せる種類に加え、最上位の `BlankLines` を許す。
区切りのレンダリングとして呼んだ場合だけの許可であり、通常の原稿のブロック命令からの `BlankLines` の返却制限は変えない。
結果の入れ子にある `BlankLines` と、深さによらず `Separator` は拒否し、区切りの再帰展開を起こさない。
未定義のスタイルは既存と同じコード（未定義の段落スタイルは G02047）、IR の不変条件違反は E06104 で拒否する。
ファイル、公開名、シグネチャの指定が不正なら、設定の位置で G03006 とする。

Emet が返すブロック列は、同じブロック列を原稿に直接書いた場合の組版規則に従う。
空の結果も許し、区切りを表示しない定義にできる。
後述する一行の占有、前後の間隔の抑制、後続との保持は、style の `rule` と `text` にだけ適用する。
Emet では、段落スタイルの罫線、間隔、保持指定と、返す行アキで著者が組み方を決める。

### 配置と改ページ

行数は版面の行の格子で数える。
[root ADR 0397](0397-paragraph-line-pitch-and-dimensional-spacing.md) の自由な配置と併用する場合は、一行を版面の `line-pitch` の実寸へ変換し、現在の位置から格子へ丸めずに置く。
`blank` は `@blank-line N` と同じ行アキとして扱い、連続する行アキの合算、上限、段の先頭と文末での破棄、改ページ直前の diagnostics も引き継ぐ。
原稿での区切りの位置を保持し、 diagnostics は内部の展開先ではなく原稿の位置を指す。

style で `rule` と `text` を指定した区切りを、可視の区切りと呼ぶ。
可視の区切りは一行分の領域を占める。
罫線はその行の送り方向の中央に、約物は通常の本文の一行と同じ位置に置く。
行方向の位置は `align` で決める。
横組みと縦組みのどちらでも、行方向と行送り方向を基準に計算する。
約物を自動的に折り返したり縮小したりせず、行長に収まらない場合は組版のエラーにする。
文字スタイルの文字サイズと罫線の太さが版面の一行の送りを超える場合も、組版のエラーにする。
字形やルビの実際の輪郭の重なりを検出する機能は追加しない。

`rule` と `text` の前後には、指定した行アキだけを置く。
隣接する段落の `space-before`、`space-after`、`space-between` は、その区切りとの境界には足さない。
明示した `@blank-line` が同じ境界にある場合は、その合計と区切りの指定の大きいほうを使う。
連続する二つの可視の区切りの境界も、前の `space-after` と後ろの `space-before` の大きいほうを使う。

可視の区切りと後ろの行アキは、後続の通常のブロックの最初の表示行と同じ段に置く。
後続が別の可視の区切りなら、通常のブロックまでまとめて保持する。
段の先頭に移った場合、区切りの前のアキは捨てるが、罫線や約物と、その後ろのアキは残す。
本の末尾や明示的な改ページの直前では、区切りは残し、後ろのアキを捨てる。
一つの空の段にも保持対象が収まらない場合は、無限に次の段へ送らず、組版のエラーにする。

### Emet と意味論 IR

意味論 IR に `Separator` を加え、区切りスタイルの名前を保持する。
評価直後の意味論 IR には、行数、約物、罫線の具体的な値を埋め込まない。
プラグインと Emet の全フィルタを宣言順に適用し終えた後、文書の組み立ての前に、区切りの名前をプロジェクトの定義から解決する。
Emet の関数指定はこの段階で一度呼び出し、結果のブロック列で置き換える。
style の `blank` はこの段階で行アキへ展開し、既存の共通の破棄判定と diagnostics へ渡す。
style の可視の区切りは、解決した設定を組版用のデータとして保持する。
区切りの展開後にプラグインと Emet のフィルタをもう一度実行することはしない。
Emet に `Block.Separator String` と `Block.separator :: String -> Blocks` を公開する。
Emet のフィルタでも、区切りを識別して残す、削除する、別の名前へ置き換える処理を書ける。
ブロック命令の出力検査では、最上位へ展開される `Separator` を許し、入れ子に置かれる場合は拒否する。
通常の公開ブロック関数の `BlankLines` の返却制限は変更せず、区切りのレンダリングの特別な呼び出しだけで許す。
採択時には、[root ADR 0122](0122-block-commands-in-plugins.md) と [root ADR 0162](0162-calling-emet-functions-from-gm.md) のブロック結果の制限に、この追加を記録する。

IR の追加に伴い、プラグインの入出力、妥当性検査、CBOR の往復、Emet の IR 変換を更新する。
ABI の更新は [root ADR 0052](0052-plugin-abi-version-bump-rule.md) に従う。
既存の `BlankLines` と `Block.styled` は変更しない。

### 出力と編集支援

PDF は上記の配置規則で組む。
HTML と EPUB は style の可視の区切りを本文の段落と異なる要素として出力し、罫線と約物を指定どおりに表示する。
Emet が生成したブロック列には、各ブロックの通常の出力方法を使う。
行数のアキは既存の行アキの出力方法に合わせ、本文段落の既定の margin と二重に加算しない。
ブラウザーの改ページ位置と PDF の一致は求めない。

プレーンテキストでは、`blank` は既存の行アキと同じとし、`text` は指定した文字列を一行に出し、`rule` は `---` を一行に出す。
可視の区切りの前後には指定した数の空行を追加し、段落区切りに元からある改行と追加の空行を区別する。

fmt は `---` の綴りを維持し、`@separator default` へ展開しない。
LSP には区切り構文の認識と、`@separator` の名前、`separators` の設定の補完を追加する。
原稿の仕様、各モジュールの仕様、 diagnostics の一覧、README、利用者向けマニュアルを実装と同時に更新する。

## 実装しないこと

Markdown の水平線の全構文、Setext 見出し、段落スタイルの行送りの変更は含めない。
style の `text` の中での原稿や Emet の式の評価は含めない。
任意の内容を生成する処理は、区切りに指定した Emet の関数に書く。
style の `text` は一行のリテラルとするが、Emet の定義では複数の段落も生成できる。

## 不変条件

- `I1`: `---` と `@separator default` は、原稿の位置の範囲を除いて同じ区切りの IR になる。
- `I2`: コード内、エスケープした原稿、表の区切り行のハイフンは区切りの IR にならない。
- `I3`: `blank` の区切りと同じ行数の `@blank-line` は、同じ配置と行アキの破棄規則を持つ。
- `I4`: 可視の区切りは一行分を占め、段落スタイルの間隔を区切りの間隔へ加算しない。
- `I5`: `style.toml` の区切り定義だけを変えても、フィルタの適用と区切りの展開の前の評価済み原稿の区切りの名前と位置は変わらない。
- `I6`: 原稿と Emet が生成した同じ名前の区切りは、同じ位置に同じ見た目で組まれる。
- `I7`: 可視の区切りを段の先頭に移しても、罫線と約物は消えない。
- `I8`: 区切りの Emet 定義を展開した後の組版は、その結果のブロック列を直接組んだ場合と等しい。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| `---` 一行、末尾改行ありとなし | `default` の区切り | I1 |
| 空行なしの本文、`---`、本文 | 独立した区切りを挟む | I1 |
| `\---`、コード内の `---`、表の区切り行 | 区切りにしない | I2 |
| 二行と三行の blank | 対応する `@blank-line` と同じ | I3 |
| 前一行、約物一行、後一行 | 本文との間隔を追加せず三行を使う | I4 |
| default を blank から rule へ変更 | IR の名前と位置は不変、見た目は変わる | I5 |
| Emet の `Block.separator "default"` | 同位置の `---` と同じ組版 | I6 |
| 可視の区切りと後続一行が残りの段に収まらない | 次の段へ送り、前アキだけを捨てる | I7 |
| Emet の空の結果と複数ブロックの結果 | 直接組んだ場合と同じ配置 | I8 |

## 受けいれ条件

- `A1`: 同じ gm の `---` を、プロジェクトの設定だけで二行アキ、三行アキ、罫線、約物に切り替えられる。
- `A2`: 約物と罫線の前後を一行ずつ空ける設定が PDF、HTML、EPUB に反映される。
- `A3`: 区切りの展開前には、Emet の生成、区切りを変更しないフィルタ、IR の保存と復元を通して区切りの名前が保たれる。
- `A4`: 横組みと縦組みで、style の可視の区切りの保持規則が守られ、すべての展開結果に意図しない欠落、重複、改ページの無限ループがない。
- `A5`: 新しい構文を含む原稿の fmt が冪等であり、設定の誤りと未定義の名前が位置付きの diagnostics で報告される。
- `A6`: 著者が Emet の区切り定義を変更するだけで、原稿の `---` を変えずに空の結果、一行アキ、複数の段落を生成できる。

## テスト設計

実装前に文法、評価、スタイルの読み込み、IR の往復、出力、改ページの順で失敗するテストを書く。
テスト名には `root ADR 0398 I1: ...` のように番号を入れる。
文法では境界表に加え、両方の段落区切り様式、末尾空白、`----`、`- - -`、箇条書き、許さない入れ子を検査する。

スタイルの検査では、未知の種類、不要なキー、0 と負の行数、不明な文字スタイル、改行のある text、未定義の区切り名を検査する。
Emet とプラグインでは、IR の往復と、フィルタが区切りを保存する場合と除く場合を検査する。
I8 と A6 では、区切り用の関数の空と複数ブロックの結果、最上位の行アキ、再帰する区切りと入れ子の行アキの拒否、通常の公開ブロック関数との許可範囲の違いを検査する。
属性付きの Emet 命令が段落と区切りを混在して返す場合の拒否と、フィルタが言語付きの区切りを返す場合の拒否も検査する。
罫線の zw の解決と、前後の段落の行送りが異なる自由な配置との併用も検査する。
Emet とプラグインのフィルタを両方の順で並べ、最後のフィルタが作った区切りも一度だけ展開されることを検査する。
fmt の冪等性と、`\---` のエスケープ保持も検査する。

配置では、ちょうど収まる場合と一行足りない場合、先頭と末尾、明示改ページ、連続する区切り、`@blank-line` との併用を検査する。
罫線と約物が一行に収まる境界と、収まらない値も検査する。
PDF の座標と描画内容、HTML と EPUB の要素と CSS、テキストの空行数を比較する。
A1、A2、A4 について、同じ原稿を四種類の設定で組み、横組みと縦組みの PDF と HTML を描画して確認する。

## トレードオフ

`---` に意味を与えるので、従来その行を文字として書いていた原稿は `\---` に直す必要がある。
原稿は場面の区切りを保ち、見た目はプロジェクトごとに変更できる。

区切りを意味論 IR に残すため、出力ごとの自由と Emet のフィルタによる操作が両立する。
一方、プラグインの ABI と各出力の更新が必要になる。
