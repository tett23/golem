# ADR 0475: 文献宣言の必須項目と名前の省略と引用の区切りを定める

Status: proposed

## 文脈

[root ADR 0470](0470-bibliography-styles-by-name-and-by-declaration.md) の実装には、宣言の省略値、名前の省略、引用全体の括弧、言語別の上書きの細部が残っている。
指示者は 2026-11-27 に、提示した七つの推奨案で試すよう指示した。
この ADR は、その七つを、同梱スタイルにも書き手の宣言にも同じように適用する規則として補足する。

## 調査した事項

実装 PR #1201 のコミット `aef9e9f9aaf2735b1b80496ef0323104ddbbdec1` のコードを読んで、次のことを確かめた。

- `Golem.Project.Bibliography.declarationOf` は、宣言の各キーを省略可能として読む。
  必須項目の不足を調べる検査はない。
- `Golem.Assemble.BibliographyNames.formatList` は、上限を超えると先頭の名前を残し、末尾に省略の文字列を付ける。
  末尾の著者を残すキーと、二人だけをつなぐ区切りはない。
- `max` を省くと上限がなく、`max = 0` は、一人以上の名前に省略を適用する値である。
- `Golem.Assemble.BibliographyStyle.overlayBibliographyStyle` は、明示された空文字列と空配列を保持して上書きする。
  言語タグを大文字小文字を区別せずに選ぶ処理はない。
- HTML と EPUB の文字列は、テキストの IR から XML のエスケープを経て出力する。
  書式に差し込む書誌の値は、原稿として再パースしない。

## 実装すること

### 必須項目と省略値

宣言には、下の表の必須項目を書く。
言語別の上書きは部分的な宣言でよく、基礎の宣言と重ねた後の値が、同じ表を満たすか調べる。
基礎の宣言は、単独で必須項目を満たすものとする。
宣言したスタイルは、選択していないものも含めて検査する。
言語別の部分的な宣言は、基礎の宣言と重ねた値を検査する。
使われない項目を補うために、別のスタイルの値を黙って借りない。
空文字列と空配列は、項目の省略とは区別する。

| 対象 | 必須項目 | 省略できる項目と扱い |
| --- | --- | --- |
| スタイル全体 | `citation-mode`、`citation`、`citation-delimiter`、`citation-sort`、`sort`、`hanging-indent`、`year-suffix`、`page-range`、`range-delimiter` | 以下の行で定める項目 |
| `citation-mode = "author-year"` | `citation-year` | ほかのモードの `citation-year` は不要 |
| `citation-mode = "note"` | 上の共通項目 | `subsequent` は `citation`、`note-channel` は `footnote` |
| `sort` が `language` を含む | `language-order` | 含まなければ不要 |
| 文献の種類の表 | 宣言した `types.<種類>` ごとの `pieces` | `char-styles` は空の表 |
| `{author}`、`{editor}` を使う書式 | 使う名前の表の `order`、`initials`、`delimiter`、`last-delimiter` | 引用の `{author}` が `names.short` を使う条件は root [ADR 0470](0470-bibliography-styles-by-name-and-by-declaration.md) のとおり |
| `names.short` を使う書式 | `delimiter`、`last-delimiter` | 姓だけを書くので `order` と `initials` は不要 |
| 姓を先に書く名前の表 | `part-delimiter` | `given-family` では不要 |
| `initials = true` の名前の表 | `initial-format`、`initial-delimiter` | `initials = false` では不要 |
| `{editor-label}` を使う書式 | `names.editor.label` | 使わなければ不要 |
| `max` を書く名前の表 | `use-first`、`et-al` | `use-last` は 0 |
| `max` のない名前の表 | 追加の必須項目なし | 名前の上限なし。`use-first`、`use-last`、`et-al` だけを書いた場合はエラー |
| 一覧の頭 | 追加の必須項目なし | `label` を省くと頭なし |
| 月の名前 | 追加の必須項目なし | `months` を省くと月は数。指定時は 12 個の文字列 |
| 位置のラベル | `{locator}` を展開する位置の種類の `locator-labels` | 使う種類に対応するラベルがなければエラー |
| 引用全体の囲み | 追加の必須項目なし | `citation-prefix` と `citation-suffix` はともに空文字列 |
| 名前二人の区切り | 追加の必須項目なし | `pair-delimiter` は `last-delimiter` |

名前の表を使うかどうかは、空の値によって片を省く前の、宣言した書式の差し込みで決める。
そのため、一人だけの書誌データを組む場合も、使う名前の表の必須項目を省けない。
`subsequent` を省いた場合は、`citation` が参照する項目だけを調べる。

文献の種類に対応する表がなければ、明示された `types.default` を使う。
一覧に載せる文献の種類にどちらもなければエラーにする。
一覧を組まない本には、一覧専用の種類の表を新たに書くことを要求しない。
ただし、種類の表を宣言した場合は、一覧の有無によらず、その書式が参照する名前の表と必須項目を調べる。
引用の書式だけに必要な名前の表も、一覧の有無によらず調べる。

必須項目の不足、名前の数の不整合、言語タグの重複、位置のラベルの不足は、エラーの G03006 としてスタイル名と項目のパスを報告する。
書式の構文が誤る場合の G03304 は変えない。
宣言を正しく読めないまま、別のスタイルで生成を続けない。
`style` 自体を省いた場合の `golem` は、root [ADR 0470](0470-bibliography-styles-by-name-and-by-declaration.md) の従来の出力を保つ。
書き手は同梱の宣言を写してから直せる。

### 名前の省略と区切り

`names.author`、`names.editor`、`names.short` に `use-last` と `pair-delimiter` を足す。
`use-last` は、上限を超えるときに末尾から残す名前の数である。
数のキーは、既存の `max` と同じく 0 以上 2147483647 以下の整数にする。
`use-first + use-last <= max` を必要条件とし、加算はオーバーフローしない形で検査する。

元の名前の数が `max` 以下なら、すべての名前を組む。
二人なら `pair-delimiter`、三人以上なら途中に `delimiter`、最後の名前の前に `last-delimiter` を使う。
空の名前の一覧は、空文字列になる。

元の名前の数が `max` より多ければ、先頭の `use-first` 人と末尾の `use-last` 人を残す。
先頭の列と末尾の列は、それぞれ `delimiter` でつなぐ。
その二つの列の間に、`et-al` を書いたとおりに一度だけ置く。
`et-al` に必要な前後の区切りも、書き手が文字列に含める。
省略した列には `pair-delimiter` と `last-delimiter` を使わない。
`first-family-given` は、省略する前の元の先頭の著者だけを姓から書く。
先頭を残さず末尾だけを残しても、残った著者を先頭の著者として書き直さない。

たとえば `max = 2`、`use-first = 2`、`use-last = 0`、`delimiter = ", "`、`et-al = ", et al."` なら、三人の名前は `A, B, et al.` になる。
`max = 20`、`use-first = 19`、`use-last = 1`、`et-al = ", …, "` なら、21 人以上で先頭 19 人と最後の一人を残す。
`max = 0` では両方の保持数は 0 であり、空でない一覧は `et-al` だけになる。

### 個別の引用と全体の囲み

スタイルに文字列の `citation-prefix` と `citation-suffix` を足す。
それぞれ、一つの引用の印の全体の前と後に一度だけ付ける。
一件ごとの `citation` と `citation-year` の書式に、全体の囲みを自動で足さない。

引用の順序を `citation-sort` で決め、各文献に属する位置、前置き、後置きを付けてから、`citation-delimiter` でつなぐ。
その全体を `citation-prefix` と `citation-suffix` で囲む。
引用が空なら囲みだけを出さない。
`note` では、注の本文の中の一つの引用全体に同じ規則を使う。
年だけの引用にも、同じ全体の囲みを使う。

`citation = ["{author}, {year}"]`、区切りが `"; "`、囲みが `"("` と `")"` なら、`(A, 2020; B, 2021)` の形になる。
一件ごとに `[{number}]` を書き、全体の囲みを空にすれば、`[1], [2]` の形にできる。
従来の `golem` の連番圧縮は保持し、ほかの宣言の番号式に自動で適用しない。

### 言語別の上書き

文献の言語は、root [ADR 0470](0470-bibliography-styles-by-name-and-by-declaration.md) のとおり、書誌データの `language`、なければ本の言語とする。
`languages` のキーと照合するときは、ASCII の大文字小文字を区別しない。
ハイフンで区切った部分を一つずつ増やし、たとえば `ja-JP` には基礎の宣言、`ja`、`ja-JP` の順に重ねる。
`ja-JP-x-example` なら、その後に `ja-JP-x` と `ja-JP-x-example` も、宣言がある場合だけ重ねる。
一致は部分の境界で行い、`ja` を `jav` に当てない。

言語の上書きも、書いた項目だけを重ねる。
空文字列、空配列、`false`、0 は、書いた値として保持する。
同じスタイルの `languages` に `ja` と `JA` のような、照合時に同じになるキーがあればエラーにする。
入れ子の `languages` は、引き続き認めない。
`language-order` の主の副タグで並べる規則は、この変更の対象にしない。

### 言語の異なる文献を一緒に組む場合

印全体と一覧全体の属性は、本の言語で上書きした宣言から選ぶ。
文献ごとの属性は、各文献の言語で上書きした宣言から選ぶ。
言語の混じった引用でも、この二つを混ぜて一つの属性を決めない。
この区別は、root [ADR 0470](0470-bibliography-styles-by-name-and-by-declaration.md) の言語別の上書きへの補足である。

| 選ぶ単位 | 属性 |
| --- | --- |
| 本の言語 | `citation-mode`、`citation-delimiter`、`citation-sort`、`citation-prefix`、`citation-suffix`、`note-channel`、`sort`、`language-order`、`year-suffix`、`hanging-indent` |
| 文献の言語 | `citation`、`citation-year`、`subsequent`、`label`、`types`、`names`、`months`、`page-range`、`range-delimiter`、`locator-labels` |

`names.short` を使うか、年だけの書式を選べるか、二度目の注の引用かは、本の言語から決めた `citation-mode` で判断する。
必要な名前の表と `citation-year` の検査にも、そのモードを使う。
一覧の `label` は一件ごとの書式なので文献の言語で選び、字下げと並び順は一覧全体で共通にする。

### 引用の前置きと後置き

原稿の `cite` の `prefix` と `suffix` は、文字列だけを認める。
ほかの型は、エラーの G02299 `cite の <名前> には文字列を書きます` とし、その引数の値の位置で報告する。
文字列は原稿として再パースせず、文献ごとのテキストの IR に保持する。
宣言の `citation-prefix` と `citation-suffix` も、同じく文字どおりのテキストとして扱う。
HTML と EPUB では、通常のテキストと同じ経路で XML のエスケープをする。

### 文書と採択の記録

仕様書、README、利用者マニュアルに、必須項目、名前の省略、二人の区切り、引用全体の囲み、言語の上書きを書く。
同梱の宣言と三つの見本の論文を、同じ規則を満たすように直す。
`docs/diagnostics.md` に G02299 を足す。
root [ADR 0470](0470-bibliography-styles-by-name-and-by-declaration.md) のステータスには、この ADR による「宣言の形と引用の細部」の補足を記録する。
root [ADR 0470](0470-bibliography-styles-by-name-and-by-declaration.md) A1 の、メンテナーが見本を目で確かめる条件は、別に残す。

## 実装しないこと

CSL のスタイルの読み込み、新しい同梱スタイルの追加、言語の推定はしない。
引用の前置きと後置きに、原稿の構文や生の HTML を認めない。

## 不変条件

- I1: 必須項目を満たさない宣言と、型か範囲の誤った新しいキーは、生成を続けず項目のパス付きのエラーになる。
- I2: 上限以下の名前はすべて一度ずつ現れ、上限を超える名前は先頭と末尾の指定数だけが元の順に一度ずつ現れる。
- I3: 省略時の `et-al` は一度だけ文字どおりに現れ、省略した列に最後専用の区切りは現れない。
- I4: 全体の囲みは、空でない一つの引用の印に一組だけ付き、各文献の位置と前後の文字列は、並べ替えても同じキーに属する。
- I5: 言語タグの大文字小文字を変えても上書き結果は同じであり、より細かい言語の明示値は粗い言語の明示値を上書きする。
- I6: 引用の前後の文字列は再パースされず、HTML と EPUB では通常の文字列と同じエスケープを経る。
- I7: スタイルの指定のない従来の本の出力は変わらない。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 必須の `citation-mode` なし | G03006 と項目のパス | I1 |
| 空の `citation` と空の `sort` を明示 | 値を借りず、空の宣言として保持 | I1, I5 |
| 名前 0 人、1 人、2 人、3 人 | 空、一人、二人の区切り、三人以上の最後の区切り | I2 |
| `max = 2` で 2 人と 3 人 | 全員と、保持数の列と省略の文字列 | I2, I3 |
| `max = 0` で 0 人と 1 人 | 空と `et-al` だけ | I2, I3 |
| `max = 20`、先頭 19、末尾 1、21 人 | 重複なく 20 人と省略の文字列 | I2, I3 |
| `first-family-given`、先頭保持 0、末尾保持 1 | 残る末尾の著者は名から書く | I2 |
| 保持数の合計が上限を超える | G03006 | I1 |
| 二件の著者年式の引用 | 括弧一組の中に区切りを挟んだ二件 | I4 |
| 空の引用 | 囲みも出ない | I4 |
| `ja` と `ja-JP` の上書きと文献の `JA-jp` | 粗い順に重ねる | I5 |
| 上書きの空文字列と空配列 | 空の明示値を保持 | I5 |
| 日本語と英語の文献の一つの引用 | 囲みと並べ方は本の言語、各文献の名前と位置ラベルはその文献の言語 | I4, I5 |
| `languages.ja` と `languages.JA` | G03006 | I1, I5 |
| 前置き `"<a>&[cite x]"` | 文字どおりのテキスト。HTML のタグや引用にならない | I6 |
| 数値の `prefix` | 引数の位置でエラー | I1, I6 |
| `style` のない本 | 従来どおり | I7 |

## 受けいれ条件

- A1: `golem` 以外の同梱の宣言スタイルと、その宣言を別名に写したものの引用と一覧が同じになる。
- A2: 三つの見本を CLI で組み、文献に関するエラーと警告が出ない。
- A3: 名前と引用の新しいキーが、TOML の読み込み、スキーマ、スタイルの上書き、各媒体の出力で同じ値を保つ。

## テスト設計

I1 から I7 と A1 から A3 の名前を付けた回帰テストを、実装前に足して失敗を確かめる。
必須キーを一つずつ省く例と、条件付きのキーを必要な場合だけ省く例を作る。
名前の数は 0、1、2、3、上限、上限に一人加えた数、最大整数の宣言を確かめる。
末尾保持は、保持数 0 と、先頭と末尾の合計が上限と等しい場合を含める。
引用は、本文、年だけ、注の外、書き手の注の中、複数キー、並べ替え、位置の指定を組み合わせる。
異なる言語でモードや全体の囲みを上書きした二つの文献も、一つの印では本の言語の属性を共用することを確かめる。
言語は、大文字小文字、複数段のタグ、部分の境界、不一致、重複、明示された空の値を確かめる。
CLI で PDF、HTML、EPUB を生成し、引用の文字列とエスケープを照合する。

## トレードオフ

宣言が長くなるが、別のスタイルの値が混ざった書誌を黙って生成することを避けられる。
同梱の宣言を写す方法で、書き始める手間を減らす。
区切りを文字列に含めるので、処理系が句読点を推測せずに済む。
