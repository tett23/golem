# ADR 0112: `*[式]` と `**[式]` をすべてのコマンドの引数に展開する

ステータス: 採択

## 文脈

docs/markup.md の「引数」の節は、`*[式]` を配列の位置引数への展開、`**[式]` を連想配列のキーワード引数への展開と定めている。
[golem-parser ADR 0013](../golem-parser/adr/0013-splat-after-keyword-arguments.md) は、`**[式]` をキーワード引数と同じ位置に書けるようにし、展開したキーがほかのキーワード引数と重なれば G02077 とすると決めた。
ところが評価器は、どのコマンドでも展開を実装していない。

- 組み込みのコマンドは、引数を AST のまま読む。キーワード引数を拾う [`keywords`](https://github.com/tett23/golem/blob/c69df1c1494ebd3cfb47b6e27ab6ed6a5745b031/modules/golem-eval/src/Golem/Eval/File.hs#L1887-L1888) は `Keyword` だけを拾い、展開の引数を黙って捨てる。位置引数も、`Positional` だけを見る。
- プラグインのコマンドには、展開の引数を `[0, null]` として渡す（[`evalCommand`](https://github.com/tett23/golem/blob/c69df1c1494ebd3cfb47b6e27ab6ed6a5745b031/modules/golem-eval/src/Golem/Eval/File.hs#L1689-L1692)）。
- `@manifest` と `@style-def` は、展開の引数を G02052 にする。G02052 は、位置引数の数の誤りや本体があることなど、ほかの原因と同じコードである。

ロードマップの v0.1.0-rc4 の「`*[式]` の展開とプラグインへの引数」は、この展開とプラグインのキーワード引数を一つの項目に挙げている（[docs/roadmap.md](../roadmap.md)）。
プラグインのキーワード引数は、別の草稿 [docs/adr/0110](0110-keyword-arguments-to-plugins.md) で扱う。
メンテナーは、組み込みのコマンドの展開も rc4 までに要るとして、この草稿で決めるよう求めた。

### 組み込みのコマンドの引数の読み方

すべての組み込みのコマンドを調べた（origin/main の c69df1c1）。
引数の位置ごとの読み方は、次の五つに分かれる。

| 読み方 | 受け取るもの | 位置 |
| --- | --- | --- |
| 値 | 語、文字列、式（[`argValue`](https://github.com/tett23/golem/blob/c69df1c1494ebd3cfb47b6e27ab6ed6a5745b031/modules/golem-eval/src/Golem/Eval/File.hs#L1915-L1926)） | `[number-text ...]` の数、プラグインのコマンドの引数 |
| 自然数 | 語、式（[`naturalArg`](https://github.com/tett23/golem/blob/c69df1c1494ebd3cfb47b6e27ab6ed6a5745b031/modules/golem-eval/src/Golem/Eval/File.hs#L1944-L1956)） | `@toc` の `depth`、`@need-lines`、`@blank-line`、`@number`、`@figure` の `page` |
| 範囲 | 語、文字列、式（`rangesArg`） | `@listing` の `lines`、コードブロックと `@listing` の `highlight` と `numbers` |
| 字（名前） | 語と文字列（`nameArg`、`argText`） | `[color 名前: ...]`、`[style 名前: ...]`、`[cite キー]`、`[aki 量]`、`[ref-number ラベル]` など三つの参照、`[kenten shape=...]`、`[number-text style=...]`、`[index reading=...]`、`@channel` の名前と `style`、`@figure`、`@table`、`@listing` の字のキー、コードブロックの開始の行のキー（式も受け取る） |
| 語だけ | 語（`A.Word` との照合） | `@page-break` の `recto` と `verso`、`@page-lines` の `+1`、`@label` のラベル、`@style` の段落スタイルの名前、`[style code: ...]` の判定、`@import` |

「語だけ」の位置は、同じ字の文字列リテラルを受け取らない。
`@page-break "recto"` は G02058、`@label "p"` は G02026 になる。
語と文字列リテラルは、どちらも字を書く書き方であり、この違いに意味はない。

引数を評価の前に読むコマンドもある。

- `@manifest` と `@style-def` は、ファイルの評価の前に設定と文字スタイルを決める（[`Golem.Eval.Settings`](https://github.com/tett23/golem/blob/c69df1c1494ebd3cfb47b6e27ab6ed6a5745b031/modules/golem-eval/src/Golem/Eval/Settings.hs#L56-L70)）。値は語と文字列だけを受け取り、式は G02052 になる。
- `@style` は、本体の行を段落ごとに分けるか（行を保つ段落スタイルか）を、評価の前に名前で決める（[`keepsLines`](https://github.com/tett23/golem/blob/c69df1c1494ebd3cfb47b6e27ab6ed6a5745b031/modules/golem-eval/src/Golem/Eval/File.hs#L390-L392)）。
- `@import` は、プロジェクトの段階で `パス as 名前空間` の形を読み、ほかの形は G03009 になる（[`importSite`](https://github.com/tett23/golem/blob/c69df1c1494ebd3cfb47b6e27ab6ed6a5745b031/modules/golem-project/src/Golem/Project/Imports.hs#L52-L56)）。

### 試しに実装して分かったこと

この ADR は、採択の前に実装を試した（ブランチ `builtin-arg-spread`、origin/main の c69df1c1 から分岐、コミット `d2e8cc29`）。

- 展開をコマンドごとに書くと、五つの読み方と三十に近い位置のそれぞれに手が入る。引数を AST の段階で展開し、展開した要素を「書いた引数」に戻せば、どのコマンドも今の読み方のまま展開を受け取れた。変えたのは、展開を一か所にまとめる関数と、「語だけ」の位置の五か所である。
- 引数の重複を除く [`uniqueKeys`](https://github.com/tett23/golem/blob/c69df1c1494ebd3cfb47b6e27ab6ed6a5745b031/modules/golem-eval/src/Golem/Eval/File.hs#L1875-L1879) は、引数を位置（ソースの範囲）で見分けていた。一つの `**[式]` から展開したキーワード引数はどれも同じ範囲を持つので、重なったキーを一つ除くと、同じ展開のほかのキーまで除かれた。引数の順番で見分けるように直した。
- 字の位置に、文字列でない値（数など）を展開すると、`[= 1]` と書いた場合と同じく、今の `argText` は空の字を返す。`[kenten **[{shape: 1}]: x]` は `未知の圏点の形です: `（値が空）になる。これは展開に限らない今の振る舞いで、この ADR では直さない。
- プラグインのコマンドの展開は、別のブランチ（`plugins-number-tcy` のコミット `dce87e9c`）でプラグインの呼び出しの中に実装していた。AST の段階で展開すると、プラグインの呼び出しには展開の引数が届かなくなるので、そちらの実装は要らなくなる。G02077 の位置も、呼び出しの位置から展開の引数の位置に揃う。

## 実装すること

### 展開の規則

コマンドの引数を読む前に、`*[式]` と `**[式]` を展開する。
インラインのコマンド、ブロックのコマンド、属性、コードブロックの開始の行、プラグインのコマンドのすべてに、同じ規則を当てる。

- `*[式]` は式を評価し、値が配列なら、要素を順に位置引数とする。
- `**[式]` は式を評価し、値が連想配列なら、要素をキーのコードポイントの順にキーワード引数とする。連想配列は順を持たないので、キーの順に並べる。
- 展開した要素は、その値をリテラルで書いた引数とする。文字列は文字列リテラル（`"..."`）と書いたのと同じであり、ほかの値（数、真偽値、`nil`、配列、連想配列）は `[= 値]` と書いたのと同じである。
- 空の配列と空の連想配列は、何も展開しない。
- 展開した引数の位置（ソースの範囲）は、展開の引数の位置とする。

展開した要素を「書いた引数」に戻すので、どのコマンドも、展開を今の読み方のまま受け取る。
`[number-text *[[12]]]` は `[number-text [= 12]]`、`[kenten **[{shape: "dot"}]: x]` は `[kenten shape="dot": x]` と同じである。
コマンドごとに展開の規則を持たせないのは、読み方の違いがすでに「語、文字列、式のどれを受け取るか」で決まっており、展開をそこに写せば足りるからである。

### 語だけの位置

名前や決まった語を受け取る位置では、語と同じ字の文字列リテラルも受け取る。

| 位置 | 今 | この ADR |
| --- | --- | --- |
| `@page-break` の `recto` と `verso` | 語だけ | 語と文字列 |
| `@page-lines` の `+1`、`-1` | 語だけ | 語と文字列 |
| `@label` のラベル | 語だけ | 語と文字列 |
| `@style` の段落スタイルの名前（`keepsLines` と `styleName`） | 語だけ | 語と文字列 |
| `[style code: ...]` の `code` の判定（`codeSlots`） | 語だけ | 語と文字列 |

字として読む位置で、語と文字列リテラルの違いを残す理由はない。
これで、展開した文字列がこれらの位置に入る。
`[style code: ...]` の判定は、展開した後の引数で行うので、`[style *[["code"]]: ##1##]` も `##1##` を地の文のまま読む。

`@import` は変えない。
`@import` はプロジェクトの段階で `パス as 名前空間` の構文として読み、引数の値を読むのではないからである。
展開を書いた `@import` は、今のとおり形の誤り（G03009）である。

### 展開を受け付けないコマンド

引数を評価の前に読むコマンドは、展開を受け付けない。
展開の値は、評価しないと分からないからである。

| コマンド | 評価の前に読むもの |
| --- | --- |
| `@manifest` | ファイルの設定 |
| `@style-def` | 文字スタイルと段落スタイルの定義 |
| `@style`（本体の形と属性の形） | 本体の行を保つかどうか |

この三つに展開を書くと、新しいエラー G02114 とする。
`@manifest` と `@style-def` の展開は、今は G02052 であり、G02052 から外す。
G02052 に残るほかの原因（位置引数の数の誤り、本体があることなど）は、[docs/adr/0132](0132-setting-command-codes-by-cause.md) で原因ごとのコードに分ける。

### diagnostic

| コード | 重大度 | 原因 | メッセージ |
| --- | --- | --- | --- |
| G02111 | エラー | `*[式]` の値が配列でない | `*[式] の値は配列でなければなりません: <型>` |
| G02112 | エラー | `**[式]` の値が連想配列でない | `**[式] の値は連想配列でなければなりません: <型>` |
| G02114 | エラー | 評価の前に引数を読むコマンドに展開を書いた | `<コマンド> は評価の前に読むので、*[式] と **[式] を書けません` |
| G02077 | エラー | 展開したキーが、前のキーワード引数か前の展開のキーと重なる | `同じキーを二度書いています: <キー>` |

- G02111 と G02112 は、[docs/adr/0110](0110-keyword-arguments-to-plugins.md) のプラグインのコマンドのコードと同じである。プラグインと組み込みのコマンドで、同じ原因には同じコードを出す。
- G02111、G02112、展開の式の誤り（未定義の名前など）のときは、そのコマンドを実行しない。インラインのコマンドは何も出さず、ブロックのコマンドとコードブロックはブロックを作らず、属性はその属性がないものとする。引数が欠けたまま実行すると、原因でない引数の誤りが重なるからである。
- G02077 は、[golem-parser ADR 0013](../golem-parser/adr/0013-splat-after-keyword-arguments.md) のとおり、後のキーの引数を除いて実行を続ける。位置は展開の引数である。
- 位置は、どれも展開の引数（`*[...]` か `**[...]`）である。

### ドキュメント

- docs/markup.md の「引数」の節に、展開の規則、語と文字列の扱い、展開を受け付けないコマンドを書く（試しの実装で書いた）。
- docs/diagnostics.md に三つの新しいコードを足し、G02052 の「意味」から展開を除く（G02052 は試しの実装で直した）。
- 採択の後、docs/roadmap.md の「`*[式]` の展開とプラグインへの引数」から展開を除く。キーワード引数の部分は、[docs/adr/0110](0110-keyword-arguments-to-plugins.md) の実装で除く（試しの実装では、展開の部分を除いた）。

## 実装しないこと

- 字の位置に文字列でない値（`[= 1]` や展開した数）を書いたときの、空の字のメッセージを直すこと。展開に限らない今の振る舞いであり、字の位置が式を受け取るかを決める別の ADR で扱う。
- 展開の値を S1 まで遅らせること。展開は S0 で値の決まる式に限る。`doc` を参照する展開は、`[= ...]` の引数と同じ扱いになる。
- `@import` の展開。

## テスト設計

試しの実装で、次のテストを先に書き、失敗することを確かめてから実装した（`@style` の G02114 のテストだけは、実装の後に足した）。

golem-eval の `FileSpec` の `spreadTests` では、次のことを確かめる。

- `[number-text *[[12]]]`、`[number-text 12 **[{style: "tcy"}]]`、`[number-text *[[12]] **[{style: "kanji"}]]` が、書いた引数と同じ数のノードになる。`[kenten **[{shape: "dot"}]: x]` は誤りがなく、`shape: "nope"` は G02039 になる。
- 空の配列と空の連想配列は何も展開しない。
- `@page-break *[["recto"]]`、`@blank-line *[[2]]`、コードブロックの開始の行の `**[{numbers: true}]` が、書いた引数と同じになる。
- 属性の `@label *[["p"]]` がラベルになる。
- `@page-break "recto"` と `@label "p"` が、語と同じに読まれる。
- `[number-text *[12]]` が G02111、`[number-text 12 **[[1]]]` が G02112 で、コマンドを実行しない（`a[number-text *[12]]b` は `ab`）。`@blank-line *[2]` も G02111 である。
- `[number-text 12 style=kanji **[{style: "tcy"}]]` が G02077 で、前の `style=kanji` が使われる。
- `[number-text *[nope]]` の誤りが、`[number-text [= nope]]` と同じである。
- `@manifest **[...]`、`@style-def character x **[...]`、`@style *[["note"]]` が G02114 になる。

golem-eval、golem-parser、golem-driver、golem-lsp、golem-plugin の既存のテストは、変えずに通った。

## トレードオフ

展開した要素を書いた引数に戻すので、展開した数は `[= 数]` と同じになり、語の `12` とは区別される。
数を語だけで受け取る位置（`@page-lines` の `+1` など）には、数を展開しても入らず、文字列の `"+1"` を展開する必要がある。
展開の値をコマンドごとに解釈する案は、位置ごとに規則が増えるので採らなかった。

`@style` に展開を書けないので、段落スタイルの名前を式で選ぶことはできない。
`@style` の本体の行の扱いを評価の後に決めるには、本体の構文解析の後の段落の分け方を変える必要があり、展開のためだけには大きすぎる。

## 決めたことの記録

- **組み込みのコマンドの展開**：メンテナーが、範囲の外とせず、rc4 までに要るので今行うと決めた（2026-10-29）。コマンドごとの規則、展開を受け付けないコマンド、G02077、型の誤りのコードをプラグインと揃えることを、この草稿で決めるよう求めた。
- **コマンドごとの規則**：この草稿は、展開した要素を書いた引数に戻す一つの規則にし、コマンドごとの違いは今の読み方（値、自然数、範囲、字、語だけ）に任せる案にした。「語だけ」の位置は、同じ字の文字列リテラルも受け取るように改める案にした。
- **プラグインのコマンドの `<数>...<数>` の語**：メンテナーが、範囲の値とすると決めた（2026-11-04）。展開した範囲の値も、同じくプラグインに範囲として届く。語の読み方は [docs/adr/0111](0111-argument-words-as-number-literals.md) が定める。
- **G02052 に残る原因**：メンテナーが、一つの原因に一つのコードとすると決めた（2026-11-04）。[docs/adr/0132](0132-setting-command-codes-by-cause.md) に分けた。
- **展開を受け付けないコマンド**：この草稿は、評価の前に引数を読む `@manifest`、`@style-def`、`@style` を G02114 とし、`@import` は構文の誤り（G03009）のままとする案にした。
