# ADR 0454: 言語サーバーで `@set` の変数の名前を変えられるようにする

Status: accepted-pending

## 文脈

[root ADR 0451](0451-import-listed-names-without-a-namespace.md) は、LSP の改名について「関数と `@set` の変数の改名は、`.gm` に出す名前が変わるときだけ、名前の並びと名前空間なしの呼び出しも書き換える」と決めた。
ところが、言語サーバーには `@set` の変数の名前を変える機能がもともと無い。
そのため、0451 の実装では、この規則は `.emet` の関数にだけ当てはまった。

メンテナーは、2026-11-26 に、`@set` の変数の改名を ADR で決めるよう求めた。
この ADR は、改名の対象、書き換える箇所、改名を断る場合を決める。
改名の対象を集める処理は参照の検索と同じなので、参照の検索が取り込んだ先の参照を落とす今の欠けも、あわせて直す。

## 調査した事項

origin/main（[3d8d5a9](https://github.com/tett23/golem/commit/3d8d5a9caf94abafc7b58980bc6aa656e4a2084b)）で、次のことを確かめた。

- `textDocument/rename` は、`.emet` なら `renameEmet`、それ以外は style.toml のレイアウトの値の `renameLayoutValue`、それでもなければラベルの `renameLabel` に振り分ける（[Server.hs#L394-L403](https://github.com/tett23/golem/blob/3d8d5a9caf94abafc7b58980bc6aa656e4a2084b/modules/golem-lsp/src/Golem/Lsp/Server.hs#L394-L403)）。
  `renameLabel` は、ラベルの定義と参照のほかの位置では `NotALabel` を返す（[Features.hs#L431-L441](https://github.com/tett23/golem/blob/3d8d5a9caf94abafc7b58980bc6aa656e4a2084b/modules/golem-lsp/src/Golem/Lsp/Features.hs#L431-L441)）。
  そのため、変数の上で名前を変えようとすると、ラベルでないという誤りになる。
- 言語サーバーは、変数の出現をすでに集めている。
  `@set` の定義と名前空間なしの参照は `OccVar Nothing`、名前空間つきの参照は `OccVar (Just ns)`、`@import` の名前の並びの名前は `OccListed` である（[Features.hs#L118-L132](https://github.com/tett23/golem/blob/3d8d5a9caf94abafc7b58980bc6aa656e4a2084b/modules/golem-lsp/src/Golem/Lsp/Features.hs#L118-L132)、[Features.hs#L149-L157](https://github.com/tett23/golem/blob/3d8d5a9caf94abafc7b58980bc6aa656e4a2084b/modules/golem-lsp/src/Golem/Lsp/Features.hs#L149-L157)、[Features.hs#L203-L204](https://github.com/tett23/golem/blob/3d8d5a9caf94abafc7b58980bc6aa656e4a2084b/modules/golem-lsp/src/Golem/Lsp/Features.hs#L203-L204)）。
  式の中のどの名前も `OccVar` になるので、組み込みの式の名前（`pi` など）や未定義の名前も `OccVar` である。
- 参照の検索の `varRefs` は、定義したファイルの名前空間なしの出現と、`* as` で取り込んだファイルの名前空間つきの出現を返す（[Features.hs#L380-L405](https://github.com/tett23/golem/blob/3d8d5a9caf94abafc7b58980bc6aa656e4a2084b/modules/golem-lsp/src/Golem/Lsp/Features.hs#L380-L405)）。
  `{ 名前 }` で取り込んだファイルの、名前の並びの名前と名前空間なしの参照は返さない。
  また、取り込んだファイルの名前空間なしの参照の上で参照を探すと、そのファイルの中だけを探し、定義したファイルを探さない。
- 取り込んだファイルは、取り込んだ変数を再び公開しない（[File.hs#L300](https://github.com/tett23/golem/blob/3d8d5a9caf94abafc7b58980bc6aa656e4a2084b/modules/golem-eval/src/Golem/Eval/File.hs#L300) の `erExports = stVars st`）。
  そのため、変数の出現は、定義したファイルと、そのファイルを直接取り込んだファイルにしかない。
- 柱の書式の `{set.<名前>}` は、そのページのファイルで `@set` した変数か、そのファイルが名前を並べて取り込んだ変数を指す。
  `{set.<名前空間>.<名前>}` は、そのページのファイルが `* as <名前空間>` で取り込んだ変数を指す（仕様書の柱の書式の表）。
  どちらも、どのファイルの変数を指すかは、柱を組むページのファイルで決まる。
  言語サーバーは、この書式の中の名前を出現として集めていない。
- 同じファイルで同じ変数を二度 `@set` すると、G02024 のエラーになる（`docs/diagnostics.md` の G02024）。
- 仕様書は、言語サーバーの名前の変更を、ラベルと `.emet` の名前について書き、`@set` の変数については書かない。

## 実装すること

### 改名の対象

`.gm` の次の位置で `textDocument/rename` を受けたとき、その位置が指す `@set` の変数の名前を変える。

- `@set` の定義の名前
- 名前空間なしの参照（`[= price]`）
- 名前空間つきの参照（`[= ns.price]`）の名前の部分
- 変数のファイルから並べた `@import` の名前（`{ price }`）

どの位置からも、指す変数（定義したファイルと名前の組）を一つに決め、その変数の出現をすべて書き換える。
名前空間なしの参照は、そのファイルで `@set` した変数なら、そのファイルの変数を指し、名前を並べて取り込んだ変数なら、取り込んだ先のファイルの変数を指す。
名前空間つきの参照は、その名前空間で取り込んだファイルの変数を指す。

振り分けは、`renameLayoutValue` の後、`renameLabel` の前に置く。
位置が `OccVar` か `OccListed` で、`@set` の変数を指さないとき（組み込みの式の名前、未定義の名前、`vars.` と `meta.` の名前、`.emet` から並べた名前）は、`@set` の変数ではないという誤りを返す。

### 書き換える箇所

変数 v（ファイル F の名前 n）の改名では、次の箇所を新しい名前にする。

1. F の `n` のすべての `@set` の名前と、F の名前空間なしの参照。
   F が G02024 のエラーを持ち、`n` を二度 `@set` していても、どちらも書き換える。
2. F を `* as ns` で取り込んだファイルの、`ns.n` の名前の部分。
3. F から名前を並べて取り込んだファイル H の、名前の並びの `n` と、H の名前空間なしの参照のうち v を指すもの。

名前空間の名前は変えない。

F を取り込んだファイルは、`@import` に書いたパスの文字列ではなく、取り込みのグラフ（その `@import` の行が指すファイル）で決める。
今の言語サーバーは、書いたままのパスと F のパスの一致で探すので、`./common/v.gm` のように書いたファイルを見落とす（[Features.hs#L401](https://github.com/tett23/golem/blob/3d8d5a9caf94abafc7b58980bc6aa656e4a2084b/modules/golem-lsp/src/Golem/Lsp/Features.hs#L401)）。
評価が取り込みのグラフで変数の表を引くのは [root ADR 0455](0455-resolve-variable-imports-through-the-import-graph.md) なので、この ADR は 0455 の後に実装する。

### 改名を断る場合

次のときは、名前を変えずに誤りを返す。
誤りのメッセージは日本語で、断った理由ごとに別の文にする。

- 新しい名前が、`@set` の名前として書けない形か、予約語（`doc`、`meta`、`vars`、`true`、`false`、`nil`）である。
- 書き換えた後に、書き換えるファイルのどれかで、名前が重なる。
  - F では、ほかの `@set` の変数、F が名前を並べて取り込んだ名前、組み込みの式の名前（`join`、`pi`、`e` など）と重なるとき。
  - H では、H の `@set` の変数、ほかの `@import` が並べた名前、組み込みの式の名前と重なるとき（0451 の G02272、G02274、G02277 になるとき）。
- H が、`n` について、すでに G02272、G02274、G02277 のどれかのエラーを持つ。
  H の名前空間なしの `n` がどの変数を指すかを、一つに決められないためである。
- style.toml の柱の書式に、古い名前か新しい名前の `{set.<名前>}` か、名前の部分が古い名前か新しい名前の `{set.<名前空間>.<名前>}` がある。
  柱の書式がどのファイルの変数を指すかはページのファイルで決まり、同じ名前を `@set` したほかのファイルの変数も指しうるので、書き換えるかを言語サーバーが決められないためである。
  誤りのメッセージに、その書式の位置を示す。
- 書き換えるファイルのどれかに、構文の誤りがある。

### 参照の検索

参照の検索（`textDocument/references`）は、改名で書き換える箇所と同じ箇所を返す。
今の欠けのうち、名前を並べて取り込んだファイルの名前の並びと名前空間なしの参照を足し、取り込んだファイルの参照の上から探しても、定義したファイルの出現を返すようにする。

### 文書

仕様書の LSP の節に、`@set` の変数の改名と、参照の検索の範囲を書く。

採択したら、0451 のステータスに `{"part":"ツール","by":["docs/adr/0454-rename-set-variables-in-the-language-server.md"],"kind":"supplement"}` を記録する。

## 実装しないこと

マニフェストの `[vars]` の変数の改名はしない。
柱の書式の中の変数の名前の書き換えはしない（改名を断る）。
`willRenameFiles` によるファイルの移動と改名の扱いは変えない。
名前空間の名前の改名は足さない。
`.gm` の名前の並びから `.emet` の関数の名前を変えることは、この ADR では足さない。

## 不変条件

- I1: 改名が成り立つとき、書き換える箇所の集合は、同じ位置で参照を探した結果の集合と等しい。
- I2: 改名の対象の変数のどの出現の位置で改名を受けても、書き換える箇所の集合は同じである。
- I3: 改名が成り立つとき、改名を当てた後のプロジェクトの出力は改名の前と同じであり、diagnostics のコードの集合も改名の前と同じである。
- I4: 改名を断る場合のどれかに当たるとき、または位置が `@set` の変数を指さないとき、書き換えは返らず、誤りが返る。
- I5: ファイル F の変数の改名は、同じ名前を `@set` したほかのファイルの変数の出現を書き換えない。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| F だけで使う変数 | F の定義と参照だけ | I1, I3 |
| G02024 の原稿で、`@set` を二度書いた変数 | 二つの `@set` と参照 | I1 |
| `* as ns` で取り込んだ G の `ns.price` から | F と G の両方 | I1, I2 |
| `{ price }` で取り込んだ H の名前の並びから | F と H の並びと参照 | I1, I2 |
| H の `[= price]` から | 前の行と同じ | I2 |
| 同じ名前を `@set` した別のファイル K | K は書き換えない | I5 |
| 新しい名前が `meta` | 誤り | I4 |
| F で、新しい名前が F の並べた名前と重なる | 誤り | I4 |
| F で、新しい名前が `pi` | 誤り | I4 |
| H で、新しい名前が H の `@set` と重なる | 誤り | I4 |
| H が `price` について G02274 を持つ | 誤り | I4 |
| F が `@set pi = 3`、H が `{ pi }`（H に G02277） | 誤り | I4 |
| `@import ./common/v.gm { price }` と書いた H の名前の並びから | F と H の並びと参照 | I1, I2 |
| style.toml に `{set.price}` | 誤り | I4 |
| style.toml に新しい名前の `{set.cost}` | 誤り | I4 |
| `[= pi]` の `pi` の上 | 誤り（`@set` の変数ではない） | I4 |

## 受けいれ条件

なし。
不変条件のテストで足りるためである。

## テスト設計

root ADR 0454 I1 から I5 を名前の先頭に置いたテストを golem-lsp に足す。
定義したファイル、`* as` で取り込むファイル、名前を並べて取り込むファイル、同じ名前を `@set` した別のファイルを持つプロジェクトを作り、表の入力を列挙して確かめる。
I3 は、改名を当てた原稿を評価し、diagnostics と出力を改名の前と比べて確かめる。
テストは、実装の前に書いて落ちることを確かめる。

## トレードオフ

柱の書式に古い名前か新しい名前があるときに改名を断るので、柱に出す変数は、手で名前を変える。
書き換えると、同じ名前を使うほかのファイルの柱が変わり、書き換えないと、改名したファイルの柱が値を失うか、別の値を拾う。
どちらを選んでも、書き手の意図と違う結果を黙って作りうるので、断って書き手に任せる。
