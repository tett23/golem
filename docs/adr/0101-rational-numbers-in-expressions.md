# ADR 0101: 式の言語の数を自然数、整数、有理数の三つの型にし、浮動小数点数をなくす

ステータス: 採択（未実装）

## 文脈

式の言語の数は、任意精度の整数と倍精度の浮動小数点数の二つである（[golem-eval ADR 0001](../golem-eval/adr/0001-expression-language-and-numerics.md)、[docs/markup.md](../markup.md) の「数の規則」）。
評価器の値の型は [`VInt !Integer` と `VFloat !Double`](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-eval/src/Golem/Eval/Value.hs#L16-L24) を別の構成子に持つ。
浮動小数点数を決定的にするために、これまでの ADR は規則を一つずつ足してきた。

- NaN と無限大はエラーにし、負のゼロは正のゼロにそろえる（[`mkFloat`](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-eval/src/Golem/Eval/Expr.hs#L40-L43) と [`finite`](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-eval/src/Golem/Eval/Number.hs#L24-L29)）。
- 整数を倍精度に変える箇所で、あふれを G02004 にする（[`asDouble`](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-eval/src/Golem/Eval/Expr.hs#L116-L128)、[golem-eval ADR 0005](../golem-eval/adr/0005-float-overflow.md)）。
- 整数と浮動小数点数の比較は、両方を有理数にして正確に比べる（[`compareNum`](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-eval/src/Golem/Eval/Expr.hs#L137-L144)）。
- 整数どうしの `/` と累乗は、正確な有理数を一度だけ倍精度に丸める（[`binary` の `Div` と `Pow`](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-eval/src/Golem/Eval/Expr.hs#L151-L181)）。
- 累乗は、正確な計算の量の上限（G02095）と倍精度の範囲（G02004 と 0）を、整数の演算だけで判定する（[`powRounded`](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-eval/src/Golem/Eval/Expr.hs#L264-L326)、[golem-eval ADR 0006](../golem-eval/adr/0006-exact-power-limit-before-range.md)、[golem-eval ADR 0007](../golem-eval/adr/0007-power-limit-message.md)）。
- `round` と `fixed` は、倍精度の値を最短の十進表記に直してから十進数として丸める（[`roundHalfAway`](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-eval/src/Golem/Eval/Number.hs#L58-L70)）。

どの規則も、計算の途中で有理数を使い、最後に倍精度へ丸めている。
倍精度に丸めるのは、値の型が倍精度だからである。
値の型を有理数にすれば、丸めの規則とあふれの判定の多くが要らなくなる。
メンテナーは、浮動小数点数の表現の揺れや、プラグインが返す特殊な値（NaN、無限大、負のゼロ）に個別に対応するより、式の言語から浮動小数点数をなくすほうがよいと判断した（[ロードマップ](../roadmap.md) の「数を有理数に寄せる」）。

数の型を一つの有理数にまとめる案もあった。
`5`、`5.0`、`10 / 2` が同じ値になり、規則は少なくなる。
メンテナーはこの案を退け、自然数、整数、有理数を別々の型にすると決めた。
後で評価を速くするときに、自然数と整数の演算を有理数の演算（既約にするための最大公約数の計算を含む）から切り離せるようにするためである。
型が値から決まるのではなく式から決まれば、評価の前に型がわかる。
[ADR 0102](0102-natural-number-type.md) は、この性質を使って、負になりうる自然数を評価の前に調べる。

### 今の数の通り道

小数のリテラルは、パーサーが読む時点で倍精度になる。
文法の [`Number`](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-parser/grammar/Golem.hpeg#L455-L456) は `[0-9]+ ('.' [0-9]+)?` であり、指数の書き方を持たない。
[`Golem.Parser.Lower.number`](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-parser/src/Golem/Parser/Lower.hs#L353-L367) は、小数を正確な有理数から一度だけ丸めて AST の [`EFloat Double`](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-parser/src/Golem/Parser/AST.hs#L99-L101) にする。

浮動小数点数が CBOR に出るのは、次の二か所だけである。

- **遅延した式のリテラル**：意味論 IR の式の [`[1, span, float]`](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-doc/schema/golem-doc.cddl#L74-L76)。`doc` を参照する式は S1 まで評価を遅らせ、S0 の名前をその値で置き換えてから IR に入れる（[`substitute`](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-eval/src/Golem/Eval/File.hs#L1568-L1578)）。このとき [`valueToExpr`](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-eval/src/Golem/Eval/Value.hs#L36-L47) が `VFloat` を `EFloat` に戻す。
- **プラグインのコマンドの引数**：CDDL の [`value`](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-doc/schema/golem-doc.cddl#L89-L92) は `int64 / float / tstr / bool / null / [* value]` であり、[`valueTerm`](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-plugin/src/Golem/Plugin.hs#L229-L237) が `VFloat` を [`floatTerm`](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-doc/src/Golem/Doc/Cbor.hs#L74-L81) で書く。

プラグインからホストへの向きでは、浮動小数点数は遅延した式の中にしか書けない。
応答は `inlines` か `document` であり、ほかに数を持つ欄（`[number-text]` の数、アキの量）は整数か整数の組である。
しかも [`checkOutput`](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-plugin/src/Golem/Plugin.hs#L289-L293) は、プラグインが返した `DeferredExpr` が要求の中のどれかと等しいことを求める。
今のプラグインが新しい値をホストに持ち込む経路はない。
復号の [`asFloat`](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-doc/src/Golem/Doc/Cbor.hs#L259-L264) は NaN と無限大を拒まないが、要求の式と等しくなれないので、`checkOutput` で落ち、G06009 になる。

意味論 IR は、すでに有理数を一つ持つ。
アキの `zw` の量は [`AkiZw !Rational`](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-doc/src/Golem/Doc/IR.hs#L244-L246) であり、CDDL では [`[int64, 1..9223372036854775807]`](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-doc/schema/golem-doc.cddl#L67) の組で書く。
IR の整数は 64 ビットの符号付き整数に限る（[golem-doc ADR 0006](../golem-doc/adr/0006-integer-range-in-ir.md)）。

### 今の原稿

リポジトリの中で小数や `/` を式に書いている原稿は、決定性の検査の式の集合（[`scripts/determinism/exprs.gm`](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/scripts/determinism/exprs.gm)）と、使い手のマニュアルの式の説明（`manual/chapters/03-markup.gm` と `manual/appendices/a-markup.gm`）である。
マニュアルは `[= 1.1 ** 10]` を埋め込んで `2.5937424601000023` と組み、`[= fixed(price * 1.1, 0)]` を例に挙げる。
v0.1.0 は 1.0.0 の前であり、互換を壊してよい（[ロードマップ](../roadmap.md) の「1.0 で約束すること」）。

### この ADR と組になる ADR

[ADR 0102](0102-natural-number-type.md) は、自然数を求める箇所の受け取り方と、負になりうる値を評価の前に調べる仕組みを決める。
[ADR 0103](0103-single-place-for-unit-conversions.md) は、長さの単位の変換を一か所にまとめる。
三つとも数の扱いを変え、ロードマップは同じ時期に、プラグインの項目より前に扱うとしている。
数の型と演算の規則（下の「数の型」と「演算」）は、この ADR が決め、[ADR 0102](0102-natural-number-type.md) が使う。

## 実装すること

### 数の型

数の型を三つにする。

- **自然数**：0 以上の整数。
- **整数**：負の数を含む整数。
- **有理数**：分数で書ける数。

三つは包含の関係にあり、自然数は整数でもあり、整数は有理数でもある。
型は値からではなく、式から決まる。
`10 / 2` の値は 5 だが、型は有理数である。
`5 - 2` の値は 3 だが、型は整数である。
どの型も、値の上限（下の「計算の量の上限」）のほかに範囲の制限を持たない。

```haskell
data Value
  = VNat !Natural    -- 自然数
  | VInt !Integer    -- 整数。0 以上の値も持ちうる
  | VRat !Rational   -- 有理数。既約で分母は正。整数の値も持ちうる
  | VString !Text
  | VBool !Bool
  | VNil
  | VArray ![Value]
  | VHash !(Map Text Value)
```

`VInt` と `VFloat` の今の構成子は、この三つに置き換わる。
評価した値の構成子は、[ADR 0102](0102-natural-number-type.md) の評価の前の解析が式に推論した型とつねに一致する。
この一致を、下の「テスト設計」のプロパティテストで確かめる。

### 変換

- **広げる変換**：自然数から整数へ、整数から有理数へは、値を変えずにいつでも変える。演算で型の違う数を組み合わせるときに、暗に行う。
- **狭める変換**：自然数か整数を求める箇所に広い型の値が届いたときだけ、値で判定して狭める。整数の値を持つ有理数は整数として、0 以上の整数は自然数として受け取る。`div(4.0, 2)` は使え、`div(1.5, 1)` は今と同じく G02001 になる。自然数を求める箇所の規則と誤りのコードは [ADR 0102](0102-natural-number-type.md) が決める。
- 狭める変換を書き手が明示する関数（`nat(x)` など）は設けない。`floor`、`ceil`、`round`、`abs` が整数か自然数を返すので、多くはそれで足りる。

### リテラル

- 整数のリテラル `[0-9]+` は自然数である。式の言語は負の数のリテラルを持たず、`-5` は自然数の `5` に単項の `-` を当てた式であり、整数になる。
- 小数のリテラル `[0-9]+ '.' [0-9]+` は、正確な十進数の有理数として読む。`0.1` は `1/10` である。倍精度には丸めない。値が整数でも型は有理数であり、`3.0` は有理数の 3 である。
- 指数の書き方を加える。文法の `Number` を `[0-9]+ ('.' [0-9]+)? ('e' [+-]? [0-9]+)?` とし、`15e-1` は `15 × 10^-1 = 3/2`、`1.5e3` は `1500` と、正確な有理数として読む。指数を持つリテラルは、値によらず有理数である。`E` の大文字は読まない。
- 指数の絶対値が 1300 を超えるリテラルは、`10` の累乗を作る前に G02086 とする。2^4096 は約 1.04 × 10^1233 なので、指数が 1300 を超えれば、仮数がどの値でも下の上限の外になる。
- AST の数のリテラルを、型ごとの三つにする。`ENat Natural`（パーサーが整数のリテラルから作る）、`EInt Integer`（パーサーは作らず、S0 の値を式に戻すときとプラグインの出力の復号で作る）、`ERat Rational` である。`EFloat Double` はなくす。

ロードマップの「式の言語の指数の書き方」は、この ADR に含める。
指数の書き方は、数を有理数として読むと決めれば、値の決め方が一つに定まる。
別の ADR にすると、倍精度として読む規則を一度書いてから消すことになる。

### 演算

演算はすべて正確に行い、丸めない。
結果の型は、引数の型だけで決まる。
表の「広い型」は、二つの引数の型のうち広いほう（自然数、整数、有理数の順に広い）を指す。

| 演算 | 自然数と自然数 | 整数を含み、有理数を含まない | 有理数を含む |
| --- | --- | --- | --- |
| `+`、`*` | 自然数 | 整数 | 有理数 |
| `-`（二項） | 整数 | 整数 | 有理数 |
| `/` | 有理数 | 有理数 | 有理数 |
| `min`、`max` | 自然数 | 整数 | 有理数 |

一つの引数の演算と関数は次のとおりである。

| 演算 | 自然数 | 整数 | 有理数 |
| --- | --- | --- | --- |
| `-`（単項） | 整数 | 整数 | 有理数 |
| `abs` | 自然数 | 自然数 | 有理数 |
| `floor`、`ceil`、`round(x)` | 自然数 | 整数 | 整数 |
| `round(x, n)` | 自然数 | 整数 | 有理数 |
| `sqrt` | 有理数 | 有理数 | 有理数 |

- `/`：正確な商を返す。割る数が 0 なら、今と同じく G02003 とする。`7 / 2` は `7/2`、`10 / 2` は有理数の 5 である。
- `**`：指数は整数の値に限る。整数でない指数は、今と同じく G02006 とする。指数の型が有理数でも、値が整数なら受け取る（`2 ** 2.0` は 4）。底が 0 で指数が負なら G02003 とする。`(a/b) ** k` は `a^k / b^k`、`(a/b) ** -k` は `b^k / a^k` として計算する。結果の型は、指数の型が自然数なら底の型、指数の型が整数か有理数なら有理数とする。`2 ** 3` は自然数、`2 ** (3 - 1)` は有理数の 4 である。
- `div(a, b)` と `a % b`：今と同じく整数の値にだけ使え、整数でない値は G02001 とする。`div` は負の無限大の方向への切り捨て、`%` は割る数の符号に合わせる規則を変えない。`div` の結果は、二つの引数がどちらも自然数なら自然数、ほかは整数とする。`%` の結果は、割る数の型が自然数なら自然数、ほかは整数とする。割る数が正なら、余りは割られる数の符号によらず 0 以上だからである。
- `round(x)`、`round(x, n)`：`x` の正確な値を、小数点以下 `n` 桁の十進数に、0 から遠い方向への四捨五入で丸める。最短の十進表記に直す手順は要らなくなる。`round(2.675, 2)` は `2.68` である。自然数と整数の `x` は、`n` によらず値を変えない。
- `fixed(x, n)`：`round(x, n)` と同じ値を、小数点以下をちょうど `n` 桁で書いた文字列にする。
- `min`、`max`：今と同じく正確に比べ、等しい値のうち先の引数を残す。残した値を、表の型に広げて返す。`min(1, 1.0)` は有理数の 1 である。
- `len`：自然数を返す。

### 比較

- `==`、`!=`、`<`、`<=`、`>`、`>=` は、型によらず値で比べる。`5 == 10 / 2` も `5 == 5.0` も真である。
- 配列と連想配列の `==` も、中の数を値で比べる。今は `[1] == [1.0]` が偽になる（[`equal`](https://github.com/tett23/golem/blob/466884dab4f15f163e2f7eb4f572102af2dad300/modules/golem-eval/src/Golem/Eval/Expr.hs#L211-L214) は配列を導出した `Eq` で比べる）。型を分けた理由は評価の速さであり、値の意味ではないので、等しさは値だけで決める。

### 計算の量の上限

整数の絶対値の上限（2 の 4096 乗未満、[docs/adr/0035](0035-security-hardening.md)）を、三つの型に同じく当てる。
有理数では、既約の分子の絶対値と分母のそれぞれに当てる。

- 演算の結果の自然数か整数の絶対値、または有理数の既約の分子の絶対値か分母が 2 の 4096 乗以上なら、G02086 とする。
- 累乗は計算の前に判定する。底の分子か分母の絶対値を `a` とし、`(a のビットの数 - 1) × |k|` が 4096 以上なら、計算せずに G02086 とする。そうでなければ、今の整数の累乗と同じく計算してから確かめる。底が既約なので、`a^k` も既約であり、判定は分子と分母を別々に行えばよい。

### 有理数で表せない値と、桁の定まらない数の丸め

`sqrt`、`pi`、`e` は、有理数で表せない値を返しうる。
また、分母に 2 と 5 のほかの素因数を持つ有理数（循環小数になるもの）は、十進の位取りで書き切れない。
どちらも、次の一つの規則で十進数に丸める。
この規則を**有効数字 17 桁の丸め**と呼ぶ。

1. 値が 0 なら 0 とする。
2. 絶対値 `q` について、`10^p ≤ q < 10^(p+1)` となる整数 `p` を、整数の比較だけで求める。
3. 小数点以下の桁数を `k = max(0, 16 - p)` とする。整数部が 17 桁未満なら有効数字が 17 桁になり、17 桁以上なら整数部をすべて残して小数点以下を書かない。
4. `q × 10^k` を最も近い整数に丸め、`10^k` で割って符号を戻す。

ちょうど半分（二つの候補から等距離）になることはない。
半分の点は分母が `2 × 10^k` を割り切る有限小数であり、無理数と、分母に 2 と 5 のほかの素因数を持つ既約の有理数は、有限小数と等しくなれないからである。
そのため、無理数と循環小数で同じ規則を使え、等距離の場合の規則は要らない。

17 桁にするのは次の二つによる。

- 倍精度の値を元に戻せる最短の十進表記は、最大で有効数字 17 桁である。今の Golem が `pi` などを本文に書くときの桁数を下回らない。
- 無理数と循環小数で同じ桁数にすると、書き手が覚える規則が一つで済む。

整数部を丸めないのは、`10 ** 30 / 3` のような大きな値で、整数部の下の桁を 0 に置き換えた表記（`333333333333333330000000000000`）が、存在しない桁を書くことになるからである。
今の倍精度の表記はこの置き換えを行っているが、正確な値を持てるようになった後に残す理由はない。

この規則を、次の二か所で使う。

- **`sqrt`、`pi`、`e`**：有効数字 17 桁に丸めた有理数（有限小数）を返す。`pi` は `3.1415926535897932`、`e` は `2.7182818284590452` とする。`sqrt(x)` は、`x` が負なら G02101 とする（下の「diagnostic」）。`x` が有理数の平方（既約の分子と分母がどちらも平方数）なら、正確な平方根を返す。そうでなければ、有効数字 17 桁の丸めを返す。`sqrt` は整数の平方根（ニュートン法で `golem-eval` の中に実装する。GHC の base は整数の平方根を持たない）と整数の比較だけで計算し、倍精度を使わない。`x × 10^(2k)` の整数部の平方根 `s` を取り、`(s + 1/2)^2` と `x × 10^(2k)` を比べて丸めの向きを決める。
- **本文への埋め込み**：循環小数になる有理数は、値を変えずに持ち、本文に書くときにだけ有効数字 17 桁に丸める（下の「本文に埋め込むときの表記」）。

### 本文に埋め込むときの表記

数を本文に埋め込むときは、型によらず、値だけで次の規則で書く。

- 整数の値は、今と同じく十進の数字で書く。`[= 10 / 2]` は「5」である。
- 整数でない有理数のうち、分母の素因数が 2 と 5 だけのもの（有限小数になるもの）は、正確な値を位取りで書く。
- 分母に 2 と 5 のほかの素因数を持つ有理数（循環小数になるもの）は、有効数字 17 桁に丸めて位取りで書く。`[= 1 / 3]` は「0.33333333333333333」、`[= 2 / 3]` は「0.66666666666666667」、`[= 10 / 3]` は「3.3333333333333333」である。
- どの場合も、末尾の 0 は書かず、指数表記と桁区切りは使わない。負の符号は ASCII の `-` で書く。
- 書く表記の小数点以下が 1000 桁を超える数は、G02102 とする（下の「diagnostic」）。`round` と `fixed` の桁の上限（1000）にそろえる。有限小数でも、丸めた循環小数でも同じである。`[= 1 / (3 * 10 ** 980)]` は小数点以下 997 桁で書けるが、`[= 1 / (3 * 10 ** 990)]` は 1007 桁になり G02102 である。

丸めるのは本文に書くときだけで、値は丸めない。
`[= 1 / 3 * 3]` は「1」である。
桁数を決めたい書き手は、今と同じく `round` か `fixed` を使う。

この規則は、仕様書（`docs/markup.md` の「数の規則」）と使い手のマニュアル（`manual/chapters/03-markup.gm` と `manual/appendices/a-markup.gm`）に書く。

### 意味論 IR と CBOR

CDDL に有理数を足す。

```cddl
; 有理数。既約で、分母は 1 以上（RFC 8949 の登録済みのタグ 30）。
; 整数の値を持つ有理数の型の数は、分母を 1 で書く
rational = #6.30([numerator: int64, denominator: 1..9223372036854775807])
```

タグ 30 の定義は、分母が 0 でない符号なしの整数であることだけを求め、分母の 1 も既約でない組も許す。
Golem は既約で書き、既約でない組を受け取ったら `Golem.Doc.Validate` で拒む。

- 式の数のリテラルを、型ごとに書く。整数は今と同じ `[0, span, int64]`、自然数は新しい `[12, span, uint64]`、有理数は新しい `[13, span, rational]` とする。S1 で評価した値の型が、S0 で推論した型と変わらないようにするためである。
- 式の `[1, span, float]` は、ホストが書かなくなる。タグの番号は使い回さないので、`1` を書いた式は下の「プラグインが返す浮動小数点数」の規則で読む。
- プラグインに渡す `value` を `int64 / rational / tstr / bool / null / [* value]` にする。`float` を除く。自然数と整数は今と同じ `int64` で、有理数は値が整数でもタグ 30 で渡す。`value` には配列があるので、`zw` のような印のない二要素の配列では配列と区別できない。このため、タグ 30 を使う。
- IR に入れる整数、自然数と、有理数の分子と分母は、`int64` の範囲に限る（自然数は `uint64`）。範囲の外の値を IR の欄に入れようとしたら、今と同じく G02091 とする（[golem-doc ADR 0006](../golem-doc/adr/0006-integer-range-in-ir.md)）。メッセージは「分子と分母」を含む文に改める。
- `Golem.Doc.Cbor.floatTerm` と、半精度と単精度を選ぶ `halfExact` は使わなくなるので消す。

### プラグインが返す浮動小数点数

プラグインは浮動小数点数を返してくることがある。
多くの言語の CBOR の符号化は、小数を倍精度で書くからである。
ロードマップのとおり、拒まずに、その値の正確な有理数に変える。

- プラグインが式の中に浮動小数点数（CBOR の major type 7 の半精度、単精度、倍精度）を書いてきたら、復号でその値の正確な有理数に変え、有理数の型のリテラル（`ERat`）とする。`0.1` の倍精度の値は `3602879701896397/36028797018963968` になる。
- 負のゼロは 0 にする。
- 変えた式は、今と同じく `checkOutput` で要求の式と比べる。要求の式が `[13, span, 30([1, 2])]` のとき、プラグインが `[1, span, 0.5]` を返せば等しくなり、受け入れる。正確な有理数が要求のどの式とも等しくなければ、今と同じく G06009 の「要求にない DeferredExpr」とする。
- NaN と、正と負の無限大は、正確な有理数を持たないので、新しいコード G06100 とする（下の「diagnostic」）。

NaN と無限大は、一つのコードにする。
Golem から見た原因は「有限の値を持たない浮動小数点数を書いた」の一つであり、拒む規則も、プラグインの作者がすべき直し方（有限の数を書く）も同じだからである。
どちらだったかは、メッセージの値（`NaN`、`Infinity`、`-Infinity`）で示す。

### プラグインの ABI

CDDL の式と `value` が変わるので、プラグインの ABI が変わる。
ABI のバージョンは [ADR 0052](0052-plugin-abi-version-bump-rule.md) の規則による。
v0.1.0-rc3 は ABI のバージョン 7 を含み、rc3 の後に CDDL と `Validate.hs` は変わっていない。
[ADR 0102](0102-natural-number-type.md) の変更も同じリリースのあいだに入るので、二つの ADR で上がるのは 7 から 8 への一回だけである。

### diagnostic

評価の番号は、評価の段階の 100 から、プラグインの番号はプラグインの段階の 100 からとる（[docs/adr/0061](0061-five-digit-diagnostic-codes.md)）。

| コード | 重大度 | 原因 | メッセージ |
| --- | --- | --- | --- |
| G02101 | error | 負の数の平方根 | `負の数の平方根は求められません` |
| G02102 | error | 本文に書く表記の小数点以下が 1000 桁を超える | `小数点以下が 1000 桁を超える数は本文に埋め込めません。round か fixed で桁数を決めます` |
| G06100 | error | プラグインが式に、有限の値を持たない浮動小数点数を書いた | `<プラグイン>.<コマンド>: 遅延した式に有限でない浮動小数点数（<値>）があります`、`<プラグイン>.<フィルタ>: 遅延した式に有限でない浮動小数点数（<値>）があります` |

循環小数は丸めて書くので、G02102 の原因は桁の上限の一つだけである。

ほかのコードは次のように変わる。

- **G02004**：廃止する。浮動小数点数の値がなくなるので、`結果が NaN か無限大になる演算です` と `整数が大きすぎて浮動小数点数に変換できません` は出なくなり、`負の数の平方根です` は G02101 に移る。`docs/diagnostics.md` で「廃止」にし、番号は使い回さない。
- **G02095**：倍精度に丸めないので、累乗の正確な計算の量の上限は要らなくなる。「廃止」にする。
- **G02086**：メッセージを `数が大きすぎます（整数と、分数の分子と分母の絶対値は 2 の 4096 乗未満に限ります）` に改める。小数の桁数の上限のメッセージは変えない。
- **G02091**：メッセージを `数が意味論 IR に書ける範囲を超えています（整数と、分数の分子と分母は -2 の 63 乗以上、2 の 63 乗未満に限ります）` に改める。
- **G02001**：型の名前（今の `typeName`）を、`整数` と `浮動小数点数` から `自然数`、`整数`、`有理数` に改める。名前は値の構成子から決まる。

### ほかの ADR との関係

この ADR は、次の規則を置き換える。
採択したら、それぞれのステータスの行に、置き換えた部分とこの ADR へのリンクを足す。

- [golem-eval ADR 0001](../golem-eval/adr/0001-expression-language-and-numerics.md)：値の型、数の規則、`pi` と `e` の定義、本文への表記。
- [golem-eval ADR 0005](../golem-eval/adr/0005-float-overflow.md)：整数から浮動小数点数への変換、整数どうしの `/`、累乗の丸め。
- [golem-eval ADR 0006](../golem-eval/adr/0006-exact-power-limit-before-range.md)：累乗の判定の順序と G02095。
- [golem-eval ADR 0007](../golem-eval/adr/0007-power-limit-message.md)：G02095 のメッセージ。

[golem-eval ADR 0006](../golem-eval/adr/0006-exact-power-limit-before-range.md) のテスト設計が挙げる `15e-1` の底のテストは、倍精度の規則を確かめるためのものなので、書かない。
代わりに、下の「テスト設計」で指数のリテラルと累乗を確かめる。
[docs/adr/0076](0076-tests-weaker-than-adr-test-designs.md) が残した課題は、この ADR で閉じる。

### ドキュメント

- `docs/markup.md` の「式文脈」と「数の規則」を書き直す。三つの型、変換、演算の型の表、比較、有効数字 17 桁の丸め、本文への表記を書く。
- 仕様書のプラグインの節の CBOR の説明と ABI のバージョンを改める。

- 開発者のマニュアルの、小数を値として持つ型の説明（`manual-dev/part2/12-purity.gm`）と、プラグインの章の CBOR の数の説明を直す。
- ロードマップの「数を有理数に寄せる」と「式の言語の指数の書き方」を、実装したら消す。

## 実装しないこと

- 浮動小数点数の値と、倍精度で計算する演算を残すこと。
- 型の宣言と、狭める変換を明示する関数。
- 超越関数（三角関数、指数関数、対数関数）。今と同じく持たない。
- 有理数で表せない値を、精度を指定して求める関数（`sqrt(x, 桁数)` など）。有効数字 17 桁を超える精度は、求めがあったら別の ADR で決める。
- 循環小数の表記（`0.(3)` のような括弧や上線）。
- 循環小数を丸めたことを知らせる diagnostic。丸めは本文への表記の規則であり、値は変えない。
- 意味論 IR の bignum。分子と分母は `int64` に限る。
- アキの `zw` の CDDL の表し方（印のない二要素の配列）を、タグ 30 にそろえること。ABI の変更が増えるだけで、`zw` には配列の値と取り違える余地がない。
- 評価を速くすること。型を分けるのはその準備であり、この ADR では演算の速さを測らない。

## テスト設計

先に次のテストを書き、今のコードで失敗することを確かめてから実装する。

### golem-parser

- `5` が `ENat 5`、`0.1` が `ERat (1 % 10)`、`2.50` が `ERat (5 % 2)`、`3.0` が `ERat 3` になること。
- `15e-1` が `ERat (3 % 2)`、`1.5e3` が `ERat 1500`、`1e0` が `ERat 1`、`2e+2` が `ERat 200` になること。
- `1E3` が数のリテラルとして読めないこと。
- `1e1301` と `1e-1301` が、評価で G02086 になり、10 の累乗を作らずに 1 秒以内に終わること。

### golem-eval

- 型：`5` が `VNat`、`-5` と `5 - 2` が `VInt`、`10 / 2` と `3.0` が `VRat` になること。`abs(0 - 3)` が `VNat 3`、`floor(7 / 2)` が `VInt 3`、`div(7, 2)` が `VNat 3`、`div(0 - 7, 2)` が `VInt (-4)`、`(0 - 7) % 2` が `VNat 1`、`2 ** 3` が `VNat 8`、`2 ** (3 - 1)` が `VRat 4`、`min(1, 1.0)` が `VRat 1` であること。
- 比較：`5 == 10 / 2`、`5 == 5.0`、`[1] == [1.0]`、`{"a": 1} == {"a": 2 / 2}` が真であること。
- 性質：任意の式（数のリテラル、`+`、`-`、`*`、`/`、`**`、`div`、`%`、`abs`、`floor`、`min` を組み合わせて生成する）について、評価した値の構成子が、[ADR 0102](0102-natural-number-type.md) の解析が推論した型と一致すること。
- `[= 0.1 + 0.2]` が「0.3」、`[= 0.1 + 0.2 == 0.3]` が真であること（評価器の単体のテスト）。
- `[= 1.1 ** 10]` が「2.5937424601」、`[= 2 ** -3]` が「0.125」、`[= 10 / 2]` が「5」、`[= 7 / 2]` が「3.5」であること。
- 循環小数：`[= 1 / 3]` が「0.33333333333333333」、`[= 2 / 3]` が「0.66666666666666667」、`[= 10 / 3]` が「3.3333333333333333」、`[= 0 - 1 / 3]` が「-0.33333333333333333」、`[= 10 ** 30 / 3]` が 3 を 30 個並べた整数、`[= 1 / 3 * 3]` が「1」であること。`[= round(1 / 3, 4)]` が「0.3333」、`[= fixed(2 / 3, 2)]` が「0.67」であること。
- 桁の上限：`[= 2 ** -1001]` が G02102（小数点以下 1001 桁）、`[= 2 ** -1000]` が 1000 桁の小数を書くこと。`[= 1 / (3 * 10 ** 980)]` が小数点以下 997 桁で書かれ、`[= 1 / (3 * 10 ** 990)]` が G02102 になること。
- `[= round(2.675, 2)]` が「2.68」、`[= round(0 - 2.5)]` が「-3」、`[= fixed(1.005, 2)]` が「1.01」であること。今は 1.005 の最短表記を丸めて「1.01」なので、変わらないことも確かめる。
- `[= pi]` が「3.1415926535897932」、`[= e]` が「2.7182818284590452」、`[= sqrt(2)]` が、有効数字 17 桁に丸めた 1.4142135623730950 の末尾の 0 を書かない「1.414213562373095」であること（17 桁めの後は 4 なので切り捨て）。`[= sqrt(9 / 4)]` が「1.5」、`[= sqrt(10 ** 100)]` が 10^50、`[= sqrt(2 * 10 ** 40)]` が整数部を丸めない「141421356237309504880」であること。`sqrt(0 - 1)` が G02101 であること。
- 性質：分母に 2 と 5 のほかの素因数を持つ任意の有理数について、有効数字 17 桁の丸めの結果が、二つの候補から等距離にならないこと。
- `div(4.0, 2)` が 2、`div(1.5, 1)` が G02001、`4.5 % 2` が G02001 であること。
- `(2 ** 4095) / 3` が値を返し、`1 / 2 ** 4095 / 2`（分母が 2 の 4096 乗）が G02086 であること。累乗では、`(3 / 2) ** 2584` が値を返し（3^2584 は約 2^4095.5）、`(3 / 2) ** 2585` が計算した後に G02086 になり（約 2^4097.1）、`(3 / 2) ** 4096` が計算せずに G02086 になること（`(3 のビットの数 - 1) × 4096 = 4096`）。
- `2 ** 2.0` が 4、`2 ** 0.5` が G02006 であること。
- 性質：任意の整数 `a` と 0 でない `b` について `a == div(a, b) * b + a % b`（今のまま）。任意の有理数 `x`、`y` について `x + y - y == x`、`x != 0` なら `x / x == 1` をプロパティテストする。
- 性質：分母の素因数が 2 と 5 だけの任意の有理数について、本文の表記を小数のリテラルとして読み直すと元の値に戻ること。

### golem-doc と golem-plugin

- `ERat (1 % 3)` を含む遅延した式が `[13, span, 30([1, 3])]` に、`ERat 5` が `[13, span, 30([5, 1])]` に、`ENat 5` が `[12, span, 5]` に符号化され、復号すると元に戻ること。CDDL の検証器でスキーマに合うこと。`30([2, 4])` を含む文書を `Validate` が拒むこと。
- プラグインに `1 / 2` を渡すと引数が `30([1, 2])` で、`10 / 2` を渡すと `30([5, 1])` で、`5` を渡すと `5` で届くこと（テスト用の wat のプラグインで、受け取った CBOR のバイト列をそのまま返させて確かめる）。
- プラグインが遅延した式を `[1, span, 0.5]`（倍精度）で返したとき、要求の式が `ERat (1 % 2)` なら受け入れること。`[1, span, 1e-300]` を返したら、要求のどの式とも等しくないので G06009 になること。
- プラグインが `[1, span, NaN]`、`[1, span, Infinity]`、`[1, span, -Infinity]` を返したら、G06100 になり、メッセージの値がそれぞれ `NaN`、`Infinity`、`-Infinity` であること。コマンドとフィルタの両方で確かめる。
- `abiVersion` が [ADR 0052](0052-plugin-abi-version-bump-rule.md) の規則の値であることを、`scripts/ci/abi-version.sh` が確かめること（既存の検査）。

### 決定性

- `scripts/determinism/exprs.gm` を、この ADR の規則の式に書き換え、循環小数の表記の式を加える。x86-64 と aarch64 で同じ出力になることは、今の検査で確かめる。

## トレードオフ

- 今の原稿の出力が変わる。`[= 1.1 ** 10]` は「2.5937424601000023」から「2.5937424601」に、`[= 1 / 3]` は「0.3333333333333333」（16 桁）から「0.33333333333333333」（17 桁）に変わる。浮動小数点数の表記を期待する書き手は少なく、v0.1.0 は互換を壊してよい時期なので、受け入れる。
- 循環小数を丸めて書くので、`[= price / 3]` のような式を書いた書き手は、桁数を決めなくてもビルドできる。そのかわり、17 桁という桁数は書き手が選んだものではない。Golem は迷ったら厳しい側を選ぶが、`1 / 3` はよく書く式であり、毎回エラーにすると書き手の負担が大きい。丸めの規則は一つに決まり、仕様書とマニュアルに書き、値そのものは丸めないので、出力を黙って変えることにはならない。
- 型を三つにすると、演算ごとに結果の型を決める表が要り、`10 / 2` が有理数になるような、値と型の食い違いを書き手が目にしうる。本文の表記と比較は値だけで決まるので、食い違いが見えるのは型の名前を含む diagnostic のメッセージに限られる。
- 有理数の計算は、分母が大きくなると倍精度より遅い。分子と分母を 2 の 4096 乗未満に限るので、一つの演算は数千ビットの整数の演算で終わる。原稿に現れる式の数は少ない。
- `pi`、`e`、`sqrt` の値は、今の倍精度の値（`pi` なら 16 桁の「3.141592653589793」）と最後の桁が変わる。
- 整数部が 17 桁以上の値では、有効数字が 17 桁を超える。存在しない桁を 0 で書くより、正確な整数部を書くほうを選んだ。
- 有理数の型の値は、整数の値でもプラグインにタグ 30 で渡る。プラグインの作者は、整数の値を受け取る引数でもタグ 30 を読む必要がある。型を値から決め直すと、[ADR 0102](0102-natural-number-type.md) の解析の結果とプラグインが受け取る形が食い違う。

## 決めたことの記録

草案で開いていた点を、次のとおりに決めた。

- **値の表し方**：メンテナーが、一つの有理数の型ではなく、自然数、整数、有理数の別々の型にすると決めた。演算の型の表、比較、配列の等しさ、CBOR の型ごとのリテラルは、この決定に合わせてこの版で決めた。
- **小数のリテラル、指数のリテラル、有理数で表せない値の 17 桁、有限小数の 1000 桁の上限、タグ 30、ABI を [ADR 0102](0102-natural-number-type.md) と一度に上げること**：メンテナーが草案のとおりに承認した。有限小数の桁の上限は v2 まではこの値でよいとされた。
- **整数部が 17 桁以上の値**：この版で、整数部を丸めないと決めた。草案の「有効数字 17 桁」をそのまま当てると整数の桁を 0 で書くことになるためである。
- **循環小数**：メンテナーが、エラーにせず丸めると決めた。桁数と丸めの規則（有効数字 17 桁、最も近い側、等距離は起こらない）は、この版で無理数の規則と同じものを選んだ。G02102 の原因は 1000 桁の上限だけにした。
- **プラグインの浮動小数点数**：メンテナーが、拒まずに正確な有理数に変えると決めた。
- **NaN と無限大**：メンテナーが新しいコードにすると決めた。この版で、一つの原因として G06100 の一つにした。
- **G02004**：メンテナーが廃止すると決めた。
- **`div` と `%`**：草案のとおり整数に限る。メンテナーの指示はなく、草案の案を保った。
- **`E` の大文字と指数の上限 1300**：メンテナーの指示はなく、草案の案を保った。
