# ADR 0127: 用語集の見出し語を引数で書く

ステータス: 採択

## 文脈

用語集のプラグイン（[docs/adr/0126](0126-glossary-plugin.md)）の `[term: 語]` は、散文スロットの文字列をそのまま見出し語にして、データ `terms` の TSV から引く。
本文に現れる形と見出し語が同じなら、これで足りる。

本文の語は、見出し語と同じ形で現れるとは限らない。

- 活用する語：見出し語「組む」が、本文では「組んだ」「組める」と現れる。
- 表記の揺れ：見出し語「組版」が、本文では「組み版」や、ルビを振った「組版（くみはん）」の一部として現れる。
- 略称と言い換え：見出し語「日本語組版処理の要件」が、本文では「JLReq」と現れる。

[docs/adr/0126](0126-glossary-plugin.md) の形では、こうした出現を一覧に載せる方法がない。
本文の語を見出し語の形に書き換えるか、TSV に「組んだ」の行を別に足すしかない。
後者では、同じ語が一覧に二度載る。

## 実装すること

`[term]` に、位置引数を一つ書けるようにする。
書いたときは、その引数が見出し語であり、散文スロットは本文に出す文字だけになる。

```
[term 組む: 組んだ]版は、[term: 組版]と呼ぶ。
[term 日本語組版処理の要件: JLReq] の 3.1 節を参照する。
```

- 位置引数を書かなければ、[docs/adr/0126](0126-glossary-plugin.md) のとおり散文スロットの文字列を見出し語にする。
- 位置引数は、語か文字列で書く（`[term 組む: …]` と `[term "組む": …]` は同じ）。
- 見出し語で TSV を引き、項目のキー、読み、本文は TSV のその行から作る。本文に出す字は、項目の本文に影響しない。

### diagnostic

原因ごとに一つのコードとする。
どれもエラーで、位置は `[term]` の呼び出しである。
誤りがあっても、本文の字は消さずに出し、項目だけを送らない。

| コード | 原因 | メッセージ |
| --- | --- | --- |
| `args` | 位置引数が二つ以上か、キーワード引数を書いた | `term には見出し語を一つだけ書けます` |
| `headword-type` | 位置引数が文字列でない（数、真偽値、配列など） | `term の見出し語は文字列で書きます` |
| `headword-empty` | 位置引数が空の文字列 | `term の見出し語が空です` |

`unknown`（TSV にない語）のメッセージは、引数で書いた見出し語を示す。

コードは、プラグインが返す後ろの部分である。
ホストがプラグインの宣言の名前を前置する形（`glossary/args`）は、プラグインの diagnostic のコードの草稿（[docs/adr/0108](0108-plugin-diagnostic-codes-and-spans.md)）が決める。

## 実装しないこと

- 見出し語を語形変化の規則から推測すること（「組んだ」から「組む」を引く）。形態素解析の辞書が要り、推測を誤れば黙って違う語に載る。
- TSV に別名の列を設けて、別名から見出し語を引くこと。別名は語ごとに数が違うので、TSV の欄の数が定まらない。使う本が現れてから決める。
- キーワード引数（`[term headword=組む: 組んだ]`）。位置引数一つで足り、`[index reading=…]` のような複数の引数を持たないからである。

## テスト設計

Rust のテスト（`cargo test -p glossary`）で、次のことを確かめる。

- `[term 組む: 組んだ]` が、本文に「組んだ」を出し、キー「組む」の項目を送る。
- 引数を書かない `[term: 組版]` が、[docs/adr/0126](0126-glossary-plugin.md) のとおりに振る舞う。
- 位置引数が二つ、キーワード引数、数の引数、空の文字列が、それぞれ `args`、`args`、`headword-type`、`headword-empty` になり、本文の字が残る。
- TSV にない見出し語が、見出し語を示す `unknown` になる。

golem-driver のテスト（`PluginsSpec`）で、`[term 組む: 組んだ]` と `[term: 組む]` の二つの出現が、一覧の一つのエントリにまとまり、出現の位置が二つになることを確かめる。

試しに実装したブランチ `plugins-glossary` では、driver のテストを先に書き、引数を受け付けない前の `glossary.wasm` で `args` の誤りになって失敗することを確かめてから実装した。
Rust のテストは実装と同時に書いた。
手元の本で `[term 組版: 組んだ]` と書いた出現が、見出し語「組版」の出現のページ（一、二）に加わることを確かめた。

## トレードオフ

見出し語を原稿に書くので、活用や略称の出現のたびに見出し語を書く手間がかかる。
TSV に別名を書く形なら一度で済むが、別名の書き方（区切りの文字、欄の数）を決める必要があり、別名が二つの語で重なったときの規則も要る。
引数の形は、出現ごとに書き手が見出し語を明示するので、どの語に載るかが原稿から読み取れる。
