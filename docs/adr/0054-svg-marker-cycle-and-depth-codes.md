# ADR 0054: SVG の `marker` の循環と深すぎる入れ子を、それぞれのコードのエラーにする

ステータス: 採択

## 文脈

[ADR 0041](0041-svg-marker-and-number-limits.md) は、SVG の図版の `marker` の循環と入れ子を G08011 にすると決めた。
G08011 は、PDF に描ける範囲の外の要素、属性、値、輪郭にしていない文字、絶対値が 10^9 を超える数をまとめたコードである。
`marker` の循環と深すぎる入れ子は、名前に `marker（循環）` と `marker（入れ子）` を添えて、同じ G08011 に入る。

### 一つのコードに一つの原因

メンテナーは、異なる原因に一つの diagnostic のコードを共有させないと決めた。
コードから原因が一つに決まらないと、利用者は `golem explain` の説明のどの原因が自分に当たるかを探すことになり、混乱するためである。

`marker` の循環と深すぎる入れ子は、範囲の外の要素とは原因が違う。
範囲の外の要素は Golem が描けないものであり、図の作成ツールの書き出しの設定で避ける。
循環は、`marker` が自分自身を置くので、描き終わらない図である。
SVG として描けない図なので、Golem の範囲によらず許さない。
深すぎる入れ子は、描けるが、手間を限るために Golem が拒む図である。
二つの直し方も違う。
循環は参照を一つ切れば直り、深すぎる入れ子は段の数を減らせば直る。

### 判定の方法

[ADR 0041](0041-svg-marker-and-number-limits.md) は、`marker` の中身を描くときに描いている `marker` の id の列を持ち、列にある `marker` をもう一度参照すれば循環とする、と書いた。

実装（golem-svg の `Golem.Svg`）は、この方法をとっていない。
描く前に `marker` の参照のグラフを作り、`markerEdges` で判定する。

1. 要素を読む走査（`elementOps`）は、問題と描画のほかに、置く `marker` の id を返す。図の本体が置く `marker` と、各 `marker` の中身が置く `marker` から、グラフを作る。
2. 強連結成分が同じ二つの `marker` のあいだの参照（自分自身への参照を含む）を、循環の参照とする。
3. 図の本体から届く `marker` だけを数える。`marker` の深さは、循環の参照を除いて、図の本体からその `marker` に至る最も長い参照の列の長さとする。
4. 届く `marker` の中身にある参照のうち、循環の参照を `marker（循環）`、深さ 9 以上の `marker` からの参照を `marker（入れ子）` とする。

各 `marker` の中身は一度だけ読み、置くたびに読み直さない。
問題を集める手間は、`marker` を置く回数ではなく文書の大きさに比例する。
描いている id の列で判定するには、置く場所ごとに中身を辿り直すことになり、各段に四つ置けば手間は 4 の深さ乗になる。
これは [ADR 0041](0041-svg-marker-and-number-limits.md) が直そうとした監査の C8 と同じ形の問題である。

二つの判定は、循環がなく深さが 9 以下の図では同じ結果になる。
違うのは次の二つの場合である。

- 循環：列による判定は、循環を閉じる参照だけを出す。`a` が `b` を置き、`b` が `a` を置き、図の本体が `a` を置くなら、`b` の中の `a` への参照だけになる。グラフによる判定は、`a` の中の `b` への参照と `b` の中の `a` への参照の二つを出す。
- 深さが 10 を超える `marker` の列：列による判定は、10 段目を置く参照で描くのをやめ、その先を見ない。12 個の `marker` が一列に並ぶ図では一つである。グラフによる判定は、範囲の外の参照も深さに数えるので、深さ 9 以上のすべての `marker` の中の参照を出す。同じ図で三つになる。

golem-svg の仕様書（「`marker` の深さと循環」の節）は、グラフによる判定を書き、ADR との違いを注記している。

## 実装すること

### 判定

`marker` の循環と入れ子の判定は、今の実装のとおり、参照のグラフで行う。

- 循環の参照は、図の本体から届く `marker` のあいだの参照のうち、両端が同じ強連結成分にあるもの（自分自身への参照を含む）とする。循環の中の参照をすべて数える。
- `marker` の深さは、循環の参照を除いた、図の本体からの最も長い参照の列の長さとする。範囲の外の参照も深さに数える。深さ 9 以上の `marker` の中の参照を、深すぎる入れ子の参照とする。
- 図の本体から届かない `marker` は数えない。
- 一つの参照が循環の参照でもあり、深さ 9 以上の `marker` の中の参照でもあれば、循環の参照とする。循環を切らなければ、段の数を減らしても直らないためである。

### コード

二つを G08011 から外し、それぞれ新しいコードにする。

| コード | 重大度 | 対象 | メッセージ |
|---|---|---|---|
| G08016 | エラー | `marker` の循環 | `SVG の図版の marker が循環しています: <パス>:<行>:<桁>（<id>）ほか <n> 件` |
| G08017 | エラー | `marker` の深すぎる入れ子 | `SVG の図版の marker の入れ子が 9 段を超えます: <パス>:<行>:<桁>（<id>）ほか <n> 件` |

- `<行>:<桁>` は、参照を持つ図形の位置である。`<id>` は、その参照が置く `marker` の id である。
- G08011 と同じく、`@figure` ごとに、文書の順の最初のものを書き、残りの件数を `ほか <n> 件` で添える。ほかになければ `ほか <n> 件` を書かない。
- 一つの `@figure` に G08011、G08016、G08017 のうち複数が当たれば、当たるものをすべて、この順に出す。どれか一つでもあれば、図版を置かず、PDF を書かない。
- 出す時と場所は G08011 と同じである。PDF を組むとき（`golem build` の PDF と `golem preflight`）にだけ出し、dev と prod の両方でエラーとし、位置は `@figure` のブロックとする。
- G08 の番号は G08014 まで使っている。G08015 は [ADR 0051](0051-reuse-repeated-pdf-content-streams.md) の草稿が使う。G08016 と G08017 は、origin の各ブランチと、この worktree のほかの草稿で使われていない。

### golem-svg の型

`SvgError` の `SvgUnsupported` を、原因ごとの三つの列を持つ形に改める。
G08011 の名前の文字列で原因を見分けることはしない。

```haskell
data SvgProblems = SvgProblems
  { spUnsupported :: ![Unsupported], -- G08011
    spMarkerCycles :: ![MarkerRef], -- G08016
    spMarkerDepth :: ![MarkerRef] -- G08017
  }
```

三つのどれかが空でなければ `Left` とする。
`MarkerRef` は、参照を持つ図形の行と桁と、置く `marker` の id を持つ。
golem-driver の `Golem.Driver.Pdf` の `Unplaced` と `figureDiagnostics`、`Golem.Driver.Svg` のメッセージを、三つのコードに合わせて改める。


### ドキュメント

- `docs/diagnostics.md` に G08016 と G08017 の節を足す。G08011 の節から `marker` の循環と入れ子を除く。
- docs/specifications.md の図版の節の `marker` の項を、G08016 と G08017 に改め、この ADR へのリンクを付ける。
- golem-svg の仕様書の「`marker` の深さと循環」の節を、この ADR に合わせて書き直す。ADR との違いの注記は消す。
- 使い手のマニュアルの付録 E に、G08016 と G08017 を足す。

## 実装しないこと

- 判定を、描いている id の列に戻すこと。理由は「文脈」の手間の問題である。
- 循環を閉じる参照だけを数えるよう、判定を絞ること。どの参照が循環を「閉じる」かは、図の本体が先に置く `marker` で変わり、グラフの性質だけでは決まらない。
- 循環を警告にして、循環の外を描くこと。循環する `marker` は描き終わらない図であり、どこで止めて描くかを Golem が決めれば、入力を黙って変えることになる。
- `use` の深さの判定の変更。
- G08011 に残るほかの原因の分け方（「未決事項」を参照）。

## テスト設計

次のテストを先に書き、失敗させてから実装する。

golem-svg の `test/SecuritySpec.hs` には、次のテストを置く。
今の `marker（循環）` と `marker（入れ子）` を確かめるテストは、原因の列を確かめる形に改める。

- 自分を参照する `marker` が、5 秒以内に、循環の列に一つの参照だけを持ち、範囲の外の列と入れ子の列が空になること。
- `a` が `b` を置き、`b` が `a` を置き、図の本体が `a` を置く SVG で、循環の列がちょうど二つ（`a` の中の `b` への参照、`b` の中の `a` への参照の順）になること。
- `a`、`b`、`c` が順に次を置き、`c` が `a` を置く三つの循環で、循環の列が三つになること。
- 図の本体が置かない循環の `marker` が、問題にならないこと。
- 深さ 9 の列（`markerChain 9`）が描かれること。
- 深さ 10 の列（`markerChain 10`）で、入れ子の列が一つになり、循環の列が空になること。
- 12 個の列（`markerChain 12`）で、入れ子の列が三つになること。
- 深さ 14 の、各段に四つ置く入れ子が、5 秒以内に入れ子の列だけを持つこと。
- 範囲の外の要素（`text`）と `marker` の循環を両方持つ SVG で、範囲の外の列と循環の列の両方が空でないこと。

golem-driver の `test/FigureSpec.hs` には、次のテストを置く。

- 二つの `marker` の循環を持つ SVG の図版を PDF に組み、G08016 が一つ出て、メッセージが `a` の中の参照の行と桁、`（b）`、`ほか 1 件` を持ち、G08011 が出ないこと。
- `markerChain 10` の図版で G08017 が一つ出て、G08011 が出ないこと。
- `text` と `marker` の循環を両方持つ図版で、G08011 と G08016 がこの順に一つずつ出て、PDF を書かないこと。

golem-syntax では、次を確かめる。

- docs の diagnostic の一覧とコードの一致の検査が、G08016 と G08017 を含めて通ること。

## トレードオフ

- 循環が長いと、一つの循環で多くの参照が数えられ、`ほか <n> 件` が大きくなる。件数は書き手が切りうる参照の数と一致する。
- 深すぎる列では、10 段目を置く参照を直せば消える参照も数える。どの参照を切っても深さが 9 以下になるとは限らないので、深さ 9 以上の参照をすべて示す。
- コードが二つ増え、golem-svg の `SvgError` の型が変わる。golem-svg を使うのは golem-driver だけである。

## 未決事項

- 同じ原則に照らすと、G08011 にはまだ複数の原因が残る。範囲の外の要素と属性、輪郭にしていない文字、絶対値が 10^9 を超える数（`（読めない数）`）、数の形を外れた値である。G08010 も、読めない画像、取り込めない PDF の各理由、読めない SVG、ルートの `大きさの数が大きすぎます` を一つのコードで出す。これらを分けるかを、別の ADR で決めるか。この ADR は `marker` の二つだけを扱う。
