# ADR 0443: 格子の配置で、回り込ませる図版が収まるかを、脇の行の脚注も数えて決める

Status: proposed

## 文脈

格子の配置では、回り込ませる図版の大きさ（図版の行数と脇の行の数の大きいほう）がページの残りに収まらなければ、図版を脇の行とともに次のページの先頭に送る（[golem-driver ADR 0005](../golem-driver/adr/0005-pdf-wrapped-figures.md)、[golem-layout ADR 0004](../golem-layout/adr/0004-wrapped-figures.md)）。
ところが、この見積もりは、脇の行の脚注を数えない。
脇の行の脚注が段の終わりを取ると、図版は今のページに残り、脇の行の一部だけが次のページに送られる。
送られた行は、図版の無いページで、除外領域の幅だけ字下げされたまま組まれる。

[root ADR 0397](0397-paragraph-line-pitch-and-dimensional-spacing.md) は、脚注で脇の行を送る扱いを [golem-driver ADR 0005](../golem-driver/adr/0005-pdf-wrapped-figures.md) から引き継ぎ、その理由を、行分割と改ページの相互の繰り返しを避けるためとした。
しかし、図版と脇の行をまとめて次のページに送るだけなら、行分割をやり直す必要は無い。
この ADR は、格子の配置で、見積もりに脇の行の脚注を数え、図版と脇の行が離れないようにする。

## 調査した事項

origin/main（[916380ce6](https://github.com/tett23/golem/commit/916380ce6e55ee4fdea3a861111fd8dd2c809e24)）で、次のことを確かめた。

- [golem-driver ADR 0005](../golem-driver/adr/0005-pdf-wrapped-figures.md) は、「`FWrapped` の大きさの見積もりは脚注を含まないので、脇の行の一部が収まらない場合がある」とし、その場合は `placeLines` の既存の処理で、収まらない行を次のページに送ると決めている。
- root [ADR 0397](0397-paragraph-line-pitch-and-dimensional-spacing.md) は、自由な配置でも、脚注の予約や最後の脇の行の長さで脇の行の一部が収まらない場合は、後続の段へ送り、短い行長とインデントをそのまま残すと決めている。
  自由な配置は、図版の除外矩形だけで収まるかを決め、脇の行の数を数えない（`Paginate/Physical.hs` の 872 行）。
- 格子の配置の `FWrapped` の `keep` は、格子の行数（図版の行数と脇の行の数の大きいほう）だけで決める（`Paginate.hs` の `FWrapped` の場合、555 行から 560 行）。
  脇の行の脚注の行数は、`beside` の行の `lbNotes` から `noteLinesOf` で、置く前に求められる。
  見出しは、`needIn` で、格子の行数と脚注の行数と、その段で最初の脚注なら区切りの行数を足して決める（`Paginate/Decide.hs` の 79 行と 256 行から 260 行）。
- 図版の前の見出しは、`nextNeed` が返す `FWrapped` の大きさ（`grid (max n (length ls))`、`Decide.hs` の 82 行）で、図版と離さないかを決める。
  この大きさも脚注を数えない。
- 次の入力をページ分割の関数に渡すと、1 ページ目に図版と行 10 と脚注が、2 ページ目に行 11 だけが置かれた（`cabal exec runghc` で確かめた）。

  ```text
  paginate 1 4 [FWrapped 1 2 [] [] [LineBox 10 [NoteBody n 2] [] [] 0, LineBox 11 [] [] [] 0], FParagraph defaultKeep (3 行)]
  ```

- 図版の行数が脇の行の数より大きく、脇の行に脚注がある場合も、`keep` は図版の行数だけで決めるので、図版と脚注の行の和が段を超えうる。
- PR #1129 は、送られた行の後に空白の行が残る不具合だけを直し、仕様書に「図版が収まるかは、脇の行の脚注を数えずに判定する」などの 4 文（回り込みの節の 5334 行から 5337 行）を足した。
- 段組みの版面では、回り込みは G07026 になる（仕様書の 2153 行）。
  格子の配置の回り込みでは、段はページと同じである。
- 次の二つのテストが、自由な配置で脚注のために脇の行を送る今の振る舞いを確かめている（`PhysicalPaginateSpec.hs` の 572 行と 695 行）。
  この ADR は自由な配置を変えないので、どちらも変わらない。

## 実装すること

### 格子の配置の見積もり

格子の配置で、回り込ませる図版が今の段に収まるかは、次の和が段の残りの行以下かで決める。

```text
max(図版の行数, 脇の行の数) + 脇の行の脚注の行数 + 区切りの行数
```

区切りの行数は、その段にまだ脚注が無く、脇の行に脚注があるときだけ足す（見出しの `needIn` と同じ）。
収まらなければ、図版と脇の行を次の段の先頭に送る。
`nextNeed` が返す `FWrapped` の大きさにも、脇の行の脚注の行数を足し、図版の前の見出しも同じ量で決める。

### 次の段でも収まらないとき

図版と脇の行を次の段の先頭に送っても収まらない（脚注がとても長い）ときは、図版と脇の行を次の段の先頭に置き、そこに入らない脇の行を後の段へ送る。
送られた行の短い行長とインデントは、今と同じくそのまま残す。
最後の行の孤立の規則で、もう一行送られることがある。

行分割はやり直さない。
図版と脇の行をまとめて送るので、行長は変わらない。

### 自由な配置

自由な配置は、この ADR では変えない。
自由な配置は、図版の除外矩形だけで収まるかを決め、脇の行の数と脚注を長さ（sp）で数える別の仕組みを持つ。
同じ扱いにするかは、別の ADR で決める。

### 文書とステータスの行

仕様書の回り込みの節の、PR #1129 が足した 4 文（5334 行から 5337 行）を、この規則で置き換える。
格子の配置と自由な配置の扱いが違うことも書く。

採択したら、[golem-driver ADR 0005](../golem-driver/adr/0005-pdf-wrapped-figures.md) の、脇の行の脚注で行を送る扱いを、格子の配置について、この ADR が置き換えたと記録する。
次の段でも収まらないときの扱いは 0005 のまま残る。
[golem-layout ADR 0004](../golem-layout/adr/0004-wrapped-figures.md) には、送る条件に脚注を足したことを補足として記録する。

## 実装しないこと

脇の行の行分割を、ページに合わせてやり直さない。
脇の行の脚注の本文の始まりを、その行と別のページに置くことはしない（脚注の本文の続きを次のページに分けることは、今の決まりのとおり行う）。
自由な配置の見積もりは変えない。
回り込ませる図版の大きさの上限（G07023）は変えない。

## 不変条件

- I1: 格子の配置で、`max(図版の行数, 脇の行の数) + 脇の行の脚注の行数 + 区切りの行数` が段の残り以下なら、図版と脇の行はすべて今の段に置かれる。
- I2: 格子の配置で、その和が段の残りより大きく、次の段の行数以下なら、図版と脇の行はすべて次の段に置かれる。
- I3: 脇の行に脚注が無い原稿の出力は、この ADR の前と等しい。
- I4: 格子の配置で、図版と脇の行が別の段に置かれるのは、その和が一つの段の行数より大きいときだけである。
- I5: 自由な配置の出力は、この ADR の前と等しい。

| 入力（格子の配置、一段 16 行、区切り 1 行） | 期待 | 不変条件 |
| --- | --- | --- |
| 図版 2 行、脇の行 5 行、最初の行に 5 行の脚注、段の残り 8 行 | 図版と脇の行は次の段の先頭 | I2 |
| 同じで、段の残りがちょうど 11 行 | 今の段に収まる | I1 |
| 同じで、段の残りが 10 行 | 次の段の先頭 | I2 |
| 同じで、段にすでに脚注があり、段の残りが 10 行 | 区切りを足さず、今の段に収まる | I1 |
| 図版 10 行、脇の行 2 行、脚注 5 行、段の残り 11 行 | 次の段の先頭（図版と脚注が重ならない） | I2 |
| 図版の前に見出しがあり、一行目と同じ図版 | 見出しも次の段 | I2 |
| 脇の行に 20 行の脚注 | 図版と脇の行は次の段の先頭で、入らない脇の行は後の段 | I4 |
| 脇の行に脚注が無い | 今と同じ | I3 |
| 自由な配置で、一行目と同じ原稿 | 今と同じ | I5 |

## 受けいれ条件

なし。
不変条件のテストで足りるためである。

## テスト設計

root ADR 0443 I1 から I5 を名前の先頭に置いたテストを、golem-layout の `PaginateSpec.hs` と、golem-driver の `PageElementsSpec.hs` に足す。
境界の表の入力をページ分割の関数に渡し、図版と脇の行の段を比べる。
golem-driver では、表の一行目のような原稿を組み、PDF の図版と脇の行が同じページにあることを確かめる。
I1、I2、I4 は、実装の前に落ちることを確かめる。
I5 は、`PhysicalPaginateSpec.hs` の今のテストが変わらず通ることで確かめる。

## トレードオフ

脚注の長い脇の行を持つ図版は、今より早く次のページに送られ、前のページの残りが空く。
その代わりに、図版の無いページに字下げされた行が残ることが、格子の配置ではほとんど無くなる。

脚注が一つの段にも収まらないほど長いときは、今と同じく離れる。
この場合まで防ぐには、脇の行の行分割をやり直す必要があり、0397 が避けた相互の繰り返しが戻る。

自由な配置は変えないので、二つの配置で振る舞いが違う。
