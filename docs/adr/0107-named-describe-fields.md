# ADR 0107: golem_describe の欄に名前を付ける

ステータス: 採択

## 文脈

`golem_describe` は、プラグインの記述を CBOR の配列で返す。
欄は位置で区別され、[golem-plugin ADR 0001](../golem-plugin/adr/0001-wasm-host-and-abi.md) のコマンドとフィルタの二つから始まり、チャネル（[golem-doc ADR 0007](../golem-doc/adr/0007-plugin-channel-lists.md)）、データの名前（[docs/adr/0105](0105-plugin-data.md)）、ブロックコマンド（[docs/adr/0122](0122-block-commands-in-plugins.md)）と増えてきた。
ホストは欄の数がちょうど合わない記述を拒む（[`decodeDescription`](https://github.com/tett23/golem/blob/fa55dc76be6fef7189cb80883fd0bb0b0630911f/modules/golem-plugin/src/Golem/Plugin.hs#L219-L224)）。

欄を一つ足すたびに、すべてのプラグインが壊れる。
rc4 のあいだに、それが二度起きた。
[docs/adr/0105](0105-plugin-data.md) がデータの名前を足したとき、ブロックコマンド（[docs/adr/0122](0122-block-commands-in-plugins.md)）の試しが五つめの欄を足したときで、どちらも golem-plugin のテスト用の wat のプラグイン十三個の記述のバイト列と長さを書き換えた。
ABI のバージョン 8 はまだリリースしていないので、どちらもバージョンを上げずに済んだ。
リリースの後なら、欄を足すたびにバージョンを上げ、すべてのプラグインを作り直してもらうことになる。

足される欄は、これで終わりそうにない。
[docs/adr/0121](0121-host-context-in-plugin-requests.md) は、プラグインがホストの文脈（組み方向など）を受け取ることを記述で宣言する欄を足す。
この ADR は、その欄も名前で足せる形を先に決める。

### 試しに実装して分かったこと

この ADR は、採択の前に実装を試した（ブランチ `plugins-tsv-table`）。

- テスト用の wat のプラグイン十三個の記述を、空でない欄だけのマップに書き換えた。記述は短いものでは 6 バイトから 1 バイト（空のマップ）に、長いものでは 40 バイトから 55 バイトになった。
- 長くなった記述が、同じ wat の次のデータの区間（`(data (i32.const 64) ...)`）と重なった（`channels.wat`）。後の区間が記述を上書きするので、データの区間を後ろへずらした。手で書いた wat では、記述の長さが変わるたびにこの確かめが要る。
- Rust の補助のクレートの記述を書く部分は、配列からマップに変えるだけで済んだ。`lookup.wasm` は 75,339 バイトから 76,860 バイトに、`tsv-table.wasm` は 84,830 バイトから 86,351 バイトになった。

## 実装すること

### 形

`golem_describe` は、欄の名前（テキスト文字列）から値へのマップを返す。

```cddl
description = {
  ? "commands" => [* tstr],
  ? "filters" => [* tstr],
  ? "channels" => [* channel-decl],
  ? "data" => [* tstr],
  ? "blocks" => [* tstr]
}
```

それぞれの欄の値の意味と検査は、今と変えない。

### 書かない欄、未知の欄、二度書いた欄

- 書かない欄は、空の配列と同じとする。コマンドだけのプラグインは `{"commands": ["hello"]}` と書けばよい。
- 未知の欄は、不正な `golem_describe`（G06005）とする。メッセージは `golem_describe に未知の欄があります: <名前>` である。
- 同じ欄を二度書くと G06005 とする。メッセージは `golem_describe の欄が重複しています: <名前>` である。
- マップでないもの（配列を含む）、長さの決まっていないマップ、テキスト文字列でないキーは、今と同じく `golem_describe の形が不正です`（G06005）とする。
- 欄の値が配列でなければ `golem_describe の欄の形が不正です: <名前>`（G06005）とする。

書かない欄を空とするのは、欄を足しても古いプラグインが壊れないようにするためである。
これがこの ADR の目的そのものである。

未知の欄を黙って読み飛ばさないのは、新しいホストのために作ったプラグインを古いホストで読んだとき、プラグインが頼る宣言（たとえば、ホストの文脈を受け取る宣言）を、ホストが知らないまま動かすことを避けるためである。
緩い規則より厳しい規則を選ぶ。
未知の欄で読み込みを止めれば、利用者はホストを上げるべきことを G06005 のメッセージから知る。

### 順と決定性

ホストは欄の順を問わない。
記述から得る値（コマンドの一覧など）は欄の順によらず同じなので、出力と diagnostic の決定性は損なわれない。
同じプラグインは同じバイト列の記述を返すので、順によって読み込みの結果が変わることもない。

決定的な符号化（RFC 8949 の 4.2.1）の順を求めて、それ以外の順を拒む案もあった。
拒んでも守られるものがなく、手で wat を書く作者の手間だけが増えるので、採らない。
Rust の補助のクレートは、空でない欄だけを、4.2.1 の順（短いキーが先、同じ長さならバイトの順）で書く。

### 意味論 IR の方針との関係

[golem-doc ADR 0001](../golem-doc/adr/0001-semantic-ir-in-cddl.md) は、IR の直和型を配列で表し、マップを使わない。
キーの順に頼る符号化を避け、同じ IR を同じバイト列にするためである。
記述は IR ではなく、ホストが一度だけ読む宣言である。
ホストはこれを符号化しないので、キーの順がホストの出力のバイト列に入ることはない。
この ADR は IR の方針を変えない。

### バージョン

ABI のバージョン 8 はまだリリースしていないので、バージョンは上げない（[docs/adr/0052](0052-plugin-abi-version-bump-rule.md)）。
この ADR の後に欄を足すことは、古いプラグインの読み込みを壊さない。
ただし、ホストの意味を変えるので、ABI の変更として扱い、リリースをまたげばバージョンを上げる。
新しい欄を書いたプラグインは古いホストでは G06005 になるので、バージョンを上げずに済ませる理由はない。

### モジュールの変更

- **golem-plugin**：`decodeDescription` がマップを読む。
- **golem-doc**：CDDL の `description` を上のとおりに変える。
- **plugins/golem-plugin-sdk**：`description_value` がマップを書く。
- テスト用の wat のプラグインと、開発者のマニュアルの wat の例の記述を書き換える。

## 実装しないこと

- 要求と応答をマップにすること。要求と応答は IR を運ぶので、IR の方針に従う。
- 欄ごとに「知らなければ無視してよい」印を付けること（CBOR のタグや、キーの前置きによる区別）。必要になれば、新しい欄の ADR で決める。
- 古い配列の形を受け付けること。リリースした ABI ではまだ使われていないので、移行の期間を設けない。

## テスト設計

下のテストのうち、見本のプラグイン tsv-table（[docs/adr/0129](0129-tsv-table-plugin.md)）を使うものは、この ADR の実装では書かない。
この ADR の実装では、同じことを wat のテスト用のプラグイン（`modules/golem-plugin/test/` と golem-driver のテストの wat）で確かめるテストを先に書く。
見本のプラグインを使うテストは、結合のテストとして、その見本のプラグインの ADR を実装するときに足す。
見本のプラグインの ADR が、この ADR より後に実装されるからである。

テストを先に書き、今の実装で失敗することを確かめてから実装した。

golem-plugin のテスト（`modules/golem-plugin/test/BlockSpec.hs` ほか）では、次のことを確かめる。

- 空のマップの記述が、すべて空の一覧になる。
- 欄の順を入れ替えても、同じ一覧になる。
- 未知の欄 `macros` が `golem_describe に未知の欄があります: macros` になる。
- 二度書いた `commands` が `golem_describe の欄が重複しています: commands` になる。
- 整数のキーが `golem_describe の形が不正です` に、配列でない値が `golem_describe の欄の形が不正です: commands` になる。
- 五つの配列を並べた古い形と、二つの配列の形が `golem_describe の形が不正です` になる。
- 既存のテスト（チャネル、データの名前、ブロックコマンド、命令数とメモリの上限）が、マップの記述で同じ結果になる。

補助のクレートの単体テストでは、空でない欄だけが 4.2.1 の順のマップになり、空の記述が空のマップになることを確かめる。

golem-driver のテストは、`lookup.wasm` と `tsv-table.wasm` を作り直して、変えずに通ることを確かめる。

## トレードオフ

記述は少し長くなる（欄の名前の分）。
読むのは読み込みのときに一度だけなので、速さには響かない。

書かない欄を空とするので、作者が欄の名前を綴り誤ると、その欄は空になり、未知の欄として G06005 になる。
黙って空になるのではないので、綴りの誤りは見つかる。

未知の欄を拒むので、新しい欄を足したホストのために作ったプラグインは、古いホストでは読み込めない。
これは位置の形でも同じであり（欄の数が合わない）、この ADR で悪くなる点ではない。

## 決めたことの記録

- **未知の欄を拒むこと**（メンテナー、2026-10-29）：未知の欄は G06005 として拒む。理由は「緩い状態を後から締めるより、厳しく始めて後から緩めるほうがよい」である。読み飛ばしてよい欄が要るようになれば、そのときに緩める ADR を書く。
- **ホストの文脈の欄との関係**：[docs/adr/0121](0121-host-context-in-plugin-requests.md) は、ホストの文脈を宣言する欄を記述に足す。この ADR の形なら、その欄は名前を一つ足すだけで済む。
- **テストのプラグイン**：メンテナーが、土台の ADR は wat のテスト用のプラグインで試し、見本のプラグインを使う結合のテストは見本のプラグインの実装のときに足す運用にすると決めた（2026-11-04）。
