# ADR 0460: `@style` の本体に、段落のほかのブロックも置けるようにする

Status: proposed

## 文脈

`@style 名前` の本体には、今は段落だけを置ける。
本体に箇条書きやコードブロックなどの段落でないブロックがあれば G02045（`@style` の本体には段落だけを置けます）とし、`@style` は何も出力しない。

[root ADR 0459](0459-take-the-next-block-as-the-body-without-indentation.md) は、`@style` を本体を受け取るコマンドとし、字下げしない次のブロックも本体として受け取ると決めた。
そのため、`@style` の次の行に箇条書きを書いた原稿は、今の G02013（このブロックには付けられません）でなく G02045 になり、ブロックが出力されなくなる。
メンテナーは、2026-11-26 に、`@style` が本体としてブロックを受け取ればよいと決めた。

この ADR は、`@style` の本体に段落のほかのブロックを置いたときの、段落スタイルの当て方を決める。

## 調査した事項

origin/main（[9e6755a](https://github.com/tett23/golem/commit/9e6755a380dc3ca7887c35f69a5e5bb36e1bf8f8)）で、次のことを確かめた。

- `@style` の本体は `styleBody` が読む（[File.hs#L1909-L1930](https://github.com/tett23/golem/blob/9e6755a380dc3ca7887c35f69a5e5bb36e1bf8f8/modules/golem-eval/src/Golem/Eval/File.hs#L1909-L1930)）。
  - 本体が無ければ G02010、本体に段落が無ければ G02046 とする。
  - 本体に段落でないブロックがあれば、そのブロックごとに G02045 とし、何も出力しない。
  - そうでなければ、本体の各段落に段落スタイルを当てる。
- 2026-11-26 にビルドした `golem`（main の 9e6755a38）で、`@style quote` の本体に箇条書きかコードブロックを字下げして書いた原稿は、G02045 になり、そのブロックは出力されなかった。

## 実装すること

### 本体のブロック

`@style 名前` の本体には、どのブロックも置ける。
`@style` は、本体のブロックを書いた順に評価し、次のように段落スタイルを当てる。

- 本体の段落と、箇条書き、番号付きの箇条書き、定義リストの中の段落は、段落スタイルを渡して評価する。
  段落スタイルの行の扱い（`line-breaks = "keep"` など）も、本体の直下の段落と同じく当てる。
- 本体の表は、今の属性の形と同じく、表のセルの段落スタイルとする。
- `@lang` と属性の内側の段落（`@style s`、`@lang en`、段落のように続けたもの）は、段落スタイルを渡して評価する。
  段落スタイルの行の扱いも、本体の直下の段落と同じく当てる。
- 出すだけのコマンドの出力には、今の属性の形と同じく当てる。
  `@printings` の奥付の段落には段落スタイルを当て、`@table` の表はセルの段落スタイルとする。
- `.emet` の関数とプラグインのブロックコマンドの結果の段落には、評価の後に段落スタイルを当てる。
  その段落は関数が組んだ段落なので、段落スタイルの行の扱いは当てない（トレードオフ）。
- 段落と表を持たないブロック（コードブロック、図版、区切りなど）と、見出しは、そのまま出力し、段落スタイルを当てない。
- フレーム（`@frame`）の中の段落と、注（`@note`、`@endnote`）の本文には当てない。
  フレームは自分の段落スタイルを持ち、注の本文はその場に出力しないためである。
- 本体の中の段落がすでに段落スタイルを持つとき（本体の中に `@style` を書いたとき）は、内側の段落スタイルを残す。

G02045 は出さない。
本体の評価の結果に、段落も表も一つも無いときは、今と同じく G02046 とする。
内側の `@style` の段落だけを持つ本体は、段落があるので G02046 にしない。

### 文書

仕様書の `@style` の本体の記述を、この ADR に合わせる。
`docs/diagnostics.md` の G02045 を、「使っていない」の状態にし、この ADR へのリンクを書く。
G02046 の説明に、段落も表も持たないブロックだけの本体も G02046 になることを書く。
マニュアルの `@style` の説明に、本体に箇条書きなどを置けることを書く。

採択したら、0459 のステータスに `{"part":"今の原稿で変わる出力","by":["docs/adr/0460-let-style-take-any-blocks-as-its-body.md"],"kind":"supplement"}` を記録する。

## 実装しないこと

表のセルの段落スタイルの決め方は、今の属性の形のまま変えない。
見出しに、段落スタイルを当てることはしない。
`@lang` の本体の扱いは変えない。

## 不変条件

- I1: 本体が段落だけの `@style` の出力と diagnostics は、この ADR の前と同じである。
- I2: `@style s` の本体に置いた箇条書き、番号付きの箇条書き、定義リストの、すべての段落の段落スタイルは s であり、ほかの出力は、同じブロックを `@style` の外に書いたときと同じである。
- I3: `@style s` の本体に置いた、段落と表を持たないブロックと見出しの出力は、同じブロックを `@style` の外に書いたときと同じである。
- I4: G02045 は出ない。
- I5: 本体の評価の結果に段落も表も無いとき、G02046 がちょうど一つ出る。
- I6: 本体の中で `@style t` を当てた段落の段落スタイルは t である。
- I7: `@style s` の本体の表と、本体の出すだけのコマンドの出力は、今の `@style s` を属性として付けた出力と同じである。
- I8: 行を保つ段落スタイル s の `@style s` の本体の、箇条書きの段落と、`@lang` と属性の内側の段落は、本体の直下の段落と同じく行を保つ。
- I9: `@style s` の本体の `@frame` の中の段落と、`@note`、`@endnote` の本文の段落スタイルは、同じものを `@style` の外に書いたときと同じである。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 本体が二つの段落 | 今と同じ | I1 |
| 本体が箇条書き | 各項目の段落にスタイル | I2 |
| 本体が入れ子の箇条書き | 入れ子の項目の段落にもスタイル | I2 |
| 本体が定義リスト | 定義の段落にスタイル | I2 |

| 本体が表だけ | 表のセルの段落スタイル（今の属性の形と同じ） | I7 |
| 本体の中の `@style t` と段落 | その段落は t | I6 |
| 本体が `@stage-direction` と段落 | その結果の段落にスタイル | I2 |
| 行を保つスタイルで、本体が箇条書き | 項目の段落は行を保つ | I8 |

## 受けいれ条件

なし。
不変条件のテストで足りるためである。

## テスト設計

root ADR 0460 I1 から I9 を名前の先頭に置いたテストを golem-eval に足す。
表の入力を、`@style` の本体に書いた原稿と、同じブロックを `@style` の外に書いた原稿の組にして評価し、段落スタイルとほかの出力を比べる。
テストは、実装の前に書いて落ちることを確かめる。

## トレードオフ

段落を持たないブロックを、段落スタイルを当てずにそのまま出力するので、`@style` で囲んだつもりのコードブロックや図版には、スタイルが当たらないことに気づきにくい。
本体に段落も表も一つも無いときは G02046 になるので、ブロックがすべて段落と表を持たないときだけは気づける。
今の G02045 のように、段落でないブロックを誤りにして出力しない扱いより、出力を残すほうを選んだ。

`.emet` の関数とプラグインのブロックコマンドの結果の段落には、評価の後に段落スタイルを当てるので、行を保つ段落スタイルでも、その段落の行は保たれない。
その段落は、そのコマンドの関数が組んだ段落であり、原稿の行を `@style` の側から知れないためである。
