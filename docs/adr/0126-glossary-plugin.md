# ADR 0126: 用語集のプラグイン

ステータス: 採択（未実装）

## 文脈

プラグインは独自のチャネルを宣言し、項目を送り、利用者は `@channel` でその一覧を置ける（[golem-doc ADR 0007](../golem-doc/adr/0007-plugin-channel-lists.md)）。
この仕組みは wat で書いたテスト用のプラグイン（`channels.wat`）でしか通っておらず、実際のプラグインで使ったことはない。
[docs/roadmap.md](../roadmap.md) の v0.1.0-rc4 は、用語集のプラグインでこの経路を試すとしている。
試すことは三つある。

- 独自のチャネルに項目を送り、巻末に一覧を組むこと。
- プラグインが値を読めないページ番号への参照（DeferredRef）を、出力に入れること。
- 独自のチャネルを使った EPUB が epubcheck を通ること。

語の並べ方と一覧の書式は、この ADR で決める。
語の定義をどこに書くかと、辞書を持たずに読みの順に並べる方法も、あわせて決める。

### 試しに実装して分かったこと

この ADR は、採択の前に実装を試した（ブランチ `plugins-glossary`）。
プラグインを Rust で書き（[docs/adr/0106](0106-sample-plugins-in-rust.md)）、縦組みの A6 の三章の本を PDF、HTML、EPUB、プレーンテキストに組んだ。
分かったことは次のとおりである。

**チャネルと DeferredRef は、そのまま使えた**。
プラグインが返したページ番号への参照（inline の tag 10）は、チャネルの項目の本文に入れても S1 で検査され、PDF ではレイアウトの繰り返しで解決された。
存在しないラベルは、原稿に書いた `[ref-page]` と同じく G04003 になった。
ホストの変更は要らなかった。

**epubcheck は通った**。
EPUBCheck 5.4.0（OpenJDK 14.0.2 で実行）で、致命的エラー、エラー、警告、情報のどれも出なかった。
ただし、見出しの中に `[term: 語]` を書き、同じファイルに `@toc` を置くと、`Duplicate ID "c-glossary-2-8"`（RSC-005）のエラーが二つ出た。
HTML の目次（[`toc`](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/modules/golem-html/src/Golem/Html.hs#L500-L510)）が見出しのインラインをそのまま書くので、項目の `<span id>` が見出しと目次の二か所に出る。
索引の印（`[index]`）でも同じエラーが出たので、チャネルに固有の不具合ではない。
PDF の目次は索引の印を除いている（[Flow.hs](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/modules/golem-driver/src/Golem/Driver/Pdf/Flow.hs#L1298)）が、HTML の目次は除いていなかった。
[golem-doc ADR 0007](../golem-doc/adr/0007-plugin-channel-lists.md) の「本の中で重複しない」は、この場合に成り立っていなかった。
このブランチで、HTML の目次から索引の印とチャネルの項目を除くように直した。

**縦組みの `[ref-page]` は算用数字のままである**。
用語集の項目の出現のページは「一、二」と漢数字になるが、同じ項目の本文に入れた参照のページは「（→2）」と算用数字で、横に倒れて組まれた。
原稿の本文に書いた `[ref-page]` も同じである。
仕様書は、ページ番号への参照を Number に解決し、縦横の表記の使い分けをほかの数と同じ経路で行うとしている（[docs/specifications.md](../specifications.md) の「目次と文書構造の参照」）。
実装は、ページ番号を `show` で文字列にしている（[`piecesOf`](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/modules/golem-layout/src/Golem/Layout/Japanese.hs#L284-L286)）。
プラグインと関係のない不具合なので、別の草稿（[docs/adr/0118](0118-ref-page-numerals-in-vertical-text.md)）で直す。
その草稿を試したブランチ `ref-page-vertical-numerals` を `plugins-glossary` にマージしたあとは、項目の参照のページも「（→二）」と漢数字になった。

**参照の表示は媒体ごとに違い、プラグインはそれを選べない**。
ページ番号への参照は、PDF ではページ番号に、HTML と EPUB ではラベルの要素の題へのリンクに、プレーンテキストでは「」で括った題になる。
プラグインは出力の媒体を知らないので、「（→12 ページ）」のように数を前提にした文言を添えると、HTML で「（→禁則処理ページ）」になる。
そこで、矢印と括弧だけを添えた。

**データの誤りが、呼び出しの数だけ繰り返される**。
TSV に欄の数の誤った行を一つ足すと、同じエラー（最初の試作のコードでは `term-tsv`）が、`[term]` を書いた八か所すべてに出た。
プラグインはデータを呼び出しごとに受け取り、呼び出しのあいだで何も覚えていない（[docs/adr/0105](0105-plugin-data.md)）。
データを一度だけ検査する場所が ABI にないので、プラグインは誤りを呼び出しの位置でしか報告できない。
誤りの位置も、TSV の行ではなく呼び出しの位置になる。
この問題は別の草稿（[docs/adr/0120](0120-plugin-data-check-at-load.md)）で扱う。

**大きさ**：`glossary.wasm` は 86747 バイトだった（読みの省略と見出し語の引数を足した後は 87544 バイト）。
三章、八つの `[term]` の本を、四つのターゲットに組む時間は測れるほど延びなかった。
同じ入力から二度組んだ 11 のファイルは、バイト列が同じだった。

## 実装すること

見本のプラグイン `glossary` を `plugins/glossary/` に置く（[docs/adr/0106](0106-sample-plugins-in-rust.md)）。

### 宣言

`golem_describe` は、次の三つを宣言する。

- コマンド `term`。
- チャネル `glossary`。並べ方は読みの順、`locators` は真とする。
- データ `terms`。

```toml
[plugins.glossary]
url = "https://github.com/tett23/golem/releases/download/v0.1.0-rc4/glossary.wasm"
data = { terms = "data/terms.tsv" }
```

### 語の定義

語、読み、定義は、データ `terms` の TSV に書く。

```
# 語	読み	定義	参照するラベル
組版	くみはん	文字や図版を版面に配置すること。
禁則	きんそく	行頭や行末に置けない約物の規則。	kinsoku
カーニング		特定の字の組の字間を詰めること。
```

- 一行が一語である。欄は、語、読み、定義、参照するラベルの順で、ラベルは省ける。
- 空の行と `#` で始まる行は読み飛ばす。
- 読みには、ひらがな、カタカナ、長音符、ASCII の英数字だけを書ける。
- 読みは空にできる。漢字を含まない語では、語そのものを読みとする。
- 次の行は誤りとし、原因ごとに別のコードにする（「プラグインの diagnostic」の節）。
  - 欄の数が 3 か 4 でない行。
  - 語、定義、ラベルの欄（4 欄めを書いたとき）が空の行。
  - 読みが空で、語が漢字を含む行。
  - 読みに上の文字のほかを含む行。
  - 前の行と同じ語の行。

定義を原稿の中（`[term]` の引数や散文スロット）に書く形は採らない。
エントリの本文は、同じキーの項目のうち文書の順で最初の項目のものになる（[golem-doc ADR 0007](../golem-doc/adr/0007-plugin-channel-lists.md)）。
定義を原稿に書くと、どの出現に定義を書いたかで一覧の本文が変わり、書かなかった出現が先にあれば定義が消える。
定義を TSV の一か所に置けば、どの出現から送っても本文が同じになる。

### 読みの順

並べ替えはホストが行う。
プラグインは項目に読みを付けて送るだけで、索引と同じ照合（`Golem.Doc.Collation`）で並ぶ。
辞書は持たない。
漢字を含む語の読みは、書き手が TSV に書く。

読みの文字を限ったのは、照合が漢字をコードポイントの順で、すべてのかなの後に並べるからである。
読みの欄に漢字を書き誤ると、エラーなしに一覧の末尾へ回る。
黙って違う順に組むより、誤りとして止めるほうを選んだ。

読みを空にできるのは、漢字を含まない語に限る。
かなの語（カーニング）は、照合がカタカナをひらがなに寄せて読むので、語そのものを読みにしても正しい位置に並ぶ。
英字の語（Golem）も、照合が英字の位置に並べる。
漢字を含む語の読みを空のままにすると、語の漢字がコードポイントの順で並び、上と同じく黙って末尾へ回るので、誤りとする。
漢字の判定は、CJK 統合漢字とその拡張、CJK 互換漢字、踊り字「々」による。
かなと英字のほかの記号（「・」など）は、読みに書けないが、語から読みを作るときは許す。
照合はそうした記号を最初の群に並べるので、位置は決まり、黙って漢字の後へ回ることはない。

### `[term: 語]`

`[term: 語]` は、散文スロットを一つだけ取る。

- 本文には、散文スロットのインラインをそのまま出す。ルビや文字スタイルも残る。
- 散文スロットの文字列（テキスト、ルビの親文字、文字スタイルの中の文字）を語とし、TSV から引く。
- TSV にある語なら、本文の後にチャネル `glossary` の項目を一つ足す。キーは語、読みは TSV の読み（空なら語）である。
- 見出し語を位置引数で書く形（`[term 組む: 組んだ]`）は、別の草稿（[docs/adr/0127](0127-glossary-headword-argument.md)）で決める。

項目の本文は、語、全角の空白、定義である。
ラベルの欄があれば、その後に `（→`、ラベルへのページ番号の参照、`）` を足す。

### 一覧

一覧は、利用者が `@channel glossary` で置く。
組み方は [golem-doc ADR 0007](../golem-doc/adr/0007-plugin-channel-lists.md) のとおりである。

| 媒体 | 一覧の項目 |
| --- | --- |
| PDF | `語　定義（→参照のページ）　出現のページの列` |
| HTML と EPUB | `語　定義（→参照先の題へのリンク）` と、出現へのリンク（`1`、`2`、…） |
| プレーンテキスト | `語　定義（→「参照先の題」）` |

出現の位置の印（アンカー）は、ホストが置く `c-glossary-<ファイル>-<位置>` の `id` を使う。
プラグインはアンカーを作らない。
参照のラベルは、原稿の `@label` で付けたものを使う。

### プラグインの diagnostic

どれもエラーであり、位置は `[term]` の呼び出しである。
誤りがあっても、本文の語は消さずに出し、項目だけを送らない。
コードは原因ごとに一つとし、TSV の行の誤りも原因ごとに分ける。

| コード | 原因 | メッセージ |
| --- | --- | --- |
| `slot` | 散文スロットが一つでないか、その文字列が空 | `term には語を一つ書きます` |
| `no-data` | `data` に `terms` がない | `manifest.toml で data の terms を渡してください` |
| `utf8` | TSV が UTF-8 でない | `terms が UTF-8 ではありません` |
| `tsv-columns` | 欄の数が 3 か 4 でない行 | `terms の <n> 行めの欄の数が 3 か 4 ではありません` |
| `tsv-empty` | 語、定義、ラベルの欄が空の行 | `terms の <n> 行めの語、定義、ラベルのどれかが空です` |
| `tsv-no-reading` | 読みが空で、語が漢字を含む行 | `terms の <n> 行めの語は漢字を含むので、読みが要ります: <語>` |
| `tsv-reading` | 読みに、かなと英数字のほかの文字を含む行 | `terms の <n> 行めの読みには、かなと英数字だけを書きます: <読み>` |
| `tsv-duplicate` | 前の行と同じ語の行 | `terms の <n> 行めの語は、前の行にもあります: <語>` |
| `unknown` | TSV にない語 | `terms にない語です: <語>` |

引数の誤り（`args`、`headword-type`、`headword-empty`）は、見出し語の草稿で決める。

コードは、プラグインが返す後ろの部分である。
ホストは、プラグインの宣言の名前を前置して `glossary/tsv-columns` のように表示する（[docs/adr/0108](0108-plugin-diagnostic-codes-and-spans.md)）。
[docs/adr/0108](0108-plugin-diagnostic-codes-and-spans.md) が実装されるまでは、前置のない `tsv-columns` のまま表示される。
この ADR のコードは [docs/adr/0108](0108-plugin-diagnostic-codes-and-spans.md) に従う。
割り当てられた G06020 から G06023 は使わなかった。
プラグインが Golem のコードを返すと、Golem の diagnostic と見分けられないからである。

### HTML の目次

HTML と EPUB の目次（`@toc`）は、見出しのインラインから索引の印とチャネルの項目を除いて書く。
PDF の目次と同じ扱いであり、`id` を見出しの位置の一か所にだけ置くためである。

### モジュールの変更

golem-* のパッケージのあいだの build-depends は変えない。

- `plugins/glossary/`（Rust の crate）と `plugins/wasm/glossary.wasm` を足す。
- golem-html の `toc` を直す。
- golem-driver のテストに、`glossary.wasm` を使うテストを足す。

## 実装しないこと

- 縦組みのページ番号への参照を漢数字にすること。プラグインと関係のない不具合として、[docs/adr/0118](0118-ref-page-numerals-in-vertical-text.md) で直す。
- 見出し語を引数で書く形。[docs/adr/0127](0127-glossary-headword-argument.md) で決める。
- 漢字を含む語の読みを、形態素解析の辞書で補うこと。読みは TSV に書く。
- 一覧の見出しの文字（「あ」「か」）と段組み。[golem-doc ADR 0007](../golem-doc/adr/0007-plugin-channel-lists.md) の「実装しないこと」のとおりである。
- 項目の書式（語と定義のあいだの空白、矢印）を利用者が変えること。
- TSV にあって原稿に現れない語を一覧に載せること。プラグインは原稿の全体を見られないので、載せる語を知るには `[term]` が要る。
- 一語に複数の参照先を持たせること。

## テスト設計

先に次のテストを書き、プラグインの wasm がない状態と、HTML の目次を直す前の状態で失敗することを確かめてから実装した。
Rust のテスト（`plugins/glossary/src/lib.rs`）は、実装と同時に書いた。
読みを省ける形と見出し語の引数を足したときは、driver のテストを先に直し、前の `glossary.wasm` で 7 件が失敗することを確かめてから wasm を作り直した。

Rust のテスト（`cargo test -p glossary`）で、次のことを確かめる。

- `golem_describe` が、コマンド `term`、読みの順で `locators` の真なチャネル `glossary`、データ `terms` を宣言する。
- 3 欄と 4 欄の行が読め、空の行と `#` の行が飛ばされる。
- 欄の数、空の欄、読みの文字、重複した語の誤りが、原因ごとのコードと行の番号とともにすべて報告される。
- 読みが空の行で、漢字を含まない語（カーニング、Golem、記号を含む語）は語が読みになり、漢字を含む語（組版、々）は `tsv-no-reading` になる。
- `[term: 組版]` が、語のテキストとチャネルの項目（キー、読み、本文）を返す。
- 4 欄めがページ番号への参照（tag 10、`RefKind::Page`）になる。
- ルビの付いた語の文字列が親文字の連なりになり、ルビが本文に残る。
- 各誤りで、本文の語が残り、チャネルの項目を返さない。

golem-driver のテスト（`modules/golem-driver/test/PluginsSpec.hs`）では、`plugins/wasm/glossary.wasm` を使い、次のことを確かめる。

- プレーンテキストで、`組版`、`カーニング`（TSV の読みは空）の順に書いた語が、読みの順（カーニング、組版）で一覧に並び、参照が「」で括った題になる。
- 横組みの PDF で、出現のページの列（`1, 2`）と、参照のページ（`（→2）`）が付く。
- 縦組みの PDF で、出現のページと参照のページがどちらも漢数字（`（→一）　一`）になり、本文の `[ref-page]` も「一」になる。このテストは、`ref-page-vertical-numerals` をマージした後の期待値である。
- 存在しないラベルの参照が G04003 になる。
- TSV にない語が `unknown` になり、位置が呼び出しで、本文に語が残る。
- 見出しの中の語と索引の印の `id` が、同じファイルの `@toc` があっても一つずつである。
- HTML で、一覧が別のファイルの出現へ相対リンクし、参照がラベルの要素へのリンクになる。HTML と EPUB のバイト列が、二度組んで同じになる。

手で確かめたこと：

- 三章の縦組みの本（A6、Noto Serif JP）を `golem build` で四つのターゲットに組み、PDF の巻末の用語集を目で確かめた。
- その EPUB を EPUBCheck 5.4.0 にかけ、メッセージが 0 件だった。取得は `scripts/ci/epubcheck-install.sh 5.4.0 33350c61038e71dfb3d45a76aed04bf5481e6d5500cb780f6e98db8bbd15a28c` で、CI と同じ版と SHA-256 である。
- 見出しに `[term]` を書き、同じファイルに `@toc` を置いた EPUB が、直す前は RSC-005 のエラーを二つ出し、直した後は 0 件になった。
- 同じ入力から二度組んだ出力の 11 のファイルが、同じバイト列だった。
- 読みを空にした語（カーニング、ルビ）と、見出し語の引数（`[term 組版: 組んだ]`）を足した本でも、上の三つが同じ結果だった。縦組みの PDF の参照のページは「（→二）」と漢数字になった。

## トレードオフ

定義を TSV に限ったので、本文を書きながら定義を足すことができず、二つのファイルを行き来することになる。
その代わり、一覧の本文はどの出現から送っても同じになり、エントリの本文を最初の項目から取る規則（[golem-doc ADR 0007](../golem-doc/adr/0007-plugin-channel-lists.md)）に左右されない。

漢字を含む語の読みは書き手に書かせるので、その数だけ読みを書く手間がかかる。
辞書を埋め込めば手間は減るが、wasm が大きくなり、辞書のライセンスを確かめる必要が生じ、読みの誤りが書き手から見えなくなる。
用語集の語は数十から数百であり、読みを一度書けば足りる。
かなと英字の語は読みを省けるので、手間はその分だけ減る。

読みを省いた語は、照合が語の文字をそのまま読むので、記号を含む語の位置は照合の規則に任せることになる。
読みを書けば、書き手が位置を決められる。

TSV の誤りは、呼び出しの数だけ報告される。
重複を減らす仕組みは、[docs/adr/0120](0120-plugin-data-check-at-load.md) で扱う。

TSV の誤りのコードを原因ごとに分けたので、コードの数が増えた（TSV だけで五つ）。
その代わり、`golem explain` や利用者のマニュアルで、原因ごとの直し方を書ける。

参照の文言を「（→」と「）」に限ったので、PDF では「（→12）」となり、「ページ」の語が付かない。
媒体によって参照の表示が違う（PDF は数、HTML は題）ので、どの媒体でも読める文言に絞った。

HTML の目次から索引の印とチャネルの項目を除いたので、目次のリンクの中に `id` は置かれない。
目次の側に置いた `id` を指すリンクは、もともとない。

## 決めたことの記録

2026-10-29、メンテナーが最初の試作の報告に対して次のことを決めた。

- HTML の目次で `id` が重複する不具合の修正（このブランチの修正）でよい。
- 縦組みの `[ref-page]` は、仕様のとおり既定で漢数字にする。縦組みでも算用数字を選べる `style.toml` の設定を rc4 で足す。別の草稿 [docs/adr/0118](0118-ref-page-numerals-in-vertical-text.md) とし、origin/main からのブランチ `ref-page-vertical-numerals` で試す。用語集のテストの期待値は、それに合わせる。
- 読みは省けるようにする。漢字を含まない語では語そのもので並べ、漢字を含む語は並べるのに読みが要るので誤りのままとする。コードは原因ごとに一つとする。
- 見出し語を引数で書く形 `[term 組版: 組んだ版]` の草稿を起こし、`plugins-glossary` で実装する（[docs/adr/0127](0127-glossary-headword-argument.md)）。
- プラグインの diagnostic のコードは、ホストが前置する形（`glossary/tsv`）とする。
- データを読み込みで一度だけ検査する草稿（[docs/adr/0120](0120-plugin-data-check-at-load.md)）を採る。
