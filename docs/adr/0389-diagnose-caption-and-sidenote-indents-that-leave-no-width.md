# ADR 0389: キャプションと傍注の行の幅を字下げが使い切るときの diagnostic

Status: accepted

## 文脈

[ADR 0367](0367-caption-sidenote-paragraphs.md) で、PDF のキャプションと傍注の本文に、段落スタイル `caption` と `sidenote` の字下げ（`indent`、`first-line-indent`、`end-indent`）を掛けるようにした。
行の使える幅は、部品の内幅から、その行の字下げと `end-indent` を引いた長さである。
部品の内幅は、部品ごとに違う。
図版のキャプションは、回り込む図版では図版の幅、一ページに回した図版では枠の長さ、ほかは段の行長である。
表のキャプションは段の行長、コードブロックのキャプションはブロックの始まりから段の終わりまでの長さ、傍注は傍注の領域の幅である。

しかし、字下げが内幅を使い切っても、それを原因として示す diagnostic は無い。
本文の段落の字下げは G07025 が検査するが、G07025 は段の行長で検査するので、`caption` と `sidenote` を検査から除いている（[`indentDiagnostics`](https://github.com/tett23/golem/blob/1af39d23caab1741845bd4a025350bf3d2b4e6a6/modules/golem-typeset/src/Golem/Typeset/Flow.hs#L478-L501)）。
G07038 に達しなければ、出るのは溢れた行ごとの G07105 の警告だけであり、prod のプロファイルでも PDF を書く。
ロードマップは、これを未決事項「キャプションと傍注の内幅を超える字下げ」に挙げている。
その項目によれば、そのとき行は一字ずつの溢れた行になり、図版のキャプションでは段の行数を超えて G07038 になることがある。

tett23 は、この場合を dev のプロファイルでは警告、prod のプロファイルではエラーにすると決めた（2026-11-17）。
書きかけの原稿では組んで結果を見られるようにし、入稿やデプロイのために組む本では、字下げの書き誤りを PDF を書く前に止めるためである。

## 調査した事項

- 行の幅の計算：`partLines` は、段落の最初の行の字下げを `indent` と `first-line-indent` の和、ほかの行の字下げを `indent` とし、各行を「内幅 − その行の字下げ − `end-indent`」の幅で分ける（[`partLines`](https://github.com/tett23/golem/blob/1af39d23caab1741845bd4a025350bf3d2b4e6a6/modules/golem-typeset/src/Golem/Typeset/Flow.hs#L244-L256)）。幅が 0 以下になる場合の扱いは無い。
- キャプションの字下げと文字の大きさの出どころ：図版、表、コードブロックのキャプションは、字下げを本の全体のスタイル（`piStyle`）の `caption` から引き、文字の大きさをそのファイルのスタイル（`uStyle u`）の `caption` から引く（[`Flow.hs`](https://github.com/tett23/golem/blob/1af39d23caab1741845bd4a025350bf3d2b4e6a6/modules/golem-typeset/src/Golem/Typeset/Flow.hs#L2575-L2604)、[`Flow.hs`](https://github.com/tett23/golem/blob/1af39d23caab1741845bd4a025350bf3d2b4e6a6/modules/golem-typeset/src/Golem/Typeset/Flow.hs#L2771-L2774)）。そのため、ファイルのスタイルが `caption` の字下げを書いても、キャプションに当たらないと読める。仕様書は、`caption` に字下げを書けばその字下げで組むと定め、`@style-def` でも書けるとする。これはコードを読んだ結果であり、動かして確かめていない。
- G07025 の形：「段の行長 − `indent` − max(0, `first-line-indent`) − `end-indent`（囲みがあれば左右の `padding` も）」が、段落の文字の大きさの 8 字分に満たない段落スタイルをエラーにする。`style.toml` と各ファイルのスタイルを検査し、位置は `style.toml` の先頭である。`caption`、`sidenote`、`code` と `toc-` で始まる段落スタイルは除く（同じ `indentDiagnostics`）。
- G07025 は、レイアウトの前に PDF を止める。`checkedGeometry` は、`indentDiagnostics` などの diagnostic が一つでもあれば、重大度を見ずにレイアウトしない（[`checkedGeometry`](https://github.com/tett23/golem/blob/1af39d23caab1741845bd4a025350bf3d2b4e6a6/modules/golem-typeset/src/Golem/Typeset/Flow.hs#L503-L510)）。
- ドライバーにも、PDF を止める門が二つある。`styleLayoutDiagnostics` の diagnostic（G07025 など）が一つでもあれば、重大度を見ずに PDF を書く対象から外す（[`Driver.hs`](https://github.com/tett23/golem/blob/1af39d23caab1741845bd4a025350bf3d2b4e6a6/modules/golem-driver/src/Golem/Driver.hs#L873-L889)）。評価の diagnostic にプロファイルを当てた後でエラーがあれば、レイアウトに入らない（[`Driver.hs`](https://github.com/tett23/golem/blob/1af39d23caab1741845bd4a025350bf3d2b4e6a6/modules/golem-driver/src/Golem/Driver.hs#L897)）。そのため、prod でだけエラーになる diagnostic（G05004 など）がある原稿では、prod はレイアウトしない。
- 重大度がプロファイルで変わるコードは、`profileDependentCodes` にまとめてある。今は G05004、G03010、G08100、G08103 の四つである（[`profileDependentCodes`](https://github.com/tett23/golem/blob/1af39d23caab1741845bd4a025350bf3d2b4e6a6/modules/golem-syntax/src/Golem/Syntax/Diagnostic.hs#L193-L199)）。
  - `docs/diagnostics.md` の「重大度がプロファイルで変わるコード」の段落は「三つ」と書き、G08103 を挙げていない。
  - golem-syntax のテストは、`profileDependentCodes` の段階の並びを `["05", "03", "08", "08"]` と決め打ちで確かめている（[`Main.hs`](https://github.com/tett23/golem/blob/1af39d23caab1741845bd4a025350bf3d2b4e6a6/modules/golem-syntax/test/Main.hs#L188)）。
- 溢れた行：PDF をターゲットに含む `golem build` は、行長からはみ出す行を、描いた行ごとに G07105 の警告で報告する。G07105 は、キャプションと傍注の行も対象とし、dev と prod の両方で警告である（`docs/specifications.md` の G07105 の段落、`docs/diagnostics.md` の G07105 の項）。
- 傍注の領域の幅は、`style.toml` の `[sidenotes]` の `width` で決まる。`[sidenotes]` の無い横組みの版面で傍注を使うと G07034、縦組みで傍注を使うと G07032 である（`docs/specifications.md` の「傍注」の節）。
- キャプションの内幅の決まり方：回り込む図版の幅は原稿の `@figure` の引数と版面で、一ページに回した図版の枠は版面で、表のキャプションの内幅は段の行長で決まる。リストの中のコードブロックの始まりは、リストの印の幅を測るまで決まらない（[`Flow.hs`](https://github.com/tett23/golem/blob/1af39d23caab1741845bd4a025350bf3d2b4e6a6/modules/golem-typeset/src/Golem/Typeset/Flow.hs#L2561-L2588)）。
- `golem check` は PDF を組まない（`docs/specifications.md` の G07108 の段落）。`golem check` は `--profile` を受け取る（`docs/specifications.md` のコマンドの表）。

## 実装すること

### 字下げが行の幅を使い切る場合

キャプションか傍注の行の幅を字下げが使い切る場合を、次のとおり定める。

- `w` を部品の内幅とする。`s`、`f`、`e` と `z` は、そのキャプションか傍注を含むファイルのスタイル（ファイルのスタイルが無ければ本の全体のスタイル）の `caption` か `sidenote` の `indent`、`first-line-indent`、`end-indent` と文字の大きさとする。
- 行の最も狭い幅 `m` を、`w` − `s` − max(0, `f`) − `e` とする。G07025 と同じく、負の `first-line-indent`（ぶら下げ）は最初の行を広げるだけなので、`m` の計算に入れない。
- `w` ≥ `z` かつ `m` < `z` のとき、字下げが行の幅を使い切るとする。1 字分に満たない行には、全角の字が一字も収まらないためである。
- `w` < `z` のときは、字下げではなく部品そのものが 1 字分より狭いので、この ADR の diagnostic を出さない（「実装しないこと」）。
- G07025 の下限（8 字分）は使わない。キャプションと傍注は本文より狭い部品に組むものであり、8 字分に満たない部品の幅そのものは誤りではないためである。
- 1 字分以上あっても、禁則、欧文の語、改行しない範囲で溢れる行はある。それは今のとおり G07105 が報告する。

### キャプション（G07127）

PDF のキャプションのうち、字下げが行の幅を使い切るものを G07127 とする。

- 検査するのは、図版、表、コードブロックのキャプションのうち、組む行が一つ以上あるもの（番号だけのものを含む）である。
- PDF をターゲットに含む `golem build` が、レイアウトの中で報告する。`golem check` と LSP は出さない。
  - 回り込む図版、一ページに回した図版、表のキャプションの内幅は、原稿と `style.toml` からも求められる。リストの中のコードブロックの内幅は、レイアウトでしか求められない。キャプションの検査を一か所にまとめるため、すべてレイアウトの中で行う。
- 実際に置くキャプションごとに一度出す。大きさの見積もりやページ分割のために組み直したキャプションでは、重ねて出さない。
- 位置は、そのキャプションを持つブロック（`@figure`、表、コードブロック）である。

メッセージは次のとおりとする。

```text
キャプションの字下げが行の幅を使い切ります。段落スタイル caption の字下げを小さくしてください
```

### 傍注（G07128）

段落スタイル `sidenote` の字下げが、傍注の領域の幅を使い切るものを G07128 とする。

- 傍注の領域の幅は `style.toml` だけで決まるので、`style.toml` と各ファイルのスタイルの `sidenote` を検査する。`[sidenotes]` が無い版面と、縦組みの版面では検査しない（縦組みの傍注は G07032 である）。
- PDF をターゲットに含むビルドと `golem check` が報告する。LSP は出さない（G07025 と同じ）。
- G07025 と違い、G07128 はレイアウトを止めない。`checkedGeometry` の門にも、ドライバーの `styleLayoutDiagnostics` の門にも掛けない。prod で G07128 が出ても、ほかにレイアウトを止める diagnostic が無ければレイアウトを行い、G07127 などのレイアウトの diagnostic を dev と同じに出す。tett23 は、なるべく多くの誤りを一度に見つけるため、止めるのはできるだけ遅らせると決めた（2026-11-17）。止めると、prod でだけ G07127 などが出なくなる。
- 一回のビルドで高々一度出す。位置は `style.toml` の先頭で、`style.toml` がなければ `manifest.toml` の先頭である（G07025 と同じ）。

メッセージは次のとおりとする。

```text
傍注の字下げが傍注の領域の幅を使い切ります。字下げを小さくするか、[sidenotes] の width を広げてください
```

### ファイルのスタイルの `caption` の字下げ

キャプションの字下げを、そのキャプションを含むファイルのスタイルの `caption` から引くように直す。
仕様書は、`caption` に字下げを書けばその字下げで組むと定め、`@style-def` でも書けるとしている（「調査した事項」）。
今の実装は字下げを本の全体のスタイルから引くので、仕様書と食い違う。
tett23 は、実装が仕様書と食い違うときは仕様書に合わせると決めた（2026-11-17）。
この直しは、G07127 の `m` を、実際に組む字下げで求めるためにも要る。

### 重大度と出力

G07127 と G07128 は、dev のプロファイルでは警告、prod のプロファイルではエラーとする。
二つのコードを `profileDependentCodes` に加える。

- dev では、二つのコードは PDF を書くかどうかを変えない。行の割り付けは今のままで、G07105、G07038、G07033 などのほかの diagnostic も今のとおり出す。
- prod では、二つのコードのどちらかが出れば PDF を書かない。
- `golem check` での G07128 の重大度は、`--profile` に従う。

### 二つのコードに分ける理由

キャプションと傍注は、原因と直し方が違うので、一つのコードにまとめない。
キャプションの内幅は原稿と版面とレイアウトで決まり、部品の種類ごとに広げ方が違う。
どの部品でも有効な直し方は、字下げを小さくすることである。
傍注の領域の幅は `style.toml` だけで決まり、直し方は字下げを小さくするか、`[sidenotes]` の `width` を広げることである。
検査する段階（レイアウトの中か前か）と位置（ブロックか `style.toml` か）も違う。

### 文書

- 仕様書の「組み込みの段落スタイル」と「傍注」の節に、二つの検査を書く。
- `docs/diagnostics.md` と、その埋め込み（`golem explain`）に G07127 と G07128 を足す。「重大度がプロファイルで変わるコード」の段落を、G08103 を含めた今の一覧に直す。G07105 の項に、G07127 が G07105 と同じキャプションに重ねて出ることを書く。
- README の、キャプションと傍注の字下げの段落に、二つの diagnostic を書く。
- ロードマップの未決事項「キャプションと傍注の内幅を超える字下げ」を消す。
- マニュアルの diagnostic の付録に二つのコードを足す。

## 実装しないこと

- 字下げの下限を 8 字分のような、1 字分より大きい値にすること。
- 部品の内幅そのものが 1 字分に満たない場合（`w` < `z`）の diagnostic 。字下げの誤りではなく、図版の `width` や `[sidenotes]` の `width` の誤りなので、決めるなら別の ADR で決める。
- 字下げを自動で小さくして組むこと。出力を黙って変えないためである。
- HTML と EPUB のキャプションと傍注の検査。HTML と EPUB には [ADR 0367](0367-caption-sidenote-paragraphs.md) の字下げを当てていない（ロードマップの未決事項「HTML と EPUB のキャプションと傍注の段落の組み方」）。
- G07025 の検査の範囲を変えること。

## 不変条件

以下で、`w`、`s`、`f`、`e`、`z` と `m` は「字下げが行の幅を使い切る場合」の節のとおりとする。

- I1: レイアウトに入った PDF のビルドで、組む行が一つ以上あるキャプションについて、G07127 がそのキャプションに出るのは `w` ≥ `z` かつ `m` < `z` のときであり、かつそのときに限る。
- I2: 版面の検査を通った `[sidenotes]` のある横組みの版面で、PDF をターゲットに含むビルドか `golem check` を動かすとき、本の全体か一つのファイルのスタイルの `sidenote` に `w` ≥ `z` かつ `m` < `z` のものがあるとき、そしてそのときに限り、G07128 が出る。
- I3: G07127 と G07128 の重大度は、dev のプロファイルでは警告、prod のプロファイルではエラーである。
- I4: dev のプロファイルで、G07127 と G07128 のほかにエラーが無いビルドは、PDF を書く。
- I5: prod のプロファイルで、G07127 か G07128 が出たビルドは PDF を書かない。
- I6: 評価の diagnostic にエラーが無く、版面の検査を通った入力で、G07128 のほかにレイアウトを止める diagnostic が無ければ、prod のプロファイルも dev と同じ G07 のコードの集合を出す。
- I7: キャプションと傍注の行の割り付け（各行の行の番号、字下げ、分けた内容）は、G07127 と G07128 を出すかどうかによらない。
- I8: G07128 は、一回のビルドで高々一度出る。
- I9: `golem check` は G07128 を出し、G07127 を出さない。
- I10: LSP は G07127 も G07128 も出さない。
- I11: PDF のキャプションの各行の字下げは、そのキャプションを含むファイルのスタイル（ファイルのスタイルが無ければ本の全体のスタイル）の `caption` の字下げから決まる。

ことわりの無い行は `w` ≥ `z` とする。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 字下げがすべて 0 で `w` ≥ `z` | 出ない | I1, I2 |
| 字下げがすべて 0 で `w` < `z` | 出ない | I1, I2 |
| 字下げが正で `w` < `z` | 出ない | I1, I2 |
| `m` がちょうど `z` | 出ない | I1, I2 |
| `m` が `z` より 1 sp 小さい | 出る | I1, I2 |
| `m` が 0 | 出る | I1, I2 |
| `m` が負 | 出る | I1, I2 |
| `f` が負で、`s` + `e` = `w` − `z` | 出ない（ぶら下げは `m` に入れない） | I1, I2 |
| 番号だけのキャプションで `m` < `z` | 出る | I1 |
| `[sidenotes]` が無い | G07128 は出ない | I2 |
| 縦組みの版面に `[sidenotes]` がある | G07128 は出ない | I2 |
| `m` < `z` の表のキャプション（G07038 に達しない）を dev と prod で組む | dev は警告で PDF あり、prod はエラーで PDF なし | I3, I4, I5 |
| `m` < `z` の `sidenote` と `m` < `z` のキャプションを dev と prod で組む | どちらのプロファイルでも G07127 と G07128 が出る | I6 |
| `m` < `z` のキャプションと傍注を組む | 行の割り付けが実装の前と同じ | I7 |
| 本の全体と二つのファイルのスタイルで `sidenote` が `m` < `z` | G07128 が一度 | I8 |
| `m` < `z` の `sidenote` と `m` < `z` のキャプションを `golem check` で検査する | G07128 だけが出る | I9 |
| `m` < `z` のキャプションと `sidenote` を LSP で開く | どちらも出ない | I10 |
| 本の全体の `caption` は字下げ 0、あるファイルのスタイルの `caption` は 1 字下げ | そのファイルのキャプションだけ 1 字下げで組む | I11 |

## 受けいれ条件

- A1: `docs/diagnostics.md` の「重大度がプロファイルで変わるコード」の段落が、`profileDependentCodes` のすべてのコードを挙げる。golem-driver の diagnostic の一覧のテストが、G07127 と G07128 の項の重大度と `profileDependentCodes` の一致で通る。

## テスト設計

テストの名前は `ADR 0389 I<n>: ` で始める。

- I1 は、字下げと内幅を小さい整数の範囲で数え尽くし、回り込む図版、回り込まない図版、一ページに回した図版（`rotate=true`）、表、リストの外と中のコードブロックのキャプションごとに、G07127 と「`w` ≥ `z` かつ `m` < `z`」の同値を確かめる。境界の表の I1 の行を、それぞれ一つのケースとして書く。
- I2 は、`[sidenotes]` の `width` と `sidenote` の字下げを数え尽くし、G07128 と「`w` ≥ `z` かつ `m` < `z`」の同値を確かめる。`[sidenotes]` の無い版面と、縦組みの版面も入れる。
- I3、I4、I5 は、G07038 と G07033 に達しない入力（表のキャプションと、短い傍注）で `golem build` を dev と prod で動かし、JSON の diagnostic の重大度と `build/pdf` の有無を確かめる。
- I6 は、評価の diagnostic にエラーが無い同じ原稿を dev と prod で組み、G07 のコードの集合を比べる。
- I7 は、`m` < `z` のキャプションと傍注の `PartLine` の並びを、実装の前のコミットで作った golden と比べる。このテストは実装の前から通るので、先に失敗させる手順の例外とする。
- I8 は、本の全体と二つのファイルのスタイルに `m` < `z` の `sidenote` を書いた原稿で、G07128 の数を数える。
- I9 は、`golem check` の JSON の出力に G07128 があり G07127 が無いことを確かめる。
- I10 は、LSP の diagnostic に二つのコードが無いことを確かめる。
- I11 は、本の全体とファイルのスタイルで `caption` の字下げが違う原稿で、図版、表、コードブロックのキャプションの `PartLine` の字下げを確かめる。実装の前は失敗する。
- A1 は、golem-driver の diagnostic の一覧のテストで確かめる。golem-syntax のテストの `profileDependentCodes` の段階の並びの期待を、二つのコードを足した並びに直す。

## トレードオフ

- 1 字分の下限は、1 字分ちょうどの行を許すので、一字ずつの行が並ぶ組版は誤りにならない。8 字分のような大きな下限は、狭い傍注の領域の正しい組版を誤りにするので、選ばなかった。
- キャプションの検査はレイアウトの中で行うので、`golem check` と LSP では見つからない。prod のビルドで初めてエラーになる原稿がありうる。
- dev で警告にとどめるので、書きかけの原稿では溢れた行のまま PDF ができる。
- G07128 はレイアウトを止めないので、G07025 と止め方が違う。そのかわり、prod でも G07127 などのレイアウトの diagnostic を一度に見られる。
