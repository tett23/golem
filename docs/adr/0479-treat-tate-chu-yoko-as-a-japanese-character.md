# ADR 0479: 縦中横の外側を和文一字として扱い、縦中横の IR を共通にする

Status: proposed

## 文脈

2026-11-27 に、指示者は縦中横の外側に余分な空きを付けず、和文の中では和文の一字と同じように扱うよう求めた。
`[number-text 1 style="tcy"]` も同じ扱いとし、異なる IR を使っていれば統一するよう求めた。
数の糖衣構文と明示コマンドは、同じ IR にする。

ここで扱う空きは、縦中横の箱と隣の文字との間に入る空きである。
箱の中の文字の組み合わせによるカーニングとは分ける。
既定の和文と欧文の間の四分アキを、縦中横の中身が数字であるという理由で箱の外側へ付けない。
書き手が明示したトラッキングやアキは保つ。

## 調査した事項

main のコミット `8702daa2642dd683ef3e3f13251dbb39d93066a5` のソースを調べた。
組版の実行には、同じ組版ソースを持つ `81adc858419ae607483e5889091d18e8561fab4d` の GHC 9.10.3 のビルドを使った。

- 意味論 IR は、文字列の `Tcy` と、`StyleTcy` を持つ `Number` を別のコンストラクターにしている。
- PDF の組版は、文字列の `Tcy` と、縦組みの `Number` の `StyleTcy` を、同じ一字分の `KindTcy` の箱にする。
- `Japanese.hs` の `normalize` は、箱の外側の文字クラスを中身の先頭と末尾の文字から求める。
  `KindTcy` に対する外側のクラスの特別な扱いはない。
- `composeInlines` に、既定の設定と文字の大きさ 655360 sp を渡し、`あ`、`Tcy "12"`、`い` を縦に組むと、前後に各 163840 sp の `JapaneseWesternGlue` が入った。
  `Number 12 (Just StyleTcy)` でも同じ結果だった。
  どちらも箱自体の長さは 655360 sp であり、外側の空きはその四分の一だった。
- 横組みの PDF は、文字列の `Tcy` を一字分の箱にするが、`Number` の `StyleTcy` は通常の数値の文字列へ展開する。
  HTML も、文字列の `Tcy` は `tcy` クラスの要素にし、横組みの `Number` は通常の文字列にする。
- 糖衣構文は、すでに `number-text` へ表記名を `style` として直接渡す。
  [root ADR 0478](0478-accept-rational-values-in-number-text.md) は、有理数の正確な値を IR に保ち、表示時に正規化すると定めている。

## 実装すること

### 箱の外側の扱い

組版で縦中横になった箱は、外側から和文の通常の一字として扱う。
外側のクラスは漢字と同じにし、箱の中の数字、欧文、括弧、句読点のクラスを、外側の空きと禁則の判定へ持ち出さない。
縦中横の箱の中では改行しない。

既定の設定では、和文と縦中横の間、および縦中横どうしの間に、和欧混植の四分アキを入れない。
欧文と縦中横の間は、欧文と和文一字の間として、通常の混植の規則を使う。
外側の括弧と句読点には、和文一字に隣接するときの既存の空きと禁則を使う。
縦中横の内部の数字を根拠に、外側の文字と数値や単位の組として結び付けない。

この扱いは、原稿の縦中横、数の表記から決まる縦中横、プラグインと Emet の縦中横、注の本文やページ番号の縦中横にも適用する。
注の呼出印全体を前の字に付ける規則など、外側に別の意味を持つ要素の配置は保つ。

トラッキングは、[root ADR 0370](0370-tracking-inline-boxes.md) と [root ADR 0414](0414-record-what-the-implementations-of-adr-0370-and-0395-decided.md) の規則を保つ。
PDF では、書き手が明示したトラッキングを、通常の和文一字と同じく、箱の外側へ一回だけ適用する。
PDF の行末で返す扱いも保つ。
HTML と EPUB は root [ADR 0414](0414-record-what-the-implementations-of-adr-0370-and-0395-decided.md) の既存の `letter-spacing` を保ち、縦中横の内部にも字間が入りうる扱いを変更しない。
明示した `[aki ...]` と、利用者が変更したアキ量の設定も保つ。
既定の設定で余分な混植アキを付けないことと、明示した字間を無効にすることを混同しない。

### 縦中横の意味論 IR

明示した縦中横は、共通の `Tcy` ノードで表す。
中身は、文字列を保つ `TcyLiteral Text` と、正確な数値を保つ `TcyNumber Rational` の二つにする。
どちらも同じ `Tcy` の原稿の位置と、同じ外側の組版規則を使う。
文字列と数値の違いは中身の型に閉じ込める。

`[tcy: 001]` は `TcyLiteral "001"` とし、先頭の 0 を保つ。
`[tcy: ab]` や `[tcy: !?]` も、文字列を数値として読み直さない。
`[number-text 1 style=tcy]` は `TcyNumber` の値 1 とする。
`##1:tcy##` も、原稿の位置を除いて同じノードと全フィールドを持つ。
`[number-text 0.10 style=tcy]` と `##0.1:tcy##` は、ともに `TcyNumber` の値 1/10 を持つ。
糖衣構文の名前解決と `style` 引数の直接の受け渡しは保つ。

`Number` に `StyleTcy` を残して明示した縦中横を表すことはせず、生成時に `TcyNumber` へ統一する。
`style` を省いた数は、書字方向と本の設定が分かるまで `Number` として値を保つ。
その数が縦中横に決まったときも、出力に渡す縦中横の箱は、明示した `TcyNumber` と同じものにする。
出力用の箱の中身は、文字列はそのまま、数値は root [ADR 0478](0478-accept-rational-values-in-number-text.md) の正規化した表記とする。
同じ表示文字列と文字のスタイルなら、どの記法から作っても同じ縦中横の箱になる。

CBOR のインラインのタグ 8 の中身を、文字列か有理数かを表すタグ付きの値に変える。
文字列は `[0, tstr]`、数値は `[1, rational]` とし、有理数の範囲と既約の検査は root [ADR 0478](0478-accept-rational-values-in-number-text.md) と同じにする。
タグ 9 の `Number` の表記欄では、`StyleTcy` に相当する値を許さない。
旧形式のタグ 8 の文字列ペイロードと、タグ 9 の `StyleTcy` は、新しいスキーマでは不正な出力として拒否する。
CDDL、IR の検査、SDK、プラグインの例、Emet、各出力の走査を同時に更新する。
ABI のバージョンは [root ADR 0052](0052-plugin-abi-version-bump-rule.md) の規則による。

### 横組みとテキスト

横組みでの表示は、IR を共通にしても既存の振る舞いを保つ。
`TcyLiteral` は既存の明示した文字列の縦中横と同じに扱い、`TcyNumber` は通常の横組みの数値として表示する。
PDF で実際に一字分の縦中横の箱になる箇所には、横組みでも上記の和文一字の外側のクラスを使う。

テキストは、文字列の縦中横では元の文字列を出す。
数値の縦中横では、整数の縦組みの漢数字を含め、root [ADR 0478](0478-accept-rational-values-in-number-text.md) の規則を保つ。
これらの違いのために、数値を意味論 IR の段階で文字列へ潰さない。

### HTML と EPUB

HTML と EPUB も、両方の中身から縦中横を作る処理を共通にする。
縦中横の前後へ、Golem が中身の数字や欧文を根拠に空白、マージン、パディングを加えない。
外側に対する通常の字間の指定は保つ。
縦中横は既存の `text-combine-upright` と EPUB の指定を使い、独立した通常の和文一字として扱う。
実際の閲覧ソフトでの字間は検証し、未検証の閲覧ソフトで同じ表示になるとは記録しない。

### 文書と採択の記録

仕様書、README、利用者マニュアルに、縦中横の外側の扱いと明示した字間との関係を書く。
開発者マニュアルには、共通の `Tcy` と中身の二つの型、CBOR、横組みの表示を書く。
採択時には、次の箇所をこの ADR による変更として記録する。

- [golem-layout ADR 0002](../golem-layout/adr/0002-japanese-composition.md) の、縦中横の外側の文字クラスを補足する。
- [root ADR 0478](0478-accept-rational-values-in-number-text.md) の、明示した `StyleTcy` を `Number` で保持する箇所を共通の `TcyNumber` へ置き換える。
- [root ADR 0125](0125-kansuji-plugin-overrides-number-text.md) の、プラグインが縦中横の数を返すノードを置き換える。

## 実装しないこと

縦中横の中のカーニング、拡大縮小、フォントの選択の規則は変えない。
通常の欧文と和文の間の四分アキを全体で無効にしない。
横組みの文字列と数値の既存の表示の違いは、この変更のために消さない。

## 不変条件

- I1: 既定の設定で、和文と縦中横の箱の間および縦中横どうしの間には、和欧混植のアキを加えない。
- I2: 縦中横の外側の空きと禁則は、中身の先頭と末尾の文字によらず、通常の和文一字と同じになる。
- I3: 明示した数の縦中横は `TcyNumber` に統一され、糖衣構文と同じ引数の明示コマンドは位置を除く IR と diagnostic が等しい。
- I4: `TcyLiteral` は文字列を、`TcyNumber` は正確な有理数を、IR と CBOR の往復で保つ。
- I5: 明示したトラッキングとアキ、PDF の行末のトラッキングの除去、HTML と EPUB の既存の `letter-spacing`、横組みとテキストの既存の表示を保つ。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| `あ[tcy: 1]い`、同じ位置の数の縦中横 | 外側の四分アキなし | I1, I2 |
| 縦中横を一つ、二つ、三つ続ける | 中で分割せず、外側は和文と同じ | I1, I2 |
| 中身が `ab`、`!?`、`001` | 中身のクラスを外側へ漏らさない | I2, I4 |
| 欧文と縦中横、括弧と縦中横 | 欧文や括弧と和文一字の既存の規則 | I2 |
| `##1:tcy##` と明示コマンド | 同じ `TcyNumber` | I3 |
| 数値の `0.10` と `0.1` | 同じ正確な値と表示 | I3, I4 |
| 文字列の `001` と数値の 1 | 中身の型と値を保つ | I4 |
| トラッキング 0、正、負と行末 | PDF は一回適用し、行末では返す。HTML と EPUB は既存の字間 | I5 |
| 横組みの文字列と三桁の数値 | 既存の箱と通常の数値表示を保つ | I5 |

## 受けいれ条件

- A1: 通常の CLI で、明示した縦中横、数の縦中横、糖衣構文を含む縦組みと横組みの PDF、HTML、EPUB、テキストを生成する。
- A2: PDF のページを描画して前後の余分な空きがないことを見て、箱の位置とアキの数値も照合する。
- A3: HTML と EPUB の縦中横の出力を確認し、実際に確認した閲覧ソフトと結果を記録する。

## テスト設計

実装前に root ADR 0479 I1 から I5 の回帰テストを追加し、少なくとも I1 と I3 が失敗することを確かめる。
既定のアキで `あ`、縦中横、`い` を組み、余分な四分アキがないことを、和文一字の対照と比較する。
中身を数字、欧文、括弧、句読点へ変え、先頭と末尾、外側の括弧と句読点、行頭と行末を比較する。
数値と単位の改行制御が中身から漏れないことも調べる。

糖衣構文と明示コマンドの位置を除いた全フィールドと diagnostic を比較する。
関数とプラグインによる上書き、未知の表記名でも、同じ名前解決と結果になることを確かめる。
CBOR と実際のプラグイン、Emet で文字列と有理数を往復し、旧形式と不正な中身を拒否することを確かめる。

明示したトラッキングとアキ、異なる文字サイズ、リンクと文字スタイル、ルビの親文字、注とページ番号も照合する。
横組みでは文字列と数値の既存の幅を比較し、整数の縦組みのテキストの表記も比較する。
root ADR 0479 A1 から A3 の手順では、実際の成果物と検証した環境を記録する。

## トレードオフ

和文の一字として外側を扱うため、箱の中の数字に基づく混植のアキや数値と単位の結び付けは使わなくなる。
共通のノードの中身を文字列と数値に分けることで、原綴りと正確な数値の双方を保つ。
一方、IR と CBOR の形を変えるため、SDK とプラグインにも同時の更新が必要になる。
