# ADR 0144: 図版のキャプションには段落だけを置く

ステータス: 採択

## 文脈

### 意味論 IR と出力の食い違い

意味論 IR の図版のキャプションは、ブロックの列である（golem-doc.cddl の `caption: [* block]`、[IR.hs の 224 行め](https://github.com/tett23/golem/blob/97be81e8de344a22a15079b2e56bf0e5ce20ea62/modules/golem-doc/src/Golem/Doc/IR.hs#L224)）。
原稿の `@figure` は、字下げした本体を `evalBlocks` で評価し、そのままキャプションにする（[File.hs の 1199 行め](https://github.com/tett23/golem/blob/97be81e8de344a22a15079b2e56bf0e5ce20ea62/modules/golem-eval/src/Golem/Eval/File.hs#L1199)）。
段落のほかに、リスト、コードブロック、図版なども入る。

一方、どの出力も、キャプションの段落だけを組む。

- PDF：段落のインラインだけを集める（[Flow.hs の 1496 行め](https://github.com/tett23/golem/blob/97be81e8de344a22a15079b2e56bf0e5ce20ea62/modules/golem-driver/src/Golem/Driver/Pdf/Flow.hs#L1496)）。
- HTML と EPUB：同じく段落だけを `<figcaption>` に書く（[Html.hs の 460 行め](https://github.com/tett23/golem/blob/97be81e8de344a22a15079b2e56bf0e5ce20ea62/modules/golem-html/src/Golem/Html.hs#L460)）。
- プレーンテキスト：同じく段落だけである（[Text.hs の 149 行め](https://github.com/tett23/golem/blob/97be81e8de344a22a15079b2e56bf0e5ce20ea62/modules/golem-text/src/Golem/Text.hs#L149)）。

段落でないブロックは、どの出力からも diagnostic なしに消える。
文書構造（S1）は、キャプションの中の図版も数える（[Assemble.hs の 541 行めから 550 行め](https://github.com/tett23/golem/blob/97be81e8de344a22a15079b2e56bf0e5ce20ea62/modules/golem-doc/src/Golem/Doc/Assemble.hs#L541-L550)）ので、消えた図版も図番号を一つ取る。

### 原稿で確かめたこと

`golem new` で作ったプロジェクトで、次の原稿を四つのターゲットで組んだ（`golem` は 5db37cb9 から組んだもので、`modules/` は [97be81e8](https://github.com/tett23/golem/tree/97be81e8de344a22a15079b2e56bf0e5ce20ea62) と同じ）。

```text
@figure img/a.svg alt=x
  外
  @figure img/a.svg alt=y
    内

@figure img/a.svg alt=z
  二つめ

@figure img/a.svg alt=w
  三つめ

  - 項目

  ```
  code
  ```
```

- diagnostic は出ず、終了コード 0 だった。
- `golem inspect --as ir` では、一つめの図版のキャプションに図版が、三つめのキャプションに箇条書きとコードブロックがある。
- PDF、HTML、テキストのどれにも、`内`、`項目`、`code` は出ない。
- 図番号は `図1-1`、`図1-3`、`図1-4` で、消えた図版が `図1-2` を取った。

書き手が書いた内容が黙って消え、図番号が飛ぶ。
「出力を黙って変えない」に反する。

### プラグインの図版（監査の F-26）

[docs/adr/0123](0123-figures-from-plugins.md) は、プラグインが返す図版を出力の最上位に限り、「出力の最上位でない図版（箇条書きの中など）」を不正な出力（G06009）とした。
`placeImages` は箇条書きと定義リストの中だけを調べ、キャプションには降りない（[Plugin.hs の 616 行めから 624 行め](https://github.com/tett23/golem/blob/97be81e8de344a22a15079b2e56bf0e5ce20ea62/modules/golem-plugin/src/Golem/Plugin.hs#L616-L624)）。
`blockKind` はキャプションの中の図版を許し（[同 641 行め](https://github.com/tett23/golem/blob/97be81e8de344a22a15079b2e56bf0e5ce20ea62/modules/golem-plugin/src/Golem/Plugin.hs#L641)）、IR の検査 `validateBlocks` もキャプションの中を拒まない（[Validate.hs の 79 行め](https://github.com/tett23/golem/blob/97be81e8de344a22a15079b2e56bf0e5ce20ea62/modules/golem-doc/src/Golem/Doc/Validate.hs#L79)）。

2026-11-04 の監査（[docs/audits/2026-11-04-rc4-plugin-adr-conformance.md](../audits/2026-11-04-rc4-plugin-adr-conformance.md) の F-26）は、これをコードの読みから指摘し、実機では確かめていなかった。
この ADR を書くために、見本の `bar-chart` を写し、最上位の図版のキャプションに `plugin:chart` の図版を入れて返すプラグインを作って組んだ。

- G06009 は出ず、ビルドは終了コード 0 で通った。
- キャプションの中の図版の `src` は `plugin:chart` のまま IR に残り、`checkFigure` も通らなかった。
- 出力では、キャプションの中の図版は上の原稿の場合と同じく消え、最上位の図版は `図1-2` になった。

[docs/adr/0123](0123-figures-from-plugins.md) の「原稿の図版の検査を一つも迂回しない」に反する。

### 二つを一つの ADR にする理由

原稿の場合とプラグインの場合は、同じ原因から起きている。
キャプションに段落でないブロックを置けること、出力がそれを組まないこと、どこもそれを拒まないことである。
直し方も一つで、キャプションに置けるものを段落に限り、原稿とプラグインの出力の入り口でそれぞれ拒む。
F-26 だけを直して `placeImages` をキャプションに降ろしても、キャプションの中の箇条書きやコードブロックは、プラグインからも原稿からも消え続ける。

## 実装すること

### 規則

図版のキャプションに置けるブロックは、段落だけとする。
段落スタイルの付いた段落は、今と同じく G02013 で拒み、スタイルを除く（[docs/adr/0123](0123-figures-from-plugins.md) と原稿の `@figure`）。

### 原稿：新しいコード G02118

| 項目 | 決めること |
| --- | --- |
| 重大度 | エラー |
| 原因 | `@figure` のキャプション（字下げした本体）を評価した結果に、段落でないブロックがある |
| メッセージ | `図版のキャプションには段落だけを書けます: <種類>` |
| 位置 | 段落でないブロックの位置。ブロックごとに一つ |
| 誤りの後 | そのブロックをキャプションから除き、図版は残す |
| 段階 | 評価（golem-eval の `Golem.Eval.File`） |

`<種類>` は、ブロックの種類の名前（図版、箇条書き、番号付きリスト、定義リスト、表、コードブロック、見出し、一覧の出力、改ページ、改ページの制御、行アキ）である。
[docs/adr/0122](0122-block-commands-in-plugins.md) の `ブロックコマンドが返せないブロックです: <種類>` と同じ名前を使う。

- 既存のコードが先に拒むものは、そのコードのままとし、G02118 を重ねて出さない。たとえば、キャプションの `@blank-line` は G02093 である。G02118 は、評価を通ってキャプションの IR に入ったブロックだけに出す。
- キャプションの中のブロックコマンドのプラグインが返したブロックも、評価を通った後のブロックとして同じく調べる。
- 図版は残すので、図版のラベルと図番号は誤りのないときと同じになる。消えたブロックの中の図版は数えない。

### プラグイン：不正な出力（G06009）

意味論 IR の不変条件 `Golem.Doc.Validate` に、「図版のキャプションのブロックは段落だけ」を足す。
違反の理由は `図版のキャプションには段落だけを置けます` とする。

- ブロックコマンドの出力（`validateBlocks`）とフィルタの出力（`validateDocument`）の両方に当てる。キャプションの中の `plugin:` の図版も、この検査で G06009 になる。
- `placeImages` の「最上位でない図版」の検査（`図版は出力の最上位にだけ置けます`）は、今のとおり箇条書きと定義リストの中だけを調べる。キャプションの中の図版は、キャプションの規則の理由で拒む。一つの原因に一つの理由の文言とするためである。
- `blockKind` の図版の枝は、キャプションの中を種類として調べなくてよくなる。キャプションは段落だけなので、段落の検査で足りる。

`Golem.Doc.Validate` の変更は ABI の変更である（docs/specifications.md の「ABI のバージョン」）。
ABI 8 はまだリリースしていない（v0.1.0-rc3 は 7）ので、[docs/adr/0052](0052-plugin-abi-version-bump-rule.md) のとおりバージョンは 8 のままとする。
CDDL の `caption: [* block]` の型は変えない。
CDDL は形を、`Validate` は不変条件を受け持つ分担を保つ。

### 文書

- docs/markup.md の「図版」の節に、キャプションには段落だけを書けること、ほかのブロックは G02118 になることを書く。
- docs/diagnostics.md に G02118 の節を足す。G06009 の節に、キャプションの理由の文言を足す。
- docs/specifications.md の図版の節と、プラグインの図版（[docs/adr/0123](0123-figures-from-plugins.md)）の節に、同じ規則を書く。意味論 IR の不変条件の一覧にも足す。
- manual-dev の IR の章の図版の記述に、キャプションが段落だけであることを足す。
- [docs/adr/0123](0123-figures-from-plugins.md) のステータスの行に、「キャプションの中の図版とブロックの扱いは [ADR 0144](0144-figure-captions-hold-paragraphs-only.md)」を足す。

## 実装しないこと

- キャプションの段落でないブロックを出力で組むこと（キャプションの中の箇条書きを PDF で組むなど）。PDF のキャプションは図番号と段落のインラインを一つの行の並びとして組む（[golem-driver ADR 0010](../golem-driver/adr/0010-caption-style.md)）ので、ブロックを組むには図版の組版を作り直すことになる。必要な本が現れてから別に決める。
- CDDL の `caption` の型を段落に狭めること。上の「プラグイン」の節を参照。
- キャプションの複数の段落の扱い。今は段落のインラインをつないで一つにする。これは原稿で書けるが消えないので、この ADR の対象の外とする。
- 監査の F-26 のうち、`plugin:` の `src` の置き換えを、キャプションの中まで行うこと。キャプションに図版を置けなくなるので要らない。

## テスト設計

先に次のテストを書き、今の main で失敗することを確かめてから実装する。

golem-eval の `FileSpec` で、次のことを確かめる。

- `@figure` のキャプションに `@figure`、箇条書き、コードブロック、表を書くと、それぞれに G02118 が一つずつ、そのブロックの位置に出る。メッセージの `<種類>` がそれぞれ図版、箇条書き、コードブロック、表である。今の main では誤りにならずに失敗する。
- そのとき図版は残り、キャプションは段落だけになる。
- キャプションに段落だけを書いた図版は、今と同じく誤りにならない。
- キャプションの `@blank-line` は、今と同じく G02093 だけで、G02118 を重ねない。
- キャプションの中に図版を書いた後の図版の図番号が、誤りの図版を数えない番号になる（上の原稿で `図1-2`）。

golem-doc のテストで、次のことを確かめる。

- `validateBlocks` と `validateDocument` が、キャプションに図版、箇条書き、コードブロックを持つ図版に `図版のキャプションには段落だけを置けます` を返す。今の main では空で失敗する。

golem-plugin の `BlockSpec` で、次のことを確かめる。

- 最上位の図版のキャプションに `plugin:` の図版を入れた応答が、G06009（`図版のキャプションには段落だけを置けます`）になる。今の main では通って失敗する。監査の F-26 の再現である。
- キャプションに箇条書きを入れた応答も同じく G06009 になる。

golem-driver では、次のことを確かめる。

- 決定性の検査、ゴールデン（`OutputGoldenSpec`）、見た目の回帰テストの参照が変わらない。リポジトリの原稿とマニュアルに、段落でないキャプションはない（`@figure` の字下げした本体を調べて確かめた）。

## トレードオフ

キャプションに段落でないブロックを書いた原稿は、エラーになって組めなくなる。
今はその内容が黙って消えているだけなので、出力は変わらない。
変わるのは、消えていたことに書き手が気づくことである。

キャプションに箇条書きや表を置きたい書き手は、置けないことを知る。
組版の規則を変えて置けるようにするより、置けないと告げるほうを先にする。
厳しい規則は、置けるようにするときに緩められるが、緩い規則は後から厳しくすると、通っていた原稿を壊すからである。

原稿の G02118 と、プラグインの G06009 は、別のコードになる。
原稿の誤りは書き手が直し、プラグインの不正な出力はプラグインの作者が直すので、直す人が違う。
G06009 の理由の文言で、キャプションの規則に当たったことが分かる。
