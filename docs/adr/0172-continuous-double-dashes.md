# ADR 0172: 二倍ダッシュをフォントによらず一続きの線にする

ステータス: 採択（未実装）

## 文脈

和文の原稿は、二倍ダッシュ（いわゆる倍ダーシ）を、全角のダッシュを二つ続けて書く（`——` か `――`）。
JLReq は、ダッシュを分離禁止文字（cl-08）とし、連続する分離禁止文字のあいだを分割せず、空けないと定める。
二字を一本の線として見せるためである。

Golem の PDF では、二倍ダッシュの二本の線のあいだに隙間があく。
蟹工船の fixture（`modules/golem-driver/test/fixtures/kanikosen`、縦組み、Noto Serif JP）を `d4a259b3` の `golem` で組み、1 ページ目の `——漁夫は` を 600dpi で描いて確かめた（2026-11-06）。
二本の縦の線のあいだに、はっきりした隙間がある。

### 隙間の原因

Golem は、和文の文字を一字ずつの箱にして組み、一字ずつシェイピングして描く（[golem-driver ADR 0015](../golem-driver/adr/0015-vertical-dashes.md) の「今の実装でダッシュが横棒になる仕組み」）。
`U+2014` と `U+2015` は分離禁止文字（`Inseparable`）に分類され（[`CharClass.hs`](https://github.com/tett23/golem/blob/a5e7bae3b51021cb5c23d9145dddc4f89aaf9ac6/modules/golem-layout/src/Golem/Layout/CharClass.hs#L42)）、二つのダッシュのあいだでは改行せず（[`Japanese.hs`](https://github.com/tett23/golem/blob/a5e7bae3b51021cb5c23d9145dddc4f89aaf9ac6/modules/golem-layout/src/Golem/Layout/Japanese.hs#L849)）、アキ量のセットも空きを 0 にする。
ペアカーニングもかけない（[golem-driver ADR 0020](../golem-driver/adr/0020-glyph-positioning-and-dash-kerning.md)）。
つまり、二つのダッシュの箱は隙間なく並んでいる。

隙間は、フォントのダッシュの字形が、字面の両側に余白（サイドベアリング）を持つことから生じる。
fixture のフォント（Noto Serif JP、1em は 1000 単位）を fontTools で調べた結果は次のとおりである。

| 字 | 字形 | 送り | 線の範囲（送りの方向） | 二つ並べたときの隙間 |
| --- | --- | --- | --- | --- |
| `U+2014` | 横組みの字形 | 890 | 43 から 846 | 87（0.087em） |
| `U+2015` | 横組みの字形 | 1000 | 71 から 929 | 142（0.142em） |
| `U+2015` | 縦組みの字形（`vert`） | 1000 | 71 から 929 | 142（0.142em） |

フォントの設計としては、二倍ダッシュの線をつなぐ仕組みは別にある。
Noto Serif JP の `ccmp` は、ダッシュが二つ続いたところを、一つの二倍ダッシュの字形に置き換える（`U+2014` が二つなら送り 1692 の一字、日本語の `locl` のもとでは送り 2000 の一字）。
HarfBuzz（uharfbuzz）で `あ——い` を一度にシェイピングすると、二つのダッシュは一字になり、線は切れない。
Golem は和文を一字ずつシェイピングするので、この置き換えは起きない。

ただし、この置き換えに頼ると、二倍ダッシュがつながるかどうかが、フォントがその合字を持つかどうかで決まる。
メンテナーは、フォントにかかわらず分離しないようにすると決めた（「決めたことの記録」）。

### 二倍ダッシュの長さ

縦組みでは、隙間のほかにもう一つの問題がある。
`U+2014` は、Noto Serif JP で縦組みの字形を持たないので、横組みの字形を回転して描く（golem-driver [ADR 0015](0015-regex-styles.md)）。
送りは横組みの送り（0.89 字）のままなので、二倍ダッシュの長さは 1.78 字になり、字詰めの格子からずれる。
golem-driver [ADR 0015](0015-regex-styles.md) は、`——` を一つの箱にすることと、回転したダッシュの送りを全角にそろえることを、「実装しないこと」として後に回した。
この ADR は、その二つを、二倍ダッシュについて扱う。

## 実装すること

### 対象

和文の中の、全角のダッシュの連なりを対象にする（「メンテナーが決めること」の 2）。

- 全角のダッシュは、`U+2014`（EM DASH）と `U+2015`（HORIZONTAL BAR）とする。二つが混ざった連なりも対象にする。
- 対象の文字は、golem-layout の一つの一覧（関数）にまとめて持つ。メンテナーは扱う文字を後で広げる可能性があるとしたので（「決めたことの記録」）、広げるときは、この一覧に文字を足し、テストの期待値を足すだけで済むようにする。広げるときは、修正の ADR で決める。
- 二字以上続いたものを、一つの連なりとする。一字のダッシュは、今のとおり組む。
- 和文の一字ずつの箱（`PChar`）になるダッシュだけを対象にする。欧文の単語に含まれるダッシュ（[golem-layout ADR 0008](../golem-layout/adr/0008-explicit-hyphens.md)）は、欧文の約物として今のとおり組む。
- ルビ、圏点、文字スタイル、色などの境目では連なりを切る。境目の両側で見た目が違いうるからである。

### 一つの箱にする（golem-layout）

- `textPieces` は、連なりを一つの片（piece）にする。片の文字列は連なりの文字をそのまま持つ。
- 箱の送りは、ダッシュの字数 × 全角（1em）とする（「メンテナーが決めること」の 3）。フォントのダッシュの送り（Noto Serif JP の `U+2014` では 0.89 字）にはよらない。二倍ダッシュは、横組みでも縦組みでもちょうど二字分の長さになり、字詰めの格子に乗る。
- 箱の文字の種類は、先頭も末尾も分離禁止文字（`Inseparable`）とする。前後の空きと改行の規則は、今の一字ずつのダッシュと同じになる。箱の中では改行しない。

### 一続きの線として描く（golem-driver）

連なりの箱は、各ダッシュの字形を、送りの方向にだけ拡大縮小して描き、線を箱の端から端までつなげる（「メンテナーが決めること」の 1）。

- 各ダッシュに、箱の中の一字分の区画（k 字めの始まりから k+1 字めの始まりまで）を割り当てる。
- フォントのダッシュの字形の線の範囲（字面の枠、`lfInkBox`）を、送りの方向に、その区画にちょうど重なるように拡大縮小し、ずらして描く。拡大の率は「1em ÷ 線の長さ」である。線の太さと、送りに直交する方向の位置は変えない。
- これで、k 字めの線の終わりと、k+1 字めの線の始まりが同じ位置になり、線は切れない。線の両端は箱の両端に一致する。
- 縦組みでは、`vert` の縦組みの字形があればそれを縦の方向に、なければ横組みの字形を回転して描く今の規則（golem-driver [ADR 0015](0015-regex-styles.md)）のまま、回転の前の字形の送りの方向に拡大縮小する。
- 拡大縮小は、PDF のテキストの行列で行い、字形はフォントの字形のまま埋め込む。文字を抜き出したときの文字列（ToUnicode）は、連なりの文字そのもの（`——`）である。
- フォントの合字（`ccmp` の二倍ダッシュ）は使わない。どのフォントでも同じ描き方にするためである。
- 字面の枠を持たない字形（線のない空の字形）のダッシュは、拡大縮小せず、今のとおり描く。そのときは notice（G07101）で、そのフォントのダッシュに線がないことを知らせる。位置は、連なりの最初のダッシュである。

### HTML、EPUB、プレーンテキスト

HTML と EPUB は、今のとおり文字をそのまま書き出し、表示はブラウザーとフォントに任せる（「メンテナーが決めること」の 4）。
プレーンテキストは、連なりの文字をそのまま書き出す。

### 仕様書

[docs/specifications.md](../specifications.md) の約物の組み方の節に、二倍ダッシュ（全角のダッシュの連なり）を一つの箱にし、一字分ずつ線をつないで描くことを書く。
golem-driver [ADR 0015](0015-regex-styles.md) の「実装しないこと」の二つ（`——` を一つの箱にすること、回転したダッシュの送りを全角にそろえること）は、二倍ダッシュについてこの ADR が改めたことを、golem-driver [ADR 0015](0015-regex-styles.md) のステータスの行に書く。

## 実装しないこと

- 一字のダッシュの送りを全角にそろえること、一字のダッシュの線を拡大縮小すること。
- 三点リーダー（`……`）と二点リーダー（`‥‥`）の連なり。点は間を空けて並ぶ字形であり、一字ずつの箱でも点の間隔はそろう（Noto Serif JP で、二つの `…` は送り 1000 の同じ字形が二つ並ぶ）。
- `U+2E3A`（TWO-EM DASH）と `U+2E3B`（THREE-EM DASH）。一字で二倍、三倍のダッシュの字形を持つ。
- HTML と EPUB で線をつなぐこと。
- 原稿の文字を書き換えること（`——` を `U+2E3A` に変えるなど）。
- 罫線（`U+2500`）を二倍ダッシュの代わりに使うこと。

## テスト設計

テストを先に書き、今の実装で失敗することを確かめてから実装する。

golem-layout のテストでは、次のことを確かめる。

- `あ——い`、`あ――い`、`あ—―い` の `——` などが一つの箱になり、送りが 2em であること。`あ———い` は 3em の一つの箱になること。
- 一字の `あ—い` は、今のとおり一字の箱であること。
- ルビ、圏点、文字スタイルの境目をまたぐダッシュは、境目で別の箱になること。
- 欧文の単語の中のダッシュ（`word—word`）は、今のとおりであること。
- 二倍ダッシュの箱の中で改行せず、前後の空きが一字のダッシュと同じであること。

golem-driver のテストでは、次のことを確かめる。

- 二つのフォントで確かめる。一つは合字を持つ Noto Serif JP、もう一つは合字を持たず、ダッシュの字形にサイドベアリングを持つテスト用のフォントである。
- それぞれのフォントの横組みと縦組みで、二倍ダッシュの各字形の線の範囲を、PDF の内容のストリームの行列と `lfInkBox` から計算する。線の終わりと次の線の始まりが一致し、両端が箱の両端に一致すること（誤差は 1/1000em 以下）。
- 線の太さと、送りに直交する方向の位置が、拡大縮小の前と同じであること。
- PDF から抜き出した文字列が `——` のままであること。
- 線のない字形のダッシュで、G07101 の notice が出て、字形が拡大縮小されないこと。
- 決定性の検査（同じ入力から同じ PDF のバイト列）が通ること。

見た目の回帰テストでは、二倍ダッシュを含むページ（蟹工船の fixture など）の参照を更新する。
更新の前に、変わったページの画像で、二倍ダッシュの線がつながり、ほかの字の位置が変わっていないこと（縦組みの `U+2014` の二倍ダッシュは、1.78 字から 2 字に伸びた分だけ後ろの字が下がること）を確かめる。

## トレードオフ

フォントのダッシュの字形を拡大縮小するので、フォントの設計者が決めた二倍ダッシュの字形（`ccmp` の合字）があっても使わない。
フォントの合字は、線の端の形や太さを二倍の長さに合わせて設計していることがあるが、拡大縮小は一字の字形を引き伸ばすだけである。
その代わり、どのフォントでも二倍ダッシュがつながり、長さがちょうど二字分になる。

線の端は、字面の枠の端までつながる。
サイドベアリングは、一字のダッシュを前後の字から離すための余白でもあるので、二倍ダッシュの両端は前後の字に、一字のダッシュより近づく。
両端の余白をフォントの余白のまま残す案は、「メンテナーが決めること」の 1 に挙げる。

`U+2014` の二倍ダッシュの長さが 1.78 字から 2 字に変わるので、縦組みの本では二倍ダッシュより後ろの字の位置が変わり、行の中の改行の位置が変わることがある。
出力のバイト列が変わるので、見た目の回帰テストの参照と、決定性の検査の期待値が変わる。

HTML と EPUB では、二倍ダッシュの見え方は今のとおりブラウザーとフォントに任せるので、PDF と見え方が食い違うことがある。

## 決めたことの記録

- **フォントによらず分離しないこと**（2026-11-06、メンテナー）：二倍ダッシュのあいだに隙間があくことがあるので修正の ADR を作るよう求め、フォントにかかわらず分離しないようにしたいとした。
- **線のつなぎ方**（2026-11-06、メンテナー）：推奨のとおり、字形を送りの方向にだけ拡大縮小してつなぐ。
- **対象の範囲**（2026-11-06、メンテナー）：推奨のとおり、和文の中の `U+2014` と `U+2015` の二字以上の連なりとする。ただし、扱う文字は広げる可能性があるとした。
- **箱の送り**（2026-11-06、メンテナー）：推奨のとおり、字数 × 1em とする。二倍ダッシュは 2em のほうが正しいとした。
- **HTML と EPUB**（2026-11-06、メンテナー）：推奨のとおり、ブラウザーとフォントに任せる。

## メンテナーが決めること

すべて決めた（「決めたことの記録」）。

1. **線のつなぎ方**：フォントのダッシュの字形を送りの方向にだけ拡大縮小し、線の両端を箱の両端までつなぐ。
2. **対象の範囲**：和文の中の `U+2014` と `U+2015` の二字以上の連なり（混ざってもよい）。対象の文字は一つの一覧にまとめ、後で広げられるようにする。
3. **箱の送り**：ダッシュの字数 × 1em。
4. **HTML と EPUB**：今のとおりブラウザーとフォントに任せる。
