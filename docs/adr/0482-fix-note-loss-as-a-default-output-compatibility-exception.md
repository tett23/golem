# ADR 0482: 既存の注の欠落修正を既定出力の互換性の例外にする

Status: accepted

## 文脈

文献の注を組む処理の検証で、書き手が明示した注も一部の場所で欠落することが分かった。
表とコードのキャプションにある注は、PDF のリンク先が無くなるエラーにもつながる。
文献スタイルの追加とは独立に、既に受け付けている原稿を正しく出すための修正が必要である。

一方、root [ADR 0470](0470-bibliography-styles-by-name-and-by-declaration.md) I1 は `style` を書かない本のどの出力も変えないと定め、root [ADR 0480](0480-complete-bibliography-sorting-and-conditional-formats.md) I7 も既定の `golem` の出力を保つと定める。
この ADR は、ここで特定した書き手の注の欠落とリンク先の欠落の修正を、その互換性の例外にする。
それ以外の既定出力の互換性は保つ。

## 調査した事項

文献機能の実装途中のコミット `fa7c74eee9dd9bf7c93af02f5ca8b1e3ee988354` から作った CLI で、有効な原稿を検証した。
原稿は、本文、Ruby の親文字、表のキャプション、表の見出しセル、表の本文セル、コードのキャプションに、それぞれ一つ、合計六つの脚注を置く。
`[bibliography].style` は書いていない。

横組みと縦組みの両方で `golem check` は終了コード 0、diagnostics なしだった。
`golem build` は G07120 を出し、終了コード 1 だった。
この diagnostic は、表とコードのキャプションにある二つの注の行先を PDF に描けないことを報告した。
HTML、EPUB、テキストには呼出印があったが、Ruby、表のキャプション、コードのキャプションの注本文が欠けていた。

下位の試験でも、注の走査で期待八件に対して五件、Ruby 内の引用の収集で期待一件に対して零件だった。
コードのページ付けでは、注の消失と短い段での拒否の不足を示す三件の失敗を確認した。
これらは作業中の実装に対する測定であり、main 上の全原稿に同じ結果が出ると主張するものではない。

試作では、キャプションの注を保持する修正後に PDF を生成できた。
HTML、EPUB、テキストの六つの注本文も保持できた。
しかし、PDF の画像確認では、Ruby 内の注の印と本文は依然として欠けていた。
PDF の Ruby は親文字から文字を集めるときに注を落としており、印を置く位置と Ruby の読みの幅への関係を決める必要がある。
この ADR は、その配置を決めない。

## 実装すること

既存の注の収集、採番、描画の経路をそろえ、表とコードのキャプションの注を欠落させない。
表のセルと通常の本文にある注も、既存の順序とチャネルの規則で一度ずつ扱う。
注のチャネルとは、既存の脚注、傍注、章末注の区別である。
この修正のために新しいチャネルや原稿の記法を足さない。

HTML、EPUB、テキストでは、Ruby の親文字にある既存の注を、収集と採番から落とさず、印と本文を対応させる。
Ruby の親文字に置いた注の本文にある引用も、既存の有効な入力として収集する。
注を含まない Ruby 内の引用の扱いは、この修正では変えない。
リンクの内側など、既存の検査で禁止している場所の引用は受け付けない。

PDF のキャプションの注は、注本文と行先の予約を配置まで渡す。
コードを次の段へ送る場合や分割する場合も、注の印と本文の対応を失わない。
空の段でも収まらない場合には、既存の該当する diagnostic と生成中止の規則を使う。
この ADR で新しい diagnostic コードや失敗時の代替出力は定めない。

この修正によって、上記の欠落や G07120 が起きていた既定の `golem` の原稿の出力が変わることを許す。
root [ADR 0470](0470-bibliography-styles-by-name-and-by-declaration.md) I1 と root [ADR 0480](0480-complete-bibliography-sorting-and-conditional-formats.md) I7 に対する例外は、この修正の範囲に限る。
仕様書、README、利用者向けマニュアルにも、実装した範囲と残る制約を同時に記録する。

## 実装しないこと

PDF の Ruby の親文字内に置く注の配置は、未決のまま分ける。
注の印を Ruby の外へ移す、Ruby を分割する、読みの範囲を変えるといった配置は、この ADR の実装に含めない。
この部分を完成扱いせず、後の ADR で決める。

文献引用から注を自動生成する規則や、最初の引用の注番号を表示する規則は変更しない。
書き手の注と文献から生成する注を識別する内部実装も、別途それぞれの採択済みの条件を満たす必要がある。
既定出力に対する一般的な変更許可、試験や画像参照の無条件の更新は含めない。

## 不変条件

- I1: 対象とする有効な原稿の注は、既存のチャネル別の順序で一度ずつ収集され、印と本文の番号が対応する。
- I2: HTML、EPUB、テキストは、対象の六つの注本文をそれぞれ一度出し、Ruby の注本文も落とさない。
- I3: PDF の表とコードのキャプションの注は、配置後にも印、本文、行先の対応を保つ。
- I4: 既存の注の配置が不可能な場合の拒否を弱めず、分割や段送りで注を消して成功させない。
- I5: 今回特定した欠落の影響を受けない既定原稿は、修正前と同じ出力を保つ。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 注なし | 修正前と同じ出力 | I5 |
| 本文の注一つ | 既存の番号と本文を一度表示 | I1, I5 |
| 六か所の注 | 全媒体で共通の収集と採番、非 PDF は六本文を保持 | I1, I2 |
| 表とコードのキャプションの注 | PDF で印と本文の行先を失わない | I3 |
| 注を持つコードの分割と段送り | 注の消失も重複もない | I1, I3, I4 |
| 注を含めて空の段に収まらないコード | 既存の該当する diagnostic で拒否 | I4 |
| PDF の Ruby 内の注 | この ADR の完成条件に含めず、未決として記録 | I1 |

## 受けいれ条件

A1: 横組みと縦組みで、Ruby の注を除いたキャプションとセルの既存の注を、通常の CLI から全媒体へ出せる。
PDF の画像で印と本文を確認し、G07120 が出ないことを確かめる。

A2: 六か所の注を持つ原稿について、HTML、EPUB、テキストの番号と注本文を検査する。
PDF の Ruby については別に残件を記録し、注機能全体や root [ADR 0470](0470-bibliography-styles-by-name-and-by-declaration.md) の完了とは扱わない。

A3: 既存の画像検証に使う 24 入力を同じ CLI 条件で出し、影響を受けない出力を比較する。
差が出たページはすべて前後を確認し、今回の修正に起因する差かを示す。

## テスト設計

I1 から I5 の名前を持つ回帰試験を、先に書いて失敗させる。
収集と採番、テキスト出力、コードのページ付け、通常の CLI の媒体ごとの試験を分ける。
既存の各チャネルで有効な組方向を検査し、禁止されている組み合わせを修正前の欠落の再現として数えない。
通常の CLI の試験では、実際に使えるフォントを設定し、別のフォント不足エラーを欠落の再現として数えない。
A1 と A2 は、通常の `check` と `build`、生成物の検査、横組みと縦組みの PDF の画像確認で確かめる。
A3 は画像参照を更新する前に確かめ、既存の監査や計測の記録は変更しない。

## トレードオフ

既定出力を変えない条件の例外を一つ設ける。
その代わり、受け付けた原稿の注が欠ける不具合を、文献スタイルを選ばない本でも修正できる。
PDF の Ruby の配置は別の判断に残るため、この修正だけではすべての注の問題は解決しない。
