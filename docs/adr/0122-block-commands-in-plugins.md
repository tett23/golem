# ADR 0122: プラグインのブロックコマンド

ステータス: 採択（未実装）

## 文脈

TSV から表を組むプラグイン（[docs/adr/0129](0129-tsv-table-plugin.md)）を書こうとして、最初に行き当たったのは ABI の形だった。
プラグインのコマンドは、インラインの列しか返せない。
[golem-plugin ADR 0001](../golem-plugin/adr/0001-wasm-host-and-abi.md) は応答を「コマンドならインラインの列、フィルタならファイル一つ分の文書」と定め（[46 行め](https://github.com/tett23/golem/blob/fa55dc76be6fef7189cb80883fd0bb0b0630911f/docs/golem-plugin/adr/0001-wasm-host-and-abi.md?plain=1#L46)）、CDDL も `response = [output: inlines / document, ...]` である（[golem-doc.cddl](https://github.com/tett23/golem/blob/fa55dc76be6fef7189cb80883fd0bb0b0630911f/modules/golem-doc/schema/golem-doc.cddl#L104)）。
表は段落の中に置けないブロックなので、コマンドからは返せない。

フィルタなら文書を返せる。
ただし、フィルタは引数を取らず、`manifest.toml` の `[[filters]]` でファイルごとに当てるものであり、原稿の特定の位置に特定の表を置く手段にならない。
原稿に目印の段落を書かせてフィルタが置き換える方法も考えられるが、目印の書き方がプラグインごとの取り決めになり、引数の評価、位置、誤りの報告を Golem が受け持てない。

原稿の側には、ブロックを置く命令の書き方がすでにある。
行頭の `@name` がブロックコマンドであり（[docs/markup.md](../markup.md) の「ブロックコマンド」）、構文は名前によらない。
今は、組み込みにない名前の `@name` を評価が G02009 にしている（[`standalone`](https://github.com/tett23/golem/blob/fa55dc76be6fef7189cb80883fd0bb0b0630911f/modules/golem-eval/src/Golem/Eval/File.hs#L517)）。
この行き止まりをプラグインに開けば、構文を足さずに済む。

決めることは五つある。
原稿での呼び方、ABI（要求、応答、宣言）、返せるブロックの範囲、置ける場所、フィルタとチャネルとの関係である。

### 試しに実装して分かったこと

この ADR は、採択の前に実装を試した（ブランチ `plugins-tsv-table`）。
ホストを変え、Rust の補助のクレートに要求と応答の型を足し、見本のプラグイン `tsv-table` を `golem build` で PDF まで組んだ。

- **宣言の欄**：`golem_describe` に五つめの欄を足すと、golem-plugin のテスト用の wat のプラグイン十三個の記述（バイト列と長さ）を書き換えることになった。[docs/adr/0105](0105-plugin-data.md) が四つめの欄を足したときと同じ作業である。欄の数を増やすたびにこの書き換えが要るので、記述を欄の名前から値へのマップにする草稿（[docs/adr/0107](0107-named-describe-fields.md)）を別に書き、同じブランチで試した。この ADR の宣言は、その草稿の `blocks` の欄として書く。
- **既存の仕組みへの乗り方**：属性のまとまり（`@label` など）の最後に置いたブロックコマンドを対象にする処理は、組み込みのブロックコマンドと同じ経路で動いた。`@label t` に続く `@tsv-table` の表は、何も足さずにラベルを持った。箇条書きの項目の中でも同じだった。
- **段落スタイルの検査**：フィルタの出力に対する段落スタイルの検査（[`unknownParaStyles`](https://github.com/tett23/golem/blob/fa55dc76be6fef7189cb80883fd0bb0b0630911f/modules/golem-eval/src/Golem/Eval/File.hs#L984)）は文書の全体に適用されるので、ブロックコマンドの出力も何も足さずに検査された。
- **出力の同一性**：同じ TSV から `@tsv-table` と `@table` で組んだ PDF は、文書の ID（`/ID` の二つめ）を除いて同じバイト列だった。
- **キーワード引数の欠け**：ホストはキーワード引数のキーを捨てて値だけを渡していた。`align=left` を受け取れないので、別の草稿（[docs/adr/0110](0110-keyword-arguments-to-plugins.md)）で直した。

## 実装すること

### 原稿での呼び方

プラグインのブロックコマンドは、組み込みのブロックコマンドと同じく、行頭の `@name 引数...` で呼ぶ。

- 評価は、組み込みのブロックコマンド、ファイルの設定（`@manifest`、`@style-def`）、属性の名前を先に調べ、どれでもなければプラグインのブロックコマンドを探す。なければ今と同じく G02009 とする。
- 引数は、インラインのプラグインのコマンドと同じく評価する。int64 に収まらない整数を含めば G02091 とし、プラグインを呼ばない（[golem-doc ADR 0006](../golem-doc/adr/0006-integer-range-in-ir.md)）。
- 字下げした行（本体）はブロックとして評価し、要求に入れて渡す。本体を取らないブロックコマンドは、プラグインが自分の diagnostic で本体を拒む。
- ブロックコマンドの名前は、インラインのコマンドの名前と別の名前空間に置く。`@name` はブロックコマンドだけを、`[name ...]` はインラインのコマンドだけを呼ぶ。一つのプラグインが同じ名前を両方に宣言してもよい。

構文を足さないので、プラグインを加えても原稿の構文解釈は変わらない（[docs/markup.md](../markup.md) の「二つの文脈」と同じ性質）。

### 宣言

プラグインは、ブロックコマンドの名前を `golem_describe` の応答の `blocks` の欄で宣言する（欄の形は [docs/adr/0107](0107-named-describe-fields.md)）。

- 名前は英小文字で始まり、英小文字、数字、`-` だけからなる。データの名前と同じ形である（[docs/adr/0105](0105-plugin-data.md)）。
- 形の誤った名前、二度書いた名前、組み込みのブロックコマンドの名前（`table`、`figure` などのほか、`label` などの属性と、`manifest`、`style-def`、`set`、`import` を含む）は、不正な `golem_describe`（G06005）とする。メッセージは `ブロックコマンドの名前が不正です: <名前>`、`ブロックコマンドの名前が重複しています: <名前>`、`組み込みのブロックコマンドの名前です: <名前>` である。
- 二つのプラグインが同じブロックコマンドを宣言すると、G06006 とする。メッセージは `複数のプラグインが同じブロックコマンドを提供しています: @<名前>（<プラグイン>、...）` である。原因はインラインのコマンドの衝突と同じなので、コードを分けない。
- 組み込みのブロックコマンドは上書きできない。`overrides` に書けるのはインラインのコマンドだけである。

組み込みの名前を宣言の時点で拒むのは、組み込みのブロックコマンドに上書きの仕組みがなく、どのプロジェクトでもその宣言は使えないからである。

### 要求と応答

```cddl
block-command-request = [2, name: tstr, args: [* argument], body: [* block], span, data]
response = [output: inlines / document / [* block], diagnostics: [* plugin-diagnostic]]
description = {? "commands" => [* tstr], ? "filters" => [* tstr], ? "channels" => [* channel-decl], ? "data" => [* tstr], ? "blocks" => [* tstr]}
```

- 要求のタグは 2 である。`span` は `@` の行（と本体）の全体の位置であり、プラグインが作るノードにはこの位置を付ける。
- 応答の `output` は、ブロックの列である。インラインの列と同じく配列なので、どちらとして読むかはホストが要求の種類で決める。インラインを返したブロックコマンドは、ブロックとして読めないので不正な出力（G06009）になる。
- ABI のバージョン 8 はまだリリースしていないので、バージョンは上げない（[docs/adr/0052](0052-plugin-abi-version-bump-rule.md)）。

### 返せるブロック

返せるブロックは、段落、箇条書き、番号付きの箇条書き、定義リスト、表、コードブロックとし、ラベルを持たない。
箇条書きと定義リストの中のブロックにも同じ制限をかける。

- 見出し、一覧の出力（`@toc`、`@index`、`@bibliography`、`@channel`）、改ページ、改ページの制御、行アキは、不正な出力（G06009）とする。メッセージは `ブロックコマンドが返せないブロックです: <種類>` である。
- ラベルは `ブロックコマンドの出力はラベルを持てません` とする。ラベルは原稿の `@label` で付ける。
- 本体から受け取ったブロックは、種類によらず、受け取ったままなら返せる。チャネルの項目を要求の中のものに限って通すのと同じ扱いである（[golem-doc ADR 0007](../golem-doc/adr/0007-plugin-channel-lists.md)）。
- ソース位置は、呼び出しの位置か、本体の中の位置に限る。遅延した式は、本体の中にあったものに限る。
- そのほか、出力は文書の最上位でないブロックとして意味論 IR の不変条件で検査する（`Golem.Doc.Validate` の `validateBlocks`）。ブロックコマンドは箇条書きの項目の中にも置けるからである。
- 段落スタイルは、フィルタの出力と同じく文書の全体で検査し、定義されていなければ G02047 とする。

見出しを除いたのは、見出しの番号、目次、柱、ラベルの解決が原稿の見出しの行を前提にしているからである。
図版は、プラグインが作った画像の図版に限り、原稿の図版と同じ検査を通して返せる。
形と検査は別の草稿（[docs/adr/0123](0123-figures-from-plugins.md)）で決め、この ADR の応答の出力もその草稿の `[blocks, images]` の形になる。
プロジェクトの画像のファイルを指す図版を返せないのは、その画像が評価の前のファイルの一覧に入っておらず、`@figure` のファイルの検査を通らないからである。
一覧の出力と改ページの類は、文書に一つだけ、あるいは最上位にだけ置けるという制約を持つので、プラグインに置かせない。

### 置ける場所

組み込みのブロックコマンドを置ける場所なら、どこにでも置ける。
文書の最上位、箇条書きの項目、定義、本体を持つ `@style` の中、図版のキャプションである。
属性のまとまりの後に置けば、属性（`@label` など）は返した最初のブロックに付く。
返したブロックが一つもなければ、属性は何にも付かない。

### フィルタとチャネル

- フィルタは、ブロックコマンドが返したブロックを、ほかのブロックと区別せずに受け取る。ブロックコマンドは評価の中で呼ばれ、フィルタはその後に当たるからである。
- ブロックコマンドの出力のインラインは、インラインのコマンドと同じく、そのプラグインが宣言したチャネルの項目を含められる。
- プラグインの読み込みか検査に誤りがあるときは、G02022 と G02090 と同じく、評価で G02009 を報告しない。読み込めなかったプラグインのブロックコマンドが、すべて未知のブロックコマンドになって本当の原因を埋もれさせるからである。G02022 と同じく、そのときは原稿の綴りの誤りも報告されないが、プラグインの誤りを直せば報告される。

### モジュールの変更

golem-* のパッケージのあいだの build-depends は変えない。

- **golem-doc**：`blocksTerm`、`termBlocksE`（`Golem.Doc.Cbor`）と `validateBlocks`（`Golem.Doc.Validate`）を足す。CDDL を上のとおりに変える。
- **golem-eval**：`PluginHook` に `phBlocks :: Map Text PluginBlockCommand` を足す。組み込みのブロックコマンドの名前の一覧 `builtinBlockCommands` を `Golem.Eval.Builtin` に置く。
- **golem-plugin**：`pluginBlocks`、`blockCommandRequest`、`callBlockCommand` を足す。
- **golem-driver**：`phBlocks` を組み、ブロックコマンドの衝突を G06006 にする。
- **plugins/golem-plugin-sdk**：`Request::Block`、`BlockCommandRequest`、`Response::blocks`、`Description::blocks` を足す。

## 実装しないこと

- プラグインが見出しを返すこと。見出しの番号、目次、柱、ラベルの解決が原稿の見出しの行を前提にしているからである。
- プラグインがプロジェクトの画像のファイルを図版にすること。
- 組み込みのブロックコマンドの上書き。
- LSP の補完にブロックコマンドの名前を出すこと。
- `golem fmt` と `golem lint` での特別な扱い。どちらも名前で振る舞いを変えない限り、今のままでよい。

## テスト設計

下のテストのうち、見本のプラグイン tsv-table（[docs/adr/0129](0129-tsv-table-plugin.md)）を使うものは、この ADR の実装では書かない。
この ADR の実装では、同じことを wat のテスト用のプラグイン（`modules/golem-plugin/test/` と golem-driver のテストの wat）で確かめるテストを先に書く。
見本のプラグインを使うテストは、結合のテストとして、その見本のプラグインの ADR を実装するときに足す。
見本のプラグインの ADR が、この ADR より後に実装されるからである。

テストは実装と同時に書いた。
golem-plugin のテストは、`pluginBlocks` と `callBlockCommand` がないのでコンパイルできないことを確かめてから実装した。

golem-plugin のテスト（`modules/golem-plugin/test/BlockSpec.hs`）では、次のことを確かめる。

- `blocks` の欄が `pluginBlocks` になる。
- `Grid`、空、`1a`、`a_b`、`a b` が名前の誤りに、二度書いた名前が重複に、`table` が組み込みの名前になる。
- `echo.wat` で、要求が `[2, 名前, 引数, 本体, 位置, データ]` のバイト列になる。
- 表、段落、箇条書きを返せる。見出し、箇条書きの中の行アキ、ラベル、要求にない位置、セルの数の合わない表は、それぞれのメッセージの不正な出力になる。本体の見出しは、ラベルごと受け取ったまま返せる。インラインを返すと不正な出力になる。

golem-eval のテスト（`modules/golem-eval/test/FileSpec.hs`）では、次のことを確かめる。

- `@grid sales align=left` が、キーを保った引数でプラグインを呼び、プラグインの diagnostic を報告する。
- ブロックの位置が呼び出しの行になる。本体が評価されて渡る。箇条書きの項目の中で呼べる。`@label` が最初のブロックに付く。
- `@nope` は G02009、`[grid]` は G02022 のままである。int64 を超える引数は G02091 で、プラグインを呼ばない。呼び出しの誤りはブロックを作らない。定義されていない段落スタイルは G02047 になる。

golem-driver のテスト（`modules/golem-driver/test/PluginsSpec.hs`）では、`plugins/wasm/tsv-table.wasm` を使い、次のことを確かめる。

- `[tsv-table sales]` は G02022、`@lookup x` は G02009 になる。
- データのファイルがなくてプラグインの読み込みが G06101 になると、`@tsv-table` の G02009 も `[tsv-table ...]` の G02022 も出ない。
- 同じ `tsv-table.wasm` を二つの名前で宣言すると G06006 になる。
- 表は箇条書きの項目の中にも置け、`@label` を受け取る。

手で確かめたこと：`golem new` で作ったプロジェクトで `@tsv-table` を使い、`golem build --target pdf` で組んだ。
同じ表を `@table` で組んだ PDF と、`/ID` を除いて同じバイト列だった。

## トレードオフ

ブロックコマンドとインラインのコマンドの名前空間を分けたので、同じ名前が二つの意味を持ちうる。
一つの名前空間にして、呼び方（`@` か `[`）で要求の種類を変える案もあった。
その案では、インラインのコマンドしか持たないプラグインに `@name` で要求を送ると、プラグインは知らない要求を受け取ってトラップし、G06009 になる。
「未知のブロックコマンド」で済むはずの綴りの誤りが、プラグインの実行の失敗として報告されるのを避けるため、宣言を分けた。

返せるブロックを絞ったので、見出しを含む節を丸ごと生成するようなプラグインは書けない。
その用途はフィルタで書ける。

## 決めたことの記録

- **名前空間を分けること**（メンテナー、2026-10-29）：ブロックコマンドとインラインのコマンドの名前空間を分ける案を採る。`@name` と `[name ...]` の意味が呼び方だけで決まり、意味論が崩れないからである。
- **図版**（メンテナー、2026-10-29）：プラグインが図版を返すことは認める。ただし、原稿の図版と同じ検査を迂回しないことを条件とし、[docs/adr/0123](0123-figures-from-plugins.md) で決める。草稿を書き、同じブランチで試した。見出しは引き続き返せない。
- **G02009 を抑えること**（メンテナー、2026-10-29）：読み込みに失敗したプラグインについて、G02022 と同じく G02009 を報告しない。試しの実装に入れた。
- **記述の欄**（メンテナー、2026-10-29）：`golem_describe` の欄を名前つき（CBOR のマップ）にする草稿を書く（[docs/adr/0107](0107-named-describe-fields.md)）。この ADR の宣言は、その `blocks` の欄である。
- **テストのプラグイン**：メンテナーが、土台の ADR は wat のテスト用のプラグインで試し、見本のプラグインを使う結合のテストは見本のプラグインの実装のときに足す運用にすると決めた（2026-11-04）。
