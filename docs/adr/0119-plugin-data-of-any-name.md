# ADR 0119: どんな名前のデータも受け取るプラグイン

ステータス: 採択

## 文脈

[docs/adr/0105](0105-plugin-data.md) では、プラグインは受け取るデータの名前を `golem_describe` の四つめの欄で宣言し、宣言にない名前を `manifest.toml` の `data` に書くと G06102 になる。
綴りの誤りを黙って捨てないための規則であり、辞書を一つ受け取るプラグイン（`lookup` の `table`、総ルビの辞書）には合っている。

TSV から表を組むプラグイン（[docs/adr/0129](0129-tsv-table-plugin.md)）では、この規則が壁になった。
本には表がいくつもあり、表ごとに TSV のファイルがある。
データの名前はプロジェクトが決めるもの（`sales`、`costs`）で、プラグインの作者は前もって知らない。
`table1` から `table99` までを宣言する手もあるが、名前が意味を失い、百個めの表で行き詰まる。

同じプラグインを二つの名前で宣言して、それぞれに一つずつ渡す方法も試した。
二つの宣言は同じブロックコマンドを提供するので、G06006（コマンドの衝突）になる。
今の仕組みでは、一冊の本に表のプラグインのデータを二つ渡す方法がない。

## 実装すること

プラグインは、`golem_describe` の `data` の欄（[docs/adr/0107](0107-named-describe-fields.md)）を `["*"]` にすると、どんな名前のデータも受け取る。

- `*` は、ほかの名前と並べられない。`["*", "table"]` は、今と同じく `データの名前が不正です: *`（G06005）とする。`*` はデータの名前の形（英小文字で始まり、英小文字、数字、`-` だけ）に合わないので、ほかの名前と取り違えることはない。
- `*` を宣言したプラグインでも、`data` の名前は同じ形でなければならない。形の誤った名前（`Sales` など）は G06102 とする。メッセージの「受け取る名前」には `英小文字で始まる任意の名前` と書く。
- データの渡し方、上限（一つのプラグインの合計で 64 MiB）、パスの検査、LSP の扱いは [docs/adr/0105](0105-plugin-data.md) のままである。
- golem-plugin は `takesData :: Plugin -> Text -> Bool` を公開し、golem-driver はそれで G06102 を判定する。

## 実装しないこと

- 名前の前置き（`table-*`）のような、部分的な型の宣言。
- コマンドごとに、渡すデータを選ぶこと。どのコマンドを呼んでも、そのプラグインのデータのすべてが渡る（[docs/adr/0105](0105-plugin-data.md) の「実装しないこと」のまま）。

## テスト設計

下のテストのうち、見本のプラグイン tsv-table（[docs/adr/0129](0129-tsv-table-plugin.md)）を使うものは、この ADR の実装では書かない。
この ADR の実装では、同じことを wat のテスト用のプラグイン（`modules/golem-plugin/test/` と golem-driver のテストの wat）で確かめるテストを先に書く。
見本のプラグインを使うテストは、結合のテストとして、その見本のプラグインの ADR を実装するときに足す。
見本のプラグインの ADR が、この ADR より後に実装されるからである。

- golem-plugin（`BlockSpec.hs`）：`["*"]` のプラグインの `takesData` が `sales` で真、`Sales` で偽になる。`["table"]` のプラグインは `table` だけで真になる。`["*", "table"]` は `データの名前が不正です: *` になる。どんな名前のデータも要求の最後の欄に入る。
- golem-driver（`PluginsSpec.hs`）：`tsv-table` に `sales` と `costs` の二つのデータを渡し、二つの表がそれぞれのファイルから組まれる。`Sales` という名前は G06102 になる。

## トレードオフ

どの呼び出しにもすべてのデータが渡るので、表が多い本では、一回の呼び出しで写すバイト数が表の数に比例して増える。
試しに、1,000 行（約 37 KB）の TSV を百個渡し、百個の表を組んだ。
`golem build --target text` は 1.64 秒で、同じ表を `@table` で組んだときの 0.52 秒の約三倍だった（Apple M1 Max、macOS、一回の計測）。
十個なら 0.26 秒と 0.16 秒である。
本の表の数と大きさでは問題にならない範囲と考えるが、データを名前で選んで渡す形にすれば、写す量は表一つ分になる。
その形は、ホストが引数を解釈してデータを選ぶことになるので、この ADR では採らない。

綴りの誤りの検査は、`*` のプラグインでは名前の形だけになる。
`salse` と書いた名前は、ホストではなく、プラグインが「渡されていない名前です」と報告する（`tsv-table` の `tsv-table-no-data`）。
誤りは黙って捨てられず、報告する側がホストからプラグインに移るだけである。
