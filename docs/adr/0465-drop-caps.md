# ADR 0465: 段落スタイルの drop-lines でドロップキャップを組む

Status: proposed

## 文脈

[root ADR 0374](0374-paragraph-style-controls.md) は、段落スタイルに `drop-lines`（0 より大きい自然数）を設け、ドロップキャップを組むと決めた。
0374 は「先頭 1 書記素を指定行数の高さで置き、その行だけ本文幅を減らす」と書く（0374 の 17 行）。
指定行数の高さの字の脇では、その行数の行を短くしないと重なるので、「その行だけ」と食い違う。
字の大きさの決め方、字と本文のあいだの空き、HTML と EPUB の写し方も決まっていない（ロードマップの「ドロップキャップの組み方」）。

メンテナーは、2026-11-26 に、0374 の残りを機能ごとの ADR に分けると決めた。
この ADR は、ドロップキャップの組み方を決める。

## 調査した事項

根拠の行は、調べを受け持ったエージェントが `git show` と `git grep` で返したものである。

- 段落スタイルのキーは、`style.toml` でも `@style-def` でも、`FromValue ParaStyleDef` が読む（[Style.hs#L2395-L2458](https://github.com/tett23/golem/blob/c034510e33476f4af68ba22636f5ab6ef8463f0a/modules/golem-project/src/Golem/Project/Style.hs#L2395-L2458)）。
  キーの表は `paraStyleNode` である（[Style.hs#L4621-L4665](https://github.com/tett23/golem/blob/c034510e33476f4af68ba22636f5ab6ef8463f0a/modules/golem-project/src/Golem/Project/Style.hs#L4621-L4665)）。
- `drop-lines` はコードに無い（`git grep -E 'drop-lines' c034510` の結果は docs/roadmap.md と 0374 だけ）。
  今は未知のキーとして G03006 になる。
- 先頭の書記素の文字スタイル `initial-style` は実装済みである（[Style.hs#L2451](https://github.com/tett23/golem/blob/c034510e33476f4af68ba22636f5ab6ef8463f0a/modules/golem-project/src/Golem/Project/Style.hs#L2451)）。

## 実装すること

### キー

段落スタイルに `drop-lines` を足す。
値は 0 より大きい自然数で、ほかの値は今と同じく G03006 とする。
`drop-lines` を書いた段落スタイルの段落は、先頭の 1 書記素をドロップキャップとして組む。
字と本文のあいだの空きは、新しいキー `drop-gap`（0 以上の寸法、既定は 0）で書く。

### 字の大きさと位置

ドロップキャップの字は、段落の 1 行目から `drop-lines` 行目までの高さを占める。

- 横組みの欧文の字は、字のキャップハイトの上端を 1 行目のキャップハイトの上端にそろえ、ベースラインを `drop-lines` 行目のベースラインにそろえる大きさにする。
- そのほかの字（和文の字と縦組みの字）は、字の仮想ボディを、1 行目の仮想ボディの始まりの辺から `drop-lines` 行目の仮想ボディの終わりの辺までの高さにする。

字の書体は、`initial-style` があればその文字スタイルの書体、無ければ段落の書体である。
`initial-style` の大きさは使わない。

### 脇の行

1 行目から `drop-lines` 行目までの行は、行の始まりを、ドロップキャップの字の送り幅と `drop-gap` の和だけ短くする。
段落の行が `drop-lines` 行より少なければ、足りない行は空の行として組み、段落の高さを `drop-lines` 行にする。
1 行目から `drop-lines` 行目までのあいだでは、ページと段を分けない。
ドロップキャップの段落には、1 行目の字下げ（`first-line-indent`）と `opening-indent` を当てない。
段落の始まりの字下げ（`indent`）は、どの行にも今と同じく当てる。
回り込む図版の脇の段落では、図版の除外領域で短くした行を、さらにドロップキャップの分だけ短くする。

### 先頭の書記素

ドロップキャップにするのは、段落の最初のテキストの 1 書記素である。
始め括弧や引用符でも、その 1 書記素をドロップキャップにする。
段落がルビ、縦中横、テキストでないインライン（画像など）で始まるときは、ドロップキャップを組まず、今と同じく組む。
そのときは、段落ごとに警告の G07143 `段落の先頭がテキストでないので、ドロップキャップを組みません` を出す。
空の段落には、ドロップキャップを組まず、診断も出さない。

### 当てる段落

`drop-lines` は、文書の最上位の段落と、`@style` などの結果をその場に置く本体の中の段落に当てる。
リストの項目、表のセル、キャプション、注、フレームの中の段落と、見出しには当てない。
これらの段落の段落スタイルが `drop-lines` を持っても、診断は出さない。
`line-breaks = "keep"` の段落スタイルでは、段落の最初の行の部分にだけ当てる。

### HTML と EPUB

HTML と EPUB では、その段落スタイルの段落の `::first-letter` に、CSS の `initial-letter: <drop-lines>` と `margin-inline-end: <drop-gap>` を書く。
ブラウザーの組み方は PDF と同じにならない。
HTML と EPUB の出力は、PDF でドロップキャップを組まない段落（当てない段落と、テキストでないインラインで始まる段落）に属性 `data-no-drop` を付け、CSS の規則を `:not([data-no-drop])` で外す。

### 文書

仕様書の段落スタイルのキーの表に `drop-lines` と `drop-gap` を書き、組み方の節を足す。
`docs/diagnostics.md` に G07143 を足す。
ロードマップの「ドロップキャップの組み方」を消す。
採択したら、0374 のステータスに `{"part":"ドロップキャップ","by":["docs/adr/0465-drop-caps.md"],"kind":"replace"}` を足す。

## 実装しないこと

2 書記素以上や、語の全体をドロップキャップにすることはしない。
ドロップキャップの字を行の外（左の余白）に出すことはしない。
`fit-characters` との併用は、[root ADR 0466](0466-fit-characters.md) で決める。

## 不変条件

- I1: `drop-lines` を書かない段落は、この ADR の前と同じに組む。
- I2: 回り込む図版の脇でない `drop-lines = n` の段落の 1 行目から n 行目の行の長さは、どれも、段落の幅から始まりの字下げと字の送り幅と `drop-gap` を引いた値である。
- I3: `drop-lines = n` の段落は、n 行以上の高さを持ち、1 行目から n 行目のあいだでページと段が変わらない。
- I4: ドロップキャップの字の面は、脇の行の字の面と重ならない。
- I5: テキストでないインラインで始まる、当てる段落の数を k とすると、G07143 はちょうど k 個出る。
- I6: 0 か自然数でない `drop-lines` の値ごとに、G03006 がちょうど一つ出る。
- I7: 当てない段落は、`drop-lines` の無い段落スタイルと同じに組み、診断を出さない。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| `drop-lines` を書かない段落 | 今と同じ | I1 |
| `drop-lines = 1` | 1 行目だけ短い。字は 1 行の高さ | I2 |
| `drop-lines = 3`、5 行の段落 | 1 行目から 3 行目が短い | I2, I4 |
| `drop-lines = 3`、1 行の段落 | 3 行の高さ。2 行目と 3 行目は空 | I3 |
| `drop-lines = 3`、ページの終わりの 2 行目から始まる段落 | 段落ごと次のページ | I3 |
| `drop-lines = 0` | G03006 | I6 |
| `first-line-indent = "1em"` と `drop-lines = 2` | 1 行目の字下げなし | I2 |
| 「「」で始まる段落と `drop-lines = 2` | 「「」をドロップキャップにする | I2 |
| ルビで始まる段落と `drop-lines = 2` | ドロップキャップなし。G07143 | I5 |
| 空の段落と `drop-lines = 2` | 今と同じ。診断なし | I1 |
| リストの項目の段落と `drop-lines = 2` | ドロップキャップなし。診断なし | I7 |

## 受けいれ条件

- A1: 横組みの欧文、横組みの和文、縦組みの和文の三つの見本を PDF で組み、メンテナーが、字の大きさと脇の行を目で確かめる。

## テスト設計

root ADR 0465 I1 から I7 を名前の先頭に置いたテストを、golem-project（キーの読み込み）と golem-typeset（行の長さ、高さ、分け方）に足す。
A1 の見本は、テストのデータに置く。
テストは、実装の前に書いて落ちることを確かめる。

## トレードオフ

欧文の字をキャップハイトでそろえるのは、欧文の組版の慣行に合わせるためである。
和文の字は仮想ボディでそろえるので、字面の小さい字は、行の高さより小さく見える。

段落の行が足りないときに空の行を足すのは、ドロップキャップが次の段落に食い込まないためである。
