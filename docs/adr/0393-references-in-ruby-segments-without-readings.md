# ADR 0393: 読みのないルビの区切りの中の参照を Reference にする

Status: accepted

## 文脈

ルビは、親文字と読みを `/` で同じ数の区切りに分けると、区切りごとに読みを振るモノルビになる。
読みの区切りを空にすると、その区切りにはルビを振らない（部分ルビ、`docs/markup.md` の「ルビ」の節）。

[ADR 0360](0360-ruby-base-references.md) で、読みのある区切りの親文字の中の `[ref-number]` と `[ref-title]` は、PDF の構造の木で `RB` の中の `Reference` になった。
しかし、読みのない区切りは `Ruby` を作らないので、`[ruby: 前/[ref-title a]後|まえ/]` の `[ref-title a]` は、文字を描くが `Reference` にもリンクにもならず、親の構造の要素の文字の葉に入る。
これは、参照の一つずつがちょうど一つの `Reference` になるという [ADR 0215](0215-ref-number-and-ref-title-as-reference.md) の R3 に反する。
ロードマップは、これを「読みのないルビの区切りの中の参照」に挙げている。

tett23 は、2026-11-18 に次のとおり決めた。

- 素直な方法で実装する。読みのない区切りの中の参照は、本文の中の参照と同じく `Reference` と `Link` にする。
- 親文字と読みの区切りの数が合わないときは、今のとおりエラー（G02015）のままとする。
- ルビの区切りに `/` を使う記法が、パースの例外になっていることは、別の課題としてロードマップに挙げる。

## 調査した事項

origin/main の [`0c11b987`](https://github.com/tett23/golem/tree/0c11b987b67104621254eda741322ff7ecf35cd0) で確かめた。

- 仕様書の、タグ付き PDF の対応の表の補いは、「読みのない区切りの親文字は `Ruby` を作らない」「読みのない区切りの親文字の中の `[ref-number]` と `[ref-title]` は、文字を描くが `Reference` も `Link` も作らず、親の構造の要素の文字の葉に入る」と書いている。
- `docs/markup.md` は、親文字と読みの区切りの数が合わなければコンパイルエラーとしている。そのコードは G02015（「モノルビの対象と読みのセグメントの数が一致しません」）である。
- [ADR 0360](0360-ruby-base-references.md) の実装（PR #1024）の担当は、読みのない区切りの中の参照を、構造の木を一時的に出力して確かめた。

## 実装すること

- 読みのない区切りの親文字の中の `[ref-number]` と `[ref-title]` は、本文の中の参照と同じく、`Reference` の中の `Link` にする。その `Reference` は、読みのない区切りの字が入る親の構造の要素の中に、原稿の順に置く。
- リンクの矩形は、その参照の字を描いた位置から求める。PDF/X-4 では、[ADR 0350](0350-omit-page-link-annotations-from-pdf-x-4.md) のとおり `Link` を文字を保持する `Span` にする。
- 読みのない区切りは、今のとおり `Ruby` を作らない。読みのある区切りの扱い（[ADR 0360](0360-ruby-base-references.md)）は変えない。
- 仕様書の対応の表の補いを書き換え、ロードマップの「読みのないルビの区切りの中の参照」の項目を消す。マニュアルに、この例外を書いた箇所があれば直す。

## 実装しないこと

- ルビの区切りの記法を変えること。ロードマップの課題として別に扱う。
- 区切りの数が合わないときの G02015 を変えること。
- HTML と EPUB の出力を変えること。

## 不変条件

- I1: どのルビでも、親文字の中の `[ref-number]` と `[ref-title]` の一つずつが、PDF の構造の木でちょうど一つの `Reference` になる。区切りに読みがあるかによらない。
- I2: 読みのない区切りの中の参照の `Reference` は、`Ruby` の中に無い。
- I3: どのルビでも、親文字の字は、構造の木の葉に、原稿の順にちょうど一度ずつ現れる。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| `[ruby: 前/[ref-title a]後\|まえ/]` | `[ref-title a]` が `Ruby` の外の `Reference` になり、「前」は `RB` にある | I1, I2, I3 |
| `[ruby: [ref-number a]/後\|/あと]` | 最初の区切りの参照が `Ruby` の外の `Reference` になる | I1, I2, I3 |
| `[ruby: 前/[ref-title a]\|まえ/えー]` | 参照は `RB` の中の `Reference`（[ADR 0360](0360-ruby-base-references.md) のまま） | I1, I3 |
| 読みのない区切りに参照が二つ続く | `Reference` が二つ、原稿の順に並ぶ | I1, I3 |
| 参照の無いルビ | `Reference` は無い | I1, I3 |

## 受けいれ条件

なし。
自動のテストで確かめられることは、すべて不変条件に書いた。

## テスト設計

テストの名前は `ADR 0393 I<n>: ` で始める。

- golem-layout の `StructureSpec` で、親文字の区切りが 3 個までで、各区切りが字、`[ref-number]`、`[ref-title]` の 2 個までの並びで、読みの有無のすべての組み合わせを数え尽くし、I1 から I3 を確かめる。
- golem-driver の `TaggedPdfSpec` で、境界の表の行を実際にビルドして確かめる。PDF/X-4 の場合も一つ入れる。

## トレードオフ

- 読みのない区切りの中の参照は `Ruby` の外に出るので、一つのルビの親文字が、構造の木では `Ruby` と `Reference` に分かれて並ぶ。読みのない区切りはもともと `Ruby` を作らないので、その字は今もルビの外にある。
