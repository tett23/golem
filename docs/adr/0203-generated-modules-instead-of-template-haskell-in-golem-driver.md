# ADR 0203: golem-driver の Template Haskell を、生成してコミットしたモジュールにする

ステータス: 採択（未実装）

## 文脈

[ADR 0202](0202-packages-that-do-not-build-for-wasm.md) は、[ADR 0199](0199-pdf-typesetting-as-wasm-reactor.md) の wasm のビルドで組めなかった五つのパッケージの扱いを決め、その扱いを当てて組めるかをもう一度確かめると決めた。
2026-11-07 に、GitHub Actions の `ubuntu-24.04` で、[ADR 0202](0202-packages-that-do-not-build-for-wasm.md) の 2 の扱いをすべて当てて確かめた（結果の全文は [#632](https://github.com/tett23/golem/pull/632) の説明にある）。
五つはすべて組め、golem-layout の Template Haskell（`Golem.Layout.Hyphenation.EnUs`）も通った。
golem-driver の依存は、golem-typeset を含めてすべて組めた。

組めなかったのは、golem-driver の Template Haskell を使う二つのモジュールである。
`Golem.Driver.Explain` と `Golem.Driver.Version` が、どちらも次のエラーで止まった。

```
loadDLLs failed: JSException "Error: cannot handle import env.__c_longjmp with kind tag
    at DyLD.loadDLLs (.../wasm32-wasi-ghc/lib/dyld.mjs:1138:15)"
```

wasm の GHC は、Template Haskell の splice を評価するとき、そのパッケージが依存するパッケージの共有ライブラリを、Node の上の `dyld.mjs` で読み込む。
`dyld.mjs` が扱える import は、関数と GOT のグローバルである。
[ADR 0202](0202-packages-that-do-not-build-for-wasm.md) の 1 で、golem-font の FreeType を `-mllvm -wasm-enable-sjlj` で組んだので、golem-font は wasm の例外処理のタグ `__c_longjmp` を import する。
golem-driver は golem-typeset を通して golem-font に依存するので、golem-driver の splice を評価するときに golem-font を読み込み、そこで止まる。
golem-layout は golem-font に依存しないので、`EnUs` は通った。
つまり、golem-font に依存するパッケージでは、wasm で Template Haskell を使えない。
[ADR 0202](0202-packages-that-do-not-build-for-wasm.md) のトレードオフは、sjlj の影響を wasm を動かすエンジンだけと見込んでおり、この影響は見込んでいなかった。

二つのモジュールの splice は、どちらもコンパイルのときにファイルを読み、その中身を文字列の定数にするだけである。

- `Golem.Driver.Version` は、リポジトリの根の `VERSION`（golem-driver の中のシンボリックリンク）を読み、`golemVersion` にする（[`Version.hs`](https://github.com/tett23/golem/blob/3b80b61f0bef1428c58baaca9302c92078525a8f/modules/golem-driver/src/Golem/Driver/Version.hs)）。`golemVersion` は PDF の組版に渡り（[`Driver.hs`](https://github.com/tett23/golem/blob/3b80b61f0bef1428c58baaca9302c92078525a8f/modules/golem-driver/src/Golem/Driver.hs#L1171)）、PDF のバイト列に入る。`golem --version` もこれを表示する。
- `Golem.Driver.Explain` は、`docs/diagnostics.md`（同じくシンボリックリンク）を読み、`parseCatalog` で形を確かめてから、文字列の定数にする（[`Explain.hs`](https://github.com/tett23/golem/blob/3b80b61f0bef1428c58baaca9302c92078525a8f/modules/golem-driver/src/Golem/Driver/Explain.hs#L29-L41)）。形が壊れていれば、コンパイルが失敗する。これを使うのは `golem explain` と、diagnostics の後の一行（`explainHint`）と、golem-lsp の `codeDescription` で、PDF の組版の道は使わない。

`docs/diagnostics.md` は 483,089 バイトあり、タブとほかの制御文字を含まない（`3b80b61f` で確かめた）。

[ADR 0199](0199-pdf-typesetting-as-wasm-reactor.md) の「メンテナーが決めること」の 5 は、Template Haskell が組めなければ、生成したモジュールをコミットする案（`scripts/gen-vertical-orientation.sh` と同じ形）を挙げていた。
メンテナーは、この案で ADR を作ると決めた（2026-11-08）。

Golem には、生成してコミットするモジュールがすでに二種類ある。

- `scripts/gen-parser.sh` が作るパーサー。CI の `build` ジョブが、生成し直して `git diff --exit-code` で差分がないことを確かめる（[`ci.yml`](https://github.com/tett23/golem/blob/3b80b61f0bef1428c58baaca9302c92078525a8f/.github/workflows/ci.yml#L379-L383)）。
- `scripts/gen-vertical-orientation.sh` が作る `Golem.Layout.Orientation.Table`。Unicode の表を上げるときに手で動かし、スクリプトのテストは `scripts/test.sh` にある（[docs/adr/0078](0078-tests-for-release-and-hand-run-scripts.md)）。

## 実装すること

### 1. 生成するスクリプト

`scripts/gen-embedded.sh` を作る。
POSIX の `sh` と BSD の `awk` でも動くように書く。
引数を取らず、次の二つのモジュールを、リポジトリの根からの決まったパスで生成し直す。

| 生成するモジュール | 読むファイル | 定数 |
| --- | --- | --- |
| `modules/golem-driver/src/Golem/Driver/Version/Embedded.hs` | `VERSION` | `versionText :: Text`（ファイルの中身そのまま） |
| `modules/golem-driver/src/Golem/Driver/Explain/Embedded.hs` | `docs/diagnostics.md` | `documentText :: Text`（ファイルの中身そのまま） |

- モジュールの先頭に、`Generated by scripts/gen-embedded.sh; do not edit.` と、元のファイルのパスを書く（`Golem.Layout.Orientation.Table` と同じ形）。
- 中身は、元のファイルの一行を一つの文字列のリテラルにした並びを、改行でつなぐ形にする。最後の行の改行の有無も、元のファイルと同じにする。一行を一つのリテラルにするので、`docs/diagnostics.md` を一行変えれば、生成したモジュールも一行だけ変わる。
- 文字列のリテラルの中では、`\` と `"` を逃がす。UTF-8 の文字は、そのまま書く。タブと、そのほかの制御文字（U+0000 から U+001F と U+007F）があれば、生成せずに、行の番号を書いて失敗する（「メンテナーが決めること」の 3）。
- 生成したモジュールは、CI の fourmolu と hlint の対象から外す。パーサーの生成物と同じ扱いである（[`ci.yml`](https://github.com/tett23/golem/blob/3b80b61f0bef1428c58baaca9302c92078525a8f/.github/workflows/ci.yml#L665-L672)）。

### 2. Template Haskell を外す

- `Golem.Driver.Version` の `golemVersion` を、`T.strip versionText` にする。
- `Golem.Driver.Explain` の `document` を、`documentText` にする。`catalog` と、ほかのエクスポートは変えない。
- 二つのモジュールから `{-# LANGUAGE TemplateHaskell #-}` を除き、golem-driver の `build-depends` から `template-haskell` を除く。
- `extra-source-files` の `VERSION` と `diagnostics.md` は、テストが読むので残す。コメントを、「生成したモジュールと比べるテストが読む」に書き直す。

golem-layout の `EnUs` の Template Haskell は、wasm で通ったので変えない（「実装しないこと」）。

### 3. 生成し直していないことを見つける

二つの方法で見つける（「メンテナーが決めること」の 2）。

- golem-driver のテストに、`versionText` が `VERSION` の中身と、`documentText` が `docs/diagnostics.md` の中身と、バイト単位で一致することを確かめるテストを足す。失敗したときのメッセージに、`sh scripts/gen-embedded.sh` を走らせるよう書く。
- CI の `build` ジョブの「Generated parser matches the grammar」の後に、`scripts/gen-embedded.sh` を走らせて `git diff --exit-code` で差分がないことを確かめる段を足す。パーサーと同じ形にする。CI の設定のテスト（`scripts/ci/test.sh`）に、この段があることの検査を足す。

`docs/diagnostics.md` の形の検査（今はコンパイルのときに行う `parseCatalog`）は、golem-driver のテストに移す。
`parseCatalog documentText` が `Right` になり、そのコードの項が一つ以上あることを確かめる。

### 4. 手順の文書

- `CONTRIBUTING.md` の「タグとリリース」の 2 に、`VERSION` を書き換えた後に `sh scripts/gen-embedded.sh` を走らせることを足す。
- `docs/diagnostics.md` を変える手順を書いている箇所（`CONTRIBUTING.md`、`docs/manual-policy.md` など、実装のときに `rg` で探す）に、同じことを足す。
- [docs/specifications.md](../specifications.md) の golem-driver の説明に、`VERSION` と `docs/diagnostics.md` を生成したモジュールで埋め込むことと、golem-font に依存するパッケージで Template Haskell を使わないことを書く。
- README の CI のジョブの表の `build` に、生成したモジュールの検査を足す。
- [ADR 0202](0202-packages-that-do-not-build-for-wasm.md) のステータスの行に、golem-driver の Template Haskell の扱いをこの ADR が決めたことを書く。

### 5. wasm でもう一度確かめる

1 から 3 を main に入れた後、[ADR 0202](0202-packages-that-do-not-build-for-wasm.md) の 3 と同じ作業用のワークフローで、もう一度確かめる。

- golem-driver（golem-plugin を外した版）と、それを組み込んだ確かめのための実行ファイルが、wasm で組めること。
- その実行ファイルで、[ADR 0199](0199-pdf-typesetting-as-wasm-reactor.md) の「テスト設計」の比べの入力（kanikosen と `scripts/determinism/` の入力）を組み、PDF の SHA-256 がネイティブと一致すること。この段階では [ADR 0199](0199-pdf-typesetting-as-wasm-reactor.md) の `Files` の入口がまだないので、ディスクから読むこと（WASI の preopen を渡すこと）を許す。
- 結果は、この ADR の実装のプルリクエストの説明と `docs/ci-timings/` に書く。

すべて通れば、[ADR 0202](0202-packages-that-do-not-build-for-wasm.md) のステータスを採択にする。
また組めないものが見つかれば、そこで止め、新しい ADR で扱いを決める。

### パッケージの依存

この ADR は、golem のパッケージのあいだの `build-depends` を変えない。
Hackage のパッケージでは、golem-driver のライブラリから `template-haskell` を除く。

## 実装しないこと

- **golem-layout の `EnUs` を生成したモジュールにすること**：wasm で通っている。golem-layout が golem-font に依存するようになれば、そのときに決め直す。
- **`Golem.Driver.Explain` を golem-driver から別のパッケージに出すこと**：「メンテナーが決めること」の 1 で退ける。
- **ネイティブだけ Template Haskell を残すこと**：「メンテナーが決めること」の 1 で退ける。
- **golem-font を sjlj なしで組み直して Template Haskell を評価すること**：Template Haskell の評価のときだけ別の golem-font を読ませる仕組みが要り、cabal の一つのビルドの中では作れない。
- **`dyld.mjs` に例外処理のタグを扱わせること**：GHC の wasm の配布物（ghc-wasm-meta）の側の変更である。上流に修正を送ることも、この ADR では行わない。

## テスト設計

テストを先に書き、今の実装で失敗することを確かめてから実装する。

### golem-driver のテスト

- `versionText` が、`VERSION` の中身とバイト単位で一致すること。`golemVersion` が、`VERSION` の中身の前後の空白を除いたものと一致すること。
- `documentText` が、`docs/diagnostics.md` の中身とバイト単位で一致すること。
- `parseCatalog documentText` が `Right` になり、コードの項が一つ以上あること。
- 今の `golem explain`、`explainHint`、golem-lsp の `codeDescription` のテストが、変わらず通ること。

この三つは、生成するモジュールがまだないので、先に書くとコンパイルが失敗する。
コンパイルの失敗を、失敗の確認とする。

### スクリプトのテスト（`scripts/test.sh`）

- `\`、`"`、日本語、空の行、`{-`、`-}`、`--` を含む小さな fixture から生成したモジュールが、期待するファイルと一致すること。最後の改行がある fixture と、ない fixture の両方で確かめる。
- タブを含む fixture と、U+0001 を含む fixture で、行の番号を書いて失敗し、モジュールを書き換えないこと。
- 二度走らせると、同じバイト列になること。

### 出力が変わらないこと

- `scripts/determinism/hashes.txt` と golden のファイルが、差分に現れないこと。`golemVersion` の値が変わらないので、PDF のバイト列も変わらない。
- `golem --version` の出力が変わらないこと（今の golem-cli のテスト）。

## トレードオフ

`docs/diagnostics.md` を変えるプルリクエストは、生成したモジュールも一緒に変えることになる。
diagnostics のコードを足すプルリクエストは多いので、この手間は頻繁に生じる。
並べて開いたプルリクエストが同じ箇所を変えると、`docs/diagnostics.md` と同じ箇所で衝突する。
一行を一つのリテラルにすれば、衝突は元のファイルと同じ行に限られ、元のファイルの衝突を直してからスクリプトを走らせ直せば解ける。
生成し直すのを忘れても、golem-driver のテストと CI の検査が落ちるので、main には入らない。

コンパイルのときに `docs/diagnostics.md` の形を確かめる保証は、テストに移る。
テストを走らせずに組んだ golem は、壊れた形の文書を持ちうる。
main に入るものは CI のテストを通っているので、リリースの実行ファイルには及ばない。

生成したモジュールは約 48 万バイトあり、リポジトリの大きさと、golem-driver のコンパイルの時間を増やしうる。
今も同じ文字列の定数を Template Haskell で作ってコンパイルしているので、定数そのものの大きさは変わらない。
増えるのは、リテラルの並びを一つの `Text` につなぐ分である。
コンパイルの時間がどれだけ変わるかは、実装のときに測る。

golem-font に依存するパッケージで Template Haskell を使えない、という制約が残る。
新しく Template Haskell を使いたくなったときは、生成するスクリプトに足すか、golem-font に依存しないパッケージに置く必要がある。
この制約を仕様書に書き、レビューで見つけられるようにする。
wasm の CI のジョブ（[ADR 0199](0199-pdf-typesetting-as-wasm-reactor.md) の 7）が入れば、違反はそのジョブで見つかる。

## メンテナーが決めること

1. **どちらのモジュールを生成するか**：推奨は、`Golem.Driver.Version` と `Golem.Driver.Explain` の両方である。golem-driver の中の Template Haskell がなくなり、ネイティブと wasm で同じソースを組む。
   - 退けた案の一つは、`Golem.Driver.Explain` を golem-driver から新しいパッケージ（golem-cli と golem-lsp が依存する）に出し、Template Haskell のまま残すことである。`docs/diagnostics.md` の生成物はなくなるが、golem のパッケージのあいだの依存が変わり、新しいパッケージは golem-font に依存しない形を保つ必要がある。`Golem.Driver.Version` の生成は、どちらにしても要る。
   - もう一つは、cabal の `if os(wasi)` で、wasm だけ生成したモジュールのディレクトリを使うことである。ネイティブの手順は変わらないが、二つのモジュールが同じ名前と型を持つことをコンパイラが確かめず、生成したモジュールが古くなっても wasm のジョブでしか気付かない。
2. **生成し直していないことを見つける方法**：推奨は、golem-driver のテストと、CI の `git diff --exit-code` の両方である。テストは手元の `cabal test` で気付け、CI の検査はパーサーと同じ形で、テストの組を選ぶ CI の行列（[docs/adr/0037](0037-ci-build-job-speedup.md)）に左右されない。
   - 退けた案は、どちらか一つだけにすることである。テストだけだと、golem-driver のテストを走らせない CI の行列で気付かない。CI の検査だけだと、手元で気付くのが push の後になる。
3. **タブと制御文字**：推奨は、生成せずに失敗することである。今の `docs/diagnostics.md` と `VERSION` はタブを含まず、逃がす規則が `\`、`"` の二つで済む。数値の逃がし方（`\9` や `\SOH`）は、後ろに続く文字によって `\&` が要り、間違えやすい。
   - 退けた案は、タブと制御文字を `\t` や `\DEL` などに逃がすことである。スクリプトが長くなり、テストすべき組み合わせが増える。必要になったら、そのときに足す。

## 決めたことの記録

- **「メンテナーが決めること」のすべて**（2026-11-08、メンテナー）：どれも推奨のとおりとした。
