# ADR 0361: 同一入力から同じ EPUB のバイト列を生成する

ステータス: 採択（未実装）

## 文脈

フォント、PDF、EPUB の出力のうち、書き手が必要とする「EPUB の決定性」の扱いを決める。

## 調査した事項

今の実装は zip のエントリの時刻を 0 にし、並びも決めて書いており、CI の決定性の検査も EPUB のハッシュを比べているが、仕様書はまだ保証しないとしている（[ADR docs/adr/0002](../adr/0002-determinism.md)、[golem-epub ADR 0001](../golem-epub/adr/0001-epub-packaging.md)）。

## 実装すること

同じ Golem のビルド、設定、原稿、素材で EPUB 全体のバイト一致を保証する。
zip エントリの順、時刻、圧縮条件と生成する識別子を入力から決め、絶対作業パスや実行時刻を記録しない。

同じビルドには EPUB を構成する圧縮器の版も含む。
入力パスの比較は、本からの相対位置を保ってプロジェクト全体を移して行う。

## 実装しないこと

異なるビルド間の一致は保証しない。

## 不変条件

1. 同一ビルドと同一入力から時刻と作業ディレクトリを変えて作った EPUB はバイト単位で等しい。

| 境界の入力 | 期待する結果 |
| --- | --- |
| 同じ本を別ディレクトリで生成 | 全バイト一致 |
| 素材の列挙順だけが異なる | 全バイト一致 |

## テスト設計

- `inv1_epub_byte_determinism_property` で次の述語を検査する。同一ビルドと同一入力から時刻と作業ディレクトリを変えて作った EPUB はバイト単位で等しい。
- `inv1_epub_byte_determinism_case_1` は「同じ本を別ディレクトリで生成」を入力とし、「全バイト一致」を確かめる。
- `inv1_epub_byte_determinism_case_2` は「素材の列挙順だけが異なる」を入力とし、「全バイト一致」を確かめる。

## トレードオフ

圧縮器を更新するときは版をまたぐバイト一致を保証しない。
