# ADR 0297: 改行しない字の隣のソフトハイフンを G07124 で知らせる

ステータス: 採択（未実装）

## 文脈

### [ADR 0285](0285-read-soft-hyphens-at-inline-boundaries-in-the-joined-word.md) の二つの文

[ADR 0285](0285-read-soft-hyphens-at-inline-boundaries-in-the-joined-word.md) は、インラインの境目の隣のソフトハイフンを、つないだ語で読むと決めた。
候補の前の字か後の字が改行しない字（リンクの語、コード、改行しない範囲）なら、候補にしない。
このときの notice について、0285 の二つの節が違うことを書いている。

- 「実装すること」の 2：ソフトハイフンが改行しない字の中にあれば G07124、ないときは G07123 とする。
- 「テスト設計」の H3：リンクの語の隣のソフトハイフンで G07124 が出ること。

実装（[#836](https://github.com/tett23/golem/pull/836)）は「実装すること」の 2 に従った（[`joinRun` の `roleOf`](https://github.com/tett23/golem/blob/39d97a1af61ea5b0dfef153d1e365273377c9800/modules/golem-layout/src/Golem/Layout/Japanese.hs#L1745-L1755)）。
H3 のテストも、リンクの語の直後のソフトハイフンを G07123 とした（[H3 のテスト](https://github.com/tett23/golem/blob/39d97a1af61ea5b0dfef153d1e365273377c9800/modules/golem-layout/test/JoinedWordEnum.hs#L692-L696)）。
`[link "u": abc]­def` のソフトハイフンは、今は G07123 である。
`­` は U+00AD を表す。

G07123 の説明（[docs/diagnostics.md](../diagnostics.md)）は、意味を「前か後ろが語の字でない」とする。
ところが、`abc` も `def` も語の字であり、候補にならない理由は、前の字がリンクの語の字であることである。
同じ説明は、0285 の実装で「境目の向こうの字がリンクの語か改行しない範囲の字なら、ソフトハイフン自身がその外にあっても分割の候補にせず、このコードを出す」を足した。
一つのコードの意味に、二つの原因が入っている。

### 決めたこと

2026-11-10 に、tett23 が次のように決めた。

- ソフトハイフンが、隣の字（インラインの境目の向こうの字、つないだ語の字）が改行しない字であるために候補にならないなら、ソフトハイフン自身が改行しない字の外にあっても G07124 とする。改行しない字は、リンクの語、文字スタイル `url` の文字、本文の中のコード、改行しない範囲である。
- G07123 は、ほかの理由で前か後ろが語の字でないソフトハイフンに残す。

コードは、原因ごとに一つとする。
G07123 の原因は「隣が語の字でない」こと、G07124 の原因は「改行しない字が分割を止める」ことになる。
この ADR は、その決定を記録し、実装と文書の変更を定める。

## 実装すること

### 1. notice の決め方

つないだ語の中のソフトハイフンの notice を、次の順で決める。

1. つないだ語の中で語の頭のもの（要素の最初の字より前のもの）は、今のとおり notice を出さない。コードと `url` の文字の中のものは、今のとおり G07124 とする。
2. ソフトハイフン自身が改行しない字の中にあれば、今のとおり G07124 とする。
3. つないだ語の中で前の字と後の字がどちらも要素の字（[ADR 0272](0272-discretionary-hyphens-hyphenation-exceptions-and-no-break.md) の候補の条件）であり、その前の字か後の字が改行しない字なら、G07124 とする。今は G07123 である。
4. ほかの候補でないもの（前か後ろが語の字でないもの、語の終わりのもの、和文の字のあいだのもの）は、G07123 とする。

3 の改行しない字は、リンクの語、`url` の文字、コード、改行しない範囲のどれでもよい。
`[link "u": abc]­.` のように後の字が語の字でないものは、隣の字がリンクの語の字でも 4 の G07123 とする。
候補にならない原因は、後の字が語の字でないことだからである。

候補にするかどうかと、行の分け方は変えない。
変えるのは、候補でないソフトハイフンのうち 3 にあたるものの notice のコードだけである。

### 2. メッセージ

G07124 の見出しとメッセージを、中の場合と隣の場合の両方を表す文にする。

- 見出し：`改行しない文字の中か隣のソフトハイフンを、分割の候補にしませんでした`
- メッセージ：`改行しない文字（コード、URL、リンク、改行しない範囲）の中か隣のソフトハイフンなので、分割の候補にしません`

G07123 の見出しとメッセージは変えない。

### 3. 文書

- [docs/diagnostics.md](../diagnostics.md) の G07123 の「意味」から、「境目の向こうの字がリンクの語か改行しない範囲の字なら、ソフトハイフン自身がその外にあっても分割の候補にせず、このコードを出す」を消す。
- G07124 の「意味」に、前か後ろの字が改行しない文字であるために候補にならないソフトハイフンもこのコードを出すことを書き、この ADR と [ADR 0285](0285-read-soft-hyphens-at-inline-boundaries-in-the-joined-word.md) を「ADR」の項目に足す。見出しとメッセージを 2 のとおりにする。golem-driver の `Explain/Embedded.hs` を作り直す。
- [docs/specifications.md](../specifications.md) の「行分割」の節のソフトハイフンの二つの段落（G07124 と G07123 の分け方）を、1 のとおりに書き直し、この ADR へのリンクを付ける。
- [docs/markup.md](../markup.md) のソフトハイフンの段落と、利用者向けのマニュアルの付録 A（`manual/appendices/a-markup.gm`）の G07124 の文に、隣の場合を足す。見た目の回帰テストの変わったページを確かめて更新する。
- [ADR 0285](0285-read-soft-hyphens-at-inline-boundaries-in-the-joined-word.md) のステータスの行に「（改行しない字の隣のソフトハイフンの notice）は ADR 0297」を足す。

### 4. 出力の変化

notice の数は変わらず、コードだけが変わる。
3 にあたる入力で、G07123 の notice が G07124 になる。
2026-11-10 の `main`（`39d97a1a`）では、リポジトリの `.gm` の原稿に、ソフトハイフンとして働く U+00AD も `[shy]` もない。
マニュアルの付録 A は、`\[shy\]` をコードの中に書くだけである。
実装のプルリクエストでは、notice の変わったフィクスチャと本を探し、その一覧（ないなら、ないこと）を説明に書く。

## 実装しないこと

- **候補にするかどうかを変えること**：改行しない字の隣のソフトハイフンは、[ADR 0285](0285-read-soft-hyphens-at-inline-boundaries-in-the-joined-word.md) の「メンテナーが決めること」の 3 のとおり、候補にしない。
- **新しいコードを足すこと**：中の場合と隣の場合は、どちらも改行しない字が分割を止める同じ原因なので、G07124 一つで知らせる。
- **語の頭のソフトハイフンの扱い**：1 の 1 のとおり、今のままとする。
- **HTML と EPUB**：今のとおり、notice を出さない。

## 不変条件

「つないだ語」は [ADR 0285](0285-read-soft-hyphens-at-inline-boundaries-in-the-joined-word.md) の「実装すること」の 1 のとおりとする。
「改行しない字」は、`lkCode`、`lkUrl`、`lkLink`、`lkNoBreak` のどれかが真の字とする。

- **N1 隣の改行しない字は G07124**：つないだ語の中で前の字と後の字がどちらも要素の字であり、どちらかが改行しない字であるソフトハイフンには、G07124 がちょうど一つ出て、G07123 は出ない。
- **N2 G07123 は語の字でないものだけ**：G07123 の出るどのソフトハイフンも、改行しない字の外にあり、つないだ語の中で前の字か後の字が要素の字でない。
- **N3 コードは原因ごとに一つ**：どのソフトハイフンにも、G07123 と G07124 の両方が出ることはない。
- **N4 分け方は変わらない**：どの入力でも、行分割の項目の並び（ソフトハイフンの罰点の位置、幅、罰則を含む）は、この ADR の前と同じである。
- **N5 notice の数は変わらない**：どの入力でも、G07123 と G07124 の数の和は、この ADR の前と同じである。
- [ADR 0285](0285-read-soft-hyphens-at-inline-boundaries-in-the-joined-word.md) の H3（境目で分けた段落と一つのテキストとで notice の種類の列が等しい）は、改行しない字を含まない入力について、今のまま成り立つ。

境界の入力：

| 量 | 調べる値 |
| --- | --- |
| ソフトハイフンの置き場所 | 改行しない字の中の終わり（`[link "u": abc­]def`）、直後（`[link "u": abc]­def`）、直前（`abc­[link "u": def]`）、両側（`[link "u": abc]­[link "u": def]`）、ソフトハイフンだけのテキストが境目にあるもの（`[link "u": abc][strong: ­]def`） |
| 改行しない字の種類 | リンクの語、`url` の文字、本文の中のコード、改行しない範囲（`[style no-break: …]`） |
| 反対側の字 | 語の字、句読点（`[link "u": abc]­.`）、段落の終わり |
| 改行しない字のないもの | `abc­[strong: def]`（notice なし）、`abc­.`（G07123） |

## テスト設計

テストを先に書き、今の実装で失敗することを確かめてから実装する。
テストの名前には、この ADR の N1 から N5 と、関わる [ADR 0285](0285-read-soft-hyphens-at-inline-boundaries-in-the-joined-word.md) の H3、[ADR 0272](0272-discretionary-hyphens-hyphenation-exceptions-and-no-break.md) の I3 の番号を入れる。

- **N1**（golem-layout）：境界の表の「ソフトハイフンの置き場所」と「改行しない字の種類」の組で、反対側が語の字のとき、notice が `[ShyInUnbreakable]` であること。`roleOf` を読むかぎり、今は直後、直前、両側、ソフトハイフンだけのテキストの組で `[ShyNotBetweenLetters]` なので失敗する。中の終わりの組は今も通る。
- **N2**（golem-layout）：反対側が句読点か段落の終わりの組と、改行しない字のない組で、notice が今のとおり（G07123 か、なし）であること。
- **N3、N5**（golem-layout）：同じ組で、notice の数が組ごとに今と同じであること。
- **N4**（golem-layout）：同じ組で、項目の並びが、notice を除いて今と同じであること。0272 の I3 のとおり、改行しない字の隣にソフトハイフンの罰点がないこと。
- **H3**：[`JoinedWordEnum.hs` の H3 のテスト](https://github.com/tett23/golem/blob/39d97a1af61ea5b0dfef153d1e365273377c9800/modules/golem-layout/test/JoinedWordEnum.hs#L692-L696) の、リンクの語の直後を G07123 とする期待を G07124 に直す。境目の列挙の H2 と H3 は変えずに通ること。
- **golem-driver**：`[link "https://example.com/": abc]­def` と `[code: ab]­cd` を PDF に組み、G07124 の notice が一つずつ、ソフトハイフンの位置に、2 のメッセージで出ること。G07123 は出ないこと。
- 文書は、`Explain/Embedded.hs` の生成の検査と、textlint と `adr-guard links --fix` で確かめる。

## トレードオフ

- G07124 の意味が「改行しない文字の中」から「中か隣」に広がる。隣の場合は、書き手がソフトハイフンを改行しない字の外に書いているので、メッセージの「中」だけでは原因を読み違える。2 で、見出しとメッセージに「隣」を足す。
- 同じ字の並びでも、隣の字にリンクを付けるかどうかで、G07123 にも G07124 にもならず notice なしになったり、G07124 になったりする。どちらも書き手が改行しない字を置いたことによる変化であり、原因を指すコードが変わる。
- notice のコードが変わるので、決定性の検査（同じ入力に同じ notice）の期待値のうち、3 にあたる入力のものが変わる。

## 決めたことの記録

2026-11-10 に、tett23 がこの ADR の判断のすべてを推奨のとおりに決めた。

1. **反対側が語の字でないとき**：`[link "u": abc]­.` のように後の字が語の字でないものは、隣の字が改行しない字でも G07123 のままとする。候補にならない原因は後の字が語の字でないことであり、原因ごとに一つのコードとする決まりに合う。隣の字が改行しない字なら反対側によらず G07124 とする案は、退けた。
