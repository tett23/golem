# ADR 0226: ISO 15930-7 の照合の期限を v1.0.0 の前に改める

ステータス: 採択

## 文脈

[ADR 0221](0221-check-iso-15930-7-for-link-annotations-before-rc4.md) は、リンクの注釈についての ISO 15930-7:2010 の照合を、メンテナーが規格の本文を入手して行い、`docs/audits/` に記録すると決めた。
期限は v0.1.0-rc4 のタグの前とし（「メンテナーが決めること」の 5）、今の出力が規格に反すると分かれば、[ADR 0182](0182-external-links.md) を改める ADR の実装まで rc4 のタグを打たないとした（同じく 4）。
実装（[#674](https://github.com/tett23/golem/pull/674)）は、ロードマップの v0.1.0-rc4 の節に照合の項目を足した。

メンテナーは、この照合を先に延ばし、v1 で扱うと決めた（2026-11-08）。
[ADR 0221](0221-check-iso-15930-7-for-link-annotations-before-rc4.md) のトレードオフも、照合を待たずに rc4 を出したければ、期限を改める ADR を書けばよいとしている。
この ADR がその ADR である。

期限を延ばすと、[ADR 0221](0221-check-iso-15930-7-for-link-annotations-before-rc4.md) の「rc4 との関係」の節が挙げた危険が残る。
v0.1.0-rc4 は、リンクの注釈を含む最初のリリースであり、照合のないまま PDF/X-4 を名乗る PDF を配る。
規格に反すると後で分かっても、そのあいだに組んだ入稿用の PDF は戻らない。
[docs/compatibility.md](../compatibility.md) の約束は 1.0.0 からなので、直すこと自体は v1.0.0 の前にできる。

## 実装すること

- 照合の期限を、v1.0.0 のタグの前に改める。照合のやり方、問い、記録の置き場所、差が見つかったときの扱い（[ADR 0221](0221-check-iso-15930-7-for-link-annotations-before-rc4.md) の「メンテナーが決めること」の 1 から 4）は変えない。ただし、4 の「rc4 のタグを打たない」は「v1.0.0 のタグを打たない」と読み替える。
- docs/roadmap.md の照合の項目を、v0.1.0-rc4 の節から v1.0.0 の節へ移し、期限の文を v1.0.0 に改める。「手で確かめる項目」の照合の記述も、同じく v1.0.0 に改める。
- v0.1.0-rc4 から v1.0.0 の前のリリースのリリースノートの「既知の問題」に、リンクの注釈を含む PDF/X-4 の PDF は、ISO 15930-7 の照合を済ませていないと書く（「メンテナーが決めること」の 1）。リリースノートの手順の書かれた文書（`CONTRIBUTING.md` の「タグとリリース」）に、この一文を書くことを足す。
- [ADR 0221](0221-check-iso-15930-7-for-link-annotations-before-rc4.md) のステータスの行に、期限をこの ADR が改めたことを書く。[ADR 0221](0221-check-iso-15930-7-for-link-annotations-before-rc4.md) は、照合が済むまで採択（未実装）のまま残す。

## 実装しないこと

- **照合そのもの**：メンテナーが v1.0.0 の前に行う。
- **rc4 の PDF からリンクの注釈を外すこと**：[ADR 0182](0182-external-links.md) の振る舞いは変えない。
- **PDF/X-4 の PDF でだけリンクの注釈を外すこと**：「メンテナーが決めること」の 2 で退ける。

## 不変条件

なし。
リリースの期限と文書の置き場所を決める ADR であり、Golem の振る舞いを変えない。

## テスト設計

自動のテストは書けない。
実装のプルリクエストで次を確かめる。

- docs/roadmap.md の v0.1.0-rc4 の節に照合の項目がなく、v1.0.0 の節にあること。
- `CONTRIBUTING.md` の「タグとリリース」に、リリースノートの既知の問題の一文が書かれていること。
- v1.0.0 のタグを打つ前に、`docs/audits/` に照合の記録があり、ロードマップの照合の項目が消えていることを、リリースの手順で確かめる（[ADR 0221](0221-check-iso-15930-7-for-link-annotations-before-rc4.md) のテスト設計の rc4 を v1.0.0 に読み替える）。

## トレードオフ

rc4 を照合に待たせずに出せる。
その代わり、rc4 から v1.0.0 の前までのリリースで、照合のないまま PDF/X-4 の PDF にリンクの注釈を書く。
入稿用の PDF を作る利用者には、リリースノートの既知の問題で知らせる。
規格に反すると後で分かったときは、その間に作られた PDF を Golem の側から直す手段はない。

## メンテナーが決めること

1. **利用者への知らせ方**：推奨は、v1.0.0 の前のリリースのリリースノートの既知の問題に書くことである。照合を済ませていないことを、入稿用の PDF を作る利用者が知ってから使える。
   - 退けた案の一つは、何も書かないことである。PDF/X-4 を名乗る PDF が規格に合うかを確かめていないことを、利用者が知らないまま使う。
   - もう一つは、PDF/X-4 の PDF にリンクの注釈があるとき notice を出すことである。照合のないことを本ごとに知らせられるが、照合が済めば消す notice のために、コードを一つ足すことになる。
2. **PDF/X-4 の PDF の扱い**：推奨は、今のとおりリンクの注釈を書くことである。照合で禁じる規定が見つかる見込みは分からず、前もって外すと、リンクを使いたい書き手の PDF から黙ってリンクが消える。
   - 退けた案は、照合が済むまで PDF/X-4 の PDF でだけリンクの注釈を外すことである。出力を黙って変えないという原則に反し、照合の後に戻す手間も残る。

## 決めたことの記録

- **「メンテナーが決めること」のすべて**（2026-11-08、メンテナー）：どれも推奨のとおりとした。
