# ADR 0356: 原因ごとに diagnostic のコードを点検する

ステータス: 採択（未実装）

## 文脈

diagnostics とビルドの結果のうち、書き手が必要とする「一つのコードに一つの原因の監査」の扱いを決める。

## 調査した事項

Golem [ADR 0321](0321-preflight-rule-error-causes.md) は、プリフライト設定を読めない六つの原因を区別した。
今回の監査は、同じ区別が必要な箇所を他の diagnostics から探す。

## 実装すること

diagnostics の一覧の各コードについて発生箇所、失敗した入力条件、書き手が直す箇所を照合する。
異なる条件を独立して再現でき、修正方法も異なる場合を分割候補とし、再現入力と旧コードの利用箇所を監査記録に残す。
コードの割当変更は候補ごとに修正提案を作る。

## 実装しないこと

監査だけで既存コードを改番しない。

## 不変条件

なし。
diagnostic の振る舞いを変更する提案を起こすまでの監査手順を定める。

## テスト設計

監査記録の各候補について二つの再現入力を実行し、同じコードが出ることと、別々の修正で各原因が消えることを確かめる。
未調査のコードがあれば一覧に残す。

## トレードオフ

コードの意味を細かくすると、旧コードを使う CI の移行が必要になる。
