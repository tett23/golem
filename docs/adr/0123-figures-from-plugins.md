# ADR 0123: プラグインが作った画像の図版

ステータス: 採択→`images/golem-plugin/` と重なる原稿の図版のエラー（G08102）は [ADR 0137](0137-plugin-image-folder-collision-g08102.md)、キャプションの中の図版とブロックの扱いは [ADR 0144](0144-figure-captions-hold-paragraphs-only.md)

## 文脈

プラグインのブロックコマンド（[docs/adr/0122](0122-block-commands-in-plugins.md)）は、最初の草稿では図版を返せなかった。
図版の検査が原稿のファイルを前提にしていたからである。
評価は `@figure` の引数からパス、形式、`alt`、`web`、`page`、`wrap`、`width`、`rotate` を検査し、PDF、HTML、EPUB はそのパスのファイルをプロジェクトのルートから読む。
プラグインはファイルを書けないので、画像を作っても置く場所がない。

それでも、図版を描くプラグインは書きたい。
TSV から表を組むプラグイン（[docs/adr/0129](0129-tsv-table-plugin.md)）の隣に、同じデータから棒グラフを描くプラグインを置けば、表と図の数字が食い違わない。
メンテナーは、プラグインが図版を返すことを認めた（2026-10-29）。
条件は、原稿の図版の検査を一つも迂回しないことである。

検査は、次の段に分かれている。

- **評価**（[`figure`](https://github.com/tett23/golem/blob/fa55dc76be6fef7189cb80883fd0bb0b0630911f/modules/golem-eval/src/Golem/Eval/File.hs#L1027)）：形式（G02074）、`web` の形式（G02073）、`alt`（G02028）、PDF の図版の `web`（G02029）、`page`（G02075）、`wrap`（G02030）、`rotate`（G02087）、回り込む図版の `width`（G02031）、ファイルの有無とパスの形（[`asset`](https://github.com/tett23/golem/blob/fa55dc76be6fef7189cb80883fd0bb0b0630911f/modules/golem-eval/src/Golem/Eval/File.hs#L1381)、G02060 など）。
- **PDF**（[`loadFigures`](https://github.com/tett23/golem/blob/fa55dc76be6fef7189cb80883fd0bb0b0630911f/modules/golem-driver/src/Golem/Driver/Pdf/Flow.hs#L2138-L2145)）：画像を読めない（G08010）、SVG の範囲の外（G08011）、PDF のページの内容が大きすぎる（G08015）、marker の循環と入れ子と区間の数（G08016、G08017、G08101）。
- **組版**：図版の大きさ、回り込み、段への収まり（G07039 など）。
- **HTML と EPUB**：SVG の動的なコンテンツ（G08014、[golem-driver の検査](https://github.com/tett23/golem/blob/fa55dc76be6fef7189cb80883fd0bb0b0630911f/modules/golem-driver/src/Golem/Driver.hs#L647)）。画像は `webSource` のパスのファイルを写す（[golem-html](https://github.com/tett23/golem/blob/fa55dc76be6fef7189cb80883fd0bb0b0630911f/modules/golem-html/src/Golem/Html.hs#L288)、[golem-epub](https://github.com/tett23/golem/blob/fa55dc76be6fef7189cb80883fd0bb0b0630911f/modules/golem-epub/src/Golem/Epub.hs#L142)）。
- **プリフライト**：実効の解像度、色空間、ICC プロファイル、塗り足し（G09006 など）。出力した PDF を読む。
- **文書の組み立て（S1）**：図版の番号、ラベル、キャプション、章の外の図版（G04004）。

評価の段の検査は、原稿の引数（AST）に対して書かれていた。
プラグインの図版に同じ検査をかけるには、まずこの検査を IR の `Figure` に対する関数にし、原稿の図版もプラグインの図版もその関数を通す必要がある。
メンテナーの判断で、これを二段に分けて試した。

### 試しに実装して分かったこと

**一段め**（ブランチ `figure-checks-on-ir`、origin/main から）は、評価の図版の検査を IR の値に対する関数にし、出力を一バイトも変えない変更である。

- 検査の各段（形式、`page`、`web`、`wrap` と `rotate` と `width`）を IR の値の関数にし、それを `@figure` と同じ順に走らせる `checkFigure` を作った。画像のファイルの有無は、呼ぶ側が渡す関数で調べる。
- `@figure` は、引数を読む処理を各段のあいだに挟んだまま、各段の関数を呼ぶ。たとえば形式の誤りがあると `wrap` の値を読まない。一つの関数にまとめて引数を先に読む形にすると、誤りが二つある図版の diagnostic が変わる。原稿の図版の diagnostic を変えないことを優先し、段の関数を共有する形にした。
- `checkFigure` が、同じ図版について `@figure` と同じコード、メッセージ、位置を出すことを、十二の図版でテストした。
- 変更の前と後で、見た目の回帰テストの十七の入力の PDF、`scripts/determinism.sh` の 112 行、二つのマニュアルの `build/` のファイルが、すべて同じバイト列だった。テストのスイートはすべて変えずに通った（OutputGoldenSpec を含む）。
- 一段めは仕様を変えないリファクタリングなので、ADR は要らないと判断した。

**二段め**（ブランチ `plugins-tsv-table`、一段めを `--no-ff` で取り込んだ後）は、プラグインの図版と見本のプラグイン `bar-chart` である。

- `bar-chart` の図版は、プラグインが作ったのと同じ SVG を置いた `@figure` と、PDF の `/ID` の二つめを除いて同じバイト列になった。縮めた知らせ（G07039）も同じに出た。
- `<text>` と `<script>` を含む SVG を返す版を手元で作ると、G08011 と G08014 が呼び出しの位置に出た。章の見出しのない原稿では G04004 が出た。どれも `@figure` と同じ処理を通った結果である。
- 未確認だったパスの問いは、次のとおりだった。`plugin:chart` は `://` を含まないので、プロジェクトの中の正しい相対パスとして読まれる（[`normalizeRelative`](https://github.com/tett23/golem/blob/fa55dc76be6fef7189cb80883fd0bb0b0630911f/modules/golem-project/src/Golem/Project/Paths.hs#L32-L34) は `://` で URL を見分ける）。したがって `plugin:` は、プラグインの出力の中でだけ意味を持たせ、ホストが別の名前に置き換える。置き換えた名前 `golem-plugin-image://...` を原稿の `@figure` に書くと、語のままでは構文の誤り（G01010）になり、文字列にすると URL（G02060）になる。プロジェクトのファイルとは取り違えない。
- 画像は、評価の結果（`erImages`）から本（`bookImages`）に運んだ。PDF、HTML、EPUB、G08014 の検査は本から読むので、`PdfInput` などの形は変えずに済んだ。
- golem-eval の build-depends に `bytestring` を、golem-epub に `containers` を足した。golem-* のパッケージのあいだの依存は変えていない。

## 実装すること

### 応答の形

ブロックコマンドの応答の出力を、ブロックの列と画像の列の組にする。

```cddl
response = [output: inlines / document / block-output, diagnostics: [* plugin-diagnostic]]
block-output = [blocks: [* block], images: [* plugin-image]]
plugin-image = [name: tstr, format: "svg" / "png" / "jpeg", bytes: bstr]
```

- プラグインが作る図版のブロック（タグ 7）は、出力の最上位に置き、`src` に `plugin:<名前>` を書いて同じ応答の画像を指す。
- 画像の名前は、英小文字で始まり、英小文字、数字、`-` だけからなり、応答の中で重ならない。
- 次のものは不正な出力（G06009）とする。指す先のない名前、どの図版からも指されない画像、`plugin:` でない `src`、`web` のある図版、出力の最上位でない図版（箇条書きの中など）、svg、png、jpeg でない形式、合計で 64 MiB（[docs/adr/0105](0105-plugin-data.md) のデータの上限と同じ）を超える画像。
- 本体から受け取った図版は、受け取ったまま返せる。
- 図版の IR の形は変えない。画像を IR の図版に埋め込むと、フィルタとほかのすべてのプラグインが受け取る文書の形が変わるからである。IR は v1 で組み直す予定なので（メンテナー、2026-10-29）、そのときに図版と画像の持ち方を改めて決める。

### 名前と置き場所

- ホストは、画像のバイト列の SHA-256 で名前を付ける。図版の `src` は `golem-plugin-image://<SHA-256 の 16 進>.<拡張子>` になる（拡張子は `.svg`、`.png`、`.jpg`）。
- HTML と EPUB では、`images/golem-plugin/<SHA-256 の 16 進>.<拡張子>` に置く。
- 同じバイト列の画像は、いくつの図版から使っても一つになる。
- 名前がバイト列だけから決まるので、同じ入力からは同じ出力のパスになる。プラグインが付けた名前は出力に現れない。

### 検査

評価は、プラグインの図版を `checkFigure` に通す。
画像の有無は、応答の画像にあるかで調べる。
原因が同じものは、原稿の図版と同じコードを、呼び出しの位置に出す。
検査を通らない図版は、`@figure` と同じくブロックにならない。

| 検査 | 原稿の図版 | プラグインの図版 |
|---|---|---|
| 形式 | 拡張子で G02074 | 応答の形式で決まり、PDF を返せない |
| `alt` | なければ G02028 | IR では必ずある |
| PDF の `web` | G02029 | PDF を返せないので起きない |
| `web` の形式 | G02073 | `web` を持てない（G06009） |
| `page` | G02075 | `checkFigure` で G02075 |
| `wrap` と `rotate`、`width` | G02087、G02031 | `checkFigure` で同じコード。値の読み違い（G02030 など）は IR では起きない |
| キャプションの段落スタイル | G02013、スタイルを除く | G02013、スタイルを除く |
| ファイルの有無とパス | G02060 など | 画像は応答にある。名前の誤りは G06009 |
| 画像を読めない、SVG の範囲 | G08010、G08011、G08015 から G08017、G08101 | 同じ読み込みで同じコード |
| SVG の動的なコンテンツ | G08014 | 同じ検査で同じコード |
| 組版、プリフライト、番号、ラベル | IR と出力の PDF から | 同じ |

### 見本

`bar-chart`（`@bar-chart <データの名前> column=<列> alt="..."`）は、TSV の一つの列の 0 以上の整数を、SVG の棒グラフにする。
字下げした行がキャプションになる。
文字を輪郭にしないと G08011 になるので、見本は文字を描かない。
座標は整数の演算で決め、同じデータからは同じバイト列の SVG になる。
TSV の読み方は `tsv-table` と同じ規則を小さく写した（`tsv-table` のクレートに依存すると、二つのプラグインの公開する関数の名前がぶつかる）。

補助のクレートには、画像の型 `Image`、応答 `Response::blocks_with_images`、図版のブロックを作る `ir::figure` を足した。

## 実装しないこと

- 見出しを返すこと。
- PDF の画像を返すこと。PDF の図版は HTML と EPUB のための `web` の画像を要するので、その組の検査が別に要る。
- 出力の最上位でない図版。原稿の図版の扱い（箇条書きの中の図版）と合わせて決める。
- フィルタとインラインのコマンドが画像を返すこと。
- プラグインがプロジェクトの画像のファイルを図版にすること。
- 原稿の図版の出力のパスが `images/golem-plugin/` と重なるときのエラー。試しの実装には入れていない。採択の前に、コード G08102（出力の段階として割り当てた）と一緒に足す。

## テスト設計

下のテストのうち、見本のプラグイン tsv-table（[docs/adr/0129](0129-tsv-table-plugin.md)）を使うものは、この ADR の実装では書かない。
この ADR の実装では、同じことを wat のテスト用のプラグイン（`modules/golem-plugin/test/` と golem-driver のテストの wat）で確かめるテストを先に書く。
見本のプラグインを使うテストは、結合のテストとして、その見本のプラグインの ADR を実装するときに足す。
見本のプラグインの ADR が、この ADR より後に実装されるからである。

テストを先に書き、今の実装でコンパイルできないか失敗することを確かめてから実装した。

golem-eval のテストでは、次のことを確かめる。

- `checkFigure` が、十二の図版について `@figure` と同じコード、メッセージ、位置を出す（一段め）。
- プラグインの図版が、ラベルを受け取り、画像が評価の結果に入る。`width` のない回り込みが G02031 になって図版にならない。PDF でない図版の `page` が G02075 になる。キャプションの段落スタイルが G02013 になって除かれる。

golem-plugin のテストでは、次のことを確かめる。

- 図版の `src` が画像の SHA-256 の名前に置き換わる。同じバイト列の二つの画像が一つになる。
- 指す先のない名前、`plugin:` でない `src`、使われない画像、PDF の形式、形の誤った名前、重なる名前、`web`、箇条書きの中の図版が、それぞれのメッセージの G06009 になる。画像の列のない出力が G06009 になる。

golem-driver のテストでは、`plugins/wasm/bar-chart.wasm` を使い、次のことを確かめる。

- 棒グラフが PDF に置かれ、HTML と EPUB に `images/golem-plugin/<SHA-256>.svg` として写り、図版の番号を持つ。
- 同じ入力から二度組んだ PDF が同じバイト列になる。
- `golem-plugin-image://...` を書いた `@figure` が G02060 になる。
- プラグインの誤りでは図版を作らない。

手で確かめたこと：`tsv-table` と `bar-chart` を宣言したプロジェクトを PDF、HTML、EPUB に組んだ。
同じ SVG の `@figure` と PDF を比べ、`<text>` と `<script>` を含む SVG を返す版で G08011 と G08014 を確かめた。

## トレードオフ

`@figure` は引数を読む処理を検査の段のあいだに挟むので、「同じ関数を通る」は「同じ段の関数を同じ順に通る」という意味になった。
段の関数を変えれば両方に適用されるが、段を足すときは `@figure` と `checkFigure` の両方に足す必要がある。
二つの順が揃っていることは、一段めのテストが確かめる。

画像を応答に入れるので、大きな画像を作るプラグインは呼び出しのたびにその画像を符号化して返す。
グラフのような SVG は小さいので、困らない見込みである。

出力の名前を内容のハッシュにしたので、HTML と EPUB の画像のファイル名から、どのプラグインのどの図かは読み取れない。
読み手に見えるのは `alt` とキャプションなので、受け入れる。

## 決めたことの記録

- **図版を返すこと**（メンテナー、2026-10-29）：プラグインが図版を返すことを認める。原稿の図版の検査を迂回しないことを条件とする。見出しは引き続き返せない。
- **応答の形**（メンテナー、2026-10-29）：`[blocks, images]` の別の列とする。IR は v1 で組み直すので、そのときに改めて決める。
- **二段に分けること**（メンテナー、2026-10-29）：一段めに、評価の図版の検査を IR の `Figure` の関数にする変更を、出力を変えないことを示して入れる。二段めに、プラグインの図版と見本の棒グラフのプラグインを入れる。
- **テストのプラグイン**：メンテナーが、土台の ADR は wat のテスト用のプラグインで試し、見本のプラグインを使う結合のテストは見本のプラグインの実装のときに足す運用にすると決めた（2026-11-04）。
