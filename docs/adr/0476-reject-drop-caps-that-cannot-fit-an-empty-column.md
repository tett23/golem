# ADR 0476: 空の段にも収まらないドロップキャップは PDF の生成を止める

Status: accepted

## 文脈

[root ADR 0465](0465-drop-caps.md) は、`drop-lines = n` の段落の先頭 n 行を同じ段に置くと定める。
しかし、その部分が空の段にも収まらない場合の扱いは定めていない。
指示者は 2026-11-27 に、縮めたり分けたりせず、エラーを出して PDF の生成を止める推奨案で試すよう指示した。

## 調査した事項

実装 PR #1203 のコミット `fb16fb8a27ebfb08736457476e78243157e73b31` のコードを読んで、次のことを確かめた。

- `Golem.Typeset.Flow.unitDropLines` が適用対象の行数を求め、`padDropLines` が足りない行を足す。
  先頭の保持行数には、ドロップキャップの行数を反映している。
- 行グリッドを使うページ分割の `placeLines` と、自由な行送りを使う `trialParagraphPartLimit` には、保持指定が空段にも収まらない場合に、一部を置いて進める経路がある。
- `@page-lines` の追加行は、その段だけに属する。
  次の段では段組の終端の既存の規則に従って容量を決め、次のページでは調整を 0 に戻す。
  正の調整によって、現在の段の通常より広い領域へ置ける場合もある。
- 自由な行送りでは、実際の行送り、必要な脚注と区切り、枠の余白を配置判定に含める。
  字の見える面の高さだけでは、配置できるかを決められない。
- PDF 出力の失敗時に、コード G08113 では既存の PDF の出力先を消すが、新しい失敗コードの扱いは追加が必要である。
- G07144 は、root [ADR 0466](0466-fit-characters.md) の文字数合わせの警告で使っている。
  G07145 は、調べた版のコードと diagnostic の一覧では使っていない。

## 実装すること

### 分けない範囲と配置の判定

ドロップキャップを実際に組む段落の、先頭から `drop-lines` 行目までは、ページと段を分けない。
本文の行が足りずに補った空行も、この範囲に含める。
この範囲を、以下では「保持する先頭部分」と呼ぶ。

保持する先頭部分が現在の段に収まらなければ、次の段へ送る。
現在の段が空でも、脚注の残りや `@page-lines` の縮小によって狭い場合は、その狭さだけでエラーにしない。
次の段か次のページで配置できるかを、通常のページ分割の順に調べる。
送り先へ移ることによって行の長さが変わる場合は、組み直した行で調べる。

現在の段が `@page-lines` によって広がり、保持する先頭部分が収まる場合は、そこに置く。
通常の空段の行数より `drop-lines` が大きいという理由だけでは、エラーにしない。

配置の可否には、同じ段落を実際に配置する判定を使う。
段落自身の行送り、補った空行、配置に必要な脚注と区切り、枠の余白を含める。
ドロップキャップの字の面の高さだけで判断しない。
図版の回り込みによって組み直す経路にも同じ規則を適用する。

### 配置できない場合

現在の段と、同じページの残りの段を配置の順に調べても収まらず、次のページの通常の空段にも収まらない保持する先頭部分は、エラーにする。
次の段の容量は、`@page-lines` と段組の終端についての既存の規則で求める。
追加行を次の段へ引き継ぐ変更はしない。
通常の空段とは、その段落を置く版面の段から、既に置いた本文と前の段から持ち越した注を除き、`@page-lines` の一時的な調整を 0 にした状態である。
段落自身が必要とする注と余白は除かない。
同じ条件の空段へ繰り返し送り続けない。

エラーのコードは G07145 とし、メッセージは `ドロップキャップの先頭 <n> 行を空の段にも配置できません` とする。
可能な場合は、その段落の原稿の位置を添える。
一つの段落の同じ失敗を、ページ分割の試行回数だけ重ねて報告しない。
先頭部分の保持とは関係なく、脚注自体を置けない場合などの既存のエラーは、その既存のコードを保つ。

G07145 が出た場合は、対象の PDF の生成を失敗として終了し、CLI は非ゼロで終わる。
保持する先頭部分を分割したり、`drop-lines` の値や字の大きさを縮めたりして、生成を続けない。
生成途中の PDF と、同じ出力先に以前からある PDF を残さない。
印刷用と画面用の PDF、およびそれらに属するページ情報を、既存の出力先の分離規則に従って片付ける。
ほかの媒体の既存の成果物は、この PDF の失敗だけでは消さない。

### 内部のデータと処理

ドロップキャップの保持する先頭部分を、一般の段落の保持指定と区別して渡す。
たまたま同じ行数を持つ一般の段落を、このエラーの対象にしない。
行グリッドを使う経路と自由な行送りの経路のどちらも、保持する先頭部分を強制的に分ける処理へ進む前に、移動かエラーを選ぶ。

保持の情報は、ページ分割に渡す行の識別子と行数に対応づける。
回り込みで行を組み直して識別子を変える場合は、この対応も更新する。
公開の意味論 IR の段落の意味は変えない。
一般の保持指定が空段に収まらない場合の既存の扱いは変えない。

### 対象と文書

root [ADR 0465](0465-drop-caps.md) がドロップキャップを当てない段落と、先頭がテキストでないためにドロップキャップを組まない段落には、G07145 を出さない。
HTML と EPUB の CSS によるドロップキャップは、この PDF の配置エラーの対象にしない。

仕様書、README、利用者マニュアルに、空段にも収まらない場合のエラーと、行数か版面を直す方法を書く。
`docs/diagnostics.md` に G07145 を足す。
root [ADR 0465](0465-drop-caps.md) のステータスには、この ADR による「空段にも収まらない場合」の補足を記録する。
root [ADR 0465](0465-drop-caps.md) A1 の、メンテナーが三つの見本を目で確かめる条件は、別に残す。

## 実装しないこと

自動で字を縮めること、行数を減らすこと、ドロップキャップだけを外すことはしない。
この変更のために、ほかの保持指定や HTML と EPUB の配置規則は変えない。

## 不変条件

- I1: 成功した PDF では、ドロップキャップの先頭から指定行数までの行は、補った空行も含めて同じ段にある。
- I2: 現在の段と同じページの残りの段にも通常の空段にも保持する先頭部分を置けない場合は、有限回の配置試行で G07145 を出し、PDF の生成を失敗として終える。
- I3: 現在か次の段に配置できる場合は、一時的な容量の不足だけを理由に G07145 を出さない。
- I4: G07145 の後には、対象の PDF とそれに属するページ情報が出力先に残らない。
- I5: ドロップキャップのない段落と適用対象外の段落の配置結果と diagnostic は、この変更によって変わらない。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 通常の空段の容量と保持する先頭部分が同じ | 分割せず成功 | I1, I3 |
| 通常の空段から一行あふれ、現在の段にも収まらない | G07145、生成失敗 | I2, I4 |
| 現在の段に二行だけ残り、保持する先頭部分は三行、通常の段には収まる | 次へ送り成功 | I1, I3 |
| 通常は三行以上入り、`@page-lines` で二行に縮めた段と三行のドロップキャップ | 通常の次段か次ページへ送り成功 | I1, I3 |
| 通常は二行、合法な `@page-lines +1` の段と三行のドロップキャップ | 広げた段で成功 | I1, I3 |
| 通常は二行、二段組み、`@page-lines +1`、現在段に一行配置済み、指定三行 | 追加行を次段へ引き継がず G07145 | I2 |
| 本文一行だけ、指定三行 | 空行も含む三行を同じ段へ配置 | I1 |
| 字の面は収まるが段落の行送りでは収まらない | 実際の配置判定で G07145 | I2 |
| 前の段の脚注の残りだけが配置を妨げる | 持ち越しを処理した後に配置できれば成功 | I3 |
| 脚注単体は配置できるが、先頭部分と必要な注を一緒に保持すると通常の空段にも収まらない | 配置を偽って成功にせず G07145 | I2 |
| 先頭部分の保持と関係なく、脚注自体を配置できない | 行グリッドでは G07125、自由な行送りでは G07130 を保つ | I5 |
| 複数段、縦組み、横組み、回り込みによる組み直し | 同じ配置判定と失敗の規則 | I1, I2, I3 |
| 古い PDF とページ情報のある出力先で失敗 | 対象の古い成果物も残らない | I4 |
| ドロップキャップなし、空段落、適用対象外、テキストで始まらない段落 | G07145 なし、従来どおり | I5 |

## 受けいれ条件

- A1: 通常の CLI で容量ちょうどと一行超過の原稿を組み、成功と G07145 による非ゼロ終了をそれぞれ確認する。
- A2: 印刷用と画面用の PDF の既存の出力先に成果物を置いた状態で失敗させ、対象の PDF とページ情報が残らないことを確認する。
- A3: HTML と EPUB だけを指定した場合は、PDF の容量が不足する条件でも、このエラーを理由に失敗しない。

## テスト設計

I1 から I5 と A1 から A3 の名前を付けた回帰テストを、実装前に足して失敗を確かめる。
行グリッドと自由な行送り、縦組みと横組み、段数、段落自身の行送り、補う空行、脚注、枠の余白、回り込みを組み合わせる。
一時的な段の縮小からの回復と、段の拡張による成功を、エラーになる例と分けて確かめる。
失敗する配置のテストには時間の上限を置き、ページを送り続ける回帰も検出する。
CLI の試験は既存の PDF とページ情報を先に作り、失敗後のファイルと終了コードを調べる。

## トレードオフ

配置できない段落のある PDF は生成できなくなるが、指定行数の途中で字と本文が別の段になる出力を防げる。
一般の保持指定とは情報を分けるため、ページ分割の内部の受け渡しが増える。
実際の配置判定を共用して、別の高さの近似による判定の食い違いを避ける。
