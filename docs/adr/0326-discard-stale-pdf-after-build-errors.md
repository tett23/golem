# ADR 0326: PDF を書けないとき、dev は前の PDF を残し、prod は消す

ステータス: 採択

## 文脈

正常に PDF を組んだ後、図版をヘッダーだけの PNG に差し替えた。
`golem build --target pdf` は G08010 と終了コード 1 を返したが、`build/pdf` には前の PDF と前の `pages.json` が残った。
一方、prod の G08100 は同じ出力先を片付ける。
失敗した理由を知らずに出力フォルダーを開くと、前の原稿を入稿に使うおそれがある。

## 実装すること

ディスクに書く prod ビルドで、対象に PDF を含み、エラーで今回の PDF を書けなかったときは、Golem の出力フォルダー `build/pdf` を片付ける。
`pages.json` はその PDF に対応するので一緒に片付ける。
dev ビルドでは、作業中に最後の組版結果と比較できるよう、失敗しても前の PDF とページ情報をそのまま残す。
複数のターゲットのうち PDF だけが成功したときは、今回の PDF を残す。

ターゲットを引数で明示した場合はその値を使う。
CLI の `build` がターゲットを省略した場合は、マニフェストの出力指定にかかわらず全ターゲットを要求するため、PDF も対象に含む。
内部 API からマニフェストに選択を委ねた場合は、読み込みで得たターゲットを最後の処理に渡す。
その場合にマニフェスト自体が読めなければ、dev は古い出力を残し、prod は安全な既存の PDF 出力を片付ける。

フォルダーを片付ける前に、出力処理と同じ検査で `build` と対象のフォルダーを確かめる。
片付けるのは PDF のフォルダーなので、検査対象は親の `build` と `build/pdf` に限る。
たとえば兄弟の `build/html` がリンクでも、安全な PDF の出力は片付ける。
途中のパスがリンクや通常のファイルならその先をたどらない。
安全に片付けられなかったときは、古い出力を片付けたと報告しない。

## 実装しないこと

`check`、`preflight`、メモリ上のビルド、PDF を選ばないビルドは、前の PDF を片付けない。
プロジェクトの外、原稿や図版の PDF、ほかのターゲットの出力も削除対象に含めない。

## 不変条件

1. B1：安全な出力先で対象に PDF を含む prod ビルドがエラーとなり PDF を書かなければ、前の PDF と対応するページ情報は残らない。
2. B2：出力しないコマンドと PDF を選ばないビルドでは前の PDF のバイト列が変わらない。
3. B3：出力先の親または子がリンクなら、リンク先のファイルの内容が変わらない。

4. B4：dev ビルドが失敗したときは、前の PDF とページ情報が存在すれば両方の内容が変わらない。

| 前の出力と今回の結果 | 処理 |
| --- | --- |
| 前の PDF なし、今回エラー | 何も作らない |
| 前の PDF あり、dev の G08010 | 前の PDF とページ情報を残す |
| 前の PDF あり、prod の G08010 | `build/pdf` を片付ける |
| PDF は成功、別のターゲットが失敗 | 今回の PDF を残す |
| HTML だけを選び、原稿にエラー | 前の PDF を残す |
| prod でマニフェスト不正、ターゲット省略 | 安全な `build/pdf` を片付ける |
| prod で `build/html` だけが外部へのリンク | 安全な PDF を片付け、リンク先は保存する |
| `build/pdf` が外部へのリンク | リンク先は保存する |

## テスト設計

`experiments/diagnostics/baseline.mjs` で正常に組んだ PDF を用意し、同じ場所で壊れた PNG をビルドする。
B1 は PDF とページ情報の有無を調べる。
B2 は PDF を指定した場合、ターゲットを省略した場合、HTML のみを選んだ場合、`check` を比較する。
B4 は同じ PNG のエラーを dev と prod に渡し、終了値と前の PDF のバイト列、ページ情報を比較する。
再現入力は `experiments/diagnostics-review/probe.mjs` にある。
内部 API に出力選択を委ねた場合の試作は、既に読んだマニフェストを読み直す。
本実装で選択結果を共有する場合とは異なる。
B3 は一時フォルダー内に別の出力先を作り、外部を指すリンクの先のバイト列を確かめる。
複数ターゲット時の部分成功、出力の途中の I/O エラー、別プロセスが出力先を同時に差し替える場合は試作で検証していない。
本実装では、生成物を一時ディレクトリに書く間に同じプロジェクトへの別の公開と片付けが重ならない仕組みも検証する。

## トレードオフ

マニフェストが壊れてターゲットを決められないとき、最後に成功した PDF を消すか残すかは利用者への影響が異なる。
dev は作業中の比較を優先する。
prod は入稿時の取り違えを避けるため、再生成できる出力フォルダーを片付ける。
必要な過去の版は、利用者がビルドの出力先とは別の場所に保存する。
