# ADR 0425: 取り込んだ PDF 図版の色の分類と、判定できない構成を決める

Status: proposed

## 文脈

[root ADR 0403](0403-include-grayscale-tones-in-single-color-figures.md) は、図版の描画色を指定したとき、白黒の濃淡の図版と一色の図版を指定色で描き、多色の図版は元の色を保つと決めた。
この規則は、取り込んだ PDF の図版にも当てはまる。
JPEG は [root ADR 0406](0406-limit-jpeg-figure-color-decoding.md) で、SVG は [root ADR 0407](0407-reject-svg-figures-that-cannot-be-recolored.md) で、判定できないときに G08113 のエラーにすると補った。
取り込んだ PDF には、この補足がない。

PDF には、ほかの形式にない色の書き方がある。
CIE 由来の色空間（Lab、CalGray、CalRGB）、関数で色を決めるシェーディング、パターン、Normal 以外の合成の方式、オーバープリント、画像と大きさの違うマスクである。
0403 は、これらが濃淡か、一色か、多色かを決めていない。
今の実装は、特色を除くこれらの多くを G08113 にしている。
それが 0403 の実装の漏れなのか、決めた振る舞いなのかは、ADR からはわからない。

この ADR は、0403 の「取り込んだ PDF の図版」の部分を補い、それぞれの分類と置き換え方と、判定できないものの扱いを決める。
[root ADR 0408](0408-preserve-rgb-and-distinguish-explicit-figure-recoloring.md) は、自身では色置換の範囲を広げないと決めた。
この ADR は、その範囲を広げる。

## 実装すること

### 図版の分類と置き換え

図版の分類は、0403 と今の実装のとおり、図版の全体で一つに決める。
描いたすべての色（シェーディング、パターン、Type 3 の字形の色を含む）を集める。
集めたすべての色が濃淡なら濃淡の図版とし、白黒の濃淡の規則を優先する。
そうでなく、すべての色が等しい一つの色なら一色の図版とする。
それ以外は多色の図版とし、元の色を保つ。

濃淡の図版では、すべての色を `s_k(1 - g)` に写す（s_k はスウォッチの成分、k は C、M、Y、K）。
一色の図版では、すべての色を指定色にする。
置き換えた色は DeviceCMYK で書く。
以下の節は、それぞれの構成について、色の集め方と、図版を置き換えるときの書き換え方を決める。

### 判定できない構成

図版の描画色を指定し、取り込んだ PDF の図版の色を判定できないか、指定色に置き換えられない場合は、G08113 のエラーにする。
その図版を含む対象媒体の生成を中止し、その媒体の古い出力を成功した成果物として残さない。
単色か多色かを判定できない場合も、元の色のまま生成を成功させない。
これは JPEG（0406）と SVG（0407）と同じ扱いである。

次の構成は、今も G08113 にしていて、この ADR の後も G08113 にする。
0403 の実装の漏れではなく、決めた振る舞いである。

- ExtGState の BM が Normal か Compatible でないもの。
  配列は、空でなく、要素がすべて Normal か Compatible のときだけ扱う。
  理由は「合成の方式」の節に書く。
- ExtGState の TR と TR2 が Identity か Default でないもの。
  描いた後の濃淡が関数で変わり、置き換えた色が濃淡の規則と一致しないためである。

次の構成は、今は G08113 か受けいれかのどちらかだが、この ADR の後は G08113 にする。

- PostScript の計算機の関数（FunctionType 4）で色を決めるシェーディング。
  色の集合を知るには、定義域の全体でプログラムを評価する必要があるためである。
- 「シェーディング」の節の、置き換えられないシェーディングを含み、ほかの色がすべて濃淡の図版。
- 線か塗りを描くときの描画の状態で、OPM が 1 で、その描き方のオーバープリントが true のもの。
  `gs` の OP は、同じ辞書に op が無ければ線と塗りの両方のオーバープリントを、あれば線のオーバープリントだけを設定する。
  op は塗りのオーバープリントを設定する。
  OPM と OP は別々の `gs` で設定でき、描画の状態は前の `gs` から引き継ぐので、一つの ExtGState ではなく描画の状態で判定する。
  置き換えた DeviceCMYK の色では、成分が 0 の版を抜かないので、白の物体が下の物体を隠さなくなるためである。
  OPM が 0 なら、プロセスカラーの四つの成分をすべて塗るので、オーバープリントは結果を変えない。
- DeviceGray でないソフトマスク。
  PDF の決まりに合わないためである。
- Matte を持ち、画像と大きさの違うソフトマスク。
  画像の画素ごとに Matte を取り除く不透明度が一つに決まらないためである。
- Matte を持ち、画像かマスクの Interpolate が true のソフトマスク。
  すべての画素を可視とする決まりでは、不透明度が 0 の画素で Matte を取り除く式が 0 で割ることになるためである。
- ICCBased で、プロファイルのデータの色空間が Gray、RGB、CMYK、Lab のどれでもないもの。
  データの色空間と N が合わないもの（Gray で N が 1 でないなど）も含める。

この検査は、`gs` で選んだ ExtGState のほかに、シェーディングパターンが持つ ExtGState にも当てはめる。

### 特色

特色（Separation と DeviceN）を使う PDF は、今までどおり、PDF を組むときに G08010 として拒む。
Golem は、プロセスカラーだけを扱うためである。
特色を扱うと決めたときに、その ADR で特色の分類を決める。

### CIE 由来の色空間

Lab、CalGray、CalRGB の色は、色の変換をせずに、成分の値のまま分類する。
Golem は、ほかの色空間でも、元の色に近い CMYK を計算せず、値のまま判定しているためである（[root ADR 0408](0408-preserve-rgb-and-distinguish-explicit-figure-recoloring.md)）。

塗りと線の色と、画像のサンプルを Decode で写した値は、分類の前に切り詰める。
CalGray と CalRGB の成分は 0 から 1 に、Lab の L* は 0 から 100 に、a* と b* は色空間の Range に切り詰める。
切り詰めた値は有理数のまま比べ、浮動小数の丸めに判定を左右させない。
シェーディングの値は、この切り詰めをせず、「シェーディング」の節の規則で扱う。

- CalGray: 成分が一つなので、つねに白黒の濃淡とする。
  灰色の値 g は、その成分の値とする。
- CalRGB: 三つの成分が等しいときだけ白黒の濃淡とし、g はその値とする。
  等しくなければ色とする。
- Lab: a* と b* がともに 0 のときだけ白黒の濃淡とし、g は L* を 100 で割った値とする。
  そうでなければ色とする。

Lab、CalGray、CalRGB の色どうしは、色空間の種類と、その辞書の値と、成分の値がすべて等しいときだけ同じ色とする。
ほかの色空間の色が同じかどうかの扱いは変えない。

ICCBased は、プロファイルのヘッダーのデータの色空間で分ける。
Gray、RGB、CMYK は、Range で 0 から 1 に写してから、今の DeviceGray、DeviceRGB、DeviceCMYK と同じ規則で判定する。
Lab は、成分の値をそのまま L*、a*、b* とし、Range で切り詰めてから、上の Lab の規則で判定する。
ICCBased の Lab の色と、Lab の色空間の色は、別の色空間の色として扱う。

### シェーディング

シェーディングは、定義の中の有限の値から色を集める。
描かれるかに関わらず、定義の中のすべての値を数える。

- FunctionType 0（サンプル）: 表のすべてのサンプルを Decode で写した値。
  Decode が無ければ Range を Decode とする。
- FunctionType 2（指数補間）: C0 と C1。
  無ければ、既定の 0 と 1 とする。
- FunctionType 3（つなぎ合わせ）: 下の関数の値を合わせたもの。
- 関数を持たないメッシュのシェーディング: ShadingType 4 と 5 はすべての頂点の色、ShadingType 6 と 7 はすべてのパッチの四隅の色。
- 関数を持つメッシュのシェーディング: その関数の値。
- Background があれば、その色。

一つの関数が多出力のときも、1 出力の関数の配列のときも、出力ごとに同じ位置の値を並べたものを一つの色とする。
1 出力の関数の配列で、成分の関数の定義（関数の種類、Domain、Range、N、Size、Order、Encode、Decode、Bounds、FunctionType 3 の下の関数の定義）がそろわないものは、同じ位置が決まらないので、下の「置き換えられないシェーディング」とする。

シェーディングは、値から色への写し方だけを変えて置き換える。
そのため、置き換えられるのは、次の二つをともに満たすシェーディングに限る。

- すべての定義の値と、関数の Range が、色空間の範囲の中にある。
  ICCBased では、色空間の Range の中にあることとする。
  Range を持たない FunctionType 2 は、Domain が `[0, 1]` の中にあり、N が 0 より大きいことも求める。
  FunctionType 2 は入力を正規化せずに `C0 + x^N (C1 - C0)` を計算するので、そうでなければ C0 と C1 の外へ外挿するためである。
  こうすれば、描くときの色空間の範囲への切り詰めが起きない。
- すべての出力の値が、一つの値 v の一次式で g を決める。
  これは次の場合である。
  - DeviceGray、CalGray、データの色空間が Gray の ICCBased: g は v を色空間の範囲で正規化した値である。
  - DeviceRGB、CalRGB、データの色空間が RGB の ICCBased: 三つの出力の定義がすべてそろい、どの位置でも三つの値が等しい場合だけである。
    ICCBased では、Range で 0 から 1 に写した後の値で比べる。
    v は R の出力の値とする。
  - Lab とデータの色空間が Lab の ICCBased: a* と b* の出力の値がすべて 0 である場合だけである。
    v は L* の出力の値とし、g は `v / 100` とする。
  - DeviceCMYK とデータの色空間が CMYK の ICCBased: C、M、Y の出力の値がすべて 0 である場合だけである。
    v は K の出力の値とし、g は 1 - v とする。

集めた値がすべて濃淡で、この二つを満たさないシェーディングを、置き換えられないシェーディングと呼ぶ。
集めた値に濃淡でない色を含むシェーディングは、その色を図版の分類に加えるだけで、置き換えられないシェーディングには当たらない。
一色の図版のシェーディングは、後に書くとおり、すべての色を指定色にして置き換える。
図版のほかの色がすべて濃淡のとき、置き換えられないシェーディングを含む図版は G08113 にする。
途中の色が濃淡かどうかも、置き換えた結果が濃淡の規則と一致するかも、定義の値からは決められないためである。
ほかに濃淡でない色があれば、その図版は多色の図版なので、元の色を保ち、G08113 にしない。

置き換えられないシェーディングの例を挙げる。
出力ごとの N が違う DeviceRGB のシェーディングは、両端が灰色でも途中が色になる。
DeviceRGB の R と B を N = 1、G を N = 2 とし、どれも C0 = 0、C1 = 1 とすると、t = 0.5 の色は (0.5, 0.25, 0.5) になる。
C、M、Y が等しく 0 でない DeviceCMYK の灰色は、g が `(1 - c)(1 - k)` で値の一次式にならない。
Range が `[-1, 1]` で `C0 = -0.5` の DeviceGray の関数のように、範囲の外の灰色の値を持つものは、描くときの切り詰めで、写した色が濃淡の規則と一致しなくなる。

置き換えでは、g が v の一次式 `g = αv + β` で書けることを使う。
写した色の出力 k は `s_k(1 - αv - β)` で、v の一次式になる。

- FunctionType 2: C0 と C1 を、それぞれの v を写した 4 成分に変える。
  N、Domain は変えない。
- FunctionType 0: v の出力の各サンプルの値を、そのまま 4 つの出力に並べた表にする。
  出力 k の Decode は、元の Decode が `[d0, d1]` なら `[s_k(1 - αd0 - β), s_k(1 - αd1 - β)]` とする。
  Size、BitsPerSample、Order、Encode は変えない。
- FunctionType 3: 下の関数をそれぞれ置き換える。
  Bounds と Encode は変えない。
- 関数の Range: 元の v の Range が `[a, b]` なら、出力 k の Range を、`[s_k(1 - αa - β), s_k(1 - αb - β)]` の両端を小さい順に並べたものとする。
  Range が無ければ、元の色空間の範囲で写す。
- 多出力の関数は、v の出力の定義を写した 4 出力の関数に置き換える。
- 1 出力の関数の配列は、v の出力の関数の定義を写した 4 つの関数の配列に置き換える。
- メッシュの頂点と四隅の色: v の値をそのまま 4 成分に並べ、Decode を FunctionType 0 と同じく写す。
- Background: 写した 4 成分にする。

写し方は v の一次式で、s_k が 0 以上なので v について単調である。
そのため、補間した後の色も、関数の Range で切り詰めた後の色も、元の色を写した色と一致する。
定義の値と関数の Range は色空間の範囲の中にあるので、色空間の範囲への切り詰めは、置き換えの前にも後にも起きない。
サンプルと頂点の値そのものは変えないので、置き換えで丸めの誤差は生じない。

一色の図版のときは、シェーディングを、すべての色が指定色の DeviceCMYK のシェーディングに置き換える。
関数は、出力が指定色の FunctionType 2（C0 と C1 が等しい）とする。
関数を持たないメッシュは、すべての頂点と四隅の色を指定色にする。
Background も指定色にする。

### パターン

パターンの色空間は、次のように扱う。

- 色付きのタイリングパターン（PaintType 1）: パターンの内容を、図版の内容と同じ規則で集め、置き換える。
- 色なしのタイリングパターン（PaintType 2）: `scn` で渡した色を集める。
  置き換えるときは、パターンの色空間の下の色空間を DeviceCMYK に変え、`scn` の成分を写した 4 成分にする。
- シェーディングパターン: 上のシェーディングの規則で集め、置き換える。

### 合成の方式

Normal でも Compatible でもない合成の方式を使う PDF は、G08113 にする。

重ねる前の物体ごとに判定して置き換えると、重なった部分の色が濃淡の規則と一致しない。
たとえば Multiply では、濃さ x と y の灰色を重ねた濃さは、加法の色で `x + y - xy` になる。
これを指定色の成分 s に写すと、`s(x + y - xy)` になるべきである。
一方、物体ごとに `sx` と `sy` に置き換えてから CMYK で重ねると、`sx + sy - s²xy` になる。
s が 0 でも 1 でもなければ、xy が 0 でない重なりで、二つは一致しない。
重ねた後の結果で判定するには、図版を画素に変えて合成する必要があり、図版の解像度と内容を変えてしまう。
そのため、どちらの方法も取らない。

BM の配列は、PDF の読み手が知っている最初の方式を使うと決められている。
Golem の読み手が知らない方式の後ろに Normal を置いた配列もありうる。
読み手によって合成が変わる図版を作らないため、空でなく、要素がすべて Normal か Compatible の配列だけを扱い、ほかの配列は先頭の要素に関わらず G08113 にする。

### Type 3 フォント

字形の中で自分の色を指定する Type 3 フォントの字形（d0 の字形）は、字形の内容（CharProcs）を図版の内容と同じ規則で集め、置き換える。
字形の内容は、図版の資源の一部として取り込むので、置き換えても図版の外に影響しない。
d1 の字形は、今までどおり、描くときの色で判定する。

### マスク

画像のマスクは、画像と同じ単位の正方形に引き伸ばして重ねる。
画像の幅を w、高さを h、マスクの幅を mw、高さを mh とする。
画像の画素 (i, j)（i は左からの列、j は上からの行）は、単位の正方形の `[i/w, (i+1)/w) × [j/h, (j+1)/h)` を覆う。
マスクの画素 (p, q) は、`[p/mw, (p+1)/mw) × [q/mh, (q+1)/mh)` を覆う。
画像の画素は、覆う範囲と面積が 0 より大きく重なるマスクの画素のうち、一つでも可視であれば可視とする。

マスクの画素が可視かは、マスクの種類で決める。

- ソフトマスク: Decode で写した値が 0 より大きければ可視とする。
- 明示マスク（ImageMask が true のマスク）: Decode で写した値が 0 であれば可視とする。

画像かマスクの Interpolate が true の場合は、補間で不可視の画素の色が見えうるので、すべての画素を可視として判定する。
この決まりは、同じ大きさのマスクにも当てはまる。
そのため、同じ大きさの明示マスクに Interpolate を付けた画像は、今は G08113 だが、この ADR の後はすべての画素を可視として判定する。
同じ大きさのソフトマスクに Interpolate を付けた画像も、今はマスクで判定しているが、この ADR の後はすべての画素を可視として判定する。
色キーのマスクは、可視の判定を今のまま値の範囲で行い、Interpolate の決まりを当てはめない。

ソフトマスクと明示マスクの標本は、判定にだけ使い、変えない。
色キーのマスクは、今のとおり、新しい DeviceGray のソフトマスクに書き換えて出力する。

Matte を持ち、画像と同じ大きさのソフトマスクでは、PDF の決まりの式 `c = m + (c' - m) / α` で Matte を取り除いた色 c を、範囲に切り詰めてから判定する（c' は画像の色、m は Matte、α はマスクの値）。
α が 0 の画素は不可視とする。
置き換えるときは、Matte も画像と同じ写しで写した新しいソフトマスクのオブジェクトにする。
写しが一次なので、写した画像と写した Matte の組は、取り除いた色を写した色と一致する。

CCITTFaxDecode で符号化したマスクは、復号してから同じ規則で判定する。
マスクを持つ CCITT の画像は、マスクをこの節の規則で扱う。

### 文書

仕様書の PDF 図版の色置換の節、diagnostic の一覧の G08113、マニュアル、ロードマップの「PDF 図版の色置換の残り」を、この ADR に合わせて直す。
仕様書の「採択した対象からの除外ではない」の文と、ロードマップの「採択した範囲から除外せず」の文は、この ADR で G08113 と決めた構成を除いたものに直す。
diagnostic の一覧の G08113 は、主な原因を「判定できない構成」の一覧に合わせ、特色を除き、ADR の欄に 0407 と 0425 を足す。

## 実装しないこと

特色を扱わない。
Lab、CalGray、CalRGB の色を、別の色空間へ色として変換しない。
FunctionType 4 の関数を評価しない。
Normal 以外の合成の方式のための合成と、図版を画素に変える処理を作らない。
図版の描画色を指定しない場合の、PDF の取り込みの範囲と出力を変えない。
新しい diagnostic のコードを足さない。

## 不変条件

I1: 描画色を指定した PDF 図版が、「判定できない構成」の一覧のどれかを使う場合は、G08113 を出し、対象媒体を生成しない。
I2: PDF を組むとき、特色（Separation か DeviceN）を使う PDF 図版は、描画色の指定に関わらず G08010 になり、G08113 にならない。

I12: 描画色を指定しない PDF 図版の受け入れの範囲と出力は、この ADR の前と一致する。

## 受けいれ条件

A1: 通常の CLI の PDF の出力で、CalRGB の灰色、Lab の灰色、FunctionType 2 の灰色のグラデーションを持つ PDF 図版が、指定色の濃淡になる。

## テスト設計

root ADR 0425 I1 から I12 を名前の先頭に置いたテストを、golem-typeset の色置換のテストに足す。
境界の表の各行を、手で組み立てた小さな PDF の図版で確かめる。

I6 は、置き換えた定義の各値と、元の値を写した値を、有理数で比べる。
あわせて、関数の種類、N、Domain、Encode、Bounds、Size、BitsPerSample、Order と、サンプルと頂点の値が変わらないことを確かめる。
補間した後の一致は、写しが一次であることから導くので、t^N を評価して比べることはしない。

I8 は、`w`、`h`、`mw`、`mh` を 1 から 4 までのすべての組み合わせで、マスクの画素の可視と不可視の 2 値の全通りを数え上げる。
期待は、画素が覆う範囲の重なりを有理数で求める幾何から作り、実装の式とは独立に計算する。

I12 は、描画色を指定しない既存の PDF 図版のテストが、変更の前と同じ出力を返すことで確かめる。
root ADR 0425 A1 は、golem-driver のテストで、実際の PDF の生成物の色を照合する。

## トレードオフ

Normal 以外の合成の方式、転送関数、OPM が 1 のオーバープリント、FunctionType 4 の関数を使う図版には、描画色を指定できない。
スウォッチの各成分が 0 か 1 だけの場合は、Multiply でも結果が一致するが、それでも拒む。
規則を一つにして、スウォッチによって受けいれる図版が変わらないようにするためである。
DTP のアプリケーションは、K 100% の文字を OPM 1 でオーバープリントして書き出すことがあるので、今は描画色の指定で通る図版の一部が G08113 になる。
拒んだ図版は、描画色の指定を外すか、これらを使わない形に書き出し直す必要がある。
その代わりに、指定色の結果が濃淡の規則と一致しない出力を、黙って作らない。

シェーディングは、値の一次式で g が決まるものだけを置き換える。
C、M、Y が等しく 0 でない DeviceCMYK の灰色や、出力ごとの定義がそろわない RGB の灰色のシェーディングは、塗りの色なら濃淡として置き換えられるが、シェーディングでは拒む。
その代わりに、補間の途中の色が規則と一致することを、定義の値だけで保証できる。

CIE 由来の色空間を値のまま分類するので、色として灰色に見えても、成分が厳密に条件を満たさない色は色として扱う。
CalGray と CalRGB の白色点、ガンマ、Matrix も、判定に使わない。
そのため、同じ g でも、CalGray と Lab では明るさの写し方が違い、三成分が等しい CalRGB が無彩色でないこともある。
既定の Range `[-100 100]` の 8-bit の Lab の画像では、a* と b* がちょうど 0 になるサンプルが無いので、濃淡と判定されない。
この扱いは、0403 の「近い RGB の値を同じ灰色と判定したりしない」と、0408 の「元の RGB の色に近い CMYK を計算せず」に合わせたものである。

シェーディングは、描かれない値も色に数える。
Domain や Extend で描かれないサンプルの色のせいで、多色と判定される図版がありうる。
その代わりに、描かれる範囲を計算する処理を持たない。

Interpolate が true の画像では、見えない画素の色も判定に入るので、マスクで隠した色のせいで多色と判定される図版がありうる。
その代わりに、補間で透けて見える画素の色を、判定から漏らさない。
