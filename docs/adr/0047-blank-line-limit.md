# ADR 0047: ページの行数以上の行アキを捨てる

ステータス: 採択

## 文脈

[ADR 0046](0046-blank-line-command.md) は、`@blank-line N` で段落のあいだに N 行の行アキを入れると定めた。
N は 1 以上の整数で、上限は IR の整数の範囲（2 の 63 乗未満）だけである。

実装（プルリクエスト #272）の後、N がとても大きい場合の振る舞いが問題になった。

- PDF では、行アキと次のブロックの最初の部分が今の段に入らなければ次の段へ進み、段の先頭で行アキを捨てる（G07047）。N がページの行数以上の行アキは、次のブロックの最初の行とともに一つの段に入ることがないので、必ず捨てられる。
- HTML と EPUB では、N 個の `<br/>` をそのまま書く。プレーンテキストでは、N 行の空行をそのまま書く。

そのため、ページの行数以上の N は、PDF で効果がないうえに、媒体のあいだで結果が食い違う。
N を大きくすると、HTML、EPUB、プレーンテキストの出力が N に比例して膨らむ。
[ADR 0046](0046-blank-line-command.md) の G04010（改ページの直前の行アキ）と同じ形の問題である。

メンテナーは、上限を設け、ページの行数以上ならお知らせを出すと決めた。

## 実装すること

### 判定

文書の組み立て（golem-doc の `Golem.Doc.Assemble`）で、本の全体の行アキを見て判定する。

- ページの行数 `L` は、`style.toml` の `[page.grid]` の `lines` とする。段組みでも、段の行の数は `L` である。
- 続けて書いた `@blank-line`（あいだに `@need-lines`、`@page-lines`、`@no-page-break` しかないもの）は、行数を足した和で判定する。PDF の改ページは、続けて書いた行アキをためて、その和で段に入るかを決める（[ADR 0046](0046-blank-line-command.md) の「PDF」）ためである。
- 行数の和が `L` 以上なら、その行アキをすべての出力で捨て、お知らせ G04011 を出す。続けて書いた `@blank-line` は、一つずつ出す。
- G04009（本の最後の行アキ）と G04010（改ページの直前の行アキ）で捨てる行アキは、先に捨て、G04011 の判定に含めない。一つの `@blank-line` に二つのコードを出さないためである。
- `@page-lines` による段の行数の増減は、判定に含めない。`@page-lines` は改ページの途中で決まる PDF だけの指定であり、HTML とプレーンテキストを組むときにも同じ判定を下すためである。

判定の順は G04009、G04010、G04011 で固定する。
同じ入力には、同じコードを同じ順に出す（[仕様書](../specifications.md) の「設計原則」の「diagnostics の決定性」）。

### 捨てた後の出力

- PDF：捨てた行アキは改ページに届かないので、G07047 は出ない。G07047 の代わりに G04011 が出る。
- HTML と EPUB：`<div class="blank-line">` を書かない。
- プレーンテキスト：行アキの空行を足さない。ブロックのあいだの一つの空行は残る。

### 設定の受け渡し

golem-driver の `assembleResults` で、`AssembleConfig` に `acPageLines :: !Int` を足し、`Style` の `[page.grid]` の `lines` を渡す。
文書の組み立ては、ほかの設定と同じく、出力の形式によらず一度だけ行う。

### diagnostic

| コード | 重大度 | 対象 | メッセージ | 段階 |
|---|---|---|---|---|
| G04011 | お知らせ | ページの行数以上の行アキ | `@blank-line の行数 <n> がページの行数 <L> 以上なので捨てます` | 文書の組み立て |

- `<n>` は、続けて書いた `@blank-line` の行数の和である。
- 位置は `@blank-line` の行である。
- G04011 を golem-syntax の `noticeCodes` に加え、`manifest.toml` の `silence-notices` で抑えられるようにする。
- 文書の組み立ての区分（04）は G04010 まで使っている。G04011 は、origin の各ブランチと作業中の worktree の docs とコードで使われていない。
- `docs/diagnostics.md` に G04011 の節を足す。

### ドキュメント

- 仕様書の「行アキ」の節に、判定と捨てた後の出力を書く。
- `markup.md` の「行アキ」の節に、ページの行数以上の行アキを捨てることを書く。
- ユーザーのマニュアルの行アキの説明に、同じことを書く。

## 実装しないこと

- N を誤りにはしない。ページの行数は `style.toml` で変わるので、同じ原稿が判型によって誤りになったりならなかったりするのを避ける。お知らせなら、出力は捨てた結果でそろい、ビルドは止まらない。
- IR の `BlankLines` の型と、評価（golem-eval）の G02092 の範囲は変えない。判定にスタイルが要るので、評価では判定できない。

## テスト設計

### golem-doc（`test/AssembleSpec.hs`）

`acPageLines` を 16 とした設定で、次を確かめる。

- `@blank-line 15` の後に段落がある本で、行アキが残り、G04011 が出ないこと。
- `@blank-line 16` の後に段落がある本で、行アキが捨てられ、`@blank-line の行数 16 がページの行数 16 以上なので捨てます` の G04011 が `@blank-line` の位置に一つ出ること。
- `@blank-line 10` と `@blank-line 6` を続けて書いた本で、二つとも捨てられ、それぞれの位置に `<n>` が 16 の G04011 が出ること。
- `@blank-line 10`、`@need-lines 3`、`@blank-line 6` の順に書いた本で、前の項目と同じになること。
- `@blank-line 10`、段落、`@blank-line 6` の本で、どちらも捨てられないこと。
- `@blank-line 20` の後に `@page-break` がある本で、G04010 だけが出て、G04011 が出ないこと。
- 本の最後の `@blank-line 20` で、G04009 だけが出て、G04011 が出ないこと。
- ファイルの末尾の `@blank-line 10` と、次のファイルの先頭の `@blank-line 6` を、和の 16 で判定すること。

### golem-driver（`test/Main.hs`）

- `[page.grid]` の `lines` が 16 のプロジェクトで、`@blank-line 16` を持つ原稿を PDF、HTML、プレーンテキストに組み、HTML に `blank-line` の `div` がなく、プレーンテキストに足した空行がなく、PDF で G07047 が出ず G04011 が一つ出ること。
- `manifest.toml` の `silence-notices` に `"G04011"` を書くと、G04011 が出ないこと。

### golem-syntax

- `noticeCodes` に G04011 が入ること（`test/Main.hs` の一覧）。
- docs の diagnostic の一覧と、コードの一致の検査が通ること。

## トレードオフ

- 閾値は、PDF で必ず捨てられる行アキにちょうど合わせて「ページの行数以上」とした。「ページの行数より多い」にすると、N がページの行数に等しい行アキが、PDF では段の先頭で捨てられ（G07047）、HTML とプレーンテキストでは残り、媒体のあいだで結果が食い違う。段の全体を空けるつもりで `L` を書いた書き手は、G04011 で、その行アキが捨てられたことを知る。
- 判定に `@page-lines` を含めないので、`@page-lines +1` で段を延ばした段では、`L` 行の行アキが PDF で入りうるのに捨てる。`@page-lines` は位置の微調整のための指定であり、ページの行数を超える行アキと組み合わせる用途は考えにくい。媒体のあいだで同じ判定を下せることを優先した。
- 判定に `style.toml` を使うので、文書の組み立てが初めてスタイルの版面の値に依存する。見出しの番号の表記など、スタイルの値はすでに `AssembleConfig` で受け取っており、依存の向き（スタイルから文書の組み立てへ）は変わらない。
