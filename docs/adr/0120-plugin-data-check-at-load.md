# ADR 0120: プラグインのデータを読み込みで一度だけ検査する

ステータス: 採択→`name` の null と、宣言にない名前の読み方は [ADR 0136](0136-missing-plugin-data-at-load.md)

## 文脈

プロジェクトはプラグインにデータのファイルを渡せる（[docs/adr/0105](0105-plugin-data.md)）。
ホストはバイト列を解釈せずに渡し、形式の誤りはプラグインが自分の diagnostic で報告する。
プラグインがデータを受け取るのはコマンドとフィルタの呼び出しのときだけなので、誤りを報告できるのも呼び出しのときだけである。

用語集のプラグイン（[docs/adr/0126](0126-glossary-plugin.md)）を試したところ、これが二つの問題になった。

- **重複**：TSV に欄の数の誤った行を一つ足すと、同じエラー（最初の試作のコードでは `term-tsv`）が、`[term]` を書いた八か所すべてに出た。呼び出しのあいだでプラグインは何も覚えていないので、どの呼び出しも同じ誤りを見つけて報告する。
- **位置**：誤りの原因は TSV の 7 行めにあるのに、diagnostic の位置は `[term]` の呼び出しになる。プラグインが返せる位置は、呼び出しの位置か要求に含まれていたノードの位置に限る方向で検討されており（[docs/adr/0108](0108-plugin-diagnostic-codes-and-spans.md)）、データのファイルの中の位置を指す形はない。

一方で、データを一度も使わない本（`[term]` を書いていない本）では、TSV の誤りがまったく報告されない。
誤りが見えるかどうかが、原稿にコマンドを書いたかどうかで変わる。

## 実装すること

- プラグインは、任意の export `golem_check_data` を持てる。ホストは、プラグインを読み込んでデータを読んだ後に一度だけ呼ぶ。
- 要求は `[data]`（[docs/adr/0105](0105-plugin-data.md) の `data` と同じ形）、応答は `[* data-diagnostic]` とする。
- `data-diagnostic = [code: tstr, severity: 0 / 1, name: tstr, line: uint64 / null, message: tstr]`。`name` はデータの名前、`line` は 1 から数えた行の番号か null である。
- ホストは、`name` のデータのファイルの `line` 行めの先頭（null ならファイルの先頭）を位置とする diagnostic にする。`name` が宣言にない名前なら、不正な応答（G06009）とする。
- `golem_check_data` がエラーを一つでも返したプラグインは、読み込みの誤りとして扱い、評価で G02022 と G02090 を報告しない（[docs/adr/0105](0105-plugin-data.md) の「diagnostic の順と位置」と同じ）。コマンドは呼ばない。
- `code` には、コマンドとフィルタの diagnostic と同じく [docs/adr/0108](0108-plugin-diagnostic-codes-and-spans.md) の規則を当てる。ホストは `<宣言名>/<コード>` の形にし、形の誤ったコードは G06009 とする。プラグインのコードは、どの export から返しても同じ形で使い手に見える。
- export がないプラグインは、今と同じく呼び出しのときに検査する。

## 実装しないこと

- 検査の結果（解析した辞書など）を呼び出しに持ち越すこと。速度の問題として別に扱う（[docs/roadmap.md](../roadmap.md) の「ビルドと LSP の速度」）。
- 行より細かい位置（列、バイトの範囲）。
- バイナリのデータの中の位置。行の番号は、テキストのデータにだけ意味がある。

## テスト設計

- wat のテスト用のプラグインで、`golem_check_data` の応答が、データのファイルの指定した行の diagnostic になること。
- 宣言にない名前の応答が G06009 になること。
- 応答の `code` が `<宣言名>/<コード>` の形で報告され、`Lookup/x` のような形の誤ったコードが G06009 になること。
- エラーを返したとき、コマンドが呼ばれず、G02022 が出ないこと。
- 用語集のプラグインで、TSV の誤った行が、`[term]` の数によらず一度だけ、TSV の行の位置で報告されること。`[term]` を書いていない本でも報告されること。

## トレードオフ

export を一つ増やすので、ABI の取り決めが広がる。
任意の export にしたので、今のプラグインは変えずに動く。
ABI のバージョン 8 はまだリリースしていないので、バージョンは上げない（[docs/adr/0052](0052-plugin-abi-version-bump-rule.md)）。

データを読み込みのたびに検査するので、LSP の評価のたびに検査の時間がかかる。
大きな辞書では、呼び出しの時間に加えて検査の時間が増える。

## 決めたことの記録

- 2026-10-29、メンテナー：この草稿を採る。
- 用語集のプラグインの TSV の誤りは、その後、原因ごとのコード（`tsv-columns`、`tsv-empty`、`tsv-no-reading`、`tsv-reading`、`tsv-duplicate`）に分けた（[docs/adr/0126](0126-glossary-plugin.md)）。`golem_check_data` の応答も、このコードをそのまま返す。
- **コードの前置き**：この版で、`golem_check_data` のコードにも [docs/adr/0108](0108-plugin-diagnostic-codes-and-spans.md) の前置きの規則を当てると決めた。export によってコードの見え方を変えないためである。
