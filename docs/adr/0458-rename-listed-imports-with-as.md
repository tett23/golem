# ADR 0458: 名前を並べた取り込みで、`as` で別名を付けられるようにする

Status: accepted-pending

## 文脈

[root ADR 0451](0451-import-listed-names-without-a-namespace.md) は、`@import パス { 名前, … }` で、並べた名前を名前空間なしで取り込めるようにした。
0451 は、取り込んだ名前に別名を付ける書き方（`{ total as sum }` など）を「実装しないこと」に挙げた。

メンテナーは、2026-11-26 に、`@import fn.emet { foo as bar }` のように別名を付けられるようにする ADR を作るよう求めた。
別名が無いと、取り込む先の名前が、取り込む側の名前（組み込みの式の名前、`@set` の変数、ほかの `@import` が並べた名前）と重なるとき、名前を並べて取り込めない。
そのとき書き手は名前空間つきの取り込みに戻るか、取り込む先の名前を変えるしかない。

この ADR は、別名の書き方、別名の形、別名と元の名前のどちらに検査を当てるか、ツールの扱いを決める。

## 調査した事項

origin/main（[9050a99](https://github.com/tett23/golem/commit/9050a990b8207454e1e0490ce4bb4111b8f7f814)）で、次のことを確かめた。

- 名前の並びは、パスの後ろの引数の語を、語の境目と語の中の `{`、`}`、`,` で字句に分け、`{`、名前、（`,`、名前）の繰り返し、`}` の順を求める（[Imports.hs#L98-L126](https://github.com/tett23/golem/blob/9050a990b8207454e1e0490ce4bb4111b8f7f814/modules/golem-project/src/Golem/Project/Imports.hs#L98-L126)）。
  そのため、今の `{ foo as bar }` は、名前 `foo` の後に `,` でも `}` でもない字句 `as` が来るので、G03009 になる（[Imports.hs#L79-L89](https://github.com/tett23/golem/blob/9050a990b8207454e1e0490ce4bb4111b8f7f814/modules/golem-project/src/Golem/Project/Imports.hs#L79-L89)）。
  字句分けは、`{`、`}`、`,` のほかのどの字も名前の字として受ける。
- 並べた名前は、名前と、その名前の位置の組の並びとして持つ（[Imports.hs#L43-L44](https://github.com/tett23/golem/blob/9050a990b8207454e1e0490ce4bb4111b8f7f814/modules/golem-project/src/Golem/Project/Imports.hs#L43-L44)）。
  評価、golem-lint、言語サーバー、柱の書式が、この組を使う。
- `.gm` のコマンドの名前は、英小文字で始まり、英小文字、数字、`-` だけからなる（仕様書の「`.gm` から関数を使う」の節の E06100）。
  式の名前と `@set` の変数の名前は、英字か `_` で始まり、英字、数字、`_` だけからなる（[Golem.hpeg#L543](https://github.com/tett23/golem/blob/9050a990b8207454e1e0490ce4bb4111b8f7f814/modules/golem-parser/grammar/Golem.hpeg#L543) の `ExprIdent`）。
- 0451 の検査は、並べた名前ごとに、予約語（G02275）、取り込む先が公開していない名前（G02276）、重なり（G02270 から G02274、G02277）を調べる。
  `.emet` を読み込めないときは、G02275 だけを調べ、名前を三つの使う場所に何も報告しない名前として入れる（0451 の I8）。
  [root ADR 0453](0453-override-built-in-commands-by-listed-imports-and-plugins.md) は、上書きできる組み込みのコマンドの名前を並べたとき、G02270 にせず上書きにすると決めた。
  [root ADR 0455](0455-resolve-variable-imports-through-the-import-graph.md) は、マニフェストの無いファイルの評価で、変数のファイルの取り込みを読み込めなかった `.emet` と同じく扱うと決めた。

## 実装すること

### 書き方

名前の並びの各項目は、名前一つか、`元の名前 as 別名` である。

```
@import functions/book.emet { tax-included as tax, total }
@import common/values.gm { price as base_price }
```

項目の字句は、位置で読む。

1. 項目の一つ目の字句は、`as` であっても元の名前である。
2. 二つ目の字句が `as` なら、別名の印である。
   `,` か `}` なら、項目は元の名前だけで終わる。
3. 別名の印の後の三つ目の字句は、`as` であっても別名である。
4. 別名の後の字句は、`,` か `}` でなければならない。

この形にならない並びは、0451 と同じく G03009 とする。
たとえば、`{ a b }`（二つ目が `as` でも `,` でも `}` でもない）、`{ a as }`（別名が無い）、`{ a as b as c }`（別名の後が `as`）、`{ as as }`（別名が無い）は G03009 である。
`{ as }` は元の名前 `as` の項目、`{ as as b }` は元の名前 `as` と別名 `b` の項目、`{ a as as }` は元の名前 `a` と別名 `as` の項目、`{ a, as }` は二つの項目である。
`as` の前後には空白を置く。
空白が無ければ、`fooasbar` は一つの名前の字句になる。

項目は、元の名前、別名、それぞれの位置を持つ。
別名の無い項目の別名は、元の名前とする。
元の名前と同じ別名を書いた項目（`{ total as total }`）は、別名の無い項目と同じ意味である。

### 別名の形

別名は、元の名前の定義を使う場所の名前の規則に従わなければならない。
インラインのコマンドとブロックコマンドでは `.gm` のコマンドの名前の規則、式（式の関数と変数）では式の名前の規則である。
元の名前が二つ以上の使う場所で公開されていれば、そのすべての規則に従わなければならない。
従わない別名は G02278（エラー）とし、位置は別名、メッセージは `別名の形が不正です: <別名>` とする。
G02278 の別名には、ほかの検査を当てず、取り込まない。

一つの項目の検査は、別名の G02275、元の名前の G02276、別名の G02278、重なり（G02270 から G02274、G02277）の順に調べ、当たった検査の後の検査はしない。
予約語の別名と、公開されていない元の名前では、使う場所が決まらないか、取り込まないので、後の検査をしない。

取り込む先を読み込めないとき（読み込めなかった `.emet`、0455 の取り込みを解かない評価）は、使う場所が分からないので、G02278 を調べない。

### 別名の意味

`元の名前 as 別名` は、取り込む先が公開する元の名前の定義を、取り込む側のファイルで別名で参照できるようにする。
別名を付けた項目は、元の名前を取り込まない。
元の名前の参照は、この項目が無いときと同じものを指す（同じファイルで、元の名前を別名なしで並べたときを除く）。
たとえば、`{ toc2 as toc }` の後の `@toc` は取り込んだ関数を呼び、`{ toc as mytoc }` の後の `@toc` は組み込みの目次のままである。

検査は、名前によって次のように当てる。

| 検査 | 当てる名前 |
| --- | --- |
| 取り込む先が公開していない（G02276） | 元の名前 |
| 別名の形（G02278） | 別名 |
| 予約語（G02275） | 別名 |
| 重なり（G02270 から G02274、G02277）と、0453 の上書き | 別名 |
| 使う場所（インライン、ブロック、式） | 元の名前の定義の種類 |

予約語を別名だけで調べるので、取り込む先が予約語の名前を公開していても、予約語でない別名を付ければ取り込める。
同じ並びで、同じ元の名前に別々の別名を付けてもよい（`{ total as sum, total as amount }`）。
同じ並びの二つの項目の別名が同じなら、0451 のとおり G02273 とする。
ほかの `@import` が並べた項目の別名と同じなら、0451 のとおり両方の別名の位置に G02272 とし、その名前の呼び出しは何も出力しない。

diagnostic の位置は、G02276 では元の名前の位置、ほかは別名の位置とする。

取り込む先を読み込めないときは、0451 と 0455 の扱いのとおり、別名を何も報告しない名前として入れ、別名の G02275 だけを調べる。
元の名前は取り込まない。
上書きできる組み込みのコマンドの名前を別名にしたとき（`{ x as toc }`）は、0453 の I8 のとおり、その呼び出しは何も出力しない。

### 組み込みの名前で決まる前処理

0453 は、`code`、第一引数が `code` の `style`、`number-text` を上書きした名前の呼び出しが、組み込みのコマンドの名前で決まる前処理と短縮記法を受けると決めた。
この前処理は、別名（呼び出しに書く名前）で決める。
そのため、`{ my-code as code }` の `[code …]` は前処理を受け、`{ code as c }` の `[c …]` は受けない。
`##N##` は、`number-text` という別名で取り込んだ関数を呼ぶ。

### ツール

- **golem fmt**：項目を `元の名前 as 別名`（`as` の前後に空白を一つ）に整える。
  元の名前と別名が同じ項目は、`元の名前` に書き換える。
- **golem lint**：使われていない項目の G05003 は、別名で数え、別名の位置で報告する。
  変数の G05002 は、別名で参照した変数も参照されたと数える。
- **LSP**：
  - 補完は、項目の一つ目の位置で、0451 と同じく取り込む先の公開された名前を出す。
    別名の位置では出さない。
  - 別名で参照した位置から定義へ移動すると、取り込む先の元の名前の定義へ移る。
  - 参照の検索は、定義から探したとき、別名での参照も返す。
    別名の位置か別名での参照の位置から探したときは、その項目の別名、そのファイルの別名での参照、取り込む先の元の名前の定義を返す。
  - 取り込む先の定義の名前を変えると、名前の並びの元の名前だけを書き換え、別名と別名での参照は書き換えない。
    そのため、[root ADR 0454](0454-rename-set-variables-in-the-language-server.md) の I1（書き換える箇所と参照の検索の結果が等しい）は、別名での参照を除いて成り立つ。
    0454 の断る場合の重なりの検査は、別名を付けた項目には当てない（その項目では元の名前を参照しないため）。
    同じファイルの別名の無い項目には、0454 のとおり当てる。
  - 別名の位置か、別名での参照の位置で改名を受けたときは、そのファイルの中の別名と、別名での参照だけを書き換える。
    0454 の改名を断る場合のすべて（形、予約語、重なり、柱の書式、構文の誤り）を新しい別名に当て、柱の書式は古い別名にも当てる。
    `.emet` から別名で取り込んだ項目にも当てはめ、重なりの検査には 0453 の上書きになる名前とプラグインのコマンドの名前を含める。
- **柱の書式**：変数のファイルから別名で取り込んだ変数は、`{set.<別名>}` で参照する。

### 文書

仕様書の次の箇所を書き換える。

- 「定義の取り込み」の節に、別名の書き方、字句の読み方、別名の形、検査を当てる名前の表を書く。
- 柱の書式の表の `{set.<名前>}` に、別名で取り込んだ変数を足す。
- LSP の補完、定義への移動、参照の検索、改名の記述に、別名を足す。
- lint の G05003 の記述と、fmt の整え方に、別名を足す。

`docs/diagnostics.md` に G02278 を足し、G03009 のメッセージと、G02272、G02273、G02275、G02276、G05003 の説明に、別名の場合を足す。

採択したら、0451 のステータスに `{"part":"実装しないこと","by":["docs/adr/0458-rename-listed-imports-with-as.md"],"kind":"replace"}` と `{"part":"書き方","by":["docs/adr/0458-rename-listed-imports-with-as.md"],"kind":"supplement"}` を、0454 のステータスに `{"part":"実装すること","by":["docs/adr/0458-rename-listed-imports-with-as.md"],"kind":"supplement"}` を記録する。

## 実装しないこと

名前空間つきの取り込み（`* as ns`）の中の名前に別名を付ける書き方は足さない。
`.emet` の中の `import` の別名は足さない。
一つの別名を二つの元の名前に付ける書き方は足さない。

## 不変条件

- I1: f と g のどちらにも重なりも 0453 の上書きも無く、f も g も `code`、`style`、`number-text` でないとき、`{ f as g }` で取り込んだファイルでの g の各種類の参照の結果は、`{ f }` で取り込んだファイルでの f の同じ種類の参照の結果と同じである。
- I2: `{ f as g }` で取り込み、f を別名なしで並べていないファイルで、f の名前空間なしの参照の diagnostics と出力は、この項目が無いときと同じである。
- I3: `{ f as g }` の G02276 は、f について `{ f }` のときと同じに決まる。
  元の名前が公開され、別名が予約語でも G02278 でもないとき、重なりのコードは、g について、g を f と同じ種類で公開する取り込む先から `{ g }` と並べたときと同じに決まる。
- I4: 項目の並びが、字句の読み方の 1 から 4 に従わなければ G03009 になる。
- I5: 元の名前が公開され、別名が予約語でないとき、使う場所の名前の規則に従わない別名ごとに、G02278 がちょうど一つ出て、その別名にほかの評価の diagnostic は出ない。
- I6: `golem fmt` で整えた原稿は、整える前の原稿と diagnostics のコードの集合と出力が同じである。
- I7: 取り込む先の定義の改名は、別名での参照を書き換えない。
  別名の改名は、取り込む側のファイルの外を書き換えない。
- I8: 同じ名前空間を二度取り込まない原稿で、すべての参照より前にある `@import` の行どうしの順を入れ替えても、別名を含む diagnostics の集合（位置を除く）と出力は変わらない（0451 の I7 を別名に広げたもの）。
- I9: 読み込めなかった `.emet` から別名で取り込んだとき、別名について G02275 のほかの評価の diagnostic は出ず、三つの使う場所での別名の呼び出しは何も出力しない。
  取り込みを解かない評価の変数のファイルから別名で取り込んだときは、`@import` の行で G02275 のほかの評価の diagnostic は出ず、式での別名の参照は diagnostic を出さない。
  コマンドの形の呼び出しは、0455 のとおり今と同じ diagnostic を出す。
- I10: 別名の改名が成り立つとき、改名を当てた後の出力と diagnostics のコードの集合は、改名の前と同じである。
- I11: 0454 の改名を断る場合のどれかに新しい別名か古い別名が当たるとき、書き換えは返らず、誤りが返る。
- I12: 一つの項目について、別名の G02275、元の名前の G02276、別名の G02278、重なりの順に調べ、当たった検査の後の検査はしない。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |

## 受けいれ条件

なし。
不変条件のテストで足りるためである。

## テスト設計

root ADR 0458 I1 から I12 を名前の先頭に置いたテストを足す。
golem-project の `importSite` のテストで、I4 の形を表の入力で確かめる。
golem-eval のテストで、`.emet` と変数のファイルを別名つきで取り込み、I1 から I3、I5、I8、I9、I12 を、三つの使う場所ごとに確かめる。
golem-evaluate のテストで、別名で取り込んだ変数の柱の書式 `{set.<別名>}` を確かめる。
golem-fmt のテストで I6 を、golem-lint のテストで別名の G05003 と G05002 を、golem-lsp のテストで補完、定義への移動、参照の検索、改名（I7、I10、I11）を確かめる。
テストは、実装の前に書いて落ちることを確かめる。

## トレードオフ

別名を付けると、原稿の名前と取り込む先の名前が違うので、名前から定義を探すには `@import` の行を見る必要がある。
名前を並べた取り込みは、0451 で名前の出どころを `@import` の行から読めるようにした形なので、別名もその行に書く。

`as` を位置で読むので、`as` という名前を取り込むときや別名にするときは、`{ as }`、`{ as as b }`、`{ a as as }` と書く。
別の記号（`=>` など）にすれば位置で読む必要は無いが、名前空間つきの取り込みが `* as ns` と書くので、同じ `as` にそろえた。

取り込む先の定義の改名で別名を書き換えないので、改名した後も、取り込む側の原稿は変わらない。
その代わりに、参照の検索の結果と改名で書き換える箇所は、別名での参照の分だけ違う。
