# ADR 0018: 段組み

ステータス: 採択

## 文脈

`style.toml` の `[page.grid]` には段数 `columns` と段間 `column-gap` があり、2 以上の段数を書ける（[golem-project ADR 0002](../golem-project/adr/0002-style-toml.md)）。
`Golem.LayoutSpec.pageGeometry` は段ごとの矩形を計算し、`pgColumns` と `pgColumnsEven` に読む順で入れている（[golem-layout-spec ADR 0001](../golem-layout-spec/adr/0001-page-geometry.md)）。
横組みでは段を左から右へ並べ、縦組みでは上から下へ並べる。
版面の幅（縦組みでは高さ）は、段の数だけの段の行長と、その間の段間の和である。

PDF の経路は、この段を使っていない。
`Golem.Driver.Pdf.columnMeasure` は最初の段の行長だけを返し、`buildFlow` はすべての行をその長さで組む。
`Golem.Layout.Paginate.paginate` は一ページを一つの行の並びとして扱い、`writeDocument` は行を版面の矩形（`typeAreaFor`）の始まりから描く。
そのため 2 段の版面では、本文は一段目の行長で組まれ、一段目の位置にだけ描かれ、二段目以降は空のままになる。
論文の組版には段組みが要るので、v1 で実装する（[仕様書の「v1 の実装で次の段階以降に回した項目」](../specifications.md)）。

既存の ADR は、段組みの位置づけで食い違っている。

- [golem-driver ADR 0007](../golem-driver/adr/0007-pdf-index-and-bibliography.md) は、索引の段組みを「段組みはフレームのレベル 2 に当たり、v1 では扱わない」として外した。仕様書の脚注のフレームのレベルの定義も、レベル 2 に「多段組」を挙げている。
- [golem-layout-spec ADR 0001](../golem-layout-spec/adr/0001-page-geometry.md) は、段数と段間から段ごとの版面を計算すると決め、`pgColumns` を出力に含めた。
- [golem-driver ADR 0005](../golem-driver/adr/0005-pdf-wrapped-figures.md) と [golem-driver ADR 0006](../golem-driver/adr/0006-pdf-sidenotes.md) は、段組みの版面での回り込みと傍注欄を「実装しないこと」に挙げている。段組みの版面が存在することを前提にした書き方である。

この ADR は、版面の段組みをフレームのレベル 1 の中に置き、v1 で実装する範囲を決める。
v2 に回す範囲は、仕様書の「v2 以降に回した事項」の「段組みの拡張」に合わせる。

## 段組みの位置づけ

フレームのレベル 2 は、名前を付けた複数のフレームと、そのあいだを本文が流れる順序を、利用者が指定するものである。
`[page.grid]` の段組みは、これに当たらない。
段は版面を等しい幅に分けたものであり、名前も持たず、本文が流れる順序も版面の定義から一つに決まる。
本文の流れは一本のままであり、改ページが「次のページ」の代わりに「次の段」へ進むだけである。

そこで、`[page.grid]` の段組みを、レベル 1 の単一のフローが版面の段を順にたどるものとして扱う。
段の幅を変えること、段ごとに別の流れを持つこと、ページごとに段数を変えることは、利用者がフレームを指定することになるので、レベル 2 に残す。

## 実装すること

### 本文を流す順序

本文は、ページの段を読む順にたどり、最後の段の次は次のページの最初の段に進む。

- 横組みでは、左の段から右の段へ進む。`pgColumns` の順である。
- 縦組みでは、上の段から下の段へ進む。各段の中では、行は右から左へ進む。`pgColumns` の順である。
- 段の順序は綴じの方向によらない。右綴じの横組みの本でも、段は左から右へ読む。

本文の行、見出し、図版、表、目次、索引、参考文献のすべてが、この順に段を埋める。

### 段の高さ

各段は、`[page.grid]` の `lines` の数の行の格子を持つ。
段の行の格子は版面の行の格子（`pgLineGrid`）と同じであり、隣り合う段の行の位置はそろう。

段の高さはそろえない。
本の最後のページや、`page-break = "recto"` の見出しの前のページでは、本文が一段目の途中で終わり、後ろの段が空のまま残ることがある。
段の高さの調整は、仕様書の「改ページの大域の最適化」に含め、v2 以降とする。

### 改ページの単位（golem-layout）

`Golem.Layout.Paginate` の改ページの単位を、ページから段に変える。
一つの段を埋める処理は、今の一ページを埋める処理と同じであり、段を閉じると次の段に進む。

```haskell
paginate
  :: Int     -- 一ページの段の数（1 以上）
  -> Int     -- 一段の行の格子の数（capacity）
  -> [Flow]
  -> [PageOut]

data PageOut = PageOut
  { poNumber :: !Int,
    poColumn :: !Int, -- 段の番号。0 から数え、pgColumns の順
    poBlank :: !Bool,
    poSlots :: ![(Int, Slotted)],
    -- 以下は今と同じ。段ごとの値になる
    ...
  }
```

`PageOut` は、一つのページの一つの段に置いたものを表す。
一段組みの版面では、今と同じく一ページに一つの `PageOut` になり、`poColumn` は常に 0 である。

- `St` に今の段の番号 `sColumn :: !Int` を加える。
- 今の `newPage` を `nextColumn` とし、今の段を閉じた後、`sColumn + 1` が段の数より小さければ同じページの次の段に、そうでなければ次のページの段 0 に進む。行の格子の使用量、脚注の量、ラベル、索引の印、表の部分は段ごとに空に戻す。
- 送った図版（`sDeferred`）と、続きの残る脚注（`sPendingNotes`）は、今のページの代わりに次の段の先頭に置く。
- 孤立行の規則、見出しと定義リストの用語の直後で区切らない規則、表の見出しの行の繰り返しは、ページの境界と同じ規則を段の境界に適用する。
- `page-break = "recto"` の見出しは、今の段を閉じた後、次の奇数ページの段 0 から置く。今のページに残る段は空のままにする。途中に偶数ページが挟まる場合は、今と同じく白ページ（`poBlank` が真の `PageOut` を一つ）を入れる。
- 柱の値（`sPageHead`）は、段を進めても戻さず、ページを進めたときにだけ戻す。同じページのすべての段の `poRunningHead` は同じ値になる。
  [golem-driver ADR 0014](../golem-driver/adr/0014-running-heads.md) の案は、柱を `paginate` から外し、`poRunningHead` と `sPageHead` を削る。その ADR が先に実装された場合は、この規則と、下の `poRunningHead` のテストは要らない。
- 閉じた段に何も置かれていない場合は、今の `closePage` と同じく `PageOut` を作らない。空の段は出力に現れない。

`labelPages` と `markPages` は `poNumber` を使うので、変えない。
段の番号はページ番号への参照に影響しない。

### 改段

[docs/adr/0017](0017-forced-page-breaks.md) が、原稿の任意の位置で改段を指定する記法 `@column-break` と、改ページの記法 `@page-break`（引数なし、`recto`、`verso`）を決め、`Golem.Layout.Paginate.Flow` に `FBreak !BreakKind` を加える。
この ADR は、それぞれの段組みでの意味を次のように決める。

- `BreakColumn`（改段）は、今の段を閉じて次の段から続ける。今の段が最後の段なら、次のページの最初の段から続ける。今の段に何も置いていなくても進むので、段の先頭での改段は空の段を一つ作る。
- 一段組みの版面の改段は、改ページと同じ結果になる。InDesign で一段のテキストフレームに改段を入れると、次のフレームに送られる動きと同じである（記憶による）。
- `BreakPage`（改ページ）は、今の段がどの段であっても、次のページの最初の段から続ける。今のページに残る段は空のままにする。
- `BreakRecto` と `BreakVerso` は、`page-break = "recto"` の見出しと同じく、次の奇数ページ（偶数ページ）の最初の段から続ける。[docs/adr/0017](0017-forced-page-breaks.md) が `rectoStart` を一般化した `parityStart` を、段の単位で閉じてからページを進める形にする。
- [docs/adr/0017](0017-forced-page-breaks.md) の実装は、この ADR の実装まで `BreakColumn` を改ページとして扱う。この ADR の実装で、`BreakColumn` を上の「次の段へ進む」に改める。

### 段の中の組版（golem-driver）

- 段落、見出し、目次の項目、索引、参考文献、脚注の本文は、段の行長で組む。`columnMeasure` が返す値は今と同じく一段の行長であり、すべての段の行長は等しいので、行分割は段の位置によらない。
- 見出しは段の中に置く。見出しの行長は段の行長であり、行取り（[golem-driver ADR 0003](../golem-driver/adr/0003-pdf-heading-styles.md)）も段の行の格子で行う。一段の行の格子の数を超える見出しは、今と同じく G0724 とする。
- 脚注の本文は、注の印を含む行が置かれた段の下部に置く。脚注の領域の幅は段の行長である。InDesign の脚注も、既定では印のある段の下に置かれる（記憶による）。
- 回り込ませない図版の行の方向の長さは、今と同じく行長（段の行長）とする。画像はその長さに縮めて置く。図版の高さが段の行の格子の数を超える場合は、今と同じく空の段の先頭にそのまま置く。
- 表は段の行長の中で列の幅を決める。列の最小の幅の合計が段の行長に収まらない表は、今と同じく G0741 とする。
- 目次の項目のページ番号のための予約の幅（[golem-driver ADR 0009](../golem-driver/adr/0009-pdf-toc-page-numbers.md)）は、段の行長から取る。
- 段落スタイルの字下げの検査（G0725、[docs/adr/0006](0006-paragraph-indent.md)）は、段の行長に対して行う。

### 描き方（golem-driver）

`writeDocument` の `drawPage` は、ページの番号 `n` が同じ `PageOut` をまとめて一つの PDF のページに描く。

- 各 `PageOut` の行、見出し、図版、キャプション、表の罫線、脚注は、版面の矩形 `typeAreaFor geom n` の代わりに、段の矩形 `columnsFor geom n !! poColumn` を基準に描く。`drawLine`、`figureRect`、`tableRules`、`captionIndent` に渡す矩形を差し替えるだけで、各関数の式は変えない。
- 一段組みの版面では、段の矩形は版面の矩形と等しいので、PDF のバイト列は今と変わらない。
- 柱とノンブル（`masterMarks`）は、ページに一度だけ描く。値は、そのページの段 0 の `PageOut` からとる。
- `PdfLayout` の `plPages` は段ごとの `PageOut` の列のまま持ち、ページへのまとめは `writeDocument` で行う。ページの順と段の順は `paginate` が返す順のままとする。

### 段組みと組み合わせない機能

次の二つは、段組みの版面での形が決まっていないので、2 段以上の版面ではエラーにする。
黙って一段組みの形で組むと、書き手が意図しない配置になるためである。

- 傍注欄：`[sidenotes]` と 2 以上の `columns` を両方書いた `style.toml` は、`pageGeometry` で G0701 とする。メッセージは「段組みの版面には傍注欄を設けられません」とする。縦組みの版面に傍注欄を設けた場合と同じ扱いである。
- 回り込み：2 段以上の版面で `wrap` を指定した図版は、図版の位置で G0726 とする。

| 診断コード | 重大度 | メッセージ |
|---|---|---|
| G0726 | エラー | `段組みの版面では図版を回り込ませられません。wrap を外すか、columns を 1 にしてください` |

G0726 は未使用である（golem-driver は G0721 から G0725 までを使っている）。
検査は `buildFlow` の図版の単位で行い、ほかの G072x の診断と同じく `bErrors` に積む。

### 索引の段組み

索引は、本の全体と同じ段数で組む。
2 段組みの本の索引は 2 段で、1 段組みの本の索引は 1 段で組まれる。
一冊の中で段数を切り替えること（本文を 1 段、索引だけを 2 段にすること）は、仕様書の「段組みの拡張」のとおり v2 以降とする。

### HTML と EPUB

HTML と EPUB には、段組みを出力しない。
CSS の `columns` も `column-count` も書かない。

- 仕様書は、EPUB と HTML が版面とマスターページを無視すると定めている。段数は版面の定義の一部である。
- リフローする媒体では、画面の幅によって一段の長さが大きく変わり、狭い画面で段組みにすると一行の字数が極端に少なくなる。回り込みを Web で行わない理由（[golem-layout ADR 0004](../golem-layout/adr/0004-wrapped-figures.md)）と同じである。
- EPUB の読書環境の中には、ページ送りを CSS の段組みで実現しているものがある（Readium CSS など）。本文に `columns` を書くと、読書環境の段組みと重なる。これは読書環境の実装についての知識によるもので、各環境での挙動は確かめていない。

改段の記法 `@column-break` の HTML と EPUB での扱いは、[docs/adr/0017](0017-forced-page-breaks.md) に従う。
段組みを出力しないので、改段は Web の媒体では見た目に現れない。

プレーンテキストも段組みを出力しない。

## データ構造の変更

- golem-layout：`paginate` に段の数の引数を加える。`PageOut` に `poColumn` を加え、意味を「ページの一つの段」に変える。`St` に `sColumn` を加える。
- golem-driver：`writeDocument` が `PageOut` をページの番号でまとめて描く。`buildFlow` が G0726 を出す。
- golem-layout-spec：`pageGeometry` が `[sidenotes]` と 2 以上の段数の組を G0701 にする。

意味論 IR と `style.toml` の欄は変えない。

## 実装しないこと

仕様書の「段組みの拡張」に合わせ、次のことは v2 以降とする。

- 段抜きの見出し（複数の段にまたがる見出し）。
- 段に収まらない図版と表を、複数の段にまたがせて置くこと。図版は段の行長に縮め、表は G0741 にする。
- 一冊の中で段数を切り替えること。索引だけを段組みにすること、章ごとに段数を変えることを含む。
- 段組みの版面での回り込みと、段をまたぐ除外領域。
- 段の高さの調整（最後のページの段の高さをそろえること）。「改ページの大域の最適化」に含める。
- 段組みの版面での傍注欄。「傍注の拡張」に含める。
- 脚注を段をまたいでページの下部に置くこと（InDesign の「段抜き脚注」にあたる設定）。
- 段の幅が段ごとに異なる版面と、段間の罫線。
- HTML と EPUB の CSS の段組み。

## テスト設計

先に書き、失敗させてから実装する。

### golem-layout（`modules/golem-layout/test/Main.hs`）

- 段の数 2、一段の行の格子 3 の `paginate` に 8 行の段落を一つ渡すと、`PageOut` が (1, 0)、(1, 1)、(2, 0) の順に出て、行の数が 3、3、2 になること。孤立行の規則で 2 行目の段の境界が動かないことも、この例で確かめる。
- 同じ条件で、段の境界をまたぐ段落の最初の 1 行だけが段の末尾に残る場合に、その行が次の段に送られること。
- 段の数 2 で、二段目の途中まで本文があるページの後に `fhRecto` の見出しを置くと、見出しが次の奇数ページの段 0 に置かれ、間に白ページ（`poBlank`）が一つ入り、二段目の残りに何も置かれないこと。
- 脚注の印を一段目の行に置くと、脚注の本文がその一段目の `PageOut` の `poFootnotes` に入り、二段目の `PageOut` には入らないこと。一段目の脚注が収まらず続く場合に、続きが二段目の `poFootnotes` に入ること。
- 段に入らない図版（`FFigure`）が次の段の先頭に送られ、送った図版より後の行が今の段に詰められること。
- 段の境界をまたぐ表で、二段目の先頭に見出しの行が繰り返されること。
- 段の数 2 のとき、二段目にだけラベルのある行を置いても、`labelPages` がそのページの番号を返すこと。
- 同じページの段 0 と段 1 の `poRunningHead` が等しいこと。段 1 で 1 の階層の見出しが始まり、段 0 にはない場合も、段 0 の値（前のページからの値）と段 1 の値が同じになること。
- 段の数 1 の `paginate` が、既存のすべての改ページのテストで今と同じ `PageOut` の列（`poColumn` が 0）を返すこと。既存のテストに段の数の引数 1 を足して確かめる。
- `FBreak BreakColumn` が、段の数 2 の段 0 では段 1 に、段 1 では次のページの段 0 に進めること。段 0 の先頭（空の段）の `FBreak BreakColumn` が段 0 を空のまま段 1 に進めること。段の数 1 では `FBreak BreakPage` と同じ結果になること。`FBreak BreakPage` が、段 0 の途中からでも次のページの段 0 に進めること（[docs/adr/0017](0017-forced-page-breaks.md)）。

### golem-driver（`modules/golem-driver/test/Main.hs`）

横組みは既存の `horizontalStyle`（A5、10pt、12 字、30 行）の `columns` を 2 にして `column-gap = "2zw"` を足したスタイル、縦組みは既存の `pdfStyle`（B6、13Q、42 字、16 行）の `characters` を 20、`columns` を 2 にして `column-gap = "2zw"` を足したスタイルを使う。42 字の二段は B6 の高さからはみ出すためである。
フォントは `fakeFonts` を使う。

- 横組みで、二段分を超える長さの段落を組むと、`layoutPdf` の `plPages` に `poColumn` が 1 の `PageOut` があり、すべての行の `lineTarget` が一段の行長（12 字分）であること。
- 横組みで、二段目の最初の行の最初のグリフが、段 1 の矩形の左辺に描かれること。描く始まりの点の x が `rectX (columnsFor geom 1 !! 1)` に一致することで確かめる。縦組みでは、二段目の最初の行の最初のグリフの y が段 1 の矩形の上辺に一致し、x が版面の右端から格子の距離だけ左にあること。
- 60 行（一段の行の格子の数 30 の 2 倍）に組まれる段落が、1 ページの二つの段に収まり、2 ページ目ができないこと。段を空のまま次のページに進んでいないことの確認である。
- 二段組みで、柱とノンブルがページごとに一度だけ描かれること。内容のストリームにノンブルの文字列が一度だけ現れることで確かめる。
- 二段組みの版面で `wrap=start` の図版を置くと G0726 になり、位置が図版のブロックであること。
- 二段組みで `@index` を置くと、索引の行が段の行長で組まれ、二段目に続くこと。

### 自動テストにしない確かめ方

実装の後に、`golem new` の欧文の雛形を A4、2 段組みにした論文の形の原稿（見出し、脚注、図版、表、`@bibliography` を含む）と、和文の雛形を縦組みの 2 段組みにした原稿を PDF にし、ビューアーで次のことを目で確かめる。

- 横組みでは左の段から右の段へ、縦組みでは上の段から下の段へ本文が続くこと。
- 隣り合う段の行の位置がそろうこと。
- 脚注が印のある段の下に置かれること。

## トレードオフ

段の高さをそろえないので、本の最後のページと章の終わりのページでは、一段目だけが埋まり二段目が空く、あるいは二段目の途中で終わる形になる。
論文の最後のページで段の高さをそろえる組み方は一般的だが、そろえるには段落の行をページの中で配り直す処理が要り、v1 の先頭から詰める改ページの方式の外に出る。

脚注を段ごとに置くので、二段組みの論文で脚注をページの下部にまとめる組み方はできない。
改ページの処理を段の単位にそのまま適用でき、脚注の領域の幅も段の行長で済む。
InDesign の既定の置き方とも一致する（記憶による）。

`PageOut` の意味をページから段に変えるので、`poNumber` が同じ `PageOut` が複数できる。
ページの単位で値を集める処理（柱、傍注、ページ数）は、まとめ方を誤ると段の数だけ重複する。
段の数 1 では今と同じ列になるので、既存のテストがそのまま回帰の検査になる。

傍注欄と回り込みを段組みの版面でエラーにするので、一段組みで書いた原稿の版面を二段にすると、ビルドが止まる場合がある。
黙って一段組みの規則で組むと、傍注欄が段と重なる位置に描かれるか、図版が段の幅を越えるので、止めて書き手に知らせる。

HTML と EPUB に段組みを出さないので、PDF と Web の媒体で見た目が分かれる。
段数は版面の定義の一部であり、版面を持たない媒体には写さないという媒体契約に従う。
