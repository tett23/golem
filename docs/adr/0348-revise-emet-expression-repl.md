# ADR 0348: golem repl emet で Emet の式を対話的に評価する

ステータス: 採択

## 文脈

本案は [Golem ADR 0335](0335-emet-expression-repl.md) の決定とテスト設計を改める。

短い Emet の式の値や型エラーを、原稿やモジュールを用意せずに確かめたい。
コマンドは `golem repl emet` とし、どの言語の REPL を開くかを `repl` の次の引数で選ぶ。
`golem repl --help` に選べる言語とその説明を載せる。

将来、段落スタイルや文字スタイルを短い原稿で試す gm の REPL も同じ入口に追加できる。

## 調査した事項

IRB 1.16.0 を `irb -f --simple-prompt --nocolorize --nomultiline` で起動し、標準入力から順に `1 +`、`2`、`exit` を渡した。
通常のプロンプトは `>>`、継続行は `?>`、結果は `=> 3` だった。
[旧案の CLI 試験](../../experiments/repl/README.md) は明示的な複数行区切りを使った試作の記録である。

旧試作は UTF-8 の入力と表示をそれぞれ 4096 バイトまでに制限し、4096 と 4097 バイトで境界を検査した。
[試作記録](../../experiments/repl/README.md) に、対話で扱う入力や値の分布からこの閾値を選んだ計測はない。

旧試作は端末を一つの評価が占める時間を短くする目的で、一式の手数を 10 万に下げた。
[旧試作の境界試験](../../experiments/repl/README.md) は手数超過後の回復を確かめた。
10 万手での応答時間や、通常の上限との所要時間の比較はこの記録にない。
通常の呼び出しは [Emet の評価器](https://github.com/tett23/golem/blob/ce1d423474050ed0dced10669cbd9499ff529bfb/modules/golem-emet/src/Golem/Emet/Eval.hs#L156-L179) で共通の手数上限と深さ上限を使う。

## 実装すること

プロジェクトの外でも、標準入力の UTF-8 の式を Emet のパーサー、型検査器、評価器に渡す。
式からは組み込みの名前、現在のセッションに登録した名前、式内で束縛した名前を使える。
許可する要求の集合は空とする。
たとえば `File.read "secret.txt"` は E05101 となり、ファイルを開かない。

端末では通常入力に `emet> `、続きを待つときに `....> ` を標準エラー出力に出す。
端末として扱う条件は標準入力と標準エラー出力がともに端末であることとする。
成功した値を標準出力に一行で書き、端末では値の前に `=> ` を付ける。

```text
emet> 1 +
....> 2
=> 3
emet> 1 + )
E01100 [4,5): …
emet> 6
=> 6
```

一行を受け取るたびに構文を調べる。
式の構文が完結していればその場で型検査と評価に進む。
宣言を確定する区切りは後述する。
式ではパーサーが入力末尾で次のトークンまたは閉じ記号を要求している場合だけ、LF を一つ挟んで次行を足す。
途中の文字を指す構文エラー、型エラー、評価エラーはその場で報告し、次の行を新しい式として読む。
エラーには元のコードとメッセージ、入力した式の先頭からの UTF-8 バイト範囲 `[start,end)` を示す。

未完の入力を待っているときの Ctrl-C はその入力を取り消し、同じ端末で次の式を読める状態に戻す。
EOF では、完成した最終行を末尾の LF の有無によらず一度評価する。
未完の式で EOF を受けた場合は保留していた構文エラーを一度報告する。
エラーを報告したセッションは終了コード 1、すべて成功または取り消しだけなら 0、引数の誤りは 2 とする。
パイプからはプロンプトを出さず、標準出力には値だけを書く。

値には既存の正確な数値表記、`True` と `False`、引用符付きの文字と文字列、リスト、タプル、コンストラクタを使う。
文字と文字列では区切りの引用符とバックスラッシュをエスケープし、LF は `\n`、タブは `\t`、その他の制御文字は `\u{16進数}` と書く。
引数付きコンストラクタは `(Just 2)` のように括弧で囲み、関数値は `<function>` と表示する。

### 定義と import

一つのセッションを一つの Emet モジュールとして扱い、トップレベルの関数、データ型、型の別名、`import` を受け付ける。
宣言の構文と公開範囲は [Emet の仕様](../golem-emet/specifications.md) に従う。
関数のシグネチャを入力すると継続プロンプトに移り、等式を入力できる。
宣言のまとまりは空行または EOF で確定するので、複数の等式や相互参照する定義を続けて書ける。
構文上未完の宣言では空行も入力に含める。
EOF まで未完ならエラーにする。
一行の import は行末で確定する。
式は従来どおり完成した時点で評価する。

宣言のまとまりは、それまでの宣言と合わせて型検査し、成功した場合だけ一括で登録する。
同じローカル名の再定義は古い宣言を置き換え、依存する既存の宣言も再検査する。
失敗または Ctrl-C の後には、直前まで使えていた定義と補完候補が残る。
宣言と import が成功したときは値を表示せず、次の入力を待つ。
次の例で二つ目の継続プロンプトに入力した空行は、関数の定義を確定する。

```text
emet> twice :: Nat -> Nat
....> twice n = n + n
....>
emet> twice 3
=> 6
```

`import "lib/text.emet"` はセッション開始時の作業ディレクトリをルートにして既存のモジュールローダーで読む。
公開名の衝突、循環、存在しないパス、ルート外のパスは Emet ファイルと同じ diagnostic にする。
モジュールを読む操作と、式の評価中のファイル要求は別々に扱う。
セッションを終えると宣言と取り込みを破棄する。

### 端末での入力補完

Tab を押すと、カーソル位置で有効な名前のうち入力中の接頭辞に一致するものを提示する。
式ではスコープ内の名前、関数、コンストラクタを、型の位置では型名を、`List.` の後ではそのモジュールのメンバーを候補にする。
import のパスの引用符内ではルート内のディレクトリと `.emet` ファイルを補う。
ほかの文字列とコメントでは候補を出さない。
一件なら入力中の語を完成させ、複数なら共通部分まで補って候補を示し、ゼロ件なら入力を保つ。
補完は入力を評価せず、端末の候補一覧はプロンプトと同じ標準エラー出力に書く。
パイプでは候補一覧を出さない。

## 実装しないこと

直前の値を表す特別な名前と、終了後も残る入力履歴は別の提案で扱う。
ほかの言語の REPL は、その言語の仕様を決めてから個別に加える。

## 資源とアルゴリズム

REPL 固有の入力長と表示長の固定上限は設けない。
表示はエスケープしながら順に書き出す。
REPL で入力した式一つを、原稿から Emet を一回呼ぶ場合と同じ予算で評価する。
手数は評価器の `stepLimit`（現在 1 億手）を使い、末尾でない呼び出しの深さは同じ評価器の `depthLimit`（現在 1 万）で検査する。
式から呼ぶ関数は同じ手数を消費し、次の入力式で新たに数える。
超過は順に E04100、E04101 とする。
文字コード、BOM、CR は Emet ファイルと同じ規則で読み、不正な UTF-8 は G01001 とする。

入力を式の右辺として解析する場合は、仮の等式に付けた接頭辞をエラーの位置から引く。
構文エラー E01100 または E01101 の位置がすべて入力末尾の空範囲なら、式と diagnostics を保留する。
本実装はパーサーの未完と不正の区別を明示的に渡してもよい。

## 不変条件

1. R1。完成した式は一度だけ評価し、一つの値を一行で表示する。
2. R2。確定したエラーの直後に新しい式を送ると、同じ確定済みの環境にその式だけを送ったときと同じ値を得る。
3. R3。未完の式に続く行を LF で連結した結果は、連結後の式を一度評価した結果と等しい。
4. R4。端末では未完の入力を取り消して次の式を評価できる。パイプの正常出力には値だけが並ぶ。
5. R5。原稿と REPL は、もう一方の上限内で手数または深さが共通上限ちょうどなら成功し、一つ超えれば同じコードで失敗する。超過を報告した後の新しい式には上限を最初から適用する。
6. R6。次の入力から見える宣言と公開名は、成功した定義と import だけを順に適用した結果に等しい。
7. R7。補完はカーソル位置から見える候補だけを提示し、確定済みの環境を変えない。端末の候補一覧は標準エラー出力にだけ現れる。

| 境界 | 観察する結果 |
| --- | --- |
| 空の入力、空白行だけ | 値なし、終了 0 |
| 最終行が LF のない `9` | 値 9 が一度出る |
| `1 +` の後に `2` | 続きを一行読み、値 3 が一度出る |
| `(1` のまま EOF | 閉じ括弧の構文エラー一つ、終了 1 |
| `1 + )` の後に `4` | 先に構文エラー、次の式は値 4 |
| `1 +` の後で Ctrl-C、次に `7` | 通常のプロンプトに戻り、値 7 |
| 4097 バイトの文字列リテラル | 評価が成功し、閉じ引用符まで表示 |
| 定義の成功、続いて不正な再定義 | 元の定義を呼べる |
| import の成功、続いて公開名が重なる import | 前者の公開名だけを使える |
| 補完候補がゼロ、一つ、複数 | 入力を保持、語を完成、候補を提示 |
| 手数が `stepLimit` ちょうど、一手超過 | 成功、E04100 |
| 末尾でない呼び出しの深さが `depthLimit` ちょうど、一段超過 | 成功、E04101 |
| 手数を超える式の後の `42` | E04100 の後に値 42 |

## テスト設計

R1 から R7 をテスト名に入れ、通常の CLI に表の入力を渡して値、diagnostics、終了コードを照合する。
端末の継続プロンプト、Ctrl-C、EOF は疑似端末で試す。
`golem repl --help` の言語一覧と `golem repl emet` の起動を検査する。
日本語の位置と 4096 バイトを超える入力と表示を検査する。
R5 は同じ純粋な関数と引数を原稿と REPL から呼び、旧試作の 10 万手を超えて成功する例と、共通上限を超えて E04100 または E04101 になる例を照合する。
R5 の手数境界は評価器の計数結果で入力の消費量を確認し、上限ちょうどと一手超過の対を作る。
深さの境界は手数を上限内に保つ非末尾再帰で一段だけ変え、どちらの入口でも表の結果になることを検査する。
R6 は複数等式の関数、型の別名、データ型、公開名と非公開名、循環と再定義失敗後の回復を CLI に順に入力して調べる。
R7 は疑似端末で Tab を送り、定義前後の候補、名前の衝突、パスの補完、カーソルの後ろの文字列が保たれることを照合する。

R7 は候補一覧が端末の標準エラー出力に現れ、値を書き出す標準出力には混ざらないことも検査する。

## トレードオフ

未完の式を続けて書けるようにすると、閉じ忘れを報告する時点は EOF または確定した構文エラーまで遅れる。
端末では Ctrl-C でその式を取り消せる。
再定義時にモジュール全体を検査すると、既存の関数から型の合わない定義を呼ぶ状態を防げる。
固定のバイト上限を外すと長い定義を貼り付けられる一方、入力を保持するメモリと値を表示する時間は入力に応じて増える。
