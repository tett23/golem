# ADR 0437: パスとボックスモデルをレイアウトエンジンに入れる

Status: superseded-pending [{"part":"「閉じたパスの内側に文字を置く」の手順 3 の求め方とその理由の文、ボックスに中身が収まらないときのエラーのコードを決める時期","by":["docs/adr/0447-find-the-strip-intervals-by-pieces-between-vertices-and-crossings.md"],"kind":"replace"}]

## 文脈

今のレイアウトエンジンは、版面、段、傍注の領域、図版を矩形（`Rect`）で表し、回り込みの除外の領域を、段の側と幅と行の数で表す。
そのため、円や多角形の中に文字を組むこと、図版の輪郭に沿って本文を回り込ませることができない。

ロードマップの「パス」の項目は、パスをレイアウトエンジンに入れ、内部の矩形もパスとして扱い、閉じたパスの内側と開いたパスの上に文字を置けるようにすると書いている。
また、v1.0.0 の「ボックスモデル」をパスが入ることを考えて決め、開発者向けのマニュアルにレイアウトエンジンの章を設けるとしている。
ボックスモデルの項目は、2026-10-25 のマージでロードマップから消えていた（消したのが意図したものかは確かめていない）。

この ADR は、パスの型、ボックスモデル、閉じたパスの内側に文字を置く規則を決める。
開いたパスの上に文字を置くことと、図版の輪郭の書き方は、別の ADR で決める。
任意の位置のテキストフレームは [root ADR 0438](0438-place-text-frames-anywhere-on-a-page.md) で、SVG の図版のパスの描画の速さは [root ADR 0439](0439-benchmark-path-drawing.md) で決める。

## 調査した事項

origin/main（[9efdc4f89](https://github.com/tett23/golem/commit/9efdc4f89b3fec75abcd37c11abb3e1d909c6725)）で、次のことを確かめた。

- `Rect` は golem-pdf の `Golem.Pdf.Rect` にあり、`rectX`、`rectY`、`rectW`、`rectH`（`Sp`、左下を原点）を持つ（[Rect.hs#L10](https://github.com/tett23/golem/blob/9efdc4f89b3fec75abcd37c11abb3e1d909c6725/modules/golem-pdf/src/Golem/Pdf/Rect.hs#L10)、[root ADR 0088](0088-rect-type-in-golem-pdf.md)）。
  golem-layout-spec が export し直し、`PageGeometry` の版面、段、傍注の領域は `Rect` である。
- 回り込みの除外の領域（`Golem.Layout.Wrap` の `Exclusion`）は、段の側、幅、行の数だけを持ち、位置も `Rect` も持たない。
  除外は、図版の直後の段落の行だけを短くする。
- golem-layout（行分け、回り込み、ページ分割）は、golem-pdf と golem-layout-spec に依存しない。
  golem-length の依存は `base` と `text` だけである。
  `style.toml` を読む golem-project は、golem-length などに依存し、golem-svg と golem-pdf には依存しない。
- パスや曲線の表し方は、次のものがある。
  - golem-svg の `Segment`（`Rational`）と、塗りの規則、線端、角の形。
    SVG の図版は、golem-typeset が golem-svg の描画を golem-pdf の描画に直す。
  - golem-pdf の `Drawing.hs` の `PathSeg`（`Rational`、図版の座標系の中で 1/65536 に丸め、小数 6 桁で書く）。
  - golem-pdf の `Writer.hs` の `PathSegment`（`LineTo`、`CurveTo`、`Sp`）と、`Mark` の `CurveFill` と `StrokedPath`（`Sp` を小数 4 桁で書く）。
  - golem-typeset の `Box.hs` の段落スタイルの囲みの `Segment`（`Rational`）と、`RuleShape.hs` の `ShapeCurve`。
- 行分け（`breakParagraph`）は、行ごとに一つの幅を受け取り、行ごとに複数の区間を表せない（[KnuthPlass.hs#L396-L400](https://github.com/tett23/golem/blob/9efdc4f89b3fec75abcd37c11abb3e1d909c6725/modules/golem-layout/src/Golem/Layout/KnuthPlass.hs#L396-L400)）。
  格子の配置では、行はページと段で共通の行の位置（`pgLineGrid`）に乗る。
  自由な配置（[root ADR 0397](0397-paragraph-line-pitch-and-dimensional-spacing.md)）では、段落ごとの行送りで行を置き、格子に乗らない。
- 回り込みで脇の行が本文の文字の大きさの 8 字に満たないときは、エラー（G07022）にする。
- 仕様書は、式の言語の数を自然数、整数、有理数とし、浮動小数を持たず、演算をすべて正確に行うと決めている。
  レイアウトの長さは、整数の `Sp` と有理数で計算している。
- 仕様書の「幾何の隔離」は、意味論の IR が幾何を持たず、幾何はレイアウトの IR に隔離し、PDF の経路だけがそれを読むと決めている。
- [root ADR 0382](0382-figure-extent-and-captions.md)（採択、未実装）は、輪郭に沿う回り込みをパスの実装の後に回し、パスの記法をロードマップの「パス」に送っている。
- 開発者向けのマニュアルに、レイアウトエンジンの章は無い。

指示者は 2026-11-23 に、この項目の ADR を書くよう求めた。

## 実装すること

### パスの型

パスの型を、新しいパッケージ `golem-geometry` の `Golem.Geometry` に置く。
`golem-geometry` は、`base`、`text`、golem-length のほかに依存しない。
golem-layout、golem-layout-spec、golem-pdf、golem-typeset、golem-project が `golem-geometry` に依存する。

パスは、部分パスの並びとする。
部分パスは、始点と、線分（`LineTo`）と三次のベジェ曲線（`CurveTo`）の並びと、閉じているかの印を持つ。
円弧は、三次のベジェ曲線で近似して表す。
座標は `Sp`（整数）で表し、PDF と同じく左下を原点とする。

塗りの規則は、非ゼロの回転数（nonzero）を既定とし、偶奇（even-odd）も選べる。
線は、太さ、線端、角の形を持つ。

パスのデータの書き方（SVG のパスのデータの `M`、`L`、`C`、`Z` と絶対座標）を読む関数を、`Golem.Geometry` に置く。
golem-project は、この関数で `style.toml` のパスを読む。

### 矩形とパス

`Rect` を `Golem.Geometry` に移し、golem-pdf の `Golem.Pdf.Rect` から export し直す。
`Rect` は、閉じたパスの特別な形とし、`rectPath :: Rect -> Path` でパスに変えられる。
ページの描画、PDF の書き出し、行の配置の速さが要るところは、`Rect` のまま扱ってよい。

`Writer.hs` の `PathSegment` と `CurveFill` と `StrokedPath`、`Box.hs` の `Segment`、`RuleShape.hs` の曲線の形は、`Golem.Geometry` のパスにそろえる。
SVG の図版の表し方（golem-svg の `Segment` と、`Drawing.hs` の `PathSeg`）は、図版の座標系と書き出しの桁数を保つため、変えない。

### ボックスモデル

レイアウトの内部で、文字を置く領域と、文字を避ける領域を、ボックスとして表す。
ボックスは、形（閉じたパス）を持つ。
文字を置くボックスは、加えて、書く向き（横組みか縦組みか）と、行の始まりの辺（形の外接矩形の、行を並べる向きの始まりの辺）を持つ。
版面、段、傍注の領域、テキストフレームは文字を置くボックスで、回り込みの除外の領域は文字を避けるボックスである。
今の矩形の領域は、形が矩形のボックスである。

ここでいうボックスは、段落スタイルの囲み（`Golem.Typeset.Box`、[root ADR 0271](0271-paragraph-backgrounds-and-borders.md)）と、行ボックス（0397）とは別のものである。
用語集に、三つの違いを書く。

回り込みの除外の領域は、今の表し方（側、幅、行の数）のまま実装してよい。
除外の領域をボックスの形で表すのは、輪郭に沿う回り込みを決める ADR で行う。

### 閉じたパスの内側に文字を置く

形が矩形でない、文字を置くボックスに文字を流すときは、次のように行の区間を求める。

1. 行の帯は、行を並べる向きに、ボックスの段落スタイルの文字の大きさ（仮想ボディの高さ）の幅を持つ帯とする。
   最初の行の帯は、外接矩形の行の始まりの辺に接して置き、次の帯からは、ボックスの段落スタイルの行送りずつずらす。
   格子の配置か自由な配置かによらず、ボックスの中では行送りで並べる。
2. 曲線を折れ線に直す。
   有理数で de Casteljau の分割を繰り返し、分けた各曲線の二つの内側の制御点と、その曲線の始点と終点を結ぶ弦との距離の 2 乗が、どちらも (1/4 sp)² 以下になるまで分け、各曲線をその弦に置き換える。
   三次のベジェ曲線は制御点の凸包の中にあるので、元の曲線と弦の距離は 1/4 sp 以下になる。
3. 各行の帯について、帯と折れ線の内側の交わりから、帯の幅の全体にわたって内側にある区間を有理数で求める。
   求め方は、帯の両端の線（横組みでは水平線、縦組みでは垂直線）と、帯の中にある折れ線の頂点を通る同じ向きの線のそれぞれで内側の区間を求め、それらすべての共通部分を取る。
   折れ線の辺は直線なので、内側の区間の端は、これらの線のあいだでは線形に動き、共通部分が帯の全体で内側にある区間になる。
   区間の端は、内側に向けて sp に丸める。
4. 一つの行の帯に区間が二つ以上あるときは、幅がボックスの段落スタイルの文字の大きさの 8 倍以上の区間のうち、書く向きで最初に現れるものを使い、ほかの区間には文字を置かない。
5. 使える区間が無い行の帯は、飛ばす。
6. 行分けには、行ごとに一つの幅として、その区間の幅をそのまま渡す。
   行分けの関数は変えない。

回り込みと違い、幅の足りない行の帯をエラーにしない。
円や多角形の上下の端は、形として細くなるのが当然だからである。

ボックスに中身が収まらないときは、エラーにする（コードは実装のときに空き番号から決める）。
中身があるのに区間が一つも無い形（空のパス、細すぎる形）も、同じエラーにする。

### 記法

パスは、`style.toml` だけで書く（幾何の隔離）。
パスの値は、パスのデータの書き方の文字列とし、`unit` のキーで座標の単位を決める。
`unit` は `mm`（既定）、`pt`、`Q` のどれかとする。
原稿（意味論の IR）にはパスを書かない。
パスを使う最初の場所は、テキストフレーム（0438）である。

### HTML と EPUB

HTML と EPUB はリフローなので、パスの形を使わない。
閉じたパスのボックスの文字は、本文の流れの中の段落として書く。

### 文書とステータスの行

仕様書に、パスの型、塗りの規則、ボックスモデル、閉じたパスの内側に文字を置く規則を書く。
仕様書のパッケージの依存の図に、`golem-geometry` を書く。
開発者向けのマニュアルに、レイアウトエンジンの章を新しく設け、ボックスモデルとパスを書く。
用語集に、ボックス、段落スタイルの囲み、行ボックスの違いを書く。
ロードマップの「パス」の項目は、この ADR で決めた部分（パスの型、ボックスモデル、閉じたパスの内側に文字を置くこと）を消し、開いたパスの上に文字を置くことと、図版の輪郭の書き方と、輪郭に沿う回り込みを残す。

採択したら、[root ADR 0088](0088-rect-type-in-golem-pdf.md) のステータスに、`Rect` の置き場所をこの ADR が補ったことを記録する。
[root ADR 0382](0382-figure-extent-and-captions.md) のステータスに、パスの型をこの ADR で決め、輪郭の書き方は別の ADR で決めることを、注記で記録する。

## 実装しないこと

開いたパスの上に文字を置くことは、この ADR では実装しない。
字ごとの位置と回転を有理数で決める方法を、別の ADR で決める。
図版の輪郭を書く方法と、輪郭に沿う回り込みは、この ADR では決めない。
二次のベジェ曲線と、円弧をそのまま表す型は持たない。
一つの行の帯の二つ以上の区間に文字を置くこと（行をまたいで区間を流すこと）はしない。
行分けの関数を、一つの行に複数の区間を渡せる形に変えない。
原稿にパスを書く記法は作らない。
SVG の図版の表し方は変えない。

## 不変条件

- I1: 矩形 `r` について、`rectPath r` の内側の判定は、`r` の内側の判定と、すべての点で等しい。
- I2: 閉じたパスのボックスに文字を流したとき、どの字の仮想ボディの矩形も、そのパスを直した折れ線の内側にある。
- I3: 閉じたパスのボックスで、使う区間の幅は、ボックスの段落スタイルの文字の大きさの 8 倍以上であり、区間の無い行の帯には文字が無い。
- I4: 折れ線に直し終えた各曲線で、二つの内側の制御点と弦との距離の 2 乗は、どちらも (1/4 sp)² 以下である。
- I5: 閉じたパスのボックスに中身が収まらないとき、エラーになり、そのボックスに文字を置かない。
- I6: この ADR の前と同じ入力（パスを使わない本）の PDF の出力は、この ADR の前とバイト列まで等しい。
- I7: 一つの行の帯に、8 字に満たない区間と 8 字以上の区間があるとき、書く向きで最初に現れる 8 字以上の区間に文字を置く。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 矩形の版面だけの本 | 出力が変わらない | I1, I6 |
| SVG の図版と角の丸い囲みを持つ本 | 出力が変わらない | I6 |
| 円のボックスに 3 行の文 | 各字が折れ線の内側にあり、上下の端の行は短い | I2 |
| 帯の中に頂点が入る星形のボックス | 頂点が区間に食い込まず、各字が内側にある | I2 |
| 円の上端で区間の幅が 8 字未満の行の帯 | その行の帯を飛ばす | I3 |
| 凹んだ形で一つの帯に 8 字以上の区間が二つ | 書く向きで最初の区間にだけ文字を置く | I2, I3 |
| 一つの帯の最初の区間が 7 字で、二つめが 8 字 | 二つめの区間に文字を置く | I3, I7 |
| 円弧と S 字の曲線 | 制御点と弦の距離の 2 乗が (1/4 sp)² 以下 | I4 |
| 制御点がすべて一直線の上にある曲線 | 分けずに弦になる | I4 |
| ちょうど収まる中身 | 組める | I5 |
| 一行あふれる中身 | エラー | I5 |
| 空のパスに中身がある | エラー | I5 |

## 受けいれ条件

A1: 円と星形の閉じたパスのテキストフレームを持つ見本を組み、PDF を目で見て、文字が形の内側に置かれていることを確かめる。
見本は、見た目の回帰テストの見本に足す。
テキストフレームを置く手段は 0438 のマスターページのフレームなので、A1 は 0438 のマスターページのフレームを実装した後に確かめ、それまでこの ADR は `accepted-pending` のままとする。

## テスト設計

root ADR 0437 I1 から I7 を名前の先頭に置いたテストを、golem-geometry、golem-layout、golem-typeset に足す。
I1 は、小さな矩形と格子の点のすべてで、内側の判定を比べる。
I2、I3、I7 は、円、楕円、星形、凹んだ多角形のボックスを、テストの中でじかに作り、行の帯ごとの区間と、置いた字の仮想ボディの矩形を有理数で調べる。
I4 は、境界の表の曲線を折れ線に直し、分け終えた各曲線の制御点と弦の距離の 2 乗を有理数で比べる。
I5 は、境界の長さ（ちょうど収まる、一行あふれる）で確かめる。
I6 は、決定性の検査のハッシュと、今の golden が変わらないことで確かめる。
各テストは、実装の前に落ちることを確かめる。
root ADR 0437 A1 は、見た目の回帰テストの見本で確かめる。

## トレードオフ

一つの行の帯に区間が二つ以上ある形では、一つの区間にしか文字を置かないので、凹んだ形の残りが空く。
その代わりに、行分けの関数を変えずに済む。

I2 は、元の曲線ではなく、直した折れ線について成り立つ。
凹んだ曲線では、弦が元の曲線から最大で 1/4 sp 外に出るので、字の矩形が元の曲線からその分だけはみ出しうる。
1/4 sp は印刷で見分けられない大きさなので、区間をさらに縮めることはしない。
その代わりに、浮動小数を使わずに、ネイティブと wasm で同じ結果になる。

パッケージが一つ増え、描画のパスの表し方をそろえる書き換えが要る。
SVG の図版の表し方は残すので、パスの表し方は二つ（図版と、それ以外）になる。

開いたパスの上の文字と、図版の輪郭は、この ADR の後に別に決める必要がある。
