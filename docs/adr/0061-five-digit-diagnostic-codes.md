# ADR 0061: diagnostic のコードを、段階の 2 桁と番号の 3 桁の 5 桁にする

ステータス: 採択

## 文脈

diagnostic のコードは、`G` と 4 桁の数字である（[golem-syntax ADR 0001](../golem-syntax/adr/0001-source-spans-and-diagnostics.md)、[golem-driver ADR 0016](../golem-driver/adr/0016-output-and-layout-diagnostic-codes.md)）。
上 2 桁が、diagnostic を出す段階（01 は構文、02 は評価、03 はプロジェクト、04 は文書の組み立て、05 は lint、06 はプラグイン、07 はレイアウト、08 は出力、09 はプリフライト）を表す。
一つの段階に使える番号は、下 2 桁の 100 個である。

仕様書の「設計原則」に「一つのコードに一つの原因」を加え、原因ごとにコードを分けることにした。
評価の区分（02）は、今 95 個を使っており、v0.1.0-rc3 の草案（[ADR 0056](0056-printings-diagnostic-codes-by-cause.md)、[ADR 0060](0060-page-break-command-codes-by-cause.md)）を入れると、残りは G0200 だけになる。
ロードマップの v1.0.0 の「一つのコードに一つの原因の監査」で、今のコードのうち原因をまとめているもの（G0306、G0701、G0810、G0811、G0737 など）を分けると、ほかの区分も足りなくなりうる。
メンテナーは、コードの形を変える ADR を起こすと決めた。

### 考えた案

1. **番号を 3 桁にする（5 桁のコード）**：`G` と、段階の 2 桁と、番号の 3 桁にする（G02058 など）。一つの段階に 1000 個を使える。今のコードは、番号の前に 0 を一つ足せば新しい形になる（G0258 は G02058）。
2. **段階の番号を足す**：番号が足りなくなった段階に、空いている段階の番号（10 から 99）を割り当てる。今のコードは変わらないが、段階と上 2 桁が一対一でなくなり、コードから段階を読めなくなる。どの段階に何番を足したかを覚える必要がある。
3. **段階を表すのをやめる**：4 桁の通し番号にする。段階の情報を失う。

1 を採る。
コードから段階を読めるという今の性質を保ち、変換が一つの規則で決まり、どの段階でも当分は足りるからである。
2 は今のコードを変えずに済むが、規則が二つになる。
v1.0.0 までは互換を壊してよいので、今のうちに形を一つにそろえるほうが単純である。

## 実装すること

### コードの形

- diagnostic のコードを、`G`、段階の 2 桁、番号の 3 桁の 5 桁にする。段階の 2 桁は今と同じである。
- 今のコードは、段階の 2 桁と番号の 2 桁のあいだに `0` を一つ足して、新しいコードにする。G0117 は G01017、G0258 は G02058、G0910 は G09010 になる。番号の意味は変えない。
- 廃止したコードも、同じ規則で新しい形にする。番号を再利用しない規則（仕様書）は変えない。
- 新しく割り当てるコードは、番号の 3 桁のうち、今のコードが使わない 100 から 999 の範囲から取る（G02100 から）。000 から 099 は、今のコードの写しのために取っておく。
- この ADR の採択の時点で採択している草案のコード（G0296 など）も、同じ規則で写す（G02096）。

### 書き換える場所

- golem-syntax の `DiagnosticCode` の値、`noticeCodes`、`profileDependentCodes`、`preflightCodes`、`diagFacts`、diagnostic を出すすべてのモジュールのコードの文字列とテスト。
- `docs/diagnostics.md` の節の見出し、本文のコード、「使っていない番号」。見出しが変わるので、GitHub のアンカー（`#g0117`）も `#g01017` に変わる。LSP の `codeDescription` の URL（`Golem.Driver.Explain`）も変わる。
- 仕様書、markup.md、glossary.md、roadmap.md、README、CONTRIBUTING と、二つのマニュアルのコード。
- 二つのマニュアルと fixture の `manifest.toml` の `silence-notices`、プリフライトの設定の `preflight.toml` のコード。
- `golem explain` のコードの形の検査（`G` と 4 桁）を、5 桁にする。
- コミット済みの ADR（`docs/adr/` と `docs/<モジュール>/adr/`）のコードも書き換える。ADR はステータスの行とリンクのほかを変えられないので（adr-guard）、このコミットだけを adr-guard の書き換えの許可で通す（「コミット済みの ADR の書き換え」）。

書き換えは、決まった規則の置き換えなので、シェルのスクリプト（`sed`）で一度に行い、スクリプトはコミットしない。

### 4 桁のコードの廃止

- 4 桁のコードは、この ADR の実装で廃止し、受け付けない。Golem の利用者はメンテナーだけなので、移行の期間を設けない。
- `golem explain` に 4 桁のコードを渡すと、ほかの形の誤ったコードと同じく使い方の誤りとする。
- `silence-notices` に 4 桁のコードを書くと、ほかの形の誤ったコードと同じく G0324（新しい形では G03024）のエラーとする。
- 監査の記録（`docs/audits/` など）は書き換えないので、4 桁のコードが残る。`docs/diagnostics.md` の冒頭に、4 桁のコードの読み替えの規則（段階の 2 桁と番号の 2 桁のあいだに `0` を一つ足す）を一度だけ書く。各節に旧コードの行は置かない。

### コミット済みの ADR の書き換え

- コミット済みの ADR の 4 桁のコードを、ほかの文書と同じ規則で 5 桁に書き換える。コードの形だけを変え、ADR の決定の中身は変えない。
- 書き換えは、ほかの変更と混ぜない一つのコミットにする。
- pre-commit hook は、環境変数 `ADR_GUARD_ALLOW` に理由を入れて通す。CI の `adr` ジョブ（`check-range`）を通すため、コミットメッセージに次のトレーラーを付ける（[adr-guard の ADR 0008](https://github.com/tett23/adr-guard/blob/main/docs/adr/0008-allow-intentional-adr-rewrites.md)）。

  ```
  ADR-Guard-Allow: diagnostic のコードを 5 桁に改めるため（docs/adr 0061）
  ```

- Claude Code の hook は、この許可を見ないので、書き換えはシェルから行う。
- 監査の記録（`docs/audits/` など）は、コミットの後に変えてはならない記録なので、書き換えない。

### 実装の順

v0.1.0-rc3 の草案は 4 桁のコードで書いてある。
この ADR は、それらの草案の実装がすべて終わった後に実装し、その時点のすべてのコードを一度に書き換える。
先に実装すると、ほかの草案のコードを実装のたびに読み替える手間が生じる。

### ADR のステータス

- [golem-syntax ADR 0001](../golem-syntax/adr/0001-source-spans-and-diagnostics.md) と [golem-driver ADR 0016](../golem-driver/adr/0016-output-and-layout-diagnostic-codes.md) のステータスの行に「、コードの形は [docs/adr 0061](0061-five-digit-diagnostic-codes.md)」を足す。

## 実装しないこと

- 番号の意味を変えること、コードを分けること。原因ごとに分けるのは、個別の ADR と v1.0.0 の監査で行う。
- 4 桁のコードを受け付ける移行の期間を設けること。

## テスト設計

テストを先に書き、今の実装で失敗することを確かめる。

- golem-syntax：すべてのコードが `G` と 5 桁であり、段階の 2 桁が出す段階と一致すること（今の 4 桁の検査を置き換える）。
- golem-driver の diagnostics.md とソースの一致の検査（`explanations`）が、5 桁で通ること。
- golem-cli：`golem explain G02058` が説明を表示し、`golem explain G0258` が使い方の誤りになること。
- golem-project：`silence-notices = ["G0262"]` が G03024 のエラーになること。
- 決定性の検査と二冊のマニュアルが、diagnostic を一つも出さずに組めること。

## トレードオフ

- すべてのコードが変わるので、覚えたコードや CI で集計していたコードが使えなくなる。今の利用者はメンテナーだけであり、1.0.0 の前に済ませるほうが費用が小さい。
- コードが 1 桁長くなる。
- 000 から 099 を写しのために取っておくので、各段階で新しく使えるのは 900 個である。今の使い方から見て、当分は足りる。
