# ADR 0330: 未宣言のプラグインと未提供のフィルタを区別する

ステータス: 採択（未実装）

## 文脈

`[[filters]]` の `plugin` が指すプラグインを見つけられないときは、プラグインの宣言または参照名を直す必要がある。
プラグインを読み込めても `filter` がそのプラグインによる提供名でなければ、直すのはフィルタ名である。
現行の CLI で二つのマニフェストをビルドすると、どちらも G06010 を返した。

## 実装すること

未宣言のプラグイン名には G06010 を保つ。
読み込んだプラグインにないフィルタ名には G06107 を割り当てる。
メッセージにはプラグイン名とフィルタ名を残す。
本実装では、前者は `[[filters]]` の `plugin` の値、後者は `filter` の値を指す。

## 実装しないこと

プラグインのダウンロード、取得先の決定、ロックファイルの diagnostic、Emet 関数で書いたフィルタの検査は変更しない。

## 不変条件

1. F1：未宣言のプラグインには G06010 が一度出て、宣言済みのプラグインによる未提供のフィルタには G06107 が一度出る。
2. F2：フィルタが存在すれば二つの diagnostic は出ない。

| プラグイン | フィルタ | 結果 |
| --- | --- | --- |
| 未宣言 | 任意 | G06010 |
| 宣言済みで読み込み成功 | 未提供 | G06107 |
| 宣言済みで読み込み成功 | 提供あり | どちらも出ない |

## テスト設計

`experiments/diagnostics/baseline.mjs` は同梱の `auto-tcy.wasm` の SHA-256 から一時キャッシュとロックファイルを作り、外部に接続せず CLI を動かす。
未宣言の `ghost.x` と、読み込んだ `tcy` の `missing` に対する F1 を比較する。
試作では現行と同じくマニフェスト先頭を指す。
値の位置と F2 は本実装の受け入れテストに加える。

## トレードオフ

フィルタの宣言エラーを拾う CI は G06107 も扱う必要がある。
プラグインの宣言を足すか、提供されるフィルタの名前に直すかを、メッセージの比較なしで振り分けられる。
