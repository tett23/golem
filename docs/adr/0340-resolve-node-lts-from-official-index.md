# ADR 0340: CI で使う Node.js の最新 LTS を公式のリリース一覧から選ぶ

ステータス: 却下

## 文脈

[PR #942 の wasm ジョブ](https://github.com/tett23/golem/actions/runs/42981201241/job/130399338741) では、Node.js のバージョン一覧を取得する処理が 3 回とも GitHub App の API 利用上限に達し、テストを開始できなかった。
同じ実行で成果物を待っていたジョブも HTTP 403 で停止した。
成果物の待機は [ADR 0333](0333-wait-for-ci-artifacts-with-fewer-api-requests.md) が扱う。

## 実装すること

GitHub Actions で最新 LTS を使うジョブは、Node.js 公式サイトのリリース一覧から、LTS のコードネームが付いたリリースのうちバージョン番号が最大のものを選ぶ。
各ジョブは選んだバージョンを setup-node に渡す。
ランナーにそのバージョンがあれば再利用する。
一覧を取得できない場合や候補がない場合は、理由を出力してジョブを失敗させる。

## 実装しないこと

成果物の取得、GitHub の認証方法、Node.js を使わないジョブには変更を加えない。

## 不変条件

1. 一覧の順序によらず、LTS の候補からメジャー、マイナー、パッチの順に数値を比較して最大のバージョンを返す。
2. 有効な LTS を確定できない場合は非ゼロで終了し、後続のセットアップを実行しない。

| 入力 | 期待する結果 |
| --- | --- |
| 空の一覧、または Current のみ | 失敗 |
| LTS が一つ | そのバージョン |
| LTS の v24.9.0 と v24.10.0、新しい Current | v24.10.0 |
| 取得失敗、または壊れた JSON | 失敗 |

## テスト設計

固定のリリース一覧を使って不変条件 1 と 2 を検査し、それぞれの番号をテスト名に含める。
実際の CI ではセットアップ後の node --version と選んだバージョンが一致することを確認する。

## トレードオフ

最新 LTS を選ぶ処理は Node.js 公式サイトの可用性に依存する。
ランナーに該当バージョンがない場合はインストールが必要で、配布物の取得にも失敗しうる。

## 参考文献

- [Node.js のリリース一覧](https://nodejs.org/dist/index.json)
- [actions/setup-node](https://github.com/actions/setup-node)

## 却下の理由

Node.js 公式サイトから一覧を取得する方法でも、配布元の障害で CI が停止しうる。
最新 LTS の解決に使う外部依存を増やす効果が見合わないため、採用しない。
