# ADR 0222: 行分割の不変条件の述語が判定しなかった仕様の点を決める

ステータス: 採択→（`_` を含む語の分綴と改行）は [golem-layout ADR 0031](../golem-layout/adr/0031-line-breaks-after-low-lines-in-identifiers.md)、L7 の上限は [ADR 0236](0236-record-what-implementations-decided-found-by-the-second-review-of-2026-11-08.md)

## 文脈

[ADR 0209](0209-line-breaking-invariants-by-exhaustive-small-inputs.md) は、仕様書の文から一つの述語に決まらないところを、述語を書かずにプルリクエストの説明に挙げると決めた。
その実装（[#655](https://github.com/tett23/golem/pull/655)）は、次の五つを挙げた。
どれも今の述語では違反にならないが、仕様が振る舞いを決めたから違反にならないのではない。
述語が判定を控えたか、実装の今の振る舞いを読み方として採っただけである。

- **L6**：伸びるグルーのない行が行長に足りないとき。
- **L11**：和文の字と欧文の語のあいだに語間の空白を書いたとき。
- **L13**：欧文の語の中の両用の字の突き出しの上限にする、字の送り。
- **句点を含む語の分綴**：`table.` は一つの箱で分綴しないが、`hyphenation.` は `hy`、`phen`、`ation.` に分綴する。L9 の「前の部分は 2 字以上、後の部分は 3 字以上」は、引用符と句点も字に数える。
- **行より長い行頭禁則の字の並び**：2 字の行に `」」」」」` を組むと、はみ出す行が一つできる。仕様書の「送り出せる候補がない場合、つまり一つの箱が行長より長い場合に限り」と合わない。

仕様書の「行分割」の節も、最初の三つを「述語は、次の場合を判定しない」として載せている。
[ADR 0206](0206-pagination-points-the-invariants-did-not-decide.md) が改ページの同じ種類の点を決めたのと同じく、この ADR は五つを決める。
三つは今の振る舞いを規則にし、述語で判定する。
二つ（L13 と句点を含む語）は振る舞いを変える。

語間の空白の隣の禁則（[golem-layout ADR 0028](../golem-layout/adr/0028-kinsoku-across-spaces-and-explicit-hyphens.md)）と、字幅の伸縮の刻み（[golem-layout ADR 0029](../golem-layout/adr/0029-expansion-steps-never-overflow-the-line.md)）は、既知の不具合として別の ADR で直す。
`FSpace` と `@need-lines` の関係は改ページの点であり、ここでは扱わない。

### L6：伸びるグルーのない行

最後の段階は、収まらない箱を次の行へ送り出し、送り出した行を「伸びの許すかぎり字間を空けて行長にそろえ」る（仕様書の「行分割」の節）。
Golem の伸びは、グルーの伸びと字幅の伸縮だけである。
和文の字のあいだには、アキ量のセットの (0, 0, 0.1zw) のグルーがあり、グルーの伸びの比には上限がない（[`glueRatio`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-layout/src/Golem/Layout/KnuthPlass.hs#L494-L511)）。
そのため、伸びるグルーが一つでもある行は、行長にそろう。
足りないまま残るのは、行に伸びるグルーがない場合である。
一字だけの行、一つの欧文の語だけの行が当たる。

述語の [`l6Justified`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-layout/test/LineBreakInvariants.hs#L245-L262) は、この行を判定しない。
判定しないので、伸びるグルーがない行が、伸縮の限度に達する前に止まっても気付かない。
[#655](https://github.com/tett23/golem/pull/655) によれば、判定を控えなければ、最後の段階の一字の和文の行のすべてが L6 を破る。

### L11：書いた空白を挟む和文と欧文

`漢 a` のように空白を書くと、和文の字と欧文の語のあいだの項目は、語間の空白のグルー一つだけになる。
和欧間の空き（既定は (八分, 四分, 二分)）は足さない。
`normalize` は、グルーの後の箱を段落の始まりと同じに扱い、空きを入れないからである（[`Japanese.hs`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-layout/src/Golem/Layout/Japanese.hs#L1133)）。
仕様書は、ここに和欧間の空きを足すかを定めていない。

### L13：欧文の語の中の両用の字の送り

突き出しの量は、行の端になる字の送りに表の比を掛けた値である（[golem-layout ADR 0014](../golem-layout/adr/0014-protrusion-amount.md)）。
欧文の語の箱では、[`wordItems`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-layout/src/Golem/Layout/Japanese.hs#L1039-L1043) の `protAt` が、字の送りを `ceAdvance` で引く。
golem-typeset の `ceAdvance` は、字の文字クラスで書体を選ぶ（[`Flow.hs`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-typeset/src/Golem/Typeset/Flow.hs#L1077-L1078)、[`shapingOf`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-typeset/src/Golem/Typeset/Fonts.hs#L506-L509)）。
区間の外の `”` は終わり括弧類なので（[`CharClass.hs`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-layout/src/Golem/Layout/CharClass.hs#L40-L41)）、和文の書体の送り（全角）を引く。
一方、`said”` の `”` は欧文の語に入り（[`Japanese.hs`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-layout/src/Golem/Layout/Japanese.hs#L589-L599)）、語の最初の字の書体、つまり欧文の書体で組む。
そのため、突き出しの量は和文の `”` の送りの 7 割になり、欧文の書体で組んだ `”` の幅を超えうる。
上限の `min w` は語の箱の幅であり、字の幅ではない。
超えた分は、`”` の前の字が版面の外に出る。

この読みはコードから得たもので、`protrusion = true` の本の PDF では確かめていない。
リポジトリの本（二つのマニュアルと complex fixture）は `hanging-punctuation` だけを使い、`protrusion` を書いていない。
`hanging-punctuation` だけでは `ceProtrusion` が偽になり、欧文の語は突き出さない。

述語の [`l13Protrusion`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-layout/test/LineBreakInvariants.hs#L429-L450) は、字だけの送り（`ceAdvance`）を上限にするので、この行を違反としない。
仕様書の「行分割」の節も、この読み方を書いている。

### 句点を含む語の分綴

欧文の語の箱は、空白でない欧文の字の並びであり、句点、読点、引用符を含む。
`wordItems` は、要素から末尾のハイフンとダッシュの連なりだけを除いて、分綴のパターンに渡す（[`wordItems`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-layout/src/Golem/Layout/Japanese.hs#L1019-L1024)）。
パターンは、語の前後に語の境の印 `.` を付けて照らす（[`patternPoints`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-layout/src/Golem/Layout/Hyphenation.hs#L55-L63)）。
`table.` は `.table..` として照らされ、句点が語の字として、語の境の印と同じ字で並ぶ。
`table` の `ta-ble` の位置は、語末の境の印を含むパターンで決まるので、`table.` では失われる。
`hyphenation.` の位置は語末の境に依らないので残り、最後の部分は `ation.` になる。
語の後に句点があるかどうかで分綴が変わる理由は、仕様書にない。
前に 2 字、後に 3 字を残す規則も、句点と引用符を字に数える。

TeX は、分綴する語を、グルーの後の最初の字から、字（`\lccode` が 0 でない文字）でない文字の前までとする（The TeXbook の付録 H）。
語の後の句点と、語の前の引用符は語に含めず、`\lefthyphenmin` と `\righthyphenmin` も字だけを数える。

### 行より長い行頭禁則の字の並び

2 字の行の `」」」」」` では、どの字のあいだも行頭禁則で分けられない。
行長に収まる分割の候補がないので、最後の段階ははみ出す行を一つ作る。
L5 は「行長に収まる分割がない」はみ出す行を許すので、違反にならない。
ただし、どの箱も行長より長くはないので、仕様書の「送り出せる候補がない場合、つまり一つの箱が行長より長い場合に限り」の「つまり」以下は、この場合を言い表していない。

## 実装すること

### 1. L6：伸びるグルーのない行は、伸びを使い切った長さで足りないままにする

規則：最後でない行に伸びるグルーがなければ、行は行長にそろわなくてよい。
ただし、字幅の伸縮を受ける箱があり、伸縮が限度に達していないなら、足りない量は刻み一つ分の伸縮より小さい（[golem-layout ADR 0029](../golem-layout/adr/0029-expansion-steps-never-overflow-the-line.md) の E6）。
足りない行は、今のとおり行頭にそろえて置く。

- 述語 `l6Justified` の「判定しない」枝を、この規則の判定に改める。
- 仕様書の「述語は、次の場合を判定しない」から L6 を除き、「送り出した行は伸びの許すかぎり字間を空けて行長にそろえ」の後に、「伸びるグルーのない行（一字だけの行、一つの欧文の語だけの行）は、行長に足りないまま行頭にそろえる」と、この ADR へのリンクを足す。

### 2. L11：書いた空白は、和欧間の空きの代わりになる

規則：和文の字と欧文の語のあいだに語間の空白を書いたときは、そのあいだの項目は語間の空白のグルー一つだけであり、和欧間の空きを足さない。
今の振る舞いのままである。

- 述語 `l11Aki` の、空白のグルーを含む組を判定から除く条件を消し、その組を、空白のグルー一つだけで、和欧間の空きのグルーがないことの判定に改める。
- 仕様書の「述語は、次の場合を判定しない」から L11 を除き、アキ量のセットの節の和欧間の空きの文に「和文の字と欧文の語のあいだに語間の空白を書いたときは、和欧間の空きを足さず、語間の空白だけを入れる」と、この ADR へのリンクを足す。

### 3. L13：欧文の語の中の字は、語を組む書体の送りで突き出す

規則：欧文の語の箱の端の字の突き出しの量は、語を組む書体でのその字だけの送り（トラッキングとカーニングを含まない）に、表の比を掛けた値である。

- golem-layout の `ComposeEnv` に、語を組む書体で一字の送りを返す欄（`ceWordCharAdvance :: Look -> Text -> Char -> Rational`、語と字を受け取る）を足す。既定の環境（`defaultComposeEnv`）では `ceAdvance` と同じ値を返す。
- `wordItems` の `protAt` は、この欄で送りを引く。
- golem-typeset の `composeEnv` は、`ceWordAdvance` が語に使う書体（語の最初の字の `shaping`）で、その字の送りを返す。
- 述語 `l13Protrusion` の上限を、`ceWordCharAdvance` の送りに改める。テストの送りの表では、欧文の語の中の両用の字は 1/2 em になる。
- 仕様書の「行分割」の節の L13 の文と、`[composition]` の `protrusion` の段落の「字の送り」を、この規則に改める。

### 4. 分綴のパターンは、語の字だけを見る

規則：分綴のパターンに渡すのは、要素の最初の字（Unicode の文字の一般カテゴリが L の字）から、その後の最初の字でない文字の前までである。
要素の前の字でない文字（引用符など）と、後の文字（句点、読点、引用符、アポストロフィの後など）は、パターンに渡さず、分綴した最初の部分と最後の部分に戻す。
前に 2 字、後に 3 字を残す規則（`patLeftMin`、`patRightMin`）は、パターンに渡した字だけを数える。
TeX の付録 H の規則と同じである。

- `wordItems` の `pieces` で、要素を前の字でない文字、パターンに渡す字、後の文字の三つに分ける。末尾のハイフンとダッシュの連なりを除く今の規則は、後の文字に含まれる。
- 結合文字は、今のとおり前の字と一つの単位として扱う。
- 述語 `l9Hyphens` の 2 字と 3 字は、分けた前と後の部分の字（一般カテゴリが L の字）を数える。
- 仕様書の「行分割」の節の分綴の段落に、この規則と、この ADR へのリンクを足す。
- `table.` が `ta` と `ble.` の二つの箱と分綴の罰点になることを、テストの送りの表のテスト（「字の送りの表」）に足す。

### 5. 行長に収まる候補がない場合の文

規則：行長に収まる分割の候補がない場合に限り、はみ出す行を作る。
候補がないのは、一つの箱が行長より長い場合と、行頭禁則、行末禁則、分離禁止で分けられない箱の並びが行長より長い場合である。
はみ出した行は、禁則を破って分けない。
[ADR 0210](0210-warn-overfull-lines-in-build.md) の G07105 が知らせる。

- 仕様書の「送り出せる候補がない場合、つまり一つの箱が行長より長い場合に限り、行長からはみ出す行を作る」を、上の三文に改める。
- 振る舞いと述語は変えない。L5 の今の述語（行長に収まる分割がない）が、この規則を確かめている。

### 6. [ADR 0209](0209-line-breaking-invariants-by-exhaustive-small-inputs.md) の不変条件の読み方

この ADR の後の L5、L6、L9、L11、L13 は、次のとおりに読む。

| 不変条件 | [ADR 0209](0209-line-breaking-invariants-by-exhaustive-small-inputs.md) の実装での読み方 | この ADR の後 |
| --- | --- | --- |
| L5 | 行長に収まる分割がないはみ出す行を許す（仕様書の文と合わない） | 同じ。仕様書の文を 5 のとおりに改める |
| L6 | 伸びるグルーのない短い行は判定しない | 伸びるグルーのない行は足りなくてよく、伸縮が限度に達していなければ足りない量は刻み一つ分より小さい |
| L9 | 2 字と 3 字は、引用符と句点も数える | パターンに渡した字だけを数える |
| L11 | 空白を書いた和文と欧文の組は判定しない | 語間の空白のグルー一つだけで、和欧間の空きはない |
| L13 | 上限は、その字だけの `ceAdvance` | 上限は、語を組む書体でのその字の送り |

採択したら、[ADR 0209](0209-line-breaking-invariants-by-exhaustive-small-inputs.md) のステータスの行に「（不変条件の L5、L6、L9、L11、L13 の読み方）は ADR 0222」を足す。

### 7. 既知の不具合の一覧と、固定した数

この ADR は、既知の不具合の一覧（`lineBugs`）の項目を足しも消しもしない。
4 で分綴の位置が変わり、列挙の分割の候補が増えるので、各項目の固定した数（`lbCounts`）と、L7 の素朴な探索の候補の数の上限に当たる入力の数を、段 3 まで数え直す。
[golem-layout ADR 0028](../golem-layout/adr/0028-kinsoku-across-spaces-and-explicit-hyphens.md) と [golem-layout ADR 0029](../golem-layout/adr/0029-expansion-steps-never-overflow-the-line.md) のどちらかが先に入っていれば、残った項目だけを数え直す。

### 8. 出力の変化

1、2、5 は振る舞いを変えない。
3 は、`protrusion = true` の本で、区間の外の欧文の語の端の両用の字（引用符、ダッシュ）の突き出しを小さくする。
4 は、句点、読点、引用符の付いた英語の語を分綴できるようにするので、英語を含む段落の分割を変えうる。
実装のプルリクエストで、golden、`scripts/visual/` の参照、二つのマニュアルと complex fixture の決定性のハッシュの変化を確かめ、説明に書く。

## 実装しないこと

- **字間を空ける和文の行の調整の順**：JLReq の 3.8 の、空きを広げる約物と字間の優先の順は、アキ量のセットの値が決める今のままとする。
- **句読点を含む語の中の分綴**：`U.S.A.` のように、字でない文字が語の中にある要素は、4 の規則のとおり最初の字の並び（`U`）だけをパターンに渡し、実質は分綴しない。語の中の句読点を飛ばして分綴する規則は作らない。
- **英語のほかの言語のパターン**：[ADR 0209](0209-line-breaking-invariants-by-exhaustive-small-inputs.md) と同じく扱わない。
- **語の最初の字が両用の字の語の書体**：区間の外の `“said` は、語の最初の字の `“` で書体を選ぶ。この書体の選び方は 3 と別の点であり、この ADR では変えない（「メンテナーが決めること」の 6）。
- **禁則と伸縮の既知の不具合**：[golem-layout ADR 0028](../golem-layout/adr/0028-kinsoku-across-spaces-and-explicit-hyphens.md) と [golem-layout ADR 0029](../golem-layout/adr/0029-expansion-steps-never-overflow-the-line.md) で直す。

## 不変条件

行の幅を W、行末の突き出しの量を P とする。

- **D1（L6）**：最後でない行で `lineOverfull` が偽の行は、最後の項目の終わりが W + P にちょうど来る（丸めの 1 sp を許す）。ただし、伸びるグルーのない行は W + P より前で終わってよく、伸縮を受ける箱があり伸縮が限度に達していなければ、足りない量は刻み一つ分の伸縮より小さい。
- **D2（L11）**：和文の字と欧文の語のあいだに語間の空白を書いた組では、そのあいだの項目は語間の空白のグルー一つだけであり、和欧間の空きのグルーはない。
- **D3（L13）**：欧文の語の箱の端の字の突き出しの量は、語を組む書体でのその字だけの送り（`ceWordCharAdvance`）に表の比を掛けた値を 1000 で切り捨てて割った値であり、その送りを超えない。
- **D4（L9）**：パターンの分綴で分けた行の前の部分は、パターンに渡した字を 2 字以上、後の部分は 3 字以上持つ。パターンに渡すのは、要素の最初の字から次の字でない文字の前までである。
- **D5（L9）**：要素の前後に字でない文字を付けても（`table` と `table.`、`“table”`）、パターンの分綴の候補の位置（字の数で数える）は変わらない。
- **D6（L5）**：はみ出す行（`lineOverfull` が真）は、行頭禁則、行末禁則、分離禁止を破らずに行長に収める分割がない行に限る。はみ出す行の中でも、禁則を破る位置では分けない。

境界の入力：

| 量 | 調べる値 |
| --- | --- |
| 伸びるグルー | なし（一字、一語）、一つ、和文の字間のグルーだけ |
| 伸縮 | なし、限度に達する、限度に達しない（刻みの切り捨ての残り） |
| 和文と欧文のあいだ | 空白なし、空白一つ、空白二つ（一つにまとめる）、行の端 |
| 区間の言語 | なし、`en`、`ja` |
| 語の端の字 | 欧文の字、`”`、`—`、`’`、`.` |
| 語の前後の字でない文字 | なし、後に `.`、後に `.”`、前に `“`、語の中に `’`（`I’ll`） |
| パターンに渡す字の数 | 4（分綴しない）、5（`table`）、11（`hyphenation`） |
| 行頭禁則の字の並び | W − 1、W、W + 1、2W + 1 |

## テスト設計

テストを先に書き、今の実装で失敗することを確かめてから実装する。
テストの名前には、D1 から D6 の番号を入れる。
1、2、5 は今の振る舞いを規則にするので、述語を改めたテストは今の実装で通る見込みである。
先に失敗させられるのは、手で作った出力の述語のテストと、3 と 4 のテストである。

- **D1**：伸びるグルーのない一語の行で、伸縮が限度に達していないのに刻み一つ分より多く足りない出力を手で作り、L6 だけが違反を返すこと。一字の和文の行が足りない出力は違反としないこと。
- **D2**：`漢 a` を組んだ項目に和欧間の空きのグルーを足した出力を手で作り、L11 だけが違反を返すこと。
- **D3**：テストの送りの表で `a”` の行末の突き出しが 1/2 em × 0.7 であること。今は 1 em × 0.7 になるので失敗する。golem-driver のテストで、`protrusion = true` の段落の行末の `said”` の突き出しが、欧文の書体の `”` の送りの 7 割であること。
- **D4、D5**：`table.`、`“table”`、`table,` が `ta` の後に分綴の罰点を持つこと。今は持たないので失敗する。`hyphenation.` の候補の位置が `hyphenation` と同じであること。`I’ll` は分綴しないこと。
- **D6**：`」」」」」` を 2 字の行で組み、はみ出す行が一つで、その中で分けないこと（今の振る舞い）。
- 列挙：段 2 までのすべての入力で、改めた L5、L6、L9、L11、L13 が違反を返さないこと。7 で数え直した固定の数が合うこと。

## トレードオフ

L6 と L11 と 5 は、今の振る舞いを規則にする。
振る舞いが良いから選んだのではなく、仕様書と述語の判定の外にあった振る舞いを、判定の中に入れるためである。
規則にすると、変えるときに ADR が要る。

L6 で一字だけの行が行長に足りないまま残ることは、JLReq の行の調整（3.8）の、行長にそろえる考え方には合わない。
ただ、一字の行には空ける字間がなく、行長にそろえるには字の前か後に空きを足すほかない。
空きの位置を決める規則は JLReq にも仕様書にもなく、この ADR で作るほどの頻度でもない。

L11 で書いた空白を和欧間の空きの代わりにすると、空白を書く書き手と書かない書き手で、和欧間の空きの幅が変わる（語間の空白は 1/4 em 前後、和欧間の空きは四分の前後で伸縮する）。
空白に和欧間の空きを足せば、書き手の空白は空きを広げるだけになり、空白を書く書き手は意図より広い空きを得る。
原稿の空白を空きに置き換えれば、書いた文字を黙って変えることになる。

3 は、突き出しの量を決める関数を一つ足す。
`ceAdvance` に語を渡す形に変える案もあるが、`ceAdvance` を使うほかの箇所（和文の字の箱）を変えることになる。

4 は、英語の語の分綴の候補を増やす。
リポジトリの本には英語の段落が少ないが、語の後に句点を持つ語は多いので、golden が変わる見込みがある。

## メンテナーが決めること

1. **L6**：推奨は、伸びるグルーのない行は行長に足りないまま行頭にそろえ、伸縮が限度に達していないときの足りない量を刻み一つ分より小さいとすることである。仕様書の「伸びの許すかぎり」の今の振る舞いを規則にし、伸縮の止まり方だけを判定に加える。
   - 退けた案の一つは、今のとおり判定しないことである。伸縮が限度より前で止まる不具合を、述語が見逃す。
   - 二つめは、一字の行の前か後に空きを足して行長にそろえることである。JLReq も仕様書も空きの位置を決めておらず、頻度の低い行のために規則を作ることになる。
2. **L11**：推奨は、書いた空白を和欧間の空きの代わりとし、空きを足さないことである（今の振る舞い）。書き手が書いた字は書いたとおりに組み、空白が空きを二重にしない。
   - 退けた案の一つは、空白に和欧間の空きを足すことである。空白を書いた箇所だけ、空きが二倍近くに広がる。
   - 二つめは、空白を和欧間の空きに置き換えることである。原稿の字を黙って別の幅にする。空白を書かせたくないなら、golem-lint の規則で知らせるのが筋である。
3. **L13**：推奨は、語を組む書体でのその字の送りで突き出しの量を決めることである。字の幅を超える突き出しは、前の字を版面の外に出す。
   - 退けた案は、今の `ceAdvance`（字の文字クラスで選ぶ書体）のままとし、仕様書の文のとおりとすることである。区間の外の英語の引用符で、突き出しが字の幅を超えうる。
4. **句点を含む語の分綴**：推奨は、TeX と同じく、パターンに語の字だけを渡し、前に 2 字、後に 3 字も字だけを数えることである。語の後に句点があるかどうかで分綴が変わる理由はない。
   - 退けた案の一つは、句点を含む語を分綴しないと決めることである。`hyphenation.` を分綴する今の振る舞いも変えることになり、文の終わりの語だけ分綴しない理由を説明できない。
   - 二つめは、今のとおりパターンに句点も渡すことである。分綴の位置が、語末の境のパターンの有無という偶然で決まる。
5. **行より長い禁則の並び**：推奨は、禁則を破らずにはみ出す行とし、仕様書の文を「行長に収まる分割の候補がない場合」に改めることである。はみ出しは [ADR 0210](0210-warn-overfull-lines-in-build.md) の警告で書き手に知らせ、黙って禁則を破らない。
   - 退けた案は、収まる候補がないときに限り禁則を破って分けることである。どの禁則を先に破るかの順を決める規則が要り、書き手は禁則が破られたことを知らない。
6. **語の最初の字が両用の字の語の書体**：推奨は、この ADR では扱わず、調べて別の ADR にすることである。区間の外の `“said` は、`ceWordAdvance` が語の最初の字の `“` で書体を選ぶので、和文の書体で送りを測る可能性がある。描く側の書体の選び方を確かめていない。
   - 退けた案は、3 と同じ ADR で決めることである。突き出しの量ではなく語の幅と描く書体の問題であり、確かめる前に決められない。
