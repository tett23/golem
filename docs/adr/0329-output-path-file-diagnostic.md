# ADR 0329: 出力先に通常のファイルがあるときのコードと .DS_Store の片付けを決める

ステータス: 採択

## 文脈

`build/pdf` にリンクを置いても通常のファイルを置いても G08013 が出る。
リンクなら指し先を保存してリンクを取り外す必要がある。
通常のファイルなら、そこを出力に使うにはファイルを別の場所に移す必要がある。
どちらでも Golem がそこに上書きしてはいけない。

## 実装すること

リンクには G08013、出力用のディレクトリと同じパスにある通常のファイルには G08104 を出す。
メッセージにプロジェクトからの相対パスを書く。
リンクを先に調べるので、通常のファイルへのリンクや、指し先がないリンクも G08013 になる。
親の `build` が使えないときは、その子を調べない。

### build と fmt が使うフォルダーの .DS_Store を消す

macOS の Finder が書く名前どおりの通常のファイル `.DS_Store` は、自動で取り除く。
`golem build` はプロジェクトのルート、`build` と、今回選んだターゲットの出力フォルダー直下を確認する。
`golem fmt` はプロジェクトのルートと、整形対象のファイルの親フォルダー直下を確認する。
引数を省略すれば、プロジェクトから見つけた整形対象を使う。
引数があればそのファイルの親だけを追加する。
`fmt --check`、`golem check`、`preflight` はこの片付けを行わない。

対象はプロジェクト内の実ディレクトリで、ファイルの名前が厳密に `.DS_Store` と一致し、リンクをたどらずに確認した種類が通常のファイルの場合だけである。
相対パスの `..`、隠しディレクトリ、途中のシンボリックリンク、プロジェクトの外、選んでいないフォルダーには入らない。
同名のリンク、ディレクトリ、特殊ファイルはそのまま残す。
書き込み権限などで削除できないときは対象パスと理由を報告し、削除できたことにはしない。
存在しなければ成功とし、同じコマンドを繰り返せる。

## 実装しないこと

リンクの取り外し、通常のファイルの改名、指し先の変更を自動では行わない。
デバイスなど特殊なファイルの扱いは別の入力を用意して決める。

## 不変条件

1. O1：リンクと通常のファイルに対するコードは異なり、そのどちらも出力先で上書きしない。
2. O2：親がリンクなら親のエラーだけを出し、その先にあるファイルは変えない。

3. O3：通常の `.DS_Store` は書き込みを行うコマンドの対象フォルダーにあれば取り除き、二回目は何も変えない。
4. O4：検査だけのコマンド、選んでいないフォルダー、同名のリンクやディレクトリには副作用がない。

| 出力先 | コード |
| --- | --- |
| 存在しない | この二つのエラーは出ない |
| 通常のディレクトリ | この二つのエラーは出ない |
| 指し先のあるリンク、壊れたリンク | G08013 |
| 通常のファイル | G08104 |

## テスト設計

`experiments/diagnostics/baseline.mjs` の O1 は、実際のビルド先にリンクと通常のファイルを順に置く。
試作は二つのコードと、通常のファイルおよびリンク先の内容が保存されていることを照合する。
現行版は両方とも G08013 を返した。
本実装では O2 の親リンクと壊れたリンクも加える。

O3 と O4 の [試作](../../experiments/diagnostics-review/finder.mjs) は専用 CLI の `fmt --check`、`fmt` を二回、PDF ビルドを順に実行した。
検査時は九か所すべてにファイルが残った。
通常の整形はルートと対象原稿の親の二か所から取り除いた。
その後ルートに再びファイルを置くと、ビルドはルートと `build` と `build/pdf` から取り除いた。
選択していない HTML 出力、外部へのリンク先、同名のディレクトリなどには変更がなかった。
試作は macOS の `lstat` を使った。
他のホストでの実装と、検査と削除の間に別のプロセスがパスを差し替える場合の対処は本実装で確かめる。

## トレードオフ

出力保護の失敗を監視する CI は G08104 を監視対象に加える必要がある。
エラーから、どのパスを退避するかを判断できる。
