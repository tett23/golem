# ADR 0221: リンクの注釈についての ISO 15930-7 の照合を、rc4 の前にメンテナーが行い、監査の記録に残す

ステータス: 採択（未実装）→照合の期限は [ADR 0226](0226-move-the-iso-15930-7-check-to-before-v1.md)

## 文脈

[ADR 0182](0182-external-links.md) は、`[color] intent` のある本（PDF/X-4 の PDF）にも、URI のアクションを持つリンクの注釈を書くと決めた。
その「実装すること」の PDF/X-4 の節は、実装に入る前に ISO 15930-7:2010 の本文で注釈とアクションの規定を確かめ、禁じる規定があればその節を改める ADR を作る、と定める。

### 照合しないまま実装した

照合は行われていない。
規格の本文は有償で、実装のときに入手できなかったためである。
実装は、照合の代わりに、ロードマップの「手で確かめる項目」に「PDF のリンクの注釈」を足した（[`roadmap.md`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/docs/roadmap.md#L233)）。
その項目は、本文で注釈と URI のアクションを禁じる規定がないことを確かめていない、と書くだけで、誰がいつ確かめるか、結果をどこに書くかを決めていない。
Fable の ADR のレビュー（2026-11-08）は、これを 0182 の違反に挙げた。

実装は、`Golem.Pdf.X4.verify` の禁止の名前から、ページの `/Annots` にあるリンクの注釈の URI のアクションだけを外した（[`X4.hs`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-pdf/src/Golem/Pdf/X4.hs#L244-L260)）。
注釈は `/F 4`（印刷のフラグ）を持ち、外観のストリーム（`/AP`）を持たない（[ADR 0182](0182-external-links.md) の「PDF」の節）。
`/F 4` は PDF/A-2 が要るフラグで、veraPDF で確かめてある。
PDF/X-4 の側は、自前の検査のほかに確かめる手段がない。
veraPDF は PDF/X を扱わない（[golem-pdf ADR 0003](../golem-pdf/adr/0003-pdf-x-4-validator.md)）。

### 規格の本文で確かめていないこと

PDF/X-4 の要件の一覧（[golem-pdf ADR 0002](../golem-pdf/adr/0002-pdf-x-4.md)）も、本文を参照せずに書かれた。
その ADR も、実装の前に本文と照合し、差分があれば新しい ADR を作ると書いたが、照合の記録はない。
[2026-10-16 の TeX との機能の差の監査](../audits/2026-10-16-tex-feature-gap.md) の PDF/X の行も、規格の本文との照合が済んでいないとする。

0182 にかかわる問いは、次の四つである。
どれも、記憶か二次の資料によるもので、本文では確かめていない。

- **Q1**：PDF/X-4 は、リンクの注釈を禁じるか。
- **Q2**：URI のアクションは、PDF/X の「外部への参照」に当たるか。[golem-pdf ADR 0002](../golem-pdf/adr/0002-pdf-x-4.md) の「外部への参照を含めない」の一文が `URI` を禁止の名前に入れた根拠であり、その文が印刷に使う内容を外から読むこと（外部のストリームなど）だけを指すのかは分かっていない。
- **Q3**：印刷のフラグを持つ注釈を、仕上がりの線（TrimBox）か塗り足し（BleedBox）の内側に置くことを禁じるか。PDF/X の系列には、そのような規定がある可能性があるが、本文で確かめていない。禁じるなら、PDF/A-2 が要る `/F 4` と食い違う。
- **Q4**：外観のストリームのない注釈を禁じるか。

### rc4 との関係

リンクの注釈が入った最初のリリースは、v0.1.0-rc4 になる（今のタグは `v0.1.0-rc1` から `v0.1.0-rc3`）。
rc4 の後に照合して禁じる規定が見つかれば、PDF/X-4 を名乗る PDF を、規格に反したまま一度配ったことになる。
[docs/compatibility.md](../compatibility.md) の約束は 1.0.0 からなので、rc4 の後に直すことはできるが、そのあいだに組んだ入稿用の PDF は戻らない。

## 実装すること

### 照合

- メンテナーが ISO 15930-7:2010 の本文を入手し、上の Q1 から Q4 に答える（「メンテナーが決めること」の 1）。Claude Code は規格を購入できず、有償の本文を読めない。
- 同じ読みで、[golem-pdf ADR 0002](../golem-pdf/adr/0002-pdf-x-4.md) の要件の一覧と本文の差も調べる（「メンテナーが決めること」の 3）。

### 記録

- 結果は、`docs/audits/<日付>-iso-15930-7-check.md` に書く（「メンテナーが決めること」の 2）。`docs/audits/` の記録は、コミットした後に変えられない（adr-guard が強制する）。
- 記録には、問いごとの答え（禁じる、禁じない、規定がないのどれか）と根拠の節の番号を書き、読んだ規格の版と入手の日付も書く。規格の本文は、著作権を守るため、短い引用を除いて写さない。要旨を自分の言葉で書く。
- 同じプルリクエストで、ロードマップの「手で確かめる項目」の「PDF のリンクの注釈」から、規格の照合の文を消す。ビューアでリンクが開くことを確かめる文は残す。
- [ADR 0182](0182-external-links.md) と [golem-pdf ADR 0002](../golem-pdf/adr/0002-pdf-x-4.md) のステータスの行に、照合の記録へのリンクを足す。

### 差が見つかったとき

- Q1 から Q4 のどれかで、今の出力が規格に反すると分かれば、[ADR 0182](0182-external-links.md) の PDF/X-4 の節を改める ADR を作る（「メンテナーが決めること」の 4）。
- その ADR を実装するまで、v0.1.0-rc4 のタグを打たない。
- [golem-pdf ADR 0002](../golem-pdf/adr/0002-pdf-x-4.md) の一覧との差は、差ごとに golem-pdf の ADR を作る。rc4 を止めるのは、今の出力が規格に反する差に限る。足りない検査（Golem の出力は規格に合っているが、`X4.verify` が調べていない要件）は、ロードマップの v1.0.0 に項目を足す。

### 期限

照合と記録は、v0.1.0-rc4 のタグを打つ前に終える（「メンテナーが決めること」の 5）。
ロードマップの v0.1.0-rc4 の節に、この照合を項目として足す。

## 実装しないこと

- **PDF/X の検証器を入れること**：Acrobat のプリフライトや callas pdfToolbox のような有償の検証器を CI に入れることは扱わない（[golem-pdf ADR 0003](../golem-pdf/adr/0003-pdf-x-4-validator.md) の決定のまま）。
- **リンクの注釈の出力を先に変えること**：照合の前に、PDF/X-4 の PDF からリンクの注釈を外すことはしない（「メンテナーが決めること」の 4 の退けた案）。
- **ビューアでの確かめ**：Acrobat Reader、macOS のプレビュー、Chrome でリンクが開くことは、今のロードマップの項目のまま、手で確かめる。

## 不変条件

この ADR は Golem の振る舞いを変えず、規格との照合の手順と記録の場所を決める。
入力と出力の関係として書ける性質がないので、不変条件は置かない。
照合で差が見つかれば、振る舞いを改める ADR がその不変条件を持つ。

## テスト設計

自動のテストは書けない。
次の確かめ方をとる。

- 記録のプルリクエストのレビューで、Q1 から Q4 のすべてに答えと節の番号があること、規格の版が ISO 15930-7:2010 であることを確かめる。
- rc4 のタグを打つ前に、`docs/audits/` に記録があり、ロードマップの v0.1.0-rc4 の照合の項目が消えていることを、リリースの手順で確かめる。
- 差が見つかった場合は、改める ADR の実装がマージされていることも確かめる。

## トレードオフ

規格の購入の費用と、本文を読む時間がメンテナーにかかる。
その代わり、PDF/X-4 を名乗る PDF について、規格の本文に基づいた判断を一度だけ記録でき、0182 と [golem-pdf ADR 0002](../golem-pdf/adr/0002-pdf-x-4.md) の二つの未照合を同じ読みで閉じられる。

rc4 を照合に待たせるので、照合が遅れれば rc4 も遅れる。
リンクの注釈は PDF/X-4 の PDF だけの問題なので、照合を待たずに rc4 を出したければ、そのときに期限を改める ADR を書けばよい。

## メンテナーが決めること

1. **誰が照合するか**：推奨は、メンテナーが本文を入手して照合することである。有償の規格を購入し、本文を読めるのは人だけで、判断の責任も入稿の PDF を配る側にある。
   - 退けた案の一つは、印刷所の担当者に PDF を見てもらうことである。印刷所の検査は、その印刷所の RIP と検証器の判断で、規格の本文の判断ではない。
   - 二つめは、二次の資料（Ghent Workgroup の仕様、ベンダーの解説）で照合したことにすることである。0182 と [golem-pdf ADR 0002](../golem-pdf/adr/0002-pdf-x-4.md) が求めたのは本文との照合で、二次の資料はその要約の誤りを含みうる。
2. **記録の場所**：推奨は、`docs/audits/` に一つの記録として置くことである。コミットの後に変えられないので、どの版の本文をいつ読んで何と判断したかが残る。
   - 退けた案の一つは、ロードマップの項目に結果を書いて項目を消すことである。項目を消すと、記録も消える。
   - 二つめは、[ADR 0182](0182-external-links.md) の改める ADR の中に書くことである。差がなかったときに ADR が要らず、記録の置き場がなくなる。
3. **照合の範囲**：推奨は、0182 の Q1 から Q4 と、[golem-pdf ADR 0002](../golem-pdf/adr/0002-pdf-x-4.md) の要件の一覧を、同じ読みで照合することである。同じ規格の本文を一度入手すれば足り、二つの ADR が同じ理由で照合を後回しにしている。
   - 退けた案は、Q1 から Q4 だけにすることである。一覧の照合は、また別の機会に同じ本文を読むことになる。
4. **差が見つかったときの扱い**：推奨は、0182 を改める ADR を作り、その実装まで rc4 を打たないことである。規格に反すると分かった PDF を、PDF/X-4 として配らない。
   - 退けた案の一つは、照合の前に、PDF/X-4 の PDF からリンクの注釈を外しておくことである。PDF/A-2 では許されると確かめた出力を、根拠なく変え、照合の結果によってはもう一度戻すことになる。
   - 二つめは、rc4 を出し、リリースノートの既知の不具合に書くことである。入稿用の PDF を作る利用者が、規格に反すると知らされたまま使うことになる。
5. **期限**：推奨は、v0.1.0-rc4 のタグの前とすることである。リンクの注釈を含む最初のリリースが rc4 だからである。
   - 退けた案の一つは、v1.0.0 の前とすることである。rc4 の PDF を、照合のないまま配る。
   - 二つめは、期限を置かず、ロードマップの「手で確かめる項目」に残すことである。今の状態と同じで、レビューが違反とした状態を閉じない。

## 決めたことの記録

- **「メンテナーが決めること」のすべて**（2026-11-08、メンテナー）：どれも推奨のとおりとした。
