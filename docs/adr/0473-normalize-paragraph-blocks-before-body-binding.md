# ADR 0473: IR の段落境界を正規化し、一段落を一ブロックにする

Status: proposed

## 文脈

[root ADR 0459](0459-take-the-next-block-as-the-body-without-indentation.md) は、空行を挟まず続けた行を一つの構文上のブロックとして本体に渡し、その中で段落を分ける。
このため、原稿では別の段落なのに、一つの暗黙の本体として扱われる。

2026-11-27 に、メンテナーは、段落をブロックコマンドの処理で決めるのではなく、IR として一段落を一ブロックにし、複数段落への適用には `:::` を使うと指定した。
この ADR は、段落境界をコマンドから独立して正規化し、その境界を本体の束縛と出力まで保つことを決める。

## 調査した事項


origin/main の [4121ea73d](https://github.com/tett23/golem/commit/4121ea73d4466eaf47353e4b84d22f08327aed1e) で、次のことを確かめた。

- [root ADR 0459](0459-take-the-next-block-as-the-body-without-indentation.md) の「本体の三つの書き方」は、直後に空行を挟まず続けた行を一ブロックとし、段落の様式が `line` なら、その本体の各行を一段落にすると定める。
- [Golem.hpeg](https://github.com/tett23/golem/blob/4121ea73d4466eaf47353e4b84d22f08327aed1e/modules/golem-parser/grammar/Golem.hpeg#L597-L606) は、ブロックコマンドの列の直後に一つの `AttributedBlock` を読む。
  パーサーが読む段落は、ファイルの段落の様式をまだ知らない。
- [commandRow](https://github.com/tett23/golem/blob/4121ea73d4466eaf47353e4b84d22f08327aed1e/modules/golem-eval/src/Golem/Eval/File.hs#L1486-L1505) は、`line` の次の段落を行ごとの段落に分け、その全部を本体に渡す。
- [Parser.hs](https://github.com/tett23/golem/blob/4121ea73d4466eaf47353e4b84d22f08327aed1e/modules/golem-parser/src/Golem/Parser.hs#L54-L71) は、`:::` 内の構文上のブロック数が一つなら G01031 を出す。
  段落の様式による分割は数えない。
- 組み込みの `@style body align=center` の直後に二行の本文を置く原稿を二組用意した。
  `line` の設定で `golem inspect a.gm --as ir` を実行すると、四つの `Paragraph` のすべてに `align=center` が付いた。
  同じ命令に `line-breaks=keep` を加えると、二つの `Paragraph` のそれぞれに一つの `LineBreak` が残った。
  `golem check` は両方で終了コード 0 だった。
  調査用原稿と IR は `/private/tmp/golem-user-paragraph-builtin-nov27/` にある。
  使用した [root ADR 0468](0468-paragraph-styles-for-headings-and-lists.md) の検証 CLI の SHA-256 は `57af1b6f61b1fa70dcb2a6691c3ad235c8bde50ac3d6f33cd8d6af3e74cef36b` である。


## 実装すること

### IR の不変な単位

段落一つは、意味論 IR の `Paragraph` を本体とする一つの `Block` として表す。
隣り合う別の段落を、一つの `Paragraph` や、暗黙の本体の一要素にまとめない。
これは、コマンドの付いていない本文、コマンドの本体、Emet とプラグインが扱う本文のすべてに当てはまる。
Emet やプラグインが明示的に段落を生成、削除、並べ替えする機能は保ち、その結果の各段落も一ブロックで表す。

既存の最終的な意味論 IR は、調査した四段落を既に四つの `Paragraph` ブロックで表していた。
改めるのは、その前段で複数の段落を一つの構文上の対象として本体に束縛する処理である。
本体を束縛する前の評価入力も、一段落一ブロックへ正規化する。
コマンドごとに先頭の段落を切り出す特例は作らない。

### 段落境界を決める段階

ファイルの段落の様式が決まった後、本体の束縛やスタイル適用より前に、共通の処理で段落のブロック列を作る。
境界は段落の様式と原稿の強制改行で決め、コマンドの名前や解決先、段落スタイルで変えない。
CST は元の文字列を保持し、正規化された各段落にも元の原稿の位置を保持する。

| 原稿 | 段落のブロック列 |
| --- | --- |
| `line` の通常の改行で分けた二行 | 二つの `Paragraph` ブロック |
| `blank-line` で空行の無い二行 | 一つの `Paragraph` ブロック |
| `blank-line` で空行を挟んだ二つの本文 | 二つの `Paragraph` ブロック |
| 行末の強制改行で続く二行 | 一つの `Paragraph` ブロックの中に `LineBreak` |

[root ADR 0016](0016-hard-line-breaks.md) の、行末のバックスラッシュによる強制改行は、一段落の中の改行として保つ。
`line-breaks = "keep"` は、既に一段落と決まった内部の改行を保持する指定とする。
`line` で別の段落になった行を、`@style` や `next-style` の結果で結合しない。
これまで `keep` を付けることで複数行を一段落にしていた `line` の原稿は、段落内の改行を強制改行で明示する。
`line` と `keep` を併用した場合も、通常の改行は段落の区切り、強制改行は段落の内部なので、両者を同義には扱わない。
`blank-line` の一段落の内部では、通常の改行を `keep` が保持する規則を保つ。

リスト全体、表、見出し、コードブロックの構造は変えない。
リストの項目や表のセルを、周囲のブロック列へ取り出すことはしない。
段落を持つ入れ子の場所でも、各段落は一ブロックとし、別の段落を合成しない。

### 一ブロックの本体と明示的なまとまり

暗黙の本体は、正規化されたブロック列の直後の一ブロックだけである。
本文が四段落なら四ブロックであり、二つの組み込み命令 `@style body align=center` は、それぞれ最初と三番目の段落だけを本体として受け取る。
以下の例は段落の様式が `line` の場合で、最初と三番目だけを中央寄せにする。

```
@style body align=center
最初の段落です。
次の段落です。
@style body align=center
別の段落です。
最後の段落です。
```

複数の段落やブロックをまとめて適用対象にするときは、`:::` で範囲を明示する。
囲みはブロックのまとまりであり、段落を結合した一つの `Paragraph` ではない。
Emet やプラグインが `Blocks` として受け取るときも、それぞれの段落のブロックを保つ。

```
@style body align=center
:::
最初の段落です。
次の段落です。
:::
```

字下げだけで複数の段落やブロックを一括適用する形は認めない。
字下げした一ブロックの本体は受け付けるが、正規化後に複数になる場合は、エラー G02290 `複数のブロックを本体にするには ::: で囲みます` を、その本体の原稿の範囲に出す。
一部だけに効果を適用したり、段落を連結したりして成功させない。
この場合も後続の検査を続け、PDF などの成果物は生成しない。

コマンドの返す複数段落も、それぞれ独立した IR ブロックとして保つ。
その結果を外側のコマンドへ一括して渡す場合にも `:::` が必要であり、暗黙に複数ブロックを一つの本体として束ねない。
一ブロックの本体が必要な位置で、評価結果が複数ブロックになった場合も G02290 とする。
この検査は共通の本体の束縛処理で行い、個々のコマンドには段落の切り分けを実装しない。
評価結果が空の場合は、各コマンドの既存の空本体の扱いを保ち、G02290 は出さない。

### 後続の段落と diagnostics

暗黙の本体の外側にある段落は、元の順で一度だけ評価する。
本体のスタイルを複写せず、通常の後続段落として [root ADR 0374](0374-paragraph-style-controls.md) の `next-style` を適用する。
直前の出力が段落ならその次スタイルを使い、出力が無ければ前の状態を保ち、最後の出力が段落以外なら通常の本文へ戻す。
いずれも段落のブロック境界は変えない。

G01031 は、受理される本体で、囲みを外しても同じ一ブロックを渡せるときだけ出す。
その判定を、段落の正規化とコマンドの解決先が分かる段階に移す。
複数段落を囲む原稿には出さない。
本体を受け取らない出力コマンド、設定だけの列、未知のコマンドに付いた囲みのエラーは、現行の規則を保ち、G01031 を追加しない。
一つの囲みの中に一つのコマンドだけがあっても、その評価結果が複数ブロックなら囲みが必要なので、G01031 は出さない。
この判定のためにコマンドを二度評価しない。
G01031 は既存のコードと重大度を保ち、段落の正規化と名前解決の後に判定する G01 の例外として、`docs/diagnostics.md` の番号の区分と段階の説明に記載する。
新しい G02290 は評価段階のコードとして登録する。
G01030 の、閉じの無い囲みのエラーは保つ。

仕様書、マニュアル、README に、一段落一ブロックと `:::` による一括適用を記載する。
既存の複数ブロックの字下げ本体は、同梱の原稿とテストデータも `:::` に移す。
`docs/diagnostics.md` の G01031 と新しい G02290、その埋め込みを同期する。
採択時に、[root ADR 0459](0459-take-the-next-block-as-the-body-without-indentation.md) の本体の単位、複数ブロックの字下げ本体、G01031 に、この ADR による変更を記録する。
[root ADR 0013](0013-paragraph-separator.md) の `keep` による段落分割の例外と、[root ADR 0016](0016-hard-line-breaks.md) の `line` と `keep` で通常改行と強制改行を同義とする部分にも、この ADR による変更を記録する。
いずれも本文は書き換えず、ステータスの変更の配列に対象部分と修正先を追加する。

## 実装しないこと

物理行を、段落の様式や強制改行に関係なく一段落にすることはしない。
複数段落を暗黙にまとめる互換モードは設けない。

## 不変条件

- I1: 正規化は原稿の段落数と境界と順を保ち、本体の束縛前と最終の意味論 IR で、それぞれの段落は一ブロックとして表される。
- I2: 段落の様式と原稿が同じなら、正規化する段落境界は、コマンド名、スタイル、`next-style` の有無によって変わらない。
- I3: 原稿の複数段落を `:::` の本体へ正規化するときは、段落数と同じ数の段落ブロックを作り、一つの `Paragraph` に合成しない。
- I4: 一ブロックの本体が必要な位置へ複数ブロックを渡そうとする箇所ごとに、G02290 が一つ出て、一括適用による成果物を生成しない。
- I5: G01031 は、受理される囲みを外しても同じ一ブロックを本体に渡せる場合にだけ、一つ出る。
- I6: 後続の段落の次スタイルは、同じ段落列を通常の後続段落として書いた場合と等しく、境界を変えない。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 空の原稿 | 段落ブロックなし | I1 |
| コマンドなしの `line` の二段落 | 二ブロック | I1, I2 |
| 四段落と二つの `@style body align=center` | 四ブロック、最初と三番目だけを中央寄せ | I1, I2 |
| 同じ `line` の原稿に `@style`、`keep`、`next-style` を付ける | 段落数と境界は同じ | I1, I2, I6 |
| `blank-line` の二行と、強制改行で続く二行 | それぞれ一段落一ブロック | I1, I2 |
| `:::` で二段落、入れ子の囲み | 各段落を独立のブロックとして保持 | I3 |
| 字下げした一段落と二段落 | 一段落は受理、二段落は G02290 一つ | I4 |
| 内側のコマンドの出力が空 | G02290 なし。外側のコマンドの既存の空本体の規則に従う | I4 |
| 生成した複数段落を暗黙の一括適用と `:::` の一括適用に渡す | 前者は G02290、後者は各ブロックに適用 | I3, I4 |
| 一段落の囲みと複数段落の囲み | 前者だけ G01031 | I5 |
| 一つの生成コマンドを囲み、その結果が複数段落になる | 囲みが必要なので G01031 なし。囲みを外すと G02290 | I4, I5 |
| 本体を取らないコマンドか未知のコマンドに付いた囲み | G01031 なし、既存のエラーを保持 | I5 |
| `@style lead`、lead の `next-style = "after"`、after に次スタイルなし、三段落 | lead、after、body の順で三ブロック | I1, I6 |
| コマンドの返す出力が空か、最後が段落以外 | 通常の次スタイルの状態遷移を保つ | I6 |

## 受けいれ条件

- A1: 通常 CLI で、架空の四段落の例と、`:::` で一括適用する対照を PDF、HTML、EPUB、テキストに出力し、IR の段落数、原稿の順、適用範囲を確かめる。
- A2: Emet とプラグインの本体に渡す値でも一段落一ブロックであることを検査し、縦組み PDF を描画して架空の段落の適用範囲を確かめる。

## テスト設計

golem-parser、golem-eval、golem-doc、golem-driver に、名前を `root ADR 0473 I<n>: ` で始めるテストを追加する。
まず、コマンドに依存した段落境界と、二段落を暗黙に渡す現状の失敗を確認する。
最終 IR の出力だけでなく、本体の束縛前の段落列と、Emet とプラグインの本体の値も比較する。
段落数、構築子、原稿の位置と順を、コマンドの有無とスタイルを変えて表駆動で検査する。
旧来の字下げ本体を移すテストは、`:::` で同じ IR を作れることと、新しい diagnostic の双方を確かめる。
G01031 は、段落の様式と解決先と評価結果のブロック数ごとに検査し、同じコマンドの評価を繰り返さないことも確かめる。
A1 は架空の段落と組み込みの `@style`、A2 は架空の段落と調査用の関数をテストデータとして固定して確かめる。
未公開原稿の本文は ADR、同梱原稿、テストデータに取り込まない。

## トレードオフ

`line` で `keep` に段落の結合を任せた原稿と、複数ブロックの字下げ本体を使った原稿は書き換えが必要になる。
段落内部の改行は強制改行、複数段落への一括適用は `:::` で明示する。
その代わり、段落の境界を、コマンドやスタイルを読まなくても段落の様式から決められる。
