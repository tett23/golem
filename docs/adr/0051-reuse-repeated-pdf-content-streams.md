# ADR 0051: PDF の図版の `Contents` で繰り返し名指したストリームを、出力でも一度だけ書く

ステータス: 採択

## 文脈

[ADR 0040](0040-pdf-import-resource-limits.md) は、PDF の図版の取り込みの資源に上限を設けた。
監査の C3 は、一つのストリームを `Contents` の配列で何度も名指しすると、展開の上限がその回数だけ倍になるという指摘だった。
[ADR 0040](0040-pdf-import-resource-limits.md) は、同じオブジェクトのストリームを一度だけ展開して使い回し、使い回した展開を合計に足さないことで、これに答えた。
「内容のストリーム」の節は、次のように書く。

> 内容のストリームの大きさは、展開の合計の上限が限る。別の上限は設けない。

テスト設計の C3 は、次のとおりである。

> 8 MiB のストリームを 40 回名指しした `Contents` が、300 MiB 未満の割り当てで読める（展開は一度）。

実装（コミット ed5b52d2、[ADR 0040](0040-pdf-import-resource-limits.md) の実装）は、これと違う。

- `Golem.Pdf.Import.pageContent`（`modules/golem-pdf/src/Golem/Pdf/Import.hs` の 1058 行から 1080 行）は、`Contents` の配列の各ストリームを展開し、改行でつないだ内容を一つの `ByteString` として作る。つないだ内容の長さが `maxStreamBytes`（256 MiB）を超えれば、`展開した大きさが上限を超えました` の理由で G0810 とする。
- golem-pdf の `test/SecuritySpec.hs` の「C3: one stream of 8 MiB named 40 times in Contents is inflated once」は、読めることではなく、この理由で拒むことと、割り当てが 300 MiB 未満であることを確かめる。
- [golem-pdf の仕様書](../golem-pdf/specifications.md) の「資源の上限」の表は、「ページの内容（`Contents` の配列をつないだもの）」の上限を 256 MiB とする。

つないだ内容は、名指しの回数に比例して大きくなる。
内容の書き換え（`rewriteContent`）は、つないだ内容の全体を読み、書き換えた内容を Flate で圧縮して、Form XObject のストリームとして出力の PDF に書く。
展開は一度でも、書き換えと圧縮と出力は名指しの回数だけ繰り返される。
実装の上限は、この増幅を止めるためのものであり、上限そのものは必要だった。
[ADR 0040](0040-pdf-import-resource-limits.md) の「別の上限は設けない」は、展開の使い回しで内容の大きさも限られると見誤った記述である。

ただし、上限で拒むのは、増幅の原因を取り除かずに結果を止めているにすぎない。
図版の内容のストリームには、動的な部分がない。
取り込みは、レイヤー（オプショナルコンテンツ）を拒み（`OptionalContent`）、何も実行しない。
同じストリームを書き換えた結果は、そのストリームのバイト列だけで決まり、何度名指されても変わらない。
したがって、同じストリームを名指しのたびに読み直し、書き直す必要はない。
一度だけ書き換え、出力にも一度だけ書き、名指しの位置からそれを呼べばよい。

また、上限を超えたときに G0810 の理由の一つとして出すのは、「一つのコードに一つの原因」の原則（[仕様書](../specifications.md) の「設計原則」）に反する。
G0810 は「図版を PDF に置けません」であり、壊れた PDF、暗号化、扱わない圧縮など、別の原因をすでに持つ。

### 出力で使い回すときの制約

出力の図版は、取り込んだページを一つの Form XObject にしたものである（`Golem.Pdf.Writer.formObject`）。
Form XObject の内容は一つのストリームであり、`Contents` のような配列を持てない。
そこで、繰り返し名指されたストリームを、それぞれ内側の Form XObject として一度だけ書き、外側の Form XObject の内容から `Do` で呼ぶ。

`Do` は、呼ぶ前のグラフィックスの状態を保存し、内側の Form を実行し、呼んだ後に元の状態に戻す（ISO 32000-1 の 8.10.1）。
内側の Form は、呼んだ時点の状態（色、CTM など）を受け継ぐので、前のストリームが設定した状態に頼る内容は、そのまま正しく描ける。
一方、内側の Form の中で変えた状態は、`Do` の後に残らない。
元の PDF で、繰り返すストリームが最上位で状態を変え（`q` と `Q` の外の `rg`、`cm`、`Tf` など）、後ろのストリームがそれに頼っていれば、`Do` に置き換えると描画が変わる。
また、`Do` はテキストオブジェクトの中（`BT` と `ET` のあいだ）とパスの組み立ての途中には置けない。
`Contents` の配列のストリームの境目は字句の区切りにだけ置けるが、テキストオブジェクトや演算子の被演算子はストリームをまたいでよい（ISO 32000-1 の 7.8.2）。

したがって、使い回せるのは、次の節の条件を満たす場合に限る。
満たさない場合は、今と同じく内容をつなぎ、つないだ内容に上限を設ける。

## 実装すること

### 書き換えの使い回し

- `Contents` の配列の各ストリームは、今と同じく、オブジェクトごとに一度だけ展開する。
- 書き換え（`rewriteContent`）も、オブジェクトごとに一度だけ行い、結果を使い回す。書き換えは被演算子と演算子の組だけを見るので、ストリームの境目に未処理の被演算子がなければ、ストリームごとに書き換えてつないだ結果は、つないでから書き換えた結果と同じになる。

### 使い回す条件

ストリームを単独で、きれいな状態（被演算子がなく、テキストオブジェクトの外で、組み立て中のパスがない状態）から読んだとき、次を調べる。
調べるのは書き換えと同じ一度の走査の中であり、別に読み直さない。

1. **境目がきれい**：読み終えたとき、未処理の被演算子がなく、テキストオブジェクトの外にあり、組み立て中のパスがない。途中で、対応する `BT` のない `ET` がない。
2. **閉じている**：`q` と `Q` の数が等しく、途中で `Q` が `q` より多くならない。`BMC` または `BDC` と `EMC` も同じである。
3. **状態を外に漏らさない**：`q` と `Q` の外（深さ 0）で、グラフィックスの状態を変える演算子を使わない。対象は、`cm`、`w`、`J`、`j`、`M`、`d`、`ri`、`i`、`gs`、色の演算子（`CS`、`cs`、`SC`、`SCN`、`sc`、`scn`、`G`、`g`、`RG`、`rg`、`K`、`k`）、クリップ（`W`、`W*`）、テキストの状態の演算子（`Tc`、`Tw`、`Tz`、`TL`、`Tf`、`Tr`、`Ts`）、`"`（`Tw` と `Tc` を変える）である。テキストの状態はテキストオブジェクトを出た後も残るので、`BT` と `ET` の中でも対象にする。

ページの `Contents` が配列で、二回以上名指されたストリームがあるとき、次のすべてを満たせば使い回す。

- 配列のすべてのストリームが、条件 1 を満たす。
- 二回以上名指されたすべてのストリームが、条件 2 と条件 3 を満たす。
- 外側の Form の `Resources` の `XObject` に、次の節で足す名前がまだない。

一回だけ名指されたストリームは、条件 2 と条件 3 を満たさなくてよい。
`q` を一つめのストリームに、対応する `Q` を三つめのストリームに置く PDF は、そのまま描ける。

### 使い回すときの出力

- 二回以上名指されたストリームを、それぞれ内側の Form XObject にして、一度だけ書く。`BBox` は外側の Form と同じ、`Matrix` は単位行列、内容はそのストリームを書き換えた結果である。キーは元のストリームのオブジェクトの番号とし、`ipObjects` に加える。
- 内側の Form の `Resources` は、外側の Form の `Resources` から、この節で足す `XObject` の名前を除いたものとする。内側の Form が自分を呼び、描画が終わらなくなるのを防ぐためである。
- 外側の Form の `Resources` の `XObject` に、内側の Form を `GolemC<番号>`（`<番号>` は元のオブジェクトの番号）の名前で足す。`XObject` の辞書が間接参照なら、写した直接の辞書に置き換えてから足す。
- 外側の Form の内容は、配列の順に、一回だけ名指されたストリームの書き換えた内容と、二回以上名指されたストリームの `/GolemC<番号> Do` を、改行でつないだものとする。
- 外側の内容の大きさは、別々のストリームの内容の和（展開の合計の上限 256 MiB と、ファイルの大きさが限る）と、`Do` の行の数（配列の長さで、ファイルの大きさが限る）で決まる。名指しの回数に比例して大きくなる部分は、`Do` の数バイトだけである。したがって、この経路には、展開の合計の上限のほかの上限を設けない。

### 使い回せないときの上限

条件を満たさないページは、今と同じく内容をつなぐ。

- つないだ内容の長さ（各ストリームの書き換える前の内容の長さの和と、あいだの改行の数）が 256 MiB（2^28 バイト）を超えれば、エラーとする。
- 長さは、つなぐ前に、展開した各ストリームの長さから計算する。超える内容をメモリに作らない。
- 二回以上名指されたストリームがない配列では、つないだ内容は別々のストリームの内容の和なので、展開の合計の上限とファイルの大きさが限る。この上限に届くのは、事実上、繰り返し名指しで条件を満たさないページだけである。
- 上限は 256 MiB とする。一つのストリームの展開の上限と同じであり、一つの Form XObject の内容として書く大きさの上限をそろえる。

### diagnostic

上限を超えたときは、G0810 ではなく、新しいコード G0815 とする。

| コード | 重大度 | 対象 | メッセージ | 段階 |
|---|---|---|---|---|
| G0815 | エラー | `Contents` をつないだ内容が 256 MiB を超える PDF の図版 | `図版の PDF のページの内容をつなぐと 256 MiB を超えます: <パス>` | 出力（golem-pdf の `Golem.Pdf.Import`、golem-driver の `Golem.Driver.Pdf`） |

- 位置は、G0810 と同じく、その `@figure` のブロックである。
- `Golem.Pdf.Import.ImportError` に、つないだ長さを持つ構成子（`ContentTooLarge !Int`）を足す。golem-driver の `Unplaced` にも対応する構成子を足し、`figureDiagnostics` で G0815 にする。
- 図版と出力の区分（08）は G0814 まで使っている。G0816 と G0817 は [docs/adr/0054](0054-svg-marker-cycle-and-depth-codes.md) の草稿が、G0818 は [golem-pdf ADR 0011](../golem-pdf/adr/0011-cff-fontfile3-subtype.md) の草稿が使うので、G0815 とする。空きの G0812 は、[golem-pdf ADR 0009](../golem-pdf/adr/0009-svg-figures.md) の案で別の意味に使われた番号なので、取り違えを避けて使わない。G0815 は、origin の各ブランチと、この worktree のほかの草稿で使われていない。草稿の採択の順で番号が変わる場合は、採択のときに付け直す。
- `docs/diagnostics.md` に G0815 の節を足す。主な原因は、同じ内容のストリームを何度も名指しし、そのストリームが最上位で状態を変えている PDF である。直し方は、図版を作った道具で PDF を書き出し直すか、図版を SVG か PNG にすることである。

### ドキュメント

- [ADR 0040](0040-pdf-import-resource-limits.md) のステータスの行を「採択→`Contents` の繰り返しの名指しの扱いと上限、テストの C3 は [ADR 0051](0051-reuse-repeated-pdf-content-streams.md)」に改める。
- golem-pdf の仕様書の「資源の上限」の表の「ページの内容（`Contents` の配列をつないだもの）」の行を、使い回せないページに限る上限とし、理由の欄を G0815 に改める。「展開の数え方」の節の最後の項目を、この ADR の使い回しの条件と出力に書き直す。
- 仕様書（[docs/specifications.md](../specifications.md)）の「図版」の節の取り込みの上限の文（1766 行）に、繰り返し名指したストリームは出力でも一度だけ書くことと、使い回せずにつないだ内容が 256 MiB を超えれば G0815 になることを足す。
- `docs/diagnostics.md` の G0810 の節から、つないだ内容の上限が G0810 になるという記述があれば除き、G0815 を指す。
- 利用者のマニュアル（`manual/chapters/03-markup.gm` の 542 行）の図版の大きさの上限の段落に、G0815 になる場合を一文で足す。

## 実装しないこと

- 条件を満たさないストリームを、状態を補って使い回すこと。最上位で変えた状態を `Do` の後に設定し直すには、内容を解釈して状態を追う必要があり、取り込みの複雑さに見合わない。
- 一回だけ名指されたストリームを、内側の Form にすること。出力の構造が変わるだけで、大きさは減らない。今の出力のバイト列を保つ。
- 上限を `manifest.toml` で変えられるようにすること。[ADR 0040](0040-pdf-import-resource-limits.md) と同じく、必要になれば別の ADR で足す。
- G0810 のほかの理由（展開の合計の上限、ページの木、相互参照など）をコードに分けること。ロードマップの「一つのコードに一つの原因の監査」で扱う。

## テスト設計

先に書き、失敗させてから実装する。

### golem-pdf（`test/SecuritySpec.hs`）

- C3 を [ADR 0040](0040-pdf-import-resource-limits.md) のもとの意図に戻す。8 MiB の空白（NUL）のストリームを 40 回名指しした `Contents` が読め、割り当てが 300 MiB 未満であること。外側の内容が `/GolemC4 Do` の 40 行であり、`ipObjects` に内容が 8 MiB の内側の Form が一つあること。今は拒むので失敗する。
- 最上位で `0 g` を繰り返して 8 MiB にしたストリーム（条件 3 を満たさない）を 40 回名指しした `Contents` が `ContentTooLarge` で拒まれ、割り当てが 300 MiB 未満であること。今は `Malformed` の理由になるので失敗する。
- 同じストリームを 32 回名指しすると拒まれ、31 回なら読めること（つないで 256 MiB と 31 バイト、248 MiB と 30 バイト）。31 回のときの外側の内容が、つないだ内容であること。
- 別々の二つのストリームの境目の値のテスト（「the total of two streams in Contents just over 256 MiB is refused」と「just under 256 MiB is read」）は、展開の合計の上限のテストとして今のまま残す。

### golem-pdf（`test/ImportSpec.hs`）

- `q 1 0 0 rg 0 0 1 1 re f Q` のストリームを二回名指しした `Contents` で、外側の内容が `/GolemC4 Do` の二行になり、内側の Form の内容が一度だけ書き換えられている（`/GolemSRGB cs 1 0 0 sc` を含む）こと。外側の `Resources` の `XObject` に `GolemC4` があり、内側の Form の `Resources` にないこと。
- 次の各場合に、使い回さずに内容をつなぐこと。
  - 繰り返すストリームが最上位で `1 0 0 rg` を使う（条件 3）。
  - 繰り返すストリームが `Q` で始まる、または `q` で終わる（条件 2）。
  - 繰り返すストリームが `BDC` を閉じない（条件 2）。
  - 配列のどれかのストリームが `BT` で終わり、次のストリームが `ET` で始まる（条件 1）。
  - 配列のどれかのストリームが被演算子 `1 0` で終わる（条件 1）。
  - ページの `XObject` の辞書に `GolemC4` がすでにある。
- 一回だけ名指されたストリームの並び（`q` で終わるストリームと `Q` で始まるストリーム）が、今と同じくつないだ内容になること。

### golem-driver（`test/Main.hs` と PDF の図版のテスト）

- 内容のストリームを二回名指しした PDF の図版を持つ本を組み、出力の PDF が `qpdf --check` を通り、図版の Form XObject の `Resources` に内側の Form があること。
- 条件を満たさないストリームを 40 回名指しした PDF の図版で、G0815 がその `@figure` の位置に一つ出て、G0810 が出ないこと。
- G0815 が `docs/diagnostics.md` にあり、コードと文書の一致の検査が通ること。
- 既存の fixture の PDF の図版の出力が、この変更の前とバイト列で同じであること。繰り返し名指しする fixture がないためである。

## トレードオフ

使い回す経路では、名指しの回数がどれほど多くても、取り込みのメモリと出力の大きさは、別々のストリームの大きさでほぼ決まる。
[ADR 0040](0040-pdf-import-resource-limits.md) がもともと C3 で求めた「読める」に戻り、その上で増幅も起きない。
代わりに、閲覧する道具は、`Do` の数だけ内側の Form を描く。
描画の手間は名指しの回数に比例するが、それは元の PDF を描くときと同じであり、Golem が増やしたものではない。

使い回す条件は、`Do` に置き換えても描画が変わらないことを、内容を解釈せずに判定できる範囲に限った。
条件 3 は保守的であり、最上位で状態を変えても後ろのストリームがそれに頼らない PDF も、使い回さずにつなぐ。
そうした PDF は、繰り返しの量が上限に届かない限り今と同じく読め、届いたときだけ G0815 になる。
メンテナーは、この保守的な条件を採った。

取り込みのコードは、書き換えの走査で条件を追う分と、出力の資源の辞書に名前を足す分だけ大きくなる。
出力の構造（内側の Form）は、繰り返し名指しのあるページにだけ現れるので、今の図版の出力は変わらない。

G0815 を新しく作るので、上限を超えた PDF の diagnostic のコードが G0810 から変わる。
上限で止まる PDF は、今は C3 の形の作為的な入力に限られ、書き手や CI がこのコードで引いている例はないと考える。
