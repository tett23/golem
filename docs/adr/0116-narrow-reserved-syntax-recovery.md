# ADR 0116: 予約された記法の回復を記法の分だけに狭める

ステータス: 採択（未実装）

## 文脈

[ADR 0115](0115-reserved-syntax-code.md) は、予約された記法（`[!`、`@!`、`..`）を書いたときのコードを G01100 一つにした。
文法のラベルも `reserved` 一つであり、回復の規則は段落の残りを読み飛ばす `SkipParagraph` である（[Golem.hpeg の 105〜107 行め](https://github.com/tett23/golem/blob/399220d4bdffc0566f69725516b3ceeb471371fc/modules/golem-parser/grammar/Golem.hpeg#L105-L107)）。
引用は、断りのないかぎり origin/main の 399220d4 のものである。

[ADR 0115](0115-reserved-syntax-code.md) は、この回復の粗さを「予約された記法の後ろの誤りが報告されにくくなる」だけだと見積もった。
実装してみると、それでは済まなかった。
読み飛ばしが記法の外まで届くと、記法を囲む規則が失敗し、予約された記法とは別のコードが出る。
G01100 が消えることもある。

### 今の振る舞い

origin/main の 399220d4 で golem を作り、`golem new` で作ったプロジェクトの原稿に次のものを書いて `golem check` で確かめた。
位置は行と字（1 から数える）である。

| 文脈 | 原稿 | 今の結果 |
| --- | --- | --- |
| 段落 | `本文 [!foo bar] です。` | G01100（1:4） |
| 段落の次の行 | `本文 [!x] です。` の次の行に `次の行 [ です。` | G01100 だけ。次の行の G01021 は出ない |
| 空行の後の段落 | `本文 [!x] です。`、空行、`次の段落 [ です。` | G01100 と G01021 |
| 見出し | `# 題 [!x] 後` の次の行に `次の段落 [ です。` | G01100 だけ。次の行の G01021 は出ない |
| 表の見出しの行 | `\| [!x] \| b \|` で始まる表 | G01010 だけ（1:1） |
| 表の本文の行 | 三行めが `\| [!x] \| d \|` の表 | G01023 だけ（2:10） |
| 表のセルの閉じない `[!` | `\| [!x \| b \|` で始まる表 | G01010 だけ（1:1） |
| コマンドの本文 | `本文 [strong: [!x]] です。` | G01100 と G01017 |
| コマンドの引数 | `本文 [strong [!x]: y] です。` | G01100 と G01017 |
| 用語 | `= 用語 [!x]` の次の行に `  定義。` | G01010 だけ（1:1） |
| リストの項目 | `- a [!x] b` の次の行に `- c [ d` | G01100 だけ。次の項目の G01021 は出ない |
| 式 | `本文 [= 1..3] です。` | G01100 と G01017 |
| 式の配列の中 | `本文 [= [1..3]] です。` | G01020 だけ（1:7） |
| 式のハッシュの中 | `本文 [= {a: 1..3}] です。` | G01020 だけ（1:7） |
| 式の関数の引数 | `本文 [= f(1..3)] です。` | G01017 だけ（1:8） |
| 一つの段落の二つの式 | `本文 [= 1..3] と [= 2..4] です。` | G01100 一つと G01017。二つめの `..` は報告されない |
| `@set` | `@set x = 1..3` の次の行に `@set y = [` | G01100 だけ。次の行の G01020 は出ない |
| ブロックの `@!` | `@!foo` の次の行に `次の行 [ です。` | G01100 だけ。次の行の G01021 は出ない |
| ブロックの `@!` の字下げした行 | `@!foo` の次の行に `  body` | G01100 だけ |
| 空行を挟んだ字下げ | `@!foo`、空行、`  body` | G01100 と G01011 |
| 語の `..` | `@listing chapters/01.gm lines=1..2` | G01100 だけ（評価の段階） |

比べるために、`@set y = [` だけの原稿は G01020、`次の行 [ です。` だけの原稿は G01021、`@foo`、空行、`  body` の原稿は G01011 になることも確かめた。

結果は三つに分かれる。

- **別のコードが加わる**：コマンドの本文と引数の `[!`、式の `..` は、G01100 の後に G01017 を出す。回復が `]` を読み飛ばすので、閉じ括弧を待つ規則が失敗するからである。
- **G01100 が消える**：表、用語、式の配列とハッシュと関数の引数では、G01100 が出ずに G01010、G01023、G01020、G01017 のどれかになる。回復の後で囲む規則が通常の失敗をすると、後戻りで捨てた試行の中の構文エラーは報告されない（[peg-hs ADR 0021 の「回復するモード」](https://github.com/tett23/peg-hs/blob/69352cd1be41b4ffa9dc75e1ea9bfcecd25a5748/docs/adr/0021-error-recovery.md#二つのモード)）。表は、見出しの行の G01100 が捨てられてブロックの失敗（G01010）になる。
- **後ろの誤りが隠れる**：空行までを読み飛ばすので、同じ段落の次の行、次のリストの項目、次の `@set` の誤りが出ない。

一つめと二つめは「一つの原因に一つのコード」に反する。
メンテナーは、この原則がほかの事情に優先し、決定性は diagnostic にも及ぶとしている。
同じ予約された記法が、書いた場所によって G01100 にも G01010 にもなるのは、この二つに反する。
三つめは原則の違反ではないが、予約された記法を直すまで別の誤りが見えない。

メンテナーは、予約された記法がちょうど G01100 だけになるように回復の範囲を狭める ADR を書くと決めた。

### 回復の規則の仕組み

peg-hs の回復の規則は、普通の規則である。
回復するモードでは、ラベルが送出されると、送出の位置から回復の規則を評価し、成功すれば、ラベルを付けた式はその終わりの位置で成功したものとして解析が続く（[peg-hs の docs/syntax.md の 1203〜1205 行め](https://github.com/tett23/peg-hs/blob/69352cd1be41b4ffa9dc75e1ea9bfcecd25a5748/docs/syntax.md#L1203-L1205)）。
一つのラベルに回復の規則は一つであり、回復の規則は引数を取れない。
diagnostic の範囲は、送出の位置から回復が読み飛ばした入力の終わりまでである（[golem-parser ADR 0009](../golem-parser/adr/0009-syntax-diagnostic-codes.md)）。

`reserved` を送出する規則は三つあり、どれも送出の直前に記法の文字を先読みで確かめている（[Golem.hpeg の 196〜200 行め](https://github.com/tett23/golem/blob/399220d4bdffc0566f69725516b3ceeb471371fc/modules/golem-parser/grammar/Golem.hpeg#L196-L200) と [436〜445 行め](https://github.com/tett23/golem/blob/399220d4bdffc0566f69725516b3ceeb471371fc/modules/golem-parser/grammar/Golem.hpeg#L436-L445)）。

```peg
ReservedBracket <- &'[!' (&{ False } '[!')^reserved { () }
ReservedBlock <- Ind(ind) &'@!' (&{ False } '@!')^reserved { () }
RangeExpr <- ...
           / &'..' (&{ False } '..')^reserved { () }
           / AddExpr ES ReservedDots { () }
           ...
ReservedDots <- !'...' &'..' (&{ False } '..')^reserved { () }
```

したがって、送出の位置には必ず `[!`、`@!`、`..` のどれかがある。
回復の規則は、呼び出し元を知らなくても、送出の位置の二字を読めばどの記法かが分かる。

`[!` を書ける規則は五つある（`HeadInline`、`Inline`、`SlotInline`、`CellInline`、`ArgValue`）。
表のセルの規則は改行を読まず、コマンドの本文の規則は `]` と `|` で止まる（[Golem.hpeg の 394〜409 行め](https://github.com/tett23/golem/blob/399220d4bdffc0566f69725516b3ceeb471371fc/modules/golem-parser/grammar/Golem.hpeg#L394-L409)、[651〜669 行め](https://github.com/tett23/golem/blob/399220d4bdffc0566f69725516b3ceeb471371fc/modules/golem-parser/grammar/Golem.hpeg#L651-L669)）。
五つの文脈のどれでも囲む規則を壊さない範囲は、`[!` から同じ行の対応する `]` までである。
`@!` はブロックの始まりであり、ブロックコマンドの本文と同じく、次の行から深く字下げした行が続きうる（[Golem.hpeg の 570〜584 行め](https://github.com/tett23/golem/blob/399220d4bdffc0566f69725516b3ceeb471371fc/modules/golem-parser/grammar/Golem.hpeg#L570-L584)）。
`..` は演算子であり、その前後の端は式の文法で読める。

## 実装すること

### 方針

予約された記法の回復は、その記法が覆う範囲だけを読み飛ばし、その後ろは文法がそのまま読み続ける。
記法が覆う範囲は、記法ごとに次のとおりとする。

| 記法 | 読み飛ばす範囲 | 解析を再開する位置 |
| --- | --- | --- |
| `[!` | `[!` から同じ行の対応する `]` まで。対応する `]` が同じ行になければ `[!` の二字だけ | 読み飛ばした範囲の次の字。囲む規則（段落、見出し、セル、コマンドの本文と引数、用語、リストの項目）が続きを読む |
| `@!` | `@!` から行の終わりまで | 次の行。字下げした行も読み飛ばさず、字下げの誤り（G01011）とする |
| `..` | `..` の二字だけ | `..` の次の字。端を式として読む |

予約された記法のコードは G01100 だけであり、diagnostic の範囲は回復が読み飛ばした範囲である。

### ラベルと回復の規則

ラベルは `reserved` 一つのままとし、回復の規則を `SkipParagraph` から、記法の二字で読み飛ばし方を選ぶ規則 `SkipReserved` に替える。

```peg
%token SkippedReserved
%recover reserved SkipReserved

SkipReserved :: ()
SkipReserved <- SkippedReserved { () }

# The recovery of the reserved syntax (docs/adr ADR 0116). Every rule that
# throws reserved looks at [!, @! or .. first, so the two characters at the
# throw tell which syntax it is.
SkippedReserved :: ()
SkippedReserved <- '[!' ReservedBracketBody ']' { () }
                 / '[!' { () }
                 / '@!' (![\n] .)* { () }
                 / '..' { () }

# Up to the ] that closes [! on the same line.
ReservedBracketBody :: ()
ReservedBracketBody <- ( '\\' ![\n] .
                       / '%%' (!'%%' ![\n] .)* '%%'
                       / '[' ReservedBracketBody ']'
                       / ![\[\]\\\n] .
                       )* { () }
```

- 回復の規則は呼び出し元を知らずに選べるので、引数は要らない。
- 対応する `]` は、`[` と `]` の入れ子を数えて探す。エスケープ（`\]`）とコメント（`%% ] %%`）の中の `]` は数えない。行の終わり（改行）を越えない。
- 同じ行で閉じない `[!` は、二字だけを読み飛ばす。表のセルで行の終わりまで読むと、行の `|` を読み飛ばしてセルの数が変わり、表の誤りが加わるからである。段落でも同じ規則を使う。

### `@!` の字下げした行

`@!` の回復は、`@!` の行の終わりまでだけを読み飛ばす。
次の行から `@!` より深く字下げした行が続いても、読み飛ばさない。
`@!` は本体を持たないので、その行は字下げの誤り（G01011）になる。
書き手は字下げの空白とタブを意識して書かないので、字下げの深さで回復の範囲を変えると、どの行が報告されずに消えたかが書き手に見えない。
字下げした行は、`@!` に限らず本体を持たない行の後の字下げと同じく報告する。

```peg
ReservedBlock(ind :: Int) :: ()
ReservedBlock <- Ind(ind) &'@!' (&{ False } '@!')^reserved { () }
```

- `ReservedBlock` は今の規則のままであり、ラベルの後ろに文法を続けない。必ず失敗する規則のラベルの後ろに何も続けないという今の書き方（[Golem.hpeg の 182〜186 行め](https://github.com/tett23/golem/blob/399220d4bdffc0566f69725516b3ceeb471371fc/modules/golem-parser/grammar/Golem.hpeg#L182-L186)）から外れない。
- `@!foo` の次の行の `  body` は、G01100 と G01011 になる。`@!foo`、空行、`  body` も、今と同じく G01100 と G01011 である。空行の有無で結果を変えない。
- G01011 の位置は、ほかの字下げの誤りと同じく、余分な空白かタブから始まる。

### 式の `..`

`..` の回復は二字だけを読み、端は文法が式として読む。
`..` の後の端を読む規則 `ReservedRange` を設け、`RangeExpr` の二つの選択肢と `ReservedDots` を置き換える。

```peg
RangeExpr <- &'...' (&{ False } '...')^range_end { () }
           / ReservedRange { () }
           / AddExpr ES ReservedRange { () }
           / AddExpr ES RangeOp ES (AddExpr)^range_end (!(ES '..'))^range_end { () }
           / CompareExpr { () }

# .. that is not ... (1....2 is ..., then .2, which is no end). After the
# recovery reads the two dots, the end is read as an expression, and the
# dots after it as well (docs/adr ADR 0116).
ReservedRange :: ()
ReservedRange <- !'...' &'..' (&{ False } '..')^reserved
                 (ES AddExpr)? (ES (ReservedRange / RangeOp (ES AddExpr)?))* { () }
```

- 端は省けるので（`[= ..5]`、`[= 5..]`）、`(ES AddExpr)?` とする。端を省いた範囲は `..` が予約する形そのものなので、G02110 を加えない。
- 端の後にさらに `..` が続けば、その `..` も G01100 になる（`[= 1..3..5]` は G01100 が二つ）。同じ原因が二か所にあるので、二つの diagnostic になる。
- 端の後に `...` が続く形（`[= 1..3...5]`）は、`...` と後の端を範囲の続きとして読み、G02110 を加えない。範囲の書き方の誤りは、予約された `..` を直した後に報告される。
- 範囲の式の CST に誤りのノードが入るので、`Golem.Parser.Lower` は今の規則どおり `EError` にする（[Lower.hs の 307〜310 行め](https://github.com/tett23/golem/blob/399220d4bdffc0566f69725516b3ceeb471371fc/modules/golem-parser/src/Golem/Parser/Lower.hs#L307-L310)）。構文の誤りのあるファイルは評価されないので、`EError` は評価に届かない。

これで、配列、ハッシュ、関数の引数、`@set` の中の `..` も、閉じ括弧と行の終わりを読み飛ばさない。

### 文脈ごとの結果

| 文脈 | 例 | 結果 |
| --- | --- | --- |
| 段落 | `a [!x] b` | `[!x]` を読み飛ばし、` b` を本文として読む |
| 見出し、用語 | `# h [!x] t`、`= t [!x]` | `[!x]` を読み飛ばし、行の残りと次の行を読む |
| 表のセル | `\| [!x] \| b \|` | `[!x]` を読み飛ばし、セルの数は変わらない |
| コマンドの本文と引数 | `[strong: [!x]]`、`[strong [!x]: y]` | `[!x]` を読み飛ばし、外の `]` で `strong` が閉じる |
| リストの項目 | `- a [!x] b` | `[!x]` を読み飛ばし、次の項目を読む |
| 閉じない `[!` | `a [!x`、`\| [!x \| b \|` | `[!` だけを読み飛ばす |
| 式 | `[= 1..3]`、`[= [1..3]]`、`[= f(1..3)]` | `..` だけを読み飛ばし、`3` と閉じ括弧を読む |
| `@set` | `@set r = 1..3` | `..` だけを読み飛ばし、行の終わりで `@set` が終わる |
| 語の引数 | `lines=1..2` | 変えない。評価の段階で G01100 になる（[ADR 0113](0113-closed-range-literal.md)） |
| ブロックの `@!` | `@!foo`、字下げしたブロックの中の `@!foo` | 行を読み飛ばし、次の行を読む。次の行が `@!` より深く字下げしていれば G01011 |

### 一つのラベルで足りる理由

ラベルを記法ごとに分けて（たとえば `reserved_bracket`、`reserved_block`、`reserved_dots`）、それぞれに回復の規則を付ける案もある。
この案では三つのラベルが同じ G01100 に写るので、テスト「every grammar label has its own diagnostic code」（[ParserSpec.hs の 180〜186 行め](https://github.com/tett23/golem/blob/399220d4bdffc0566f69725516b3ceeb471371fc/modules/golem-parser/test/ParserSpec.hs#L180-L186)）に例外を設ける必要がある。
送出の位置の二字で回復の規則が記法を選べるので、ラベルを分ける理由がない。
ラベルとコードの一対一を保ち、テストは変えない。

### peg-hs

peg-hs は変えない。
回復の規則は普通の規則なので、記法による読み飛ばし方の選び分けは順序付き選択で書ける。
新しい回復の種類も、回復の規則の引数も要らない。

### 生成物とテストの更新

- `scripts/gen-parser.sh` で `Golem.Parser.Generated` と `StrippedGrammar` を作り直し、ラベルの安全性の検査（[golem-parser ADR 0007](../golem-parser/adr/0007-grammar-label-safety.md)）を通す。
- `Golem.Parser.Convert` で、`SkippedReserved` を誤りのトークン（`KError`）にする（[Convert.hs の 115〜116 行め](https://github.com/tett23/golem/blob/399220d4bdffc0566f69725516b3ceeb471371fc/modules/golem-parser/src/Golem/Parser/Convert.hs#L115-L116) の `SkippedExpr` と同じ）。
- 今のテストのうち、回復の粗さを期待値にしているものを改める（[ParserSpec.hs の 254〜259 行め](https://github.com/tett23/golem/blob/399220d4bdffc0566f69725516b3ceeb471371fc/modules/golem-parser/test/ParserSpec.hs#L254-L259) と [296〜304 行め](https://github.com/tett23/golem/blob/399220d4bdffc0566f69725516b3ceeb471371fc/modules/golem-parser/test/ParserSpec.hs#L296-L304)）。`[= 1..3]`、`[= a..b]`、`[= ..5]`、`[= 5..]` の G01017 と、`[strong: [!x]]` の G01017 を消し、表のセルの `[!x]` を `[A]` と同じコードにする期待を G01100 に変える。

### ドキュメント

- docs/diagnostics.md の G01100 の節に、記法ごとの diagnostic の範囲（`[!` は対応する `]` まで、`@!` は行の終わりまで、`..` は二字）と、`@!` の次の行の字下げが G01011 になることと、予約された記法の後ろは今までどおり読まれて誤りが報告されることを書く。
- docs/specifications.md と README.md は、予約された記法の回復の範囲を書いていないので変えない。

## 実装しないこと

- ラベルを記法ごとに分けること。
- peg-hs に回復の種類や回復の規則の引数を足すこと。
- 行をまたぐ `[!` の対応する `]` を探すこと。段落では行をまたいでも囲む規則は壊れないが、表のセルでは行を読み飛ばすことになる。回復の規則は呼び出し元を知らないので、どの文脈でも行で止める。
- `[!` の中の文字列リテラル（`"a]b"`）を数えること。`[!` の後に何が続くかは決めていない（[ADR 0115](0115-reserved-syntax-code.md)）。
- ほかのラベルの回復を狭めること。同じ測り方で、`[= f(1...)]` が G02110 を出さずに G01017 だけになることを確かめた。`range_end` の回復 `SkipExpr` が関数の引数の `)` を読み飛ばすためであり、同じ種類の問題だが、この ADR では扱わない。
- 語と文字列の中の `..`。今も評価の段階で G01100 だけになる。

## テスト設計

先に次のテストを書き、今のコードで失敗することを確かめてから実装する。
範囲はバイトのオフセットで書き、`(コード, 始まり, 終わり)` の組の集合で確かめる。

### 予約された記法がちょうど G01100 になること

| 入力 | 期待 |
| --- | --- |
| `a [!foo bar] b\n` | `(G01100, 2, 12)` |
| `a [!x\nb] c\n` | `(G01100, 2, 4)` |
| `# h [!x] t\n` | `(G01100, 4, 8)` |
| `= t [!x]\n  d\n` | `(G01100, 4, 8)`。定義リストが一つできる |
| `\| [!x] \| b \|\n\|---\|---\|\n\| c \| d \|\n` | `(G01100, 2, 6)`。表が一つでき、列は二つ |

### 変えないこと

- [ADR 0115](0115-reserved-syntax-code.md) と [ADR 0113](0113-closed-range-literal.md) のテストのうち、上で改めるもの以外（エスケープ、コードブロック、コメント、行の途中の `@!`、`[A]` の G01021、G02110 の入力、メッセージ）が通ること。
- テスト「every grammar label has its own diagnostic code」と、ラベルの安全性のテスト（`LabelSafetySpec`）が変えずに通ること。
- 上の入力のそれぞれで、`parse` の木のテキストが入力と一致すること（ロスレス性）。
- 語の `lines=1..2` が、評価の段階の G01100 だけのままであること。

### 文書

- `adr-guard links` と textlint が通ること。

## トレードオフ

- 予約された記法を直すまで出なかった誤りが、同時に出るようになる。直す順が変わるだけで、誤りの数は増えない。
- `[!` の対応する `]` を探す規則は、`[!` の後の書き方を決めないまま、角括弧の入れ子だけを仮定する。マクロの記法を決めたときに文字列などを足すと、この規則も変わる。
- 閉じない `[!` は二字だけを読み飛ばすので、その後ろは本文として読まれる。後ろに `[A]` のような誤りがあれば、G01100 と G01021 が出る。どちらも書き手が書いた別々の誤りである。
- `@!` の次の行を字下げして本体のつもりで書いた原稿は、G01100 のほかに字下げした行ごとに G01011 が出る。`@!` は本体を持たないので、字下げは G01100 とは別の誤りである。字下げの深さで読み飛ばす範囲を変える案は、書き手が意識しない空白とタブで報告される誤りが変わるので採らなかった。
- `..` の端を式として読むので、端の中の誤り（`[= 1..(2]`）は、`..` のない式（`[= 1 + (2]`）と同じく報告される。

## 決めたことの記録

- **回復を狭めること**：メンテナーが決めた。予約された記法は G01100 だけを出す。
- **一つのラベル**：この版で決めた。送出の位置の二字で読み飛ばし方を選べるので、ラベルを分けず、ラベルとコードの一対一のテストに例外を設けない。
- **記法ごとの範囲**：この版で決めた。`[!` は同じ行の対応する `]` まで、`@!` は行の終わりまで、`..` は二字とした。
- **`@!` の字下げした行**：最初の草稿は、`@!` より深く字下げした行を、ラベルの後ろの文法で読み飛ばす案だった。メンテナーが、字下げした行は誤りにすると決めた（2026-11-04）。書き手は字下げの空白とタブを意識しないので、字下げで回復の範囲を変える例外は認めない。
- **ステータスの行**：この ADR を採択したら、[ADR 0115](0115-reserved-syntax-code.md) のステータスの行を「採択→予約された記法の回復の範囲は [ADR 0116](0116-narrow-reserved-syntax-recovery.md)」に、[ADR 0113](0113-closed-range-literal.md) のステータスの行を「採択→`..` の回復の範囲は [ADR 0116](0116-narrow-reserved-syntax-recovery.md)」に変える。
