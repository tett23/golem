# ADR 0162: .gm から Emet の関数を使う

ステータス: 採択

## 文脈

[ADR 0160](0160-emet-function-language-core.md) は関数を書く言語 `.emet` を、[ADR 0161](0161-emet-requirements-and-driver-handlers.md) は関数が処理系に求める要求を決める。
この ADR は、原稿の `.gm` から関数を使う方法を決める。
言語の名前は、メンテナーの案の `.gmx` から Emet（拡張子 `.emet`）に変えた（[ADR 0160](0160-emet-function-language-core.md) の「決めたことの記録」）。

### 破棄した草案からの引き継ぎ

この ADR は、破棄した [docs/adr/0150](0150-calling-gmx-functions-from-gm.md) を引き継ぐ。
0150 は [PR #526](https://github.com/tett23/golem/pull/526) で誤って採択され、「メンテナーが決めること」に挙げた点はどれも「推奨のとおり」と記録されて [PR #534](https://github.com/tett23/golem/pull/534) と [PR #536](https://github.com/tett23/golem/pull/536) で実装されたが、メンテナーは 2026-11-05 に取り下げ、実装を戻した（[PR #538](https://github.com/tett23/golem/pull/538)。[仕様書の「破棄した ADR」](../specifications.md#破棄した-adr)）。
[ADR 0160](0160-emet-function-language-core.md) と同じく、メンテナーが決めた点だけを「決めたことの記録」に書き、それ以外は「メンテナーが決めること」に挙げる。
本文は推奨の案で書いてある。

### メンテナーの案と立ち位置

メンテナーの最初の案は、`pub inline` と `pub block` を付けた関数を、`.gm` のインラインのコマンドとブロックコマンドとして使えるようにすることだった。

```
pub inline/block docStyles :: Evaluated -> FileId -> Style => file
```

今の Golem は、書き手が関数を定義する仕組みを持たない。
[golem-eval ADR 0001](../golem-eval/adr/0001-expression-language-and-numerics.md) は「ユーザー定義の関数、条件式、繰り返し」を実装しないことに挙げ、[docs/markup.md](../markup.md) の式文脈の節は、関数を定義する仕組みを「プラグインの役割とする」と書いている。
ロードマップは、この立場を改める項目を v0.1.0-rc4 に置いた（[docs/roadmap.md](../roadmap.md) の「`.gmx` の関数の宣言」）。
小さな計算や書式のためにプラグインを作るのは重いからである。

同じ項目は、関数とプラグインの立ち位置を分けている。

- **関数**：社内の使い手や組版のオペレーターが、手元の不便を解消するために書く。
- **プラグイン**：技術者が作って配る。

このため、関数には `plugins.lock` やレジストリのような再配布の仕組みを持たせない。
宣言を書いたファイルをコピーして使うことは防げないが、それは配布の仕組みとは扱わない。

2026-11-05 に、メンテナーは使い方の範囲を広げた（「決めたことの記録」）。
関数は `.gm` に `@import` で取り込み、名前はそのファイルの中だけで見える。
コマンドのほかに、式文脈から呼べ、フィルタにもできる。
`.emet` の補完と lint も v0.1.0-rc4 で持つ。

メンテナーは、将来の方向も示した。

- 意味論 IR を書き換える関数が欲しい。
- 組み込みのコマンドを関数で書き換える可能性がある。
- 関数の種類を、インラインとブロックのほかに、式にも広げたい。
- キーワード引数を持たせたい。

この ADR は、これらを今すべて実装するのではなく、実装するときに形を変えずに足せるように設計する。
IR を書き換える関数とフィルタのために、IR を `.emet` から読めるデータ型として表す（下の「意味論 IR を表すデータ型」）。
関数の種類は `pub` の後ろの語で表し、語を足せば種類を足せるようにする（下の「関数の種類」）。

### 実装から分かったこと

戻した実装（PR #534、#536）から、次が分かった。

- **未知のコマンドのコードは二つある**。インラインのコマンドが未知なら G02022、ブロックコマンドが未知なら G02009 である（[docs/adr/0122](0122-block-commands-in-plugins.md)）。`.emet` が読み込めないときに抑えるのは両方である。
- **IR を読めない値にすると、本文を調べる関数を書けない**。戻した実装は `Inlines` と `Blocks` を中身の読めない値にし、組み込みの関数（`Inline.ruby` など）でだけ作れるようにした（[`Builtins.hs`](https://github.com/tett23/golem/blob/ba6635adfc787a92a1c003a37650a5919a26e3eb/modules/golem-gmx/src/Golem/Gmx/Builtins.hs#L29-L60)）。フィルタと IR を書き換える関数には、中身を読める形が要る。
- **`Inline` と `Block` の一覧に足りない関数があった**。`List Inlines` と `List Blocks` をつなぐ関数と、段落スタイルを付ける段落を足した。IR をリストのデータ型にすれば、`++` と `List.concat` で足りる。
- **`pub block` の本体の受け取り方**は、最後の引数が `Blocks` かどうかで決めた。`Blocks` でなければ本体を渡さず、本体があれば G02123 とした。
- **golem-eval の `ctxFunctions`** で、組み込み、プラグイン、関数の順に名前を解決できた（[`File.hs`](https://github.com/tett23/golem/blob/9e439d758c000c6977f389d17345eca5435399e8/modules/golem-eval/src/Golem/Eval/File.hs#L584-L603)）。golem-eval は golem-emet に依存しなかった。
- **LSP** は、`.emet` を `.gm` としては評価せず、driver が `Evaluated` に関数のコマンドの一覧を持つことで、補完、宣言への移動、参照の検索、ホバーを実装できた（[PR #536](https://github.com/tett23/golem/pull/536)）。
- **`golem fmt`** は golem-cli から golem-driver を通して `.emet` を整形し、golem-fmt は golem-emet に依存しなかった。

## 実装すること

### 立場の変更

この ADR は、[golem-eval ADR 0001](../golem-eval/adr/0001-expression-language-and-numerics.md) の「実装しないこと」のうち「ユーザー定義の関数」を改める。
書き手は `.emet` に関数を定義し、`.gm` からコマンド、式、フィルタとして使える。
条件式と繰り返しは、`.gm` の式文脈には今後も足さない（[docs/roadmap.md](../roadmap.md) の課題にしなかった事項の「式の拡張」のまま）。
`.emet` の中で、パターンマッチと再帰として書ける。

[docs/markup.md](../markup.md) の「ユーザーが関数を定義する仕組みは持たず、それはプラグインの役割とする。」は、実装のときに、関数を `.emet` に定義して `@import` で使う旨と、その節へのリンクに書き換える。
[golem-eval ADR 0001](../golem-eval/adr/0001-expression-language-and-numerics.md) のステータスの行には、実装のときに、ユーザー定義の関数をこの ADR が改めたことと、この ADR へのリンクを加える。

### 取り込み

`.gm` は、`.emet` を `@import` で取り込む（「決めたことの記録」）。

```
@import functions/book.emet as book
```

- 形は `@set` の変数の取り込みと同じ `@import パス as 名前空間` である。パスの拡張子が `.emet` なら関数の取り込み、`.gm` なら変数の取り込みとする。
- 取り込んだ関数は、`as` で付けた名前空間を通してだけ参照でき、`@import` を書いたファイルの中だけで見える。ほかの `.gm` から使うには、そのファイルでも `@import` を書く。
- パス、ファイルの同一性、ルートの外の扱いは、`.gm` の `@import` の規則（[仕様書の「プロジェクトの構成と import」](../specifications.md#プロジェクトの構成と-import)）に従う。同じ `.emet` を多くのファイルが取り込んでも、読み込みと型の検査は一度だけ行い、結果を共有する。
- `.emet` の読み込みか型の検査に誤りがあるときは、`.emet` の中の位置に誤りを出し、その名前空間を通した呼び出しで G02022（未知のインラインのコマンド）、G02009（未知のブロックコマンド）、G02002（未定義の名前）を報告しない。読み込めなかった関数の呼び出しが、すべて未知の名前になって本当の原因を埋もれさせるからである（プラグインの読み込みの失敗と同じ扱い。[docs/adr/0122](0122-block-commands-in-plugins.md)）。

名前空間を通すので、関数の名前は組み込みのコマンド、プラグインのコマンド、ほかの `.emet` の関数と重ならない。
戻した実装の名前の衝突の検査（G03105 から G03107）は要らなくなる。
命令文脈のコマンドの名前に `.` を一つ許す文法の変更が要る（下の「呼び方」。「メンテナーが決めること」の 1）。

### 関数の種類

関数の種類は、`pub` の後ろの語で表す。

| 宣言 | 種類 | `.gm` からの使い方 |
| --- | --- | --- |
| `pub inline` | インラインのコマンド | `[book.tax-included 1000]` |
| `pub block` | ブロックコマンド | `@book.word-table data/words.tsv` |
| `pub filter` | フィルタ | `manifest.toml` の `[[filters]]` |
| `pub fn` | 式の関数 | 式文脈の `[= book.total(prices)]` |
| `pub` | 公開した関数 | ほかの `.emet` だけ |

- 一つの関数には、`inline`、`block`、`filter`、`fn` のうち多くても一つを書く（「決めたことの記録」）。文法が一つだけを受け付けるので、`pub inline fn f` は構文の誤り（E01100）になる。
- 種類の語のない `pub` の関数は、ほかの `.emet` からだけ呼べ、`.gm` からは見えない。`.gm` に出す関数を、作者が語で選ぶためである。
- `pub inline`、`pub block`、`pub filter`、`pub fn` の関数も、ほかの `.emet` からは普通の関数として呼べる。
- 種類の語は、[ADR 0160](0160-emet-function-language-core.md) の予約語である。種類を足すとき（たとえば IR を書き換える関数）は、語を一つ予約語に足し、この表に行を足す（「メンテナーが決めること」の 11）。

### 呼び方

- インラインのコマンドは `[名前空間.名前 引数...]`、ブロックコマンドは `@名前空間.名前 引数...` と書く。命令文脈のコマンドの名前は、名前空間の語、`.`、コマンドの名前からなる形を許す。`.` は一つだけであり、`.` の前後は今のコマンドの名前と同じ規則（英小文字で始まり、英小文字、数字、`-` だけ）に従う。
- 名前空間にない名前は、インラインなら G02022、ブロックなら G02009 とし、メッセージに名前空間の名前を書く。名前空間そのものがなければ、同じコードで、未定義の名前空間であることを書く。
- 式文脈では `名前空間.名前(引数, ...)` と書く（「式文脈からの呼び出し」）。

### コマンドの名前

`.gm` のコマンドの名前は、英小文字で始まり、英小文字、数字、`-` だけからなる。
`.emet` の識別子は `-` を持てない。
`-` を許すと、引き算と区別するために空白の規則が要るからである。
そこで、`.gm` に出す名前は、宣言の種類の語の後ろに文字列で書く（「決めたことの記録」）。

```haskell
pub inline "tax-included" taxIncluded :: Nat -> Inlines
pub block "word-table" wordTable :: String -> Blocks -> Blocks
pub inline price :: Nat -> Inlines
```

- 文字列の名前は、`.gm` のコマンドの名前の規則に従わなければならない。従わなければ E06100 とする。
- 文字列を省けば、`.emet` の関数の名前をそのままコマンドの名前にする。そのときは、関数の名前が `.gm` の規則に従わなければ（英大文字や `_` を含めば）E06100 とし、メッセージに文字列の名前を書く形を添える。
- 一つの `.emet` の中で、二つの関数が同じコマンドの名前を出せば E06106 とする。インラインのコマンドとブロックコマンドは別の名前空間にある（[docs/adr/0122](0122-block-commands-in-plugins.md)）ので、`pub inline` と `pub block` が同じ名前を出しても重ならない。
- `.emet` の中からは、`taxIncluded` のように関数の名前で呼ぶ。文字列の名前は `.gm` からだけ使う。
- `pub filter` も同じ形でフィルタの名前を書く。`pub fn` は式文脈から呼ぶので、`.emet` の名前をそのまま使う（下の「式文脈からの呼び出し」）。

### 引数の写し方

コマンドの引数は、組み込みのコマンドと同じく評価してから関数に渡す（「メンテナーが決めること」の 3）。

- シグネチャの引数のうち、`Inlines` でも `Blocks` でもなく、キーワード引数でもない型の引数が、位置引数に順に対応する。可変長引数は、その後ろの残りの位置引数をすべて受け取る（下の「可変長引数」）。
- インラインのコマンドでは、その後ろに並ぶ `Inlines` の引数が、散文スロットに順に対応する。
- ブロックコマンドでは、最後の引数を `Blocks` にすると、字下げした本体を受け取る。最後の引数が `Blocks` でなければ本体を受け取らない。
- `Inlines` と `Blocks` の引数を、ほかの型の引数の前に置くと E06102 とする。

値の写し方は次の表のとおりである。

| `.gm` の値 | `.emet` の型 |
| --- | --- |
| 自然数、整数、有理数 | `Nat`、`Int`、`Rat`（[docs/adr/0101](0101-rational-numbers-in-expressions.md) の暗の広げ方に従う） |
| 文字列（語を含む） | `String` |
| 真偽値 | `Bool` |
| 配列 | `List a`（要素がすべて `a` に写せる場合） |

- 連想配列、範囲、`nil` は v1 では渡せない。シグネチャにこれらに当たる型を書く手段もない。
- 引数の型が `.gm` から渡せない型（関数の型、利用者のデータ型、`Maybe a`、`Char`、組、`Inline`、`Block`）の関数を `pub inline` と `pub block` にすると E06102 とする。`Inlines` と `Blocks` は、散文スロットと本体としてだけ受け取れる。
- 位置引数の数がシグネチャと合わなければ G02120 とする。可変長引数を持つ関数では、可変長引数の前の引数の数より少なければ G02120 とする。
- 値の型が引数の型に写せなければ G02121 とする。メッセージには、引数の位置と、求めた型と、渡した値の型を書く。
- 散文スロットの数が合わなければ G02122 とする。
- 本体を受け取らない関数のブロックコマンドに本体を書くと、G02123 とする。

どの誤りでも、関数を呼ばない。

### キーワード引数

コマンドはキーワード引数を受け取れる（「決めたことの記録」）。
Koka の名前付きの引数にならい、シグネチャの引数の位置に、括弧で囲んで名前、型、既定の値を書く。
等式では、ほかの引数と同じく、引数の位置のパターンで受け取る。

```haskell
pub inline price :: Nat -> (tax :: Bool = True) -> (unit :: String = "円") -> Inlines
price n tax unit = Inline.text (String.fromNat n ++ unit ++ (tax ? "（税込）" : ""))
```

```
[book.price 1000]
[book.price 1000 tax=false unit=" 円"]
```

- 名前を付けた引数（`(tax :: Bool = True)`）がキーワード引数である。型の上では、名前のない引数と同じ一つの矢印であり、名前と既定の値は `.gm` から呼ぶときにだけ使う。
- キーワード引数は、位置引数と可変長引数の後ろ、散文スロットと本体の前に置く。ほかの位置に置くと E06103 とする。
- キーワード引数の型は、上の表で `.gm` から渡せる型に限る。既定の値は、その型のリテラルに限る。既定の値のないキーワード引数は書けない（E06103）。
- `.gm` で省いたキーワード引数は、既定の値を受け取る。
- シグネチャにないキーワード引数は G02119、同じキーワード引数を二度書くと、組み込みのコマンドと同じコードにする。
- キーワード引数の名前は、`.gm` から使う名前である。`-` を含む名前は、コマンドの名前と同じく文字列で書く（`("font-size" :: Rat = 10)`）。英小文字と数字だけの名前は、識別子のまま書ける（`(tax :: Bool = True)`）。どちらも `.gm` のキーワード引数の名前の規則に従わなければ E06100 とする。
- `.emet` の中から呼ぶときは、キーワード引数も位置で渡す（`price 1000 True "円"`）。既定の値は使えない。`.emet` の中の呼び出しはカリー化しており、どこで引数が終わるかが決まらないからである。
- 引数の名前は、等式のパターンの変数の名前とは関係がない。等式では、`price n t u` のようにどの名前で受けてもよく、パターンマッチもできる。
- `pub fn` とフィルタは、v1 ではキーワード引数を持たない。式文脈の関数の呼び出しの記法（`f(x)`）がキーワード引数を持たないからである。シグネチャに書けば E06103 とする。`pub inline`、`pub block`、`pub fn`、`pub filter` のほかの関数のシグネチャに名前を付けた引数を書いても、E06103 とする。

### 可変長引数

コマンドと `pub fn` は、可変長引数を受け取れる（「決めたことの記録」）。
可変長引数は、組み込みの型 `Varargs a` で書く（「決めたことの記録」）。
`Varargs a` は `List a` と同じ型であり、等式ではリストとして受け取る。
記号を足さずに型の名前で表すので、シグネチャは Haskell の型の書き方のままである。

```haskell
pub inline tags :: String -> Varargs String -> Inlines
tags sep words = Inline.text (String.join sep words)

pub fn sum :: Varargs Nat -> Nat
sum [] = 0
sum (x : xs) = x + sum xs
```

```
[book.tags ・ 組版 校正 入稿]
[= book.sum(1200, 800, 450)]
```

- `Varargs a` の引数は、`.gm` から呼ぶとき、残りの位置引数をすべて受け取り、リストにする。一つも渡さなければ空のリストになる。
- 可変長引数は一つの関数に多くても一つであり、位置引数の最後（キーワード引数、散文スロット、本体の前）に置く。二つ書くか、ほかの位置に置くと E06105 とする。
- `a` は、`.gm` から渡せる型（「引数の写し方」の表）に限る。違えば E06102 とする。
- 可変長引数の値の型の誤りは G02121 とし、メッセージに何番目の値かを書く。
- `Varargs a` は、`pub inline`、`pub block`、`pub fn` の引数の位置にだけ書ける。ほかの位置（ほかの関数のシグネチャ、戻り値の型、データ型の欄）に書くと E06105 とする。`List a` と同じ型なので、ほかの位置では意味がなく、読み手を迷わせるからである。
- `.emet` の中から呼ぶときは、リストを渡す（`sum [1, 2, 3]`）。

### 式文脈からの呼び出し

`pub fn` を付けた関数を、式文脈から呼べる（「決めたことの記録」）。

```
@import functions/book.emet as book
[= book.total([1200, 800, 450])]
```

- 引数の写し方は、コマンドの位置引数と同じ表に従う。戻り値は、`Nat`、`Int`、`Rat`、`String`、`Bool`、それらの `List` を、表の逆向きに `.gm` の値に写す。
- 引数の型が写せない `pub fn` は E06102、戻り値の型が写せない `pub fn` は E06101 とする。どちらも `.emet` の宣言の誤りであり、式文脈から呼ぶ前に見つかる。
- 名前は `.emet` の名前をそのまま使う。式文脈では `-` が引き算なので、コマンドの名前の写し方を当てない。
- `pub fn` でない関数の名前を式文脈に書くと、G02002（未定義の名前）とし、メッセージに、その関数が `pub fn` でないことを書く。
- 引数の数の誤りは G02120、値の型の誤りは G02121 とする。コマンドと原因が同じなので、コードを分けない。
- 式の型は、評価の前に推論する（[docs/markup.md](../markup.md) の「評価の前の解析」）。関数の型は、`.emet` の読み込みの後に分かるので、推論は `@import` した `.emet` の型の検査を待つ。
- 要求を持つ関数も呼べる。要求は [ADR 0161](0161-emet-requirements-and-driver-handlers.md) のとおり driver が処理する。

### フィルタ

`pub filter` の関数は、プラグインのフィルタと同じく、ソースファイル一つ分の評価済みの文書を受け取り、書き換えた文書を返す（「決めたことの記録」）。

```haskell
pub filter "first-ruby" firstRuby :: Blocks -> <file "data/words.tsv"> Blocks
```

```toml
[[filters]]
function = "functions/ruby.emet"
filter = "first-ruby"
files = ["chapters/01.gm", "chapters/02.gm"]
```

- `pub filter` の型は `Blocks -> Blocks` か、要求の列を付けた `Blocks -> <...> Blocks` でなければならない。違えば E06101 とする。
- フィルタは `manifest.toml` の `[[filters]]` で当てる（「メンテナーが決めること」の 5）。`function` に `.emet` のパスを、`filter` にフィルタの名前（宣言に書いた文字列の名前か、省いたときは関数の名前）を書く。`plugin` と `function` はどちらか一方だけを書く。両方を書くか、どちらも書かなければ G03001 とする。
- プラグインのフィルタと `.emet` のフィルタは、`[[filters]]` の宣言の順に一つの並びとして当てる。
- フィルタが受け取るのは、フィルタを当てるファイルの評価済みの文書だけである（プラグインのフィルタと同じ）。
- 返した文書は、プラグインのフィルタの出力と同じく、意味論 IR の不変条件で検査する（`Golem.Doc.Validate`）。違反は、プラグインのフィルタの出力と同じ規則で、`.emet` の関数の名前を添えて E06104 とする。
- フィルタの手数の上限は、[docs/adr/0124](0124-filter-fuel-by-document-size.md) にならい、`1 億 + 10000 × 文書のバイト数` とする（「決めたことの記録」）。1 億は [ADR 0160](0160-emet-function-language-core.md) のコマンドと式の上限である。文書のバイト数は、フィルタを当てる `.gm` のファイルのバイト数とする。プラグインのフィルタは要求の CBOR のバイト数で数えるが、`.emet` のフィルタは CBOR を作らないので、入力の原稿で数える。どちらも入力だけで決まるので、上限を超えるかどうかは実行の環境によらない。係数の 10000 は、足りなければ 50000 くらいまで上げる。

### 意味論 IR を表すデータ型

フィルタと、将来の IR を書き換える関数のために、意味論 IR を `.emet` から読めるデータ型として表す（「メンテナーが決めること」の 7）。
組み込みのモジュール `Inline` と `Block` が、データ型 `Inline` と `Block` とそのコンストラクタを持つ。
`Inlines` は `List Inline`、`Blocks` は `List Block` の別名である。

```haskell
emphasizeFirst :: Inlines -> Inlines
emphasizeFirst (Inline.Text s : rest) = Inline.Strong [Inline.Text s] : rest
emphasizeFirst xs = xs
```

- コンストラクタの範囲は、プラグインとの ABI のシリアライズ形式（[仕様書の「シリアライズ形式」](../specifications.md#シリアライズ形式)）が表すインラインとブロックと同じとする。ABI は互換性を保つと決めているので、`.emet` の型もそれと同じ速さでしか変わらない。golem-doc の内部の型を写すと、内部の変更が利用者の関数を壊すからである。
- 欄の多くは、文字列、数、`Inlines`、`Blocks` のような読める値である。注と傍注の本文は `Blocks`、ルビの親文字と読みは文字列で読める。
- 評価を遅らせた値（ページ番号や相互参照の値。DeferredRef）は、中身の読めない組み込みの型 `Inline.Deferred` の欄に入る。関数はそれをそのまま返すか、別の位置に置くことしかできない。S1 と S2 の値を関数が読めないので、評価の階層は崩れない。
- ソースの位置は、データ型の欄に出さない。受け取ったまま返したノードは元の位置を保ち、関数が作ったノードは、コマンドと式では呼び出しの位置を、フィルタではフィルタを当てたファイルの先頭の位置を持つ。
- 組み込みの関数（`Inline.text`、`Inline.ruby`、`Block.paragraph` など）は、よく使うノードを作る近道として残す。一覧は仕様書に書く。
- 意味論 IR の不変条件に反する値（ルビの中のルビ、ブロックコマンドが返した見出しなど）は、型では防がず、返した時点で検査する。コマンドの出力は、プラグインのコマンドの出力と同じく最上位でないブロックとして（[docs/adr/0122](0122-block-commands-in-plugins.md)）、フィルタの出力は文書として検査し、違反は E06104 とする。
- 段落スタイル、文字スタイル、色の名前は、組み込みのコマンドと同じく検査し、なければ同じコード（G02047 など）とする。

IR をデータ型にしたので、散文スロットと本体で受け取った `Inlines` と `Blocks` も、パターンマッチで中を読める。
戻した実装が書けなかった、初出の語にだけルビを振るような関数は、フィルタとしても、散文スロットを調べるコマンドとしても書ける。

### 評価の段階

関数は、プラグインのコマンドとフィルタと同じく、ファイル内評価（S0）でだけ呼ぶ（[仕様書の「実行の範囲」](../specifications.md#実行の範囲)）。
S1 と S2 の値は受け取れず、`doc` を参照する引数はプラグインのコマンドと同じ扱いとする。
関数は純粋であり、`file` の要求の値も一回のビルドで一つに決まる（[ADR 0161](0161-emet-requirements-and-driver-handlers.md)）ので、ファイルを並列に評価できる。
文書の全体を書き換える関数（S1 の後に動くもの）は、この ADR では足さない。
足すときも、上のデータ型を使い、種類の語を一つ足す。

### モジュール

golem-eval の `EvalContext` に、関数の表を足す（「メンテナーが決めること」の 8）。
型は golem-eval に置き、中身は golem-driver が golem-emet から作る。
golem-eval は golem-emet に依存しない。

- **golem-parser**：命令文脈のコマンドの名前に、名前空間と `.` を許す。
- **golem-eval**：名前空間ごとの関数の表（インラインのコマンド、ブロックコマンド、式の関数。引数、散文スロットか本体、キーワード引数、位置を受け取り、値か IR と diagnostic を返す関数）を `EvalContext` に足す。`@import` の `.emet` の名前空間を、この表で解決する。式の型の推論に、関数の型を渡す。
- **golem-emet**：種類、名前の写し方、引数とキーワード引数の写し方、IR のデータ型と golem-doc の IR のあいだの変換、出力の検査の呼び出しを持つ。
- **golem-driver**：`.gm` の `@import` と `[[filters]]` から `.emet` を集めて読み込み、型の検査をし、関数の表を作る。`.emet` のフィルタを、プラグインのフィルタと同じ並びで当てる。LSP のために、`Evaluated` に取り込んだ関数の一覧を持つ。`golem fmt` と `golem lint` に `.emet` を加える。
- **golem-cli**：`golem fmt` と `golem lint` が `.emet` を golem-driver を通して扱う。
- **golem-lsp**：下の「LSP」のとおり、golem-emet に依存する。
- **golem-project**：`manifest.toml` の `[[filters]]` の `function` と、`[functions.requires]`（[ADR 0161](0161-emet-requirements-and-driver-handlers.md)）を読む。

build-depends の変更は、golem-driver と golem-lsp に golem-emet を足すことだけである（[ADR 0160](0160-emet-function-language-core.md) の「パッケージ」）。

### LSP

`.emet` の補完は v0.1.0-rc4 で持つ（「決めたことの記録」）。

- `.emet` のファイルの diagnostics を公開する。`.emet` を `.gm` としては評価しない。
- `.emet` の中の補完は、その位置で見える名前（局所の束縛、引数のパターンの変数、最上位の宣言、`import` した名前空間の公開された名前、組み込みのモジュールの名前、コンストラクタ）と、要求の列の中の要求の名前を出す。
- `.emet` の中のホバーは型を、宣言への移動は同じ `.emet` か `import` した `.emet` の宣言を示す。
- `.gm` の補完は、`@import` した名前空間の後ろの `.` で、その名前空間の関数を出す。命令文脈ではインラインとブロックのコマンドの名前を、式文脈では式から呼べる関数の名前を出す。
- `.gm` の関数の名前から、`.emet` の宣言へ移動できる。参照の検索で、`.emet` の関数を呼ぶ `.gm` の箇所を一覧にできる。
- `.gm` の関数の名前にカーソルを置くと、シグネチャ（要求を含む）を表示する。
- `.emet` を開いて編集すれば、それを `@import` する `.gm` と、それをフィルタに当てる `.gm` を評価し直す。
- `.emet` の整形は fmt を呼ぶ。

### lint

`.emet` の lint は v0.1.0-rc4 で持つ（「決めたことの記録」）。
規則は、`.gm` の lint と同じく、ほぼ確実に誤りである記述に限り、抑制の手段を持たない（[仕様書の「lint」](../specifications.md#lint)）。
`golem lint` と LSP が出す（「メンテナーが決めること」の 9）。

| コード | 重大度 | 原因 |
| --- | --- | --- |
| E07100 | エラー | 使われていない、`pub` のない最上位の関数とデータ型 |
| E07101 | エラー | 使われていない `.emet` の `import` |
| E07102 | エラー | 使われていないパターンの変数（`_` で始まる名前を除く） |

使われていない `where` の束縛は、lint の規則にせず、型の検査の notice の E02109 とする（[ADR 0160](0160-emet-function-language-core.md)。「決めたことの記録」）。
lint の規則は notice を出さない（[golem-syntax ADR 0002](../golem-syntax/adr/0002-notice-severity.md)）ので、lint から外した。

`.gm` の「使われていない `@import`」の規則は、`.emet` の `@import` にも当てる。
`pub` の付いた関数は、プロジェクトのどこからも使われていなくても、lint の対象にしない。
書きかけの関数を先に公開しておく書き方を妨げないためである。

### 配布しないこと

関数のファイルは、プロジェクトのルートの中のパスでだけ指せる。
URL、ロックファイル、レジストリ、版の解決は持たない。
ほかのプロジェクトで使うには、ファイルをコピーする。
それを配布の仕組みとは扱わず、Golem は関数の出どころを記録しない。

### 組み込みのコマンドとの関係

関数は名前空間を通して呼ぶので、組み込みのコマンドを上書きしない。
組み込みのコマンドを関数で書き換えることは、この ADR では扱わない。
扱うときは、プラグインの `overrides` と同じく `manifest.toml` で宣言する形か、Golem が組み込みのコマンドの一部を `.emet` で書いて同梱する形を、別の ADR で決める。
どちらの形でも、この ADR の IR のデータ型とコマンドの引数の写し方を使える。

### 決定性の検査

決定性の検査（同じ入力から同じ出力のバイト列と同じ diagnostics を得ること）に、関数を使う fixture を加える（ロードマップの「決定性の検査の対象にする」）。
fixture は、インラインのコマンド、キーワード引数を持つコマンド、可変長引数を持つコマンド、ブロックコマンド、`pub fn` の関数、フィルタ、`File.read` で読む TSV、末尾再帰を使う関数を一つずつ持つ。

### 仕様書と言語仕様

実装のときに、次の文書を変える。

- [docs/specifications.md](../specifications.md)：「関数」の節を足し、プラグインとの立ち位置の違い、`@import`、関数の種類、フィルタ、IR のデータ型、手数と深さの上限を書く。モジュールの図に golem-emet を足す。「lint」の節に `.emet` の規則を足す。
- [docs/markup.md](../markup.md)：上の「立場の変更」の書き換えと、名前空間を付けたコマンドの名前、式文脈の関数の呼び方。
- [docs/diagnostics.md](../diagnostics.md)：接頭辞 `E` のコードの体系と、三つの ADR のコードの節。
- [docs/roadmap.md](../roadmap.md)：「`.gmx` の関数の宣言」の項目を消し、文書の全体を書き換える関数、組み込みのコマンドの書き換え、式文脈のキーワード引数を、未決の項目として足す。

### 誤りのコード

この ADR が使うコードは次のとおりである。

| コード | 重大度 | 原因 |
| --- | --- | --- |
| E06100 | エラー | `.gm` の名前の規則に従わないコマンド、フィルタ、キーワード引数の名前 |
| E06101 | エラー | 種類に合わない戻り値の型（`pub inline` が `Inlines` でない、`pub filter` が `Blocks -> Blocks` でない、`pub fn` が `.gm` の値に写せないなど） |
| E06102 | エラー | `.gm` から渡せない引数の型か、引数の並びの誤り |
| E06103 | エラー | 既定の値のないキーワード引数、キーワード引数の位置の誤り、`.gm` から呼ぶコマンドでない関数のキーワード引数 |
| E06104 | エラー | 関数の出力が意味論 IR の不変条件に反する |
| E06105 | エラー | 可変長引数が二つあるか、位置の誤り、または書けない位置の `Varargs` |
| E06106 | エラー | 一つの `.emet` の中で、二つの関数が同じコマンドかフィルタの名前を出す |
| G02119 | エラー | シグネチャにないキーワード引数 |
| G02120 | エラー | 位置引数の数がシグネチャと合わない |
| G02121 | エラー | 値の型が引数の型に写せない |
| G02122 | エラー | 散文スロットの数が合わない |
| G02123 | エラー | 本体を受け取らない関数のブロックコマンドに本体を書いた |
| E07100 から E07102 | エラー | 上の「lint」の表 |

`E` のコードは、[ADR 0160](0160-emet-function-language-core.md) の「型と評価の誤りのコード」が作る接頭辞の、段階 E06（`.gm` から使う関数の宣言と出力）と E07（lint）である。
戻した実装は、同じ誤りに `G106` のコードを使っていたが、新しい接頭辞にしたので、`G10` の番号はどれも使わない。
`.emet` の lint は、`.gm` の lint（`G05`）と規則の対象が違うので、E07 に置く。

G02119 から G02123 は、`.gm` の側の誤りなので `G` のコードとし、戻した実装が同じ意味で使っていた番号を使う。
G02119 は、戻した実装ではキーワード引数をすべて受け付けない誤りだったが、どちらもシグネチャにないキーワード引数を渡したことを表すので、同じ意味として使う。

## 実装しないこと

- 文書の全体（S1 の後）を書き換える関数。IR のデータ型と種類の語で足せる形にしておく。
- 組み込みのコマンドを関数で上書きすること。
- `pub fn` とフィルタのキーワード引数。
- `.emet` の中の呼び出しでの可変長の渡し方と、キーワード引数の省略。
- 名前空間を付けない関数の取り込みと、プロジェクトの全体で見える関数。
- 連想配列、範囲、`nil` の引数。
- 関数の配布、版の管理、出どころの記録。
- `.emet` の意味に応じた色付け（semantic tokens）。

## テスト設計

テストを先に書き、関数の表と `.emet` の `@import` がないためにコンパイルできないことを確かめてから実装する。

golem-parser のテストでは、`[book.tax-included 1000]` と `@book.word-table x` を名前空間つきのコマンドとして読み、`[a.b.c]` が構文の誤りになることを確かめる。

golem-emet のテストでは、次のことを確かめる。

- `pub inline "tax-included" taxIncluded` が `tax-included` のコマンドを出し、`.emet` の中からは `taxIncluded` で呼べること。文字列を省いた `pub inline price` が `price` のコマンドを出すこと。`pub inline "Tax"`、`pub inline "tax_included"`、文字列を省いた `pub inline taxIncluded` が E06100 になること。二つの `pub inline` が同じ名前を出せば E06106、`pub inline` と `pub block` が同じ名前を出しても誤りにならないこと。
- `pub inline` の戻り値が `String` なら E06101、`pub filter` の型が `Blocks -> Inlines` なら E06101 になること。
- `Inlines` の引数を `Nat` の引数の前に置くと E06102、`Maybe Nat` の引数の `pub inline` が E06102 になること。
- 既定の値のないキーワード引数、散文スロットの後ろのキーワード引数、`pub fn` のキーワード引数が E06103 になること。`price 1000 True "円"` を `.emet` の中から呼べること。
- `Varargs` を二つ持つ関数、`Varargs` の後ろに位置引数を持つ関数、`pub` だけの関数とデータ型の欄の `Varargs` が E06105 になること。`Varargs Nat` の値を `List Nat` の関数に渡せること。
- 引数が `Maybe Nat` の `pub fn` が E06102、戻り値が `Inlines` の `pub fn` が E06101 になること。
- IR のデータ型と golem-doc の IR のあいだの変換が、任意の IR で往復して元に戻ること（プロパティテスト）。

golem-eval と golem-driver のテストでは、次のことを確かめる。

- `@import functions/book.emet as book` の後で `[book.tax-included 1000]` が関数の返したインラインになり、位置が呼び出しの位置であること。`@import` のないファイルでは同じ呼び出しが G02022 になること。
- `[book.emph-twice: 本文]` の散文スロットが `Inlines` の引数に渡り、中の `[note: ...]` が受け取ったまま注になること。散文スロットのテキストをパターンマッチで読めること。
- `@book.word-table x` の本体が `Blocks` の引数に渡ること。`@label` が返した最初のブロックに付くこと。
- `[book.price 1000]` が既定の値を、`[book.price 1000 tax=false]` が渡した値を受け取ること。`[book.price 1000 rate=1]` が G02119 になること。
- 引数の数の誤りが G02120、`[book.tax-included abc]` が G02121、散文スロットの数の誤りが G02122、本体を受け取らない関数への本体が G02123 になり、どれも関数を呼ばないこと。
- `[= book.total([1, 2])]` が 3 になること。`pub fn` でない `pub` の関数を式文脈から呼ぶと G02002 になり、メッセージに `pub fn` でないことが出ること。
- `[book.tags ・ 組版 校正]` が三つの語を、`[book.tags ・]` が空のリストを受け取ること。`[= book.sum(1, 2, 3)]` が 6、`[= book.sum()]` が 0 になること。`[book.tags]` が G02120、`[book.tags ・ 1]` が G02121 になること。
- `.emet` のフィルタとプラグインのフィルタを `[[filters]]` に交互に書くと、その順に当たること。`plugin` と `function` を両方書くと G03001 になること。
- ブロックコマンドが見出しを返すと E06104、フィルタがルビの中にルビを作ると E06104 になること。関数が返した段落スタイルの名前が未定義なら G02047 になること。
- `.emet` に型の誤りがあるとき、その名前空間を通した呼び出しに G02022、G02009、G02002 が出ないこと。
- 決定性の fixture を二度組み、出力のバイト列と diagnostics が一致すること。並列と逐次で一致すること。

golem-lint のテストでは、E07100 から E07102 がそれぞれの記述で出て、使われていない `where` の束縛には lint の誤りが出ず、`_` で始まる変数と使われていない `pub` の関数には出ないことを確かめる。

golem-lsp のテストでは、`.emet` の中の補完（局所の名前、名前空間の名前、要求の名前）、`.gm` の名前空間の後ろの補完、宣言への移動、ホバーのシグネチャ、`.emet` の編集で `.gm` の diagnostics が公開し直されることを確かめる。

## トレードオフ

関数を `@import` で取り込み、名前をファイルの中に閉じたので、関数を使う章のファイルごとに `@import` を書く。
その代わり、関数の名前が組み込みのコマンドや将来足す組み込みのコマンドと重ならず、どの関数がどのファイルから来たかを原稿だけで読める。
命令文脈のコマンドの名前に名前空間と `.` を足すので、golem-parser の文法と LSP の補完を変える。

IR をデータ型として読めるようにしたので、本文を調べる関数を書ける。
その代わり、IR のデータ型は利用者の関数が依存する面になり、プラグインとの ABI と同じく互換性を保つ必要がある。
不変条件は型で防がず、返した時点で検査するので、ルビの中のルビのような誤りは型の検査ではなく評価のときに見つかる。

キーワード引数を引数の位置に書き、等式では位置で受け取るので、Haskell の等式の書き方を変えずに済む。
その代わり、`.emet` の中から呼ぶときは既定の値を使えず、すべての引数を位置で渡す。
既定の値をリテラルに限ったので、ほかのキーワード引数から計算した既定の値は書けない。

可変長引数を型の名前で表すので、新しい記号は要らない。
`Varargs a` は `List a` と同じ型なので、`.emet` の中では区別がなく、`.gm` から呼ぶときにだけ意味を持つ。

`.emet` のフィルタを `manifest.toml` の `[[filters]]` で当てるので、関数を使う場所が `@import` と `manifest.toml` の二つに分かれる。
フィルタは当てる順が意味を持ち、プラグインのフィルタと一つの並びにする必要があるので、`manifest.toml` に置いた。

LSP の宣言への移動、参照の検索、ホバーは、ロードマップが求める補完と diagnostics より広い。
戻した実装で費用が分かっているので入れたが、削れば golem-lsp の変更は小さくなる。

## 決めたことの記録

メンテナーが決めたことだけを書く。

- **`pub inline` と `pub block` でコマンドにすること**（メンテナーの案）：`pub inline` と `pub block` を付けた関数を、`.gm` のインラインのコマンドとブロックコマンドにする。
- **`pub inline/block` の読み方**（2026-11-04、メンテナー）：「片方」と答えた。関数には `inline` と `block` のどちらか一方だけを書く。`filter` と `fn` を加えた四つのうち一つだけとすることと、複数を書いた宣言を構文の誤り（E01100）とすることは、この草稿の帰結である。
- **関数の立ち位置**（ロードマップ、メンテナー）：関数は社内の使い手と組版のオペレーターのものであり、配布の仕組みを持たない。[golem-eval ADR 0001](../golem-eval/adr/0001-expression-language-and-numerics.md) の立場を改める。
- **`@import` とファイルのスコープ**（2026-11-05、メンテナー）：「関数は @import で取りこみ、スコープはファイルに閉じる」。名前空間つきのコマンドの名前（「呼び方」）と、そのための golem-parser の文法の変更を、メンテナーは「問題なし」とした。
- **補完と lint**（2026-11-05、メンテナー）：「gmx の補完と lint は rc4 で持つ」（gmx は Emet の旧名）。lint の規則の中身は、この草稿の案であり、「メンテナーが決めること」の 9 に挙げる。
- **式文脈からの呼び出し**（2026-11-05、メンテナー）：「式文脈から関数を呼べるようにする」。
- **種類 `fn`**（2026-11-05、メンテナー）：関数の種類に `fn` を足すとし、「式もいずれ持たせたい」は `fn` で対応するとした。式文脈から呼ぶ関数は `pub fn` で宣言する。種類の語のない `pub` の関数を `.gm` から見えなくすることは、この草稿の帰結である。
- **フィルタ**（2026-11-05、メンテナー）：「フィルタにもできる」。`manifest.toml` の `[[filters]]` で当てるこの草稿の案を、メンテナーは「問題なし」とした。
- **将来の方向**（2026-11-05、メンテナー）：将来の方向として、組み込みのコマンドを関数で書き換える可能性があること、IR を書き換える関数が欲しく、それを念頭に設計したいこと、関数の種類をインラインとブロックのほかに式にも広げたいことを挙げた。IR をデータ型として読めるようにすること（「メンテナーが決めること」の 7）と、種類を語で足せるようにすること（同 11）は、これを受けた案である。
- **キーワード引数**（2026-11-05、メンテナー）：キーワード引数を持たせたいとし、v0.1.0-rc4 で持たせると決めた。
- **可変長引数**（2026-11-05、メンテナー）：「可変長引数も」。v0.1.0-rc4 で持たせる。
- **キーワード引数の形**（2026-11-06、メンテナー）：「b で。引数位置パターンマッチで処理できるので」。Koka の名前付きの引数にならい、シグネチャの引数の位置に名前と既定の値を書き、等式では位置で受け取る。
- **フィルタの手数**（2026-11-06、メンテナー）：係数はとりあえず 10000 とし、50000 くらいに増やす可能性があるとした。文書のバイト数あたりの係数を 10000 とする。文書のバイト数を原稿のファイルで数えることは、この草稿の帰結である。
- **IR のデータ型、lint、LSP**（2026-11-06、メンテナー）：「7 推奨で。9 推奨で。10 推奨で」。
- **語のない `pub`**（2026-11-06、メンテナー）：語のない `pub` は、ほかの `.emet` から使う可能性があるので、この仕様でよいとした。語のない `pub` の関数は `.gm` から見えず、ほかの `.emet` からだけ使う。
- **使われていない束縛**（2026-11-06、メンテナー）：「使わなかった束縛は notice にして」。lint の規則から外し、[ADR 0160](0160-emet-function-language-core.md) の E02109 にする。
- **可変長引数の形**（2026-11-06、メンテナー）：「可変長引数とする。あまり Haskell から離れたくない」「専用の型で表す」「List a との互換性をとる」。`Varargs a` の型で書き、`List a` と同じ型とする。
- **コマンドの名前**（2026-11-06、メンテナー）：「引き算とまじるのはまずいので a をとる」。`.gm` に出す名前を宣言に文字列で書く。
- **`@set` との関係**（2026-11-06、メンテナー）：「推奨で」。
- **関数の表**（2026-11-06、メンテナー）：推奨のとおりとし、golem-eval は拡張するか、責務を後で分割する可能性があるとした。

## メンテナーが決めること

採択の前に、次のことを決めてほしい。
本文は推奨の案で書いてあり、違う案を採れば書き換える。
決めた項目は、番号を変えないように残し、決めたことを書く。

1. **名前空間つきのコマンドの名前**：決めた。`.gm` の `@import` と同じく名前空間を必ず付け、`[book.tax-included 1000]` と書く。命令文脈のコマンドの名前に `.` を一つ許す（「決めたことの記録」）。
2. **名前の写し方**：決めた。`.gm` に出す名前を宣言に文字列で書く（「決めたことの記録」）。文字列を省いたときに関数の名前をそのまま使えることと、キーワード引数の名前にも同じ形を使うことは、この草稿の案である。
3. **`@set` との関係**：決めた。推奨のとおり、関数の引数を組み込みのコマンドと同じく評価してから渡し、`@set` の変数を `.emet` から直接読む手段は持たない（「決めたことの記録」）。
4. **キーワード引数の形**：決めた。シグネチャの引数の位置に `(名前 :: 型 = 既定の値)` と書き、等式では位置で受け取る（「決めたことの記録」）。
5. **フィルタの当て方**：決めた。`manifest.toml` の `[[filters]]` に `function` の欄を足し、プラグインのフィルタと一つの並びにする（「決めたことの記録」）。
6. **フィルタの手数の上限**：決めた。`1 億 + 10000 × 文書のバイト数` とし、足りなければ係数を 50000 くらいまで上げる（「決めたことの記録」）。
7. **IR をデータ型として読めるようにするか**：決めた。推奨のとおり、プラグインとの ABI と同じ範囲のコンストラクタを持つデータ型にし、不変条件は返した時点で検査する（「決めたことの記録」）。
8. **関数の表を golem-eval に置くか**：決めた。推奨のとおり、名前空間ごとの関数の表を `EvalContext` に足す（「決めたことの記録」）。golem-eval は、後で広げるか、責務を分ける可能性がある。
9. **lint の規則**：決めた。上の表の三つをエラーとする。最初の案の四つのうち、使われていない `where` の束縛は notice にした（「決めたことの記録」）。
10. **LSP の範囲**：決めた。推奨のとおり、diagnostics と補完に、宣言への移動、参照の検索、ホバーを加える（「決めたことの記録」）。
11. **種類の語で種類を足すこと**：決めた。関数の種類を `pub` の後ろの語（`inline`、`block`、`filter`、`fn`）で表し、語のない `pub` の関数は `.gm` から見えず、ほかの `.emet` からだけ使う。将来の種類は語を足して表す（「決めたことの記録」）。

12. **可変長引数の形**：決めた。型の名前を `Varargs` とし、`List a` と同じ型にする（「決めたことの記録」）。
