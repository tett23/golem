# ADR 0359: PDF の展開量と連結後の内容量を別々に制限する

ステータス: 採択（未実装）

## 文脈

フォント、PDF、EPUB の出力のうち、書き手が必要とする「取り込む PDF の内容の上限とストリームのつなぎ」の扱いを決める。

## 調査した事項

[仕様書](../specifications.md) は、一つの図版に対する全フィルタ段の展開量と、連結する内容の長さに、それぞれ 256 MiB の上限を設けている。
現行の連結経路では、各ストリームの内容のほかに区切りの改行がこの上限を消費する。

## 実装すること

図版全体の展開量は、従来どおり各フィルタ段の出力を合算し、同じストリームを一度だけ数える。
以下の境界例は他の資源を展開せず、一段のフィルタを使う連結経路について示す。
内容量には隣接するストリーム間に挿入する改行 1 バイトも足す。
どちらも 256 MiB までとし、連結前に両方を検査する。

他の展開だけで上限を超えた場合は、連結後の長さにかかわらず失敗する。

## 実装しないこと

上限そのものは引き上げない。

## 不変条件

1. n 本（n ≥ 1）の内容を連結するとき、連結長は各内容長の和に n − 1 を足した値に等しい。

| 境界の入力 | 期待する結果 |
| --- | --- |
| 1本で256 MiB | 受理 |
| 2本で合計256 MiB引く1バイト | 受理 |
| 2本で合計256 MiB | 拒否 |

## テスト設計

- `inv1_imported_content_separators_property` で次の述語を検査する。n 本（n ≥ 1）の内容を連結するとき、連結長は各内容長の和に n − 1 を足した値に等しい。
- `inv1_imported_content_separators_case_1` は「1 本で 256 MiB」を入力とし、「受理」を確かめる。
- `inv1_imported_content_separators_case_2` は「2 本で合計 256 MiB 引く 1 バイト」を入力とし、「受理」を確かめる。
- `inv1_imported_content_separators_case_3` は「2 本で合計 256 MiB」を入力とし、「拒否」を確かめる。

## トレードオフ

連結後のメモリ量を制限できるが、分割数によって受理できる入力の総量が変わる。
