# ADR 0241: 図の原稿の約物の詰めを、既定のアキ量のセットの写しから決める

ステータス: 採択

## 文脈

[ADR 0239](0239-decide-the-conditions-of-the-outlined-figure-check-and-the-punctuation-of-figure-sources.md) は、二つのマニュアルの図の原稿の隣り合う約物を、Golem が本文を組むのと同じ空きで組むと決めた。
どの字を `halt` の `tspan` で包むかは、0239 の「実装すること」の 3 の表で決まる。
表は、その時点の既定のアキ量のセット `gyomatsu-yakumono-hankaku` の最適の空きを、手で写したものである。
`scripts/manual/outline-prepare.sh --check` は、その表を awk の分岐として持ち（[`punct`](https://github.com/tett23/golem/blob/16e10ba646f5391ed0b4e821006fe4214608676c/scripts/manual/outline-prepare.sh#L128-L146)）、約物の字の分類も自分で持つ（[`BEGIN` の分類](https://github.com/tett23/golem/blob/16e10ba646f5391ed0b4e821006fe4214608676c/scripts/manual/outline-prepare.sh#L147-L154)）。
`scripts/manual/check-figures.sh` は、`docs.yml` の `manual` ジョブで、これを二冊の原稿に当てる。

### 0039 から 0041 の後に食い違う組

[golem-layout ADR 0039](../golem-layout/adr/0039-set-consecutive-opening-brackets-and-brackets-beside-middle-dots-as-jlreq.md) と [golem-layout ADR 0040](../golem-layout/adr/0040-put-a-quarter-em-after-a-middle-dot-before-closing-brackets-and-full-stops.md) と [golem-layout ADR 0041](../golem-layout/adr/0041-take-the-ideographic-space-out-of-japanese-characters-in-the-default-aki-set.md) は、既定のセットの約物と和字間隔の組を変える。
0039 は PR #731 で実装中であり、0040 と 0041 は採択（未実装）である。
三つを実装した後、0239 の表は本文と次の組で食い違う。

- 始め括弧類が続く組（`（「`）は、本文がベタ組になり、0239 の表は「詰めない」のままである。
- 終わり括弧類と和字間隔の組（`）　`）と、和字間隔と始め括弧類の組（`　「`）は、本文が空きを置かなくなり、0239 の表は「詰めない」のままである。
- 中点類を含む組は、本文がどの組も約物の墨の外の空きだけで組めるようになるが、0239 の表は今もエラーにする。

0239 の表を手で直せば、この食い違いは消える。
しかし、表が既定のセットの二つめの写しである限り、既定のセットを次に変えたときに同じことが起きる。
今回も、0039 の文脈が書くとおり、食い違いは 0239 を書く途中で見つかった。

### 写しはすでにずれている

約物の字の分類も、写しのずれを持つ。
`outline-prepare.sh` は `〚`、`〛`、`〞` を括弧類に数える。
Golem の [`charClass`](https://github.com/tett23/golem/blob/16e10ba646f5391ed0b4e821006fe4214608676c/modules/golem-layout/src/Golem/Layout/CharClass.hs#L38-L54) は、この三字を括弧類に数えず、`Ideograph` とする。
本文は、この三字の前後に括弧類の空きを置かないので、`」〚` の `〚` を包めという今の検査は、本文と違う組み方を求める。
今の原稿にはこの三字がないので、検査の結果は変わらない。

### 本文の空きと、約物の字の墨の外の空き

本文は、約物の字を半角の箱として置く（[`punctSpace`](https://github.com/tett23/golem/blob/16e10ba646f5391ed0b4e821006fe4214608676c/modules/golem-layout/src/Golem/Layout/Japanese.hs#L796-L806)）。
始め括弧類は前に、終わり括弧類と句点類と読点類は後ろに二分、中点類は前後に四分の空きを、箱の外に持つ。
字の間には、既定のセットの規則（[`defaultAkiSet`](https://github.com/tett23/golem/blob/16e10ba646f5391ed0b4e821006fe4214608676c/modules/golem-layout/src/Golem/Layout/Aki.hs#L78-L106)）の最適の空きを置く。
図の原稿は `text-spacing-trim: space-all` で全角の字をそのまま並べるので、字の間には二つの字の墨の外の空きの和が残る。
その和から本文の空きを引いた量（以下、詰める量）が、`halt` で取り去るべき量である。

0239 の表は、この引き算を当時のセットの六つの組に当てた結果と一致する。
同じ引き算を、0041 の後のセットに当てると、次の表になる。
O は始め括弧類、C は終わり括弧類、F は句点類と読点類、M は中点類、S は和字間隔である。
「本文の空き」は 0041 の後の既定のセットの最適の空き（em）で、0039 から 0041 の「変えた後」の値から求めた。

### golem から既定のセットを読む手だて

`golem` の今のサブコマンド（`new`、`build`、`check`、`preflight`、`plugin`、`lint`、`fmt`、`lsp`、`inspect`、`explain`）には、アキ量のセットの値を書き出すものがない。
`check-figures.sh` は `docs.yml` で、golem を作らずに走る。
したがって、golem のサブコマンドから読むには、サブコマンドを足したうえで、`manual` ジョブで golem を作るか、`ci.yml` の成果物を取る必要がある。

一方、golem-layout のテストのスイート `golem-layout-test` は、すでに golem-layout に依存しており、`defaultAkiSet`、`charClass`、`punctSpace` を読める（三つとも公開のモジュールにある）。
このスイートに、三つの値を書き出したファイルと比べるゴールデンのテストを足せば、golem-* の build-depends を足さずに、コードと一致することが CI で保証されたファイルができる。
`check-figures.sh` はそのファイルを awk で読めばよく、golem を作る必要はない。

### 検査の厳しさの方針との関係

0239 の「決めたことの記録」は、ブラウザの検査を厳密にせず、致命的な崩れか、費用に比べて効果の大きいものだけを確かめると決めた。
`check-figures.sh` はブラウザの検査ではないが、同じ方針に照らして費用を見積もる。
この ADR の費用は、ゴールデンのテスト一つと、生成したファイル一つと、awk の読み込みである。
走らせる費用は、今の `check-figures.sh` とほとんど同じである。
効果は、既定のセットを変えるプルリクエストで、図と本文の食い違いが CI で見つかることである。
ただし、既定のセットを変える頻度は低く、0039 から 0041 の後にまた変える予定は、`docs/roadmap.md` に載っていない。
手で表を直す案（「メンテナーが決めること」の 1）より費用がかかるのは確かである。

## 実装すること

### 1. 既定のセットの写しのファイル

`golem-layout-test` に、ゴールデンのテストを一つ足す。
テストは、次の内容を `modules/golem-layout/test/golden/default-aki-set.tsv` と比べ、違えば失敗する。
`--accept` を付けて走らせると、ファイルを書き直す（tasty-golden を `golem-layout-test` の build-depends に足す。golem-* のパッケージではない）。

ファイルは UTF-8 で、行の終わりは LF である。
先頭の行は `#` で始まるコメントで、この ADR の番号と、書き直す手順（`cabal test golem-layout:golem-layout-test --test-options=--accept`）を書く。
続く行は、タブで区切った次の二種類である。

- `char` の行：`char`、字、クラスの名前、前の墨の外の空き、後ろの墨の外の空き。字は、U+3000 から U+30FF と U+FF00 から U+FFEF のうち、`charClass` が `Opening`、`Closing`、`MiddleDot`、`FullStop`、`Comma`、`IdeographicSpace` のどれかである字のすべてで、符号位置の順に並べる。空きは `punctSpace` の値である。
- `aki` の行：`aki`、前の位置の名前、後ろの位置の名前、最小、最適、最大。位置は 15 のクラスと `line-start`、`paragraph-start`、`line-end` で、`AkiPos` の `Ord` の順にすべての組（18 かける 18 の 324 行）を並べる。値は `akiBetween defaultAkiSet` の値である。

クラスと位置の名前は、`style.toml` のアキ量のセットの規則に書く名前（`opening`、`closing`、`middle-dot`、`full-stop`、`comma`、`ideographic-space` など）とする。
数は、既約の分数を `1/2` のように書き、整数は `0` のように書く。
`gyomatsu-yakumono-zenkaku` と利用者のセットは書かない。

### 2. 検査がファイルから詰める字を決める

`outline-prepare.sh` は、`--check` でも写しを作るときでも、このファイルを読む。
既定の場所は、スクリプトからの相対の `../../modules/golem-layout/test/golden/default-aki-set.tsv` とする。
テストのために、環境変数 `GOLEM_AKI_TABLE` でほかのファイルを渡せるようにする。
`BEGIN` の約物の分類と、`punct` の組ごとの分岐を消し、ファイルの `char` の行で字のクラスと墨の外の空きを決める。
ファイルの `char` の行にない字は、今の分類の `x` と同じく、約物とみなさない。

横書きの `text` の中で、`char` の行にある字が二つ隣り合う組のそれぞれで、詰める量 e を、前の字の後ろの墨の外の空きと後ろの字の前の墨の外の空きの和から、`aki` の行の最適の空きを引いて求める。
包む字は、次の順に決める。

1. e が 0 なら、どちらも包まない。
2. e が後ろの字の前の墨の外の空きと等しく、後ろの字が中点類でなければ、後ろの字を包む。
3. e が前の字の後ろの墨の外の空きと等しく、前の字が中点類でなければ、前の字を包む。
4. そのほかの組は、エラーにする。メッセージには組の二字と、詰める量を書く。

中点類を包むと、前と後ろの両方の組の空きが変わるので、中点類は包まない。
分数は、awk の浮動小数点の数にせず、分子と分母の整数のまま比べる。
縦書きの中の隣り合う約物と、`halt` 以外の要素を中に持つ `text` は、今のままエラーにする。
ファイルがない場合と、読めない行がある場合は、ファイルの名前と行の番号を書いてエラーにする。

### 3. 原稿と輪郭

`manual-dev/images/src/purity.svg` の 90 行目の `）　` の `）` を `<tspan class="halt">）</tspan>` で包み、`scripts/manual/outline-figures.sh manual-dev purity` で輪郭の SVG を作り直す。
ほかの原稿は変えない。

### 4. 文書

- `docs/manual-policy.md` の図の項の「どの字を包むかは、`scripts/manual/check-figures.sh` が CI で確かめる」に、包む字は本文の既定のアキ量のセットから決まり、その値は golem-layout のテストが書くファイルから読むことを足す。
- README の図の手順の、包む字を列挙した文（「包むのは、終わり括弧類、句点類、読点類の前の…」）と、中点類をエラーにする文を、この ADR の決め方に改める。既定のセットを変えたら `golem-layout-test` を `--accept` で走らせ、`check-figures.sh` が失敗すれば図の原稿を直すことを書く。
- README のゴールデンの節の、`--accept` を受け付けるスイートの列挙に `golem-layout-test` を足す。
- 開発者のマニュアルの `manual-dev/part2/15-manuals.gm` の図の段落に、包む字が本文の既定のアキ量のセットから決まることを書く。マニュアルの変更は ADR を要しないが、実装のプルリクエストに含める。
- 仕様書は変えない。この ADR は Golem の振る舞いを変えず、開発の手順だけを変える。
- 0239 のステータスの行に、「図の原稿の約物の詰めの表（実装すること 3 の表と、不変条件 I4 と、I7 の中点類の部分）は [docs/adr/0241](0241-derive-the-punctuation-of-figure-sources-from-the-default-aki-set.md)」を足す。

### 5. 実装の順

この ADR の実装は、[golem-layout ADR 0041](../golem-layout/adr/0041-take-the-ideographic-space-out-of-japanese-characters-in-the-default-aki-set.md) の実装がマージされた後の main から始める（「メンテナーが決めること」の 5）。
そうすれば、ゴールデンのファイルは最初から 0041 の後の値になり、3 の原稿の変更をこの ADR のプルリクエストに入れられる。

## 実装しないこと

- **`golem` のサブコマンドでアキ量のセットを書き出すこと**：利用者に見えるコマンドと出力の形が増え、`docs.yml` で golem を作る必要も生じる（「メンテナーが決めること」の 1）。
- **図ごとのアキ量のセットと、`gyomatsu-yakumono-zenkaku`**：0239 のとおり、図は既定のセットだけに合わせる。
- **約物と、ほかのクラスの字の組**：和欧間の空き（`j` と `w` の四分）は、ブラウザの `text` にない空きであり、0239 と同じく図に当てない。ほかの組は、0041 の後のセットの規則から引き算すると、どれも詰める量が 0 になる（規則から求めた値で、組んで確かめてはいない）。
- **両用の字（`‘`、`’`、`“`、`”`、`«`、`»`）**：`charClass` は括弧類とするが、1 の字の範囲の外にあり、今と同じく約物とみなさない。原稿のフォントでの字幅を確かめていない。
- **行頭、段落の先頭、行末の空き**：`aki` の行には書くが、0239 のとおり図の文字列に当てない。
- **縦書きの中の隣り合う約物**：0239 のとおりエラーのままとする。
- **ブラウザの検査（`svg-text.mjs`）の変更**：輪郭が原稿と一致するかの検査は、この ADR で変わらない。

## 不変条件

番号はこの ADR のものである。
0239 の I5、I6、I8 と、I7 の縦書きと `halt` 以外の要素の部分は、そのまま残る。
0239 の I4 と、I7 の中点類の部分は、F1 から F3 に置き換わる。

| 番号 | 不変条件 |
| --- | --- |
| F1 | `check-figures.sh` を通る原稿の横書きの `text` の中の、表の `char` の行にある字が隣り合うすべての組で、包まない側の墨の外の空き（前の字の後ろと後ろの字の前）の和が、表の `aki` の行の最適の空きと等しい。 |
| F2 | `check-figures.sh` を通る原稿で、中点類の字は `halt` で包まれない。 |
| F3 | 表の `char` の行にある二字の横書きの組のそれぞれで、包み方（包まない、前の字、後ろの字、両方）のうち `check-figures.sh` を通るものは、「実装すること」の 2 の手順が選ぶ一つだけであり、手順がエラーにする組では一つもない。 |
| F4 | `modules/golem-layout/test/golden/default-aki-set.tsv` のバイト列は、`golem-layout-test` が `defaultAkiSet`、`charClass`、`punctSpace` から書くバイト列と等しい。 |
| F5 | 表の `char` の行の字は、1 の範囲で 1 の六つのクラスのどれかに属する字のすべてであり、それ以外の字（`〚`、`〛`、`〞`、`“` など）を含まない。 |
| F6 | 手順がエラーにする組を持つ原稿、表のファイルがない場合、表に読めない行がある場合に、`check-figures.sh` は 0 でない終了コードで終わり、原稿か表の行の番号を標準エラーに書く。 |
| F7 | 同じ表と同じ原稿に対する `check-figures.sh` の終了コードと標準エラーのバイト列は、何度走らせても同じである。 |

## テスト設計

テストを先に書き、失敗することを確かめてから実装する。
テストの名前には、この ADR の番号と不変条件の番号（`ADR0241-F3` のように）を入れる。

- F4：`golem-layout-test` に、tasty-golden のテストを足す。ファイルがまだないので、最初は失敗する。
- F5：同じスイートに、HUnit のテストを足す。生成する `char` の行の字が、1 の範囲の字のうち六つのクラスに属するものと一致し、`〚`、`〛`、`〞`、`“` を含まないことを確かめる。
- F1 から F3：`scripts/manual/test.sh` に、実際の表についての総当たりのテストを足す（[ADR 0204](0204-pagination-invariants-by-exhaustive-small-inputs.md) の小さな入力の総当たり）。六つのクラスから一字ずつ代表の字を選び、二字の組の 36 通りのそれぞれについて、四つの包み方の原稿を作り、`check-figures.sh` を走らせる。通った包み方がちょうど一つ（手順がエラーにする組では零）であること（F3）と、通った包み方で F1 の等式が成り立つこと（F1）と、中点類を包んだ原稿がどれも通らないこと（F2）を確かめる。等式は、テストが表を自分で読んで計算する。境界の表の三つの字の組も、同じ形で足す。
- F6：`GOLEM_AKI_TABLE` で境界の表の fixture の表を渡し、終了コードと標準エラーの行の番号を確かめる。
- F7：同じ原稿と表で二度走らせ、終了コードと標準エラーを `cmp` で比べる。
- 0239 の `ADR0239-I4` と `ADR0239-I7` のテストのうち、この ADR で期待が変わるもの（`P O O with the third in halt`、`O S is not in the table`、`S P is not in the table`、`P and a middle dot`）は、この ADR の番号の名前で書き直す。期待の変わらないものは、0239 の名前のまま残す。

自動のテストにできないことは、実装のプルリクエストで次のように確かめる。

1. `purity.svg` の輪郭を作り直し、`check-figures.sh` が通ることを確かめる。
2. 実装のプルリクエストの説明に、生成したファイルの `aki` の行のうち六つのクラスの組の値が、「文脈」の表の「本文の空き」と一致することを書く。
3. ブラウザの検査（`browser.yml` の I4）は、マージの後の毎晩の実行に任せる。0239 の方針のとおり、このために検証の実行を足さない。

## トレードオフ

既定のセットの写しは、手で写した表から、テストが書き CI が一致を保証するファイルに変わる。
写しが一つ残ることは変わらないが、コードとずれたまま main に入ることはなくなる。
代わりに、既定のセットを変えるプルリクエストは、ゴールデンを `--accept` で書き直し、図の原稿に食い違いがあれば原稿を直して Inkscape で輪郭を作り直す必要がある。
これは、食い違いを作るプルリクエストにその始末を負わせることであり、0239 のときのように別の ADR を書く途中で見つかるよりも安い。

`scripts/manual/` のスクリプトが、`modules/golem-layout/test/` のファイルを読む。
build-depends は増えないが、ドキュメントの検査がモジュールのテストの置き場所に依存する。
ファイルを動かすと `check-figures.sh` は F6 のエラーで止まるので、気づかずに検査が空回りすることはない。

詰める量を引き算で決めると、0239 が「表にない」としてエラーにしていた組（O と S など）も通る。
引き算が 0 になる組は、ブラウザの `space-all` と本文が同じ空きで組むので、エラーにする理由がない。
中点類の組も通るようになるが、`space-all` の下で中点類を全角のまま並べた幅が、Chromium と Safari と Inkscape でそろうことは確かめていない。
そろわなければ、毎晩のブラウザの検査（I4）が幅の差として見つける見込みである。
四分の差は 20px の字で 5 画素であり、Chromium の大きさの上限の 2 画素を超える。

既定のセットの全体を書くと、ファイルは 350 行ほどになり、図の検査が使わない組（行頭、欧文など）も含む。
代わりに、既定のセットを変えるプルリクエストの差分に、変わった組と値が表の行として現れ、レビューで読める。
六つのクラスの組だけを書けば、ファイルは小さくなるが、この利点は失う（「メンテナーが決めること」の 3）。

この ADR は、費用に比べた効果が大きいとは言い切れない。
既定のセットを次に変える予定はなく、手で表を直せば、今の食い違いは同じく消える。
推奨の根拠は、0039 から 0041 の食い違いと、字の分類の三字のずれの、二つの実例である。

## メンテナーが決めること

1. **既定のセットの値をどこから読むか**：推奨は、`golem-layout-test` のゴールデンのファイルから読むことである。
   - 退けた案の一つは、0239 の表を手で直すことである。費用はいちばん小さいが、次に既定のセットを変えたときに同じ食い違いが起き、字の分類の写しのずれも残る。この ADR を却下するなら、この案が残る。
   - 二つめは、`golem` にアキ量のセットを書き出すサブコマンド（たとえば `golem inspect` の新しい `--as`）を足すことである。利用者に見えるコマンドと出力の形が仕様になり、`docs.yml` の `manual` ジョブで golem を作るか `ci.yml` の成果物を待つ必要が生じる。
   - 三つめは、`golem-layout-test` が `outline-prepare.sh` を読み、その表を `defaultAkiSet` と比べることである。Haskell のテストがシェルスクリプトの書き方に依存し、表の書き方を変えるたびにテストを直すことになる。
   - 四つめは、`check-figures.sh` が golem で小さな原稿を組み、PDF の字の位置から空きを測ることである。`manual` ジョブで golem とフォントが要り、費用が大きい。
2. **ファイルの置き場所**：推奨は、`modules/golem-layout/test/golden/default-aki-set.tsv` である。ほかのパッケージのゴールデンと同じく、テストのスイートの下に置く。
   - 退けた案は、`docs/golem-layout/` に置くことである。仕様書からリンクできるが、生成したファイルを `docs/` に置く前例がなく、手で直してよい文書と見分けにくい。
3. **ファイルに書く範囲**：推奨は、`aki` の行に既定のセットのすべての位置の組を書き、`char` の行は 1 の範囲の六つのクラスの字に限ることである。
   - 退けた案の一つは、`aki` の行も六つのクラスの組（36 行）に限ることである。ファイルは小さいが、既定のセットの変更を差分で読む利点を失う。
   - 二つめは、`char` の行に、六つのクラスに属するすべての字（両用の字を含む）を書くことである。両用の字の図での字幅を確かめていない。
4. **前と後ろのどちらも包める組**：推奨は、後ろの字を先に試すことである（2 の手順の 2 と 3 の順）。0239 の C と O の選び方と同じになり、今の原稿の `halt` が変わらない。
   - 退けた案は、前の字を先に試すことである。墨の位置は同じだが、今の原稿の五つの `」（` と `」「` の `halt` を書き換えることになる。
5. **実装の順**：推奨は、[golem-layout ADR 0041](../golem-layout/adr/0041-take-the-ideographic-space-out-of-japanese-characters-in-the-default-aki-set.md) の実装がマージされた後に実装することである。
   - 退けた案は、0039 の実装の後、0040 と 0041 の前に実装することである。仕組みは 0040 と 0041 のプルリクエストで試されるが、0041 のプルリクエストが purity の原稿を直して Inkscape で輪郭を作り直す必要が生じる。0041 のプルリクエストは見出しの番号などで出力の変化がすでに大きい。
6. **中点類の組を通すこと**：推奨は、引き算で組める中点類の組を通すことである。0041 の後のセットでは、どの組も中点類を包まずに組める。
   - 退けた案は、0239 のとおり中点類を含む組をエラーのまま残すことである。開発者のマニュアルの本文は「中黒（・）」のように中点類を括弧で括るので、図に同じ書き方をすると止まる。

## 決めたことの記録

- **「メンテナーが決めること」のすべて**（2026-11-09、メンテナー）：どれも推奨のとおりとした。
- **優先すること**（2026-11-09、メンテナー）：既定のままでそれなりの組版ができることを優先する。図の詰め方を本文の既定のアキ量のセットから決めるのは、既定の組み方を一か所で保つためである。
