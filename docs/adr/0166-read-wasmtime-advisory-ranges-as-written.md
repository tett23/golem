# ADR 0166: wasmtime のアドバイザリの範囲、修正版、パッケージを、上流の書き方のまま読む

ステータス: 採択

## 文脈

[ADR 0157](0157-check-wasmtime-pin-against-advisories.md) は、固定した wasmtime の版を、bytecodealliance/wasmtime のリポジトリのアドバイザリと毎日照合すると決めた。
範囲（`vulnerable_version_range`）は、カンマで区切った比較を書かれた順に読み、`>=` で区間を始めて `<` か `<=` で閉じる。
パッケージは `wasmtime` か `wasmtime-` で始まるものだけを照合し、ほかの名前は誤り（終了コード 2）とする。
0157 は採択されたが、実装はまだない。

### 0157 の規則を実際のデータに当てた結果

2026-11-05 に API で取得した 86 件のアドバイザリ（`vulnerabilities` の要素は 137）に、0157 の規則をそのまま当てた。
固定した 49.0.5 では、当たるものが 4 件、誤りが 11 件になり、終了コードは 2 である。
当たる 4 件は、どれも 49.0.5 に当たらないアドバイザリである。

- **上限を先に書いた範囲**：`<= 6.0.0, >= 0.37.0`（GHSA-ff4p-7xrq-q5r8）、`<= 6.0.0, >= 1.0.0`（GHSA-xm67-587q-r2vw）、`<= 0.38.1, >=0.37.0`（GHSA-5fhj-g3p3-pq9g）。0157 の規則は、これを「6.0.0 以下」と「0.37.0 以上」の和と読み、49.0.5 を含める。上流が意図したのは、0.37.0 から 6.0.0 までの一つの区間である。
- **上限のない範囲**：GHSA-vc8c-j3xm-xj73 の範囲は `>= 29.0.0` だけで、修正版（`patched_versions`）は `36.0.5, 40.0.3, 41.0.1` である。本文の Patches の節は、この三つの版で直したこと、ほかの系列は直さないので、サポートされたメジャー版に上げるよう書く。41.0.1 より後の 49.0.5 は直った版だが、範囲だけを読むと当たる。

誤りの 11 件は、二種類に分かれる。

- **パッケージ `cranelift-codegen`**：6 件（GHSA-5fhj-g3p3-pq9g、GHSA-7f6x-jwh5-m9r4、GHSA-ff4p-7xrq-q5r8、GHSA-hpqh-2wqx-7qp5、GHSA-jqwc-c49r-4w2x、GHSA-xm67-587q-r2vw）。cranelift は wasmtime と別の番号（49.0.5 には 0.136.5）を振るので、0157 は照合できないとした。うち GHSA-hpqh-2wqx-7qp5 は `cranelift-codegen` の要素だけを持つ。
- **読めない範囲の形**：5 件。`0.34.0, 0.34.1, 0.35.0, and 0.35.1`（GHSA-gwc9-348x-qwv2）、`<= 0.34.0 (excluding 0.33.1)`（GHSA-88xq-w8cq-xfg7）、`>= 0.26.0 && <= 0.29.0`（GHSA-4873-36h9-wv49）、`>=0.19.0 && <=0.29.0`（GHSA-v4cp-h94r-m7xf）、末尾にカンマの残った `>= 30.0.0, <= 36.0.7, >= 37.0.0, <= 43.0.1, 44.0.0,`（GHSA-p8xm-42r7-89xg）。`&&` の二件は、エコシステムが `crates.io` の古いアドバイザリである。

この状態で 0157 を実装すると、毎日の照合は初日から失敗し続ける。
失敗が常態になれば、本当に当たるアドバイザリが出たときの失敗も見落とされる。

### 範囲の書き方の二つの流儀

GitHub の Advisory Database の多くのアドバイザリでは、一つの `vulnerable_version_range` は、カンマで区切った比較の「かつ」で一つの区間を表す（`>= 1.0.0, < 1.0.1` の形）。
`<= 6.0.0, >= 0.37.0` はこの読み方で正しく読める。
一方、wasmtime の新しいアドバイザリは、`<36.0.19, >=37.0.0, <48.0.7, >=49.0.0, <49.0.4` のように、一つの要素に区間の和を書く。
これを「かつ」で読むと空の範囲になる。
二つの流儀は、比較を版の順に並べ替えてから区間に読めば、どちらも同じ規則で読める。
下限と上限の二項からなる範囲は、並べ替えると下限、上限の順になり、一つの区間になる。
和の形は、もともと版の順に書かれているので、並べ替えても変わらない。

### パッケージの版の出どころ

`licenses/wasmtime-v49.0.5/MANIFEST.tsv` は、`scripts/wasmtime-licenses.sh` が `crates/c-api` の `cargo metadata`（すべての機能、各ターゲット）から作った、`libwasmtime.a` に入りうるクレートの名前と版の一覧である（[ADR 0007](0007-third-party-licenses.md)）。
アドバイザリに出る六つのパッケージ（`wasmtime`、`wasmtime-wasi`、`wasmtime-wasi-http`、`wasmtime-c-api`、`wasmtime-c-api-impl`、`cranelift-codegen`）は、どれもこの一覧にある。
`cranelift-codegen` は `0.136.5` である。
wasmtime の版を上げるときは、この一覧も作り直してコミットする（CONTRIBUTING.md）。
リリースの `scripts/release/licenses.sh` は、固定した版の一覧がなければ止まる。

## 実装すること

0157 の照合のスクリプト `scripts/wasmtime-advisories.sh` の、範囲、修正版、パッケージの読み方を、次のとおりに変える。
取得、ワークフロー、出力の行、終了コードの意味（当たれば 1、誤りなら 2）、ドキュメントは 0157 のとおりとする。
0157 とこの ADR は、一つのプルリクエストで実装する。

### パッケージの版

- 固定した版 `V` は、0157 のとおり `fetch-wasmtime.sh --expected` から取る（テストでは環境変数 `WASMTIME_VERSION`）。
- パッケージの版は、`licenses/wasmtime-v$V/MANIFEST.tsv` の `package` と `version` の列から引く（テストでは環境変数 `WASMTIME_MANIFEST` でファイルを渡す）。ファイルがなければ誤りとする。
- アドバイザリのパッケージがこの一覧にあれば、一覧の版で照合する。同じ名前が複数の版で載っていれば、どれか一つでも当たれば当たりとする。
- 一覧にないパッケージは誤りとする。上流はクレートの名前を変えてきた（49 では内部のクレートが `wasmtime-internal-` で始まる名前になった）。「リンクしていない」と「名前が変わった」を区別できないので、黙って外さない。
- エコシステムは `rust` か `crates.io` に限り、ほかは誤りとする。

### 範囲

- 末尾の `(excluding A, B …)` を先に切り離し、括弧の中の版を除く版として持つ。括弧が末尾以外にあれば誤りとする。
- 残りを、カンマ、`&&`、単語の `and` で項目に分ける。各項目の前後の空白、比較の記号と版のあいだの空白を除く。空の項目は捨てる（末尾のカンマ）。
- 項目は `>=V`、`>V`、`<=V`、`<V`、`=V`、`V` のどれかで、`V` は `<数>.<数>.<数>` に限る。ほかは誤りとする。
- 項目を版の順に並べる。同じ版が二度出れば誤りとする。
- 並べた順に、次の規則で区間に読む。
  - 下限（`>=`、`>`）は区間を開く。開いた区間があれば誤りとする。
  - 上限（`<`、`<=`）は開いた区間を閉じる。開いた区間がなく、まだ区間が一つもなければ、下限のない区間として閉じる。ほかの場合は誤りとする。
  - 一つの版（`=V`、`V`）は、その版だけの区間とする。開いた区間があれば誤りとする。
  - 最後に開いた区間が残れば、上限のない区間とする。
- パッケージの版が除く版のどれかなら当たらない。そうでなく、どれかの区間に入れば、範囲に入ったとする。

### 修正版

範囲に入った版が、上限のない区間（`[L, ∞)`）に入ったときだけ、`patched_versions` を読む。
上限のある区間に入ったときは読まず、当たりとする。

- `patched_versions` を、カンマと単語の `and` で項目に分ける。項目は `V` か `>= V` で、どちらも版 `V` として読む。読めない項目があれば誤りとする。
- 系列を、メジャー版が 1 以上なら `<メジャー>`、0 なら `0.<マイナー>` とする。
- 修正版のうち、`L` 以上でパッケージの版以下のもの `P` があり、`P` がパッケージの版と同じ系列にあるか、`P` が修正版の最大であれば、直った版として当たりにしない。
- 直った版としたときは、`note: GHSA の ID<TAB>パッケージ<TAB>版<TAB>範囲<TAB>修正版` を標準エラーに書く。終了コードには影響しない。

上限のない区間に限る理由は、修正版と範囲が食い違う場面を、範囲が閉じていない場面に絞るためである。
GHSA-897f-g5gm-fmxm（`<36.0.19, >= 37.0.0, <43.0.0`、修正版は `36.0.19` だけ）では、37 から 42 の系列は直されていない。
修正版の最大より後なら直った、という規則を上限のある区間にも当てると、この 37.0.0 から 42.x を誤って外す。

### 0157 のステータス

0157 のステータスの行を「採択（未実装）→範囲、修正版、パッケージの読み方は [ADR 0166](0166-read-wasmtime-advisory-ranges-as-written.md)」に変える。
実装のプルリクエストで、両方を「採択」に変える。

## 実装しないこと

- 照合から外すアドバイザリの一覧。0157 が退けた理由（外す判断を誤ると黙って脆弱な版が残る）は今も成り立つ。この ADR で読めるようにした 15 件は、どれも人の判断ではなく、データの書き方を読むことで解決する。
- 上限のある区間で、修正版を見て当たりを外すこと。GHSA-hc7m-r6v8-hg9q（`<= 38.0.3`、修正版 `38.0.4, 37.0.3, 36.0.3, 24.0.5`）は、37.0.3 を範囲に含めるが修正版にも挙げる。範囲を信じて当たりとする。固定する版は最新の系列なので、古い系列での食い違いは今の照合に影響しない。
- cranelift の版を wasmtime の版から計算すること（49.0.5 なら 0.136.5）。対応は規則として公表されておらず、一覧から引けば足りる。
- 上流のアドバイザリのデータを直す依頼。依頼するかは tett23 が決める。

## テスト設計

`scripts/test.sh`（[ADR 0078](0078-tests-for-release-and-hand-run-scripts.md)）に足す。
fixture は、2026-11-05 に取得した 86 件のアドバイザリから、`ghsa_id`、`severity`、`summary`、`vulnerabilities`（`package`、`vulnerable_version_range`、`patched_versions`）だけを残した JSON とする。
パッケージの版は、`licenses/wasmtime-v49.0.5/MANIFEST.tsv` をそのまま使う。
49.0.2 の場面では、その一覧の `49.0.5` を `49.0.2` に、`0.136.5` を `0.136.2` に置き換えた fixture を使う。

0157 のテスト設計の項目は、`cranelift-codegen` を誤りとする項目を除いてそのまま残す。
次の項目を先に書き、0157 の規則で実装したものに当てて失敗させてから実装する。
ただし、0157 の規則は実装されていないので、範囲を読む関数の項目は、0157 の規則で書いた版を同じプルリクエストの最初のコミットに置いて失敗を確かめる。

### 範囲の読み方（一つのアドバイザリの fixture）

- `<= 6.0.0, >= 0.37.0` で、0.37.0、6.0.0 が当たり、0.36.9、6.0.1、49.0.5 が当たらない。
- `<= 6.0.0, >= 1.0.0` と `<= 0.38.1, >=0.37.0` で、49.0.5 が当たらない。
- `0.34.0, 0.34.1, 0.35.0, and 0.35.1` で、0.34.1 と 0.35.1 が当たり、0.34.2 が当たらない。
- `<= 0.34.0 (excluding 0.33.1)` で、0.34.0 と 0.33.0 が当たり、0.33.1 と 0.34.1 が当たらない。
- `>= 0.26.0 && <= 0.29.0` と `>=0.19.0 && <=0.29.0` で、0.29.0 が当たり、0.30.0 が当たらない。
- `>= 30.0.0, <= 36.0.7, >= 37.0.0, <= 43.0.1, 44.0.0,`（末尾のカンマ）で、44.0.0 と 36.0.7 が当たり、44.0.1 と 36.0.8 が当たらない。
- 0157 の項目（`<36.0.19, >=37.0.0, <48.0.7, >=49.0.0, <49.0.4` など）が、並べ替えの後も同じ結果になる。
- `>=49.0.0, >=50.0.0`、`~49.0`、`<= 1.0.0 (excluding 0.9.0) , >= 2.0.0`（括弧が末尾にない）、`>=49.0.0, <=49.0.0`（同じ版）で、終了コードが 2 である。
- `<36.0.0, <37.0.0`（区間のあとに下限のない上限）で、終了コードが 2 である。

### 修正版の読み方

- GHSA-vc8c-j3xm-xj73（`>= 29.0.0`、`36.0.5, 40.0.3, 41.0.1`）で、49.0.5、41.0.1、40.0.3、36.0.5 が当たらず、41.0.0、40.0.2、37.0.0、29.0.0 が当たる。49.0.5 のとき、標準エラーに `note:` の行が一つ出る。
- 同じ範囲で `patched_versions` が空なら、49.0.5 が当たる。
- 同じ範囲で `patched_versions` が `50.0.1` なら、49.0.5 が当たる。
- GHSA-897f-g5gm-fmxm（`<36.0.19, >= 37.0.0, <43.0.0`、`36.0.19`）で、37.0.0 と 42.0.0 が当たる。
- GHSA-3p27-qvp9-27qf（修正版に `44.0,3` という読めない項目がある、範囲は上限で閉じる）で、45.0.0 が当たり、49.0.5 で誤りにならない。修正版は、上限のない区間に入ったときだけ読むことを確かめる。
- 上限のない範囲に入り、修正版が読めない（`>= 29.0.0`、`41.0,1`）とき、終了コードが 2 である。

### パッケージの読み方

- `cranelift-codegen` の `<= 0.93.0, >= 0.88.0` は、一覧の `0.136.5` で照合して当たらない。同じ範囲を `0.90.0` を載せた一覧で照合すると当たる。
- 一覧にないパッケージ（`wasmtime-cranelift`）で、終了コードが 2 である。
- エコシステムが `npm` の要素で、終了コードが 2 である。
- 一覧に同じパッケージが二つの版で載り、片方だけが範囲に入るとき、当たる。
- `WASMTIME_MANIFEST` のファイルがないとき、終了コードが 2 である。

### fixture の全体

- 49.0.5 で、当たるものがなく、誤りがなく、終了コードが 0 である。標準エラーの `note:` は GHSA-vc8c-j3xm-xj73 の一行だけである。
- 49.0.2 で、当たるアドバイザリの ID の一覧が、次の 25 件と一致し、終了コードが 1 である。0157 の文脈が API の応答から数えた 25 件と同じ数である。GHSA-3982-jqvv-277m、GHSA-3r89-v5mq-j5xf、GHSA-54p9-vhhq-8f7q、GHSA-5hhx-4wrr-3j9g、GHSA-5qpp-g3j2-8frx、GHSA-63h4-6cx9-pjfj、GHSA-6fr9-xmw9-5352、GHSA-7v24-42x9-pxf7、GHSA-93g3-36p8-x2gc、GHSA-9prg-84vf-g5fc、GHSA-9pvw-hwfg-92h5、GHSA-h4wp-g4x3-7398、GHSA-hmmr-87qq-258j、GHSA-hmwq-g22x-qjw5、GHSA-jxcf-8qw5-5c33、GHSA-m6w2-jwq2-cv2c、GHSA-m9f7-9w4p-gv38、GHSA-mghf-wjfp-p5xm、GHSA-p79w-pv2r-29qp、GHSA-q554-3cjc-rx7p、GHSA-qw58-7h65-crq2、GHSA-r8xh-cgf7-392j、GHSA-vcg5-q8m5-8379、GHSA-w36r-2hch-9xp9、GHSA-wjc8-633q-pwxr。

この 25 件と 49.0.5 の結果は、ADR を書くときに、上の規則を作業用のスクリプトで fixture に当てて得た。
同じスクリプトで、fixture に出るすべての版とその前後の版について 0157 の規則と比べると、結果が変わるのは、上限を先に書いた三つの範囲と GHSA-vc8c-j3xm-xj73 だけだった（0157 で読めない 5 件の範囲を除く）。

自動テストにできないものは、0157 のとおり、`workflow_dispatch` で一度動かして 49.0.5 で成功することを確かめる。

## トレードオフ

- 修正版を読む規則は、上流が修正版を「その版から先は直っている」の意味で書くことに依存する。上限のない範囲で、最新の系列を直さず古い系列の修正版だけを挙げたアドバイザリが出ると、最新の系列を誤って外す。wasmtime はサポートしている系列（最新を含む）を同時に直して公表するので、この形は今のデータにない。外したときは `note:` の行が実行のログに残る。
- 範囲を版の順に並べ替えるので、書き間違えた範囲（`>= 37.0.0, < 36.0.0` など）も、和として広く読むことがある。広く読む誤りは、当たりが増える側（厳しい側）に倒れる。
- パッケージの版を、ライセンスの一覧から引く。一覧は、すべての機能とすべてのターゲットの閉包なので、実際に `libwasmtime.a` に入るものより広い。照合も広い側に倒れる。一覧が固定した版と食い違うと照合は誤り（終了コード 2）で止まる。
- 新しい書き方（`or`、`||`、`^` など）が現れると、照合は誤りで止まる。その日のうちに気付き、読み方を足す ADR を書く。
