# ADR 0164: `golem explain` の重複の除き方と、プラグインのコードの形の誤りの文を、誤りの場所ごとに決める

ステータス: 採択

## 文脈

[ADR 0151](0151-explain-uses-plugin-code-rule.md) は、`golem explain` が受けるプラグインのコードの形を golem-plugin の `pluginCodeForm` で判定し、形に合わない `/` を含む引数を使い方の誤り（終了コード 2）にした。
2026-11-05 の監査（[PR #541](https://github.com/tett23/golem/pull/541) の docs/audits/2026-11-05-gmx-and-ci-conformance.md の F-05 と F-06）は、0151 の実装に二つの低い所見を挙げた。
どちらも 0151 からの逸脱ではなく、0151 が決めなかったところに残った振る舞いである。

引用はすべて origin/main の 19d0ec3e のものである。

### 重複の除き方（F-05）

`explain` は、引数の列から `nubOrdOn T.toUpper` で重複を除いてから、一つずつ判定する（[cli/Main.hs#L248-L261](https://github.com/tett23/golem/blob/19d0ec3e0ac22110392a6a64160f59e0890786f6/modules/golem-cli/app/Main.hs#L248-L261)）。
この除き方は、大文字と小文字を区別しない Golem のコードのために [golem-cli ADR 0009](../golem-cli/adr/0009-explain-several-codes.md) が決めたものである。
0151 は「今の重複の除き方も変えない」とした。

一方、プラグインのコードの判定は大文字と小文字を区別する。
`/` の後は英小文字で始まらなければならず（[ADR 0139](0139-plugin-diagnostic-code-starts-with-letter.md)）、`/` の前の宣言の名前は `manifest.toml` の TOML のキーなので、`lk` と `LK` は別の宣言である。
大文字に直して同じになる二つの引数が、片方は正しく片方は誤っている、あるいは二つとも正しく別のコードである、ということが起きる。
重複を除く段階で後の引数が捨てられるので、結果が引数の順で変わる。

2026-11-05 に、[revert-gmx の 5657ab18](https://github.com/tett23/golem/commit/5657ab1834821f02f320f5670d60058087d90c42) から build した `golem`（`explain` と `pluginCode` は main の 19d0ec3e と同じ）で次を確かめた。

| 引数 | 標準出力 | 標準エラー出力 | 終了コード |
| --- | --- | --- | --- |
| `X/A x/a` | なし | `X/A` の形の誤りの一行 | 2 |
| `x/a X/A` | `x/a` の一行 | なし | 0 |
| `lk/x LK/x` | `lk/x` の一行 | なし | 0 |
| `LK/x lk/x` | `LK/x` の一行 | なし | 0 |
| `nope NOPE` | なし | `診断のコードは G と 5 桁の数字です: nope` | 2 |
| `NOPE nope` | なし | `診断のコードは G と 5 桁の数字です: NOPE` | 2 |

一行めと二行めは、同じ二つの引数の集合で、終了コードが 2 と 0 に分かれる。
二行めは、形の誤りの `X/A` を報告せずに 0 で終わる。
三行めと四行めは、別の宣言の二つのコードのうち、後のものを黙って落とす。

五行めと六行めの Golem のコードは、標準エラー出力の文に写る引数の綴りが違うだけで、誤りの種類も終了コードも同じである。
`checkCode` は大文字に直した値だけで正誤を決めるので（[cli/Main.hs#L148-L156](https://github.com/tett23/golem/blob/19d0ec3e0ac22110392a6a64160f59e0890786f6/modules/golem-cli/app/Main.hs#L148-L156)）、大文字に直して同じになる二つの Golem の引数は、必ず同じ判定になる。
重複を除いても失われるものはない。
プラグインのコードにはこの性質がない。

### 形の誤りの文（F-06）

`pluginCode` は、`/` を含む引数が形に合わないとき、どこが合わないかにかかわらず、`/ の後は英小文字で始まり、英小文字、数字、- だけからなります` の文を返す（[cli/Main.hs#L163-L171](https://github.com/tett23/golem/blob/19d0ec3e0ac22110392a6a64160f59e0890786f6/modules/golem-cli/app/Main.hs#L163-L171)）。
上と同じ `golem` で確かめると、次の引数はどれもこの文で終了コード 2 になった。

| 引数 | 実際に合わない場所 |
| --- | --- |
| `a/b/c` | `/` が二つある |
| `x /a` | `/` の前に空白がある |
| `/a` | `/` の前が空である |
| `x y/A` | `/` の前に空白があり、`/` の後も英大文字で始まる |
| `x/A` | `/` の後が英大文字で始まる |

`/` の後が正しい `a/b/c`、`x /a`、`/a` に「`/` の後は…」と書くのは、直す場所を誤って示す。
0151 のトレードオフは、Golem のコードに `/` を混ぜた場合の文の食い違いだけを挙げ、この三つを挙げなかった。

### 原則

- 同じ入力からは同じ出力を得る。この決定性は diagnostics と終了コードにも及ぶ。
- 緩く受けるより厳しく断る。誤りを黙って落とさない。
- 一つの原因に一つの報告を当てる。違う原因を一つの文にまとめない。

`golem explain` の文は diagnostic のコードではないが、使い方の誤りとして利用者に直す場所を伝える点では同じ役を持つので、同じ原則を当てる。

## 実装すること

### 重複の除き方

重複を除く前に、引数ごとに比べる値（キー）を決める。

- `/` を含まない引数（Golem のコードとして判定するもの）のキーは、大文字に直した値とする。今と同じである。
- `/` を含む引数（プラグインのコードとして判定するもの）のキーは、引数そのものとする。大文字と小文字を区別し、綴りが一字でも違えば別の引数として扱う。

キーが同じ引数は、最初に現れたものだけを扱う（[golem-cli ADR 0009](../golem-cli/adr/0009-explain-several-codes.md) と同じ）。
`/` は大文字に直しても `/` のままなので、`/` を含む引数と含まない引数のキーが同じになることはない。

```haskell
-- 重複を除くキー。Golem のコードは大文字と小文字を区別せず、プラグインのコードは区別する
dedupKey :: T.Text -> T.Text
dedupKey s
  | T.any (== '/') s = s
  | otherwise = T.toUpper s
```

`explain` の `nubOrdOn T.toUpper` を `nubOrdOn dedupKey` に置き換える。
重複を除く段階と判定の段階の順は今のままとする。

この後は、キーが同じ二つの引数は必ず同じ判定（正しいコード、未知のコード、形の誤りのどれか）になる。
Golem のコードは上の `checkCode` の性質により、プラグインのコードは綴りが同じなので、そうなる。
重複を除いて捨てる引数は、残した引数と同じ判定を受けるものだけになり、出力の節の集合、誤りの種類の集合、終了コードは、引数の順によらなくなる。
標準出力と標準エラー出力の並びは、今と同じくコマンドラインの順に従う。

上の表の引数は、次のようになる。

| 引数 | 標準出力 | 標準エラー出力 | 終了コード |
| --- | --- | --- | --- |
| `X/A x/a` | `x/a` の一行 | `X/A` の形の誤りの一行 | 2 |
| `x/a X/A` | `x/a` の一行 | `X/A` の形の誤りの一行 | 2 |
| `lk/x LK/x` | `lk/x` の一行、空行、`LK/x` の一行 | なし | 0 |
| `nope NOPE` | なし | `nope` の形の誤りの一行（今と同じ） | 2 |

### 形の誤りの文

`/` を含み、プラグインのコードの形に合わない引数は、次の順に検査し、最初に当たった一つの文を一行で標準エラー出力に書く。
文の前半（`プラグインの診断のコードの形が不正です: <引数>。`）は三つで共通とし、後半で直す場所を示す。

1. `/` を二つ以上含む。

   ```
   プラグインの診断のコードの形が不正です: <引数>。/ は一つだけです
   ```

2. `/` の前が空か、空白を含む。

   ```
   プラグインの診断のコードの形が不正です: <引数>。/ の前はプラグインの宣言の名前で、空でなく、空白を含みません
   ```

3. `/` の後が `pluginCodeForm` を満たさない。今の文のままとする。

   ```
   プラグインの診断のコードの形が不正です: <引数>。/ の後は英小文字で始まり、英小文字、数字、- だけからなります
   ```

`a/b/c` は 1、`x /a` と `/a` は 2、`x/A` と `x/404` と `G01017/` は 3 の文になる。
`x y/A` は 2 と 3 の両方に当たるが、2 の文だけを書く。
一つの引数に一行という [golem-cli ADR 0009](../golem-cli/adr/0009-explain-several-codes.md) の形を保つためである。

1 を先に検査するのは、`/` が二つ以上あると「`/` の前」と「`/` の後」が定まらないからである。
2 を 3 より先にするのは、引数の左から順に読む順に合わせるためである。

どの文も使い方の誤りとして扱い、終了コードを 2 とする。
正しいコードの節を書いた後に書き、使い方の表示は書かない。
これは 0151 と同じである。

`/` の前の宣言の名前の形は、今と同じく検査しない（[ADR 0151](0151-explain-uses-plugin-code-rule.md) の「実装しないこと」）。
2 の検査は、0151 の「空でなく、空白を含まない」をそのまま文にしたものである。

### データ構造

`pluginCode` の型は変えない。
`Left` に入れる文を、上の三つから選ぶ。

```haskell
pluginCode :: T.Text -> Maybe (Either T.Text T.Text)
pluginCode s
  | not (T.any (== '/') s) = Nothing
  | [name, c] <- T.splitOn "/" s = Just (check name c)
  | otherwise = Just (Left (bad "/ は一つだけです"))
  where
    check name c
      | T.null name || T.any isSpace name = Left (bad "/ の前はプラグインの宣言の名前で、空でなく、空白を含みません")
      | not (pluginCodeForm c) = Left (bad "/ の後は英小文字で始まり、英小文字、数字、- だけからなります")
      | otherwise = Right (s <> ": プラグインの診断のコードです。説明は golem にはないので、プラグインの文書を参照してください")
    bad why = "プラグインの診断のコードの形が不正です: " <> s <> "。" <> why
```

golem-\* のあいだの build-depends は変えない。

### 文書

- docs/specifications.md の「プラグイン」の節の `golem explain` の項（今の 3196〜3197 行め）に、三つの文と検査の順を書く。
- docs/specifications.md の CLI の表の `golem explain [CODE...]` の行と、README.md のコマンドの表の同じ行の「大文字に直して同じになるコードは最初のものだけを扱う」を、「Golem のコードは大文字に直して同じになるものを、プラグインのコードは綴りが同じものを、最初のものだけ扱う」の意に改める。
- 開発者のマニュアルの CLI の章（`manual-dev/part1/01-cli.gm`）の、`golem explain` が 2 で終わる場合の箇条（今の 133 行め）の「`/` の後が英小文字で始まらないなど」に、`/` が二つ以上あることと `/` の前が空か空白を含むことを足す。
- [ADR 0151](0151-explain-uses-plugin-code-rule.md) のステータスの行に、「重複の除き方と形の誤りの文は [ADR 0164](0164-explain-dedup-and-plugin-code-messages.md)」を足す。
- [golem-cli ADR 0009](../golem-cli/adr/0009-explain-several-codes.md) のステータスの行に、「プラグインのコードの重複の除き方は [docs/adr/0164](../../adr/0164-explain-dedup-and-plugin-code-messages.md)」を足す。

## 実装しないこと

- プラグインのコードの `/` の後を英小文字に直して受けること。`X/A` を `x/a` として扱うと、どのプラグインも出せないコードを正しいとすることになり、0139 と 0151 の厳しさに反する。
- Golem のコードの重複を、綴りが同じものに限ること。`G01017 g01017` が同じ節を二度書き、[golem-cli ADR 0009](../golem-cli/adr/0009-explain-several-codes.md) の決定とテストに反する。
- 一つの引数に当たるすべての誤りを報告すること（`x y/A` に 2 と 3 の二つの文を書くこと）。上の「形の誤りの文」に理由を書いた。
- `/` の前の宣言の名前の形を検査すること。0151 のとおり扱わない。
- 重複を除く前に判定し、判定の結果ごとに重複を除くこと。キーを分ければ同じ性質が得られ、段階の順を変えずに済む。
- `nope NOPE` の文に写る綴りを、引数の順によらないもの（大文字に直した値など）にすること。綴りは利用者が渡した最初の引数のものを写し、判定と終了コードは順によらないので、今のままとする。

## テスト設計

先に次のテストを golem-cli の `explainTests`（`modules/golem-cli/test/Main.hs`）に書き、今の main で失敗することを確かめてから実装する。
`badPluginCode` は、文の後半を引数に取る形に改める。

- `golem explain X/A x/a` が終了コード 2 で終わり、標準出力が `golem explain x/a` の標準出力と等しく、標準エラー出力が `X/A` の 3 の文の一行だけであること。今の main では標準出力が空で失敗する。
- `golem explain x/a X/A` が、上と同じ標準出力、標準エラー出力、終了コードになること。今の main では終了コード 0 で失敗する。
- `golem explain lk/x LK/x` が終了コード 0 で終わり、標準出力が `lk/x` の一行、空行、`LK/x` の一行であること。今の main では `LK/x` の一行がなく失敗する。
- `golem explain a/b/c` と `x/a/` と `/a/b` のそれぞれが、終了コード 2 で終わり、標準出力が空で、標準エラー出力が 1 の文の一行だけであること。今の main では 3 の文なので失敗する。
- `golem explain "x /a"`、`/a`、`"x y/A"`、`/A` のそれぞれが、終了コード 2 で終わり、標準出力が空で、標準エラー出力が 2 の文の一行だけであること。今の main では 3 の文なので失敗する。

次のテストは今も通るが、変えずに通り続けることを確かめる。

- `x/404`、`x/-`、`x/0`、`x/2x`、`x/-a`、`lookup/No-key` が 3 の文になること（今のテスト）。`G01017/` を足す。
- `golem explain G01017 g01017 G01002 G01017` と `G01017 G0101 nope G0101` のテスト（[golem-cli ADR 0009](../golem-cli/adr/0009-explain-several-codes.md)）。
- `golem explain nope NOPE` が終了コード 2 で終わり、標準エラー出力が `診断のコードは G と 5 桁の数字です: nope` の一行だけであること（新たに足す）。
- `golem explain x/a x/a` が `x/a` の一行だけを書いて終了コード 0 で終わること（新たに足す）。
- golden の `explain-bad-code` と `explain-unknown-code`。

## トレードオフ

- 重複の除き方が、Golem のコードとプラグインのコードで分かれる。一つの規則で説明できなくなるが、二つの判定が大文字と小文字を区別するかどうかで分かれている以上、除き方も分けないと結果が順で変わる。
- `lk/x LK/x` のように、利用者が大文字と小文字を取り違えた同じコードのつもりの二つも、二行になる。宣言の名前は TOML のキーで大文字と小文字を区別するので、二つは別のコードであり、片方を黙って落とすより二行のほうが正しい。
- `x y/A` のように二つの場所が誤っている引数は、一つめを直した後に、もう一度実行して二つめの文を見ることになる。一つの引数に一行という形と、一つの文に一つの原因という形を保つことを優先した。ごく稀な入力である。
- 2 の文は「空である」と「空白を含む」の二つの条件を一つの文にまとめる。二つは `/` の前という同じ場所の同じ規則（0151 の「空でなく空白を含まない」）であり、3 の文が 0139 の形の複数の条件を一つにまとめているのと同じ粒度とした。
- `/` の前の名前の形を検査しないので、`G01017/x` は今と同じくプラグインのコードとして受ける。

## 決めてほしい点

- **重複を除くキー**：推奨は、`/` を含む引数は綴りそのもの、含まない引数は大文字に直した値とすること。退けた案は、すべての引数を綴りで比べること（`G01017 g01017` が二度書かれ、[golem-cli ADR 0009](../golem-cli/adr/0009-explain-several-codes.md) に反する）、プラグインのコードの `/` の後を英小文字に直して受けること（緩く受けることになる）、大文字に直して同じになる引数のうち一つでも誤っていれば全体を誤りとすること（`lk/x LK/x` の二つの正しいコードを誤りにしてしまう）。
- **形の誤りの文の数**：推奨は、誤りの場所（`/` の数、`/` の前、`/` の後）ごとに三つとすること。退けた案は、`/` の前を「空である」と「空白を含む」に分けて四つにすること。分けたほうが細かいが、同じ規則の二つの条件であり、`/` の後の文の粒度と揃わない。
- **一つの引数に二つ以上の誤りがある場合**：推奨は、`/` の数、`/` の前、`/` の後の順に検査し、最初の一つだけを書くこと。退けた案は、当たった誤りをすべて一行ずつ書くこと（一つの引数に一行という [golem-cli ADR 0009](../golem-cli/adr/0009-explain-several-codes.md) の形が崩れ、誤りの行数が引数の数と合わなくなる）と、一行に原因を並べること（組み合わせの数だけ文が増える）。
