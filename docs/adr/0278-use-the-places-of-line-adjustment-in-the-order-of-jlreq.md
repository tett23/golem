# ADR 0278: 行の調整で、詰める箇所と空ける箇所を JLReq の優先順位の順に使う

ステータス: 採択（未実装）

## 文脈

### ロードマップの項目

[docs/roadmap.md](../roadmap.md) の v1.0.0 の「行分割と禁則」に、次の項目がある。

- **行の調整の順**：行を詰める処理と空ける処理を、JLReq の 3.8.3（詰める処理の優先順位）と 3.8.4（空ける処理の優先順位）の順で行う。今は、行の比を行のすべてのグルーに同じ割合で掛ける。順に従うには、グルーの種類（約物の空き、和欧間、欧文間隔、字間）を行分割の項目に持たせ、段ごとに比を求める置き方が要る。「追い込みと追い出しの設定」（[ADR 0274](0274-prefer-pulling-in-and-limit-the-stretch-of-lines.md)）とは別の ADR で決める。

[ADR 0274](0274-prefer-pulling-in-and-limit-the-stretch-of-lines.md) は、追い込みを優先する量り方と行の伸びの上限を決め、この順を範囲の外に置いた。
採択のときに、tett23 はこの順を v1.x に回さず、v1.0.0 で別の ADR として扱うと決めた（[ADR 0274](0274-prefer-pulling-in-and-limit-the-stretch-of-lines.md) の「決めたことの記録」の 7）。
この ADR がその別の ADR である。

### 今の置き方

PDF の段落は、Knuth と Plass の方式で行に分ける（[golem-layout ADR 0001](../golem-layout/adr/0001-knuth-plass-line-breaking.md)）。
行分割の項目のグルーは、幅、伸び、縮みの三つの値だけを持つ（[`Item`](https://github.com/tett23/golem/blob/7e8fe7d3d59d893342c0e55a1cb6d1a39245a482/modules/golem-layout/src/Golem/Layout/KnuthPlass.hs#L149-L153)）。
どの空きから作ったグルーか（語間の空白か、読点の後ろの二分か、仮名と漢字のあいだか）は、項目に残らない。

決まった分割の行を置くときは、足りない幅か余る幅を、行のグルーの伸びか縮みの合計で割った比を求め、すべてのグルーに同じ比を掛ける（[`placeLine`](https://github.com/tett23/golem/blob/7e8fe7d3d59d893342c0e55a1cb6d1a39245a482/modules/golem-layout/src/Golem/Layout/KnuthPlass.hs#L524-L543)、[`glueRatio`](https://github.com/tett23/golem/blob/7e8fe7d3d59d893342c0e55a1cb6d1a39245a482/modules/golem-layout/src/Golem/Layout/KnuthPlass.hs#L545-L565)）。
欧文の字幅の伸縮（[golem-layout ADR 0005](../golem-layout/adr/0005-microtypography.md)）を使う段落では、字幅が先に取り分を取り、残りをグルーに配る。

グルーの量は、語間の空白とアキ量のセット（[docs/adr/0019](0019-aki-settings.md)）から決まる。
既定のセット `gyomatsu-yakumono-hankaku` の値は次のとおりである（[`defaultAkiSet`](https://github.com/tett23/golem/blob/7e8fe7d3d59d893342c0e55a1cb6d1a39245a482/modules/golem-layout/src/Golem/Layout/Aki.hs#L78-L119)、語間の空白は [`itemsFor`](https://github.com/tett23/golem/blob/7e8fe7d3d59d893342c0e55a1cb6d1a39245a482/modules/golem-layout/src/Golem/Layout/Japanese.hs#L1235-L1242)）。

| 空き | 最小 | 最適 | 最大 |
| --- | --- | --- | --- |
| 語間の空白（欧文間隔） | 送りの 2/3 | 空白の送り | 送りの 3/2 |
| 中点類の前と後ろ | 0 | 四分 | 四分 |
| 始め括弧類の前、終わり括弧類と読点と句点の後ろ | 0 | 二分 | 二分 |
| 和文の字と欧文のあいだ（和欧間） | 八分 | 四分 | 二分 |
| 仮名と漢字の前（字間） | 0 | 0 | 1/10 em |

行末の約物の後ろの空きは、グルーではなく、行の最後の箱の端に置く固定の量である（[`withEdges`](https://github.com/tett23/golem/blob/7e8fe7d3d59d893342c0e55a1cb6d1a39245a482/modules/golem-layout/src/Golem/Layout/Japanese.hs#L1759-L1767)）。
`gyomatsu-yakumono-hankaku` ではこの量は 0 であり、`gyomatsu-yakumono-zenkaku` では二分（中点類は前後に四分）で縮まない（[`builtinAkiSets`](https://github.com/tett23/golem/blob/7e8fe7d3d59d893342c0e55a1cb6d1a39245a482/modules/golem-layout/src/Golem/Layout/Aki.hs#L121-L130)）。
どちらのセットでも、行末の空きは行の調整に使わない。

同じ比を掛けるので、読点と語間の空白を含む行を詰めると、読点の後ろと語間は同じ割合で縮む。
仮名と漢字のあいだと和欧間を含む行を空けると、和欧間は字間の 2.5 倍の速さで広がる（伸びが 1/4 em と 1/10 em なので）。
どちらも、JLReq の順とは違う。

### JLReq の詰める順と空ける順

JLReq の 3.8.2 は、行の調整に使える箇所を、規定の空き量を詰める処理（追込み処理）と字間を空ける処理（追出し処理）に分ける。
3.8.3 と 3.8.4 は、それぞれについて、どの箇所をどの順に、どこまで使うかを定める。
どちらの段も、その段の箇所を「文字サイズ比で均等に」詰めるか空ける。

3.8.3 は、詰める順として次の六つの段を挙げる。

- a. 欧文間隔（cl-26）を、最小で四分まで。
- b. 行末の終わり括弧類、読点類、句点類の後ろの二分を、ベタ組に。
- c. 行末の中点類の前後の四分を、一緒にベタ組に。
- d. 行中の中点類の前後の四分を、最小でベタ組まで。
- e. 行中の始め括弧類の前、終わり括弧類と読点類の後ろの二分を、最小でベタ組まで。
- f. 和欧間の四分を、最小で八分まで。

3.8.3 は続けて、JIS X 4051 の順として、b と c を除いた四つの段（a、d、e、f）を挙げる。
JIS X 4051 は行末の終わり括弧類、読点類、中点類の後ろをベタ組にするので、b と c に当たる箇所がない。
既定のセット `gyomatsu-yakumono-hankaku` も行末をベタ組にするので、Golem の既定は JIS X 4051 の四つの段と一致する。

3.8.3 の注は、ほかの組み方も挙げる。

- 句点類の後ろの二分は、文の区切りとしての役割が大きいので、行末のほかでは調整に使わない。
- 始め括弧類の前と終わり括弧類の後ろを、読点類の後ろより先に詰める例がある。
- 和欧間の四分を、固定した空き量として調整に使わない例がある。

3.8.4 は、JIS X 4051 の空ける順として、次の四つの段を挙げる。

- a. 欧文間隔を、最大で二分まで。
- b. 和欧間の四分を、最大で二分（又は三分）まで。
- c. a と b のほかの、空ける処理を避けるとされていない箇所の字間を、最大で四分まで。
- d. a から c の段で調整できない場合は、a から c の箇所に加え、分割禁止とされていない字間を均等に空ける。

付録の「行の調整処理で空ける処理が可能な箇所」は、d の段を、それまでの段で空けた量に追加して、第 1 段階から第 4 段階までの箇所を均等に空けると説明する。
付録の表（表 3 から表 6）は PDF 版にだけあり、この ADR の作成では読んでいない。
箇所ごとの可否（たとえば約物の空きを d の段で空けるか）は、表を読まないと確かめられない。

### 今の出力で順が置き方を変える行

二つのマニュアルを組み、行ごとに順で置き方が変わるかを数えた。
方法は次のとおりである。

- origin/main（`71df05af`、[ADR 0274](0274-prefer-pulling-in-and-limit-the-stretch-of-lines.md) の実装の前）の golem に、決まった行の項目を書き出す一行を足して組んだ（main には入れていない）。
- 行の字と比と行の幅の組で重複を除き、段落の最後の行、両端を揃えない段落の行、はみ出す行を除いた。
- グルーの種類は、幅と伸びと縮みの形から推定した（字間は幅 0 で伸びだけ、約物の空きは縮みが幅に等しい、など）。マニュアルは欧文の語の前後に空白を書くので、和欧間の多くは語間の空白のグルーになる。
- 「実装すること」の既定の順で置いた量と、今の同じ比の量を、グルーごとに比べた。本文は約 9.2 pt なので、0.5 pt は約 0.05 em である。

| 数えた行 | 利用者のマニュアル | 開発者のマニュアル |
| --- | --- | --- |
| 両端を揃える行 | 5,571 | 3,152 |
| 詰める行 | 1,625 | 968 |
| そのうち、種類の違うグルーを二つ以上縮める行 | 1,332 | 887 |
| そのうち、語間の空白だけで詰め終わる行 | 399 | 345 |
| 詰める行で、あるグルーの量が 0.5 pt を超えて変わる行 | 789 | 556 |
| 同じく 1 pt を超えて変わる行 | 95 | 76 |
| 空ける行 | 3,478 | 1,930 |
| そのうち、種類の違うグルーを二つ以上伸ばす行 | 2,132 | 1,442 |
| そのうち、語間の空白だけで空け終わる行 | 633 | 529 |
| 空ける行で、あるグルーの量が 0.5 pt を超えて変わる行 | 1,370 | 845 |
| 同じく 1 pt を超えて変わる行 | 53 | 43 |
| 空ける行で、最後の段（3.8.4 の d）まで使う行 | 414 | 140 |

詰める行の 8 割から 9 割、空ける行の 6 割から 7 割で、種類の違うグルーが同時に動いている。
順を入れると、その多くで語間の空白が先に動き、約物の空きと字間が動かなくなるか、動く量が減る。
数は種類の推定と試算によるもので、実装して組み直した数ではない。
英語の本（Nightmare Abbey）は数えていない。
英語の段落のグルーは語間の空白だけなので、文字の大きさが一つなら置き方は変わらない（不変条件の A7）。

### [ADR 0274](0274-prefer-pulling-in-and-limit-the-stretch-of-lines.md) との分担

[ADR 0274](0274-prefer-pulling-in-and-limit-the-stretch-of-lines.md) は、どの分割を選ぶか（詰める行の量り方）と、行の伸びの上限を決めた。
上限は、決まった分割の行を置くときにだけ当て、分割を変えない（[ADR 0274](0274-prefer-pulling-in-and-limit-the-stretch-of-lines.md) の R7）。
この ADR が決めるのは、決まった行の中で、詰める量と空ける量をどのグルーにどれだけ配るかである。
分割の量り方は、[ADR 0274](0274-prefer-pulling-in-and-limit-the-stretch-of-lines.md) のまま変えない。

InDesign の文字組みアキ量設定には、行の調整の優先順位に当たる設定があると考えられる。
InDesign は Golem の開発の環境で動かせないので、その振る舞いは確かめていない。
この ADR は JLReq の記述に従う。

## 実装すること

### 1. グルーの種類

行分割の項目のグルーに、種類を持たせる。
種類は、そのグルーを作った空きで決まり、アキ量のセットの規則によらない。

| 種類（`style.toml` の名前） | グルー | JLReq の段 |
| --- | --- | --- |
| `word-space` | 語間の空白（本文の中のコードと上付き、下付きの範囲の空白を除く） | 3.8.3 の a、3.8.4 の a |
| `middle-dot` | 前か後ろの字が中点類である空き | 3.8.3 の d |
| `brackets` | 始め括弧類の前、終わり括弧類の後ろの空き | 3.8.3 の e |
| `comma` | 読点類の後ろの空き | 3.8.3 の e |
| `full-stop` | 行中の句点類の後ろの空き | 3.8.3 の注は、行中では調整に使わないとする |
| `paragraph-start` | 段落の先頭の空き（始め括弧類と中点類の前） | なし |
| `japanese-western` | 和文の字と欧文の字のあいだの空き | 3.8.3 の f、3.8.4 の b |
| `between-characters` | ほかの和文の字のあいだの空き（仮名と漢字の前の伸び） | 3.8.4 の c |

二つの字のあいだの空きは、表の上から順に当てて、最初に当たる種類とする。
段落の先頭の空きは、後ろの字の分類によらず `paragraph-start` とする。
終わり括弧類か読点類の後ろに中点類が来る空き（既定のセットで 3/4 em）は、`middle-dot` になる。

どれにも当たらないグルー（本文の中のコードの空白、段落の終わりのグルーなど）は、名前を持たない種類とする。
両端を揃えない段落でグルーの伸びを 0 にする処理（[docs/adr/0189](0189-paragraph-alignment-spacing-and-end-indent.md)）は、種類を変えない。

段落の終わりのグルー（`filStretch` の伸び）と、両端を揃えない段落の行の端の伸び（[docs/adr/0189](0189-paragraph-alignment-spacing-and-end-indent.md)）は、今のとおり扱う。
段落の終わりのグルーのある行は、そのグルーがすべての伸びを受け持つ。

### 2. 詰める順と空ける順

詰める行（足りない幅が負の行）は、詰める量を次のように配る。
詰める量は、今と同じく、字幅の圧縮が取り分を取った残りである。

1. 段落スタイルの `shrink-order`（3）の段を、書いた順に並べる。どの段にも書かれていない種類は、すべてを一つの段にまとめて最後に置く。
2. 前の段から順に、その段の種類のグルーの縮みの合計を、その段の容量とする。
3. 残りの詰める量が容量以下なら、その段のグルーを、それぞれの縮みに比例して詰め、終える。容量を超えるなら、その段のグルーを縮みの限度まで詰め、残りを次の段に回す。
4. すべての段で詰めても残るなら、行ははみ出す。すべてのグルーを縮みの限度まで詰める（今の比 −1 と同じ）。

空ける行（足りない幅が正の行）は、空ける量を次のように配る。

1. 段落スタイルの `stretch-order` の段を、詰める行と同じく並べ、書かれていない種類の段を最後に置く。
2. 前の段から順に、その段の種類のグルーを、それぞれの伸びに比例して、伸びの限度まで空ける。
3. すべての段で限度まで空けても残る量は、最後の段（3.8.4 の d）で配る。伸びが正のすべてのグルーに、そのグルーの文字の大きさに比例して足す。どのグルーも同じ em の数だけ広がる。伸びが正で大きさを持つグルーがない行では、伸びに比例して足す。
4. 伸びが正のグルーがない行は、今のとおり、足りないまま行頭にそろえる（[docs/adr/0222](0222-line-breaking-points-the-invariants-did-not-decide.md)）。

段の中では、同じ段のすべてのグルーが同じ割合（そのグルーの縮みか伸びに対する比）で動く。
アキ量のセットの空きでは、同じ種類の空きはどれも同じ em の数の範囲を持つので、これが JLReq の「文字サイズ比で均等」に当たる。

グルーの伸びと縮みの値（アキ量のセットの最小と最大、語間の空白の値）は変えない。
段の限度は、今のアキ量のセットの最小と最大である。
既定のセットの字間の伸びの限度は 1/10 em のままであり、3.8.4 の c の四分ではない（「メンテナーが決めること」の 3）。

### 3. 段落スタイルの欄 `shrink-order` と `stretch-order`

段落スタイルに、二つの欄を足す。
値は配列で、要素は 1 の種類の名前か、名前の配列（同じ段に置く種類）である。

```toml
[paragraph-styles.body]
shrink-order = ["word-space", "middle-dot", ["brackets", "comma"], "japanese-western"]
stretch-order = ["word-space", "japanese-western", "between-characters"]
```

既定は、この例の値である。
`shrink-order` の既定は、3.8.3 の JIS X 4051 の四つの段（a、d、e、f）であり、JLReq の六つの段から行末の二つの段を除いた順と同じである。
書かれていない `full-stop`、`paragraph-start`、`between-characters` は、最後の段になる。
既定のセットでは `between-characters` に縮みがないので、最後の段は句点類の後ろと段落の先頭の空きである。
`stretch-order` の既定は、3.8.4 の a から c の段である。

書き手は、たとえば次のように書ける。

- 括弧類を読点類より先に詰める（3.8.3 の注）：`shrink-order = ["word-space", "middle-dot", "brackets", "comma", "japanese-western"]`
- すべてを同じ割合で詰める（今の詰め方）：`shrink-order = []`

`based-on` で引き継ぎ、`@style-def` でも書ける。
欄を当てる段落（本文、キャプション、傍注、表のセル、目次の項目、注、定義リストと箇条書き）と、`code` に書けないことは、[ADR 0274](0274-prefer-pulling-in-and-limit-the-stretch-of-lines.md) の `line-adjustment` と `stretch-limit` と同じとする（[ADR 0274](0274-prefer-pulling-in-and-limit-the-stretch-of-lines.md) の「実装すること」の 3）。

### 4. 値の検査

次の値は、その値の位置で G03006 とする。
新しいコードは足さない。
G03006 は `style.toml` の値の誤りのコードであり、[ADR 0274](0274-prefer-pulling-in-and-limit-the-stretch-of-lines.md) の二つの欄と同じ原因の分類である。

- 配列でない値。
- 文字列でも文字列の配列でもない要素、空の内側の配列、内側の配列の中の配列。
- 1 の表にない名前。
- 同じ欄に二度書いた名前。二度めの位置で G03006 とする。

`code` に書いた欄は、今の規則のとおり G03006 とする。

### 5. 行分割の項目と置き方

`golem-layout` の `Glue` に、二つの欄を足す。

- **`itemKind :: !GlueKind`**：1 の種類。名前を持たない種類を `OtherGlue` とする。
- **`itemZw :: !Sp`**：そのグルーの文字の大きさ（1 zw）。2 の最後の段の比に使う。アキ量のセットの空きは、空きの量を決めた大きさ（[`normalize` の `between` の `base`](https://github.com/tett23/golem/blob/7e8fe7d3d59d893342c0e55a1cb6d1a39245a482/modules/golem-layout/src/Golem/Layout/Japanese.hs#L1801-L1833)）、語間の空白はその空白の文字の大きさとし、`OtherGlue` は 0 とする。

`Params` に、順を表す欄 `pAdjustOrder :: AdjustOrder` を足す。

```haskell
data AdjustOrder
  = AdjustUniform
  | AdjustStaged {aoShrink :: [[GlueKind]], aoStretch :: [[GlueKind]]}
```

`AdjustUniform` は、今の置き方（すべてのグルーに同じ比）である。
`defaultParams` は `AdjustUniform` とし、`golem-layout` だけを使う呼び出しの出力を変えない。
段落スタイルから値を渡す箇所（[ADR 0274](0274-prefer-pulling-in-and-limit-the-stretch-of-lines.md) の 3 と同じ）で、`AdjustStaged` を当てる。

`Line` に `lineAdjustOrder` を足し、`mkLine` が `Params` の値を写す（[ADR 0274](0274-prefer-pulling-in-and-limit-the-stretch-of-lines.md) の `lineStretchLimit` と同じ）。
`placeLine` は、行の比の代わりに、グルーごとの量の一覧（`glueAmounts :: Line -> [Rational]`）を使う。
`glueRatio` は、`AdjustUniform` の行の量と、今のテストのために残す。

行分割の判定（`evaluate` の不良度、罰点、適合度、段階、送り出し）は、グルーの伸びと縮みの合計だけを読み、種類と順を読まない。
順を変えても、分割は変わらない（A1）。

量はすべて有理数で求め、置く位置を一度だけ丸める（今の `placeLine` と同じ）。
段の順は書いた順と 1 の表の順で決まり、同じ値の比べ合いがないので、同じ入力からは同じ量が出る。

### 6. ほかの調整との関係

- **伸びの上限（`stretch-limit`）**：[ADR 0274](0274-prefer-pulling-in-and-limit-the-stretch-of-lines.md) の上限 m を書いた段落では、空ける量を、伸びの合計の m/1000 倍で頭打ちにしてから、2 の順で配る。行の項目の終わりの位置は、[ADR 0274](0274-prefer-pulling-in-and-limit-the-stretch-of-lines.md) の R6 のとおりである。上限が最後の段より前の段で頭打ちにすると、最後の段は使われない。
- **[ADR 0274](0274-prefer-pulling-in-and-limit-the-stretch-of-lines.md) の R5**：R5 の前半「はみ出していない行の `glueRatio` は m/1000 以下である」は、`AdjustStaged` の行では「行に足す伸びの合計が、行の伸びの合計の m/1000 倍以下である」と読む。段に分けると、一つのグルーの伸びの比は m/1000 を超えうる（先の段のグルーは限度まで伸びる）からである。
- **追い込みの優先（`line-adjustment`）**：分割の量り方なので、この ADR は変えない。
- **字幅の伸縮**：今のとおり、字幅が先に取り分を取り、残りを 2 の順で配る。JLReq に字幅の伸縮の段はない。
- **ぶら下げ組**：句読点を行長の外に出す処理は、行の自然な幅を変えるだけで、グルーを作らない。2 の配り方は変わらない。
- **行末の約物の空き**：箱の端の固定の量なので、どの段にも入らない（「実装しないこと」）。

### 7. HTML と EPUB

HTML と EPUB には書き出さない。
CSS に、行の調整の順を指定する性質はない。

### 8. 文書

- [docs/specifications.md](../specifications.md) の段落スタイルのキーの一覧に二つの欄を足し、「行分割」の節に、グルーの種類、二つの順、既定の値、最後の段の配り方を書く。表のセル、キャプション、傍注に当てる欄の一覧にも足す。
- 同じ節の「送り出した行は伸びの許すかぎり字間を空けて行長にそろえる」に、空ける量を 2 の順で配ることを足す。
- [TeX と InDesign との差異](../differences-from-tex-and-indesign.md) に、TeX はすべてのグルーに同じ比を掛けること、Golem は JLReq の順に段を分けること、InDesign の優先順位の設定を確かめていないことを書く。
- [docs/roadmap.md](../roadmap.md) の v1.0.0 の「行分割と禁則」から「**行の調整の順**」の行を消す。
- 実装のプルリクエストで、[ADR 0274](0274-prefer-pulling-in-and-limit-the-stretch-of-lines.md) のステータスの行に、R5 の前半の読み方はこの ADR が決めることを足す。

### 9. 出力の変化

分割は変わらないので、行の数、ページの数、ページの分け方は変わらない。
変わるのは、行の中の字の位置である。
二つのマニュアル、golden、complex fixture、kanikosen、Nightmare Abbey の PDF と決定性のハッシュ、`scripts/visual/pages/` の参照が変わる。
実装のプルリクエストで、「今の出力で順が置き方を変える行」の数え方で、二つのマニュアルの行を、推定ではなく実装した種類で数え直し、画像の変わったページの数とともに説明に書く。

## 実装しないこと

- **行末の約物の空きを詰める段（3.8.3 の b と c）**：行末の空きは箱の端の固定の量であり、`gyomatsu-yakumono-zenkaku` の二分は、JLReq のとおりなら二分かベタ組のどちらかで、中間を取れない。比で連続に動くグルーでは表せず、分割ごとに二つの幅を量る変更が行分割に要る（「メンテナーが決めること」の 7）。
- **分割禁止の字間を空けないこと**：3.8.4 の c と d は、分割禁止の字間を空けない。どの字間を分割禁止とし、その伸びを外すかは、[golem-layout ADR 0049](../golem-layout/adr/0049-align-the-character-classes-and-unbreakable-pairs-with-jlreq.md) がロードマップに回した項目で扱う。この ADR は、どのグルーが伸びるかを変えない。
- **句点類の後ろを詰めないこと**：3.8.3 の注のとおりにするには、句点類の後ろの空きの最小を二分にする。アキ量のセットの値の変更であり、分割も変わるので、この ADR では行わない。既定では、句点類の後ろは最後の段で詰める（「メンテナーが決めること」の 2）。
- **字間の伸びの限度を四分にすること**：3 のとおり。
- **種類ごとの順を分割の量り方に入れること**：「メンテナーが決めること」の 1。
- **順の結果の報告**：段の配り方は書き手の設定のとおりの結果なので、diagnostic を出さない。
- **HTML と EPUB**：7 のとおり。

## 不変条件

「行」は `brLines` の各行、「グルー」は行の項目のグルーとする。
「詰める量」と「空ける量」は、字幅の伸縮の取り分を除いた、行に足す量の大きさとする。
グルー g の量 a(g) は、`glueAmounts` が返す、g の幅に足す量（詰めるときは負）とする。
g の縮みを z(g)、伸びを y(g)、文字の大きさを s(g)、段を k(g) とする。
O は `AdjustStaged` の順とする。

- **A1 順は分割を変えない**：どの O でも、`brPositions`、`brDemerits`、`brPass` は、`AdjustUniform` の入力と同じである。
- **A2 行の長さは変わらない**：どの O でも、各行の最後の項目の終わりの位置は、`AdjustUniform` の入力と同じである（丸めの 1 sp を許す）。[ADR 0209](0209-line-breaking-invariants-by-exhaustive-small-inputs.md) の L5 と L6、[ADR 0274](0274-prefer-pulling-in-and-limit-the-stretch-of-lines.md) の R6 は、そのまま成り立つ。
- **A3 限度**：詰める行で、どの g でも −z(g) ≤ a(g) ≤ 0 である。空ける行で、最後の段を使わない行では、どの g でも 0 ≤ a(g) ≤ y(g) である。
- **A4 段の順**：詰める行で、a(g) < 0 の g があれば、k(h) < k(g) のどの h も a(h) = −z(h) である。空ける行で、a(g) > 0 の g があれば、k(h) < k(g) のどの h も a(h) = y(h) である。最後の段を使う行では、伸びが正のどの g も a(g) ≥ y(g) である。
- **A5 段の中は同じ割合**：最後の段のほかで、同じ段の g と h は a(g)·z(h) = a(h)·z(g)（空ける行では y で同じ式）を満たす。
- **A6 最後の段は同じ em の数**：最後の段を使う行で、伸びが正で s が正の g と h は、(a(g) − y(g))·s(h) = (a(h) − y(h))·s(g) を満たす。
- **A7 一つの種類の行**：伸びるか縮むグルーが一つの種類だけで、そのグルーの s(g) と y(g) の比がどれも等しい行は、どの O でも、`placeLine` が `AdjustUniform` と同じである。詰める行では、比の条件なしで同じである。
- **A8 空の順は今の詰め方**：`shrink-order` が空の入力の詰める行は、`placeLine` が `AdjustUniform` と同じである。
- **A9 項目の並び**：`composeInlines` の項目から種類と大きさを除いた並びは、この ADR の前と同じである。[ADR 0209](0209-line-breaking-invariants-by-exhaustive-small-inputs.md) の L1 から L4 と L7 から L13 は、そのまま成り立つ。
- **A10 欄の検査**：4 の誤りのそれぞれに、G03006 がちょうど一つ出る。正しい値には diagnostic を出さない。
- **A11 HTML と EPUB**：二つの欄をどう書いても、HTML と EPUB の出力のバイト列は、欄を書かない入力と同じである。
- **A12 決定性**：同じ入力を二度組むと、`glueAmounts` は同じである。

境界の入力：

| 量 | 調べる値 |
| --- | --- |
| 詰める量 | 0、最初の段の容量より 1 sp 少ない、ちょうど最初の段の容量、1 sp 多い、すべての縮みの合計、1 sp 多い（はみ出す） |
| 空ける量 | 0、最初の段の容量、限度のある段の容量の合計、1 sp 多い（最後の段）、それより十分に多い |
| 行のグルーの種類 | なし、一つ、同じ段の二つ、違う段の二つ、順にあるが行にない段を挟む |
| 順 | 既定、逆順、すべてを一つの段、空、一つの種類だけを書く |
| 文字の大きさ | 一つ、二つ（小さい文字の括弧の空き、ルビの隣） |
| `stretch-limit` | 書かない、限度のある段の中で頭打ちにする値、最後の段で頭打ちにする値 |
| 字幅の伸縮 | なし、あり（`expansion`） |
| 行の位置 | 最初の行、中ほどの行、段落の最後の行、両端を揃えない段落の行 |
| 組方向 | 横組み、縦組み |
| 段階 | 1、2、送り出し（4）、はみ出す行 |

## テスト設計

テストを先に書き、今の実装で失敗することを確かめてから実装する。
テストの名前には、A1 から A12 の番号を入れる。

- **A1**：[ADR 0209](0209-line-breaking-invariants-by-exhaustive-small-inputs.md) の列挙の入力のすべてで、`AdjustUniform` と三つの順（既定、逆順、すべてを一つの段）の `brPositions`、`brDemerits`、`brPass` が等しいこと。
- **A2**：同じ列挙の入力のすべての行で、最後の項目の終わりの位置が `AdjustUniform` と 1 sp の差の内にあること。
- **A3 から A6**：同じ列挙の入力のすべての行で、述語が成り立つこと。手で作る入力として、語間の空白一つと読点の後ろの二分一つを持つ行を、語間の縮みより 1 sp 多く詰め、語間が限度まで、読点の後ろが 1 sp だけ詰まること（今は二つが同じ割合で詰まるので失敗する）。和欧間と字間を持つ行を、限度のある段の合計より多く空け、和欧間と字間が同じ em の数だけ限度を超えて広がること。
- **A7、A8**：英語だけの段落と、`shrink-order = []` の段落の `placeLine` が `AdjustUniform` と等しいこと。
- **A9**：列挙の入力のすべてで、`composeInlines` の項目から種類と大きさを除いた並びが、この ADR の前の実装の出力と等しいこと。実装の最初に、今の実装の出力を列挙の部品 2 個まで記録して比べる。
- **A10**：`shrink-order = "word-space"`、`["word-space", 1]`、`[[]]`、`[["brackets", ["comma"]]]`、`["tab"]`、`["comma", "comma"]` がそれぞれ G03006 を一つ出し、`[paragraph-styles.code]` の `stretch-order = []` が G03006 を一つ出すこと。`style.toml` と `@style-def` の両方で確かめる。
- **A11**：二つの欄を書いた本と書かない本の HTML と EPUB のバイト列が同じであること。
- **A12**：二つのマニュアルを二度組んだ PDF のバイト列が同じであること（今の決定性の検査）。
- **種類**：1 の表の各行について、その空きを作る二字（と語間の空白、段落の先頭）を組み、グルーの `itemKind` が表のとおりであること。
- **列挙の予算**：列挙に三つの順を足すと、組む入力は約 4 倍になる。プルリクエストの段で部品 2 個までの時間を測り、範囲ごとの予算 10 秒（[ADR 0208](0208-widen-lightweight-formal-methods.md) の 4）を超えるなら、プルリクエストでは既定の順だけを調べ、ほかの二つは毎晩のジョブの段で調べる。
- **二つのマニュアルの数え直し**：9 の数え方で数え、説明に書く。手で確かめる項目であり、自動のテストにはしない。

## トレードオフ

順を置き方だけに入れたので、分割を選ぶときには、どの種類のグルーが伸びるかを見ない。
語間の空白だけで空けられる行と、字間を空けなければならない行が、同じ伸びの合計なら同じ不良度になる。
JLReq の順に従う行を選びやすくするには、量り方に段を入れる必要がある。
その代わり、順を変えても分割とページが変わらず、[ADR 0274](0274-prefer-pulling-in-and-limit-the-stretch-of-lines.md) の量り方とも独立に確かめられる。

`Glue` に欄を足すので、グルーを作るか形で分ける箇所（ソースとテストに約 150）がすべて変わる。
置き方のために、行分割の項目の型が広がる。

既定の字間の伸びの限度が 1/10 em なので、3.8.4 の c の四分より早く最後の段に入る。
最後の段では、和欧間と語間の空白も字間と同じ em の数だけ広がる。
JLReq のとおりなら、字間が四分になるまで和欧間は二分のままである。
二つのマニュアルでは、最後の段まで使う行は、空ける行の 1 割前後（414 と 140）である。

一つのグルーが二つの段にまたがる空き（終わり括弧類か読点類の後ろに中点類が来る空き）は、一つの種類にしか入れない。
JLReq では、中点類の四分は d の段、読点類の二分は e の段で詰める。
この空きは `middle-dot` として d の段で詰まり、読点類の分も先に詰まる。

## メンテナーが決めること

1. **順の表し方**：推奨は、順を置き方だけに入れ、分割の量り方（グルーの伸びと縮みの合計からの不良度）を変えないことである。分割とページが変わらず、順を書き換えても組み直しの範囲が行の中にとどまる。
   - 退けた案の一つは、TeX のグルーの無限の次数（fil、fill、filll）のように、段を次数として量り方に入れることである。TeX は、高い次数の伸びがある行では低い次数のグルーを動かさず、不良度を 0 にする。段ごとの限度（四分まで、二分まで）を表せず、限度を超えて広がる行の不良度も量れない。
   - もう一つは、行の不良度を、使った段と段の中の比から求めることである。分割が変わり、[ADR 0274](0274-prefer-pulling-in-and-limit-the-stretch-of-lines.md) の R2 の量り方と重なる。段の不良度を決める式の根拠が JLReq にない。
2. **既定の詰める順**：推奨は、JIS X 4051 の四つの段（欧文間隔、中点類、括弧類と読点類、和欧間）とし、句点類の後ろと段落の先頭の空きを最後の段に置くことである。既定のセットの行末の扱いと一致し、JLReq の六つの段の行中の順とも同じである。
   - 退けた案の一つは、句点類の後ろを詰めないことである。3.8.3 の注のとおりだが、縮みの合計が変わり、分割が変わる。アキ量のセットの最小で決めることであり、順の欄では決めない。
   - もう一つは、括弧類を読点類より先に詰めることである。3.8.3 の注は、それを行う例があると書くだけで、本文の順は二つを同じ段に置く。
3. **字間の伸びの限度**：推奨は、アキ量のセットの最大（既定で 1/10 em）を c の段の限度とし、既定のセットを変えないことである。段の限度の出どころがアキ量のセットの一つになり、[ADR 0274](0274-prefer-pulling-in-and-limit-the-stretch-of-lines.md) の `stretch-limit` の目安の表（1000 で 1/10 em、2500 で四分）もそのまま使える。
   - 退けた案の一つは、既定のセットの字間の最大を四分にすることである。伸びの合計が 2.5 倍になり、不良度が下がって、追い出す行が増え、分割が大きく変わる。[ADR 0274](0274-prefer-pulling-in-and-limit-the-stretch-of-lines.md) の目安の表も合わなくなる。
   - もう一つは、順の欄に段ごとの限度を書けるようにすることである。空きの範囲を決める値が、アキ量のセットと順の欄の二か所になる。
4. **最後の段の配り方**：推奨は、伸びが正のグルーに、文字の大きさに比例して配ることである。3.8.4 の d と付録の「均等に空ける」に従う。
   - 退けた案は、今と同じく伸びに比例して配ることである。グルーに大きさを持たせずに済み、`stretch-order = []` が今の置き方と同じになるが、和欧間が字間の 2.5 倍の速さで広がる偏りが残る。
5. **設定の場所と形**：推奨は、段落スタイルの二つの欄に種類の名前の配列で書き、書かれていない種類を最後の段にまとめることである。JLReq の注が挙げる組み方の違いを書き手が選べ、書き漏らした種類も調整に使われるので、欄の書き方で分割が変わらない（A1）。
   - 退けた案の一つは、アキ量のセットの規則に段を書くことである。語間の空白はアキ量のセットにないので書けず、利用者が足す規則のすべてに段が要る。
   - もう一つは、`"jlreq"` や `"jis-x-4051"` のような名前の付いた組から選ぶことである。どの種類がどの段かが欄から読めず、組の外の順を書けない。
   - もう一つは、順を固定し、設定にしないことである。JLReq 自身が、括弧類と読点類の順や和欧間の扱いに複数の組み方を挙げている。
6. **項目の型**：推奨は、`Glue` に種類と大きさの欄を足すことである。グルーとその調整の性質が一つの値にまとまる。
   - 退けた案は、項目の並びと同じ長さの種類の一覧を、別に `breakParagraph` へ渡すことである。項目を足すか除く処理（語間の空白を捨てる、改行を禁じる罰点を挟む）のたびに、二つの並びの位置をそろえる必要がある。
7. **行末の約物の空き**：推奨は、この ADR では扱わず、ロードマップの v1.x の「行分割と禁則」に「行末の約物の空きを行の調整に使う（JLReq の 3.8.3 の b と c）」を足すことである。既定のセットでは行末の空きが 0 なので、既定の組版は変わらない。
   - 退けた案は、この ADR で扱うことである。二分かベタ組のどちらかを選ぶ空きは連続に動くグルーでは表せず、分割の候補ごとに二つの幅を量る変更が要る。
8. **`stretch-limit` との順**：推奨は、空ける量を上限で頭打ちにしてから段の順で配ることである。[ADR 0274](0274-prefer-pulling-in-and-limit-the-stretch-of-lines.md) の R6 の行の終わりの位置を変えずに済む。
   - 退けた案は、上限を「限度のある段までで止める」のような段の位置で書けるようにすることである。既定の字間の限度が 1/10 em なので、c の段で止めると多くの行が行末で大きく余る。

## 決めたことの記録

2026-11-10 に、tett23 が「メンテナーが決めること」のすべてを推奨のとおりに決めた。

1. 順は、推奨のとおり置き方だけに入れ、分割の量り方を変えない。
2. 既定の詰める順は、推奨のとおり JIS X 4051 の四つの段（欧文間隔、中点類、括弧類と読点類、和欧間）とし、句点類の後ろと段落の先頭の空きを最後の段に置く。
3. 字間の伸びの限度は、推奨のとおりアキ量のセットの最大（既定で 1/10 em）とし、既定のセットを変えない。
4. 最後の段は、推奨のとおり伸びが正のグルーに文字の大きさに比例して配る。
5. 順は、推奨のとおり段落スタイルの `shrink-order` と `stretch-order` に種類の名前の配列で書き、書かれていない種類を最後の段にまとめる。
6. 項目の型は、推奨のとおり `Glue` に種類と大きさの欄を足す。
7. 行末の約物の空きは、推奨のとおりこの ADR では扱わない。採択のプルリクエストで、ロードマップの v1.x に「行末の約物の空きを行の調整に使う（JLReq の 3.8.3 の b と c）」を足した。
8. `stretch-limit` との順は、推奨のとおり空ける量を上限で頭打ちにしてから段の順で配る。

採択のときに、草案の後に origin/main に入った変更（[ADR 0267](0267-pdf-bookmarks-and-links-inside-the-document.md) の実装）に合わせて、ソースコードへのリンクを `7e8fe7d3` のコミットに改め、`Japanese.hs` の行の番号を直した。
