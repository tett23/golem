# ADR 0335: golem repl emet で Emet の式を対話的に評価する

ステータス: 採択

## 文脈

短い Emet の式の値や型エラーを、原稿やモジュールを用意せずに確かめたい。
コマンドは `golem repl emet` とし、どの言語の REPL を開くかを `repl` の次の引数で選ぶ。
`golem repl --help` に選べる言語とその説明を載せる。

Ruby の IRB は、入力した式が完成した時点で評価し、継続入力を別のプロンプトで示す。
Ruby 4.0.7 と IRB 1.16.0 で、`1 +` の次行に `2` を打つと値が 3 になり、ゼロ除算の後も次の式を評価できた。
IRB では直前の値を `_` で参照できた。
Emet の初版には、区切りの命令を覚えずに複数行を書けること、評価結果が入力と見分けられること、書きかけの入力を取り消して続けられることを取り入れる。

## 実装すること

プロジェクトの外でも、標準入力の UTF-8 の式を Emet のパーサー、型検査器、評価器に渡す。
式ごとに組み込みの名前と式内で束縛した名前を使える。
ファイルなどを読むハンドラを必要とする式は、評価する前に要求の検査で拒む。

端末では通常入力に `emet> `、続きを待つときに `....> ` を標準エラー出力に出す。
端末として扱う条件は標準入力と標準エラー出力がともに端末であることとする。
成功した値を標準出力に一行で書き、端末では値の前に `=> ` を付ける。

```text
emet> 1 +
....> 2
=> 3
emet> 1 + )
E01100 [4,5): …
emet> 6
=> 6
```

一行を受け取るたびに構文を調べる。
構文が完結していればその場で型検査と評価に進む。
パーサーが入力末尾で次のトークンまたは閉じ記号を要求している場合だけ、LF を一つ挟んで次行を足す。
途中の文字を指す構文エラー、型エラー、評価エラーはその場で報告し、次の行を新しい式として読む。
エラーには元のコードとメッセージ、入力した式の先頭からの UTF-8 バイト範囲 `[start,end)` を示す。

未完の入力を待っているときの Ctrl-C はその入力を取り消し、同じ端末で次の式を読める状態に戻す。
EOF では、完成した最終行を末尾の LF の有無によらず一度評価する。
未完の式で EOF を受けた場合は保留していた構文エラーを一度報告する。
エラーを報告したセッションは終了コード 1、すべて成功または取り消しだけなら 0、引数の誤りは 2 とする。
パイプからはプロンプトを出さず、標準出力には値だけを書く。

値には既存の正確な数値表記、`True` と `False`、引用符付きの文字と文字列、リスト、タプル、コンストラクタを使う。
文字列の改行や制御文字はエスケープし、関数値は `<function>` と表示する。

## 実装しないこと

初版は各入力を独立した純粋な式として評価する。
トップレベルの定義や import、直前の値を表す名前、履歴の永続化、端末用の行編集と補完は今回の範囲に含めない。
ほかの言語の REPL は、その言語の仕様を決めてから個別に加える。

## 資源とアルゴリズム

入力と表示する値に、それぞれ UTF-8 で 4096 バイトの上限を設ける。
行を連結した LF は入力に数え、最後の LF と端末の表示用の接頭辞は数えない。
入力超過時はその物理行の末尾まで読み捨て、保留中の式を取り消して次の行から読む。
表示が上限を超えた場合は値の一部を書き出す前にエラーを返す。
評価器の上限は式ごとに 100000 手、深さ 10000 とする。

試作では入力を式の右辺として解析し、仮の等式に付けた接頭辞をエラーの位置から引く。
構文エラー E01100 または E01101 の位置がすべて入力末尾の空範囲なら、式と diagnostics を保留する。
本実装はパーサーの未完と不正の区別を明示的に渡してもよい。

## 不変条件

1. R1。完成した式は一度だけ評価し、一つの値を一行で表示する。
2. R2。確定したエラーの直後に新しい式を送ると、単独で送ったときと同じ値を得る。
3. R3。未完の式に続く行を LF で連結した結果は、連結後の式を一度評価した結果と等しい。
4. R4。端末では未完の入力を取り消して次の式を評価できる。パイプの正常出力には値だけが並ぶ。
5. R5。入力、出力、評価の上限ちょうどを受け付け、超過を報告した後の新しい式には上限を最初から適用する。

| 境界 | 観察する結果 |
| --- | --- |
| 空の入力、空白行だけ | 値なし、終了 0 |
| 最終行が LF のない `9` | 値 9 が一度出る |
| `1 +` の後に `2` | 続きを一行読み、値 3 が一度出る |
| `(1` のまま EOF | 閉じ括弧の構文エラー一つ、終了 1 |
| `1 + )` の後に `4` | 先に構文エラー、次の式は値 4 |
| `1 +` の後で Ctrl-C、次に `7` | 通常のプロンプトに戻り、値 7 |
| 入力 4096 バイト、4097 バイト | 前者を評価し、後者は入力超過 |
| 手数を超える式の後の `42` | E04100 の後に値 42 |

## テスト設計

[CLI 試験](../../experiments/repl/check.mjs) は実行ファイルの通常の入口に標準入力を送り、値、diagnostics、終了コードを比較する。
端末の継続プロンプト、Ctrl-C、EOF は疑似端末で試す。
日本語の位置、1 MiB の行を読んだ直後の回復、入出力と手数の境界も検査する。
[再現手順と実測](../../experiments/repl/README.md) に利用したコマンドと検証範囲を載せる。

## トレードオフ

未完の式を続けて書けるようにすると、閉じ忘れを報告する時点は EOF または確定した構文エラーまで遅れる。
端末では Ctrl-C でその式を取り消せる。
入力を一式ずつ独立させると失敗後も同じ条件で試せるが、値に名前を付けて繰り返し使う作業にはモジュールが必要になる。
