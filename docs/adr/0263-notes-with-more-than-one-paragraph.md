# ADR 0263: 複数段落の注

ステータス: 採択

## 文脈

学術書の注や翻訳書の訳注は、二つ以上の段落になることがある。
今の Golem の注は、一つの段落にしか書けない。
[2026-10-17 の調査](../audits/2026-10-17-latex-gap-for-v1.md) は、これを v1.0.0 に入れる項目（9）とし、所有者はそのとおりに決めた。
docs/roadmap.md の v1.0.0 の「LaTeX との差を埋める項目」の「複数段落の注」が、この項目である。
調査は v2 に同じ名前の項目があると書いたが、origin/main（87857c6e）のロードマップには、v1.0.0 のこの項目のほかに複数段落の注を扱う項目はない。

注の本文の型を変えるので、意味論 IR、CDDL、プラグインの ABI が変わる。
1.0.0 の後に変えると互換を壊すので、1.0.0 の前に入れる（[ADR 0174](0174-compatibility-promises-for-1-0.md)）。

### 今の注

意味論 IR の脚注と傍注は、本文としてインラインの並びを持つ（[`Golem.Doc.IR` の `Note` と `Sidenote`](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-doc/src/Golem/Doc/IR.hs#L274-L275)、CDDL の [タグ 12 と 13](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-doc/schema/golem-doc.cddl#L61-L62)）。
原稿では `[note: 本文]` と `[sidenote: 本文]` の散文スロットに本文を書く。
評価は、散文スロットをインラインとして評価し、ファイルの中の仮の番号を振る（[`Golem.Eval.File`](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-eval/src/Golem/Eval/File.hs#L2259-L2266)）。
番号は、文書の組み立て（S1）が `[notes]` の `numbering` の範囲で振り直す。

散文スロットの中では、段落を分ける手段がない。
空行の様式でも改行の様式でも、散文スロットの中の改行は文字を生まず、段落も区切らない（[docs/markup.md](../markup.md) の「段落と改行」）。
強制改行の `\` も、散文スロットの中には書けない（G02056）。

PDF のページの下の脚注は、注の本文を一つの段落として、本文の段落と同じ書体、大きさ、行長で行に分け、一行を格子の一行とする（[`anchoredByLine` の `noteBody`](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-typeset/src/Golem/Typeset/Flow.hs#L1907-L1911)）。
ページ分割は、注を格子の行の数（`NoteBody`）としてだけ扱う（[`Paginate.Types`](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-layout/src/Golem/Layout/Paginate/Types.hs#L36)）。
ページ（段）の先頭に置いても収まらない注は、収まる行までを置き、残りを次のページに続ける（[`splitNotes`](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-layout/src/Golem/Layout/Paginate/State.hs#L195-L202)）。
分ける位置は行の境であり、段落の内か外かを見ない。
章末の注（[golem-driver ADR 0026](../golem-driver/adr/0026-chapter-end-notes.md)）は、注を一つずつ段落として組み、本文の段落と同じ規則でページをまたぐ。
HTML と EPUB は、注を一つの `<aside epub:type="footnote">` に、段落の要素で包まずに書く（[`Golem.Html` の `notesSection`](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-html/src/Golem/Html.hs#L748)）。
プレーンテキストは、章の注を印と本文の一行ずつで書く（[`Golem.Text` の `file`](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-text/src/Golem/Text.hs#L99-L106)）。

### JLReq、InDesign、LaTeX

JLReq は、注の種類と配置を 4.2 で扱う。
横組みの脚注は、合印のあるページに入りきらない部分を次のページに回してよく、その場合は矢印などのガイドを付けるとよいとする（4.2.5）。
脚注が二行以上になったときの字下げ（二行目以下を全角下げるか、一行目を下げるか）も 4.2.5 にある。
複数の段落を持つ注の組み方は、確かめた範囲では書かれていない。

InDesign の脚注は複数の段落を持て、脚注の段落の段落前と段落後のアキは、複数の段落を持つ脚注でだけ適用されるとされる（調査の 9 に挙げたヘルプのページ。本文は読めず、検索の抜粋で確かめた）。
二つめ以降の段落の字下げが一つめとどう違うかは確かめられていない。

LaTeX は、`\footnote` の引数の中に `\par` か空行を書けば段落を分けられる。

### 注の本文の見た目

脚注と章末の注の本文は、段落スタイルを当てる手段がない（docs/roadmap.md の「組版の自由の原則に反する箇所」の「脚注と章末の注の本文」）。
字下げも段落の前後の空きも、注の本文には適用されない（[仕様書](../specifications.md) の段落スタイルの字下げの節）。
注の段落のあいだの空きは、その項目で注に段落スタイルを当てるときに決まる。
この ADR は、段落を並べる仕組みだけを決める。

### ほかの ADR との関係

この ADR は、同じ時期の ADR のどれにも依存しない。
[ADR 0262](0262-table-numbers-captions-column-widths-and-cell-styles.md) も意味論 IR を変える。
二つの ABI の変更は、[ADR 0052](0052-plugin-abi-version-bump-rule.md) の規則により、次のリリースまでのあいだで一つの版の上げにまとまる。
[ADR 0267](0267-pdf-bookmarks-and-links-inside-the-document.md) の脚注の印のリンクは、この ADR の注の本文の最初の段落を指す。

## 実装すること

### 1. 意味論 IR

脚注と傍注の本文を、ブロックの並びにする。

```haskell
  | Note !SrcSpan !Int [Block]
  | Sidenote !SrcSpan !Int [Block]
```

- 本文の型は、インラインの型の引数 `r` によらない。ルビの親文字の中の注の本文にも、ルビを書ける。本文は親文字の外に組むので、ルビの中のルビにはならない。`noRuby` は注をそのまま通す。
- CDDL では、脚注と傍注の新しいタグ（23 と 24）を加え、タグ 12 と 13 を廃止する（タグは使い回さない）。

  ```cddl
  / [23, span, uint64, [+ block]]                  ; note (docs/adr/0263)
  / [24, span, uint64, [+ block]]                  ; sidenote (docs/adr/0263)
  ```

- `Golem.Doc.Validate` に次の不変条件を加える。脚注の本文は一つ以上の段落で、どの段落も段落スタイルを持たない（`Paragraph Nothing`）。傍注の本文は、段落スタイルを持たない段落をちょうど一つ持つ。本文の段落のインラインには、今の注の本文と同じ検査（改行の位置、リンク、言語のタグなど）を当てる。
- ABI のバージョンは [ADR 0052](0052-plugin-abi-version-bump-rule.md) の規則による。今の版 8 は v0.1.0-rc4 に含まれるので、次のリリースまでのあいだに別の ADR（[ADR 0262](0262-table-numbers-captions-column-widths-and-cell-styles.md) など）が先に上げていれば変えず、上げていなければ 9 にする。
- Emet の `Inline` のデータ型の `Note` と `Sidenote` は、本文を `Blocks` で持つ（仕様書の「意味論 IR のデータ型」）。

注の本文を辿るモジュール（golem-doc の `withoutAnchors` と `Validate` と `Url`、golem-assemble の注の番号の振り直しと章末の注の収集、golem-eval、golem-typeset、golem-html、golem-epub、golem-text、golem-lint、見本のプラグイン）は、本文の段落のインラインを辿るように改める。

### 2. 記法

一つの段落の注は、今のとおり `[note: 本文]` と書く。
評価は、本文を段落スタイルのない段落一つとして IR に置く。

二つ以上の段落の注は、本文に名前を付けてブロックコマンド `@note` で書き、本文の位置に `[note 名前]` を書く。

```
外国の本を訳すときの判断[note kakucho]は、訳者の数だけある。

@note kakucho
  原書の初版の表記に従った。
  第二版では、この語は別の綴りに改められている。
```

- `@note 名前` の字下げした行（本体）が、注の本文である。本体の段落の区切りは、ほかのブロックコマンドの本体と同じく、そのファイルの段落の様式に従う。改行の様式では一行が一つの段落、空行の様式では空行で区切ったまとまりが一つの段落になる。
- 名前は、`@label` と同じ字（英小文字、数字、`-`、`_`）の語で書く。名前はファイルごとに閉じ、ラベルとは別の名前の集まりである。`@label kakucho` と `@note kakucho` は衝突しない。
- `[note 名前]` は、同じファイルの `@note 名前` を、`@note` の前でも後でも引ける。
- `@note` は、ブロックを置ける場所ならどこにでも書ける。`@note` は出力に何も置かない。
- 注の番号は、`[note 名前]` の位置で振る。本体は `@note` の位置で評価する（その位置までの `@set` の値を読む）。
- `@note` に属性（`@label`、`@lang`、`@style` など）を付けると、付けられない属性として G02013 とする。本体の段落への `@style` も G02013 とする（図版のキャプションと同じ）。本体の段落への `@lang` は、ほかの段落と同じく書ける。

誤りは次のとおりである。

- G02137：注の名前が定義されていない。`[note 名前]` の名前の `@note` がそのファイルにない。`[note 名前]` は何も出力しない。
- G02142：注の名前の書き方の誤り。`[note]` か `@note` に、名前を一つの語で書かなかった（名前がない、二つある、式で書いた）。名前の欠けと未定義は直し方が違うので、コードを分ける。`[note]` は何も出力せず、`@note` は使われない。
- G02138：使われない注の本文。`@note 名前` を指す `[note 名前]` がそのファイルにない。本文を黙って捨てないためのエラーである。
- G02139：一つの `@note` を、二つ以上の `[note 名前]` が指している。二つめ以降の `[note]` に報告し、二つめ以降は何も出力しない。
- G02140：同じファイルに、同じ名前の `@note` が二つ以上ある。二つめ以降に報告し、最初の定義を使う。
- G02141：`@note` の本体に、段落でないブロック（リスト、表、コード、図版、`@note` など）がある。そのブロックごとに報告して、そのブロックを除く。
- G02143：`@note` に本体がない（字下げした本体を書かなかった）。G02141 でブロックを除いた結果として段落が残らないときは、G02143 を出さない（原因は G02141 だけである）。
- G02141 と G02143 のどちらかで段落が一つも残らなければ、その名前を指す `[note]` は何も出力しない。
- `[note 名前: 本文]` のように名前と散文スロットを両方書くと、散文スロットの数の誤り（G02038）とし、メッセージを `note は名前を書くと散文スロットを取りません` とする。

`[sidenote]` の記法は変えない。
傍注は本文を一つの段落に限る（「メンテナーが決めること」の 3）。

### 3. PDF

ページの下の脚注は、本文の段落を順に行に分け、行を続けて置く。

- 最初の段落の先頭にだけ、今の注の側の印と四分アキを付ける。二つめ以降の段落は、新しい行から印なしで始める。
- 段落の書体、大きさ、行長、行分割の設定は、今の注の本文と同じとする。字下げと段落のあいだの空きは置かない。一つめの段落の二行目以降と同じく、二つめ以降の段落も行の始まりからそろえる。原稿で段落の先頭に全角の空白を書けば、それが字下げになる。
- 注の格子の行の数（`NoteBody` の行の数）は、すべての段落の行の数の和とする。
- ページ分割の規則は変えない。ページ（段）の先頭に置いても収まらない注だけを分け、分ける位置は段落の内でも段落の境でもよい。
- 本文の中の索引の印のページは、今のとおり、注の印を含む本文の行のページとする。

章末の注は、注の一つめの段落を今の注の段落と同じく組み、二つめ以降の段落を、印を付けずに、同じ書体、大きさ、行長で続けて組む。
段落のあいだに空きを入れず、本文の段落と同じ規則でページをまたぐ。

傍注は、本文が一つの段落なので変わらない。

タグ付き PDF では、`Note` の中に、注の側の印の `Lbl` と、段落ごとの `P` を置く。

### 4. HTML と EPUB

章末の注の一覧の `<aside epub:type="footnote">` の中に、段落ごとに `<p>` を置き、本文の参照へ戻るリンクを最初の `<p>` の先頭に置く。
一つの段落の注も `<p>` で包む（「メンテナーが決めること」の 4）。
`style.css` には、`aside` の中の `p` の上下の余白を 0 にする規則を足し、一つの段落の注の見た目を変えない。
傍注の出力は変えない。

### 5. プレーンテキスト

章末の注の並びで、注の一つめの段落を今のとおり印の後に書き、二つめ以降の段落をそれぞれ次の行に書く。
二つめ以降の行に印も字下げも付けない。

### 6. ほかのツール

- golem-fmt は、`@note` の本体を、ほかのブロックコマンドの本体と同じく整形する。
- golem-lsp は、評価の diagnostics を出すほかに変えない。`[note 名前]` から `@note` への定義へのジャンプは作らない。

### 7. 文書

- [仕様書](../specifications.md) の「脚注」の節（「複数段落の注は v1 では扱わない」を消し、記法と組み方を書く）、「傍注」の節（本文は一つの段落）、タグ付き PDF の表、HTML の CSS、プラグインのシリアライズ形式、意味論 IR のデータ型を改める。
- [docs/markup.md](../markup.md) の「脚注」の節（「注の本文はインラインの要素に限る」を改める）と、ブロックコマンドの一覧に `@note` を足す。
- [docs/diagnostics.md](../diagnostics.md) に G02137 から G02143 を足し、G02013 と G02038 の意味とメッセージを改める。
- マニュアルの記法の章と付録（`manual/chapters/03-markup.gm`、`manual/appendices/a-markup.gm`）に、複数段落の注の書き方を書く。InDesign との対応の付録（`manual/appendices/f-indesign.gm`）にも足す。
- docs/roadmap.md から、v1.0.0 の「LaTeX との差を埋める項目」の「複数段落の注」の項目を消す。
- docs/roadmap.md の v2 以降に、「注の本文のリストとコード」（脚注の本文に段落でないブロックを置くこと）を足し、「傍注の拡張」に「複数の段落の傍注」を足す。

### パッケージの依存

golem のパッケージのあいだの `build-depends` は変えない。

## 実装しないこと

- **注の本文の段落でないブロック**：IR の型は任意のブロックを持てるが、評価と Validate は段落だけを受け付ける。リストやコードを注に置く要求が出たら、PDF の脚注の領域での組み方を決めてから広げる。
- **複数の段落の傍注**：傍注はページをまたがず、収まらなければエラーになる（[golem-layout ADR 0006](../golem-layout/adr/0006-sidenotes.md)）。段落を増やすと、その場面が増える。v2 の「傍注の拡張」で扱う。
- **注の段落のあいだの空きと字下げ**：注に段落スタイルを当てる項目（「組版の自由の原則に反する箇所」の「脚注と章末の注の本文」）で決める。
- **分ける位置を段落の境に寄せること、分けたときのガイド（JLReq の 4.2.5 の矢印）**：今の注の分け方を変えない。
- **一つの本文を二つの印から指すこと**：G02139 とする。同じ注を二度出すと、本文の中の索引の印も二度数えることになる。
- **ファイルをまたいで本文を引くこと**：名前はファイルの中に閉じる。ファイルごとに評価する仕組み（S0）を変えない。

## 不変条件

- **I1 一つの段落の注は変わらない**：`[note: 本文]` は、段落スタイルのない段落を一つ持つ注になり、その段落のインラインは今の注の本文と等しい。`@note` を使わない本の PDF とプレーンテキストのバイト列は、この ADR の前と同じである。HTML と EPUB は、注の `<p>` と `style.css` の規則のほかは同じである。
- **I2 書く位置によらない**：G02137 から G02143 の出ないファイルで、`@note` のブロックを、ファイルの中のブロックを置ける別の位置に動かしても、どの出力のバイト列も変わらない（本体が読む `@set` の値が変わらない範囲で）。
- **I3 一つの本文に一つの印**：G02137 から G02143 の出ないファイルでは、`@note` の数と `[note 名前]` の数が等しく、名前で一対一に対応する。
- **I4 注の行の数**：PDF の脚注の格子の行の数は、本文の各段落を同じ設定で行に分けた行の数の和に等しい。行は段落の順、段落の中の順に並ぶ。
- **I5 印は一つ**：PDF の脚注と章末の注、プレーンテキストの注は、それぞれ注の側の印をちょうど一つ、最初の段落の先頭に持つ。
- **I6 分けるのは収まらないときだけ**：脚注の行が二つの段に分かれるのは、その注の行の全体が、印を含む行の段の先頭に置いても段に収まらないときに限る（今の規則のまま）。
- **I7 傍注は一つの段落**：Validate は、段落の数が 1 でない傍注と、段落の数が 0 の脚注と、段落でないブロックを持つ注を、それぞれ違反とする。
- **I8 決定性**：同じ入力からは、同じ出力と、同じ順の同じ diagnostic を得る。

境界の入力：

| 量 | 調べる値 |
| --- | --- |
| 本文の段落の数 | 0（本体なし）、1、2、3 |
| `[note 名前]` の数と `@note` の数 | 0 と 1、1 と 0、1 と 1、2 と 1、1 と 2 |
| `@note` の位置 | 印の前、印の後、リストの項目の中 |
| 段の残りの行と注の行の数 | ちょうど収まる、一行足りない |
| 段の行の数と注の行の数 | 注が段に収まる、段の行の数と等しい、一行あふれる（分ける位置が段落の境と段落の中の両方） |
| 段落の行の数 | 1、2（二つめの段落が一行だけ次の段に回る場合を含む） |
| 本体の中の段落でないブロック | なし、リスト一つ、`@note` 一つ |
| 段落の様式 | 改行の様式、空行の様式 |
| 傍注の段落の数（プラグインの出力） | 0、1、2 |

## テスト設計

テストを先に書き、今の実装で失敗することを確かめてから実装する。
テストの名前には不変条件の番号を入れる。

- **golem-doc のテスト**（I7）：新しいタグの CBOR の往復と CDDL の検査、タグ 12 と 13 を読まないこと、Validate が段落の数と種類の違反をそれぞれ一つ返すこと。
- **golem-eval のテスト**（I1、I3）：`[note: 本文]` の IR、二つの段落の様式での `@note` の本体の段落の分け方、G02137 から G02143 と G02038 と G02013 のそれぞれの例と、境界の表の数の組み合わせのすべて。`@note` の本体が `@set` の値を読む位置。
- **golem-eval と golem-driver のテスト**（I2）：小さなファイルを作り、`@note` のブロックをブロックを置けるすべての位置に動かして、四つの出力のバイト列が等しいことを確かめる。
- **golem-typeset のテスト**（I4、I5）：二つと三つの段落の注の行の数と並び、印の数。
- **golem-layout のテスト**（I6）：`splitNotes` の入力を、段の残りの行と注の行の数の小さな組で列挙し、分けるのは収まらないときだけであることを確かめる（[ADR 0204](0204-pagination-invariants-by-exhaustive-small-inputs.md) の `Golem.TestSupport.Enum`）。注の内訳（段落の数）はページ分割に渡らないので、行の数だけを列挙する。
- **golem-driver のテスト**（I1）：`@note` を使わない今の golden の PDF とテキストが変わらないこと。複数段落の脚注がページをまたぐ PDF と章末の注の PDF、タグ付き PDF の `Note` の中の `P` の数。
- **golem-html、golem-epub、golem-text のテスト**（I1、I5）：`<aside>` の中の `<p>` の数とリンクの位置、`style.css` の規則、プレーンテキストの行。
- **決定性**（I8）：diagnostics の順を固定するテスト。

## トレードオフ

本文を注の位置から離して書くので、原稿を読む人は、印と本文のあいだを名前で行き来することになる。
一つの段落の注は今のとおり印の位置に書けるので、離れるのは複数の段落の注だけである。

名前をファイルに閉じると、章をまたいで同じ本文を使い回せない。
一つの本文に一つの印の規則があるので、使い回す場面はもともとない。

使われない `@note` をエラーにすると、書きかけの注を残したままでは PDF を得られない。
本文を黙って捨てない原則を優先する。
書きかけの本文は、コメント（`%`）にして残せる。

注の段落のあいだに空きも字下げも置かないので、段落の境は、原稿の先頭の全角の空白がなければ見えない。
空きと字下げは、注に段落スタイルを当てる項目で決める。
それまでのあいだ、改行の様式の原稿が書く全角の空白で、段落の境を示せる。

傍注の型だけを広げ、記法と組み方を変えないと、型と実装の幅に差が残る。
その差は Validate が閉じるので、プラグインが二つの段落の傍注を返しても、出力が黙って変わることはない。

## メンテナーが決めること

1. **複数段落の注の記法**：推奨は、`[note 名前]` と、本体を持つ `@note 名前` である。本体はほかのブロックコマンドの本体と同じ規則で段落に分かれ、二つの段落の様式のどちらでも同じ意味になる。後で本文にリストやコードを許すときも、記法を変えずに済む。
   - 退けた案の一つは、散文スロットの中で段落を区切る印（たとえば `[par]`）を設けることである。注の位置に本文を書けるが、本文はインラインのままで、リストやコードを置く道がない。注の中でだけ意味を持つインラインのコマンドが増える。
   - もう一つは、散文スロットの中の空行を段落の区切りにすることである。改行の様式では空行を無視し、散文スロットの中の改行も段落を区切らないので、二つの様式で同じ原稿の意味が変わる。
   - もう一つは、注の印を含む段落の直後に、字下げした行で本文を続けることである。一つの段落に注が二つあると、どの本文がどの印のものかを位置で決めることになる。
2. **注の本文に置けるブロック**：推奨は、IR の型を任意のブロックの並びにし、評価と Validate で段落だけを受け付けることである。型を一度だけ変え、後で受け付けるブロックを足すときに ABI を壊さない。
   - 退けた案の一つは、IR の型を段落の並び（インラインの並びの並び）にすることである。リストやコードを足すときに、もう一度 ABI を変える。
   - もう一つは、リストとコードもこの ADR で受け付けることである。PDF の脚注の領域でのリストの字下げ、コードの背景と改ページを、注の行の格子の上で決める必要があり、v1.0.0 の範囲を広げる。
3. **傍注**：推奨は、IR の型を脚注と同じくブロックの並びにし、記法と組み方を変えず、Validate で段落をちょうど一つに限ることである。意味論 IR の注の二つの型がそろい、複数の段落の傍注を後で入れるときに ABI を変えずに済む。
   - 退けた案の一つは、傍注をインラインのまま残すことである。この ADR の範囲は狭くなるが、1.0.0 の後に傍注の段落を増やすと ABI を壊す。
   - もう一つは、複数の段落の傍注もこの ADR で組むことである。傍注はページをまたがないので、長い傍注が収まらないエラーの場面が増え、収まらない傍注の扱い（v2 の「傍注の拡張」）を先に決める必要がある。
4. **HTML と EPUB の段落の要素**：推奨は、一つの段落の注も `<p>` で包み、`aside` の中の `p` の余白を 0 にすることである。注の形が段落の数によらず一つになる。
   - 退けた案は、二つ以上の段落の注だけを `<p>` で包むことである。今の出力のバイト列は変わらないが、同じ要素に二つの形ができ、読者側の CSS が両方を扱う必要がある。
5. **本体のない `@note` のコード**：推奨は、段落でないブロック（G02141）と分けて G02143 にすることである。本体を書き忘れたのか、書いた本体に使えないブロックがあるのかで直し方が違い、一つのコードに一つの原因の原則に合う。
   - 退けた案は、二つを G02141 にまとめることである。「本体が一つ以上の段落の並びでない」という一つの条件とも読めるが、原因が二つになる。
6. **使われない `@note`**：推奨はエラー（G02138）である。原稿に書いた本文がどの出力にも出ないことを、黙って許さない。
   - 退けた案は、warning にすることである。書きかけの原稿は組めるが、CI で見落とされたまま本が出る。

コードの番号は、採択のときに、使われていない番号であり同じ時期の ADR と重ならないことを確かめて振り直した（「決めたことの記録」）。

## 決めたことの記録

2026-11-09 に、tett23 がすべて推奨のとおりに決めた。

1. 複数段落の注の記法は、推奨のとおり `[note 名前]` と、本体を持つ `@note 名前` とする。
2. 注の本文の IR の型は、推奨のとおり任意のブロックの並びとし、評価と Validate で段落だけを受け付ける。
3. 傍注は、推奨のとおり IR の型を脚注と同じくブロックの並びにし、記法と組み方を変えず、Validate で段落をちょうど一つに限る。
4. HTML と EPUB では、推奨のとおり一つの段落の注も `<p>` で包み、`aside` の中の `p` の余白を 0 にする。
5. 本体のない `@note` は、推奨のとおり段落でないブロック（G02141）と分けて G02143 とする。
6. 使われない `@note` は、推奨のとおりエラー（G02138）とする。

diagnostic のコードは、採択のときに、docs/diagnostics.md と origin/main のコードで使われていない番号であり、同じ時期の ADR と重ならないことを確かめて、G02137 から G02143 とした。
草案の仮の番号から振り直した。
