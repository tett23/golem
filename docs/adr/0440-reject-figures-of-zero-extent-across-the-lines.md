# ADR 0440: 行の送りの方向の長さが 0 sp になる図版を、PDF の組版のエラーにする

Status: accepted-pending

## 文脈

図版の画像は、行の方向の長さを `width` などで決め、行の送りの方向の長さを、画像の縦横の画素の比から求める。
行の送りの方向の長さは sp に切り捨てるので、行の方向の長さに比を掛けた値が 1 sp に満たない図版では、0 sp になる。
`width` が極めて小さい図版と、行の方向に極端に長い画素の比を持つ図版が、これに当たる。
番号もキャプションも持たない図版でそうなると、ページ分割に渡す図版の行数が 0 になる。

[root ADR 0352](0352-prove-pagination-in-lean.md) の Lean のモデルの証明の途中で、ページ分割の関数に行数 0 の図版を渡すと、その後の回した図版が先のページに置かれ、図版の順が原稿と入れ替わることが分かった。
0 sp の画像は何も描かないので、利用者の誤りである見込みが大きい。
この ADR は、そうした図版を PDF の組版のエラーにし、行数 0 の図版をページ分割に渡さないと決める。

## 調査した事項

origin/main（[8a73c31ee](https://github.com/tett23/golem/commit/8a73c31ee27817569893daea62f56ddeeb2205c8)）で、次のことを確かめた。

- 回り込ませない図版の行の送りの方向の長さは、`fitFigure` が、縮める前の長さ `across0`（行の方向の長さ `along0` に比を掛けて sp に切り捨てた値）から求める（[Flow.hs#L4901-L4907](https://github.com/tett23/golem/blob/8a73c31ee27817569893daea62f56ddeeb2205c8/modules/golem-typeset/src/Golem/Typeset/Flow.hs#L4901-L4907)）。
  版面に収まらないときは、`acrossMax`（0 未満にしない）まで縮める。
  回り込ませる図版は、別の式で同じく比を掛けて切り捨てる（[Flow.hs#L3221-L3223](https://github.com/tett23/golem/blob/8a73c31ee27817569893daea62f56ddeeb2205c8/modules/golem-typeset/src/Golem/Typeset/Flow.hs#L3221-L3223)）。
- 画像の行数 `m` は、行の送りの方向の長さを行送りで割って切り上げたもので、下限は無い（[Flow.hs#L3224](https://github.com/tett23/golem/blob/8a73c31ee27817569893daea62f56ddeeb2205c8/modules/golem-typeset/src/Golem/Typeset/Flow.hs#L3224)）。
- ページ分割に渡す図版の行の送りの方向の長さは、`(pfImageLines + pfCaptionSpan) * pitch` である（[Flow.hs#L3761](https://github.com/tett23/golem/blob/8a73c31ee27817569893daea62f56ddeeb2205c8/modules/golem-typeset/src/Golem/Typeset/Flow.hs#L3761)）。
  自由な配置（`Paginate/Physical.hs`）も同じ値を使う。
  回した図版は `FPageFigure` で、長さを持たない。
- 版面に収まらない図版は、今も G07038 か G07131 になる（[Flow.hs#L3234-L3254](https://github.com/tett23/golem/blob/8a73c31ee27817569893daea62f56ddeeb2205c8/modules/golem-typeset/src/Golem/Typeset/Flow.hs#L3234-L3254)）。
  このとき `acrossMax` が 0 なので、縮めた後の長さも 0 sp になる。
- 図版の `width` は、0 より大きい値なら受け付ける（[FigureWidth.hs#L32-L55](https://github.com/tett23/golem/blob/8a73c31ee27817569893daea62f56ddeeb2205c8/modules/golem-doc/src/Golem/Doc/FigureWidth.hs#L32-L55)）。
  `0.00001pt` は 1 sp に丸められて受け付けられる。
- `@nonumber` を付けてキャプションを書かない図版は、キャプションの行数が 0 になる。
- 版面の行送りは、文字の大きさ以上でなければならない（G07001）。
- 評価の `checkFigure` は、ファイルの有無と形式と `page`、`wrap`、`rotate` を見て、画像の大きさを読まない。
  HTML、EPUB、プレーンテキストは組版を通らない。
- PDF の組版のエラー（G07 系）は、PDF をターゲットに含む `golem build` だけで出し、PDF のターゲットだけを止める（仕様書の 989 行と 3391 行）。
- プリフライトの G09006（解像度の不足）は、0 sp の辺を持つラスターの図版を 0 ppi として扱う。
  プリフライトは書いた PDF を検査するので、PDF を書かなければ動かない。
- ページ分割の関数に、行数 0 の図版と回した図版を続けて渡すと、回した図版が先のページに置かれる（`paginate 1 5 [FFigure 1 0 [] [], FPageFigure 2 [] []]` を runghc で動かして確かめた）。
- 縦組みで幅 1 px、高さ 2 px の PNG を `@nonumber` と `width=0.00001pt` で置いた原稿は、diagnostic を出さずに組めた（11 月 8 日のビルドの `golem` で確かめた）。
  そのビルドでは、後に回した図版を置いても順の入れ替わりは再現せず、8a73c31ee のビルドでは確かめていない。

## 実装すること

PDF の組版で、図版の縮める前の行の送りの方向の長さ（回り込ませない図版では `across0`、回り込ませる図版では 3223 行の値）が 0 sp なら、エラーにして、その図版をページに置かない。
コードは G07 系に新しく一つ足す（番号は実装のときに空き番号から決める）。
メッセージは、図版の行の方向の長さか画素の比のために、行の送りの方向の長さが 0 になることを伝える。
位置は、その図版の `@figure` の行とする。

同じ図版が G07038 か G07131 になるときは、このコードを出さない。
縮める前の長さで判定するので、収まらない図版は縮めた後の 0 sp でこのコードにならない。

このエラーは、ほかの G07 系のエラーと同じく、PDF をターゲットに含む `golem build` だけで出し、PDF のターゲットだけを止める。
`golem check` と LSP では出さない。
HTML、EPUB、プレーンテキストは、今までどおり書く。

切り上げて 1 行にすることはしない。
0 sp の画像は何も描かないので、1 行を空けると、利用者の気付かないところで出力が変わるためである。

PDF を書かないので、プリフライトの G09006 は、この図版について出ない。

仕様書の「キャプションと大きさ」の節と `docs/diagnostics.md` に、このコードを書く。

## 実装しないこと

`width` の下限を新しく決めない。
ページ分割の関数（golem-layout）は変えない。
行数 0 の図版がページ分割に届かないことを、ページ分割の前提とする。
HTML の `width` の書き方（1 sp の幅が小数点以下 4 桁の `0.0000pt` になること）は、この ADR では直さない。

## 不変条件

- I1: PDF の組版がページ分割に渡す、回り込ませない図版の `FFigure` と、回り込ませる図版の `FWrapped` の行数は、どの入力でも 1 以上である。
- I2: 縮める前の行の送りの方向の長さが 0 sp で、G07038 にも G07131 にもならない図版は、新しいコードのエラーを一つ出し、PDF を書かない。
- I3: 縮める前の行の送りの方向の長さが 0 sp の図版を含まない原稿の出力と diagnostic は、この ADR の前と等しい。
- I4: 新しいコードは、`golem check` と LSP では出ず、HTML、EPUB、プレーンテキストの出力を止めない。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 縦組み、幅 1 px 高さ 2 px の PNG、`@nonumber`、`width=0.00001pt` | 新しいコードで、PDF は無い | I1, I2 |
| 横組み、幅 2 px 高さ 1 px の PNG、`@nonumber`、`width=0.00001pt` | 新しいコードで、PDF は無い | I1, I2 |
| 同じ大きさで番号とキャプションを持つ図版 | 新しいコード（キャプションの行の有無によらない） | I2 |
| 回り込ませる図版で、長さが 0 sp になる | 新しいコード | I1, I2 |
| 回した図版で、枠の行長に比を掛けて 0 sp になる | 新しいコード | I2 |
| 自由な配置で、長さが 0 sp になる | 新しいコード | I1, I2 |
| 縮める前の長さがちょうど 1 sp になる図版 | 1 行を占め、エラーは無い | I1, I3 |
| 版面より大きく G07038 になる図版 | G07038 だけで、新しいコードは無い | I2 |
| ふつうの大きさの図版 | 出力が変わらない | I3 |
| 長さ 0 sp の図版を含む原稿の `golem check` と HTML のビルド | 新しいコードは無く、HTML は書かれる | I4 |

## 受けいれ条件

なし。
不変条件のテストで足りるためである。

## テスト設計

root ADR 0440 I1 から I4 を名前の先頭に置いたテストを、golem-typeset と golem-driver に足す。
I1 は、図版の行の方向の長さと画素の比を列挙し、ページ分割に渡す行数が 1 以上か、エラーになるかのどちらかであることを確かめる。
I2 と I4 は、境界の表の原稿を組み、diagnostic と出力を調べる。
I3 は、決定性の検査のハッシュと今の golden が変わらないことで確かめる。
I1 と I2 は、実装の前に落ちることを確かめる。

## トレードオフ

今は黙って組めている極端に小さい図版が、PDF ではエラーになる。
その図版は何も描かず、しかもページ分割の関数に図版の順を入れ替えさせうるので、エラーにして利用者に知らせるほうがよい。

ページ分割の関数の側で行数 0 の図版を正しく扱う方法もあるが、0 sp の画像を置く意味が無いので採らない。

HTML、EPUB、プレーンテキストは組版を通らないので、この誤りを見つけられない。
同じ原稿でも、PDF だけがエラーになる。
