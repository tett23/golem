# ADR 0273: プロジェクトのないディレクトリなら、空でなくても golem new で作る

ステータス: 採択（未実装）

## 文脈

### 用途は、Markdown で書いてきた原稿の移行である

tett23 は、Markdown で管理してきた原稿を Golem に移したい。
そうした原稿のディレクトリは、たいてい git のリポジトリであり、`.git/`、`README.md`、章ごとの `.md`、図版のディレクトリ、`.gitignore` を持つ。
移すときは、このディレクトリをそのままプロジェクトにして、`golem new .` で `manifest.toml` と `style.toml` を置き、履歴を保ったまま原稿を `.gm` に書き換えていきたい。

ところが、今の `golem new` は空でないディレクトリを一律に断る。
[`createProject`](https://github.com/tett23/golem/blob/e0de85a3ceca2ebf850adf986a5867fe764c96e0/modules/golem-driver/src-plugins/Golem/Driver/New.hs#L198-L223) は、ディレクトリに何か一つでもあれば `ディレクトリが空ではありません: <パス>` を返し、[`newProject`](https://github.com/tett23/golem/blob/e0de85a3ceca2ebf850adf986a5867fe764c96e0/modules/golem-cli/app/Main.hs#L423-L435) はそれを標準エラー出力に書いて終了コード 1 で終える。
この規則は [golem-cli ADR 0001](../golem-cli/adr/0001-command-line-interface.md) の「指定したディレクトリが空でない場合はエラーとし、既存のファイルを上書きしない」による。
守りたいのは後半の「上書きしない」であり、前半の「空でない」は、それを確かめる手段として最も粗いものだった。
`.git/` が一つあるだけで断られるので、移行の用途では、別のディレクトリに作ってから手で移すしかない。

### 今の振る舞い

雛形が書くパスは、[`templateFiles`](https://github.com/tett23/golem/blob/e0de85a3ceca2ebf850adf986a5867fe764c96e0/modules/golem-driver/src-plugins/Golem/Driver/New.hs#L27-L35) の五つと、`--no-fonts` を付けないときの [`templateFonts`](https://github.com/tett23/golem/blob/e0de85a3ceca2ebf850adf986a5867fe764c96e0/modules/golem-driver/src-plugins/Golem/Driver/New.hs#L173-L196) の二つである。

| パス | 中身 | `--no-fonts` |
| --- | --- | --- |
| `manifest.toml` | 本の構成。章の一覧は `["chapters/01.gm"]` | 書く |
| `style.toml` | 版面とフォントの設定 | 書く |
| `chapters/01.gm` | 最初の章の見本 | 書く |
| `preflight.toml` | プリフライトの設定（[golem-cli ADR 0006](../golem-cli/adr/0006-preflight.md)） | 書く |
| `.gitignore` | `build/` の一行 | 書く |
| `fonts/` のフォント | 日本語は `NotoSerifJP-Regular.otf`、英語は `SourceSerif4-Regular.otf` | 書かない |
| `fonts/` のライセンス | `LICENSE-NotoSerifJP.txt` か `LICENSE-SourceSerif4.md` | 書かない |

`functions/` と `plugins.lock` は雛形にない。

`golem new` は、空かどうかの検査、フォントの取得とハッシュの検査、ファイルの書き込みの順に進む。
取得に失敗すれば何も書かない（[golem-cli ADR 0003](../golem-cli/adr/0003-new-project-page-and-fonts.md)）。
ないディレクトリは、途中のディレクトリも含めて作る。

2026-11-09 に、手元の `golem 0.1.0-rc4` で次を確かめた。

- 中身のあるディレクトリでは、`ディレクトリが空ではありません: d` を出し、終了コード 1 で終える。コードは付かない。
- 引数が通常のファイル（`golem new afile`）だと、`createDirectory: already exists (File exists)` の IO の例外と GHC のバックトレースを出して終える。
- 引数の途中が通常のファイル（`golem new afile/book`）でも、`inappropriate type (Not a directory)` の例外になる。

後の二つは diagnostic ですらない。
空でないディレクトリを受け付ければ、引数のパスと雛形のパスに何があるかを細かく調べることになるので、この二つも同じ ADR で diagnostic にする。

### 移行するリポジトリで、雛形とぶつかるもの

Markdown の原稿のリポジトリで、雛形のパスにすでにありそうなのは `.gitignore` だけである。
`README.md` と `.md` の章は、雛形のパスと名前が重ならない。
`chapters/` のディレクトリはありうるが、中身は `.md` なので、`chapters/01.gm` とはぶつからない。
`manifest.toml`、`style.toml`、`preflight.toml` が Markdown のリポジトリにあることはまれで、あれば別の道具の設定か、Golem のプロジェクトそのものである。
`fonts/` は、原稿をほかの道具で組んできたリポジトリにはありうる。

`.gitignore` を断る理由にすると、GitHub で作ったリポジトリの多くで移行が止まる。
一方で、`.gitignore` を書き換えるのは、利用者のファイルを黙って変えることになる。
この ADR は、`.gitignore` をほかの雛形のファイルと分けて扱う。

## 実装すること

### 1. 引数のディレクトリ

引数のパス（以下、対象）は、次のどれかでなければならない。

- **ない**：lstat がエントリを見つけない。途中のディレクトリも含めて作る。今と同じである。
- **ディレクトリ**：シンボリックリンクを辿った先がディレクトリである。利用者が名前を挙げたパスなので、`cd` と同じく辿る。

それ以外（通常のファイル、ファイルへのシンボリックリンク、辿れないシンボリックリンク、途中の要素がディレクトリでないパス）は G03133 とし、ほかの検査をせず、何も作らずに終了コード 1 で終える。

### 2. プロジェクトがすでにあるとき

対象に `manifest.toml` か `style.toml` のエントリ（種類を問わない。辿れないシンボリックリンクも含む）があれば、あるものそれぞれに G03131 を出す。
G03131 を一つでも出したら、ほかのパスの衝突（G03132）は報告しない。
`golem new` をプロジェクトの中で二度実行すると、雛形のパスがすべてぶつかる。
そこで七つのエラーを並べても、原因（ここはすでにプロジェクトである）が埋もれる。

### 3. 雛形のファイルとぶつかるとき

`manifest.toml`、`style.toml`、`.gitignore` を除く書き込むパス（以下、衝突を検査するパス）について、次のどれかに当たれば G03132 を出す。

- そのパスにエントリがある（通常のファイル、ディレクトリ、シンボリックリンクのどれでも）。
- 途中の要素（`chapters`、`fonts`）にエントリがあり、それがシンボリックリンクでないディレクトリでない。

途中の要素が当たったときは、その要素（`chapters` など）のパスで一つだけ出し、その下のパスには出さない。
`--no-fonts` のときは、`fonts/` の二つのパスと `fonts` の要素を検査しない。
書かないので、ぶつからない。

シンボリックリンクを一律に衝突とみなすのは、雛形のファイルをリンクの先、つまり対象の外に書かないためである。
`writeFile` はリンクを辿るので、`chapters` が別の場所へのリンクなら、`chapters/01.gm` はその場所に書かれる。

### 4. `.gitignore` があるとき

`.gitignore` にエントリがあれば（種類を問わない）、書かずに残し、プロジェクトを書き終えた後に notice の G03134 を出す。
終了コードは 0 のままである。
エラーで何も書かないときは、G03134 を出さない。
書かなかったファイルについて知らせても、ほかに何も書いていないので意味がない。

`.gitignore` に `build/` がすでにあるかは読まない。
中身を読むと、gitignore の書き方（否定、ワイルドカード、ディレクトリの指定）を解釈しなければ正しく判定できないからである。

### 5. 順序と、全か無か

検査はすべて、フォントの取得と書き込みより前に終える。
エラーが一つでもあれば、取得せず、対象を作らず、何も書かない。
検査は、引数のディレクトリ（1）、プロジェクトの有無（2）、雛形との衝突（3）の順に進み、前の段にエラーがあれば後の段を調べない。
3 では、すべての衝突を一度に報告する。
一つずつ直しては実行し直す手間を省くためである。

検査が通れば、今と同じくフォントを取得して検査し、ファイルを書く。
`.gitignore` がすでにあれば、書くファイルから外す。

### 6. 雛形の中身

雛形の中身は変えない。
`manifest.toml` の章の一覧は、空でないディレクトリでも `["chapters/01.gm"]` のままとし、対象にある `.md` や `.gm` を章に加えない。
雛形は、どこに作っても同じバイト列（`id` を除く）になる。

`--no-fonts` の案内（置くべきフォントとその URL）は、`fonts/` にすでにファイルがあっても今と同じく出す。
置いてあるファイルが雛形の求めるフォントかどうかを、`--no-fonts` では確かめないからである。

### 7. diagnostic のコード

番号は、docs/diagnostics.md と origin/main のコードと ADR で使われていない最初の番号である（origin/main の最後は G03130）。
段階は、プロジェクトのファイルを扱うので 03 とする。

| コード | 重大度 | メッセージ | 原因 |
| --- | --- | --- | --- |
| G03131 | エラー | `プロジェクトのファイルがすでにあります: <パス>` | 対象に `manifest.toml` か `style.toml` がある |
| G03132 | エラー | `雛形のファイルを書くパスに、すでにエントリがあります: <パス>` | 雛形のファイルのパスか、その途中の要素がふさがっている |
| G03133 | エラー | `ディレクトリではありません: <パス>` | 引数のパスがディレクトリでなく、作ることもできない |
| G03134 | notice | `.gitignore がすでにあるので書きませんでした。build/ を除外してください: <パス>` | 対象に `.gitignore` がある |

`<パス>` は、引数のパスと雛形のパスを `</>` でつなぎ、`System.FilePath.normalise` で整えたものである。
`golem new .` なら `manifest.toml`、`golem new book` なら `book/manifest.toml` になる。
位置は、[G03002](../diagnostics.md#g03002) の引数のファイルと同じく、そのパスの先頭（`<パス>:1:1`）とする。
人が読む形で標準エラー出力に書き、`golem explain` の案内の行も付ける（`putHuman`）。
`golem new` は `--format` と `--no-notices` を受け付けないので、それは変えない。

並びは決定的にする。
G03131 は `manifest.toml`、`style.toml` の順、G03132 はパスのバイト列の昇順とする。
`listDirectory` の順には依らない（雛形のパスを一つずつ lstat するので、ディレクトリを列挙しない）。

フォントの取得とハッシュの誤りは、今のとおりコードのない一行のままとする。
G03134 は `Golem.Syntax.Diagnostic.noticeCodes` に加える。

### 8. 構造

`createProject` を、副作用のない判定と、ファイルシステムを読む部分と書く部分に分ける。

- `targetEntries`（IO）：対象と、衝突を検査するパスと途中の要素と `.gitignore` のそれぞれを lstat し、エントリの種類の表を作る。種類は、ない、通常のファイル、ディレクトリ、シンボリックリンク（辿った先がディレクトリか）の四つである。
- `planProject`（純粋）：書くパスの一覧と種類の表から、diagnostic の並びか、書くファイルの一覧と G03134 の有無を返す。1 から 5 の規則はすべてここに書く。
- 書く部分は今の `createProject` の後半をそのまま使う。

`planProject` が純粋なので、不変条件をエントリの種類の組み合わせのすべてで確かめられる。

### 9. 文書

- docs/specifications.md の「CLI」の `golem new` の行と、雛形の段落に、空でないディレクトリの規則と四つのコードを書く。
- docs/diagnostics.md に G03131 から G03134 の節を足す。`golem explain` はこの文書の節を表示するので、`golem explain` の文言はこれで決まる。
- README.md の `golem new` の行に、プロジェクトのないディレクトリなら空でなくても作れることを足す。
- manual/chapters/01-first-book.gm の「プロジェクトを作る」に、既存の原稿のフォルダの中でも作れること、`manifest.toml` か `style.toml` があると作れないこと、`.gitignore` は書き換えないことを足す。
- [golem-cli ADR 0001](../golem-cli/adr/0001-command-line-interface.md) のステータスの行に、空でないディレクトリの扱いはこの ADR によることを足す。

## 実装しないこと

- Markdown の原稿を `.gm` に変換すること。この ADR の範囲ではない。
- 既存の `.gitignore` に `build/` を書き足すこと、ほかの雛形のファイルと中身を合わせること。利用者のファイルは変えない。
- 衝突したファイルを飛ばして残りを書くこと（`.gitignore` を除く）。
- 上書きを許すオプション（`--force` など）。
- 検査と書き込みのあいだに、ほかのプロセスが対象を変えた場合の扱い。検査の後に作られたファイルは上書きされうる。Golem は一人の利用者が手で実行する前提であり、排他の作成（`O_EXCL`）には golem-driver に unix のパッケージを足す必要がある。
- 書き込みの途中の IO の誤り（ディスクの空きの不足や権限）で残ったファイルの片付け。今と同じである。
- フォントの取得の誤りへのコードの付与。

## 不変条件

入力は、対象のパスとその途中の要素、雛形のパス（衝突を検査するパス、途中の要素、`manifest.toml`、`style.toml`、`.gitignore`）のそれぞれのエントリの種類と、`--no-fonts` の有無、フォントの取得の成否とする。
書くパスの集まりを W とする（`--no-fonts` なら `fonts/` の二つを除く）。

- **I1 上書きしない**：実行の前からあったどのエントリも、実行の後に種類と中身（通常のファイルのバイト列、シンボリックリンクの先）が変わらない。
- **I2 全か無か**：エラーを一つでも出した実行では、実行の後のファイルシステムが実行の前と同じであり（対象がなかったなら、対象もない）、フォントの取得を呼ばない。
- **I3 エラーの条件**：エラーを出すのは、対象がない、またはディレクトリであるのどちらでもないとき、`manifest.toml` か `style.toml` にエントリがあるとき、衝突を検査するパスか途中の要素がふさがっているとき、フォントの取得に失敗したときに限る。どれにも当たらなければ、終了コードは 0 である。
- **I4 書くもの**：成功した実行の後に新しくできたエントリは、W から既存の `.gitignore` を除いたファイルと、それを置くために作ったディレクトリ（対象、`chapters`、`fonts`）に限る。書いたファイルの中身は、空のディレクトリに作ったときと同じである。
- **I5 コードと原因**：G03133 を出すのは対象が 1 の規則に反するときに限り、そのときほかのコードを出さない。G03133 がなければ、G03131 は `manifest.toml` と `style.toml` のうちエントリのあるものにちょうど一つずつ出る。G03131 があれば G03132 と G03134 は出ない。G03132 は、ふさがっている途中の要素と、途中の要素がふさがっていない衝突を検査するパスのうちエントリのあるものに、ちょうど一つずつ出る。G03134 は、成功した実行で `.gitignore` にエントリがあったときに限り、ちょうど一つ出る。
- **I6 決定性**：diagnostic の並び（コード、パス、順）は、入力のエントリの種類と `--no-fonts` だけで決まる。ディレクトリの列挙の順、雛形のパスでないエントリ、既存のファイルの中身に依らない。
- **I7 関係のないエントリは結果を変えない**：雛形のパスでも途中の要素でもないエントリ（`.git/`、`README.md`、`chapters/` の中の `.md` など）を足しても除いても、diagnostic の並びと書くファイルの一覧は変わらない。
- **I8 `--no-fonts` は `fonts/` を見ない**：`--no-fonts` の実行では、`fonts` とその下のエントリを変えても、diagnostic の並びと書くファイルの一覧は変わらない。

境界の入力：

| 対象の状態 | 結果 |
| --- | --- |
| 対象がない | 対象と雛形を作る。diagnostic なし、終了コード 0 |
| 途中のディレクトリもない（`a/b/c`） | 途中も作る。終了コード 0 |
| 空のディレクトリ | 雛形を作る。終了コード 0 |
| 関係のないファイルだけ（`.git/`、`README.md`、`01-intro.md`、`images/`） | 雛形を作り、既存のものは変えない。終了コード 0 |
| `chapters/` に `.md` がある | `chapters/01.gm` を足す。終了コード 0 |
| `manifest.toml` がある | G03131 一つ。何も書かない |
| `style.toml` だけがある | G03131 一つ |
| `manifest.toml` と `style.toml` とほかの雛形のファイルがある | G03131 二つだけ |
| `manifest.toml` が辿れないシンボリックリンク | G03131 |
| `chapters/01.gm` がある | G03132（`chapters/01.gm`） |
| `chapters` が通常のファイル | G03132（`chapters`）一つ |
| `chapters` がディレクトリへのシンボリックリンク | G03132（`chapters`） |
| `preflight.toml` がディレクトリ | G03132（`preflight.toml`） |
| `chapters/01.gm` と `preflight.toml` がある | G03132 二つ、パスの昇順 |

| `.gitignore` と `manifest.toml` がある | G03131 だけ。G03134 は出ない |
| `.gitignore` と `chapters/01.gm` がある | G03132 だけ。G03134 は出ない |

| 引数の途中が通常のファイル（`afile/book`） | G03133 |

## テスト設計

テストを先に書き、今の実装で失敗することを確かめてから実装する。
テストの名前には、不変条件の番号を入れる。

### 判定の列挙（golem-driver のテスト）

- `planProject` の入力を、golem-test-support の `Golem.TestSupport.Enum` で列挙する。対象の種類（ない、ディレクトリ、通常のファイル、ディレクトリへのリンク、ファイルへのリンク、辿れないリンク、途中がファイル）と、雛形の九つのパス（`manifest.toml`、`style.toml`、`chapters`、`chapters/01.gm`、`preflight.toml`、`.gitignore`、`fonts`、フォント、ライセンス）のそれぞれの種類（ない、通常のファイル、ディレクトリ、リンク）と、`--no-fonts` の有無のすべてを試す。親の要素がない、または通常のファイルのときに子にエントリがある組み合わせは、ファイルシステムで起きないので除く。
- I3、I5、I6、I8 の述語を、すべての入力で確かめる。I6 は、同じ入力を二度判定して並びが同じことと、並びが入力の種類の表だけの関数であること（表を逆順に与えても同じ）で確かめる。
- 回帰：今の規則（空でなければエラー）を `planProject` の形に写した関数が、「関係のないファイルだけ」の入力で I3 に反することを、述語が違反として返すこと。

### ファイルシステムの上で（golem-driver のテスト）

- 境界の表のすべての行を、一時ディレクトリの上で `createProject` に渡して確かめる。フォントは偽の取得の関数で与え、ネットワークに接続しない。
- I1：実行の前と後で、既存のエントリの種類と中身（ハッシュ）を比べる。
- I2：エラーの行で、実行の後のディレクトリの木が前と同じこと、偽の取得の関数が呼ばれないこと。
- I4：成功の行で、新しいエントリの集まりが W から既存の `.gitignore` を除いたものと作ったディレクトリに等しく、書いたファイルが空のディレクトリに作ったものとバイト列で等しいこと（`id` は同じ UUID を与える）。
- I7：関係のないエントリ（`.git/HEAD`、`README.md`、`chapters/01-intro.md`）を足した入力と足さない入力で、diagnostic の並びと書いたファイルが同じこと。
- 今の `CliSpec` の「a directory that is not empty is left alone」は、I7 のテストに置き換える。

### コマンド（golem-cli のテスト）

- 今の `CommandsSpec` の「a directory that is not empty: 1, and its files are left alone」を、`notes.txt` のあるディレクトリで雛形が書かれ、`notes.txt` が変わらず、終了コードが 0 であるテスト（I1、I7）に置き換える。
- G03131、G03132、G03133、G03134 のそれぞれで、標準エラー出力の全体（`<パス>:1:1: error[G03131]: ...` の行と案内の行）と終了コードを固定する（I5）。`golem new .` でパスが `manifest.toml` になることも確かめる。
- 引数が通常のファイルのとき、標準エラー出力に GHC の例外とバックトレースが出ないこと。
- docs/diagnostics.md の節と、ソースで使うコードと `noticeCodes` が合うことは、今の golem-driver のテストが確かめる。

## トレードオフ

`.gitignore` だけを飛ばすので、雛形のファイルの扱いが二通りになる。
すべてをエラーにすれば規則は一つで済むが、移行するリポジトリの多くで、`.gitignore` をいったん退けてから戻す手間が要る。
飛ばしたときは G03134 で知らせるので、`build/` を除外しないまま出力をコミットする危険は、利用者が案内を読む限り残らない。
読まなければ残る。

`manifest.toml` の章の一覧に見本の章を入れたままなので、移行する利用者は、見本を消して自分の章を並べ直すことになる。
その代わり、雛形はどこに作っても同じであり、空のディレクトリに作ったときと同じく、そのまま四つのターゲットを組める（[golem-cli ADR 0003](../golem-cli/adr/0003-new-project-page-and-fonts.md)）。

シンボリックリンクを衝突とみなすので、`fonts` を共有のフォントのディレクトリへのリンクにしている利用者は、`--no-fonts` を付けるか、リンクを外す必要がある。
対象の外に書かないことを優先した。

検査と書き込みのあいだの競合は扱わない。
同じディレクトリに二つの `golem new` を同時に走らせると、上書きが起こりうる。

コードが四つ増える。
今は `golem new` の誤りにコードが一つもなかったので、`golem explain` で引けるものが増える代わりに、docs/diagnostics.md の節も四つ増える。

## メンテナーが決めること

1. **何が `golem new` を止めるか**：推奨は、`manifest.toml` か `style.toml` があればエラー（G03131）、ほかの雛形のファイルとぶつかればエラー（G03132）、`.gitignore` だけは書かずに notice（G03134）とすることである。どれも上書きしない。`.gitignore` は見本ではなく利便のためのファイルで、移行するリポジトリではたいていすでにある。ほかの雛形のファイルは、ぶつかることがまれで、飛ばすと結果が変わる（`chapters/01.gm` を飛ばすと、`manifest.toml` が利用者のファイルを章として指す。フォントを飛ばすと、ハッシュを確かめていないフォントで組む）。
   - 退けた案の一つは、依頼の文言どおり `manifest.toml` と `style.toml` だけを止める条件にし、ほかはすべて飛ばして notice を出すことである。上の理由で、飛ばしたファイルによって雛形の意味が変わる。
   - もう一つは、`.gitignore` も含めてすべてエラーにすることである。規則は一つで済むが、移行の用途で毎回ぶつかる。
   - もう一つは、`.gitignore` に `build/` を書き足すことである。利用者のファイルを変える。
   - もう一つは、黙って飛ばすことである。出力を黙って変えないという方針に反する。
2. **G03131 と G03132 を分けるか**：推奨は、分けることである。G03131 は「ここはすでにプロジェクトである」、G03132 は「関係のないファイルが雛形の場所にある」で、原因も直し方（別のディレクトリを選ぶか、ファイルを退けるか）も違う。
   - 退けた案は、一つのコードにまとめることである。一つのコードに一つの原因の原則に反する。
3. **すでにプロジェクトがあるとき、ほかの衝突を報告するか**：推奨は、G03131 だけを出し、G03132 を出さないことである。同じプロジェクトで二度実行したときに七つのエラーが並び、原因が埋もれる。
   - 退けた案は、すべてを報告することである。
4. **シンボリックリンク**：推奨は、引数のパスは辿り、雛形のパスと途中の要素のシンボリックリンクは、先が何であっても衝突とみなすことである。雛形を対象の外に書かない。
   - 退けた案の一つは、途中の要素のディレクトリへのリンクを辿ることである。`fonts` を共有のディレクトリにしている利用者には便利だが、雛形のファイルが対象の外に書かれる。
   - もう一つは、引数のパスのリンクも辿らないことである。利用者が自分で名前を挙げたパスであり、`cd` で入れるディレクトリに作れないのは驚きが大きい。
5. **雛形の章の一覧**：推奨は、見本の章 `chapters/01.gm` を入れたままにすることである。雛形がどこでも同じになり、そのまま組める。
   - 退けた案の一つは、空でないディレクトリでは章の一覧を空にすることである。雛形の中身がディレクトリの状態で変わり、章のない `manifest.toml` を組んだときの振る舞いにも依る。
   - もう一つは、対象の `.gm` を見つけて章の一覧に並べることである。順を決める規則が要り、この ADR の範囲を越える。
6. **`--no-fonts` の案内**：推奨は、`fonts/` にすでにファイルがあっても今と同じく出すことである。置いてあるファイルが求めるフォントかを確かめないので、URL を示す意味がある。
   - 退けた案は、すでにあるファイルを案内から除くことである。
7. **コードの番号**：G03131、G03132、G03133、G03134 とする。origin/main の最後の G03130 の次からであり、レビューの worktree のほかの草案とも重ならない。採択のときに、同じ時期の ADR と重ならないことを確かめ直す。

## 決めたことの記録

2026-11-09 に、tett23 が推奨のとおり次を決めた。

1. `golem new` を止めるのは、`manifest.toml` か `style.toml` があるとき（G03131）と、ほかの雛形のファイルとぶつかるとき（G03132）とする。`.gitignore` だけは書かずに残し、notice（G03134）で知らせる。どれも上書きしない。
2. G03131 と G03132 は分ける。
3. すでにプロジェクトがあるときは G03131 だけを出し、G03132 を出さない。
4. 引数のパスのシンボリックリンクは辿り、雛形のパスと途中の要素のシンボリックリンクは、先が何であっても衝突とみなす。
5. 雛形の章の一覧は、見本の章 `chapters/01.gm` を入れたままにする。
6. `--no-fonts` の案内は、`fonts/` にすでにファイルがあっても今と同じく出す。
7. コードの番号は G03131、G03132、G03133、G03134 とする。採択のときに、origin/main の docs/diagnostics.md と [ADR 0260](0260-front-matter-folios-and-page-labels.md) から 0272 のコードと重ならないことを確かめ直した。
