# ADR 0339: 命令の引数列と原稿内の式に通常コメントを書けるようにする

ステータス: 採択

## 文脈

命令の引数や計算式のそばに説明を書き、説明の中には複数行のコマンドの断片も載せたい。
通常コメントを原稿の具体構文木（CST）に保存すれば、整形しても説明は残る。
抽象構文木（AST）からはコメントを除く。
命令や Emet の式がコメントを読んで振る舞いを変える抜け道を作らないためである。

## 調査した事項

[Golem の文法](../../modules/golem-parser/grammar/Golem.hpeg) では、インライン命令、ブロック命令、コードブロックの開始行が同じ `Arguments` 規則を使う。
`Arguments` は位置引数を先に、キーワード引数を後に読み、間の `Sp` はスペースとタブを読む。
引用符なしの値を読む `Word` の除外文字に `%` はない。
`Comment` は `%%`、校正コメントの `ProofComment` は `%%=` で始まり、どちらも段落末を越えない。

## 実装すること

### 引数列と式を読む規則

三つの `Arguments` の呼び出し元すべてで、先頭、引数の間、末尾に通常コメントをいくつでも認める。
コメントだけなら引数はゼロ個であり、必須引数の不足は従来どおり報告する。
コメントを挟んでも、位置引数がキーワード引数に先行する規則は変わらない。

原稿に書く式では、引数の式にも `@set` の右辺にも、先頭、トークン間、末尾に通常コメントを認める。
式を読むときはコメントの前後のトークンを別々に保つ。
たとえば `1+%%注%%2` は `1+2` と同じ式になり、`ab%%注%%cd` の前後から識別子 `abcd` を作ることはない。
コメント内は最初の閉じ `%%` まで原稿どおりに保存し、段落末までは改行を許す。
コメント内の改行は、`@set` の右辺やコードブロックの開始行を終える改行として消費しない。
文字列リテラル内の `%%` と `%%=` は文字列値であり、Emet が返した文字列も原稿のコメントとして再解釈しない。

引数を読み始める位置では、独立した `%%注%%` を通常コメントとして読む。
一方、`key=` の直後は値が必要なので、`key=%%注%%` と `key=%%=注記%%` はいずれも引用符不足である。
位置引数とキーワード引数のどちらも、引用符なしの文字列値の途中や末尾に `%%` があれば引用符不足とする。
既存原稿が位置引数 `%%注%%` を値として使っていれば `"%%注%%"` に、`key=x%%注%%` は `key="x%%注%%"` に書き換える。
単独の `%` はこの変更の対象に含めない。

### 整形と lint

`fmt` は、引数列と式でコメントと引数やトークンの相対位置を保つ。
同じ境界に複数のコメントがあれば、互いの順序も保つ。
次の表は、境界を一意に読める入力に対する整形規則である。

| 境界 | 整形後 |
| --- | --- |
| 命令名と先頭コメント、引数とコメント（両方向）、コメント同士 | 半角スペース一つ |
| 末尾コメントとインライン命令の閉じ `]` または本文を導く `:` | 詰める |
| 式のトークンとコメント（両方向） | 半角スペース一つ |
| 式の開始記号と先頭コメント、末尾コメントと式の終了記号 | 詰める |
| 閉じ記号のない式の末尾コメントと行末 | 空白を足さない |

スペースを入れる境界でも、境界が一意なら空白なしの入力を受理する。
`golem lint` はその境界に限り一か所につき info を一件生成し、半角スペース一つの挿入を提示する。
コメント同士なら後ろの開始 `%%`、コメントの直後に引数があれば引数の先頭、引数の直後ならコメントの開始を指す。
既にスペースやタブがあれば info は出さず、整形時に半角スペース一つにする。
[Golem ADR 0104](0104-info-severity.md) は lint 規則からの info を認めず、CLI の info を verbose 表示に限っている。
この ADR はコメントの区切り不足に限り、その二点を変更する。
整形前の通常の `golem lint` でもこの info を表示し、明示的な `silence-info` の指定には従う。

### エラーと回復

引数列または式のコメントの開始位置で `%%=` を見たら、校正コメントの禁止を報告する。
両方に同じコードを使い、メッセージで引数列と式を区別する。
校正内容が分かるよう、開始から閉じ記号の末尾までを指す。
閉じ記号がなければ段落末かファイル末までを指し、閉じ忘れのエラーを重ねない。
閉じた校正コメントの後から解析を再開し、独立した誤りを原稿順に報告する。
引数列と式で通常コメントを閉じ忘れた場合、G01018 は開始から段落末かファイル末までを指す。
この範囲は新たにコメントを許す位置に適用し、本文や見出しなどの既存の位置では [golem-parser ADR 0009](../golem-parser/adr/0009-syntax-diagnostic-codes.md) が定める段落末の幅ゼロの範囲を使う。
必須の式に閉じた通常コメントしかなければ、最後の閉じ記号の直後を幅ゼロで指す。

引用符不足は問題の値全体を指す。
引用符なしの値の途中で `%%` を見つけたら、既存の `Word` の終端までを値として回復する。
たとえば `key=x%%注%% next=y` では `x%%注%%` だけが引用の対象になる。
`key=%%注%%` のようにコメントの形が値を占める場合は、同じ行で閉じ、値全体の範囲が一意で、引用後も元の文字列を渡せる場合に限り、値全体を引用する修正候補を付ける。
値の途中や末尾の `%%` には閉じ記号を求めず、範囲と値の保存を同様に確かめる。
`fmt` は修正候補を適用しない。
[仕様書のもぐら叩きに関する設計原則](../specifications.md#もぐらの数がわからないもぐら叩きをさせない) に従い、回復できる引用符不足を一回の実行で原稿順にすべて報告し、その原稿は一切書き換えない。
ほかの対象ファイルは整形を続け、エラーのある原稿を報告してコマンド全体は失敗として終了する。

引数なしの実行でも、引用符不足だけを理由にプロジェクト全体の整形を打ち切らない。
[golem-fmt ADR 0004](../golem-fmt/adr/0004-fmt-without-arguments-fixes-cr.md) の読み込み手順に、引用符不足から回復しながら章と参照先を列挙する経路を加える。
ファイルごとに書き込みの可否を決め、回復した値を元の原稿に書き戻さない。

## 実装しないこと

Emet 自体の文法の変更と、引数列や式にある校正コメントの表示は扱わない。
文法全体の列挙とモデルによる証明は、パーサーと fmt の往復を扱う後続 ADR で決める。

## 不変条件

1. 正しい引数列や式から通常コメントを取り除き、元のトークン境界を保ったとき、ソース位置を除いた AST は等しい。
2. 整形前後の CST から順に取り出したコメントの内容と前後の引数またはトークンが一致し、二度目の整形結果は一度目とバイト単位で一致する。
3. 区切り不足の info の件数は、整形表に従ってコメントの境界に半角スペースを新たに挿入する箇所の数に等しい。
4. 校正コメント一つから生じるエラーは一件であり、閉じ忘れ、式不足、引用符不足もそれぞれ上記の範囲を指す。
   独立したエラーの列は原稿順に一致する。
5. 引用符不足を含むファイルの実行前後のバイト列は等しい。
   他ファイルの整形結果は、それぞれを単独で整形した結果と等しい。

## テスト設計

不変条件の番号をテスト名に含める。
三つの引数列と原稿内の式の入口で、次の境界を先に失敗するテストとして書く。

| 番号 | 入力の境界例 | 確かめる結果 |
| --- | --- | --- |
| 1、2 | 引数なし、コメント一つだけ、二つだけ | 引数はすべてゼロ個。コメントの内容と順序が残る |
| 1、2 | 位置引数とキーワード引数の間に複数行のコメント | 引数の順序とコメント内の改行を保存。引数を逆順にすれば引数順のエラー |
| 2、3 | `[cmd%%注%%]`、`[cmd x %%注%% : 本文]` | `[cmd %%注%%]` と `[cmd x %%注%%: 本文]`。info は順に一件、ゼロ件 |
| 2、3 | `"x"%%甲%%%%乙%%key=y` | 三境界で info。スペースやタブが既にあればその境界ではゼロ件 |
| 2、3 | `1+%%注%%2`、`(%%前%% 1 %%後%%)` | info は二件、ゼロ件。整形後はどちらもゼロ件 |
| 1、4 | 式が必須の場所に `%%甲%% %%乙%%` | 最後の閉じ記号の直後を幅ゼロで指す |
| 4 | 通常コメントと校正コメントの閉じ忘れを段落末、ファイル末で各一例 | 開始から末尾まで。禁止された校正コメントからのエラーは一件 |
| 4 | 閉じた校正コメント二つ、文字列内の `"%%=注%%"` | 独立した二件だけを原稿順に報告。文字列は値として保存 |
| 4、5 | `key=%%=注%%`、`x%%y`、`key=x%%` が同じ原稿にある | 値全体を指す三件と、それぞれの引用候補。ファイルは元のまま |
| 3、5 | 引用符不足と区切り不足を持つ原稿に、整形可能な別ファイルを添える | 別ファイルだけを書き換えて失敗。引用符を手で直した後の再実行で区切りが整う |

## トレードオフ

コメントを CST に残すので、整形と lint は AST から復元できない境界を扱う必要がある。
一方、引数の個数や式の値を決める処理にはコメントが入り込まない。
引用符を省いていた既存原稿には書き換えが生じるため、採択後の実装時に仕様書と README に移行例を載せる。
