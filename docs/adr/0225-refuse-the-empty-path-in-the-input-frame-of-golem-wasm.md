# ADR 0225: golem.wasm の入力の枠で、空のパスを断る

ステータス: 採択（未実装）

## 文脈

[ADR 0199](0199-pdf-typesetting-as-wasm-reactor.md) の入力の枠は、ファイルの並びである。
枠の仕様は、パスについて「プロジェクトのルートからの相対パスで、`normalizeRelative` の結果と一致しなければならない」と書き、同じパスが二度現れたら断るとする。
読めない枠は、状態 1 の結果になる（長さが足りない、パスが UTF-8 でない、パスが正規化されていない、同じパスが二度ある）。

2026-11-08 のセキュリティ監査（[docs/audits/2026-11-08-security-audit.md](../audits/2026-11-08-security-audit.md) の W-02、情報）は、枠が空のパス `""` を受け付けることを記録した。
`Golem.Wasm.Frame` の `isNormalized` は、空の文字列を区切りで分け、空の区間を捨てた結果も空の文字列なので、`""` を正規化済みとする（[`Frame.hs:115-121`](https://github.com/tett23/golem/blob/eeb70246124fc9cba002150078a47c54e29b512f/modules/golem-wasm/src/Golem/Wasm/Frame.hs#L115-L121)）。
golem-project の `normalizeRelative` も、`""` に対して `Right ""` を返す（[`Paths.hs:32-42`](https://github.com/tett23/golem/blob/eeb70246124fc9cba002150078a47c54e29b512f/modules/golem-project/src/Golem/Project/Paths.hs#L32-L42)）。
監査は、`memoryFiles` の表にキー `""` が入るだけで、どの参照も空のパスを引かないので、影響を見つけなかった。

### 仕様が空のパスを許すか

今の仕様の文言は、空のパスを許す。
`normalizeRelative ""` は `""` であり、枠のパスはその結果と一致するからである。
`.`、`a/..` のように `""` に正規化されるパスは、結果と一致しないので、今も断る。

一方で、空のパスはルートそのものを指し、ファイルの名前を持たない。
枠の仕様の例（`manifest.toml`、`kumo-no-ito.gm` など）はどれもファイルであり、空のパスで渡せる中身はない。
ディスクのビルドでは、空のパスのファイルを読むことはない（ルートはディレクトリなので）。
枠だけが、ディスクにありえない入力を受け付けている。

空のパスを断るのは、今の仕様が許す入力を断ることなので、コードの修正ではなく仕様の変更として、この ADR で決める。

## 実装すること

- `Golem.Wasm.Frame` の `readFiles` は、パスが空のファイルを断る。理由を表す `FrameError` に、新しい構成子 `EmptyPath` を足す（「メンテナーが決めること」の 2）。
- 空のパスの判定は、UTF-8 の検査の後、正規化の検査の前に置く。誤りは、枠の中で最初に読めないファイルのものとする（今と同じ規則）。空のパスより前に同じパスが二度あれば、`Duplicate` が先である。
- `respond` は、`EmptyPath` でも今の読めない枠と同じく、状態 1 の結果を返し、組まない。
- `normalizeRelative` と `isNormalized` は変えない（「メンテナーが決めること」の 3）。
- [ADR 0199](0199-pdf-typesetting-as-wasm-reactor.md) の状態 1 の理由の並びと、docs/specifications.md の入力の枠の節（パスは `normalizeRelative` の結果と一致しなければならない、の文）に、「空でない」を足す。`Frame.hs` の冒頭の注釈も同じに直す。

## 実装しないこと

- `normalizeRelative` が空のパスを誤りにすること。golem-project の `normalizeRelative` は、ディスクのビルドの章、図版、表、フォントのパスの正規化に使う。`@table ""` のような原稿の空のパスがどう報告されるかを、この ADR では調べていない。
- 枠の中のパスの長さやファイルの数に上限を置くこと。ファイルの数による手間は、重複の検査を n log n にした修正（監査の W-01）で抑えた。
- ホストの側（ブラウザーのページや `scripts/wasm/run.mjs`）で空のパスを避けること。枠は、ホストの誤りを状態 1 で知らせる。

## 不変条件

枠を、パスと中身の組の並び (p1, c1), …, (pn, cn) とする。

- **F1**：`readFiles` が枠を受け付けるのは、どの pi も、UTF-8 であり、空でなく、`isNormalized` を満たし、それより前の pj（j < i）と異なるときに限る。
- **F2**：受け付けない枠では、誤りは、F1 を満たさない最初のファイルのものである。そのファイルが複数の条件を満たさないときは、UTF-8、空、正規化、重複の順に最初の条件を報告する。
- **F3**：空でないパスだけからなる枠の読み方（受け付けるか、どの誤りか、受け付けたファイルの並び）は、この ADR の前と同じである。
- **F4**：ディスクのビルドの、パスの正規化と diagnostic は変わらない。

境界の入力：

| 量 | 調べる値 |
| --- | --- |
| パス | `""`、`"."`、`"a/.."`、`"a"`、`"/"` |
| 空のパスの位置 | 枠の最初、途中、最後 |
| ほかの誤りとの順 | 空のパスの前に重複、後に重複、空のパスが二度、前に長さの足りないファイル |
| 中身 | 空、1 バイト |

## テスト設計

テストを先に書き、今の実装で失敗することを確かめてから実装する。
テストの名前には、F1 から F4 の番号を入れる。

### golem-wasm（`modules/golem-wasm/test/Main.hs`）

- **F1**：`readFiles (writeFiles [("", "x")])` が `Left EmptyPath` であること。今は `Right [("", "x")]` なので失敗する。`respond` が状態 1 の結果を返し、組む関数を呼ばないこと（今の「every input that cannot be read is the result of status 1, without a build」に足す）。
- **F1、F2**：境界の入力の表の位置と順のそれぞれで、誤りが F2 のとおりであること。`""` が二度ある枠は、最初の `""` の `EmptyPath` である。
- **F3**：今の性質のテスト（生成した正規化済みの空でないパスの枠を書いて読み直すと同じ、W-01 の二乗の読み方と同じ）が、そのまま通ること。二乗の読み方の参照の実装には、空のパスを断る判定を足さない。生成するパスは空にならないので、比べる結果は変わらない。
- **F4**：golem-project のテストの `normalizeRelative ""` が今と同じ `Right ""` であること（今のテストになければ足す）。

## トレードオフ

ホストが空のパスを渡すと、今は組めていた枠が状態 1 になる。
空のパスの中身はどこからも読まれないので、組んだ結果は変わらない。
今の振る舞いに頼るホストがあれば、そのホストは空のパスを渡すのをやめる必要がある。
リポジトリの中のホスト（`scripts/wasm/run.mjs`）は、ディレクトリの下のファイルのパスを渡すので、空のパスを渡さない。

`FrameError` の構成子を一つ足すので、構成子を網羅する `case` を持つ利用者の側（テスト）が変わる。
状態 1 は理由を外に出さないので、ホストから見えるのは状態だけである。

## メンテナーが決めること

1. **空のパスを断るか**：推奨は、断ることである。空のパスはファイルを指さず、ディスクのビルドに対応する入力がない。枠が受け付ける入力を、ディスクのビルドで作れる入力にそろえられる。
   - 退けた案は、今のまま受け付け、仕様に「空のパスは受け付けるが、どこからも読まれない」と書くことである。コードは変わらないが、ディスクにない入力を受け付けるという例外を、仕様に一つ残すことになる。
2. **誤りの表し方**：推奨は、`FrameError` に `EmptyPath` を足すことである。空のパスは正規化の規則（`normalizeRelative` の結果と一致すること）を満たしているので、`NotNormalized` にすると、その構成子の意味（正規化で変わるか断られるパス）と食い違う。一つの原因に一つの表し方を当てる。
   - 退けた案は、`NotNormalized ""` とすることである。構成子は増えないが、上の理由で原因を混ぜる。
3. **直す場所**：推奨は、枠の `readFiles` だけを直し、`normalizeRelative` と `isNormalized` を変えないことである。`isNormalized` は `normalizeRelative` の写しであり（[`Frame.hs:110-114`](https://github.com/tett23/golem/blob/eeb70246124fc9cba002150078a47c54e29b512f/modules/golem-wasm/src/Golem/Wasm/Frame.hs#L110-L114) の注釈）、写しの規則が元と食い違うのを避ける。
   - 退けた案は、`normalizeRelative` が空のパスを誤りにすることである。ディスクのビルドのすべてのパスの扱いに及び、原稿の空のパスの diagnostic が変わりうる。その影響を調べていない。
