# ADR 0150: .gm から .gmx の関数をコマンドとして呼ぶ

ステータス: 採択

## 文脈

[ADR 0148](0148-gmx-function-language-core.md) は関数を書く言語 `.gmx` を、[ADR 0149](0149-gmx-requirements-and-driver-handlers.md) は関数が処理系に求める要求を決めた。
この ADR は、原稿の `.gm` から関数を呼ぶ方法を決める。

メンテナーの案は、`pub inline` と `pub block` を付けた関数を、`.gm` のインラインのコマンドとブロックコマンドとして使えるようにすることである。

```
pub inline/block docStyles :: Evaluated -> FileId -> Style => file
```

今の Golem は、書き手が関数を定義する仕組みを持たない。
[golem-eval ADR 0001](../golem-eval/adr/0001-expression-language-and-numerics.md) は「ユーザー定義の関数、条件式、繰り返し」を実装しないことに挙げ、[docs/markup.md](../markup.md) の式文脈の節は、関数を定義する仕組みを「プラグインの役割とする」と書いている。
ロードマップは、この立場を改める項目を v0.1.0-rc4 に置いた（[docs/roadmap.md](../roadmap.md) の「`.gm` の中の関数の宣言」）。
小さな計算や書式のためにプラグインを作るのは重いからである。

同じ項目は、関数とプラグインの立ち位置を分けている。

- **関数**：社内の使い手や組版のオペレーターが、手元の不便を解消するために書く。
- **プラグイン**：技術者が作って配る。

このため、関数には `plugins.lock` やレジストリのような再配布の仕組みを持たせない。
宣言を書いたファイルをコピーして使うことは防げないが、それは配布の仕組みとは扱わない。

ロードマップの項目は、宣言を `.gm` の中に書くことを前提にしていた。
案は宣言を `.gmx` に分けたので、項目の「宣言の記法」「`@set` との関係」「`@import` で別のファイルから使うこと」は、この ADR の形に読み替える。

## 実装すること

### 立場の変更

この ADR は、[golem-eval ADR 0001](../golem-eval/adr/0001-expression-language-and-numerics.md) の「実装しないこと」のうち「ユーザー定義の関数」を改める。
書き手は `.gmx` に関数を定義でき、`.gm` からコマンドとして呼べる。
条件式と繰り返しは、`.gm` の式文脈には今後も足さない（[docs/roadmap.md](../roadmap.md) の課題にしなかった事項の「式の拡張」のまま）。
`.gmx` の中で、パターンマッチと再帰として書ける。

[docs/markup.md](../markup.md) の「ユーザーが関数を定義する仕組みは持たず、それはプラグインの役割とする。」は、実装のときに、関数を `.gmx` に定義してコマンドとして呼ぶ旨と、その節へのリンクに書き換える。
[golem-eval ADR 0001](../golem-eval/adr/0001-expression-language-and-numerics.md) のステータスの行には、実装のときに、ユーザー定義の関数をこの ADR が改めたことと、この ADR へのリンクを加える。

### 公開するコマンドの宣言

```haskell
pub inline reading :: String -> Inlines => file;
pub inline taxIncluded :: Nat -> Inlines;
pub block wordTable :: String -> Blocks -> Blocks => file;
```

- `pub inline` を付けた関数はインラインのコマンドに、`pub block` を付けた関数はブロックコマンドになる。
- `pub inline` の戻り値の型は `Inlines`、`pub block` の戻り値の型は `Blocks` でなければならない。違えば G10601 とする。
- 一つの関数には `inline` と `block` のどちらか一方だけを書く（下の「決めたことの記録」）。文法が一方だけを受け付けるので、`pub inline block f` は構文の誤り（G10100）になる。インラインとブロックの両方に同じ名前のコマンドを出したいときは、関数を二つ書き、名前の写し方で同じ名前にする。インラインのコマンドとブロックコマンドは別の名前空間にある（[docs/adr/0122](0122-block-commands-in-plugins.md)）ので、重ならない。
- `pub inline` と `pub block` は、`manifest.toml` の `[functions]` の `files` に書いた `.gmx` の中でだけ意味を持つ（[ADR 0149](0149-gmx-requirements-and-driver-handlers.md)）。`import` で読まれるだけの `.gmx` の `pub inline` は、ほかの `.gmx` から普通の関数として呼べるが、コマンドにはならない。

### コマンドの名前

`.gm` のコマンドの名前は、英小文字で始まり、英小文字、数字、`-` だけからなる。
`.gmx` の識別子は `-` を持てないので、関数の名前をコマンドの名前に写す。

- 英大文字の一字を、`-` と、その英小文字に置き換える。`taxIncluded` は `tax-included`、`wordTable` は `word-table` になる。
- 英大文字が続く名前（`toHTML`）、`_` を含む名前、英字のほかの字を含む名前は、`pub inline` と `pub block` に使えない。G10600 とし、メッセージに使える形の例を添える。この制約で、写し方は一対一になる。

### 名前の登録と衝突

関数のコマンドは、プラグインのコマンドと同じく、プロジェクトの全体の名前である。
`.gm` に `@import` を書かずに呼べる。

- 組み込みのコマンドと同じ名前は G03105 とする。組み込みのコマンドを関数で上書きする手段は設けない。上書きはプラグインの `overrides` の役割である。
- プラグインのコマンドと同じ名前は G03106 とする。
- 二つの `.gmx` が同じ名前のコマンドを出せば G03107 とする。
- どれも読み込みの時点のエラーであり、位置は後から読んだ `.gmx` の宣言である。

`.gmx` の読み込みか型の検査に誤りがあるときは、評価で G02009 を報告しない。
読み込めなかった関数のコマンドが、すべて未知のコマンドになって本当の原因を埋もれさせるからである（プラグインの G02022 と同じ扱い。[docs/adr/0122](0122-block-commands-in-plugins.md)）。

### 引数の写し方

コマンドの引数は、プラグインのコマンドと同じく評価してから関数に渡す。

- シグネチャの引数のうち、`Inlines` でも `Blocks` でもない型の引数が位置引数に、順に対応する。
- インラインのコマンドでは、その後ろに並ぶ `Inlines` の引数が、散文スロットに順に対応する。
- ブロックコマンドでは、最後の引数を `Blocks` にすると、字下げした本体を受け取る。
- `Inlines` と `Blocks` の引数を、ほかの型の引数の前に置くと G10602 とする。

値の写し方は次の表のとおりである。

| `.gm` の値 | `.gmx` の型 |
| --- | --- |
| 自然数、整数、有理数 | `Nat`、`Int`、`Rat`（[docs/adr/0101](0101-rational-numbers-in-expressions.md) の暗の広げ方に従う） |
| 文字列（語を含む） | `String` |
| 真偽値 | `Bool` |
| 配列 | `List a`（要素がすべて `a` に写せる場合） |

- 連想配列、範囲、`nil` は v1 では渡せない。シグネチャにこれらに当たる型を書く手段もない。
- 引数の型が `.gm` から渡せない型（関数の型、利用者のデータ型、`Maybe a`）の関数を `pub inline` と `pub block` にすると G10602 とする。
- キーワード引数は v1 では受け付けず、G02119 とする。
- 位置引数の数がシグネチャと合わなければ G02120 とする。
- 値の型が引数の型に写せなければ G02121 とする。メッセージには、引数の位置と、求めた型と、渡した値の型を書く。
- 散文スロットの数が合わなければ G02122 とする。
- 本体を受け取らない関数のブロックコマンドに本体を書くと、G02123 とする。

どの誤りでも、関数を呼ばない。

### 戻り値の作り方

関数は、組み込みのモジュール `Inline` と `Block` の関数で、意味論 IR を作って返す。

- `Inline`：`text`、`ruby`、`kenten`、`charStyle`、`color`、`tcy`、`number` と、`Inlines` をつなぐ `++` を持つ。ルビの入れ子のような、意味論 IR の不変条件に反する値は、型で作れないようにする。
- `Block`：`paragraph`、`bulletList`、`orderedList`、`defList`、`table`、`code` を持つ。プラグインのブロックコマンドが返せるブロックと同じ範囲である（[docs/adr/0122](0122-block-commands-in-plugins.md)）。見出し、一覧の出力、改ページ、行アキは作れない。
- 散文スロットと本体で受け取った `Inlines` と `Blocks` は、中身を読めない値として扱う。そのまま返すか、ほかの値で包んで返せる。中に注、相互参照、索引の印、評価を遅らせた値があっても、受け取ったまま渡るので、評価の階層は崩れない。
- 関数が作ったノードのソースの位置は、呼び出しの位置とする。
- 段落スタイル、文字スタイル、色の名前は、組み込みのコマンドと同じく検査し、なければ同じコード（G02047 など）とする。

### 評価の段階

関数は、プラグインのコマンドと同じく、ファイル内評価（S0）でだけ呼ぶ（[仕様書の「実行の範囲」](../specifications.md#実行の範囲)）。
S1 と S2 の値は受け取れず、`doc` を参照する引数はプラグインのコマンドと同じ扱いとする。
関数は純粋であり、`file` の要求の値も読み込みの時点で決まるので、ファイルを並列に評価できる。

### 式文脈から呼ばないこと

v1 では、関数を `[= f(x)]` の式文脈から呼べない。
戻り値は `Inlines` か `Blocks` であり、式の値にならないからである。
数や文字列を返す関数を式から呼ぶことは、別の ADR で扱う。

### モジュール

golem-eval の `EvalContext` に、関数のコマンドの表を足す。
型は golem-eval に置き、中身は golem-driver が golem-gmx から作る。
golem-eval は golem-gmx に依存しない。

- **golem-eval**：`FunctionCommand` と `FunctionBlockCommand`（引数、散文スロットか本体、位置を受け取り、IR と diagnostic を返す関数）と、`EvalContext` の `ctxFunctions` を足す。コマンドの解決は、組み込み、プラグイン、関数の順に調べ、どれでもなければ G02009 とする。名前の衝突は読み込みで止めるので、順は結果に影響しない。
- **golem-gmx**：`pub inline` と `pub block` の一覧、名前の写し方、引数の写し方を持つ。
- **golem-driver**：`[functions]` を読み、golem-gmx で読み込みと型の検査をし、関数のコマンドの表を作る。名前の衝突を検査する。`golem fmt` に `.gmx` の整形を加える。
- **golem-lsp**：下の「LSP」のとおり、golem-gmx に依存する。
- **golem-project**：`manifest.toml` の `[functions]` を読む。

build-depends の変更は、golem-driver と golem-lsp に golem-gmx を足すことだけである（[ADR 0148](0148-gmx-function-language-core.md) の「パッケージ」）。

### LSP

- `.gmx` のファイルの diagnostics を公開する。
- `.gm` の補完に、関数のインラインのコマンドとブロックコマンドの名前を出す。
- `.gm` のコマンドの名前から、`.gmx` の宣言へ移動できる。参照の検索で、`.gmx` の関数を呼ぶ `.gm` の箇所を一覧にできる。
- `.gm` のコマンドの名前にカーソルを置くと、シグネチャ（要求を含む）を表示する。
- `.gmx` を開いて編集すれば、`files` からたどれる `.gmx` と、関数を呼ぶ `.gm` を評価し直す。
- `.gmx` の整形は fmt を呼ぶ。
- `.gmx` の中の補完は、v1 では持たない。

### 配布しないこと

関数のファイルは、プロジェクトのルートの中のパスでだけ指せる。
URL、ロックファイル、レジストリ、版の解決は持たない。
ほかのプロジェクトで使うには、ファイルをコピーする。
それを配布の仕組みとは扱わず、Golem は関数の出どころを記録しない。

### 決定性の検査

決定性の検査（同じ入力から同じ出力のバイト列と同じ diagnostics を得ること）に、関数を使う fixture を加える。
fixture は、インラインのコマンド、ブロックコマンド、`File.read` で読む TSV、末尾再帰を使う関数を一つずつ持つ。

### 仕様書と言語仕様

実装のときに、次の文書を変える。

- [docs/specifications.md](../specifications.md)：「関数」の節を足し、プラグインとの立ち位置の違いと、手数と深さの上限を書く。モジュールの図に golem-gmx を足す。
- [docs/markup.md](../markup.md)：上の「立場の変更」の書き換えと、関数のコマンドの呼び方。
- [docs/diagnostics.md](../diagnostics.md)：上 2 桁 `10` の段階と、三つの ADR のコードの節。
- [docs/roadmap.md](../roadmap.md)：「`.gm` の中の関数の宣言」の項目を消す。

## 実装しないこと

- 式文脈から関数を呼ぶこと。
- 関数をフィルタにすること。
- 関数で組み込みのコマンドを上書きすること。
- キーワード引数、連想配列と範囲の引数。
- `Inlines` と `Blocks` の中身を読むこと（文字を取り出す、パターンマッチで分ける）。
- 見出し、一覧の出力、改ページ、行アキ、図版を返すこと。
- `.gm` に `@import` で関数を取り込むこと。関数はプロジェクトの全体の名前である。
- プロジェクト全体の変数。ロードマップの別の項目（「プロジェクト全体の変数」）で扱う。`.gmx` の値を `[= ...]` から読む形を採るかも、その ADR で決める。
- 関数の配布、版の管理、出どころの記録。
- `.gmx` の中の補完と、`.gmx` の lint。

## テスト設計

テストを先に書き、`ctxFunctions` と `[functions]` の読み込みがないためにコンパイルできないことを確かめてから実装する。

golem-gmx のテストでは、次のことを確かめる。

- `taxIncluded` が `tax-included` に写ること。`toHTML` と `to_html` が G10600 になること。
- `pub inline` の戻り値が `String` なら G10601 になること。
- `Inlines` の引数を `Nat` の引数の前に置くと G10602、`Maybe Nat` の引数の `pub inline` が G10602 になること。

golem-eval のテストでは、次のことを確かめる。

- `[tax-included 1000]` が、関数の返したインラインになること。位置が呼び出しの位置であること。
- `[emph-twice: 本文]` の散文スロットが `Inlines` の引数に渡り、中の `[note: ...]` が受け取ったまま注になること。
- `@word-table words` の本体が `Blocks` の引数に渡ること。`@label` が返した最初のブロックに付くこと。
- キーワード引数が G02119、引数の数の誤りが G02120、`[tax-included abc]` が G02121、散文スロットの数の誤りが G02122、本体を受け取らない関数への本体が G02123 になり、どれも関数を呼ばないこと。
- 関数が返した段落スタイルの名前が未定義なら G02047 になること。

golem-driver のテストでは、次のことを確かめる。

- 組み込みのコマンドと同じ名前が G03105、プラグインのコマンドと同じ名前が G03106、二つの `.gmx` の同じ名前が G03107 になること。
- `.gmx` に型の誤りがあるとき、その関数を呼ぶ `.gm` に G02009 が出ないこと。
- 決定性の fixture を二度組み、出力のバイト列と diagnostics が一致すること。並列と逐次で一致すること。

golem-lsp のテストでは、関数のコマンドの名前の補完、宣言への移動、ホバーのシグネチャ、`.gmx` の編集で `.gm` の diagnostics が公開し直されることを確かめる。

## トレードオフ

関数のコマンドをプロジェクトの全体の名前にしたので、`.gm` に `@import` を書かずに呼べる。
その代わり、関数の名前が組み込みのコマンドに将来足す名前と重なると、そのとき関数の側を改名させることになる。
プラグインのコマンドも同じ性質を持つので、Golem の利用者には同じ規則として説明できる。

`Inlines` の中身を読めないので、初出の語にだけルビを振るような、本文を調べる関数は書けない。
本文を調べる仕事は、今のところプラグインのフィルタの役割である。
中身を読む操作を足すと、注や評価を遅らせた値の扱いを `.gmx` の型で表す必要があり、この ADR の範囲を超える。

キーワード引数を受け付けないので、引数の多い関数は位置で並べることになる。
`.gmx` の等式の引数は名前ではなくパターンなので、キーワードを引数に結び付ける規則を別に作る必要があり、v1 では採らなかった。

## 決めたことの記録

- **`pub inline` と `pub block`**（2026-11-04、メンテナー）：関数には `inline` と `block` のどちらか一方だけを書く。両方を書いた宣言は構文の誤り（G10100）とする。

- **採択**：メンテナーが採択した（2026-11-04）。この ADR が決めてほしい点として挙げた項目は、どれも ADR の推奨のとおりとする。

## メンテナーが決めること

1. **`.gm` からの見え方**：推奨は、`[functions]` の `files` の関数を、プロジェクトの全体のコマンドの名前にすることである（プラグインと同じ）。採らなかった案は、`.gm` に `@import functions/book.gmx as f` と書き、`[f.tax-included 1000]` で呼ぶことである。名前の衝突はなくなるが、命令文脈の名前に `.` を許す文法の変更と、章ごとの `@import` が要る。ロードマップの「`@import` で別のファイルから使うこと」は、`.gmx` どうしの `import` だけで満たすと読んだ。
2. **名前の写し方**：推奨は、英大文字を `-` と英小文字に決まった規則で写すことである。採らなかった案は、(a) 宣言にコマンドの名前を文字列で書く（`pub inline "tax-included" taxIncluded :: ...`）、(b) `.gmx` の識別子に `-` を許すことである。(a) は一つのものに二つの名前を持たせ、(b) は引き算と区別するために空白の規則を足すことになる。
3. **`pub inline/block` の読み方**：決めた（「決めたことの記録」）。
4. **式文脈からの呼び出し**：推奨は v1 では持たないことである。採らなかった案は、`pub` の関数のうち、引数と戻り値が数、文字列、真偽値、配列のものを `[= f(x)]` で呼べるようにすることである。ロードマップの「小さな計算」には、こちらのほうが合う。ただし、式文脈の型の推論（[docs/markup.md](../markup.md) の「評価の前の解析」）に関数の型を足すことになり、プロジェクト全体の変数の ADR と同時に決めたほうが、名前空間の規則が一つで済む。
5. **`Inlines` の中身を読むか**：推奨は読めないことである。採らなかった案は、`Inline.plainText :: Inlines -> String` だけを持つことである。散文スロットの文字に応じて出力を変える関数（読みの辞書を引くなど）が書けるようになるが、中の注や相互参照を文字としてどう読むかを決める必要がある。
6. **キーワード引数**：推奨は v1 で受け付けないことである。採らなかった案は、最後の引数をレコードにし、キーワード引数をレコードの欄に写すことである（`pub inline f :: Nat -> { align :: String } -> Inlines`）。無名のレコードの型が要り、[ADR 0148](0148-gmx-function-language-core.md) の型の一覧を広げる。
7. **関数のコマンドの表を golem-eval に置くか**：推奨は、`PluginHook` と別に `ctxFunctions` を足すことである。採らなかった案は、driver が関数を `PluginCommand` に包み、プラグインのコマンドの表に混ぜることである。golem-eval は変わらないが、int64 の検査（G02091）やプラグインの G06 のコードが関数にも当たり、原因と違うコードが出る。
