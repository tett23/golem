# ADR 0026: 組みにくい公有の作品を fixture に十作加える

ステータス: 採択

## 文脈

golem-driver のテストは、公有の作品として『テンペスト』と『蟹工船』の二冊を組んでいる（[docs/adr/0023](0023-fixture-converters-without-python.md)）。
二冊は、横組みの戯曲と縦組みの小説という両極を一冊ずつ押さえるが、組版の難所の多くを含まない。
『テンペスト』には脚注の本文も表も字下げした詩もなく、『蟹工船』のルビは漢字の親文字への短いルビがほとんどで、字下げ、返り点、短歌、戯曲の台詞の組み方は現れない。
行分割や禁則の不具合は一冊の分量を組んで初めて見えることが多いので、難所を含む本を増やしたい。

一方で、今の変換（`golem-fixtures gutenberg-play` と `aozora`）は、二冊の原文に合わせて書いたものである。
Project Gutenberg の戯曲以外のテキスト（詩、注のある小説、例文の二段組の教科書）は変換できない。
青空文庫の変換は、字下げ、地付き、改ページ、返り点、傍点の形の違い、くの字点の注記を、注記ごと捨てる。
[ADR 0023](0023-fixture-converters-without-python.md) は、二つの変換の規則を Python のスクリプトの写しに固定しているので、規則を足すには別の ADR が要る。

### フォントの置き方

既存の二冊は、使うフォントを各プロジェクトの `fonts/` にコミットしている（Noto Serif JP は 6.2 MB、Source Serif は 0.6 MB）。
十冊のそれぞれに同じファイルを置くと、およそ 34 MB がリポジトリに増える。
Golem はフォントをプロジェクトルートの中のファイルからだけ読み、シンボリックリンクでルートの外を指すと G0802 になる（手元で確かめた）。
二つのマニュアルは、フォントをコミットせずにスクリプトで取得して置いている（`/manual/fonts/` を無視している）。

### フォント

十冊は `fonts/` をコミットしない。
新しいスクリプト `scripts/fixtures/copy-fonts.sh` が、『蟹工船』と『テンペスト』の `fonts/` を十冊の `fonts/` に写す。
`fetch-public-domain.sh` は最後にこのスクリプトを呼ぶ。
`.gitignore` に `modules/golem-driver/test/fixtures/pd/*/fonts/` を足す。

### 変換の新しい命令

`golem-fixtures` に三つの命令を足す。
既存の `gutenberg-play` と `aozora` の出力は変えない。

```
golem-fixtures gutenberg-text [OPTION...] INPUT.txt OUTPUT.gm
golem-fixtures aozora-prose INPUT.txt OUTPUT.gm
golem-fixtures aozora-verse INPUT.txt OUTPUT.gm
```

#### gutenberg-text

Project Gutenberg の戯曲以外のテキストを変換する。
本文は空行で区切ったまとまり（ブロック）ごとに次の順で判定する。

1. `--heading PREFIX`（何度でも書ける）：最初の行が PREFIX で始まるブロックは一段目の見出しにする。
2. `--caps-heading N`：一行だけで小文字を含まないブロックは N 段目の見出しにする。
3. `--numbered-headings`：字下げのない三行以下のブロックで、最初の行が「数字と `. `」で始まるブロックは二段目の見出しにする。
4. `--speakers`：最初の行が大文字の名前と `.` で始まるブロックは、その名前を `[strong: …]` にする。名前だけのブロックは名前だけの段落にする。
5. 韻文：二行以上のブロックで、`--verse` のときは「すべての行が 60 字未満か、すべての行が字下げしてある」もの、`--verse` がないときは「すべての行が字下げしてあり、すべての行が大文字で始まり、最後の行を除くどれかの行が 60 字未満である（折り返した散文でない）」ものを `@style verse` にする。ブロックの中で最も浅い字下げからの差は、空白二つを 1zw として行頭の `[aki]` で表す。66 字以上の行の次の、小文字で始まる行は、原文の折り返しとみなして前の行につなぐ。
6. 引用：字下げしたブロックで韻文でないものは、行をつないで `@style quote` の段落にする。
7. ほかは行をつないで段落にする。

ほかの選択肢は次のとおりである。

- `--start TEXT`、`--end TEXT`：前後の空白を除いて TEXT に等しい行から、TEXT に等しい行の手前までを本文とする。書かなければ Project Gutenberg の始まりと終わりの印のあいだの全体である。
- `--two-columns`：空白二つで字下げしたブロックの直後に空白四つで字下げしたブロックが続くものを、表の一行（左と右）にする。連続する行は一つの表にまとめ、見出しの行は空にする。
- `--notes MARKER`：MARKER に等しい行より後を注の節とし、`[N] 本文` のブロックを注 N の本文とする。本文の `[N]` を `[note: 注の本文]` に置き換え、注の節は出力しない。
- `--bold-equals`：`=…=` を `[bold: …]` にする。

`_…_` を斜体にし、`--` をダッシュにし、`[`、`\`、`%%` と行頭の特別な文字をエスケープするのは `gutenberg-play` と同じ規則による。
`[Illustration…]` や `[Greek: …]` のような角括弧の注記は、エスケープして本文のまま残す。

#### aozora-prose と aozora-verse

`aozora` の規則（ルビ、傍点、縦中横、見出し、外字、底本の節）に、次の注記を足す。

| 注記 | 変換 |
| --- | --- |
| `［＃「…」に白ゴマ傍点］`、`丸傍点`、`白丸傍点`、`黒三角傍点`、`白三角傍点`、`二重丸傍点`、`蛇の目傍点` | `[kenten shape=…: …]`（`open-sesame`、`circle`、`open-circle`、`triangle`、`open-triangle`、`open-double-circle`、`double-circle`） |
| `［＃「…」は太字］`、`［＃「…」は斜体］` | `[bold: …]`、`[italic: …]` |
| 返り点（`［＃レ］`、`［＃一］`〜`［＃三］`、`［＃上］`、`［＃中］`、`［＃下］`、`［＃甲］`、`［＃乙］` と、その組み合わせの `［＃一レ］` など） | `[style kunten: …]` |
| 訓点の送り仮名 `［＃（ト）］` | `[style kunten: ト]` |
| `［＃改ページ］`、`［＃改丁］`、`［＃改見開き］` | `@page-break`、`@page-break recto`、`@page-break recto`（見開きの始まりを奇数ページで近似する） |
| `／＼`、`／″＼` | `〳〵`、`〴〵` |
| `※［＃始め二重括弧、1-2-54］`、`※［＃終わり二重括弧、1-2-55］` | `⦅`（U+2985）、`⦆`（U+2986） |
| `［＃ここから中見出し］…［＃ここで中見出し終わり］` などの範囲の見出し | 見出し |
| `［＃「…」は同行中見出し］` などの同行見出し | `[bold: …]`（行の中に見出しを置く記法がないため） |

`aozora-prose` は、字下げを段落スタイルにする。

- `［＃N字下げ］` で始まる行と、`［＃ここからN字下げ］` から `［＃ここで字下げ終わり］` までの行は、`@style indent-N-N` を付けた段落にする。
- `［＃ここから改行天付き、折り返してM字下げ］` の範囲と `［＃改行天付き、折り返してM字下げ］` で始まる行は `@style indent-0-M`、`［＃ここからN字下げ、折り返してM字下げ］` は `@style indent-N-M` にする。
- 段落スタイル `indent-F-R` は、一行目を F 字、二行目以降を R 字下げる。各プロジェクトの `style.toml` で、原稿が使うものだけを定義する（`indent = "Rzw"`、`first-line-indent = "(F−R)zw"`）。

`aozora-verse` は、空行で区切った行のまとまりを一つの連とし、連ごとに `@style verse` にする。
字下げは、行頭に全角の空白を字数だけ置いて表す。

二つの命令は、次の注記を捨て、文字は残す。
変換できないことを README に書く。

- 傍線（`に傍線`、`に二重傍線`、`に鎖線`、`に破線`、`に波線`）と、ばつ傍点。Golem に傍線の記法がない。
- 行をまたぐ範囲の傍点（`［＃傍点］…［＃傍点終わり］`）。十作に現れないので扱わない。
- 地付きと地からの字上げ（`［＃地付き］`、`［＃地からN字上げ］`）。段落スタイルに行の揃えがない。
- 行右小書き、行左小書き、段階の小さな文字、ページの左右中央。
- 返り点の位置。返り点は小さな文字として本文の流れの中に置き、漢字の左下には付けない。

JIS X 0213 の面区点番号だけで Unicode の符号位置のない外字は、`aozora` と同じく `〓` にする。
対応表をリポジトリに持たないためである。

### テスト

golem-driver のテストに、十冊を検査する群を足す（「テスト設計」の節）。

### ドキュメント

`modules/golem-driver/test/fixtures/README.md`、`fetch-public-domain.sh` の先頭のコメント、`manual-dev` の「フィクスチャとライセンス」の章、README.md の Development の節を直す。

## 実装しないこと

- 『テンペスト』と『蟹工船』の変換の規則の変更。
- 返り点を漢字の左下に付ける組版、傍線、地付き、行の揃え、小書き。どれも記法の追加が要るので、別の ADR で扱う。
- JIS X 0213 の面区点番号から Unicode への対応表。
- 変換を CI で動かすこと。原文の取得にネットワークを使うので、今と同じく手で動かす。
- 原文とフォントのコミット。

## テスト設計

### 先に書いて失敗させるテスト

`modules/golem-fixtures/test/Main.hs` に、小さな入力と期待する出力の組で次を書く。

- `gutenberg-text`：見出し（`--heading`、`--caps-heading`、`--numbered-headings`）、話者の名前（名前だけのブロックを含む）、`--verse` の有無による韻文の判定、相対の字下げの `[aki]`、折り返しの行のつなぎ、引用の段落、`--two-columns` の表、`--notes` の注、`--bold-equals`、`--start` と `--end`、斜体とエスケープ。
- `aozora-prose`：傍点の形、太字と斜体、返り点と送り仮名（`｜` で範囲を示したルビの親文字の中の返り点を含む）、改ページと改丁、くの字点、二重括弧の外字、範囲の見出し、行頭の字下げと範囲の字下げと天付きの折り返し、捨てる注記（傍線、地付き、小書き）。
- `aozora-verse`：連と全角の空白の字下げ、見出しと改ページで連を区切ること。
- 命令の名前と選択肢の誤り（知らない選択肢、値のない選択肢）。

golem-driver のテストに、十冊のそれぞれについて次を確かめる群を足す。

- 既定では、出力を書かずに検査し（`golem check` と同じ）、エラーの診断がないこと。
- 環境変数 `GOLEM_PD_BOOKS` があれば、すべてのターゲットに組み、エラーの診断がないこと、四つのターゲットのファイルが書かれること、PDF が qpdf の検査を通ること、縦組みの本の PDF だけが `/Identity-V` を含むこと。

十冊をすべてのターゲットに組むと、手元（Apple M 系）で 35 秒かかる（うち *Nightmare Abbey* が 17 秒）。
CI の build のジョブはキャッシュが当たれば 100 秒ほどなので、既定では組まずに検査だけにする。
検査だけなら十冊で 2 秒に満たない。

### 自動テストにしない確かめ方

- `fetch-public-domain.sh` で十冊を作り直し、コミットした原稿と一致することを確かめる。
- 十冊を `golem build --target pdf` と `--target html` で組み、`golem check` を通し、診断と組版の目に見える問題を記録する。何ページかを画像にして目で確かめる。

## トレードオフ

- 十冊を組む試験は既定では動かないので、組版の段階で生じる誤り（G07xx など）は、CI では見つからない。手で `GOLEM_PD_BOOKS=1` を付けて確かめる必要がある。
- 十冊の原稿がリポジトリに入り、テキストでおよそ 1.2 MB 増える。原文の取得を CI で行わないので、原稿をコミットする今の形を続ける。
- フォントをコミットしないので、十冊はそのディレクトリで `golem build` を実行する前に `copy-fonts.sh` が要る。既存の二冊の「そのまま組める」性質は十冊に及ばない。代わりに 34 MB を足さずに済む。
- `gutenberg-text` の判定は行の形から推し量るので、選んだ五作の原文に合わせた規則であり、ほかの作品には選択肢を足す必要がある。誤りは、韻文と散文の取り違えのように原稿の上で見える形で残る。
- 変換できない注記を捨てると、地付きの署名や傍線の強調が普通の文字になる。注記をそのまま本文に残す案は、組んだ結果に `［＃…］` が並び、組版の検査の素材として役に立たないので採らない。
