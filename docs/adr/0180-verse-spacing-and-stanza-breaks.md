# ADR 0180: 韻文の前後の空きと、連をページの境で分ける規則

ステータス: 採択（未実装）

## 文脈

ロードマップの v0.1.0-rc4 に、韻文の二つの項目がある。
どちらも fixture の『The Hunting of the Snark』で見つかった。

- **韻文の後の空き**：韻文の段落と、その直後の本文の段落とのあいだに空きがない。
- **連の分割**：韻文の連が、ページの境で 2 行ずつに分かれる。

韻文は、`line-breaks = "keep"` の段落スタイル（組み込みの `verse`）を付けた段落で書く（[docs/adr/0003](0003-verse-line-breaks.md)、[docs/adr/0005](0005-character-and-paragraph-styles.md)）。
一つの段落が一つの連であり、段落の中の改行が韻文の行の区切りになる。
組み込みの `verse` は `space-between = 1` を持ち、連と連のあいだに一行を空ける。

### 再現

fixture の `pd/snark` を作業用のディレクトリに写し、`tempest` の fixture のフォントを置いて、`main`（`50b9fca8`）から作業用のディレクトリでビルドした `golem` で PDF を組んだ（2026-11-06）。
ページは 80dpi の PNG に描いて見た。
ページごとの行の並びは、PDF の内容のストリームの文字の位置から、行送り（14pt）で続く行のまとまりの大きさとして数えた（作業用のスクリプトで、コミットしない）。

- 1 ページ目で、献辞の韻文の最後の連の `Yet haunt my dreaming gaze!` の直後の行に、本文の段落 `Contents` が空きなしに続く。その直後の目次の韻文（`PREFACE` から始まる連）も、`Contents` の直後に空きなしに続く。
- 本文の連はほとんどが四行である。27 ページのうち、連がページの境で分かれる箇所は 16 ある。分かれ方は、前のページに三行と次のページに一行が 8 か所、一行と三行が 5 か所、二行と二行が 3 か所だった。

ロードマップの記述は「2 行ずつ」だが、今の `main` では一行だけをページの端に残す分かれ方のほうが多い。

### 韻文の後に空きがない原因

段落のあいだの空きは、PDF では `blocks` の `gapBefore` が置く（[`Flow.hs`](https://github.com/tett23/golem/blob/50b9fca8a0744f6f9d92808db231e6c04ac35d2c/modules/golem-driver/src/Golem/Driver/Pdf/Flow.hs#L1269-L1274)）。
`gapBefore` は、前の段落と次の段落が同じ段落スタイルのときだけ、その `space-between` の行を空ける。
`space-between` は「同じ段落スタイルの段落が続くとき」の空きであり（[docs/adr/0005](0005-character-and-paragraph-styles.md)）、違うスタイルの段落とのあいだに空きを置く欄はない。
そのため、連と連のあいだには一行が空くが、韻文と本文のあいだは空かない。

段落の前後の空きの欄（`space-before` と `space-after`）は、同じ v0.1.0-rc4 の「段落の前後のアキ」で、[docs/adr/0189](0189-paragraph-alignment-spacing-and-end-indent.md)（提案）が扱っている。
docs/adr/0189 は、組み込みの `verse` に前後の空きの既定を持たせることを「実装しないこと」とし、この項目に回している。

### 連が分かれる原因

`line-breaks = "keep"` の段落は、韻文の行ごとに一つの単位になる（[`Flow.hs`](https://github.com/tett23/golem/blob/50b9fca8a0744f6f9d92808db231e6c04ac35d2c/modules/golem-driver/src/Golem/Driver/Pdf/Flow.hs#L1284-L1296)）。
単位はそれぞれ一つの `FParagraph` の流れになり（[`Flow.hs`](https://github.com/tett23/golem/blob/50b9fca8a0744f6f9d92808db231e6c04ac35d2c/modules/golem-driver/src/Golem/Driver/Pdf/Flow.hs#L1803)）、改ページは `placeLines` で一つずつ置かれる。
`placeLines` の孤立行の規則（段落の最初と最後の行を、ページの境に一つだけ残さない）は、一つの `FParagraph` の中でだけ働く（[`Paginate.hs`](https://github.com/tett23/golem/blob/50b9fca8a0744f6f9d92808db231e6c04ac35d2c/modules/golem-layout/src/Golem/Layout/Paginate.hs#L304-L320)）。
韻文の行は折り返さなければ一行の段落なので、規則は何もしない。
連は、行のどの境でもページを分けられる。

[docs/adr/0003](0003-verse-line-breaks.md) は、行ごとに段落にすることで「折り返しが二行か三行の韻文の行は、ページをまたいで分かれない」ことを意図し、「連の途中で改ページしうる」ことを受け入れた。
連の分け方の規則は、どの ADR も決めていない。

fixture の版面は一ページ 33 行で、四行の連と一行の空きを繰り返すと 5 行ごとに連が終わる。
33 は 5 で割り切れないので、連を分けずにページを埋めることはできない。
連を分けないなら、ページの下に空きの行が残る。

## 実装すること

この ADR は、段落の前後の空きの欄を [docs/adr/0189](0189-paragraph-alignment-spacing-and-end-indent.md) に頼る。
docs/adr/0189 を実装した後に実装する（「メンテナーが決めること」の 1）。

### 組み込みの `verse` の前後の空き

組み込みの段落スタイル `verse` に、`space-before = 1` と `space-after = 1` を持たせる（「メンテナーが決めること」の 2）。

- 韻文と、前後の違うスタイルの段落とのあいだに、一行を空ける。空きの合わせ方、段の先頭で捨てること、HTML と EPUB の書き方は、docs/adr/0189 の規則に従う。
- 連と連のあいだは、今のとおり `space-between` の一行である（docs/adr/0189 の規則の 2）。
- `[paragraph-styles.verse]` に `space-before = 0` と `space-after = 0` を書けば、今の組み方に戻せる。

### 連をページの境で分ける規則（golem-driver、golem-layout）

`line-breaks = "keep"` の段落の行を、改ページで一つの連として扱い、連の始めと終わりに韻文の行を一つだけ残さない（「メンテナーが決めること」の 3）。
本文の段落の孤立行の規則を、韻文の行を単位にして連に当てる形である。

- `Golem.Layout.Paginate.Types` の `Flow` に、連を表す `FStanza [[LineBox]]` を加える。外の列が韻文の行、内の列がその行を折り返した行の箱である。
- `Golem.Driver.Pdf.Flow` は、`line-breaks = "keep"` の一つの段落から作った韻文の行の単位を、一つの `FStanza` にまとめる。段落の罫線を持つ段落（`FRuled`）は、今のとおり扱う。
- 改ページは、`FStanza` を次の規則で置く。
  - 韻文の行は、今のとおり、折り返した行の途中でページを分けない。
  - 段に収まる韻文の行の数を k、連の韻文の行の数を n とする。n − k が 1 なら k を 1 減らし、その後 k が 1 で n が 2 以上なら k を 0 にする（`placeLines` の規則と同じ形）。
  - k が 0 になったら、連の全体を次の段に送る。
  - 段が空で、それでも k が 0 になる場合（連が段より高いなど）は、今の `placeLines` と同じく、収まるだけの行を置く。
- 見出しを後と離さない規則と `@no-page-break` の先読み（`nextNeed`）は、`FStanza` の最初の二つの韻文の行の行数（n が 1 なら一つ）を、後のものの量とする。今は最初の韻文の行の行数である。
- 改ページの判定の繰り返し（`Golem.Layout.Paginate.Decide`）も、`FStanza` を `FParagraph` と同じく、行を持つ流れとして扱う。

四行の連は、二行と二行でだけ分かれうる。
三行以下の連は分かれない。

### HTML、EPUB、プレーンテキスト

連の分け方は PDF だけの規則であり、HTML と EPUB では何も出力しない。
HTML と EPUB の前後の空きは、docs/adr/0189 の CSS の規則で書く。
プレーンテキストは変えない。

### ドキュメント

- 仕様書の組み込みの段落スタイルの説明（`verse` は `line-breaks = "keep"`、`space-between = 1`）に、`space-before = 1` と `space-after = 1` を加える。
- 仕様書の改ページの節に、`line-breaks = "keep"` の段落を一つの連として扱い、連の始めと終わりに韻文の行を一つだけ残さないことを書き、この ADR へのリンクを付ける。
- 使い手のマニュアルの韻文の説明に、韻文の前後に一行が空くことと、連がページの境で一行だけ残らないことを書く。
- [docs/adr/0003](0003-verse-line-breaks.md) のステータスの行に「連をページで分ける規則は [docs/adr/0180](0180-verse-spacing-and-stanza-breaks.md)」を加える。
- ロードマップの v0.1.0-rc4 から「韻文の後の空き」と「連の分割」を消す。v2 の「韻文の拡張」の「連をページで分けない指定」は、v1.0.0 の「段落スタイルの分割禁止と連動」の「段落を分割しない」で表せるので、その項目へ寄せる。

## 実装しないこと

- 連をページで分けない指定。v1.0.0 の「段落スタイルの分割禁止と連動」で扱う。
- 連の始めと終わりに残す行の数を変える設定。同じく v1.0.0 の「段落スタイルの分割禁止と連動」で扱う。
- 本文の段落の孤立行の規則を変えること。
- 一つの韻文の行が段より高い場合の扱いを変えること。
- 見開きの左右で行の数をそろえる最適化。
- HTML と EPUB で、連をページで分けないための CSS（`break-inside` など）。

## テスト設計

テストを先に書き、今の実装で失敗することを確かめてから実装する。

golem-layout の改ページのテスト（`Paginate` のテスト）に、次を加える。

- 段の残りが 3 行のところに、一行ずつの韻文の行が四つの `FStanza` を置くと、二行がその段に、二行が次の段に置かれること。
- 段の残りが 1 行のところに同じ連を置くと、連の全体が次の段に置かれること。
- 段の残りが 3 行のところに、韻文の行が三つの `FStanza` を置くと、三行がその段に置かれ、残りが 2 行のところでは連の全体が次の段に置かれること。
- 二つめの韻文の行が二行に折り返す連で、折り返した行のあいだでページが分かれないこと。
- 段より高い連を空の段に置くと、収まるだけの行が置かれること。
- 見出しの直後の `FStanza` で、見出しと最初の二つの韻文の行が同じ段に置かれること。

golem-driver のテストに、次を加える。

- `line-breaks = "keep"` の一つの段落が一つの `FStanza` になり、韻文の行の数が段落の中の改行の数より一つ多いこと。
- 組み込みの `verse` の段落の後に本文の段落を置くと、あいだに一行の `FSpace` があること。前に置いた場合も同じであること。
- `[paragraph-styles.verse] space-before = 0` と `space-after = 0` で、その空きがなくなること。
- `verse` の段落が二つ続くと、あいだの空きが `space-between` の一行だけであること。

見た目の回帰テストでは、韻文を含む fixture（『The Hunting of the Snark』、『テンペスト』、『The Merry Wives of Windsor』、『The Frogs』、『Nightmare Abbey』、『The Elements of Style』、『一握の砂』、『春と修羅』）の参照を更新する。
更新の前に、『The Hunting of the Snark』の 1 ページ目で韻文と `Contents` のあいだに一行が空くことと、どのページの境でも連の一行だけが残っていないことを、変わったページの画像で確かめる。

## トレードオフ

韻文の前後に一行が空くので、韻文を含むすべての本の組みが変わる。
戯曲の fixture では、韻文の台詞と散文の台詞のあいだにも一行が空く。
今は、韻文の台詞どうしのあいだにだけ一行が空き、韻文と散文の台詞のあいだは空かないので、韻文の台詞がどこで終わるかの見え方がそろっていなかった。
空けたくない本は、`[paragraph-styles.verse]` の二つの欄を 0 にする。

連の始めと終わりに一行だけを残さないので、ページの下に一行の空きが残ることがある。
本文の段落の孤立行の規則と同じ扱いである。

二行と二行の分かれ方は残る。
連を分けない規則にすると、四行の連と一行の空きの本では、ページの下に最大で四行の空きが残る。
どちらを選ぶかは本ごとに違うので、v1.0.0 の段落スタイルの「段落を分割しない」の欄で書き手が選べるようにする。

`FStanza` を加えるので、改ページの流れの種類が一つ増える。
`FParagraph` の列で連を表し、境目に印を置く案は、改ページのどの関数も印を読み飛ばす必要がある。
一つの連を一つの流れにするほうが、孤立行の規則を一か所に書ける。

docs/adr/0189 に頼るので、docs/adr/0189 が退けられるか、前後の空きの欄の形が変わると、この ADR の空きの部分は書き直しになる。

## 決めたことの記録

- **韻文の後の空きを直すこと**（ロードマップ、v0.1.0-rc4 の「韻文の後の空き」）：韻文の段落と、その直後の本文の段落とのあいだに空きがない。
- **連の分割を直すこと**（ロードマップ、v0.1.0-rc4 の「連の分割」）：韻文の連が、ページの境で 2 行ずつに分かれる。
- **二つの項目を一つの ADR にすること**（2026-11-06、ADR の作成の依頼）：「韻文の後の空き」と「連の分割」を一つの ADR で扱う。
- **すべての項目**（2026-11-07、メンテナー）：「推奨で問題ない」。「メンテナーが決めること」の 1 から 3 を、すべて推奨のとおりとした。

## メンテナーが決めること

すべて決めた（「決めたことの記録」）。

1. **docs/adr/0189 との順**：決めた。推奨のとおり、この ADR を docs/adr/0189 の後に実装する（「決めたことの記録」）。前後の空きの欄と規則を docs/adr/0189 に任せ、この ADR は組み込みの `verse` の既定と連の規則だけを決める。番号の順とは逆になるので、`/goal` では docs/adr/0189 を先に実装する。退けた案の一つは、`line-breaks = "keep"` の段落の前後に `space-between` の行を空ける規則をこの ADR で足す案である。docs/adr/0189 の欄と同じことを別の規則で表すことになり、二つの規則が重なる。もう一つは、空きと連を別々の ADR に分ける案である。作成の依頼が一つの ADR にまとめるとしている。
2. **組み込みの `verse` の前後の空き**：決めた。推奨のとおり、前と後の両方を一行にする（「決めたことの記録」）。韻文の段落が、連のあいだと同じ一行で前後から区切られる。退けた案の一つは、ロードマップの記述どおり後だけを一行にする案である。1 ページ目の目次の韻文のように、本文の直後に来る韻文の前に空きがなく、前後で見え方が違う。もう一つは、組み込みの既定を変えず、fixture の `style.toml` に書く案である。組み込みの `verse` を使うほかの本では空きがないままになる。
3. **連の分け方の規則**：決めた。推奨のとおり、本文の段落の孤立行の規則を連に当て、連の始めと終わりに韻文の行を一つだけ残さない（「決めたことの記録」）。今ある規則を同じ形で使い、ページの下の空きは最大で一行にとどまる。数えるのは、版面の行ではなく韻文の行とする。二行に折り返した韻文の行が一つだけ次のページに残ると、版面の行では二行でも、連の一行だけが離れて見えるからである。退けた案の一つは、連を分けない案である。四行の連の本で、ページの下に最大で四行の空きが残る。分けないかどうかは本ごとに違うので、v1.0.0 の段落スタイルの欄に任せる。もう一つは、今のまま分ける案で、ロードマップの項目が直らない。
