# ADR 0128: 縦中横を自動で当てる見本のフィルタ auto-tcy

ステータス: 採択

## 文脈

縦組みの本文では、2 桁の算用数字や `!?` を縦中横で組むことが多い（JLReq の 3.2.4）。
今の Golem では、書き手が一つずつ `[tcy: !?]` か `[number-text 12 style=tcy]` と書くか、本の既定（`[numbers]` の `vertical` の `auto`）を `##12##` で使う。
地の文に書いた `12` と `!?` には、縦中横は当たらない。

rc4 では、これを自動で当てるフィルタを見本のプラグインとして作る（[docs/roadmap.md](../roadmap.md) の v0.1.0-rc4、[docs/adr/0106](0106-sample-plugins-in-rust.md)）。
ルビのプラグインは文字列にルビを付けて返すだけだが、このフィルタはテキストのノードを割り、組み込みのノードを挟む。
文書の全体を受け取って書き換えるフィルタの経路を、実際のプラグインで通す。

### 決めること

1. 当てる対象（何桁の数字か、どの記号の並びか）と、その決め方。
2. ノードの境をまたぐ文字の並び（`[strong: 1]2`）の扱い。
3. 触らない箇所（コード、ルビ、圏点、既存の縦中横）。
4. フィルタが縦組みか横組みかを知る方法。
5. diagnostic。

### 試しに実装して分かったこと

この ADR は、採択の前に実装を試した（ブランチ `plugins-number-tcy`、`plugins-foundation` から分岐）。
`plugins/auto-tcy` を作り、golem-driver のテストと、縦組みと横組みの小さなプロジェクトの `golem build`（PDF）で動かした。
試してわかったことは次のとおりである。

- **書字方向が分からない**：最初の試しでは、フィルタの要求は名前、文書、データだけを持ち、書字方向を持たなかった（[golem-plugin ADR 0001](../golem-plugin/adr/0001-wasm-host-and-abi.md)、[docs/adr/0105](0105-plugin-data.md)）。書字方向は `style.toml` の `[page]` の `writing-mode` で本ごとに決まるが、フィルタには `style.toml` が渡らなかった。
  - 数字には、IR の数のノード（tag 9）に `tcy` の表記を付けて返すことで、これを避けられた。数のノードはレイアウトが書字方向を見て組むので、横組みでは算用数字のままになる（[`numberPieces`](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/modules/golem-layout/src/Golem/Layout/Japanese.hs#L378-L385)）。
  - 記号の並びには、縦中横のノード（tag 8）しかない。縦中横のノードは、書字方向によらず一字分の箱になる（[`piecesOf`](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/modules/golem-layout/src/Golem/Layout/Japanese.hs#L282)）。同じ原稿を `writing-mode = "horizontal"` で組むと、`!?` は全角一字分の箱の中央に置かれ、前後に空きのある `本当か !? 、` になった。書き手が横組みで `[tcy: !?]` と書いた場合と同じ組み方であり、字が詰まったり重なったりはしないが、横組みでは不要な空きである。
  - プラグインが本の文脈を宣言して受け取る仕組み（[docs/adr/0121](0121-host-context-in-plugin-requests.md)）で解いた。`auto-tcy` は `writing-mode` を宣言し、横組みの本では文書を変えずに返す。同じ原稿を横組みで組み直すと、`!?` の前後の空きはなくなり、`auto-tcy-split` の警告も出なかった。
- **プレーンテキストの数**：数のノードを返すと、プレーンテキストの縦組みでは、縦中横の数を位取りの漢数字で書く（[docs/specifications.md](../specifications.md) の `[numbers]`）。原稿の `12` が、プレーンテキストでは「十二」になる。`[number-text 12 style=tcy]` と書いた場合と同じ振る舞いであり、ホストが G02063 で勧める書き方（[`builtinWith` の `BTcy`](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/modules/golem-eval/src/Golem/Eval/File.hs#L1740-L1746)）とも合うので受け入れた。
- **位置**：ホストは、出力のノードの位置が要求のノードの位置であることを検査する（[`checkOutput`](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/modules/golem-plugin/src/Golem/Plugin.hs#L311-L313)）。テキストのノードを割ると、割った断片には元のノードの位置をそのまま付けるしかない。`第12回` の `12` の数のノードは、`第12回` の全体を指す。テキストのノードの位置はエスケープなどで原稿のバイトと一対一にならないので、プラグインは位置を細かく計算できない。
- **フィルタを当てるファイル**：`[[filters]]` の `files` に、当てるファイルを一つずつ書く必要がある（[docs/specifications.md](../specifications.md) の「プラグイン」）。本の全体に当てるフィルタでも、章のファイルを足すたびに `files` を直すことになる。
- **辿れないインライン**：補助のクレートの `Document::map_inlines` は、図版のキャプションと見出しの `toc-title` を辿らない（どちらも CBOR の値のまま持つ。[docs/adr/0106](0106-sample-plugins-in-rust.md)）。このフィルタは、図版のキャプションの数字に縦中横を当てない。
- **データの誤りの位置**：`config` の誤りは、フィルタを当てたファイルの先頭に出すしかない。
- **diagnostic のコード**：`kansuji` と同じく `auto-tcy-split` のような文字列にした（[docs/adr/0108](0108-plugin-diagnostic-codes-and-spans.md)）。
- **縦組みで組んだ結果**：縦組みの PDF では、地の文の `第12回` の `12` と `本当か!?` の `!?` が縦中横で、`3.14` と `x86` が回転した欧文のまま組まれた。`[strong: 1]2` は警告 `auto-tcy-split`（位置は `[strong: 1]` の行と列）を出し、回転した欧文のまま組まれた。二回のビルドで、PDF のバイト列と JSON の diagnostic は同じだった。
- **大きさ**：`auto-tcy.wasm` は 124588 バイトだった（本の文脈を読む前は 121976 バイト）。

## 実装すること

### 置き場所と宣言

`plugins/auto-tcy` に、[docs/adr/0106](0106-sample-plugins-in-rust.md) の手順で置く。
プラグインはフィルタ `auto-tcy`、データの名前 `config`、本の文脈 `writing-mode`（[docs/adr/0121](0121-host-context-in-plugin-requests.md)）を宣言する。

```toml
[plugins.auto-tcy]
url = "https://github.com/tett23/golem/releases/download/v0.1.0-rc4/auto-tcy.wasm"
data = { config = "auto-tcy.conf" }   # 省いてよい

[[filters]]
plugin = "auto-tcy"
filter = "auto-tcy"
files = ["chapters/01.gm", "chapters/02.gm"]
```

### 当てる対象

このフィルタは、文書を**塊**に分けて読む。
塊は、インラインの列を読む順に並べた文字のうち、ASCII の図形文字（U+0021 から U+007E）の極大の並びである。
空白、和文の文字、全角の記号は塊を区切る。

一つのテキストのノードに収まる塊が次のいずれかなら、縦中横にする。

- **数字**：ASCII の数字だけからなり、桁数が `digits`（既定は 2）のいずれか。IR の数のノードに表記 `tcy` を付けて返す。先頭が 0 の 2 桁以上の数字（`05`）は、数のノードでは 0 が消えるので、縦中横のノード（tag 8）で返す。
- **記号**：`marks`（既定は `!!`、`!?`、`?!`、`??`）のいずれかと一致する。縦中横のノードで返す。

塊の全体で判断するので、`3.14`、`x86`、`A4`、`10%`、`!!!`、`12a` には当てない。
`1年` の `1` は 1 桁なので当てない。
全角の数字と記号（`１２`、`！？`）は、書き手の書いた文字を変えないために当てない。

### ノードの境

塊は、テキストのノードの境をまたいで数える。
`[strong: 1]2` の塊は `12` であり、二つのノードにまたがる。

- 二つ以上のノードにまたがる塊は、書き換えない。
- その塊の全体が上の対象に当たるときは、警告 `auto-tcy-split` を出す。メッセージは `ノードの境をまたぐので縦中横にしませんでした: <塊>。[tcy: ...] か [number-text ... style=tcy] で書いてください` である。位置は、塊にかかるノードの位置を合わせた範囲である。
- `x[strong: 86]` のように、全体が対象に当たらない塊は、何も言わない。

またぐ塊を書き換えないのは、割った結果が書き手の意図と合うか分からないからである。
`[strong: 1]2` を縦中横にするには、`1` を太字にした縦中横を作る必要があるが、縦中横のノードは文字スタイルを中に持てない。
黙って片方だけを当てると、書き手の入力と違う出力を黙って作ることになる。

一方、`第[strong: 12]回` の `12` は、太字のノードの中だけで塊になるので、太字の中で縦中横にする。

### ノードの種類ごとの扱い

| ノード | 塊の数え方 | 書き換え |
| --- | --- | --- |
| テキスト | 文字をそのまま並べる | する |
| 文字スタイル、色 | 中身を並べる | する。ただし文字スタイル `code` の中身はしない |
| 圏点、ルビの親文字 | 中身を並べる | しない |
| 縦中横 | 文字を並べる | しない |
| 数、相互参照、遅延した式、引用 | 中身が分からない字として並べる | しない |
| 脚注、傍注 | 印の位置で塊を区切る。本文は別の列として読む | 本文の中はする |
| 強制改行、アキ | 塊を区切る | なし |
| 索引の印、校正のコメント、チャネルの項目 | 何も並べない（組まれないので）。チャネルの項目の本文は別の列として読む | 本文の中はする |

中身が分からない字にかかる塊は書き換えない。
その塊のうち、一つのテキストのノードに収まる部分が対象に当たるときは、`auto-tcy-split` を出す（`[= n]12` の `12`）。
`[= n]` が数字を出すかどうかは、S0 では分からないからである。

コードのブロックは、補助のクレートが CBOR の値のまま渡すので、もともと触らない。

### config

```
# auto-tcy.conf
digits = 2 3
marks = !! !? ?! ?? !!!
```

- 一行に一つ、`キー = 値` と書く。値は空白で区切った並びである。空行と `#` で始まる行は飛ばす。
- `digits` は 1 から 4 の数の並び、`marks` は数字を含まない 1 字から 4 字の ASCII の図形文字の並びである。
- `none` と書くと空の並びになり、その種類の対象には当てない。

TOML にしなかったのは、キーが二つで、TOML の読み手をプラグインに入れるほどの理由がないからである。
`manifest.toml` の値を直接プラグインに渡す経路は、[docs/adr/0105](0105-plugin-data.md) が「実装しないこと」に置いている。

### 横組みの本

本の文脈の `writing-mode` が `horizontal` なら、文書を変えずに返し、`auto-tcy-split` の警告も出さない。
`config` の誤りは、横組みの本でも報告する。
フィルタの宣言の誤りを、書字方向を変えるまで見逃さないためである。

### diagnostic

| コード | 重大度 | 原因 |
| --- | --- | --- |
| `auto-tcy-split` | 警告 | 対象に当たる塊がノードの境をまたぐ |
| `auto-tcy-config-utf8` | エラー | `config` が UTF-8 でない |
| `auto-tcy-config-syntax` | エラー | `キー = 値` の形でない行 |
| `auto-tcy-config-key` | エラー | 知らないキー |
| `auto-tcy-config-digits` | エラー | `digits` の値の誤り |
| `auto-tcy-config-mark` | エラー | `marks` の値の誤り |
| `auto-tcy-no-command` | エラー | コマンドとして呼ばれた（`golem_describe` でコマンドを宣言しないので、ホストからは起きない） |

`auto-tcy-split` の重大度は警告である。
文書は書き換えずに残るので、出力は書き手の原稿のとおりであり、ビルドは止めない。
`config` の誤りのときは、文書を書き換えずに返し、位置はフィルタを当てたファイルの先頭とする。

### モジュールとドキュメント

- golem-* のパッケージのあいだの build-depends は変えない。Haskell のコードは golem-driver のテストだけを変える。
- 使い手のマニュアルのプラグインの章に、見本のフィルタとして `auto-tcy` の宣言と `config` を載せる。
- 採択の後、`docs/roadmap.md` の v0.1.0-rc4 から「縦中横を自動で当てるフィルタ」を除く。

## 実装しないこと

- 全角の数字と記号を半角に直して縦中横にすること。書き手の文字を変えることになる。
- 縦中横の中に文字スタイルを持たせること（IR の縦中横のノードは文字列だけを持つ）。
- 図版のキャプションと見出しの `toc-title` に当てること。補助のクレートがそれらを型で持つようになってから足す。
- 欧文の語を正立させる、1 桁の数字を全角にするなど、縦中横以外の縦組みの調整。
- 本の全体のファイルにフィルタを当てる宣言の書き方（`files = "all"` など）。ホストの変更なので、別の ADR で扱う。

## テスト設計

テストは、Rust の単体テスト（`cargo test -p auto-tcy`）と、golem-driver の `PluginsSpec` で行う。
Rust の単体テストは実装と同時に書いた。
golem-driver のテストは、`plugins/wasm/auto-tcy.wasm` を除いた状態で失敗することを確かめた。

Rust の単体テスト（`plugins/auto-tcy/src/lib.rs`）では、次のことを確かめる。

- `第12回`、`本当か!?`、`12`、`1月12日と10月`、`05年`。
- 当てないもの：`1年`、`123年`、`3.14`、`x86`、`A4`、`!!!`、`!`、`１２`、`！？`、`12a`、`a 1 b`、`10%`。空白が塊を区切ること。
- `code` の中、ルビの親文字、圏点、既存の縦中横を書き換えないこと。
- 文字スタイルと色の中を、外の隣を見て書き換えること。
- `[strong: 1]2`、`!` と `[bold: ?]`、縦中横の `1` と `2` が警告になり、`[strong: 1]23` と `x[strong: 86]` が警告にならないこと。
- 遅延した式の隣の `12` が警告になり、`年` は警告にならないこと。表記の決まっていない数の隣も同じ。
- 強制改行が塊を区切り、索引の印は区切らないこと。
- 脚注の本文が別の列であること。
- `config` の読み方とすべての誤り。`none`。
- フィルタの要求に対する応答と、`config` の誤りの位置。横組みの文脈では文書が変わらず、`config` の誤りは報告すること。
- 記述が `writing-mode` を宣言すること。

golem-driver のテスト（`modules/golem-driver/test/PluginsSpec.hs` の `autoTcyTests`）では、次のことを確かめる。

- 原稿の `第12回、本当か!?、3.14、123、[strong: 34]` の S0 のインライン。
- `[strong: 1]2` が警告になり、文書が変わらないこと。`golem build` の diagnostic の重大度が警告（`Warning`）であること。
- 横組みの本で、`第12回、本当か!?、[strong: 1]2` の文書が変わらず、警告も出ないこと。
- `[code: 12][tcy: !?]` が変わらないこと。
- `config` の `digits = 3` と `marks = !!!`。
- `config` の誤りが、横組みの本でも、ファイルの先頭のエラーになること。

手で確かめたこと：縦組みの小さなプロジェクトで `golem build` が PDF を書き、`12` と `!?` が縦中横で組まれること。
横組みのプロジェクトで、数字と記号の並びが地の文のまま組まれること。

## トレードオフ

塊を ASCII の図形文字の極大の並びとしたので、規則は単純だが、`10%` や `No.1` のような並びには当たらない。
これらを縦中横にしたい書き手は、`config` では指定できず、`[tcy: ...]` と書く。
規則を細かくすると、`3.14` の `14` や `x86` の `86` を誤って当てる危険が増える。

ノードの境をまたぐ塊は書き換えず警告にしたので、書き手が `[strong: 1]2` と書いた箇所は手で直すことになる。
警告を抑える手段はない（[docs/adr/0108](0108-plugin-diagnostic-codes-and-spans.md) は、プラグインの警告を `silence-notices` で抑えることを「実装しないこと」に置いている）。

本の文脈の `writing-mode` を宣言したので、`style.toml` の書字方向を変えると、フィルタを当てたファイルの S0 の結果が変わる。
LSP は `style.toml` の変更でプロジェクトの全体を評価し直す（[docs/adr/0121](0121-host-context-in-plugin-requests.md)）。

## 決めたことの記録

- **ノードの境をまたぐ並び**：メンテナーが、書き換えずに警告 `auto-tcy-split` を出す案でよいと決めた（2026-10-29）。重大度は警告であり、エラーではない。
- **書字方向**：メンテナーが、プラグインが要る本の文脈を宣言する仕組みを入れると決めた。`auto-tcy` は `writing-mode` を宣言し、横組みの本では何もしない。
- **diagnostic のコード**：メンテナーが、ホストがプラグインの宣言の名前をコードの前に付ける形でよいと決めた（[docs/adr/0108](0108-plugin-diagnostic-codes-and-spans.md)）。その草稿の実装の後は、プラグインは `split` などの後ろの部分を返す。
