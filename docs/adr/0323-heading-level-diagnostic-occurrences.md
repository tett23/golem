# ADR 0323: 見出しの上限を超えた箇所ごとに G01012 を一度報告する

ステータス: 採択（未実装）

## 文脈

[Golem ADR 0188](0188-headings-beyond-level-3.md) の調査時には、同じ見出しについて `golem check` が二度、HTML ビルドが一度 G01012 を返した。
現行の上限は六階層である。
今回の試作は七つの `#` で始まる見出しを使い、章と import の組み合わせを変えて両方のコマンドを比べた。

| 入力 | check の件数 | HTML ビルドの件数 |
| --- | --- | --- |
| 二つの不正な見出しを持つ章 | 2 | 2 |
| 同じ章を入れ子の章一覧に置く | 2 | 2 |
| 同じ章を二度指定する | 2 | 2 |
| 二章にそれぞれ二つと一つ置く | 3 | 3 |
| 二章が同じ不正なファイルを import する | 1 | 1 |
| 章としても import 先としても同じ不正なファイルを読む | 1 | 1 |

## 実装すること

この六つのプロジェクトを CLI の回帰テストにする。
[Golem ADR 0337](0337-test-build-and-check-in-the-same-process.md) の共通関数で check と HTML ビルドをテストプロセスから実行する。
JSON に出た G01012 のファイルと開始位置と終了位置を、重複を消す前に比較する。
既存の再現記録に加え、どのオプション、章一覧、import 先で diagnostics が重なったかを記録できるようにする。

## 実装しないこと

再現した六つの入力には、diagnostics の列の重複を取り除く処理を足す根拠がない。
同じ文言の diagnostic でも、別の位置の見出しなら両方を報告する。
過去の重複を起こした条件と、重複がなくなったコミットは未確認である。

## 不変条件

1. H1：実際に読むファイルにある上限超過の見出し一つにつき、各コマンドはその位置の G01012 を一つ返す。
2. H2：同じプロジェクトで二つのコマンドの G01012 の位置が一致する。

| 境界 | 件数 |
| --- | --- |
| 六つの `#` | 0 |
| 七つの `#` | 1（七つ目から） |
| 同じ文字列を別の二つのファイルに置く | 2 |
| 同じファイルを二つの章が import する | 1 |

## テスト設計

`experiments/diagnostics/baseline.mjs` が六構成に対して `check --format json` と `build --target html --format json` を実行する。
`expected.mjs` の H1 は結果を位置の配列のまま比較し、同じ位置が複数回現れないことも検査する。
基準版で六構成とも通った。
本実装では入力から予期したファイルと開始位置を列挙し、両コマンドがそろって一件を落とした場合も失敗させる。

## トレードオフ

同じプロセスで二つの経路を呼ぶと、各入力の子プロセス起動を省き、diagnostics を後から結合した結果を調べられる。
引数の解析と標準エラー出力は CLI の結合テストで確かめる。
