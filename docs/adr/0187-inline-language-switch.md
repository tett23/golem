# ADR 0187: 原稿の一部の言語を `[lang]` と `@lang` で指定する

ステータス: 採択（未実装）

## 文脈

本の言語は、`manifest.toml` の `[metadata] language` だけで決まる。
原稿の一部の言語を指定する記法はない。
ロードマップの v0.1.0-rc4 の「原稿の中の言語の切り替え」は、その記法を加え、引用符と和欧の扱いをその部分の言語で切り替えられるようにする項目である。
その部分をその言語の分綴のパターンで分綴することは、v1.0.0 の「本の中の別の言語の分綴」で扱う。
この ADR は、v1.0.0 の項目が言語の区間をそのまま使えるように作る。

### 本の言語が今決めていること

本の言語が出力を変えるのは、次の箇所である（コードを読んで確かめた）。

- 番号と題のあいだの区切り（全角の空白か半角の空白）、注の一覧の見出しの文言、見出しの `lines` の既定、`@printings` を組めるか。どれも主の副タグが `ja` かどうかで決める（[`numberSeparator`](https://github.com/tett23/golem/blob/50b9fca8a0744f6f9d92808db231e6c04ac35d2c/modules/golem-doc/src/Golem/Doc/Numbering.hs#L15-L19)）。
- HTML と EPUB の `html` の要素の `lang` と `xml:lang`、EPUB の `dc:language`（[`Html.hs`](https://github.com/tett23/golem/blob/50b9fca8a0744f6f9d92808db231e6c04ac35d2c/modules/golem-html/src/Golem/Html.hs#L334-L337)、[`Epub.hs`](https://github.com/tett23/golem/blob/50b9fca8a0744f6f9d92808db231e6c04ac35d2c/modules/golem-epub/src/Golem/Epub.hs#L86-L92)）。

`language` の値の形は検査しない。
v0.1.0-rc3 の `golem check` は、`language = "日本 語!"` のマニフェストを終了コード 0 で通した（2026-11-06）。

一方、PDF の組版は本の言語を見ない。

### 和欧の扱い

PDF の段落は、文字の種類（JLReq の文字クラス）で和文と欧文に分けて組む（[`charClass`](https://github.com/tett23/golem/blob/50b9fca8a0744f6f9d92808db231e6c04ac35d2c/modules/golem-layout/src/Golem/Layout/CharClass.hs#L33-L49)）。
欧文（`western`）の文字の連なりは一つの語の箱になり、欧文のフォント（役割の `latin`）で組み、パターンで分綴する。
ほかの文字は一字ずつの箱になり、和文のフォント（役割の `ja`）で組み、アキ量のセットの空きと禁則を当てる。
和文と欧文のあいだには、和欧間の空きが入る。

和文にも欧文にも使う文字（以下、両用の文字）は、文字だけでは種類が決まらない。
今の扱いは次のとおりである（[`textPiecesAt`](https://github.com/tett23/golem/blob/50b9fca8a0744f6f9d92808db231e6c04ac35d2c/modules/golem-layout/src/Golem/Layout/Japanese.hs#L374-L385)）。

- `‘’“”—‐‑–` は、どちらかの側の最も近い文字（両用の文字を飛ばした先）が欧文の文字なら、欧文の語に含める。そうでなければ、和文の文字クラス（`“` は始め括弧類、`—` は分離禁止文字など）の一字として組む。
- `…`（U+2026）は、つねに和文の分離禁止文字である。英文の `wait… what` の `…` も、和文の一字として和文のフォントで組み、前の `t` とのあいだに和欧間の空きが入る（コードを読んだ推定。PDF を測っては確かめていない）。
- `«»` は、つねに和文の始め括弧類と終わり括弧類である。`‹›`（U+2039、U+203A）は、文字クラスの表のどこにもないので、漢字等（`ideograph`）として組む。

このため、次のような原稿は、書き手の意図と違う組み方になる。

- 英語の本の中の `“東京”`：最も近い文字が漢字なので、引用符を和文の括弧として全角で組む。英語の本では欧文の引用符にしたい。
- 日本語の本の中の `“Hello”と言った`：引用符を欧文として組む。和文の引用符として全角で組みたい場合がある。
- フランス語の引用 `« Bonjour »`：`«` と `»` を和文の括弧として組む。

### 分綴

パターンで分綴するとき、PDF はつねに英語（en-US）のパターンを使う（[`Flow.hs`](https://github.com/tett23/golem/blob/50b9fca8a0744f6f9d92808db231e6c04ac35d2c/modules/golem-driver/src/Golem/Driver/Pdf/Flow.hs#L1044)）。
本の言語が日本語でも、欧文の語は英語のパターンで分ける。
英語の本の中のフランス語の語も英語のパターンで分けるので、fixture の Nightmare Abbey で「prover-be」と分けている（ロードマップの v1.0.0 の「本の中の別の言語の分綴」）。

## 実装すること

### 記法

言語を指定する記法は二つある（「メンテナーが決めること」の 1 と 7）。
文の中の語句は、インラインのコマンド `[lang]` で指定する。
段落、リスト、表のようなブロックの全体は、ブロックコマンド `@lang` で指定する。

#### インラインの `[lang]`

インラインのコマンド `[lang <タグ>: 散文]` で、散文の部分の言語を指定する。

```
英語では [lang en: “Tokyo”] と書く。
He said [lang fr: « Bonjour »] and left.
She wrote [lang ja: “東京”] on the card.
```

- 位置引数はちょうど一つで、言語のタグを語か文字列で書く。ないか二つ以上なら新しいエラー（G02131、`lang には言語のタグを一つ書きます`）とする。キーワード引数は取らない。
- タグは BCP 47 の形（`ja`、`en-US`、`zh-Hant-TW` など）でなければ、新しいエラー（G02132、`言語のタグの形が誤っています: <タグ>`）とする。検査するのは形だけで、IANA の登録簿に載っているかは調べない。登録簿を同梱すると、同じ入力でも Golem の版によって結果が変わるからである。
- 散文スロットはちょうど一つで、違えば今のインラインのコマンドと同じく G02038 とする。
- `[lang]` は入れ子にでき、内側の指定が勝つ。
- 見出し、表のセル、脚注、ルビの親文字の中にも書ける。文字スタイルと同じ位置に書ける。
- 組み込みのコマンドに `lang` を足すので、プラグインは `lang` という名前のインラインのコマンドを持てなくなる（[docs/adr/0122](0122-block-commands-in-plugins.md) の規則）。

#### ブロックの `@lang`

ブロックコマンド `@lang <タグ>` で、ブロックの言語を指定する。
`@style` と同じく、属性の形と本体の形の二つで書ける（[docs/markup.md](../markup.md) の「段落スタイル」と「ブロックへの属性」）。

```
@lang en
He said nothing, and the silence was the answer.

@lang fr
- Bonjour.
- Merci.

@lang en
  The first paragraph of a long quotation.

  The second paragraph of the quotation.

  - A list inside it.
```

- 属性の形：インデントのない次の行のブロックに、言語が付く。ブロックの種類は問わない。段落、見出し、箇条書き、番号付きの箇条書き、定義リスト、表、コードブロック、図版、一覧の出力（`@toc` など）、プラグインと `.gm` の関数のブロックコマンドに付けられる。リストに付ければ、リストの全体（すべての項目の中のブロック）がその言語になる。
- 本体の形：2 つ深くインデントしたブロックを並べる。本体のすべてのブロックに、言語が付く。本体には段落のほかのブロックも置ける。`@style` の本体が段落だけを置ける（G02045）のと違うのは、長い引用が段落とリストを混ぜることが多いからである。見出しも置ける。文書の最上位にだけ置けるコマンド（改ページ、改ページの制御、`@blank-line`）は、ほかのブロックコマンドの本体と同じく、今のコード（G02059、G02071、G02093）になる。
- 属性の形の `@lang` は、`@label`、`@style` などのほかの属性と並べて書ける。属性のまとまりの後にブロックがなければ、今のとおり G02010 とする。
- 位置引数とタグの形の誤りは、`[lang]` と同じコード（G02131、G02132）とする。キーワード引数は取らない。
- 一つのブロックに `@lang` を二つ付ければ、後に書いたものが勝つ。今の `@label` を二度書いたときと同じ扱いである（[`applyAttr`](https://github.com/tett23/golem/blob/50b9fca8a0744f6f9d92808db231e6c04ac35d2c/modules/golem-eval/src/Golem/Eval/File.hs#L1109-L1114) は属性を書いた順に当て、後の値で上書きする）。
- 組み込みのブロックコマンドに `lang` を足すので、プラグインと `.gm` の関数は `lang` という名前のブロックコマンドを持てなくなる。
- プラグインと `.gm` の関数のブロックコマンドに付けた `@lang` は、それが返したブロックのうち、言語を持たないものに付く。

`@lang` は、それを付けたブロックの中のインラインのすべてに及ぶ。
`[lang]` と `@lang` の入れ子では、内側の指定が勝つ。
`@lang en` を付けた段落の中の `[lang fr: ...]` はフランス語である。
`@lang en` の本体の中の、`@lang de` を付けたブロックはドイツ語である。
リストの項目、定義リストの説明、図版のキャプションの中のブロックは、外のブロックの言語を受け継ぎ、自分の `@lang` があればそれが勝つ。
脚注と傍注の本文は、注の印を置いた位置の言語を受け継ぐ。

新しいコードの番号は、ほかの草案と重ならないよう、採択の前に確かめて振り直す。

### 意味論 IR

インラインの要素に、言語の区間を足す。

```
  / [21, span, lang: tstr, inlines]                ; language span (docs/adr ADR 0187; tag 20 is the link of docs/adr ADR 0182)
```

- `lang` は原稿に書いたタグをそのまま持つ。大文字と小文字は変えない。
- `Golem.Doc.Validate` は、`lang` が BCP 47 の形であることを検査する。プラグインと Emet の関数が形の誤ったタグを返せば、ほかの不変条件の違反と同じコードで報告する（プラグインなら G06009）。
- Emet の IR のデータ型（[ADR 0162](0162-calling-emet-functions-from-gm.md)）の `Inline.Inline` に、コンストラクタ `Lang String Inlines` を足す。プラグインとの ABI と同じ範囲のコンストラクタを持つという [ADR 0162](0162-calling-emet-functions-from-gm.md) の決めごとに従う。組み込みの `plain` は、`Lang` の中の文字を、`CharStyle` と同じく返す。golem-emet の仕様書の型の表も改める。
- ABI の変更である。v0.1.0-rc3 の ABI のバージョンは 7、今の main は 8 で、8 はまだどのリリースにも含まれていないので、バージョンは 8 のままである（[docs/adr/0052](0052-plugin-abi-version-bump-rule.md)）。
- 題を写す箇所（目次の項目、`[ref-title]` の写し、柱）は、言語の区間を残す。索引の印とチャネルの項目を除く今の規則（[docs/adr/0145](0145-title-copies-drop-anchor-inlines.md)）は、言語の区間の中にも及ぶ。

ブロックの言語は、ブロックの欄にする（「メンテナーが決めること」の 8）。

```
block = [span, label: tstr / null, lang: tstr / null, body: block-body]   ; lang: docs/adr ADR 0187
```

- Haskell の `Block` に `blockLang :: !(Maybe Text)` を足す（[`IR.hs`](https://github.com/tett23/golem/blob/50b9fca8a0744f6f9d92808db231e6c04ac35d2c/modules/golem-doc/src/Golem/Doc/IR.hs#L91-L96)）。
- 本体の形の `@lang` は、評価器が本体の最上位のブロックの一つずつに `blockLang` を書く。本体をまとめるブロックは作らない。IR には、属性の形と本体の形の違いが残らない。ブロックが自分の `@lang` を持てば、そちらを書く。
- `Golem.Doc.Validate` は、`blockLang` が BCP 47 の形であることを検査する。プラグインの出力の誤りは G06009 とする。
- プラグインの SDK の `Block`（[`ir.rs`](https://github.com/tett23/golem/blob/50b9fca8a0744f6f9d92808db231e6c04ac35d2c/plugins/golem-plugin-sdk/src/ir.rs#L141-L146)）に `lang: Option<String>` を足し、CBOR の読み書きを改める。
- Emet の `Block` の型（[`Builtins.hs`](https://github.com/tett23/golem/blob/50b9fca8a0744f6f9d92808db231e6c04ac35d2c/modules/golem-emet/src/Golem/Emet/Builtins.hs#L125-L141)）は変えない。ブロックの言語は、ブロックのラベルと同じく、値の外で運ぶ（[`Golem.Emet.IR`](https://github.com/tett23/golem/blob/50b9fca8a0744f6f9d92808db231e6c04ac35d2c/modules/golem-emet/src/Golem/Emet/IR.hs#L1-L14)）。関数が作ったブロックは言語を持たず、外のブロックの言語を受け継ぐ。
- 見出しの題を写すとき、見出しのブロックの言語は、写した題の全体を包む言語の区間にする。目次の項目と `[ref-title]` の写しの言語が、見出しと同じになる。
- ABI の変更である。インラインの言語の区間と同じく、バージョンは 8 のままである。

### 区間の言語の決め方

ある文字の言語は、それを含む最も内側の `[lang]` のタグとする。
`[lang]` の中になければ、それを含む最も内側の、`blockLang` を持つブロックのタグとする。
どちらもなければ、その文字には区間の言語がない（以下、区間の外と呼ぶ）。
以下の「区間」は、`[lang]` の区間と、`@lang` を付けたブロックの中の両方を指す。
区間の言語が「和文」か「欧文」かは、主の副タグ（最初の `-` の前を英小文字にしたもの）が `ja` かどうかで決める。
番号と題のあいだの区切りと同じ判定である。

中国語と韓国語の区間（`zh`、`ko`）は、v0.1.0-rc4 では欧文の区間と同じに扱い、それぞれの組版の規則は v1.x で扱う（「メンテナーが決めること」の 3）。
この ADR の実装で、ロードマップの v1.x に次の項目を足す。

> - **中国語と韓国語の組版**：`[lang]` と `@lang` で `zh` と `ko` を指定した部分は、欧文と同じに扱う（[ADR 0187](adr/0187-inline-language-switch.md)）。両用の文字は欧文の語に含め、漢字とハングルは和文の文字クラスで組むので、どちらの言語の規則にもなっていない。その部分に、中国語（簡体字と繁体字）と韓国語の組版の規則（約物の幅と配置、禁則、字間、ハングルの語間の空白と改行の位置）を当てる。拠る文書（W3C の clreq と klreq）と、本の言語が `zh` か `ko` の本をどこまで組めるようにするかを、ADR で決める。ハングルの音節の箱の単位は、v2 以降の「箱の単位と書記素クラスタの食い違い」と合わせて扱う。

### PDF の和欧の扱い

両用の文字の一覧を一つに決め、golem-layout の一つの関数にまとめて持つ（「メンテナーが決めること」の 2）。

```
‘ ’ “ ” « » ‹ › — – ‐ ‑ …
```

区間の言語による扱いは次のとおりである。

- **欧文の区間**：両用の文字は、つねに欧文（`western`）とし、隣の欧文の文字と一つの語の箱にする。欧文のフォントで組み、和欧間の空きもアキ量のセットの空きも入れない。突き出し（`protrusion`）は、今の欧文の約物の量の表に従う（表にない `«»‹›…` は突き出さない）。
- **和文の区間**：両用の文字は、つねに和文の文字クラスの一字とする（`“‘«‹` は始め括弧類、`”’»›` は終わり括弧類、`—…` は分離禁止文字、`–‐‑` はハイフン類）。隣が欧文の文字でも、欧文の語に含めない。和文のフォントで組む。
- **区間の外**：今のとおり、最も近い文字で決める。本の言語は見ない。今の本の出力を変えないためである。

両用の文字でない文字の扱いは、区間の言語で変えない。
欧文の区間の中の仮名と漢字は和文の一字として組み、和文の区間の中のラテン文字は欧文の語として組む。
文字の種類そのものを言語で変えると、どちらのフォントにも字形のない文字を組むことになるからである。

`‹›` は、区間の外では今のとおり漢字等のまま組む。
文字クラスの表に足すと、区間の外の出力が変わるからである。

区間の境目は、文字スタイルの境目と同じく、語の箱の境目になる。
欧文の区間の中の語と外の語のあいだに空白がなければ、二つの語の箱が空きなしで並ぶ。

### 分綴

v0.1.0-rc4 では、分綴のパターンは今のとおり英語のパターン一つだけである。
言語の区間の中の欧文の語は、次のように分綴する（「メンテナーが決めること」の 4）。

- 主の副タグが `en` の区間：英語のパターンで分綴する。
- そのほかの言語の区間：パターンで分綴しない。語に書いたハイフンとダッシュでの改行（[golem-layout ADR 0008](../golem-layout/adr/0008-explicit-hyphens.md)）は今のとおり行う。
- 区間の外：今のとおり英語のパターンで分綴する。

v1.0.0 の「本の中の別の言語の分綴」が使えるように、次の形にする。

- golem-layout の `Look` に、区間の言語（`Maybe Text`、区間の外は `Nothing`）を足す。言語の区間は、文字スタイルと同じく `Look` を変えるだけで、語の箱の作り方に入る。
- 語の箱を分綴するときのパターンは、`ComposeEnv` の一つのパターン（`cePatterns`）でなく、言語からパターンを引く関数で決める。v0.1.0-rc4 のこの関数は、`en` と区間の外で英語のパターンを返し、ほかの言語で `Nothing`（分綴しない）を返す。
- v1.0.0 では、この関数にパターンを足すだけで、区間の言語での分綴になる。

### 支援技術への言語の情報

支援技術が読める形で言語の情報を出すことは、落とせない要件とする（「決めたことの記録」の 2026-11-07）。
本は、すべての人のためのものだからである。
スクリーンリーダーは、言語の情報で読み上げの音声と規則を切り替える。
そのため、HTML と EPUB にはいつも `lang` と `xml:lang` を書き、PDF にも言語の情報を書く。
言語の情報を出力から落とす箇所を作らない。

### HTML と EPUB

言語の区間を `<span lang="<タグ>" xml:lang="<タグ>">` で書く（「メンテナーが決めること」の 5）。

- HTML の出力は XHTML なので、根の `html` の要素と同じく、`lang` と `xml:lang` の両方を書く。
- 区間の言語が本の言語と同じでも書く。原稿に書いたことを、そのまま出力に残す。
- `blockLang` を持つブロックは、そのブロックを表す最も外側の要素（`p`、`h1` から `h6`、`ul`、`ol`、`dl`、`table`、コードブロックと図版の要素）に、`lang` と `xml:lang` を書く。本体の形の `@lang` は、本体のブロックの一つずつに書く。本体を包む要素は作らない。
- 本文の `@toc` の項目は題をインラインの要素のまま書くので、区間を残す。
- HTML の目次のページ（`index.xhtml`）と EPUB のナビゲーション文書は、今は題を文字列にして書き（[`Html.hs`](https://github.com/tett23/golem/blob/50b9fca8a0744f6f9d92808db231e6c04ac35d2c/modules/golem-html/src/Golem/Html.hs#L1153)、[`Epub.hs`](https://github.com/tett23/golem/blob/50b9fca8a0744f6f9d92808db231e6c04ac35d2c/modules/golem-epub/src/Golem/Epub.hs#L131)）、インラインの要素を落とす。この二つでも、言語の区間だけは `<span lang xml:lang>` で残す。文字スタイルなど、ほかのインラインの要素は今のとおり落とす。
- 両用の文字の扱い（和文の全角の括弧か、欧文の引用符か）は、ブラウザーとフォントに任せる。`lang` があれば、ブラウザーは区間の言語のフォントを選べる。

### PDF の言語の情報

PDF には、タグ付き PDF の構造の要素の `/Lang` で、言語を書く（[ADR 0183](0183-tagged-pdf-and-pdf-a.md)）。

- `[lang]` の区間は、構造の要素 `Span` に `/Lang` を付けて書く。
- `blockLang` を持つブロックは、そのブロックの構造の要素（`P`、`H1` から `H6`、`L`、`Table` など）に `/Lang` を付ける。
- 区間の外の文字は、カタログの `/Lang`（本の言語）で決まる。
- `/Lang` の値は、原稿に書いたタグのままとする。

ADR は番号の順に実装するので、この ADR を実装するときには、[ADR 0183](0183-tagged-pdf-and-pdf-a.md) の構造の木がある。
この ADR の実装で、IR の言語の区間から構造の要素 `Span` を作り、`blockLang` をブロックの構造の要素の `/Lang` に書く。
[ADR 0183](0183-tagged-pdf-and-pdf-a.md) の構造の木の作り方（IR の要素から構造の要素への対応）に、この二つを足す形である。

### プレーンテキスト

区間の中の文字をそのまま書き出す。

### 引用符の文字

原稿に書いた引用符の文字は変えない。
`[lang fr: "Bonjour"]` の `"` を `«` や `“` に置き換えることはしない（「メンテナーが決めること」の 6）。
言語の区間が変えるのは、PDF の組み方と HTML と EPUB の属性だけである。

### LSP と構文の定義

- 補完のインラインのコマンドの名前に `lang` を足す。
- tree-sitter と TextMate の文法は、インラインのコマンドを名前によらず読むので、変えない（実装で確かめる）。

### ドキュメント

- 仕様書に「原稿の中の言語」の節を足し、区間の言語の決め方、両用の文字の一覧と扱い、分綴、HTML と EPUB の属性を書く。和欧の扱いの節（欧文の単語の箱）と分綴の節から、この節を指す。
- [docs/markup.md](../markup.md) のインラインのコマンドの一覧に `[lang]` を、ブロックコマンドの一覧と「ブロックへの属性」の節に `@lang` を足す。
- IR の CDDL（`modules/golem-doc/schema/golem-doc.cddl`）と、仕様書のプラグインの ABI の節に、言語の区間を足す。
- [docs/diagnostics.md](../diagnostics.md) に G02131 と G02132 を足す。
- 使い手のマニュアルに、`[lang]` と `@lang` の使い方と、区間の外は今のとおりであることを書く。
- ロードマップの v1.x に、「区間の言語の決め方」の節に書いた「中国語と韓国語の組版」の項目を足す。
- ロードマップの v1.0.0 の「本の中の別の言語の分綴」を、この ADR の区間と、言語からパターンを引く関数を使うと書き換える。

## 実装しないこと

- 章のファイルごとの言語（`chapters` の項目の `language`）。ファイルの全体は、本体の形の `@lang` で包める。
- 区間の外の文字を、本の言語で決めること。
- 英語のほかの分綴のパターン（v1.0.0 の「本の中の別の言語の分綴」）。
- 引用符の文字を言語に合わせて置き換えること。
- 中国語と韓国語の組版の規則（区間を欧文と同じに扱う）。v1.x で扱う。
- 言語のタグを IANA の登録簿で検査すること。
- `manifest.toml` の `language` の形を検査すること。今の本が組めなくなりうるので、別の ADR にする。ロードマップに項目を足すことを提案する。
- 本体の形の `@lang` の本体を包むブロック（HTML の `div` など）。
- 正規表現スタイルで言語の区間を作ること。

## テスト設計

テストを先に書き、今の実装で失敗することを確かめてから実装する。

golem-parser と golem-eval のテストでは、次のことを確かめる。

- `[lang en: text]` が IR の言語の区間（タグ `en`）になること。今は未知のインラインのコマンド（G02022）になるので失敗する。
- `[lang: x]`、`[lang en fr: x]` が G02131、`[lang e_n: x]`、`[lang 123: x]`、`[lang en-: x]` が G02132 になること。`[lang en-US: x]`、`[lang zh-Hant-TW: x]`、`[lang "de-CH-1996": x]` が通ること。
- `[lang en]` と `[lang en: a | b]` が G02038 になること。
- 入れ子の `[lang en: a [lang fr: b] c]` が、外の区間の中に内の区間を持つ IR になること。
- 見出しの中の `[lang]` が見出しの題に残り、`[ref-title]` の写しにも残ること。
- 属性の形の `@lang en` が、次の段落、見出し、リスト、表、コードブロック、図版の `blockLang` になること。リストに付けたとき、項目の中のブロックは `blockLang` を持たず、外のリストの言語を受け継ぐこと。
- 本体の形の `@lang en` が、本体の最上位のすべてのブロックの `blockLang` になり、本体の中で `@lang de` を付けたブロックだけが `de` になること。本体の中の見出しも通ること。本体の中の `@page-break` が G02059 になること。
- `@lang` の後にブロックがなければ G02010、`@lang` と `@lang en fr` が G02131、`@lang e_n` が G02132 になること。
- `@lang en` を付けた見出しの題が、目次の項目と `[ref-title]` の写しで、`en` の言語の区間に包まれること。

golem-doc のテストでは、`Validate` が形の誤ったタグの言語の区間と `blockLang` を拒むことと、CBOR の往復で言語の区間と `blockLang` が変わらないことを確かめる。
プラグインの SDK のテストでは、`Block` の `lang` が同じバイト列と往復することを確かめる。
golem-emet のテストでは、関数に渡して返したブロックが `blockLang` を保ち、関数が作ったブロックが `blockLang` を持たないことを確かめる。

golem-layout のテストでは、次のことを確かめる。

- 和文の本文の中の `[lang en: “東京”]` の `“` と `”` が欧文の語の箱（欧文の役割）になり、区間の外の `“東京”` は今のとおり和文の括弧の箱になること。
- `[lang ja: “Hello”]` の `“` と `”` が和文の始め括弧類と終わり括弧類の箱になり、`Hello` は欧文の語の箱のままであること。
- `[lang en: wait… what]` の `…` が `wait…` の語に含まれ、和欧間の空きが入らないこと。区間の外の `wait… what` は今のとおりであること。
- `[lang fr: « Bonjour »]` の `«` と `»` が欧文の箱になること。
- `@lang en` を付けた和文の段落の中の `“東京”` が、`[lang en: “東京”]` と同じ箱になること。その段落の中の `[lang ja: “東京”]` は和文の括弧の箱になること。
- `[lang fr: proverbe]` がパターンで分けられず、`[lang en: proverbe]` と区間の外の `proverbe` は今のとおり分けられること。`[lang fr: porte-monnaie]` は `porte-` の後ろで分けられること。
- 言語からパターンを引く関数が、`en`、`en-GB`、`Nothing` で英語のパターンを、`fr` と `ja` で `Nothing` を返すこと。

golem-html と golem-epub のテストでは、次のことを確かめる。

- `[lang fr: x]` が `<span lang="fr" xml:lang="fr">x</span>` になり、本文の `@toc` の項目、目次のページ、ナビゲーション文書の項目にも残ること。今の目次のページとナビゲーション文書は区間を落とすので失敗する。目次のページとナビゲーション文書で、文字スタイルは今のとおり落ちること。
- `@lang en` を付けた段落、見出し、リスト、表が、`<p lang="en" xml:lang="en">` のように、最も外側の要素に属性を持つこと。本体の形の `@lang` が、本体のブロックの一つずつに属性を書き、包む要素を作らないこと。
- EPUB の出力が epubcheck を通ること。

golem-driver のテストでは、次のことを確かめる。

- `[lang]` と `@lang` を使わない fixture の PDF、HTML、EPUB、プレーンテキストの出力のバイト列が変わらないこと。決定性の検査の期待値で確かめる。
- PDF の構造の木で、`[lang fr: x]` が `/Lang (fr)` を持つ `Span` になり、`@lang en` を付けた段落の `P` と、リストの `L` が `/Lang (en)` を持つこと。[ADR 0183](0183-tagged-pdf-and-pdf-a.md) の構造の木を文字にしたゴールデンで確かめる。
- `[lang]` と `@lang` を含む fixture の PDF が、[ADR 0183](0183-tagged-pdf-and-pdf-a.md) の CI の veraPDF の検査（PDF/UA-1）を通ること。

見た目の回帰テストでは、両用の文字を区間の中と外で組んだページを fixture に加え、参照の画像で、引用符の幅、和欧間の空き、分綴を目で確かめてから参照を固定する。

## トレードオフ

区間の外の文字は今のとおり最も近い文字で決めるので、`[lang]` を書かない原稿の出力は変わらない。
その代わり、英語の本の中の `“東京”` のような原稿は、書き手が `[lang en: ...]` で包むまで今の組み方のままである。
本の言語で区間の外を決める案は、「メンテナーが決めること」の 3 に挙げる。

両用の文字の一覧は固定する。
一覧にない文字（`―`、`‥`、`・` など）は、区間の言語によらず今の文字クラスのまま組む。
一覧を広げると、区間の中の組み方が変わる。

`‹›` は区間の外では漢字等のまま組むので、区間の外で `‹›` を使う原稿の組み方は直らない。

欧文の区間で英語のほかの言語の分綴を止めるので、`[lang fr: ...]` の中の長い語は、v1.0.0 でフランス語のパターンが入るまで、行の伸び縮みだけで吸収することになる。
英語のパターンで誤って分けるより、分けないほうがよいと考えた。

本体の形の `@lang` は、本体のブロックの一つずつに言語を書くので、HTML の出力に本体のまとまりが残らない。
引用の全体を一つの要素として装飾したいときは、段落スタイルを使う。
その代わり、IR のブロックの入れ子が増えず、見出しを本体に置いても目次と番号の扱いが変わらない。

ブロックの言語を IR のブロックの欄にしたので、ブロックを読むプラグインはすべて、新しい欄を読むよう作り直すことになる。
ABI のバージョン 8 はまだリリースに含まれていないので、この変更で配った ABI を壊すことはない。

## 決めたことの記録

- **原稿の中の言語の切り替え**（ロードマップ）：原稿の一部の言語を指定する記法を加え、引用符と和欧の扱いを、その部分の言語で切り替えられるようにする。その部分の言語で分綴することは、v1.0.0 の「本の中の別の言語の分綴」で扱う。
- **分綴に使えるように作ること**（2026-11-06、ADR の作成の依頼）：v1.0.0 で分綴を言語の区間で切り替えられるように設計する。
- **ブロックの言語の指定**（2026-11-07、メンテナー）：ブロックの言語を指定する機能を入れる。インラインの記法だけで段落の全体を包むのは、手間が大きすぎる。草稿が退けた `@lang` を、`[lang]` に加えて入れる。
- **中国語と韓国語**（2026-11-07、メンテナー）：中国語と韓国語の組版は v1.x で扱う。
- **支援技術**（2026-11-07、メンテナー）：支援技術への対応は落とせない仕様である。本はすべての人のためにある。HTML と EPUB にはいつも `lang` と `xml:lang` を書き、PDF にも言語の情報を届ける。
- **ほかの項目**（2026-11-07、メンテナー）：「メンテナーが決めること」の 2、4、5、6 を推奨のとおりとし、3 の区間の外の扱いも推奨のとおりとした。
- **ブロックの `@lang` の形と IR**（2026-11-07、メンテナー）：問題ないとした。「メンテナーが決めること」の 7 と 8 を推奨のとおりとした。

## メンテナーが決めること

すべて決めた（「決めたことの記録」）。
7 と 8 は、ブロックの言語を指定する機能を入れるという決定を受けて加えた。

1. **記法**：決めた。インラインのコマンド `[lang <タグ>: 散文]` に加えて、ブロックコマンド `@lang <タグ>` を入れる。文字スタイルの欄 `language` にする案と、`[en: ...]` のようにタグをコマンドの名前にする案は、草稿のとおり退けた。前者は、言語が見た目でなく内容の属性であり、`[style]` の名前を見ても言語が分からない。後者は、コマンドの名前の規則と衝突し、プラグインのコマンドと名前を取り合う。
2. **両用の文字の一覧**：決めた。`‘ ’ “ ” « » ‹ › — – ‐ ‑ …` の 13 字とする。
3. **区間の外と、中国語と韓国語**：決めた。区間の外は今のとおり最も近い文字で決める。`zh` と `ko` の区間は、v0.1.0-rc4 では欧文と同じに扱い、それぞれの組版の規則はロードマップの v1.x の「中国語と韓国語の組版」で扱う。
4. **v0.1.0-rc4 の分綴**：決めた。`en` の区間と区間の外は英語のパターンで分綴し、ほかの言語の区間ではパターンで分綴しない。
5. **HTML と EPUB の属性**：決めた。`lang` と `xml:lang` を、区間の言語が本の言語と同じでも書く。支援技術についての決定により、目次のページと EPUB のナビゲーション文書でも、言語の区間を落とさない。
6. **引用符の文字**：決めた。原稿の文字を置き換えない。
7. **`@lang` の形と本体に置けるもの**：決めた。`@style` と同じく属性の形と本体の形の両方を持ち、本体にはどの種類のブロックも置けるようにする（「ブロックの `@lang`」）。
   退けた案は三つある。
   属性の形だけにする案は、何段落も続く引用の一つずつに `@lang` を書かせ、手間が大きいという決定の理由に戻る。
   本体に段落だけを置ける（`@style` と同じ）案は、引用の中のリストや表を指定できない。
   言語を段落スタイルの欄にする案は、言語ごとに段落スタイルを作らせ、`@style` と `@lang` の両方を一つの段落に付けられなくなる。
8. **IR でのブロックの言語の表し方**：決めた。ブロックの欄（`block = [span, label, lang, body]`）にし、本体の形の `@lang` は評価器が本体のブロックの一つずつに書く。
   退けた案は二つある。
   言語を持つブロックを新しい種類のブロック（`[14, lang, [* block]]` のように中にブロックを並べるもの）にする案は、本体の中の見出しが文書の最上位からはずれ、目次、見出しの番号、改ページの規則、ブロックを読むプラグインのすべてが、入れ子の中を探すことになる。
   欄を配列の最後（`[span, label, body, lang]`）に置く案は、どちらでも ABI の形は変わり、利点がない。属性（ラベルと言語）を本体の前にまとめるほうが読みやすい。
