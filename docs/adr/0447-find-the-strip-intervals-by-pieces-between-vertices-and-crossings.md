# ADR 0447: 行の帯の内側の区間は、頂点と辺の交点で分けた部分ごとに求める

Status: superseded [{"part":"テスト設計","by":[],"kind":"note","note":"メンテナーは 2026-11-25 に、頂点が 3 から 6 の多角形をすべて列挙する代わりに、頂点の数ごとに全体から均等に選んだ 40 個で確かめることを認めた。列挙を速くするのは別の課題とする。"}]

## 文脈

[root ADR 0437](0437-paths-and-the-box-model.md) は、閉じたパスのボックスに文字を流すとき、各行の帯について、帯の幅の全体にわたって内側にある区間を求めると決めた（「閉じたパスの内側に文字を置く」の手順 3）。
求め方として、帯の両端の線と、帯の中にある折れ線の頂点を通る線のそれぞれで内側の区間を求め、それらの共通部分を取ると書いている。
その理由として、折れ線の辺は直線なので、内側の区間の端はこれらの線のあいだで線形に動く、と書いている。

ところが、この求め方は、帯を斜めに横切る細い切れ込みを見落とす。
切れ込みの頂点が帯の外にあれば、調べる線は帯の両端の二本だけになる。
切れ込みが帯の中で自分の幅より大きく横にずれると、二本の線のどちらでも内側に見える区間を、二本の線のあいだで切れ込みが通る。
共通部分はその区間を内側に残し、そこに置いた字は形の外にはみ出す。
これは 0437 の I2（どの字の仮想ボディの矩形も折れ線の内側にある）と食い違う。
PR #1144 の実装はこの点で手順 3 から離れたので、この ADR で求め方を決め直す。

0437 は、ボックスに中身が収まらないときのエラーのコードを実装のときに決めるとしている。
ただし、今の本の組版には、ボックスに文字を流すところがまだ無い。
そのため、このコードを決める時期も、この ADR で決め直す。

この ADR では、横組みの座標で書く。
行を並べる向きを y、行の向きを x とする。
縦組みでは、x と y を入れ替えて読む。

## 調査した事項

PR #1144（ブランチ `impl-0437`、[f568efddc](https://github.com/tett23/golem/commit/f568efddcf19cf0e1ca1df851ad4c7e7182ed1ed)）で、次のことを確かめた。

- 内側の判定は、ボックスの塗りの規則（nonzero か even-odd）で、辺の上の点を内側と数える（[Polygon.hs#L94](https://github.com/tett23/golem/blob/f568efddcf19cf0e1ca1df851ad4c7e7182ed1ed/modules/golem-geometry/src/Golem/Geometry/Polygon.hs#L94)）。
- `stripInside` を `cabal repl golem-geometry` で呼んだ結果は、次のとおりである。
  - 頂点がすべて帯の外（y = −10 と 20）にある斜めの切れ込み `[(0,-10),(10,-10),(10,20),(8,20),(2,-10),(1,-10),(7,20),(0,20)]` と帯 0 から 10 で `[(0,3),(6,10)]`。
    帯の両端の線の内側の共通部分は `[0,3]`、`[4,5]`、`[6,10]` で、0437 の求め方では、切れ込みが帯の中で通る `[4,5]` が内側に残る。
  - 帯の端に頂点のある V 字の切れ込み `[(0,0),(10,0),(10,10),(6,10),(0,5),(5,10),(0,10)]` と帯 0 から 10 で `[(0,0),(6,10)]`。
  - 二つの辺が帯の中で交わる蝶ネクタイ形 `[(0,0),(10,10),(10,0),(0,10)]` と帯 4 から 6 で、nonzero でも even-odd でも `[(0,4),(6,10)]`。
  - 高さ 0 の帯（y0 = y1）では `[]`。
- 実装は、帯を、帯の中にある頂点の y と、辺どうしの交点の y で部分に分ける（[Polygon.hs#L151-L153](https://github.com/tett23/golem/blob/f568efddcf19cf0e1ca1df851ad4c7e7182ed1ed/modules/golem-geometry/src/Golem/Geometry/Polygon.hs#L151-L153)）。
  各部分では、部分の中央の y で隣り合う二つの辺の組ごとに、塗りの規則で外側の隙間を、左の辺の部分の両端での x の小さいほうから、右の辺の両端での x の大きいほうまで除く（[Polygon.hs#L164-L177](https://github.com/tett23/golem/blob/f568efddcf19cf0e1ca1df851ad4c7e7182ed1ed/modules/golem-geometry/src/Golem/Geometry/Polygon.hs#L164-L177)）。
  水平な辺は、隙間を作る辺から除く（[Polygon.hs#L136](https://github.com/tett23/golem/blob/f568efddcf19cf0e1ca1df851ad4c7e7182ed1ed/modules/golem-geometry/src/Golem/Geometry/Polygon.hs#L136)）。
- `cabal test golem-geometry` は 29 件がすべて通った。
- ボックスに中身が収まらないことを表す `BoxOverflow` は、golem-layout の `flowInBox` の結果（[BoxModel.hs#L173-L188](https://github.com/tett23/golem/blob/f568efddcf19cf0e1ca1df851ad4c7e7182ed1ed/modules/golem-layout/src/Golem/Layout/BoxModel.hs#L173-L188)）とそのテストにだけ現れ、G のコードを割り当てていない。
  本の組版からボックスに文字を流す経路は、まだ無い。

## 実装すること

### 行の帯の内側の区間

高さが正の各行の帯（y0 < y1）について、帯の幅の全体にわたって内側にある区間を、次のように求める。

1. 帯を、帯の中にある折れ線の頂点の y と、帯の中で交わる二つの辺の交点の y で、部分に分ける。
2. 各部分で、部分の中央の y を横切る辺を x の順に並べ、隣り合う二つの辺のあいだの隙間のうち、ボックスの塗りの規則で外側のものを求める。
   その隙間について、左の辺の部分の両端での x の小さいほうから、右の辺の部分の両端での x の大きいほうまで（両端を含まない）を除く。
   片側に辺が無い隙間は、その側へ限りなく除く。
3. すべての部分で除いた残りの共通部分を、帯の全体で内側にある区間とする。
4. 区間の端は、0437 のとおり、内側に向けて sp に丸める。

部分の中では頂点が無く、辺の順も変わらないので、隙間ごとの回転数は部分の全体で一定である。
辺は直線なので、部分の中で隙間が通る範囲は、隙間の左右の辺の部分の両端での x で決まる。
水平な辺は部分の境目の線の上にあり、辺の上の点は内側と数えるので、隙間を作らない。

0437 の手順 4 から 6（区間の選び方、区間の無い帯の扱い、行分けへの渡し方）は変えない。

### ボックスからあふれるときのエラーのコード

ボックスに中身が収まらないときのエラーのコードは、[root ADR 0438](0438-place-text-frames-anywhere-on-a-page.md) のテキストフレームの実装で、0438 の diagnostic の表の、フレームの中身が形に収まらない行のコードとして決める。
それまでは、0437 の I5 の「エラー」を、golem-layout の `flowInBox` が返す `Left BoxOverflow` で満たし、利用者に見える diagnostic は出さない。

## 実装しないこと

0437 の不変条件と境界の表は変えない。
行の帯の幅と並べ方、曲線を折れ線に直す方法は変えない。

## 不変条件

内側は、ボックスの塗りの規則で、辺の上の点を含めて数える。

- I1: 高さが正のどの帯と閉じた折れ線についても、求めた区間（丸めの前と後のどちらでも）のどの点 x も、帯のどの y でも内側にある。
- I2: 高さが正のどの帯と閉じた折れ線についても、帯のすべての y で内側にある x は、丸めの前の区間のどれかに入る。
- I3: 結果は、帯の両端の線と帯の中の頂点を通る線のそれぞれの内側の区間の共通部分に含まれる。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 正方形 `(0,0)-(10,10)` と帯 2 から 4 | `[(0,10)]` | I1, I2, I3 |
| 頂点がすべて帯の外にある斜めの切れ込み（調査した事項の形）と帯 0 から 10 | `[(0,3),(6,10)]` | I1, I2, I3 |
| 帯の端に頂点のある V 字の切れ込み（調査した事項の形）と帯 0 から 10 | `[(0,0),(6,10)]` | I1, I2 |
| 蝶ネクタイ形と帯 4 から 6、nonzero と even-odd | どちらも `[(0,4),(6,10)]` | I1, I2 |
| 帯の中に凹んだ頂点のある星形 | 頂点で狭まった区間 | I1, I2, I3 |
| 帯の中にある水平な辺 | 辺の上は内側で、隙間を作らない | I1, I2 |
| 同じ向きに回る穴を持つ形 | nonzero では穴も内側、even-odd では外側 | I1, I2 |
| 交点が帯の端の線の上にある形 | 交点で部分に分けない | I1, I2 |
| 頂点の一点だけで帯に触れる形 | 長さ 0 の区間か、区間なし | I1, I2 |
| 空の折れ線 | 区間なし | I1, I2 |

## 受けいれ条件

なし。
不変条件のテストで足りるためである。

## テスト設計

root ADR 0447 I1 から I3 を名前の先頭に置いたテストを、golem-geometry の `RegionSpec.hs` に足す。
I1 から I3 は、0 から 10 の整数の格子の上の、頂点が 3 から 6 の多角形と、整数の端を持つ帯を列挙する。
I1 は、標本の y を、帯の両端と、帯の中の頂点と交点の y と、各部分の中点に取り、区間の点が内側かを調べる。
I2 は、結果に無い各 x について、外側になる y が標本にあることを調べる向きで確かめる。
実装はもうあるので、I1 のテストが 0437 の線の共通部分の求め方では落ちることを、その求め方をテストの中で写して確かめる。
今ある切れ込みのテストは、この ADR の I1, I2 の名前に付け直す。

## トレードオフ

部分に分けるので、頂点と交点の多い形では計算が増える。
その代わりに、帯の全体で内側にある区間を厳密に求められ、字が形の外にはみ出さない。

エラーのコードを後に回すので、0437 だけでは、ボックスからあふれたことを利用者に知らせる手段が無い。
ただし、0438 までは、ボックスに文字を流す経路そのものが無い。
