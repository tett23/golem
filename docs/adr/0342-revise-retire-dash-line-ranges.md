# ADR 0342: 行の範囲を三つのピリオドで区切る

ステータス: 採択

## 文脈

本案は [Golem ADR 0316](0316-retire-dash-line-ranges.md) の決定とテスト設計を改める。

`@listing` の `lines` とコードブロックの `highlight` は、整数の行番号と両端を含む範囲を読む。
`1-2` と `1...2` は現行の `lines` でともに成功し、前者だけに G02108 が付く。

## 調査した事項

[試作のテスト](../../experiments/syntax/test.mjs) を `node --test experiments/syntax/test.mjs` で動かす。
[現行 CLI との照合](../../experiments/syntax/cli.mjs) は `node experiments/syntax/cli.mjs /path/to/golem` で再現する。
CLI の比較には Golem のコミット `0a8d21a0` をビルドして使った。
[実行結果](../../experiments/syntax/cli.log) に、旧記法の notice と、移行後の入力での終了コードを記録した。
Haskell の評価器も変更し、実際に原稿をパースして評価した。
[評価器のテスト](../../experiments/syntax/Sources.hs) は三つの提案を合わせて 14 通りを検査する。
変更前は 6 通り、変更後は [14 通りすべて](../../experiments/syntax/sources-green.log) が期待したコードに一致した。
再現コマンドは `sh experiments/syntax/sources.sh` である。

試作は評価器へ渡したアセットの参照の結果と意味論 IR のブロック数を記録した。

`highlight` に旧記法がある例はエラーが一つ、コードブロックが一つだった。

## 実装すること

範囲を読む共通の関数で、旧区切りを認識した引数に G02251 を一つ出す。
範囲の両端をそのまま残し、区切りを `...` に変えるよう案内する。
式が返した文字列にも同じ判定を適用する。
掲載と強調の両方で、カンマ区切りの行番号と範囲を受け取る。
カンマの後の空白を許す。
空白を含む引数は `lines="1...3, 5...7"` のように引用する。
掲載は指定順に各範囲の行を取り出す。
強調は各範囲の行を対象とする。
語と文字列の負号付きの端は行指定の構文解析でエラーにする。
式や変数の結果は評価した後、各端に正整数を要求する。
ゼロと負値では対象の処理を失敗させる。
一般の式で使う範囲の負の端には影響しない。

旧記法を廃止する最初のリリースは v1.0.0 とする。
v1.0.0 より前のプレリリースでは従来の notice を出す。
rc4 のタグには G02108 が notice として登録されている。
旧コードを廃止し、G02251 をエラーとして登録する。
旧コードを `silence-notices` に書いた設定は G03024 になるので、リリースノートに削除手順を載せる。

## 実装しないこと

原稿や設定ファイルをビルド中に書き換える機能は扱わない。

## 不変条件

1. 新しい区切りと単一行番号では今回のエラーを出さない。
2. 一つの有効な項目列に旧区切りが一つ以上あれば、引数全体に G02251 を一つだけ出す。
3. 構文と項目数が有効で旧区切りを一つ使った同じ入力に対し、予告済みの rc4 は G02108 の notice、v1.0.0 は対応する新コードのエラーを出す。
4. 廃止したコードだけを `silence-notices` に書いた有効な本は、rc4 では設定を受理し、v1.0.0 では G03024 になる。

| リリースをまたいで比較する入力 | rc4 | v1.0.0 |
| --- | --- | --- |
| `@listing a.txt lines=1-2` | G02108 の notice | G02251 のエラー |
| 旧コードを抑止する設定だけ | 設定を受理 | G03024 |

以下は v1.0.0 の入力例である。

| 入力 | 結果 |
| --- | --- |
| `1`、`1...1` | 現行と同じ |
| `1-2` | G02251 が一つ |
| `highlight=1-2,4-5` | G02251 が一つ |
| `lines=1-2,4-5` | G02251 が一つ |
| `3--1` | 負の端の構文エラー |
| `1...3, 5...7` | 1〜3 行目と 5〜7 行目 |
| `1.,.3, 5..,7`、`5..7` | 構文エラー |
| `lines=[= n]` で n が 0 または -1 | 評価後にエラー |

## テスト設計

不変条件 3 と 4 は、rc4 タグの CLI と v1.0.0 として配布する候補の CLI に同じ fixture を渡し、重大度、コード、終了コードを各列と照合する。
抑止設定は旧コードごとに独立した入力を使う。
各テスト名に対応する不変条件の番号を入れる。
不変条件 1 と 2 の番号をテスト名に含め、表の各入力でコード、位置、件数を照合する。
採択後は引数の正確な位置、式が返した文字列、各ターゲットの出力を検査する。
`--no-notices` を指定しても新しいエラーによってビルドは失敗することを確かめる。

## トレードオフ

字面を一律に置換すると負の端の符号まで変わる。
引数を構文解析してから置き換えるべき区切りと両端を示せば、この誤りを避けられる。
