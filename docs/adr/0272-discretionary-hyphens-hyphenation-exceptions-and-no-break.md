# ADR 0272: 任意ハイフン、分綴の例外、分離禁止

ステータス: 採択

## 文脈

### 書き手が語の分け方を直す手段がない

欧文の本では、パターンの分綴が誤った位置で語を分けることがある。
Golem の書き手には、それを原稿か設定で直す手段がない。
[2026-10-17 の調査](../audits/2026-10-17-latex-gap-for-v1.md) の 17 は、次の三つを v1.0.0 で埋める不足とした。

- 語を分けてよい位置を原稿で指定すること（InDesign の任意ハイフン、LaTeX の `\-`）。
- 本ごとの分綴の例外の一覧（InDesign の文書の中の辞書、LaTeX の `\hyphenation`）。採択のときに、原稿のファイルごとの一覧も加えた。
- 改行しない文字の範囲（InDesign の文字パネルの分離禁止、LaTeX の `\mbox` と `~`）。

調査の「所有者の決定」は、この項目を v1.0.0 に置いた。
[ロードマップ](../roadmap.md) の v1.0.0 の「LaTeX との差を埋める項目」の「任意ハイフン、分綴の例外、分離禁止」がそれであり、v1.x の「行分割の拡張」から、ソフトハイフン（U+00AD）と原稿で分割の位置を指定する記法を先に取り出すと書いている。
和文の本でも、欧文の名前や型番を行末で分けたくない場面がある。

この ADR は、同じ時期の ADR（[ADR 0260](0260-front-matter-folios-and-page-labels.md) から 0271）のどれにも依らない。
同じ時期の ADR の順では最後に実装する。

### U+00AD の今の扱い

原稿の U+00AD は、今は特別に扱われていない。
この節の観察は、2026-11-09 に `golem new` の雛形（Noto Serif JP）の本文を `これは in­com­pre­hen­si­bil­ity と­いう語。­extraordinarily` にして（`­` は U+00AD）、インストールされた golem 0.1.0-rc4 で組んだ結果である。

- 構文と評価は U+00AD をほかの字と同じく本文の文字列に残す。HTML とプレーンテキストの出力には、U+00AD がそのまま入っていた。
- PDF の行分割では、U+00AD は欧文の字である。`charClass` は U+00A0 から U+024F を欧文（`Western`）にする（[`CharClass.hs` の 78 行](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-layout/src/Golem/Layout/CharClass.hs#L78)）。そのため、U+00AD は前後の欧文の字と一つの語になる。
- 欧文の語の分綴は、要素の最初の字（一般カテゴリが L の字）から、次の字でない文字の前までをパターンに渡す（[`wordItems`](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-layout/src/Golem/Layout/Japanese.hs#L1089-L1150)、[docs/adr/0222](0222-line-breaking-points-the-invariants-did-not-decide.md)）。U+00AD は一般カテゴリが Cf なので、`in­com­pre…` では最初の `in` だけがパターンに渡り、語の全体が一つの箱になる。U+00AD は分割の候補にならないうえに、パターンの分綴まで止めている。
- U+00AD の後の明示のハイフンの候補もない。`explicitParts` が分けるのは `-‐–—` の後だけである（[`Japanese.hs` の 1219 行から 1233 行](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-layout/src/Golem/Layout/Japanese.hs#L1219-L1233)）。
- 和文の字のあいだの U+00AD（`と­いう`）は、それだけで一つの欧文の語になる。組んだ PDF では、`と` と U+00AD のあいだが 5.46pt 空いていた。和欧間の空きか両端揃えの伸びかは、この観察では切り分けていない。
- PDF の内容のストリームでは、U+00AD は HarfBuzz の既定の無視する字（Default_Ignorable_Code_Point）として、送りが 0 の空白の字形（CID 1）で描かれていた。ToUnicode は CID 1 を U+00AD に対応させており、抜き出した文字列に U+00AD が残る。空白の字形を別の場所で空白として使えば、同じ字形が二つの文字列に当たる。

### 分割禁止ハイフン（U+2011）はすでに扱われている

U+2011 の後は、明示のハイフンの候補にしない（[仕様書の「行分割」](../specifications.md#行分割)、[golem-layout ADR 0008](../golem-layout/adr/0008-explicit-hyphens.md)）。
U+2011 を含む要素は、パターンでも分綴しない（`isHyphenCharacter` は U+2011 を含む。[`CharClass.hs` の 104 行から 111 行](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-layout/src/Golem/Layout/CharClass.hs#L104-L111)）。
InDesign の分割禁止ハイフンにあたる文字は、書き手が U+2011 を書けば今でも働く。
InDesign が分割禁止ハイフンを含む語のほかの位置で分綴するかは確かめていない。
この ADR は U+2011 の扱いを変えない。

### 分綴の例外の仕組みはある

`Golem.Layout.Hyphenation` は、ハイフンで分けた語（`ta-ble`）の例外の一覧を持てる（[`withExceptions` と `hyphenPoints`](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-layout/src/Golem/Layout/Hyphenation.hs#L39-L53)）。
例外は小文字にした語で引き、見つかればパターンを使わずにその位置で分ける。
ハイフンのない語は分綴しない。
例外の位置には、前に 2 字、後に 3 字を残す規則（`patLeftMin`、`patRightMin`）を当てない。
同梱の en-US の例外（hyph-utf8 の `hyph-en-us.hyp.txt`、14 語）は、コンパイルのときに埋め込む（[`EnUs.hs`](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-layout/src/Golem/Layout/Hyphenation/EnUs.hs#L18-L37)）。
`withExceptions` は例外の表を置き換えるので、同梱の例外に本の例外を足すには、合わせる関数が要る。

パターンは、語の言語から `patternsFor` で引く（[`Languages.hs`](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-layout/src/Golem/Layout/Hyphenation/Languages.hs#L16-L25)、[ADR 0187](0187-inline-language-switch.md)）。
主の副タグが `en` の区間と区間の外は en-US のパターンで、ほかの言語の区間はパターンを持たない。
v1.0.0 の「本の中の別の言語の分綴」が、ほかの言語のパターンを足す。
例外の一覧も言語ごとに持たないと、その項目の後で英語の例外がフランス語の語に当たる。

### 改行しない範囲

`[aki]` の前後では改行しないが、文字の範囲を改行しないものにする手段はない。
InDesign の文字パネルの分離禁止は、文字の属性として範囲の中の改行を禁じる。
この語は JLReq の分離禁止文字（cl-08、`—` や `…`）と同じ字面だが、指すものが違う。
混同を避けるため、仕様書と原稿の名前では「改行しない範囲」と呼び、InDesign の分離禁止にあたると書き添える。

v1.0.0 の「語句の泣き別れの禁止」は、書き手が分けない範囲を指定する記法を、この項目の文字スタイルと一つにすると書いている。
範囲の指定の手段はこの ADR で決め、その項目は自動の規則（数と単位など）を決める。

範囲が行長より長いとき、範囲を守れば行がはみ出す。
今の行分割は、収まる分割の候補がない場合に限り、はみ出す行を作り、`golem build` は G07105 の警告で報告する（[docs/adr/0210](0210-warn-overfull-lines-in-build.md)）。
長い語や禁則で分けられない並びも、同じ G07105 で報告している。
改行しない範囲は書き手が付けた属性なので、直し方が違う（範囲を短くするか、範囲を外す）。

## 実装すること

### 1. ソフトハイフン（U+00AD）

原稿の U+00AD を**ソフトハイフン**と呼ぶ。
PDF の行分割で、ソフトハイフンを次のように扱う。

- ソフトハイフンは字の箱を作らない。行分割の項目を作る前に本文の文字列から取り除き、位置を覚えておく。文字の分類、和欧間の空き、アキ量のセットの空き、語の区切りは、ソフトハイフンがないものとして決める。`と­いう` は `という` と同じに組む。
- 取り除いた位置の前の字と後の字が、同じ欧文の語の要素の中で、どちらも字（一般カテゴリが L。結合文字は前の字に含めて数える）なら、そこを**ソフトハイフンの候補**とする。続けて書いたソフトハイフンは一つとして扱う。
- ソフトハイフンの候補は、行末にハイフンを描く罰点とする。幅は `-` の送り、罰則はパターンの分綴と同じ 50 で、一回目の段階から使う（TeX の `\-` が `\hyphenpenalty` の任意の分割を一回目の段階から置くのと同じ）。連続するハイフンの罰点と、突き出し（[golem-layout ADR 0014](../golem-layout/adr/0014-protrusion-amount.md)）はパターンの分綴と同じに当てる。前に 2 字、後に 3 字を残す規則は当てない。
- ソフトハイフンを一つでも含む要素は、パターンでも例外の一覧でも分綴しない。要素の最初の字より前にあるソフトハイフン（`­table`、`“­table”`）は候補にならないので、その要素を分けないという指定になる。InDesign の、語の頭の任意ハイフンでその語を分けない振る舞いにあたる（調査の 17 が引いた InDesign のヘルプの抜粋による）。
- 明示のハイフンで分けた要素ごとに、この規則を当てる（[docs/adr/0179](0179-lines-ending-in-explicit-hyphens.md)）。`co-op­er­ate` は `co-` の後と、`op­er­ate` のソフトハイフンの位置で分けられる。
- `explicit-hyphen-penalty` が 10000 でも、ソフトハイフンの候補は置く。
- ソフトハイフンの候補でないソフトハイフンは、語の頭のものを除き、notice で報告する（5 の G07123 と G07124）。前後の字が字でないもの（`a­.`、語の終わりのもの、和文の字のあいだのもの）は G07123、改行しない文字（コード、`url` の文字、リンクの語、4 の改行しない範囲）の中のものは G07124 とする。どちらも出力は同じで、ソフトハイフンを描かない。

PDF の描き方は次のとおりとする。

- ソフトハイフンの字形は描かない。ToUnicode にも ActualText にも U+00AD を書かない。分けなかった語の抜き出した文字列は、ソフトハイフンのない語になる。
- ソフトハイフンの候補で分けた行の行末には、パターンの分綴と同じく `-` の字形を描く。抜き出した文字列も、パターンの分綴と同じになる。
- カーニングと字の幅は、ソフトハイフンで分けた部分のあいだを、パターンの分綴で分けた部分のあいだと同じに扱う。
- `pages.json` の位置（[docs/adr/0195](0195-page-start-positions-of-pdf.md)）は、取り除く前の原稿の文字の位置で数える。

ほかの媒体では次のとおりとする。

- HTML と EPUB は、U+00AD をそのまま書く。HTML は `hyphens` に `auto` を書いていないので、閲覧環境はソフトハイフンの位置でだけ分綴する。コードの文字スタイルには `hyphens: none` があるので（[`Html.hs` の 1079 行](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-html/src/Golem/Html.hs#L1079)）、閲覧環境はそこで分けない。リンクの中のソフトハイフンでは閲覧環境が分けうるので、PDF と違う。
- プレーンテキストは、今のとおり U+00AD をそのまま書く。プレーンテキストは行を折り返さないので、ソフトハイフンは表示を変えない。

### 2. ソフトハイフンの記法 `[shy]`

組み込みのインラインのコマンド `[shy]` を足す（「メンテナーが決めること」の 1）。
`[shy]` は、評価で U+00AD の一字の文字列になる。
U+00AD はエディタで見えないので、原稿で見える記法を用意する。
原稿に U+00AD をじかに書いても、`[shy]` と同じに扱う。

- `[shy]` は引数を取らない。位置引数かキーワード引数を書けば G02152 とし、`[shy]` を出力しない。
- 散文スロットを書けば、ほかのスロットを取らないコマンドと同じく G02038 とする（`takesNoSlot`）。
- `shy` は、プラグインが上書きできない組み込みのコマンド（`FixedBuiltin`）とする（[`Builtin.hs`](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-eval/src/Golem/Eval/Builtin.hs#L45-L58)、[docs/adr/0027](0027-exhaustive-command-dispatch-by-types.md)）。プラグインと `.gm` の関数は、この名前のコマンドを持てなくなる。
- 意味論 IR とプラグインの ABI は変わらない。`[shy]` は IR の文字列の中の U+00AD になるからである。
- `\-` は今は `-` のエスケープであり（行頭の `-` に使う）、意味を変えると今の原稿が変わるので使わない。

### 3. 分綴の例外の一覧

`style.toml` の `[composition.hyphenation-exceptions]` に、言語ごとの例外の一覧を書けるようにする（「メンテナーが決めること」の 2）。

```toml
[composition.hyphenation-exceptions]
en = ["ta-ble", "pro-ject", "Golem"]
fr = ["ma-nu-scrit"]
```

- キーは BCP 47 の言語のタグ、値は文字列の配列である。文字列は、分けてよい位置に `-`（U+002D）を書いた語である。`-` のない語は分綴しない。
- 語に書ける字は、字（一般カテゴリが L）と `-` だけである。ほかの字があれば G03127 とする。`-` が語の端にあるか、二つ続けば G03128 とする。
- キーが BCP 47 の形でなければ G03126 とする。形だけを検査し、IANA の登録簿は見ない（`[lang]` の G02132 と同じ `isLanguageTag`）。
- 大文字と小文字だけが違うキーが二つあれば、G03130 とする。
- 同じキーの中で、小文字にして `-` を除いた語が同じものが二つあれば、`-` の位置が同じでも違っても G03129 とする。
- 値が配列でないか、文字列でない要素があれば、ほかの `style.toml` の値の誤りと同じく G03006 とする。
- これらはエラーであり、`style.toml` のほかの誤りと同じく、ビルドを止める。

例外を引く規則は次のとおりとする。

- 語の言語は、パターンを引く言語と同じものとする。区間の中の語は区間のタグ、区間の外の語は区間の外に当てるパターンのタグ（今は `en-US`）である。「本の中の別の言語の分綴」が区間の外の扱いを変えれば、例外もそれに従う。
- タグは RFC 4647 の lookup で引く。小文字にした語の言語のタグで探し、なければ最後の副タグを一つずつ外して探す。`en-GB` の区間の語は `en-gb`、`en` の順に探す。`en-US` だけを書いた本では、`en` の区間の語に例外は当たらない。
- 例外は、パターンに渡すのと同じ字の並び（要素の最初の字から、次の字でない文字の前まで、結合文字を除く）を小文字にして引く。小文字にするのは今の `hyphenPoints` と同じ `T.toLower` である。
- 見つかれば、パターンの代わりにその位置で分ける。前に 2 字、後に 3 字を残す規則は当てない（今の同梱の例外と同じ。「メンテナーが決めること」の 3）。
- 本の例外は、同じ語の同梱の例外を置き換え、ほかの同梱の例外は残す。
- パターンを持たない言語（今は `en` のほかのすべて）の例外も当てる。一覧にある語だけを分綴し、ほかの語はパターンで分綴しない。
- 例外による候補は、パターンの分綴の候補と同じ罰点とし、二回目の段階から使う。TeX の `\hyphenation` の語が分綴の試みの中で使われるのと同じである。
- ソフトハイフンを含む要素には、例外を当てない（1 のとおり）。

`style.toml` の一覧は本ごとの一覧であり、InDesign の文書の中の辞書にあたる。
`@style-def` では書けない。
ファイルごとの一覧は、下の「ファイルごとの例外の一覧」に書く。

#### ファイルごとの例外の一覧

複数の著者の原稿をまとめた本では、原稿ごとに分綴の規則を変える必要が出る（2026-11-09 の tett23 の決定）。
著者ごとに語の分け方の流儀が違い、ある著者の原稿にだけ当てたい例外がある。
そこで、本の一覧に加えて、原稿のファイルごとに例外の一覧を書けるようにする（「メンテナーが決めること」の 7）。

ファイルの一覧は、ファイルの設定（[docs/adr/0014](0014-in-file-settings.md)、docs/markup.md の「ファイルの設定」）の新しいコマンド `@hyphenation-exceptions` で書く。

```
@hyphenation-exceptions en ta-ble pro-ject Golem
@hyphenation-exceptions fr ma-nu-scrit
```

- 最初の位置引数は言語のタグ、二つ目からの位置引数は例外の語である。どちらも語か文字列リテラルで書く。語と言語のタグの規則と誤りは、`style.toml` の一覧と同じである（G03126、G03127、G03128、G03129）。
- 一つのファイルに、言語ごとに一行を書く。大文字と小文字を除いて同じ言語のタグの行が二つあれば、`style.toml` の大文字と小文字だけが違うキーと同じく G03130 とする。一つの言語の語は一行に並べる。
- 置き場所は `@manifest` と `@style-def` と同じく、ファイルの設定の並びの中である。ほかの場所に書けば G02049 とする。
- 引数の誤りは、ファイルの設定のほかのコマンドと同じ原因ごとのコードとする。位置引数が二つより少なければ G02052、本体は G02097、展開する引数は G02114、語と文字列のほかで書いた値は G02116 である。キーワード引数を書けば G02153 とする。
- 誤りのある語は、その語だけを捨てる。言語のタグの誤りと G03130 では、その行の全体を捨てる。どれもエラーなので、ビルドは止まる。
- `hyphenation-exceptions` は組み込みのブロックコマンドの名前になり、プラグインと `.gm` の関数はこの名前のコマンドを持てなくなる。

ファイルの一覧は、`@manifest` と `@style-def` と同じく、そのファイルにだけ適用される。
`@import` したファイルにも、そのファイルを `@import` するファイルにも及ばない。
語の段落を出したブロックのあるファイル（`@import` で取り込んだブロックは、取り込まれたファイル）の一覧を当てる。
注の本文とキャプションは、それを書いたファイルの一覧を当てる。
Golem が作る行（目次、索引、柱、参考文献の一覧、章末の注の見出し）には、ファイルの一覧を当てず、本の一覧だけを当てる。

例外は、次の順で引き、最初に見つかったものを使う（「メンテナーが決めること」の 8）。

1. 語を出したファイルの一覧。語の言語のタグで、そのファイルの一覧のキーを RFC 4647 の lookup で引く。
2. `style.toml` の本の一覧。同じく本の一覧のキーを lookup で引く。
3. 同梱の例外。
4. パターン。

二つの一覧は、それぞれのキーで別々に lookup する。
ファイルの一覧に `en` の行があり、本の一覧に `en-US` のキーがある本では、`en-US` の区間の語を、まずファイルの `en` で引き、なければ本の `en-US` で引く。
ファイルの一覧の語は、本の一覧の同じ語（小文字にして `-` を除いて等しい語）を置き換え、本の一覧のほかの語は残す。
ほかの規則（残す字の数の規則を当てないこと、パターンを持たない言語にも当てること、二回目の段階から使うこと、ソフトハイフンを含む要素に当てないこと）は、本の一覧と同じである。

HTML と EPUB は、自動の分綴をしないので、例外の一覧を読まない。
プレーンテキストも読まない。

### 4. 改行しない範囲

文字スタイルに `no-break` の欄（真偽値）を足す（「メンテナーが決めること」の 4）。
InDesign の文字パネルの分離禁止にあたる。
組み込みの文字スタイル `no-break`（`no-break = true` だけを持つ）を足し、原稿では `[style no-break: 100 円]` と書く。
組み込みの文字スタイルの数は、この時期の [ADR 0264](0264-paragraph-styles-for-toc-entries.md) と [ADR 0269](0269-superscript-and-subscript.md) も足すので、実装の順で決まる。
仕様書には、実装したときの数を書く。

PDF の行分割では、行の箱の見た目（`Look`）に `lkNoBreak` を足し、次のように扱う。

- **範囲の中の候補**：分割の候補の前の最も近い字と、後の最も近い字が、どちらも `lkNoBreak` の字であるとき、その候補を範囲の中の候補とする。範囲の中の候補は置かない。和文の字のあいだ、語間の空白、明示のハイフンの後、パターンと例外の分綴、ソフトハイフン、ルビの親文字のあいだ、コードの改行の位置のすべてに当てる。
- 範囲の端の候補（範囲の最後の字と範囲の外の次の字のあいだなど）は、今のとおりの規則で決める。
- 範囲は、候補を消すだけである。箱の幅、グルーの伸び縮み、和欧間の空き、アキ量のセットの空き、禁則、突き出し、字幅の伸縮は変えない。範囲の中の語間の空白は、改行しないまま伸び縮みする。
- 強制改行（行末の `\`）は、範囲の中でも改行する。書き手が明示した改行だからである。
- 入れ子にした文字スタイルの `no-break` は、`code` と同じく、どれか一つが真なら真とする（[`Fonts.hs` の 449 行](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-typeset/src/Golem/Typeset/Fonts.hs#L449)）。内側に `no-break = false` を書いても、外側の範囲は解けない。
- 表のセルの最小の幅は、範囲を分けられない並びとして数える（`cellExtent` は無限の罰点で分けないので、変える必要はない）。

範囲が行に収まらないとき、範囲を分けず、はみ出す行を作る。
はみ出しの量を測る位置（行の箱を行頭から見て、終わりが行長を超える最初の箱）が範囲の中の箱なら、その行を G07105 ではなく G07122 の警告で報告する（「メンテナーが決めること」の 5）。
重大度、位置、量の書き方、dev と prod の扱い、`golem check` と LSP で出さないことは G07105 と同じとする。
`golem preflight` の `overfull-lines`（G09013）は、今のとおり、はみ出したすべての行を報告する。

HTML と EPUB では、文字スタイルの規則（`.cs-<名前>`）に `white-space: nowrap` を書く。
強制改行の `br` は `nowrap` の中でも改行するので、PDF と同じになる。
プレーンテキストは行を折り返さないので、この欄を読まない。

## 実装しないこと

- **U+2011 の扱いを変えること**：今のとおり、後ろで改行せず、含む要素を分綴しない。
- **行末のハイフンを ToUnicode で U+00AD にすること**：パターンの分綴とソフトハイフンで分けた行末のハイフンは、今のパターンの分綴と同じく `-` として抜き出す。抜き出した文字列から行末のハイフンを見分けられるようにするかは、別の ADR で決める。
- **ソフトハイフンの罰則を設定にすること**：TeX の `\hyphenpenalty` にあたる欄は作らず、パターンの分綴と同じ 50 に固定する。
- **本の一覧の語を外す書き方**：ファイルの一覧で、本の一覧の語を外してパターンに戻す書き方は作らない。ファイルの一覧に同じ語を、パターンと同じ位置か `-` のない形で書けば、本の一覧の語を置き換えられる。
- **マニフェストの章の項目の一覧**：例外の一覧は、章の項目には書けない。原稿のファイルに書く（「メンテナーが決めること」の 7）。
- **利用者の辞書をプロジェクトの外に置くこと**：InDesign のユーザー辞書のように複数の本で共有する一覧は作らない。共有するなら `style.toml` を写す。
- **ほかの言語のパターン**：v1.0.0 の「本の中の別の言語の分綴」で扱う。
- **語句の泣き別れの自動の規則**：数と単位などをどの規則で分けないかは、「語句の泣き別れの禁止」で決める。
- **U+200B と U+2060 の扱い**：改行してよい位置と改行しない位置を表すほかの書式の文字は、この ADR では決めない。
- **索引の語と正規表現スタイルからソフトハイフンを除くこと**：IR の文字列に U+00AD が残るので、`[index]` の語や正規表現スタイルはソフトハイフンを含む文字列を見る。除くかは、要るときに別の ADR で決める。
- **HTML でリンクの中のソフトハイフンを止めること**：閲覧環境の分綴は、ブラウザの検査を緩く保つ方針のとおり、致命的な崩れでない限り PDF に合わせない。

## 不変条件

段落の入力を、字の並び、各字の `Look`（`lkNoBreak`、`lkCode`、`lkUrl`、`lkLink`、`lkLang`）、ソフトハイフンの位置、例外の表とする。
行は、行分割の出力の `Paragraph` の行とする。

- **I1 ソフトハイフンは字にならない**：どの行のどの箱の文字列にも、U+00AD は含まれない。すべての行の字をつないだ文字列は、入力から U+00AD と語間の空白を除いたものに等しい（[docs/adr/0209](0209-line-breaking-invariants-by-exhaustive-small-inputs.md) の L1 を、U+00AD を除いた入力で読む）。
- **I2 欧文の語の中で分ける位置**：欧文の語の中で行を分ける位置は、パターンか例外の分綴の罰点、明示のハイフンとダッシュの直後の罰点、ソフトハイフンの候補の罰点のどれかである（L8 を広げたもの）。
- **I3 ソフトハイフンの候補**：ソフトハイフンの罰点は、取り除いた位置の前の字と後の字が同じ要素の字（一般カテゴリが L）である位置にちょうど一つずつあり、幅は `-` の送り、罰則は 50 で、改行しない範囲の外であり、`lkCode`、`lkUrl`、`lkLink` のどれも真でない。ソフトハイフンで分けた行は行末にハイフンの幅を持ち、`brPass` が 1 の行でも分けられる（L9 を広げたもの）。
- **I4 ソフトハイフンを含む要素は分綴しない**：U+00AD を一つでも含む要素には、パターンと例外の分綴の罰点がない。
- **I5 例外の位置**：小文字にした字の並びが例外の一覧の語に一致する要素では、パターンと例外の分綴の罰点の位置の集まりが、一覧の語の `-` の位置の集まりにちょうど等しい。`-` のない語では空である。
- **I6 例外の言語**：語の言語のタグで lookup して当たったキーの一覧だけを当てる。当たるキーがなければ、分綴の罰点の位置は例外の一覧を空にした入力と同じである。
- **I7 範囲の中で分けない**：行の境の前の最も近い字と後の最も近い字が、どちらも `lkNoBreak` の字であるのは、その境が強制改行のときに限る。
- **I8 範囲は候補を消すだけ**：`lkNoBreak` をすべて偽にした入力の項目の並びから、範囲の中の候補を無限の罰点に置き換えたものが、もとの入力の項目の並びに等しい（箱、グルー、罰点の幅と伸縮が同じ）。
- **I9 はみ出しの報告は行ごとに一つ**：はみ出したどの行にも、G07105 か G07122 のどちらか一つだけを出す。G07122 になるのは、はみ出しを測る位置の箱が `lkNoBreak` の箱であるときに限る。
- **I10 同じ IR**：`[shy]` と原稿にじかに書いた U+00AD は、同じ IR の文字列になる。HTML、EPUB、プレーンテキストの出力は、どちらで書いても同じバイト列になる。
- **I11 例外の一覧の検査**：どの `[composition.hyphenation-exceptions]` の値と、どのファイルの `@hyphenation-exceptions` の並びについても、誤りのある語とキーのそれぞれに、5 の表のコードがちょうど一つ出る。一つの語に二つの誤りがあれば、G03127、G03128、G03129 の順で最初のものだけを出す。誤りがなければ、どのコードも出ない。
- **I12 ファイルの一覧が先**：ファイル f のブロックから出た語の要素 e について、f の一覧の lookup で当たったキーの一覧に e があれば、分綴の罰点の位置はその語の `-` の位置にちょうど等しい。なければ、分綴の罰点の位置は、f の一覧を空にした入力と同じである。
- **I13 ファイルの一覧はそのファイルにだけ適用される**：ファイル f の `@hyphenation-exceptions` を変えても、f のほかのファイルのブロックから出た段落と、Golem が作る行の、行分割の項目の並びは変わらない。

境界の入力：

| 量 | 調べる値 |
| --- | --- |
| U+00AD の前の要素の字の数 | 0（語の頭）、1、2、3 |
| U+00AD の後の要素の字の数 | 0（語の終わり）、1、2、3 |
| 続けて書いた U+00AD | 1、2 |
| U+00AD の隣 | 字、明示のハイフン、句読点、空白、和文の字 |
| ソフトハイフンで分けた前の部分の幅 | 行長よりハイフンの幅だけ短い、ちょうど行長、行長より 1sp 長い |
| 改行しない範囲の字の数 | 0、1、2、行長にちょうど収まる数、一字あふれる数 |
| 範囲の中身 | 和文だけ、欧文の語だけ、語間の空白を含む、ソフトハイフンを含む、強制改行を含む |
| 範囲の位置 | 段落の先頭、行の境にかかる、段落の末尾、二つの範囲が隣り合う |
| 例外の語 | `-` なし、一つ、二つ、`a-b`（前に 1 字）、大文字を含む |
| 例外の誤り | 空の文字列、`-`、`a-`、`-a`、`a--b`、数字を含む、同じ語の二度目 |
| 例外のキー | `en`、`en-US`、`EN` と `en`、`fr`（パターンなし）、形の誤り |
| 一覧の置き場所 | 本だけ、ファイルだけ、両方に同じ語で違う位置、両方に違う語、ファイルの `en` と本の `en-US` |
| ファイルの一覧の及ぶ範囲 | 書いたファイル、`@import` したファイル、`@import` するファイル、目次と柱に出る見出し |
| `@hyphenation-exceptions` の引数 | 言語だけ、言語と語一つ、キーワード引数、本体、展開、ファイルの設定の外 |

## テスト設計

テストを先に書き、今の実装で失敗することを確かめてから実装する。
テストの名前には、不変条件の番号を入れる。

### 行分割の列挙（golem-layout のテスト）

- `LineBreakEnum` の欧文の部分（`latinParts`）に、U+00AD の一字を足す。`table`、`a`、`hyphenation` などの部分と並べると、語の頭、語の中、語の終わり、和文の字のあいだのソフトハイフンが、小さい入力として出る。部分が一つ増えると列挙は増えるが、正確さを時間より優先する方針のとおり、上限の段は変えず、時間を測って [docs/adr/0208](0208-widen-lightweight-formal-methods.md) の予算を超えるときだけ上限を見直す。
- `LineBreakInvariants` の L1、L8、L9 の述語を、I1、I2、I3 のとおりに広げる。I4 の述語を足す。
- 改行しない範囲の列挙 `NoBreakEnum` を新しく作る。部分の並びのそれぞれの部分に、範囲の中か外かを割り当て、要素の数の段で列挙する。行長は 2 から 5 字とする。I7 と I8 の述語を足し、すべての入力で確かめる。
- 回帰：今の実装では、`in­com­pre­hen­si­bil­ity` が一つの箱になり（I2 と I3 の違反）、`と­いう` の U+00AD が箱になる（I1 の違反）ことを、述語が違反として返すこと。

### 分綴（golem-layout のテスト）

- I5：例外を重ねた `Patterns` で、例外の語はその位置で、`-` のない語は分けず、一覧にない語はパターンのとおりに分けること。同梱の en-US の例外の一つを本の例外で置き換え、ほかの 13 語が残ること。
- I6：`en-GB` の語が `en` のキーに当たり、`en` の語が `en-US` だけのキーに当たらないこと。区間の外の語が `en` のキーに当たること。`fr` のキーの例外が、パターンを持たない `fr` の区間の語に当たること。
- I12：境界の表の「一覧の置き場所」のすべてで、ファイルの一覧、本の一覧、同梱の例外、パターンの順に引くこと。
- 例外の語を小文字にして、結合文字を除いた字の並びで引くこと（`Table` が `ta-ble` に当たる）。

### 描画とテキストの層（golem-typeset と golem-driver のテスト）

- ソフトハイフンで分けた行の行末に `-` の字形を描き、分けなかった語の内容のストリームに U+00AD の字形がなく、ToUnicode に U+00AD がないこと。
- `pages.json` の位置が、取り除く前の原稿の文字の位置で数えたものであること。
- I9：範囲の中の箱ではみ出す行に G07122 が一つ、範囲の外の箱ではみ出す行に G07105 が一つ出ること。両方が一つの段落にある入力で、行ごとに一つずつ出ること。
- G07123 と G07124 が、5 に書いた位置にそれぞれ一つ出ること。語の頭のソフトハイフンでは出ないこと。

### 評価とプロジェクト（golem-eval と golem-project のテスト）

- I10：`[shy]` と U+00AD をじかに書いた原稿の IR が等しいこと。`[shy x]` で G02152、`[shy: a]` で G02038 になること。
- I11：境界の表の例外の誤りのそれぞれで、`style.toml` とファイルの一覧の両方について、コードがちょうど一つ出ること。誤りのない一覧では、コードが出ないこと。
- `@hyphenation-exceptions` の引数：境界の表の六つの入力で、G02052、G02153、G02097、G02114、G02049 がそれぞれ一つ出ること。言語と語一つの行は誤りにならないこと。
- I13：二つのファイルと `@import` したファイルの本で、一つのファイルの一覧だけを変えたとき、ほかのファイルの段落と目次と柱の行分割の項目の並びが変わらないこと（golem-driver のテスト）。
- 組み込みの文字スタイル `no-break` が、`style.toml` に書かなくても使え、利用者が同じ名前の表を書けば書いたキーだけを上書きすること。

### HTML（golem-html のテスト）

- 文字スタイル `no-break` の規則に `white-space: nowrap` があること。U+00AD が出力にそのまま残ること。

## トレードオフ

ソフトハイフンを箱から取り除くと、PDF から抜き出した文字列は原稿と一字違う。
原稿の字を変えないという今の規則（ToUnicode と ActualText で原稿の文字列に戻す）からは外れる。
その代わり、PDF の中の語を検索でき、空白の字形を U+00AD と取り違えることがない。
U+00AD は表示しない書式の文字であり、抜き出した文字列で語を見つけられるほうが読み手の役に立つ。

ソフトハイフンを含む要素をパターンで分綴しないので、書き手が一か所だけ指定した長い語は、ほかの位置で分けられない。
InDesign が任意ハイフンを含む語のほかの位置で分綴するかは、確かめていない。
Golem では、書き手が指定した位置だけで分けるほうが、書き手の意図に沿うと判断した。
U+2011 を含む要素を分綴しない今の規則とも合う。

例外の一覧に前に 2 字、後に 3 字を残す規則を当てないので、`a-ble` と書けば 1 字で分ける。
書き手が明示した位置を守るためである。
TeX は例外の語にもこの規則を当てるように読めるが、この ADR を書くときに TeX で確かめてはいない。
実装のときに TeX で確かめ、違えば [TeX と InDesign との差異](../differences-from-tex-and-indesign.md) に書く。

例外を、パターンに渡す字の並び（結合文字を除く）で引くので、原稿が分解した形（`e` と U+0301）で書いた語と、一覧に合成済みの字（`é`）で書いた語は一致しない。
一覧の検査は結合文字を字でないものとして拒むので、一覧の側では分解した形を書けない。
正規化をするかは、分解した形の原稿が問題になってから決める。

改行しない範囲が行に収まらないとき、範囲を守ってはみ出す行を作る。
範囲の中で改行すれば版面に収まるが、書き手の指定を黙って破ることになる。
はみ出しを G07122 で知らせ、直すのは書き手に任せる。

ファイルごとの一覧を原稿のファイルに書くので、本の分綴の規則が `style.toml` と原稿のファイルに分かれる。
ある語がどう分かれるかを知るには、`style.toml` と、その語を書いたファイルの先頭の両方を見ることになる。
その代わり、著者の原稿の例外は原稿と一緒に動き、ほかの本に移しても付いてくる。

`[shy]` と `@hyphenation-exceptions` を足すと、プラグインと `.gm` の関数が `shy` と `hyphenation-exceptions` という名前のコマンドを持てなくなる。
1.0.0 の後に足すと互換を壊すので、1.0.0 の前に足す。

HTML ではリンクの中のソフトハイフンで分けうるので、PDF と HTML で分け方が違う。
HTML の行分けはもともと閲覧環境に任せており、PDF と同じ位置で分けることは保証していない。

## メンテナーが決めること

1. **ソフトハイフンの記法**：推奨は、組み込みのコマンド `[shy]` を足し、U+00AD をじかに書くことも受け付けることである。U+00AD はエディタで見えず、原稿の差分でも見えない。HTML の文字参照 `&shy;` と同じ名前なので、Web の書き手に通じる。
   - 退けた案の一つは、U+00AD だけを受け付けることである。原稿でソフトハイフンの有無が見えず、レビューで気付けない。
   - もう一つは、LaTeX と同じ `\-` にすることである。`\-` は今は `-` のエスケープであり、行頭の `-` を書くのに使うので、意味を変えると今の原稿が変わる。
   - もう一つは、`[hyphen]` のような長い名前にすることである。語の中に何度も書くので、短いほうが原稿を読みやすい。
2. **本の例外の一覧の置き場所**：推奨は、`style.toml` の `[composition.hyphenation-exceptions]` である。分綴の設定（`explicit-hyphen-penalty`、`pretolerance`、`tolerance`）が `[composition]` にあり、同じ表で探せる。
   - 退けた案の一つは、最上位の `[hyphenation-exceptions]` である。行分割の設定が二か所に分かれる。
   - もう一つは、プロジェクトの別のファイル（TeX の `.hyp` の形）である。`style.toml` は一つのファイルという今の規則（「`style.toml` の分割」は v1.x）に反する。
   - もう一つは、言語を分けない一つの一覧である。「本の中の別の言語の分綴」の後で、英語の例外がほかの言語の語に当たる。
3. **例外の位置に、残す字の数の規則を当てるか**：推奨は、当てないことである。今の同梱の例外と同じで、書き手が書いた位置を守る。
   - 退けた案は、当てることである。TeX に合うと見込まれるが、書き手が `-` を書いた位置で分けられない理由が一覧からは見えない。
4. **改行しない範囲の指定の手段**：推奨は、文字スタイルの欄 `no-break` と、組み込みの文字スタイル `no-break` である。InDesign の分離禁止が文字の属性であるのと合い、書き手が定義した文字スタイル（人名のスタイルなど）にも付けられる。組み込みのスタイルがあるので、`style.toml` に書かなくても使える。「語句の泣き別れの禁止」も、この手段で範囲を書ける。
   - 退けた案の一つは、組み込みのコマンド `[nobr: ...]` を足すことである。同じことが文字スタイルで書け、書き方が二つになる。
   - もう一つは、組み込みの文字スタイルを足さず、欄だけを足すことである。範囲を指定するたびに `style.toml` に文字スタイルを書くことになり、既定で使えない。
   - もう一つは、組み込みの名前を `nobreak` や `keep-together` にすることである。`style.toml` の欄と同じ kebab-case の `no-break` のほうが、欄の名前と組み込みの名前を一つ覚えれば済む。
5. **範囲が行に収まらないときの報告**：推奨は、はみ出しを測る位置の箱が範囲の中なら G07105 の代わりに G07122 で報告することである。原因（書き手が付けた属性）と直し方が長い語のはみ出しと違うので、一つのコードに一つの原因の原則に従って分ける。
   - 退けた案の一つは、今の G07105 のままにすることである。書き手は、長い語のはみ出しと範囲のはみ出しを、コードで見分けられない。
   - もう一つは、範囲の中で改行して収めることである。書き手の指定を破り、出力を黙って変える。
   - もう一つは、エラーにして PDF を書かないことである。長い語のはみ出しが警告なのと釣り合わず、範囲が一つ長いだけで本が組めなくなる。
6. **候補にならないソフトハイフンの報告**：推奨は、notice の G07123 と G07124 で報告することである。原稿に書いたソフトハイフンが働かないことを、書き手に知らせる。notice なので、`silence-notices` で止められる。
   - 退けた案の一つは、報告しないことである。和文の字のあいだに貼り付けたソフトハイフンに気付けない。
   - もう一つは、一つのコードにまとめることである。前後が字でないことと、改行しない文字の中にあることは、原因も直し方も違う。

7. **ファイルごとの例外の一覧を書く場所**（採択のときに足した）：推奨は、ファイルの設定のコマンド `@hyphenation-exceptions` である。例外は原稿の語の性質であり、著者の原稿と一緒に動く。`@import` で取り込むファイルにも書ける。
   - 退けた案の一つは、マニフェストの章の項目のキー（`{ file = "...", hyphenation-exceptions = { en = [...] } }`）である。本の構成と一緒に見られるが、原稿をほかの本に移すと付いてこず、`@import` で取り込むファイルに書けない。
   - もう一つは、`@style-def` の種類を足すこと（`@style-def hyphenation en ta-ble`）である。`@style-def` はスタイルを定義するコマンドであり、[docs/adr/0014](0014-in-file-settings.md) は `[composition]` をファイルの中で書けない本の全体の設定とした。例外の一覧はスタイルではない。
8. **ファイルの一覧と本の一覧の優先**（採択のときに足した）：推奨は、語ごとにファイルの一覧を先に引き、なければ本の一覧を引くことである。ファイルの一覧が本の規則の例外であり、本の一覧のほかの語は残る。
   - 退けた案は、ファイルの一覧が言語ごとに本の一覧を丸ごと置き換えることである。原稿ごとに違う語だけを書けば済むという使い方に合わない。

## 決めたことの記録

2026-11-09 に、tett23 が次のとおり決めた。

1. ソフトハイフンの記法は、推奨のとおり組み込みのコマンド `[shy]` とし、U+00AD をじかに書くことも受け付ける。
2. 本の例外の一覧は、推奨のとおり `style.toml` の `[composition.hyphenation-exceptions]` に書く。
3. 例外の位置には、推奨のとおり残す字の数の規則を当てない。
4. 改行しない範囲は、推奨のとおり文字スタイルの欄 `no-break` と組み込みの文字スタイル `no-break` で指定する。
5. 改行しない範囲が行に収まらないときは、推奨のとおり G07122 で報告する。
6. 候補にならないソフトハイフンは、推奨のとおり notice の G07123 と G07124 で報告する。
7. ファイルごとの例外の一覧を作れるようにする。tett23 は、複数の著者の原稿をまとめた本を作るとき、原稿ごとにルールを変える必要が出る場合があると述べた。草案は「実装しないこと」でファイルごとの一覧を退けていたので、これを改め、「ファイルごとの例外の一覧」の節、G02153、I11 の拡張、I12、I13、境界の入力、テストを足した。書く場所（ファイルの設定の `@hyphenation-exceptions`）と、本の一覧との優先（語ごとにファイルの一覧が先）は、採択のときの判断であり、「メンテナーが決めること」の 7 と 8 に推奨と退けた案を書いた。
8. diagnostic のコードは、採択のときに、docs/diagnostics.md と origin/main のコードで使われていない番号であり、同じ時期の ADR と重ならないことを確かめて、G02152、G02153、G03126 から G03130、G07122、G07123、G07124 とした。
草案の仮の番号から振り直し、G02153 は採択のときに足した。
