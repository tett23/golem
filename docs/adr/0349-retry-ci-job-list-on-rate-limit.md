# ADR 0349: CI の警告検査でジョブ一覧の利用上限が解除されるのを待つ

ステータス: 採択

## 文脈

CI の集約ジョブ `ci` は、ビルドとテストが出した警告を [Golem ADR 0245](0245-keep-the-warnings-of-ci-at-zero.md) に従って検査する。
検査対象を決める最初の問い合わせは、現在の実行と試行番号を指定して GitHub Actions のジョブ一覧を取得する。
この問い合わせが利用上限に達すると、警告を一件も検査できずに終了する。

## 調査した事項

2026 年 11 月 11 日の [#946 の集約ジョブ](https://github.com/tett23/golem/actions/runs/43004687214/job/130483263186) は、ジョブ一覧の取得で HTTP 403 と `API rate limit exceeded for installation` を受けて失敗した。
[再実行](https://github.com/tett23/golem/actions/runs/43004687214/job/130495594880) では一覧を取得し、changes、scripts-linux、editors のログを検査した。
同日の [#918 の実行](https://github.com/tett23/golem/actions/runs/43004892422) でも、試行 2 の集約ジョブが同じ応答で失敗した。

[Golem ADR 0333](0333-wait-for-ci-artifacts-with-fewer-api-requests.md) は、成果物を待つ処理で受けた利用上限を識別し、再試行時刻を決める方法を定めている。
警告検査は同じ GitHub API からジョブ一覧を得る別の呼び出しである。

## 実装すること

警告検査のジョブ一覧取得にも、[Golem ADR 0333](0333-wait-for-ci-artifacts-with-fewer-api-requests.md) の応答の識別と待ち時間の計算を適用する。
同じ実行、同じ試行番号の一覧を全ページ取得してから、従来の対象ジョブのログを検査する。
途中のページが失敗したら、不完全な一覧を破棄し、対象を重複させずに一覧を取り直す。
一覧取得に使える時間は待機を含めて 60 分とする。
指定された再試行時刻が期限以降であれば再問い合わせをせず、利用上限の理由を残して失敗する。

## 実装しないこと

対象は集約ジョブによるジョブ一覧の取得に限る。
ログ本体のダウンロード、Node.js の選択、警告の許可条件はそれぞれ現在の手順に従う。

## 不変条件

1. I1：一度で取得できた一覧では、現在と同じジョブのログを各一回検査する。
2. I2：利用上限に達した後、指定された待ち時間より前には同じ一覧を要求しない。
3. I3：取得が途中で失敗した一覧の内容を警告検査に渡す件数はゼロである。
4. I4：利用上限を示さない権限エラーか、待機期限への到達で失敗し、以降の問い合わせ回数はゼロである。

| 入力 | 期待する結果 |
| --- | --- |
| 完了した対象ジョブがゼロ、一つ | ゼロなら現在どおり失敗、一つならそのログを一回検査 |
| 二ページ目が利用上限で、待機後に成功 | 完全な一覧にある各ジョブのログを一回検査 |
| 利用上限の HTTP 403 で残り枠がゼロ、解除が 10 秒後 | 11 秒後以降に一覧を再取得 |
| 権限不足の HTTP 403 | 再試行せず失敗 |
| 次に試せる時刻が期限ちょうど、または期限の一秒後 | 再問い合わせをせず失敗 |

## テスト設計

不変条件の番号を名前に含むシェルテストで、時計、待機、API の応答を置き換える。
問い合わせの時刻、実行と試行の識別子、検査したジョブ ID、終了コードを照合する。
二ページ目だけに警告を持つジョブを置き、再取得後も許可していない警告で失敗することを確かめる。

## トレードオフ

待機中は集約ジョブが runner を占有する。
一時的な上限なら同じ試行で警告の検査を終えられ、検査するログを後続の試行で集め直す負担が減る。
