# ADR 0131: 初出の語にルビを振るプラグイン

ステータス: 採択（未実装）

## 文脈

難読語や固有名に、章の最初の出現でだけルビを振る組み方は、一般書でよく使われる。
二度目からは読みを知っているものとして、本文を読みやすく保つためである。
ロードマップの v0.1.0-rc4 は、この処理を見本のプラグインとして作り、語と読みの指定の仕方、章の境の判定、配布の形を ADR で決めるとしている（[docs/roadmap.md](../roadmap.md)）。

このプラグインは、原稿の各所でルビを書く手間を省くためのものである。
語と読みは本ごとに違うので、プラグインに埋め込まず、プロジェクトのデータとして渡す（[docs/adr/0105](0105-plugin-data.md)）。
プラグインは Rust で書き、`plugins/` に置く（[docs/adr/0106](0106-sample-plugins-in-rust.md)）。

### 章の境をフィルタは知らない

「章ごとの最初」を決めるには、章の境が要る。
ところが、フィルタが受け取るのはソースファイル一つ分の文書だけであり、ほかのファイルは見えない（[仕様書の「種類」と「実行の範囲」](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/docs/specifications.md#L2831)、[同 L2847](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/docs/specifications.md#L2847)）。
ホストは、`[[filters]]` に書いたファイルごとにフィルタを呼ぶ（[`applyFilters`](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/modules/golem-driver/src/Golem/Driver/Plugins.hs#L97-L111)）。
要求にあるのは文書とデータだけで、そのファイルが何番めの章か、どの章に属するかは入っていない。

ファイルを章とみなせるのは、マニフェストの `chapters` の項目が一つのファイルのときに限られる。
`chapters` は入れ子の配列を許し、入れ子の配列は全体で一つの章になる（[仕様書の注の番号の範囲](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/docs/specifications.md#L909)）。
一つの章を二つのファイルに分けた本では、二つめのファイルのフィルタは、一つめのファイルに語が出たことを知りえない。

したがって、フィルタだけでは「章ごと」を正しく実装できない。
この ADR は、ファイルを単位にする（「実装すること」）。
入れ子の章では、二つめ以降のファイルの最初の出現にもルビが振られる。
ルビが足りなくなるのではなく、余分に振られる側に外れるので、読み手が読みを失うことはない。

### 試しに実装して分かったこと

この ADR は、採択の前に実装を試した（ブランチ `plugins-ruby`）。
`first-ruby` を作り、`golem build` で四つのターゲットを組んだ。

- **大きさと速度**：wasm は 133699 バイトだった。高野聖（約 160 KB の一章）に五語の TSV を渡して四つのターゲットを組むと 1.85 秒で、プラグインのない同じ本（1.85 秒）と差が出なかった。
- **照合の命令の数**：最初の作りでは、各位置で語の長さごとに文字列を作って辞書を引いた。fixture の原稿のルビから作った 3456 語の TSV で、英文の nightmare-abbey（約 160 KB）を組むと 22.7 億の命令を使い、命令数の上限（10 億）で止まった。語を最初の文字で分けて持ち、その文字の語だけを長い順に比べる作りに直すと、1.2 億になった。直した後は、fixture の十冊と高野聖を四つつないだ章（約 650 KB）のどれでも、7.6 億以下だった（[docs/adr/0124](0124-filter-fuel-by-document-size.md) の表）。
- **ABI の欠け**：なかった。フィルタの要求と応答、データの受け渡しは、[docs/adr/0105](0105-plugin-data.md) のとおりに動いた。
- **出力の位置**：テキストのノードを割ってルビを挟むと、割った断片はどれも元のノードの位置を持つ。ホストの検査（要求に含まれていた位置だけを許す）は、これで通った。
- **データの誤りの重複**：TSV の誤りは、プラグインがフィルタを当てたファイルの数だけ報告される。二つのファイルに当てると、同じ誤りが二度出る。プラグインはファイルごとに独立に呼ばれ、ほかの呼び出しで報告したことを知らないからである。
- **diagnostic の位置**：TSV の誤りは、データのファイルの中の位置を指せない。プラグインは、フィルタを当てたファイルの先頭（`[file, 0, 0]`）を指す。草稿の [docs/adr/0108](0108-plugin-diagnostic-codes-and-spans.md) は、diagnostic の位置を「呼び出しの位置か、要求に含まれていたノードの位置」に限るとしている。フィルタには呼び出しの位置がなく、ファイルの先頭は要求のどのノードの位置でもないので、この草稿のままではフィルタがデータの誤りを報告できなくなる。この問題は、[docs/adr/0108](0108-plugin-diagnostic-codes-and-spans.md) の「フィルタの diagnostic の位置」の節で直す。
- **辿れないブロック**：補助のクレートは、図版とコードのブロックを CBOR の値のまま持つ（[docs/adr/0106](0106-sample-plugins-in-rust.md)）。そのため、図版のキャプションの語にはルビを振れない。

## 実装すること

### プラグインと宣言

見本のプラグイン `first-ruby` を作る。
フィルタ `first-ruby` を一つ持ち、コマンドは持たない。
データ `words` を受け取る。

```toml
[plugins.first-ruby]
url = "https://github.com/tett23/golem/releases/download/v0.1.0-rc4/first-ruby.wasm"
data = { words = "data/words.tsv" }

[[filters]]
plugin = "first-ruby"
filter = "first-ruby"
files = ["chapters/01.gm", "chapters/02.gm"]
```

### 語と読みの TSV

`words` は UTF-8 の TSV であり、一行に語と読みをタブで区切って書く。
ルビの記法（[docs/markup.md の「ルビ」](../markup.md#ルビ)）と同じく、`/` で語と読みを同じ数の区切りに分ける。

```tsv
# 注釈の行
東京	とうきょう
東/京/都	とう/きょう/と
お/父/さん	/とう/
東京都庁	
```

- `/` のない行は、語の全体に一つの読みを振る**グループルビ**になる。
- `/` で区切った行は、区切りごとに読みを振る**モノルビ**になる。読みの区切りを空にすると、その区切りにはルビを振らない（部分ルビ）。
- 読みを空にした行は、ルビを振らない**止めの語**になる。止めの語に一致した部分には、ほかの語が一致しない。`京都` を登録した本で、`東京都庁` の中の `京都` にルビが振られるのを防ぐのに使う。
- 空行と `#` で始まる行は飛ばす。行末の CR は除く。
- 照合に使う語は、`/` を除いた文字列である。語の中に `/` という文字は書けない。

次の行は誤りとし、すべての誤りを行の番号とともに報告する。
一つでも誤りがあれば、文書を書き換えずに返す。

| 誤り | メッセージ |
| --- | --- |
| タブがない | `語と読みをタブで区切った二つの欄がありません` |
| タブが二つ以上ある | `欄が三つ以上あります` |
| 語が空 | `語が空です` |
| 語と読みの区切りの数が違う | `語と読みの / で区切った数が一致しません` |
| 語の区切りが空 | `語の / のあいだが空です` |
| 読みの区切りがすべて空 | `読みのない区切りだけの読みです。ルビを振らない語は読みを空にします` |
| 二度書いた語（`/` を除いて比べる） | `語が重複しています（<最初の行> 行め）: <語>` |

### 照合

テキストのノードを左から読み、各位置で最も長い語を取る。
一致はテキストのノードの中で閉じ、ノードの境をまたがない（`東[bold: 京]` の `東京` には一致しない）。
形態素解析はしないので、語の境は確かめない。
語の一部が別の語の中に現れる誤りは、止めの語で防ぐ。

### 初出の単位と順序

初出の単位は、フィルタを当てたファイル一つとする。
ファイルの中では、文書の順に辿り、ある語に最初に一致した箇所にだけルビを振る。

- 辿る順は、段落、箇条書きの項目、表（見出しの行、次に各行）、定義リストの語と説明である。
- 注と傍注の本文は、注の印の位置で辿る。注の中で最初に出た語は、注の中でルビが振られ、その後の本文では振られない。
- 色と文字スタイルの中は辿る。

次の箇所は書き換えず、出現にも数えない。

- **見出し**：見出しは目次と柱にも写るので、ルビを振らない。見出しで最初に出た語は、本文の最初の出現でルビが振られる。
- **コード**（文字スタイル `code`）：コードの中の文字に読みは振らない。
- **圏点**：圏点の中のルビは、PDF で G07045 になる（[docs/markup.md](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/docs/markup.md#L1145)）。
- 縦中横、数、参照、遅延した式、索引の印、文献の引用、校正の注記、チャネルの項目。
- 図版とコードのブロック（キャプションを含む）。補助のクレートが辿らない。

原稿に書いたルビは、そのまま残す。
原稿のルビの親文字に現れる語は、そこで出現したものとして数える。
著者が読みを示した後に、同じ語へプラグインがもう一度ルビを振らないためである。

### 出力の形

一致した語は、意味論 IR のルビ（tag 4）にする。
各区切りの親文字は一つのテキストのノードであり、位置は元のテキストのノードの位置とする。
一致しなかった前後の文字は、元の位置を持つテキストのノードとして残し、隣り合う断片は一つにつなぐ。

### diagnostic

プラグインが返す diagnostic は、次の三つである。
どれもエラーで、位置はフィルタを当てたファイルの先頭とする。

| コード | 原因 | メッセージ |
| --- | --- | --- |
| `first-ruby-no-words` | `words` を渡していない | `manifest.toml の data で words を渡してください` |
| `first-ruby-utf8` | `words` が UTF-8 でない | `words が UTF-8 ではありません` |
| `first-ruby-tsv` | TSV の行の誤り（行ごとに一つ） | `words の <行> 行め: <上の表のメッセージ>` |

コードの形は [docs/adr/0108](0108-plugin-diagnostic-codes-and-spans.md) に従う。

### 置き場所と配布

- `plugins/first-ruby/` に置き、`plugins/wasm/first-ruby.wasm` をコミットする（[docs/adr/0106](0106-sample-plugins-in-rust.md)）。
- 二つのルビのプラグイン（この ADR と [docs/adr/0130](0130-sou-ruby-plugin.md)）が共有する処理（TSV の読み込み、最長一致、文書の辿り方、読みの割り当て）は、ライブラリのクレート `plugins/ruby-common/` に置く。`crate-type` を持たないので、`build.sh` は wasm を作らない。
- 配布は [docs/adr/0106](0106-sample-plugins-in-rust.md) のとおり、Golem のリリースに `.wasm` を添える。
- Golem の本体（golem-* のパッケージ）は変えない。build-depends も変えない。

## 実装しないこと

- 本の章の単位での初出。フィルタに章の情報を渡すか、複数のファイルを見るフィルタを作る必要があり、どちらもプラグインの仕組みの変更になる。将来の候補は「将来の課題」に書く。
- 語ごとに初出の単位を変えること（本の全体で一度だけ、など）。
- 語の境の判定（形態素解析）。誤った一致は止めの語で防ぐ。
- 見出し、図版のキャプション、コードのキャプションへのルビ。
- ノードの境をまたぐ語の一致。
- 原稿の中に語と読みを書く記法。データの TSV だけで指定する。
- TSV の誤りを、データのファイルの中の位置で報告すること。データに位置を与える形は、草稿の [docs/adr/0108](0108-plugin-diagnostic-codes-and-spans.md) の「トレードオフ」が別に決めるとしている。

## テスト設計

Rust の単体テスト（`cargo test`）は、補助のクレート `ruby-common` に次を置く。

- TSV：グループルビ、モノルビ、部分ルビ、止めの語、注釈の行、空行、CRLF を読むこと。上の表の誤りを、すべての行について行の番号とともに返すこと。
- 照合：最も長い語を左から取ること。止めの語がほかの語の一致を防ぐこと。
- 辿り方：見出しを飛ばすこと、注を印の位置で辿ること、コードと圏点と縦中横と索引の印とチャネルの項目を書き換えないこと、原稿のルビの親文字の文字列を渡すこと、表と箇条書きと定義リストを辿ること。
- データ：`words` がなければ何もしないこと、UTF-8 でなければ `-utf8`、TSV の誤りは行ごとに `-tsv` のエラーになること。

`first-ruby` の単体テストでは、次を確かめる。

- ファイルの中で最初の出現にだけルビを振ること。
- モノルビと部分ルビが TSV のとおりになること。
- 止めの語にルビを振らず、その中の語にも振らないこと。
- 見出しを書き換えず、見出しの出現を数えないこと。
- 原稿のルビを出現として数えること。
- 注の中の出現を、注の印の位置で数えること。
- コードと圏点の中を書き換えず、数えないこと。
- `words` がないとき、TSV が誤っているとき、文書を書き換えずにエラーを返すこと。
- 同じ入力から同じ CBOR のバイト列になること。

golem-driver のテスト（`PluginsSpec`）では、`plugins/wasm/first-ruby.wasm` を二つの章（`a.gm` と `b.gm`）のフィルタにして、次を確かめる。

- 各ファイルで最初の出現にだけルビが振られ、`b.gm` では改めて振られること。原稿のルビが出現に数えられること。
- TSV の誤りが、フィルタを当てたファイルの数（二つ）だけ報告されること。
- `words` がなければ `first-ruby-no-words` になること。

手で確かめたこと：高野聖の fixture に五語の TSV を渡し、`golem build` で四つのターゲット（PDF を含む）を組んだ。
最初の `地図` にだけルビが振られ、diagnostic はフォントにない字の警告（G08100）だけだった。

テストは Rust の実装と同時に書いた。
先に失敗させる手順は踏んでいない。

## トレードオフ

ファイルを初出の単位にしたので、一つの章を複数のファイルに分けた本では、ルビが余分に振られる。
章の単位を正しく扱うには、フィルタの要求に章の情報を足すだけでは足りず、前のファイルでどの語が出たかをフィルタが知る必要がある。
ファイルを独立に評価するという Golem の前提（[仕様書の「プロジェクトの構成と import」](../specifications.md#プロジェクトの構成と-import)）を崩すので、見本のプラグインのために変えるには大きすぎる。

形態素解析をしないので、語の一部に別の語が一致することがある。
止めの語で個別に防げるが、防ぐべき組を見つけるのは利用者である。
形態素解析を使うと、辞書の大きさと実行量の上限の問題を抱える（[docs/adr/0130](0130-sou-ruby-plugin.md)）。
初出ルビの対象は、利用者が選んだ少数の語なので、最長一致で足りると判断した。

見出しにルビを振らないのは、組版の慣習と目次への写り方を優先した選択である。
見出しにだけ現れる難読語は、ルビなしになる。
必要なら、利用者が原稿の見出しにルビを書けばよい。

TSV の誤りは、ファイルの数だけ重ねて報告される。
ホストの側で重複を除く仕組みはない。
データの検査をプラグインの読み込みの段で一度だけ行う形（プラグインがデータを検査する関数を export するなど）は、ABI の変更になるので、この ADR では扱わない。

## 将来の課題

本の章を単位にした初出は、チャネル（[golem-doc ADR 0007](../golem-doc/adr/0007-plugin-channel-lists.md)）を通して扱える可能性がある。
チャネルの項目は文書構造（S1）の段階で全章から集まり、マニフェストの章の順に並ぶ。
各ファイルのフィルタが、語の出現をチャネルの項目として送り、章ごとの最初の出現を S1 で決める形が考えられる。
ただし、今のプラグインは S0 でしか実行されず、S1 の結果を受け取ってルビを振り分ける経路はない（[仕様書の「実行の範囲」](https://github.com/tett23/golem/blob/668ed3acc8df131ed53fdafe49200b4a8ed05d2d/docs/specifications.md#L2847)）。
採るなら、その経路を決める ADR が要る。
