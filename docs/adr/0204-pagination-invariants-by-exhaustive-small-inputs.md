# ADR 0204: ページ分割の不変条件を、小さな入力のすべてで確かめる

ステータス: 採択→（不変条件の I2、I4、I5、I6、I8 の読み方）は [ADR 0206](0206-pagination-points-the-invariants-did-not-decide.md)

## 文脈

### 境界のバグが続いている

2026-09-01 から 2026-11-08 までの main のコミット（マージを除く約 1,280）のうち、題に境界を示す語を含むものを拾うと、境界の入力で見つかったバグを直したものと、境界の入力のテストを足したものが多い。
ページ分割と行分割では、次のようなものがある。

- 見出しだけがページの末尾に残る（[golem-layout ADR 0013](../golem-layout/adr/0013-heading-footnotes.md) と [golem-layout ADR 0019](../golem-layout/adr/0019-keep-with-next-counts-footnotes.md)。どちらも、注の行を数えていなかった）。
- 図版の順が入れ替わる（[golem-layout ADR 0015](../golem-layout/adr/0015-figure-order.md)）。
- 段に入らない見出し（[golem-layout ADR 0020](../golem-layout/adr/0020-heading-taller-than-column.md)）。
- 最後の行分割の回で、入らないものを送る（題「Push out what does not fit in the last line-breaking pass」）。
- 行頭と行末の分離禁止文字（題「Test inseparable characters at the line edges」）。

どれも、ある規則と別の規則が、段の末尾や空の段のような端で重なったときに起きている。
見つけたのは、fixture を組んで目で見たとき（golden を足す作業など）であり、テストが先に見つけたものは少ない。

今も、仕様書の「既知の不具合」に、ページ分割のものが一つある（[docs/specifications.md](../specifications.md) の「図版を追い越した見出しが、本文から離れる」）。
段に入らない図版の後に見出しと段落が続くと、図版が次のページに送られ、見出しが前のページの最後の行に残り、段落が図版の後に置かれる。
見出しをその後の段落の最初の 2 行と同じ段に置く規則が、間に送った図版が入ると守られない。
`complex-vertical` の fixture で見つかり、golden と見た目の回帰テストの参照は今の配置を固定している。

### ページ分割は確かめやすい

ページ分割は、golem-layout の `paginateWithin` の一つの純粋な関数である（[`Paginate.hs`](https://github.com/tett23/golem/blob/b7acd268e6c94f918071f2230035418c88e36be0/modules/golem-layout/src/Golem/Layout/Paginate.hs#L84-L101)）。
入力は、格子の行の数で数えた流れ（`Flow` の並び）と、段の数、段の行の数、注の区切りの行の数であり、出力は段ごとの `PageOut` である（[`Types.hs`](https://github.com/tett23/golem/blob/b7acd268e6c94f918071f2230035418c88e36be0/modules/golem-layout/src/Golem/Layout/Paginate/Types.hs)）。
フォントも寸法も要らないので、小さな入力を大量に作って速く組める。

今の golem-layout のテスト（`PaginateSpec`、約 740 行）は、手で選んだ例と hedgehog の性質のテストである。
hedgehog は入力を乱数で作るので、規則が重なる端の組み合わせに当たるかは運に左右される。
境界のバグは小さな入力で起きることが多い（small scope hypothesis）。
段の行の数が 3 から 8、流れの要素が 6 個以下のような小さな入力のすべてを、小さい順に試せば、端の組み合わせを漏らさず、見つけた反例は最も小さいものになる。

### 規則どうしの矛盾は、テストより前に見つけたい

ページ分割の規則には、互いに譲り合うものがある（見出しを後と離さない規則と、空の段からは送らない規則など）。
二つの規則が同時に守れない入力があるとき、どちらを優先するかが仕様書に書かれていなければ、実装は暗黙にどちらかを選ぶ。
「図版を追い越した見出し」は、見出しの規則と、図版を送る規則（[golem-layout ADR 0003](../golem-layout/adr/0003-pagination-and-s2.md)）のあいだの優先が決まっていないために起きている可能性がある。
規則を Alloy の制約として書けば、すべての規則を同時に満たす配置がない入力を、Alloy が小さい順に探す。
メンテナーは Alloy と Z3 を手元に入れた（2026-11-08）。

### 列挙のライブラリ

小さな入力を小さい順に並べるライブラリには LeanCheck（BSD-3-Clause）がある。
値を大きさの段（tier）の並びとして列挙し、組み合わせの子（`cons1` から `cons5`、`\/`、`><` など）で型ごとの列挙を作る。
メンテナーは、依存に入れずに Golem の側で必要な分だけ書き直すと決めた（2026-11-08。グローバルの方針の「再実装が容易なら依存に入れない」）。

## 実装すること

### 1. 列挙の部品

golem-test-support に `Golem.TestSupport.Enum` を作る（「メンテナーが決めること」の 1）。

- 値の列挙を、大きさの段のリスト（`newtype Tiers a = Tiers [[a]]`）で表す。段 n には、大きさ n の値をすべて、決まった順で入れる。
- 組み合わせの子：一つの値（大きさ 0）、`cons1` から `cons4`（構成子を一つ足すと大きさが一つ増える）、和（`\/`、段ごとに並べてつなぐ）、積（`><`、大きさの和で段を作る）、`mapT`、`filterT`、段の大きさの上限で打ち切る `upTo`。
- 基本の列挙：`Bool`、範囲を指定した `Int`（`intsIn lo hi`）、リスト（`listsOf`）、長さを指定したリスト。
- 調べる関数：`checkAll :: Int -> Tiers a -> (a -> [Violation]) -> Result a` は、段 0 から上限の段までを順に調べ、違反のある最初の値と違反を返す。同じ上限なら、いつも同じ値を返す。
- 型のクラス（LeanCheck の `Listable`）は作らない。列挙は値として渡す。テストごとに範囲を変えるので、型で一つに決めないほうが書きやすいからである。
- LeanCheck の残り（関数の列挙、`Listable` の導出、`holds` と `counterExample` の多くの別名、性質の型を数で選ぶ仕組み）は作らない。

### 2. ページ分割の入力の列挙

golem-layout のテストに `PaginateEnum` を作り、`paginateWithin` の入力を列挙する。

- 段の行の数：3 から 8。段の数：1 と 2。注の区切りの行の数：1。
- 流れの要素の候補（行の数は 1 から 4）：注のない段落、注を一つ持つ行のある段落、一行の見出し（注の有無）、`page-break = "recto"` の見出し、図版（1 から段の行の数より一つ多い行の数まで）、`FSpace 1`、`FBreak`。
- 要素の数で段を分け、上限は「メンテナーが決めること」の 3 の数とする。
- `lbId` は、流れの先頭から順に振る。

罫線を持つ段落、表、コード、回り込む図版、段の切り替え、手での制御（`FNoBreak`、`FNeedLines`、`FAdjustLines`、`FBlank`）は、この ADR では列挙しない（「実装しないこと」）。

### 3. 不変条件の述語

golem-layout のテストに `PaginateInvariants` を作り、仕様書の「改ページ」の節の規則を、`[Flow]` と `[PageOut]` を受け取って違反の並びを返す述語として書く。
述語は実装の内部（`St`、`Env`）を読まず、入力と出力だけを読む。
「不変条件」の節に挙げる I1 から I8 を、それぞれ一つの関数にする。

述語を書いていて、仕様書の文から一つの述語に決まらないところが見つかれば、述語を書かずに、そのところを PR の説明に挙げる。
どちらとも読める規則をテストで決めることはしない。
仕様の改めは、新しい ADR で決める。

### 4. すべての入力で確かめるテスト

golem-layout のテストに、列挙したすべての入力で I1 から I8 を確かめるテストを足す。

- 違反があれば、最も小さい入力を Haskell の値として、違反した不変条件と出力とともに表示する。表示をそのまま `PaginateSpec` の例に貼れるようにする。
- 既知の不具合の扱い：仕様書の「既知の不具合」に載っているもの（今は「図版を追い越した見出し」）と、このテストで新しく見つかったものは、述語の側ではなく、テストの中の明示した一覧（入力の形の条件と、不具合の項目へのリンク）で除く（「メンテナーが決めること」の 4）。一覧にない違反は失敗にする。一覧の各項目は、直す ADR が入ったときに消す。
- 新しく見つかった違反は、仕様書の「既知の不具合」と docs/roadmap.md に足し、上の一覧に入れる。この ADR の中では直さない。

### 5. Alloy のモデル

`docs/golem-layout/models/pagination.als` に、ページ分割の規則のモデルを書く（「メンテナーが決めること」の 5）。

- 一つの段と次の段の境目を、要素（段落の行、見出し、図版）の並びと段の行の数でモデルにする。
- 規則（I3 から I6 と、図版を送る規則、空の段からは送らない規則）を事実（fact）ではなく述語（pred）として書く。すべての規則を同時に満たす配置がない入力を `run` で探し、規則の組ごとに、両立しない最も小さい例を出す。
- 結果（両立しない規則の組と、その最も小さい例）を、`docs/golem-layout/models/README.md` に書く。Alloy の版とコマンドも書く。
- 見つかった両立しない組のそれぞれについて、仕様書が優先を決めているかを確かめる。決めていなければ、docs/roadmap.md の「未決事項」に足す。

### 6. CI

- プルリクエストの CI（golem-layout のテストの入る行列）では、「メンテナーが決めること」の 3 の上限の段まで調べる。
- 毎晩の `race.yml` と同じ形の定期のジョブで、上限を一つか二つ上げて調べる（「メンテナーが決めること」の 3）。上限は環境の変数（`GOLEM_ENUM_DEPTH`）で渡す。
- Alloy のモデルは CI で動かさない（「メンテナーが決めること」の 5）。

### 7. 文書

- [docs/specifications.md](../specifications.md) の「改ページ」の節に、規則を不変条件として確かめていることと、テストの場所を書く。
- docs/roadmap.md の「手で確かめる項目」に、ページ分割の規則を変える ADR では Alloy のモデルを直して走らせ直すことを足す。
- README の CI のジョブの表に、定期のジョブを足す。
- `CONTRIBUTING.md` に、反例の表示を `PaginateSpec` の例にする手順を書く。
- `CLAUDE.md` に、振る舞いを決める ADR は「不変条件」の節を持ち、番号を付けた不変条件と境界の入力の表を書くことを書く（メンテナーの指示、2026-11-08）。この ADR の「不変条件」の節が、その最初の例である。

### パッケージの依存

この ADR は、golem のパッケージのあいだの `build-depends` を、次のように変える。

| パッケージの構成要素 | 足す | 除く |
| --- | --- | --- |
| golem-layout のテスト（golem-layout-test） | golem-test-support | |

golem-test-support は golem のパッケージに依存しないので、`scripts/ci/test-only-deps.sh` の検査（[docs/adr/0087](0087-test-support-dependencies-and-shared-fixtures.md)）は変わらない。
Hackage のパッケージは足さない。

## 不変条件

段の行の数を C、段の数を K とする。
出力の段は、ページの番号と段の番号の順に並べたものとする。

- **I1 すべて一度だけ置く**：入力のすべての行（`lbId`）と図版（`ffId`）が、出力のどこかにちょうど一度ずつ現れる。白ページの段は何も持たない。
- **I2 段からあふれない**：どの段でも、置いた格子の行と、注の本文の行と、注があればその区切りの行の和が、C を超えない。ただし、空の段にも入らない見出し（`TallHeading` として報告されるもの）と、空の段に置いた段落の一行目の注の続き（注の本文を次の段に続ける規則）は除く。
- **I3 順を保つ**：行と見出しは、入力の順に出力に現れる。図版どうしも、入力の順に現れる（[golem-layout ADR 0015](../golem-layout/adr/0015-figure-order.md)）。図版と本文のあいだでは、図版が入力より後に現れることだけを許す（送った図版）。
- **I4 孤立行がない**：二行以上の段落の最初の一行だけが段の最後に置かれ、残りが次の段に置かれることはない。ただし、その段が段落の一行目の前に何も持たない（空の段）ときは除く。
- **I5 寡婦行がない**：二行以上の段落の最後の一行だけが段の最初に置かれることはない。ただし、その前の段が空の段から始まり、その段落の行だけを持つときは除く。
- **I6 見出しは後と離れない**：見出しは、続く見出しのすべてと、その後の段落の最初の 2 行（段落が 2 行未満ならすべて）と、同じ段に置かれる。ただし、見出しが段の最初の要素であるときは除く（空の段からは送らない）。
- **I7 注は合印の段にある**：注の本文の最初の行は、合印のある行と同じページに置かれる。
- **I8 改丁**：`page-break = "recto"` の見出しは、奇数ページの最初の段の最初に置かれる。

I2、I4、I5、I6 の「ただし」は、仕様書の「空の段では、この二つの規則で一行も置けなくなる場合は、入るだけの行を置く」と「空の段からは送らない」を述語にしたものである。
実装のときに、この読み方が仕様書と食い違うとわかれば、3 のとおり述語を書かずに PR の説明に挙げる。

境界の入力：

| 量 | 調べる値 |
| --- | --- |
| 段の残りの行 | 0、1、2、ちょうど要素が入る、一つ足りない |
| 段落の行の数 | 1、2、3（孤立行と寡婦行の両方に当たる最小）、C、C + 1 |
| 図版の行の数 | 1、C − 1、C、C + 1 |
| 見出しの並び | 0、1、2（続く見出し） |
| 注 | なし、段の最初の注、二つめの注 |
| 段の数 | 1、2（段の最後とページの最後が別になる） |

## 実装しないこと

- **見つけた違反を直すこと**：直す ADR を、違反ごとに別に作る。
- **ほかの流れの要素の列挙**：罫線、表、コード、回り込む図版、段の切り替え、手での制御。試験導入の結果を見て、範囲を広げる ADR で決める。
- **ページの番号の参照の固定点（S2）**：`resolvePageRefs` の繰り返しは調べない。
- **素朴な参照の実装と比べること**：ページ分割は最適化ではなく先頭から詰める手順なので、別の簡単な実装を作っても、同じ規則を二度書くことになる。比べる代わりに、不変条件で確かめる。行分割には、すでに `KnuthPlassReference` がある。
- **LiquidHaskell と SBV**：Z3 は入れたが、この ADR では使わない。範囲を広げる ADR で決める。
- **LeanCheck の全体を書き直すこと**：1 に挙げたものだけを書く。

## テスト設計

テストを先に書き、今の実装で失敗することを確かめてから実装する。

### 列挙の部品（golem-test-support のテスト）

LeanCheck のテストを参考にする。

- `Bool` の段は `[[False, True]]`、`intsIn 0 3` は大きさの順に `0`、`1`、`2`、`3` を一つずつの段に持つこと。
- 長さ n までの `Bool` のリストの段の大きさが、2 の累乗（1、2、4、8 と、各段の和）になること。
- `\/` と `><` で作った段の大きさが、元の段の大きさから計算した数（和の段は和、積の段は畳み込み）に一致すること。
- どの段にも、同じ値が二度現れないこと（重複のなさ）。上限の段までの値の集まりが、同じ範囲を素朴に作った集まりと一致すること（漏れのなさ）。
- `checkAll` が、違反のある値のうち最も小さい段の最初のものを返し、同じ上限で何度呼んでも同じ値を返すこと。
- `upTo` が、上限より後の段を評価しないこと（無限の列挙でも止まる）。

### ページ分割の列挙と不変条件（golem-layout のテスト）

- 列挙：段の行の数が 3 で要素が 2 個までのとき、作る入力の数が、候補の数から計算した数と一致すること。
- 述語のテスト：I1 から I8 のそれぞれについて、規則を破った出力を手で作り、その述語だけが違反を返すこと。仕様書の例外（空の段など）に当たる出力では、違反を返さないこと。
- 回帰：[golem-layout ADR 0013](../golem-layout/adr/0013-heading-footnotes.md) と [golem-layout ADR 0019](../golem-layout/adr/0019-keep-with-next-counts-footnotes.md) を直す前の実装の振る舞い（見出しだけがページの末尾に残る出力）を、I6 が違反として返すこと。
- 試験導入の判定：既知の不具合の一覧を空にして全体のテストを走らせ、「図版を追い越した見出し」に当たる最も小さい反例が見つかること。見つからなければ、列挙か述語に漏れがあるとして、直してから一覧を戻す。

### Alloy のモデル

自動のテストは書けないので、5 で走らせた結果を README に書き、次のことを確かめる。

- 規則を一つも課さないときは配置が見つかり、すべてを課すと見つからない入力があること（モデルが空でも全否定でもないこと）。
- 「図版を追い越した見出し」に当たる、見出しの規則と図版を送る規則の組が、両立しない組として出ること。

## トレードオフ

不変条件を仕様書の文から書き直すので、仕様書の曖昧さがテストを書く段で表に出る。
曖昧なところで手が止まり、試験導入が仕様の改めの ADR を待つことがありうる。
その代わり、規則の優先が暗黙に実装で決まっている箇所が見える。

列挙は、入力の数が要素の数とともに指数的に増える。
上限を一つ上げると、時間が数倍から十数倍になりうる。
プルリクエストでは小さく、毎晩のジョブで大きく調べるのは、CI を 5 分以内に保つ方針（`CONTRIBUTING.md`）のためである。
毎晩のジョブで見つかった反例は、main に入った後に見つかる。

既知の不具合をテストの中の一覧で除くと、除く条件を広く書きすぎて、別の違反まで隠すおそれがある。
条件は入力の形（どの要素がどの順に並ぶか）で狭く書き、一覧の各項目に、除いた反例の数をテストで数えて固定する。
数が変われば、テストが落ちる。

LeanCheck を書き直すと、テストの部品を Golem が持ち続けることになる。
使う機能を 1 に限るので、量は小さいと見込める。

Alloy のモデルは実装と別に書くので、実装と食い違っても気付かない。
モデルの目的は規則どうしの矛盾を探すことであり、実装の正しさは 4 のテストが確かめる。

## メンテナーが決めること

1. **列挙の部品を置く場所**：推奨は golem-test-support である。範囲を広げたときに、golem-layout のほかのテスト（パーサー、表など）からも使える。golem-test-support は golem のパッケージに依存しないので、どのテストからも依存できる。
   - 退けた案は、golem-layout のテストの中に置くことである。依存は変わらないが、範囲を広げるときに写すか移すことになる。
2. **不変条件を書く場所**：推奨は、ADR の「不変条件」の節と、テストの述語の両方である。ADR には文で、テストには関数で書き、ADR の I1 から I8 の番号をテストの名前に入れて対応を取る。
   - 退けた案は、述語だけにすることである。規則を変える ADR を書くときに、どの不変条件が変わるかを ADR の上で議論できない。
3. **列挙の上限**：推奨は、プルリクエストでは要素 5 個まで、毎晩のジョブでは 7 個までである。実装のときに時間を測り、プルリクエストで golem-layout のテストが 30 秒以上延びるなら、上限を下げる。
   - 退けた案は、上限を時間で決めることである（決めた秒数までに調べられたところまで）。調べた範囲がマシンの速さで変わり、同じコミットで結果が変わりうる。
4. **既知の不具合の扱い**：推奨は、テストの中の明示した一覧で除き、一覧の各項目の反例の数を固定することである。一覧にない違反は CI を落とすので、新しい不具合はマージの前に見つかる。
   - 退けた案の一つは、既知の不具合を持つ不変条件のテストを、直すまで止めることである。その不変条件のほかの違反を見逃す。
   - もう一つは、見つかった違反をこの ADR の中で直すことである。直し方は規則の優先を決めることであり、違反ごとに ADR で決めるほうがよい。
5. **Alloy のモデルを CI で動かすか**：推奨は、動かさず、規則を変える ADR のときに手で走らせることである。モデルは ADR を書く段で規則の矛盾を探すための道具であり、実装が変わってもモデルの結果は変わらない。CI に Java と Alloy を入れる手間に見合わない。
   - 退けた案は、CI で走らせ、README の結果と一致することを確かめることである。モデルを変えずに README だけを変えることは防げるが、規則を変える ADR でモデルを直し忘れることは防げない。
