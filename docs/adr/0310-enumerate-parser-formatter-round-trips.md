# ADR 0310: 文法から生成した短い原稿でパーサーとフォーマッターの往復を確かめる

ステータス: 採択（未実装）

## 文脈

[ADR 0208](0208-widen-lightweight-formal-methods.md) は、短い入力をすべて列挙して確かめる範囲を、ページ分割から広げると決めた。
ロードマップで残った範囲の最初には、同じ原稿を読むパーサーとフォーマッターを選ぶ。
文法が認める原稿と、一箇所だけ壊した原稿を対にすると、構文を保つ性質と diagnostic の位置を別々に確かめられる。

## 実装すること

テストで `peg-grammar` の `parseGrammar` に `Golem.hpeg` を渡す。
最初は見出し記号の規則 `HashMark` の各選択肢からリテラルを取り出し、本文の一文字を付けて見出しを作る。
本文の代表は ASCII、漢字、補助平面の文字から一つずつ選ぶ。
空原稿と二段落も調べる。
選択肢を読めないときは規則名と式を示して失敗させる。
深すぎる見出しには、壊した文字の UTF-8 バイト位置を生成時に記録する。

PR の上限は、[ADR 0281](0281-budgets-of-the-exhaustive-tests-and-what-moves-to-the-nightly-job.md) の時間の予算に照らして決める。
試作の件数は、この上限を決めるための候補である。

## 実装しないこと

任意の Haskell の意味述語や回復アクションを逆向きに実行する生成器はこの範囲に含めない。

## 不変条件

1. G1：正常な原稿で構文の diagnostics が空になり、整形前後の位置を除いた構文木が等しい。
2. G2：正常な原稿を二度整形した結果は、一度整形した結果と等しい。
3. G3：深さ 7 の見出しでは、G01012 の開始バイト位置は行頭から 6 バイト後になる。

| 境界の入力 | 期待する結果 |
| --- | --- |
| 空原稿 | G1 と G2 が成り立つ |
| `###### 😀` | 深さ 6 の見出しとして読める |
| `####### a` | 7 個目の `#` に G01012 が付く |
| 絵文字と空行の後の深さ 7 | 絵文字を 4 バイトとして開始位置を求める |

## テスト設計

未コミットの試作 `experiments/formal/Parser.hs:17` は、文法の 6 個の選択肢から見出しを生成する。
worktree のルートで `experiments/formal/compile.sh experiments/formal/Parser.hs` を実行し、正常 28 件と異常 4 件で終了コード 0 を得た。
本実装では G1、G2、G3 をテスト名に付け、最初の反例の原稿と規則名を表示する。
エスケープを足すときはフォーマッターが除去できるエスケープだけを正規化してから比較する。

位置の期待値を 1 バイトずらした対照は、G01012 の開始位置の不一致で失敗した。
再現には試作のルートで `experiments/formal/mutations.sh` を使う。

## トレードオフ

文法ファイルを文字列として分割する案では、改行や引用符の変更が生成器の故障になる。
文法木を読む案なら、本体と同じ peg-hs の版をテスト専用の依存に使える。
試作の入力は見出しと段落に限るため、ほかの構文の網羅率には数えない。
