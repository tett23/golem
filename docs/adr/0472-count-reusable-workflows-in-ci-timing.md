# ADR 0472: CI の時間の計測で再利用ワークフローのジョブも数える

Status: accepted-pending

## 文脈

[root ADR 0392](0392-budget-the-pull-request-ci-at-five-minutes.md) は、プルリクエストの CI の依存関係をたどった最も長い道の時間を測り、中央値の予算を 300 秒とした。
しかし、計測するスクリプトは、別のワークフローを呼ぶジョブの時間を落としている。
[root ADR 0457](0457-split-the-tests-rest-runner-in-two.md) の A1 の再計測で見つかった。
この ADR は、再利用ワークフローを含む依存関係の読み方を補う。
予算の値と、検査を走らせるイベントは変えない。

## 調査した事項

2026-11-27 に、origin/main の [4121ea73d](https://github.com/tett23/golem/commit/4121ea73d4466eaf47353e4b84d22f08327aed1e) と GitHub のジョブの一覧を調べた。

- [ci-critical-path.sh](https://github.com/tett23/golem/blob/4121ea73d4466eaf47353e4b84d22f08327aed1e/scripts/ci/ci-critical-path.sh) は、ジョブの名前から matrix の括弧以降を外し、ワークフローのジョブの識別子と照合する。
  `parser-fmt-proofs / prove (grammar)` は `parser-fmt-proofs / prove` となり、親の識別子 `parser-fmt-proofs` に一致しない。
  親の時間が無いときは 0 秒になる。
- [ci.yml](https://github.com/tett23/golem/blob/4121ea73d4466eaf47353e4b84d22f08327aed1e/.github/workflows/ci.yml) は、`parser-fmt-proofs` からローカルの `parser-fmt-proofs.yml` を呼ぶ。
  [呼ばれるワークフロー](https://github.com/tett23/golem/blob/4121ea73d4466eaf47353e4b84d22f08327aed1e/.github/workflows/parser-fmt-proofs.yml) の `prove` と `nightly-cli` のあいだには依存関係が無い。
  PR では `nightly-cli` を省く。
- [root ADR 0457](0457-split-the-tests-rest-runner-in-two.md) のマージ後の、ビルドを省かなかった成功 PR の最新 20 回に既存スクリプトを使うと、中央値は 318 秒だった。
  同じ一覧のうち 12 回に、再利用ワークフローの証明ジョブがある。
  その 12 回の、最も長い証明ジョブの時間は 743 秒から 1197 秒だった。
- このワークフローの子のジョブは並列なので、調査用の計算で親の時間を子の最大時間とすると、同じ 20 回の中央値は 864 秒になった。
  この値は実装後に一般の計測スクリプトで照合する。
  一覧の実行番号は [PR #1200](https://github.com/tett23/golem/pull/1200) の記録にある。

## 実装すること

ローカルの再利用ワークフローも読み、呼出元と呼出先の依存関係を一つの有向グラフにする。
呼出先のジョブの名前には、呼出元の識別子と ` / ` を前に付け、GitHub が返す名前と照合する。
再利用ワークフローの中の再利用も、同じ規則で読む。

呼出先のうち依存先の無いジョブは、呼出元の依存先の後に始まる。
呼出元の後のジョブは、呼出先のすべてのジョブが終わってから始まる。
呼出元そのものには実行時間を足さず、子のジョブの時間を二重に数えない。
matrix の脚は、今と同じく最も長い脚の時間を使う。
省いたジョブは 0 秒とし、ランナーを待った時間は数えない。

呼出先は、計測対象の版にある `uses: ./...` のファイルから読む。
外部リポジトリの再利用ワークフロー、読めない呼出先、循環する呼出しや依存関係、グラフに対応しない実行中または実行済みのジョブがあれば、理由を出して計測を中止する。
読めない時間を 0 秒にして中央値を出さない。
`--needs` の既存の表示は保ち、展開したグラフを確認する別のオプションを足す。

[root ADR 0457](0457-split-the-tests-rest-runner-in-two.md) の A1 を測り直し、入力のジョブの時刻と、依存関係の版と、結果を新しい記録に残す。
コミット済みの 318 秒の記録は変更せず、新しい記録から誤りの理由を示す。
予算を超えていれば、次の改善を別の ADR で決める。
README と仕様書に、ローカルの再利用ワークフローも数えることと、読めない場合は計測を中止することを書く。

## 実装しないこと

証明の範囲を減らすことと、証明を PR の CI から外すことはしない。
予算と、スイートの時間の上限の式は変えない。
外部のワークフローをネットワークから取り寄せて解析することはしない。

## 不変条件

- I1: 再利用ワークフローと循環が無く、一覧のジョブをグラフに照合できる入力の時間と中央値は、変更前と等しい。
- I2: 直列の子のジョブの時間は足し、並列の子と matrix の脚は最も長い時間を使う。
- I3: 呼出元の依存先の時間と、子の時間と、呼出元の後のジョブの時間は、それぞれ一度だけ数える。
- I4: ランナーを待った時間を変えても、計測した時間は変わらない。
- I5: 読めない呼出先、循環、対応しない実行中または実行済みのジョブがあれば、計測は 0 でない終了コードで終わり、中央値を出さない。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 再利用の無い既存の境界の入力 | 変更前と同じ | I1 |
| 子が並列で 20 秒と 40 秒 | 子の部分は 40 秒 | I2 |
| 子が直列で 20 秒と 40 秒 | 子の部分は 60 秒 | I2 |
| 親の前が 10 秒、子が 40 秒、後が 5 秒 | 55 秒 | I3 |
| 二重の再利用の中の matrix が 20 秒と 40 秒 | 子の部分は 40 秒 | I2, I3 |
| 子をすべて省いた | 子の部分は 0 秒 | I2 |
| 子の開始を 2 時間待った | 待ち時間の無い入力と同じ | I4 |
| 呼出先のファイルが無い、または外部の参照 | 理由を出して失敗 | I5 |
| 自分自身を呼ぶワークフロー | 理由を出して失敗 | I5 |
| 一覧にグラフと照合できない実行済みジョブ | 理由を出して失敗 | I5 |

## 受けいれ条件

- A1: [root ADR 0457](0457-split-the-tests-rest-runner-in-two.md) と同じ 20 回の一覧を、実装したスクリプトで測り直し、調査用の計算と照合して、新しい記録とロードマップに反映する。

## テスト設計

root ADR 0472 I1 から I5 のテストを `scripts/ci/test.sh` に、まず追加して失敗させる。
一時的なローカルのワークフローとジョブの JSON で、境界の表を確かめる。
既存の [root ADR 0392](0392-budget-the-pull-request-ci-at-five-minutes.md) のテストもすべて通す。
A1 は保存した 20 回の入力で確かめる。

## トレードオフ

ワークフローを複数読むので、解析する範囲は広がる。
読めない場合に計測を止めると新しい記法に追従する手間が生じるが、時間を落として予算を満たすと誤認することを防ぐ。
