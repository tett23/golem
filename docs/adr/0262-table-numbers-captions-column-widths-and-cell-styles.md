# ADR 0262: 表の番号とキャプション、列の幅、文字の大きさ

ステータス: 採択（未実装）

## 文脈

技術書と学術書は、表を「表 3-2」のように番号で参照し、本文より小さい文字で組むことが多い。
今の Golem の表は、番号もキャプションも持たない。
列の幅は自動で決まるだけで、セルは本文と同じ書体と大きさで組む。
[2026-10-17 の調査](../audits/2026-10-17-latex-gap-for-v1.md) は、これを v1.0.0 に入れる項目（8）とし、所有者はそのとおりに決めた。
docs/roadmap.md の v1.0.0 の「LaTeX との差を埋める項目」の「表の番号とキャプション、列の幅、文字の大きさ」が、この項目である。

### 今の表

意味論 IR の表は、列の揃え、見出しの行、本体の行だけを持つ（[`Golem.Doc.IR` の `Table`](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-doc/src/Golem/Doc/IR.hs#L109)、CDDL の [タグ 5](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-doc/schema/golem-doc.cddl#L21)）。
原稿の書き方は二つある。
行頭の `|` で書く表と、CSV か TSV のファイルから作る `@table` である（[ADR 0184](0184-table-positional-path.md)）。
どちらも同じ IR の表になる。

PDF では、セルの一行を行の格子の一行として、本文の書体と大きさで組む（[golem-driver ADR 0008](../golem-driver/adr/0008-pdf-tables.md)）。
列の幅は、セルの最小の幅と自然な幅から決め、列の間隔は一字分である（[golem-driver ADR 0037](../golem-driver/adr/0037-table-column-widths.md)、[`columnWidths`](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-layout/src/Golem/Layout/Table.hs#L57-L77)、[`layoutTable`](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-layout/src/Golem/Layout/Table.hs#L101-L102)）。
HTML と EPUB は `<table>` を書き、列の幅は読者側のエンジンに任せる。
プレーンテキストは、セルをタブで区切った行を書く（[`Golem.Text`](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-text/src/Golem/Text.hs#L134)）。

表には `@label` を付けられ、`[ref-page]` で表を置いたページを引ける。
`[ref-number]` で引くと、番号を持たない要素への参照（G04005）になる（[`Golem.Assemble`](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-assemble/src/Golem/Assemble.hs#L566-L588)）。
表への `@caption` と `@nonumber` は、付けられない属性（G02013）である。

### 番号とキャプションを持つほかのブロック

図版とコードブロックは、すでに番号とキャプションを持つ。
二つの仕組みは少し違う。

- 図版は、`@figure` の字下げした行に段落でキャプションを書く。番号はすべての図版に振り、`@nonumber` で外す（[ADR 0200](0200-figures-and-listings-without-numbers.md)）。キャプションは画像の下に置く。
- コードブロックは、直前の `@caption 本文` の一行でキャプションを書く（[golem-driver ADR 0023](../golem-driver/adr/0023-code-block-book-features.md)）。番号（既定 `リスト{chapter}-{n}`）はキャプションのあるものにだけ振り、`@nonumber` で外せる。キャプションはコードの上に置き、キャプションと最初のコードの一行を同じページに置く。

どちらの番号も、階層 1 の見出しで数え直し、文書の組み立て（S1）で決める（[`numberDocs`](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-assemble/src/Golem/Assemble.hs#L321-L331)）。
キャプションは、段落スタイル `caption` の `font` と `size` で組む（[golem-driver ADR 0010](../golem-driver/adr/0010-caption-style.md)）。
番号とキャプションのあいだの区切りは、本の言語で決まる（[golem-driver ADR 0042](../golem-driver/adr/0042-listing-caption-number-separator.md)）。

表の原稿は、`|` の表も `@table` も一行ずつの記法で、字下げした本体を持たない。
キャプションを付ける形は、図版よりコードブロックに近い。

### キャプションの位置

JLReq は、図版のキャプションを「一般に図版の下側に配置する」と書く（4.3.1）。
表については、置く位置を直接には書かない。
ただし、分割してよい表の規則に、キャプションの行間、キャプションとヘッダー行のあいだ、ヘッダー行の中では分割しないとある（4.4.6）。
キャプションがヘッダー行の前、つまり表の上にあることを前提にした規則である。
4.4.3 の配置の例も、表の文字を本文の 9 ポイントより小さい 7 ポイントとし、キャプションも 7 ポイントで組み、表番号だけをゴシック体にしている。

InDesign は、表のキャプションを表の上にも下にも置ける（調査の 8 に挙げたヘルプのページ。本文は読めておらず、抜粋で確かめた）。
LaTeX の `table` 環境は、`\caption` を書いた位置にキャプションを置く。

### 小さい文字と行の格子

本文より小さい文字の表は、行の格子との関係を決める必要がある。
キャプションは、本文の行送りと文字の大きさの比を保った行送りで組み、全体を収める最も少ない数の格子の行を占める（[golem-driver ADR 0010](../golem-driver/adr/0010-caption-style.md) の `headingBlock` による求め方）。
表のページ分割は、格子の行を単位にした流れの要素（`FTable`）で行う（[`Paginate.Types`](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-layout/src/Golem/Layout/Paginate/Types.hs#L80)）。
表の行ごとに格子の行に載せれば、ページ分割の仕組みは変わらない。

### 段落スタイルを当てる場所

v1.0.0 の「段落スタイルの拡張」は、「見出し、リスト、表などへの段落スタイルの適用」を含む。
この ADR は、そのうちの表を受け持つ。
InDesign では、表スタイルとセルスタイルがセルの中の段落スタイルを決める（調査の 8 のヘルプのページ。抜粋で確かめた）。
Golem はセルスタイルを持たないので、表のセルに一つの段落スタイルを当てる。

### ほかの ADR との関係

この ADR は、同じ時期の ADR のどれにも依存しない。
[ADR 0267](0267-pdf-bookmarks-and-links-inside-the-document.md) の相互参照のリンクは、この ADR の表の番号への参照も扱う。
表の分割の規則（キャプションを見出しの行と離さないこと）は表の中の規則であり、段落スタイルの分割禁止の欄（[ADR 0261](0261-keep-options-of-paragraph-styles.md)）とは別に決める。

## 実装すること

### 1. 意味論 IR

表を、図版とコードブロックと同じく記録型にする。

```haskell
data BlockBody
  = ...
  | TableBlock !Table
  ...

data Table = Table
  { tableAligns :: ![Alignment],
    -- | the width of each column; [] when no column has a width (all are auto)
    tableWidths :: ![ColumnWidth],
    -- | the caption; a table with a caption has a table number unless tableNoNumber
    tableCaption :: !(Maybe [Inline]),
    tableNoNumber :: !Bool,
    -- | the paragraph style of the cells; Nothing is the built-in table
    tableStyle :: !(Maybe Text),
    tableHeader :: ![[Inline]],
    tableRows :: ![[[Inline]]]
  }

data ColumnWidth
  = ColumnAuto
  | -- | in zw of the cells' paragraph style
    ColumnZw !Rational
  | ColumnAbs !Sp
  | -- | in percent of the width the columns share
    ColumnPercent !Rational
```

- CDDL では、表の新しいタグ（14）を加え、タグ 5 を廃止する（タグは使い回さない）。

  ```cddl
  / [14, table]                                    ; table (docs/adr/0262)
  table = [aligns: [* alignment], widths: [* column-width], caption: inlines / null, nonumber: bool, style: tstr / null, header: [* inlines], rows: [* [* inlines]]]
  column-width = [0] / [1, rational] / [2, uint64] / [3, rational]  ; auto, zw, sp, percent
  ```

- `Golem.Doc.Validate` に次の不変条件を加える。`widths` は空か、列の数と同じ長さである。`ColumnAuto` のほかの幅は 0 より大きい。`nonumber` が真の表はキャプションを持つ（コードブロックと同じ文言の型で、`キャプションのない表は番号を持たないので、@nonumber は要りません`）。`style` は `body` を表さない（`body` は名前で書く。段落と違い、null は `table` である）。
- ABI のバージョンは [ADR 0052](0052-plugin-abi-version-bump-rule.md) の規則による。今の版 8 は v0.1.0-rc4 に含まれるので、この ADR の実装より前に次のリリースまでの別の ADR が上げていなければ 9 にし、上げていれば変えない。
- Emet の `Block` のデータ型の表のコンストラクタも、同じ欄を持つ形に変える（仕様書の「意味論 IR のデータ型」）。プラグインと関数が返す表の段落スタイルは、段落と同じく G02047 で検査する。

### 2. 記法

表に付けられる属性を三つ増やし、属性を一つ新しく作る。
`|` の表と `@table` のどちらにも、同じく付けられる。

```
@label tbl-formats
@caption 出力の形式
@column-widths 8zw auto
@style small-table
| 形式 | 用途 |
|---|---|
| PDF | 印刷 |
| EPUB | 電子書籍 |
```

- `@caption 本文`：表のキャプションである。書き方と誤りはコードブロックと同じとする（本文は行の残りで、インラインの要素を書ける。本文のない `@caption` は G02069）。キャプションのある表は表番号を持つ。
- `@nonumber`：キャプションのある表に、表番号を振らない。番号を消費しない。キャプションのない表への `@nonumber` は、コードブロックと同じく G02134 とする。
- `@style 段落スタイル`：表のセルに当てる段落スタイルである。書かなければ組み込みの `table` を当てる。名前のない段落スタイルは、段落と同じく G02047 とする。
- `@column-widths 幅...`：列の幅を左の列から順に並べる。値は `auto`、寸法（`mm`、`pt`、`Q`、`H`、`in`、`zw`）、割合（`%`）である。寸法と割合の数の書き方は、図版の `width`（[ADR 0190](0190-non-wrapping-figure-width.md)）と同じである。値を一つだけ書けば、すべての列に当てる。二つ以上書くときは、列の数と同じ数を書く。

`zw` は、セルに当てる段落スタイルの文字の大きさを一字とする。
`%` は、行長から列の間隔の和を引いた幅（列が分け合う幅）に対する割合とする。
`50% 50%` の二列の表は、列の間隔を除いた行長をちょうど分ける。

誤りは次のとおりである。

- G02135：`@column-widths` の値が `auto`、寸法、割合のどれとしても読めない、0 である、式である。値ごとに一つ報告し、その `@column-widths` を捨てる（すべての列を `auto` とする）。
- G02136：`@column-widths` の値の数が、一つでも列の数でもない。`@column-widths` の行に報告し、捨てる。
- 表でないブロックへの `@column-widths` は G02013 とする。
- `@style` を段落と表のほかのブロックに付けると、今と同じく G02013 とする。

`@caption`、`@nonumber`、`@style` を表に付けても G02013 にしないよう、[golem-eval](https://github.com/tett23/golem/blob/87857c6e74c3494d5f23149101415cb566b2d850/modules/golem-eval/src/Golem/Eval/File.hs) の属性の検査を改める。
改行の様式で、属性が直後の一行の段落にだけ付く規則は、表には当てない。
属性は直後の表の全体に付く。

### 3. 表番号

- 表番号は、図版、リスト番号とは別の数で数え、階層 1 の見出しで数え直し、文書の組み立て（S1）で決める。数えるのは、キャプションがあり、`@nonumber` のない表である。リストの項目と定義リストの説明の中の表も数える。
- 表記は、`style.toml` の新しい表 `[tables]` の `number`（既定 `表{chapter}-{n}`）で決める。差し込みの読み方は `[figures]` の `number` と同じであり、差し込みを含まない書式と未知のキーは G03006 とする。
- 書式の表記で表せない番号は、図版の G04013 とリスト番号の G04014 と同じ扱いで、G04100 とする（[ADR 0213](0213-numbers-the-number-formats-cannot-write.md)）。その表は番号の文字列なしで組む。
- 章の外の表に `{chapter}` を使う書式を当てると、図版とコードブロックと同じく G04004 とする。メッセージの「図版とコード」を「図版、表、コード」に改める。
- `[ref-number ...]` は、番号のある表を図版とコードブロックと同じ形（`3-2`、章の番号と表の番号）で返し、`[ref-title ...]` はキャプション（索引の印とチャネルの項目を除いたもの）を返す（[ADR 0215](0215-ref-number-and-ref-title-as-reference.md)）。番号のない表への `[ref-number]` は G04005、キャプションのない表への `[ref-title]` は G04006 である。`[ref-number]` が `number` の書式に従わない既知の不具合（仕様書の「既知の不具合」）は、表にも同じく当たる。直すのは別の項目である。
- 番号とキャプションのあいだには、図版とコードブロックと同じ区切りを入れる（[golem-driver ADR 0042](../golem-driver/adr/0042-listing-caption-number-separator.md)）。

キャプションの位置は、`[tables]` の `caption-position` で本ごとに決める（「メンテナーが決めること」の 3）。

| キー | 値 | 既定 | 意味 |
| --- | --- | --- | --- |
| `caption-position` | `"above"`、`"below"` | `"above"` | 表のキャプションを置く側。`"above"` は表の前（横組みの上、縦組みの右）、`"below"` は表の後（横組みの下、縦組みの左） |

- ほかの値と、文字列でない値は、`[tables]` のほかの値と同じく G03006 とする。
- 既定を上にするのは、JLReq の 4.4.6 が、キャプションをヘッダー行の前に置く前提で分割の規則を書いているからである。
- キャプションの位置は、表番号、`[ref-number]`、`[ref-title]` を変えない。
- 表ごとに位置を変える属性は作らない。v1.x の「表の拡張」に置く。

### 4. 組み込みの段落スタイル `table`

組み込みの段落スタイルに `table` を加える。
組み込みの段落スタイルの数は、この時期の [ADR 0264](0264-paragraph-styles-for-toc-entries.md) も目次の六つを足すので、実装の順で決まる。
定義は `caption` と同じ形で、`based-on = "body"` と、`indent`、`first-line-indent`、`end-indent` の 0 を持つ。
したがって、既定では本文と同じ書体と大きさで組み、今の出力は変わらない。
`[paragraph-styles.table]` か `@style-def paragraph table` に 0 でない字下げを書くと G03006、0 を書くと G03100 とし、`rule-before`、`rule-after`、`background`、`padding`、`border`、`border-width` を書けないことも `caption` と同じとする（[golem-driver ADR 0043](../golem-driver/adr/0043-caption-sidenote-do-not-inherit-indent.md)）。

セルに当てる段落スタイルのうち、適用される欄は `caption` と同じとする。
PDF では `font`、`size`、`aki-set`、`kerning`、`tracking`、`proportional-metrics`、`baseline-shift` が、どの出力でも `regex-styles` が適用される。
`line-breaks`、`space-between`、`space-before`、`space-after`、`align`、字下げ、罫線、背景は適用されない。
セルの揃えは、今のとおり列の揃えで決める。
`@style` で `body` などの字下げを持つ段落スタイルを当てても、字下げは適用されない。
キャプションの段落スタイルを図版と同じ規則で黙って捨てているので、それに合わせる。

v1 でセルに当てる欄は、この小さい文字の表に要る、キャプションと同じ欄に限る。
セルに当てない欄（`line-breaks`、`space-between`、`space-before`、`space-after`、`align`、字下げ、罫線、背景と囲み）をセルに当てることは、v1.x の「表の拡張」で扱う（「メンテナーが決めること」の 7）。
見出しの行に本体と別の段落スタイルを当てることも、v1.x の「表の拡張」で扱う。

表のキャプションは、図版とコードブロックのキャプションと同じく `caption` で組む。

### 5. PDF

- キャプションは、`caption-position` の側に置く。`"above"` では表の上（縦組みでは右）、`"below"` では表の下（縦組みでは左）である。表番号と区切りとキャプションを、段落スタイル `caption` の見た目と段の行長で、段の行の始まりからそろえて組む。行の送りと格子の行の占め方は、コードブロックのキャプションと同じとする。
- `"above"` では、表の前の空き（[golem-driver ADR 0031](../golem-driver/adr/0031-table-spacing-and-rules.md)）をキャプションの前に置き、表の始まりの罫をキャプションと見出しの行のあいだに引く。`"below"` では、表の終わりの罫を本体の最後の行とキャプションのあいだに引き、表の後の空きをキャプションの後に置く。
- キャプションを、それに接する行と同じ段に置く。`"above"` では、キャプション、見出しの行、本体の最初の行を同じ段に置く（JLReq の 4.4.6）。収まらない位置からは、表をキャプションごと次の段に送る。`"below"` では、本体の最後の行とキャプションを同じ段に置く。収まらなければ、本体の最後の行の前で段を改め、次の段に、繰り返す見出しの行、本体の最後の行、キャプションを置く。見出しの行と本体の最初の行を同じ段に置く今の規則は、どちらの位置でも変わらない。
- キャプションとそれに接する行が空の段に収まらない場合は G07116 とし、表を組まない。`"above"` ではキャプション、見出しの行、本体の最初の行であり、`"below"` では見出しの行、本体の最後の行、キャプションである（本体が一行なら、その行が最初の行と最後の行を兼ねる）。キャプションのない表の見出しの行と本体の行が収まらない場合は、今の G07042 のままである。キャプションの行が加わることで初めて収まらなくなる原因を、G07042 と分ける。
- ページをまたいだ先では、見出しの行を今のとおり繰り返し、キャプションは繰り返さない。`"below"` のキャプションは、表の最後の部分にだけ置く。
- セルは、セルの段落スタイルの役割と大きさ（ts）で組む。版面の文字の大きさを fs、行送りを p とする。セルの行の送りは round(p × ts ÷ fs) とし、表の行は、その行の最も多くの行を持つセルの行の全体を収める最も少ない数の格子の行を占める（キャプションと同じ `headingBlock` の求め方）。セルの行は、表の行の最初の格子の行の先頭にそろえて置く。ts = fs なら、今と同じく一行が格子の一行になる。
- 罫の位置の求め方（`a`、`d`、`c`）は今のままとし、`a` と `d` を ts のグリフから求める。
- 列の間隔は、ts の一字分とする。
- 列の幅は次の 6 で決める。

### 6. 列の幅の決め方（golem-layout）

`Golem.Layout.Table` の `layoutTable` に列の幅の指定を渡し、次のように決める。
列が分け合う幅を W（行長 − 列の間隔の和）とする。

1. `auto` でない列の幅を sp で求める。`zw` は ts に掛け、`%` は W に掛け、どちらも sp の未満を切り捨てる。
2. 指定した幅の和が W を超えれば、G07114 とし、表を組まない。
3. 指定した幅が、その列のセルの最小の幅（`cellExtent` の最小の幅）より狭い列があれば、その列ごとに G07115 とし、表を組まない。
4. `auto` の列は、W から指定した幅の和を引いた残りを使える幅として、今の `columnWidths` で決める。`auto` の列の最小の幅の和が残りに収まらなければ、今の G07041 とする。
5. 指定のない表（`widths` が空）は、すべての列を `auto` とし、今と同じ幅になる。

G07114 と G07115 は、G07041 と同じく PDF を組むときにだけ出す。
指定した幅は、自然な幅より広くても狭くても、そのまま使う。
指定した幅の列に残りを配ることはしない。

### 7. HTML と EPUB

- キャプションのある表は、`<table>` の最初の子に `<caption>` を置き、表番号を `<span class="number">` に入れ、区切りとキャプションを続ける。見出しとコードブロックのキャプションと同じ形である。HTML の `<caption>` は表の最初の子に置く要素なので、`caption-position = "below"` でも置く位置は変えず、`style.css` の `table > caption` の規則に `caption-side: bottom` を書く。`"above"` では何も書かない。
- 列の幅の指定のある表は、`<colgroup>` に列ごとの `<col>` を置き、`auto` でない列に `style="width: ..."` を書く。`zw` は `em` に、寸法は図版の `width` と同じ写し方で、`%` は `%` にする。HTML の `%` は表の幅に対する割合なので、PDF の W とは基準が違う。指定のない表には `<colgroup>` を書かない。
- `table` でない段落スタイルを当てた表は、`<table>` に `ps-名前` の class を付ける。`style.css` には、`table` と、表に当てた段落スタイルの `font-family` と `font-size` を、`table.ps-名前 th, table.ps-名前 td`（`table` は class のない `table` の `th, td`）の規則に書く。`size` を CSS に書く場所に表を加える。
- タグ付き PDF では、キャプションを `Table` の `Caption` にする（ISO 32000-1 の 14.8.4 の標準の構造の型）。`"above"` では最初の子に、`"below"` では最後の子に置き、読む順を組んだ順に合わせる。`Caption` を `Table` の最後の子に置けることは、規格の本文で確かめていない。実装のときに veraPDF の PDF/UA-1 の検査で確かめ、通らなければ最初の子に置く。

### 8. プレーンテキスト

キャプションのある表は、`caption-position` が `"above"` なら行の前に、`"below"` なら行の後に、表番号、区切り、キャプションの一行を書く。
コードブロックのキャプションの行と同じ形である。

- **セルに当てない欄をセルに当てること**：v1 でセルに当てるのは、キャプションと同じ欄だけである。ほかの欄は v1.x の「表の拡張」に置く（2026-11-09 の tett23 の決定）。
- **表ごとのキャプションの位置**：v1 の `caption-position` は本ごとの値である。表ごとに変える属性は v1.x の「表の拡張」に置く。図版のキャプションの位置は v1.0.0 の「図版とキャプションの拡張」で扱う。
- **ページをまたいだ先でキャプションを繰り返すこと、表の続きを示す文言**：v1.x の「表の拡張」に残す。
- **表目次**：v2 の「目次の拡張」に残す。
- **表の行を格子から外して詰めること**：表の全体を格子の外で組めば、小さい文字の一行の行も詰まるが、ページ分割の要素を変える必要がある（「メンテナーが決めること」の 4）。
- **`@table` の `widths=` のキーワード引数**：`@column-widths` を `@table` にも付けられるので、書き方を一つにする。

## 不変条件

表番号の書式を F、セルの段落スタイルの大きさを ts、版面の文字の大きさを fs、列が分け合う幅を W とする。

- **I1 表番号の連番**：どの章でも、キャプションがあり `@nonumber` のない表は、文書の順に 1、2、… の番号を取る。ほかの表は番号を取らず、後の表の番号を変えない。
- **I2 数の独立**：図版、コードブロック、`@nonumber` の表を足しても除いても、ほかの表の番号は変わらない。
- **I3 参照**：番号のある表の `[ref-number]` は `章の番号-表の番号` を、`[ref-title]` はキャプションから索引の印とチャネルの項目を除いたものを返す。番号のない表の `[ref-number]` は G04005 を、キャプションのない表の `[ref-title]` は G04006 を、ちょうど一つ出す。
- **I4 既定で変わらない**：`@caption`、`@column-widths`、`@style` を付けず、`table` の段落スタイルを変えない本は、PDF、HTML、EPUB、プレーンテキストのバイト列が、この ADR の前と同じである。
- **I5 指定した幅**：G07114、G07115、G07041 のどれも出ない表では、指定した列の幅が 6 の 1 の値とちょうど等しく、列の幅の和と列の間隔の和が行長以下である。
- **I6 auto だけの表**：`widths` が空か、すべて `auto` の表の列の幅は、今の `columnWidths` に W と同じ範囲を渡した値と等しい。
- **I7 誤りの判定**：指定した幅の和が W を超えることと G07114 が出ることは同値である。指定した幅がその列の最小の幅より狭い列の数と、G07115 の数は等しい。
- **I8 キャプションを離さない**：G07116 の出ない表では、`caption-position` が `"above"` ならキャプションの最後の行、見出しの行、本体の最初の行が同じ段にあり、`"below"` なら本体の最後の行とキャプションの最初の行が同じ段にある。どちらの位置でも、キャプションの行はちょうど一つの段にあり、表の部分のうちちょうど一つだけがキャプションを持つ。
- **I9 格子の行**：どの表の行も、最も多くの行を持つセルの行の全体を収める最も少ない数の格子の行を占める。ts = fs なら、その数はセルの行の数に等しい。表の後の本文の行は格子の上にある。
- **I10 決定性**：同じ入力からは、同じ出力と、同じ順の同じ diagnostic を得る。
- **I11 位置は番号を変えない**：`caption-position` を `"above"` から `"below"` に変えても、どの表の番号、`[ref-number]`、`[ref-title]` の値も変わらない。

境界の入力：

| 量 | 調べる値 |
| --- | --- |
| 章の中の番号のある表 | 0、1、2、`@nonumber` の表を間に一つ |
| 章 | 章の中、章の外（F が `{chapter}` を使う、使わない） |
| `@column-widths` の値の数 | なし、1、列の数、列の数 − 1、列の数 + 1 |
| 列の数 | 1、2、3 |
| 指定した幅の和 | W − 1sp、W、W + 1sp |
| 指定した幅と最小の幅 | 最小の幅 − 1sp、最小の幅、自然な幅、自然な幅 + 1sp |
| `%` の和 | 99%、100%、101% |
| `auto` の列の残り | 最小の幅の和 − 1sp、最小の幅の和、自然な幅の和 |
| ts | fs、fs より小さい（キャプションと同じ比）、行送りの比で割り切れない値 |
| キャプションの行の数 | 0、1、段の行の数 − 見出しの行 − 本体の一行、それより一つ多い |
| ページの残り | キャプションと見出しの行と本体の一行がちょうど入る、一行足りない |
| `caption-position` | 書かない、`"above"`、`"below"`、ほかの値（G03006） |
| `"below"` の段の残り | 本体の最後の行とキャプションがちょうど入る、一行足りない、本体が一行だけの表 |

## テスト設計

テストを先に書き、今の実装で失敗することを確かめてから実装する。
テストの名前には不変条件の番号を入れる。

- **golem-doc のテスト**：新しい表の CBOR の往復と CDDL の検査、タグ 5 を読まないこと、Validate の四つの不変条件（`widths` の長さ、0 以下の幅、キャプションのない `nonumber`、`style` の `body`）がそれぞれ一つの違反を返すこと。
- **golem-eval のテスト**：`|` の表と `@table` の両方で、四つの属性が IR の欄になること。G02135（値ごと）、G02136、表でないブロックの `@column-widths` の G02013、キャプションのない表の `@nonumber` の G02134、未定義の段落スタイルの G02047。改行の様式で、属性が表の全体に付くこと。
- **golem-assemble のテスト**（I1、I2、I3）：表番号の数え方を、表、図版、コードブロック、`@nonumber`、章の見出しを並べた小さな文書のすべての並び（要素 5 個まで）で列挙し、I1 と I2 を述語で確かめる（[ADR 0204](0204-pagination-invariants-by-exhaustive-small-inputs.md) の `Golem.TestSupport.Enum`）。`[ref-number]` と `[ref-title]` と G04004、G04005、G04006、G04100 の例。
- **golem-layout のテスト**（I5、I6、I7）：`layoutTable` の列の幅を、列の数 1 から 3、最小の幅と自然な幅と指定した幅を小さな整数の組で列挙し、述語で確かめる。I6 は今の `columnWidths` の出力との一致として書く。
- **golem-typeset と golem-driver のテスト**（I4、I8、I9）：既定の本の PDF のバイト列が変わらないこと（今の golden を使う）。ts < fs の表の行の格子の行の数、キャプションと見出しの行と本体の最初の行が同じ段にあること、ページの残りの境界でキャプションごと送ること、G07116（キャプションのない同じ表では G07042 だけが出ること）、G07114、G07115。縦組みでキャプションが表の右にあること。`"below"` で、キャプションが表の下（縦組みでは左）にあり、段の残りの境界で本体の最後の行の前で段を改めること、空の段に見出しの行と最後の行とキャプションが入らない場合の G07116（I8）。golem-assemble のテストで、二つの位置で番号と参照が同じであること（I11）。golem-project のテストで、`caption-position` のほかの値が G03006 になること。
- **golem-html、golem-epub、golem-text のテスト**（I4）：`<caption>`、`"below"` の `caption-side: bottom`、`<colgroup>`、`ps-名前` の class と CSS、プレーンテキストのキャプションの行（上と下）、指定のない表の出力が変わらないこと。タグ付き PDF の `Caption`。
- **決定性**（I10）：diagnostics の順を固定するテスト。

## トレードオフ

キャプションを `@caption` の一行にすると、段落を二つ持つキャプションは書けない。
図版のキャプションは段落の並びなので、図版と表で書き方が分かれる。
表の記法は字下げした本体を持たないので、本体を足すより、コードブロックの書き方に合わせるほうが記法を増やさない。

表の行を格子の行に載せると、一行だけのセルの行は、文字を小さくしても行の高さが変わらない。
小さい文字で得るのは、列の幅に収まる字の数と、複数行のセルの行の高さだけである。
その代わり、ページ分割と、表の後の本文が格子に載ることは変わらない。

組み込みの段落スタイルに `table` を加えると、`style.toml` にすでに `[paragraph-styles.table]` を書いた本は、その定義がすべての表のセルに当たるようになる。
リリースノートに、互換を変える点として書く。

キャプションの位置は本ごとの値であり、一冊の中で表ごとに変えられない。
上と下が混ざる本は少ないと見て、IR の欄を増やさずに済む本ごとの設定にとどめた。

指定した幅より広い語のある列を、はみ出させずにエラーにすると、書き手は幅を広げるか語を改めるまで PDF を得られない。
はみ出した出力を黙って作らない原則を優先する。

## メンテナーが決めること

1. **キャプションの書き方**：推奨は、コードブロックと同じ `@caption 本文` の一行である。`|` の表と `@table` の両方に同じく書け、記法を増やさない。
   - 退けた案は、図版のように字下げした本体でキャプションを書くことである。`|` の表と `@table` には本体がなく、本体を新しく作ると、表の記法の作り直し（セルの結合の ADR）と重なる。
2. **番号を振る表**：推奨は、コードブロックと同じく、キャプションのある表にだけ振ることである。キャプションのない小さな表に番号が付かず、番号を外す `@nonumber` もほとんど要らない。
   - 退けた案は、図版のようにすべての表に振ることである。今の本のすべての表に番号が付き、出力が変わる。
3. **キャプションの位置**：推奨は、`[tables]` に `caption-position` を設け、既定を表の上とすることである（2026-11-09 の tett23 の決定で改めた）。JLReq の 4.4.6 がキャプションをヘッダー行の前に置く前提で書かれ、コードブロックのキャプションも上にあるので既定は上とし、下に置く本のために設定を設ける。下に置く表の分割の規則（本体の最後の行とキャプションを離さない）は、この ADR で決める。
   - 退けた案は、表の上に固定し、設定を作らないことである（草案の推奨）。下に置く本を組めず、使い手の組版の自由に応えない。
4. **小さい文字のセルの行と格子**：推奨は、表の行ごとに、キャプションと同じ求め方で格子の行に載せることである。ページ分割の要素（`FTable`）と不変条件を変えない。
   - 退けた案は、表の全体を格子の外で詰めて組み、表が占める格子の行の数だけを切り上げることである。一行の行も詰まるが、表の途中の改ページで格子の行と表の行が対応しなくなり、ページ分割の要素を作り直すことになる。
5. **セルの段落スタイル**：推奨は、組み込みの `table` を既定とし、表ごとに `@style` で替えられるようにすることである。`[paragraph-styles.table]` の一か所で本のすべての表を小さくでき、例外の表だけに `@style` を書く。
   - 退けた案の一つは、組み込みを作らず `@style` だけにすることである。小さい文字の表が多い本では、すべての表に `@style` を書くことになる。
   - もう一つは、組み込みの名前を `table-cell` にすることである。セルに当たることは明らかになるが、`caption`、`sidenote`、`code` が当てる対象の名前であることに合わせる。
6. **組み込みの `table` の既定の大きさ**：推奨は、本文と同じ大きさ（`body` を引き継ぐ）とし、今の出力を変えないことである。キャプションの既定も本文と同じである。
   - 退けた案は、JLReq の 4.4.3 の例に合わせて本文より小さくすることである。よい既定にはなるが、既存のすべての表の組み方が変わり、`caption` との釣り合い（キャプションも同じ大きさにする例）も同時に変えることになる。
7. **セルに当てる欄**：推奨は、v1 ではキャプションと同じ欄（`regex-styles` を含む）とし、「正規表現スタイルの届かない文字」から表のセルを消すことである。セルに当てないほかの欄は v1.x で扱う（2026-11-09 の tett23 の決定）。
   - 退けた案は、`font` と `size` だけを当てることである。文字の大きさの項目としては足りるが、段落スタイルの一部だけが適用される場所がもう一つ増える。
8. **列の幅の値の IR の形**：推奨は、`ColumnWidth` の型（単位ごとのコンストラクタ）である。アキの量（`AkiAmount`）と同じく、プラグインが単位を取り違えず、Validate が値の範囲を検査できる。
   - 退けた案は、図版の `width` と同じく書いた文字列で持つことである。読み取りが golem-typeset と golem-html に分かれ、プラグインが読めない文字列を返したときの検査が要る。
9. **`%` の基準**：推奨は、行長から列の間隔の和を引いた W である。`50% 50%` がちょうど収まる。
   - 退けた案は、図版と同じく行長とすることである。図版と揃うが、`%` の和が 100 の表がいつも列の間隔だけはみ出し、G07114 になる。
10. **指定した幅より広いセルの中身**：推奨は G07115 のエラーである。
    - 退けた案は、セルの中身を列の外にはみ出させて組み、notice で知らせることである。隣の列と字が重なる出力を作る。

コードの番号は、採択のときに、使われていない番号であり同じ時期の ADR と重ならないことを確かめて振り直した（「決めたことの記録」）。

## 決めたことの記録

2026-11-09 に、tett23 が次のとおり決めた。
tett23 は、基本的に使い手の組版の自由に応えたいと述べた。
下の 3、7、11 は、この方針による。

1. キャプションは、推奨のとおりコードブロックと同じ `@caption 本文` の一行で書く。
2. 表番号は、推奨のとおりキャプションのある表にだけ振る。
3. キャプションの位置は、v1 で指定できるようにする。草案の推奨（上に固定）を改め、`[tables]` の `caption-position`（`"above"` と `"below"`、既定 `"above"`）を設け、下に置くときの分割の規則と G07116 の範囲、HTML、タグ付き PDF、プレーンテキストの出力、不変条件の I8 と I11、境界の入力を足した。表ごとに位置を変える属性は v1.x の「表の拡張」に置いた。これは採択のときの判断であり、tett23 の言葉は「キャプションの位置は v1 で指定できるようにする」である。
4. 小さい文字のセルの行は、推奨のとおり表の行ごとにキャプションと同じ求め方で格子の行に載せる。
5. セルの段落スタイルは、推奨のとおり組み込みの `table` を既定とし、表ごとに `@style` で替えられるようにする。
6. 組み込みの `table` の既定の大きさは、推奨のとおり本文と同じとする。
7. セルに当てる欄は、v1 ではキャプションと同じ欄とし、ほかの欄は v1.x で対応する。docs/roadmap.md の v1.x の「表の拡張」に足した。
8. 列の幅の値の IR の形は、推奨のとおり `ColumnWidth` の型とする。
9. `%` の基準は、推奨のとおり行長から列の間隔の和を引いた W とする。
10. 指定した幅より広いセルの中身は、推奨のとおり G07115 のエラーとする。
11. 見出しの行に別の段落スタイルを当てることは、v1.x に足す。docs/roadmap.md の v1.x の「表の拡張」に足した。
12. diagnostic のコードは、採択のときに、docs/diagnostics.md と origin/main のコードで使われていない番号であり、同じ時期の ADR と重ならないことを確かめて、G02135、G02136、G04100、G07114、G07115、G07116 とした。
草案の仮の番号から振り直した。G04 の新しいコードは、docs/diagnostics.md の「番号の区分」のとおり 100 から振る。
