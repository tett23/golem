# ADR 0459: 続けて書いたブロックコマンドを一つのコマンドとし、字下げしない次のブロックと `:::` で囲んだブロックを本体として受け取る

Status: proposed

## 文脈

本体（最後の引数が `Blocks`）を受け取るブロックコマンドは、今は字下げした本体だけを受け取る。

```
@stage-direction
  雨の音。指定まで流す。
```

字下げせずに次の行に段落を書くと、ブロックコマンドと段落は属性のまとまりとして読まれる。
`stage-direction` は属性ではないので G02011（属性のまとまりに属性でないコマンドがあります）になり、段落は本体にならずに別に組まれる。

```
@stage-direction
雨の音。指定まで流す。
```

メンテナーは、2026-11-26 に、次のことを決めた。

- 本体を受け取るブロックコマンドは、字下げしない次のブロックを本体として受け取る。
  本体は一つのブロックであることが多く、字下げを要らなくするほうが書きやすいからである。
- 規則に例外を作らない。
  `@style` と `@lang` も、次のブロックを本体として受け取る。
- 続けて書いたブロックコマンドは、一つのコマンドになる。
- 二つ以上のブロックを字下げせずに本体にするときは、`:::` の行で囲む。
  直後の一つのブロックだけなら、`:::` を省ける。
  一つのブロックを `:::` で囲んでもよいが、情報の diagnostic を出す。

この ADR は、続けて書いたブロックコマンドの読み方、本体の三つの書き方、`:::` の文法を決める。
`@style` の本体に段落のほかのブロックを置けるようにすることは、[root ADR 0460](0460-let-style-take-any-blocks-as-its-body.md) で決める。

## 調査した事項

origin/main（[9e6755a](https://github.com/tett23/golem/commit/9e6755a380dc3ca7887c35f69a5e5bb36e1bf8f8)）で、次のことを確かめた。

### 文法

- 文法は、続けて書いたブロックコマンドの行と、その直後の空行を挟まない一つのブロックを、属性のまとまり（`BlockGroup`）として読む（[Golem.hpeg#L578-L592](https://github.com/tett23/golem/blob/9e6755a380dc3ca7887c35f69a5e5bb36e1bf8f8/modules/golem-parser/grammar/Golem.hpeg#L578-L592)）。
  直後のブロックになれるのは、見出し、箇条書き、番号付きの箇条書き、定義リスト、表、コードブロック、段落である。
  各ブロックコマンドは、字下げした本体を持てる（[Golem.hpeg#L593-L595](https://github.com/tett23/golem/blob/9e6755a380dc3ca7887c35f69a5e5bb36e1bf8f8/modules/golem-parser/grammar/Golem.hpeg#L593-L595)）。
- 段落は、空行でもブロックの始まりでもない行を続きの行にする（[Golem.hpeg#L269-L273](https://github.com/tett23/golem/blob/9e6755a380dc3ca7887c35f69a5e5bb36e1bf8f8/modules/golem-parser/grammar/Golem.hpeg#L269-L273)）。
  `paragraph-separator = "line"` のファイルでは、評価が段落のブロックを行ごとの段落に分ける。
- `:::` の読み方は文法に無く、`:::` だけの行は段落の本文である。
  `\` は、どの字の前に置いてもエスケープになる（[Golem.hpeg#L309-L310](https://github.com/tett23/golem/blob/9e6755a380dc3ca7887c35f69a5e5bb36e1bf8f8/modules/golem-parser/grammar/Golem.hpeg#L309-L310)）。

### 評価

- 評価は、属性のまとまりを三つの段で読む。
  - まず、ファイルの設定（`@manifest` など）をまとまりから抜いて G02049 とする（[File.hs#L1186-L1195](https://github.com/tett23/golem/blob/9e6755a380dc3ca7887c35f69a5e5bb36e1bf8f8/modules/golem-eval/src/Golem/Eval/File.hs#L1186-L1195)）。
  - 次に、改ページの仲間（`@page-break`、`@column-break`、`@no-page-break`、`@need-lines`、`@page-lines`、`@blank-line`、`@separator`）をまとまりから抜き、直後のブロックの前に置く（[File.hs#L1220-L1235](https://github.com/tett23/golem/blob/9e6755a380dc3ca7887c35f69a5e5bb36e1bf8f8/modules/golem-eval/src/Golem/Eval/File.hs#L1220-L1235)）。
  - 残りのまとまりに直後のブロックがあるとき、属性でないコマンドがあれば G02011 とし、属性だけを直後のブロックに付ける。
    直後のブロックが無く、最後が属性でないブロックコマンドで、その前がすべて属性なら、属性をそのコマンドの結果に付ける（[File.hs#L1237-L1255](https://github.com/tett23/golem/blob/9e6755a380dc3ca7887c35f69a5e5bb36e1bf8f8/modules/golem-eval/src/Golem/Eval/File.hs#L1237-L1255)）。
    同じ属性を二度書けば G02012 とする。
- `@note` と `@endnote` には属性を付けられず、属性を前に置くと G02013 になる（[File.hs#L1261-L1266](https://github.com/tett23/golem/blob/9e6755a380dc3ca7887c35f69a5e5bb36e1bf8f8/modules/golem-eval/src/Golem/Eval/File.hs#L1261-L1266)）。
- `@style` を表に付けると、表のセルの段落スタイルになる（[File.hs#L1632-L1638](https://github.com/tett23/golem/blob/9e6755a380dc3ca7887c35f69a5e5bb36e1bf8f8/modules/golem-eval/src/Golem/Eval/File.hs#L1632-L1638)）。
  `@style` を `@printings` に付けると、奥付の各段落に段落スタイルを当てる。
- 本体を受け取る組み込みのブロックコマンドは、`@note`、`@endnote`、`@frame`、`@style`、`@lang` である（[File.hs#L693-L715](https://github.com/tett23/golem/blob/9e6755a380dc3ca7887c35f69a5e5bb36e1bf8f8/modules/golem-eval/src/Golem/Eval/File.hs#L693-L715)）。
  `@style` と `@lang` は、本体が無ければ属性として次のブロックか、後のコマンドの結果に付く。
- `.emet` の関数は、本体を受け取るかを関数の表に持つ。
  プラグインのブロックコマンドは、どれも本体のブロックを受け取る。

### 実行

2026-11-26 にビルドした `golem`（main の 9e6755a38）で、`golem inspect --as ir` の結果を比べた（文字の位置を除いて比べた）。

- `@stage-direction`（`pub block "stage-direction" stageDirection :: Blocks -> Blocks`）と次の行の段落は、G02011 になった。
- `@style stage` と次の行の段落、`@lang en` と次の行の段落は、属性として付けた結果と、字下げした本体として受け取った結果が同じだった。
- `@style quote` と次の行の箇条書き、`@style quote` と次の行のコードブロックは、属性として読むと G02013 でブロックが出力に残り、字下げした本体として読むと G02045（`@style` の本体には段落だけを置けます）でブロックが出力されなかった。
- `paragraph-separator = "line"` のファイルで、`@style quote` と二行の段落は、属性の形では一行目の段落にだけスタイルが付き、字下げした本体の形では二つの段落の両方に付いた。
  `@lang en` も同じだった。
- `@style quote`、`@lang en`、字下げした段落は、段落に言語は付くがスタイルは付かず、diagnostic も出なかった。
  同じ二つを字下げしない段落に付けた今の属性の形では、スタイルと言語の両方が付いた。
- 精読で、次のことも確かめた。
  - `@style quote` と次の行の表は、エラーなしで表のセルの段落スタイルが `quote` になった。
  - `@lang en` と次の行の `@toc` は、エラーなしで目次に言語が付いた。
  - `@lang en` と次の行の見出しは、エラーなしで見出しに言語が付いた。
  - `@label x` の次の行の `:::` は、ラベルの付いた段落 `:::` になった。
    `\:::` は段落 `:::` になった。

## 実装すること

### コマンドの種類

まとまりのコマンドを、評価がその位置でその名前を解いた先によって、次の三つに分ける。

- **本体を受け取るコマンド**：`.emet` の `pub block` のうち最後の引数が `Blocks` のもの（名前空間つきの呼び出し、名前を並べて取り込んだ呼び出し、[root ADR 0453](0453-override-built-in-commands-by-listed-imports-and-plugins.md) の上書きを含む）、プラグインのブロックコマンド（`block-overrides` の上書きを含む）、組み込みの `@note`、`@endnote`、`@frame`、`@style`、`@lang`。
- **属性**：本体を受け取らない属性（`@label`、`@number`、`@nonumber`、`@notoc`、`@toc-title`、`@caption`、`@column-widths`）。
- **出すだけのコマンド**：本体を受け取らず、属性でもないコマンド（`@set`、`@toc`、`@index`、`@bibliography`、`@channel`、`@printings`、`@figure`、`@table`、`@listing`、最後の引数が `Blocks` でない `pub block` など）。

ファイルの設定と改ページの仲間は、今と同じく、まとまりを読む前に抜く。

呼び出しを解いた先が分からない名前は、出すだけのコマンドとして扱い、何も出力しない。
分からない名前は、何も報告しない名前として取り込んだ名前（読み込めない `.emet` から並べた名前、G02272 の名前）、読み込めない `.emet` の名前空間つきの名前、プラグインの読み込みか検査に誤りがあって未知になった名前である。
そのまとまりでは、G02011 と G02123 を出さない。
誤りの元は、`.emet`、プラグイン、G02272 の側で報告するので、同じ原因から誤りを重ねないためである。

### 続けて書いたコマンドを一つのコマンドとして読む

設定と改ページの仲間を抜いた後のまとまりのコマンドを、書いた順に c1、c2、…、cn とする。
まとまりは、後に書いたコマンドほど内側にある、一つのコマンドとして読む。
各コマンド ci は、一つ内側の結果 Ri+1 を受け取り、自分の結果 Ri を返す。
まとまりの結果は R1 である。

- 本体を受け取るコマンドは、Ri+1 を本体として受け取る。
- 属性は、Ri+1 の最初のブロックに付く。
  属性を付けられないブロックなら、今と同じく G02013 とする。
- 出すだけのコマンドは、一番内側（cn）に置いたときだけ使える。
  cn が出すだけのコマンドなら、Rn はそのコマンドの出力である。
  出すだけのコマンドを一番内側でない位置に置けば、そのコマンドを書いた位置で評価して出力を前に置く。
  そのコマンドより外側に属性があれば、今と同じく G02011 とする。
  外側に属性が無ければ、今と同じく G02011 を出さない（続けて書いた `@set` や `@import` の行は、今と同じくエラーにならない）。

一番内側の結果 Rn+1 は、まとまりの本体である（次の節）。
本体が無ければ、cn の結果から始める（cn が本体を受け取るコマンドで本体が無ければ、今と同じく、そのコマンドの本体の無いときの diagnostic にする）。

- `@note` と `@endnote` の外側に、属性、`@style`、`@lang` を置けば、今と同じく G02013 とする。
- 同じ属性か、同じ `@style` か `@lang` を一つのまとまりに二度書けば、今と同じく G02012 とする。
- `@style` を、本体を受け取るほかのコマンドの外側に置いたとき、スタイルは、内側の結果の段落に当てる（0460 の当て方）。
  内側が、属性、`@lang`、原稿に書いたブロックだけのとき、`@style` は段落スタイルを渡してそのブロックを評価するので、段落スタイルの行の扱い（`line-breaks = "keep"` など）も今と同じく当たる。

この読み方は、今の属性のまとまりの読み方を含む。
属性だけのまとまりと直後のブロックは、属性が直後のブロックに付く。
属性と、最後の出すだけのコマンドのまとまりは、属性がそのコマンドの出力に付く。
`@style` と `@lang` を属性として付けた今の原稿は、`@style` と `@lang` が内側の結果を本体として受け取り、段落、表、見出し、`@toc` などの出力に同じく付く。

### 本体の三つの書き方

まとまりの本体は、次の三つの書き方のどれかで書く。

1. **字下げした本体**：今と同じ。
   cn の行の後に、字下げして書く。
   字下げした本体は、cn の本体である。
   c1 から cn−1 のどれかが字下げした本体を持てば、そのコマンドは自分の本体を受け取り、まとまりは、そのコマンドで分かれる（そのコマンドまでで一つのまとまり、その後で次のまとまり）。
2. **直後の一つのブロック**：cn の行のすぐ次の行から書いた、一つのブロック。
   見出しも含む。
   空行を挟まずに続けた行は、一つのブロックである。
   cn が字下げした本体を持つときは、直後のブロックはまとまりに含めず、ふつうのブロックとして組む。
3. **`:::` で囲んだブロック**：cn の行のすぐ次の行に `:::` だけの行を置き、本体のブロックを書き、`:::` だけの行で閉じる。

cn が出すだけのコマンドで、直後のブロックがあるときは、今と同じく G02011 とし、直後のブロックはふつうのブロックとして組む。
cn が出すだけのコマンドで、`:::` で囲んだブロックがあるときは、G02123（本体を受け取らないコマンドに本体を書いた）とし、囲んだ中はふつうのブロックとして順に組む。
設定と改ページの仲間を抜いた後にコマンドが残らないまとまりに、`:::` で囲んだブロックがあるときも、G02123 とし、囲んだ中はふつうのブロックとして順に組む。

段落の区切りは、どの書き方でも、そのファイルの段落の様式に従う。
`paragraph-separator = "line"` なら、本体の段落のブロックの行ごとに一つの段落になる。

### `:::` の文法

- 開く行は、ブロックコマンドの行（`@set` の行を含む）のすぐ次にある、そのコマンドと同じ字下げの `:::` だけの行である。
  行末の空白は無視する。
- 開いた中では、開いた行と同じ字下げの `:::` だけの行は、段落を終え、閉じる行になる。
  ただし、その行がブロックコマンドの行のすぐ次にあれば、入れ子の開く行になる。
  コードブロックの中の行は、閉じる行として数えない。
- 開いた中の最後のブロックがブロックコマンドの行のとき、閉じる行の前に空行を一つ置く。
  空行が無ければ、その `:::` は入れ子の開く行になる。
- 開いた中には、見出しと空行を含む、どのブロックも書ける。
- 閉じる行が無いまま、そのファイルか、外側の本体が終われば、G01030（エラー）とする。
  位置は開いた行で、メッセージは `::: を閉じる行がありません。ブロックコマンドの直後で閉じるときは、閉じる行の前に空行を置きます` とする。
  開いた中は、そのファイルか外側の本体の終わりまでを本体として読む。
- 開いた中が一つのブロックだけのとき、G01031（情報）とする。
  位置は開いた行で、メッセージは `::: で囲まなくても、直後の一つのブロックは本体になります` とする。
- 開く行の位置でも閉じる行の位置でもない `:::` だけの行は、今と同じく段落の本文として読む。
  開く行か閉じる行の位置に本文として `:::` を書くときは、`\:::` と書く。

### 今の原稿で変わる出力

次の原稿は、エラーが無くても、出力が変わる。

- `paragraph-separator = "line"` のファイルで、`@style` か `@lang` の次の行から二行以上の段落を続けた原稿。
  今は一行目の段落にだけ付き、この ADR の後は、すべての行の段落に付く。
- 本体を持つブロックコマンドの外側に `@style` を置いた原稿（字下げした本体を含む）。
  今はスタイルが付かず、この ADR の後は付く。
- ブロックコマンドの行のすぐ次の行の `:::` を、本文として書いた原稿。
  今は本文で、この ADR の後は開く行になる。

次の原稿は、エラーの扱いが変わる。

- `@style` の次の行に、箇条書き、番号付きの箇条書き、定義リスト、コードブロックを続けた原稿。
  今は G02013 でブロックが出力に残る。
  0460 の後は、エラーでなくなる。
- 本体を受け取るコマンドの次の行に、字下げせずに段落などを続けた原稿。
  今は G02011 で、この ADR の後は本体になる。
- `@style` の次の行に見出しか `@toc` を続けた原稿。
  今は G02013 で、この ADR と 0460 の後は、見出しや目次をそのまま出し、段落も表も無いので G02046 になる。
- 字下げした本体を持つコマンドの直後に、空行なしでブロックを続けた原稿。
  今は G02011 で、この ADR の後は、続けたブロックをふつうのブロックとして組み、エラーにしない。

0460 は、この ADR と同じプルリクエストで実装する。
`@style` を外側に置いた組み合わせと、本体のブロックの当て方は、0460 が無いと成り立たないためである。

### ツール

- **golem fmt**：三つの書き方を、そのまま残す。
  `:::` で囲んだ中は、字下げしない本体として整形する。
- **LSP**：本体にしたブロックの中の補完と定義への移動は、字下げした本体と同じに扱う。
  `:::` の範囲を折りたたみの範囲として返す。
- **semantic tokens**：`:::` の開く行と閉じる行を、区切りの記号として色付けする。

### 文書

仕様書のブロックコマンドの本体の記述と、属性のまとまりの記述を、この ADR の読み方に書き改める。
`docs/markup.md` とマニュアルに、三つの書き方と `:::` を書く。
`docs/diagnostics.md` に G01030 と G01031 を足し、G02011、G02012、G02013、G02045、G02123 の説明を、この ADR に合わせる。
マニュアルと見本の原稿のうち、今の原稿で変わる出力に当たるものを探し、変わった結果を見た目の回帰テストの参照で確かめる。

## 実装しないこと

本体を受け取らない属性の意味は変えない。
G02011 のコードと文言は変えない。
`:::` に、名前や引数を書く書き方は足さない。

## 不変条件

ここで「diagnostics が同じ」とは、diagnostics のコードと、その diagnostic が指すブロックが同じことを言う（書き方の分だけ位置はずれる）。

- I1: まとまり G とブロック B について、G の次の行に字下げせずに B を書いた原稿、B を `:::` で囲んだ原稿、B を cn の字下げした本体に書いた原稿の出力は同じである。
  diagnostics は、`:::` で囲んだ原稿にだけ G01031 が一つ加わり、ほかは同じである。
- I2: 本体を受け取るコマンドだけを c1 から cn まで続けたまとまりの出力は、各コマンドの本体に一つ後のコマンドを字下げして入れ子に書き、cn の本体に B を書いた原稿の出力と同じである。
  属性を含むまとまりの出力は、属性を除いたまとまりの出力の最初のブロックに、その属性を付けたものと同じである。
- I3: 二つ以上のブロックを `:::` で囲んだ原稿の出力と diagnostics は、同じブロックを cn の字下げした本体に書いた原稿と同じである。
- I4: 閉じない `:::` の囲みごとに、G01030 がちょうど一つ、その開いた行の位置に出る。
- I5: この ADR の前にエラーの無かった原稿のうち、今の原稿で変わる出力に当たらないものの出力は、この ADR の後も同じである。
- I6: 出すだけのコマンドを一番内側でない位置に置き、それより外側に属性を置いたまとまりでは、G02011 がちょうど一つ出る。
  外側に属性が無ければ、G02011 は出ない。
- I7: `golem fmt` は、三つの書き方を変えず、整形した原稿の出力と diagnostics は整形の前と同じである。

## テスト設計

root ADR 0459 I1 から I7 を名前の先頭に置いたテストを足す。
golem-parser のテストで、`:::` の開く行、閉じる行、入れ子、空行の要る閉じ方、コードブロックの中、閉じない場合（I4）、開く行の位置でない `:::`（I5）を確かめる。
golem-eval のテストで、表の入力を、三つの書き方と字下げした入れ子の原稿の組にして評価し、出力と diagnostics を比べる（I1、I2、I3、I5、I6）。
I5 は、今ある見本とテストの原稿に加え、表の「今と同じ」の行の入力で確かめる。
プラグインのブロックコマンドの場合は、golem-driver のプラグインのテストで確かめる。
golem-fmt のテストで I7 を、golem-lsp のテストで本体の中の補完、定義への移動、`:::` の折りたたみを確かめる。
今の原稿で変わる出力は、マニュアルと見本の見た目の回帰テストの参照の差分で確かめ、差分をプルリクエストに書く。
テストは、実装の前に書いて落ちることを確かめる。

## トレードオフ

字下げしない本体を受け取るので、原稿の見た目からは、次のブロックが本体か、ふつうのブロックかが分からない。
どちらになるかは、コマンドが本体を受け取るかで決まり、そのためにはコマンドの定義を見る必要がある。
本体は一つのブロックであることが多いので、書きやすさを優先した。

続けて書いたコマンドを、外側から内側への一つのコマンドとして読むので、属性、`@style`、`@lang`、本体を受け取るコマンドが一つの規則で読める。
その代わりに、`@style` と `@lang` を例外にしないことで、今の原稿で出力の変わるものがある（今の原稿で変わる出力）。
変わるのは、行ごとに段落を区切るファイルの二行目以降と、本体を持つコマンドの外側の `@style` と、ブロックコマンドの直後の本文の `:::` で、前の二つは書き手の意図に近づく変更である。

`:::` を開く記号と閉じる記号に共に使うので、ブロックコマンドの行で終わる本体は、閉じる行の前に空行が要る。
記号を分ければ空行は要らないが、メンテナーは `:::` にそろえることを選んだ。

見出しも直後の一つのブロックとして本体にするので、ブロックコマンドの直後に見出しを書くと、見出しがそのコマンドの本体になる。
今の属性も直後の見出しに付くので、読み方は属性とそろう。

解いた先が分からない名前は本体を受け取らないので、`.emet` の型の誤りを直したときに、次のブロックが本体に変わることがある。
その間は誤りのある原稿なので、ブロックを消さずに残すほうを選んだ。
