# ADR 0220: 機能を組み合わせた二冊のページの数の範囲を 16 から 32 に改め、テストで確かめる

ステータス: 採択

## 文脈

[ADR 0175](0175-complex-typesetting-fixture.md) は、機能を組み合わせた二冊の fixture（`complex-vertical` と `complex-horizontal`）を作り、一冊を 16 ページから 24 ページとした（「メンテナーが決めること」の 3）。
理由は二つで、相互作用を起こすのに要るのはページと段の境、目次と索引のページ番号、柱の切り替わりであってページの数ではないこと、ページが増えるほどゴールデンの差分が読めなくなり CI の時間も増えることである。

今の `complex-vertical` は 25 ページで、範囲を一つ超えている。
2026-11-08 のレビューは、これを [ADR 0175](0175-complex-typesetting-fixture.md) の違反とした。

### ページの数の移り変わり

見た目の回帰テストの参照（`scripts/visual/pages/complex-vertical.txt`、一行が一ページ）の行の数を、コミットごとに数えた。

| コミット | 内容 | 縦組み | 横組み |
| --- | --- | --- | --- |
| `af9d79bc` | 二冊を加えた（[ADR 0175](0175-complex-typesetting-fixture.md)） | 23 | 16 |
| `9f6e6031` | 幅を持つ図版（[ADR 0190](0190-non-wrapping-figure-width.md)） | 23 | 16 |
| `4ceefb13` | 段落の前後のアキ（[ADR 0189](0189-paragraph-alignment-spacing-and-end-indent.md)） | 25 | 18 |
| `890bafe3` | [ADR 0177](0177-note-mark-style-and-numerals.md) | 25 | 18 |

[ADR 0189](0189-paragraph-alignment-spacing-and-end-indent.md) の実装で変わったページを受け入れた `4ceefb13` で、両方の本が 2 ページずつ増えた。
このコミットは、範囲を超えたことに触れていない。
ページの数を確かめるテストがないので、CI は止まらなかった。
`ComplexFixtureSpec` は原稿の記法だけを読み、出力のページを数えない（[`ComplexFixtureSpec.hs`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-driver/test/ComplexFixtureSpec.hs#L1-L12)）。

### 2 ページずつ増える理由

`complex-vertical` を組み、`pages.json` で各ページの始まりを読んだ（origin/main の `f366145c` を組んだ `golem`、2026-11-08）。
段の行の数は 15 である。

| ページ | 中身 |
| --- | --- |
| 1 | 扉 |
| 2 | 白ページ（目次を奇数ページから始めるため） |
| 3〜4 | 目次 |
| 5〜10 | 一章 |
| 11〜18 | 二章（16 ページは行を持たない、回した図版のページ） |
| 19〜24 | 三章 |
| 25 | 索引 |

`style.toml` の `[headings.1]` は `page-break = "recto"` で、目次、三つの章、索引のどれも奇数ページから始まる。
ある章が 1 ページ伸びると、次の章の前に白ページが一つ入り、本は 2 ページ伸びる。
逆に、範囲に戻すために 1 ページ分を削っても、白ページが一つ増えるだけで、本は短くならない。
24 ページ以下に戻すには、索引を 23 ページから始める必要があり、二章か三章を 2 ページ（30 行、約 1,200 字）削ることになる。

### 範囲の上限が守っていたもの

[ADR 0175](0175-complex-typesetting-fixture.md) は、ゴールデンの PDF を一冊 100 KB 前後と見込んだ（推測であり、測っていない、と書いている）。
今のゴールデンは、`pdf-complex-vertical.txt` が 417,996 バイト（25 ページ）、`pdf-complex-horizontal.txt` が 504,897 バイト（18 ページ）である。
横組みの本は縦組みより 7 ページ少ないのに大きい。
ゴールデンの大きさは、ページの数よりも、ページに描く命令の数で決まっている。
差分の読みやすさは、変更が動かすページの数で決まり、本の総ページ数が 24 から 25 になっても変わらない。

## 実装すること

- 一冊のページの数の範囲を、16 ページ以上 32 ページ以下に改める。
- `OutputGoldenSpec` で二冊の PDF を組むとき、ページの数がこの範囲にあることを断言する。範囲の外なら、ページの数と範囲をメッセージに書いて失敗させる。断言はゴールデンの比較より前に置き、`--accept` で参照を書き直しても通らないようにする。
- fixture の README（`modules/golem-driver/test/fixtures/README.md` の「Each book is 16 to 24 pages」）を改める。
- [ADR 0175](0175-complex-typesetting-fixture.md) のステータスの行に、ページの数の範囲はこの ADR、と足す。

## 実装しないこと

- **原稿を削って 24 ページに戻すこと**（「メンテナーが決めること」の 1）。
- **ページの数をちょうどの値で固定すること**：ゴールデンと見た目の回帰テストの参照が、すでにページをすべて固定している。
- **白ページを数えないこと**：白ページもゴールデンと CI の描画の時間に入るので、PDF のページをそのまま数える。
- **ゴールデンの大きさの上限**：大きさを決めるのは描く命令の数で、別の決定になる。

## 不変条件

- **N1**：`complex-vertical` と `complex-horizontal` の PDF のページの数は、どちらも 16 以上 32 以下である。
- **N2**：N1 を破る変更では、`OutputGoldenSpec` が、ゴールデンを `--accept` で書き直した後も失敗する。

境界の入力：

| 量 | 調べる値 |
| --- | --- |
| ページの数 | 15、16、32、33 |

## テスト設計

- 範囲の断言を、ページの数を受け取る関数として書き、境界の入力の表の四つの値で、15 と 33 だけが失敗することを確かめる。
- 断言を加えた `OutputGoldenSpec` が、今の二冊（25 ページと 18 ページ）で通ることを確かめる。今の 24 ページの上限で断言を書けば、`complex-vertical` で失敗することも、実装の前に確かめる。
- N2：作業用の写しで `complex-vertical` の三章に 3 ページ分の段落を足し、`--accept` を付けても `OutputGoldenSpec` が失敗することを手で確かめ、プルリクエストの説明に書く。

## トレードオフ

- 上限を緩めるので、二冊は今より 7 ページまで伸びうる。章が奇数ページから始まるので、伸びるのは 2 ページずつになる。
- 上限を ADR で決めた後で、実装に合わせて改めることになる。ただ、今の上限は白ページによって 2 ページ刻みでしか守れず、1 ページ分の変化で範囲を外れる。
- テストが一つ増え、二冊のページの数を変える ADR は、範囲を超えるなら ADR を書く必要がある。

## メンテナーが決めること

1. **範囲を守る方法**：推奨は、上限を 32 に改め、ページの数をテストで確かめることである。上限が守っていた差分の読みやすさは、総ページ数では決まっていない（「文脈」）。32 は下限 16 の 2 倍で、今の 25 ページから、章の伸び 2 ページ分が 3 回入る余地がある。
   - 退けた案の一つは、二章か三章を 2 ページ削って 24 ページに戻し、テストを足すことである。白ページの仕組みで 1 ページでは足りず、約 1,200 字を削ることになる。削る段落には、ページをまたぐコードブロックや罫線を持つ段落のように、[ADR 0175](0175-complex-typesetting-fixture.md) が求める境の相互作用を持つものが多い。次に組みを変える ADR で、また範囲を外れやすい。
   - 二つめは、`[headings.1]` の `page-break = "recto"` を外して白ページをなくすことである。奇数ページから始める見出しと柱の相互作用を、fixture から外すことになる。
   - 三つめは、上限をなくすことである。ページの数を確かめるものがなくなり、今回のように範囲を外れても誰も気付かない。
2. **確かめる場所**：推奨は、二冊を実際のフォントで組む `OutputGoldenSpec` で断言することである。
   - 退けた案の一つは、`ComplexFixtureSpec` に置くことである。このモジュールは原稿だけを読み、組まない。
   - 二つめは、`scripts/visual/pages/` の参照の行の数を数える CI の検査にすることである。参照はゴールデンと同じく書き直せるので、書き直しと同時に範囲を外れても止まらない。

## 決めたことの記録

- **「メンテナーが決めること」のすべて**（2026-11-08、メンテナー）：どれも推奨のとおりとした。
