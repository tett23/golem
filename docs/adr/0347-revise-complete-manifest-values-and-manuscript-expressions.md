# ADR 0347: 原稿の入力位置と設定の欄に合う候補を返す

ステータス: 採択（未実装）

## 文脈

本案は [Golem ADR 0334](0334-complete-manifest-values-and-manuscript-expressions.md) の決定とテスト設計を改める。

原稿の式で文字数を求めたいとき、書き手は関数の名前と、何を数える関数なのかを知りたい。
設定で段落の区切り方を選ぶときは、その欄に書ける値を知りたい。
[ロードマップ](../roadmap.md) はこの二つを LSP の入力補完で扱う。

[Golem ADR 0169](0169-lsp-completion-in-style-and-preflight-toml.md) は style.toml と preflight.toml の値を補完する。
manifest.toml は対象外だった。
[Golem ADR 0162](0162-calling-emet-functions-from-gm.md) は原稿から呼ぶ Emet の関数を、名前空間に続くピリオドで補完する。
これらの候補を引き続き使う。

## 調査した事項

基準コミットのサーバーに UTF-16 で問い合わせると、新しいプロトコル試験 5 件のうち 4 件が失敗した。
絵文字の後のインライン命令は既存の実装で通った。
試作を加えた後は、既存の LSP テストを含む 197 件が通った。
コマンドと各項目に対応するテストは、未コミットの試作の `experiments/lsp-completion/README.md` に記録した。

試作では同一行のエスケープ、式中の文字列、閉じた式、配列を含む式を確かめた。

試作では複数行のコードブロックの境界と各エディターで説明を表示する操作は未検証である。

既存の設定スキーマの全葉とデコーダーを自動で突き合わせるテストは今回追加していない。

試作では段落区切りと PDF 宣言の綴りを読み取り処理と共有し、役割、数の表記、diagnostic コードは既存の一覧を使う。

## 実装すること

プロジェクト直下の manifest.toml では、書きかけの値の位置から欄を特定する。
段落区切りには `blank-line` と `line`、PDF/A 宣言には `2a`、PDF/UA 宣言には `1` を返す。
引用符の外なら文字列を二重引用符で囲む。
引用符の中なら中身だけを返す。
編集中の設定はエディターが持つ本文を読む。

原稿の行頭の `@` にはブロック命令、本文の `[` にはインライン命令、`[=` の式には組み込みの定数と関数を返す。
命令の引数と `meta.`、`vars.`、Emet の名前空間には、それぞれ従来の候補を返す。
説明のある候補は `CompletionItem.documentation` にプレーンテキストを入れる。
Emet の公開関数は宣言の署名を表示する。

### 設定欄ごとの範囲

| 設定と欄 | 採択時に返す候補 | 候補の出所 |
| --- | --- | --- |
| style.toml と preflight.toml の列挙と列挙の配列要素 | スキーマに並ぶ語 | 既存の `LEnum` と `NArray` |
| 同じ 2 ファイルの真偽値の欄と偽だけを許す欄 | 引用符の外で `true` と `false`、または `false` だけ | 既存の `LBoolean` と `LFalse` |
| 同じ 2 ファイルの名前参照 | 欄が指せる名前 | 既存の `LRef` |
| manifest.toml の `source.paragraph-separator`、章ごとの同名の欄 | 段落の区切り方 2 語 | 原稿設定の読み取りに使う表 |
| 章の `page-numbering.style` | 数の表記 12 語 | 数の表記の一覧 |
| `metadata.creators` と `metadata.contributors` の各 `role` | 役割 9 語 | 役割を表す型と `roleWord` |
| `targets.pdf.pdfa`、`targets.pdf.pdfua` | 各 1 語 | PDF 宣言の読み取りに使う表 |
| `targets.text.variants` の各要素 | 出力の向き 2 語 | テキスト出力で使われる向き |
| `diagnostics.silence-notices`、`diagnostics.silence-info` の各要素 | 欄ごとに抑制できるコード | `noticeCodes` と `infoCodes` |
| manifest.toml の `vars`、言語タグ、パス、数値、日付 | 0 個 | 入力できる値を列挙しない |

`variants` の読み取り処理は文字列を受け取り、出力に使う向きだけを拾う。
候補は出力に使う 2 語とし、未知の語を拒む変更は加えない。
`vars` は真偽値も書ける自由入力欄なので、真偽値専用の欄には数えない。
今回調べた設定ファイルはこの 3 ファイルである。
プラグイン独自の設定や生成ファイルは対象の一覧に加えていない。

## 実装しないこと

設定に新しい値を導入すること、自由入力欄に値を推測して並べること、式の戻り値の型で候補を順位付けすることは扱わない。
[Golem ADR 0346](0346-revise-named-layout-values.md) は、名前の宣言と参照先の型を扱う。
型に合う名前を値の位置で候補に加える。
名前の変更も同提案に従う。

## 不変条件

1. T1。対象の設定欄の候補をその欄の TOML 値として読むと、表に挙げた候補の集合に一致する。編集中のファイルで同じ位置を問い合わせれば、ディスクへの保存の有無で候補は変わらない。
2. M1。命令名、式の名前、命令の引数の位置で候補を混ぜない。通常の本文とコードブロックの内部では空のリストを返す。
3. D1。説明のある候補は名前と説明を別々のフィールドで返す。説明は挿入する文字に含めない。

| 書きかけの末尾 | 候補 |
| --- | --- |
| `[metadata]` の `language = ` | 0 個 |
| `[targets.pdf]` の `pdfa = ` | `"2a"` の 1 個 |
| `[source]` の `paragraph-separator = "` | `blank-line` と `line` |
| 真偽値専用欄の裸の値、引用符内 | 前者は真と偽、後者は候補なし |
| 列挙の配列の要素 | 挿入後に読んだ候補の集合はその欄の列挙値と一致 |
| 行頭の `@` | `page-break` を含む |
| 本文の絵文字に続く `[` | `strong` を含む |
| `[= ` | 定数 `pi`、関数 `len` を含む |

## テスト設計

T1 は対象の各設定ファイルで表の全欄を列挙し、スカラーと配列要素を区別して補完を要求する。
カーソル以外が完成した設定例に候補を適用して TOML として読み、値の集合を表の出所と双方向に照合する。
真偽値は裸の値と引用符内の両方、列挙配列は要素の内外、自由入力欄は候補ゼロを調べる。
D1 は候補の説明と編集後の本文を別々に照合する。
テスト名に T1、M1、D1 の対応する番号を入れる。
UTF-16 を選んだクライアントから `textDocument/completion` を送り、ラベル、説明、候補が空になる位置を調べる。
未保存の manifest.toml で対象の表を変えて再度問い合わせる。
Emet の署名は公開したものと照合する。

M1 は命令名、命令の引数、式の名前、`meta.`、`vars.`、Emet の各名前空間を対照し、それぞれの位置で期待する候補だけが返ることを検査する。
さらにコードブロックの中に行頭の `@` と `[=` を書き、閉じた直後に通常の補完へ戻るところまで検査する。

## トレードオフ

説明を最初の応答に入れると、候補を選んだ後にサーバーへ問い合わせずに読める。
候補数に応じて署名を送る量が増える。
`completionItem/resolve` を使う案は最初の応答を短くできるが、選んだ候補を後から識別する仕組みが要る。

設定の候補を LSP だけに書く案では、設定の読み取りと二重に語を管理する。
