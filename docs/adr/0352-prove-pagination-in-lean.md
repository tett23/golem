# ADR 0352: 改ページの規則と終了を Lean 4 で証明する

ステータス: 採択（未実装）

## 文脈

[改ページの Alloy モデル](../golem-layout/models/pagination.als) は、一つの段に何を置き、何を次の段に送るかについて、指定した範囲で規則の両立を調べる。
Lean 4 では一般化できる性質を上限なしで証明し、各段での判断と有限の原稿全体の終了を結び付ける。

## 調査した事項

現行のモデルは段の容量を 3〜6 行に限り、図版を高々二つ、空行を高々一つに限る。
[通常の期待値](../golem-layout/models/expected.txt) に 28 件、[夜間の期待値](../golem-layout/models/nightly.txt) に 14 件あり、コマンドごとに解があるかを記録している。
解は、配置の実例を表す場合も、複数の規則を同時に満たす配置がない反例を表す場合もある。
たとえば tallFigure には、空の 6 行の段に縮小前の 7 行の図版を渡すと収まりと図版送りの規則を同時に満たせない例がある。

Golem は図版のキャプションを段の行長で行分割する。
画像に残る高さから縮小率を決め、キャプションだけで段が埋まると G07038 を出す。
規則と反例の対応は [モデルの検査結果](../golem-layout/models/README.md) に記録されている。

## 実装すること

既存の 42 件について、元の述語、入力の前提、配置についての量化、期待する結果を Lean の定理または具体的な証人に対応付ける。
「この範囲に解がない」という結果を、定理の仮定に置いてはならない。
有限の探索範囲を取り除くと反例が現れた場合は最小反例と両立しない規則を記録する。
歴史上の規則を比較するコマンドも、どの規則がどの入力で結果を変えるかを示す例として残す。

入力は有限の原稿と 1 行以上の容量を持つ段とする。
キャプション本文、書字方向、行長、格子、組版の設定と送りの計測関数を入力とし、改行位置と占有行数を求める。
計測関数は文字列の文脈を受け取れるものとし、文字ごとの送りの和に分解できるという仮定は置かない。
実フォントを使う Golem の結果と同じ計測値を使って照合する。

画像には任意の正の寸法を許す。
本文から得たキャプションの占有行数を段の容量から引き、画像の縦横比と実装の寸法の丸めに従って縮小する。
一段の遷移状態に、残りの原稿、待機中の図版の列、段の使用済み行数、配置済みの内容を持つ。
縮小した図版をこの遷移に渡し、次の段に進むたびに更新した状態を引き継ぐ。
空の段や 1〜2 行の段では、既存の規則が指定する順に制約を緩める。
規則で結果が決まらない場合は入力を縮小し、判断を要する箇所を示す。

## 不変条件

1. 同じキャプション本文、設定、計測結果は同じ改行位置と占有行数を与える。実装との比較には図番号がキャプションを構成する場合も含める。
2. キャプションが容量以上を占めれば G07038 になる。画像に行が残れば、縮小後の図版とキャプションは空の段に収まり、その寸法が改ページに渡る。
3. 任意の正の段容量で、一段の配置は適用される規則と優先順を満たす。緩める規則とその前提を定理に明示する。
4. 有限な有効入力の改ページは終了する。次の段に送るだけの段階も含めて減少する尺度を示す。
5. 配置対象の内容は全体で過不足なく出力される。待機した図版は規則の定める順序で一度だけ配置される。段頭で捨てる空きなどは対応する消費規則を明示する。

| 境界入力 | 確かめる性質 |
| --- | --- |
| 空の原稿、一行だけの原稿 | 4、5。内容が増えず終了する |
| 容量 1、2、3 の段で段落が分かれる | 3、4。実装の優先規則を適用し、送るだけの処理を繰り返さない |
| キャプションの改行位置の前後に一文字足す | 1、2。本文から求めた行数で残りの高さを計算する |
| 画像に残る行が一行、ゼロ行、キャプションが一行超過 | 2。収まる寸法または G07038 |
| 空の段にちょうど収まる図版、一行高い図版 | 2、3。縮小前の反例と縮小後の配置を区別する |
| 図版が一つ、二つ、さらに後ろに図版を加える | 3〜5。途中で送った図版の欠落、重複、順序の逆転を検出する |

## テスト設計

実装前に不変条件の番号を名前に入れた対応テストを作る。
各定理の前提と結論を、対応する Alloy コマンドの有限範囲に戻した場合の結果とも照合する。
実装ではキャプションの改行位置と行数、縮小後の寸法、各段への割り当て、送った図版の最終位置を検査する。
送りの異なる実フォントの例を含め、Lean に渡した計測結果を記録する。

Lean の証明は手元の Lean 4 で実行し、版、再現コマンド、結果を残す。
移行完了は 42 件の対応、一般化できる性質の証明、実装との境界例の照合で判定する。
未証明の項目や未説明の反例がある間は置き換えを完了としない。
完了時に Alloy の定期実行を終了し、規則やモデルの変更時はローカルの Lean で再検証する手順を CONTRIBUTING に記す。
Golem の実装との対応テストは通常のテストとして走らせる。

## 実装しないこと

フォントデータから送りを算出するシェーピングエンジンの内部は証明の対象外とする。

## トレードオフ

上限を外すと、Alloy の小さな入力では現れなかった規則の衝突も扱う必要がある。
一方、規則が成り立つ前提と反例を切り分けることで、検査範囲を広げた先でも同じ規則を使えるか判断できる。
