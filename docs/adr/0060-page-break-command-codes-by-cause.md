# ADR 0060: 改ページのコマンドの誤りを原因ごとのコードに分ける

ステータス: 採択（未実装）

## 文脈

仕様書の「設計原則」の「一つのコードに一つの原因」は、異なる原因の誤りを一つの diagnostic のコードにまとめないことを求める。
改ページのコマンドの誤りは、二つのコードが複数の原因をまとめている。

- G0258（[ADR 0017](0017-forced-page-breaks.md)）：`@page-break` の引数が `recto` でも `verso` でもない。`@column-break` に引数を書いた。どちらかに本体を書いた。
- G0270（[ADR 0030](0030-manual-page-break-control.md)）：`@no-page-break` に引数を書いた。`@need-lines` の引数が 1 以上の整数でない。`@page-lines` の引数が、符号を付けた 0 でない整数でない。三つのどれかに本体を書いた。

[ADR 0056](0056-printings-diagnostic-codes-by-cause.md) の草案は、`@printings` の誤りを分けるときに、これらを v1.0.0 の監査に回すとした。
メンテナーは、後回しにする理由がないとして、今分けると決めた。

### 評価の区分の番号が足りない

diagnostic のコードの上 2 桁は段階を表すので、評価の区分（02）に使える番号は G0200 から G0299 の 100 個である。
今使っていないのは G0200 と G0299 だけであり、[ADR 0056](0056-printings-diagnostic-codes-by-cause.md) の草案が G0296、G0297、G0298 を使う。
コマンドごとに引数と本体の誤りを分けると、この区分だけで五つの番号が新しく要り、足りない。

そこで、原因を「どのコマンドか」ではなく「何が誤っているか」で分ける。
書き手は、コードから原因と直し方を引く。
引数を取らないコマンドに引数を書いた誤りは、どのコマンドでも直し方が同じ（引数を消す）であり、一つの原因である。
本体を持てないコマンドに本体を書いた誤りも、直し方が同じ（次の行の字下げをやめる）であり、一つの原因である。
引数の形が決まっているコマンドでは、形がコマンドごとに違い、直し方も違うので、コマンドごとに分ける。

## 実装すること

改ページのコマンドの誤りを、次のコードにする。
どれも重大度はエラーで、誤ったコマンドは今のとおり捨てる。

| コード | 原因 | 対象のコマンド | メッセージ | 位置 |
|---|---|---|---|---|
| G0296 | 引数を取らないコマンドに引数を書いた | `@column-break`、`@no-page-break`（と `@printings`） | `<名前> は引数を取りません` | コマンドの行 |
| G0297 | 本体を持てないコマンドに本体を書いた | `@page-break`、`@column-break`、`@no-page-break`、`@need-lines`、`@page-lines`（と `@printings`） | `<名前> は本体を持てません` | 本体の最初のブロック |
| G0258 | `@page-break` の引数が `recto` でも `verso` でもない | `@page-break` | `@page-break の引数は recto か verso です` | コマンドの行 |
| G0270 | `@need-lines` の引数が 1 以上の整数でない | `@need-lines` | `@need-lines の引数は 1 以上の整数です` | コマンドの行 |
| G0299 | `@page-lines` の引数が、符号を付けた 0 でない整数でない | `@page-lines` | `@page-lines の引数は +1 や -1 のように符号を付けた 0 でない整数です` | コマンドの行 |

- G0296 と G0297 は、[ADR 0056](0056-printings-diagnostic-codes-by-cause.md) の草案が `@printings` の引数と本体の誤りに割り当てたコードを、同じ原因のほかのコマンドにも広げたものである。メッセージの `<名前>` に、`@` を付けたコマンドの名前が入る。
- 引数の形が決まっているコマンド（`@page-break`、`@need-lines`、`@page-lines`）で、引数を二つ以上書いた場合と、キーワード引数を書いた場合は、それぞれの引数の形の誤り（G0258、G0270、G0299）とする。直し方が「決まった形の引数を一つだけ書く」で同じだからである。
- 引数と本体の両方が誤っていれば、両方のコードを、表の順に出す。今の実装は本体の誤りだけを出す。
- G0258 の題を `@page-break の引数が誤っています` に、G0270 の題を `@need-lines の引数が誤っています` に改める。
- 02 の区分は G0298 まで使う（G0296 から G0298 は [ADR 0056](0056-printings-diagnostic-codes-by-cause.md) の草案）。G0299 は、origin の各ブランチと、この worktree のほかの草案で使われていない。

### ADR のステータス

- [ADR 0017](0017-forced-page-breaks.md) のステータスの行に「、`@page-break` と `@column-break` の誤りのコードは [ADR 0060](0060-page-break-command-codes-by-cause.md)」を足す。
- [ADR 0030](0030-manual-page-break-control.md) のステータスの行に「、`@no-page-break`、`@need-lines`、`@page-lines` の誤りのコードは [ADR 0060](0060-page-break-command-codes-by-cause.md)」を足す。

### ドキュメント

- `docs/diagnostics.md`：G0258 と G0270 の節を一つの原因に絞り、G0299 の節を足す。G0296 と G0297 の節（[ADR 0056](0056-printings-diagnostic-codes-by-cause.md)）の対象に、改ページのコマンドを足す。
- 仕様書の「改ページ」と「改ページの手での制御」の節、markup.md の改ページの節のコードを改める。
- 使い手のマニュアルの付録 E の G0258 と G0270 の項を改め、G0299 の項を足す。

## 実装しないこと

- 評価の区分の番号が足りなくなることへの対処。この ADR で G0299 を使うと、02 の区分で残るのは G0200 だけになる（「未決事項」）。
- ほかのコマンドの引数の誤りのコードを、G0296 と G0297 にまとめ直すこと。v1.0.0 の「一つのコードに一つの原因の監査」で、同じ原因のコードを洗い出すときに扱う。

## テスト設計

テストを先に書き、今の実装で失敗することを確かめる。

golem-eval の `test/FileSpec.hs` で、次を確かめる。

- `@column-break recto` と `@no-page-break x` が、それぞれ `<名前> は引数を取りません` の G0296 を一つ出すこと。今は G0258 と G0270 なので失敗する。
- 六つのコマンドの次の行を字下げした原稿が、それぞれ `<名前> は本体を持てません` の G0297 を出すこと。
- `@page-break page`、`@page-break recto verso`、`@page-break x=1` が G0258 を出すこと。
- `@need-lines 0`、`@need-lines 2.5`、`@need-lines` が G0270 を出すこと。
- `@page-lines 1`、`@page-lines +0`、`@page-lines` が G0299 を出すこと。今は G0270 なので失敗する。
- `@column-break recto` の次の行を字下げした原稿が、G0296 と G0297 をこの順に出すこと。

golem-syntax と golem-driver では、docs の diagnostic の一覧とコードの一致の検査が、G0299 を含めて通ることを確かめる。

## トレードオフ

- G0296 と G0297 は、複数のコマンドに出るので、メッセージのコマンドの名前を見ないと、どのコマンドの誤りかが分からない。直し方はコマンドによらず同じなので、コードで引く書き手が迷うことはない。
- 引数の形の誤りのうち、引数の数の誤りとキーワード引数を書いた誤りを、形の誤りと一つにまとめる。どれも「決まった形の引数を一つだけ書く」で直るので、一つの原因として扱う。

## 未決事項

- 評価の区分（02）の番号は、この ADR で残り一つ（G0200）になる。新しい原則で原因ごとにコードを分けていくと、ほかの区分でも番号が足りなくなりうる。コードの形を変える（区分ごとの桁を増やす、区分の番号を足すなど）かを、別の ADR で決める必要がある。
