# ADR 0025: 索引の段組み

ステータス: 採択

## 文脈

索引は、本の全体と同じ段数で組む（[ADR 0018](0018-multi-column-layout.md) の「索引の段組み」）。
一段組みの本の索引は一段で、一冊の中で段数を切り替えること（本文を一段、索引だけを二段にすること）は、仕様書の「v2 以降に回した事項」の「段組みの拡張」に送られている。

ところが、和文の書籍にも欧文の書籍にも、索引だけを本文より多い段数で組む体裁がある。
索引の項目は短い語とページ番号の列であり、本文の行長で一段に組むと、行の後半が空いたまま索引のページだけが増える。
利用者のマニュアルを読んだ所有者も、索引を二段にすることを求めている（[ADR 0024](0024-manual-audiences-and-policy.md)）。
マニュアルの本文は一段組みなので、今の仕様では索引だけを二段にできない。

今の索引の組み方をコードと仕様で確かめると、次のとおりである。

- `@index` は、その位置に索引の項目の段落を並べるだけで、改ページをしない（[golem-driver ADR 0007](../golem-driver/adr/0007-pdf-index-and-bibliography.md)）。マニュアルでは、`@index` の前の `# 索引` の見出しが `[headings.1]` の `page-break = "recto"` で改丁するので、索引は新しいページの見出しの直後から始まる。
- 改ページの単位は段であり、ページの段の数と段の行の数は、本の全体で一つである（[ADR 0018](0018-multi-column-layout.md) の `paginate`）。
- 一ページの柱とノンブルは、段の数によらず一度だけ描く。

「段組みの拡張」の全体（段抜きの見出し、任意の位置での段数の切り替え、段組みの版面での回り込み）を v1 に入れる必要はない。
索引という一つの出力に限って段数を変えられれば、索引の体裁の要求は満たせる。
ただし、見出しの直後から索引を段組みにするには、見出しを一段のまま置き、同じページの残りを段に分ける必要がある。
索引を常に新しいページから始めると、マニュアルのように見出しの後に `@index` を置く本では、見出しだけのページができてしまう。

## 実装すること

### style.toml の [index]

`style.toml` に `[index]` の表を設ける。

```toml
[index]
columns = 2
column-gap = "2zw"
```

| キー | 型 | 既定 | 意味 |
| --- | --- | --- | --- |
| `columns` | 1 以上の整数 | 版面の段数（`[page.grid]` の `columns`） | 索引を組む段数 |
| `column-gap` | 寸法 | `[page.grid]` の `column-gap` | 索引の段間。`zw` は版面の文字の大きさを一字とする |

`[index]` がない本、または `columns` が版面の段数と等しい本は、今と同じく本の段組みのまま索引を組む。
以下の規則は、`columns` が版面の段数と異なる場合にだけ当てる。

`columns` が 1 未満か整数でない場合と、`column-gap` が寸法として読めないか負の場合は、`style.toml` を読むときのエラー（G0325）とし、位置はその値とする。

### 索引の段の幅

索引の段は、版面の文字の領域の幅（版面の段の行長の和と段間の和）を、`columns` の数の等しい幅に分け、あいだに `column-gap` を空けたものとする。

```
索引の段の行長 = (W − (columns − 1) × column-gap) ÷ columns
W = 版面の段数 × 版面の段の行長 + (版面の段数 − 1) × 版面の段間
```

索引の段の行長は sp に切り捨てる。
字送りの格子の整数倍にはそろえない。
索引の行は、語とページ番号の長さで決まる成り行きの行であり、格子にそろえる利点が小さいからである。
索引の段の行長が、版面の文字の大きさの 8 字分に満たない場合は、エラー（G0744）とする。
8 字分は、段落スタイルの字下げ（G0725）とリスト（G0727）と同じ基準である。
G0744 は `style.toml` だけで決まるので、PDF をターゲットに含む `golem check` も報告し、位置は `[index]` の `columns` の値とする。

行の位置は、版面の行の格子のままとする。
索引の段も版面と同じ行送りで行を置くので、隣り合う段の行の位置はそろい、索引の前後の本文とも格子が続く。

傍注欄（`[sidenotes]`）のある版面では、文字の領域の幅に傍注欄を含めない。
索引は傍注を持たないので、索引のページの傍注欄は空のまま残る。
[ADR 0018](0018-multi-column-layout.md) は傍注欄と 2 以上の版面の段数の組をエラーにしたが、索引の段数はこの組に数えない。

### 切り替えの位置

PDF では、`@index` の位置で段数を切り替える。

**版面が一段組みの場合**。
`@index` の前の内容が置かれた行の後から、そのページの残りの行を `columns` の段に分け、最初の段から索引を組む。
`# 索引` のような見出しは一段の行長のまま、索引の段の上に置かれる。
ページの残りの行が一行もなければ、次のページの最初から段に分ける。
次のページからは、ページの全体の行を段に分ける。

切り替えのページに脚注があれば、脚注の本文が占める行をページの下から除いた残りを段に分ける。
索引の項目は脚注を持たないので、索引の段の中で脚注の量は増えない。

**版面が二段以上の場合**。
`@index` の位置で今のページを閉じ、索引を次のページの最初から組む。
今のページの残りの段は空のまま残す。
段の途中から別の段数に切り替える形（ページの一部の段にだけ索引の段を作るなど）は、段抜きと同じ問題になり、決めることが多いからである。

**索引の後**。
索引の最後の項目を置いた後は、ページを閉じ、次の内容を次のページから版面の段数で組む。
ページの残りを元の段数に戻して続けると、索引の段の下に本文が一段で続く形になり、段抜きと同じ問題になる。
索引の後には奥付や白ページが続くことが多く、改ページで足りると考える。
本の最後が索引なら、ページを閉じるだけで白ページは作らない。

**段の高さ**。
索引の段の高さはそろえない（[ADR 0018](0018-multi-column-layout.md) と同じ）。
最後のページでは、後ろの段が空のまま残ることがある。

**縦組み**。
縦組みの本では、段は上から下に並ぶ（[ADR 0018](0018-multi-column-layout.md)）。
一段組みの版面で切り替えるときは、`@index` の前の内容が置かれた行より左の残りの行を、上から下へ `columns` の段に分ける。

**柱とノンブル**。
柱とノンブルは、今と同じくページに一度だけ描く。
切り替えによって変えない。

**索引の印のページ**。
索引の印のページを求める処理（レイアウトを繰り返して収束させる）は変えない。
索引の段組みで索引のページ数が変わると、そのあとのページ番号が変わりうるが、今の繰り返しで扱える。

### 改ページの単位（golem-layout）

`paginate` は、ページの段の数と段の行の数を本の全体で一つとして受け取っている。
これを、流れの途中で段の組を変えられる形にする。

```haskell
-- 段の組。ページのどの行からどの行までを、何段に、どの行長で分けるか
data ColumnSet = ColumnSet
  { csColumns  :: !Int,   -- 段の数
    csMeasure  :: !Int,   -- 段の行長（sp）
    csGap      :: !Int,   -- 段間（sp）
    csFirstLine :: !Int   -- ページの中で段が始まる行（0 から数える）
  }

data Flow
  = -- 今の要素に加えて
    FSwitchColumns !ColumnSet   -- 索引の始まり
  | FRestoreColumns             -- 索引の終わり

data PageOut = PageOut
  { -- 今の欄に加えて
    poColumnSet :: !ColumnSet
  }
```

`FSwitchColumns` を受けると、版面が一段組みなら、今のページの使った行の後を `csFirstLine` とする段の組を作り、版面が二段以上ならページを閉じて次のページの行 0 から始める。
`FRestoreColumns` を受けると、ページを閉じ、次のページから版面の段の組に戻る。
一ページの中に段の組が二つ（上の一段と下の索引の段）ある場合は、`PageOut` を段の組ごとに分けて返し、描画の側が同じページに重ねて描く。
`FSwitchColumns` を流れに入れない本では、`PageOut` の値は今と同じであり、PDF のバイト列も変わらない。

`Golem.Driver.Pdf` は、`ChannelOutput IndexOutput` の前後に `FSwitchColumns` と `FRestoreColumns` を置き、索引の段落を索引の段の行長で行分割する。
`[index]` の `columns` が版面の段数と等しいか、`[index]` がない場合は、何も置かない。

### HTML、EPUB、プレーンテキスト

HTML と EPUB には、索引の段組みを出力しない。
CSS の `columns` を書かない理由は、本文の段組みを出力しない理由（[ADR 0018](0018-multi-column-layout.md) の「HTML と EPUB」）と同じであり、索引に限っても、狭い画面で一段の字数が少なくなることと、読書環境の段組みと重なることは変わらない。
プレーンテキストは索引を出力しない。

### 診断

| コード | 重大度 | 段階 | 出す条件 | メッセージ |
| --- | --- | --- | --- | --- |
| G0325 | エラー | プロジェクト | `[index]` の `columns` が 1 以上の整数でない、または `column-gap` が寸法として読めないか負である | `[index] の columns は 1 以上の整数です` または `[index] の column-gap が正しくありません` |
| G0744 | エラー | レイアウト | 索引の段の行長が版面の文字の大きさの 8 字分に満たない | `索引の段の行長が足りません。columns を減らすか column-gap を狭めてください` |

`[index]` の未知のキーは、`style.toml` のほかの表と同じく G0306 とする。
番号は、[golem-syntax ADR 0002](../golem-syntax/adr/0002-notice-severity.md)（G0262 から G0265、G0323、G0324、G0407、G0408）と [golem-driver ADR 0017](../golem-driver/adr/0017-pdf-code-blocks.md)（G0266、G0730、G0743、G0808）と重ならないように選んだ。

### データ構造の変更

- golem-project：`Style` に `[index]` を表す欄（`Maybe IndexStyle`。`columns :: Int`、`columnGap :: Maybe Dimension`）を足す。
- golem-layout：上の `ColumnSet`、`FSwitchColumns`、`FRestoreColumns`、`poColumnSet` を足す。
- golem-driver：索引の前後に段の組の切り替えを置き、索引の段落の行長を索引の段の行長にする。
- 意味論 IR とプラグインの ABI は変えない。

### ドキュメント

- docs/specifications.md の「style.toml」に `[index]` の二つのキーと、索引の段の幅の決め方を書き、この ADR へリンクする。
- 同じく「索引」の節に、`[index]` の `columns` が版面の段数と異なるときの切り替えの位置（一段組みではページの途中から、二段以上では次のページから、索引の後は改ページ）を書く。
- 同じく「v2 以降に回した事項」の「段組みの拡張」から「一冊の中で段数を切り替えること（索引だけを段組みにすることなど）」を「索引のほかで一冊の中で段数を切り替えること」に改め、索引の段組みはこの ADR で v1 に入れたことを書く。
- docs/diagnostics.md に G0325 と G0744 の節を足す。
- docs/glossary.md の「段」の項目に、索引の段を加える。
- 次の ADR のステータスの行を変える。[ADR 0018](0018-multi-column-layout.md) は「採択→索引の段組みは [ADR 0025](0025-index-columns.md)」とする。[golem-driver ADR 0007](../golem-driver/adr/0007-pdf-index-and-bibliography.md) は、索引の段組みの参照先を [ADR 0018](0018-multi-column-layout.md) と [ADR 0025](0025-index-columns.md) の二つにする。
- 利用者のマニュアルの「スタイルの設定」の章に `[index]` を書き、マニュアルの索引を二段で組む（[ADR 0024](0024-manual-audiences-and-policy.md)）。

## 実装しないこと

- 索引のほかの部分（目次、参考文献、本文の任意の位置）で段数を切り替えること。「段組みの拡張」に残す。
- 段抜きの見出し。切り替えのページで見出しが段の上に置かれるのは、見出しが一段組みの部分に属するからであり、段抜きの仕組みではない。
- 版面が二段以上の本で、ページの途中から段数を切り替えること。
- 索引の後に、同じページの残りで本文を続けること。
- 索引の段の高さをそろえること。
- 索引の見出し（「あ」「か」のような行の区切り）。[golem-driver ADR 0007](../golem-driver/adr/0007-pdf-index-and-bibliography.md) のとおり扱わない。
- HTML と EPUB の索引の段組み。

## テスト設計

### 先に書いて失敗させるテスト

golem-project のテストで、`[index]` の読み込みを確かめる。

- `columns = 2` と `column-gap = "2zw"` を読めること。`column-gap` を省くと `[page.grid]` の `column-gap` になること。
- `columns = 0`、`columns = -1`、`columns = 1.5`、`columns = "2"` が G0325 になり、位置がその値であること。
- `column-gap = "-1zw"` と `column-gap = "abc"` が G0325 になること。
- `[index]` の未知のキー（`colums`）が G0306 になること。

golem-layout の `paginate` のテストで、流れと `PageOut` の列を比べる。

- `FSwitchColumns` のない流れで、`PageOut` の列が今と同じであること（今のテストがそのまま通ること）。
- 一段組みで、一ページ 10 行、見出しが 2 行を使った後に `FSwitchColumns`（2 段）が来ると、そのページの 3 行目から 8 行ずつの段が二つでき、索引の行が一段目の 8 行、二段目の 8 行の順に入ること。
- 同じ条件で索引が 20 行のとき、残りの 4 行が次のページの一段目の始まりから入ること。
- ページの残りが 0 行のとき、次のページの行 0 から段に分けること。
- 切り替えのページに脚注の本文が 2 行あるとき、段の行の数が 6 になること。
- 二段組みの版面で `FSwitchColumns`（3 段）が来ると、今のページが閉じられ、次のページの行 0 から 3 段になること。
- `FRestoreColumns` の後の内容が、次のページの行 0 から版面の段組みで入ること。索引が本の最後なら、余分なページができないこと。
- 縦組みでも、段が上から下に並ぶ順で同じ結果になること。

golem-driver の PDF のテストで、次を確かめる。

- 一段組みの本（行長 32 字、段間 2zw）で `[index] columns = 2` のとき、索引の段の行長が 15 字分になり、二段目の行の始まりが一段目の始まりから 17 字分の位置にあること。
- 索引の段の行が、版面の行の格子の位置にあること。
- 柱とノンブルが、切り替えのページにも、索引のページにも、一度だけ描かれること。
- `[index]` がない本と、`columns` が版面の段数と等しい本の PDF のバイト列が、この ADR の前と同じであること。
- `columns = 5` で段の行長が 8 字分を切る版面が、G0744 になること。PDF をターゲットに含む `golem check` でも報告されること。
- 傍注欄のある一段組みの本で、`[index] columns = 2` が G0701 にならず、索引の段の幅が傍注欄を含まない文字の領域から決まること。
- 索引の段組みで索引のページ数が変わる本で、索引の後のページへの参照が正しいページ番号になること（レイアウトの繰り返しで収束すること）。

golem-html のテストで、`[index] columns = 2` を書いても、HTML と EPUB の出力のバイト列が変わらないことを確かめる。

### 自動テストにできないものの確かめ方

- 利用者のマニュアル（[ADR 0024](0024-manual-audiences-and-policy.md)）の PDF を開き、索引の見出しの下から二段で組まれていること、段の行がそろっていること、索引の後の奥付が新しいページから始まることを目で確かめる。
- 縦組みの小さな見本を組み、段が上から下に並ぶことを目で確かめる。
- CI の `determinism` ジョブで、マニュアルのハッシュが x86-64 と aarch64 で一致することを確かめる。

確かめた結果は、実装のプルリクエストのコメントに書く。

## トレードオフ

- 段数の切り替えを索引に限るので、目次や参考文献を段組みにしたい要求には応えない。範囲を一つに絞ることで、段抜きや任意の位置の切り替えを決めずに済む。
- 一段組みではページの途中から、二段以上では次のページから切り替えるので、版面の段数によって切り替えの位置の規則が違う。二段以上の途中から切り替える形は、段ごとに残りの高さが違い、段抜きと同じ判断が要る。
- 索引の後を改ページにするので、索引が短い本では、索引の後のページの残りが空く。索引は本の後付けにあり、後に続くのは奥付や白ページであることが多いので、影響は小さいと見込む。
- 索引の段の行長を字送りの格子にそろえないので、索引の段の左右の端が本文の字送りの格子とずれる。格子にそろえると、段間か段の幅のどちらかが指定と変わる。
- `PageOut` を段の組ごとに分けるので、一ページが二つの段の組を持つ場合を描画の側が扱う必要がある。ページを単位にした今の描画の処理を、段の組を単位に回す形に変える。
- HTML と EPUB に索引の段組みを出さないので、媒体のあいだで索引の見た目が違う。媒体契約は提示の分岐を許している。
