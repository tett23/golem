# ADR 0233: 目で見る項目の見本を見た目の回帰のテストに加え、幾何の性質をテストにする

ステータス: 採択（未実装）

## 文脈

[docs/roadmap.md](../roadmap.md) の「手で確かめる項目」のうち、次の五つは PDF を目で見ることを求めている。

- **縦組みのダッシュ**（[golem-driver ADR 0015](../golem-driver/adr/0015-vertical-dashes.md)）
- **リストの字下げ**（[golem-driver ADR 0013](../golem-driver/adr/0013-list-indents.md)）
- **段組みの脚注**（[ADR 0018](0018-multi-column-layout.md)）
- **組版の新しい機能の見え方**（圏点、隠しノンブル、`palt` と `vpal`、ルビの親文字の太字、縦組みの注の印、参考文献の空き、表の罫と空き、段落の罫線、線の種類と色）
- **v0.1.0-rc3 のリリースの前のマニュアルの目視**

「組版の新しい機能の見え方」は、確かめていない理由を「環境に PDF を画像にする道具がなく」と書いている。
この理由は、今は当たらない。
CI の `visual` ジョブは、shem で PDF のすべてのページを 72 dpi の画像にし、`scripts/visual/pages/` の SHA-256 と比べ、違ったページの前後の画像を成果物 `visual-diff` に上げる（[ADR 0094](0094-visual-regression-page-hashes-at-72-dpi.md)、[ADR 0096](0096-before-and-after-images-of-changed-pages.md)）。
見本が見た目の回帰のテストの入力にあれば、実装のプルリクエストの CI が、そのページの画像を作る。

### 目で見ることの中身は三つに分かれる

項目の文を読み分けると、目で見ることには三つの種類が混ざっている。

一つめは、変わらないことの確かめである。
リストの字下げの「決定性の検査の蟹工船とテンペストの出力が変わらないこと」がこれにあたる。
この項目を書いた後に、[ADR 0173](0173-rc4-refactoring.md) が `scripts/determinism/hashes.txt` に出力の SHA-256 を固定し、CI の `determinism` ジョブが毎回照らすようになった。
今の `main` の蟹工船とテンペストの出力は、固定した値と同じである。
この部分は、もう手で確かめる理由がない。

二つめは、幾何の性質である。
「罫が字面に接しない」「空の見出しの行の罫が二重にならない」「表の前後に一行の空きがある」「罫線が格子の行を崩さず、段の端で版面の外に出ない」「脚注がその段の下に組まれる」「縮めた図版が版面に収まる」は、どれも組んだ結果の矩形の位置と大きさで決まる。
golem-driver のテストは、組んだ結果の行と箱を読める（`verseLines`、`lineTexts` など）。
これらは、画像を見なくてもテストに書ける。

三つめが、人の判断である。
「技術書として読める見た目」「二倍ダッシュが一本の線に見える」「点の丸さ」「波線のつながり」は、幾何に言い直すと別のものになる。
たとえば二倍ダッシュが一本に見えるかは、二つの字形の間の隙間が 0 であることだけでなく、字形の端の形にもよる。
この種類は、人が一度見て受け入れ、その後は見た目の回帰のテストで変わらないことを守るのが、自動にできる範囲である。

### rc3 の項目は時期を過ぎている

「v0.1.0-rc3 のリリースの前のマニュアルの目視」は、v0.1.0-rc3 のリリースの前に行うと書いている。
v0.1.0-rc3 は 2026-10-24 にリリースされた（GitHub の Releases）。
この項目は、名前の時期を過ぎたまま残っている。

## 実装すること

### 1. 見本の fixture

`modules/golem-driver/test/fixtures/specimens/` を足す。
今の見た目の回帰のテストの入力（`scripts/visual/build.sh --list`）が含まない見本だけを、横組みと縦組みの二つの PDF に組む。

隠しノンブルは、トンボを付けた PDF でしか見えないので、今の `kanikosen-marks-japanese` の入力にあるかを実装の最初に確かめ、なければこの fixture のトンボを付けた版を足す。
見本は、ADR ごとに見出しを立て、見出しの下にその ADR の番号を書く。
受け入れるときに、どのページが何の見本かがわかるようにするためである。

フォントは、今の fixture の Noto Serif JP などを `scripts/fixtures/copy-fonts.sh` と同じく写す。

### 2. 見た目の回帰のテストに加える

`scripts/visual/build.sh` の入力の一覧に `specimens-horizontal` と `specimens-vertical` を足し、`scripts/visual/run.sh --accept` で参照を作る。
参照を作るプルリクエストの CI の `visual-diff` に、すべてのページの画像が出る（参照がないページは「足されたページ」として報告される）。
メンテナーは、その画像を見て、人の判断の三つめの種類を受け入れる。
受け入れた結果は、そのプルリクエストの説明に、ページごとに書く。

### 3. 幾何の性質のテスト

golem-driver のテストに、次を先に書いて失敗させる。
どれも 1 の fixture か、今の入力（The Elements of Style、蟹工船、二冊のマニュアル）の組んだ結果を読む。

- 表の罫の矩形と、隣のセルの字の箱の矩形が交わらない（[golem-driver ADR 0031](../golem-driver/adr/0031-table-spacing-and-rules.md)）。
- 空の見出しの行で、同じ位置に二本の横の罫がない。
- 表の前と後の行の送りが、本文の一行の送りの二倍以上ある。
- 段落の罫線の上下の位置が格子の行の境目にあり、罫線の矩形が版面の矩形の中にある（[golem-driver ADR 0027](../golem-driver/adr/0027-paragraph-style-rules.md)）。
- 段組みの脚注が、その注の印のある段の矩形の下にあり、横の範囲がその段と同じである（[ADR 0018](0018-multi-column-layout.md)）。
- 縮めた図版の矩形が版面に収まり、回した図版とそのキャプションが同じ回転を持つ（[golem-driver ADR 0034](../golem-driver/adr/0034-fit-figures-to-column.md)）。
- 番号付きリストの 10 番目以降の項目の本文の行頭が、1 番目から 9 番目と同じ位置にある（[golem-driver ADR 0013](../golem-driver/adr/0013-list-indents.md)）。

### 4. ロードマップと文書

- 「リストの字下げ」から、蟹工船とテンペストの出力が変わらないことを外す（`hashes.txt` が守る）。
- 「段組みの脚注」を外す。3 のテストと、2 の受け入れで足りる。
- 「縦組みのダッシュ」「リストの字下げ」「組版の新しい機能の見え方」は、PDF を目で見ることを「見た目の回帰のテストの参照を受け入れるときに見る」に書き換え、2 のプルリクエストで受け入れたら外す。InDesign との比べ合わせと、HTML を Safari で見ることは残す。
- 「v0.1.0-rc3 のリリースの前のマニュアルの目視」の扱いは「メンテナーが決めること」の 3 による。
- `scripts/visual/README` か開発者のマニュアルの「見た目の回帰テスト」の節に、見本の fixture と、参照を受け入れるときに見ることを書く（[docs/manual-policy.md](../manual-policy.md) のとおり、マニュアルは同じプルリクエストで直す）。

## 実装しないこと

- 人の判断の種類を、画像の比べ合わせの閾値で置き換えること。たとえば二倍ダッシュの隙間を画素で測っても、一本に見えるかは決まらない。
- InDesign の出力を参照の画像にすること。InDesign を CI で動かせず、InDesign の版で参照が変わる。
- 見本の fixture を determinism の `hashes.txt` に加えること。見た目の回帰のテストの参照で、ページの画像は守られる。

## 不変条件

| 番号 | 不変条件 |
| --- | --- |
| I1 | 手で確かめる項目のうち、人の判断を要る見た目の見本は、見た目の回帰のテストの入力にある。 |
| I2 | 見本のページが変わったプルリクエストは、`visual` ジョブが失敗し、前後の画像を成果物に上げる。 |
| I3 | 3 の幾何の性質は、変更のたびにテストで確かめる。 |

## テスト設計

3 のテストは、上に書いたとおり先に書いて失敗させる。
失敗させる方法は、性質ごとに、その性質を破る原稿をテストの中で作って、テストが失敗することを確かめることである（表の罫と字の箱を交わらせるために、セルの空きを 0 にする、など）。
破る原稿で失敗しないテストは、何も確かめていない。

2 は、`scripts/visual/test.sh` の今の検査（入力の一覧と参照のファイルの対応）が、足した入力にも働くことで確かめる。

## トレードオフ

見本を足すと、`visual` ジョブで shem が画像にするページが増える。
[ADR 0095](0095-visual-job-in-ci.md) は、比べ合わせの時間の目安を 2 分にしている。
見本は横組みと縦組みで合わせて数十ページの見込みで、マニュアルの数百ページに比べて小さい。
実装のプルリクエストで `check.sh` の時間を測り、目安を超えるなら見本のページを減らす。

人の判断は、参照を受け入れる一度だけになる。
その一度が見落としなら、見落とした見た目が参照として固定される。
今の「手で確かめる項目」も一度だけ見ることを求めており、見落としの扱いは変わらない。
変わるのは、見たページの画像が CI の成果物に残り、後から同じ画像を見直せることである。

## メンテナーが決めること

1. **見本を別の fixture にすること**：推奨は、見本だけの fixture を足すことである。今の入力のどのページが何の見本かを探さなくてよく、見本を足すときにほかの入力の参照を変えない。
   - 退けた案は、マニュアルや蟹工船の今のページを見本とみなすことである。マニュアルの文章を直すたびに見本のページの位置が動き、どのページを見ればよいかが変わる。
2. **人の判断を残す範囲**：推奨は、上の三つめの種類だけを残し、参照の受け入れで一度見ることである。
   - 退けた案は、すべてを幾何のテストに置き換えて、目で見ることをやめることである。「一本の線に見える」のような性質は、幾何に言い直すと別の性質になる。
3. **rc3 の項目**：推奨は、名前を「v0.1.0-rc4 のリリースの前のマニュアルの目視」に改め、rc3 の作業の箇所のうち、まだ見ていないものを rc4 の前にまとめて見ることである。小項目のうち、`\|` が `|` として表示されることは、[ADR 0232](0232-check-inks-fonts-figures-links-and-epubs-structurally-in-ci.md) の Poppler の `pdftotext` で開発者のマニュアルの PDF から文字列を取り出すテストにし、図版を段に収めて回す試料は 1 と 3 に移す。
   - 退けた案の一つは、rc3 はリリースされたので項目を消すことである。目で見るべき箇所が、見られないまま消える。
   - 二つめは、名前を変えずに残すことである。過ぎた時期の名前は、いつまでに見るのかを示さない。
