# ADR 0478: number-text で有理数を受け付け、小数を含む糖衣構文を追加する

Status: accepted-pending

## 文脈

`number-text` は、現在は整数の値だけを本文の数として受け付ける。
2026-11-27 に、指示者は `[number-text]` と `##0.1##` のような記法で小数点を許すよう求めた。
当初の文字列として保持する案を取り下げ、有理数として受け取り、`0.10` と `0.1` を同じ値と表記に正規化すると決めた。
`style=tcy` の場合は、正規化した表記全体を縦中横にする。

数値の解釈と本文の数値表示には、既存の [root ADR 0101](0101-rational-numbers-in-expressions.md) の規則を使う。
糖衣構文の表記名を `style` へ直接渡し、明示コマンドと同じ意味論 IR を作る規則も保つ。

## 調査した事項

main のコミット `81adc858419ae607483e5889091d18e8561fab4d` のソースと、そのコミットからビルドした CLI で、次を確かめた。

- `Golem.Doc.IR` の `Number` は `Integer` を持ち、CDDL のタグ 9 の値の欄も `int64` である。
- `Golem.Eval.File` の `BNumberText` は `intOf` で整数の値を取り出す。
  `Golem.Eval.Value.numberOf` は自然数、整数、有理数の値を有理数として取り出し、文字列は受け付けない。
- `Golem.Eval.Number.renderNumber` は、有限小数を正確に、その他の有理数を有効数字 17 桁へ丸めて表示する。
  末尾の 0、指数表記、桁区切りを出さず、小数部が 1000 桁を超える場合は桁数を返す。
- CBOR の既存の `rational` はタグ 30 の分子と分母の組である。
  分子は符号付き 64 ビット整数、分母は 1 以上の符号付き 64 ビット整数とし、復号は既約でない組も拒否する。
- 文法の `NumberBody` は、すでに `.` を保持できる。
  糖衣構文の評価側の `shorthandNumber` が小数点を拒んでいる。
- 通常の `golem inspect FILE --as ir` では、`[number-text 0.1]` と `[number-text "0.10"]` は G02019、`##0.1##` と `##0.10:tcy##` は G02078 になった。
  `[number-text 1.0]` と `[number-text [= 1/1]]` は整数 1 の `Number` になり、`[number-text [= 1/10]]` は G02019 になった。
  CLI の SHA-256 は `58971f721f116e6149265729fa097a9fe2e92ff3301763e1b6b8b3d3b42064d3` である。

## 実装すること

### 有理数の受け取りと範囲

組み込みの `number-text` は、自然数、整数、有理数を受け付ける。
既存の引数の評価と `numberOf` を使い、数値を既約な有理数へ変える。
裸の語を式と同じ数値にする [root ADR 0111](0111-argument-words-as-number-literals.md) の規則は変えない。
引用符付きの文字列を数値として読み直さない。

意味論 IR へ入れる前に、既約な有理数の分子と分母を検査する。
分子は -9223372036854775808 以上 9223372036854775807 以下、分母は 1 以上 9223372036854775807 以下とする。
範囲を超えた場合は G02091 を出し、その要素を IR に入れない。
整数は分母を 1 とするため、既存の整数の範囲は変わらない。
引数の評価が先に失敗した場合は、その diagnostic を保つ。
範囲の値を本文へ渡した場合の G02113 も保つ。
正常に得られた非数値の型と位置引数の数の誤りは、引き続き G02019 とする。
G02019 と G02091 の説明を、有理数を受け付ける条件に合わせる。

### 糖衣構文

`##N##` と `##N:S##` の `N` に、既存の整数の綴りの後へ、`.` と一文字以上の ASCII の数字を一回続けたものを認める。
既存の整数の綴りは、`0` または先頭に 0 のない数字の並びである。
負の数、指数表記、分数式を糖衣構文へ追加しない。
それらの数値は、明示コマンドの既存の引数と式で渡す。

| 記法 | 同じ意味の明示コマンド | 組み込みが保持する有理数 |
| --- | --- | --- |
| `##0.1##` | `[number-text 0.1]` | 1/10 |
| `##0.10:tcy##` | `[number-text 0.10 style=tcy]` | 1/10 |
| `##1.0##` | `[number-text 1.0]` | 1/1 |
| `##12##` | `[number-text 12]` | 12/1 |

糖衣構文の表記名は、引き続き `style=S` の引数として直接渡す。
糖衣構文側で表記名を列挙せず、通常のコマンドと同じ名前解決と引数の評価を使う。
関数やプラグインで `number-text` を上書きした場合も、同じ引数の明示コマンドと同じ解決先へ渡す。
数値型を一律に有理数型へ変えるのは組み込みの IR を作るときとし、上書き先へ渡す引数の型は既存の数値の評価規則を保つ。

開きを読めた不正な中身と閉じの欠落は、従来と同じ G02078 にし、何も組まない。
`##1.2.3##`、`##1.##`、`##1..2##`、`##00.1##` は有効にしない。
`##.1##` のように開きとして認識しないものは、既存の構文の扱いを保つ。
G02078 の説明には、新たに受け付ける小数の記法を書く。
コード、エスケープ、fmt による原稿の綴りの保持は変えない。

### 意味論 IR と ABI

`Number` の値の型を `Integer` から `Rational` へ変える。
原稿の位置と任意の `NumberStyle` は保ち、原綴りの文字列は持たない。
`##0.10:tcy##` と `[number-text 0.1 style=tcy]` は、位置を除いて同じ `Number` を作る。
自動番号などの整数のカウンターは型を変えず、`Number` を作る箇所で分母 1 の有理数へ変える。

CBOR のタグ 9 の値の欄を `int64` から既存の `rational` へ変える。
CDDL、エンコード、デコード、IR の検査、SDK、プラグインの例を同じ変更で更新する。
分母が 0 以下の組、既約でない組、範囲外の値、旧整数ペイロードは拒否する。
プラグインの不正な出力の diagnostic は、既存の G06009 を使う。
ABI のバージョンは [root ADR 0052](0052-plugin-abi-version-bump-rule.md) の規則で決める。

### 表記と出力

整数の値は、既存の十進表記、漢数字、自動の表記の規則を保つ。
整数でない値は、root [ADR 0101](0101-rational-numbers-in-expressions.md) の本文の数値表示を使う。
有限小数は正確に表示し、その他の有理数は有効数字 17 桁へ丸める。
末尾の 0、指数表記、桁区切りを出さず、小数部の桁数の制限とエラーの扱いも既存の本文の数値表示に合わせる。
たとえば、`0.10` は `0.1`、`1.0` は `1`、`[= 1/3]` は `0.33333333333333333` になる。
丸めは表示時だけに行い、IR の有理数の値は変えない。

整数でない値は、`kanji`、`kanji-digits`、本の自動の表記でも、上記の算用数字の表記を使う。
漢数字による小数の表記は追加しない。
`style=tcy` の場合は、縦組みの PDF、HTML、EPUB で、正規化した符号と小数点を含む表記全体を一つの縦中横にする。
整数でない値は、横組みと、縦中横を持たないテキストでも、正規化した算用数字の表記をそのまま出す。
整数の縦組みのテキストは、`tcy` 指定時も既存の漢数字の表記を保つ。
ルビの親文字、見出し、参照、読み上げ用の文字列など、`Number` を文字列にする箇所にも同じ数値表示を使う。
有理数に言語の `show` を当てて、内部表現を本文へ出さない。

### 文書と採択の記録

仕様書、README、利用者マニュアルに、有理数の引数、小数の糖衣構文、正規化、縦中横を書く。
開発者マニュアルとスキーマの説明には、IR と ABI の変更を書く。
G02019、G02078、G02091 の説明と埋め込みも同期する。
採択時には、次の ADR の該当部分を、この ADR による変更として記録する。

- [golem-parser ADR 0011](../golem-parser/adr/0011-number-shorthand.md) と [golem-parser ADR 0014](../golem-parser/adr/0014-number-shorthand-with-an-explicit-style.md) の、小数点を拒む条件と `Number` の値の型。
- [golem-eval ADR 0002](../golem-eval/adr/0002-file-evaluation.md) と [golem-eval ADR 0003](../golem-eval/adr/0003-evaluation-diagnostic-codes.md) の、`number-text` が整数だけを受け付ける条件。
- [golem-doc ADR 0006](../golem-doc/adr/0006-integer-range-in-ir.md) の、`Number` の値の欄を `int64` とする条件。

## 実装しないこと

式の数値型、計算、一般の関数やプラグインの引数の規則は変えない。
文字列の数値への暗黙の変換、版番号の表記、原綴りの保存、漢数字の小数表記は追加しない。

## 不変条件

- I1: 有効な糖衣構文と同じ引数の明示コマンドは、位置を除く意味論 IR と diagnostic のコードと重大度が等しい。
- I2: `0.10` と `0.1` は同じ有理数と表記になり、整数の値を含め原綴りを保存しない。
- I3: 丸めは出力時だけに行い、IR と CBOR の往復は正確な有理数と表記の指定を保つ。
- I4: `tcy` は正規化した表記全体へ適用し、整数の既存の表記とカウンターの値は変えない。
- I5: 既存の引数の評価の失敗と範囲の値の G02113 を保つ。
  正常に得られた非数値は G02019、既約な有理数の IR の範囲外は G02091、不正な糖衣構文は G02078 とし、その要素を IR に入れない。
- I6: 不正なプラグインの `Number` は拒否し、G06009 を出す。
- I7: コード、エスケープ、fmt による原稿の綴りの保持は変えない。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| `0.10` と `0.1` | 同じ値 1/10 と表記 `0.1` | I1, I2 |
| `1.0` と整数 1 | 分母 1、既存の整数の表記 | I2, I4 |
| 式の 1/3 | 値を保ち、表示だけ有効数字 17 桁 | I3 |
| 小数に `tcy` を指定 | 表記全体が一つの縦中横 | I4 |
| 分子と分母の範囲の端、その一つ外 | 端は受理し、範囲外は G02091 | I5 |
| 空の引数、文字列、範囲の値 | 既存の条件ごとのエラー | I5 |
| 分母 0、未約分の組、旧整数のプラグイン出力 | G06009 | I6 |
| コードとエスケープ、fmt の反復 | 原稿の綴りと整形結果を保持 | I7 |

## 受けいれ条件

- A1: 通常の CLI で縦組みと横組みの PDF、HTML、EPUB、テキストを作り、正規化と糖衣構文の等価性を確かめる。
- A2: 実際のプラグインの CBOR を介して有理数の `Number` を受け取り、同じ規則で表示できる。

## テスト設計

root ADR 0478 I1 から I7 と A1、A2 の名前を付けて、実装前に回帰テストを足して失敗させる。
`0.1`、`0.10`、`1.0`、`0.00`、既存の整数を両記法で比較し、位置を除く IR の一致を調べる。
上書きした `number-text` と未知の表記名でも、明示コマンドと同じ引数の型、解決先、diagnostic になることを確かめる。
負の数、`[= 1/10]`、`[= 1/3]`、指数表記は明示コマンドで調べる。
`kanji`、`kanji-digits`、既定、`tcy` の各表記で、整数との互換性と非整数の表示を照合する。

分子の上下端、分母の上端と、それぞれの範囲外を評価と CBOR で調べる。
範囲の検査を約分後に行う例も加える。
引用符付きの文字列、配列、空の引数、不正な糖衣構文には所定のエラーを確かめる。
範囲の値の G02113 と、引数の評価で先に出る G02086 などのエラーが保たれることも確かめる。
プラグインの負例には、旧整数ペイロード、分母 0、負の分母、未約分の組、範囲外の組を使う。
正しい有理数の CBOR の往復で値を失わず、各負例は G06009 になることを確かめる。

通常の CLI による全媒体の検証では、`0.10` の出力が `0.1` になり、`1/3` の IR は丸められないことを調べる。
縦組みの `tcy` は一つの箱になることをレイアウトで調べ、PDF のページも描画して見る。
ルビ、見出し、表セル、参照、読み上げ用の文字列にも同じ規則を確かめる。
コードとエスケープを含む原稿の保持、fmt の二回目以降の一致、既存の自動番号の試験も通す。

## トレードオフ

有理数で保持するため、原綴りの末尾の 0 や、小数点を書いたかどうかは区別しない。
循環小数の表示は近似になるが、値は IR に正確に残り、既存の本文の数値表示と規則を共有する。
IR の値の型を変えるため、プラグインと SDK も同じ変更で更新する必要がある。
