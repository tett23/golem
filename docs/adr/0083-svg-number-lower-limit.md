# ADR 0083: SVG の図版の 0 でない数の絶対値に下限を設ける

ステータス: 採択

## 文脈

[ADR 0041](0041-svg-marker-and-number-limits.md) は、SVG の図版の数の絶対値を 10^9 以下に限った。
大きいほうだけの限りであり、小さいほうには限りがない。
2026-10-24 のセキュリティ監査（[docs/audits/2026-10-24-security-audit.md](../audits/2026-10-24-security-audit.md)）の C6 は、この空きを突く。

### 今の読み方

数の読み手は、仮数を 60 桁まで、指数を 4 桁まで読む（[`lexNumber`](https://github.com/tett23/golem/blob/19948d11bb3064fb2950f351ab8b16e1e2744523/modules/golem-svg/src/Golem/Svg/Number.hs#L79-L108)）。
上限の判定 [`exceeds`](https://github.com/tett23/golem/blob/19948d11bb3064fb2950f351ab8b16e1e2744523/modules/golem-svg/src/Golem/Svg/Number.hs#L71-L77) は、指数が -60 より小さい数をすべて通す。
そのため `1e-9999` は、10 の -9999 乗の有理数として読まれる。
どの diagnostic も出ない。

### 遅くなる場所

円弧の計算（[`arc`](https://github.com/tett23/golem/blob/19948d11bb3064fb2950f351ab8b16e1e2744523/modules/golem-svg/src/Golem/Svg.hs#L768-L782)）は、端点が楕円に収まるかを、半径の比の二乗の和 `lambda` で調べる。
半径が `1e-9999` なら、`lambda` は 10 の約 2 万乗になる。
`lambda` が 1 を超えると、半径を `sqrtR lambda` 倍に広げる。
[`sqrtR`](https://github.com/tett23/golem/blob/19948d11bb3064fb2950f351ab8b16e1e2744523/modules/golem-svg/src/Golem/Svg/Number.hs#L110-L124) は、値を整数にしてから、値そのものを初期値にしたニュートン法で整数平方根を求める。
初めのうちは一回ごとに値が半分にしかならないので、多倍長の除算を桁の数に比例した回数だけ繰り返す。

監査の再現のテスト（ブランチ `security-audit-2026-10-24-tests` の [「A-SA」](https://github.com/tett23/golem/blob/b9b141b3008b82f5a4224b2b2d3a228be97ff725/modules/golem-svg/test/SecuritySpec.hs#L303-L305)）では、`1e-9999` の半径の円弧 30 個を持つ 1 KB の SVG が、30 秒の時間切れになった。
この ADR を書くときに、golem-svg の 19948d11 のソースで `readSvg` の時間を測り直した（Apple Silicon、`-O1`）。

| 円弧の半径 | 円弧の数 | 時間 |
| --- | --- | --- |
| `1e-9` | 6 | 0.016 秒 |
| `1e-60` | 30 | 0.053 秒 |
| `1e-100` | 30 | 0.041 秒 |
| `1e-1000` | 2 | 0.016 秒 |
| `1e-9999` | 1 | 2.06 秒 |

時間は指数の大きさに対して急に増える。
`1e-1000` の 2 個は速いが、`1e-9999` の 1 個は 2 秒かかる。
`isqrt` の初期値を良くすれば一つの円弧は速くなる。
ただし、`lambda` の桁が大きいことは変わらず、桁の大きな有理数がほかの計算に流れる経路も残る。

### 小さな数が割る数になる場所

小さな数が害になるのは、割る数になるときである。
円弧の半径のほかに、ルートと `marker` の `viewBox` の幅と高さがある。
[`viewBoxMatrix`](https://github.com/tett23/golem/blob/19948d11bb3064fb2950f351ab8b16e1e2744523/modules/golem-svg/src/Golem/Svg.hs#L878-L883) は、ビューポートの大きさを `viewBox` の幅と高さで割って倍率にする。
`width="100" height="50" viewBox="0 0 1e-30 1e-30"` の SVG を読むと、行列の成分は 5 × 10^31 になった。
[ADR 0041](0041-svg-marker-and-number-limits.md) は、数を 10^9 以下に限れば、`Drawing.fixed` が書く整数部は 10 桁までに収まると書いた。
小さな数を割る数にすれば、この前提はもう成り立っていない。

### SVG の仕様が決めていること

SVG 2 の 9.5.1「Out-of-range elliptical arc parameters」は、円弧のパラメーターにどんな数を書いてもよいとし、描くときの補正を三つ決めている。

- 半径のどちらかが 0 なら、端点を結ぶ直線とする。
- 半径が負なら、絶対値を使う。
- 楕円が端点に届かないなら、解がちょうど一つになるまで、楕円を縦横の比を保って広げる。

0 でない小さな半径に下限はない。
`1e-9999` の半径の円弧は、仕様では直線ではなく、端点を直径とする半円（半径の比が 1 なら）として描かれる。
実装ノートの B.2.5「Correction of out-of-range radii」も、0 の半径を直線とし、`lambda` が 1 を超えれば半径を広げる、と同じ手順を書いている。

この事実が、直し方の候補を一つ消す。
小さな半径の円弧を直線として描けば、仕様と違う図を PDF に描くことになる。
HTML と EPUB は SVG をそのまま写すので、ブラウザーは半円を描く。
同じ図版が、PDF では直線、HTML では半円になる。
これは入力を黙って変えることであり、Golem はそうしない。
notice を添えても、出力が仕様と違うことは変わらない。

### 考えた案

1. **0 でない数の絶対値に下限を設ける**：上限と同じく、読んだ後に値を判定し、下限より小さい 0 でない数を読めない数とする。円弧に限らず、割る数になるすべての経路を一つの規則で閉じる。
2. **小さすぎる半径の円弧だけを拒む**：円弧の半径に限って下限を設ける。`viewBox` の経路は残る。
3. **小さすぎる半径の円弧を直線として描く**：上の理由で採らない。
4. **数を丸めて読む**：`1e-9999` を 0 に丸めれば、円弧は直線になる。3 と同じく出力が仕様と違う。[ADR 0041](0041-svg-marker-and-number-limits.md) も、入力を黙って変えないために丸めを退けている。
5. **平方根の計算を速くする**：一つの円弧は速くなるが、桁の大きな有理数を受け入れることは変わらない。どこまでの桁なら速いかを、計算の経路ごとに確かめ続けることになる。

1 を採る。
規則が上限と対になり、数の読み手の一か所で判定でき、割る数になる経路を一つずつ数え上げずに済むからである。

### 下限の値

下限を 10^-9 とする。
上限の 10^9 と対になり、読める 0 でない数は 10^-9 以上 10^9 以下の一つの範囲になる。

値を決めた理由は三つある。

- 10^-9 より小さい数は、割る数になるか大きな倍率を掛けられない限り、PDF の出力に現れない。PDF に書く座標と行列は 1/65536 に丸める（仕様書の図版の節）。
- `viewBox` の倍率は、10^9 を 10^-9 で割った 10^18 までになる。PDF の実数の範囲（±3.403 × 10^38）に収まる。
- `lambda` は、座標が 10^9、半径が 10^-9 のとき約 10^36 で、測った `1e-60` の場合より小さい。

ただし、浮動小数点数の誤差を書き出す道具の SVG は、この下限で拒まれうる。
JavaScript の `String(Math.cos(Math.PI / 2))` は `6.123233995736766e-17` を返す（Node で確かめた）。
回転の行列をこのように書く道具があれば、その SVG は G08011 になる。
実在の作図ツールがそう書き出すかは、確かめていない。
下限を 10^-60 にすればこの誤差は通るが、`viewBox` の倍率は 10^69 になり、PDF の実数の範囲を超える。

## 実装すること

### 数の範囲

- 数の読み手が返す値は、0 か、絶対値が 10^-9 以上 10^9 以下の数とする。0 でなく絶対値が 10^-9 より小さい数は、10^9 を超える数と同じく読めない数とする。
- `0`、`0.0`、`-0`、`0e5` のような 0 は読める。0 の半径の円弧は、今のとおり直線として描く。
- 判定は、上限と同じく、仮数の整数と 10 の指数のまま行う。指数が十分に小さければ、10 の累乗を計算せずに下限より小さいとする。`1e-9999` から大きな整数を作らない。
- 値を丸めることはしない。
- 下限は、上限と同じく、パスの座標、円弧の半径、変換の行列の成分、`stroke-width`、`stroke-dasharray`、図形の属性、色の `rgb()` の数、`marker` の `markerWidth`、`markerHeight`、`refX`、`refY`、`viewBox`、`orient` のすべてに当てる。

### diagnostic

- 新しいコードは作らない。下限より小さい数を持つ属性とプロパティは、10^9 を超える数と同じく、名前に `（読めない数）` を添えて G08011 にする。
- ルートの `width`、`height`、`viewBox` に下限より小さい 0 でない数があれば、G08010 とし、理由を `大きさの数が小さすぎます` とする。上限を超えるときの `大きさの数が大きすぎます` と同じく、図版の大きさが決まらないためである。ルートの三つの属性に、上限を超える数と下限より小さい数の両方があれば、`大きさの数が大きすぎます` とする。
- 出す時と場所は、今の G08010 と G08011 と同じである。PDF を組むとき（`golem build` の PDF と `golem preflight`）にだけ出し、dev と prod の両方でエラーとする。

### golem-svg

- `Golem.Svg.Number` に下限 `numberFloor`（10^-9）を置き、`exceeds` を上限と下限の両方を判定する関数に改める。
- `tooLarge` を、範囲の外の数があるかを返す関数に改める（名前は実装で決める）。`valueName` はこれを使い、範囲の外の数があれば `（読めない数）` を添える。
- `rootGeometry` は、上限を超える数と下限より小さい数を分けて、二つの理由を返す。
- `sqrtR` と `isqrt` は変えない。

### ADR のステータス

- [ADR 0041](0041-svg-marker-and-number-limits.md) のステータスの行の末尾に、「、0 でない数の絶対値の下限（10^-9）は [ADR 0083](0083-svg-number-lower-limit.md)」を足す。

### ドキュメント

- `docs/diagnostics.md` の G08011 の節の「意味」に、絶対値が 10^-9 より小さい 0 でない数も読めない数であることを書き、「直し方」に、座標と行列の値を丸めて書き出し直すことを足す。ADR の行にこの ADR を足す。
- `docs/diagnostics.md` の G08010 の節に、理由 `大きさの数が小さすぎます` を足す。
- 仕様書の図版の節の SVG の数の項を、「0 か、絶対値が 10^-9 以上 10^9 以下」に改め、ルートの大きさの理由を足し、この ADR へのリンクを付ける。
- golem-svg の仕様書の「数の上限」の節を「数の範囲」に改め、下限の値と判定の場所を書く。
- 利用者向けマニュアルの 3 章（`manual/chapters/03-markup.gm`）の SVG の数の段落を、10 億分の 1 より小さい 0 でない数もエラーになると改める。
- 利用者向けマニュアルの付録 E（`manual/appendices/e-errors.gm`）の G08011 の `（読めない数）` の説明に、小さすぎる数を足す。G08010 の説明に、大きさの数が小さすぎる場合を足す。

## 実装しないこと

- 小さすぎる半径の円弧を直線として描くこと、数を 0 に丸めること。理由は「文脈」の SVG の仕様のとおりである。
- 下限より小さい数を警告にして描くこと。[ADR 0041](0041-svg-marker-and-number-limits.md) と同じく、範囲の外はエラーにする。
- 読めない数を G08011 から別のコードに分けること。G08011 が複数の原因を持つことは [ADR 0054](0054-svg-marker-cycle-and-depth-codes.md) の未決事項であり、この ADR は今の `（読めない数）` に小さい側を足すだけにする。
- `sqrtR` の初期値の改良。下限があれば `lambda` の桁は小さく、速くする理由がない。
- 計算の途中の値（`viewBox` の倍率、行列の積）に上限を設けること。下限によって一つの `viewBox` の倍率は 10^18 までになるが、行列の積の大きさは数の範囲だけでは決まらない。

## テスト設計

次のテストを先に書き、19948d11 で失敗することを確かめてから実装する。

golem-svg の `test/SecuritySpec.hs` には、監査の再現のテスト（ブランチ `security-audit-2026-10-24-tests` の「A-SA」）を移し、結果を確かめる形に強める。

- A-SA：`1e-9999` の半径の円弧 30 個を持つ 1 KB の SVG が、5 秒以内に G08011 の `d（読めない数）` だけになること。今は 30 秒の時間切れで失敗する。
- 半径が `1e-9` の円弧は読め、`9.99999999e-10` の円弧は `d（読めない数）` になること。今は後者が読めるので失敗する。
- 半径が `-1e-9999` の円弧も `d（読めない数）` になること。
- 半径が `0` と `0e-9999` の円弧は、直線として読めること（今も通る）。
- `transform="scale(1e-10)"`、`stroke-width="1e-10"`、`stroke-dasharray="1 1e-10"`、`points="0 0 1e-10 1"`、`rgb(1e-10, 0, 0)`、`marker` の `refX="1e-10"` が、それぞれの名前に `（読めない数）` を添えた G08011 になること。
- `viewBox="0 0 1e-10 1"` と `width="1e-10"` のルートが、G08010 の `大きさの数が小さすぎます` になること。
- `width="1e10" viewBox="0 0 1e-10 1"` のルートが、`大きさの数が大きすぎます` になること。
- 範囲の中の数で作る最も重い円弧（座標が 10^9、半径が 10^-9 の円弧 30 個）が、5 秒以内に読めること。

golem-svg の `test/NumberSpec.hs` には、次を置く。

- `parseNumber` が `1e-9` を返し、`1e-10`、`-1e-10`、`1e-9999`、`0.000000000999` を返さないこと。`0`、`-0`、`0e-9999` は 0 を返すこと。
- 仮数が 60 桁で指数が `-9999` の数を、10 の累乗を作らずに判定すること（`1e-9999` の判定が 0.1 秒以内に終わることで確かめる）。

golem-driver の `test/FigureSpec.hs` には、次を置く。

- `1e-9999` の半径の円弧を持つ SVG の図版を PDF に組み、G08011 が一つ出て、メッセージに `d（読めない数）` があり、PDF を書かないこと。
- 既存の fixture の SVG の図版の出力が、この変更の前とバイト列で同じであること。

## トレードオフ

- 浮動小数点数の誤差（`6.123233995736766e-17` など）を書き出す道具の SVG は、図版として置けなくなる。座標を丸めて書き出し直す手間が利用者にかかる。
- 10^-9 の下限は、`viewBox` の倍率を PDF の実数の範囲に収める値として決めた。誤差を通すために下限を下げれば、倍率が範囲を超える。
- 規則が数の読み手の一か所に収まり、割る数になる経路を一つずつ調べずに済む。新しい経路（将来の `use` やグラデーションなど）が増えても、数の範囲は同じである。
- ルートの大きさの理由が一つ増え、G08010 の理由は今より一つ多くなる。
