# ADR 0148: 関数を書く言語 .gmx の核

ステータス: 破棄

## 文脈

v0.1.0-rc4 のロードマップは、書き手が関数を宣言できるようにする項目を持つ（[docs/roadmap.md](../roadmap.md) の「`.gm` の中の関数の宣言」）。
関数は、社内の使い手や組版のオペレーターが手元の不便を解消するためのものであり、技術者が作って配るプラグインとは立ち位置を分ける。

メンテナーは、この関数を `.gm` の中ではなく、別のファイル `.gmx` に書く案を出した。
`.gmx` は Haskell の方言であり、`.gm` の `[...]` と `@` の記法を使わない。
案の要点は次のとおりである。

- 言語は正格評価とし、`lazy` を付けたものだけを遅延評価する。
- 最上位の宣言のうち `pub` を付けたものを公開する。
- オフサイドルール（字下げで構造を決める規則）を採らない。`golem fmt` との相性が悪いからである。
- `if` と `for` を持たない。分岐は引数の位置のパターンマッチで、繰り返しは再帰で書く。再帰は末尾呼び出しの最適化で実装する。三項演算子はパターンマッチの糖衣構文とする。
- パターンマッチは網羅していなければならない。
- 関数が処理系に求めるもの（要求）をシグネチャに書く。代数的エフェクトを部分的に実装したものであり、要求を処理するハンドラは driver に集める。

案の例は、Golem 自身の Haskell のコード（[`cidSystemInfo`](https://github.com/tett23/golem/blob/4f86b945b6e60913fc63e22c0bf4ec14e5114bed/modules/golem-font/src/Golem/Font.hs#L194-L199)）をそのまま写したものである。
`T.pack` と `String` と `Int` が出てくるが、これは Haskell の `Data.Text` を前提にしている。
`.gmx` の型と名前空間の例として読むと、文字列の型が二つあるように見えるので、この ADR で型の一覧を決め直す。

この話題は一つの ADR に収まらないので、三つに分ける。

- **この ADR**：言語の核。ファイル、構文、型、評価、パターンマッチ、再帰と停止、fmt、新しいパッケージ。
- **[ADR 0149](0149-gmx-requirements-and-driver-handlers.md)**：要求。シグネチャの `=>` の後ろの書き方、要求の一覧、driver のハンドラ、`manifest.toml` での許可。
- **[ADR 0150](0150-calling-gmx-functions-from-gm.md)**：`.gm` からの呼び出し。`pub inline` と `pub block`、名前、引数と戻り値の写し方、プラグインとの関係、LSP。[golem-eval ADR 0001](../golem-eval/adr/0001-expression-language-and-numerics.md) の立場を改める。

三つは同時に採択し、同じ順に実装する。
この ADR だけを実装しても、`.gm` から関数を呼べないので、使い手には何も変わらない。

## 実装すること

### ファイル

- 拡張子は `.gmx` とし、文字コードは UTF-8 とする。
- BOM と CR の扱いは `.gm` と同じである。BOM は G01002、CR は G01003 とし、`golem fmt` で直せる。原因が `.gm` と同じなので、コードを分けない。
- 一つのファイルが一つのモジュールである。`module` の宣言は書かない。モジュールの名前は、読み込む側が `as` で付ける。

### 字句

- 識別子は Haskell と同じく、値と関数は英小文字か `_` で始まり、型とコンストラクタは英大文字で始まる。識別子に `-` は使えない。
- 予約語は `pub`、`inline`、`block`、`data`、`type`、`import`、`as`、`where`、`case`、`of`、`lazy`、`otherwise` とする。`otherwise` はガードにだけ書ける語であり、`Bool` の値ではない。`if`、`then`、`else`、`for`、`while`、`let`、`in` も予約し、使うと G10102（使えない予約語）とする。書き手が慣れた言語の癖で書いたときに、名前の誤りではなく、使えない構文であることを伝えるためである。
- コメントは `--` から行末までとする。`{- -}` は持たない。
- 文字列のリテラルは `"..."` とし、エスケープは `\"`、`\\`、`\n`、`\t`、`\u{XXXX}` に限る。文字のリテラル（`'a'`）は持たない。一字の文字列 `"a"` で書く。
- 数のリテラルは、`.gm` の式文脈と同じ規則（自然数、小数、指数）で読む（[docs/adr/0101](0101-rational-numbers-in-expressions.md)）。

### オフサイドルールを使わない区切り

字下げに意味を持たせないので、どこで宣言が終わるかを記号で示す。
Haskell は字下げの規則の代わりに `{`、`;`、`}` で書く構文を持っており（Haskell 2010 Report の 2.7 節）、それを唯一の書き方にする。

- 最上位の宣言は `;` で終わる。シグネチャも等式も一つの宣言である。
- `case ... of` の後ろは `{ ... }` で囲み、中の選択肢を `;` で区切る。最後の `;` は書いてもよい。
- ガード（`|`）は等式の一部であり、`;` で区切らない。
- 改行と字下げは空白と同じであり、構文に影響しない。字下げは `golem fmt` が決める。

`where` は関数の末尾に置き、中の束縛を `{ }` で囲む（下の「決めたことの記録」）。

- `where` は一つの関数に多くても一つであり、その関数の最後の等式（ガードがあれば最後のガードの右辺）の後ろに置く。最後の等式の終わりの `;` は、`where { ... }` の後ろに書く。
- 最後でない等式の後ろの `where` と、二つめの `where` は、G10103（関数の末尾にない `where`）とする。`case` の選択肢とガードの後ろには、`where` を書けない。
- `where` の束縛は、その関数のすべての等式から見える。等式ごとの引数のパターンの変数は、`where` の中からは見えない。引数の値を使う局所の関数は、その値を引数として受け取る形で書く。
- `where` の中の束縛は `;` で区切る。最後の `;` は書いてもよい。区切りの記号は、`case` の選択肢と同じく、下の「メンテナーが決めること」の 1 に従う。
- `where` の中の束縛は、その中で `where` を持てない。入れ子にした局所の定義は、同じ `where` の中に並べる。
- 束縛の前に `lazy` を付けると、その束縛を遅延評価する（下の「評価」）。

案の例は、次のように書く。

```haskell
cidSystemInfo :: String -> String -> Nat -> Maybe CidSystemInfo;
cidSystemInfo registry ordering supplement
  | String.all printable registry && String.all printable ordering = Just (CidSystemInfo registry ordering supplement)
  | otherwise = Nothing
  where {
    printable c = c >= " " && c <= "~";
  };
```

`supplement >= 0` は、型を `Nat` にすれば要らなくなるので消した。
`T.pack` は、文字列の型が一つなので要らない。
`printable` は一字の文字列を受け取り、`>=` と `<=` はコードポイントの順で比べる。
`printable` は引数のパターンの変数を使わないので、関数の末尾の `where` に置ける。

等式が二つ以上ある関数では、`where` は最後の等式の後ろに一つだけ置き、すべての等式から使う。

```haskell
label :: Maybe Nat -> String;
label Nothing = bracket "なし";
label (Just n) = bracket (String.fromNat n)
  where {
    bracket s = "［" ++ s ++ "］";
  };
```

### 宣言

- **関数**：シグネチャと、一つ以上の等式からなる。最上位の関数はシグネチャを必ず持つ。同じ関数の等式は続けて書き、あいだにほかの宣言を挟まない。
- **データ型**：`data Shape = Circle Rat | Rect Rat Rat;` の形の代数的データ型と、`data Book = Book { title :: String, year :: Nat };` の形のレコードを宣言できる。型の引数（`data Pair a b = ...`）を持てる。
- **型の別名**：`type Name = String;` を書ける。
- **公開**：`pub` を付けた関数とデータ型を、ほかのモジュールに公開する。データ型を公開すると、コンストラクタも公開する。中身を隠した型は v1 では作れない。
- **取り込み**：`import "lib/text.gmx" as T;` で、ほかの `.gmx` を名前空間 `T` の下に取り込む。`T.name` の形でだけ参照できる。名前空間を付けない取り込みは認めない。`.gm` の `@import` と同じ規則である（[仕様書の「プロジェクトの構成と import」](../specifications.md#プロジェクトの構成と-import)）。パスはプロジェクトのルートの中に限り、外を指せば G03003 とする。循環は G10203 とする。

### 型

型は静的に検査する。
最上位の関数はシグネチャを持つので、型の推論は `where` の中の局所の宣言と式の中にとどまる。
推論は Hindley-Milner の型推論で行い、型クラスは持たない。

組み込みの型は次のとおりである。

| 型 | 中身 |
| --- | --- |
| `Nat`、`Int`、`Rat` | `.gm` の式文脈の三つの数の型と同じ。自然数から整数へ、整数から有理数へは暗に広げる（[docs/adr/0101](0101-rational-numbers-in-expressions.md)、[docs/adr/0102](0102-natural-number-type.md)） |
| `Bool` | `True` と `False` |
| `String` | Unicode のスカラー値の列。文字列の型はこれ一つである |
| `List a` | リスト。`[]` と `[a, b, c]` で書く |
| `Maybe a` | `Just a` と `Nothing` |
| `Inlines`、`Blocks` | 意味論 IR のインラインの列とブロックの列（[ADR 0150](0150-calling-gmx-functions-from-gm.md)） |

浮動小数点数の型は持たない。
`.gm` の式と同じく、計算の結果が実行の環境によって変わらないようにするためである。

- `==`、`/=`、`<`、`<=`、`>`、`>=` は、数、`Bool`、`String` にだけ使える組み込みの演算子である。ほかの型の値は、パターンマッチで比べる。型クラスを持たないので、利用者のデータ型に比較を足す手段はない。
- `+`、`-`、`*`、`/`、`div`、`%`、`**` は、式文脈の数の規則（結果の型、0 での割り算、累乗の上限）にそのまま従う。誤りのコードも式文脈と同じ（G02001 など）であり、位置は `.gmx` の中を指す。原因が同じなので、コードを分けない。
- `++` は `String` どうしと `List a` どうしをつなぐ。
- 文字を表す型は持たない。一字は、長さ 1 の `String` で表す。`String` どうしの大小は、Unicode のコードポイントの順で比べる（`.gm` の式文脈と同じ）。
- 字の単位の操作は、モジュール `String` の関数で行う。`String.chars :: String -> List String` は一字ずつの文字列のリストを、`String.fromChars :: List String -> String` はその逆を返す。`String.all`、`String.any`、`String.map` は、一字の文字列を受け取る関数を各字に当てる。`String.length` は Unicode のスカラー値の数を返す。
- `T.pack` のような文字列の型の変換は、型が一つなので持たない。
- 文字列とリストの操作は、組み込みのモジュール `String` と `List` の関数として持つ（`String.all`、`String.length`、`List.map`、`List.foldl` など）。一覧は仕様書に書く。組み込みのモジュールは `import` なしで使え、利用者の名前空間と重なる名前は G10204 とする。

### 評価

- 評価は正格であり、関数を呼ぶ前に引数を左から順に評価する。
- `lazy` は `where` の中の束縛にだけ付けられる（`lazy table = parse (File.read "words");`）。`lazy` を付けた束縛は、最初に使ったときに一度だけ評価する。関数、引数、最上位の宣言、`where` の全体には付けられず、付けると G10100 とする。
- `lazy` のない `where` の束縛は、関数が呼ばれたとき、どの等式を選ぶかを調べる前に上から順に評価する。
- 関数の引数は、つねに呼ぶ前に評価する。
- `&&` と `||` は、右辺を必要なときだけ評価する。
- 関数は純粋であり、要求（[ADR 0149](0149-gmx-requirements-and-driver-handlers.md)）を通さずに外の値を読めない。

遅延評価の位置で誤りが起きるかどうかは、どの値を使ったかで決まる。
どの値を使うかは入力だけで決まるので、同じ入力からは同じ diagnostic になる（diagnostics の決定性。[仕様書の「設計原則」](../specifications.md#設計原則)）。

### パターンマッチ

- 等式の引数の位置にパターンを書ける。パターンは、変数、`_`、リテラル、コンストラクタ、リスト（`[]`、`[a, b]`）、レコード（`Book { title = t }`）である。
- `case e of { p1 -> e1; p2 -> e2 }` で、式の中でも分岐できる。
- ガード（`| 条件 = 式`）は、等式と `case` の選択肢に書ける。条件は `Bool` の式である。
- `if` の式は持たない。条件で分ける場合はガードか `case` で書く。
- 三項演算子 `c ? a : b` は、`case c of { True -> a; _ -> b }` の糖衣構文である。一つ目の選択肢が `True` の場合、二つ目が `_` の場合になる。`?` と `:` は右に結合し、`a ? b : c ? d : e` は `a ? b : (c ? d : e)` と読む。

リストを先頭と残りに分けるパターンは、`List.uncons` と `Maybe` のパターンで書く。
Haskell の `:` は三項演算子の `:` と重なるので、リストの演算子にしない。

### 網羅性の検査

パターンマッチは、すべての値を網羅しなければならない。
網羅していない等式の並びと `case` は、型の検査の段階で G10300 とし、メッセージに網羅していない値の形の例を一つ添える。
検査は Maranget の方法（参考文献）で行う。

ガードの条件は意味で解析せず、構文の規則で検査する。
条件の意味を解析して網羅を判定すると、どの条件の組を網羅と見なすかが解析の強さで決まり、その範囲を仕様の言葉で書きにくいからである。

- **ガードの規則**：ガードを持つ等式と `case` の選択肢は、ガードの並びの最後を `otherwise` にしなければならない。最後のガードが `otherwise` でなければ G10302 とする。ほかの条件（`True`、`n >= 0 || n < 0` など）は、つねに真になる式でも `otherwise` と見なさない。
- **例外**：ガードの並びの最後が `otherwise` でなくても、関数の最後の等式（`case` なら最後の選択肢）がガードを持たず、パターンがすべて変数か `_` であれば、G10302 にしない。値は必ずその等式に落ちるからである。
- **`otherwise` の後ろ**：`otherwise` の後ろのガードは、決して選ばれないので G10301 とする。
- **選ばれない選択肢**：前の選択肢がすべて覆っていて、決して選ばれない選択肢も G10301 とする。書き手の思い違いを示すことが多いからである。
- **パターンとの組み合わせ**：`otherwise` で終わるガードの並びを持つ等式は、ガードのない等式としてパターンの網羅に数える。終わらない等式は、上の例外に当たる場合にだけ許され、網羅に数えない。

| メッセージ | 位置 |
| --- | --- |
| `ガードの並びの最後が otherwise ではありません: <関数の名前>` | 並びの最後のガード（縦線から右辺の終わりまで） |

### 再帰と停止

`for` と `while` は持たず、繰り返しは再帰で書く。

- **末尾呼び出し**：等式の右辺、`case` の選択肢の右辺、三項演算子の二つの枝、ガードの右辺の位置にある関数の呼び出しを、末尾呼び出しとする。`&&` と `||` の右辺も末尾の位置である。末尾呼び出しは、相手の関数によらず（相互再帰を含め）呼び出しの深さを増やさない。これを最適化ではなく言語の約束とし、仕様書に書く。
- **深さの上限**：末尾でない呼び出しは深さを一つ増やす。深さが 10000 を超えたら G10401 とする。
- **手数の上限**：`.gm` の一つの呼び出しが始めた評価の手数（簡約の数）に、上限を設ける。上限を超えたら G10400 とする。手数は言語の意味で数えるので、上限を超えるかどうかと止まる位置は、マシンと実行の環境によらない。
- **大きさの手数**：`++` と、文字列とリストを作る組み込みの関数は、作った値の長さを手数に足す。`s ++ s` を繰り返して手数の小さいまま巨大な値を作ることを防ぐためである。
- **数の大きさ**：累乗と数のリテラルは、式文脈と同じ上限に従う（[golem-eval ADR 0006](../golem-eval/adr/0006-exact-power-limit-before-range.md)）。

二つの上限は、原因が違うので別のコードにする。
G10401 は、末尾でない再帰が深すぎることを表し、関数を末尾再帰に書き直せば直ることが多い。
G10400 は、仕事の量が多すぎるか、止まらないことを表し、書き直しで深さを減らしても直らない。
上限を超えた呼び出しは、出力を何も返さない。
途中までの結果を組むと、書き手の入力と違う出力を黙って作ることになるからである。

| コード | 重大度 | メッセージ | 位置 |
| --- | --- | --- | --- |
| G10400 | エラー | `関数の評価の手数が上限（<上限> 手）を超えました: <関数の名前>（<.gmx のパス>:<行>）` | 評価を始めた `.gm` のコマンドの呼び出し |
| G10401 | エラー | `末尾でない呼び出しの深さが上限（10000）を超えました: <関数の名前>（<.gmx のパス>:<行>）` | 評価を始めた `.gm` のコマンドの呼び出し |

`<関数の名前>` と `<.gmx のパス>:<行>` は、上限を超えた時点で評価していた関数とその宣言である。
位置を `.gm` の呼び出しにするのは、同じ関数でも、止まるかどうかが呼び出しの引数で決まるからである。
どちらの値も評価の意味だけで決まるので、同じ入力からは同じメッセージになる。
`.gmx` の中を指す位置を持たせると、一つの誤りが二つのファイルに載り、LSP の表示が呼び出しの数だけ増える。

手数の上限の値は、実装のときに測って決め、この ADR の採択のあとに仕様書に書く。
測る対象は、[ADR 0150](0150-calling-gmx-functions-from-gm.md) のテストの関数と、プラグインの見本（`kansuji`、`first-ruby`）と同じ仕事を `.gmx` で書いたものである。
決め方は [docs/adr/0124](0124-filter-fuel-by-document-size.md) にならい、正常に終わる最大の手数の数倍とする。
利用者が `manifest.toml` で上限を変える手段は設けない。
本ごとに上限が変わると、同じ関数が本によって動いたり止まったりするからである（[docs/adr/0124](0124-filter-fuel-by-document-size.md) と同じ理由）。

評価器は、継続を明示したスタックを持つ抽象的な計算機として実装する。
GHC のスタックに深さを任せると、深さの上限がランタイムの設定で変わるからである。

### 型と評価の誤りのコード

新しい段階として、上 2 桁 `10` を「関数（`.gmx` の読み込み、型の検査、評価）」に割り当てる（[docs/diagnostics.md](../diagnostics.md) の「番号の区分」）。
番号は、ほかの段階と同じく 100 から使う。
この ADR が使うコードは次のとおりである。

| コード | 重大度 | 原因 |
| --- | --- | --- |
| G10100 | エラー | `.gmx` の構文の誤り（期待した字句を添える） |
| G10101 | エラー | 閉じていない `{`、`(`、`[`、文字列 |
| G10102 | エラー | 使えない予約語（`if`、`for` など） |
| G10103 | エラー | 関数の末尾にない `where`（最後でない等式の後ろ、二つめ、`case` とガードの後ろ、`where` の中） |
| G10200 | エラー | 未定義の名前 |
| G10201 | エラー | 型の不一致 |
| G10202 | エラー | シグネチャのない最上位の関数 |
| G10203 | エラー | `import` の循環 |
| G10204 | エラー | 同じ名前の二度の定義（組み込みのモジュールとの重なりを含む） |
| G10205 | エラー | 公開されていない名前の参照 |
| G10206 | エラー | 等式がシグネチャの引数の数と合わない |
| G10300 | エラー | 網羅していないパターンマッチ |
| G10301 | エラー | 選ばれない選択肢（`otherwise` の後ろのガードを含む） |
| G10302 | エラー | ガードの並びの最後が `otherwise` ではない |
| G10400 | エラー | 手数の上限を超えた |
| G10401 | エラー | 末尾でない呼び出しの深さの上限を超えた |

G10100 と G10101 は、golem-parser の構文の誤りと同じく、peg-hs のラベル付きの失敗で分ける（[golem-parser ADR 0009](../golem-parser/adr/0009-syntax-diagnostic-codes.md)）。
実装の中で原因がさらに分かれれば、G10104 から番号を足す。

### fmt

`golem fmt` は `.gmx` も整形する。

- 字下げは空白二つとし、`{` の後と `}` の前で改行して、中を一段下げる。ガードは等式の名前の行の次の行から一段下げる。
- 宣言のあいだの空行は一つにまとめる。
- 行の長さで折り返さない。`.gm` と同じく、改行の位置は書き手が決める。
- 整形の前後で AST が一致すること、二度整形しても結果が変わらないことを、プロパティテストで検査する（[仕様書の「fmt」](../specifications.md#fmt) と同じ）。

字下げに意味がないので、fmt が字下げを変えても意味は変わらない。
オフサイドルールの言語では、字下げを変えると束縛の範囲が変わりうるので、fmt は字下げを自由に直せない。
この性質が、オフサイドルールを採らない理由である。

### パッケージ

新しいパッケージ `golem-gmx` を `modules/golem-gmx` に作る。

- 文法は `modules/golem-gmx/grammar/Gmx.hpeg` に置き、peg-hs で生成する。生成物はコミットし、CI で生成し直して一致を検査する（[golem-parser ADR 0002](../golem-parser/adr/0002-parser-on-peg-hs.md)、[golem-parser ADR 0008](../golem-parser/adr/0008-hpeg-extension.md)）。
- CST、AST、型の検査、網羅性の検査、評価器、整形を、このパッケージに置く。
- build-depends は、golem-syntax（位置と diagnostic）、golem-doc（`Inlines` と `Blocks` の中身）、golem-eval（`Value` と数の演算）と、peg-runtime だけにする。golem-eval の数の演算を使うのは、式文脈と `.gmx` で数の規則を二つ持たないためである。
- golem-gmx に依存するのは golem-driver と golem-lsp だけとする（[ADR 0150](0150-calling-gmx-functions-from-gm.md)）。golem-fmt は golem-gmx に依存せず、`golem fmt` は golem-driver を通して `.gmx` の整形を呼ぶ。

## 実装しないこと

- 型クラス、高階の種、GADT、存在型、ランクの高い型。
- 中身を隠した型（コンストラクタを公開しない `pub data`）。
- 浮動小数点数と超越関数。
- オフサイドルール。字下げで書いた `where` は、`{` がないので G10100 になる。
- `if`、`for`、`while`、`let ... in`。
- 利用者が演算子を定義すること。
- 利用者がハンドラを書くこと（[ADR 0149](0149-gmx-requirements-and-driver-handlers.md)）。
- REPL と、`.gmx` だけを実行するコマンド。

## テスト設計

テストを先に書き、golem-gmx のモジュールがないためにコンパイルできないことを確かめてから実装する。

golem-gmx のテストでは、次のことを確かめる。

- **構文**：上の `cidSystemInfo` を読めること。字下げと改行を変えた同じ宣言が、同じ AST になること。`;` を落とした宣言が G10100、閉じていない `{` が G10101、`if` が G10102 になること。字下げで書いた `where` が G10100 になること。上の `label` を読め、二つの等式から `bracket` を使えること。最初の等式の後ろの `where`、二つめの `where`、`case` の選択肢の後ろの `where`、`where` の中の `where` が、それぞれ G10103 になること。`where` の中から引数のパターンの変数を参照すると G10200 になること。
- **型**：未定義の名前が G10200、`Nat` を求める位置の `String` が G10201、シグネチャのない最上位の関数が G10202、`import` の循環（長さ 1 を含む）が G10203、二度の定義が G10204、公開されていない名前が G10205 になること。`Nat` から `Rat` へ暗に広がること。`'a'` が G10100 になること。`String.chars "漢字"` が二つの一字の文字列になること。
- **網羅性**：`Maybe` の `Nothing` を欠いた等式が G10300 になり、メッセージに `Nothing` が出ること。`otherwise` のないガードの並びが G10302 になり、最後に変数だけのガードのない等式があれば誤りにならないこと。最後のガードが `True` でも G10302 になること。`otherwise` の後ろのガードと二つ目の `_` が G10301 になること。三項演算子は常に網羅すること。
- **評価**：正格な `where` の束縛の 0 での割り算が、使わなくても G02 の割り算のコードになり、`lazy` を付けた束縛なら使わなければ誤りにならないこと。`lazy` を関数と引数に付けると G10100 になること。
- **末尾呼び出し**：1000 万回の末尾再帰と、二つの関数の相互の末尾再帰が、G10401 にならずに終わること。末尾でない再帰が深さ 10000 を超えて G10401 になり、メッセージと位置が上の表のとおりであること。
- **手数**：止まらない末尾再帰が G10400 になり、二度実行して同じメッセージと位置になること。上限を超えた呼び出しが出力を返さないこと。`s ++ s` を繰り返す関数が、メモリを使い果たす前に G10400 になること。
- **決定性**：同じ関数を並列に評価した結果と diagnostic が、逐次に評価したものと一致すること。
- **fmt**：任意の AST から作った原稿について、整形の前後で AST が一致し、二度の整形で変わらないことをプロパティテストする。

## トレードオフ

`;` と `{ }` を書かせるので、Haskell の利用者には見慣れない形になる。
字下げで書いた Haskell のコードを貼ると、そのままでは読めない。
その代わり、字下げを fmt に任せられ、字下げの誤りで意味が変わることがない。
社内の使い手は Haskell を知らないことが多いと考えられるので、Haskell のコードを貼れることより、字下げを気にせずに書けることを選ぶ。

型クラスを持たないので、利用者のデータ型を `==` で比べられず、`show` のような汎用の関数も書けない。
型クラスは、型の検査と誤りのメッセージを複雑にする。
小さな計算と書式のための言語には、組み込みの型に限った比較で足りると考える。
足りないと分かれば、別の ADR で扱う。

手数の上限で止めるので、正しいが重い関数は止まる。
止まったときに、上限を上げる手段を使い手は持たない。
重い仕事はプラグインの役割とする（[ADR 0150](0150-calling-gmx-functions-from-gm.md)）。

拡張子 `.gmx` は、GameMaker Studio 1 のプロジェクトのファイルも使う。
エディタや GitHub の言語の判定が XML として扱うおそれがあり、`.gitattributes` の `linguist-language` で直せる範囲である。

新しいパッケージを一つ足し、golem-driver と golem-lsp の build-depends を変える。
golem-gmx は golem-eval に依存するので、golem-eval の数の演算の変更が `.gmx` にも及ぶ。
二つの言語の数の規則が同じであることを保つための、意図した依存である。

## 決めたことの記録

- **`where` の位置**（2026-11-04、メンテナー）：`where` は関数の末尾に置き、束縛を `{ }` で囲む。この草稿は「関数の末尾」を、一つの関数に一つの `where` を、最後の等式の後ろに置くことと読んだ。Haskell の `where` は等式ごとに置け、その等式の引数を参照できるが、関数ごとに一つにすると、`where` が等式の引数を参照できなくなる。メンテナーは「where は関数の末尾に `{}` 内で宣言させる」と確かめた。
`where` の中から等式の引数が見えるかは、下の「メンテナーが決めること」の 9 に残す。
束縛の区切りは、`case` の選択肢と同じく `;` とし、区切りの記号の決定（同じ節の 1）に従う。
- **ガードの網羅性**（2026-11-04、メンテナー）：ガードのある関数の網羅性は、条件の意味を解析せず、構文の規則で検査する。規則は「網羅性の検査」の節のとおりで、`otherwise` で終わらないガードの並びは G10302 とする。
- **止まらない評価のコード**（2026-11-04、メンテナー）：コードを ADR で決め、上限の値だけを実装のときに測る。深さの上限（G10401）と手数の上限（G10400）は原因が違うので分け、どちらもエラーとし、位置は評価を始めた `.gm` の呼び出しとする。
- **文字列の型**（2026-11-04、メンテナー）：文字列の型は `String` 一つとする。`Char` の型と文字のリテラルを持たず、一字は長さ 1 の `String` で表す。字の単位の操作は `String.chars` などの関数で行う。「メンテナーが決めること」の 5 はこれで決まった。
- **`lazy` の対象**（2026-11-04、メンテナー）：`lazy` は束縛に付ける。関数と引数には付けない。「メンテナーが決めること」の 4 はこれで決まった。

- **採択**：メンテナーが採択した（2026-11-04）。この ADR が決めてほしい点として挙げた項目は、どれも ADR の推奨のとおりとする。

## メンテナーが決めること

採択の前に、次のことを決めてほしい。
それぞれに、この草稿の推奨と、採らなかった案を書く。

1. **区切りの記法**：推奨は Haskell の明示の `{ ; }` だけを使うことである。採らなかった案は、(a) `end` で閉じる記法（Ruby や Elixir の形）、(b) 行頭の 0 桁めで最上位の宣言を区切り、その中だけ字下げを無視する弱い規則である。(a) は Haskell の方言から離れ、(b) は 0 桁めという字下げの規則が残るので、fmt が字下げを自由に直せない。
2. **`[]` を使わないことの範囲**：案の「`[]` や `@` は使わない」を、`.gm` の命令文脈とブロックコマンドの記法を使わない意味と読み、リストのリテラル `[a, b]` は認めた。リストのリテラルも認めない読み方なら、`List.of a b` のような関数で書くことになる。
3. **`if` の扱い**：案の「`if` はパターンマッチにのみ出現する」を、条件はガードとしてだけ書けると読み、ガードの記号は案の例のとおり `|` にした。採らなかった案は、選択肢に `p if 条件 -> e` と書く形（Rust や Scala の形）である。記号を二つ持つことになるので採らなかった。
4. **`lazy` の意味**：決めた（「決めたことの記録」の「`lazy` の対象」）。
5. **文字列の型**：決めた（「決めたことの記録」の「文字列の型」）。
6. **リストの先頭と残りの分解**：推奨は `:` を持たず、`List.uncons` で分けることである。採らなかった案は、(a) 三項演算子の記号を変えて `:` を残すこと、(b) Elm と同じく `::` をリストに、`:` を型に使うことである。(a) は三項演算子の形を変え、(b) は案のシグネチャの `::` を変える。
7. **網羅しない選択肢の重大度**：推奨は、選ばれない選択肢（G10301）もエラーにすることである。採らなかった案は警告にすることである。緩い規則より厳しい規則の原則に従った。
8. **手数の上限を一つの呼び出しごとにするか**：推奨は `.gm` の一つの呼び出しごとに数えることである（プラグインのコマンドと同じ）。採らなかった案は、ファイルごとか本ごとに合計で数えることである。合計で数えると、ある呼び出しが止まるかどうかが、前の呼び出しの重さで変わる。
9. **関数の末尾の `where` から等式の引数が見えるか**：`where` を関数の末尾に一つ置くことは決めた。推奨は、等式が一つでも二つ以上でも、`where` から引数のパターンの変数を見えなくすることである。規則が等式の数によらないからである。採らなかった案は、等式が一つの関数に限って、その等式の引数を見えるようにすることである。Haskell の書き方に近く、案の例のような関数で引数を局所の関数に渡し直さずに済むが、等式を一つ足すだけで `where` の中の名前が未定義（G10200）になる。
