# ADR 0006: 意味論 IR の大きな整数

ステータス: 採択

## 文脈

式の整数は任意精度であり、絶対値が 2 の 4096 乗未満なら値として作れる（[docs/adr/0035](../../adr/0035-security-hardening.md)）。
この整数は、次の欄として意味論 IR に入る。

- `[number-text ...]` の数（Number、inline の tag 9）
- 見出しと番号付きリストの項目の `@number`
- コードブロックの行番号（`numbers=N` と `@listing` の `lines=` から振る）
- アキの量（`[aki ...]` の `zw` の分子と分母、`sp`）
- 遅延した式（`DeferredExpr`）の整数のリテラル。`@set` の値を `doc` と組み合わせた式では、変数が整数のリテラルに置き換わって入る
- プラグインのコマンドの引数（`value`）

CDDL（`modules/golem-doc/schema/golem-doc.cddl`）は、これらの欄を `int` と定めている。
`int` は CBOR の major type 0 と 1 であり、表せるのは -2^64 から 2^64 - 1 までである。

v0.1.0-rc4 の作業中のコード（a2b6106e）で、次の原稿を `golem inspect --as cbor` に通すと、仕様の食い違いを再現できる。

```
@set n = 2 ** 70

数は[number-text [= n]]と[number-text [= -(2 ** 64) - 1]]です。
```

一つ目の Number は `c2 49 40 00 …`（tag 2 の正の bignum）、二つ目は `c3 49 01 00 …`（tag 3 の負の bignum）で書き出される。
`@number 1180591620717411303424` を付けた見出しも、`haNumber` が tag 2 になる。
CDDL の検証器に掛ければ、どれもスキーマに合わない。

原因は三つの箇所にある。

- `Golem.Doc.Cbor` は、Haskell の `Integer` の欄を `TInteger` にして `cborg` の `encodeInteger` で書く。`encodeInteger` は、major type 0 と 1 に収まらない値を bignum（RFC 8949 の 3.4.3 節）で書く。復号の側も、`decodeTerm` が tag 2 と 3 を `TInteger` として読む。
- 評価器は、値を IR の欄に入れるときに範囲を確かめない。`[number-text ...]`（`Golem.Eval.File` の `BNumberText`）、`@number`（`withNumber`）、プラグインの引数（`Golem.Plugin` の `valueTerm`）は、`Integer` をそのまま渡す。
- テストの生成器（`modules/golem-doc/test/Gen.hs`）は、Number の値を ±10^12 の範囲でしか作らない。CDDL の検証器を使うスキーマのテストは、範囲の外の値を一度も見ていない。

調べる途中で、関連する不具合を二つ見つけた。

**`Int` の欄の復号の桁あふれ**：`Golem.Doc.Cbor` の `asIntI` は、`fromInteger` で `Integer` を `Int` に変える。
位置（`span`）、ファイルの識別子、注の番号、見出しの階層、タグの番号などの欄に、プラグインが 2^64 + 5 を書くと、黙って 5 に変わる。
この値は `validateDocument` の範囲の検査も通ってしまう。

**京を超える漢数字**：`Golem.Doc.Numerals` の `kanji` は、位の名前を「万、億、兆、京」までしか持たない。
京の上に残った値は、算用数字のまま前に付く。
縦組みのプレーンテキストで `[number-text [= 2 ** 70] style=kanji]` を組むと `11八千五十九京千六百二十兆…` になり、`[= 10 ** 20]` は `1`、`[= 10 ** 24]` は `10000` になる。
後の二つは値そのものが失われている。
この不具合が出るのは絶対値が 10^20 以上の数だけであり、64 ビットの符号付き整数の範囲（絶対値が約 9.2 × 10^18 以下）の外にある。

プラグインの ABI のバージョンは 7 である。
v0.1.0-rc2 の ABI は 6 であり、7 はまだリリースしていない。

## 実装すること

### IR の整数の範囲

意味論 IR の整数の欄は、64 ビットの符号付き整数（-2^63 以上 2^63 - 1 以下）に限る。
bignum は IR に入れない。
多くの言語の CBOR のライブラリとプラグインの SDK が、そのまま数として扱える範囲だからである。
bignum は、利用者から求めがあったときに別の ADR で検討する。

CDDL に次の規則を足し、上の「文脈」に挙げた欄の `int` を `int64` にする。

```cddl
int64 = -9223372036854775808..9223372036854775807
```

`zw` の分母は `1..9223372036854775807` とする。
Haskell の型が `Int` の欄（位置、ファイルの識別子、見出しの階層、注の番号、`page-control` の数、図版の `page`、`callouts`）も、今の `int` と `uint` を `int64` の範囲に狭める。
GHC の `Int` は 64 ビットなので、範囲は Haskell の型と一致する。
Haskell の型（`Integer`）は変えず、範囲を値を作る箇所と復号で確かめる。

### 評価の G02091

範囲の外の整数を IR の欄に入れようとしたら、新しいエラー G02091 を出し、その要素を IR に入れない。

- 重大度：エラー。プロファイルによって変わらない。
- 段階とモジュール：評価（golem-eval の `Golem.Eval.File`）。
- 位置と、出したあとの扱いは下の表のとおりとする。

メッセージは次の文言とする。

```
整数が意味論 IR に書ける範囲を超えています（-2 の 63 乗以上、2 の 63 乗未満に限ります）
```


| 欄 | 位置 | 扱い |
| --- | --- | --- |
| `[number-text ...]` の数 | コマンド | 何も出さない（今の G02019 の誤りと同じ） |
| `@number N` | `@number` の行 | `@number` がないものとして番号を振る |
| コードの行番号（`numbers=N`、`lines=`） | 引数を書いたブロック | `numbers` を書かなかったものとして番号を振る |
| アキの量 | コマンド | 何も出さない（今の G02055 の誤りと同じ） |
| 遅延した式の整数 | 式文脈の `[= ...]` | 何も出さない |
| プラグインの引数 | コマンド | プラグインを呼ばない |

コードブロックの行番号は、最初の番号と行の数の和が範囲の外になる場合も G02091 とする。
遅延した式は、変数を置き換えた後の式に範囲の外の整数のリテラルが一つでもあれば G02091 とする。
評価の結果の値が S1 で範囲の外になっても、それは本文の文字列になるので、IR の範囲とは関係しない。

### 復号の範囲の検査

- `Golem.Doc.Cbor` の復号は、`int64` の欄に範囲の外の値（major type 0 と 1 の大きな値、tag 2 と 3 の bignum）があれば `スキーマに合いません: 整数が範囲の外です` とする。プラグインの出力なら、今の不正な出力と同じく G06009 になる。
- `asIntI` は `Int` の範囲を確かめ、`fromInteger` で黙って丸めない。
- 符号化は、範囲の中の値しか来ないので、今のまま `encodeInteger` で書く。バイト列は変わらない。符号化の入口で範囲を確かめ、外れた値は処理系の誤り（テストで捕まえるべき不具合）として扱う。

### 漢数字

IR の数は絶対値が 2^63 以下なので、`kanji` の位は京（10^16）までで足りる。
2^63 - 1 は `九百二十二京三千三百七十二兆三百六十八億五千四百七十七万五千八百七` になる。
見出しの番号は S1 で `@number` から数え続けるので、2^63 - 1 を少し超えうるが、10^20 には届かない。
したがって、京を超える漢数字の不具合に届く入力はなくなる。
`kanji` の位は増やさず、`kanji` の定義域が絶対値 10^20 未満であることを関数の説明に書く。

### ABI のバージョン

ABI のバージョンは 7 のままとする。
7 はまだリリースしておらず、同じリリースの中の変更だからである。
プラグインの SDK（別のリポジトリ）は、整数を 64 ビットの符号付き整数として扱えばよい。

## 実装しないこと

- bignum を IR に入れること。利用者から求めがあったときに検討する。そのときは、`kanji` の位を京より上に広げることと、10^52 以上の数の表記を合わせて決める必要がある。
- 式の値そのものを 64 ビットに制限すること。本文に埋め込む `[= ...]` の値は文字列として IR に入るので、言語仕様の任意精度の整数と [docs/adr/0035](../../adr/0035-security-hardening.md) の上限のままとする。
- `Int` の欄の型を広げること。

## テスト設計

先に次のテストを書き、今のコードで失敗することを確かめてから直す。

- **スキーマとの一致**：生成器（`Gen.hs`）の Number、`@number`、コードの行番号、整数のリテラル、アキの値の範囲を、`int64` の両端まで広げる。生成した文書の CBOR が、CDDL の検証器（`cddl` の CLI）で適合することを確かめる。往復（符号化して復号すると元に戻る）も同じ生成器で確かめる。
- **評価の境界**：`[number-text [= 2 ** 63 - 1]]` と `[number-text [= -(2 ** 63)]]` は IR に入り、`[number-text [= 2 ** 63]]` と `[number-text [= -(2 ** 63) - 1]]` は G02091 になって何も出さない。
- **ほかの欄**：`@number 9223372036854775808` の見出しが G02091 になり、`@number` がないときと同じ番号になる。`numbers=9223372036854775807` で二行のコードが G02091 になる。`[aki 99999999999999999999mm]` が G02091 になる。`@set n = 2 ** 70` の後の `[= n + doc.chapters.count]` が G02091 になる。プラグインのコマンドに `[= 2 ** 63]` を渡すと G02091 になり、プラグインが呼ばれない。
- **復号**：Number が 2^63 の CBOR、Number が tag 2 の bignum の CBOR を復号すると、`整数が範囲の外です` になる。位置の開始に 2^64 + 5 を書いた CBOR を復号すると、5 にならずにスキーマの誤りになる。テスト用のプラグイン（wat）が範囲の外の Number を返すと G06009 になる。
- **漢数字**：`kanji` が、2^63 - 1 を上の表記に、-2^63 を `マイナス九百二十二京三千三百七十二兆三百六十八億五千四百七十七万五千八百八` に、10^16 を `一京` にすることを確かめる。

## トレードオフ

IR の整数を 64 ビットに限ると、式では作れる数が `[number-text ...]` や `@number` に渡せないことがある。
書き手は、式の値の上限（2 の 4096 乗）と IR の上限（2 の 63 乗）の二つを知る必要がある。
bignum を許す案もあったが、プラグインの SDK に bignum を扱わせることになり、組版の原稿で 2^63 を超える数を漢数字や縦中横で組む需要も見えていない。
範囲の外を黙って書き出したり丸めたりせず、G02091 で知らせるので、二つ目の上限は書き手に見える。

CDDL の `int` を `int64` に狭めると、今は通る 2^63 以上 2^64 未満の値も通らなくなる。
この範囲の値は Haskell の `Int` の欄では黙って負の数になり、`Integer` の欄では言語によって読めないので、狭めて失うものはない。

## ドキュメント

メインのセッションが、次の変更をする。

- 仕様書の「既知の不具合」から「IR の大きな整数」を、`docs/roadmap.md` の「既知の不具合の修正」から同じ項目を消す。
- 仕様書の「シリアライズ形式」の節に、整数の欄は 64 ビットの符号付き整数に限ることを書く。
- `docs/markup.md` の「数の表記」と `@number` の節に、渡せる整数の範囲と G02091 を書く。
- `docs/diagnostics.md` に G02091 の節を足す。
- 開発者向けマニュアルの意味論 IR の章と、利用者向けマニュアルの diagnostic の付録を直す。
