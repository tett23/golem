# ADR 0008: 複数の `@index` と `@bibliography`

ステータス: 採択

## 文脈

`@toc`、`@index`、`@bibliography` は、チャネルの一覧を置くブロックコマンドである（仕様書の「チャネル」の節）。
[golem-doc ADR 0002](0002-document-assembly.md) は、`@toc` を文書に一つまでとし、二つ目からをエラー（G0402）にすると定めた。
`@index` と `@bibliography` の数は、どの ADR も定めていない。

v0.1.0-rc4 の作業中のコード（a2b6106e）で、二つの章のファイルの両方に `@index` と `@bibliography` を置き、`golem build` を実行した。
diagnostic は出ず、終了コードは 0 だった。
HTML では、どちらのファイルにも索引と参考文献の一覧の全体が出た。
一つのファイルに `@bibliography` を二つ置くと、そのファイルの XHTML に `id="cite-knuth1984"` が二つでき、文書の中で `id` が重複する。
HTML は文書の中の `id` の重複を許さず、EPUB の XHTML も同じ規則に従う。
プレーンテキストでも、参考文献の一覧が置いた数だけ繰り返される。

原因は `modules/golem-doc/src/Golem/Doc/Assemble.hs` の `assemble` にある。
`numberCitations` と `indexGroups` は、文書の全体から一つの一覧を作る。
出力の経路は、`ChannelOutput` のブロックを見つけるたびに、その一つの一覧の全体を書く。
golem-html は、参考文献の項目の `id` を `cite-<キー>` に固定している。

一冊に索引や参考文献を複数置く組み方は、実際にある。
学術書や論文集には章ごとに参考文献を置く本があり、合本には巻ごとに索引を置く本がある。
LaTeX では、biblatex の `refsection` と chapterbib が章ごとの参考文献を、imakeidx が複数の索引を扱う。
同じ一覧の全体を二度出す本は、ほとんど見当たらない。
そこで、複数の一覧を誤りにせず、それぞれの一覧に文書の一部分の項目を載せる。

人名索引と事項索引のように、同じ範囲の項目を種類で分ける一覧は、この ADR では扱わない。
項目に種類を付ける手段は、プラグインの独自のチャネル（[golem-doc ADR 0007](0007-plugin-channel-lists.md)）が与える。

## 実装すること

### 一覧の範囲

同じ種類の一覧（`@index` どうし、`@bibliography` どうし）を、文書の順に L1、L2、…、Ln とする。
文書の順は、マニフェストの章の順、ファイルの中のブロックの順（`allBlocks` の前順）である。
項目（索引の印、引用の印）は、その項目より後にある最初の一覧 Li に載る。
最後の一覧 Ln より後の項目は、Ln に載る。

- 一覧が一つなら、置いた位置によらず、文書のすべての項目を載せる。今の振る舞いと同じである。
- 章の末尾ごとに `@bibliography` を置けば、章ごとの参考文献になる。
- 項目のブロックと一覧のブロックの前後は、ブロックの順で決める。脚注、傍注、図版のキャプション、表のセルの中の項目は、それを含むブロックの位置にあるものとする。
- 項目のない一覧は、今、項目のない一覧に出しているものと同じものを出す。

`@toc` は、今のまま文書に一つだけとし、G0402 を変えない。
章ごとの小目次は、`docs/roadmap.md` の v2 の「目次の拡張」に残す。

### 参考文献の番号

- 番号は一覧ごとに 1 から振る。一覧の中の順は、今と同じく、その一覧の範囲で最初に引用された順である。
- 同じ文献を二つの範囲で引用すれば、両方の一覧に載り、それぞれの一覧の番号を持つ。
- 引用の印は、その印が載る一覧での番号を表示する。
- 文書に `@bibliography` がなければ、今と同じく文書の全体で番号を振る。

### 索引

- 索引の一覧は、その範囲の印だけで項目を作り、並べ替えとページ番号の規則は今と同じとする。
- 索引の一覧から本文の印へのリンク（HTML と EPUB）の先は、今と同じ印の位置（`i-<ファイル>-<位置>`）である。印の `id` は印ごとに一つなので、一覧が増えても重複しない。
- PDF の印のページの収束の判定（G0721）は、すべての一覧の印を合わせて行う。
- プレーンテキストには、今と同じく索引を出力しない。

### 引用の印のリンク

HTML と EPUB の引用の印は、その印が載る一覧の、その文献の項目へリンクする。
一覧が別のファイルにあれば、参照先のファイルへの相対リンクにする。
一覧が一つの本では、[golem-html ADR 0003](../../golem-html/adr/0003-cite-links-across-files.md) の「最初の `@bibliography` へのリンク」と同じ先になる。
二つ以上の本では、この ADR の規則がその ADR の規則に代わる。
文書に `@bibliography` がなければ、印をリンクにしない（[golem-html ADR 0003](../../golem-html/adr/0003-cite-links-across-files.md) と同じ）。

### HTML の `id`

参考文献の項目の `id` を、本の全体で一意にする。

- 一覧を文書の順に、一覧の中の項目を番号の順にたどり、項目ごとに `id` を決める。
- 候補は `cite-<キー>`、`cite-<キー>-2`、`cite-<キー>-3`、… の順とし、本の中でまだ使っていない最初の候補を使う。
- 一覧が一つの本では、どの項目も `cite-<キー>` になり、今の出力と同じである。
- キーが `knuth-2` の文献と、二つ目の一覧の `knuth` の文献のように、候補が別のキーの `id` と重なる場合も、先に決めた `id` を避けるので重複しない。

`id` は出力の段階の値なので、golem-html で `Book` から求める。
EPUB の本文は golem-html の出力なので、同じ `id` になる。

### PDF とプレーンテキスト

- PDF は、それぞれの `@bibliography` の位置に、その一覧の項目を `[n] ` と書誌で組み、それぞれの `@index` の位置に、その一覧の索引を組む。
- プレーンテキストは、それぞれの `@bibliography` の位置に、その一覧を出す。

## データ構造

`Golem.Doc.Assemble` の `Book` の、一つの一覧を表す欄を、一覧ごとの欄に変える。

```haskell
-- 一覧のブロックの位置（ファイルとブロックの範囲）
type ListAt = (FileId, SrcSpan)

data Book = Book
  { -- 今の bookCitations :: [(Text, Int)] に代わる
    bookBibliographies :: ![(Maybe ListAt, [(Text, Int)])],
    -- 引用の印ごとの、載る一覧と番号。キーは印のファイルと範囲
    bookCiteMarks :: !(Map (FileId, SrcSpan) (Maybe ListAt, Int)),
    -- 今の bookIndex :: [IndexGroup] に代わる
    bookIndexes :: ![(ListAt, [IndexGroup])],
    ...
  }
```

`bookBibliographies` は、`@bibliography` があれば一覧ごとに一つ、なければ位置が `Nothing` の一つを持つ。
出力の経路は、`ChannelOutput` のブロックの位置から、その一覧を引く。
`bookCiteMarks` は、PDF、HTML、EPUB、プレーンテキストが引用の印の番号を引くのに使う。

IR と CBOR は変えないので、プラグインの ABI は 7 のままである。

## 実装しないこと

- 複数の一覧を誤りにすること。今の振る舞いのうち、誤りにした組み方はない。
- 同じ範囲の項目を種類で分ける一覧（人名索引と事項索引など）。[golem-doc ADR 0007](0007-plugin-channel-lists.md) の独自のチャネルで扱う。
- 複数の `@toc` と章ごとの小目次。
- 参考文献の項目から本文の引用の印へ戻るリンク。

## テスト設計

先に次のテストを書き、今のコードで失敗することを確かめてから実装する。

- golem-doc（`AssembleSpec.hs`）
  - `@bibliography` が一つの文書で、置く位置を先頭、途中、末尾に変えても、`bookBibliographies` の項目と番号が今の `numberCitations` と同じになる。
  - 章 1 で A、B、章 2 で B、C を引用し、各章の末尾に `@bibliography` を置いた文書で、一つ目の一覧が A=1、B=2、二つ目が B=1、C=2 になり、章 2 の B の印の番号が 1 になる。
  - 最後の `@bibliography` の後の引用が、最後の一覧に載る。
  - 脚注の中の引用が、脚注の印を含む段落の位置の一覧に載る。
  - `@index` を二つ置いた文書で、それぞれの一覧が自分の範囲の印だけを持つ。
  - `@bibliography` がない文書で、`bookBibliographies` が位置 `Nothing` の一つの一覧を持ち、番号が今と同じになる。
  - `@toc` が二つの文書では、今のまま G0402 が出る。
- golem-html
  - 上の章ごとの参考文献の本で、一つ目の一覧の B が `cite-B`、二つ目の一覧の B が `cite-B-2` になり、章 2 の B の印が `cite-B-2` へリンクする。
  - 同じファイルに `@bibliography` を二つ置いた本で、そのファイルの `id` に重複がない。
  - キー `knuth-2` の文献を一つ目の一覧に、`knuth` を両方の一覧に持つ本で、二つ目の一覧の `knuth` が `cite-knuth-3` になる。
  - 一覧が一つの本の出力が、今の出力とバイト単位で同じになる（golden）。
- golem-driver
  - 章ごとの参考文献の本の PDF で、それぞれの一覧の位置に、その範囲の書誌が組まれる。
  - 二つの `@index` を置いた本の PDF で、それぞれの索引に、その範囲の印のページだけが載る。
  - プレーンテキストで、それぞれの `@bibliography` の位置に、その範囲の一覧が出る。
  - EPUB を epubcheck に通し、`id` の重複とリンク切れの誤りが出ないことを確かめる（CI の epubcheck の fixture に、章ごとの参考文献の章を足す）。

## トレードオフ

一覧ごとに範囲を分けると、同じ一覧の全体を二か所に出すことはできなくなる。
そのような本は少なく、分けるほうが、章ごとの参考文献と巻ごとの索引という実際の需要に合う。
一覧が一つの本の出力は変わらない。

一覧の範囲を「後にある最初の一覧」で決めると、章の冒頭に `@bibliography` を置く本では、その章の引用が次の章の一覧に載る。
範囲を明示する記法（biblatex の `refsection` のような区切り）を足す案もあったが、記法が一つ増える。
章の末尾に置く本が大半なので、記法を足さずに位置だけで決める規則を選んだ。

`id` の接尾辞を、本の中で使っていない候補から選ぶので、別のキーの文献が増えると、ある文献の `id` が変わることがある。
`id` は Golem の出力の中のリンクの先であり、外から参照する名前として保証していないので、受け入れる。

## ドキュメント

メインのセッションが、次の変更をする。

- 仕様書の「索引」と「引用と参考文献」の節に、複数の一覧の範囲、参考文献の番号、引用の印のリンク、`id` の規則を書く。
- 仕様書の「既知の不具合」から「`@index` と `@bibliography` の重複」を消す。
- 利用者向けマニュアルの索引と参考文献の章に、章ごとの参考文献の書き方を足す。
- [golem-html ADR 0003](../../golem-html/adr/0003-cite-links-across-files.md) の草稿の「`@bibliography` を二つ以上置いた本では、最初の一覧へリンクする」は、この ADR の規則に置き換わる。二つの ADR を同じ時期に採択するなら、その草稿の該当の文を、この ADR へのリンクに直す。
