# ADR 0007: プラグインの独自のチャネル

ステータス: 採択

## 文脈

仕様書の「チャネル」の節は、脚注、索引、参考文献、目次を、文書の各所から項目を集めて別の位置に一覧として出す形（チャネル）として一般化している。
同じ節の「プラグインとの関係」は、次の三つを述べる。

- プラグインはチャネルに項目を送れるが、チャネルの中身は読めない。
- 送ることはファイル内評価（S0）でできるので、プラグインの実行範囲の規則を変えずに済む。
- 用語集のような独自の一覧も、プラグインで作れる。

一つ目と二つ目は今の実装に合っている。
プラグインのコマンドとフィルタの出力に注（inline の tag 12）、索引の印（tag 14）、引用の印（tag 15）を含めれば、S1 はそれを原稿に書いた印と同じく集める。

三つ目は実装に合わない。
意味論 IR のチャネルを出力するブロック（block の tag 8、[golem-doc ADR 0001](0001-semantic-ir-in-cddl.md)）は、`channel = [0, depth: uint] / [1] / [2]`（目次、索引、参考文献）の三種類に固定されている。
インラインの側にも、名前を付けたチャネルへ項目を送る要素はない。
プラグインの `golem_describe` が宣言できるのはコマンドとフィルタだけであり（[golem-plugin ADR 0001](../../golem-plugin/adr/0001-wasm-host-and-abi.md)）、一覧を置く組み込みのブロックコマンドも三つしかない。
したがって、プラグインが独自のチャネルに項目を送り、その一覧を本のどこかに出す経路はない。
2026-10-16 の監査（[docs/audits/2026-10-16-tex-feature-gap.md](../../audits/2026-10-16-tex-feature-gap.md)）も、用語集と複数の索引を、計画のない不足として挙げている。

プラグインは v0.1.0-rc4 で仕上げ、v1 に含める。
用語集、略語集、人名索引、図版の出典の一覧のように、本文の各所から集めて一か所に出す一覧は、プラグインの作者が最初に作りたがるものの一つである。
そこで、仕様の文を消すのではなく、プラグインが独自のチャネルを宣言し、項目を送り、利用者がその一覧を置ける仕組みを作る。
プラグインの ABI のバージョン 7 はまだリリースしていないので、ABI はバージョンを変えずに広げられる。

一覧を複数置いたときの範囲は、[golem-doc ADR 0008](0008-multiple-index-and-bibliography.md) が `@index` と `@bibliography` に定める規則に合わせる。

実装は v0.1.0-rc4 で行う。

## 実装すること

### チャネルの宣言

プラグインは、`golem_describe` の応答で、コマンドとフィルタに加えてチャネルを宣言する。

- チャネルの名前は、英小文字で始まり、英小文字、数字、`-` だけからなる。
- 並べ方（`order`）は、文書の順（`0`）か、読みの順（`1`）のどちらかとする。
- ページ番号（`locators`）は、一覧の項目に出現の位置（PDF のページ番号、HTML と EPUB のリンク）を付けるかどうかである。

次の名前は組み込みのチャネルのために予約し、宣言できない：`toc`、`index`、`bibliography`、`note`、`notes`、`sidenote`、`cite`。

プラグインの読み込みの時点で、次を新しいエラー G0612 とする。
位置とメッセージの形は、コマンドの名前の衝突（G0606）と同じく `manifest.toml` の先頭とし、プラグインの名前を書く。

- 二つのプラグインが同じ名前のチャネルを宣言した：`複数のプラグインが同じチャネルを宣言しています: <チャネル>（<プラグイン>、<プラグイン>）`
- 予約した名前か、形の誤った名前を宣言した：`<プラグイン>: このチャネルの名前は使えません: <チャネル>`

### チャネルの項目

プラグインのコマンドとフィルタは、出力のインラインに、チャネルの項目（新しい inline の tag 19）を含めて送る。
項目は次の欄を持つ。

- **チャネル**：送り先のチャネルの名前。
- **キー**：同じ項目を一つにまとめるための文字列か、null。
- **読み**：読みの順のチャネルで並べるための文字列か、null。
- **本文**：一覧に出す内容（インラインの列）。

項目は、出現の位置に何も出さない。
本文に出したい語（用語集の語など）は、プラグインが項目と並べて、ふつうのインラインとして返す。

ホストは、プラグインの出力を検証するとき、次を不正な出力（G0609）とする。

- 項目のチャネルが、出力したプラグイン自身の宣言したチャネルでない（`宣言していないチャネルです: <チャネル>`）。
- 読みの順のチャネルの項目の読みが null か空である（`読みの順のチャネルの項目には読みが要ります: <チャネル>`）。
- 本文に、注、傍注、索引の印、引用の印、チャネルの項目を含む（メッセージは `チャネルの項目の本文に置けない要素があります` である）。一覧の中から、ほかのチャネルへ項目を送らないためである。

### 一覧を置くブロックコマンド

原稿には、組み込みのブロックコマンド `@channel` で一覧を置く。

```
# 用語集

@channel glossary style=glossary
```

- 位置引数は、チャネルの名前を一つ取る。
- キーワード引数 `style` は、一覧の項目を組む段落スタイルの名前とし、省けば `body` とする。
- 読み込んだプラグインが宣言していない名前は、新しいエラー G0290 とする。メッセージは `宣言されていないチャネルです: <チャネル>`、位置はブロックコマンドである。引数の数の誤りも G0290 とし、メッセージは `@channel にはチャネルの名前を一つ書きます` とする。
- `style` の段落スタイルが定義されていなければ、`@style` と同じく G0247 とする。
- プラグインの読み込みか検査が誤りを出したときは、G0290 を出さない。読み込めなかったプラグインのチャネルが、すべて未知のチャネルになって本当の原因を埋もれさせるためである（未知のコマンドの G0222 と同じ扱い）。
- 同じチャネルの `@channel` を二つ以上置いてよい。それぞれの一覧の範囲は、[golem-doc ADR 0008](0008-multiple-index-and-bibliography.md) の規則（項目は、その後にある最初の同じチャネルの一覧に載り、最後の一覧より後の項目は最後の一覧に載る）に従う。
- `@channel` を置かないチャネルの項目は、どこにも出ない。diagnostic は出さない。

### S1 の集約

一覧ごとに、範囲の項目から一覧の項目（エントリ）を作る。

1. キーが同じ項目を一つのエントリにまとめる。キーが null の項目は、それぞれが一つのエントリになる。
2. エントリの本文と読みは、まとめた項目のうち文書の順で最初の項目のものとする。
3. エントリの出現の位置は、まとめた項目の位置を文書の順に並べたものとする。
4. 文書の順のチャネルでは、エントリを最初の出現の位置の順に並べる。読みの順のチャネルでは、読みを索引と同じ照合（`Golem.Doc.Collation`、[golem-doc ADR 0002](0002-document-assembly.md) の「索引の並べ替え」）で比べ、等しければキーをコードポイントの順で、それも等しければ最初の出現の位置の順で並べる。

並べ方は入力だけで決まるので、決定性は保たれる。

### 出力

| 媒体 | 一覧の位置に出すもの | 項目の出現の位置 |
| --- | --- | --- |
| PDF | エントリを一つの段落として、`style` の段落スタイルで組む。`locators` が真なら、本文の後に全角の空白とページ番号の列を付ける | 何も組まない |
| HTML と EPUB | `<section class="channel" data-channel="<チャネル>">` の中の `<ul>` に、エントリを `<li>` として並べる。`locators` が真なら、本文の後に出現の位置へのリンク（`1`、`2`、… の番号）を付ける | `locators` が真なら `<span id="c-<チャネル>-<ファイル>-<位置>"></span>` |
| プレーンテキスト | エントリの本文を一行ずつ書く。出現の位置は書かない | 何も書かない |

- PDF のページ番号の書き方は索引と同じとする。昇順に並べ、同じページは一度だけ出し、区切りは横組みで `, `、縦組みで `、` とし、縦組みでは `[numbers]` の `vertical` の表記にする。脚注と傍注の本文の中、図版のキャプションの中の項目のページも、索引の印と同じ規則で決める。
- PDF の出現の位置のページは、索引の印と同じくレイアウトを繰り返して収束させ、上限の回数までに収束しなければ G0721 とする。G0721 のメッセージに並べる語には、エントリの本文の文字列を使う。
- HTML と EPUB の出現の位置の `id` は、ファイルの番号と位置の二つの整数で終わるので、チャネルの名前に `-` を含んでも、本の中で重複しない。リンクは、索引と同じく参照先のファイルへの相対リンクにする。
- エントリのない一覧は、PDF とプレーンテキストでは何も出さず、HTML と EPUB では空の `<ul>` を持つ `<section>` を出す（今の空の索引と同じ）。
- 一覧は目次と EPUB のナビゲーション文書に入れない。見出しは、利用者が `@channel` の前に書く。

### プラグインが読めるもの

プラグインは、今と同じくチャネルの中身を読めない。
エントリの並びやページ番号は S1 と S2 で決まり、プラグインには渡らない。

## データ構造

### 意味論 IR（CDDL）

```cddl
; inline-no-ruby に足す
  / [19, span, channel: tstr, key: tstr / null, reading: tstr / null, inlines] ; channel item (golem-doc ADR 0007)

; channel に足す
channel = [0, depth: uint] / [1] / [2] / [3, name: tstr, style: tstr / null]

; golem_describe の応答
description = [commands: [* tstr], filters: [* tstr], channels: [* channel-decl]]
channel-decl = [name: tstr, order: 0 / 1, locators: bool]       ; order: document, reading
```

ABI のバージョンは 7 のままとする。
7 はまだリリースしておらず、同じリリースの中の変更だからである。
二つの欄の `description` は不正な応答（G0605）になるので、プラグインの SDK は三つ目の欄を書く必要がある。

### Haskell の型

```haskell
-- Golem.Doc.IR
data InlineF ruby = ... | ChannelItem !SrcSpan !ChannelItem
data ChannelItem = ChannelItemData
  { ciChannel :: !Text, ciKey :: !(Maybe Text), ciReading :: !(Maybe Text), ciBody :: ![Inline] }
data ChannelBlock = TocOutput !Int | IndexOutput | BibliographyOutput | CustomOutput !Text !(Maybe Text)

-- Golem.Doc.Assemble
data ChannelEntry = ChannelEntry
  { ceKey :: !(Maybe Text), ceBody :: ![Inline], ceLocations :: ![(FileId, SrcSpan)] }
-- Book に足す。一覧ごとに、一覧の位置、チャネルの名前、エントリ
bookChannels :: ![((FileId, SrcSpan), Text, [ChannelEntry])]
```

チャネルの宣言（名前、並べ方、`locators`）は、プラグインの読み込みの結果として評価と S1 と出力に渡す。

## 実装しないこと

- 原稿から、プラグインを通さずにチャネルへ項目を送る組み込みのコマンド。需要が見えてから ADR で決める。
- プラグインがチャネルの中身、エントリの並び、ページ番号を読むこと（[golem-plugin ADR 0001](../../golem-plugin/adr/0001-wasm-host-and-abi.md) のとおり）。
- 一覧の段組み、見出しの文字（「あ」「か」のような行の区切り）、エントリの階層（副項目）。索引の拡張（`docs/roadmap.md` の v2）と合わせて扱う。
- 図目次と表目次。仕様書の「図目次や表目次も、ラベル付きの図や表が送られるチャネルとして同じ仕組みで追加できる」は、組み込みのチャネルの話であり、v2 の「目次の拡張」のままとする。
- 一覧の文言の多言語化と、`style.toml` でエントリの書式を変えること。

## テスト設計

テスト用のプラグインを wat で書く（[golem-plugin ADR 0001](../../golem-plugin/adr/0001-wasm-host-and-abi.md) のとおりリポジトリに置く）。
`glossary`（読みの順、`locators` が偽）と `people`（文書の順、`locators` が真）の二つのチャネルを宣言し、コマンド `term` と `person` が項目と語を返す。
先に次のテストを書き、失敗することを確かめてから実装する。

- **ABI**：三つの欄の `description` が読める。二つの欄の `description` が G0605 になる。予約した名前（`index`）と形の誤った名前（`Glossary`）の宣言が G0612 になる。二つのプラグインが同じ `glossary` を宣言すると G0612 になる。
- **CDDL**：生成器（`Gen.hs`）にチャネルの項目と `CustomOutput` を足し、往復と CDDL の検証器での適合を確かめる。
- **検証**：宣言していないチャネルの項目、読みのない読みの順の項目、本文に注を含む項目を返すプラグインが、それぞれ G0609 になる。
- **評価**：`@channel unknown` が G0290、`@channel` と `@channel a b` が G0290、`style` に未定義のスタイルを書くと G0247 になる。プラグインの読み込みが失敗したプロジェクトでは G0290 が出ない。
- **S1**：同じキーの三つの項目が一つのエントリになり、本文が最初の項目のもの、出現の位置が三つになる。キーが null の二つの項目が二つのエントリになる。読みの順のチャネルで、`かんじ`、`かな`、`カナ` の読みのエントリが索引と同じ順に並ぶ。文書の順のチャネルで、ファイルをまたいで最初の出現の順に並ぶ。`@channel people` を二つの章の末尾に置くと、それぞれの章の項目だけが載る（[golem-doc ADR 0008](0008-multiple-index-and-bibliography.md) の規則）。
- **出力**：
  - PDF で、`people` のエントリにページ番号の列が付き、`glossary` のエントリには付かない。縦組みでページ番号が漢数字になる。脚注の中の項目のページが、注の印を含む行のページになる。
  - HTML で、`people` の項目の位置に `id` が置かれ、一覧のリンクが別のファイルへの相対リンクになる。チャネルの名前が `a-1` と `a` のときも `id` が重複しない。
  - EPUB を epubcheck に通し、誤りが出ない。
  - プレーンテキストで、エントリの本文が一行ずつ出る。
  - 一覧のバイト列が、同じ入力から毎回同じになる。

## トレードオフ

一覧の形を、文書の順と読みの順、ページ番号の有無の組み合わせに限った。
用語集（読みの順、ページ番号なし）、略語集（読みの順）、人名索引（読みの順、ページ番号あり）、図版の出典の一覧（文書の順）は、この範囲で作れる。
副項目や段組みの要る一覧は作れないが、形を広げるのは、使うプラグインが現れてから ABI のバージョンを上げて行えばよい。

項目を送るのをプラグインに限ったので、プラグインを使わない書き手は独自の一覧を作れない。
組み込みのコマンドを足すと、項目の欄（キー、読み、本文）を原稿の記法で書く方法を決める必要があり、プラグインの需要を確かめる前に記法を固定することになる。

エントリの本文を最初の項目のものにしたので、同じキーの項目が違う本文を持っていても diagnostic は出ない。
本文を揃えるのはプラグインの責任とし、ホストはプラグインの意図を推測しない。

## ドキュメント

メインのセッションが、次の変更をする。

- 仕様書の「チャネル」の節の「プラグインとの関係」に、チャネルの宣言、項目、`@channel`、エントリのまとめ方と並べ方、媒体ごとの出力を書く。
- 仕様書の「プラグイン」の節と `docs/markup.md` のブロックコマンドの一覧に、`@channel` を足す。
- 仕様書の「既知の不具合」から「プラグインの独自の一覧」を消す。
- `docs/roadmap.md` の v0.1.0-rc4 に「プラグインの独自のチャネル」を足し、実装したら消す。
- `docs/diagnostics.md` に G0290 と G0612 を足し、G0605 と G0609 の理由に、この ADR のメッセージを加える。
- 開発者向けマニュアルの意味論 IR の章（`manual-dev/part1/06-ir.gm`）の「プラグインとチャネル」の節とタグの表、プラグインの章を直す。利用者向けマニュアルのプラグインの章に `@channel` を足す。
