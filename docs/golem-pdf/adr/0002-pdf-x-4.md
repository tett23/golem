# ADR 0002: PDF/X-4 への準拠

ステータス: 採択→検証ツールの選定は ADR 0003

## 文脈

Golem の印刷用の PDF は、商業の入稿に耐える PDF/X-4 に準拠させる。
準拠する規格は ISO 15930-7:2010 とする。
この規格は PDF 1.6 を基礎とし、印刷に必要なすべての要素をファイルの中に含む PDF/X-4 と、ICC プロファイルを外部から参照する PDF/X-4p を定める。
Golem が出力するのは PDF/X-4 だけである。

規格の本文は有償であり、この ADR を書いた時点では本文を参照できていない。
以下の要件の一覧は、一般に知られている PDF/X-4 の要件と、検証ツールの文書から作ったものである。
実装を始める前に規格の本文を入手し、一覧と照合して、差分があればこの ADR を改める新しい ADR を作る。

## 実装すること

### 要件

- PDF の版を 1.6 とする。
- 出力インテント：`OutputIntents` に、`S` を `GTS_PDFX` とし、`style.toml` の `color.intent` の ICC プロファイル（v1 では Japan Color 2001 Coated）を `DestOutputProfile` として埋め込み、`OutputConditionIdentifier` を設定した辞書を置く。
- XMP のメタデータ：カタログに XMP のメタデータのストリームを置き、`pdfxid:GTS_PDFXVersion` を `PDF/X-4` とする。題名（`dc:title`）、作成日時と更新日時、文書 ID などの項目を、規格の要求に従って書く。
- トラッピング：`Trapped` を `False` とする。Golem はトラッピングを行わないためである。
- ページのボックス：各ページに `TrimBox` を置き、`BleedBox` を置く場合は `MediaBox` の内側に収める。
- フォント：使うすべてのフォントを埋め込む（golem-font ADR 0002）。
- 色：本文の色は、出力インテントと同じ CMYK の色空間で書く。画像は ICC プロファイル付きで埋め込み、変換しない。
- 禁止される要素：暗号化、JavaScript、外部への参照を含めない。

### 日時と ID

XMP と文書情報辞書の日時と ID は、ADR 0001 の規則に従って決定的に作る。

### 検証

- 出力の PDF を、PDF/X-4 の検証ツール（プリフライト）で検査する。
- 自由に使える PDF/X の検証ツールは限られている。CI で使う検証ツールの選定は、実装の最初の段階で行い、選んだツールと版をこの ADR を改める ADR に記録する。それまでは、上の要件ごとの検査を Golem のテストとして書く。

## 実装しないこと

- PDF/X-4p（外部の ICC プロファイルの参照）。
- スポットカラー（Separation と DeviceN の色空間）。
- 透明の効果。PDF/X-4 は透明を許すが、v1 のレイアウトは透明を使わない。
- トラッピング。

## テスト設計

- 出力の PDF を解析し、上の要件のそれぞれ（版、出力インテント、XMP の `GTS_PDFXVersion`、`Trapped`、各ページの `TrimBox`、フォントの埋め込み、禁止される要素がないこと）を検査するテストを書く。
- XMP のメタデータを golden テストで固定する。
- 検証ツールを選んだ後は、CI でそのツールの検査を通すことを確かめる。

## トレードオフ

規格の本文を参照せずに要件を書いたので、この ADR の要件には漏れがある可能性がある。
実装の前に本文と照合する手順をこの ADR に組み込み、漏れは新しい ADR で補う。

自由に使える検証ツールが限られているので、CI での検証は Golem 自身のテストに頼る期間がある。
商業の印刷所に入稿する前には、印刷所の側のプリフライトでも確かめることを README に記載する。
