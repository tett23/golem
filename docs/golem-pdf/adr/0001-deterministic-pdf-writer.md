# ADR 0001: 決定的な PDF の直列化

ステータス: 採択

## 文脈

既存の Haskell の PDF のライブラリは、PDF/X-4 と決定性の要件を満たさないので、PDF の生成は自前で実装すると決めている。
PDF のバイト列には、非決定性が入り込む場所が多い。
オブジェクトの番号と並び、辞書のキーの順序、実数の書き方、圧縮の実装と設定、フォントやリソースの名前、日時、文書 ID がそれである。
この ADR は、レイアウトの結果を受け取り、これらをすべて固定して PDF を書く直列化を定める。
PDF/X-4 に固有の要件は ADR 0002 で扱う。

## 実装すること

### 入力

レイアウト（golem-layout ADR 0003）から、ページごとの記述を受け取る。

```haskell
data Page = Page
  { pageMediaBox :: !Rect
  , pageTrimBox  :: !Rect
  , pageBleedBox :: !Rect
  , pageContent  :: ![Mark]
  }

data Mark
  = GlyphRun !FontRef !Sp ![(GlyphId, Sp, Sp)]   -- フォント、大きさ、グリフと位置
  | Rule !Rect
  | Image !ImageRef !Rect
  | SetColor !Swatch
```

### 直列化の規則

- PDF の版は 1.6 とする（PDF/X-4 の基礎となる版）。
- オブジェクトの番号は、カタログ、ページツリー、各ページ、フォント、画像、メタデータの順に、文書の中で初めて参照された順で振る。
- 辞書のキーは、キーの名前の順に並べて書く。
- 相互参照は、従来の相互参照表で書き、相互参照ストリームとオブジェクトストリームは使わない。
- フォントや画像のリソースの名前（`/F1`、`/Im1` など）は、初めて参照された順に振る。
- 座標と寸法は、整数の sp を pt に変換し、小数点以下 4 桁に丸めて、末尾のゼロを除いた十進数で書く。丸めは最近接偶数丸めとし、整数の計算で行う。

### 圧縮

- 内容のストリームとフォントのストリームは Flate で圧縮する。
- 圧縮には zlib 1.3.2 を使い、同梱して版を固定し、圧縮の水準を固定する。zlib の版が変わると圧縮の結果のバイト列が変わりうるので、版を上げるときは ADR を作成し、README の表に記載する。

### 画像

- JPEG は、復号せずにそのまま埋め込む（`DCTDecode`）。
- PNG は、画素を取り出して Flate で圧縮し直して埋め込む。
- 画像の ICC プロファイルは、そのまま `ICCBased` の色空間として埋め込む。プロファイルのない RGB の画像には sRGB のプロファイルを付ける。Golem は画像の色を変換しない。

### 日時と文書 ID

日時と文書 ID は、specifications.md の「メタデータ」の節の規則に従い、マニフェストの `metadata.date` と、本の識別子と入力全体のハッシュから作る。

## 実装しないこと

- PDF/X-4 に固有の要件（出力インテント、XMP、ボックスの検査）。ADR 0002 で扱う。
- 暗号化、注釈、しおり（アウトライン）、リンク。
- 相互参照ストリームとオブジェクトストリームによる、ファイルの縮小。

## テスト設計

- 同じページの記述から二回書いた PDF のバイト列が一致することを確かめる。
- 二つのアーキテクチャで書いた PDF のバイト列が一致することを確かめる。
- 実数の書き方（0、負の数、小数点以下の丸め、末尾のゼロ）を確かめる。
- qpdf の `--check` で、出力の PDF の構造が正しいことを確かめる。
- JPEG が復号されずに埋め込まれ、ICC プロファイルが保たれることを確かめる。

## トレードオフ

相互参照ストリームとオブジェクトストリームを使わないので、PDF のファイルは少し大きくなる。
その代わり、PDF の構造が単純になり、出力を人が読んで確かめやすく、ファイルの差分もとりやすい。

zlib を同梱して版を固定するので、zlib の更新も ADR を経た手作業になる。
