# ADR 0012: PDF/X-4 の検査は、見つけた禁止の名前を見つけた順に並べる

ステータス: 採択（未実装）

## 文脈

`Golem.Pdf.X4.verify` は、PDF が PDF/X-4 の要件を満たすかを確かめる（[ADR 0003](0003-pdf-x-4-validator.md)）。
要件の一つ「JavaScript と外部への参照」は、トレーラーとオブジェクトの中に `JavaScript`、`JS`、`URI`、`Launch`、`GoToR` の名前があれば、見つけた名前を「、」でつないだ問題文（`<名前>、<名前> があります`）を出す。

テストの質を上げる作業（2026-10-23）で、名前が見つけた順の逆に並ぶことが分かった。
重複を除く関数 `nubOrd'` が、リストを反転してから右から畳み込むためである。
たとえば、`JavaScript`、`URI`、`Launch` の順に見つかると、問題文は `Launch、URI、JavaScript があります` になる。

出力は決定的であり、仕様書と ADR は並びの順を決めていない。
ただ、ほかに名前やページの番号を並べる問題文（TrimBox のないページ、埋め込んでいないフォント）は、走査の順のまま並べており、この問題文だけが逆になる理由はない。
`nubOrd'` の名前と形から見て、見つけた順に一度ずつ並べる意図で書かれたものと読める。
読み手は、PDF の中を先頭から探すときに、問題文の順で名前を探す。

## 実装すること

- 禁止の名前を、トレーラー、オブジェクトの順に走査して最初に見つけた順に、一度ずつ並べる。
- 名前の一覧、走査の範囲、問題文の形は変えない。
- この並びを、仕様書の PDF/X-4 の検査の節に書く（「見つけた順に一度ずつ」）。
- [ADR 0003](0003-pdf-x-4-validator.md) のステータスの行に「、禁止の名前の並びは [ADR 0012](0012-x4-forbidden-names-in-found-order.md)」を足す。

## 実装しないこと

- 名前を辞書の順や決まった順（一覧の順）に並べること。見つけた順のほうが、PDF の中を探す手がかりになる。
- 禁止の名前の一覧を変えること。

## テスト設計

テストを先に書き、今の実装で失敗することを確かめる。

- golem-pdf：`JavaScript`、`URI`、`Launch` をこの順に持つ PDF で、問題文が `JavaScript、URI、Launch があります` になること。今は逆順になるので失敗する。
- golem-pdf：同じ名前が二度出る PDF（`URI`、`JavaScript`、`URI`）で、`URI、JavaScript があります` になること。
- golem-pdf：トレーラーにある名前が、オブジェクトの中の名前より先に並ぶこと。

## トレードオフ

- 問題文の文言の並びが変わるので、今の出力と比べている人がいれば差が出る。利用者はメンテナーだけであり、問題はない。
