# ADR 0002: 行末に空白のある改行でも、欧文の単語のつながり（G05001）を見つける

ステータス: 採択

## 文脈

[ADR 0001](0001-lint-rules.md) は、段落の中の改行の前後がともに欧文の文字である箇所を G05001 とした。
改行は文字を生まないので、そうした改行の前後の単語は、空白なしにつながる。

テストの質を上げる作業（2026-10-23）で、G05001 が次のような原稿を見逃すことが分かった。

```
word··
word
```

（`·` は半角の空白を表す。）

- 言語の仕様は、行末の空白を無視する（[markup.md](../../markup.md) の「空白の扱い」）。AST も行末の空白を捨てるので、この段落は「wordword」と組まれる。
- G05001 の判定（`Golem.Lint.latinJoinedByNewline`）は、構文木（CST）の改行の直前のテキストの最後の文字を見る。CST では、行末の空白が `KText "word··"` の中に入るので、最後の文字は空白になり、欧文の文字と判定されない。
- リストの項目の継続行（`"- word··\n   word\n"`）でも同じことが起きる。

つまり、lint は、仕様のとおりに単語がつながる箇所を見逃している。
書き手は改行の前に空白を置けば単語が分かれると思いやすいので、この見逃しは、単語のつながりに気づけない原稿を生む。

## 実装すること

- G05001 の判定で、改行の直前の文字を求めるとき、テキストの末尾の半角の空白（U+0020）とタブを除いてから最後の文字を見る。言語の仕様が無視する空白と同じ範囲である。
- 改行の直後の文字も、仕様が無視する行頭の半角の空白とタブを除いてから見る。行頭の空白は今も別のトークン（`KWhitespace`）になっていて除かれているが、テキストの頭に入る場合にも同じに扱う。
- 全角の空白（U+3000）は、仕様が無視しないので除かない。全角の空白を挟んだ改行は単語をつながないので、今のとおり G05001 にしない。
- エスケープした空白（`\·`）は、仕様が残すので除かない。今のとおり G05001 にしない。
- 強制改行（行末の `\`）は、[docs/adr 0016](../../adr/0016-hard-line-breaks.md) のとおり G05001 の対象にしない。
- diagnostic の位置、メッセージ、重大度は変えない。位置は今のとおり改行の文字である。

### ドキュメント

- docs/diagnostics.md の G05001 の節に、行末に半角の空白があっても単語がつながることを、主な原因として足す。
- 仕様書の lint の節の G05001 の説明に、改行の前後の文字は、仕様が無視する行末と行頭の空白を除いて判定することを書く。
- [ADR 0001](0001-lint-rules.md) のステータスの行に「、G05001 の行末の空白の扱いは [ADR 0002](0002-latin-join-after-trailing-spaces.md)」を足す。

## 実装しないこと

- lint のほかの規則の変更。
- 行末の空白そのものを報告すること。仕様が無視するものであり、書き手の誤りとは限らない。

## テスト設計

テストを先に書き、今の実装で失敗することを確かめる。

golem-lint の `test/Main.hs` の G05001 のテストに、次を足す。

- `"word··\nword\n"` が、改行の位置に G05001 を一つ出すこと。今の実装では出ないので失敗する。
- `"word\t\nword\n"`（行末のタブ）が G05001 を出すこと。
- `"- word··\n   word\n"`（リストの項目の継続行）が G05001 を出すこと。
- `"word　\nword\n"`（行末の全角の空白）が G05001 を出さないこと。
- `"word\\·\nword\n"`（行末のエスケープした空白）が G05001 を出さないこと。
- `"word··\\\nword\n"`（強制改行）が G05001 を出さないこと。
- 和文の後の行末の空白（`"語··\nword\n"`）が G05001 を出さないこと。

golem-cli では、`golem lint` で同じ原稿が G05001 を出すことを、一件確かめる。

## トレードオフ

- 今まで出なかった G05001 が出るようになる原稿がある。どれも、出力で単語が実際につながっている箇所であり、出すほうが正しい。
