# ADR 0001: lint の規則

ステータス: 採択→G05001 の韻文の扱いは [docs/adr/0003](../../adr/0003-verse-line-breaks.md)、段落スタイルの扱いは [docs/adr/0005](../../adr/0005-character-and-paragraph-styles.md)、G05001 の改行の様式の扱いは [docs/adr/0013](../../adr/0013-paragraph-separator.md)、G05001 の強制改行の扱いは [docs/adr/0016](../../adr/0016-hard-line-breaks.md)

## 文脈

lint の対象は、構文としては正しいが、ほぼ確実に誤りである記述に限る（specifications.md）。
規則はユーザーが変更も追加もできず、警告を抑制する手段もない。
そのため、誤検知の余地がある規則は採用しない。
表記の好みは扱わず、外部の校正ツールに任せる。

lint の規則には、ファイルの中だけで判定できるものと、プロジェクトの全体を見ないと判定できないもの（使われていない変数、参照されていないラベル）がある。
lint は、ビルドと同じ段階（構文解析、S0、S1）を通した結果を使う。

## 実装すること

### 規則

| コード | 規則 | 重大度 |
|---|---|---|
| G05001 | 段落内の改行の前後がともに欧文の文字である箇所（改行は文字を生まないので、単語が空白なしに連結される） | エラー |
| G05002 | 使われていない `@set` 変数。そのファイルの中でも、そのファイルを import するどのファイルからも参照されていないもの | エラー |
| G05003 | 使われていない `@import` | エラー |
| G05004 | 参照されていない `@label` | dev では警告、prod ではエラー |

- G05001 の「欧文の文字」は、Unicode の文字の一般カテゴリが文字か数字で、かつ文字体系がラテン文字、ギリシア文字、キリル文字のいずれかであるものとする。
- G05002 と G05003 の判定には、golem-project の import のグラフと、S0 での名前の参照の記録を使う。
- G05004 の判定には、S1 のラベルの表と参照の記録を使う。

### 実行

- `golem lint [--profile dev|prod]` は、プロジェクトの全体を構文解析し、S0 と S1 まで評価してから規則を適用する。構文エラーやコンパイルエラーがある場合は、それらの診断も出力する。
- 診断は golem-syntax の形式で、ファイルの順と位置の順に並べて出力する。
- 終了コードは、エラーが一つでもあれば 1、警告だけなら 0 とする。
- golem-cli に `golem lint` を加える。

### ライブラリとしての提供

規則は、CLI と LSP が共有するライブラリとして実装する。
LSP は、編集中のファイルに規則を適用して診断を返す。

## 実装しないこと

- 表記の規則（全角と半角、約物の使い分けなど）。
- 規則の設定ファイル、規則の無効化、箇所ごとの警告の抑制。
- 修正の自動適用。修正案は診断に載せるが、適用は LSP の操作として利用者が選ぶ。

## テスト設計

- 規則ごとに、検出すべき例と検出してはならない例を golden テストで固定する。
- G05001：欧文どうし、和文どうし、和欧の境界での改行のそれぞれで、欧文どうしの場合だけ検出することを確かめる。
- G05002：他のファイルから import されて使われる変数を検出しないことを確かめる。
- G05004：dev と prod で重大度が変わり、dev では終了コードが 0 になることを確かめる。
- 誤検知の余地がないことを確かめるため、docs/markup.md の正しい例のすべてで、lint の診断が出ないことを確かめる。

## トレードオフ

lint をビルドと同じ段階まで評価してから行うので、lint の実行はビルドの S1 までと同じだけの時間がかかる。
ファイルの外を見る規則（使われていない変数、参照されていないラベル）を正しく判定するには、プロジェクトの全体の評価が欠かせないためである。
