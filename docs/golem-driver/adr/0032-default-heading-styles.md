# ADR 0032: 既定の見出し

ステータス: 採択

## 文脈

`style.toml` に `[headings.<階層>]` の `size` を書かない見出しは、PDF で本文と同じ大きさで組まれ、前後に空きがない。
[docs/roadmap.md](../../roadmap.md) の「既定の見出し」が、これを v1 の課題にしている。
`golem new` が作る雛形の `style.toml` は、`[headings.1]` に `number` だけを書いているので、雛形から始めた本の見出しは、どれも本文と見分けにくい。

### 今の振る舞い

コードで確かめた結果は次のとおりである。

- `Golem.Project.Style` の `HeadingStyle` は、`font`、`size`、`number`、`page-break` の四つを持つ（`hsFont`、`hsSize`、`hsNumber`、`hsRectoBreak`）。前後の空きと、占める行数のキーはない。
- 見出しの大きさは、`size` がなければ版面の文字の大きさになる（[ADR 0003](0003-pdf-heading-styles.md)）。
- 見出しが占める行の格子の数は、`Golem.Layout.Paginate.headingBlock` が見出しの大きさと行数から決める、全体を収める最も少ない数である。見出しはその領域の中央に置かれる。版面の文字と同じ大きさの一行の見出しは、格子の一行だけを占め、前後の行と同じ間隔で並ぶ。
- 改ページは、見出しの直後で改ページしない規則（`keep`）で、見出しと、続く段落の最初の 2 行（`nextNeed`）を同じ段に置く。この規則は一つ先のブロックしか見ないので、見出し、見出し、段落と続くと、最初の見出しがページの末尾に残る。仕様書の「既知の不具合」の「見出しの後ろの改ページ」がこれである。
- `golem new` の雛形（`modules/golem-driver/test/golden/new-ja-style.toml`、`new-en-style.toml`）は、`[headings.1]` に `number` だけを書く。
- 決定性の検査の PDF の入力（`scripts/determinism/pdf-style.toml`）と、golem-driver のテストの sample（`modules/golem-driver/test/fixtures/sample/style.toml`）も、`[headings.1]` に `number` だけを書く。
- 二つのマニュアルは、`[headings.1]` に `size = "20Q"`、`[headings.2]` に `size = "15Q"` を書き、`[headings.3]` には `size` を書かない。

HTML と EPUB は見出しの大きさを CSS に書かず（[docs/roadmap.md](../../roadmap.md) の「Web 経路のスタイル」）、ブラウザーと読書環境の `h1` から `h3` の既定の大きさで表示される。
見出しが本文と見分けにくい問題は、PDF にだけある。

### 行取り

日本語の書籍では、見出しの前後の空きを、見出しが占める行の数（行取り）で決めることが多い。
たとえば「3 行取り」の見出しは、本文の 3 行分の領域を占め、その中央に置かれる。
行取りで決めると、見出しの後の本文の行が、版面の行の格子からずれない。
JLReq は、見出しの配置の方法として、改丁、改ページ、行取りを挙げ、大見出し、中見出し、小見出しの順に、行取りを小さくしていく例を示している（記憶によるもので、節の番号と例の値は確かめていない）。

[ADR 0003](0003-pdf-heading-styles.md) の「見出しの行取り」は、行取りの領域の中央に見出しを置く規則を決めた。
行取りの行数を指定する設定は、[docs/roadmap.md](../../roadmap.md) の「見出しの行取りの指定」（行数と、行取りの中の位置）として v1.0.0 の項目に残っている。
既定の空きを行取りで表すなら、利用者がその既定を打ち消す手段として、行数の設定が同時に要る。
既定の空きを入れたのに打ち消す手段がなければ、今の詰めた見出しを望む本を組めなくなるためである。
この ADR は、行取りの指定のうち行数だけを `lines` のキーとして加え、行取りの中の位置はロードマップに残す。

### 欧文の本

欧文の本の行送りは、和文の本より文字の大きさに近い。
`golem new` の英語の雛形は 9.5pt の文字を 12pt で送り（比はおよそ 1.26）、日本語の雛形は 12.5Q を 20H で送る（比は 1.6）。
同じ行数の行取りでも、文字の大きさに対する空きは、欧文の本のほうが小さい。
そこで、既定の行数を言語ごとに分け、欧文の本ではより多くの行を取る。

欧文の組版では、見出しの前の空きを後ろの空きより大きくすることが多い（記憶による）。
行取りの中の位置を中央以外にする設定は、ロードマップの「見出しの行取りの指定」に残るので、欧文の本でも中央に置く。

### メンテナーが決めたこと

- 既定の値の表（下の「既定の値」）を採る。実際に組んで不自然であれば、修正の ADR で直す。
- 二つのマニュアルの見出しは、この ADR の既定に任せ、今の組み方を保つ値（`lines = 1`）を書いて固定しない。マニュアルは Golem の組版の見本であり（[docs/adr/0022](../../adr/0022-manual-as-typesetting-sample.md)）、既定の見出しの見本にもなるためである。
- 「見出しの後ろの改ページ」の不具合は、この ADR で直す。見出しの既定の空きを大きくすると、二つの見出しが続くときに最初の見出しがページの末尾に残る場合が目立つためである。

## 実装すること

### 行取りの行数の設定（golem-project）

`[headings.<階層>]` に `lines` のキーを加える。

```toml
[headings.2]
size = "1.25zw"
lines = 3
```

| キー | 型 | 意味 |
| --- | --- | --- |
| `lines` | 整数 | 見出しが占める行の格子の最小の数（行取り）。1 以上 |

- `HeadingStyle` に `hsLines :: Maybe Int` を加える。
- 1 未満の値と、整数でない値は G03006 とする。
- `lines = 1` と、版面と同じ大きさ（`size = "1zw"`）を書いた見出しは、今と同じに組まれる。

### 既定の値（golem-driver）

`[headings.<階層>]` の `size` と `lines` を書かない場合に、次の既定の値を使う。
キーごとに既定を当てるので、`[headings.1]` に `number` だけを書いた見出しにも、`size` と `lines` の既定が効く。
`font` の既定は、今と同じく本文の役割である。

本の言語（マニフェストの `language`）が `ja` で始まる本は、次の表を使う。

| 階層 | `size` | `lines` |
| --- | --- | --- |
| 1 | `"1.5zw"` | 5 |
| 2 | `"1.25zw"` | 3 |
| 3 | `"1zw"` | 2 |

ほかの言語の本は、次の表を使う。

| 階層 | `size` | `lines` |
| --- | --- | --- |
| 1 | `"1.5zw"` | 6 |
| 2 | `"1.25zw"` | 4 |
| 3 | `"1zw"` | 2 |

- `zw` は、[ADR 0003](0003-pdf-heading-styles.md) のとおり、版面の文字の大きさを一字とする。
- 既定の値は、golem-driver の純粋な関数 `headingDefaults :: Text -> Int -> (Dim, Int)`（言語、階層 → 大きさ、行数）で決める。`style.toml` はマニフェストを読まないので、言語で決まる既定は golem-project ではなく golem-driver に置く。
- 既定の `lines` が 1 ページの行の格子の数を超える版面では、既定の `lines` を格子の数に切り詰める。小さい版面のテストや本で、利用者が書いていない値によって G07024 が出ることを防ぐためである。`lines` を書いた場合は切り詰めず、超えれば G07024 とする。
- `page-break` の既定は今のまま（改ページしない）とする。

### 行取りの計算（golem-layout）

`headingBlock` に、最小の行数を引数として加える。

```haskell
headingBlock
  :: Sp   -- 版面の文字の大きさ fs
  -> Sp   -- 行送り p
  -> Sp   -- 見出しの文字の大きさ s
  -> Int  -- 見出しの行数 m（1 以上）
  -> Int  -- 最小の行取り L（1 以上）
  -> HeadingBlock
```

- [ADR 0003](0003-pdf-heading-styles.md) の手順の 3 で求めた格子の数を N0 として、占める格子の数を N = max N0 L とする。
- 手順の 4 の領域の長さ R と hbOffset は、この N で求める。見出しは、L 行の領域の中央に置かれる。
- L = 1 のとき、結果は今の `headingBlock` と一致する。

見出しの行取りの領域は、ページや段の先頭でも削らない。
行取りの空きを削ると、同じ階層の見出しでも、ページの先頭にあるかどうかで占める格子の数が変わり、改ページの判定が見出しの位置に依存するためである。

### 見出しが続くときの改ページ（golem-layout）

`Golem.Layout.Paginate` の `nextNeed` の `FHeading` の場合を、見出しの格子の数にその次の `nextNeed` を足した値に替える。

```haskell
(FHeading _ _ n _ : rest) -> n + nextNeed rest
```

見出し、見出し、段落と続くと、最初の見出しの `keep` は、二つの見出しの格子の数と段落の最初の 2 行を合わせた数で判定される。
合わせた数が段の格子の数を超える場合は、今の `keep` の規則（空の段では送らない）で、送り続けることはない。

### 雛形と既存の本への影響

- `golem new` の雛形の `style.toml` は変えない。雛形の見出しには `size` と `lines` の既定が効くので、雛形から作った本の PDF は、この ADR の前と変わる。golden の `new-ja-style.toml` と `new-en-style.toml` は変わらない。
- `[headings.<階層>]` の `size` か `lines` を書いていない既存の本の PDF は、見出しの大きさと行取りが変わり、改ページも変わる。今の組み方を保つには、各階層に `size = "1zw"` と `lines = 1` を書く。
- 二つのマニュアルの `style.toml` には `lines` を書かず、`[headings.3]` にも `size` を書かない。マニュアルの見出しは、`[headings.1]` と `[headings.2]` の `size` のほかは既定に任せる。
- 決定性の検査の PDF（`scripts/determinism.sh` の `pdf/`）と、二つのマニュアルの PDF の出力が変わる。CI の `determinism` ジョブは二つのアーキテクチャの出力を比べるだけで、過去の出力のハッシュを持たないので、ジョブの設定は変えない。
- golem-driver のテストのうち、見出しの位置やページ数を期待値に持つもの（`size` を書かない `horizontalStyle` などの版面で見出しを組むテスト）は、期待値を直すか、テストの `style.toml` に `size = "1zw"` と `lines = 1` を書いて今の組み方を保つ。どちらにするかはテストごとに選び、見出しの組み方そのものを確かめるテストでないものは、後者にする。
- HTML、EPUB、プレーンテキストの出力は変わらない。

### ドキュメント

- 仕様書の「style.toml」の節に、`lines` のキーと、言語ごとの既定の値の表を書く。見出しの行取りの段落（「本文より大きい見出しは、行の格子からずらさずに置く」）に、最小の行取りの規則を加える。
- 仕様書の「既知の不具合」から「見出しの後ろの改ページ」を消す。
- [docs/roadmap.md](../../roadmap.md) の「既定の見出し」の項目を消す。「見出しの行取りの指定」の項目を、行取りの中の位置だけを残す文に直す。
- 使い手のマニュアルの `manual/chapters/05-style.gm` の見出しの節と `manual/appendices/c-style.gm` の `[headings.<階層>]` の節に、`lines` と既定の値を書く。`manual/appendices/i-known-issues.gm` から見出しの後ろの改ページの項目を消す。`manual/appendices/h-roadmap.gm` を、ロードマップに合わせて直す。
- 開発者のマニュアルで `headingBlock` の引数に触れている箇所があれば直す。
- [ADR 0003](0003-pdf-heading-styles.md) のステータスの行に、見出しの既定の大きさと最小の行取りをこの ADR で加えたことを、この ADR へのリンクで書き足す。
- [golem-layout ADR 0003](../../golem-layout/adr/0003-pagination-and-s2.md) のステータスの行に、見出しが続くときの改ページの規則をこの ADR で改めたことを書き足す。

## データ構造

- golem-project：`HeadingStyle` に `hsLines :: Maybe Int` を加える。
- golem-layout：`headingBlock` に最小の行取りの引数を加える。`nextNeed` の `FHeading` の値を替える。
- golem-driver：`headingDefaults` を新設する。見出しの役割と大きさを決める `headingFace` は、`size` がない場合に版面の文字の大きさの代わりに既定の値を使う。

## 実装しないこと

- 行取りの中の位置の指定（中央のほかに、前寄せや後ろ寄せ）。[docs/roadmap.md](../../roadmap.md) の「見出しの行取りの指定」に残す。
- 見出しの既定の書体を本文と変えること（合成の太字を含む）。合成の太字（[ADR 0012](0012-synthetic-bold-weight.md)）を見出しの既定にすると、太字の書体を持つ本と持たない本で既定の見え方が変わるので、書体は本文の役割のままにする。
- 既定の `page-break`（章の見出しを奇数ページから始めること）。改丁の既定は白ページを増やし、出力の変化が大きい。
- 4 階層め以降の見出しの既定。意味論の IR の見出しは 3 階層までである。
- HTML と EPUB の見出しの大きさと前後の空き。
- ページや段の先頭で、見出しの前の空きを削ること（「トレードオフ」）。
- 同行見出し（見出しに続けて同じ行から本文を組む形）。

## テスト設計

実装の前に書き、失敗することを確かめる。

### style.toml（`modules/golem-project/test/Main.hs`）

- `[headings.2] lines = 3` が `hsLines = Just 3` になる。`[headings.2]` に `lines` がなければ `Nothing` になる。
- `lines = 0`、`lines = -1`、`lines = 1.5`、`lines = "3"` が G03006 になる。

### 既定の値（`modules/golem-driver/test/Main.hs`）

- `headingDefaults "ja" 1` が `(Zw (3 % 2), 5)`、`headingDefaults "ja-JP" 3` が `(Zw 1, 2)`、`headingDefaults "en" 1` が `(Zw (3 % 2), 6)`、`headingDefaults "fr" 2` が `(Zw (5 % 4), 4)` になる。

### 行取り（`modules/golem-layout/test/Main.hs`）

- `headingBlock` の L = 1 の結果が、どの s と m でも、今の `headingBlock` の結果と一致する（今の実装を写したテストの中の関数と比べるプロパティテスト）。
- fs = 13Q、p = 22H、s = 13Q、m = 1、L = 3 で、hbSpan が 3、hbOffset が p（中央の行）になる。
- fs = 13Q、p = 22H、s = 40Q、m = 2、L = 2 で、hbSpan が L ではなく大きさから決まる値になる。
- `paginate`：`FHeading`（2 格子）、`FHeading`（2 格子）、5 行の `FParagraph` の順の流れを、最初の見出しの前に 4 格子の空きしか残らない段に置くと、最初の見出しが次の段の先頭に送られる。今の実装では、最初の見出しが元の段の末尾に残ることを、この期待値で確かめる。
- `paginate`：見出しと続く見出しの格子の数の和が段の格子の数を超える流れで、空の段に置いた見出しが送られず、処理が終わる。

### PDF（`modules/golem-driver/test/Main.hs` または `PdfSpec.hs`）

- `[headings.1]` に `number` だけを書いた日本語の本で、1 の階層の見出しのグリフの大きさが版面の文字の 1.5 倍であり、見出しの後の段落の最初の行が、見出しの最初の格子の 5 つ後の格子にある。
- 同じ本の言語を `en` にすると、見出しの後の段落の最初の行が 6 つ後の格子にある。
- `[headings.1]` に `size = "1zw"` と `lines = 1` を書いた本の PDF が、この ADR の前の実装で `size` と `lines` を書かずに組んだ PDF とバイト列で一致する。テストでは、前の実装の出力の代わりに、見出しの各行が本文と同じ格子の位置にあることを確かめる。
- 1 ページの格子が 3 行の版面で、`lines` を書かない 1 の階層の見出しが G07024 にならず、`lines = 4` を書いた見出しが G07024 になる。
- 二回のビルドと、並列と逐次の行分割で、PDF のバイト列が一致する。

### 自動テストにしない確かめ方

- `golem new` の日本語と英語の雛形をそのまま組み、見出しが本文より大きく、前後に空きがあり、見出しの後の本文が行の格子にそろうことを目で確かめる。
- 二つのマニュアルを組み、エラー、警告、お知らせが出ないことと、3 の階層の見出しの前後に空きができたことを目で確かめる。

## トレードオフ

既定の値を変えるので、`size` と `lines` を書いていない既存の本の PDF が変わる。
v1 の前のプレリリースの段階であり、見出しが本文と見分けられない今の既定を v1 で固定するより、ここで変えるほうがよいと判断した。
今の組み方を保つ値（`size = "1zw"`、`lines = 1`）は、この ADR で書けるようになる。

既定の値を言語で分けたので、同じ `style.toml` でも、マニフェストの言語を変えると見出しの行取りが変わる。
言語でなく行送りと文字の大きさの比から行数を計算する方法もあるが、計算の規則が利用者から見えにくくなるので、表の値を採った。

行取りの空きをページや段の先頭でも削らないので、ページの先頭の見出しの上に、空きが残る。
和文の書籍では行取りを保つのが普通であり、欧文の書籍では見出しの前の空きをページの先頭で削ることが多い（記憶による）。
欧文の本だけ削ると、ページの先頭かどうかで見出しの占める格子の数が変わり、改ページの判定が見出しの位置に依存するので、v1 では削らない。

`lines` のキーを加えたので、ロードマップの「見出しの行取りの指定」の一部を、v1.0.0 より前に実装することになる。
既定の空きを入れる以上、打ち消す手段を同時に用意する必要があるためである。
