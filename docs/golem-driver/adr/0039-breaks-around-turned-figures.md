# ADR 0039: 回した図版を待つあいだの改段と、回した図版のページの後の改ページ

ステータス: 採択（未実装）

## 文脈

[ADR 0034](0034-fit-figures-to-column.md) の「ページへの置き方」は、回した図版（`rotate=true`）について次のように定めた。

- 回した図版は、本文を持たないページを一つ占める。
- 回した図版に出会ったとき、今のページに何も置いていなければ、そのページに置く。そうでなければ待ちに加え、本文を続ける。
- 改ページ、改段、段組みの切り替え、`page-break = "recto"` の見出しの前では、待っている回した図版をすべて置いてから進む。

この記述は、強制の改ページと改段の規則（[docs/adr/0017](../../adr/0017-forced-page-breaks.md)、[docs/adr/0018](../../adr/0018-multi-column-layout.md)）と組み合わせたときの二つの場合を決めていない。

一つめは、段組みの版面で、回した図版が待っているあいだの改段（`@column-break`）である。
[docs/adr/0018](../../adr/0018-multi-column-layout.md) は、改段を次の段へ進むことと定める。
回した図版はページを一つ占めるので、「置いてから進む」には今のページを閉じるしかない。
次の段へ進むだけにすると、回した図版は待ったままで、改段の後の本文が回した図版より前に組まれる。

二つめは、回した図版のページの直後の改ページ（`@page-break`）である。
[docs/adr/0017](../../adr/0017-forced-page-breaks.md) は、改ページは今のページに何も置いていなくても閉じ、中身のないページを白ページにすると定める。
回した図版を置くと、次のページは空のまま始まる。
そこで `@page-break` に出会うと、[docs/adr/0017](../../adr/0017-forced-page-breaks.md) の規則のままでは、回した図版のページと次の本文のあいだに白ページが一ページ入る。
書き手が回した図版の後に `@page-break` を書くのは、後の本文を新しいページから始めるためであり、回した図版のページがすでにその新しいページの役を果たしている。

[ADR 0034](0034-fit-figures-to-column.md) の実装（プルリクエスト #259、コミット ab296714）は、この二つを次のように扱った。

- 段組みの版面で回した図版が待っているときの改段は、改ページとして扱う（`Golem.Layout.Paginate` の `applyBreak` の `BreakColumn`）。
- 今のページが空で、最初の段にあり、一つ前のページが回した図版のページなら、改ページは何もしない（同じく `breakPage` と `afterPageFigure`）。

メンテナーはこの振る舞いでよいとし、仕様書の図版の節（1816 行と 1817 行）と、使い手のマニュアル（`manual/chapters/03-markup.gm` の回した図版の段落）に書いた。
しかし、どの ADR にもない。
レビュー（`.claude/reviews/2026-10-20-adr-spec-review.md` の A-6）が、この食い違いを挙げた。
この ADR は、実装の振る舞いを決定として記録する。

## 実装すること

### 回した図版が待っているあいだの改段

段組みの版面で、待ちに回した図版が一つでもあるとき、改段（`@column-break`）は改ページ（`@page-break`）として扱う。

- 今のページを閉じ、待っている図版を [ADR 0034](0034-fit-figures-to-column.md) の規則で置く。回した図版はそれぞれ一ページを占める。
- 改段の後の本文は、回した図版のページの次のページから続く。
- 今のページの残りの段は空のまま残る。
- 待ちに回した図版がなければ、改段は [docs/adr/0018](../../adr/0018-multi-column-layout.md) のとおり次の段へ進む。回さない図版だけが待っている場合も同じである。
- 一段組みの版面では、改段はもともと改ページと同じなので変わらない。

### 回した図版のページの直後の改ページ

改ページは、次の三つがすべて成り立つとき、何もしない。

- 今のページに何も置いていない（すべての段が空で、脚注もない）。
- 今の段が最初の段である。
- 一つ前のページが、回した図版のページである。

このとき、本文は今のページ（回した図版のページの次のページ）から続き、白ページを足さない。
三つのどれかが成り立たなければ、改ページは [docs/adr/0017](../../adr/0017-forced-page-breaks.md) のとおりとし、空のページも閉じて白ページにする。

この規則は、回した図版がどの経路で置かれたかによらない。
空のページで出会って置いた場合も、待っていた回した図版を改ページや改段で置いた場合も、同じく扱う。
そのため、回した図版を置いた直後の改ページが二つ以上続いても、すべて何もせず、白ページは足さない。

改ページが続く場合もすべて吸収することは、メンテナーが決めた。
理由は次のとおりである。

- 回した図版のページの直後に改ページを重ねる書き手が求めているのは、後の本文を新しいページから始めることであり、そこに白ページが要る場面はまれである。すべて吸収するほうが、書き手から見て自然な結果になる。
- 白ページが要るときは、書き手が手で作れる。回した図版のページの次のページが奇数なら `@page-break verso`、偶数なら `@page-break recto` を書くと、そのページを白ページとして閉じ、次のページから続く。`page-break = "recto"` の見出しと改ページの手での制御（[docs/adr/0030](../../adr/0030-manual-page-break-control.md)）も、今のとおり使える。
- 判定は一つ前のページの中身だけから決まり、回した図版のページを改ページがすでに使ったかを覚える状態を持たない。同じ原稿の並びからいつも同じページの列が決まる。

### 文書

- 仕様書の図版の節の二つの項目（「回した図版が待っているあいだの改段」と「本文を持たないページに回した図版を置いた直後の改ページ」）に、この ADR へのリンクを付ける。二つめの項目に、改ページが続いても白ページを足さないことを書き足す。
- 仕様書の改ページの節の、空のページを閉じて白ページにする規則に、回した図版のページの直後を除くことと、この ADR へのリンクを書き足す。
- docs/markup.md の改ページと改段の節に、回した図版との関係を一文ずつ足し、この ADR へリンクする。
- 使い手のマニュアル（`manual/chapters/03-markup.gm` の回した図版の段落）に、改ページが続いても白ページを足さないことと、白ページが要るときは `@page-break verso` か `@page-break recto` を書くことを書き足す。

### ステータスの行

- [ADR 0034](0034-fit-figures-to-column.md)：「採択→（縦組みの枠の行の送りの向き）は [golem-driver ADR 0038](0038-turned-figure-line-progression.md)、（待っている回した図版と改段、回した図版のページの後の改ページ）は golem-driver ADR 0039」とする。
- [docs/adr/0017](../../adr/0017-forced-page-breaks.md)：今のステータスの行に、「（回した図版のページの直後の改ページで白ページを足さないこと）は golem-driver ADR 0039」を足す。空のページを閉じて白ページにする規則の例外になるためである。
- [docs/adr/0018](../../adr/0018-multi-column-layout.md)：今のステータスの行に、「（回した図版が待っているあいだの改段）は golem-driver ADR 0039」を足す。改段を次の段へ進むとした規則の例外になるためである。

## 実装しないこと

- `@page-break recto` と `@page-break verso`、`page-break = "recto"` の見出しの扱いは変えない。回した図版のページの次のページが偶奇の条件に合わなければ、今のとおり白ページを一ページ足す。改丁は、ページの偶奇を合わせることが目的であり、回した図版のページはその役を果たさないためである。
- 段組みの切り替え（索引の段）の前の扱いは、[ADR 0034](0034-fit-figures-to-column.md) のとおりで変えない。
- 回さない図版だけが待っているときの改段は変えない。
- HTML、EPUB、プレーンテキストは、`rotate` を読まないので変わらない。
- コードは変えない。

## テスト設計

golem-layout の `test/PaginateSpec.hs` の、回した図版のテストの群（`pageFigureTests`）に加える。
実装はすでにこの振る舞いなので、テストを先に書いて、今の実装で通ることを確かめる。
決定を記録する ADR なので、テストが失敗する段階はない。

一つめの規則は、既存のテスト「a waiting turned figure is placed before a column break」（二段組みで、本文、回した図版、改段、本文が、1 ページ目の最初の段、回した図版のページ、3 ページ目になる）が固定している。
次を加える。

- 二段組みで、回さない図版だけが待っているときの改段は、同じページの次の段へ進む（回した図版がないときは [docs/adr/0018](../../adr/0018-multi-column-layout.md) のとおりであること）。
- 空のページで回した図版に出会い、その直後に `FBreak BreakPage` と段落が続くと、ページは回した図版のページと本文のページの二つで、`poBlank` が真のページがない。
- 本文、回した図版、`FBreak BreakPage`、段落の並び（既存の「a waiting turned figure is placed before a forced page break」）に加えて、改ページを二つ続けた並びと三つ続けた並びでも白ページがない。
- 空のページ（1 ページ目）で回した図版に出会い、その直後に `FBreak BreakRecto` が来ると、2 ページ目が白ページになり、本文は 3 ページ目から続く。回した図版のページが 2 ページ目で、直後に `FBreak BreakVerso` が来ると、3 ページ目が白ページになる。手で白ページを作る方法が働くことを固定する。
- 回した図版のない、空の最初のページでの `FBreak BreakPage` は、今のとおり白ページを作る（例外が回した図版の後に限られること）。

## トレードオフ

- 改段を改ページとして扱うと、今のページの残りの段が空のまま残る。代わりに次の段へ進み、回した図版を後のページに送る案は、書き手が改段で区切った本文が回した図版より前に組まれ、[ADR 0034](0034-fit-figures-to-column.md) の「置いてから進む」と食い違う。空の段は書き手の改段の意図からの帰結なので、こちらを採る。
- 回した図版のページの直後の改ページを何もしないとすると、同じ原稿の `@page-break` が、前に回した図版があるかどうかで白ページを作ったり作らなかったりする。回した図版のページは書き手が位置を決めないフロートのページなので、書き手が意図した「新しいページから始める」に合わせるほうを優先した。
- 回した図版がない場合、`@page-break` を二つ続けると白ページが一ページできる（[docs/adr/0017](../../adr/0017-forced-page-breaks.md)）。回した図版のページの直後では二つ続けても白ページができないので、改ページの数と白ページの数の対応は、回した図版の後でだけ崩れる。最初の一つだけを吸収する案は、改ページがすでに回した図版のページを使ったかを覚える状態が要り、白ページが要る場面もまれなので採らない。白ページが要る書き手は `@page-break verso` か `recto` で作れる。
