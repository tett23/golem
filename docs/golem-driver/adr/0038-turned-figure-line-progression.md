# ADR 0038: 縦組みで回した図版の枠の行の送りを、ページの下から上とする

ステータス: 採択

## 文脈

[ADR 0034](0034-fit-figures-to-column.md) は、`rotate=true` の図版を、回す前の向きの枠の中に組んでから 90 度回して置くと定めた。
縦組みについて、「回した図版の枠」の節は次のように書く。

> 右に回すので、枠の行は、ページの右から左へ走り、枠の行の送りはページの上から下へ進む。

同じ ADR の「PDF への描き方」の節は、縦組みで使う `TurnedRight` の行列を `[0 −1 1 0 x y+H]` と定める。
枠の中の点 `(u, v)`（枠の左下が原点）は、ページの点 `(x + v, y + H − u)` に移る。

縦組みの枠の中では、行は枠の上から下（`v` の減る向き）へ走り、行の送りは枠の右から左（`u` の減る向き）へ進む。
この行列で移すと、次のようになる。

- 枠の行の向き（`v` の減る向き）は、ページの `x` の減る向き、つまり右から左になる。本文の記述と一致する。
- 枠の行の送りの向き（`u` の減る向き）は、ページの `y` の増える向き、つまり下から上になる。本文の記述（上から下）と食い違う。

[ADR 0034](0034-fit-figures-to-column.md) の実装（プルリクエスト #259）は、行列のほうに従った。
画像とキャプションを枠の格子の先頭から置くので、縦組みで回した図版では、画像がページの下の側に、キャプションがその上の側に来る。

行列のほうが正しい。
図版の上の辺がページの右に向くように回すと、読み手は本を左に 90 度回して、図版を正しい向きで見る。
本を左に回すと、ページの下の辺は読み手から見て右に来る。
縦組みの行の送りは、読み手から見て右から左へ進むので、ページの上では下から上へ進む。
本文の「上から下」は、行の送りの向きを回す前の枠の向きのまま書き写した誤りである。

メンテナーは、実装のほうが正しいとして、この ADR で記述を改めると決めた。

## 実装すること

- [ADR 0034](0034-fit-figures-to-column.md) の「回した図版の枠」の縦組みの記述のうち、枠の行の送りの向きを次のように改める。「右に回すので、枠の行は、ページの右から左へ走り、枠の行の送りはページの下から上へ進む」。
- 行列、枠の大きさ、寄せ、ページへの置き方は、[ADR 0034](0034-fit-figures-to-column.md) のとおりで変えない。
- 実装（`Golem.Driver.Pdf` と golem-pdf の `Turned`）は、すでにこの向きで描いているので変えない。
- 縦組みで回した図版の行の送りの向きを確かめるテストを加える（「テスト設計」）。
- 仕様書の図版の節の、回した図版の枠の説明に、縦組みでは枠の行がページの右から左へ走り、行の送りがページの下から上へ進むこと、横組みでは枠の行がページの下から上へ走ることを書く。
- [ADR 0034](0034-fit-figures-to-column.md) のステータスの行を「採択→（縦組みの枠の行の送りの向き）は golem-driver ADR 0038」とする。

## 実装しないこと

- 回す向きは変えない。縦組みは右に回し、図版の上の辺をページの右に向ける（JLReq §2.3.2 の 3）。
- 横組みの枠の向きは変えない。[ADR 0034](0034-fit-figures-to-column.md) の記述（枠の行はページの下から上へ走る）と行列が一致しているためである。

## テスト設計

golem-driver の `test/FigureSpec.hs` の回した図版のテストに、次を加える。
テストを先に書いて、今の実装で通ることを確かめる。
記述の誤りを正す ADR なので、テストが失敗する段階はない。

- 縦組み（`vertical10 60`）で、キャプションを持つ回した図版を組み、PDF の座標で、キャプションの行がすべて画像の矩形より上（`y` が大きい側）にあること。
- 同じ図版で、キャプションが二行以上のとき、二行めが一行めより上にあること。
- 横組み（`horizontal20 "left" 20`）で、同じく回した図版を組み、キャプションの行が画像の矩形より右にあること（枠の行の送りは、左に回すとページの左から右へ進む）。

## トレードオフ

- 採択済みの ADR の記述と実装が食い違ったまま残ると、後でその節を読んで実装を「直す」人が出る。行列だけを正とする注記を仕様書に書くこともできたが、ADR の記述そのものを改める手段は新しい ADR だけなので、この ADR を起こした。
