# ADR 0024: 罫線の指定と脚注の区切り線

ステータス: 採択→罫線の色と線の種類は [ADR 0028](0028-rule-colour-and-style.md)

## 文脈

PDF のページ下の脚注は、本文と脚注のあいだを格子の一行だけ空けて組んでいる（[golem-layout ADR 0003](../../golem-layout/adr/0003-pagination-and-s2.md)）。
`Golem.Layout.Paginate` は、ページ（段組みでは段）に脚注を置くとき、脚注の行の数に区切りの一行を足した数を、版面の下から差し引く。
`Golem.Driver.Pdf` の `drawColumn` は、脚注の行を版面の最後の格子の行から置き、区切りの一行には何も描かない。

本文と脚注の境が空白の一行だけだと、脚注の一行目が本文の続きに見えることがある。
とくに、脚注の本文と本文が同じ書体と同じ大きさで組まれる今の PDF では（[仕様書](../../specifications.md)の「脚注の印」の項のとおり、脚注の本文には番号も付かない）、どこから脚注かを見分ける手がかりが位置しかない。
書籍の組版では、本文と脚注のあいだに短い罫線（区切り線）を引くことが多く、InDesign の脚注のオプションにも区切り線の設定がある。
所有者は、二つのマニュアル（`manual/`、`manual-dev/`）の脚注の前に罫線を入れることを求めている（[docs/adr/0024](../../adr/0024-manual-audiences-and-policy.md)）。

今の `style.toml` の `[notes]` には `placement`（`"page-foot"` か `"chapter-end"`）しかなく、区切り線を設定する手段はない。
コードで確かめると、`Golem.Project.Style` の `Notes` は `placement` だけを読み、`Golem.Driver.Pdf` に脚注のための罫線を描く処理はない。

## 実装すること

### 罫線の指定（共通の値の形）

罫線を引く場所は、脚注の前のほかにも考えられる。
段落スタイルの上下の罫線（InDesign の段落境界線にあたるもの）は v1 の課題であり（[仕様書](../../specifications.md)の「段落スタイルの罫線」の項）、表の罫線の設定は v2 の課題である。
場所ごとに別々の書き方を作ると、同じ長さ、太さ、間隔を、表ごとに違うキーと違う検査で書くことになる。
そこで、`style.toml` の罫線を表す値の形を一つ定め、`[notes.rule]` をその最初の使い手にする。

罫線の指定は、次のキーを持つ TOML の表である。

| キー | 型 | 意味 |
| --- | --- | --- |
| `length` | 寸法 | 罫線の長さ |
| `weight` | 寸法 | 罫線の太さ。既定は `"0.3pt"` |
| `space-before` | 寸法 | 罫線の前（横組みでは上、縦組みでは右）の間隔 |
| `space-after` | 寸法 | 罫線の後（横組みでは下、縦組みでは左）の間隔 |

- 値の検査は、どの使い手でも同じにする。
  - `length` が寸法として読めない値の場合と、0 以下の場合は G0306 とする。
  - `weight` が寸法として読めない値の場合、0 以下の場合、`zw` の場合は G0306 とする。太さを字の大きさに比例させる理由がないためである。
  - `space-before` と `space-after` が寸法として読めない値の場合と、負の場合は G0306 とする。0 は書ける。
  - `zw` は、使い手が決める字の大きさで解決する。
  - 未知のキーは、ほかの表と同じく G0306 とする。位置は罫線の指定の表か、その値とする。
- 使い手ごとに決めるのは、次の三つである。
  - `length` が必須か、書かないときにどの長さにするか。
  - 間隔を何から何までの距離として測るか、行の格子とどう合わせるか。
  - `zw` をどの字の大きさで解決するか。
- 罫線の色と線の種類（破線など）は、この ADR では形に入れない。v1 の課題（[仕様書](../../specifications.md)の「罫線の色と線の種類」の項）として、キーを足す ADR で、すべての使い手に同時に加える。

golem-project に、罫線の指定を表す型 `RuleSpec` と、TOML の表から `RuleSpec` を読む関数を一つ置く。
`RuleSpec` は、長さ（`Maybe`、`zw` を含む寸法）、太さ（`Sp`）、二つの間隔（どちらも `Maybe`、`zw` を含む寸法）を持つ。
使い手は、この関数で読んだ値に、使い手ごとの条件（`length` が必須かなど）を検査として足す。
この ADR で実装する使い手は `[notes.rule]` だけである。

### style.toml の設定

`[notes]` の下に、罫線の指定の表 `[notes.rule]` を加える。
表があるときだけ、PDF のページ下の脚注の前に区切り線を引く。
表がなければ、今と同じく何も引かない。

```toml
[notes]
placement = "page-foot"

[notes.rule]
length = "10zw"
weight = "0.3pt"
space-before = "1zw"
space-after = "0.5zw"
```

脚注の区切り線での、各キーの扱いは次のとおりである。

| キー | 既定 | 脚注の区切り線での意味 |
| --- | --- | --- |
| `length` | なし（必須） | 区切り線の長さ。`zw` は版面の文字の大きさ（`[page.grid]` の `font-size`）で解決する |
| `weight` | `"0.3pt"` | 区切り線の太さ |
| `space-before` | なし | 本文の最後の行の字面の下端から、区切り線の上端までの間隔の最小値 |
| `space-after` | なし | 区切り線の下端から、脚注の一行目の字面の上端までの間隔 |

- 値の検査は、前の節の罫線の指定の検査のとおりである。
- 脚注の区切り線では `length` を必須とし、ない場合は G0306 とする。位置は `[notes.rule]` の表とする。
- `space-before` と `space-after` は、どちらか一方だけを書いてもよい。書かなかった側は 0 として扱う。どちらも書かなければ、次の節の「間隔を書かない場合」のとおりに引く。
- `placement = "chapter-end"` のときに `[notes.rule]` を書いても誤りにしない。章末注には区切り線を引かないので、効果はない。

### 区切り線の位置

本文と脚注のあいだには、格子の行を単位とする区切りの領域を置く。
今は、この領域が格子の一行で、何も描かずに空けている。
行の格子は変えないので、区切りの領域の高さ（縦組みでは幅）は、いつも格子の行の整数倍になる。

**間隔を書かない場合**：区切りの領域は今と同じ一行で、区切り線をその行の字面の上下（縦組みでは左右）の中央に引く。
本文の行、改ページ、脚注の置き方はどれも変わらない。

**間隔を書いた場合**：区切りの領域の行の数 n を、次の式で決める。
`b` は `space-before`、`w` は `weight`、`a` は `space-after`、`p` は格子の行送り、`h` は格子の字面の高さ（`[page.grid]` の `font-size`）である。

```
n = max(1, ceil((b + w + a - (p - h)) / p))
```

本文の最後の行の字面の下端から、脚注の一行目の字面の上端までの距離は、`n * p + (p - h)` になる。
この距離が `b + w + a` 以上になる最小の n を選ぶ。

区切り線は、脚注の一行目の字面の上端から `a` だけ離して引く。
n を整数に切り上げたことで余った距離は、すべて区切り線の上の間隔に入る。
したがって、`space-after` は書いた値のとおりになり、`space-before` は書いた値以上になる。
脚注に近い側の間隔を正確に保つのは、区切り線が脚注に属する印として見えるようにするためである。

n が 2 以上になると、脚注を持つページの本文の行は、今より n - 1 行少なくなる。
ページあたりの本文の行の数が変わるので、改ページと脚注の置き方も変わりうる。
行の格子そのものは変わらないので、本文の行は今と同じ格子の位置に置かれる。

- 横組みでは、上の位置に、版面か段の左端から `length` の長さで、水平に引く。
- 縦組みでは、上の位置（「上」を「右」に読み替える）に、版面か段の上端から `length` の長さで、垂直に引く。
- 段組みの版面では、脚注を置いた段ごとに、その段の区切りの行に引く。
- 前のページから続く脚注だけを置いたページにも引く。脚注の行があるページ（段）には、必ず区切りの行があるためである。
- 色は、表の罫線（[ADR 0008](0008-pdf-tables.md)）と同じ描き方とする。

`length` が、区切り線を引く行の行長（段組みでは段の行長）より長い場合は、版面を計算できないエラー（G0701）とする。
黙って行長に切り詰めると、指定した長さと PDF の長さが食い違うためである。
検査は `golem-layout-spec` の `pageGeometry` で、ほかの版面の検査の後に行い、ビルドと `golem check` の両方で報告する。

### データ構造の変更

- golem-project に `RuleSpec` と、それを読む関数を置く（「罫線の指定」の節）。
- `Golem.Project.Style` の `Notes` を、`placement` に加えて `Maybe RuleSpec` を持つ形にする。`length` があることは読み込みで検査しているので、使う側では `length` を必ずあるものとして扱う。`Style` の注の欄も同じく広げる。
- 区切りの領域の行の数 n を、`golem-layout-spec` の `pageGeometry` で上の式から求め、版面の値として持つ。間隔を書かないときと、`[notes.rule]` がないときは 1 とする。
- `Golem.Layout.Paginate` が、脚注を置くときに足す区切りの行の数を、今の固定の 1 から版面の n に改める（`sep` の値）。
- `Golem.Driver.Pdf` の `drawColumn` で、脚注の行があるとき、区切りの領域に `P.Rule` を一つ加える。位置は上の節のとおりに求める。`zw` は、`[page.grid]` の `font-size` で解決する。

### HTML と EPUB

HTML は脚注を章末にまとめ、EPUB は脚注をポップアップで見せる（[仕様書](../../specifications.md)の「脚注」）。
どちらもページ下の脚注を持たないので、区切り線を出力しない。
プレーンテキストも同じである。

### ドキュメント

- docs/specifications.md の「style.toml」の例と表に `[notes.rule]` を加え、「脚注」の節に PDF の区切り線を書く。
- docs/diagnostics.md の G0306 の主な原因と、G0701 の検査の順に、この ADR の条件を加える。
- 使い手のマニュアルの「スタイルの設定」と付録 C に `[notes.rule]` を書く。
- 二つのマニュアルの `style.toml` に `[notes.rule]` を書き、脚注の前に区切り線を引く。

## 実装しないこと

- 区切り線の色、線の種類（破線など）、行頭からの位置のずらし。
- 区切り線を引かずに、本文と脚注の間隔だけを変えること。間隔は `[notes.rule]` の中でだけ書ける。
- 脚注のほかの罫線の使い手。段落スタイルの罫線は v1 の課題として別の ADR で、表の罫線の設定は v2 の課題として、この ADR の罫線の指定の形を使って足す。
- 前のページから続く脚注だけのページで、区切り線の長さや形を変えること（InDesign の「段の最初の脚注」と「続きの脚注」の区別にあたるもの）。
- 章末注の前の区切り線と見出し。
- 脚注の本文の番号と書体と大きさ。仕様書の「脚注の印」の項のまま残す。
- HTML と EPUB の区切り線（CSS の `border` など）。

## テスト設計

### 先に書いて失敗させるテスト

golem-project（`Golem.Project.Style` のテスト）：

- `[notes.rule]` に `length = "10zw"` だけを書いた `style.toml` を読むと、長さが 10zw、太さが 0.3pt の `RuleSpec` になること。
- `length = "30mm"`、`weight = "0.5pt"` を読むと、その値になること。
- 罫線の指定を読む関数を、脚注と無関係な表で直接テストする。`length` を書かない表が `length` のない `RuleSpec` になり、誤りにならないこと（必須かどうかは使い手が決めるため）。`weight = "1zw"`、`space-before = "-1pt"`、未知のキーが、それぞれ G0306 になること。
- `[notes.rule]` に `length` がない場合、`length = "abc"` の場合、`length = "0mm"` の場合、`weight = "1zw"` の場合、未知のキー `color` がある場合に、それぞれ G0306 になること。
- `[notes.rule]` がない `style.toml` を読むと、`RuleSpec` がないこと。
- `space-before = "1zw"`、`space-after = "0.5zw"` を読むと、その値になること。`space-after` だけを書くと、`space-before` が 0 になること。
- `space-before = "-1pt"`、`space-after = "abc"` が、それぞれ G0306 になること。

golem-layout-spec（`pageGeometry` のテスト）：

- 一行 40 字の横組みの版面で `length = "41zw"` を書くと G0701 になり、`length = "40zw"` なら版面を計算できること。
- 二段組みで一段の行長が 20 字の版面で、`length = "21zw"` を書くと G0701 になること。
- 区切りの領域の行の数：字の大きさ 10pt、行送り 17pt（`p - h` = 7pt）の版面で、間隔を書かなければ 1、`space-before = "0pt"`、`weight = "0.3pt"`、`space-after = "5pt"` なら 1（5.3pt ≤ 7pt + 17pt）、`space-before = "15pt"`、`space-after = "10pt"` なら 2（25.3pt − 7pt = 18.3pt を 17pt で割って切り上げ）になること。

golem-layout（`Golem.Layout.Paginate` のテスト）：

- 区切りの領域が 2 行の版面で、脚注を一行持つページの本文の行が、区切りの領域が 1 行の場合より一行少なくなること。
- 脚注のないページの本文の行の数は、区切りの領域の行の数によらないこと。

golem-driver（PDF のテスト）：

- 横組みで、脚注を一つ持つページの PDF に、区切りの格子の行の字面の中央を通り、版面の左端から `length` の長さの水平の矩形（太さ `weight`）が描かれること。
- 同じ原稿で脚注のないページには、その矩形が描かれないこと。
- 縦組みで、区切り線が版面の上端から `length` の長さの垂直の矩形になること。
- 二段組みで、脚注を置いた段だけに区切り線が描かれ、その左端が段の左端と一致すること。
- 前のページから脚注が続くページにも区切り線が描かれること。
- 間隔を書いた場合、区切り線の下端と脚注の一行目の字面の上端の距離が `space-after` と一致し、区切り線の上端と本文の最後の行の字面の下端の距離が `space-before` 以上であること。
- `[notes.rule]` のない `style.toml` では、今と同じ PDF のバイト列になること（決定性の検査の出力が変わらないこと）。

### 自動テストにできないものの確かめ方

- 二つのマニュアルを `scripts/manual/build.sh` で組み、脚注のあるページを画像にして、区切り線が本文と脚注のあいだに見えることを目で確かめる。

## トレードオフ

区切り線の既定を「なし」にしたので、区切り線が要る本は `[notes.rule]` を書かなければならない。
既定で引くと、脚注を持つ既存の本の PDF がすべて変わり、しかもどの長さと太さを既定にするかの根拠を Golem が持たない。
長さと太さは本ごとに決める値なので、書いた本だけに引く形を選んだ。

区切り線の前後の間隔を寸法で書けるようにしたが、区切りの領域は格子の行の整数倍に切り上げる。
間隔を寸法のとおりにすると、脚注の行が格子から外れ、見開きの左右で脚注の行の位置がそろわなくなる。
切り上げの余りを区切り線の上の間隔に回すので、`space-before` は最小値の意味になる。
InDesign の脚注のオプションにある、最初の脚注の前の間隔の最小値と、最初のベースラインの位置の設定に近い考え方である（InDesign の画面と振る舞いでは確かめていない）。

間隔を書かないときは、今と同じ一行の領域の中央に引く。
間隔を書かずに区切り線だけを足しても、本文の行と改ページは変わらない。

`length` を行長との比（「行長の 3 分の 1」のような値）ではなく寸法にした。
ほかの `style.toml` の長さと同じ書き方にそろえるためである。
行長を変えたときは、区切り線の長さも書き直す必要がある。

罫線の指定を共通の値の形にしたが、使い手は今は脚注だけである。
使い手が一つのうちに形を決めると、後の使い手の要求に合わない可能性がある。
それでも、長さ、太さ、前後の間隔は、段落の罫線にも表の罫線にもある性質であり、場所によって変わるのは間隔の測り方と長さの既定だけなので、その二つを使い手に任せる形にした。
後の使い手で足りないキーが見つかったら、キーを足す ADR で形を広げる。
