# ADR 0040: `keep-in-column = false` の罫線を版面の外に出すのは、版面の端に接する段の端だけとする

ステータス: 採択

## 文脈

[ADR 0027](0027-paragraph-style-rules.md) は、段落と見出しの罫線のうち `keep-in-column = false` のものを、段の端で、罫線の領域の行を取らずに版面の外に引くと決めた。
行に直交する方向について、次のように書く。

> 段の始まりの前の罫線は版面の上（横組み）か右（縦組み）の余白に、段の終わりの後の罫線は版面の下（横組み）か左（縦組み）の余白に入る。
> 段組みで、段の端が版面の端でない場合（縦組みの二段めの始まりなど）は、段間に入る。

出せる範囲の検査（G0701）にも、「段のあいだに入る場合は、段間の半分以下であること」とある。

仕様書（1477 行）と実装は、二文めを採っていない。

- 仕様書は「版面の上端（縦組みでは右端）に接する段の始まりと、段の終わりで、領域の行を取らずに版面の外の余白に引く」と書く。
- `Golem.Layout.Paginate` の `planOf`（683 行）は、段の始まりの前の罫線を、段が版面の上端（縦組みでは右端）から始まるとき（`top st == 0`）だけ版面の外に出し、ほかは段の中に収める。
- `Golem.LayoutSpec` の `ruleChecks` は、行に直交する方向の `i + w` を余白とだけ比べ、段間とは比べない。

[ADR 0035](0035-paragraph-rules-split-and-space-units.md) の「メンテナーが決めたこと」は、ページの途中から始まる段（索引の段など）の始まりで罫線を段の中に収める実装（#198）を、その ADR では改めないとした。
レビュー（`.claude/reviews/2026-10-20-adr-spec-review.md` の A-8）が、この食い違いを挙げた。

### 段間に罫線が入る場合は、今の版面にはない

行に直交する方向は、行送りの方向である。
横組みでは段は左右に並び、どの段も行送りの方向に版面の上端から下端まで延びる。
縦組みでは段は上下に並び（仕様書の段組みの節）、どの段も行送りの方向に版面の右端から左端まで延びる。
どちらの組方向でも、段間は行の方向にあり、行送りの方向にはない。
縦組みの二段めの始まり（行送りの方向の端）は、版面の右端であって段間ではない。
段間に接するのは二段めの天（行の方向の端）であり、そこへ出る罫線は行の方向の `start-indent` の負の値で決まり、[ADR 0027](0027-paragraph-style-rules.md) の行の方向の規則（段間の半分まで）がすでに扱っている。

したがって、行送りの方向で段の端が版面の端でないのは、段の並びがページの途中から始まる場合だけである。
今の実装でこれが起きるのは、`[index]` の `columns` が版面の段数と違うときに、`@index` の位置で段数を切り替えた索引の最初のページである（[docs/adr/0025](../../adr/0025-index-columns.md)）。
索引の後は次のページから版面の段組みに戻るので、段の終わりはいつも版面の下端（縦組みでは左端）に接する。
ページの途中から始まる段の始まりの前にあるのは、段間ではなく、同じページの前の内容である。
そこへ罫線を出すと前の内容に重なるので、段の中に収める実装が正しい。

[ADR 0027](0027-paragraph-style-rules.md) の二文めは、行の方向と行送りの方向を取り違えた記述であり、実装と仕様書のほうに合わせる。
メンテナーは、この読み（行の方向と行送りの方向の取り違え）を正しいと確かめた。

## 実装すること

### 規則

`keep-in-column = false` の罫線を、領域の行を取らずに版面の外に引くのは、次の二つの位置だけとする。

- 段の始まりの前の罫線で、その段が版面の上端（縦組みでは右端）から始まるとき。罫線は版面の上（縦組みでは右）の余白に入る。
- 段の終わりの後の罫線。罫線は版面の下（縦組みでは左）の余白に入る。段の終わりはいつも版面の端に接する。

ほかの位置の `keep-in-column = false` の罫線は、`keep-in-column = true` と同じ `k` で段の中に収める。
ページの途中から始まる段（索引の段）の始まりの前の罫線がこれにあたる。
[ADR 0027](0027-paragraph-style-rules.md) が定めた二つの例外（段に脚注がある段の終わり、組んだ一行目の張り出しを足すと余白を超える段落）は変えない。

### G0701 の検査

行に直交する方向の検査は、`i + w` を、その側の余白（奇数ページと偶数ページの狭いほう）とだけ比べる。
段間の半分とは比べない。
行送りの方向の罫線が段間に入る位置がないためである。
行の方向の検査（`start-indent`、`end-indent`、`length` で出る量を余白と段間の半分と比べる）は変えない。

### コード

`Golem.Layout.Paginate` と `Golem.LayoutSpec` は、すでにこの規則で動いているので変えない。

### 文書

- 仕様書の段落の罫線の節（1477 行）に、この ADR へのリンクを付け、ページの途中から始まる段（索引の段）の始まりでは段の中に収めることを書き足す。
- 同じ節の G0701 の項目（1478 行）に、行に直交する方向では段間と比べないことを書き足す。
- docs/diagnostics.md の G0701 の「主な原因」の項目（`start-indent`、`end-indent`、`length`、`keep-in-column = false` を並べて「余白の幅か段間の半分を超えて」と書くもの）を、段間の半分と比べるのは行の方向の三つのキーだけであり、`keep-in-column = false` は余白とだけ比べる、と分けて書く。
- 使い手のマニュアル（`manual/appendices/c-style.gm` の `keep-in-column` の行と、`manual/chapters/05-style.gm` の罫線の段落）は、「ページの頭と終わりの罫線」を余白に出すと書いており、この ADR の規則と合うので変えない。

### ステータスの行

- [ADR 0027](0027-paragraph-style-rules.md)：「採択→分けて組んだ段落の罫線と間隔の単位は [ADR 0035](0035-paragraph-rules-split-and-space-units.md)、（`keep-in-column = false` の罫線を版面の外に出す位置と、段間との比較）は ADR 0040」とする。
- [ADR 0035](0035-paragraph-rules-split-and-space-units.md)：「メンテナーが決めたこと」で改めないとした項目をこの ADR が決めるので、「採択→（ページの途中から始まる段の始まりの `keep-in-column = false` の罫線）は ADR 0040」とする。

## 実装しないこと

- ページの途中から始まる段の始まりで、罫線を前の内容とのあいだの空きに出すこと。前の内容との距離を測る規則が要り、索引の見出しの罫線のほかに使い道がない。
- 段組みの切り替えをほかの場所（索引のほか）に広げること。広げて、段の終わりが版面の端に接しない段ができたら、その段の終わりの後の罫線の扱いを別の ADR で決める。
- 罫線の領域の行の数 `k` の式は変えない。
- G0701 を原因ごとに分けること。G0701 は、`[page]` がないことから罫線のはみ出しまで十の原因を一つのコードで報告し、最初に当てはまった一つだけを出す。この ADR が扱う罫線の検査も、「仕上がりの線を超えます」と「段間の半分を超えます」の二つの原因を G0701 で出す。違う原因に一つのコードを使わないという diagnostic の原則に反するが、分けると [ADR 0016](0016-output-and-layout-diagnostic-codes.md) が決めたコードの割り当てと、G0701 のすべての原因が変わる。罫線の外の位置を決めるこの ADR とは別の ADR で扱う。

## テスト設計

実装はすでにこの規則で動いているので、テストを先に書いて、今の実装で通ることを確かめる。
決定を記録する ADR なので、テストが失敗する段階はない。

golem-driver の `test/ParagraphRuleSpec.hs` に加える。
既存のテスト「keep-in-column = false: the rule of the first paragraph of a page in the head margin」は一段組みの最初の段だけを固定している。

- 横組みの二段組みで、二段めの先頭の段落の前の罫線（`keep-in-column = false`）が、版面の上の余白（版面の上端より上）に引かれ、その段落の一行目が二段めの最初の格子の行にある。
- 縦組みの二段組みで、二段めの先頭の段落の前の罫線が、版面の右の余白（版面の右端より右）に引かれ、段間（一段めと二段めのあいだ）には描かれない。
- 版面と違う段数の索引で、ページの途中から始まる索引の段の最初の項目に前の罫線を持つ段落スタイルを当てると、罫線は段の中に引かれ、領域の行を一行以上取る。索引の項目に段落スタイルの罫線を当てる手段がなければ、golem-layout の `test/PaginateSpec.hs` で、`csFirstLine` が 0 でない段の始まりの `FRuled` の前の罫線が `keep-in-column = true` と同じ `k` を取ることを確かめる。

golem-layout-spec の `test/Main.hs` に加える。

- 二段組みで段間を 1zw とし、`keep-in-column = false` の後の罫線の `i + w` を、段間の半分より大きく下の余白より小さくすると、G0701 を出さない。

## トレードオフ

- [ADR 0027](0027-paragraph-style-rules.md) の段間に関する記述を残して、将来ページの途中で終わる段が加わったときの規則とする案もあった。しかし、その記述は今の版面で起きない位置を、行の方向と取り違えて書いたものであり、残すと読み手が実装の欠けと誤解する。起きるようになった時点で、その版面の形に合わせて決める。
- ページの途中から始まる段で罫線を段の中に収めると、版面の上端から始まる段と、同じ段落スタイルでも行の数が変わる。前の内容に罫線が重なるよりよいと判断した。
