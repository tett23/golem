# ADR 0041: 隠しノンブルの検査を `size` の半分の幅で行い、仕上がりの線を越える誤りを G0329 に分ける

ステータス: 採択（未実装）

## 文脈

[ADR 0021](0021-hidden-folios.md) は、トンボを付けた PDF に入れる隠しノンブルの数字を、ノドの仕上がりの線から `gutter` の距離にある中心線に、一字ずつ縦に並べると決めた。
各字は、字の送りの幅をこの中心線にそろえて置く。

版面との重なりの検査（G0750）について、[ADR 0021](0021-hidden-folios.md) の「版面との重なり」の節は次のように書く。

> 列の左右の範囲（中心線から字の送りの幅の半分ずつ）が、そのページの版面か傍注欄に、左右の方向で重なる場合はエラー（G0750）とする。

同じ節は、検査を `Golem.LayoutSpec.pageGeometry` で行うとし、ノドの仕上がりの線を越える場合の G0306 については「読み込みの段階では `size` の半分を字の送りの半分と見なして検査する」と書く。
G0750 にはこの見なしを書いていない。

仕様書（1015 行）、docs/diagnostics.md の G0750、実装は、G0750 でも `size` の半分を使う。

- 仕様書は「数字の列の左右の範囲（中心線から `size` の半分ずつ）」と書く。
- `Golem.LayoutSpec` の `hiddenFolioGeometry`（329 行）は、`centre - size / 2 < x + w && centre + size / 2 > x` で重なりを判定する。
- `Golem.Project.Style` の `[hidden-folio]` の読み込み（701 行）も、G0306 を `size` の半分で判定する。

レビュー（`.claude/reviews/2026-10-20-adr-spec-review.md` の A-9）が、この食い違いを挙げた。

### pageGeometry は字の送りを知らない

`pageGeometry` は `style.toml` だけから版面と傍注欄とマスターページの位置を計算し、フォントを読まない。
G0750 は、ビルドでも `golem check` でも、レイアウトの前に報告する（仕様書の隠しノンブルの節）。
字の送りを使うには、本文の役割の欧文のフォント（なければ和文のフォント）を読み、`0` から `9` の十字の送りを調べてから検査することになる。
プロポーショナルな数字を持つ書体では、字ごとに送りが違うので、最も広い字を求める必要もある。

`size` の半分は、欧文の書体の数字の送り（多くの書体で 0.5em から 0.6em。[ADR 0021](0021-hidden-folios.md) の「位置と形」）より大きい。
数字の送りが 1em を超える書体は通常ないので、`size` の半分で重ならなければ、実際の字も版面に重ならない。
検査は実際より厳しい側に倒れる。

### 仕上がりの線を越える誤りが G0306 にまとまっている

`gutter` が `size` の半分より小さい（数字の列がノドの仕上がりの線を越える）ときのエラーは、今は G0306 である。
`Golem.Project.Style` の `[hidden-folio]` の `FromValue` が `failTableAt` で読み込みを止め、`decodeStrictBy "G0306"` がそれを G0306 にする。
メッセージは `[hidden-folio] の gutter が size の半分より小さいため、隠しノンブルが仕上がりの線を越えます` であり、どの値でいくつにすればよいかを示さない。

G0306 は、`style.toml` が TOML として読めないこと、スキーマに合わないこと、値が範囲の外にあることを報告するコードである（docs/diagnostics.md）。
数字の列と仕上がりの線の位置の関係は、どのキーも単独では正しい値なのに、二つのキーの組み合わせで起きる誤りであり、これらとは別の原因である。
diagnostic には、違う原因に一つのコードを使わないという原則がある。
メンテナーは、この誤りを G0306 から分けて専用のコードにし、この ADR で決めると決めた。

## 実装すること

### 規則

G0750 の「数字の列の左右の範囲」は、中心線から `size` の半分ずつとする。
フォントの字の送りは使わない。
仕上がりの線を越える誤り（G0329、下の節）も、同じ `size` の半分で判定する。

数字を描く位置は [ADR 0021](0021-hidden-folios.md) のとおりとし、各字の送りの幅を中心線にそろえる。
検査の幅と描く幅は別のものであり、検査の幅は描く幅の上限として使う。

### G0329：隠しノンブルが仕上がりの線を越える

`[hidden-folio]` の `gutter` が `size` の半分より小さい（`2 × gutter < size`）場合を、G0306 から分けて G0329 とする。

- **番号**：G0329。プロジェクトと `style.toml` の検査の区分（G03xx）で、使っている最後の番号は G0328 である。docs/diagnostics.md、origin のすべてのブランチ、このときの ADR の草稿（G0296 から G0298、G0815 から G0819 を使う）のどれも G0329 を使っていないことを確かめた。
- **重大度**：エラー。
- **段階とモジュール**：プロジェクト（golem-project の `Golem.Project.Style`）。`style.toml` を読むときの検査であり、今の G0306 と同じく、`enabled`、`--marks`、ターゲットによらず検査する。`style.toml` だけで決まり、実行のたびに同じ結果になるようにするためである。
- **位置**：`style.toml` の `[hidden-folio]` の `gutter` の値の位置。`gutter` を書かず `size` だけを書いた場合は、`size` の値の位置とする（今の G0306 の位置と同じ）。どちらも書かなければ既定の値（`6pt` と `1.5mm`）であり、この誤りは起きない。
- **メッセージ**：`[hidden-folio] の gutter（<gutter>）が size（<size>）の半分（<半分>）より小さいため、隠しノンブルの数字が仕上がりの線を越えます（gutter を <下限> 以上にするか、size を <上限> 以下にします）`
- **値の書き方**：どの値も mm で、小数第 2 位まで書く。`<gutter>`、`<size>`、`<半分>` は、読み込んだ sp の値を有理数のまま mm に直し、小数第 3 位を四捨五入する。`<下限>` は、0.01mm の倍数のうち、`style.toml` の寸法と同じ変換（`mmToSp`）で sp に直したときに `2 × gutter ≥ size` を満たす最小の値とする。`<上限>` は、同じ変換で sp に直したときに `size ≤ 2 × gutter` を満たす最大の値とする。書き手がメッセージの値をそのまま `"1.06mm"` のように書けば、sp への丸めを含めて必ず検査を通る。書かなかったキーは既定の値を使う。
- **メッセージの例**：`size = "6pt"`、`gutter = "2pt"` では、`[hidden-folio] の gutter（0.71mm）が size（2.12mm）の半分（1.06mm）より小さいため、隠しノンブルの数字が仕上がりの線を越えます（gutter を 1.06mm 以上にするか、size を 1.41mm 以下にします）` となる。
- **事実**（`diagFacts`）：`gutter`、`size`、`min-gutter`、`max-size` を sp の整数で持つ。
- G0329 は、`style.toml` をスキーマのとおりに読めた後の検査（`styleChecks`）の一つとし、ほかの検査の誤り（G0311 など）と一緒に出す。TOML として読めないか、スキーマに合わない（G0306 などで読み込みが止まる）ときは、G0329 を検査しない。今の G0306 は読み込みを止めていたので、ほかの検査の誤りが一緒に出るようになる点が変わる。

G0306 の `[hidden-folio]` の誤りは、ほかの原因（`zw` の寸法、0 以下の値、読めない寸法、`pages` の表にない値、未知のキー）だけになる。

G0750 と一つのコードにまとめる案は採らない。
G0750 は数字の列が版面か傍注欄に重なる誤りで、直すには `gutter` を小さくするかノドの余白を広げる。
G0329 は仕上がりの線を越える誤りで、直すには `gutter` を大きくするか `size` を小さくする。
直し方が逆なので、別の原因である。

### コード

- `Golem.LayoutSpec` は、すでに G0750 をこの規則で判定しているので変えない。`hiddenFolioGeometry` の Haddock は「half the size on each side of its centre line」と書いており、そのまま残す。
- `Golem.Project.Style`：`[hidden-folio]` の `FromValue` から `gutter` と `size` の比較を除き、`styleChecks` に G0329 の検査を加える。位置は `checkPosition` で `[hidden-folio]` の `gutter`（なければ `size`）の値から取る。`gutter` と `size` を書いたかどうかを位置に使うので、`HiddenFolio` の読み込みは、書いたキーの経路が分かる形で検査に渡す。
- `Golem.Driver.Explain.Catalog`（`golem explain` の一覧）に G0329 を加える。

### 文書

- docs/diagnostics.md に G0329 の節を加える（意味、重大度、メッセージ、段階とモジュール、ADR、主な原因、直し方）。G0306 の「意味」の「使わない」の列に、隠しノンブルの `gutter` と `size` の関係（G0329）を足す。G0750 の ADR の行にこの ADR を加える。
- 仕様書の隠しノンブルの節（キーの表の後と、1015 行の G0750 の段落）に、この ADR へのリンクを付け、次を書く。
  - `gutter` が `size` の半分より小さい場合は、`style.toml` を読むときのエラー（G0329）であること。
  - G0750 と G0329 は、どちらも数字の列の幅を `size`（中心線から `size` の半分ずつ）として測ること。`pageGeometry` がフォントを読まないためであり、実際の数字の幅より広いこと。
- 使い手のマニュアル：
  - `manual/appendices/c-style.gm` の `[hidden-folio]` の節の「エラー（G0306）になります」を G0329 に改め、「数字の列が版面か傍注欄に重なると、エラー（G0750）になります」に、数字の列の幅を `size` と同じとして測ることを書き足す。
  - 付録 E（`manual/appendices/e-errors.gm`）の G03 の項の並びに G0329 の項を加え、原因と直し方（`gutter` を大きくするか、`size` を小さくする。メッセージの値に直せば通る）を書く。G0750 の項は幅に触れていないので変えない。

### ステータスの行

- [ADR 0021](0021-hidden-folios.md)：「採択→（数字の列の幅と、仕上がりの線を越える誤りの G0306 から G0329 への分離）は ADR 0041」とする。

## 実装しないこと

- フォントを読んでから、数字の実際の送りで G0750 と G0329 を検査すること。検査をレイアウトの後に移すことになり、`golem check` がフォントを読む必要が出る。
- 数字の字形の外接矩形（インクの範囲）で検査すること。
- G0750 と G0329 を警告に下げること。どちらの設定も入稿できないので、エラーのままとする。
- `enabled = false` のときや、トンボを付けないときに G0329 を出さないこと。`style.toml` の検査を CLI のオプションに依らせないため、今の G0306 と同じく常に検査する。
- G0306 のほかの原因を分けること。G0306 のすべての原因に関わるので、別の ADR で扱う。

## テスト設計

### 先に書いて失敗させるテスト

golem-project の `test/Main.hs` の「a gutter less than half the size is G0306」を、次のテストに置き換える。
今の実装は G0306 を出すので失敗する。

- `[hidden-folio]` に `size = "6pt"`、`gutter = "2pt"` を書くと、G0329 が一つで、G0306 を含まない。メッセージが「メッセージの例」の文字列と一致する。位置が `gutter` の値の位置である。
- `size = "8mm"` だけを書く（`gutter` は既定の 1.5mm）と、G0329 で、位置が `size` の値の位置である。
- 境界を示す値がそのまま使えることを、性質として確かめる。`size` と `gutter` の組をいくつか（`6pt` と `2pt`、`8mm` と `1.5mm`、`13Q` と `1mm`、`7pt` と `0.5mm`）選び、それぞれについて、`gutter` をメッセージの下限の値（mm の文字列）に替えた `style.toml` と、`size` をメッセージの上限の値に替えた `style.toml` が、どちらも G0329 を出さないこと、下限より 0.01mm 小さい `gutter` と上限より 0.01mm 大きい `size` は G0329 を出すことを確かめる。
- `2 × gutter = size` ちょうど（sp に丸めの起きない `size = "6pt"`、`gutter = "3pt"`）は G0329 を出さない。
- `enabled = false` でも G0329 を出す。
- `gutter = "1zw"` は今のとおり G0306 であり、G0329 ではない。
- G0329 の誤りと、段落スタイルの文字の大きさが版面の文字の大きさを超える誤り（G0311）を同じ `style.toml` に書くと、G0329 と G0311 の両方が出る。未知のキー（G0306）と一緒に書くと、読み込みが止まるので G0306 だけが出る。

golem-driver のテスト：

- `golem explain G0329` が説明を返す。

### 今の実装で通ることを確かめるテスト

既存のテスト（golem-layout-spec の `test/Main.hs` の「G0750: a hidden folio on the type area, only with crop marks and when enabled」）は、ノドの余白 1.5mm と 15mm の二つだけを比べ、境界を固定していない。
同じファイルに次を加える。
G0750 の判定は変えないので、これらは今の実装で通る。

- `[hidden-folio]` の `size` を 6pt とし、ノドの余白（版面の位置の `gutter`）を M とする。`[hidden-folio]` の `gutter` を M − 3pt にすると、中心線から版面までがちょうど `size` の半分になり、G0750 を出さない。
- 同じく `[hidden-folio]` の `gutter` を M − 3pt + 1sp にすると、G0750 を出す。数字の送りを 0.55em とすれば、実際の字は版面から 1pt 以上離れるので、検査がフォントの送りでなく `size` の半分で決まることを固定する。
- 奇数ページと偶数ページでノドの側が入れ替わっても、同じ境界で判定する。

## トレードオフ

- `size` の半分は数字の実際の幅より広いので、ノドの余白がぎりぎりの設定では、実際には重ならない数字に G0750 を出し、実際には仕上がりの線を越えない数字に G0329 を出す。数字の送りを 0.55em とすると、6pt で片側に約 0.5mm（1.35pt）の差である。判定を緩めて入稿の後に気づくより、厳しく倒すほうを採る。
- フォントに依らないので、書体を替えても G0750 と G0329 の結果は変わらない。二つの検査が同じ幅を使うので、検査のあいだで食い違いが起きない。
- メッセージに値と直す先を入れるので、メッセージが長くなる。書き手が単位を換算して境界を探す手間を省くほうを採った。値をすべて mm で書くのは、`size` と `gutter` を違う単位（`pt` と `mm` など）で書いた本でも、比べられるようにするためである。
