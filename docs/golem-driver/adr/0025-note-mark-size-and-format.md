# ADR 0025: 注の印の大きさと書式

ステータス: 採択

## 文脈

所有者から、二つのマニュアル（`manual/`、`manual-dev/`）の PDF で、本文の注の印（`*1`）が小さすぎるという指摘があった。

### 今の印の組み方

印の大きさと形は、[ADR 0018](0018-footnote-marks-and-numbers.md) が固定した。

- 印の大きさ `m` は、印の位置の文字の大きさ `s` の半分である。golem-layout の `Golem.Layout.Japanese` の `noteMarkSize`（``s `div` 2``）が決め、`piecesOf` の `markPiece` が箱の幅を、golem-driver の `Golem.Driver.Pdf` の `drawLineAt` が描く大きさを、同じ関数で求める。
- 印の文字列は `*` と算用数字の番号である。`piecesOf` が本文の印を、`Golem.Driver.Pdf` の `withNoteMark` が注の本文の先頭の印（`*1 `）を作る。
- 番号の印の傍注（`marker = "number"`）も、文字列を番号だけにして同じ箱（`KindNoteMark`）で組むので、同じ大きさになる。

[ADR 0018](0018-footnote-marks-and-numbers.md) は、印の形式の設定（接頭辞、接尾辞、数字の表記、上付きと通常の選択、文字スタイル）を「実装しないこと」に置いた。
仕様書の「v1 の実装で次の段階以降に回した項目」には、「注の印の書式」が残っている。

### 今ある設定で大きくできるか

コードで確かめると、印の大きさを変える設定はない。

- `style.toml` の `[notes]` が読むキーは `placement`、`numbering`、`rule` の三つだけである（`Golem.Project.Style` の `Notes`）。
- 印の箱は、その位置の `Look` を持つ。原稿で注を文字スタイルの中に置けば（`[style 大きい: [note: ...]]`）、`s` が文字スタイルの大きさになり、`m` もその半分になる。しかし、印の字面の上端は大きい `s` の字面の枠の上端にそろうので、印が本文の字面より上に出る。注を書くたびに原稿に書く必要もあり、設定の代わりにはならない（コードを読んで確かめた。PDF に組んでは確かめていない）。

### 大きさの目安

二つのマニュアルの本文は 13Q（約 9.2pt）なので、今の印は 6.5Q（約 4.6pt）である。
JLReq の 4.2.3「合印の処理」は、合印の文字の大きさを 6 ポイント前後としている。
JLReq が述べているのは、合印を行間（縦組みでは右、横組みでは上）に置く組み方である。
Golem は印を行の中に置き、字面の上端（縦組みでは右端）にそろえるので、置き方は同じではない。
それでも、6 ポイントという大きさは、印が読める大きさの目安になる。
13Q の本文では、6pt はおよそ `0.65zw` にあたる。

### 印の書式

JLReq の 4.2.2「注の番号」は、注の番号の書き方として、算用数字（縦組みと横組み）、漢数字（縦組み）、アステリスクの連なり、†、‡、¶、§ のような記号の連なりを挙げる。
縦組みでは番号の両側に括弧を付けることが多く、横組みでは閉じ括弧だけを付けることが多い、とも書いている。
Golem の `*1` の形は、このどれとも違う。
括弧を付ける形（`1)`、`(1)`）と、漢字を添える形（`注1`）は、算用数字のまま書式の文字列で表せる。

InDesign の脚注のオプションには、番号の形式、接頭辞と接尾辞、参照番号の位置と文字スタイルの設定がある（[ADR 0018](0018-footnote-marks-and-numbers.md) と同じく記憶によるもので、資料では確かめていない）。

### メンテナーが決めたこと

印の文字スタイル（印を組む書体と色）は、`[notes]` の `mark-style` として v0.1.0-rc4 で加える。
この ADR では扱わず、別の ADR で決める。
この ADR の `mark-size` と `mark-format` は、`mark-style` を加えた後も意味を変えない。

## 実装すること

### 設定（golem-project）

`[notes]` に二つのキーを加える。

```toml
[notes]
numbering = "chapter"
mark-size = "0.65zw"
mark-format = "*{n}"
```

| キー | 型 | 意味 |
| --- | --- | --- |
| `mark-size` | 寸法 | PDF の本文の印の大きさ。`zw` は、印の位置の文字の大きさに対する比とする。既定は `"0.5zw"` |
| `mark-format` | 文字列 | PDF の本文の印と、注の本文の先頭の印の書式。`{n}` を注の番号（算用数字）に置き換える。既定は `"*{n}"` |

- `Style` に `stNotesMarkSize :: Dim`（既定 `Zw (1 % 2)`）と `stNotesMarkFormat :: Text`（既定 `"*{n}"`）を加える。
- `mark-size` が寸法として読めない値の場合、0 以下の場合、`zw` で 1 を超える場合は G0306 とする。1 を超える `zw` は、印が本文の字より大きくなり、字面の枠の上端にそろえる組み方が成り立たないためである。
- `mark-format` が `{n}` をちょうど一つ含まない場合は G0306 とする。`{n}` だけの書式（番号だけの印）は書ける。
- 既定の値は今の振る舞いと同じなので、二つのキーを書かない本の出力は変わらない。

### 印の大きさ（golem-layout、golem-driver）

`noteMarkSize` を、設定の寸法を受け取る形に替える。

```haskell
-- | The size of a note mark in text of a size (ADR 0018, ADR 0025).
noteMarkSize :: Dim -> Sp -> Sp
noteMarkSize d s = max 1 (min s (dimToSp s d))
```

- 絶対の寸法（`"6pt"` など）が、印の位置の文字の大きさを超える場合は、その文字の大きさで組む。小さい文字（キャプションなど）の中の印が、その文字より大きくならないようにするためである。
- `piecesOf` は、`ComposeEnv` に加える `ceNoteMarkSize :: Dim` で印の大きさを求める。`drawLineAt` は、`Style` の `stNotesMarkSize` で同じ値を求める。箱の幅と描く大きさが同じ関数から出るのは、今と同じである。
- 印の位置（横組みの字面の上端、縦組みの字面の右端）と箱の幅の決め方は、[ADR 0018](0018-footnote-marks-and-numbers.md) のまま、新しい `m` で計算する。
- 番号の印の傍注（`MarkerNumber`）も、同じ `mark-size` で組む。仕様書の「傍注」の節が、番号の印を脚注の印と同じ大きさで組むと書いているためである。書式は今のまま番号だけとし、`mark-format` は使わない。

### 印の書式（golem-layout、golem-driver）

- `piecesOf` は、本文の印の文字列を、`ComposeEnv` に加える `ceNoteMarkFormat :: Text` の `{n}` を番号に置き換えて作る。
- `withNoteMark` は、注の本文の先頭に、同じ書式で作った文字列と半角の空白を付ける。この印は、今と同じく注の本文の大きさで組み、上げない。
- 番号は算用数字で書く。

### ドキュメント

- 仕様書の「脚注」の節の印の説明を、`mark-size` と `mark-format` の既定で書き直す。「style.toml」の節の例と `[notes]` の説明に二つのキーを加える。
- 仕様書の「v1 の実装で次の段階以降に回した項目」から「注の印の書式」を消す。数字の表記（漢数字など）が残ることは、この ADR の「実装しないこと」に書いたので、残った事項を同じ一覧に「注の印の数字の表記」として足す。
- docs/roadmap.md の v1.0.0 の「注の印の書式」を消し、v0.1.0-rc4 の節に「注の印の文字スタイル（`[notes]` の `mark-style`）」を加える。
- 二つのマニュアルの `style.toml` の `[notes]` に `mark-size = "0.65zw"` を書く。`docs/manual-policy.md` の「二つのマニュアルに共通する体裁」に、その値と理由（JLReq の合印の大きさの目安）を書く。
- 利用者のマニュアルの `manual/chapters/05-style.gm` の「注と図の設定」の節と `manual/appendices/c-style.gm` の `[notes]` の節に、二つのキーを加える。

## 実装しないこと

- HTML、EPUB、プレーンテキストの印。HTML と EPUB の印は番号のリンクであり、大きさは CSS とリーダーが決める。プレーンテキストの印は [golem-text ADR 0001](../../golem-text/adr/0001-plain-text-output.md) が `*1` と `※1` に固定している。
- 算用数字のほかの数字の表記（漢数字、平字、記号の連なり）。JLReq の 4.2.2 が挙げる形であり、番号の表記を書式から選ぶ仕組みが要る。
- 印の文字スタイル（書体、色）。v0.1.0-rc4 で `[notes]` の `mark-style` として加える予定であり、別の ADR で決める。印の位置の計算は大きさ `m` だけで決まり、書体を変えると字面の枠の中心（`lfEmBoxCentral`）の求め方も変える必要があるので、この ADR とは分ける。
- 本文の印と注の本文の先頭の印に、別々の書式を付けること。
- 印を行間に置く組み方。[ADR 0018](0018-footnote-marks-and-numbers.md) の「実装しないこと」のまま残す。
- 縦組みで、印の幅が本文の字の大きさを超える場合の扱い。[ADR 0018](0018-footnote-marks-and-numbers.md) は 5 字以上の印で起きるとしたが、印を大きくし、書式で字を足すと、より短い印で起きる。v1 では扱わず、仕様書の「脚注」の節にその条件を書く。
- 傍注の `MarkerSymbol`（`※`）の大きさの変更。

## テスト設計

実装の前に書き、失敗することを確かめる。

### style.toml（`modules/golem-project/test/Main.hs`）

- `[notes]` がないとき、`stNotesMarkSize` が `Zw (1 % 2)`、`stNotesMarkFormat` が `"*{n}"` である。
- `mark-size = "0.65zw"`、`"6pt"`、`"8Q"` を読める。
- `mark-size` の `"0zw"`、`"1.5zw"`、`"abc"` が G0306 になる。`"1zw"` は読める。
- `mark-format = "注{n}"`、`"{n})"`、`"{n}"` を読める。`"注"`（`{n}` がない）と `"{n}-{n}"`（二つある）が G0306 になる。

### 箱（`modules/golem-layout/test/Main.hs`）

測る関数には、テストの中で固定の値を返す関数を使う。

- `mark-size = "0.65zw"` の横組みで、印の箱の幅が、`*1` を大きさ `dimToSp s (Zw 0.65)` で測った値に等しい。縦組みで、幅がその大きさに等しい。
- 11Q の文字の中の印に `"6pt"` を与えると、印の大きさが 6pt になる。`"20pt"` を与えると、11Q になる。
- `mark-format = "注{n}"` で、印の箱の文字列が `注1` になる。
- 番号の印の傍注の箱が、`mark-size` の大きさで、文字列が番号だけである。

### PDF（`modules/golem-driver/test/Main.hs`）

- 横組みで `mark-size = "0.65zw"` にすると、印のグリフの大きさが `m` であり、印の基準線が本文の基準線より `(c + 1/2) × (s − m)` 上にあり、印の後ろの字のグリフの原点が、印の最後のグリフの送りの終わり以降にある。
- 縦組みで同じ設定にすると、印の右端が行の中心線から `s/2` 右にある。
- `mark-format = "{n})"` で、本文の印が `1)` で、注の本文の最初の行の先頭が `1) ` である。
- 既定と同じ値を書いた `style.toml` と、二つのキーを書かない `style.toml` で、PDF のページの内容のストリームが同じになる（インスタンス ID は `style.toml` のバイト列を含むので比べない）。キーを書かない本の PDF が今と変わらないことは、既存の PDF のテストがそのまま通ることで確かめる。
- 二つのマニュアルを組み、診断が出ない。

### 自動テストにしない確かめ方

- 二つのマニュアルの注のあるページを画像にし、印が大きくなったこと、印が次の字に重ならないこと、印の上端が本文の字面の上端にそろうことを目で確かめる。
- 縦組みの試料（蟹工船の原稿に注を足したもの）を `mark-size = "0.65zw"` で組み、印が行の右にそろい、隣の行と重ならないことを目で確かめる。

## トレードオフ

既定を今と同じ `0.5zw` にした。
JLReq の目安に合わせて既定を大きくすると、注を持つすべての本の PDF が変わる。
しかも、6 ポイントの目安を `zw` の比に直すと、本文の大きさごとに比が変わるので、一つの比を既定にする根拠がない。
大きくしたい本が書く形にし、二つのマニュアルはそれを書く。

`mark-size` に、`zw` の比と絶対の寸法の両方を書けるようにした。
`zw` なら、キャプションのように文字の大きさが変わる場所でも、印が本文との釣り合いを保つ。
絶対の寸法なら、JLReq の目安をそのまま書ける。
絶対の寸法が小さい文字より大きくなる場合は文字の大きさで止めるので、書いた値どおりにならない場合がある。

書式を、接頭辞と接尾辞の二つのキーではなく、`{n}` を含む一つの文字列にした。
見出しの番号の書式（`[headings.N]` の `number = "第{n}章"`）と同じ書き方にそろえるためである。

本文の印と注の本文の先頭の印に同じ書式を使うので、本文では `1)`、注では `1.` のように変えることはできない。
キーを一つにして、印と注の対応を読み手が取り違えないことを優先した。

PDF だけに効く設定にしたので、同じ本の HTML と EPUB の印は、`mark-format` によらず番号のリンクのままになる。
プレーンテキストの印も今の形のまま残る。
媒体ごとに印が違うことは、今もプレーンテキストの印（縦書きの `※1`）で起きている。

文字スタイルで印を組む形（InDesign の参照番号の文字スタイルにあたるもの）は採らなかった。
文字スタイルは書体と色も変えられるので、大きさのほかに、字面の枠の中心の求め方まで変える必要がある。
大きさだけなら `m` を変えるだけで [ADR 0018](0018-footnote-marks-and-numbers.md) の計算がそのまま使える。
文字スタイルは、v0.1.0-rc4 で `mark-style` を足す ADR で扱う。
