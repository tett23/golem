# ADR 0029: 本文の中のコードの背景の色

ステータス: 採択

## 文脈

ロードマップの v1.0.0 の「本文の中のコードの背景の色」は、本文の中のコード（`[code: ...]`）に背景の色を付ける項目である。
コードブロックは段落スタイル `code` の `background` で背景を塗れるが（[ADR 0017](0017-pdf-code-blocks.md)）、本文の中のコードには背景の色を付ける手段がない。
技術書では、本文の中のファイル名やコマンドに薄い網をかけ、地の文と見分けやすくすることが多い。

[ADR 0017](0017-pdf-code-blocks.md) は、本文の中のコードの背景を「実装しないこと」に置いた。
その理由として、一つの語が行をまたいで分かれたときの塗り方、ルビや圏点との重なり、縦組みでの向きを決める必要があることを挙げた。
HTML と EPUB でも、媒体の差を作らないために `<code>` に背景を付けないとした。
この ADR は、その三つを決め、PDF、HTML、EPUB に同時に背景を加える。

### 今のコード

コードで確かめると、次のとおりである。

- `[code: ...]` は文字スタイル `code` を付ける `[style code: ...]` の別名であり、意味論 IR は `CharStyle "code"` である。
- 文字スタイルの定義 `CharStyleDef` は `font`、`size`、`color` などを持つが、背景のキーはない。
- golem-layout の `Look` は、`lkColor`（文字の色）と `lkCode`（コードとして組むか）を持つ。`lkCode` の文字は `codePieces` で箱にされ、空白と `/` の後でだけ改行できる。コードの前後の空きは、端の文字のクラスで決まる（`normalize`）。
- `Golem.Driver.Pdf` の `drawLineAt` は、行の箱を順に描き、同じ色の箱の並びを一つの `Saved [SetColor ...]` で囲む。背景を描く処理は、コードブロックの背景と枠と強調の帯（ページの最初に描く）だけである。
- golem-html は、文字スタイル `code` を `<code>` で出し、`style.css` に `pre, code` の `font-family` だけを書く。
- 二つのマニュアルの `style.toml` は、`[character-styles.code]` に `color = "code"`（青）を、`[paragraph-styles.code]` に `background = "code-bg"`（墨 8%）を書いている。
- ルビの読みが隣の字にかかるのは、隣が圏点のない仮名か、隣のルビの読みの空いた場所の場合だけである（golem-layout の `Golem.Layout.Japanese` の `allowance`）。本文の中のコードの字は `codePieces` で `PCode` の箱になるので、隣のルビの読みはコードの字にかからない。
- 横組みのルビの読みは、親文字のうち最も大きい字の大きさ `s` だけ親文字の基準線から上げた基準線に置く（`Golem.Driver.Pdf` の `drawLineAt`）。圏点は、字面の枠の上端（縦組みでは右端）の外に置く（[ADR 0019](0019-pdf-kenten-shapes.md)）。どちらも行の字面の外にある。

### メンテナーが決めたこと

- 背景の既定は、段落スタイル `code` の `background` のスウォッチを引き継ぐ。背景がないと、本文の中のコードが地の文の中で見つけにくいためである。
- `padding` はいつも効き、誤りにならない。背景がない場合も、コードの前後に余白を取る。
- 背景の行と直交する方向の範囲とルビと圏点の位置の関係を決め、重ならない既定の余白を選ぶ。
- 文字の色と背景は、両方を同時に設定できる。二つのマニュアルは、青い字と網の両方を使う。

メンテナーが今のマニュアルで指摘したルビの重なりは、本文の中のコードではなく、コードブロックの背景と直後の行のルビの重なりだった。
原因と直し方は、草稿の[コードブロックの直後の行のルビと圏点](0033-ruby-after-code-block.md)で扱う。
この ADR は、本文の中のコードの背景について、重なりが起きうる二つの向き（行の方向と、行に直交する方向）のどちらでも、背景とルビと圏点が重ならないことを規則とテストで定める。

## 実装すること

### style.toml の設定

文字スタイルに、二つのキー `background` と `padding` を加える。

```toml
[character-styles.code]
background = "code-bg"
padding = "0.25zw"
```

| キー | 型 | 既定 | 意味 |
| --- | --- | --- | --- |
| `background` | スウォッチの名前か `false` | 段落スタイル `code` の `background` | 背景の色。`false` は背景を塗らない |
| `padding` | 寸法 | `"0.25zw"` | コードの前後に取る、行の方向の余白。`zw` はその文字スタイルの文字の大きさを一字とする |

- 二つのキーは、組み込みの文字スタイル `code` と、`based-on` をたどって `code` に行き着く文字スタイル（`lkCode` の文字スタイル）にだけ書ける。ほかの文字スタイルに書くと G0306 とする。型は文字スタイルの全体に持たせ、実装をコードに絞る（仕様書の「設計原則」の「広い型、狭い実装」）。段落スタイルの `background` と `padding` を `code` に絞ったのと同じ形である。
- 二つのキーは、ほかのキーと同じく `based-on` でキーごとに引き継ぐ。
- `background` を書かなければ、段落スタイル `code` の `background` を使う。段落スタイル `code` にも `background` がなければ、背景を塗らない。`background = false` は、段落スタイルの背景を引き継がないことを表す。`true` は G0306 とする。
- `background` のスウォッチが `[color.swatches]` にない場合は G0313 とする。`padding` が寸法として読めない場合と負の場合は、寸法の値の誤りとして G0306 とする。
- `padding` は、背景の有無によらず効く。背景がなくても、`background` を書かなくても、誤りにしない（メンテナーの決定）。背景がなければ、余白は空きとして見える。
- `color`（文字の色）と `background` は一緒に書ける。
- ファイルの先頭の `@style-def character` にも、同じ条件で書ける。
- 余白の既定 `0.25zw` は、コードを含むすべての本に効く。背景を持たない本でも、本文の中のコードの前後が広がり、行の分け方が変わりうる。

### 組み方（golem-layout）

- `Look` に、背景のスウォッチ `lkBackground :: Maybe Text` と、行の方向の余白 `lkPadding :: Sp` を加える。
- コードの文字の並び（一つの `[code: ...]`、または同じ文字スタイルが続く範囲）の最初の箱の前と、最後の箱の後に、それぞれ `padding` の幅を足す。背景の有無によらない。足した幅は、その箱の送りに含め、箱の中の字は前の余白の分だけ後ろから描く。`BoxContent` に、前と後の余白の幅を持たせる。
- 余白を箱の中に入れるので、余白とコードの文字のあいだでは改行しない。
- コードの前後の空き（アキ量のセットの空き、和欧間の空き）は、今と同じく端の文字のクラスで決め、余白の外に置く。
- 余白は行分割の幅に入るので、本文の中のコードを持つ本では行の分け方が変わりうる。
- ルビの読みは、コードの字にも余白にもかけない。今の `allowance` が `PCode` に 0 を返す振る舞いを、余白を足した箱でも保ち、テストで固定する。

### 背景とルビと圏点の位置

背景が塗る範囲と、ルビと圏点を置く範囲を、次のように分ける。

- **行に直交する方向**：背景は、その行の字面（行の大きさの字面の枠）だけを塗り、字面の外には広げない。ルビの読み（親文字の字面の外、横組みの上、縦組みの右）と圏点（字面の枠の外）は、どちらも字面の外にあるので、背景と重ならない。隣の行のルビは行間にあり、これも背景と重ならない。行と直交する方向の余白のキーを設けないのは、字面の外に広げると、すぐ外にあるルビと圏点に重なるためである。
- **行の方向**：コードの外のルビの読みは、コードの字と余白にかからない（前の節）。コードの中の字にルビを振った場合（`[code: [ruby: 値|あたい]]` のように書けた場合）、親文字は背景の上にあり、読みは字面の外にあるので背景と重ならない。読みが親文字より長く、コードの外の仮名にかかる場合は、読みが背景の幅より外に出るが、字面の外なので背景とは重ならない。

余白の既定 `0.25zw` は、ルビの読みの位置からではなく、背景の端と隣の字のあいだを空けるために選ぶ。
背景を字面だけに塗るので、ルビと圏点との重なりは、余白の値によらず起きない。
四分の余白は、和欧間の空き（四分）と合わせて、背景の端と隣の和字のあいだに四分以上の空きを残す。

### 描き方（golem-driver の PDF）

背景は、行ごとに、同じ背景を持つ箱の並びを一つの矩形で塗る。

- **行の方向**：並びの最初の箱の始まり（前の余白を含む）から、最後の箱の終わり（後の余白を含む）まで塗る。並びの中の空白（コードの中の語間）も塗る。行末の空白と、行頭と行末で除かれる空きは塗らない。
- **行と直交する方向**：その行の字面（横組みでは行の大きさの字面の上端から下端、縦組みでは中心線から左右に行の大きさの半分）を塗る。`drawLineAt` の行の字面（`lineFace`）と同じ範囲である。行送りは行の大きさ以上なので、背景が隣の行に重ならない。
- **行をまたぐコード**：コードが空白か `/` の後で次の行に分かれた場合は、行ごとに別の矩形を塗る。前の余白は最初の行の始まりにだけ、後の余白は最後の行の終わりにだけある。分かれた側（前の行の終わりと次の行の始まり）は余白なしで、箱の端で切る。
- **縦組み**：行の方向を天から地とし、上の規則のまま塗る。縦組みの中で回転して組む欧文の箱も、同じ矩形の中に入る。
- **ルビと圏点**：ルビと圏点は字面の外（横組みの上、縦組みの右）に描くので、背景の外にある（「背景とルビと圏点の位置」の節）。背景は、その行の文字より先に描き、文字とルビと圏点を背景の上に描く。
- **注の印**：コードの中に注の印を置くと（`[code: a[note: ...]]` のような書き方が通る場合）、印の箱も背景の並びに入る。
- **色**：スウォッチの CMYK を DeviceCMYK で塗る。`Saved [SetColor sw, Rule rect]` の形で、コードブロックの背景と同じである（[ADR 0017](0017-pdf-code-blocks.md)）。

背景は、`drawLineAt` で描くすべての行に効く。
本文の段落、見出し、キャプション（コードブロックのキャプションを含む）、表のセル、脚注、傍注の行の中のコードが対象である。
柱とノンブルは文字スタイルで組まないので、背景を持たない。

背景のスウォッチは、golem preflight の使ったスウォッチ（`vwSwatchesUsed`）に加える。
総インキ量の検査（G0915）が、本文の中のコードの背景にも及ぶ。

### HTML と EPUB

`style.css` の `code` の規則（`code` を引き継ぐ文字スタイルは `cs-名前` の規則）に、次を書く。

```css
code {
  background-color: rgb(235, 235, 235);
  padding-inline: 0.25em;
}
```

- `background-color` は、解決した背景（書かなければ段落スタイル `code` の背景）のスウォッチの RGB の近似で書く。段落スタイル `code` の `background` と同じ変換である。背景がなければ書かない。
- `padding-inline` は、背景の有無によらず書く。
- `padding` は、行の方向（`padding-inline`）にだけ、`zw` を `em` にして書く。縦組みの本でも行の方向になるよう、`padding-inline` で書く。
- `box-decoration-break` は書かない。CSS の既定（`slice`）では、行をまたぐ要素の分かれた側に余白を付けないので、PDF と同じ形になる。
- 背景の行と直交する方向の範囲は、ブラウザーの行の内容の領域（フォントのアセンダーとディセンダー）で決まり、PDF の字面とは一致しない。
- 行と直交する方向の `padding` は書かない。ルビの注釈（`rt`）は親文字の内容の領域のすぐ外に置かれるので、上下に余白を足すと網がルビに重なりうる。

プレーンテキストは変えない。

### データ構造

- `Golem.Project.Style` の `CharStyleDef` に `csBackground :: Maybe (Maybe Text)` と `csPadding :: Maybe Dim` を加える。外の `Nothing` は書いていないこと（段落スタイル `code` の背景を使う）、`Just Nothing` は `false` である。解決した文字スタイルでは、段落スタイル `code` の背景を当てはめた `Maybe Text` になる。
- golem-layout の `Look` に `lkBackground` と `lkPadding` を、`BoxContent` に前と後の余白の幅を加える。
- `Golem.Driver.Pdf` の `PageDrawn` の `pdBackgrounds` に、本文の中のコードの背景のスウォッチを加える。

- docs/markup.md：「コード」の節に、`style.toml` で背景を付けられることを一文加える。

## 実装しないこと

- コードでない文字スタイルの背景（蛍光ペンのような網）。型は持つが、v1 では `code` の系統に限る。
- 背景の角を丸めること、枠を付けること。
- 行をまたいで分かれた側にも余白を付けること（CSS の `box-decoration-break: clone` にあたるもの）。
- 背景の網の濃淡（スウォッチの網の割合）。スウォッチの CMYK をそのまま使う。
- 背景を、行に直交する方向に字面より広く塗ること。ルビと圏点に重なるためである。
- 柱とノンブルの中のコードの背景。

## テスト設計

実装の前に書き、失敗することを確かめる。

### style.toml（`modules/golem-project/test/Main.hs`）

- `[character-styles.code] background = "code-bg"` を読むと、`csBackground` が `code-bg` になる。`padding` を書かなければ、解決した文字スタイルの余白が `0.25zw` になる。
- `[character-styles.code]` に `background` を書かず、`[paragraph-styles.code] background = "code-bg"` がある本で、解決した文字スタイル `code` の背景が `code-bg` になる。段落スタイルにも背景がなければ、背景がない。
- `background = false` で、段落スタイルの背景があっても背景がない。`background = true` が G0306 になる。
- `background` のない文字スタイル `code` に `padding = "0.5zw"` を書いても診断が出ない。
- `[character-styles.path] based-on = "code"` が、`code` の `background` を引き継ぐ。`path` に `background` を書いて上書きできる。
- `based-on` が `code` に行き着かない文字スタイル（`[character-styles.term]`）に `background` か `padding` を書くと G0306 になる。
- `background = "none-such"`（スウォッチにない）が G0313、`padding = "-1pt"` と `padding = "abc"` が G0306 になる。
- `@style-def character code background=code-bg` を読める。

### 組み方（`modules/golem-layout/test/Main.hs`）

測る関数には、テストの中で固定の値を返す関数を使う。

- 背景を持つ `[code: ab]` の最初の箱の幅が、`a` の送りに `padding` を足した値になり、最後の箱の幅が `b` の送りに `padding` を足した値になる。背景がなくても、同じ幅になる。
- コードの直前の漢字に、親文字より長いルビを振ると、読みはコードの側にかからず、親文字の字間が空く（今の `allowance` の振る舞いを余白つきの箱で保つ）。
- 和字と背景を持つコードのあいだの空き（和欧間の空き）が、背景のない場合と同じ量で、余白の外にある。
- 余白と最初の文字のあいだに改行の機会がない。

### PDF（`modules/golem-driver/test/Main.hs`）

- 横組みで `[code: manifest.toml]` に背景を付けると、その行の文字より前に、スウォッチの CMYK で塗った矩形が一つ描かれ、矩形の始まりが最初の箱の始まり、終わりが最後の箱の終わり、上下が行の字面の上端と下端に一致する。
- `[code: a b]` の中の空白も矩形に含まれる。
- 行末の `/` の後で分かれた `[code: modules/golem-driver/src]` が、二つの行に一つずつ矩形を持ち、前の行の矩形は余白なしで最後の箱の終わりで、次の行の矩形は余白なしで最初の箱の始まりで切れる。
- 縦組みで、矩形が行の中心線から左右に行の大きさの半分ずつ、天から地の方向に描かれる。
- 背景を持つコードにルビを振ると、ルビの字が矩形の外にあり、矩形より後に描かれる。
- 背景を持つコードの直前と直後の字にルビを振ると、読みのグリフの範囲が背景の矩形と交わらない。
- 背景を持つコードに圏点を付けると、圏点のグリフの範囲が背景の矩形と交わらない。
- 背景を持つコードの次の行にルビがあると、そのルビの読みのグリフの範囲が背景の矩形と交わらない。
- 脚注と表のセルの中のコードにも矩形が描かれる。
- 本文の中のコードを持たない本の PDF のバイト列が変わらないことを、既存の PDF のテストと決定性の検査で確かめる。コードを持つ本は余白で変わるので、既存のテストの期待値を余白の分だけ改める。
- golem preflight の見え方の `vwSwatchesUsed` に、背景のスウォッチが入る。

### HTML（`modules/golem-html/test/Main.hs`）

- 背景を持つ文字スタイル `code` の本の `style.css` の `code` の規則に、`background-color`（RGB の近似）と `padding-inline: 0.25em` が出る。
- `based-on = "code"` の文字スタイルに背景があれば、`cs-名前` の規則に同じ二つが出る。
- 背景のない本の `style.css` の `code` の規則に、`padding-inline` だけが出る。

### 自動テストにしない確かめ方

- 二つのマニュアルを組み、本文の中のコードのあるページを画像にして、網が字面の高さで塗られ、行をまたぐコードの分かれた側に余白がないこと、網が前後の字に重ならないこと、ルビ（「ルビ」の節の例）と圏点が網に重ならないことを目で確かめる。
- 縦組みの試料に `[code: ...]` を置いて組み、網が行の幅に収まり、隣の行に重ならないことを目で確かめる。
- HTML を Safari と Chrome で開き、行をまたぐ `<code>` の網の形を確かめる。

## トレードオフ

背景の既定を、段落スタイル `code` の背景にした（メンテナーの決定）。
コードブロックに網をかけた本では、本文の中のコードにも網がかかる。
本文の中のコードだけ網をなくしたい本は、`background = false` を書く。

余白を背景の有無によらず効かせた（メンテナーの決定）。
本文の中のコードを持つすべての本で、行の分け方が変わりうる。
背景がない本では、余白はコードの前後の空きとして見える。

余白を行の幅に入れた。
入れずに背景だけを外に広げると、行の分け方は変わらないが、網が前後の字に重なる。
とくに和欧間の空きが四分より狭い組み方では、網が隣の和字にかかる。

行と直交する方向の範囲を、行の字面に固定した。
字面より広く塗ると、字面のすぐ外に置くルビの読みと圏点に網が重なる。
行送りが字の大きさに近い版面では、上下の行の網が接するか重なる。
字面に固定すると、網の高さはどの行でも同じになり、行の格子が崩れない。
その代わり、欧文のディセンダー（`g`、`p`）とアクセントが網からはみ出すことがある。

行をまたぐコードの分かれた側に余白を付けないことにした。
CSS の既定（`slice`）と同じ形にして、PDF と HTML の網の形をそろえるためである。
分かれた側の網は字の端で切れるので、網の端が字に接して見える。

HTML と EPUB にも背景を付けたので、[ADR 0017](0017-pdf-code-blocks.md) が避けた媒体の差の一部が残る。
網の高さは、PDF では字面、HTML ではフォントの内容の領域で決まり、一致しない。
背景を付けるかどうかが媒体で違う差より、網の高さの差のほうが小さいと判断した。

キーを文字スタイル `code` の系統に限った。
コードでない文字スタイルにも同じ描き方を使えるが、蛍光ペンのような網は、字面の範囲と余白の既定が違う使い方になりうる。
必要になったら、制限を外す ADR で扱う。
