# ADR 0026: 章末の注

ステータス: 採択

## 文脈

`style.toml` の `[notes]` の `placement` は、`"page-foot"`（ページ下）と `"chapter-end"`（章末）の二つの値を読み込む。
しかし、どの出力も、この値で注の置き方を変えない。
[docs/roadmap.md](../../roadmap.md) の「章末の注」が、この欠けを v1 の課題にしている。
仕様書の「style.toml」の節も、`placement` は読み込むだけだと書いている。

### 今の振る舞い

コードで確かめた結果は次のとおりである。

- **golem-project**：`Golem.Project.Style` は `placement` を `enumKey "placement" ["page-foot", "chapter-end"]` で読み、`stNotesPlacement :: Text`（既定 `"page-foot"`）に入れる。読み手は、ほかのモジュールにない（`stNotesPlacement` を参照するのは `Style.hs` とそのテストだけである）。
- **PDF**：`Golem.Driver.Pdf` の `compose` は、段落の注の本文を `withNoteMark` で印を付けて組み、印を含む行の `slNotes` に持たせる。改ページ（`Golem.Layout.Paginate`）は、その行の `lbNotes` を見て、注の本文をページ（段）の下部に置く。`placement` によらず、注は常にページ下に組まれる。
- **HTML と EPUB**：`Golem.Html.page` は、XHTML の文書ごとに、文書の中のすべての注を `notesSection` で `<section class="notes">` にまとめ、文書の末尾に置く。XHTML の文書はソースファイル一つに一つなので、注はファイルの末尾に集まる。EPUB は同じ XHTML を包む。
- **プレーンテキスト**：`Golem.Text.file` は、ファイルごとの出力の末尾に、そのファイルの注を並べる。

つまり、HTML、EPUB、プレーンテキストは、`placement` によらず「ファイルの末尾」に注をまとめている。
仕様書の「脚注」の節は、HTML とプレーンテキストを「章末にまとめる」と書いている。
章を一つのファイルで書く本ではこの記述は正しいが、マニフェストの章を複数のファイルに分けた本（`chapters` の入れ子の配列）では、注は章の末尾ではなく各ファイルの末尾に出る。

### 章の単位

注の番号は、`[notes]` の `numbering` の範囲で振り直す（[ADR 0018](0018-footnote-marks-and-numbers.md)）。
既定の `"chapter"` の範囲は、マニフェストの `chapters` の一つの項目である。
章末の注を置く「章」も、同じ単位にするのが自然である。
番号を振り直す単位と注をまとめる単位がそろっていれば、章末の注の一覧の番号は 1 から順に並び、読み手は一覧の中で番号を探せる。

`numbering = "file"` の本で、一つの章が複数のファイルからなる場合は、章末の一覧の中で同じ番号が二度現れる。
`numbering = "book"` の本では、章末の一覧の番号が 1 から始まらないが、番号は一覧の中で重ならない。

### 注の印の大きさと書式

[ADR 0025](0025-note-mark-size-and-format.md)（提案）は、`[notes]` に `mark-size` と `mark-format` を加える。
`mark-size` は本文の印の大きさであり、`mark-format` は本文の印と注の本文の先頭の印の書式である。
章末の注でも、本文の印は脚注と同じ箱（`KindNoteMark`）で組めばよく、二つのキーの意味は変わらない。

### InDesign と組版の慣習

InDesign は、脚注と別に文末脚注の機能を持ち、文末脚注を記事の末尾かドキュメントの末尾に置き、見出しの文言を設定できる（記憶によるもので、資料では確かめていない）。
JLReq は、注を置く位置として、脚注、傍注、章末または節末の後注、巻末の後注を挙げる（節の番号と本文は確かめていない）。
章末の注には、「注」のような見出しを付け、本文の終わりから続けて組むことが多い。

### メンテナーが決めたこと

- HTML、EPUB、プレーンテキストは、注をファイルの末尾ではなく、章（マニフェストの章。複数のファイルからなることがある）の末尾にまとめる。仕様書の「章末にまとめる」という記述に、実装を合わせる。
- v1 では、章末の注の一覧の前で改ページしない。一覧の前で改ページする設定は v2 で加える。
- v1 では、一覧の見出しの文言を固定する（日本語の本は「注」、ほかは「Notes」）。文言の設定は v2 で加える。

## 実装すること

### 設定（golem-project）

`[notes]` にキーを加えない。
`placement` の二つの値は今のまま読む。

- `Style` の `stNotesPlacement` を `Text` から `NotesPlacement` に替える。

  ```haskell
  data NotesPlacement = PlaceFoot | PlaceChapterEnd
    deriving stock (Eq, Show)
  ```

### 一覧の見出しの文言

章末の注の一覧の見出しの文言は、マニフェストの `[metadata] language` が `ja` で始まれば「注」、そうでなければ「Notes」とする。
空の言語も「Notes」とする。
v1 では文言を変える設定を設けない（メンテナーの決定）。
PDF、HTML、EPUB、プレーンテキストのどれも、同じ規則で文言を決める。

### 章末の注を置く位置（golem-driver、PDF）

`placement = "chapter-end"` の本では、PDF の注を次のように組む。

- 注を含む行の `LineBox` の `lbNotes` を空にする。改ページは注の本文をページ下に置かず、区切りの領域も取らない。本文の印は、脚注のときと同じ箱（`KindNoteMark`）で組む。
- マニフェストの章ごとに、章の中の注を出現の順に集める。章の割り当ては、[ADR 0018](0018-footnote-marks-and-numbers.md) の `acChapterOf` を作るときと同じ規則（`chapters` の最上位の項目の番号を、`chapterFiles` の順で各ファイルに割り当てる）とする。マニフェストの章に属さないファイルは、それぞれが一つの章になる。今の `chapterOfFile` の規則のままである。
- 章の注の一覧を、章の最後のファイルの最後のブロックの後に置く。ただし、そのファイルの末尾に改ページの印（`ForcedBreak`、[docs/adr/0017](../../adr/0017-forced-page-breaks.md)）が続く場合は、一覧をその印の前に置く。ファイルの末尾の改ページは次のファイルの最初のものに効くので、一覧の後に残すと、改ページの意味が変わらない。
- 注のない章には、見出しも一覧も置かない。
- 一覧は本文の終わりから続けて組み、前で改ページしない。

注は、本文の段落のほか、見出し、図版のキャプション、表のセル、定義リスト、リストの項目の中にも書ける。
どこに書いた注も、文書の中の出現の順に一覧に並べる。
番号を振る範囲の規則（[ADR 0018](0018-footnote-marks-and-numbers.md)）により、`numbering` が `"chapter"` なら、一覧の番号は 1 から順に並ぶ。

### 一覧の組み方（golem-driver、PDF）

- **見出し**：「一覧の見出しの文言」の節の文言を、見出しと同じ規則（[ADR 0003](0003-pdf-heading-styles.md) の行取り）で、2 の階層の見出しの役割と大きさで組む。`[headings.2]` がなければ、2 の階層の見出しの既定（[ADR 0032](0032-default-heading-styles.md) を実装した後はその既定、実装する前は本文の役割と版面の文字の大きさ）を使う。番号を付けず、目次、柱の値、見出しの番号の数えには入れない。
- **注**：一つの注を一つの段落として組む。段落の先頭には、ページ下の脚注と同じく、`withNoteMark` で印と半角の空白を付ける。[ADR 0025](0025-note-mark-size-and-format.md) を実装した後は、印の文字列を `mark-format` で作る。注の本文の大きさ、書体、行長は、ページ下の脚注の本文と同じ（本文の役割、版面の文字の大きさ、段の行長）とする。二行目以降は、ページ下の脚注と同じく字下げしない。注と注のあいだに空きを入れない。
- **改ページ**：見出しは、ほかの見出しと同じく、続く段落の最初の行と離さない（`nextNeed`）。注の段落は、本文の段落と同じく、孤立行と泣き別れの規則（`placeLines`）でページをまたぐ。
- **区切り**：ページ下の脚注の区切りの領域と区切り線（[ADR 0024](0024-rule-spec-and-footnote-separator.md)）は使わない。

`Golem.Driver.Pdf` の `UnitKind` に、一覧の見出しの単位 `UNotesTitle` を加える。
`UHeading` を使わないのは、`UHeading` が柱の値と、目次のページ番号を引く見出しの表（`extras` の `hAcc`）に入るためである。
`UNotesTitle` は、行取り（`headingBlock` と `headAcc`）と G0724 の検査を `UHeading` と同じく通し、改ページの `Flow` では `FHeading`（`fhRecto` は偽）に写す。
`hAcc` と柱の値には入れない。

注の本文の中の索引の印は、一覧の行に置かれるので、索引のページ番号は一覧のページになる。
ページ下の脚注で、注の本文の索引の印のページを、印を含む本文の行のページにしている今の扱いとは異なるが、印が実際に置かれたページを指すので、こちらが正しい。

### 番号の範囲と章の不一致の警告

`numbering = "file"` で、二つ以上のファイルからなる章に、二つ以上のファイルの注があり、その章の注を章末にまとめる出力がある場合は、警告 G0327 を出す。
章末にまとめる出力は、`placement = "chapter-end"` の PDF と、`placement` によらず HTML、EPUB、プレーンテキストである。
ターゲットが PDF だけで `placement = "page-foot"` なら出さない。

| 診断コード | 重大度 | 条件 | メッセージ |
| --- | --- | --- | --- |
| G0327 | 警告 | 章末の注の一覧の中で、番号が重なる | `章末の注の番号が章の中で重なります（<章の最初のファイル>）。[notes] の numbering を "chapter" にしてください` |

警告の位置は、その章の二つ目のファイルの最初の注とする。
出力は止めず、重なった番号のまま組む。
G0327 は、03 の区分（プロジェクト）の最後に使った G0326 の次の番号である。
マニフェストと `style.toml` の組み合わせから決まる診断なので、03 の区分に置く。

### HTML、EPUB、プレーンテキスト

三つとも、`placement` によらず、注を章の末尾にまとめる（メンテナーの決定）。
ページを持たない媒体には、ページ下という置き場所がないためである。
章の単位と、章の中の注の順は、PDF の章末の注と同じである。

- **置く場所**：章の最後のファイルの出力（XHTML の文書、またはテキストのファイル）の末尾に、章のすべての注を置く。章のほかのファイルの末尾には、注を置かない。章が一つのファイルなら、今と同じ位置になる。
- **見出し**：一覧の前に、「一覧の見出しの文言」の節の文言を置く。HTML と EPUB では `<section class="notes">` の最初に `<h2>` で置き、目次とナビゲーション文書には入れない。プレーンテキストでは、注の並びの前に一行で置き、空の行で本文と隔てる。今の HTML とプレーンテキストは見出しを置かないので、注を持つすべての本の出力が変わる。
- **改ページ**：EPUB でも、一覧の前で改ページ（`break-before`）しない。

**HTML と EPUB のリンク**：本文の参照（`noteref`）と一覧の注（`footnote`）は、別の XHTML の文書に分かれうる。

- 本文の参照の `href` は、一覧を置いた文書への相対のリンク（`linkTo` と同じ形）にする。同じ文書なら今と同じ `#note-N` である。
- 一覧の注から本文の参照へ戻るリンクも、参照を置いた文書への相対のリンクにする。
- id は今と同じ `note-N` と `noteref-N` とする。ただし、`numbering = "file"` で番号が章の中で重なる場合（G0327）は、章の中のファイルの順番 k（1 から）を入れて `note-k-N` と `noteref-k-N` とし、その章のすべての注に使う。一つの文書の中で id が重ならないためである。

**プレーンテキスト**：注の印（`*1`、縦書きでは `※1`）は今のままとする。

### ドキュメント

- 仕様書の「style.toml」の節の `[notes]` の説明から「`placement` は読み込むが、どの出力も注の置き方を変えない」を消し、`placement` の二つの値が PDF にだけ効くことを書く。
- 仕様書の「脚注」の節に、PDF の章末の注の規則（章の単位、一覧の位置、見出しの文言、改ページ、区切り線を使わないこと）を書く。HTML、EPUB、プレーンテキストが章の最後のファイルの末尾に章の注をまとめること、見出しを置くこと、文書をまたぐリンクを書く。
- [docs/diagnostics.md](../../diagnostics.md) に G0327 の節を加える。
- [docs/roadmap.md](../../roadmap.md) の「章末の注」の項目を消す。
- [docs/roadmap.md](../../roadmap.md) の「v2 以降に回した事項」に、「章末の注の拡張」として、一覧の前で改ページする設定と、一覧の見出しの文言の設定を加え、この ADR へのリンクを付ける。
- 使い手のマニュアルの `manual/chapters/05-style.gm` の「注と図の設定」の節と、`manual/appendices/c-style.gm` の `[notes]` の節に、`placement` の意味と、見出しの文言が固定であることを書く。`manual/appendices/e-errors.gm` に G0327 を加える。`manual/appendices/h-roadmap.gm` から章末の注を消す。
- [ADR 0018](0018-footnote-marks-and-numbers.md) のステータスの行に、「実装しないこと」に置いた `placement = "chapter-end"` をこの ADR で扱ったことを、この ADR へのリンクで書き足す。

## データ構造

- golem-project：`NotesPlacement` を新設し、`Style` の `stNotesPlacement` の型を替える。
- golem-html と golem-text：章ごとの注を集める関数を置き、ファイルと章の対応（`chapterFiles`）を受け取る。HTML の `notesSection` は、文書の注ではなく、その文書で終わる章の注を受け取る。
- golem-driver：`UnitKind` に `UNotesTitle` を加える。
- golem-layout：変えない。章末の注の一覧は、`FHeading` と `FParagraph` だけで表せる。

## 実装しないこと

- 巻末の注（本の最後にまとめる後注）と、節末の注。`placement` の値を増やせば表せるが、今回は章末だけにする。
- 一覧の前の改ページと改丁。v2 で、一覧の前で改ページする設定を加える予定である（メンテナーの決定）。
- 一覧の見出しの文言の設定。v2 で加える予定である（メンテナーの決定）。v1 の文言は言語で決まる「注」か「Notes」に固定する。
- 一覧の段組み。
- 注の一覧の段落の字下げ（二行目以降を印の後ろにそろえる形）と、一覧の文字の大きさの設定。ページ下の脚注にもない設定であり、[ADR 0018](0018-footnote-marks-and-numbers.md) の「実装しないこと」のまま残す。
- 本文の印と一覧の注のあいだの PDF のリンク（`/Link` の注釈）。ページ下の脚注にもまだない。
- HTML、EPUB、プレーンテキストで、`placement` によって注の置き方を変えること。三つとも常に章末にまとめる。
- 見出しごと（ページ下か章末か）に、注の置き方を混ぜること。
- 傍注の置き方の変更。傍注は `placement` によらず今のまま組む。

## テスト設計

実装の前に書き、失敗することを確かめる。

### style.toml（`modules/golem-project/test/Main.hs`）

- `[notes]` がないとき、`stNotesPlacement` が `PlaceFoot` である。
- `placement = "chapter-end"` が `PlaceChapterEnd` になる。
- `chapter-end-title` のような未知のキーは、今と同じく G0306 になる。

### PDF（`modules/golem-driver/test/Main.hs` または `PdfSpec.hs`）

テストのフォントと `horizontalStyle` の版面を使う。

- 注を二つ持つ一つのファイルの本を `placement = "chapter-end"` で組むと、どのページにも脚注の行がなく、本文の最後の行の後に「注」の見出しと、`*1 ` と `*2 ` で始まる二つの段落がある。同じ本を `"page-foot"` で組むと、今と同じ PDF になる（バイト列で比べる）。
- 二つの章（章ごとに一つのファイル）にそれぞれ注がある本で、一つ目の章の一覧が二つ目の章の見出しより前にあり、二つ目の章の一覧の番号が 1 から始まる。
- 一つの章を二つのファイルに分けた本（`chapters` の入れ子の配列）で、一覧が二つ目のファイルの末尾にだけあり、一つ目のファイルの末尾にない。
- 章の最後のファイルが `@page-break` で終わる本で、一覧が改ページの前（同じページ）にあり、次の章が改ページの後のページから始まる。
- 注のない章に、一覧の見出しがない。
- マニフェストの言語が `ja` の本で見出しが「注」、`en` の本と言語のない本で「Notes」になる。
- 一覧の見出しが、目次（`@toc`）と柱の値に現れない。2 の階層の見出しの番号が、一覧の見出しで進まない。
- `[headings.2] size` を版面の文字より大きくした本で、一覧の見出しがその大きさで組まれる。
- 一覧がページをまたぐ本（版面の行数を少なくし、注を多く書く）で、見出しがページの末尾に一人で残らず、注の段落が孤立行の規則でページをまたぐ。
- 注の本文に索引の印を置いた本で、索引のページ番号が一覧のページになる。
- `[notes.rule]` を書いても、区切り線が描かれない（今の仕様のまま）。
- 二回のビルドと、並列と逐次の行分割で、PDF のバイト列が一致する。

### 診断（`modules/golem-driver/test/Main.hs`）

- `placement = "chapter-end"`、`numbering = "file"` で、二つのファイルからなる章の両方に注がある本が G0327 の警告になり、PDF は出力される。
- 同じ本で `numbering = "chapter"` または `"book"` なら G0327 が出ない。
- 同じ本で `placement = "page-foot"` の場合、ターゲットが PDF だけなら出ず、HTML かプレーンテキストを含めば出る。
- 診断の文書の検査（コードがすべて載っていること）が、G0327 の節を加えた後に通る。

### HTML、EPUB、プレーンテキスト（`modules/golem-html/test/Main.hs`、`modules/golem-epub/test/Main.hs`、`modules/golem-text/test/Main.hs`）

- `placement = "chapter-end"` と `"page-foot"` で、HTML、EPUB、プレーンテキストの出力がバイト列で一致する。
- 一つの章を二つのファイルに分けた本で、一つ目のファイルの出力に注の一覧がなく、二つ目のファイルの出力の末尾に、二つのファイルの注が出現の順に並ぶ。
- 同じ本の HTML で、一つ目のファイルの本文の参照の `href` が、二つ目のファイルの文書の `#note-N` への相対のリンクであり、一覧の注から一つ目の文書の `#noteref-N` へ戻るリンクがある。
- 一覧の前に、言語が `ja` なら「注」、`en` なら「Notes」の見出しがある。HTML では `<section class="notes">` の最初の `<h2>` であり、EPUB のナビゲーション文書に入らない。
- `numbering = "file"` で同じ本を組むと、id が `note-1-1`、`note-2-1` のように重ならない。
- 章が一つのファイルの本では、注の位置は今と同じで、見出しが増えたことだけが違う。
- EPUB を epubcheck にかけ、文書をまたぐ `noteref` のリンクで誤りが出ない。

### 自動テストにしない確かめ方

- `manual/` の `style.toml` を一時的に `placement = "chapter-end"` にして組み、付録の注が章の末尾の一覧になり、本文の印と一覧の番号が対応することを目で確かめる。マニュアルの設定は変えない。
- 複数のファイルからなる章を持つ試料の EPUB を Apple Books と Kindle Previewer で開き、文書をまたぐ注の参照からポップアップか移動で注を開けることを確かめる。

## トレードオフ

章の単位をマニフェストの章にしたので、見出し 1 の位置で注をまとめることはできない。
一つのファイルに複数の章（見出し 1）を書く本では、ファイルの末尾に、ファイルの中のすべての章の注がまとまる。
注の番号の範囲（[ADR 0018](0018-footnote-marks-and-numbers.md)）がマニフェストの章を単位にしており、二つの単位をそろえることを優先した。

`numbering = "file"` と章末の注の組み合わせは、番号の重なる一覧を作りうるが、エラーにせず警告にとどめた。
重なった番号でも、一覧の順と本文の順は一致するので、読めないわけではない。

HTML、EPUB、プレーンテキストは `placement` によらず章末にまとめるので、`placement` は PDF でだけ効く設定になる。
章の最後のファイルにまとめると、本文の参照と注が別の XHTML の文書に分かれうる。
EPUB の脚注のポップアップは、リーダーによっては文書をまたぐ参照で開かず、注の文書への移動になる可能性がある（どのリーダーがそうなるかは確かめていない）。
注をファイルの末尾に置けば参照と注は同じ文書にそろうが、同じ章の注の一覧が章の途中に何度も現れ、PDF の章末の注とも形が違う。
章を単位にそろえることを、文書をまたがないことより優先した（メンテナーの決定）。

一覧に見出しを置くので、注を持つすべての本の HTML、EPUB、プレーンテキストの出力が変わる。
見出しがないと、章の最後の段落と注の一覧の境目が、テキストでは見分けにくい。

v1 では一覧の見出しの文言と、一覧の前の改ページを設定できない。
どちらも v2 で加える予定であり、それまでは言語で決まる文言と、本文から続けて組む形だけになる。

一覧の見出しを 2 の階層の見出しの設定で組むので、一覧の見出しの書体と大きさを独立に決めることはできない。
