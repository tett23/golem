# ADR 0021: 隠しノンブル

ステータス: 採択→（数字の列の幅と、仕上がりの線を越える誤りの G0306 から G0329 への分離）は [ADR 0041](0041-hidden-folio-overlap-check-by-size.md)

## 文脈

ノンブルの見えないページが何ページも続く本は、印刷所と製本所にとって扱いにくい。
刷った紙を折り、丁合いを取り、綴じる工程で、ページの順を確かめる手がかりがないからである。
仕様書の「v1 の実装で次の段階以降に回した項目」の「隠しノンブル」は、この問題を挙げ、入れる位置、大きさ、書体、入れるページ、切り替え、トンボのない PDF での扱いを ADR で決めるとしている。

今の PDF でノンブルを描く処理を、コードで確かめると次のとおりである。

- `Golem.Driver.Pdf` の `writeDocument` の中の `drawPage` は、白ページ（`poBlank`）でなければ `masterMarks` を呼ぶ。
- `masterMarks` は、そのページのマスターページ（`pageMasters` が [golem-driver ADR 0014](0014-running-heads.md) の規則で選ぶ）が `mgFolio` を持てば、ページの通し番号（`poNumber`）を `formatNumber` で書式に当てはめ、`textAt` で本文の役割と版面の文字の大きさで描く。
- マスターページがない場合と、マスターページに `folio` がない場合は、ノンブルを描かない。
- トンボは `PdfInput` の `piMarks :: Maybe P.MarkStyle` で決まり、`P.framePage` がページの外側に描く（[golem-pdf ADR 0004](../../golem-pdf/adr/0004-crop-marks-and-bleed.md)）。`--marks none` のとき `piMarks` は `Nothing` である。

つまり、白ページ、`folio` のないマスターページを当てた前付けのページ、マスターページを一つも定義しない本のすべてのページには、ノンブルが何も入らない。
章扉の前後に白ページを置く和文の書籍では、ノンブルのないページが二ページ以上続くことは珍しくない。

隠しノンブルの慣用を、国内の印刷所の入稿の案内で確かめた。
どれも同人誌の印刷所の資料であり、商業出版の印刷所の社内の基準は確かめられていない。

- 株式会社栄光は、仕上がりのノドの側の位置から内側 3mm 以内に入れると、製本で綴じ込まれて見えなくなるとし、無線綴じの本で隠しノンブルを勧めている。
- 大陽出版は、ノドの側の断ち切りの線に沿って、断ち切りの線より内側に入れ、塗り足しの部分には入れないこととしている。二桁以上の数字は縦に並べるのが望ましく、5pt 未満のような小さすぎる文字と、薄い灰色の文字は避けるよう求めている。黒ベタの上では白い文字か白い縁を使うよう求めている。
- プリンティングインの PICO は、ノドの側の仕上がりの位置のぎりぎりに入れ、10 ページ目からは縦組みにすると目立たないとしている。
- CLIP STUDIO PAINT の解説は、入稿先が一般に一字 2mm 以上の大きさを求めるとし、同ソフトの隠しノンブルの機能は 6pt（約 2.12mm）に固定されているとしている。ノドの側のおよそ 3mm は糊で完全に隠れるとも書いている。

天地の位置を数値で示した資料は見つからなかった。
無線綴じでは背の全体に糊が入るので、ノドの側の線に沿っていれば、天地のどこに置いても隠れる。
中綴じの本では見開きの中央にノドが見えるので、隠しノンブルは隠れない。
InDesign には隠しノンブルの専用の機能がなく、利用者がマスターページにページ番号のテキストフレームを置いて作る（記憶による。Adobe の資料では確かめていない）。

## 実装すること

### いつ入れるか

隠しノンブルは、入稿用の PDF にだけ入れる。
PDF にトンボを付けるとき（`golem build --marks japanese` と `--marks western`）に入れ、`--marks none`（既定）では入れない。

トンボのない PDF は、画面で読むための PDF として使われる。
隠しノンブルは仕上がりの線の内側にあるので、トンボのない PDF に入れると、閲覧の画面ではノドの側に小さな数字として見えてしまう。
トンボの有無はすでに出力を変える CLI のオプションであり、インスタンス ID の入力に入っているので、隠しノンブルの有無をこれに結び付けても決定性は崩れない。

`style.toml` に `[hidden-folio]` の表を加え、トンボを付けた PDF でも止められるようにする。

```toml
[hidden-folio]
enabled = true          # 既定 true。中綴じの本では false にする
pages = "unnumbered"    # 既定。"all" ですべてのページ
size = "6pt"            # 既定
gutter = "1.5mm"        # 既定。ノドの仕上がりの線から数字の列の中心線まで
```

| キー | 型 | 既定 | 意味 |
| --- | --- | --- | --- |
| `enabled` | 真偽値 | `true` | トンボを付けた PDF に隠しノンブルを入れるか |
| `pages` | `"unnumbered"` か `"all"` | `"unnumbered"` | 入れるページ |
| `size` | 寸法（`mm`、`pt`、`Q`、`H`） | `"6pt"` | 数字の大きさ |
| `gutter` | 寸法（`mm`、`pt`、`Q`、`H`） | `"1.5mm"` | ノドの仕上がりの線から、数字の列の中心線までの距離 |

`[hidden-folio]` を書かない本は、すべてのキーが既定の値になる。
つまり、トンボを付けた PDF には、何も書かなくても隠しノンブルが入る。
入稿先が隠しノンブルを求めない場合と、中綴じの本の場合は、`enabled = false` を書く。

`size` と `gutter` は判型と同じく文字の大きさに依存しない長さなので、`zw` で書くとエラー（G0306）とする。
0 以下の値、寸法として読めない値、未知のキー、`pages` の表にない値も G0306 とする。

### 入れるページ

`pages = "unnumbered"` では、ノンブルを描かないページに入れる。
ノンブルを描かないページとは、次のどれかである。

- 白ページ。
- マスターページがないページ（マスターページを一つも定義しない本のすべてのページ）。
- マスターページが `folio` を持たないページ。

`pages = "all"` では、すべてのページに入れる。
すべてのページに入れるよう求める入稿先があるためである。

判定は、`masterMarks` がノンブルを描くかどうかと同じ条件で行う。
今後ノンブルを描かないページの条件が増えたときに、隠しノンブルの条件が取り残されないよう、ノンブルを描くかどうかを一つの関数にまとめ、`masterMarks` とこの判定の両方がそれを使う。

### 位置と形

数字は、ページの通し番号（`poNumber`）を算用数字（ASCII の `0` から `9`）で書いたものとする。
ノンブルの書式（`folio` の `format`）は使わない。
印刷所が確かめるのは物理的なページの順であり、ローマ数字や漢数字では読み違えるおそれがあるからである。
縦組みの本でも算用数字とする。

数字は、二桁以上でも一字ずつ天から地へ縦に並べる。
各字は正立させ、字の送りは `size` とする。
縦に並べると列の幅が一字分に収まり、桁数が増えてもノドからはみ出さないためである（大陽出版と PICO の案内に合わせる）。

列の位置は次のとおりとする。

- 左右：ノドの側の仕上がりの線から `gutter` の距離に、列の中心線を置く。ノドの側は、綴じの方向とページの偶奇から `gutterSide` で決める。各字は、字の送りの幅をこの中心線にそろえて置く。
- 天地：列の全体（字の数 × `size`）の中央を、仕上がりの判型の高さの中央にそろえる。

既定の 6pt と 1.5mm では、算用数字の字の幅（多くの欧文の書体で 0.5em から 0.6em）はおよそ 1.1mm から 1.3mm なので、列はノドの仕上がりの線から 0.9mm 前後から 2.1mm 前後までに収まる。
栄光の案内の「内側 3mm 以内」と、CLIP STUDIO PAINT の解説の「ノドの側のおよそ 3mm は糊で隠れる」の両方に収まる。
仕上がりの線に接しない余地を残すのは、断裁のずれで数字が切れないためである。
天地の中央に置くのは、どの資料も天地の位置を定めておらず、天と地の断裁と、柱やノンブルから最も遠い位置だからである。

書体は本文の役割の欧文のフォントとし、欧文のフォントがなければ和文のフォントとする。
色は本文の文字と同じ黒とする。
黒ベタの上で白抜きにする処理は行わない。

隠しノンブルは、ページのほかのもの（本文、図版、罫、柱、ノンブル）の後に描く。
全面の図版のページでも、数字が図版に隠れないためである。

### 版面との重なり

列の左右の範囲（中心線から字の送りの幅の半分ずつ）が、そのページの版面か傍注欄に、左右の方向で重なる場合はエラー（G0750）とする。
ノドの余白が数ミリしかない判型の設定は、隠しノンブルが本文に重なるか、本文がノドに綴じ込まれる設定であり、どちらにしても入稿できないからである。
この検査は、`[hidden-folio]` の値と版面の寸法だけで決まるので、`Golem.LayoutSpec.pageGeometry` で行い、位置は `style.toml` の先頭とする。
`enabled = false` の場合と、トンボを付けない PDF の場合は検査しない。
`golem check` では、`--marks` に `japanese` か `western` を渡したときだけ検査する。

列の左右の範囲がノドの仕上がりの線を越える場合（`gutter` が字の送りの半分より小さい場合）は、`style.toml` を読むときに G0306 とする。
字の送りは書体で決まるので、読み込みの段階では `size` の半分を字の送りの半分と見なして検査する。

| 診断コード | 重大度 | 段階 | メッセージ |
| --- | --- | --- | --- |
| G0750 | エラー | レイアウト | `隠しノンブルが版面に重なります。[hidden-folio] の gutter を小さくするか、ノドの余白を広げてください` |

G0750 は未使用である（[golem-syntax ADR 0002](../../golem-syntax/adr/0002-notice-severity.md) と [ADR 0017](0017-pdf-code-blocks.md) が予約した番号とも重ならない）。

### HTML、EPUB、プレーンテキスト

ページを持たない媒体なので、隠しノンブルを出さない。
`[hidden-folio]` を読み飛ばす。

### 決定性

隠しノンブルの有無と位置は、`style.toml`、`--marks`、収束した最終回のページの列だけで決まる。
隠しノンブルは行の格子の外に描き、改ページに影響しない。

- 同じく「style.toml」の節に `[hidden-folio]` の四つのキー、入れるページ、位置と形、G0750 を書き、この ADR へリンクする。CLI の節の `--marks` の説明に、トンボを付けた PDF に隠しノンブルが入ることを書く。
- docs/glossary.md に「隠しノンブル」を加える。
- docs/diagnostics.md に G0750 の節を足す。
- 利用者のマニュアル（`manual/`）に、隠しノンブルが入ること、中綴じの本では `enabled = false` にすることを書く（[docs/adr/0024](../../adr/0024-manual-audiences-and-policy.md)）。説明は `manual/chapters/06-output.gm` の「塗り足しとトンボ」の節（ラベル `print-pdf`）の、入稿用の PDF を作る手順の前に置き、設定のキーは `manual/appendices/c-style.gm` に節を加えて書く。`manual/chapters/05-style.gm` の「柱とノンブル」の節から、その説明へ参照を張る。

## データ構造の変更

```haskell
-- golem-project
data HiddenFolioPages = HiddenUnnumbered | HiddenAll

data HiddenFolio = HiddenFolio
  { hfEnabled :: !Bool,
    hfPages :: !HiddenFolioPages,
    hfSize :: !Dim,
    hfGutter :: !Dim
  }

-- Style に加える
stHiddenFolio :: !HiddenFolio

-- golem-layout-spec：PageGeometry に加える
pgHiddenFolio :: !(Maybe HiddenFolioGeometry)

data HiddenFolioGeometry = HiddenFolioGeometry
  { hgSize :: !Sp,
    hgGutter :: !Sp,
    hgAll :: !Bool
  }
```

`pageGeometry` は、`hfEnabled` が真でトンボを付けるときだけ `pgHiddenFolio` を `Just` にする。
トンボの有無を `pageGeometry` に渡すため、引数に `Bool` を一つ足す。

golem-driver に、テストのための純粋な関数を置く。

```haskell
-- | ページの番号から、隠しノンブルの各字の文字と描く位置（字の送りの箱の中心）へ
hiddenFolios :: PdfInput -> PageGeometry -> PdfLayout -> Map Int [(Char, (Sp, Sp))]

-- | ノンブルを描くページか（masterMarks と hiddenFolios が共有する）
drawsFolio :: Bool -> Maybe MasterGeometry -> Bool
```

意味論 IR とプラグインの ABI は変えない。

## 実装しないこと

- 中綴じの本で、隠しノンブルの代わりにノドの外の位置へノンブルを入れること。製本の方式を `style.toml` に持たないので、利用者が `enabled = false` にする。
- 天地の位置、字の向き（横に並べる）、書体、色を変える設定。入稿先の求めとして天地の中央と縦の並びで足りない例が見つかったら、新しい ADR で足す。
- 黒ベタや濃い図版の上で、数字を白抜きにすることと、白い縁を付けること。図版の色を読まずに判定できないためである。
- 隠しノンブルにノンブルの書式を使うこと。
- 面付けした PDF での隠しノンブル（仕様書の「面付け」とともに v2 以降）。
- 縦組みの本の中の横組みの部分（仕様書の「縦組みの本の中の横組みの部分」）での数え方。その ADR で決める。

## テスト設計

先に書き、失敗させてから実装する。

### golem-project（`modules/golem-project/test/Main.hs`）

- `[hidden-folio]` を書かない `style.toml` で、`stHiddenFolio` が `enabled = true`、`pages = "unnumbered"`、`size = 6pt`、`gutter = 1.5mm` になること。
- `enabled = false`、`pages = "all"`、`size = "8Q"`、`gutter = "2mm"` が読めること。
- `size = "1zw"`、`gutter = "-1mm"`、`size = "0pt"`、`pages = "blank"`、未知のキー `font` が、それぞれ G0306 になること。
- `size = "6pt"`、`gutter = "1mm"`（字の送りの半分 3pt ≒ 1.06mm を下回る）が G0306 になること。

### golem-layout-spec（`modules/golem-layout-spec/test/Main.hs`）

- ノドの余白が 1.5mm しかない版面で、トンボありのとき G0750 になり、トンボなしと `enabled = false` のときは G0750 にならないこと。
- ノドの余白が 15mm の版面で G0750 にならないこと。

### golem-driver（`modules/golem-driver/test/Main.hs`）

`hiddenFolios` の表で確かめる。
フォントは `fakeFonts`（字の送りが分かっているもの）を使う。

- トンボありで、白ページを含む本を組むと、白ページの番号にだけ表の値があり、ノンブルを描くページにはないこと。
- トンボなし（`piMarks = Nothing`）では、表が空になること。
- `enabled = false` では、トンボありでも表が空になること。
- `pages = "all"` では、すべてのページに値があること。
- マスターページを定義しない本では、すべてのページに値があること。前付けのファイルに `folio` のない `master` を当てると、そのページに値があること。
- 左綴じの本の奇数ページでは列の中心の x が `gutter`（仕上がりの判型の左端から）、偶数ページでは判型の幅から `gutter` を引いた値になること。右綴じの本では左右が逆になること。
- 123 ページ目の値が、`'1'`、`'2'`、`'3'` の三字で、y が `size` ずつ下がり、三字の中央が判型の高さの中央にあること。
- 塗り足しがあり、トンボを付けたとき、位置が仕上がりの判型（TrimBox）に対して決まること。PDF の内容のストリームの座標では、塗り足しとトンボの分だけ移っていること。
- PDF の内容のストリームで、隠しノンブルの字が、同じページの図版の描画より後にあること。
- 隠しノンブルの有無だけが違う二つの PDF で、`plPages` が一致すること。
- トンボありの PDF を並列と逐次で組み、バイト列が一致すること。
- `scripts/determinism.sh` の出力のうち、トンボを付けない PDF のハッシュが変わらないこと。

### 自動テストにしない確かめ方

実装の後に、白ページと章扉を含む和文の縦組みの本と、欧文の横組みの本を `--marks japanese` で組み、Acrobat で開いて、次を目で確かめる。

- 白ページのノドの側の天地の中央に、縦に並んだ小さな数字があり、トンボの仕上がりの線の内側 3mm 以内に収まっていること。
- 数字がノドの側にあり、小口の側にないこと（奇数ページと偶数ページの両方）。
- 出力プレビューで、数字が墨の版だけに出ていること。

確かめた結果は、実装のプルリクエストのコメントに書く。

## トレードオフ

隠しノンブルを既定で入れるので、中綴じの本をトンボ付きで入稿する利用者は、`enabled = false` を書き忘れると見える位置に数字が出る。
既定を入れない側にすると、無線綴じの本で白ページが続くときに、利用者が設定を知らないまま入稿し、印刷所から問い合わせを受けることになる。
国内の書籍は無線綴じが多いので、無線綴じを既定の前提にした。

トンボの有無に結び付けるので、トンボを付けずに入稿する印刷所（仕上がりの判型と塗り足しだけの PDF を求める入稿先）では、隠しノンブルが入らない。
`--marks none` に塗り足しだけを付けた PDF を入稿に使う流れもあるので、この点は利用者の声を待って見直す。
`style.toml` から「トンボがなくても入れる」を選べるようにすると、閲覧用と入稿用を同じ `style.toml` から作り分けられなくなる。

位置と大きさの既定は、同人誌の印刷所の案内から決めた。
商業出版の印刷所の基準は確かめていないので、`size` と `gutter` を変えられるようにした。
天地の位置を中央に固定したのは、資料が天地の位置を定めていないからであり、慣用に反する根拠が見つかれば新しい ADR で変える。
