# ADR 0036: 結合文字を前の字と一つの箱に組む

ステータス: 採択

## 文脈

仕様書の「既知の不具合」に「結合文字」がある。
U+0301 COMBINING ACUTE ACCENT のような結合文字を、前の字と一つにせず、別の箱として組む不具合である。
[docs/roadmap.md](../../roadmap.md) の「既知の不具合の修正」は、HarfBuzz のクラスタの単位で箱を作り、文字のクラスをクラスタの先頭の字で決める直し方を案として挙げ、[ADR 0030](0030-ligature-text-layer.md) と同じくクラスタの単位で扱うとしている。

### 再現

今の `main` から作った golem（a2b6106e）で、本文の和文に Noto Serif JP、欧文に Source Serif 4 を使う横組みの小さなプロジェクトを作り、次の段落を組んだ。

```
Precomposed: café naïve résumé.

Combining: cafe◌́ nai◌̈ve re◌́sume◌́.

和文の中の cafe◌́ と、か◌゙（結合濁点）と、が。
```

`◌́` は U+0301、`◌̈` は U+0308、`◌゙` は U+3099 COMBINING KATAKANA-HIRAGANA VOICED SOUND MARK を表す。
PDF の内容のストリームを読むと、二段落めは次のように組まれていた。

- `cafe` は Source Serif 4 で組まれ、U+0301 は和文のフォント（Noto Serif JP）のグリフとして、`e` の送りの後に、さらに空きを置いて描かれた。PNG に描くと、アクセントは `e` の上に載らず、`e` と次の語のあいだに浮く。
- U+0308 は、Noto Serif JP にグリフがないので .notdef（グリフ ID 0）になり、送りが 1.25 字分ある箱として描かれた。`nai` と `ve` のあいだに大きな隙間が空く。

三段落めの `か◌゙` は、見た目のうえでは「が」に近く組まれたが、これは和文のペアカーニング（[docs/adr/0020](../../adr/0020-indesign-character-features.md)）が二字を別の箱として詰めた偶然の結果である。

### 原因

原因は二箇所にある。

一つめは、行分割の前に原稿の文字を箱に分ける golem-layout である。
`Golem.Layout.Japanese` の `textPieces` は、欧文の語の文字（`charClass` が `Western` で空白でない字）の並びを一つの語（`PWord`）にし、それ以外の字を一字ずつの箱（`PChar`）にする。
前の字に付ける例外は異体字セレクタ（`isVariationSelector`、[golem-pdf ADR 0006](../../golem-pdf/adr/0006-cid-system-info.md)）だけである。
`Golem.Layout.CharClass` の `charClass` は、ASCII、U+00A0 から U+024F、U+0370 から U+04FF を欧文とし、U+0300 から U+036F の結合文字を漢字等（`Ideograph`）に分類する。
その結果、`cafe◌́` は、欧文の語 `cafe` と、漢字等の一字 `◌́` の二つの箱になる。
二つの箱のあいだには、欧文と和文のあいだの空き（既定のアキ量のセットでは四分アキ、[docs/adr/0019](../../adr/0019-aki-settings.md)）と改行の位置が入り、分綴のパターンも `cafe` だけにかかる。

二つめは、箱の文字を描くときに書体を選ぶ golem-driver である。
`Golem.Driver.Fonts` の `runs` と `Golem.Driver.Pdf` の `runsOf` は、文字ごとに欧文か和文かで書体を選び、書体が変わる位置でランを分ける。
異体字セレクタだけは前の字のランに残すが、結合文字は欧文のクラスでないので和文の書体のランになる。
HarfBuzz は、結合文字を前の字と別のランで受け取るので、前の字の上に置く位置決め（GPOS の mark）も、合成済みの字への置き換えもできない。

### クラスタの単位

HarfBuzz は、既定のクラスタの単位（`HB_BUFFER_CLUSTER_LEVEL_MONOTONE_GRAPHEMES`）で、結合文字を前の基底の字と同じクラスタにまとめる。
Golem はクラスタの単位を指定していないので、この既定で組んでいる。
ただし、golem-layout は行分割の前に箱を作り、シェイピングの結果を知らない（グリフの送りは関数で受け取る）。
HarfBuzz のクラスタを箱の単位にするには、箱を作る前に段落の全体をシェイピングする必要があり、行分割と描画の分担（[ADR 0002](0002-pdf-pipeline.md)）を変えることになる。

HarfBuzz の既定のクラスタの単位は、基底の字と、それに続く結合文字（一般カテゴリーが Mn、Mc、Me の字）をまとめる。
golem-layout が同じ規則で文字をまとめれば、箱の単位と HarfBuzz のクラスタは、結合文字については一致する。
異体字セレクタは一般カテゴリーが Mn なので、今の異体字セレクタの扱いは、この規則の特別な場合になる。

### メンテナーが決めたこと

- v1 で組む言語は日本語と欧文に限る。v2 では、より多くの言語を扱う。箱の単位と書記素クラスタが一致しない場合は、v2 の項目として扱う。

## 実装すること

### 結合文字の判定（golem-layout）

`Golem.Layout.CharClass` に、前の字と一つにまとめる字の判定を加える。

```haskell
-- | 前の字と一つの箱にまとめる字：一般カテゴリーが Mn、Mc、Me の字
-- （結合文字。異体字セレクタを含む。golem-driver ADR 0036）
isExtending :: Char -> Bool
isExtending c = generalCategory c `elem` [NonSpacingMark, SpacingCombiningMark, EnclosingMark]
```

- 基底の字一つと、それに続く `isExtending` の字の並びを、この ADR では「字のまとまり」と呼ぶ。字のまとまりの文字のクラスは、基底の字のクラスとする。
- 段落の始まり、空白の後、改行の後など、前に基底の字がない結合文字は、それだけで一つの字のまとまりとし、クラスは今のとおりその字の `charClass` で決める。
- ZWJ（U+200D）、ZWNJ（U+200C）、絵文字の修飾子のように Mn、Mc、Me でない字は、この ADR では扱わない。今のとおり一字ずつの箱になる。

### 箱の作り方（golem-layout）

`Golem.Layout.Japanese` で、異体字セレクタを前の字に付けていた処理を、字のまとまりの単位に広げる。

- `textPieces` は、原稿の文字列を字のまとまりに分けてから、欧文の語と和文の字を分ける。欧文の語に入るかどうか（`latinish`）は、字のまとまりの基底の字で決める。`cafe◌́` は一つの `PWord`（文字列 `cafe◌́`）になり、`か◌゙` は一つの `PChar`（基底の字 `か`、後に付く文字列 `◌゙`）になる。
- `PChar` の三つめの欄は、異体字セレクタに限らず、基底の字に続く字のまとまりの残り全体とする。`itemsFor` は今のとおり、この欄が空でなければ、字のまとまりの全体を `ceWordAdvance` で一度にシェイピングした送りを箱の幅にする。
- `withoutSelectors` は、文字のクラスを決めるために末尾の結合文字を除く関数として、`isExtending` で判定する。名前は `baseText` に改める。`normalize` の前後の字のクラス、`kernPairs` の一字の判定は、この関数を通した文字で行う。
- `codeItems` の `sameSide` と `codePieces` は、`isExtending` の字を前の字の側に付ける。コードの中の結合文字も前の字から離れない。
- ルビの親文字（`baseChars`、`baseAdvances`）は、字のまとまりを一つの親文字として数える。モノルビは字のまとまりのあいだで分け、結合文字だけを親文字にしない。
- 圏点（`takesKenten`）は、字のまとまりの基底の字で判定し、字のまとまりに一つだけ付ける。

### 欧文の語の分綴（golem-layout）

`wordItems` の分綴は、語から結合文字を除いた文字列にパターンをかけ、得た位置を元の語の字のまとまりの境に写す。

- パターンの分綴の位置は、「その位置より前の基底の字の数」で表す。元の語では、その数の基底の字と、それぞれに続く結合文字の後で分ける。
- 明示したハイフンで分ける処理（`explicitParts`）は、今のとおりハイフンの字の並びで分ける。ハイフンに続く結合文字は、ハイフンの側に残す。
- どの分け方でも、箱が結合文字で始まることはない。

### 書体の選び方（golem-driver）

- `Golem.Driver.Fonts` の `runs` と `Golem.Driver.Pdf` の `runsOf` は、`isExtending` の字を前の字のランに残す。今の異体字セレクタの扱いを広げたものである。
- `Golem.Driver.Pdf` の `shapingOf` は、字のまとまりの基底の字で、欧文と和文のどちらのシェイピングにするかを決める。
- 縦組みで横組みの字形に回す判定（`turnsInVertical`、[ADR 0015](0015-vertical-dashes.md)）は、今のとおりクラスタの最初の文字で行う。
- 書体に結合文字のグリフがなく、合成済みの字もない場合、HarfBuzz は .notdef を出す。今のとおり `golem preflight` の G09002 で報告し、ほかの書体で補うことはしない（v2 の「フォントのフォールバック」で扱う）。

### テキスト層

ToUnicode と ActualText は、[ADR 0030](0030-ligature-text-layer.md) の規則のまま扱う。
HarfBuzz が `e◌́` を合成済みの `é` のグリフにした場合、そのグリフの対応の候補は、`e◌́` のクラスタ（`ClusterWhole`）と、原稿に合成済みで書いた `é` のクラスタ（`ClusterWhole`）の二つになる。
先に描いたほうが ToUnicode の対応になり、もう一方の出現は ActualText で囲まれる。
抜き出した文字列は、どちらの出現でも原稿の文字列に戻る。
異体字セレクタを ToUnicode と ActualText の文字列から除く処理（`clusterText`）は、今のとおり異体字セレクタだけにかける。
結合文字は除かない。

### IR とプラグインの ABI

意味論の IR は原稿の文字列をそのまま持ち、変えない。
プラグインの ABI は 7 のままとする。

### ドキュメント

- 仕様書の「既知の不具合」から「結合文字」の項目を消す。
- 仕様書の「フォント」の節の異体字セレクタの段落を、結合文字（一般カテゴリーが Mn、Mc、Me の字）を前の字と一つの箱にし、同じ書体で一度にシェイピングすること、文字のクラスは基底の字で決めることに広げ、この ADR へのリンクを付ける。異体字セレクタは結合文字の一つとして扱われることを書く。
- [docs/roadmap.md](../../roadmap.md) の「既知の不具合の修正」から「結合文字」の項目を消す。
- 利用者のマニュアルの付録 I（`manual/appendices/i-known-issues.gm`）から「結合文字が前の字と離れる」の項目を消し、付録 H（`manual/appendices/h-roadmap.gm`）の直す不具合の一覧から同じ項目を消す。
- [docs/roadmap.md](../../roadmap.md) の「v2 以降に回した事項」に、次の項目を加える（ロードマップはメインのセッションが改める）。
  - **箱の単位と書記素クラスタの食い違い**：行分割の箱は、基底の字と続く結合文字（一般カテゴリーが Mn、Mc、Me の字）を一つにまとめて作る（この ADR）。ハングルの音節、ZWJ でつないだ絵文字、地域指示子の組、インド系の文字の子音の結合のように、HarfBuzz のクラスタや UAX #29 の拡張書記素クラスタがこの単位と一致しない文字では、一つの字が二つの箱に分かれうる。日本語と欧文のほかの言語を組むときに、箱の単位をシェイピングの結果か UAX #29 から決める仕組みを扱う。
- [ADR 0030](0030-ligature-text-layer.md) のステータスの行に、結合文字を基底の字と一つのクラスタに組むことをこの ADR で扱ったことを、この ADR へのリンクで書き足す。
- [golem-pdf ADR 0006](../../golem-pdf/adr/0006-cid-system-info.md) のステータスの行に、異体字セレクタを前の字に付ける処理を結合文字に広げたことを、この ADR へのリンクで書き足す。

## 実装しないこと

- Unicode の正規化（NFC、NFD）。原稿の文字列は変えない。合成済みの字に置き換えるかどうかは、HarfBuzz とフォントに任せる。
- UAX #29 の拡張書記素クラスタの全体（ハングルの音節、ZWJ でつないだ絵文字、地域指示子の組など）。この ADR は Mn、Mc、Me の字だけを前の字にまとめる。
- 段落の全体をシェイピングしてから箱を作る仕組み。箱の単位を HarfBuzz の結果から作るには、行分割と描画の分担を変える必要がある。
- 箱の単位と書記素クラスタ（HarfBuzz のクラスタ、UAX #29 の拡張書記素クラスタ）が一致しない場合の扱い。v1 は日本語と欧文だけを組むので、この食い違いは起きない。より多くの言語を扱う v2 の「箱の単位と書記素クラスタの食い違い」（[docs/roadmap.md](../../roadmap.md) に加える項目）で扱う。
- 結合文字のグリフがない書体で、ほかの書体の結合文字を重ねること。
- 前に基底の字がない結合文字の文字のクラスの見直し。
- HTML、EPUB、プレーンテキスト。これらは原稿の文字列をそのまま書くので、結合文字の扱いは読者側の処理系に任される。

## テスト設計

実装の前に書き、失敗することを確かめる。

### golem-layout（`modules/golem-layout/test/Main.hs`）

- `isExtending` が、U+0301、U+0308、U+3099、U+FE00、U+E0100 で真、`e`、`か`、U+309B（結合でない濁点）、U+200D で偽である。
- `cafe◌́ au lait` を `composeInlines` で項目にすると、最初の箱の文字列が `cafe◌́` であり、`cafe` と `◌́` のあいだにグルーも罰点もない。
- `か◌゙が` を項目にすると、箱が二つ（`か◌゙` と `が`）で、一つめの箱の幅が `ceWordAdvance` に `か◌゙` を渡した値である。
- `か◌゙。` で、`。` の前の空きと禁則が `か。` と同じである（文字のクラスが基底の字の `Kana` で決まる）。
- 段落の始まりの `◌́a` で、`◌́` が一つの箱になり、エラーにならない。
- 英語のパターンを持つ環境で `re◌́sume◌́s` を分綴すると、どの箱も結合文字で始まらず、結合文字を除いた `resumes` の分綴の位置と同じ数の位置で分かれる。
- モノルビの親文字 `e◌́a` が二つの親文字（`e◌́` と `a`）に分かれる。
- 異体字セレクタの既存のテスト（`葛` と U+E0100 の組み、禁則が異体字セレクタのない場合と同じであること）がそのまま通る。

### golem-driver（`modules/golem-driver/test/PdfSpec.hs`）

- The Tempest の fixture のフォント（Source Serif）を本文の欧文の書体にし、`fixtures/kanikosen` の Noto Serif JP を和文の書体にした横組みの本で、`cafe◌́` と `café` の二つの段落を組む。`cafe◌́` の段落のグリフはすべて欧文の書体のフォントの資源で描かれ、和文の書体のフォントの資源のグリフを含まない。
- 同じ本で、`cafe◌́` の語の幅（最初のグリフの始まりから次の語の最初のグリフまで）が、`café` の語の幅と等しい。
- 同じ本の PDF から、ActualText を考慮して抜き出した文字列が、原稿の `cafe◌́` と `café` に戻る。
- `Golem.Driver.Fonts` の `shapeText` で、欧文と和文の書体が別の役割について `cafe◌́` を組むと、すべてのグリフの書体の番号が欧文の書体のものである。

### 自動テストにしない確かめ方

- この ADR の再現の原稿を組んで PNG に描き、アクセントと分音記号が前の字の上に載ることを目で確かめる。
- 『牛山ホテル』など十冊の fixture と二つのマニュアルを組み、PDF が変わらないことを確かめる。どれも結合文字を含まないので、内容のストリームのバイト列が同じになる見込みである。

## トレードオフ

ロードマップの案は、HarfBuzz のクラスタを箱の単位にすることだった。
この ADR は、HarfBuzz の既定のクラスタの単位と同じ規則（基底の字と、続く Mn、Mc、Me の字）を golem-layout で再現する形を選んだ。
箱を作る前に段落をシェイピングする形は、行分割が受け取るグリフの送りの関数を、段落のシェイピングの結果に置き換えることになり、変更の範囲がこの不具合に見合わない。
代わりに、HarfBuzz が別の規則でクラスタをまとめる文字（インド系の文字の子音の結合など）では、箱の単位とクラスタが一致しない。
Golem が組む言語は日本語と欧文なので、v1 ではこの差を受け入れる。

結合文字を判定する規則を一般カテゴリーにしたので、異体字セレクタの特別な扱いがこの規則に吸収される。
異体字セレクタだけを列挙する今の判定と、結合文字を列挙する判定を並べて持つより、規則が一つで済む。
ToUnicode の文字列から異体字セレクタを除く処理だけは、[golem-pdf ADR 0006](../../golem-pdf/adr/0006-cid-system-info.md) の理由（異体字を基底の字で探せるようにする）が結合文字には当てはまらないので、異体字セレクタに限ったまま残す。
