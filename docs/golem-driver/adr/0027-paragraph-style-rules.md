# ADR 0027: 段落スタイルの罫線

ステータス: 採択→分けて組んだ段落の罫線と間隔の単位は [ADR 0035](0035-paragraph-rules-split-and-space-units.md)、（`keep-in-column = false` の罫線を版面の外に出す位置と、段間との比較）は [ADR 0040](0040-rules-outside-column-only-at-type-area-edge.md)

## 文脈

ロードマップの v1.0.0 の「段落スタイルの罫線」は、段落の前と後に引く罫線（InDesign の段落境界線にあたるもの）を段落スタイルに書けるようにする項目である。
見出しの下の罫線や、節の区切りの罫線に使う。
長さ、太さ、間隔は、[ADR 0024](0024-rule-spec-and-footnote-separator.md) の罫線の指定（`RuleSpec`）の形で書く。

所有者は、次の二つを決めている。

- 長さの既定は、当面は段の行長（段の最大の長さ）に固定する。
- 罫線を持つ段落は、改ページと改段で分けず、一つのページ（段）に置く。その段落の注のうち、そのページに収まらないものは、次のページ（見開きで扱う場合は次の見開き）に回す。

ロードマップの未決事項「段落の罫線の間隔と行の格子」も、この ADR で決める。
脚注の区切り線は、区切りの領域を格子の行の整数倍に切り上げる（[ADR 0024](0024-rule-spec-and-footnote-separator.md)）。
段落の罫線は本文の行のあいだに入るので、同じ決め方を使えるかは確かめる必要がある。

### 今のコード

コードで確かめると、次のとおりである。

- `Golem.Project.Style` の `ParaStyleDef` は、罫線のキーを持たない。`RuleSpec` の使い手は `[notes.rule]` だけである。
- `Golem.Layout.Paginate` の `FParagraph` は、行ごとに改ページしてよい段落である（孤立行と泣き別れだけを避ける）。
- 見出し（`FHeading`）は、`putBlock` で一つのまとまりとして置く。今は、見出しの行の注を `splitNotes` で分け、入る行だけをそのページに置き、残りを次のページに送る。草稿の[見出しの脚注がページに入らないときの改ページ](../../golem-layout/adr/0013-heading-footnotes.md)は、これを改める。見出しが段に入るかを、見出しの格子の数に注の本文の行と区切りの行を足した量（見出しの必要量）で判定し、入らなければ見出しを注とともに次の段に送る。注の本文を分けて次の段に続けるのは、見出しを空の段に置いた場合だけになる。罫線を持つ見出しはこの改めた規則に従うが、罫線を持つ段落は従わない（「改ページと注」の節）。
- 見出しは段落スタイルでなく `[headings.N]` で組む。原稿の `@style` は段落にだけ付けられる（[docs/markup.md](../../markup.md)）。段落スタイルに罫線を足しただけでは、見出しの下の罫線は引けない。
- 罫線は、`Golem.Driver.Pdf` が `P.Rule`（塗った矩形）で描く。版面の格子の行 k の字面の上端は、版面の上端から `k × p`（`p` は行送り）にある（`noteRule` の計算）。

### メンテナーが決めたこと

- 見出しの罫線（`[headings.N]` の `rule-before` と `rule-after`）は、この ADR で定める。ロードマップの項目は段落スタイルの罫線だが、使い道に見出しの下の罫線を挙げているためである。
- 罫線は版面の外（余白）に出してよい。出し方のキー、出せる範囲、塗り足しと仕上がりの線との関係、golem preflight の安全域の検査との関係は、この ADR で決める（「版面の外に出す罫線」の節）。
- 罫線を持つ段落が空の段にも入らない場合は、エラーではなくお知らせ（G07046）とし、分けて組む（「入らない段落の分け方」の節）。
- 回り込む図版の脇に、罫線を持つ段落を組まない。その段落は図版の後から始まり、図版の脇の残りの行は空く。
- 罫線を持つ段落は、注が入らなくても、その位置に留まる。注のうち、そのページに収まらないものだけを次のページに回す。見出しの改めた規則（草稿の[見出しの脚注がページに入らないときの改ページ](../../golem-layout/adr/0013-heading-footnotes.md)）とは違う扱いになる（「改ページと注」の節）。
- `keep-in-column` の既定を `true` にすることを認めた。
- 罫線の領域には、隣の行（罫線を持つ段落の一行目と、後の罫線の次の行）のルビと圏点の張り出しを数え、罫線がルビと圏点に重ならないようにする。張り出しの求め方は、草稿の[コードブロックの直後の行のルビと圏点](0033-ruby-after-code-block.md)と共有する。

## 実装すること

### style.toml の設定

段落スタイルに、二つのキー `rule-before` と `rule-after` を加える。
どちらも、[ADR 0024](0024-rule-spec-and-footnote-separator.md) の罫線の指定の表か、`false` をとる。

```toml
[paragraph-styles.section]
rule-before = { weight = "0.5pt", space-before = "1zw", space-after = "0.5zw" }

[paragraph-styles.lead]
rule-after = { length = "10zw", space-before = "0.5zw" }
```

| キー | 既定 | 段落の罫線での意味 |
| --- | --- | --- |
| `length` | 段の行長 | 罫線の長さ。`zw` は段落スタイルの文字の大きさで解決する |
| `weight` | `"0.3pt"` | 罫線の太さ |
| `space-before` | なし | 罫線の前（横組みでは上、縦組みでは右）の間隔 |
| `space-after` | なし | 罫線の後（横組みでは下、縦組みでは左）の間隔 |
| `start-indent` | `"0zw"` | 段の行の始まり（横組みでは左端、縦組みでは上端）から罫線の始まりまでの距離。負の値は段の外に出す |
| `end-indent` | `"0zw"` | 段の行の終わり（横組みでは右端、縦組みでは下端）から罫線の終わりまでの距離。負の値は段の外に出す |
| `keep-in-column` | `true` | 段の端の罫線を段の中に収めるか。`false` なら版面の外に出す |

- 前の罫線（`rule-before`）は段落の一行目の前に、後の罫線（`rule-after`）は段落の最後の行の後に引く。
- 罫線と段落のあいだの間隔（前の罫線の `space-after`、後の罫線の `space-before`）を、**内側の間隔**と呼ぶ。罫線と前後の組版の要素のあいだの間隔（前の罫線の `space-before`、後の罫線の `space-after`）を、**外側の間隔**と呼ぶ。
- 間隔は、段落の行が載る格子の行の字面（`[page.grid]` の `font-size` の高さ）から測る。段落スタイルの文字が版面の文字より小さくても、格子の字面から測る。罫線の位置が段落の文字の大きさで揺れず、隣の段落とそろうためである。
- 罫線は、段の行の始まりから `start-indent` の位置から引く。段落の字下げには合わせない。
- `length` を書かなければ、罫線の長さは段の行長から `start-indent` と `end-indent` を引いた値になる。二つを書かなければ、長さは段の行長である（所有者の決めた既定）。
- `length` を書いた場合は、罫線の終わりは `start-indent` と `length` で決まる。`length` と `end-indent` を一緒に書くと G03006 とする。
- 求めた長さが 0 以下なら G03006 とする。
- 罫線が出せる範囲を超える場合は G07001 とする（「版面の外に出す罫線」の節）。[ADR 0024](0024-rule-spec-and-footnote-separator.md) の `[notes.rule]` の検査の後に、同じ `pageGeometry` で、`[paragraph-styles]` を名前の順に、次に `[headings.N]` を階層の順に検査する。
- `start-indent`、`end-indent`、`keep-in-column` は段落と見出しの罫線にだけ書ける。`[notes.rule]` に書くと G03006 とする。脚注の区切り線は段の下部の決まった位置に引くので、段の外に出す使い道がない。
- `rule-before` と `rule-after` は、`based-on` で表ごとに引き継ぐ。`regex-styles` と同じく、書けば親の表を置き換え、キーごとには合わせない。`false` は、親の罫線を引き継がないことを表す。`true` は G03006 とする。
- 値の検査は、[ADR 0024](0024-rule-spec-and-footnote-separator.md) の罫線の指定の検査のとおりである。
- 組み込みの段落スタイル `caption`、`sidenote`、`code` に書くと G03006 とする。キャプションと傍注は段落スタイルの `font` と `size` だけを使い、`code` は書けるキーを限っているためである。
- ファイルの先頭の `@style-def paragraph` には書けない。一行の `key=value` では表を書けないためである。書くと、未知のキーと同じく G03006 とする。

見出しの `[headings.N]` にも、同じ二つのキーを加える。
`length` の `zw` は見出しの文字の大きさで解決し、間隔は見出しが占める格子の行の領域（最初の格子の行の字面の上端から、最後の格子の行の字面の下端まで）から測る。
見出しの階層どうしは引き継がないので、`false` は書けるが効果はない。

### 間隔と行の格子

罫線は、格子の行を単位とする**罫線の領域**に引く。
行の格子は変えず、本文の行も、罫線を持つ段落の行も、今と同じ格子の位置に置く。
脚注の区切り線（[ADR 0024](0024-rule-spec-and-footnote-separator.md)）と同じ考え方を、段落の前後に当てる。

記号を次のように置く。
`p` は格子の行送り、`h` は格子の字面の高さ（`[page.grid]` の `font-size`）、`w` は `weight`、`i` は内側の間隔、`o` は外側の間隔、`r` はルビと圏点の張り出し（次の段落）である。
書かなかった間隔は 0 とする。

**ルビと圏点の張り出し**：ルビの読みと圏点は、行の前（横組みの上、縦組みの右）の行間に張り出す。
罫線の領域の前の行の張り出しは領域と逆の側に出るので、領域に入るのは、領域の後の行（前の罫線では罫線を持つ段落の一行目、後の罫線では次の要素の最初の行）の張り出しだけである。
その行の張り出しの最大を `r` とし、張り出しのない行では 0 とする。
`r` は、親文字の字面の端から、読みの字面の枠の外側の端、または圏点の外側の端までの距離であり、草稿の[コードブロックの直後の行のルビと圏点](0033-ruby-after-code-block.md)と同じ関数で求める。
間隔は、領域の後の行の字面ではなく、その字面を `r` だけ延ばした端から測る。
罫線がルビと圏点に重ならないためである。

**段の中の罫線**：罫線の領域の行の数 k を、次の式で決める。

```
k = max(0, ceil((i + w + o + r - (p - h)) / p))
```

段落の字面と、隣の格子の行の字面とのあいだの距離は、`k × p + (p - h)` になる。
この距離が `i + w + o + r` 以上になる最小の k を選ぶ。
k が 0 なら、罫線は行間（`p - h`）の中に入り、段落の前後に行を足さない。

罫線は、段落の字面から内側の間隔 `i` だけ離して引く。
前の罫線では、段落の一行目の字面を `r` だけ延ばした端から `i` だけ離す。
切り上げで余った距離は、すべて外側の間隔に入る。
内側の間隔は書いた値のとおりになり、外側の間隔は書いた値以上になる。
罫線が段落に属する印として見えるよう、段落に近い側を正確に保つ。
脚注の区切り線が `space-after`（脚注に近い側）を正確に保つのと同じ理由である。

`space-before` と `space-after` のどちらも書かない場合は、`i` と `o` を 0 として k を決め、罫線を、距離 `k × p + (p - h)` から張り出し `r` を除いた範囲の中央に引く。

**段の端の罫線**：前の罫線の上に段の中の要素がない場合（段の始まり）と、後の罫線の下に段の中の要素がない場合（段の終わり）は、外側の間隔を数えない。

```
k = max(1, ceil((i + w + r) / p))
```

段の終わりの後の罫線では、領域の後の行がないので `r` は 0 である。

段の始まりの格子の行の字面の上端と、段の終わりの格子の行の字面の下端を、段の端とする。
脚注を置いた段では、脚注の区切りの領域の前の格子の行が段の終わりである。
罫線は段落の字面（前の罫線では `r` だけ延ばした端）から `i` だけ離して引き、どちらの間隔も書かなければ、その端と段の端の中央に引く。
`keep-in-column = true`（既定）では、罫線は段の端の内側に収まり、版面の外には出ない。
`keep-in-column = false` の場合は次の節のとおりである。

### 版面の外に出す罫線

罫線は、行の方向と、行に直交する方向の両方で、版面の外に出せる。

**行の方向**：`start-indent` と `end-indent` に負の値を書くと、罫線は段の行の始まりと終わりより外に出る。
InDesign の段落境界線の左インデントと右インデントに負の値を書く使い方にあたる（記憶によるもので、InDesign の画面では確かめていない）。
出せる範囲は次のとおりとし、超えると G07001 とする。

- 罫線は仕上がりの線の内側に収める。横組みでは版面の左右の余白、縦組みでは天と地の余白の幅までである。余白はページの左右（奇数ページと偶数ページ）で違いうるので、両方のページで検査する。
- 段組みの版面で、隣の段の側に出す場合は、段間（`column-gap`）の半分までとする。隣の段の罫線と重ならないためである。
- 検査は `pageGeometry` で、段落スタイルの文字の大きさで `zw` を解決して行う。

**行に直交する方向**：`keep-in-column = false` の罫線は、段の端で、段落の字面（前の罫線では一行目の字面を `r` だけ延ばした端）から内側の間隔 `i` だけ離した位置に引き、罫線の領域の行を取らない（k = 0）。
段の始まりの前の罫線は版面の上（横組み）か右（縦組み）の余白に、段の終わりの後の罫線は版面の下（横組み）か左（縦組み）の余白に入る。
段組みで、段の端が版面の端でない場合（縦組みの二段めの始まりなど）は、段間に入る。
InDesign の段落境界線の「フレーム内に収める」を切った状態にあたる（記憶によるもので、確かめていない）。
次の場合は、`keep-in-column = false` を書いても段の中に収める（`true` と同じ k で数える）。

- 段の終わりの後の罫線で、その段に脚注がある場合。罫線が脚注の区切りの領域に入るためである。
- 段の端でない位置の罫線。段の中の罫線と隣り合う罫線は、もともと版面の外に出ない。

出せる範囲は次のとおりとし、超えると G07001 とする。

- `i + w` が、その側の余白（版面の端から仕上がりの線まで）以下であること。段のあいだに入る場合は、段間の半分以下であること。`pageGeometry` の検査は行の内容を知らないので、`r` を 0 として検査する。
- 組んだ一行目の張り出し `r` を足すと `i + w + r` が余白（または段間の半分）を超える段落では、その罫線を段の中に収める（`keep-in-column = true` と同じ k で数える）。罫線が仕上がりの線を越えないためである。
- 罫線の外側の間隔 `o` は、版面の外では数えない。

**塗り足しと仕上がりの線**：罫線は塗り足しの領域に出さない。
仕上がりの線ちょうどで終わる罫線も、塗り足しの幅まで延ばさない（「実装しないこと」）。

**golem preflight**：版面の外に出した罫線も、ほかの罫線と同じく `pdRules` に入る。
仕上がりの線から `[live-area]` の `distance` より内側に入らない罫線は、G09012（線の範囲が安全域からはみ出す）で報告される。
G07001 は仕上がりの線を超えるかだけを見て、安全域は golem preflight に任せる。
余白に置いた柱とノンブルとの重なりは、どちらでも検査しない（トレードオフ）。

**隣り合う罫線**：後の罫線を持つ段落の直後に、前の罫線を持つ段落が同じ段で続く場合（あいだに空きの行がない場合）は、二つの罫線を一つの領域に置く。
前の段落の後の罫線を A、後の段落の前の罫線を B とする。

```
k = max(0, ceil((iA + wA + max(oA, oB) + wB + iB + rB - (p - h)) / p))
```

`rB` は、後の段落の一行目の張り出しである。
A は前の段落の字面から `iA`、B は後の段落の一行目の字面を `rB` だけ延ばした端から `iB` だけ離して引く。
二つの外側の間隔は、大きいほうを二つの罫線のあいだの間隔の最小値とする。
四つの間隔のどれも書かなければ、距離から `rB` を除いた範囲を三つに等しく分けて二つの罫線を引き、割り切れない余りは真ん中の間隔に入れる。
`space-between`（同じ段落スタイルの段落のあいだの空きの行）がある場合は、空きの行が二つの領域を隔てるので、それぞれを段の中の罫線として数える。

どの式も sp の整数で計算し、割り算は切り上げか切り捨てを一度だけ行う（[docs/adr/0002](../../adr/0002-determinism.md)）。

### 改ページと注

罫線を持つ段落と見出しは、前の罫線の領域、段落の行、後の罫線の領域を合わせて一つのまとまり（**罫線のまとまり**）として置く。

- まとまりは改ページと改段で分けない。今の段に入らなければ、次の段から置く。
- 空の段にも入らないまとまりは、お知らせ（G07046）を出し、次の節のとおり分けて組む。
- 段の始まりに置くか、段の終わりで終わるかで k が変わる。段の終わりで終わるかは、段の中の罫線の k で置いたときにまとまりの終わりが段の終わりに達するかで決め、達する場合は段の端の k で数え直す。数え直したまとまりが入らなければ、次の段から置く。
- **罫線を持つ段落**：まとまりが段に入るかは、まとまりの格子の行の数だけで判定し、注の本文の行を数えない。まとまりを置いたら、注の本文のうち入る分だけをその段の下に置き、残りを次のページに送る（今の `putBlock` と `splitNotes`）。メンテナーの決定のとおり、段落はその位置に留まり、注だけが動く。今の Golem は見開きを単位に注を置かないので、送り先は次のページ（段組みでは、注の続きを置く次の段）である。
- **罫線を持つ見出し**：草稿の[見出しの脚注がページに入らないときの改ページ](../../golem-layout/adr/0013-heading-footnotes.md)の見出しの必要量に、罫線の領域の行を足して判定する。入らなければ、見出しを注と罫線とともに次の段に送る。注を分けるのは、空の段に置いた場合だけである。罫線を持つかどうかで、見出しの注の扱いを変えない。
- 二つの扱いが違うのは、見出しと段落で、注より優先するものが違うためである。見出しは、後の本文と離さないことと、見出しと注を同じページに置くことを優先する（見出しの草稿の決定）。罫線を持つ段落は、節の区切りのように位置そのものに意味があるので、位置を保つことを優先する（メンテナーの決定）。罫線を持つ段落は複数の行からなることがあり、注に合わせて送ると、送った段の末尾に見出しより大きな空きが残ることもある。
- 見出しの直後で改ページしない規則（`nextNeed`）は、続く要素が罫線のまとまりなら、その全体の行の数を数える。
- 回り込む図版の脇には、罫線を持つ段落を組まない。図版の脇に組む段落を集めるとき、罫線を持つ段落の前で止め、その段落は図版の後から置く。図版の脇の残りの行は空ける。
- 箇条書きの項目、表のセル、注の本文、定義リストの中の段落には、段落スタイルが付かないので、罫線も引かない。

### 入らない段落の分け方

空の段にも入らないまとまりには、お知らせ G07046 を出し、PDF を書く。
組み方は次のとおりとする。

- **段落**：罫線を持たない段落（`FParagraph`）と同じく、孤立行と泣き別れの規則で行を段に分ける。前の罫線の領域は最初の部分の前に、後の罫線の領域は最後の部分の後に置く。分けた箇所（段の終わりと次の段の始まり）には罫線を引かない。前の罫線は最初の部分を置く段の始まりにあるので、段の端の k で数える。
- **見出し**：見出しの行は分けない。見出しの行だけで空の段に入らない場合は、今と同じく G07024（エラー）である。見出しの行と前の罫線の領域は入るが後の罫線の領域が入らない場合は、後の罫線を引かずに置く。前の罫線の領域も入らない場合は、前の罫線も引かない。
- 注の扱いは、ほかの罫線を持つ段落と同じく、入らない注の本文を次のページに送る。

G07046 はお知らせなので、`manifest.toml` の `[diagnostics]` の `silence-notices` で抑制できる。
`Golem.Syntax.Diagnostic` の `noticeCodes` に G07046 を加える。

### 描き方

- 横組みでは、罫線の領域の中の上の位置に、段の左端から `start-indent` の位置から長さの分だけ水平に引く。縦組みでは「上」を「右」に読み替え、段の上端から垂直に引く。`keep-in-column = false` の段の端の罫線は、領域を取らず、版面の外の上の位置に引く。
- 罫線は太さ `w` の塗った矩形（`P.Rule`）で描く。色は、脚注の区切り線と表の罫線と同じく、色を設定しない描き方とする。
- golem preflight の線の太さの検査（G09018）と仕上がりの線の検査（G09012）のために、罫線を `PageDrawn` の `pdRules` に、種類「段落の罫線」と「見出しの罫線」で加える。

### データ構造

- `Golem.Project.Style` の `ParaStyleDef` に、`psRuleBefore` と `psRuleAfter`（どちらも `Maybe (Maybe RuleSpec)`）を加える。外の `Nothing` は引き継ぎ、`Just Nothing` は `false`、`Just (Just r)` は罫線である。解決した段落スタイルでは `Maybe RuleSpec` になる。
- `RuleSpec` に、`rsStartIndent :: Dim`（既定 `Zw 0`）、`rsEndIndent :: Maybe Dim`、`rsKeepInColumn :: Bool`（既定 `True`）を加える。型は罫線の指定の全体に持たせ、読める使い手を段落と見出しに絞る。
- `HeadingStyle` に、`hsRuleBefore` と `hsRuleAfter`（どちらも `Maybe RuleSpec`）を加える。
- `LineBox` に、行の前の張り出し `lbOverhang :: Sp` を加える。golem-driver が、草稿の[コードブロックの直後の行のルビと圏点](0033-ruby-after-code-block.md)の判定と同じ関数で求めて入れる。
- golem-layout に、罫線の領域の行の数を求める純粋な関数を置く。張り出し `r` を引数に取る。段の中、段の端、隣り合う罫線の三つの場合を、上の式のとおりに一か所で計算する。罫線の位置（領域の端からの距離）も同じ関数が返し、改ページと描画が同じ値を使う。
- `Golem.Layout.Paginate` の `Flow` に、罫線のまとまり `FRuled` を加える。前と後の罫線の測り（内側と外側の間隔、太さ、書いたかどうか、段の中に収めるか）と、段落の行（見出しなら見出しの `FHeading` の値）を持つ。
- `PageOut` に、段に置いた罫線の領域の一覧（領域の最初の格子の行、行の数、罫線の位置、罫線の種類と測り）を加える。`Golem.Driver.Pdf` は、この一覧から罫線を描く。

### HTML と EPUB

段落スタイルの `ps-名前` の CSS に、前の罫線を `::before`、後の罫線を `::after` の擬似要素として書く。
見出しは `hN` の要素の `::before` と `::after` に書く。

```css
.ps-section::before {
  content: "";
  display: block;
  width: 100%;
  border-top: 0.5pt solid;
  margin: 1em 0 0.5em;
}
```

- `width` は、`length` がなければ `100%`、あれば寸法（`zw` は `em`）とする。`start-indent` と `end-indent` は `margin-inline-start` と `margin-inline-end` に書き、`length` がなく indent があれば `width` を書かない（`display: block` の幅が残りに広がる）。負の値もそのまま書く。
- `keep-in-column` は HTML と EPUB では使わない。
- `border-top` は `weight` と `solid` とし、色は書かない（文字の色になる）。
- `margin` は、前の罫線では上に外側の間隔、下に内側の間隔を、後の罫線では上に内側の間隔、下に外側の間隔を書く。書かなかった間隔は 0 とする。
- 縦組みの本の HTML と EPUB でも同じ CSS を書く。`border-top` と `margin` の上下は、CSS の書字方向で論理的な向きにならないので、`border-block-start` と `margin-block` で書く。

行の格子への切り上げは、HTML と EPUB では行わない。
プレーンテキストには罫線を出力しない。

### 診断

- G03006：`rule-before` と `rule-after` の値の誤り、`true`、組み込みの `caption`、`sidenote`、`code` と `@style-def` に書いた場合、`length` と `end-indent` を一緒に書いた場合、求めた長さが 0 以下の場合、`[notes.rule]` に `start-indent`、`end-indent`、`keep-in-column` を書いた場合。
- G07001：罫線が出せる範囲を超える場合。メッセージは `段落スタイル <名前> の罫線が仕上がりの線を超えます`、`段落スタイル <名前> の罫線が段間の半分を超えます` と、同じ形の `見出し <階層> の罫線が…` とする。
- G07046（新しいコード、お知らせ）：罫線を持つ段落か見出しが、空の段にも入らない。メッセージは `罫線を持つ段落が版面に入らないため、分けて組みました（段落スタイル <名前>）` と `罫線を持つ見出しが版面に入らないため、罫線を省きました（見出し <階層>）`、位置は段落か見出しの位置、モジュールは golem-driver の `Golem.Driver.Pdf` とする。PDF は書く。G07043（コードブロックが版面に入らない）と G07044、G07045 の後の空いた番号を選んだ。G07045 と同じく、07 の区分のお知らせである。

### ドキュメント

- docs/specifications.md：「style.toml」の段落スタイルのキーの説明に `rule-before` と `rule-after` を、見出しの節に同じキーを加える。「罫線の指定」の節の「今の使い手」に段落スタイルと見出しを、表に `start-indent`、`end-indent`、`keep-in-column`（段落と見出しの罫線だけ）を加え、版面の外に出せる範囲を書く。「改ページ」の節に罫線のまとまりの扱い（注の判定、空の段に入らないときの分け方）を、HTML と EPUB の CSS の段落に擬似要素を書く。
- docs/diagnostics.md：G07046 の節（重大度はお知らせ、`silence-notices` で抑制できること）を足す。G07001 の検査の順とメッセージ、G03006 の主な原因を直す。G09012 の主な原因に、版面の外に出した罫線を加える。
- docs/roadmap.md：v1.0.0 の「段落スタイルの罫線」と、未決事項の「段落の罫線の間隔と行の格子」を消す。
- 使い手のマニュアル：`manual/chapters/05-style.gm` の段落スタイルの節と、`manual/appendices/c-style.gm` の段落スタイルと見出しの表に二つのキーを加える。`manual/appendices/f-indesign.gm` に段落境界線との対応（左インデントと右インデント、フレーム内に収める）を、`manual/appendices/h-roadmap.gm` の項目から段落の罫線を消す（色と線の種類は [ADR 0028](0028-rule-colour-and-style.md) まで残す）。`manual/appendices/e-errors.gm` に G07046 を加える。
- 開発者のマニュアル：改ページのまとまりの種類を説明する箇所があれば、罫線のまとまりを加える。

## 実装しないこと

- 罫線の色と線の種類。[ADR 0028](0028-rule-colour-and-style.md) で、罫線の指定のすべての使い手に同時に加える。
- 罫線の寄せ（中央、行末）。罫線は段の行の始まりから `start-indent` の位置から引く。
- 罫線を塗り足しの領域に出すこと。仕上がりの線で終わる罫線を、塗り足しの幅まで自動で延ばすこと。
- 版面の外に出した罫線と、柱、ノンブル、傍注欄との重なりの検査。
- 罫線の長さを、段落の行の長さ（文字の幅）に合わせること。
- 段落の前後の空き（InDesign の段落前のアキと段落後のアキ）を、罫線なしで書くこと。
- 分けて組んだ段落の分けた箇所に罫線を引き直すこと。
- 見開きを単位にした注の置き方。今の Golem の注はページ（段）を単位に置く。
- 箇条書きの項目、表のセル、注の本文、定義リストの中の段落の罫線。
- 索引の段（[docs/adr/0025](../../adr/0025-index-columns.md)）の中の罫線。索引の項目は段落スタイルで組まないので、起きない。
- `@style-def` での罫線の指定。
- HTML と EPUB の罫線の位置を、PDF の格子にそろえること。

## テスト設計

実装の前に書き、失敗することを確かめる。

### style.toml（`modules/golem-project/test/Main.hs`）

- `[paragraph-styles.section] rule-before = { weight = "0.5pt" }` を読むと、`length` のない `RuleSpec` が前の罫線になる（段落の罫線では `length` が要らない）。
- `rule-after = { length = "10zw", space-before = "0.5zw" }` を読める。
- `based-on = "section"` の段落スタイルが、`rule-before` を表ごと引き継ぐ。`rule-before = { weight = "1pt" }` を書いた子は、親の `space-before` を引き継がない。`rule-before = false` を書いた子は罫線を持たない。
- `rule-before = true`、`rule-before = { weight = "1zw" }`、`rule-before = { color = "x" }`（この ADR では未知のキー）が G03006 になる。
- `[paragraph-styles.caption]`、`[paragraph-styles.sidenote]`、`[paragraph-styles.code]` に `rule-before` を書くと G03006 になる。
- `@style-def paragraph x rule-before=...` が G03006 になる。
- `[headings.2] rule-after = { space-before = "0.25zw" }` を読める。
- `rule-before = { start-indent = "-2zw", end-indent = "-2zw", keep-in-column = false }` を読める。書かなければ `rsStartIndent` が `Zw 0`、`rsEndIndent` が `Nothing`、`rsKeepInColumn` が `True` になる。
- `rule-before = { length = "10zw", end-indent = "1zw" }` と、`start-indent = "30zw"`、`end-indent = "10zw"`（40 字の段で長さが 0）が G03006 になる。
- `[notes.rule]` に `keep-in-column = false` か `start-indent` を書くと G03006 になる。

### 版面（golem-layout-spec の `pageGeometry` のテスト）

- 一行 40 字の版面で、`rule-before = { length = "41zw" }` の段落スタイルが G07001 になり、`"40zw"` なら版面を計算できる。段落スタイルの `size = "0.5zw"` なら、`"80zw"` が版面の文字の 40 字分なので通り、`"81zw"` が G07001 になる。
- 二段組みで段の行長が 20 字の版面で、`length = "21zw"` は、右の段から右の余白に、左の段から段間に出るので、段間の半分を超えれば G07001 になる。
- 左右の余白が 15mm の横組みの版面で、`start-indent = "-14mm"` は通り、`"-16mm"` が G07001 になる。左右の余白が奇数ページと偶数ページで違う版面では、狭いほうで検査される。
- 天の余白が 10mm の横組みの版面で、`keep-in-column = false`、`space-after = "9mm"`、`weight = "0.5pt"` の前の罫線が通り、`space-after = "10mm"` が G07001 になる。

### 罫線の領域（golem-layout の関数のテスト）

字の大きさ 10pt、行送り 17pt（`p - h` = 7pt）の格子で確かめる。

- 段の中、間隔なし、太さ 0.3pt：k = 0、罫線は 7pt の行間の中央にある。
- 段の中、内側 2pt、外側 4pt、太さ 0.5pt：6.5pt ≤ 7pt なので k = 0。罫線は段落の字面から 2pt にある。
- 段の中、内側 5pt、外側 10pt、太さ 0.5pt：15.5pt − 7pt = 8.5pt を 17pt で割って切り上げ、k = 1。外側の間隔は 17pt + 7pt − 5.5pt = 18.5pt になる。
- 段の始まり、内側 5pt、外側 10pt、太さ 0.5pt：5.5pt を 17pt で割って切り上げ、k = 1。外側の間隔は数えない。
- 段の始まり、`keep-in-column = false`、内側 5pt：k = 0、罫線は段落の字面から 5pt 外（版面の外）にある。
- 段の終わり、`keep-in-column = false` で、その段に脚注がある：段の中に収める k で数える。
- 隣り合う罫線、`iA` = 2pt、`oA` = 3pt、`oB` = 6pt、`iB` = 2pt、太さはどちらも 0.5pt：2 + 0.5 + 6 + 0.5 + 2 = 11pt、11pt − 7pt = 4pt を切り上げて k = 1。二つの罫線のあいだは 6pt 以上ある。
- 隣り合う罫線で四つの間隔がどれもない場合、三つの間隔が等しく、余りが真ん中に入る。
- 段の中の前の罫線、内側 2pt、外側 4pt、太さ 0.5pt で、段落の一行目に張り出し 5.6pt のルビがある：6.5 + 5.6 = 12.1pt、12.1pt − 7pt = 5.1pt を切り上げて k = 1（ルビがなければ k = 0）。罫線は読みの外側の端から 2pt にある。
- 段の中の後の罫線、間隔なし、太さ 0.3pt で、次の段落の一行目に張り出し 5.6pt のルビがある：k = 0 のまま、罫線は 7pt − 5.6pt = 1.4pt の範囲の中央にあり、読みと交わらない。
- 圏点の張り出し（字の大きさの半分の 5pt）も、ルビと同じく数えられる。
- 隣り合う罫線で、後の段落の一行目にルビがある場合、`rB` が足される。
- 段の始まりの前の罫線、内側 5pt、太さ 0.5pt、一行目に張り出し 5.6pt：11.1pt を 17pt で割って切り上げ、k = 1。
- 段の終わりの後の罫線では、張り出しを数えない。

### 改ページ（`Golem.Layout.Paginate` のテスト）

- 段の残りが 3 行のとき、罫線の領域が前に 1 行ある 3 行の段落は、次の段の先頭から置かれ、段の始まりの k で数えられる。
- 段の残りが 4 行のとき、罫線のない 6 行の段落は今と同じく 4 行と 2 行に分かれ、同じ段落に後の罫線を付けると、全体が次の段から置かれる。
- 罫線を持つ段落の行に、段の残りに入らない長さの注がある場合、段落はその段に置かれ、注の入らない部分が次のページに送られる。段落の行が段に入る限り、段落は送られない。
- 罫線を持つ見出しの行に、段の残りに入らない長さの注がある場合、見出しは注と罫線とともに次の段に送られる（草稿の[見出しの脚注がページに入らないときの改ページ](../../golem-layout/adr/0013-heading-footnotes.md)と同じ判定に、罫線の領域を足したもの）。
- 罫線のまとまりが空の段に入らない場合、`Golem.Driver.Pdf` が G07046 のお知らせを出し、PDF を書く。段落は孤立行と泣き別れの規則で分かれ、前の罫線は最初の部分の前に、後の罫線は最後の部分の後にだけある。
- 見出しの行と前の罫線は入るが後の罫線が入らない場合、G07046 が出て、見出しは後の罫線なしで置かれる。
- `silence-notices = ["G07046"]` で G07046 が出ない。
- 見出しの直後に罫線を持つ 5 行の段落が続き、段の残りが見出しの行と 4 行のとき、見出しも次の段に送られる。
- 後の罫線を持つ段落の直後に前の罫線を持つ段落が続くと、領域が一つにまとまる。`space-between = 1` があると、二つの領域が空きの行を挟んで別に数えられる。
- 段の終わりで終わるまとまりは、段の端の k で数え直される。
- 回り込む図版の直後に罫線を持つ段落があると、その段落は図版の脇に組まれず、図版の後から置かれる。

### PDF（`modules/golem-driver/test/Main.hs`）

- 横組みで、前の罫線を持つ段落の上に、段の左端から段の行長の水平の矩形（太さ `weight`）が描かれ、矩形の下端と段落の一行目の格子の字面の上端の距離が内側の間隔に等しい。
- 縦組みで、同じ罫線が段の上端から段の行長の垂直の矩形になり、矩形の左端と一行目の字面の右端の距離が内側の間隔に等しい。
- `length = "10zw"` で、矩形の長さが段落スタイルの文字の大きさの 10 字分になる。
- 二段組みで、段落を置いた段の左端から引かれる。
- `start-indent = "-2zw"` と `end-indent = "-2zw"` で、矩形が段の左端の 2 字前から右端の 2 字後まで描かれる。
- `keep-in-column = false` で、ページの先頭の段落の前の罫線が版面の上の余白に描かれ、段落の一行目が版面の最初の格子の行にある。
- 同じ設定で一行目にルビがあり、`i + w + r` が天の余白を超える場合、罫線は段の中に収められ、一行目が一つ後の格子の行に置かれる。
- 前の罫線を持つ段落の一行目と、後の罫線を持つ段落の次の行にルビと圏点を置くと、どの読みと圏点のグリフの範囲も、罫線の矩形と交わらない。
- 仕上がりの線の近くまで出した罫線で、golem preflight が G09012 を出す。
- 見出しの `rule-after` が、見出しの領域の最後の格子の行の字面の下端から、内側の間隔の位置に描かれる。
- 罫線を持たない本の PDF のバイト列が変わらないことを、既存の PDF のテストと決定性の検査で確かめる。
- golem preflight の見え方（view）に、種類「段落の罫線」の罫線が入る。

### HTML（`modules/golem-html/test/Main.hs`）

- `rule-before` を持つ段落スタイルの CSS に、`.ps-名前::before` の規則（`content`、`display: block`、`width: 100%`、`border-block-start`、`margin-block`）が出る。`length = "10zw"` で `width: 10em` になる。
- `[headings.2] rule-after` で、`h2::after` の規則が出る。
- `start-indent = "-2zw"` で、`margin-inline-start: -2em` が出る。

### 自動テストにしない確かめ方

- 横組みと縦組みの試料に、節の区切りの罫線と見出しの下の罫線を付けて組み、PDF を画像にして、罫線が格子の行を崩さずに入り、段の端で版面の外に出ないことを目で確かめる。
- HTML を Safari と Chrome で開き、罫線が段落の前後に出ることを確かめる。

## トレードオフ

罫線の領域に、隣の行のルビと圏点の張り出しを数えることにした（メンテナーの決定）。
同じ段落スタイルの罫線でも、一行目や次の行にルビがあるかで、罫線の位置と領域の行の数が変わる。
張り出しを数えないと、行間に入れた細い罫線がルビの読みを横切る。
張り出しの求め方を草稿の[コードブロックの直後の行のルビと圏点](0033-ruby-after-code-block.md)と共有するので、コードブロックと罫線で、ルビと重ならないとみなす範囲がそろう。
`keep-in-column = false` の検査は版面を計算するときに行の内容を知らないので、張り出しで余白を超える段落だけを、組んだ後に段の中に収める。
書いた設定どおりに版面の外に出ない段落が生じうる。

間隔の扱いには、ほかに三つの候補があった。

- **罫線を行間だけに引き、行を足さない**：格子が崩れず、改ページも変わらない。しかし、行間（`p - h`）より大きい間隔を書けず、見出しの下の罫線のように字面から離したい場合に使えない。
- **間隔を書いたとおりに取り、後の行を格子からずらす**：InDesign のフレームグリッドを使わない組み方に近い。しかし、本文を格子に載せ、見開きの行の位置をそろえるという今の PDF の前提（段落スタイルに行送りの欄を設けない理由）に反する。
- **間隔を格子の行の数で書く**：計算は簡単だが、罫線の指定の形（寸法の `space-before` と `space-after`）を段落の罫線だけ変えることになり、[ADR 0024](0024-rule-spec-and-footnote-separator.md) の共通の形が崩れる。

採った形は、脚注の区切り線と同じく、領域を格子の行の整数倍に切り上げる。
脚注の区切り線との違いは、行の数の下限を 0 にしたことである。
細い罫線と小さい間隔なら行間に収まり、段落の前後に行を足さない。
脚注の区切り線は、今の振る舞い（いつも一行を空ける）を変えないために下限を 1 にしているので、二つの式は同じではない。

内側の間隔を正確に保ち、余りを外側の間隔に回したので、外側の間隔は最小値の意味になる。
前の要素から罫線までの距離は、段落ごとに格子の都合で変わる。

段の端で外側の間隔を数えないので、段の始まりの段落と段の中の段落で、罫線の前の空きが違って見える。
数えると、ページの頭の罫線の上に、何もない行ができる。

`keep-in-column` の既定を `true`（段の中に収める）にした。
`false` を既定にすると、ページの頭の罫線が余白に出て、柱と近づくことがある。
柱との重なりは検査しないので、余白に出すかは本ごとに決めて書く形にした。
InDesign の「フレーム内に収める」の既定は確かめていない。

版面の外に出せる範囲を仕上がりの線までにし、塗り足しには出さないことにした。
裁ち落としの罫線（仕上がりの線を越えて塗り足しまで延ばす罫線）は、塗り足しの幅と仕上がりのずれを考える別の設計が要る。
安全域の検査は golem preflight の G09012 に任せたので、G07001 は仕上がりの線を超える明らかな誤りだけを止める。
余白に置いた柱とノンブルとの重なりは、どの検査も見ない。

罫線を持つ段落を分けないので、長い段落に罫線を付けると、前の段に大きな空きが残る。
所有者の決定のとおり、罫線を持つ段落は見出しや節の区切りのような短い段落を想定している。
空の段にも入らない段落は、お知らせを出して分ける。
エラーにすると、長い引用に罫線を付けた本が組めなくなる。
黙って分けると、分けた箇所に罫線がないことに気付きにくい。

罫線を持つ段落は、注が入らなくても位置に留め、注だけを次のページに送ることにした（メンテナーの決定）。
段落と注の本文が別のページに分かれることがある。
見出しは、草稿の[見出しの脚注がページに入らないときの改ページ](../../golem-layout/adr/0013-heading-footnotes.md)のとおり注とともに送るので、注の扱いが段落と見出しで二通りになる。
`Golem.Layout.Paginate` の `FRuled` は、中身が見出しか段落かで、入るかの判定を分ける。

隣り合う罫線をまとめる規則を足したので、改ページの計算が、後の要素を見て前の要素の領域を決めることになる。
まとめないと、二つの罫線がともに同じ行間を使うと数え、重なって描かれることがある。

HTML と EPUB では、格子への切り上げをせず、書いた間隔をそのまま `margin` にする。
リフローの媒体には行の格子がないので、PDF と同じ見た目は求めない。

見出しの罫線を同じ ADR に含めたので（メンテナーの決定）、段落スタイルのほかに `[headings.N]` のキーも増える。
見出しに段落スタイルを付ける仕組みを作るほうが一般的だが、`[headings.N]` と段落スタイルのどちらが優先するかなど、決めることが増える。
