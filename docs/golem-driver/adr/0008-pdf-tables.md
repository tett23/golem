# ADR 0008: PDF で表を組む

ステータス: 採択→罫線の位置、表の前後の空き、空の見出しの行は [ADR 0031](0031-table-spacing-and-rules.md)、列の幅の二つめの場合の配り方は [ADR 0037](0037-table-column-widths.md)

## 文脈

表は、行頭の `|` で始まる行か、`@table src=data.csv` で書く（[markup.md](../../markup.md) の「表」の節）。
一行目が見出しの行であり、区切りの行の `:` で列の揃え（左寄せ、中央、右寄せ）を指定する。
セルの中身はインラインの要素に限り、セルの結合とセルの中のブロックは扱わない。

意味論 IR では、表は `Table [Alignment] [[Inline]] [[[Inline]]]` である（`Golem.Doc.IR`）。
順に、列の揃え、見出しの行のセル、本体の行ごとのセルを持つ。
`Alignment` は `AlignDefault`、`AlignLeft`、`AlignCenter`、`AlignRight` の四つである。
意味論 IR は幾何を持たないので、列の幅も罫線も持たない。

HTML は `<table>` の `<thead>` に見出しの行を `<th>` で、`<tbody>` に本体の行を `<td>` で出し、揃えを `align-left` などのクラスで表す。
罫線と列の幅は指定せず、読者側のエンジンに任せている。
縦組みの本では `body` に `writing-mode: vertical-rl` を指定しているので、表も縦組みで表示される。
行は右から左へ並ぶ縦の列になり、セルは上から下へ並ぶ。

PDF の経路（[ADR 0002](0002-pdf-pipeline.md)）は、表を組んでいない。
`Golem.Driver.Pdf` の `unitsOf` は、見出しの行と本体の各行を、セルの中身を全角の空白でつないだ一つの段落にしている。
列はそろわず、罫線もなく、見出しの行と本体の区別もない。

PDF の本文は行の格子（[golem-layout-spec ADR 0001](../../golem-layout-spec/adr/0001-page-geometry.md)）の上に置き、改ページは格子の行の数で数える（[golem-layout ADR 0003](../../golem-layout/adr/0003-pagination-and-s2.md)）。
図版は格子の行の単位に切り上げた高さで置き、後に続く本文が格子からずれないようにしている（[golem-layout ADR 0004](../../golem-layout/adr/0004-wrapped-figures.md)）。
表もこの枠組みの中に収める。

## 実装すること

### 表の幾何の考え方

- 表の各セルの中身を、行の格子の上に組む。セルの一行は格子の一行に当たり、文字の大きさと行送りは本文と同じとする。
- 表の行の高さは、その行のセルのうち最も行数の多いセルの行数（格子の行の数）とする。
- 表は格子の行の単位で改ページされる。改ページは表の行と行のあいだだけで行い、表の行の途中では改ページしない。
- 以下では、行の進む方向（横組みでは左から右、縦組みでは上から下）の長さを「列の幅」、行の並ぶ方向の長さを「高さ」と呼ぶ。

### 縦組みの表

縦組みの本では、表も縦組みで組む。
本文と同じく、セルの中の行は上から下へ進み、表の行は右から左へ並ぶ。
列の幅は版面の縦の長さ（字詰めの方向）で数え、列は上から下へ並ぶ。
HTML と EPUB の縦組みでの表示と同じ配置であり、意味内容と配置の対応が媒体のあいだで変わらない。

幾何の計算は、行の方向と行の並ぶ方向だけで書き、縦組みと横組みで同じ関数を使う。
描くときに座標へ写す処理は、今の `drawLine` の `origin` と同じく `pgVertical` で分ける。

縦組みでの揃えは、`AlignLeft` を天寄せ（行の始まりの側）、`AlignRight` を地寄せ（行の終わりの側）とする。
CSS の `text-align: left` が縦組みでは行の始まりの側に寄せることと合わせる。

### 列の幅

列の幅は、セルの中身の二つの幅から決める。

- 最小の幅：セルの中で改行できる位置のあいだの幅の最大値。改行できる位置は、箱の直後のグルーと、`infPenalty` 未満で `itemFlagged` でない罰点とする。ハイフンを入れる改行は最小の幅の計算では使わない。
- 自然な幅：セルを一行に組んだときの幅。箱、グルーの自然な幅の和とし、罰点の幅と段落の末尾のグルーは含めない。

列の最小の幅と自然な幅は、その列のすべてのセル（見出しの行を含む）の最大値とする。
列の間隔は一字分（`pgFontSize`）とし、表の外側には空きを付けない。
使える幅 W は、段の行長から列の間隔の合計を引いた値とする。

1. 自然な幅の合計が W 以下なら、各列の幅を自然な幅とする。
2. そうでなく、最小の幅の合計が W 以下なら、各列に最小の幅を与え、残り（W から最小の幅の合計を引いた値）を、自然な幅と最小の幅の差に比例して配る。配る量は整数の sp で切り捨て、切り捨てで余った sp は左（縦組みでは上）の列から 1sp ずつ配る。
3. 最小の幅の合計が W を超えるなら、G07041 のエラーとする。

計算はすべて整数の sp で行い、浮動小数点数を使わない（[docs/adr/0002](../../adr/0002-determinism.md)）。
表の幅（列の幅と間隔の和）が行長より短い場合は、表を行の始まりの側に寄せる。

### セルの組版

- 各セルの中身を `composeInlines` で項目に直し、列の幅を行長として `breakParagraph` で行に分ける。
- セルでは、ぶら下げ組と突き出しを使わない。`ComposeEnv` の `ceHanging` と `Params` の `pProtrusion` を偽にする。行末の約物が列の幅の外に出ると、隣の列の間隔に入り込むためである。
- 揃えは、セルの各行の内容の幅（最後の箱の終わりの位置）と列の幅の差で決める。`AlignRight` は差の全部を、`AlignCenter` は差の半分（切り捨て）を行の始まりに足す。`AlignLeft` と `AlignDefault` は足さない。両端揃えで組まれた行は差が 0 になるので、揃えは実質的に最後の行に効く。
- 見出しの行は本体と同じ書体と大きさで組む。PDF の経路はまだ太字を区別しないので、見出しの行は下の罫線で本体と区別する。
- セルの中の注の印、索引の印、ページ番号への参照は、段落の中と同じく、その印を含むセルの行が置かれる格子の行に付ける（[ADR 0007](0007-pdf-index-and-bibliography.md)）。
- 表に付けたラベルは、表の最初の格子の行に付ける。`[ref-page ...]` で表のページを参照できる。

### 罫線

罫線は横の罫（行の並ぶ方向を区切る罫）だけを引き、縦の罫は引かない。

- 表の始まりの罫と終わりの罫：太さ 0.6pt。
- 見出しの行の下の罫：太さ 0.3pt。
- 本体の行のあいだには罫を引かない。

罫線は、隣り合う二つの格子の行の字面の枠のあいだの空き（行送りから文字の大きさを引いた長さ）の中央に、表の幅の長さで引く。
表の始まりの罫は表の最初の格子の行の前の空きに、終わりの罫は最後の格子の行の後の空きに引く。
字面の枠は、図版の位置の計算（`figureRect`）と同じく、格子の位置から文字の大きさの分だけ行の並ぶ方向に広げた範囲とする。
罫線は golem-pdf の `Rule` の矩形として描く。
横組みでは幅が表の幅で高さが罫の太さの矩形、縦組みでは高さが表の幅で幅が罫の太さの矩形になる。
色は本文の文字と同じく、色を指定しない既定の塗りとする。

### ページをまたぐ表

- 表を置き始める位置に、見出しの行と本体の最初の行が収まらない場合は、表を次のページから始める。見出しの行だけがページの末尾に残らないようにするためである。
- 本体の行が収まらなくなった位置で改ページし、次のページの先頭に見出しの行を繰り返してから、続きの行を置く。
- 各ページの表の部分ごとに、始まりの罫、見出しの行の下の罫、終わりの罫を引く。
- 繰り返した見出しの行には、ラベル、注、索引の印を付けない。これらは最初の見出しの行で一度だけ数える。
- 見出しの行と本体のある一行の高さの和がページの格子の行の数を超える場合は、G07042 のエラーとする。その表の行はどのページにも収まらないためである。
- 見出しの行の直前の見出し（章や節の見出し）は、今の規則と同じく次のブロックと同じページに置く。表の場合の「次のブロックの最初の部分」は、見出しの行と本体の最初の行とする。
- 段落の孤立行の規則は、表の行には適用しない。

### データ構造の変更

golem-layout に、表の列の幅とセルの組版を担う純粋な関数のモジュール `Golem.Layout.Table` を足す。

```haskell
-- | 列の最小の幅と自然な幅
cellExtent :: [Item] -> (Sp, Sp)

data TableError = ColumnsTooWide !Sp !Sp -- 最小の幅の合計、使える幅

-- | 使える幅、各列の (最小の幅, 自然な幅) から列の幅を決める
columnWidths :: Sp -> [(Sp, Sp)] -> Either TableError [Sp]

data SetCell = SetCell
  { scOffset :: !Sp,   -- 表の始まりからの位置（列の位置と揃えの量の和）
    scLines :: ![Line]
  }

data SetTable = SetTable
  { stWidths :: ![Sp],
    stWidth :: !Sp,             -- 列の幅と間隔の和
    stHeader :: ![SetCell],
    stRows :: ![[SetCell]],
    stHeaderLines :: !Int,      -- 見出しの行の高さ（格子の行の数）
    stRowLines :: ![Int]        -- 本体の各行の高さ
  }

layoutTable :: Params -> Sp -> Sp -> [Alignment] -> [[Item]] -> [[[Item]]] -> Either TableError SetTable
-- 引数は順に、行分割の設定、段の行長、列の間隔、揃え、見出しの行のセルの項目、本体の行ごとのセルの項目
```

`Golem.Layout.Paginate` に、表の流れと、ページごとの表の部分を足す。

```haskell
data Flow
  = ...
  | FTable
      { ftId :: !Int,
        ftHeader :: ![LineBox],    -- 見出しの行の格子の行
        ftRows :: ![[LineBox]]     -- 本体の行ごとの格子の行
      }

data TableSegment = TableSegment
  { tsTable :: !Int,
    tsFirst :: !Int,          -- 表の部分の最初の格子の行の位置
    tsHeaderEnd :: !Int,      -- 見出しの行の最後の格子の行の位置
    tsLast :: !Int            -- 表の部分の最後の格子の行の位置
  }

data PageOut = PageOut
  { ...,
    poTables :: ![TableSegment]
  }
```

- 表の格子の行は、ほかの行と同じく `SLine` の `poSlots` に積む。繰り返した見出しの行は、最初の見出しの行と同じ `LineBox` の番号を使い、ラベル、注、印を空にして積む。
- 格子の行の配置と脚注の扱いは、今の `putLine` と `fitting` を使う。表の一行は、`fitting` がその行のすべての格子の行を収められる場合にだけ置く。
- `nextNeed` の `FTable` の場合は、見出しの行と本体の最初の行の高さの和とする。

`Golem.Driver.Pdf` には次を足す。

- `UnitKind` に `UTable [Alignment] [[Inline]] [[[Inline]]]` を足し、`unitsOf` の `Table` をこの単位に写す。
- 単位の行分割の結果を、段落の行の列と表の `SetTable` の和の型にする。表の単位は、すべてのセルを一つの仕事として組む。並列に実行しても結果は単位の文書の順に並べ直すので、決定性は変わらない（[ADR 0002](0002-pdf-pipeline.md)）。
- `Built` に `bTableLines :: Map Int [(Sp, SetLine)]`（格子の行の番号から、その行に置くセルの行と表の始まりからの位置）と `bTables :: Map Int Sp`（表の番号から表の幅）を足す。
- `drawPage` は、`SLine` の番号が `bTableLines` にあればセルの行をそれぞれの位置にずらして描き、`poTables` から罫線を描く。セルの行を描く処理は `drawLine` に行の始まりの位置のずれを渡せるようにして使う。

### 診断

診断コードは [golem-syntax ADR 0001](../../golem-syntax/adr/0001-source-spans-and-diagnostics.md) の区分に従い、レイアウトの `G07xxx` から空いている番号を使う。

- G07041（エラー）：表の列の最小の幅の合計が版面の行長に収まらない。位置は表のブロック、メッセージには最小の幅の合計と使える幅を mm で示す。
- G07042（エラー）：見出しの行と本体の一行の高さの和が、ページの格子の行の数を超える。位置は表のブロック、メッセージには表の何行目かを示す。

G07042 は改ページの前にドライバーで検査し、`paginate` には収まる表だけを渡す。
`paginate` はエラーを返さない今の形のままにする。

### ドキュメント

- specifications.md の「v1 の実装で次の段階以降に回した項目」から「表の組版」を除く。
- specifications.md に PDF での表の組み方（行の格子への配置、列の幅の決め方、罫線、ページをまたぐ表の見出しの行の繰り返し、縦組みの表）を書き加える。markup.md には、PDF での見た目の詳細は書かない。

## 実装しないこと

- セルの結合とセルの中のブロック。記法が扱わないためである。
- 縦の罫と、本体の行のあいだの罫。罫線の種類を選ぶ設定も持たない。
- 表のための `style.toml` の設定（文字の大きさ、罫線の太さ、列の間隔、表の寄せ）。v1 では処理系が固定の値を持つ。
- 表の文字を本文より小さくすること。行の格子から外れる組み方は、格子にそろえる今の枠組みの外にある。
- 列の幅の指定。記法に列の幅を書く欄がない。
- 縦組みの本の中に横組みの表を挿入すること。一冊の中で組み方向を切り替える仕組みがまだないためである。
- 表の行の途中での改ページ。行がページに収まらない表は G07042 のエラーとする。
- 表の番号とキャプション。記法が持たないためである。
- 表の続きを示す「（続き）」のような文言。
- HTML と EPUB の表の出力の変更。

## テスト設計

### golem-layout の `Golem.Layout.Table`

文字の幅は、既存のテストと同じく全角の文字を 1em、ほかを半角とする組み方の環境で作る。

- `cellExtent`：`PDF` は最小の幅と自然な幅がどちらも 1.5em であること。`日本語` は最小の幅が 1em、自然な幅が 3em であること。`あ。` は句読点の前で改行できないので、最小の幅が自然な幅と等しいこと。
- `columnWidths`：使える幅 100sp で、`[(10, 30), (20, 40)]` は自然な幅の和が収まるので `[30, 40]` になること。
- `columnWidths`：使える幅 100sp で、`[(10, 60), (20, 80)]` は残りの 70sp を差の 50 と 60 に比例して 31 と 38 に配り、余った 1sp を最初の列に足して `[42, 58]` になること。
- `columnWidths`：使える幅 20sp で、`[(10, 30), (20, 40)]` は `ColumnsTooWide 30 20` になること。
- `layoutTable`：二行に折り返すセルと一行のセルが同じ行にあるとき、その行の高さが 2 になること。
- `layoutTable`：`AlignRight` の列の一行のセルの `scOffset` が、列の位置に列の幅と内容の幅の差を足した値になること。`AlignCenter` では差の半分（切り捨て）を足すこと。
- `layoutTable`：セルの行でぶら下げが起こらず、行の内容の幅が列の幅を超えないこと。

### golem-layout の `Golem.Layout.Paginate`

- 格子の行が 4 のページに、高さ 1 の見出しの行と高さ 1 の本体の行が 5 つある表を置くと、1 ページ目に見出しと本体の 3 行、2 ページ目に繰り返した見出しと本体の 2 行が置かれること。両ページに `TableSegment` が一つずつあること。
- 同じ構成で、見出しの行に付けたラベルと注が、1 ページ目にだけ数えられること。
- ページの残りが 1 行のときに表を置くと、表が次のページから始まること。
- 高さ 2 の本体の行は、ページの残りが 1 行なら次のページへ送られ、行の途中で分かれないこと。
- 章の見出しの直後の表で、見出しの行と本体の最初の行が収まらないとき、章の見出しも次のページへ送られること。

### golem-driver

既存の `fakeFonts` を使い、テストの原稿に表を足して確かめる。

- 横組みの表を含む PDF の内容のストリームに、罫線の `re f` が三つ（表の始まり、見出しの行の下、表の終わり）あること。
- 行数の少ない版面（`lines = 5`）で二ページにまたがる表では、`re f` が六つになり、見出しの行のセルの文字のグリフが二つのページに現れること。
- 縦組みの版面では、罫線の矩形の幅が高さより小さく、セルの行がそれぞれの列の位置だけ下にずれて描かれること。
- 列の多い表で最小の幅の合計が行長を超えると G07041、本体の一行が `lines` を超える行数に折り返すと G07042 になり、PDF が書かれないこと。
- `@table src=data.csv` の表も同じく組まれること。
- 表を含む原稿で、並列と逐次で PDF のバイト列が一致し、二回のビルドでも一致すること。qpdf の検査も通ること。

既存の HTML、EPUB、プレーンテキストの golden テストが変わらないことも確かめる。
実装の後に、Golem のリポジトリの縦組みと横組みのテストの原稿に表を足して PDF を出し、列のそろい、罫線の位置、ページをまたぐ表の見出しの繰り返しを目で確かめる。

## トレードオフ

セルを本文と同じ文字の大きさで格子に載せるので、表の行の高さは格子の行の単位に固定される。
罫線は行間の空きの中央に引くので、罫線と文字の間隔は行送りと文字の大きさの差の半分しかなく、行間の狭い版面では窮屈に見える。
表の前後に格子の行を一行空けると窮屈さは和らぐが、ページの先頭と末尾でその空きを消す規則が改ページに要る。
v1 では格子のそろいと改ページの単純さを優先し、空きを入れない。

表の始まりの罫と終わりの罫は、表がページの先頭や末尾にあると、版面の外に行間の空きの半分だけはみ出す。
はみ出しは文字の大きさより小さく、裁ち落としには届かないので受け入れる。

縦組みの表を縦組みで組むので、数値の多い表は読みにくくなる。
縦組みの本で表だけを横組みにする組み方は一般的だが、組み方向の切り替えは型にも配置にも新しい仕組みが要る。
媒体のあいだで配置をそろえられ、計算を横組みと共有できる縦組みの表を v1 の形とする。

列の幅を、CSS の自動の表の配置を簡略にした規則で決める。
読者側のエンジンの結果とは一致しないが、媒体契約は提示の一致を求めないので、PDF では整数の sp で決定的に計算できる規則を優先する。
