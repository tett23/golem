# ADR 0003: PDF の見出しを見出しのスタイルの書体と大きさで組む

ステータス: 採択→見出しの既定の大きさと最小の行取りは [golem-driver ADR 0032](0032-default-heading-styles.md)、見出しの注を置く規則は [golem-layout ADR 0013](../../golem-layout/adr/0013-heading-footnotes.md)

## 文脈

`style.toml` の `[headings.<階層>]` は、見出しのフォントの役割（`font`）、文字の大きさ（`size`）、番号の書式（`number`）、改ページ（`page-break`）、柱に使うか（`running-head`）を持つ（[golem-project ADR 0002](../../golem-project/adr/0002-style-toml.md)）。
PDF のパイプライン（[ADR 0002](0002-pdf-pipeline.md)）は、このうち `number` と `page-break = "recto"` だけを使っている。
見出しは本文と同じ書体と大きさで組まれ、`font` と `size` は読み込まれるだけで出力に効かない（[仕様書の「v1 の実装で次の段階以降に回した項目」](../../specifications.md)）。

現状をコードで確かめると、次のとおりである。

- `Golem.Driver.Fonts.golemFontProvider` は `[fonts.body]`（なければ最初の役割）のファイルだけを読み込む。`LoadedFonts` の関数は役割を引数に取らず、フォントの番号は本文の和文が 0、欧文が 1 に固定されている。
- `Golem.Driver.Pdf.composeEnv` は版面の文字の大きさ（`pgFontSize`）で `ComposeEnv` を一つ作り、すべての段落と見出しをそれで組む。`SetLine` の `slSize` も常に版面の文字の大きさである。
- `Golem.Layout.Paginate` は見出しの各行を行の格子の一行として置く。文字の大きさが行送りを超える見出しは、隣の行と重なる。
- `Golem.Project.Style` は、見出しの `font` が `[fonts]` にある役割を指すかを検査していない。HTML は未知の役割を `serif` に落として黙って出力する。

見出しを別の書体と大きさで組むには、三つのことが要る。
一つ目は、複数の役割のフォントを読み込み、行分割の寸法を役割と大きさごとに測ることである。
二つ目は、本文より大きい見出しを、行の格子からずらさずにページに置く規則（行取り）である。
三つ目は、複数のフォントを使ったときのサブセット化と埋め込みの単位を決めることである。

[golem-layout ADR 0003](../../golem-layout/adr/0003-pagination-and-s2.md) は「見出しや図版のように行の格子に収まらないブロックの後は、次の格子の位置から再開する」と定めているが、見出しが何行分を占めるかは定めていない。
この ADR でその規則を決める。

## 実装すること

### style.toml の検査

- `[headings.<階層>]` の `font` が `[fonts]` にない役割を指す場合は、エラー G0308「style.toml にないフォントの役割です: <役割>」とする。
- 検査は `Golem.Project.Style.parseStyle` の `checks` に加える。PDF のターゲットに限らず、すべてのターゲットで同じ診断を出す。未知のキーをエラーにするのと同じく、綴りの誤りが見た目の劣化としてしか現れないことを防ぐためである。
- G0308 は今の G03 の番号（G0301 から G0307 と G0309）の空きである。

### 見出しの書体と大きさの決め方

階層 l の見出しの書体と大きさを、次のように決める。

- 役割：`[headings.l]` の `font`。なければ本文の役割（`body`、なければ今と同じく最初の役割）。
- 大きさ：`[headings.l]` の `size` を `dimToSp` で sp にしたもの。`zw` は版面の文字の大きさ（`pgFontSize`）を一字とする。`size` がなければ版面の文字の大きさ。
- `[headings.l]` がない階層は、本文の役割と版面の文字の大きさで組む。

見出しの番号（「第一章」）と題の間の全角の空きを含め、見出しの行の文字はすべてこの役割と大きさで組む。
目次の項目と柱は、今と同じく本文の役割と版面の文字の大きさで組む。

### 複数の役割のフォントの読み込み（golem-driver）

`Golem.Driver.Pdf.LoadedFonts` の、文字の幅とシェイピングの関数に、フォントの役割の名前を引数として加える。

```haskell
data LoadedFonts = LoadedFonts
  { lfAdvance :: Text -> Char -> Rational,      -- 役割、文字 → em 単位の送り
    lfWordAdvance :: Text -> Text -> Rational,  -- 役割、欧文の語 → em 単位の送り
    lfShape :: Text -> Bool -> Text -> [(Int, Int, Rational, Text)],
    lfCode :: Int -> Int -> Int,                -- 変えない
    lfEmbed :: Int -> Bool -> [(Int, Text)] -> P.Font  -- 変えない
  }
```

`lfShape` が返すフォントの番号は、役割の中の番号ではなく、読み込んだフォントのファイル全体の通し番号（以下、フェイスの番号）とする。
`lfCode` と `lfEmbed` はフェイスの番号を受け取るので、型を変えない。

`Golem.Driver.Fonts.golemFontProvider` は次のように読み込む。

- 読み込む役割は、本文の役割と、`[headings.*]` の `font` が指す役割とする。ほかの役割は読み込まない。仕様書の「ライセンスで埋め込みが禁止されているフォントを使った場合は、エラーとする」に合わせ、使わないフォントのライセンスでビルドを止めないためである。
- フェイスの番号は、本文の役割の和文、本文の役割の欧文、残りの役割を名前の昇順に並べた各役割の和文、欧文の順に振る。本文だけを使う文書では、番号が今と同じ（和文 0、欧文 1）になり、出力のバイト列が変わらない。
- 同じバイト列のファイルは一つのフェイスにまとめる。比較はバイト列の一致で行う。二つの役割が同じファイルを指す場合に、同じフォントを二度埋め込まないためである。
- 異なるバイト列のファイルが同じ PostScript 名を持つ場合は、エラー G0805「PostScript 名が同じ異なるフォントがあります: <名前>（<パス 1>、<パス 2>）」とする。サブセットの名前の接頭辞はグリフの集合だけから決まる（[golem-font ADR 0002](../../golem-font/adr/0002-subsetting-and-embedding.md)）ので、二つのフォントのグリフの集合が一致すると、異なるフォントが同じ `BaseFont` の名前で埋め込まれるためである。
- 役割の中で文字をどのファイルで組むかは、今の規則を役割ごとに適用する。欧文の文字（`charClass` が `Western`）は欧文のファイル、ほかは和文のファイルで組み、片方しかない役割ではその一つで組む。
- 文字の送りのキャッシュ（`memo`）は、役割と文字の組をキーにする。キャッシュは純粋な関数の結果を覚えるだけなので、出力は変わらない。
- 読み込まれていない役割の名前を渡された場合は、本文の役割として扱う。G0308 の検査があるので通常は起きないが、関数を全域にしておく。

### 行分割の寸法（golem-driver、golem-layout）

- `Golem.Driver.Pdf.composeEnv` に、組む単位の役割と文字の大きさを引数として加える。返す `ComposeEnv` の `ceFontSize` をその大きさに、`ceAdvance` と `ceWordAdvance` をその役割の `lfAdvance` と `lfWordAdvance` にする。`ceRubyOverhang` の `zw` も、その大きさを一字として sp にする。
- `buildFlow` は、`UHeading` の単位を見出しの役割と大きさの `ComposeEnv` で組み、ほかの単位は今と同じく本文の役割と版面の文字の大きさで組む。
- 見出しの行長は、本文と同じ段の行長（`measure`）とする。
- golem-layout の `ComposeEnv` と `composeInlines` は変えない。一つの段落を一つの大きさと一つの役割で組む点は今と同じであり、変わるのは段落ごとに渡す環境だけである。

### 見出しの行取り（golem-layout）

見出しの行の送りと、見出しが占める行の格子の数を、次の純粋な関数で決める。
`Golem.Layout.Paginate` に置き、エクスポートする。

```haskell
data HeadingBlock = HeadingBlock
  { hbPitch :: !Sp,   -- 見出しの行の送り
    hbSpan :: !Int,   -- 占める行の格子の数
    hbOffset :: !Sp   -- 最初の格子の位置から見出しの最初の行の字面の始まりまでの距離
  }

headingBlock
  :: Sp   -- 版面の文字の大きさ fs
  -> Sp   -- 行送り p
  -> Sp   -- 見出しの文字の大きさ s
  -> Int  -- 見出しの行数 m（1 以上）
  -> HeadingBlock
```

計算は次のとおりとする。
すべて整数の sp で行い、丸めは一度だけにする。

1. 見出しの行の送り hp = p × s / fs を有理数で計算し、最近接偶数丸め（Haskell の `round`）で整数にする。本文の行送りと文字の大きさの比を見出しにも保つ。
2. 見出しの全体の長さ（行の進む方向）E = (m − 1) × hp + s。
3. 占める格子の数 N = max 1 ⌈(E + p − fs) / p⌉。本文の m 行が m 個の格子を占めるのと同じ式であり、s = fs のとき N = m になる。
4. 占める領域の長さ R = (N − 1) × p + fs。見出しをこの領域の中央に置き、hbOffset = (R − E) `div` 2 とする。

見出しの j 行目（0 から数える）の位置は、最初の格子の番号を k として、次のとおりとする。

- 字面の始まり T_j = k × p + hbOffset + j × hp（横組みでは版面の上端から、縦組みでは右端から）。
- 横組みのベースラインは T_j + round(s × `baselineRatio`)、縦組みの行の中心線は T_j + s `div` 2。行の格子（[golem-layout-spec ADR 0001](../../golem-layout-spec/adr/0001-page-geometry.md)）と同じ定義である。

s = fs のとき、hp = p、N = m、hbOffset = 0 となり、各行の位置は今の行の格子の位置と一致する。

### 改ページ（golem-layout）

`Golem.Layout.Paginate` の型を次のように変える。

- `FHeading` に、占める格子の数 `fhSpan :: !Int` を加える。
- `Slotted` に `SHeading !Int !Int`（最初の行の番号、行数）を加える。
- 見出しは一つのブロックとして置き、ページをまたいで分けない。今は見出しの行を `placeLines` で一行ずつ置き、孤立行の規則でページをまたぐことがある。
- 次のブロックと離さない規則（`keep`）と、前のブロックの `nextNeed` には、行数の代わりに `fhSpan` を使う。
- `recto` の見出しは、今と同じく奇数ページの先頭から置く。
- 見出しの行に注の印がある場合は、その注の本文を、ブロックを置くページの下部に、`putLine` と同じ規則で置く。
- 見出しのラベルは、ブロックを置いたページのラベルとする。

`fhSpan` が 1 ページの行の格子の数を超える見出しは置けない。
golem-driver は `paginate` を呼ぶ前にこれを検査し、エラー G0724「見出しが版面に入りません（<階層> の見出し: <題>）」とする。
`paginate` は診断を返さない純粋な関数のままにする。
G0724 は改ページの番号（G072x）の空きである。
G0722 と G0723 は [ADR 0005](0005-pdf-wrapped-figures.md) の案が使う。

### 描画（golem-driver）

- `SetLine` に、その行を組んだ役割 `slFace :: !Text` を加える。`slSize` は見出しの行では見出しの大きさになる。
- `writeDocument` の `drawLine` は、行の格子の番号の代わりに、行の位置（行の方向に交わる向きの距離）を受け取る形にする。`SLine` では今と同じく `gridAt slot` を、`SHeading` では上の T_j から求めた位置を渡す。
- 行の中のグリフは、その行の `slFace` の役割で `lfShape` に渡す。ルビと圏点の大きさは、今と同じく行の大きさの半分とする。

### サブセット化と埋め込み

- 使ったグリフは、今と同じく `FontRef`（フェイスの番号 × 2 + 縦組みか）ごとに集める。フェイスの番号が増えるだけで、集め方は変えない。
- 同じファイルを本文と見出しの両方で使う場合は、上の規則で一つのフェイスになり、両方のグリフの和集合で一つのサブセットを作る。
- インスタンス ID には、今と同じく埋め込んだフォントのプログラムのバイト列を含める（[golem-pdf ADR 0001](../../golem-pdf/adr/0001-deterministic-pdf-writer.md)）。

### 決定性

[docs/adr/0002](../../adr/0002-determinism.md) の規則を次のように守る。

- フェイスの番号は、役割の名前とファイルのバイト列だけから、上の順で決まる。ディレクトリの列挙やハッシュ表の走査順に依存しない。役割の集合は `Data.Map` で持つ。
- 行取りの計算は整数の sp と有理数だけで行い、浮動小数点数を使わない。
- 段落ごとの並列の行分割は今と同じく文書の順に並べ直す。見出しの環境は単位ごとに純粋に決まるので、並列と逐次で結果は変わらない。

### ドキュメント

- 仕様書の「v1 の実装で次の段階以降に回した項目」から「見出しの書体と大きさ」を削り、「style.toml」と「フォント」の節に、見出しの行取りの規則と、`font` が未知の役割を指すとエラーになることを書く。
- README の `style.toml` の説明に同じことを書く。

## 実装しないこと

- 見出しの `running-head` と、マスターページの `content = "heading.1.short"` の解釈。今の改ページは常に 1 の階層の短い題を柱に使っており、この ADR では変えない。
- 柱、ノンブル、目次の項目を見出しの書体で組むこと。
- 見出しの前後の空き（行取りの領域の中の位置を中央以外にする設定、前後に足す行数の設定）。中央に置く規則だけを持つ。
- 見出しを本文の字送りの格子（字詰め）にそろえること。見出しの文字は見出しの大きさで詰めずに並べる。
- 傍注の `[sidenotes]` の `font` と `size`。傍注はまだ PDF に出力していない。
- 段組みで、見出しを複数の段にまたがせること（段抜きの見出し）。
- HTML と EPUB で見出しを見出しの役割の書体で組むこと。

## テスト設計

先に書いて失敗させるテストを並べる。

### golem-project（modules/golem-project/test/Main.hs）

- `[headings.1]` の `font = "nope"` を含み `[fonts.nope]` がない `style.toml` が、G0308 になること。
- `[headings.1]` の `font = "heading"` と `[fonts.heading]` を含む `style.toml` が、診断なしで読めること。

### golem-layout（modules/golem-layout/test/Main.hs）

- `headingBlock`：fs = 13Q、p = 22H、s = 20Q の場合、m = 1 で N = 2、m = 2 で N = 3 になり、hbPitch と hbOffset が上の式を sp で計算した値と一致すること。
- `headingBlock`：s = fs の場合、どの m でも N = m、hbPitch = p、hbOffset = 0 になること。
- `paginate`：`fhSpan = 3` の一行の見出しが三つの格子を占め、続く段落の最初の行が見出しの最初の格子の 3 つ後に置かれること。
- `paginate`：ページの残りが `fhSpan` に足りない場合に、見出しのブロックが分かれずに次のページの先頭に送られること。
- `paginate`：見出しの直後で改ページしない規則が、`fhSpan` と続く段落の最初の 2 行を合わせた数で判定されること。

### golem-driver（modules/golem-driver/test/Main.hs）

テストのフォントは、役割ごとに送りが変わる偽の `LoadedFonts`（今の `fakeFonts` に役割の引数を加えたもの）と、golem-font のテスト用のフォントを使う。

- 横組みの `horizontalStyle`（10pt、12 字）に `[headings.1] size = "20pt"` を加え、全角 8 字の見出しを組むと、見出しが 2 行に分かれ、内容のストリームに大きさ 20pt の `Tf` があること。同じ見出しを `size` なしで組むと 1 行になること。
- 実際のフォントで、本文の欧文を `SourceSansPro-Regular.otf`、`[fonts.heading]` の欧文を `SourceSerifVariable-Roman.ttf` とし、`[headings.1] font = "heading"` で組むと、二つの欧文のフォントが埋め込まれ、各サブセットのグリフが、そのフォントで描いた文字のグリフだけであること。ToUnicode で見出しの文字列が取り出せること。
- `[fonts.heading]` が `[fonts.body]` と同じファイルを指す場合に、フォントのプログラムが一つだけ埋め込まれること（`FontFile2` と `FontFile3` の数で数える）。
- `[headings.1]` に `font = "body"` と版面と同じ `size` を書いた `style.toml` の PDF が、それらを書かない `style.toml` の PDF とバイト列で一致すること。
- 見出しの役割を加えた入力で、並列と逐次の行分割の PDF のバイト列が一致し、二回のビルドの PDF も一致すること。
- PostScript 名が同じで、バイト列が異なる二つのフォント（テスト用のフォントの末尾に 4 バイトの 0 を足したものを作る）を本文と見出しの役割に指定すると、G0805 になること。
- 1 ページの行の格子の数を超える見出し（`horizontalStyle` の行数を 3 にした版面に 60pt の見出し。N = 5 になる）が G0724 になること。
- 出力の PDF を qpdf で検査し、今の PDF/X-4 の検査（[golem-pdf ADR 0002](../../golem-pdf/adr/0002-pdf-x-4.md)）を通ること。

自動テストにしない確かめ方として、実装の後に `golem new` の和文の雛形に `[fonts.heading]` と `[headings.1] size = "20Q"` を加えてビルドし、見出しが二行分の領域の中央に置かれ、続く本文が行の格子にそろうことを目で確かめる。

## トレードオフ

見出しの行取りを、本文の行送りと文字の大きさの比から自動で決めるので、利用者は「3 行取り」のように行数を直接指定できない。
行数の指定は日本語組版で一般的な設定だが、v1 では設定の数を増やさず、大きさから決まる最小の行数で組む。
行数を指定する設定は、要望が出たときに新しい ADR で `[headings.<階層>]` のキーとして足す。

見出しをページをまたいで分けないので、版面の行数より長い見出しは組めず、エラーになる。
見出しは短いことが前提であり、分けて組むと柱と目次の扱いも決める必要が生じるため、エラーで止める。

PostScript 名が同じで中身の異なるフォントをエラーにするので、同じフォントの異なる版を本文と見出しに使い分けることはできない。
サブセットの名前の規則（[golem-font ADR 0002](../../golem-font/adr/0002-subsetting-and-embedding.md)）を変えれば許せるが、その規則を変えると既存のすべての PDF の出力が変わる。
まれな構成のために出力を変えることは避ける。

使う役割のフォントだけを読み込むので、使わない役割のファイルが壊れていても、PDF のビルドは通る。
ファイルの存在は `loadStyle` が検査しているので、パスの誤りは今と同じくエラーになる。
