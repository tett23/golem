# ADR 0031: 表の前後の空きと罫線

ステータス: 採択

## 文脈

fixture の The Elements of Style（[docs/adr/0026](../../adr/0026-ten-public-domain-fixtures.md)）の PDF の 39 ページで、表の組み方に三つの問題が見つかった。
ロードマップの「表の前後の空きと罫線」の項目である。

- 表の上の罫が、前の段落の最後の行の文字（g や p の下に伸びた部分）に接する。
- 表の下の罫が、表の最後の行の文字の下に伸びた部分を横切る。
- 見出しの行が空の表で、罫が一行の間隔で二本並ぶ。

### 再現

今の `main`（e3e19da）で fixture を組み、39 ページを PDFKit で画像にして確かめた。
版面は本文 10pt、行送り 14pt で、本文の欧文のフォントは Source Serif である。
罫の位置は [ADR 0008](0008-pdf-tables.md) のとおり、隣り合う格子の行の字面の枠のあいだの空きの中央にある。
字面の枠は、格子の行の上端から文字の大きさ（10pt）の範囲で、基準線はその上端から 8.8pt（0.88 倍）下にある。
空きは 14 − 10 = 4pt なので、上の罫の中心は前の行の基準線の 3.2pt 下、下の罫の中心は表の最後の行の基準線の 3.2pt 下になる。
Source Serif の p と g の字面は基準線の 2.45pt 下まで、y は 2.55pt 下まで伸びる（CoreText で測った字形の外接矩形）。
太さ 0.6pt の罫の上端は基準線の 2.9pt 下なので、字面とのすき間は 0.35pt から 0.45pt しかなく、画像では接して見える。

この表は `| | |` の見出しの行（セルがすべて空）を持つ。
空の見出しの行も格子の一行を取り、その上に表の始まりの罫、その下に見出しの行の下の罫が引かれるので、罫が 14pt の間隔で二本並ぶ。

### 原因

三つの問題には、別々の原因がある。

一つめは、罫の位置を決める字面の枠が、欧文の字面を覆わないことである。
字面の枠の下端は基準線の 0.12 倍下にあるが、欧文の小文字の下に伸びる部分は 0.25 倍前後まで下がる。
和文の字形は字面の枠に収まるので、縦組みと和文の横組みではこの問題は起きない。
行送りが文字の大きさの 1.4 倍の欧文の版面では、罫を置く空きが文字の大きさの 0.4 倍しかなく、そのうちの 0.13 倍ほどを字面が使う。

二つめは、表の前後に空きを置く規則がないことである。
[ADR 0008](0008-pdf-tables.md) は、表の最初の行を前の段落の次の格子の行に置き、表の次の段落を表の最後の行の次の格子の行に置く。
罫は行のあいだの空きに収めるので、罫と前後の本文のあいだは、行送りから文字の大きさを引いた空きの半分しかない。

三つめは、セルがすべて空の行も一行の高さを持つことである。
golem-layout の `layoutTable` は、行の高さをセルの行数の最大値と 1 の大きいほうにする（`maximum (1 : ...)`）。
本体の空の行に一行を与えるのは正しいが、見出しの行がすべて空の場合は、Markdown の表の書き方で見出しを持たない表を書いたものと読める。
The Elements of Style の二列の例文は、見出しのない表をこの形で書いている。

### 罫の位置の考え方

欧文の書籍の表（LaTeX の booktabs など）では、罫は表の文字のすぐ外に引き、罫と前後の本文のあいだには別に空きを取る。
罫と字面のすき間を表の内側と外側で同じにすると、罫が表の一部に見える。
行の格子の上では、空きの量を格子の行の単位にすれば、表の後の本文が格子からずれない（[golem-layout ADR 0004](../../golem-layout/adr/0004-wrapped-figures.md) の図版と同じ考え方）。

罫と字面のすき間は、字面の実際の範囲で測る必要がある。
フォントの `hhea` の上昇と下降の値は、行の高さのための値であり、Source Serif では上昇が 1.036 倍と字面より大きい。
golem-driver は、圏点の位置のために FreeType からグリフの字面の範囲を読む `lfInkBox` を既に持つ（[ADR 0019](0019-pdf-kenten-shapes.md)）。
表のセルに描くグリフの字面の範囲から、表の字面の上端と下端を求められる。

### メンテナーが決めたこと

- 表の前後の空きは、格子の一行で足りる。空きの量などの細かい設定は、v2 の「表の拡張」の `style.toml` の設定で扱う。
- HTML と EPUB は、空の見出しの行を今のとおり空の `<thead>` の行として出す。

## 実装すること

### 空の見出しの行

- 見出しの行のすべてのセルが、空白のほかに中身を持たない場合、PDF ではその表を見出しの行のない表として組む。
- 見出しの行のない表は、見出しの行の格子の行を持たず、見出しの行の下の罫を引かず、ページをまたいでも見出しの行を繰り返さない。
- 表のラベルと注は、見出しの行の代わりに本体の最初の行の格子の行に付く。空の見出しの行には注も索引の印も書けないので、失われるものはない。
- 列の幅の計算では、見出しの行のセルを今のとおり数える（空のセルの幅は 0 なので、結果は変わらない）。

### 表の前後の空き

- 表の前に格子の一行の空きを置く。ただし、段（一段の版面ではページ）の最初の行から表が始まる場合と、表の直前が見出しの場合は置かない。見出しには見出しの行取りの空きがあるためである。
- 表の後に格子の一行の空きを置く。段の最後の行で表が終わる場合は置かず、次の段の先頭にも空きを持ち越さない（今の韻文の連のあいだの空き `FSpace` と同じ扱い）。
- 表が二つ続く場合、そのあいだの空きは一行とする。
- ページをまたぐ表の続きの部分は、次の段の最初の行から始まるので、前の空きを持たない。
- 段落スタイルの段落の間隔（`space-between`、[docs/adr/0005](../../adr/0005-character-and-paragraph-styles.md)）は、表の前後の空きに足す。
- 表を置き始める位置の判定（見出しの行と本体の最初の行が収まるか、[ADR 0008](0008-pdf-tables.md)）と、見出しの直後で改ページしない規則（golem-layout の `nextNeed`）は、前の空きの一行を含めて数える。

### 罫の位置

罫の中心の位置を、表の字面の上端と下端から決める。
行の進む方向に直交する向き（横組みでは下向き、縦組みでは左向き）に、段の始まりからの距離で書く。

- 横組みでは、表の字面の上の高さ `a` と下の深さ `d` を、表のすべてのセル（見出しの行を含む）に描くグリフの `lfInkBox` から求める。`a` はグリフの字面の上端の基準線からの高さの最大値、`d` は下端の基準線からの深さの最大値とし、それぞれグリフの文字の大きさを掛けて sp に丸める。字面の範囲を持つグリフが一つもない場合は、字面の枠（`a` は文字の大きさの 0.88 倍、`d` はその残り）を使う。
- 縦組みでは、`a` と `d` を字面の枠の半分ずつ（文字の大きさの半分）とする。縦組みの和文の字形は字面の枠に収まるためである。
- すき間 `c` を `max 0 ((p − a − d) div 2)` とする。`p` は行送りである。隣り合う二行の字面のあいだの空きの半分にあたる。
- 格子の行 `k` の基準線（縦組みでは行の中心線）の位置を `B k` とすると、表の始まりの罫の中心は `B first − a − c`、見出しの行の下の罫の中心は `B headerEnd + d + c`、表の終わりの罫の中心は `B last + d + c` とする。
- 縦組みでは、この式は [ADR 0008](0008-pdf-tables.md) の位置（字面の枠のあいだの空きの中央）と同じ値になる。横組みの和文でも、字面が字面の枠に近いので、ほぼ同じ位置になる。
- 罫の太さ（0.6pt と 0.3pt）と長さ（表の幅）は変えない。

計算はすべて整数の sp で行う（[docs/adr/0002](../../adr/0002-determinism.md)）。
字面の範囲はフォントのファイルから決まるので、出力は決定的である。

### データ構造

golem-layout の `Golem.Layout.Table` の `layoutTable` は、見出しの行のセルの一覧が空のとき、`stHeader` を空にし、`stHeaderLines` を 0 にする。
ドライバーは、空の見出しの行を空の一覧として渡す。

golem-layout の `Golem.Layout.Paginate` を次のように変える。

```haskell
data Flow
  = ...
  | FTable
      { ftId :: !Int,
        ftSpaceBefore :: !Int, -- 表の前の空き（格子の行の数）。段の最初の行では使わない
        ftHeader :: ![LineBox], -- 空なら見出しの行のない表
        ftRows :: ![[LineBox]]
      }

data TableSegment = TableSegment
  { tsTable :: !Int,
    tsFirst :: !Int,
    tsHeaderEnd :: !(Maybe Int), -- 見出しの行の最後の格子の行。見出しの行のない表は Nothing
    tsLast :: !Int
  }
```

- `placeTable` は、段の最初の行でなければ `ftSpaceBefore` の行を空けてから表を置く。空きを含めて見出しの行と本体の最初の行が収まらなければ、空きを置かずに次の段から始める。
- `nextNeed` の `FTable` は、`ftSpaceBefore`、見出しの行の高さ、本体の最初の行の高さの和とする。
- 表の後の空きは、ドライバーが `FTable` の後に `FSpace 1` を置いて表す。表が二つ続く場合は、後の表の `ftSpaceBefore` を 0 にする。

golem-driver の `Golem.Driver.Pdf` は、表の番号から表の幅を引く `plTables :: Map Int Sp` を、幅と `a` と `d` を持つ値の表にする。

```haskell
data TableGeometry = TableGeometry
  { tgWidth :: !Sp,
    tgAscent :: !Sp, -- 表の字面の上の高さ a
    tgDescent :: !Sp -- 表の字面の下の深さ d
  }
```

`tableRules` は、`tsHeaderEnd` が `Nothing` の部分では見出しの行の下の罫を引かない。

### ドキュメント

- 仕様書の「表」の節の罫線の項目を、罫を表の字面の外にすき間 `c` を空けて引く形に書き直し、表の前後の一行の空きと、空の見出しの行を見出しのない表として組むことを加える。この ADR へのリンクを付ける。
- [ADR 0008](0008-pdf-tables.md) のステータスの行を「採択→罫線の位置、表の前後の空き、空の見出しの行は [ADR 0031](0031-table-spacing-and-rules.md)」に変える。
- ロードマップから「表の前後の空きと罫線」の項目を消す。
- 利用者のマニュアルの付録I（`manual/appendices/i-known-issues.gm`）から「表の前後に空きがない」の項目を消す。付録H に同じ項目があれば消す。
- 利用者のマニュアルの「表」の節（`manual/chapters/03-markup.gm`）の PDF の説明に、表の前後に一行の空きを置くことと、見出しの行のセルをすべて空にすると PDF では見出しの行のない表になることを加える。

## 実装しないこと

- 前後の空きの量と罫と字面のすき間の設定。v2 の「表の拡張」の `style.toml` の設定で扱う。
- HTML、EPUB、プレーンテキストの空の見出しの行の扱いを変えること。HTML と EPUB は今のとおり空の `<thead>` の行を出す。
- 表の上下の罫を、前後の本文と表のあいだの空きの中央に置く組み方。「トレードオフ」を参照。
- 縦組みの表で、横に回した欧文の字面の範囲を測ること。縦組みは今のとおり字面の枠で決める。
- 行送りが字面の高さより狭い版面（`a + d > p`）で、罫と字面が重ならないようにすること。`c` を 0 にして字面に接して引き、それ以上は調整しない。

## テスト設計

実装の前に書き、失敗することを確かめる。
テストの偽のフォントは、どのグリフの字面も基準線の 0.8 倍上から 0.1 倍下までとしている（`modules/golem-driver/test/Support.hs` の `lfInkBox`）。
`horizontalStyle`（10pt、行送り 15pt）では `a` = 8pt、`d` = 1pt、`c` = 3pt になる。

### golem-layout（`modules/golem-layout/test/Main.hs`、`PaginateSpec.hs`）

- `layoutTable` に空の見出しの行を渡すと、`stHeader` が空で `stHeaderLines` が 0 になる。
- 段の途中から始まる `FTable`（`ftSpaceBefore` = 1）の `tsFirst` が、前の行の次の次の格子の行になる。
- 段の最初の行から始まる `FTable` の `tsFirst` が、その段の最初の行になる。
- 空きを含めると見出しの行と本体の最初の行が収まらない位置では、表が次の段の最初の行から始まり、前の段には空きの行を残さない。
- 見出しの後の `FTable` が、見出しの直後で改ページしない規則で、空きの一行を含めて数えられる。
- 見出しの行のない表がページをまたぐと、どの部分も `tsHeaderEnd` が `Nothing` で、次のページの部分が本体の行から始まる。

### golem-driver（`modules/golem-driver/test/ReferencesSpec.hs`）

- `前。`、表、`後。` の横組みの本で、表の最初の行のグリフの基準線が `前` の基準線の 2 行送り（30pt）下にあり、`後` の基準線が表の最後の行の基準線の 2 行送り下にある。
- 同じ本で、表の始まりの罫の中心が表の最初の行の基準線の 11pt（`a + c`）上にあり、見出しの行の下の罫と表の終わりの罫の中心が、それぞれの行の基準線の 4pt（`d + c`）下にある。
- 見出しの行が `| | |` の表で、罫が二本だけ引かれ、本体の最初の行が表の前の空きの次の格子の行にある。
- 見出しの行が空の表がページをまたぐと、二ページめの表の部分に罫が二本だけ引かれ、本体の行から始まる。
- 表で始まる本で、表の最初の行が版面の最初の格子の行にある。
- 縦組みの表で、罫の位置が今と同じ（隣り合う字面の枠のあいだの空きの中央）であり、表の前後に一行の空きがある。
- 表が二つ続く本で、二つの表のあいだの空きが一行である。
- 見出しの行が `| | |` の表の HTML と EPUB の出力が、今のとおり空のセルの `<thead>` の行を持つ。
- 既存の表のテスト（罫が三本、ページをまたぐ表、CSV の表、並列と逐次で同じバイト列）が、行の位置を前後の空きの分だけ直したうえで通る。

### 自動テストにしない確かめ方

- fixture の The Elements of Style を組み、39 ページを画像にして、罫が前の段落と表の最後の行の字面に接しないこと、空の見出しの行の罫が二重にならないこと、表の前後に空きがあることを目で確かめる。
- 蟹工船の原稿に縦組みの表を足して組み、罫の位置が変わらず、前後に一行の空きが入ることを目で確かめる。
- 二つのマニュアルの表のあるページを画像にして、同じことを確かめる。

## トレードオフ

罫を表の字面のすぐ外に置き、前後の本文とのあいだは格子の一行の空きで分けた。
罫を空きの行の中央に置けば、罫と前後の本文の距離はそろうが、罫と表の距離が開き、罫が表から離れて見える。
LaTeX の booktabs の組み方に近い、罫を表に寄せる形を採った。
代わりに、表の上の罫の上（前の段落とのあいだ）は、罫の下（表の最初の行とのあいだ）よりずっと広くなる。

空きを格子の一行にしたので、行送りが大きい版面では空きが広すぎる場合がある。
半行の空きは、後の本文を格子からずらすので採れない。
表の行を格子から外して空きを細かく決める組み方は、[ADR 0008](0008-pdf-tables.md) の、セルの行を格子に載せる枠組みを崩す。

罫と字面のすき間を、表に実際に描くグリフの字面から求めた。
表ごとに字面の範囲が違えば、罫の位置も表ごとにわずかに違う。
下に伸びる字のない表（数字だけの表など）では、下の罫が字に寄る。
フォントの全グリフから求める形は、使わない字形（下に深く伸びる記号など）に引きずられて罫が離れすぎ、`hhea` の値は Source Serif のように字面より大きいので、どちらも採らなかった。

見出しの行の判定を、セルがすべて空かどうかで行った。
記法に見出しの行のない表を書く手段がなく、Markdown の表でも同じ書き方が広く使われているためである。
見出しの行に空白だけを書いた表を、見出しのある表として組みたい場合は、表せなくなる。
