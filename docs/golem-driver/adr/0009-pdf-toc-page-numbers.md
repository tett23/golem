# ADR 0009: PDF の目次にページ番号を出す

ステータス: 採択

## 文脈

[仕様書](../../specifications.md) の「目次と文書構造の参照」の節は、PDF の目次を章題とページ番号の一覧と定めている。
今の PDF の目次は、番号と題だけを出し、ページ番号を出していない（[仕様書の「v1 の実装で次の段階以降に回した項目」](../../specifications.md)）。

現状をコードで確かめると、次のとおりである。

- `Golem.Driver.Pdf` の `unitsOf` は、`ChannelOutput (TocOutput depth)` を、`bookToc` の項目ごとに一つの `UPara` の単位に写す。単位の中身は、見出しの番号、全角の空白、短い題（`teTitle`）であり、索引の印は除いてある。行長は本文と同じ段の行長（`measure`）で、ほかの段落と区別されない。
- 目次の項目 `TocEntry`（`Golem.Doc.Assemble`）は、階層、番号の文字列、題、HTML のアンカー、ファイルを持つが、見出しのブロックの `SrcSpan` を持たない。見出しの情報の表 `bookHeadings` はブロックの `SrcSpan` を鍵にしているので、項目から見出しの位置を引けない。
- ページ番号への参照は、ラベルからページを引く。`LineBox` の `lbLabels` には `@label` で付けたラベルだけが入り、ラベルのない見出しはページを引く鍵を持たない。
- [ADR 0007](0007-pdf-index-and-bibliography.md) は、索引の印の `SrcSpan` を `lbMarks` と `poMarks` で改ページまで運び、`markPages` で印のページの表を作った。`fixpoint` は、ラベルのページと印のページの組（`Assumed`）が変わらなくなるまで組み直す。上限は `maxIterations`（5 回）である。
- 見出しは `FHeading` のブロックとして置かれ、ページには `SHeading` の最初の行の番号として残る（[ADR 0003](0003-pdf-heading-styles.md)）。

目次にページ番号を出すには、三つのことを決める必要がある。
一つ目は、目次の項目から、その見出しが置かれたページを引く方法である。
二つ目は、目次の行の形（リーダー、ページ番号の位置、縦組みでの表記）である。
三つ目は、目次が複数のページにまたがる場合に、ページ番号の解決が収束することの保証である。

三つ目の問題は、次の機構で起きる。
目次は普通は本文より前に置く。
ページ番号を目次の項目の段落に入れて行分割すると、ページ番号の表記の幅が題の折り返しを変え、目次の行数を変える。
目次の行数が変わって目次のページ数が一ページ増えると、目次より後のすべてのページの番号が一つずれ、目次のページ番号の表記が再び変わる。
`page-break = "recto"` の見出しがあると、ページの偶奇が変わって白ページの有無も変わるので、ずれはさらに大きくなる。
索引のページ番号（[ADR 0007](0007-pdf-index-and-bibliography.md)）も同じ循環を持つが、索引は普通は巻末にあり、後ろのページを動かさない。
目次は巻頭にあるので、同じ方法を採ると、本のすべてのページ番号が目次の組み方に依存する。

## 実装すること

### 見出しの位置を目次の項目に持たせる（golem-doc）

`Golem.Doc.Assemble` の `TocEntry` に、見出しのブロックの `SrcSpan` を加える。

```haskell
data TocEntry = TocEntry
  { teLevel :: !Int,
    teNumber :: !(Maybe Text),
    teTitle :: ![Inline],
    teAnchor :: !Text,
    teFile :: !FileId,
    teSpan :: !SrcSpan -- 見出しのブロックの位置。bookHeadings の鍵と同じ
  }
```

`assemble` の `toc` の内包表記は、すでに見出しのブロックの `sp` を束縛しているので、それを渡す。
HTML、EPUB、プレーンテキストは `teSpan` を読まない。

### 見出しのページを求める（golem-driver）

見出しのページは、ラベルのページ（`labelPages`）と索引の印のページ（`markPages`）と同じく、改ページの結果の `PageOut` から求める。

- `Golem.Driver.Pdf` の `Built` に、見出しの最初の行の番号からその見出しのブロックの `SrcSpan` への表 `bHeadingSpans :: Map Int SrcSpan` を加える。`buildFlow` の `step'` が `UHeading` の単位に番号を振るときに、`nextId` と `uSpan u` を積む。
- 次の関数を `Golem.Driver.Pdf` に加え、エクスポートする。

```haskell
headingPages :: Map Int SrcSpan -> [PageOut] -> Map SrcSpan Integer
-- 見出しの最初の行の番号から位置への表、ページ
```

各ページの `poSlots` の `SHeading lid _` について、`lid` を表で引き、その見出しの位置をページの番号に写す。

見出しのページの鍵は、ラベルの名前ではなく見出しのブロックの `SrcSpan` とする。
ラベルのない見出しにも目次の項目はあり、合成のラベルを作ると、利用者のラベルの名前空間と衝突しうるためである（[ADR 0007](0007-pdf-index-and-bibliography.md) が印をラベルの表に入れなかった理由と同じ）。

見出しのページの表は、`Assumed` に入れず、S2 の繰り返しの外で、収束した最終回のページから一度だけ作る。
次の節の行の形では、ページ番号が行分割にも改ページにも影響しないためである。
傍注の配置を収束の後に一度だけ行う [ADR 0006](0006-pdf-sidenotes.md) と同じ扱いになる。

### 目次の行の形

目次の項目を、次の形で組む。

- 項目の中身は、今と同じく、番号、全角の空白、短い題の並びとする。
- 階層 l の項目は、すべての行を (l − 1) 字下げする。字の大きさは版面の文字の大きさ fs とする。
- 行の終わりの側に、ページ番号のための幅 R を予約する。項目のすべての行を、行長 `measure − 字下げ − R` で組む。
- ページ番号は、項目の最後の行に、行の終わり（横組みでは版面の右端、縦組みでは版面の下端）にそろえて置く。字下げにかかわらず、すべての項目のページ番号の終わりは同じ位置になる。
- 最後の行の題の終わりとページ番号のあいだを、**リーダー**（題とページ番号を結ぶ点の列）で埋める。

各寸法は次のとおりとする。

- 空き g = fs ÷ 2。題とリーダーのあいだ、リーダーとページ番号のあいだに置く。
- ページ番号の幅の見込み W は、ページ番号 999 を目次の項目と同じ環境で組んだ幅とする。三桁のページ番号を収める幅である。
- 予約の幅 R = W + 2 × fs。二つの空き g と、少なくとも一字分のリーダーを収める。
- リーダーの一字 u は、目次の項目の見た目で「…」（U+2026）の送りを測った幅とする。`charClass` が `Inseparable` の文字なので、和文の側の役割で組まれる。縦組みでは、縦書きの字形に置き換わった三点リーダーになる。

ページ番号は、[ADR 0007](0007-pdf-index-and-bibliography.md) の索引と同じく、`Number` の inline として組む。
横組みでは算用数字、縦組みでは `[numbers]` の `vertical` の表記（既定では漢数字）になる。
ページ番号も数なので、ほかの数と同じ経路で表記を決めるという仕様（[仕様書](../../specifications.md) の「目次と文書構造の参照」）に従う。
数はページの通し番号（`poNumber`）であり、マスターページのノンブルの書式（`format`）は使わない。
索引のページ番号と同じ扱いである。

### リーダーとページ番号の位置の計算

最後の行の配置を、純粋な関数で決める。
`Golem.Driver.Pdf` に置き、エクスポートする。

```haskell
data TocGeometry = TocGeometry
  { tgMeasure :: !Sp,     -- 段の行長
    tgReserve :: !Sp,     -- W
    tgGap :: !Sp,         -- g
    tgLeaderUnit :: !Sp,  -- u
    tgLeaders :: !Bool,   -- [toc] leader が dots か
    tgLook :: !Look       -- リーダーを組む見た目
  }

data TocPage = TocPage
  { tpLeaderStart :: !Sp, -- 行の始まりからリーダーの始まりまで
    tpLeader :: !Line,     -- リーダーの字を並べた行（空でもよい）
    tpNumberStart :: !Sp,  -- 行の始まりからページ番号の始まりまで
    tpNumber :: !Line      -- ページ番号を組んだ行
  }

tocPage :: TocGeometry -> Sp -> Line -> TocPage
-- 最後の行の題の終わり e（行の始まりからの距離、字下げを含む）、ページ番号の行
```

ページ番号の行の幅を w（`tpNumber` の箱の幅の和）として、次のように決める。
すべて整数の sp で計算する。

1. ページ番号の始まり ns = measure − w。
2. リーダーの終わり le = measure − max W w − g。w が W 以下なら、le はページ番号によらず一定になり、上下（縦組みでは左右）の項目のリーダーの点の位置がそろう。
3. リーダーの字数 k = max 0 ((le − (e + g)) `div` u)。`[toc] leader = "none"` なら k = 0 とする。
4. リーダーの始まり ls = le − k × u。リーダーは終わりの側にそろえて並べ、余りは題の側に寄せる。
5. ns < e + g なら、ページ番号を ns = e + g に置き、k = 0 とする。題の最後の行が行長を超えて組まれた場合（`lineOverfull`）にだけ起こり、その行と同じくページ番号も版面の外にはみ出す。

e は最後の行を `placeLine` で配置したときの最後の箱の終わりに、字下げを足した値とする。
最後の行は `measure − 字下げ − R` で組まれているので、行長を超えなければ e ≤ measure − R である。
このとき 5 の場合が起こるのは w > W + g + fs のときだけであり、横組みの算用数字では 6 桁、縦組みの漢数字では 6 字（千二百三十四）を超えるページ番号に当たる。

`tpLeader` は、幅 u、中身「…」、見た目 `tgLook` の箱を k 個並べた `Line` とする。
行分割は通さず、`Line` を直接作る（比率 0、伸縮 0）。
`tpNumber` は、`[Number sp0 n Nothing]` を目次の項目の環境で `composeInlines` した箱を並べた `Line` とする。
縦中横（`tcy`）の表記も、今の `composeInlines` と描画の経路でそのまま組める。

### 単位と流れ（golem-driver）

- `UnitKind` に `UTocEntry !Int !SrcSpan`（階層、見出しの位置）を加え、`unitsOf` は目次の項目をこの単位に写す。中身は今の `UPara` と同じとする。
- `buildFlow` の `widthOf` と `lineIndent` は、`UTocEntry l _` の行長を `measure − (l − 1) × fs − R`、字下げを `(l − 1) × fs` とする。
- 流れは、今と同じく `FParagraph` とする。目次の項目は段落と同じ孤立行の規則でページをまたいでよい。ページ番号は最後の行と一緒に次のページへ移る。
- `Built` に、目次の項目の最後の行の番号から、見出しの位置と e への表 `bTocLines :: Map Int (SrcSpan, Sp)` を加える。

`layoutPdf` は、`fixpoint` が収束した後に、次の順で目次のページ番号を決める。

1. 最終回の `bHeadingSpans` とページから `headingPages` を作る。
2. `bTocLines` の各項目について、見出しのページ n を引き、`tocPage` で `TocPage` を作る。ページを引けない項目には `TocPage` を作らず、題だけを出す。正しく組めていれば起こらないので、テストで起こらないことを確かめる。
3. 結果を `PdfLayout` の `plTocPages :: !(Map Int TocPage)`（最後の行の番号ごと）に入れる。

`TocGeometry` の W と u は、目次の項目の環境（本文の役割と fs の `composeEnv`）で一度だけ測る。

### 描画（golem-driver）

`writeDocument` の `drawPage` は、`SLine lid` の行に `plTocPages` の項目がある場合、その行の格子の位置 `gridAt slot` で、次の二つを描く。

- `drawLine ta (gridAt slot) (SetLine (tpLeader tp) fs (tpLeaderStart tp) [] [])`
- `drawLine ta (gridAt slot) (SetLine (tpNumber tp) fs (tpNumberStart tp) [] [])`

`slIndent` に始まりの距離を渡すので、`drawLineAt` の既存の計算で横組みと縦組みの両方に置ける。
リーダーとページ番号のグリフは、`drawLineAt` が返す使用済みのグリフに含まれるので、フォントのサブセットにも入る。

`layoutPages` は、目次の項目の最後の行の文字列に、リーダーの字とページ番号の文字列をこの順に足す。
テストで行の文字列からページ番号を確かめるためである。

### style.toml（golem-project）

`[toc]` の表を加える。

```toml
[toc]
leader = "dots"   # "dots"（既定）か "none"
```

- `Style` に `stTocLeader :: !Text` を加え、既定を `"dots"` とする。値は `enumKey` で検査し、ほかの値は今の未知の値と同じく G0306 とする。
- `"none"` はリーダーを描かない。ページ番号の位置と予約の幅 R は `"dots"` と同じである。
- HTML、EPUB、プレーンテキストは `[toc]` を読まない。

目次の項目の書体と大きさを指定する欄は、この ADR では設けない。
設ける場合は、[ADR 0010](0010-caption-style.md) のキャプションと [ADR 0011](0011-sidenote-font.md) の傍注と同じく、`[toc]` の `font` と `size` の名前にする。

### S2 の繰り返しとの関係

目次の項目の行分割は、題（S0 で決まる）、番号（S1）、版面の寸法、予約の幅 R だけで決まる。
R はページ番号 999 の幅から決まり、実際のページ番号によらない。
ページ番号は行分割の後に、予約の幅の中へ描くだけなので、目次の行数と目次のページ数は、S2 のどの回でも同じになる。
したがって、目次のページ番号が後のページを動かすことはなく、繰り返しの回数も増えない。

見出しの中で S1 と S2 の値を参照することはエラーなので（[仕様書](../../specifications.md) の「目次と文書構造の参照」）、題の幅が S2 で変わることもない。

### 決定性

- 見出しのページの表は、最終回のページの `poSlots` の順と `Data.Map` だけから決まる。
- W、u、g、R、リーダーの字数とページ番号の位置は、整数の sp だけで計算する。
- 並列と逐次の行分割は、今と同じく文書の順に並べ直してから番号を振るので、`bHeadingSpans` と `bTocLines` の番号も一致する（[docs/adr/0002](../../adr/0002-determinism.md)）。

### ドキュメント

- [仕様書](../../specifications.md) の「v1 の実装で次の段階以降に回した項目」から「目次」を削る。
- [仕様書](../../specifications.md) の「目次と文書構造の参照」の節に、PDF の目次の行の形（階層ごとの字下げ、ページ番号の予約の幅と位置、リーダー、ページ番号の表記）と、目次のページ番号が改ページを変えないことを書き、この ADR へのリンクを付ける。
- [仕様書](../../specifications.md) の `style.toml` の例と説明に `[toc]` の `leader` を加える。
- [記法の仕様](../../markup.md) の `@toc` の説明に、PDF ではページ番号を出すことを書く。

## 実装しないこと

- 目次の項目の書体と大きさ（`[toc]` の `font` と `size`）、階層ごとの書体の切り替え。項目は本文の役割と版面の文字の大きさで組む（[ADR 0003](0003-pdf-heading-styles.md) の決定のまま）。
- 字下げの幅、空き、予約の幅、リーダーの字を `style.toml` で変える設定。
- 題が二行以上に折り返したときの、二行目以降のぶら下げ（番号の幅だけ下げること）。
- ページ番号の書式（ノンブルの `format`、ローマ数字の前付けのノンブル）を目次に使うこと。
- 前付けと本文でページ番号を振り直すこと。ページ番号は今と同じく本の通し番号とする。
- 章ごとの小目次（[仕様書](../../specifications.md) の「v2 以降に回した事項」）。
- 図目次と表目次。
- HTML、EPUB、プレーンテキストの目次の変更。これらはページを持たないので、今のリンクの一覧と題の一覧のままとする。EPUB の `page-list` も扱わない。

## テスト設計

先に書いて失敗させるテストを並べる。

### golem-doc（modules/golem-doc/test/AssembleSpec.hs）

- 二つの見出しと `@toc` を持つ文書を `assemble` すると、各 `TocEntry` の `teSpan` が見出しのブロックの `SrcSpan` に一致し、`bookHeadings` の鍵であること。
- `@notoc` の見出しの位置が `bookToc` の `teSpan` に現れないこと。

### golem-project（modules/golem-project/test/Main.hs）

- `[toc]\nleader = "none"\n` が読め、`stTocLeader` が `"none"` になること。`[toc]` がなければ `"dots"` になること。
- `[toc]\nleader = "dash"\n` と `[toc]\nfont = "body"\n` が G0306 になること。

### golem-driver の単体のテスト（modules/golem-driver/test/Main.hs）

`tocPage` に、fs = 10pt、measure = 120pt、W = 15pt、g = 5pt、u = 10pt、リーダーありの `TocGeometry` と、手で作った幅 10pt のページ番号の `Line` を与える。

- e = 60pt のとき、k = 3、`tpLeaderStart` = 70pt、`tpNumberStart` = 110pt になること。
- e = 62pt のときも `tpLeaderStart` = 70pt であり、リーダーの終わりが e = 60pt の場合と同じ 100pt になること（点の位置がそろうこと）。
- e = 85pt のとき、k = 1、`tpLeaderStart` = 90pt になること。
- 幅 20pt のページ番号（W を超える）では、`tpNumberStart` = 100pt、リーダーの終わりが 95pt になること。
- e = 118pt（行長を超えた行）、幅 10pt では、`tpNumberStart` = 123pt、k = 0 になること。
- `tgLeaders = False` では、どの e でも k = 0 で、`tpNumberStart` がリーダーありの場合と同じになること。

### golem-driver のレイアウトのテスト

フォントは `fakeFonts`（全角 1 em、半角 1/2 em）を使う。
横組みは `horizontalStyle`（10pt、12 字）、ページの少ない版面は `fiveLines`（5 行）とする。
W は「999」の 15pt、R は 35pt になる。

- `@toc depth=2` と、二つの章の見出しを持つ原稿の `flowLines` で、目次の一段目の項目の行の `lineTarget` が 85pt、字下げが 0 であり、二段目の項目の行の `lineTarget` が 75pt、字下げが 10pt であること。
- `pagesMini` と `fiveLines` で、`@toc` の後に 12 個の章の見出しと、それぞれ数行の本文を置く。目次が 3 ページにまたがり、各項目の行の文字列の末尾のページ番号が、その見出しの題が現れるページの番号に一致すること。
- 同じ原稿で、`flowLines`（ページ番号を仮定しない一回目）の目次の行と、`layoutPdf` の最終回の `plLines` の目次の行が、行数と各行の箱の並びで一致すること。目次の行がページ番号に依存しないことの確認である。
- 見出しのページが 9 ページから 10 ページに繰り上がる原稿（[ADR 0007](0007-pdf-index-and-bibliography.md) のテストの、段落を足して印のページを 9 から 10 に繰り上げる原稿と同じ組み立て）で、目次に `10` が出て、エラーなしに収束すること。
- `[headings.1] page-break = "recto"` の見出しが白ページの後の奇数ページに置かれる原稿で、目次のページ番号がその奇数ページであること。
- `plTocPages` が、`bookToc` のうち深さに入るすべての項目の最後の行に `TocPage` を持つこと（ページを引けない項目がないこと）。
- `[toc] leader = "none"` で、目次の行の文字列に「…」が現れず、ページ番号は現れること。
- 縦組みの `pdfStyle` で、目次のページ番号が `Number` として組まれ、`[numbers]` の既定の漢数字（3 ページなら「三」）の文字が目次の行に現れること。
- 目次の項目のページ番号のグリフが PDF の内容に現れ、そのグリフの x 座標（横組み）が、すべての項目で、ページ番号の終わりが版面の右端にそろう位置にあること。
- 目次を含む原稿（既存の `test/fixtures/sample` は `front.gm` に `@toc depth=2` を持つ）を並列と逐次でビルドし、PDF のバイト列が一致すること。二回のビルドでも一致し、qpdf の検査を通ること。

既存の HTML、EPUB、プレーンテキストの golden テストが変わらないことも確かめる。

自動テストにしない確かめ方として、実装の後に `golem new` の和文の雛形に `@toc` と数章の見出しを足してビルドし、縦組みの目次でリーダーの点が項目のあいだで左右にそろい、ページ番号が地にそろうことを目で確かめる。

## トレードオフ

ページ番号の幅を、実際の番号ではなくページ番号 999 の幅で予約する。
三桁までのページ番号では、目次の行分割と改ページがページ番号に依存しなくなり、目次が S2 の繰り返しを増やさない。
代わりに、題の行は常に R だけ短くなり、二桁のページ番号しかない薄い本でも、題が予約の幅の手前で折り返す。
LaTeX の目次も、ページ番号の幅を固定の寸法で予約している（`\@pnumwidth`）。

四桁以上のページ番号は予約の幅を超えるが、空きとリーダーの一字分を食うだけで、題とは重ならない。
重なるのは、行長を超えた題の行か、六桁（縦組みでは漢数字の六字）を超えるページ番号に限られる。
その場合はページ番号を題の後ろに置き、版面からはみ出させる。
エラーにしないのは、行長を超えた行を本文でもエラーにしていないことに合わせるためである。

縦組みで漢数字（`kanji`）の表記を使うと、W が「九百九十九」の五字分になり、R が七字分になる。
漢数字の位取りの表記は桁の割に長いので、縦組みの目次で題の行を長く保ちたい場合は、`[numbers] vertical` を `kanji-digits` か `tcy` にする。
目次のページ番号だけ別の表記にする設定は、数の表記を一つの経路で決める仕様と衝突するので、設けない。

見出しのページを S2 の繰り返しの外で求めるので、目次のページ番号は、ページ番号への参照（`[ref-page ...]`）と違って、仮の値で組まれる回がない。
これは、目次のページ番号を行分割の外に置いたことで成り立つ。
将来、目次のページ番号を題と同じ段落に入れて組む形（予約の幅を持たない形）に変える場合は、見出しのページを `Assumed` に加え、索引の印と同じく繰り返しに含める必要がある。

## 検討の経緯

見出しのページを索引の印と同じ `asMarks` に入れる案も考えた。
見出しのブロックの位置は `#` から、索引の印の位置は `[` から始まるので、同じ `SrcSpan` にはならない。
それでも採らなかったのは、ページ番号が行分割に影響しない目次を繰り返しに含めると、ラベルも印もない原稿で一回で済む収束の判定が二回に増えるためである。
G0721 のメッセージに見出しの題を並べる処理も要らなくなる。
