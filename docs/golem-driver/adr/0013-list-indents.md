# ADR 0013: PDF のリストの字下げ

ステータス: 採択

## 文脈

原稿のリストは、行頭の `-`（箇条書き）と `+`（番号付き）で項目を書き、2 つの空白のインデントで入れ子にする（[記法の仕様](../../markup.md) の「リスト」の節）。
意味論 IR では `BulletList [ListItem]` と `OrderedList [ListItem]` になり、`ListItem` は `@number` で指定した番号 `itemNumber` と、段落や入れ子のリストなどのブロックの列 `itemBlocks` を持つ。

PDF の経路の現状を、`Golem.Driver.Pdf.unitsOf` で確かめると次のとおりである。

- `BulletList` は、項目の最初の段落のインラインの先頭に `・` の文字を足す（`prefixFirst`）。`OrderedList` は、項目の順に 1 から数えた番号と `. `（ピリオドと半角の空白）を足す。
- 項目の中の段落は `UPara noIndent` になる。項目の二行目以降も、項目の二つ目の段落も、行の始まりから組まれる。
- 入れ子のリストは、外のリストの項目の中のブロックとして同じ `blocks True` で展開されるので、外のリストと同じ位置から組まれる。
- `itemNumber` を読んでいない。HTML（`start` と `value` の属性）とプレーンテキスト（`Golem.Text.itemNumbers`）は `@number` に従うが、PDF だけが常に 1 から数える。
- 印の後の半角の空白は行分割の glue になるので、項目ごとに伸び縮みし、二行目以降の位置を決める基準にならない。

[docs/adr/0006](../../adr/0006-paragraph-indent.md) は、段落スタイルの字下げをリストの項目の段落に効かせないとし、リストの字下げを別に扱うとした。
項目の最初の行には印が付くので、段落の字下げを加えると印の前が空くためである。

HTML と EPUB は、`ul`、`ol`、`li` の要素を出し、リストの CSS を書いていない。
ブラウザーの既定では、印は項目の本文の外側に置かれ（`list-style-position: outside`）、本文の折り返した行は最初の行の本文の始まりにそろう。
入れ子のリストは、外の項目の本文の中に置かれるので、一段ずつ深く下がる。
`padding-inline-start` も `list-style-position` も論理方向の指定なので、縦組みでも行の始まりの側（天）に効く。

InDesign の箇条書きと自動番号は、段落の左インデントと 1 行目左インデントで印と本文の位置を決める。
Adobe のヘルプ「Create bulleted and numbered lists」は、左インデントを正、1 行目左インデントを同じ量の負にしてぶら下げにし、印と本文の間をタブの位置で決めると説明している。
このページは直接は読めず（HTTP 403）、検索エンジンの要約で内容を確かめた（https://helpx.adobe.com/ca/indesign/desktop/format-and-style-text/lists-and-numbering/create-lists.html ）。
InDesign の入れ子のリストは、階層ごとの段落スタイルに利用者が字下げの量を設定して作る（記憶による）。
Golem には段落スタイルの階層の設定がないので、入れ子の字下げを自動で決める。

## 実装すること

### 組み方

項目の印をぶら下げ、本文の行の始まりをそろえる。
InDesign で左インデントを印の幅に、1 行目左インデントをその負にした組み方である。

- 一つのリストの印の幅 M を、そのリストのすべての項目の印の最大の幅から決める（次節）。
- 項目の最初の段落の最初の行は、印の箱を行の始まりに置き、その後に本文を続ける。印の箱の幅は M なので、本文は印の長さによらず同じ位置から始まる。
- 項目の最初の段落の二行目以降、項目の二つ目以降の段落、項目の中のコードブロックの行と定義リストの行は、本文の始まり（印の箱の後の位置）から組む。
- 入れ子のリストは、外の項目の本文の始まりを基準にする。外のリストの印の幅を M1、内のリストの印の幅を M2 とすると、内の項目の印は M1 の位置から、内の本文は M1 + M2 の位置から始まる。
- 字下げは行の始まりの側から測る。縦組みでは天からの距離になる（[docs/adr/0006](../../adr/0006-paragraph-indent.md) と同じ）。

### 印の字形と番号の書式（style.toml）

箇条書きの印の字形と、番号付きリストの番号の書式を、`style.toml` の `[lists]` で指定できるようにする。
入れ子の深さごとに別の値を書ける。

```toml
[lists]
bullets = ["・", "◦", "▪"]
numbers = ["{n}.", "({a})", "{i}"]
gap = "0.5zw"
```

- **bullets**：箇条書きの印の文字列の配列。一段目のリストに最初の要素、二段目に二つ目の要素を使う。入れ子が配列より深ければ、最後の要素を使い続ける。既定は `["・"]` である。
- **numbers**：番号付きリストの番号の書式の配列。深さの扱いは `bullets` と同じである。既定は、横組みの本で `["{n}."]`、縦組みの本で `["{n}、"]` である。
- **gap**：印と本文の間の空き。寸法で書き、`zw` はその段落の文字の大きさで数える。既定は下の「印の幅」の G の規則による。

番号の書式は、番号を表す差し込みをちょうど一つ含む文字列とする。
差し込みの前後の文字は、そのまま印になる（`({a})` なら、括弧と括弧の間に番号が入る）。

| 差し込み | 表記 | 例（3 番） |
|---|---|---|
| `{n}` | 本の数の表記。横組みでは算用数字、縦組みでは `[numbers]` の `vertical` の表記 | `3`、`三` |
| `{1}` | 算用数字 | `3` |
| `{一}` | 漢数字（`[numbers]` の漢数字の表記と同じ規則） | `三` |
| `{①}` | 丸数字（1 から 50 まで） | `③` |
| `{a}`、`{A}` | ラテン文字の小文字、大文字（26 を超えると `aa`、`ab` と続ける） | `c`、`C` |
| `{i}`、`{I}` | ローマ数字の小文字、大文字（1 から 3999 まで） | `iii`、`III` |
| `{ア}`、`{イ}` | 片仮名のアイウエオ順、イロハ順（46 字と 47 字まで） | `ウ`、`ハ` |

次の場合は、`style.toml` を読むときに G0322（リストの書式の誤り）とする。

- `bullets` か `numbers` が空の配列であるか、空の文字列を含む。
- `numbers` の書式が差し込みを含まないか、二つ以上含むか、表にない差し込み（`{x}` など）を含む。差し込みでない `{` と `}` は、`{{` と `}}` で書く。
- `gap` が寸法として読めないか、負である。

| 診断コード | 重大度 | メッセージ |
|---|---|---|
| G0322 | エラー | `[lists] の <欄> が正しくありません: <理由>` |

G0322 は未使用である。`style.toml` の一般の誤りの G0306 から、リストの印と番号の書式の誤りを分けて、どの欄の誤りかをコードで引けるようにする（提案中の ADR のあいだで、G0317 から G0322 を分けて割り当てた）。

番号がその書式で表せない（丸数字の 51 番、ローマ数字の 0 番など）項目があれば、PDF、HTML、EPUB、プレーンテキストのどれで組んでも、その項目の位置で G0729 とする。

| 診断コード | 重大度 | メッセージ |
|---|---|---|
| G0729 | エラー | `リストの番号 <番号> は、書式 <書式> で表せません` |

G0729 は未使用である（G0726 は [docs/adr/0018](../../adr/0018-multi-column-layout.md)、G0727 はこの ADR の下の「深すぎる入れ子」、G0728 は [golem-driver ADR 0016](0016-output-and-layout-diagnostic-codes.md) の案が使う）。

`[lists]` は本に一つで、ファイルの中の設定（[docs/adr/0014](../../adr/0014-in-file-settings.md)）では上書きしない。
リストごとに書式を変える原稿の記法も設けない（「実装しないこと」）。

### 印と印の幅

印の内容は、そのリストの入れ子の深さ（一段目が 1）の `bullets` と `numbers` の要素で決める。
既定の値では、次のとおりになる。

| リスト | 横組み | 縦組み |
|---|---|---|
| 箇条書き | `・` | `・` |
| 番号付き | 番号の `Number` と `.` | 番号の `Number` と `、` |

- `{n}` の番号は `Number` の inline として組む。横組みでは算用数字、縦組みでは `[numbers]` の `vertical` の表記になり、目次と索引のページ番号と同じ経路で表記が決まる（[golem-driver ADR 0007](0007-pdf-index-and-bibliography.md)、[golem-driver ADR 0009](0009-pdf-toc-page-numbers.md)）。縦組みの `、` は、プレーンテキストの縦書きの番号の形（`一、`）に合わせる。ほかの差し込みは、その表記の文字列にしてから組む。縦組みで `{1}`、`{a}`、`{i}` の番号を組むときは、ほかの欧文と同じく回転して組み、2 字までの算用数字だけは縦中横にする（`[numbers]` の縦中横の規則と同じ）。
- 番号は `@number` に従う。今 `Golem.Text` にある `itemNumbers :: [ListItem] -> [Integer]` を `Golem.Doc.IR` に移してエクスポートし、PDF とプレーンテキストの両方から使う。項目に `@number N` があればその項目を N とし、以後は N から数え続ける。HTML の `start` と `value` の扱いと同じ結果になる。
- 印の後の半角の空白はなくす。印と本文の間の空きは、次の式の G で表す。

リストの印の幅 M は次のとおりとする。
fs は版面の文字の大きさ（`pgFontSize`）である。

1. 各項目の印を、その項目の最初の段落と同じ `ComposeEnv` で `composeInlines` に通し、箱の幅の和を w とする。
2. 空き G は、`[lists]` の `gap` があればその値とする。なければ、印の最後の文字が全角の字面の外に空きを持つ約物（`・`、`、`、`。`、閉じ括弧類）なら 0、ほかは fs / 2 とする。既定の印では、横組みの番号付きリストが fs / 2、ほかが 0 になる。
3. M = ⌈(最大の w + G) / fs⌉ × fs とする。全角の字の単位に切り上げ、本文の行頭を字送りの格子にそろえる。

`fakeFonts`（欧文の字は 0.5 字、ほかは 1 字）では、`・` の M は 1 字、`1.` から `99.` までの番号の M は 2 字、`100.` 以上の番号を含むリストの M は 3 字になる。

番号の右揃え（`9.` と `10.` のピリオドの位置をそろえること）はしない。
番号は印の箱の始まりにそろえる。
InDesign の自動番号の配置の既定も左揃えである（記憶による）。

### 単位と字下げ（golem-driver）

`Golem.Driver.Pdf` の `Unit` に、リストの情報を加える。

```haskell
data Unit = Unit
  { ...
    -- | 外から順に、囲んでいるリストの番号。リストの番号は文書の順に 0 から振る
    uLists :: ![Int],
    -- | 項目の最初の段落の印のインライン
    uMarker :: !(Maybe [Inline])
  }
```

- `unitsOf` は、リストを文書の順にたどって番号を振る（`mapAccumL` で数を運ぶ）。項目の中のすべての単位の `uLists` に、囲んでいるリストの番号を外から順に入れる。
- 項目の最初のブロックが段落なら、その最初の単位の `uMarker` に印を入れる。今の `prefixFirst` は削る。項目の最初のブロックが段落でない場合（入れ子のリストから始まる項目など）は、今と同じく印を付けない。
- 項目の中の段落は、段落スタイルの `font` と `size` を使い、`indent` と `first-line-indent` は使わない。これは今と同じである。

`buildFlow` は、行分割の前にリストの印の幅を求める。

```haskell
-- | リストの番号から印の幅 M へ
listWidths :: (Unit -> ComposeEnv) -> Sp -> Bool -> [Unit] -> Map Int Sp
```

単位の字下げを次のように決める。
O は `uLists` のすべてのリストの M の和、Mi は `uLists` の最後のリストの M である。

- `uMarker` のある単位は `UPara (Indent O (-Mi))` とする。印の箱が最初の行の始まりに入るので、最初の行の字下げは O − Mi、行長は `measure − O + Mi` になり、本文に使える長さは二行目以降と同じ `measure − O` になる。
- `uLists` が空でなく `uMarker` のない段落とコードブロックの行は `UPara (Indent O 0)` とする。
- 定義リストの用語（`UTerm`）の行も、`uLists` が空でなければ O だけ下げる。`UTerm` に `Indent` を持たせ、`widthOf` と `lineIndent` で `UPara` と同じく扱う。
- `uLists` が空の単位は今と同じである。

印の箱は、組んだ後の項目の列の先頭に足す。

- 印のインラインを `composeInlines` に通した箱の列の後に、幅 Mi − w、内容が空の箱を一つ置き、それを段落の `Item` の列の先頭に足す。
- 印の箱と本文の間には glue も罰点も置かないので、行分割は印の直後で行を分けない。
- 内容が空の箱は描くグリフを持たないので、`writeDocument` は変えない。行の始まりのずらしは今の `slIndent` で表される。
- 注の印の行を求める `lineIndexOfItems` は、足した箱の数だけ項目の番号をずらして呼ぶ。

回り込みの図版の脇のリストの項目も、`lineIndent` と `widthOf` を通るので、[docs/adr/0006](../../adr/0006-paragraph-indent.md) の段落の字下げと同じく除外領域の幅に字下げが加わる。

### 深すぎる入れ子

本文に使える長さ `measure − O` が fs の 8 字分に満たない単位があれば、その単位の位置で G0727 とする。
8 字分は、字下げの下限（G0725）と回り込みの脇の行の下限（G0722）に合わせる。
回り込みの図版の脇で、行長から字下げを引いた値が 0 以下になる行も、今の G0725 と同じ判定で G0727 とする。

| 診断コード | 重大度 | メッセージ |
|---|---|---|
| G0727 | エラー | `リストの入れ子が深く、項目の本文の行長が足りません。行長を本文の文字の大きさの 8 字分以上残してください` |

G0727 は未使用である（golem-driver は G0721 から G0725 までを使い、[docs/adr/0018](../../adr/0018-multi-column-layout.md) の案が G0726 を使う）。

### 段落スタイルとの関係

- リストの項目の中の段落には、これまでどおり段落スタイルの `indent` と `first-line-indent` を効かせない。リストの字下げが、項目の中の段落の字下げを決める。
- 段落スタイルの `font` と `size` は効く。印の幅も、その段落の大きさで組んだ印の w から決まる。
- 段落スタイルの `space-between` も今と同じく効く。

### HTML、EPUB、プレーンテキスト

印の字形と番号の書式は、HTML、EPUB、プレーンテキストでも `[lists]` に従う。

- HTML と EPUB は、`[lists]` を書いた本では、深さごとの `@counter-style` を CSS に書き、`ul` と `ol` の `list-style-type` にその名前を当てる。箇条書きは `system: cyclic` と `symbols` に印の文字列を、番号付きは差し込みに応じた `system`（`{1}` は `extends decimal`、`{a}` は `extends lower-alpha`、`{i}` は `extends lower-roman`、`{一}` は `extends cjk-decimal` など）と、書式の前後の文字の `prefix` と `suffix` を書く。`{n}` は、横組みの本では `decimal`、縦組みの本では `[numbers]` の `vertical` の表記に合う `system` にする。CSS に対応する `system` がない差し込み（`{①}`、`{ア}`、`{イ}`）は、`system: fixed` と、リストの項目の数だけの `symbols` を並べて書く。
- `[lists]` を書かない本の HTML と EPUB の出力は変えない。
- プレーンテキストは、今の `・` と番号の代わりに、深さごとの印と書式で組んだ文字列を項目の前に置く。`[lists]` を書かない本の出力は変えない。

字形と書式以外の組み方について、HTML と EPUB の出力は変えない。
ブラウザーの既定の組み方は、印をぶら下げること、本文の行の始まりをそろえること、入れ子を一段ずつ深く下げること、縦組みで天から測ることの四つで、この ADR の PDF の組み方と一致する。
字下げの量（ブラウザーの既定は 40px）と、印の字形（`disc` と `decimal`）は一致させない。

プレーンテキストの組み方も、印の文字列のほかは変えない。
すでに入れ子ごとに全角の空白一つを前に置き、印と番号を付けている。
プレーンテキストには行の折り返しがないので、ぶら下げを表す必要がない。

### ドキュメント

- 仕様書の「v1 の実装で次の段階以降に回した項目」から「リストの字下げ」を削る。
- 仕様書の「style.toml」の節の字下げの段落に、リストの項目の段落は段落スタイルの字下げを受けず、PDF では印の幅でぶら下げ、入れ子は外の項目の本文の始まりから下げることを書き、この ADR へリンクする。
- [記法の仕様](../../markup.md) の「リスト」と「番号付きリスト」の節に、PDF の印（横組みの番号の後のピリオド、縦組みの読点）と、`@number` が PDF でも効くことを書く。
- 仕様書の「style.toml」の節に `[lists]` の三つの欄と、差し込みの表と、G0322 と G0729 の条件を書く。
- docs/glossary.md の「字下げ」の項目に、リストの項目のぶら下げを加える。

## データ構造の変更

- golem-doc：`itemNumbers` を `Golem.Doc.IR` に移す。
- golem-text：`itemNumbers` を golem-doc から import する。出力は変えない。
- golem-driver：`Unit` に `uLists` と `uMarker` を加える。`UTerm` に `Indent` を持たせる。`listWidths` を加え、`prefixFirst` を削る。

- golem-project：`Style` に `stLists :: ListStyle` を加える。`data ListStyle = ListStyle { lsBullets :: NonEmpty Text, lsNumbers :: Maybe (NonEmpty NumberFormat), lsGap :: Maybe Dim }` とし、`data NumberFormat = NumberFormat { nfPrefix :: Text, nfStyle :: NumberStyle, nfSuffix :: Text }`、`data NumberStyle = NsBook | NsArabic | NsKanji | NsCircled | NsLowerAlpha | NsUpperAlpha | NsLowerRoman | NsUpperRoman | NsIroha | NsAiueo` とする。`lsNumbers` が `Nothing` のときは、組み方向による既定を使う。
- golem-doc：番号を書式の文字列にする `formatNumber :: NumberStyle -> Integer -> Maybe Text` を置き、PDF、HTML、プレーンテキストから使う。`Nothing` が G0729 になる。

意味論 IR は変えない。

## 実装しないこと

- リストごと、項目ごとに印の字形や番号の書式を変える原稿の記法。本に一つの `[lists]` だけで決める。
- 段落スタイルに印の字形や番号の書式を持たせること（InDesign の段落スタイルの箇条書きと自動番号の設定にあたる）。仕様書の「段落スタイルの拡張」の「リストへの段落スタイルの適用」に含める。
- 印の文字に文字スタイル（色や書体）を当てること。
- 番号の右揃えと、印の幅を `style.toml` で指定すること。
- 番号の前に上の階層の番号を付けること（`1.2.` のような番号）。
- リストの階層ごとに段落スタイルを当てること（InDesign の階層ごとの段落スタイルにあたる設定）。仕様書の「段落スタイルの拡張」の「リストへの段落スタイルの適用」に含める。
- 項目の中の図版と表を字下げすること。今と同じく、行の始まりから置く。
- HTML と EPUB の CSS で、字下げの量と印の字形を PDF に合わせること。

## テスト設計

### 自動テストにしない確かめ方

実装の後に、入れ子の箇条書きと、10 項目を超える番号付きリストと、二行以上に折り返す項目を含む原稿を、横組みと縦組みで PDF と EPUB にし、ビューアーと EPUB の読書環境で、PDF と Web の媒体で印のぶら下げと入れ子の深さの関係が同じであることを目で確かめる。

## トレードオフ

印の幅を全角の字の単位に切り上げるので、`1.` のような短い番号の後の空きは、字面の幅によっては半角より広くなる。
本文の行頭を字送りの格子にそろえることを優先する。
和文の本文では、行頭が格子からずれると、項目の本文と前後の段落の字の位置がそろわなくなるためである。

印の幅をリストの中の最大の印から決めるので、`9.` までの項目と `10.` からの項目が同じリストにあると、すべての項目が `10.` に合わせた幅で下がる。
項目ごとに幅を変えると、隣り合う項目の本文の始まりがそろわない。
InDesign でもタブの位置はリストの段落で共通に設定するので、本文の始まりはそろう。

HTML と EPUB の字下げの量は PDF に合わせないので、媒体によって見た目が異なる。
`[lists]` を書いた本の印の字形と番号の書式は、`@counter-style` で HTML と EPUB にも出すが、`@counter-style` に対応しない読書環境では、既定の印と算用数字で表示される。
組み方の構造（ぶら下げと入れ子の深さ）と、対応する環境での字形と書式は一致させる。

`[lists]` を本に一つにしたので、同じ本の中でリストごとに印を変えることはできない。
リストごとの指定は、段落スタイルの拡張でリストに段落スタイルを当てられるようになったときに、段落スタイルの欄として加えるのが筋がよい。

縦組みの番号の後を `、` にするので、横組みと縦組みで番号の形が変わる。
縦組みでピリオドを横倒しの欧文として組むより、和文の縦組みの慣習に近い。
