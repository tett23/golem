# ADR 0018: 脚注の印と番号

ステータス: 採択→章末の注（`placement = "chapter-end"`）は [golem-driver ADR 0026](0026-chapter-end-notes.md)、注の印の大きさと書式は [ADR 0025](0025-note-mark-size-and-format.md)、注の本文の先頭の印の後の空きは [golem-layout ADR 0018](../../golem-layout/adr/0018-url-line-breaks.md)

## 文脈

PDF の脚注には、仕様書の「v1 の実装で次の段階以降に回した項目」に挙げた二つの不具合がある。
一つは印の組み方で、本文の印（`*1`）が次の字と重なり、ページの下の注の本文には番号が付かない。
もう一つは番号の衝突で、あるファイルの注 1 の位置に、別のファイルの注 1 の本文が組まれる。
どちらも、マニュアルの付録の注で見つかった。

### 番号の振り方

注の番号は、golem-eval の `Golem.Eval.File` が評価の状態 `stNote` で数え、ファイルごとに 1 から振る。
意味論 IR の `Note` は、位置、番号、本文を持つ（`Note !SrcSpan !Int [Inline]`）。
仕様書の「脚注」の節は、番号がそのファイルだけで決まるのでファイル内評価（S0）で決まる、と書いている。
傍注の番号も、同じくファイルごとに振る。

### 印の組み方

golem-layout の `Golem.Layout.Japanese` の `piecesOf` は、`Note` から二つの部品を作る。

```haskell
Note _ n body -> [PAnchor (\i -> AnchorNote i n body), PBox lk ("*" <> T.pack (show n)) KindText (lkSize lk `div` 2)]
```

箱の幅は、印の字数によらず、段落の文字の大きさの半分に固定されている。
一方、golem-driver の `Golem.Driver.Pdf` の `drawLineAt` は、`KindText` の箱を `runAt` で段落と同じ大きさのまま描く。
`*1` は、本文の大きさで少なくとも一字分の送りを持つので、半分の幅の箱からはみ出して次の字に重なる。
傍注の印の `MarkerNumber`（[ADR 0006](0006-pdf-sidenotes.md)）も、同じ形の箱を同じ描き方で描くので、同じく重なる。

箱の両隣の扱いにも問題がある。
`normalize` は印の箱を普通の箱として扱い、印の先頭の `*` から字の種類を欧文と判定する。
そのため、和文の後の印の前に和欧間の空きが入り、印の前で行が分かれることもある。

### 注の本文

`buildFlow` は、注の本文を `composeInlines bodyEnv' nbody` でそのまま組む。
傍注の本文の先頭には印と半角の空白を付けるが（[ADR 0006](0006-pdf-sidenotes.md)）、脚注の本文には何も付けない。
読み手は、ページの下の注がどの印に対応するのかを、順番から推し量るしかない。

### 番号の衝突

注の本文の行は、印を含む行の `SetLine` の `slNotes :: [(Int, [Line])]` に、番号を鍵にして持たせている。
改ページ（`Golem.Layout.Paginate`）も、`NoteBody {nbId :: Int}` の `nbId` に番号を入れ、ページに置いた注を `poFootnotes :: [(Int, Int, Int)]`（番号、何行目から、何行）で返す。
描画の `drawColumn` は、すべての行の `slNotes` から番号の一致する注を集めて連結し、その中から `from` と `cnt` で行を切り出す。

```haskell
noteLines = concat [take cnt (drop from (concat [ls | sl <- Map.elems (plLines layout), (nid', ls) <- slNotes sl, nid' == nid])) | (nid, from, cnt) <- poFootnotes p]
```

番号はファイルごとに振り直すので、二つ以上のファイルに注 1 があると、注 1 の本文の行は本の全体の注 1 を連結したものになる。
`plLines` は行の番号の順の表なので、先のファイルの注 1 の行が前に来て、後のファイルの注 1 の位置には先のファイルの本文が組まれる。

### 番号を振る範囲

ファイルごとに振り直す今の方式は、章を複数のファイルに分けたときに、章の途中で番号が 1 に戻る。
章の中で番号が戻るのは、読み手にとって分かりにくい。
一冊の全体で通し番号にする本もある。

InDesign の脚注のオプションについて、次のことは記憶によるものであり、資料では確かめていない。

- 番号の形式、開始番号、番号を振り直す単位（ページごと、見開きごと、セクションごと）を選べる。振り直さなければ、ドキュメントの全体で通し番号になる。
- 本文の参照番号の位置（上付き、下付き、通常）と文字スタイルを選べる。
- 接頭辞と接尾辞を、参照番号、脚注の本文、その両方のどこに付けるかを選べる。
- ブックでは、ドキュメントをまたいで番号を続けるかどうかを選べる。

Golem のファイルは InDesign のドキュメントにおおよそ当たり、マニフェストの章（`chapters` の一つの項目）は、ブックの中の章に当たる。
ページごとと見開きごとの振り直しは、ページが決まるまで番号が決まらないので、仕様書の「脚注」の節が v1 では採らないと決めている。

### 置き場所の設定

`style.toml` の `[notes]` の `placement`（`"page-foot"` と `"chapter-end"`）は、`Golem.Project.Style` の `stNotesPlacement` に読み込まれるが、PDF のパイプラインは読んでいない。
PDF の注は、`placement` によらずページの下に組まれる。
この ADR はこの欄を扱わない（「実装しないこと」）。

## 実装すること

### 番号を振る範囲の設定（golem-project）

`[notes]` に `numbering` の欄を加える。

```toml
[notes]
placement = "page-foot"
numbering = "chapter"
```

| 値 | 意味 |
|---|---|
| `"chapter"` | マニフェストの章ごとに 1 から振る。`chapters` の配列の一つの項目が一つの章であり、入れ子の配列は全体で一つの章になる。既定 |
| `"file"` | ファイルごとに 1 から振る（今の振り方） |
| `"book"` | 本の全体で 1 から通し番号にする |

- `Style` に `stNotesNumbering :: NoteNumbering` を加え、既定を `NumberPerChapter` とする。`NoteNumbering` は golem-doc に置き（下の節）、golem-project はそれを使う。
- 三つ以外の値は、ほかの `enumKey` の欄と同じく `style.toml` の値の誤り（G0306）とする。
- 傍注の番号も、同じ欄の範囲で振り直す。傍注は脚注と別に数える。

既定を `"chapter"` にするのは、章を一つのファイルで書く本では今と同じ番号になり、章を複数のファイルに分けた本では章の途中で番号が戻らなくなるためである。

### 番号の振り直し（golem-doc、S1）

番号を振る範囲が本の構成に依存するので、番号は文書の組み立て（S1）で振り直す。
評価（S0）はこれまでどおりファイルごとに番号を振り、`golem check` と LSP はその番号を使う。

```haskell
data NoteNumbering = NumberPerFile | NumberPerChapter | NumberPerBook
  deriving stock (Eq, Show)

data AssembleConfig = AssembleConfig
  { ...
    acNoteNumbering :: !NoteNumbering,
    -- | bookDocs の各文書が属するマニフェストの章の番号（0 から）
    acChapterOf :: ![Int]
  }
```

- `assemble` は、文書の順と文書の中の出現の順に `Note` と `Sidenote` をたどり、範囲の始まりで数を 1 に戻して番号を書き換える。注の本文の中の注は、仕様書の「脚注」の節のとおり今も作れないので、たどる順の問題は生じない。
- 範囲の始まりは、`NumberPerFile` では各文書の先頭、`NumberPerChapter` では `acChapterOf` の値が前の文書と変わる文書の先頭、`NumberPerBook` では最初の文書の先頭だけである。
- golem-driver は、マニフェストの `manifestChapters` の最上位の項目の番号を、`chapterFiles` と同じ順で各ファイルに割り当てて `acChapterOf` を作る。
- 書き換えた番号は `bookDocs` に入るので、PDF、HTML、EPUB、プレーンテキストのすべてが同じ番号を使う。HTML の注の `id`（`note-<番号>`）は出力するファイルの中で一意であればよく、章や本の全体で振っても重ならない。

### 注の鍵（golem-layout、golem-driver）

注の本文を探す鍵を、番号から注そのものを指す値に替える。

```haskell
-- Golem.Layout.Paginate
data NoteId = NoteId !SrcSpan !Int -- 注の位置と、同じ位置の注の中での順
  deriving stock (Eq, Ord, Show)

data NoteBody = NoteBody {nbId :: !NoteId, nbLines :: !Int}
```

- `AnchorNote` に注の `SrcSpan` を加える（`AnchorNote !Int !Int !SrcSpan [Inline]`、項目の番号、注の番号、位置、本文）。
- `NoteId` の二つ目の値は、一つの段落の中で同じ位置を持つ注の、出現の順の番号（0 から）とする。`[note: ...]` から作った注の位置は互いに異なるので、普通は 0 である。プラグインが一つの呼び出しから複数の注を返すと位置が同じになるので、その場合を区別するために持つ。
- `SetLine` の `slNotes` を `[(NoteId, [Line])]` に、`PageOut` の `poFootnotes` と改ページの中の注の状態（`sNotes`、`sPendingNotes`）の鍵を `NoteId` に替える。
- `drawColumn` は、`NoteId` が一致する注だけを集める。一つの注の行は一つの `SetLine` にしかないので、連結は起きない。

### 本文の印（golem-layout）

`BoxKind` の最後に `KindNoteMark` を加える（既存の値の番号を変えないため最後に置く）。
`piecesOf` は、`Note` から次の部品を作る。

- 印の文字列は、今と同じく `*` と番号（`*1`）とする。
- 印の大きさ `m` は、その位置の文字の大きさ `s` の半分（`s` を 2 で整数の除算をした値）とする。
- 横組みの箱の幅は、印の文字列を大きさ `m` で測った送り（`ceWordAdvance` を `m` の `Look` で呼んだ値）とする。
- 縦組みの箱の幅（行の方向の長さ）は `m` とする。印は、縦組みの中で横に並べた一行（縦中横と同じ向き）として描く。
- 箱の `bcLook` は、その位置の `Look`（大きさ `s`）のままとし、`m` は描画で求める。

傍注の `MarkerNumber` の箱も、文字列を番号だけにして同じ `KindNoteMark` で作る。
`MarkerSymbol`（`※` を本文の大きさで置く）と `MarkerNone` は変えない。

`normalize` は、`KindNoteMark` の箱を前の字に付けて扱う。

- 印の前には `Penalty 0 infPenalty NoHyphen` を置き、空きを置かない。印は行頭に来ない。
- 印と次の箱の間の空きと分割の可否は、印の前の箱と次の箱の組で決める。印がないときと同じ空きが、印の後ろに入る。
- 段落の先頭の印には、`leading` の空きを置かない。
- 行末に来た印の箱の `bcEdgeEnd` は 0 とする。前の箱の行末の空きは、印が後ろにあるので使わない。

### 印の描画（golem-driver）

`drawLineAt` に `KindNoteMark` の分岐を加え、印の文字列を大きさ `m` の `Look` で描く。
本文の字の和文の書体の字面の枠の中心の高さを `c`（`lfEmBoxCentral`、全角を 1 とする値）とする。

- **横組み**：印の字面の枠の上端を、本文の字面の枠の上端にそろえる。印の基準線は、本文の基準線より `(c + 1/2) × (s − m)` だけ上に置く。印の始まりは箱の始まりとする。
- **縦組み**：印を横書きの向き（縦書き用のフォントの参照を使わない `GlyphRun`）で描く。印の右端を本文の字面の枠の右端（行の中心線から `s/2` 右）にそろえる。行の方向には、箱の範囲（長さ `m`）の中心に印の字面の枠の中心を置く。印の基準線は、箱の始まりから `m/2 + c × m` 下にある。
- 縦組みで印の幅が `s` を超える場合（大きさ `m` で 5 字以上の印）は、印が行の左にはみ出す。番号が 1000 を超える注で起きるが、v1 では扱わない。

ベースラインシフト（[docs/adr/0020](../../adr/0020-indesign-character-features.md)）は、ほかの字と同じく印にもかける。

### 注の本文の番号

注の本文の先頭に、本文の印と同じ文字列と半角の空白を付ける（`*1 注の本文`）。
傍注の本文の先頭の印（[ADR 0006](0006-pdf-sidenotes.md)）と同じ形である。
この印は注の本文の大きさで組み、上げずに本文と同じ基準線に置く。
二行目以降は字下げしない。

### ドキュメント

- 仕様書の「脚注」の節を書き直す。番号は `[notes]` の `numbering` の範囲で振り、既定はマニフェストの章ごととする。範囲が本の構成に依存するので、番号は文書の組み立て（S1）で決まり、評価（S0）の番号はファイルごとの仮の番号であることを書く。「傍注」の節の「番号はファイルごとに振る」も同じく直す。
- 仕様書の「style.toml」の節の例と `[notes]` の説明に `numbering` を加える。
- 仕様書の「v1 の実装で次の段階以降に回した項目」から「脚注の印」と「PDF の脚注の番号の衝突」の二つの項目を消す。
- 利用者のマニュアル（`manual/`）の次の箇所を直す（[docs/adr/0024](../../adr/0024-manual-audiences-and-policy.md)）。
  - `manual/chapters/03-markup.gm` の「注」の節の「注の番号は、ファイルごとに 1 から振ります。」
  - `manual/chapters/04-manifest.gm` の「章を並べる」の節の「脚注の番号は、ファイルごとに 1 から振り直します。」
  - `manual/chapters/05-style.gm` の「注と図の設定」の節の `[notes]` の説明と、`manual/appendices/c-style.gm` の「`[notes]`」の節。
  - `manual/appendices/a-markup.gm` の「段落の中のコマンド」の `[note: ...]` の項の「番号はファイルごとに 1 から振ります。」
- 開発者のマニュアルの `manual-dev/part2/15-manuals.gm` の「開発者のマニュアルの書き方」の「脚注の印を句点の前に置くと、今の PDF では印が次の字と重なるので、段落の末尾に置いている」を、印が重ならなくなったことに合わせて直す。
- [ADR 0006](0006-pdf-sidenotes.md) のステータスの行に、傍注の番号の印の組み方と番号を振る範囲をこの ADR で変えたことを、この ADR へのリンクで書き足す。

## 実装しないこと

- ページごとと見開きごとの番号の振り直し。仕様書の「脚注」の節が v1 では採らないと決めている。
- 印の形式の設定（接頭辞、接尾辞、数字の表記、上付きと通常の選択、文字スタイル）。印は `*` と算用数字に固定する。プレーンテキストの横書きの印（`*1`）と同じ形である。
- 縦組みで、印をルビのように行間に置く形。行間の配置はルビと位置を取り合うので、ルビとの関係を決める必要がある。
- 注の本文の二行目以降を印の後ろにそろえる字下げと、注の本文の大きさと書体の設定。
- 本文と脚注の間の区切りの罫。今の改ページは区切りに一行の空きを取るが、罫は描かない。
- `[notes]` の `placement = "chapter-end"` を PDF で使うこと。PDF の注はページの下に組む。この欄を PDF で使うか、欄を廃止するかは別の ADR で決める（「トレードオフ」）。
- 傍注の印の `MarkerSymbol` の大きさの変更。

## テスト設計

実装の前に書き、失敗することを確かめる。

### style.toml（`modules/golem-project/test/Main.hs`）

- `[notes]` がないとき、`stNotesNumbering` が `NumberPerChapter` である。
- `numbering = "file"`、`"chapter"`、`"book"` を読める。
- `numbering = "page"` が G0306 になる。

### 番号の振り直し（`modules/golem-doc/test`）

注を二つずつ持つ三つの文書 a、b、c を、`acChapterOf = [0, 0, 1]`（a と b が一つの章）で組み立てる。

- `NumberPerFile` で、番号が a から順に 1、2、1、2、1、2 になる。
- `NumberPerChapter` で、1、2、3、4、1、2 になる。
- `NumberPerBook` で、1 から 6 になる。
- 傍注を混ぜた文書で、脚注と傍注が別々に数えられる。
- 振り直した後の `Note` の位置と本文が変わらない。

### 印と注の鍵（`modules/golem-layout/test/Main.hs`）

測る関数には、テストの中で固定の値を返す関数を使う。

- `漢[note]字` の項目が、漢の箱、`Penalty 0 infPenalty`、印の箱、字の箱の順になり、印の前後に和欧間の `Glue` がない。印の箱の `boxKind` が `KindNoteMark` である。
- 横組みで、印の箱の幅が `*1` を大きさ `s/2` で測った値に等しい。縦組みで `s/2` に等しい。
- `」[note]あ` で、印の後ろに `」` と `あ` の組の空きが入る。
- 傍注の `MarkerNumber` の箱が `KindNoteMark` で、文字列が番号だけである。
- 同じ段落に `[note]` を二つ置くと、`AnchorNote` の位置が異なる。
- 改ページで、一つのページに `NoteId` の異なる二つの注 1 が来ても、`poFootnotes` に二つの項目が別々に入る。

### PDF（`modules/golem-driver/test/Main.hs`）

- 二つのファイルがそれぞれ注 1 を持つプロジェクトで、`numbering = "file"` にして組む。各ページの注の行が、そのページの印を含むファイルの注の本文である。今の実装で、後のファイルの注の位置に先のファイルの本文が組まれることを、この期待値で確かめる。
- 注の本文の最初の行の先頭が `*1 ` である。
- 横組みで、印のグリフの大きさが `s/2` であり、印の後ろの字のグリフの原点が、印の最後のグリフの送りの終わり以降にある。印の基準線が本文の基準線より `(c + 1/2) × (s − m)` 上にある。
- 縦組みで、印のグリフが横書きのフォントの参照で描かれ、印の右端が行の中心線から `s/2` 右にある。
- `numbering` の既定で、章を二つのファイルに分けた本の二つ目のファイルの最初の注が、1 ではなく続きの番号になる。HTML とプレーンテキストの出力も同じ番号である。
- マニュアル（`manual/`）を組み、診断が出ない。

### 自動テストにしない確かめ方

- マニュアルの付録の注のページを PDF で開き、印が次の字に重ならないこと、注の本文に番号が付き、本文の印と一致することを目で確かめる。
- 縦組みの試料（蟹工船の原稿に注を足したもの）を組み、印が行の右にそろい、行間の文字と重ならないことを目で確かめる。

## トレードオフ

番号の範囲の既定を `"chapter"` に変えるので、一つのファイルに複数の章を書いた本では、今までと番号が変わらないが、章を複数のファイルに分けた本では番号が変わる。
変わった番号のほうが読み手の期待に合うと判断した。
今の振り方が要る本は `numbering = "file"` と書く。

番号を S1 で振り直すので、評価（S0）の番号と出力の番号が食い違うことがある。
LSP と `golem check` はファイル単位で動き、本の構成を読まないためである。
LSP で注の番号を見せる機能は今はないので、食い違いが書き手の目に触れる場面は今のところない。

マニフェストの章を番号の範囲に使い、見出し 1 を使わなかった。
図番号の `{chapter}`（「style.toml」の節）は見出し 1 で振り直すので、二つの「章」の意味が異なる。
見出し 1 を使うと、見出しのない前付けや後付けのファイルの注が、直前の章の番号を引き継ぐ。
マニフェストの章なら、書き手が配列の形で範囲を明示できる。

印を `*` と算用数字に固定した。
InDesign の既定は上付きの数字だけだと記憶しているが、確かめていない。
Golem のプレーンテキストと PDF の印の形をそろえることを優先し、形式の設定は要望が出てから加える。

縦組みで印を行の中に置くので、印の分だけ行の字数が減る。
行間に置く形なら字数は変わらないが、ルビとの取り合いを決める必要がある。

`[notes]` の `placement` が PDF で効かないことは、この ADR を書くために読んだコードで分かった。
仕様書とマニュアルは `"chapter-end"` を選べると書いているので、記述と実装が食い違っている。
この食い違いを v1 の課題として仕様書に足すかどうかは、所有者の判断を待つ。
