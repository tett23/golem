# ADR 0023: 技術書のためのコードブロックの機能

ステータス: 採択

## 文脈

[golem-driver ADR 0017](0017-pdf-code-blocks.md) は、PDF のコードブロックを正しく読める形で組むための中核を決めた。
等幅の書体の役割 `code`、行頭の空白とタブの保持、両端揃えとハイフネーションとアキをかけない組み方、背景と内側の余白、長い行の折り返し、行のあいだでの改ページである。
技術書の機能（行番号、ファイル名とキャプション、行の強調、注釈の印、差分、PDF の色分け、枠、折り返した印、改ページの続きの表示、`@listing` への同じ指定）は、どれも中核の行の置き方の上に載るとして、別の ADR に回した。
この ADR は、その残りを決める。

[ADR 0017](0017-pdf-code-blocks.md) は採択済みで、実装中である。
この ADR は、[ADR 0017](0017-pdf-code-blocks.md) の組み方（行の格子の占め方、背景、`padding`、折り返し、改ページ）が実装されていることを前提にする。

今の原稿と IR の扱いを、コードで確かめると次のとおりである。

- 文法（`modules/golem-parser/grammar/Golem.hpeg`）の `CodeBlock` は、```` ``` ```` の後に言語の名前（`Lang <- [a-zA-Z0-9_+\-]+`）を一つだけ書ける。言語の名前の後に何かを書くと、コードブロックとして読めない。
- 意味論 IR（`Golem.Doc.IR`）のコードブロックは `CodeBlock (Maybe Text) Text`（言語の名前と、コードの全体）であり、プラグインとの CBOR では tag 6 の二つの欄になる（`Golem.Doc.Cbor`）。IR の ABI の版は `abiVersion = 5` である。
- `@listing` は `Golem.Eval.File.listing` が評価し、`src`（または最初の位置引数）と `lines=N-M` だけを読む。言語の名前を指定する手段がなく、IR は常に `CodeBlock Nothing ...` になる。ほかのキーワード引数は黙って無視される。
- ブロックへの属性のコマンド（`attributeCommands`）は `label`、`toc-title`、`number`、`nonumber`、`notoc`、`style` であり、コードブロックに付けられるのは `@label` だけである。
- 図番号は `Golem.Doc.Assemble.numberDocs` が、階層 1 の見出しで数え直して振り、`[figures]` の `number`（既定 `図{chapter}-{n}`）で表記する。章の外の図版に `{chapter}` を使うと G0404 になる。
- HTML（`Golem.Html`）は、言語の名前があれば skylighting で字句に分け、`<span class="kw">` のような短い class を付ける（`highlighted`、`shortClass`）。`style.css` には、これらの class の色を書いていない。

技術書の慣用を、手元の和文の技術書（オライリー・ジャパン、技術評論社、翔泳社の本）で確かめた結果は次のとおりである（記憶による。特定の書籍の版と頁は確かめていない）。

- リストの番号とキャプションは、コードの上に置く（「リスト 3.2　設定の読み込み」）。図番号とキャプションを図の下に置くのと逆である。
- 行番号は、コードの左に右揃えで置き、本文で「12 行目」のように参照する。
- 注釈の印は、行末に丸数字（①）か黒丸数字（❶）を置き、本文で同じ印を使って説明する。
- 差分は、行頭の `+` と `-` と、行の背景の色（または網）で示す。
- 改ページで分かれたリストには、分かれる側の末尾に「（次ページに続く）」のような文言を置く本と、何も置かない本がある。

AsciiDoc は、行末の `<1>` を注釈の印（callout）として扱い、本文の `<1>` の一覧で説明する。
Pandoc の Markdown と AsciiDoc は、コードブロックの開始の行に属性（行番号の開始、強調する行など）を書く。

## 実装すること

### 記法

コードブロックの開始の行の言語の名前の後と、`@listing` に、同じキーワード引数を書けるようにする。

````
```haskell numbers=10 file="src/Main.hs" highlight=12,14-15 callouts=true
main :: IO ()
main = do
  args <- getArgs          <1>
  mapM_ putStrLn args      <2>
```
````

```
@caption 設定の読み込み
@listing src/Config.hs lines=20-48 lang=haskell numbers=true highlight=25
```

| キー | 値 | 既定 | 意味 |
| --- | --- | --- | --- |
| `numbers` | `true`、`false`、0 以上の整数 | `[code]` の `line-numbers` | 行番号を付けるか。整数は付けたうえで最初の行の番号にする |
| `file` | 文字列 | なし | コードの上に出すファイル名 |
| `highlight` | 行番号の並び（`3`、`3,5-7`） | なし | 強調する行 |
| `diff` | `true`、`false` | `false` | 行頭の `+`、`-`、空白を差分の印として読む |
| `callouts` | `true`、`false` | `false` | 行末の `<N>` を注釈の印として読む |
| `lang` | 言語の名前 | なし | 色分けの言語。`@listing` にだけ書ける |

引数の規則は、ほかのブロックコマンドとインラインの命令文脈と同じである。
```` ``` ```` の開始の行では、言語の名前を書く場合はキーワード引数より前に書く。
言語の名前を書かずに、```` ``` numbers=true ```` のようにキーワード引数だけを書いてもよい。
言語の名前のほかの位置引数と、表にないキーはエラー（G0269）とする。
`@listing` の今の G0236（パスがない）と G0237（`lines` の範囲が不正）は変えない。

**行番号の数え方**。
コードブロックの各行は、行番号を表示するかどうかによらず、番号を持つ。
最初の行の番号は、`numbers` が整数ならその値、`@listing` で `lines=N-M` を書いたなら N、ほかは 1 とする。
後の行は一つずつ増える。
`@listing src/Config.hs lines=20-48` の最初の行は 20 番になり、ファイルの行番号と一致する。
`diff=true` のコードでは、`-` の行（削除した行）は番号を持たず、数えない。
差分の後のコードの行番号に合わせるためである。

**強調**。
`highlight` の値は、上の数え方の行番号の並びとする。
カンマで区切り、`N-M` は N から M までの行とする。
コードブロックにない番号（`-` の行を含む）を書くとエラー（G0269）とする。

**差分**。
`diff=true` のコードでは、各行の最初の一字を差分の印として読み、コードの本文から取り除く。
`+` は追加した行、`-` は削除した行、空白（U+0020）は変わらない行である。
空の行は、変わらない空の行とする。
ほかの字で始まる行はエラー（G0269）とし、位置はその行とする。
色分けは、印を取り除いた後のコードの全体に当てる。

**注釈の印**。
`callouts=true` のコードでは、行末の `<N>`（N は 1 から 50 までの整数）を注釈の印として読み、コードの本文から取り除く。
`<1> <2>` のように空白で区切って並べた複数の印も読む。
印の前の空白も取り除く。
N が 1 から 50 の外ならエラー（G0269）とする。
丸数字（①から㊿）は Unicode に 50 までしかないためである。
本文では、利用者が同じ丸数字（①）を地の文に書いて説明する。
印を本文から参照するコマンドは設けない。

`callouts` を既定で切っておくのは、`List<1>` のように `<数>` で終わるコードが言語によってはあるからである。

**キャプション**。
コードブロックと `@listing` の直前に、属性のブロックコマンド `@caption 本文` を書く。
本文は `@toc-title` と同じく行の残りであり、インラインの要素を書ける。
`@caption` を付けたコードブロックは、リスト番号を持つ。
コードブロックのほかのブロック（段落、見出し、図版など）に `@caption` を付けると、ほかの属性と同じく G0213 とする。
図版のキャプションは、今のとおり `@figure` の字下げした行で書く。
本文のない `@caption` はエラー（G0269）とする。

`@caption` を開始の行の引数（`caption="..."`）にしなかったのは、キャプションに `[code: ...]` のようなインラインの要素を書けるようにするためである。
引数の文字列リテラルの中では、インラインの命令を書けない。

### リスト番号

キャプションを持つコードブロックに、章ごとの番号を振る。
数え方は図番号と同じく、階層 1 の見出しで数え直す。
図番号とは別に数える。
キャプションのないコードブロックは番号を持たず、数えない。

表記は `style.toml` の `[code]` の `number` で決める。
既定は `リスト{chapter}-{n}` とし、図番号の既定（`図{chapter}-{n}`）と形をそろえる。
差し込みは図番号と同じく `formatNumber` で埋める。

章の外のコードブロックに `{chapter}` を使う書式を当てると、図版と同じく G0404 とする。
G0404 の題とメッセージを、図版とコードの両方を指す文言に広げる。

`@label` を付けたキャプションのあるコードブロックは、`[ref-number ...]` でリスト番号を、`[ref-title ...]` でキャプションを参照できる。
キャプションのないコードブロックを `[ref-number ...]` と `[ref-title ...]` で参照すると、番号や題を持たない要素と同じく今の診断でエラーとする（[golem-doc ADR 0003](../../golem-doc/adr/0003-document-diagnostic-codes.md)）。

### style.toml

`[code]` の表を加える。

```toml
[code]
number = "リスト{chapter}-{n}"   # 既定
line-numbers = false             # 既定。true ですべてのコードブロックに行番号
line-number-color = "gray"       # 既定なし（本文の文字の色）
highlight = "code-hl"            # 既定なし（K 15% の網）
added = "code-add"               # 既定なし（背景を塗らない）
removed = "code-del"             # 既定なし（背景を塗らない）
wrap-mark = "↩"                  # 既定は空（印を描かない）
continued = "（次ページに続く）"  # 既定は空（描かない）

[code.colors]
keyword = "code-kw"
comment = "code-cm"
string = "code-st"
```

| キー | 型 | 既定 | 意味 |
| --- | --- | --- | --- |
| `number` | 書式 | `"リスト{chapter}-{n}"` | リスト番号の表記 |
| `line-numbers` | 真偽値 | `false` | `numbers` を書かないコードブロックに行番号を付けるか |
| `line-number-color` | スウォッチの名前 | なし | 行番号の色 |
| `highlight` | スウォッチの名前 | なし | 強調する行の背景 |
| `added`、`removed` | スウォッチの名前 | なし | 差分の追加した行と削除した行の背景 |
| `wrap-mark` | 文字列 | `""` | 折り返した行の行末に描く印 |
| `continued` | 文字列 | `""` | 改ページで分かれたコードブロックの、分かれる側の末尾に描く文言 |

`[code.colors]` は、字句の種類からスウォッチの名前への表であり、PDF の色分けに使う。
字句の種類は skylighting の `TokenType` を kebab-case にした名前（`KeywordTok` は `keyword`、`DataTypeTok` は `data-type`）とする。
書ける名前は `keyword`、`data-type`、`dec-val`、`base-n`、`float`、`char`、`string`、`comment`、`other`、`alert`、`function`、`region-marker`、`error`、`constant`、`special-char`、`verbatim-string`、`special-string`、`import`、`documentation`、`annotation`、`comment-var`、`variable`、`control-flow`、`operator`、`built-in`、`extension`、`preprocessor`、`attribute`、`information`、`warning` である。
表にない種類の字句と、`[code.colors]` を書かない本の字句は、本文の文字の色で組む。
既定を色なしにするのは、本文を墨一色で刷る本が多く、色分けを既定にすると、その本でも利用者が色を消す設定を書く必要が生じるからである。

`[code]` と `[code.colors]` の未知のキー、`number` が差し込みを含まない書式、真偽値でない `line-numbers` は G0306 とする。
スウォッチの名前が `[color.swatches]` にない場合は、文字スタイルの `color` と同じく G0313 とする。

強調の網の既定を K 15% にするのは、強調だけは行番号や印のような別の手がかりを持たず、色を設定しない本で強調が見えなくなるのを避けるためである。
この網は `[color.swatches]` の名前を持たない、プロセスカラーの墨 15% の DeviceCMYK とする。
追加と削除の行は `+` と `-` の印で区別できるので、背景の既定を持たない。

[ADR 0017](0017-pdf-code-blocks.md) の段落スタイル `code` に、枠のキーを二つ足す。

| キー | 型 | 既定 | 意味 |
| --- | --- | --- | --- |
| `border` | スウォッチの名前 | なし | 枠の色。書かなければ枠を描かない |
| `border-width` | 寸法（`mm`、`pt`、`Q`、`H`） | `"0.25pt"` | 枠の線の太さ |

ADR 0017 の `background` と `padding` と同じく、`code` にだけ書け、ほかの段落スタイルに書くと G0306 とする。
`@style-def paragraph code` でも書ける。

### PDF の組み方

コードブロックの領域を、行の始まりの側から次の列に分ける。
どの列も、コードの文字の大きさとコードの役割のフォントで組む。

1. 内側の余白（ADR 0017 の `padding`）。
2. 行番号の列（行番号を付けるときだけ）。幅は、そのコードブロックの最大の行番号の桁数の数字を組んだ幅とし、各番号を列の終わりにそろえる。列の後に、空白の送りの 2 倍を空ける。
3. 差分の印の列（`diff=true` のときだけ）。幅は空白の送りの 2 倍とし、`+` か `-` を列の始まりに置く。変わらない行には何も置かない。
4. コードの列。ADR 0017 のとおりに組む。
5. 注釈の印と折り返した印は、コードの列の中に置く（下を参照）。
6. 内側の余白。

ADR 0017 の行長の不足の検査（G0743）は、行長から、左右の `padding`、行番号の列と空き、差分の印の列、`wrap-mark` の幅を引いた幅で行う。
行番号と差分の印を付けた結果、コードの列がコードの文字の 8 字分に満たなくなれば、G0743 になる。

**行番号**。
行番号は算用数字で、縦組みの本でも ADR 0017 の縦組みのコードと同じく行の方向に置く。
折り返した続きの行には、行番号を置かない。
`line-number-color` があればその色で、なければ本文の文字の色で描く。

**ファイル名**。
`file` があれば、コードブロックの最初の部分の先頭に一行を足し、ファイル名をコードの列の始まりにそろえて描く。
この行は背景の内側にあり、ADR 0017 の行の格子の占め方の計算では、コードの一行として数える。
改ページで分かれた後の部分には、ファイル名を繰り返さない。

**キャプション**。
キャプションのあるコードブロックは、リスト番号、全角の空白、キャプションを、コードブロックの上に置く。
組み方は図版のキャプションと同じく、段落スタイル `caption` の `font` と `size` で、行送りの比を保って組む（[ADR 0010](0010-caption-style.md)）。
キャプションは背景の外にあり、行の格子の上から始める。
キャプションの最後の行の後から、ADR 0017 の規則でコードブロックの格子の行を占める。
キャプションとコードブロックの最初のコードの一行（と上下の `padding`）が同じページに収まらなければ、キャプションごと次のページから始める。
キャプションを分けて置くことはしない。

**強調、追加、削除の背景**。
強調する行と、`added` か `removed` の色を持つ差分の行は、その行（折り返した続きの行を含む）が占めるコードの行送りの帯を、背景の左右の範囲いっぱいに塗る。
帯の天地は、その行の最初の行のベースラインからコードの行送りで数えた、行送りの範囲とする。
帯は ADR 0017 の背景の上、文字の下に描く。
強調と差分の色が同じ行に重なる場合は、強調の色で塗る。

**色分け**。
言語の名前（```` ``` ```` の後の名前、または `@listing` の `lang`）が skylighting の構文にあれば、HTML と同じく字句に分け、`[code.colors]` の表にある種類の字句をそのスウォッチの色で描く。
言語の名前が skylighting にない場合と、字句に分けるのに失敗した場合は、色を付けずに組み、診断を出さない。
HTML の今の扱い（`highlighted`）と同じにするためである。
色は文字の色だけを変え、太さや斜体は変えない。

**注釈の印**。
注釈の印は、丸数字（① は U+2460、㉑ は U+3251、㊱ は U+32B1 から）で描く。
同じ行に複数の印があれば、空白の送り一つ分を空けて並べる。
印の位置は、コードブロックの単位で決める。

- 印を持つ行の（折り返した場合は最後の部分の）行末の位置の最大に、空白の送りの 2 倍を足した位置を、印の列の始まりとする。
- 印の列の始まりに印の幅を足して、コードの列に収まれば、印を持つすべての行の印をその位置にそろえる。
- 収まらなければ、各行の印を、その行の行末から空白の送りの 2 倍の後に置く。それでも収まらない行は、ADR 0017 の折り返しと同じく印の前で折り返し、続きの行の始まりの位置に印を置く。

丸数字は、コードの役割のフォントで組む。
欧文のフォントに丸数字がなければ、ほかの文字と同じく和文のフォントで組む。

**折り返した印**。
`wrap-mark` が空でなければ、ADR 0017 の規則で折り返した行のうち、次の行に続く各行の行末に、その文字列をコードの列の終わりにそろえて描く。
印の幅の分だけ、ADR 0017 の折り返しの幅を狭める。
印がコードの文字に重ならないためである。
印は行番号の色の規則に合わせ、`line-number-color` があればその色で描く。

**続きの表示**。
`continued` が空でなければ、ADR 0017 の改ページでコードブロックが分かれるとき、最後の部分のほかの各部分の末尾に一行を足し、その文字列をコードの列の終わりにそろえて描く。
この行は背景の内側にあり、その部分が占める格子の行の計算に含める。
ページに残る格子の行に、コードの一行、この行、上下の `padding` が収まらなければ、ADR 0017 と同じく次のページから始める。
一ページに、コードの一行、この行、上下の `padding` が収まらない場合は、ADR 0017 の G0743（一行が一ページに収まらない）とする。

**枠**。
`border` があれば、ADR 0017 の背景の矩形と同じ矩形の線を、`border-width` の太さでスウォッチの色で描く。
線の中心を矩形の辺に置く。
改ページで分かれた部分ごとに、閉じた矩形を描く。

### HTML と EPUB

- キャプションかファイル名のあるコードブロックは、`<figure class="listing">` で包む。キャプションは `<figcaption>` にリスト番号、全角の空白、キャプションを入れ、`<pre>` の前に置く。ファイル名は `<div class="code-file">` で、`<pre>` の直前に置く。
- 行番号、強調、差分、注釈の印のどれかを持つコードブロックは、各行を `<span class="line">` で包み、行の改行は `</span>` の後に置く。行番号は `<span class="ln" aria-hidden="true">12</span>`、差分の印は `<span class="dm" aria-hidden="true">+</span>`、注釈の印は `<span class="callout">①</span>` とする。強調する行は `class="line hl"`、追加と削除の行は `class="line add"` と `class="line del"` とする。
- `style.css` に、`.ln` と `.dm` の `user-select: none`、`.ln` の右揃えの幅（最大の桁数の `ch`）、`.hl`、`.add`、`.del` の背景の色（スウォッチの RGB の近似、強調の既定は K 15% の近似）、`.ln` の色を書く。`[code.colors]` があれば、`code span.<短い class>` の `color` を書く。`[code.colors]` がなければ、今のとおり色を書かない。`border` があれば、`pre` に `border` を書く。
- `wrap-mark` と `continued` は、ページと固定の行長を持たない媒体なので出さない。
- `@listing` の `lang` は、```` ``` ```` の言語の名前と同じく `class="sourceCode language-..."` にする。

コピーしたときに行番号と差分の印が混ざらないよう、`aria-hidden` と `user-select: none` を付ける。

### プレーンテキスト

キャプションがあれば、リスト番号、全角の空白、キャプションの一行をコードの前に出す。
ファイル名があれば、その一行をその後に出す。
差分の印は、取り除く前の行の最初の一字のまま出す。
注釈の印は、丸数字にして行末に空白一つを空けて出す。
行番号、強調、色は出さない。

### 診断

| コード | 重大度 | 段階 | 出す条件 | メッセージ |
| --- | --- | --- | --- | --- |
| G0269 | エラー | 評価 | コードブロックと `@listing` の引数と中身の誤り、`@caption` の本文の欠け | 下の一覧 |

G0269 のメッセージは、誤りの種類ごとに次のとおりとする。

- 表にないキー：`コードブロックに書けないキーです: <キー>。numbers、file、highlight、diff、callouts（@listing では lang も）を書けます`
- 言語の名前のほかの位置引数：`コードブロックの開始の行には、言語の名前とキーワード引数だけを書けます`
- 値の誤り：`<キー> の値が正しくありません: <値>`
- 強調の行がない：`highlight の行 <番号> はこのコードにありません`
- 差分の印の誤り：`diff=true のコードの行は +、-、空白のどれかで始めます`。位置はその行。
- 注釈の印の範囲：`注釈の印の番号は 1 から 50 までです: <番号>`。位置はその行。
- `@caption` の本文の欠け：`@caption には本文を書きます`

G0269 は未使用である。
G0404 は、題を `章の外にある図版とコードに、章番号を使う番号を振れません` に変え、`[code]` の `number` が `{chapter}` を使う場合も出す。
`@caption` をコードブロックのほかのブロックに付けた場合は、今の G0213 で報告する。
`[code]`、`[code.colors]`、`border`、`border-width` の誤りは、既存の G0306 と G0313 で報告する。
ADR 0017 の G0730（折り返したお知らせ）と G0743（行長の不足、一ページに収まらない）は、上に書いた幅と行の数で同じく出す。

### 意味論 IR とプラグインの ABI

コードブロックの IR を次のように変える。

```haskell
data BlockBody
  = ...
  | CodeBlock !Code -- CodeBlock (Maybe Text) Text を置き換える
  ...

data Code = Code
  { codeLang :: !(Maybe Text),
    codeNumbers :: !(Maybe Bool),      -- Nothing なら [code] の line-numbers
    codeFile :: !(Maybe Text),
    codeCaption :: !(Maybe [Inline]),
    codeDiff :: !Bool,
    codeLines :: ![CodeLine]
  }

data DiffMark = DiffAdded | DiffRemoved | DiffContext

data CodeLine = CodeLine
  { clText :: !Text,                  -- 差分の印と注釈の印を取り除いた行
    clNumber :: !(Maybe Integer),     -- 削除した行は Nothing
    clDiff :: !(Maybe DiffMark),      -- diff=true でなければ Nothing
    clHighlight :: !Bool,
    clCallouts :: ![Int]
  }
```

行番号、差分の印、注釈の印、強調は golem-eval が評価の段階で決めて IR に入れる。
誤りを原稿の行の位置で報告でき、PDF、HTML、プレーンテキストが同じ読み方を共有するためである。
リスト番号は、図番号と同じく golem-doc の `numberDocs` が振り、`Book` に `bookListings :: Map SrcSpan Text` を加える。

プラグインとの CBOR の tag 6 の形が変わるので、`abiVersion` を 6 に上げる。
ABI の版の違うプラグインは、今と同じく G0605 で読み込みを止める。

### ドキュメント

- docs/specifications.md の「v1 の実装で次の段階以降に回した項目」の「PDF のコードブロック」を、本文の中のコードの背景の色だけを残す形に書き換える。技術書の機能をこの ADR で扱ったことを、項目から外す。
- 同じく「style.toml」に `[code]`、`[code.colors]`、段落スタイル `code` の `border` と `border-width` を、「目次と文書構造の参照」の節の近くにリスト番号を書く。
- docs/markup.md の「コードブロック」に、開始の行と `@listing` のキーワード引数の表、行番号の数え方、差分と注釈の印の書き方を書く。「ブロックへの属性」に `@caption` を加える。「ブロックコマンド」の `@listing` の行に `lang` を加える。
- docs/diagnostics.md に G0269 の節を足し、G0404 の題と意味を広げる。
- プラグインの文書（docs/golem-plugin/specifications.md）の IR の説明があれば、コードブロックの形と ABI の版 6 を書く。
- 利用者のマニュアル（`manual/`）に、行番号、キャプション、強調、差分、注釈の印、`[code]` の設定を書く（[docs/adr/0024](../../adr/0024-manual-audiences-and-policy.md)）。使い方は `manual/chapters/03-markup.gm` の「コードと外部のファイル」の節（ラベル `code-blocks`）に、記法は `manual/appendices/a-markup.gm` の「ブロックの記法」と「ブロックコマンド」に、設定のキーは `manual/appendices/c-style.gm` に書く。G0269 の項を加え、G0404 の項を広げた題と意味に改める。対象は `manual/appendices/e-errors.gm`（付録E「診断の一覧」。[golem-cli ADR 0006](../../golem-cli/adr/0006-preflight.md) より前に実装するときは `d-errors.gm` の付録D）である。

## データ構造の変更

- golem-parser：文法の `CodeBlock` の開始の行に、言語の名前の後の `Arguments` を加える。生成したパーサーとラベルを外した文法を生成し直す。AST の `CodeBlock` に引数の列を加える。
- golem-doc：`CodeBlock !Code`、`Code`、`CodeLine`、`DiffMark` を加え、`Book` に `bookListings` を加える。`AssembleConfig` に `acListingFormat` を加える。CBOR の tag 6 を変え、`abiVersion` を 6 にする。
- golem-eval：属性のコマンドに `caption` を加える。`listing` が `lang`、`numbers`、`file`、`highlight`、`diff`、`callouts` を読む。
- golem-project：`Style` に `stCode :: !CodeStyle`（`[code]` と `[code.colors]`）を加え、`ParagraphStyle` に `psBorder :: !(Maybe Text)`、`psBorderWidth :: !(Maybe Dim)` を加える。
- golem-layout：ADR 0017 のコードの行の単位に、行番号の列、差分の印の列、注釈の印の位置、折り返した印の幅、ファイル名の行と続きの表示の行、キャプションの行を加える。
- golem-driver：帯と枠の描画、字句の色を加える。
- golem-html、golem-text：上の出力を加える。

## 実装しないこと

- 本文から注釈の印を参照するコマンド（`[callout 1]` など）。利用者が丸数字を本文に書く。
- 黒丸数字（❶）など、注釈の印の形を変える設定。
- 注釈の印を `// <1>` のようなコメントの中に書く記法（AsciiDoc にはある）。
- 色分けの字句の太さと斜体、色分けの配色の既定の組（テーマ）。
- 行番号を数行おきに表示すること（5 行ごとなど）。
- 強調を行の一部（語）に限ること。
- 差分の行の中の変わった字の強調（語の単位の差分）。
- `@listing` で、ファイルの拡張子から言語の名前を推すこと。
- キャプションを下に置く設定、リスト番号とキャプションで書体を変えること。仕様書の「図版とキャプションの拡張」と合わせて扱う。
- リストの目次（リストの一覧）。仕様書の「目次の拡張」の図目次と表目次と合わせて扱う。
- 本文の中のコード（`[code: ...]`）の背景の色。ADR 0017 のとおり、仕様書の項目に残す。
- 縦組みの本で、コードブロックを横組みの囲みとして組むこと。
- 改ページで分かれた後の部分の先頭に「（続き）」を描くこと。

## テスト設計

先に書き、失敗させてから実装する。

### golem-parser

- ```` ```haskell numbers=10 file="a.hs" ```` が、言語の名前 `haskell` と二つのキーワード引数のコードブロックとして読めること。
- ```` ``` numbers=true ```` が、言語の名前のないコードブロックとして読めること。
- 言語の名前だけの今のコードブロックの AST が変わらないこと。生成したパーサーとラベルを外した文法が同じ入力を受理すること（今の golem-parser のテスト）。

### golem-eval

- `numbers=10` の三行のコードの `clNumber` が 10、11、12 になること。`numbers=true` で 1、2、3、`numbers=false` で `codeNumbers = Just False` になること。
- `@listing x.hs lines=20-22` の行番号が 20、21、22 になること。`numbers=5` を足すと 5、6、7 になること。
- `highlight=2,4-5` で、2 番、4 番、5 番の行の `clHighlight` が真になること。`highlight=9` が三行のコードで G0269 になること。
- `diff=true` の `+a`、`-b`、` c`、空の行が、`DiffAdded`、`DiffRemoved`、`DiffContext`、`DiffContext` になり、`clText` が `a`、`b`、`c`、空になること。`-b` の `clNumber` が `Nothing` で、` c` の番号が `+a` の次になること。`xa` の行が G0269 になり、位置がその行であること。
- `callouts=true` の `foo  <1>` が `clText = "foo"`、`clCallouts = [1]` になり、`bar <2> <3>` が `[2, 3]` になること。`<51>` が G0269 になること。`callouts` を書かないコードでは `<1>` が本文に残ること。
- `@caption 設定の [code: x] の読み込み` を付けたコードブロックの `codeCaption` が、文字スタイル `code` を含むインラインの列になること。`@caption` を段落に付けると G0213、本文のない `@caption` が G0269 になること。
- ```` ```haskell foo ````（余分な位置引数）、`unknown=1`、`numbers=-1`、`numbers=abc`、`diff=yes` が G0269 になること。
- `@listing x.hs lang=haskell` の `codeLang` が `haskell` になること。```` ``` ```` の開始の行の `lang=haskell` が G0269 になること。

### golem-doc

- キャプションのある二つのコードブロックと一つのキャプションのないコードブロックを含む二つの章で、リスト番号が `リスト1-1`、`リスト1-2`、`リスト2-1` になり、キャプションのないブロックが番号を持たないこと。図番号と独立に数えること。
- 章の外のキャプションのあるコードブロックが G0404 になること。`number = "リスト{n}"` では G0404 にならないこと。
- `@label` を付けたキャプションのあるコードブロックを `[ref-number ...]` と `[ref-title ...]` で参照できること。キャプションのないブロックを `[ref-number ...]` で参照すると、今の番号を持たない要素の診断になること。
- CBOR の往復で `Code` が変わらないこと。`abiVersion` が 6 であること。

### golem-project

- `[code]` のすべてのキーと `[code.colors]` を読めること。何も書かないときの既定が上の表のとおりであること。
- `[code] line-numbers = "yes"`、未知のキー、`[code.colors] keywords = "x"`（表にない種類）、`number = "リスト"`（差し込みなし）が G0306 になること。
- `[code] highlight = "nope"` と `[code.colors] keyword = "nope"`（スウォッチがない）が G0313 になること。
- `[paragraph-styles.code] border = "black"`、`border-width = "0.5pt"` を読めること。`[paragraph-styles.quote] border = "black"` と `border-width = "1zw"` が G0306 になること。

### golem-layout と golem-driver

組版の結果は、ADR 0017 のテストと同じく、ページごとの行と字の位置の一覧で比べる。

- 行番号：9 行目から 11 行目のコードで、行番号の列の幅が二桁の数字の幅になり、`9` と `10` の終わりの位置がそろうこと。コードの最初の字の位置が、`padding`、列の幅、空白の送りの 2 倍の和であること。折り返した続きの行に番号がないこと。
- 行長の不足：行番号と差分の印を付けた結果、コードの列が 8 字分を切るリストの中のコードブロックが G0743 になり、付けなければ G0743 にならないこと。
- ファイル名：`file` のあるコードブロックが、ないものより格子の行を一つ多く（または計算のとおりに）占め、最初の行にファイル名があること。改ページで分かれた後の部分の先頭にないこと。
- キャプション：キャプションがコードブロックの上にあり、`caption` の大きさで組まれ、背景の矩形の外にあること。ページの残りにキャプションとコードの一行が収まらないとき、キャプションごと次のページに送られること。
- 強調：`highlight=2` で、2 行目の帯の矩形が K 15% で、背景の矩形の後、2 行目の字の前に描かれること。`[code] highlight` があればそのスウォッチになること。折り返した 2 行目では帯が続きの行も覆うこと。
- 差分：`+` と `-` が差分の印の列に描かれ、`added` と `removed` を書いたときだけ帯が塗られること。
- 色分け：`[code.colors] keyword = "kw"` で、Haskell の `where` の字が `kw` の色で、ほかの字が本文の文字の色で描かれること。`[code.colors]` がないとき、色の設定の演算子が内容のストリームにないこと。skylighting にない言語の名前で、色なしで組まれ、診断が出ないこと。
- 注釈の印：短い二行に `<1>` と `<2>` を付けたとき、二つの丸数字の始まりの位置がそろい、長いほうの行末から空白の送りの 2 倍の位置にあること。そろえると収まらない長い行があるとき、行ごとの位置になること。
- 折り返した印：`wrap-mark = "↩"` で、折り返した行の行末に `↩` が列の終わりにそろって描かれ、最後の部分には描かれないこと。印の幅だけ、折り返す位置が前に来ること。
- 続きの表示：`continued` を書いた本で、二ページに分かれたコードブロックの前の部分の末尾に文言の行があり、後の部分にないこと。文言の行の分だけ、前の部分のコードの行が一行少ないこと。
- 枠：`border` で、部分ごとに背景と同じ矩形の線が `border-width` の太さで描かれること。
- 縦組み：縦組みの版面で、行番号の列が行の方向の始まりに置かれること。
- `@listing` に同じ指定をしたコードが、```` ``` ```` の同じ指定のコードと同じに組まれること。
- 技術書の機能を使わないコードブロックの組版の結果が、ADR 0017 の組み方と一致すること。
- 並列と逐次で組んだ PDF のバイト列が一致すること。

### golem-html と golem-text

- キャプションとファイル名のあるコードブロックが `<figure class="listing"><figcaption>リスト1-1　...</figcaption><div class="code-file">a.hs</div><pre>` になること。どちらもないコードブロックの出力が今と変わらないこと。
- 行番号、強調、差分、注釈の印の各 `span` と class が出ること。`style.css` に `.ln` と `.dm` の `user-select: none` が書かれること。
- `[code.colors]` があるとき、`code span.kw` の `color` が書かれ、ないとき書かれないこと。
- プレーンテキストで、キャプションの行、ファイル名の行、差分の印のついた行、丸数字の印が出ること。

### 自動テストにしない確かめ方

## トレードオフ

技術書の機能を開始の行のキーワード引数にしたので、```` ``` ```` の後に書けるものが言語の名前だけでなくなり、文法が変わる。
属性のブロックコマンド（`@numbers` など）で書く方式にすると、機能ごとにコマンドが増え、`@listing` と ```` ``` ```` で書き方が分かれる。
キーワード引数なら、`@listing` と同じ書き方を ```` ``` ```` にそのまま使える。
キャプションだけは、インラインの要素を書くために `@caption` に分けた。

IR のコードブロックの形を変えるので、プラグインの ABI の版が上がり、今のプラグインは作り直しが要る。
IR を変えずに属性を文字列のまま渡すと、行番号や差分の読み方をプラグインと各出力がそれぞれ実装することになる。

注釈の印を `<N>` に決めたので、コードの中の `<数>` で終わる行と衝突しうる。
`callouts=true` を書いたコードブロックでだけ読むことで、衝突を書き手が選べる範囲に限った。

色分けの既定を色なしにしたので、色分けを使うには `[code.colors]` を書く必要がある。
色分けの既定の配色を持つと、墨一色の本で色を消す設定が要り、プロセスカラーの配色を Golem が決めることにもなる。

強調の網の既定に、名前のない K 15% を使うので、「色は名前で指定する」原則（仕様書の「スポットカラー」の項）の例外が一つ増える。
既定を持たない場合は、強調を指定したのに何も見えないコードブロックが黙って組まれる。

続きの表示は、分かれる側の末尾だけに描き、後の部分の先頭の「（続き）」は描かない。
両方を描くと、一つの改ページで格子の行を二行使い、短いコードブロックが分かれにくくなる。
