# ADR 0033: コードブロックの直後の行のルビと圏点

ステータス: 採択

## 文脈

メンテナーから、使い手のマニュアルの PDF でルビがコードブロックに重なっているという指摘があった。
ローカルで最後に組んだマニュアルの PDF の 44 ページ（「振り仮名」の節）で、コードブロック `[ruby: a\/b|えー]` の直後の段落の一行目にある、親文字「a/b」のルビ「えー」の上半分が、コードブロックの背景（墨 8% の網）に隠れている。
ページを画像にして確かめた（PDFKit でページを描くだけの使い捨てのスクリプトによる。リポジトリには置かない）。

### 原因

コードで確かめると、原因はコードブロックの背景の範囲が、直後の行のルビの置き場所まで広がっていることにある。

- コードブロックは、`codeSpan` の数の格子の行を占める（golem-layout の `Golem.Layout.Code`）。背景の矩形（`Golem.Driver.Pdf` の `codeRect`）は、最初の格子の行の字面の上端から行間の半分 `(p − h)/2` だけ前から、`n × p` の幅で塗る（`p` は行送り、`h` は格子の字面の高さ、n は占める格子の行の数）。したがって、背景の後の端は、直後の格子の行の字面の上端（縦組みでは右端）から `(p − h)/2` だけ手前にある。帯と枠（[ADR 0023](0023-code-block-book-features.md)）も同じ範囲に描く。
- 横組みのルビの読みは、親文字のうち最も大きい字の大きさ `s` だけ親文字の基準線から上げた基準線に、親文字の半分の大きさで置く（`drawLineAt`）。字面の枠の上端を基準線から `0.88s` とする書体では、読みの字面の枠は、親文字の字面の上端からおよそ `0.06s` から `0.56s` までの範囲にある（`0.88` は書体による。マニュアルの書体の値は確かめていない）。圏点は、字面の上端から圏点の大きさ（`s/2`）の範囲にある（[ADR 0019](0019-pdf-kenten-shapes.md)）。
- マニュアルの版面は、本文 13Q、行送り 22H である。行間は 9H で、背景と直後の行の字面のあいだは、その半分の 4.5H（およそ 1.1mm）しかない。ルビの読みは字面からおよそ 1.8mm まで張り出すので、読みの外側の 0.7mm ほどが背景に入る。画像で見た重なりの量と合う。

ルビと圏点は、どの行でも行間に張り出す。
行間をルビの置き場所として使うのは、本文の行どうしでは問題にならない。
コードブロックは、行間の半分まで背景を塗るので、直後の行のルビと圏点の置き場所を奪う。
コードブロックの直前の行のルビと圏点は、その行の前（横組みの上、縦組みの右）に張り出し、コードブロックとは逆の側にあるので重ならない。

### 本文の中のコードの背景との関係

草稿の[本文の中のコードの背景の色](0029-inline-code-background.md)は、本文の中のコードの背景を行の字面だけに塗り、ルビと圏点と重ならないように決めた。
今回の重なりはコードブロックの背景で起きており、本文の中のコードとは描き方も直し方も違うので、別の ADR にする。

## 実装すること

### 空きの行を一行足す

コードブロックの直後の行が、コードブロックの側にルビか圏点を張り出し、その張り出しが背景に届く場合は、コードブロックとその行のあいだに空きの行を一行足す。

- **届くかの判定**：直後の行のルビと圏点の張り出しの最大を `r` とする。`r` は、親文字の字面の端から、読みの字面の枠の外側の端、または圏点の外側の端までの距離である。コードブロックに枠があれば枠の太さの半分を `b`、なければ 0 とする。`r > (p − h)/2 − b` のとき、届くとする。`r` は、描画（`drawLineAt`）が読みと圏点を置く位置と同じ関数で求める。同じ関数を、草稿の[段落スタイルの罫線](0027-paragraph-style-rules.md)の罫線の領域の計算にも使い、`LineBox` の `lbOverhang` に入れる。
- **対象のコードブロック**：背景、帯、枠のどれかを持つコードブロックだけを対象にする。どれも持たないコードブロックは行間を塗らないので、空きの行を足さない。
- **対象の行**：コードブロックの直後に置く要素の最初の行である。段落の行、見出しの行、定義リストの用語の行、表の見出しの行がこれにあたる。行の中のどこにルビがあっても、背景は段の行の始まりから終わりまで塗るので、届くかの判定は行の全体で一つにする。
- **足し方**：golem-driver は、レイアウトの流れ（`Flow`）を作るとき、該当する `FCode` の直後に `FSpace 1` を置く。`FSpace` は、段でまだ何も使っていなければ空きを取らないので（[docs/adr/0003](../../adr/0003-verse-line-breaks.md)、`Golem.Layout.Paginate`）、コードブロックが段の終わりで終わり、直後の行が次の段の先頭に来る場合は、空きの行は残らない。
- **縦組み**：ルビと圏点は行の右に張り出し、コードブロックの直後の行の右はコードブロックの側なので、同じ規則で判定する。
- 空きの行は、行の格子をずらさない。直後の行は、一行あとの格子の行に置く。

### 足さない場合

- コードブロックの直後に、`space-between` などの空きの行がすでにある場合。
- コードブロックの直後に改ページ（`ForcedBreak`）がある場合。
- 直後の要素が図版か、別のコードブロックの場合。図版は行間に張り出す読みを持たない。

### ドキュメント

- docs/specifications.md：「コードブロック」の節に、背景、帯、枠を持つコードブロックの直後の行のルビと圏点が背景に届く場合は、空きの行を一行足すことを書き、この ADR へのリンクを付ける。
- 使い手のマニュアル：`manual/chapters/05-style.gm` のコードブロックの背景の説明に、同じことを一文で加える。

## 実装しないこと

- 背景の範囲を、直後の行のルビの有無によって縮めること。コードブロックごとに網の大きさが変わって見えるためである（トレードオフ）。
- 空きの行の代わりに、行の格子からずらして直後の行を置くこと。
- コードブロックの前の端（直前の行の側）の判定。直前の行のルビと圏点はコードブロックと逆の側に張り出すので、重ならない。
- 表、図版、見出しの行取りの余白とルビの重なり。どれも行間を塗らないので、今は起きない。
- 段落スタイルの罫線とルビの重なり。草稿の[段落スタイルの罫線](0027-paragraph-style-rules.md)が、同じ張り出しを罫線の領域に数えて扱う。
- HTML と EPUB。行の格子がなく、`<pre>` の背景と次の段落のルビの位置はブラウザーが決める。

## テスト設計

実装の前に書き、失敗することを確かめる。

### 判定の関数（golem-driver の純粋な関数のテスト）

- 字の大きさ 10pt、行送り 17pt（行間の半分 3.5pt）の格子で、ルビのない行は届かない。
- 同じ格子で、読みの張り出し 5.6pt の行（10pt の親文字のルビ）は届く。
- 行送り 25pt（行間の半分 7.5pt）の格子では、同じルビの行は届かない。
- 枠の太さ 1pt のコードブロックでは、張り出しが 3.1pt の行が届く（3.5pt − 0.5pt を超えるため）。
- 圏点の張り出し（字の大きさの半分）も、同じく判定される。

### PDF（`modules/golem-driver/test/Main.hs`）

- 背景を持つコードブロックの直後に、一行目にルビのある段落を置くと、段落の一行目がコードブロックの最後の格子の行の二つ後の格子の行に置かれ、読みのグリフの範囲が背景の矩形と交わらない。
- 同じ本で、段落の一行目にルビがなければ、一行目はコードブロックの直後の格子の行に置かれる（今と同じ）。
- 背景、帯、枠のどれも持たないコードブロックでは、ルビがあっても空きの行が入らない。
- 縦組みで、コードブロックの直後の行のルビが、背景の矩形と交わらない。
- コードブロックが段の最後の格子の行で終わる場合、ルビのある段落は次の段の先頭から置かれ、先頭に空きの行がない。
- コードブロックの直後の行のルビの有無によらず、PDF のバイト列が二回のビルドで一致する。
- ルビのある行がコードブロックの直後にない本の PDF のバイト列が変わらないことを、既存の PDF のテストで確かめる。

### 自動テストにしない確かめ方

- 使い手のマニュアルを組み、「振り仮名」の節の `[ruby: a\/b|えー]` のコードブロックの直後の行で、ルビ「えー」が網に重ならないことを、ページを画像にして目で確かめる。

## トレードオフ

背景の範囲を変えず、空きの行を足すことにした。
背景を直後の行のルビの分だけ縮めると、行の格子は保てるが、同じ本のコードブロックの網の下の余白が、直後の行によって違って見える。
空きの行は格子を保ち、網の大きさもそろうが、ページの行を一行使う。
コードブロックの直後の行にルビか圏点がある場合だけなので、使う行は少ない。

すべてのコードブロックの背景を、行間に張り出さないように変える案もある。
しかし、背景の上下の余白が減り、コードの行とコードブロックの端が近づく。
コードブロックの占める格子の行の数（`codeSpan`）も変わり、コードブロックを持つすべての本の改ページが変わる。

判定を行の全体で一つにしたので、背景から横に離れた位置のルビでも空きの行が入る。
背景は段の行の始まりから終わりまで塗るので、横に離れた位置は、段落の字下げの分しかない。
