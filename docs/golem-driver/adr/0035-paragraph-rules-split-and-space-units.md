# ADR 0035: 分けて組んだ段落の罫線と、罫線の間隔の単位

ステータス: 採択

## 文脈

[ADR 0027](0027-paragraph-style-rules.md) は、段落スタイルと見出しの罫線を定めた。
実装のプルリクエスト（#198）では、ADR が定めていない箇所を実装の側で決め、ずれとして報告した。
メンテナーは、そのうち二つについて振る舞いを決めた。
どちらも [ADR 0027](0027-paragraph-style-rules.md) の定めを改めるか補うので、この ADR で定める。

### 分けて組んだ段落の罫線

罫線を持つ段落が空の段にも入らないとき、[ADR 0027](0027-paragraph-style-rules.md) の「入らない段落の分け方」は、段落を孤立行と泣き別れの規則で段に分け、前の罫線の領域を最初の部分の前に、後の罫線の領域を最後の部分の後に置くと定めている。
お知らせ G0746 を出し、分けた箇所には罫線を引かない。

#198 の実装は、前の罫線を最初の部分の前に引いた。
後の罫線は、その領域が最後の部分の後に入れば引き、入らなければ省いた。
[ADR 0027](0027-paragraph-style-rules.md) は、後の罫線が入らない場合の扱いを定めていなかった。

メンテナーは、段落を分けて組んだときは、前の罫線も後の罫線も引かないと決めた。
後の罫線は、入るかどうかにかかわらず引かない。
前の罫線も、不要なので省く。

### 罫線の間隔の単位

[ADR 0027](0027-paragraph-style-rules.md) の表は、`space-before` と `space-after` を寸法とし、`length` の `zw` だけを段落スタイル（見出しでは見出し）の文字の大きさで解決すると定めている。
間隔の `zw` をどの大きさで解決するかは書いていない。
#198 の実装は、間隔を格子の字面から測ることに合わせ、間隔の `zw` を版面の文字の大きさ（`[page.grid]` の `font-size`）で解決した。

罫線の指定の寸法は、`Golem.Project.Style` の `parseSignedDim` で読むので、今のコードでも `mm`、`pt`、`Q`、`H`、`zw` を書ける。
ただし、仕様書とマニュアルの段落の罫線の説明は、例と既定を `zw` だけで書いており、`mm` を書けることが読み取りにくい。

メンテナーは、段落と見出しの罫線の間隔を、今の単位に加えて `mm` でも指定できることを求めた。
ここでの間隔は、罫線と本文のあいだの間隔（`space-before` と `space-after`）であり、破線の線分のあいだの `gap`（[ADR 0028](0028-rule-colour-and-style.md)）ではない。
あわせて、`zw` の解決のしかたを決め、文書に書くよう求めた。

HTML と EPUB の CSS は、#198 の実装では間隔の `zw` を `em` に写している。
`em` はその要素の文字の大きさで解決されるので、段落スタイルの `size` が版面の文字と違えば、PDF と違う間隔になる。

### メンテナーが決めたこと

- 分けて組んだ段落には、前の罫線も後の罫線も引かない。後の罫線の領域が最後の部分の後に入る場合も同じである。
- 段落と見出しの罫線の間隔（`space-before` と `space-after`）は、`mm` でも書ける。これを仕様とする。
- 間隔の `zw` は、HTML と EPUB でも PDF と同じく版面の文字の大きさで解決する。
- `keep-in-column = false` の罫線は、ページの途中から始まる段（索引の段など）の始まりでは、段の中に収める（#198 の実装のとおり）。この ADR では改めない。

## 実装すること

### 分けて組んだ段落

- 罫線を持つ段落が空の段にも入らず、段落を段に分けて組んだときは、前の罫線と後の罫線のどちらも引かず、どちらの罫線の領域の行も取らない。段落は、罫線を持たない段落と同じく、孤立行と泣き別れの規則で段に分けて組む。
- 段落は今のとおり、今の段が空でなければ次の段の始まりから組む。前の罫線の領域を取らないので、最初の部分は段の最初の格子の行から始まる。
- 最後の部分の直後には、罫線のない段落と同じく次の要素が続く。
- 分けた箇所（段の終わりと次の段の始まり）には、今のとおり罫線を引かない。
- 隣り合う罫線の規則（[ADR 0027](0027-paragraph-style-rules.md) の「隣り合う罫線」）は、分けて組んだ段落には使わない。直前の段落の後の罫線は、一つの領域を共有せず、その段落だけの罫線として数える。直後の段落の前の罫線も、段の中の罫線か段の始まりの罫線として数える。
- お知らせ G0746 の段落のメッセージを `罫線を持つ段落が版面に入らないため、罫線を省いて分けて組みました（段落スタイル <名前>）` に改める。見出しのメッセージは変えない。docs/diagnostics.md の G0746 の「意味」に、分けて組んだ段落には罫線を引かないことを書く。
- 見出しは分けないので、この節の対象にならない。見出しの罫線を省く規則は [ADR 0027](0027-paragraph-style-rules.md) のとおりである。

### 罫線の間隔の単位

- 段落スタイルと見出しの罫線の `space-before` と `space-after` には、`mm`、`pt`、`Q`、`H`、`zw` のどれでも書ける。今の読み方を変えず、仕様として明記する。
- 間隔の `zw` は、段落スタイルでも見出しでも、版面の文字の大きさ（`[page.grid]` の `font-size`）を一字として解決する。間隔を格子の行の字面から測るので、字面の大きさにそろえる。`[notes.rule]` の間隔と同じ解決である。
- `length`、`start-indent`、`end-indent` の `zw` は、[ADR 0027](0027-paragraph-style-rules.md) のとおり段落スタイル（見出しでは見出し）の文字の大きさで解決する。
- `mm` の間隔は、PDF では sp に変換して使う。HTML と EPUB では、今のとおり `pt` に換算して CSS に書く。罫線の指定は寸法を sp か `zw` として読み、書いた単位を残さないためである。

### HTML と EPUB の間隔の `zw`

- 段落スタイルと見出しの罫線の擬似要素（`::before` と `::after`）の `margin-block` では、間隔の `zw` を版面の文字の大きさの固定の長さに換算して書く。`[page.grid]` の `font-size` が絶対的な寸法なら、`zw` の値にその大きさを掛けて `pt` に換算する。`space-before = "1zw"` は、版面の文字の大きさが 10pt なら `10pt` になる。
- `style.toml` に `[page.grid]` がないか、`font-size` が絶対的な寸法でない本では、間隔の `zw` を `rem` に写す。根の要素の文字の大きさを版面の文字の大きさの代わりとみなす。
- 罫線の `length`、`start-indent`、`end-indent` の `zw` は、今のとおり `em` に写す。PDF でも段落スタイル（見出しでは見出し）の文字の大きさで解決するので、`em` と同じ大きさになる。
- 換算は sp の整数で行い、`pt` の小数は今の `cssLength` と同じく小数第三位までに丸める（[docs/adr/0002](../../adr/0002-determinism.md)）。

### ドキュメント

- docs/specifications.md：「style.toml」の段落スタイルの罫線の段落と、改ページの節の罫線のまとまりの段落に、分けて組んだ段落には罫線を引かないことと、間隔の単位と `zw` の解決を書く。HTML と EPUB の CSS の段落に、間隔の `zw` を版面の文字の大きさの `pt`（`[page.grid]` がなければ `rem`）に換算することを書く。
- docs/diagnostics.md：G0746 の「意味」と、段落のメッセージを直す。
- 使い手のマニュアル：`manual/chapters/05-style.gm` と `manual/appendices/c-style.gm` の罫線の説明に、間隔（罫線と本文のあいだ）を `mm` でも書けることと、間隔の `zw` が PDF でも HTML と EPUB でも版面の文字の大きさで決まることを書く。`mm` で書いた例を一つ加える。分けて組んだ段落には罫線を引かないことを書く。`manual/appendices/e-errors.gm` の G0746 の説明を直す。
- [ADR 0027](0027-paragraph-style-rules.md) のステータスを「採択→分けて組んだ段落の罫線と間隔の単位は [ADR 0035](0035-paragraph-rules-split-and-space-units.md)」にする。

## 実装しないこと

- 分けた箇所に罫線を引き直すこと（[ADR 0027](0027-paragraph-style-rules.md) のとおり）。
- 分けて組んだ段落の最初の部分か最後の部分にだけ罫線を残すこと。
- 間隔の `zw` を段落スタイルの文字の大きさで解決すること。PDF でも HTML と EPUB でも行わない。
- HTML と EPUB の罫線の間隔を、行の格子の行の数に切り上げること（[ADR 0027](0027-paragraph-style-rules.md) のとおり行わない）。
- 間隔を格子の行の数で書くこと。
- 破線と点線の `dash` と `gap`（[ADR 0028](0028-rule-colour-and-style.md)）の単位を変えること。今も `mm` を書け、`zw` は書けない。

## テスト設計

実装の前に書き、失敗することを確かめる。

### style.toml（`modules/golem-project/test/Main.hs`）

- `rule-before = { space-before = "3mm", space-after = "1.5mm" }` を読むと、`rsSpaceBefore` と `rsSpaceAfter` が `mm` を sp にした `Abs` の値になる。
- `[headings.2] rule-after = { space-before = "2mm" }` も同じく読める。

### 改ページ（`modules/golem-layout/test/PaginateSpec.hs`）

- 空の段に入らない、前と後の罫線を持つ段落を分けて組むと、その段落の `PlacedRule` がどのページにもなく、罫線の領域の行も取らない。最後の部分の後に十分な空きがある場合も同じである。
- 分けて組んだ段落の最初の部分が、段の最初の格子の行から始まる。
- 後の罫線を持つ段落の直後に、前の罫線を持ち分けて組む段落が続くと、直前の段落の後の罫線は、その段落だけの領域に置かれる（二つの罫線を一つの領域に置かない）。
- 分けて組んだ段落の直後に前の罫線を持つ段落が続くと、その前の罫線は段の中の罫線として数えられる。

### PDF（`modules/golem-driver/test/ParagraphRuleSpec.hs`）

- 横組みで、`space-after = "2mm"` の前の罫線を持つ段落の一行目の字面の上端と、罫線の矩形の下端の距離が 2mm になる。
- 段落スタイルの `size = "0.5zw"` の段落で、`space-after = "1zw"` の前の罫線の内側の間隔が、版面の文字の大きさの一字分になる（段落の文字の大きさの一字分ではない）。
- 前と後の罫線を持つ長い段落を分けて組むと、G0746 が新しいメッセージで出て、PDF にその段落の罫線が一本も描かれない。

### HTML（`modules/golem-driver/test/ParagraphRuleSpec.hs`）

- `space-before = "3mm"` の前の罫線の CSS の `margin-block` に、3mm を `pt` に換算した値が書かれる。
- 版面の文字の大きさが 10pt の本で、`size = "0.5zw"` の段落スタイルの `rule-before = { space-before = "1zw", space-after = "0.5zw" }` の CSS が `margin-block: 10pt 5pt` になる（`em` で書かない）。
- 同じ段落スタイルの `length = "10zw"` は、今のとおり `width: 10em` になる。
- 見出しの罫線の間隔の `zw` も、版面の文字の大きさの `pt` になる。
- `[page.grid]` のない本で、`space-before = "1zw"` が `margin-block: 1rem 0` になる。

### 自動テストにしない確かめ方

- 一ページより長い段落に前後の罫線を付けて組み、PDF を画像にして、どの部分にも罫線がないことを目で確かめる。

## トレードオフ

分けて組んだ段落には、前の罫線も後の罫線も引かないことにした（メンテナーの決定）。
後の罫線を、入る場合だけ引くと、同じ段落スタイルでも、最後の部分の長さによって後の罫線が出たり出なかったりする。
前の罫線だけを残すと、罫線が段落の始まりにしかなく、段落が一つのまとまりとして区切られて見えない。
分けて組むのは例外の場合なので、例外のときの見た目を一つに決め、罫線をすべて省くほうが、お知らせ G0746 を見た利用者が結果を予測しやすい。
代わりに、節の区切りの罫線を書いた本では、分けた段落の前後に区切りが出ない。
メッセージに罫線を省いたことを書き、利用者が気付けるようにする。

間隔の `zw` を版面の文字の大きさで解決することにした。
段落の文字の大きさで解決すると、同じ `space-after = "1zw"` でも、小さい文字の段落では罫線が字面に近づく。
間隔は格子の行の字面から測るので、格子の字面の大きさにそろえるほうが、隣の段落の罫線と位置がそろう。
代わりに、`length` と間隔で `zw` の大きさが違うので、利用者は二つの解決を覚える必要がある。
仕様書とマニュアルに明記して補う。

HTML と EPUB でも、間隔の `zw` を版面の文字の大きさで解決することにした（メンテナーの決定）。
`em` のままにすると、段落スタイルの `size` によって PDF と HTML で間隔の比が変わる。
換算の形には、固定の長さ（`pt`）と `rem` の二つがあった。
`rem` は根の要素の文字の大きさで決まり、読者が文字の大きさを変えると間隔も追従する。
しかし、Golem は根の要素の文字の大きさを版面の文字の大きさに合わせて書いていないので、`rem` では PDF と同じ値にならない。
版面の文字の大きさが絶対的な寸法で決まっている本では `pt` に換算し、PDF と同じ間隔にした。
代わりに、読者が文字を大きくしても罫線の間隔は変わらない。
`[page.grid]` のない本には換算の元がないので、`rem` に写して根の文字の大きさに任せる。
