# ADR 0042: コードブロックのリスト番号とキャプションのあいだの区切りを、本の言語で決める

ステータス: 採択（未実装）

## 文脈

[golem-html ADR 0002](../../golem-html/adr/0002-heading-number-spacing.md) は、番号と題のあいだの区切りを本の言語で一つに決めた。
`[metadata] language` の主の副タグが `ja` なら全角の空白（U+3000）、ほかの言語なら半角の空白（U+0020）とし、番号の文字列が空白で終われば区切りを足さない。
この規則は golem-doc の `Golem.Doc.Numbering.numberSeparator` にあり、見出し、目次、図版のキャプション、柱、EPUB のナビゲーション文書が使う。
同じ ADR は、書式ごとに区切りを変えないことを、同じ本の中で番号の後の揃いが変わらないためと説明している。

[ADR 0023](0023-code-block-book-features.md) は、キャプションのあるコードブロックに章ごとのリスト番号を振り、キャプションを次のように組むと決めた。

- PDF：リスト番号、全角の空白、キャプションを、コードブロックの上に置く（209 行）。
- HTML：`<figcaption>` にリスト番号、全角の空白、キャプションを入れる（259 行）。
- プレーンテキスト：リスト番号、全角の空白、キャプションの一行をコードの前に出す（269 行）。

二つの ADR は同じ日（2026-10-15）に採択され、[golem-html ADR 0002](../../golem-html/adr/0002-heading-number-spacing.md) の「適用する箇所」の表には、リスト番号が入っていない。
仕様書（1220 行と 1437 行）と実装は [ADR 0023](0023-code-block-book-features.md) に従い、言語によらず全角の空白を置く。

- `Golem.Driver.Pdf` の `codeCaptionOf`（2289 行）：`num <> "　"`。
- `Golem.Html` の `CodeBlock`（437 行）：`escapeXml n <> "　"`。
- `Golem.Text` の `CodeBlock`（137 行）：`(<> "　")`。

そのため、英語の本では、図版のキャプションは番号の後が半角の空白で区切られ、コードブロックのキャプションは全角の空白で区切られる。
[golem-html ADR 0002](../../golem-html/adr/0002-heading-number-spacing.md) が挙げた問題（欧文の書体の多くは U+3000 の字形を持たず、PDF では和文の書体に切り替えて一字分を空ける）が、コードブロックのキャプションに残っている。
レビュー（`.claude/reviews/2026-10-20-adr-spec-review.md` の A-11）が、この食い違いを挙げた。

コードブロックのキャプションだけを全角の空白に固定する理由は、どちらの ADR にも書かれていない。
リスト番号とキャプションは、図番号とキャプションと同じく「番号と題」の組であり、例外とする理由は見当たらない。
メンテナーは、例外を設けず、コードブロックのキャプションを本の言語の区切りに従わせると決めた。

## 実装すること

### 規則

コードブロックのリスト番号とキャプションのあいだには、`numberSeparator` の区切りを置く。

- 本の言語が `ja` なら全角の空白、ほかの言語なら半角の空白とする。
- リスト番号の文字列が空白（U+0020、U+3000、タブ）で終われば、区切りを足さない。`[code]` の `number` の末尾に空白を書いた本で、空白が二重にならないためである。
- キャプションのないコードブロックは番号を持たないので、区切りも置かない（今のとおり）。

日本語の本の出力は変わらない。
英語の本では、PDF、HTML、EPUB、プレーンテキストのコードブロックのキャプションで、全角の空白が半角の空白になる。

### コード

- `Golem.Driver.Pdf` の `codeCaptionOf`：`num <> "　"` を `num <> numberSeparator lang num` に替える。言語は見出しと同じく `[metadata] language` から取る（`numberedTitle` と同じ値）。
- `Golem.Html` の `CodeBlock` の `<figcaption>`：`escapeXml n <> "　"` を `escapeXml (n <> numberSeparator (hcLanguage (cCfg c)) n)` に替える。EPUB は golem-html の出力を使うので、同じく変わる。
- `Golem.Text` の `CodeBlock` のキャプション：`(<> "　")` を `\n -> n <> numberSeparator (cLanguage c) n` に替える。

### 文書

- 仕様書のコードブロックの PDF の項目（1220 行）と HTML の段落（1437 行）の「リスト番号、全角の空白、キャプション」を「リスト番号、区切り、キャプション」に改め、「目次と文書構造の参照」の節の区切りの規則（610 行）とこの ADR へリンクする。
- 仕様書のプレーンテキストの節にコードブロックのキャプションの記述があれば、同じく改める。
- docs/markup.md のコードブロックの節（480 行）に、リスト番号とキャプションのあいだに本の言語で決まる区切りが入ることを書く。
- 使い手のマニュアル：`manual/chapters/03-markup.gm` のリスト番号の段落（505 行の付近）と、`manual/appendices/c-style.gm` の `[code]` の `number` の行（358 行）に、見出しの `number` と同じく、番号とキャプションのあいだに日本語の本では全角の空白が、英語の本では半角の空白が入り、書式が空白で終われば足さないことを書く。

### ステータスの行

- [ADR 0023](0023-code-block-book-features.md)：「採択→（リスト番号とキャプションのあいだの区切り）は ADR 0042」とする。
- [golem-html ADR 0002](../../golem-html/adr/0002-heading-number-spacing.md)：「採択→（区切りを置く箇所にコードブロックのキャプションを加えること）は [golem-driver ADR 0042](../../golem-driver/adr/0042-listing-caption-number-separator.md)」とする。この ADR は 0002 の規則を変えず、適用する箇所を広げるだけだが、0002 の表だけを読んだ人がリスト番号を例外と誤解しないためにリンクを残す。

## 実装しないこと

- `[code]` の `number` の既定（`"リスト{chapter}-{n}"`）を本の言語で変えること。英語の本でも既定は「リスト」のままであり、図番号の既定（`"図{chapter}-{n}"`）と同じ扱いである。既定の書式を言語で選ぶかは、図番号と合わせて別の ADR で決める。
- HTML の `<figcaption>` のリスト番号を、図版のキャプションと同じ `<span class="number">` で包むこと。区切りの規則とは別の、マークアップの変更である。
- 区切りを段落スタイルごとに `style.toml` で選べるようにすること。メンテナーは、これを v1.0 で扱うと決め、docs/roadmap.md に載せる。それまでは、[golem-html ADR 0002](../../golem-html/adr/0002-heading-number-spacing.md) の「実装しないこと」のとおり、書式の末尾に空白を書けば区切りを足さない。
- 傍注の番号とリストの印の後の空き。[golem-html ADR 0002](../../golem-html/adr/0002-heading-number-spacing.md) の範囲の外のままとする。

## テスト設計

### 先に書いて失敗させるテスト

`modules/golem-driver/test`：

- `language = "en"` の本で、キャプションのあるコードブロックの HTML の `<figcaption>` が `L1 設定` の形（リスト番号の後が半角の空白）であり、U+3000 を含まないこと。既存の `PdfSpec.hs` のテスト（`<figcaption>L1　設定</figcaption>`）が日本語の本でなければ、そのテストの期待を本の言語に合わせて直す。
- 同じ英語の本の PDF で、コードブロックのキャプションの組む前の文字列が `L1 ` で始まり、U+3000 を含まないこと。
- `language = "ja"` の本では、HTML と PDF のどちらも今のとおり U+3000 であること。
- `[code] number = "Listing {n}: "` の英語の本で、HTML と PDF のキャプションに空白が二つ続かないこと。

`modules/golem-text/test`：

- 英語の本で、コードブロックのキャプションの行が `リスト1-1 設定の読み込み` の形（半角の空白）であること。既存のテスト（`Main.hs` 119 行の `リスト1-1　設定の読み込み`）は日本語の本なので変わらないことを確かめる。

### 自動テストにしない確かめ方

`golem new --language en` の雛形にキャプションのあるコードブロックと図版を足して PDF と HTML に組み、図版のキャプションとコードブロックのキャプションで、番号の後の空きが同じ幅であることを目で確かめる。

## トレードオフ

- 英語の本の出力が変わる。v1 のリリースの前であり、[golem-html ADR 0002](../../golem-html/adr/0002-heading-number-spacing.md) が英語の本の見出しの出力を変えたのと同じ判断である。
- コードブロックのキャプションを例外として全角の空白のまま残す案もあった。コードブロックは和文の本の中でも欧文の書体で組むことが多いが、キャプションは段落スタイル `caption` で組む本文の文であり、コードの書体とは関係がない。例外を残すと、同じ本の中で番号の後の空きが要素の種類で変わり、[golem-html ADR 0002](../../golem-html/adr/0002-heading-number-spacing.md) が避けたかった不揃いが残る。
