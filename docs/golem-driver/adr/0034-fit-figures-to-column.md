# ADR 0034: 回り込ませない図版を段に収め、回して置けるようにする

ステータス: 採択

## 文脈

golem-pdf の [ADR 0009](../../golem-pdf/adr/0009-svg-figures.md) の実装（プルリクエスト #194）で、縦組みの版面に行長いっぱいで置いた図版が、ページの端で切れて見えるという報告があった。
実装した側は、縦組みの図版の大きさの決め方から来るもので、golem-pdf の [ADR 0009](../../golem-pdf/adr/0009-svg-figures.md) の範囲の外だと判断した。
メンテナーは、v0.1.0-rc3 で直すと決めた。

### 再現

開発者のマニュアル（manual-dev）は、`style.toml` の `writing-mode` が `horizontal` であり、縦組みの章を持たない。
origin/main（4c07747）で組んだ開発者のマニュアルの六つの図版は、どれも横長で、版面の中に収まっていた。
報告の現象は、開発者のマニュアルでは再現しなかった。

そこで、縦組みの小さなプロジェクトを作って組んだ。
B5、本文 13Q、一行 40 字、26 行、行送り 22H の縦組みの版面に、キャプションを付けた次の三つの SVG の図版を置いた。
PDF のページを画像にして確かめた（PDFKit でページを描くだけの使い捨てのスクリプトによる。リポジトリには置かない）。

| 図版 | 縦横の大きさ | 結果 |
|---|---|---|
| 枠と対角線だけの横長の図 | 1300 × 920 | 画像の左の端が紙の左の端を越えて切れ、キャプションは紙の外に置かれて見えない |
| 開発者のマニュアルの `stages.svg` | 1300 × 920 | 同じく、図の左の部分が切れ、キャプションが見えない |
| 枠と対角線だけの縦長の図 | 600 × 1600 | 版面の中に収まる |

diagnostic は一つも出なかった。
同じ縦長の図を、同じ字数と行数の横組みの版面（34 行）に置くと、画像の下の部分が紙の下の端を越えて切れた。
横組みでも、縦長の図で同じことが起きる。

### 原因

原因は、回り込ませない図版の大きさを、行長だけから決めていることにある。
`Golem.Driver.Pdf` の `placeFigure` は、次のように計算する（[ADR 0005](0005-pdf-wrapped-figures.md) の「図版の大きさ」のとおり。行の番号は origin/main の 92c3c5a のもの）。

- 行の方向の長さ `along` は、版面の行長とする（1875 行）。
- 行の送りの方向の長さ `across` は、`along` に画像の縦横の比を掛けて求める（1880 行）。横組みでは `along × 高さ ÷ 幅`、縦組みでは `along × 幅 ÷ 高さ` である。
- 画像が占める格子の行の数を `m = ⌈across ÷ 行送り⌉` とする（1881 行）。

`across` と `m` には上限がない。
`m` とキャプションの行の数の合計が段の行の数を超えると、golem-layout の `paginate` は、図版を空の段の先頭に置き、収まらない分をそのまま段の外に出す（`Golem.Layout.Paginate` の 341 行と 658 行の `isEmpty st`）。
`figureRect`（2480 行から 2483 行）は、縦組みでは画像の右の辺を版面の右の辺にそろえ、左へ `across` だけ広げるので、段の外に出た分は版面の左の余白を越え、紙の外に出る。
キャプションの行は画像の後の格子の行に置くので、紙の外に出る。

上の再現の版面では、行長が 130mm、版面の行の送りの方向の長さが 140.75mm である。
横長の図の `across` は `130 × 1300 ÷ 920` でおよそ 183.7mm、`m` は 34 になり、段の 26 行を超える。
画像の左の端は、紙の左の端から 20mm ほど外に出る。

縦組みで目立つのは、縦組みでは行長が画像の高さになるからである。
技術書の図の多くは横長なので、高さを行長にそろえると、幅は行長より大きくなる。
縦組みの版面の行の送りの方向の長さは、行長と同じ程度か、それより短いことが多い。
横組みでは行長が画像の幅になるので、横長の図は版面の高さに収まり、問題は縦長の図に限られる。

### 仕様と ADR の記述

[仕様書](../../specifications.md) の「図版」の節は、「回り込ませない図版の幅は版面の行長とし」と書く。
ここでの「幅」は行の方向の長さであり、縦組みでは画像の高さになる。
段の行の数を超える図版の扱いは、仕様書の「図版」の節にはない。

[ADR 0005](0005-pdf-wrapped-figures.md) は、「一ページに収まらない回り込ませない図版の扱い」を実装しないこととし、`paginate` の既存の動作（空のページにそのまま置く）を変えないと決めた。
[docs/adr/0018](../../adr/0018-multi-column-layout.md) も、図版の高さが段の行の格子の数を超える場合は、空の段の先頭にそのまま置くと決めた。
[ロードマップ](../../roadmap.md) の v2 の「図版とキャプションの拡張」には、「版面より大きい図版を縮小する」があり、v1 は空のページにそのまま置くと書く。
v0.1.0-rc4 の「回り込ませない図版の幅」には、`width` の指定と、行の中の寄せと、行長より大きい図版の縮小がある。

どの記述も、縦組みでは横長の図という、ありふれた図版が段からはみ出すことを想定していない。
はみ出した図版は、紙の外に出て読めなくなり、しかも diagnostic が出ない。

### メンテナーの判断

草稿への回答として、メンテナーは次のことを決めた。

- 横組みの縦長の図も同じ規則で縮める。v2 の「版面より大きい図版を縮小する」を前倒しする。v1 は、数式の組版と雑誌のレイアウトを除くすべてに対応し、実用に足りなければならないからである。
- 縮めた図版は、余白が小さくなるほうに寄せる。紙の端までの距離が短いほうの端に寄せる読み方で確定し、横組みの B5 でノドの側に寄ることも認めた。
- 回した図版にも同じ寄せの規則を当て、LaTeX の中央の置き方には合わせない。LaTeX との互換は失うが、規則は一つのほうがよい。
- 回さない図版のキャプションは、今は縮める前の行長で組む。問題のある例が見つかったら ADR を作る。
- 図版を縮めたら、必ずお知らせを出す。利用者が気づけないことを Golem が黙って行うのが最も悪いからである。お知らせの抑制は本の全体の単位でよい。
- キャプションだけで段に収まらない場合は、新しいエラーのコードにする。
- 図版を 90 度回して置く扱い（JLReq §2.3.2）も rc3 に入れる。rc4 はプラグインに集中し、v1 では小さな不具合と振る舞いを直し終えている必要があるからである。横組みでも回せるようにする。実装が安いなら、利用者が自由に組み合わせられるほうがよい。
- 回した図版のキャプションは、LaTeX の `sidewaysfigure` にならい、図版とともに回す。v1 は、数式を除いて LaTeX にできることをすべてできるようにする。

### 組版の規則

JLReq は、縦組みの図版の高さを、できれば基本版面の段の高さか、基本版面の高さにそろえるとする（§2.2.5 の 2）。
今の `along` を行長にする規則は、これに合う。
一方で JLReq は、図版と表は通常、基本版面の中に置くとし、はみ出すのは、縮めると文字が読めなくなる場合と、視覚の効果のために紙の端まで伸ばす場合に限る（§2.5.1 の 4）。
大きさの都合で、図版と表を 90 度回して置くこともあり、縦組みでは図版の上をページの右に、横組みでは左にそろえる（§2.3.2 の 3）。
本を回して読む向きを、読み進める流れと干渉させないためである。
JLReq の公開されている版（2020 年 8 月 11 日の Working Group Note）には、図版の大きさを段の行長と段の深さの両方に収める手順は書かれていない。

InDesign は、図版の内容をフレームに合わせる方法として、縦横の比を保って内容がフレームの中にすべて収まるように拡大縮小する「内容を縦横比率に応じて合わせる」を持つ。
フレームの大きさを段に合わせ、この方法を選ぶと、図版は縦横どちらの方向にも段を越えない。
図版を回すのは、書き手がフレームか内容を回転させる操作であり、自動では回さない。

LaTeX は、graphicx の `\includegraphics` に `width` と `height` を両方与え、`keepaspectratio` を指定すると、縦横の比を保ち、どちらの値も超えない大きさに縮める。
`width=\linewidth,height=\textheight,keepaspectratio` が、行長と版面の高さの両方に収める決まった書き方である。
図版を回すのは、`angle` のキーか rotating パッケージの `sidewaysfigure` であり、どちらも書き手が指定する。
pLaTeX の縦組みでの `\includegraphics` の振る舞いは確かめていない。

rotating パッケージの説明書（rotating.pdf）によれば、`sidewaysfigure` は次のように振る舞う。

- 図版とキャプションを一つの箱に組み、箱ごと 90 度回す（§2.2、§5）。
- 回した図版は、つねに一ページを占める（§2.1）。図版をフロートとして扱うので、本文は回した図版を待たずに今のページを埋め、回した図版は後のフロートのページに置かれる。
- 箱の幅を `\textheight` にして組む（§5）。キャプションは、回した後にページの高さの方向に走る行として、版面の高さを行長に組まれる。
- 片面の文書では、図版の下をページの右に向ける（`clockwise`、既定）か左に向ける（`counterclockwise`）かを選ぶ。両面の文書（`book` の既定）では、ページの奇数と偶数で回す向きを変え、右のページでは左に 90 度、左のページでは右に 90 度回す（§2.1、§5 のコードの 179 行から 207 行）。どちらのページでも図版の上はノドに向く。`figuresright` と `figuresleft` で向きを一つに固定できる。
- 既定では、回した図版をフロートのページの中央に置く（§2.4）。
- 二段組みでは、`sidewaysfigure*` が二段にまたがるフロートとして置く（§2.2、§5）。

三つとも、「行長にそろえる」を第一にしつつ、版面に収まらなければ縦横の比を保って縮め、回すのは書き手が選ぶ点で一致する。
回す向きは、JLReq が書字の方向ごとに一つに決め、LaTeX の両面の既定はページごとに変える点で食い違う。
[仕様書](../../specifications.md) の「仕様が不明瞭な場合」の節は JLReq、InDesign、TeX と LaTeX の順に拠ると定めるので、JLReq の向きを取る。
LaTeX でも `figuresleft` と `figuresright` で同じ向きにできる。

## 実装すること

### 図版の大きさ

回り込ませない図版の大きさを、行長と段の行の送りの方向の長さの両方に収める。
横組みと縦組みで同じ規則を使う。
回した図版は、同じ規則を「回した図版の枠」（「図版を回して置く」の節）に当てる。

1. `along₀` を段の行長、`across₀` を `along₀` に画像の縦横の比を掛けた値とする。横組みでは `along₀ × 高さ ÷ 幅`、縦組みでは `along₀ × 幅 ÷ 高さ` である。今の `along` と `across` と同じである。
2. 画像が置ける行の送りの方向の長さの上限 `acrossMax` を、次のように決める。`L` は段の行の数（`pgLineGrid` の長さ）、`p` は行送り、`h` は本文の文字の大きさである。
   - キャプションがある場合は、`(L − s) × p` とする。`s` はキャプションが占める格子の行の数（今の `hbSpan`）である。画像が `L − s` 行を占め、残りの `s` 行にキャプションを置く。
   - キャプションがない場合は、`(L − 1) × p + h` とする。版面の行の送りの方向の長さ（golem-layout-spec の `lineDepth`）に等しい。
3. `across₀ ≤ acrossMax` なら、`along = along₀`、`across = across₀` とする。
4. `across₀ > acrossMax` なら、`across = acrossMax` とし、`along` を `acrossMax` を画像の縦横の比で割った値とする。縦横の比は保つ。
5. `m = ⌈across ÷ p⌉` は今と同じ式で求める。手順 2 によって、`m` とキャプションの行の数の合計は `L` を超えない。

縦横の比は、今と同じく `figureProportions` の有理数で計算し、sp に切り捨てる。
浮動小数点数を使わないので、x86-64 と aarch64 で同じ値になる（[docs/adr/0002](../../adr/0002-determinism.md)）。

### 寄せ

縮めた図版は、行の送りの方向には段の行の格子を使い切るので、余りは行の方向にだけできる。
その余りの置き方を、「余白が小さくなるほうに寄せる」というメンテナーの判断から、次のように決める。

- **寄せる先**：図版を置く領域（段か、回した図版の版面）の、余りのできる方向の二つの端のうち、仕上がりの紙の端までの距離が短いほうの端に、図版をそろえる。
- **距離**：領域の端から、その側の仕上がりの紙の端（`pgPageSize` の矩形の辺）までの長さである。段組みでは、ほかの段と段の間の空きも距離に含む。断ち落としの領域は含まない。
- **同じ距離**：二つの距離が等しければ、行の始まりの端にそろえる（縦組みの天、横組みの左）。
- **方向**：回さない図版の余りは行の方向にできる。縦組みでは天と地、横組みでは左と右の二つの端を比べる。

この規則は、寄せた図版の外側にできる紙の端までの余白を、二つの置き方のうち小さいほうにする。
縦組みでは、天の余白と地の余白のうち小さいほうに寄る。
横組みでは、ページの奇数と偶数によってノドと小口の左右が入れ替わるので、寄せる側もページごとに決まる。
たとえば、左綴じの B5 で、ノドの余白が 24mm、小口の余白が 28mm の版面（開発者のマニュアル）では、奇数ページでは左（ノド）、偶数ページでは右（ノド）に寄る。
ノドの余白が小口の余白より大きい版面では、小口に寄る。
段組みでは、横組みの左の段は左に、右の段は右に、縦組みの上の段は天に、下の段は地に寄る。

縮めていない図版は行長いっぱいなので、寄せの規則は位置を変えない。
回り込ませる図版の位置（`wrap` の `start` と `end`）は変えない。

寄せる側はページの番号で決まるので、図版を置くページが決まった後に `figureRect` が決める。
`figureRect` は、ページの番号を受け取るように引数を一つ加える。
キャプションの行の位置は変えず、段の行の始まりから組む。

### キャプション

回さない図版のキャプションは、今と同じく `along₀`（段の行長）を行長として組む。
縮めた後の `along` では組まない。
縮めた `along` でキャプションを組むと、キャプションの行の数が変わり、手順 2 の `s` が変わり、`acrossMax` が変わるという循環ができるためである。
縮めた画像より長いキャプションで問題のある例が見つかったら、キャプションの行長を画像に合わせるかを決める ADR を作る。

### 縮めたことのお知らせ（G0739）

図版を縮めたら（手順 4）、図版ごとにお知らせ G0739 を出す。
回した図版を枠に収めるために縮めた場合も出す。
位置は `@figure` のブロックの `SrcSpan` である。
メッセージは `図版を段に収めるため <r>% に縮めました` とし、回した図版では `段に` を `ページに` とする。
`r` は `along × 100 ÷ along₀` の整数の切り捨てである。

回さずに置いた図版が、回せばより大きく置ける場合は、メッセージの後に `。rotate=true で回して一ページに置くと、より大きく置けます` を足す。
より大きく置けるとは、同じ図版を回して枠に収めたときの画像の面積（`along × across`）が、回さないときの面積より大きいことである。
`r` は置き方ごとの行長に対する割合なので、回したときと回さないときの比べには使わない。

お知らせなので、ビルドは失敗しない。
`manifest.toml` の `silence-notices` と `--no-notices` で抑制できる（[golem-syntax ADR 0002](../../golem-syntax/adr/0002-notice-severity.md)）。
抑制は本の全体の単位であり、図版ごとには抑制できない。
二つのマニュアルはお知らせを一つも出さずに組めなければならないので、マニュアルの図版は縮めずに収まる大きさで作る。

### キャプションだけで段に収まらない場合（G0738）

`s ≥ L`（キャプションだけで段の行の数に達する）場合は、画像を置く行が残らない。
回した図版では、`L` を枠の行の数 `L′` に読み替える。
この場合はエラー G0738 とし、図版のブロックの `SrcSpan` を示す。
メッセージは `図版のキャプションが段の行数を超えます（<s> 行。段は <L> 行）` とし、回した図版では `段` を `ページ` とする。
dev と prod の両方でエラーである。
回り込ませる図版の G0723 とは別のコードにする。
G0723 は除外領域の行数の誤りで、直し方（図版を小さくする）が違うためである。

### 図版を回して置く

`@figure` に `rotate=true` を書くと、PDF で図版とキャプションを一緒に 90 度回し、一ページに置く。
LaTeX の `sidewaysfigure` にならう。
回すのは書き手が指定したときだけで、自動では回さない。
回すと読み手は本を回して読むので、それを選ぶのは書き手であり、Golem が黙って選んではならないからである。
自動で回さない代わりに、縮めた図版のお知らせ G0739 が、回したほうが大きく置ける場合にそれを知らせる。

#### 書き方

- **値**：`true` か `false` で、省けば `false` である。ほかの値はエラー G0287 とする。メッセージは `rotate は true か false です: <値>` とする。
- **回り込みとの組み合わせ**：`rotate=true` と `wrap` を両方書くとエラー G0287 とする。メッセージは `回して置く図版は回り込ませられません` とする。回した図版は一ページを占め、脇に本文を置かないためである。
- 横組みと縦組みの両方で使える。

#### 向き

JLReq §2.3.2 の 3 に従い、書字の方向ごとに一つの向きに決める。
ページの奇数と偶数では変えない。

- 縦組み：右に 90 度回し、図版の上の辺をページの右に向ける。LaTeX の `figuresleft` と同じ向きである。
- 横組み：左に 90 度回し、図版の上の辺をページの左に向ける。LaTeX の `figuresright` と同じ向きである。

#### 回した図版の枠

回した図版は、回す前の向きで、枠と呼ぶ仮の版面の中に組む。
枠を回すと、ページの版面（`typeAreaFor` の矩形）にちょうど重なる。
段組みの版面でも、すべての段にまたがる版面を使う（LaTeX の `sidewaysfigure*` にあたる）。

- 横組み：枠の行の方向の長さ `Fm` は版面の高さ、行の送りの方向の長さ `Fd` は版面の幅である。左に回すので、枠の行は、ページの下から上へ走る。
- 縦組み：枠の行の方向の長さ `Fm` は版面の幅、行の送りの方向の長さ `Fd` は版面の高さである。右に回すので、枠の行は、ページの右から左へ走り、枠の行の送りはページの上から下へ進む。

枠の中は、本の書字の方向のまま、回さない図版と同じに組む。

- **行の格子**：枠の行送りは本文の行送り `p` とし、枠の行の数を `L′ = ⌊(Fd − h) ÷ p⌋ + 1` とする。格子は枠の行の送りの方向の始まりの端から数える。
- **大きさ**：「図版の大きさ」の手順 1 から 5 を、`along₀ = Fm`、`L = L′` として当てる。画像の縦横の比は、枠の中では回す前のままである。収まらなければ縮め、G0739 を出す。
- **キャプション**：`Fm` を行長として、本の書字の方向で組む。LaTeX が `\textheight` を行長にして組むのにあたる。図番号とキャプションの組み方（段落スタイル `caption`、行送り、格子の行の占め方）は回さない図版と同じである。キャプションだけで `L′` 行に達すれば G0738 とする。
- **枠の中の位置**：画像とキャプションを、枠の格子の先頭から、回さない図版と同じ順に置く。画像の行の方向の余りは「寄せ」の規則に従う。比べる二つの端は、枠を回した後のページの上の端であり、横組みでは天と地、縦組みでは右と左である。
- **ページの上の位置**：画像とキャプションを合わせた矩形が枠の行の送りの方向に余る場合も、「寄せ」の規則で、ページの上の二つの端（横組みでは右と左、縦組みでは天と地）のうち紙の端に近いほうへ寄せる。LaTeX の既定はページの中央に置くが、寄せの規則を一つにするために中央にはしない（トレードオフの節）。

#### ページへの置き方

回した図版は、本文を持たないページを一つ占める。
LaTeX のフロートのページと同じく、本文は回した図版を待たずに今のページを埋める。

- 回した図版に出会ったとき、今のページに何も置いていなければ（すべての段が空で、脚注もない）、そのページに置く。
- そうでなければ、回した図版を待ちに加え、本文を続ける。待ちの扱いは [golem-layout ADR 0015](../../golem-layout/adr/0015-figure-order.md) に従い、回した図版の後の図版も、回さない図版を含めて待つ。
- 次のページを始めるときに、待っている図版を原稿の順に置く。回した図版はそのページを占め、その後の待っている図版は、さらに次のページの先頭から置く。
- 改ページ（`@page-break` など）、改段、段組みの切り替え、`page-break = "recto"` の見出しの前では、ほかの待っている図版と同じく、待っている回した図版をすべて置いてから進む。
- 回した図版のページには、柱とノンブル（隠しノンブルを含む）を、ほかのページと同じく置く。脚注は置かず、前のページから続く脚注は、回した図版のページの次の本文のページに続ける。
- 図番号は、今と同じく S1 が原稿の順に振る。置く位置が後のページに移っても変わらない。図版を指すページ番号の参照（`ref-page`）は、回した図版を置いたページを指す。

#### HTML と EPUB とプレーンテキスト

- HTML と EPUB は `rotate` を読まず、図版とキャプションを回さずに置く。ページのない媒体では、読み手が本を回すことがなく、画面の幅は読書システムが決めるためである。この扱いは仕様書とマニュアルに書く。
- プレーンテキストは図版を描かないので、変わらない。

### PDF への描き方

golem-pdf の `Mark` に、印の群を 90 度回して置く `Turned` を加える。

```haskell
-- Golem.Pdf.Writer
data Turn = TurnedRight | TurnedLeft
  deriving stock (Eq, Show)

data Mark
  = ...
  | {- | marks drawn in a frame whose origin is its lower left corner,
    turned and placed in the rectangle, inside q and Q -}
    Turned !Turn !Rect ![Mark]
```

golem-driver は、回した図版の画像とキャプションの行を、枠の左下を原点にした座標で、回さない図版と同じ関数で描く。
`Turned` は、その印の群を `q` と `Q` で囲み、次の行列の `cm` で、回した後の矩形 `(x, y, W, H)` に置く。
枠の大きさは `(H, W)` である。

| `Turn` | `cm` の行列 `[a b c d e f]` | 意味 |
|---|---|---|
| `TurnedRight` | `[0 −1 1 0 x y+H]` | 枠の上の辺がページの右、左の辺が上に来る |
| `TurnedLeft` | `[0 1 −1 0 x+W y]` | 枠の上の辺がページの左、右の辺が上に来る |

値は、今と同じく 1/65536 に丸めて書く。
`Image` と `Form` の印は変えない。
キャプションの文字はテキストとして描くので、回しても PDF から文字列を抜き出せる。

### データ構造

```haskell
-- Golem.Doc（意味論 IR）
data Figure = Figure
  { ...
    figRotate :: !Bool
  }

-- Golem.Driver.Pdf
data PlacedFigure = PlacedFigure
  { ...
    pfAlong :: !Sp, -- 縮めた後の値
    pfAcross :: !Sp, -- 縮めた後の値
    pfFullAlong :: !Sp, -- 縮める前の行長（along₀）
    pfTurn :: !(Maybe P.Turn) -- 回した図版
  }

figureRect :: PageGeometry -> Int -> Rect -> Int -> PlacedFigure -> Rect
-- 版面、ページの番号、段か枠の矩形、画像の先頭の格子の番号、図版

-- Golem.Layout.Paginate
data Flow
  = ...
  | FPageFigure {fpId :: !Int, fpLabels :: ![Text], fpMarks :: ![SrcSpan]}

data Slot
  = ...
  | SPageFigure !Int -- そのページのすべてを占める
```

CBOR では、`figRotate` を今の七つの要素の後に八つめの要素（真偽値）として書く。
CDDL（`modules/golem-doc/schema/golem-doc.cddl`）の `figure` も同じに改める（[golem-doc ADR 0001](../../golem-doc/adr/0001-semantic-ir-in-cddl.md)）。
golem-pdf の [ADR 0008](../../golem-pdf/adr/0008-pdf-figures.md) が `page` を七つめの要素として加えたのと同じ形である。

golem-preflight が見る図版と文字の矩形は、回した後のページの上の矩形とする。
`ImageView` に回したかどうかを加え、G0906 と G0907 の実効の解像度は、回した図版では画素の幅を矩形の高さで、画素の高さを矩形の幅で割る。
G0911（断裁の危険域）は、回した後の矩形で調べる。

### 変えないもの

- 回り込ませる図版（`wrap`）の大きさ。`width` が行の方向の長さを決め、収まらなければ G0722 と G0723 になる（[ADR 0005](0005-pdf-wrapped-figures.md)）。
- `paginate` の `FFigure` の規則。手順 2 によって回り込ませない図版は必ず空の段に収まるので、`isEmpty st` で収まらない図版を置く分岐は、回り込ませない図版では使われなくなる。分岐そのものは、ほかの要素のために残す。
- HTML と EPUB の図版の大きさ。行の格子も段もなく、図版の大きさはブラウザーと読書システムが決める。

## 実装しないこと

- 回り込ませない図版の `width`。ロードマップの「回り込ませない図版の幅」で扱う。
- 寄せる側を書き手が選ぶ指定。
- 回さない図版のキャプションを、縮めた後の大きさに合わせて組み直すこと。問題のある例が見つかったら ADR を作る。
- お知らせを原稿の中で局所的に抑制すること。本の全体での抑制で困る例が出たら、textlint の無効にするコメントのように、`.gm` の中でお知らせを局所的に抑制するブロックコマンドを、別の ADR で加える。
- 図版を自動で回すこと。
- 回した図版を、本文と同じページに置くこと。
- 回す向きを、ページの奇数と偶数で変えること（LaTeX の両面の既定）や、書き手が選ぶこと。
- 回した図版のページに、二つ以上の回した図版を並べること（LaTeX のフロートのページは複数のフロートを置ける）。
- 90 度以外の角度で回すこと。
- 回り込ませる図版を回すこと。
- HTML と EPUB で図版を回すこと。
- 表を回して置くこと。表は行の格子で組むので、回すには表の組み方そのものを変える必要がある。
- 図版を複数のページに分けること、見開きに置くこと、紙の端まで伸ばすこと。
- 回り込ませる図版の大きさの規則の変更。

## テスト設計

実装の前に書き、失敗することを確かめる。
golem-driver のテスト（`modules/golem-driver/test/FigureSpec.hs`）に加え、`layoutPdf` の `PdfLayout`、`figureRect`、diagnostic、PDF の内容のストリームを調べる。
画像は、テストの中で書く SVG（`width` と `height` だけを持つ枠の `rect`）と、golem-pdf のテストの 2 × 3 の JPEG を使う。

### 段に収める規則

- 縦組み（`pdfStyle`）で、横長の図（3:1）をキャプションなしで置く。`across₀` が版面の行の送りの方向の長さを超えるように、行の数を選ぶ。`pfAcross` が `(L − 1) × p + h` に等しく、`pfAlong` が `pfAcross × 高さ ÷ 幅` の切り捨てに等しい。`figureRect` の矩形が段の矩形の中にある。
- 同じ図に一行のキャプションを付ける。`pfImageLines` が `L − s` に等しく、`pfImageLines + pfCaptionSpan` が `L` 以下である。キャプションの最後の行が段の中にある。
- 縦組みの縦長の図（2 × 3）は、今と同じく `pfAlong` が行長に等しい。
- 横組み（`horizontalStyle`）で、縦長の図（1:3）の `pfAcross` が上限に等しく、矩形の下の辺が段の矩形の下の辺より下にない。
- 横組みの横長の図は、今と同じく `pfAlong` が行長に等しい。
- 二段組みの縦組みの版面で、二段目に置いた横長の図の矩形が、二段目の段の矩形の中にある。
- 縮めた図版の前に本文を置き、段の残りが足りない場合、図版が次の段の先頭に送られ、収まる（[golem-layout ADR 0015](../../golem-layout/adr/0015-figure-order.md) の規則が変わらない）。

### 寄せ

- 縦組みで天の余白が地の余白より小さい版面では、縮めた図版の上の辺が段の上の辺に一致する。奇数ページと偶数ページで同じである。
- 縦組みで天の余白が地の余白より大きい版面では、下の辺が段の下の辺に一致する。
- 横組みの左綴じで、ノドの余白が小口の余白より小さい版面では、奇数ページの図版の左の辺が段の左の辺に、偶数ページの図版の右の辺が段の右の辺に一致する。
- 同じく、ノドの余白が小口の余白より大きい版面では、奇数ページでは右、偶数ページでは左にそろう。
- 右綴じの横組みで、上の二つの場合の左右が入れ替わる。
- 左右（または天地）の余白が等しい版面では、行の始まりの端（横組みの左、縦組みの天）にそろう。
- 横組みの二段組みで、左の段の図版は左に、右の段の図版は右にそろう。縦組みの二段組みで、上の段の図版は天に、下の段の図版は地にそろう。
- 縮めた図版のキャプションの最初の行の始まりが、段の行の始まりに一致する。
- 縮めていない図版の矩形は、今と同じ位置にある。

### お知らせとエラー

- 縮めた図版ごとに G0739 が一つ出て、位置が `@figure` のブロックであり、割合が `along × 100 ÷ along₀` の切り捨てに等しい。
- 縮めていない図版では G0739 が出ない。
- 縦組みで縮めた横長の図（回すと画像の面積が大きくなる）では、メッセージに `rotate=true` の案内が入る。回しても面積が大きくならない図版と、すでに回した図版では入らない。
- `silence-notices = ["G0739"]` で G0739 が出ず、PDF のバイト列は変わらない。
- 段の行の数を少なくしたスタイルで、段の行の数以上の行を占めるキャプションを付けた図版が G0738 になり、図版のブロックの `SrcSpan` を示す。dev と prod の両方でエラーである。
- 回り込ませる図版で除外領域が一ページの行数を超える場合は、今と同じく G0723 になる。

### 回して置く

golem-eval のテストに加える。

- `rotate=true` と `rotate=false` が `figRotate` に入り、省けば `False` である。
- `rotate=yes` が G0287 になる。
- `rotate=true wrap=end width=4zw` が G0287 になる。

golem-doc のテストに加える。

- `figRotate` を持つ `Figure` が CBOR の往復で変わらず、CDDL の検査を通る。

golem-pdf のテストに加える。

- `Turned` の二つの `Turn` で、表の行列が 1/65536 に丸めて書かれ、印の群が `q` と `Q` で囲まれる。

golem-layout のテスト（`Golem.Layout.Paginate`）に加える。

- 本文の途中に `FPageFigure` を置くと、本文が今のページを埋め、次のページが `SPageFigure` だけを持ち、本文はその次のページに続く。
- 空のページで `FPageFigure` に出会うと、そのページに置く。
- `FPageFigure` の後の `FFigure` は、収まる場合も待ち、`SPageFigure` のページの次のページの先頭に置かれる。
- 待っている `FPageFigure` は、強制の改ページと `page-break = "recto"` の見出しの前に置かれる。
- 前のページから続く脚注は、`SPageFigure` のページを飛ばし、次の本文のページに続く。

golem-driver のテストに加える。

- 縦組みで `rotate=true` の図版の印が `Turned TurnedRight` で、その矩形が版面の矩形に等しい。横組みでは `Turned TurnedLeft` である。奇数ページと偶数ページで向きが変わらない。
- 横組みで回した図版のキャプションの行長が版面の高さに、縦組みでは版面の幅に等しい。
- 枠の行の数が `⌊(Fd − h) ÷ p⌋ + 1` であり、枠に収まらない図版は縮められ、G0739 が `ページに` の文言で出る。
- 枠の行の数以上の行を占めるキャプションで G0738 が出る。
- 回した図版の画像とキャプションの矩形が、回した後のページの上で版面の中にある。キャプションのグリフが PDF の内容に現れ、文字列として抜き出せる。
- 二段組みの版面でも、回した図版の矩形が二つの段にまたがる版面に等しい。
- 回した図版のページに柱とノンブルが描かれる。
- 回した図版の図番号が、原稿の順の番号のままであり、`ref-page` がそのページを指す。
- 回した図版を含む本の HTML と EPUB の `<figure>` は、回さない図版と同じである。

golem-preflight のテストに加える。

- 回した 300 × 600 画素の画像の実効の解像度が、画素の幅を矩形の高さで割った値と、画素の高さを矩形の幅で割った値の小さいほうになる。
- 回した図版の G0911 の検査が、回した後の矩形で行われる。

### 決定性

- 縮めた図版と回した図版を含む縦組みの原稿を並列と逐次でビルドし、PDF のバイト列が一致する。二回のビルドでも一致する。
- 縮めず回さない図版だけを持つ本の PDF のバイト列が変わらないことを、既存の PDF のテストと `scripts/determinism.sh` で確かめる。寄せの規則は縮めた図版にしか適用されないので、二つのマニュアルの PDF も変わらない。二つのマニュアルが、お知らせなしで組めることを `scripts/manual/build.sh` で確かめる。

### 自動テストにしない確かめ方

- この ADR の文脈の縦組みのプロジェクト（横長の図、`stages.svg`、縦長の図）を組み、ページを画像にして、図版とキャプションが版面の中にあり、縮めた図版が余白の小さいほうに寄ることを目で確かめる。同じ字数と行数の横組みの版面でも確かめる。
- 同じプロジェクトで横長の図に `rotate=true` を書き、図版とキャプションが一緒に回って一ページに置かれ、図版の上がページの右（横組みでは左）に向くことを確かめる。

## トレードオフ

### 縮める規則

縦横どちらにも収まる大きさに縮めるので、縦組みの横長の図は、行長より短い高さで置かれる。
JLReq が勧める「高さを段の高さにそろえる」から外れるが、紙の外に出るよりよい。
高さを段にそろえたい図は、書き手が図の側の縦横の比を変えて作るか、回して置けばよい。

横組みの縦長の図も同じ規則で縮める。
今は紙の下の端を越えて切れるので、出力が変わるのは誤った出力だけである。

### 寄せ

紙の端までの距離で決めるので、同じ本の中でも、横組みでは奇数ページと偶数ページで寄る側が変わる。
小口に固定すれば見開きで外側にそろうが、ノドの余白が小口より小さい版面では、余白の大きい側に図版が寄り、メンテナーの判断と逆になる。
距離で決める規則は、どの版面でも一つの式で決まり、テストで確かめやすい。

キャプションは段の行の始まりから組むので、画像を行の終わりの側に寄せたページでは、画像とキャプションの始まりがずれる。
キャプションの行長を画像に合わせる ADR を作るときに、キャプションの寄せも合わせて決める。

LaTeX の `sidewaysfigure` は、既定で回した図版をフロートのページの中央に置く（rotating.pdf §2.4）。
Golem は回した図版にも同じ寄せの規則を当て、中央には置かない。
このため、回した図版の位置は LaTeX と互換でなくなる。
メンテナーは、LaTeX との互換を失っても、寄せの規則を一つにするほうがよいと判断した。
図版の置き方ごとに規則が変わらなければ、書き手は一つの規則だけで位置を予測できる。

### お知らせ

縮めるたびにお知らせを出すので、縮めてよいと分かっている図版でも毎回出る。
`silence-notices` で G0739 を抑制できるが、抑制すると本のすべての図版について知らせが止まる。
利用者が気づけないことを黙って行うよりよいと判断した。
局所的な抑制は、困る例が出たら別の ADR で加える。

### 回す扱い

自動で回せば、書き手は何も書かずに大きな図を得られる。
しかし、回すかどうかで読み手の読み方が変わるので、Golem が黙って決めるべきではない。
回したほうが大きく置ける場合は、お知らせ G0739 の案内で書き手が知ることができる。

回した図版は、小さくても一ページを占める。
本文と同じページに回した図版を置くと、読み手は同じページの中で本を回したり戻したりすることになる。
LaTeX の `sidewaysfigure` も同じ理由で一ページを占める。
小さな図版は回さずに置けばよい。

回す向きを書字の方向ごとに固定するので、LaTeX の両面の既定（図版の上をノドに向ける）とは、ページの半分で向きが逆になる。
JLReq が向きを一つに決めており、仕様書の「仕様が不明瞭な場合」の節の順により JLReq を採る。
読み手は、本のどのページの回した図版も、同じ向きに本を回して読める。

HTML と EPUB では回さないので、PDF と見え方が変わる。
ページのない媒体では、横長の図は画面の幅で縮めて置くのが読みやすく、回すと読み手が端末を回すことになる。
