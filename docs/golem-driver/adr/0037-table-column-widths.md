# ADR 0037: 表の列の幅を短い列から満たして配る

ステータス: 採択

## 文脈

二つのマニュアルの PDF を読み直したところ、表の見出しとセルが不自然に折り返していた。
列の幅が狭い列では、字のあいだが大きく空き、最後の行に一字だけが残る。

### 再現

今の `main` から作った golem（a2b6106e）で二つのマニュアルを組み、次の表を PNG に描いて確かめた。

- 開発者のマニュアルの「決定性が純粋性に求めること」の表（133 ページ、三列）。一列めの「時計を読まない」が「時計を読まな」と「い」の二行に分かれ、「環境変数、ロケール」は一行めの「環境変数、ロ」の字のあいだを空けて組まれる。どの行も二行の高さを取る。三列めの「超越関数を持たない。sp と有理数。」は、改行できないコードの前で字のあいだが大きく空く。
- 利用者のマニュアルの付録 D の「組み込みの設定」の表（219 ページ）。二列めの「検査しない」が、字のあいだを空けた「検査しな」と「い」に分かれる。

開発者のマニュアルの表の列の幅を PNG から測ると、行長 40 字（列の間隔の二字を除いて 38 字）に対して、およそ 6.5 字、10 字、21.5 字であった。
一列めの最も長いセルは「ディレクトリを列挙しない」の 12 字であり、ほかのセルは 4 字から 9 字である。

### 今の配り方

列の幅は `Golem.Layout.Table` の `columnWidths` が決める（[ADR 0008](0008-pdf-tables.md)）。
各列は、二つの幅を持つ。

- 最小の幅：セルの中の改行できる位置のあいだの幅の最大値。和文のセルでは、ほとんど一字の幅である。
- 自然な幅：セルを一行に組んだ幅。

列の最小の幅と自然な幅は、その列のすべてのセルの最大値である。
自然な幅の合計が使える幅 W に収まれば自然な幅を使い、収まらなければ、各列に最小の幅を与えて、残りを「自然な幅と最小の幅の差」に比例して配る。
これは CSS の表の自動の配置（CSS 2.1 の 17.5.2.2 の参考の算法、CSS Tables 3 の列の幅の配分）と同じ、最小の幅から自然な幅までを共通の比で補間する方法である。

和文の列の最小の幅は一字なので、比例の基準は、ほぼ自然な幅そのものになる。
自然な幅が 12 字の短い列も、33 字の長い列も、同じ割合だけ自然な幅に届かない。
上の表の一列めは、自然な幅の 12 字に対して 6.5 字しか受け取らず、7 字の「時計を読まない」が折り返す。
短い列は、自然な幅に少し足りないだけで、セルの多くが二行になる。
さらに、その行は両端揃えで組まれるので、字のあいだが空き、最後の行に一字だけが残る。

### 参照した組み方

- JLReq の 4.4.3 は、表の例の列の幅を、その列のセルの最も長い文字列の幅に左右の二分アキを足し、表の文字の大きさの整数倍にしたと説明する。ヘッダー行のセルは、一行にすると列の幅の釣り合いが取れないときにだけ二行にしている。つまり、各列はまず自分の最も長い項目の幅を取り、折り返すのは釣り合いのためのごく一部のセルに限られる。
- InDesign の表は、列の幅を利用者が決める。内容から列の幅を配る自動の算法はなく、ここで倣う振る舞いはない。
- LaTeX の tabularx は、`l`、`c`、`r` の列を自然な幅で組み、`X` の列だけが残りの幅を等分して折り返す。短い列は折り返さず、長い列が残りを分け合う。

JLReq と tabularx に共通するのは、短い列には自然な幅を与え、折り返しは長い列に寄せることである。

## 実装すること

### 列の幅の配り方（golem-layout）

`columnWidths` の二つめの場合（自然な幅の合計が W を超え、最小の幅の合計が W 以下の場合）を、次の配り方に替える。
一つめの場合（自然な幅が収まる）と三つめの場合（最小の幅が収まらず G0741）は変えない。

列 i の最小の幅を `lo_i`、自然な幅を `hi_i` とする。
上限 C に対して、列 i の幅を `clamp C lo_i hi_i`（C を `lo_i` 以上 `hi_i` 以下に収めた値）とし、その合計を `S(C)` とする。

1. `S(C) <= W` を満たす最大の整数 C を求める。`S` は C について単調に増えるので、0 から最大の `hi_i` までの二分探索で求める。
2. 各列の幅を `clamp C lo_i hi_i` とする。
3. 残り `W - S(C)` を、幅が自然な幅に届いていない列に、左（縦組みでは上）の列から 1sp ずつ配る。C が最大なので、残りはそうした列の数より小さく、一巡で配り終わる。

自然な幅が C 以下の列は自然な幅を受け取り、折り返さない。
自然な幅が C を超える列は、最小の幅が C を超えないかぎり同じ幅 C を受け取り、折り返しはそれらの列に集まる。
これは、短い列を先に満たし、残りを長い列で等分する配り方（水を注ぐ配り方）であり、tabularx の振る舞いを、`X` の列を指定せずに内容から決めたものにあたる。

```haskell
-- | 列の幅（golem-driver ADR 0037）：自然な幅が収まれば自然な幅、
-- 収まらなければ、上限 C で頭を揃えて短い列から満たし、余りを左から 1sp ずつ
columnWidths :: Sp -> [(Sp, Sp)] -> Either TableError [Sp]
```

計算はすべて整数の sp で行う（[docs/adr/0002](../../adr/0002-determinism.md)）。
関数の型は変えない。

### セルの最後の字

セルの段落では、最後の二つの和文の字のあいだで改行しない。

- `Golem.Driver.Pdf` は、セルの中身を `composeInlines` で項目にしたあと、段落の最後の箱が和文の一字の箱（欧文の語、ルビ、縦中横、注の印でない箱）で、その箱と前の箱とのあいだに改行の位置があれば、それをなくす。改行の位置が罰点なら無限の罰点（`infPenalty`）に替え、アキ量のセットのグルーなら、その前に無限の罰点を置く（[golem-layout ADR 0002](../../golem-layout/adr/0002-japanese-composition.md) の行頭禁則と同じ形）。
- この置き換えは、列の最小の幅と自然な幅を求める前に行う。最小の幅は、最後の二字を一つの区間として数える。
- 本文の段落には当てない。JLReq の 3.5.4 の段落末尾処理は、本文の段落の最終行が一字になることを許容する例が多いとしており、本文の組み方は変えない。

### ドキュメント

- 仕様書の表の節（PDF の表）の列の幅の説明を、この ADR の配り方に改め、この ADR へのリンクを付ける。セルの最後の二字のあいだで改行しないことも書く。
- [ADR 0008](0008-pdf-tables.md) のステータスの行に、列の幅の二つめの場合の配り方をこの ADR で改めたことを、この ADR へのリンクで書き足す。
- 開発者のマニュアルで、表の列の幅を説明する箇所があれば改める。
- [docs/roadmap.md](../../roadmap.md) に、次の項目を加える（ロードマップはメインのセッションが改める）。v0.1.0-rc4 と v1.0.0 のどちらに置くかはメンテナーが決める。
  - **追い込みと追い出しの設定**：行の調整で、行末に収まらない字を前の行に追い込むか、次の行に追い出すかと、その優先の順を、段落スタイルで設定できるようにする（JLReq の 3.8 の詰める処理と空ける処理）。今は追い込みをせず、収まらない箱を追い出して、足りない幅を行の中の字のあいだで埋める（PR #231）。改行できないコードや URL の前の行で字のあいだが大きく空く場合（開発者のマニュアルの表のセルの「超越関数を持たない。」の行）を、この設定で避けられるようにする（この ADR）。

## 実装しないこと

- 列の幅を表の文字の大きさの整数倍にすること（JLReq の 4.4.3 の例）。欧文のプロポーショナルな書体のセルでは、整数倍に丸めると自然な幅との差が大きくなり、W に収まる場合も収まらなくなる場合がある。表の文字の大きさの指定と合わせて、v1.0.0 の「表の番号とキャプション、列の幅、文字の大きさ」で扱う。
- 利用者が列の幅を指定する記法。同じく v1.0.0 の項目で扱う。
- 表の高さ（行の数の合計）を最小にする列の幅の探索。列の数が増えると組み合わせが急に増え、セルを何度も行に分ける必要がある。
- セルの行揃え（左揃え、均等割り）の変更。セルの行は今のとおり両端揃えで組む。改行できないコードの前で字のあいだが空く行は、[golem-layout ADR 0001](../../golem-layout/adr/0001-knuth-plass-line-breaking.md) の追い出しのとおりであり、この ADR では変えない。メンテナーが v0.1.0-rc4 か v1.0.0 で加える追い込みと追い出しの設定（[docs/roadmap.md](../../roadmap.md) に加える項目）で扱う。
- HTML と EPUB の表。列の幅は今のとおり読者側のエンジンに任せる。

## テスト設計

実装の前に書き、失敗することを確かめる。

### golem-layout（`modules/golem-layout/test/Main.hs`）

- `columnWidths 100 [(10, 30), (20, 40)]` が今のとおり `Right [30, 40]` である（自然な幅が収まる場合）。
- `columnWidths 20 [(10, 30), (20, 40)]` が今のとおり `Left (ColumnsTooWide 30 20)` である。
- `columnWidths 100 [(10, 60), (20, 80)]` が `Right [50, 50]` である。今の実装は `Right [42, 58]` を返すので、このテストは今の期待値を置き換える。
- 開発者のマニュアルの表を模した `columnWidths 38 [(1, 12), (4, 13), (9, 33)]`（字を単位にした値）が `Right [12, 13, 13]` である。
- 最小の幅が上限 C を超える列：`columnWidths 26 [(11, 11), (1, 5), (1, 16)]` が `Right [11, 5, 10]` である（付録 D の表を模した値）。
- 余りの配り方：`columnWidths 10 [(0, 9), (0, 9), (0, 9)]` が `Right [4, 3, 3]` である（C が 3、余り 1 を左の列に配る）。
- 性質：二つめの場合の結果について、幅の合計が W に等しく、各列の幅が最小の幅以上、自然な幅以下であり、自然な幅が C 以下の列はちょうど自然な幅を受け取る。QuickCheck で、列の数が 1 から 8、幅が 0 から 1000 の入力について確かめる。

### golem-driver（`modules/golem-driver/test/ReferencesSpec.hs`）

- 本文の和文の書体を Noto Serif JP にした行長 40 字の横組みの本で、開発者のマニュアルの「決定性が純粋性に求めること」の表と同じ原稿の表を組む。一列めのすべてのセルが一行で組まれる。
- 同じ本で、二行以上に分かれたセルの最後の行が、どれも和文の二字以上を持つ。
- 二列の表の最後のセルが `あ` 一字のとき、最後の二字のあいだに改行の位置がない。最小の幅が二字分になる。

### 自動テストにしない確かめ方

- 二つのマニュアルを組み、この ADR の再現に挙げた二つの表と、プレーンテキストの節の表、チャネルの表を PNG に描いて、短い列が折り返さないことを目で確かめる。

## トレードオフ

水を注ぐ配り方は、短い列に自然な幅を与えるぶん、長い列の幅を狭める。
開発者のマニュアルの表では、三列めの幅が 21.5 字から 13 字に減り、三列めのセルの行の数は増える。
見積もると、表の全体の行の数は 16 行から 17 行に増える。
代わりに、一列めと二列めの見出しのような短いセルは、どれも一行に収まる。
表を読むときは、短い列の項目を手がかりに長い列を読むので、短い列が分かれないことを優先した。
JLReq の 4.4.3 の例と tabularx も、同じく短い列を折り返さない。

今の配り方は CSS の表の自動の配置と同じで、ブラウザーの表と見た目がそろうという利点があった。
しかし、CSS の算法は欧文の語を単位にした最小の幅を前提にしており、和文の一字を最小の幅にすると、短い列ほど割合の上で多く削られる。
和文の表で JLReq の例に近い結果を得るには、配り方そのものを替えるほうが単純である。

セルの最後の二字のあいだで改行しないことで、和文のセルの最小の幅が一字から二字に増える。
列の数が多く、行長がぎりぎりの表では、今は収まる表が G0741 になる場合がありうる。
その場合は、エラーの位置の表を書き手が直すことになる。

報告された不具合のうち、短い列のセルが折り返すこと、狭い列で字のあいだが空くこと、最後の行に一字だけが残ることは、この ADR の配り方とセルの最後の字の規則で解消する見込みである。
二つの再現の表では、短い列がどれも自然な幅を受け取るので、折り返す短いセルがなくなる。
残る、改行できないコードの前の行の字のあいだは、表に限らない行の調整の問題であり、追い込みと追い出しの設定で扱う。
