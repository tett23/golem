# Golem 言語仕様

この文書は、Golem の原稿を書くための記法を定める。
処理系全体の設計思想、評価の階層、出力の扱いは [specifications.md](./specifications.md) にあり、この文書はそこで決めた事項を記法の側から記述する。

## 原稿の例

```
@import common/values.gm as values
@set version = "1.0"

@label intro
# はじめに

Golem は[ruby: 組/版|くみ/はん]の結果を、同じ入力から常に同じバイト列として出力する[note: この性質を決定性と呼ぶ。]。
本書は第[= version]版である。
%% 図を一枚入れる %%

詳しくは第[ref-number design]章「[ref-title design]」で説明する。

= 決定性
  同じ入力から同じ出力を得る性質。
```

## ファイル

原稿のファイルは文字コードを UTF-8 とし、拡張子を `.gm` とする。

- BOM は付けない。先頭に BOM のあるファイルはエラー（G0102）とする。
- 改行は LF に限る。CR を含むファイル（CRLF の改行と単独の CR の両方）はエラー（G0103）とし、`golem fmt` で LF に直せる。改行の扱いが入力によって揺れると、同じ原稿から同じ出力が得られなくなるためである。
- Unicode の正規化は行わない。正規化をかけると CJK 互換漢字が統合漢字に置き換わり、書き手が選んだ異体字が失われるためである。

## 文書の構造

原稿は、ブロックの並びである。
段落と段落の区切り方は、マニフェストで選ぶ様式によって空行か改行ひとつになる（「段落と改行」の節を参照）。
ブロックには段落、見出し、リスト、定義リスト、ブロックコマンドがある。
ブロックの種類は行頭の文字で決まり、段落の中身はインラインの要素の並びである。

### 段落と改行

段落の区切り方には、空行の様式と改行の様式の二つがある。
どちらを使うかは、マニフェストの `[source]` の `paragraph-separator` で選ぶ（[docs/adr/0013](adr/0013-paragraph-separator.md)）。
既定は空行の様式である。

```toml
[source]
paragraph-separator = "line"
```

| 値 | 様式 |
|---|---|
| `"blank-line"` | 空行の様式。空行で段落を区切る |
| `"line"` | 改行の様式。改行ひとつで段落を区切る |

章の配列の項目に `{ file = "chapters/02-en.gm", paragraph-separator = "blank-line" }` と書くと、その章のファイルにだけ別の様式を使える。
ファイルの先頭に `@manifest paragraph-separator=line` と書くと、そのファイルの中の上書きになり、章の項目と `[source]` より優先する（「ファイルの設定」の節を参照）。
`@import` でだけ参照されるファイルには、`[source]` の様式が効く。

#### 空行の様式

空行で区切られた行のまとまりが一つの段落になる。
段落内の改行は文字を生まない。
改行の前後は、空白を挟まずにそのままつながる。

```
吾輩は猫である。
名前はまだ無い。
```

この二行は「吾輩は猫である。名前はまだ無い。」という一続きの本文になる。
欧文の単語の間で改行すると単語どうしが連結されるので、欧文の語句は改行で分けずに一行で書く。

#### 改行の様式

一行が一つの段落になる。
青空文庫の形式のように、改行ひとつで段落を区切る和文の原稿をそのまま書ける。

```
　吾輩は猫である。
　名前はまだ無い。
```

この二行は二つの段落になる。
行頭の半角の空白とタブは本文に含めない。
全角の空白（U+3000）は本文に含める。

改行の様式では、次の規則に従う。

- 空行は無視する。空行がいくつあっても、改行ひとつと同じく段落の区切りになるだけで、空きを生まない。
- 見出し、リスト、定義リスト、表、コードブロック、ブロックコマンドは、空行の様式と同じ規則で書く。段落の直後の行でも、行頭の文字でブロックが始まる。
- リストの項目の続きの行（2 つ深くインデントした行）は、項目の中の次の段落になる。
- 属性は、直後の一行の段落にだけ付く。複数の段落に段落スタイルを付けるには、本体を持つ `@style` を使う。
- `line-breaks = "keep"` の段落スタイルの段落（`@style verse` など）では、改行は行の区切りであり、連は空行で区切る。空行の様式と変わらない。属性の形の `@style verse` も、直後の一行ではなく、直後の段落の全体を一つの連にする。
- 段落の中で行を折り返して書く手段は設けない。一つの段落は一行で書く。例外は強制改行（「強制改行」の項を参照）で、行末の `\` で終わる行と次の行は一つの段落になる。強制改行は出力の行も改めるので、長い段落を見やすく折り返して書く用途には使えない。
- 散文スロットの中とコメントの中の改行は、段落を区切らない。散文スロットの中の改行は、空行の様式と同じく文字を生まない。

#### 強制改行

段落の行の末尾に `\` を書くと、段落を分けずに、その位置で行を改める（[docs/adr/0016](adr/0016-hard-line-breaks.md)）。
住所、署名、手紙の結びのように、一つの段落の中で行を改めたいときに使う。

```
〒100-0001\
東京都千代田区千代田1-1\
山田太郎様
```

強制改行は、次の規則に従う。

- `\` は行の最後の文字でなければならない。`\` の後に空白を書くと、エスケープした空白（`\ `）と行末の空白になり、強制改行にならない。
- `\` の前の空白とタブは無視する。次の行の先頭の空白とタブも無視する。全角の空白（U+3000）は無視しない。
- `\` の次の行は、同じ段落の続きの行でなければならない。空行、ファイルの末尾、ブロックの始まりの文字（`#`、`- ` など）で始まる行が続くと、構文エラー（G0124）になる。
- 二つの段落の様式のどちらでも、意味は同じである。空行の様式では、強制改行の次の行と、その後の改行でつながる行が、新しい行になる。改行の様式では、`\` で終わる行と次の行が一つの段落になる。
- 強制改行の後の行は同じ段落の行なので、段落スタイルの一行目の字下げは掛からない。
- リストの項目、定義リストの説明、図版のキャプションの段落にも書ける。見出し、定義リストの用語、表のセルは一行で書く記法なので、強制改行を書けない。表の行の閉じる `|` の後の `\` も、見出しと同じく構文エラー（G0124）になる（[golem-parser ADR 0010](golem-parser/adr/0010-ruby-slash-escape-and-table-cell-breaks.md)）。
- 散文スロットの中（注、ルビ、文字スタイルなど）には書けない（G0256）。行をまたいで斜体などを続けたいときは、行ごとにコマンドを閉じて開き直す。
- 中身のない行は作れない。段落の最初の行が `\` だけの場合、`\` だけの行が続く場合、`\` の次の行がコメントだけの場合は、エラー（G0257）になる。

#### 空白の扱い

行末の空白は無視する。
表のセルの両端と、散文スロットの末尾の空白も同じく無視する。
これらの位置に空白を置きたい場合は、`\ ` とエスケープして書く。
ただし、`line-breaks = "keep"` の段落（「韻文」の節）の行末では、エスケープした空白も除く。
全角の空白（U+3000）は無視しない。

行分けを保つには、段落スタイル `verse` を `@style verse` で付ける（「韻文」の節を参照）。

## エスケープ

バックスラッシュ `\` が唯一のエスケープ文字である。
特殊な意味を持つ文字の前に `\` を置くと、その文字は本文の文字として扱われる。
`\` 自身は `\\` と書く。

エスケープが必要になるのは、次の位置にある文字である。

- 本文中の `[`。`[` は常にインラインの要素の開始として解釈されるので、本文に `[` を書くときは `\[` とする。
- 命令文脈の散文スロットの中の `]` と `|`。
- ルビの親文字と読み、索引の語の中の `/`。区切りでない `/` は `\/` と書く（[golem-parser ADR 0010](golem-parser/adr/0010-ruby-slash-escape-and-table-cell-breaks.md)）。
- 行頭の `#`、`-`、`+`、`=`、`@`、`|`。これらは行頭でブロックの種類を表すので、段落を行頭からこれらの文字で始めるときはエスケープする。
- `%%`。コメントの開始と区別するため、本文に `%%` を書くときは `\%%` とする。

単独の `%` はエスケープしなくてよい。

行末の `\` は、何もエスケープせず、強制改行になる（「強制改行」の項を参照）。
本文の `\` を行末に置くときは `\\` と書く。
`\\` の後の改行は、ほかの改行と同じく段落の様式に従う。

## コメント

コメントは `%%` で始まり `%%` で終わる。
コメントの中身は出力されない。

```
本文。%% 出典を確認する %%
```

`%%=` で始まるコメントは校正用である。
dev ビルドでのみ出力に現れ、prod ビルドに残っていると警告になる。

```
%%= この段落はまだ書きかけ %%
```

コメントは段落の境界（空行）を越えられない。
段落の中で閉じていないコメントは構文エラーとなる。

## ブロック

### 見出し

行頭の `#` の数が見出しの階層を表す。

```
# 章の見出し
## 節の見出し
### 項の見出し
```

見出しの番号は自動で振られ、表記（「第 1 章」か「1.」か）は `style.toml` のスタイルで決まる。
番号は 1 から始まり、番号を指定しない見出しは直前の番号に 1 を加えた番号になる。
番号は属性のブロックコマンドで明示でき、その後の見出しは指定した番号から数え続ける。
番号からの除外を指定した見出しは、番号を消費しない。
見出しの文字列は自由に付けてよい。

見出しの中では、文書構造（S1）とレイアウト後（S2）の値を参照できない。
具体的には、`doc` 名前空間、`[ref-number ...]`、`[ref-title ...]`、ページ番号への参照を見出しに書くとコンパイルエラーになる。
変数、import した定義、`meta` 名前空間は見出しでも使える。

### リスト

行頭の `-` と空白で項目を始める。
入れ子は 2 つの空白によるインデントで表す。

```
- 印刷用の PDF
- 電子書籍
  - EPUB
  - HTML
```

PDF では、項目の印（既定は `・`）を行の始まりにぶら下げ、項目の二行目以降と二つ目以降の段落を本文の始まりにそろえる。
入れ子のリストは、外の項目の本文の始まりから下げる。
印の字形は `style.toml` の `[lists]` の `bullets` で、入れ子の深さごとに変えられる（[golem-driver ADR 0013](golem-driver/adr/0013-list-indents.md)）。

### 番号付きリスト

行頭の `+` と空白で項目を始める。

```
+ 原稿を書く
+ push する
+ CI が組版する
```

番号は 1 から自動で振られる。
途中の番号から始めるには、項目の直前に `@number N` を置く。
`@number N` のある項目は N 番になり、以後の項目は N から数え続ける。
この番号は、HTML、EPUB、プレーンテキストに加えて PDF でも効く。
PDF の既定の番号は、横組みでは算用数字とピリオド（`1.`）、縦組みでは本の数の表記と読点（`一、`）である。
番号の書式は `style.toml` の `[lists]` の `numbers` で、入れ子の深さごとに変えられる（[golem-driver ADR 0013](golem-driver/adr/0013-list-indents.md)）。
番号を本文に手で書かないのは、項目を入れ替えるたびに番号を直す必要が生じるためである。
入れ子の規則は箇条書きのリストと同じである。

### 定義リスト

行頭の `=` と空白で用語を書き、その直後のインデントしたブロックに説明を書く。
説明には段落、リスト、コードなどのブロックを複数置ける。

```
= 決定性
  同じ入力から同じ出力を得る性質。

= HTTP
= HyperText Transfer Protocol
  二つの用語が一つの説明を共有する。

= モナド
  圏論における定義。
=:
  プログラミングにおける定義。
```

`=` の行が連続すると、それらの用語が次の説明を共有する。
`=:` は、直前の用語を引き継いだまま新しい説明を始める。
これにより、用語と説明の多対多の対応をそのまま書ける。

### ブロックコマンド

行頭の `@` に続く名前がブロックコマンドである。
インラインの命令文脈 `[name ...]` に対応する、行単位の命令である。

```
@name 位置引数... key=value...
```

引数の規則はインラインの命令文脈と同じである。

v1 で定めるブロックコマンドは次のとおりである。

- `@set name = 式`：ファイル単位の変数を定義する。式は式文脈の言語で書く。
- `@import path as ns`：別のファイルで `@set` により定義した変数を、名前空間 `ns` の下に取り込む。名前空間は省略できない。パスはプロジェクトルートの中に限る。v1 で取り込めるのは変数だけである。
- `@label name`：直後のブロックにラベルを付ける。
- `@toc depth=N`：目次を出力する。文書に一つだけ置ける。PDF では、各項目に見出しのページ番号をリーダーとともに出す（[golem-driver ADR 0009](golem-driver/adr/0009-pdf-toc-page-numbers.md)）。
- `@index`：索引を出力する。
- `@bibliography`：参考文献の一覧を出力する。
- `@printings`：マニフェストの `[[metadata.printings]]` から、発行の履歴（`2026年10月16日　初版第1刷発行` の形の段落）を一項目一段落で組む。引数と本体は取らない。日本語の本でだけ使える（[docs/adr/0033](adr/0033-colophon-contributors-and-printings.md)）。
- `@figure`：図版を置く（「図版」の節を参照）。
- `@table src=path format=形式 align=揃え cells=text`：CSV か TSV のファイルから表を作る（「表」の節を参照）。`format`、`align`、`cells` は省ける（[golem-eval ADR 0004](golem-eval/adr/0004-tsv-tables.md)）。
- `@listing path lines=N-M lang=言語`：Golem 以外のファイルの内容をコードとして取り込む（「コードブロック」の節を参照）。パスは最初の引数に書く。`lang` は色分けの言語の名前である。コードブロックの開始の行と同じキーワード引数も書ける。`src=path` とも書けるが廃止予定であり、お知らせ（G0265）を出す（[golem-syntax ADR 0002](golem-syntax/adr/0002-notice-severity.md)）。
- `@style 名前`：段落に段落スタイルを付ける（「段落スタイル」の節を参照）。
- `@page-break`、`@page-break recto`、`@page-break verso`：次のページ、次の奇数ページ、次の偶数ページから続ける（「改ページ」の節を参照）。
- `@column-break`：次の段から続ける（「改ページ」の節を参照）。
- `@no-page-break`：前のブロックと次のブロックのあいだで、改ページも改段もしない（「改ページ」の節を参照）。
- `@need-lines N`：今の段の残りが N 行に足りなければ、次の段から続ける（「改ページ」の節を参照）。
- `@page-lines +N`、`@page-lines -N`：印の位置の段の行数を、その段に限り N 行増やす（減らす）（「改ページ」の節を参照）。
- `@manifest key=value`：そのファイルにだけ効く設定で、マニフェストの `[source]` のキーを上書きする（「ファイルの設定」の節を参照）。
- `@style-def 種類 名前 key=value...`：そのファイルにだけ効く文字スタイルと段落スタイルを定義する（「ファイルの設定」の節を参照）。

### 図版

```
@label fig-arch
@figure images/arch.pdf web=images/arch.png alt="Golem の構成図"
  構成図のキャプション。
```

`@figure` の最初の引数が画像のパスである。
`@figure` に続くインデントした行がキャプションになる。

- `alt` の代替テキストは必須であり、欠けているとコンパイルエラーになる。
- 画像の形式は PDF、SVG、PNG、JPEG で、拡張子（`.pdf`、`.svg`、`.png`、`.jpg`、`.jpeg`。大文字と小文字を区別しない）で決める。ほかの拡張子はコンパイルエラー（G0274）になる。
- PDF の画像は EPUB と HTML で表示できないので、`web` に Web 用の代替画像（PNG、JPEG、SVG）を指定する。PDF の画像で `web` を省くとコンパイルエラーになる。`web` にほかの形式を書くと G0273 になる。`web` は PNG、JPEG、SVG の図版にも書け、HTML と EPUB は `web` があればそれを使う。
- PDF の画像は、`page` で何ページ目を置くかを選べる（`page=3` など）。1 以上の整数で、省けば 1 である。整数でない値、0 以下の値、PDF でない画像の `page` は G0275 になる。
- SVG の画像は、PDF でもベクターのまま描く（[golem-pdf ADR 0009](golem-pdf/adr/0009-svg-figures.md)）。扱うのは、パス、基本の図形、変換、塗りと線、マーカー、単純な CSS の範囲である。範囲の外のもの（グラデーション、`use`、クリップ、1 でない不透明度など）と、輪郭にしていない文字は、PDF を組むときに G0811 のエラーになる。文字は図の作成ツールで輪郭にして書き出す。HTML と EPUB は SVG をそのまま置く。
- PDF の画像は、そのページの切り抜きの枠（CropBox）をベクターのまま置く（[golem-pdf ADR 0008](golem-pdf/adr/0008-pdf-figures.md)）。PDF に置けない画像（壊れた画像、暗号化された PDF、フォントを埋め込んでいない PDF など）は、PDF を組むときに G0810 のエラーになる。

```
@figure images/figures.pdf page=3 web=images/fig3.png alt="三つめの図"
```

図番号は章ごとに自動で振られ、表記は `style.toml` のスタイルで決まる。

`wrap` を指定すると、図版を版面の端に寄せ、本文を図版の脇に回り込ませる。

```
@figure images/logo.png alt="ロゴ" wrap=end width=12zw
  ロゴのキャプション。
```

- `wrap=start` は行の始まりの側（横組みでは左、縦組みでは上）、`wrap=end` は行の終わりの側に図版を寄せる。
- 回り込ませる図版には `width`（横組みでは幅、縦組みでは高さ）を必須とする。
- 回り込みは PDF でだけ行い、EPUB と HTML では回り込ませない通常の図版として出力する。

### 表

行頭の `|` で始まる行が表の行である。
一行目が見出しの行であり、二行目の区切りの行で本体と分ける。
区切りの行の `:` で列の揃えを指定する（`:---` は左寄せ、`:---:` は中央、`---:` は右寄せ）。

```
| 形式 | 用途 |
|---|---|
| PDF | 印刷 |
| EPUB | 電子書籍 |
```

セルの中身はインラインの要素に限る。
セルの結合と、セルの中のブロックは扱わない。

データの表は、`@table` で CSV か TSV のファイルから作れる（[golem-eval ADR 0004](golem-eval/adr/0004-tsv-tables.md)）。

```
@table src=data/sizes.tsv align=left,right,right
@table src=data/export.txt format=tsv
```

キーワード引数は次の四つである。

| 引数 | 値 | 既定 |
|---|---|---|
| `src` | 表のファイルのパス | なし（G0234） |
| `format` | `csv` か `tsv` | パスの拡張子で決める |
| `align` | 列の揃えのカンマ区切りの並び | すべての列が既定の揃え |
| `cells` | `text` | `text` |

`format` を書かなければ、拡張子が `.tsv`（`.TSV` も）のファイルを TSV、それ以外を CSV として読む。
`format` に `csv` と `tsv` のほかの値を書くとエラー（G0280）になる。

CSV は RFC 4180 の規則で読む。
カンマでセルを区切り、`"` で囲んだセルにはカンマと改行を書け、`""` が一つの `"` になる。
空の行は捨てる。

TSV はタブでセルを区切り、引用符もエスケープもない。
`"` と `\` は書いたままの文字である。
ファイルの末尾の行の終わりを一つだけ捨て、途中の空の行は一つの空のセルを持つ行として読む。

どちらも、行の終わりは LF か CRLF であり、一行目が見出しの行になる。
すべての行のセルの数は、見出しの行と同じでなければならない（違えば G0285）。
文字コードは UTF-8 に限り、ファイルの先頭の BOM は読み飛ばす。
LF の前にない CR はエラー（G0282）になる。
セルの中身は地の文として扱い、インラインの記法を解釈しない。

`align` は列の揃えを左の列から順に並べる。
値は `left`、`center`、`right`、`default` で、原稿の `|` の表の区切りの行の `:---`、`:---:`、`---:`、`---` にあたる。
値を一つだけ書けば、すべての列に当てる（`align=right`）。
二つ以上書くときは、表の列の数と同じ数を書く。
数が合わないとき、空の値、ほかの値、式を書いたときはエラー（G0281）になる。
縦組みでは、`left` が天寄せ、`right` が地寄せになる。

`cells` はセルの読み方を決める引数として予約してあり、今は `text`（地の文として読む）だけを書ける。
`cells=markup` は、将来セルをインラインの記法として読むための名前であり、今はエラー（G0284）になる。

### コードブロック

行頭の ```` ``` ```` で始まる行から、次の ```` ``` ```` の行までがコードブロックである。
最初の ```` ``` ```` の後に言語の名前を書くと、構文に応じて色分けされる。

````
```haskell
main = putStrLn "Golem"
```
````

コードブロックの中身は書いたままのテキストとして扱い、コマンド、コメント、エスケープを解釈しない。

ファイルの内容を取り込む場合は `@listing` を使う。

```
@listing src/Main.hs lines=10-20
```

`lines` を省くと、ファイル全体を取り込む。

コードブロックは、```` ``` ```` も `@listing` も、組み込みの段落スタイル `code` で組む（[golem-driver ADR 0017](golem-driver/adr/0017-pdf-code-blocks.md)）。
書体は `style.toml` の `[fonts.code]` の役割で指定し、なければ本文の書体で組む。
PDF では、行頭と行の途中の空白をそのまま残し、タブは空白の 2 字分ごとの位置まで進める。
両端揃え、ハイフネーション、和欧間の空きはかけない。
版面の行長に収まらない行は折り返し、続きの行を元の行の字下げより空白 2 字分深く始める。
折り返したことはお知らせ（G0730）で伝える。
空行は、先頭と末尾のものも残す。
`code` は原稿の `@style` には書けない（G0266）。

技術書のための機能は、開始の行の言語の名前の後と `@listing` に、同じキーワード引数で書く（[golem-driver ADR 0023](golem-driver/adr/0023-code-block-book-features.md)）。

````
@caption 設定の読み込み
```haskell numbers=10 file="src/Main.hs" highlight=12,14-15 callouts=true
main :: IO ()
main = do
  args <- getArgs          <1>
  mapM_ putStrLn args      <2>
```
````

```
@listing src/Config.hs lines=20-48 lang=haskell numbers=true highlight=25
```

| キー | 値 | 既定 | 意味 |
| --- | --- | --- | --- |
| `numbers` | `true`、`false`、0 以上の整数 | `[code]` の `line-numbers` | 行番号を付けるか。整数は付けたうえで最初の行の番号にする |
| `file` | 文字列 | なし | コードの上に出すファイル名 |
| `highlight` | 行番号の並び（`3`、`3,5-7`） | なし | 強調する行 |
| `diff` | `true`、`false` | `false` | 行頭の `+`、`-`、空白を差分の印として読む |
| `callouts` | `true`、`false` | `false` | 行末の `<N>` を注釈の印として読む |
| `lang` | 言語の名前 | なし | 色分けの言語。`@listing` にだけ書ける |

言語の名前を書く場合は、キーワード引数より前に書く。
言語の名前を書かずに、```` ``` numbers=true ```` のようにキーワード引数だけを書いてもよい。
言語の名前のほかの位置引数と、表にないキーはエラー（G0269）とする。

コードブロックの各行は、行番号を表示するかどうかによらず、番号を持つ。
最初の行の番号は、`numbers` が整数ならその値、`@listing` で `lines=N-M` を書いたなら N、ほかは 1 である。
後の行は一つずつ増える。
`@listing src/Config.hs lines=20-48` の最初の行は 20 番になり、ファイルの行番号と一致する。
`diff=true` のコードでは、`-` の行（削除した行）は番号を持たず、数えない。
`highlight` には、この数え方の行番号を、カンマで区切って書く。
`N-M` は N から M までの行である。
コードブロックにない番号を書くとエラー（G0269）とする。

`diff=true` のコードでは、各行の最初の一字を差分の印として読み、コードの本文から取り除く。
`+` は追加した行、`-` は削除した行、空白は変わらない行である。
空の行は、変わらない空の行とする。
ほかの字で始まる行はエラー（G0269）とする。

`callouts=true` のコードでは、行末の `<N>`（N は 1 から 50 まで）を注釈の印として読み、印とその前の空白をコードの本文から取り除く。
`<1> <2>` のように空白で区切った複数の印も読む。
印は丸数字（①）で組まれる。
本文では、同じ丸数字を地の文に書いて説明する。
`List<1>` のように `<数>` で終わるコードがあるので、`callouts` は既定で切ってある。

キャプションは、コードブロックと `@listing` の直前に `@caption` で書く（「ブロックへの属性」の節を参照）。
キャプションのあるコードブロックはリスト番号（既定 `リスト{chapter}-{n}`）を持ち、コードの上にリスト番号とキャプションを置く。
行番号の表示、強調と差分の背景の色、色分けの色、折り返した印、改ページで分かれたときの続きの表示は、`style.toml` の `[code]` と `[code.colors]` で決める。

### 段落スタイル

段落の見た目は、`style.toml` の `[paragraph-styles.名前]` で定義した段落スタイルで決まる（[docs/adr/0005](adr/0005-character-and-paragraph-styles.md)）。
段落スタイルは `@style 名前` で段落に付ける。
`@style` は二つの形で書ける。

```
@style quote
引用の段落。この段落だけが quote になる。

@style verse
  Full fathom five thy father lies;
  Of his bones are coral made;

  Nothing of him that doth fade,
  But doth suffer a sea-change
```

- 属性の形：インデントのない次の行に段落を書く。直後の段落一つに段落スタイルが付く。
- 本体の形：2 つ深くインデントした段落を並べる。本体のすべての段落に段落スタイルが付く。本体には段落だけを置ける。段落以外のブロックを置くとエラーになる。

`@style` の引数は段落スタイルの名前一つである。
`style.toml` にもそのファイルの `@style-def` にもない名前はエラーになる。

段落の字下げは段落スタイルの `indent`（すべての行）と `first-line-indent`（最初の行に加える量。負ならぶら下げ）で指定する（[docs/adr/0006](adr/0006-paragraph-indent.md)）。
既定は 0 なので、段落スタイルで字下げを指定する場合は、段落の先頭の全角の空白を書かない。

組み込みの段落スタイルは `body`、`verse`、`caption`、`sidenote`、`code` の五つである。
`code` はコードブロックを組む段落スタイルで、原稿の `@style` には書けない（「コードブロック」の節を参照）。
段落スタイルを付けない段落は `body` で組む。
`caption` と `sidenote` は、図版のキャプションと傍注の本文の書体と大きさを決める段落スタイルでもある。

スタイルの名前は、英小文字で始まり、英小文字、数字、`-` だけからなる。
そのファイルでだけ使う段落スタイルは、ファイルの先頭の `@style-def paragraph` でも定義できる（「ファイルの設定」の節を参照）。

#### 正規表現スタイル

段落スタイルの `regex-styles` に、正規表現と文字スタイルの組を並べると、段落の中で正規表現に一致した文字にその文字スタイルが当たる（[docs/adr/0015](adr/0015-regex-styles.md)）。
InDesign の正規表現スタイル（英語版の GREP スタイル）に当たる。
原稿の該当箇所にいちいち `[style 名前: ...]` を書かずに、数字だけを欧文の書体にする、「第 N 章」の N を太字にする、といった指定ができる。

```toml
[character-styles.latin-digits]
font = "latin"

[paragraph-styles.body]
regex-styles = [
  { pattern = '[0-9０-９]+', style = "latin-digits" },
  { pattern = '(?<=第)[0-9]+(?=章)', style = "bold" },
]
```

- 正規表現は TOML のリテラル文字列（`'...'`）で書くと、`\` をそのまま書ける。基本の文字列（`"..."`）では `\` を `\\` と書く。ファイルの中で足す場合は「ファイルの設定」の節の `@style-def regex` を使う。
- `regex-styles` は一つのキーとして `based-on` で引き継ぐ。書かなければ親の並びを引き継ぎ、書けば親の並びを置き換える。`regex-styles = []` は引き継がないことを表す。組み込みの段落スタイルは `regex-styles` を持たない。
- 並びの順は意味を持つ。同じ文字に複数の組が一致した場合は、後の組の文字スタイルが勝つ。
- 原稿で手で当てた文字スタイル、色、圏点は、正規表現スタイルに勝つ。
- 組み込みの `strong` を使うと、HTML では意味の強調の `<strong>` になる。見た目だけを変えたい場合は `bold` か、自分で定義した文字スタイルを使う。

正規表現の方言は、InDesign の方言（Boost の Perl 互換）の部分集合である。

| 構文 | 意味 |
|---|---|
| 文字 | その文字に一致する |
| `\` と英数字でない文字 | その文字に一致する（`\.`、`\\`、`\[`、`\~` など） |
| `\t`、`\n` | タブ、行の区切り（強制改行と `keep` の段落の行の区切り） |
| `\xHH`、`\x{H...}` | 符号位置で書いた文字 |
| `.` | `\n` を除く任意の一字 |
| `[...]`、`[^...]` | 文字クラス。範囲（`a-z`、`\x{3041}-\x{3096}`）、下の文字クラスのエスケープ、POSIX の文字クラスを含められる |
| `[:alpha:]`、`[:digit:]`、`[:alnum:]`、`[:upper:]`、`[:lower:]`、`[:space:]`、`[:punct:]` | 文字クラスの中の POSIX の文字クラス。Unicode の一般カテゴリーで決める |
| `\d`、`\D` | 数字（全角の数字を含む）とその補集合 |
| `\w`、`\W` | 語の文字（漢字、仮名を含む）とその補集合 |
| `\s`、`\S` | 空白（全角の空白を含む）とその補集合 |
| `\l`、`\u` | 小文字、大文字 |
| `\p{名前}`、`\P{名前}` | 一般カテゴリー（`L`、`Lu`、`Nd`、`Punctuation` など） |
| `*`、`+`、`?`、`{n}`、`{n,}`、`{n,m}` | 量指定子（欲張り） |
| `*?`、`+?`、`??`、`{n,}?`、`{n,m}?` | 量指定子（怠惰） |
| `\|`、`(...)`、`(?:...)` | 選択と群 |
| `^`、`$` | 段落の先頭と末尾 |
| `\b`、`\B` | 語の境界とその否定 |
| `(?=...)`、`(?!...)` | 先読み |
| `(?<=...)`、`(?<!...)` | 後読み。中身は固定の長さに限る |
| `\K` | そこまでの一致を一致の範囲から外す |
| `(?i)` | 正規表現の先頭にだけ書ける。大文字と小文字を区別しない |

表にない構文はエラーになる。
後方参照、名前付きの群、アトミックな群、所有的な量指定子、条件、コメントの群、先頭でないフラグ、`\Q`、`\h`、`\A` のような表にない英字のエスケープ、`\p{Han}` のような文字体系、長さの決まらない後読みは使えない。
InDesign の `~` で始まるメタ文字（`~m` など）も使えない。
文字の `~` は `\~` と書く。
和文の文字体系は `[\x{4E00}-\x{9FFF}]` のように符号位置の範囲で書く。

当てる範囲は次のとおりである。

- 一致は段落ごとに求め、段落をまたがない。
- 段落にはその段落スタイル（付けなければ `body`）の並びを、図版のキャプションには `caption` の並びを、傍注の本文には `sidenote` の並びを当てる。リストの項目と定義リストの説明の段落にも当てる。
- 脚注の本文、見出し、定義リストの用語、表のセル、目次、索引、参考文献には当てない。
- ルビは親文字だけに一致し、読みには一致しない。
- 縦中横、数の表記（`[number-text ...]`）、相互参照、`[= ...]` で `doc` を参照した値、文献の引用、脚注と傍注の位置は、それぞれ一字として扱い、中の文字には一致しない。たとえば `[0-9]+` は縦中横の数字に一致しない。
- 強制改行は `\n` として一致の対象になるが、文字スタイルは強制改行をまたがない。

### 韻文

詩や戯曲の韻文は、組み込みの段落スタイル `verse` を付けて書く（[docs/adr/0003](adr/0003-verse-line-breaks.md)、[docs/adr/0005](adr/0005-character-and-paragraph-styles.md)）。

```
@style verse
  Full fathom five thy father lies;
  Of his bones are coral made;
  Those are pearls that were his eyes:

  Nothing of him that doth fade,
  But doth suffer a sea-change
```

本体の段落の一つが一つの連であり、段落の中の各行が韻文の一行である。
連は空行で区切る。

`verse` は `line-breaks = "keep"` の段落スタイルである。
`line-breaks = "keep"` の段落スタイルを付けた段落では、次の規則で行を分ける。

- 段落の中の改行は、ほかの段落と違い、行の区切りになる。
- 行の区切りになるのは、インラインのコマンドの外にある改行だけである。散文スロットの中の改行（`[note: ...]` の中など）は、ほかの段落と同じく文字を生まない。行をまたいで斜体などを続けたい場合は、行ごとにコマンドを閉じて開き直す。
- 各行の先頭と末尾の空白とタブは、エスケープした空白（`\ `）も含めて無視する。行末のエスケープした空白にはお知らせ（G0279）を出す（[golem-parser ADR 0012](golem-parser/adr/0012-keep-trailing-escaped-space.md)）。全角の空白（U+3000）は無視しないので、和文の詩で行ごとに字下げしたい場合は全角の空白を使う。
- 行頭でエスケープの要る文字（`#`、`-`、`+`、`=`、`@`、`|`）は、ほかの段落と同じく `\` でエスケープする。
- 行末の `\`（強制改行）は、改行と同じ意味になる。行の区切りは一つだけ生じ、`\` の次の行も新しい韻文の行として、一行目の字下げが掛かる（[docs/adr/0016](adr/0016-hard-line-breaks.md)）。

PDF では、版面の行長を超えた行を折り返し、折り返した部分を字下げする（ぶら下げ）。
各行の字下げは `style.toml` の `[paragraph-styles.verse]` の `indent` と `first-line-indent` で、連の間に空ける行の数は `space-between` で指定する（[docs/adr/0006](adr/0006-paragraph-indent.md)）。
既定は `indent = "2zw"`、`first-line-indent = "-2zw"` であり、各行の始まりは字下げせず、折り返した部分を二字下げる。

### ブロックへの属性

ラベルや見出しの属性は、対象のブロックの直前の行にブロックコマンドとして書く。
属性のブロックコマンドが連続した場合は、それらがまとめて次のブロックに付く。

```
@label preface
@nonumber
@notoc
# まえがき
```

属性のブロックコマンドの直後にブロックがない場合はコンパイルエラーとなる。
ただし、属性のまとまりの最後に属性でないブロックコマンド（本体を持つ `@style` や `@figure`）を置くと、それが対象のブロックになる。

```
@label song
@style verse
  Full fathom five thy father lies;
```

`@style` を属性として付けられるのは段落だけである。

見出しに付けられる属性は次の四つである。

- `@toc-title 短い題`：目次と柱に使う短い題。指定しなければ見出しの題を使う。
- `@number N`：見出しの番号を `N` にする。以後の見出しは `N` から数え続ける。
- `@nonumber`：番号を振らない。この見出しは番号を消費しない。
- `@notoc`：目次に載せない。

`@number` は番号付きリストの項目にも付けられ、リストを途中の番号から始めるのに使う。

コードブロックと `@listing` には、`@caption 本文` でキャプションを付けられる（[golem-driver ADR 0023](golem-driver/adr/0023-code-block-book-features.md)）。
本文は `@toc-title` と同じく行の残りであり、`[code: ...]` のようなインラインの要素を書ける。
キャプションを付けたコードブロックはリスト番号を持ち、`@label` を付ければ `[ref-number ...]` と `[ref-title ...]` で参照できる。
コードブロックのほかのブロックに `@caption` を付けるとエラー（G0213）、本文のない `@caption` はエラー（G0269）とする。
図版のキャプションは、今のとおり `@figure` の字下げした行で書く。

### 改ページ

原稿の任意の位置で、ページや段を改められる（[docs/adr/0017](adr/0017-forced-page-breaks.md)）。

```
@page-break
@page-break recto
@page-break verso
@column-break
```

| 記法 | 意味 |
|---|---|
| `@page-break` | 次のページから続ける（改ページ） |
| `@page-break recto` | 次の奇数ページから続ける（改丁） |
| `@page-break verso` | 次の偶数ページから続ける |
| `@column-break` | 次の段から続ける（改段） |

改ページは本文の流れの中の一点を表し、その後にある最初のもの（行、見出し、図版、表など）を、次の規則で決まる位置から置く。

- `page`：今のページを閉じ、次のページから置く。今のページに何も置いていなくても閉じるので、二つ続けると白ページが一ページできる。
- `recto`：今のページに何も置いておらず、奇数ページなら何もしない。そうでなければ次の奇数ページから置き、途中の偶数ページは白ページになる。見出しの `page-break = "recto"` と同じ規則である。
- `verso`：`recto` の奇数と偶数を入れ替えた規則である。
- `column`：今の段を閉じ、次の段から置く。今の段が最後の段なら、次のページの最初の段から置く。今の段に何も置いていなくても進むので、段の先頭の改段は空の段を一つ作る。一段組みの版面では `page` と同じになる（[docs/adr/0018](adr/0018-multi-column-layout.md)）。
- 段組みの版面の `page`、`recto`、`verso` は、今の段がどの段であっても、次のページの最初の段から置く。今のページに残る段は空のままにする。

本の最後の改ページは捨て、本の末尾に白ページを作らない。
ファイルの末尾の改ページは、次のファイルの最初のものに効く。
改ページが続く場合は、書いた順にそれぞれを適用する。
白ページには柱もノンブルも描かない。

改ページは文書の最上位にだけ置ける。
リストの項目、定義リストの説明、ブロックコマンドの本体（`@figure` のキャプション）の中に置くとコンパイルエラー（G0259）になる。
本体の形の `@style` の中は、ほかのブロックと同じく G0245 になる。
`@page-break` の位置引数は一つまでで `recto` か `verso` とし、`@column-break` は引数を取らない。
どちらもキーワード引数と本体を持たず、誤りは G0258 になる。

属性のまとまりの中に書いてもよい。
まとまりの中の位置によらず、改ページはまとまりの対象のブロックの直前に置かれ、`@label` などの属性は改ページを飛ばして対象のブロックに付く。

```
@page-break recto
@label appendix
# 付録
```

`@label x` の後に改ページだけが続いて対象のブロックがなければ、属性の後にブロックがない誤り（G0210）になる。

HTML と EPUB では、改ページの後の最初のブロックの要素に `data-break-before` 属性（`page`、`recto`、`verso`）を付け、`style.css` に `break-before` の規則を書く。
文書の最後の改ページと改段は何も出力しない。
プレーンテキストでは何も出力しない。

#### 改ページの手での制御

改ページを止めたり、改ページの位置を少しずらしたりする印も書ける（[docs/adr/0030](adr/0030-manual-page-break-control.md)）。

```
@no-page-break
@need-lines 5
@page-lines +1
@page-lines -1
```

| 記法 | 意味 |
|---|---|
| `@no-page-break` | 前のブロックと次のブロックのあいだで、改ページも改段もしない |
| `@need-lines N` | 今の段の残りが N 行に足りなければ、次の段から続ける |
| `@page-lines +N`、`@page-lines -N` | 印の位置の段の行数を、その段に限り N 行増やす（減らす） |

空きと行数は、版面の行の格子の行数で書く。
三つの印は PDF の改ページにだけ効く。

- `@no-page-break`：前のブロックの最後の部分と、後のブロックの最初の部分（段落なら最初の 2 行、見出しなら占める格子の行）を同じ段に置く。前が段落か定義リストの用語なら、前の最後の 2 行（3 行以下の段落では全体）を次の段に送る。孤立行と泣き別れの規則は保ち、空の段からは送らない。前が見出しなら、見出しを後と離さない規則のとおりで、何も変わらない。前が図版、表、コードブロックなどなら、改ページの置き方は変えない。
- `@need-lines N`：印の後のブロックを置く直前に、今の段の残りの行（脚注の行を除く）が N に足りず、今の段が空でなければ、次の段から続ける。残りが足りていれば何もしない。印が続く場合は最も大きい N を使う。後に改ページの印が続く場合は、改ページを先に適用し、その後の段で判定する。本の最後の印は捨てる。
- `@page-lines ±N`：印の前のものをすべて置いた時点の段の行数を、その段に限り増やす（減らす）。段の先頭の印はその段に効き、前のもので段が満ちていてもその段に効く。増やした行は版面の行の格子を行の進む方向に延ばした位置に置き、脚注はその段の下部に置く。一つの段に効く印が複数あれば増減を足す。前にまだ適用していない改ページの印があれば先に適用し、その後の段に効く。白ページには効かない。

守れない指定は警告（G0737）にし、PDF はそのまま組む。

- `@no-page-break` で、前の最後の部分と後の最初の部分が同じ段に置けなかった場合。本の先頭や末尾に書いた場合、後が送られた図版の場合、前と後を合わせて段に入らない場合を含む。
- `@need-lines` の N が段の行の格子の数を超える場合。段の格子の数として扱う。
- `@page-lines` の結果の行数が、増やした行が裁ち落としを除いたページの内側に収まる数を超える場合と、その段にすでに置いた行（脚注の行を含む）の数より少ない場合。収まる数に切り詰める。

三つの印は文書の最上位にだけ置け、リストの項目、定義リストの説明、ブロックコマンドの本体の中に置くと G0271 になる。
本体の形の `@style` の中は、ほかのブロックと同じく G0245 になる。
`@no-page-break` は引数を取らない。
`@need-lines` は 1 以上の整数の位置引数を一つ取る。
`@page-lines` は、`+` か `-` の符号を付けた 0 でない整数の位置引数を一つ取る。
どれもキーワード引数と本体を持たず、誤りは G0270 になる。
属性のまとまりの中に書いてよく、規則は `@page-break` と同じである。
`@no-page-break` の直前か直後に、ほかのブロックを挟まずに `@page-break` か `@column-break` を書くと G0272 になる。
間に `@need-lines` か `@page-lines` があっても同じ位置とみなす。

HTML と EPUB では、`@no-page-break` の後の最初のブロックの要素に `data-break-before="avoid"` 属性を付け、本で使った場合に限り `style.css` に `break-before: avoid` の規則を書く。
`@need-lines` と `@page-lines` は何も出力しない。
プレーンテキストでは、三つの印はどれも何も出力しない。

### ファイルの設定

ファイルの先頭には、そのファイルにだけ効く設定とスタイルを書ける（[docs/adr/0014](adr/0014-in-file-settings.md)）。
ファイルの先頭から続く `@manifest` と `@style-def` の行の並びを、ファイルの設定と呼ぶ。

```
@manifest paragraph-separator=line
@style-def paragraph letter based-on=body indent=2zw first-line-indent=0zw
@style-def character sender font=gothic

@style letter
拝啓[style sender: 浅川]殿
```

`@manifest` は、マニフェストの `[source]` の節のキーを、そのファイルについて上書きする。

- 引数はキーワード引数だけである。キーは `[source]` のキーであり、値は語（`line`）か文字列（`"line"`）で書く。
- 書名、著者、`id`、出力ターゲットのように本の全体で一つの値は上書きできない。上書きできないキーと未知のキーはエラーになる。
- `[source]` のキーは [docs/adr/0013](adr/0013-paragraph-separator.md) が設ける。一つのファイルに効く値は、ファイルの中の上書き、章の項目、`[source]`、既定の順で最初に見つかったものである。

`@style-def` は、そのファイルにだけ効く文字スタイルと段落スタイルを定義する。

- 最初の位置引数は種類であり、`character`（文字スタイル）、`paragraph`（段落スタイル）、`regex`（正規表現スタイル）のどれかである。`regex` の書き方は下に書く。
- 二つ目の位置引数は、定義するスタイルの名前である。名前の規則は `style.toml` と同じく、英小文字で始まり、英小文字、数字、`-` だけからなる。
- その後に、キーワード引数でスタイルの欄を書く。キーは `style.toml` の `[character-styles.名前]` と `[paragraph-styles.名前]` と同じである。
- 一つのスタイルは一行で定義する。同じ名前を二つの `@style-def` に分けて書くことはできない。

値は、`style.toml` の TOML の値として次のように読む。

| 原稿の値 | TOML の値 | 例 |
|---|---|---|
| 文字列（`"..."`） | 文字列 | `font="gothic"` |
| 語 `true`、`false` | 真偽値 | `synthetic-bold=true` |
| 整数の語（`-` を前に付けてもよい） | 整数 | `space-between=1` |
| ほかの語 | 文字列 | `indent=2zw`、`first-line-indent=-1zw`、`line-breaks=keep` |

`synthetic-bold="true"` は文字列なので、型の誤りになる。
欄の型、未知のキー、値の範囲の検査は `style.toml` と同じである。
`font` は `[fonts]` にある役割だけを、`color` は `[color.swatches]` にあるスウォッチだけを指せる。

置き場所の規則は次のとおりである。

- `@manifest` と `@style-def` はファイルの最初のブロックとして置く。二つは任意の順に並べてよく、どちらも複数の行に分けて書ける。前と途中には、コメントと空行を置いてよい。
- ファイルの設定の直後には、空行を挟まずにほかのブロックを書いてよい。
- `@import` と `@set` は、ファイルの設定の後に書く。
- ほかの場所に書いた `@manifest` と `@style-def` はエラーになる。

効く範囲と同じ名前の扱いは次のとおりである。

- 上書きと定義は、そのファイルにだけ効く。`@import` したファイルにも、そのファイルを `@import` するファイルにも及ばない。
- 一つのファイルで使えるスタイルは、組み込みのスタイル、`style.toml` のスタイル、そのファイルの `@style-def` のスタイルである。ファイルの中のどの位置からも使える。
- `style.toml` と組み込みのスタイルと同じ名前を定義すると、そのファイルの中でだけ上書きになる。書いたキーだけが `style.toml` の定義の同じキーに勝ち、書かなかったキーは `style.toml` の値を保つ。たとえば `@style-def paragraph body indent=1zw` は、そのファイルの `body` の字下げだけを変える。
- 上書きは、`based-on` でその名前を引き継ぐスタイルにも及ぶ。`body` の字下げを上書きすると、字下げを自分で持たない段落スタイルの字下げも、そのファイルの中で変わる。
- 上書きした定義の `based-on` に自分の名前は書けない。`body` の上書きにも `based-on` は書けない。
- 同じファイルの中で、同じ種類の同じ名前を二度定義するとエラーになる。文字スタイルと段落スタイルは別の名前の空間であり、同じ名前を両方に定義してよい。
- 誤りのある `@style-def` は、定義の全体を捨てる。

HTML と EPUB では、ファイルの中のスタイルを持つ章の `<body>` に class `file-<n>`（`n` は章の順）を付け、そのスタイルの規則を `style.css` の最後に `body.file-<n>` の下に書く。

`@style-def regex` は、そのファイルの段落スタイルに正規表現スタイル（「段落スタイル」の節）の組を一つ足す（[docs/adr/0015](adr/0015-regex-styles.md)）。

```
@style-def regex body pattern="[0-9]+" style=latin-digits
@style-def regex letter pattern="(?<=拝)啓" style=strong
```

- 二つ目の位置引数は、組を足す段落スタイルの名前である。組み込み、`style.toml`、同じファイルの `@style-def paragraph` のどれかの名前でなければならない。
- キーワード引数は `pattern`（正規表現）と `style`（文字スタイルの名前）の二つで、どちらも必須である。値は語で書いても文字列として読む。
- 一行が一つの組である。同じ段落スタイルに何行でも書け、書いた順に、`style.toml` から見たその段落スタイルの並びの後に加わる。同じ名前を二度定義した誤りにはならない。
- 足した組は、`regex-styles` を自分で書かずにその段落スタイルを `based-on` で引き継ぐ段落スタイルにも及ぶ。
- Golem の文字列の中では、`\` の後の文字はその文字になる（`"\d"` は `d`）。正規表現の `\` は `\\` と書く（`pattern="\\d+"`）。
- 誤りのある組（未知の文字スタイル、方言の外の正規表現）は、その組だけを捨て、ほかの組は効く。
- `@style-def paragraph` のキーワード引数に `regex-styles` は書けない。

## インライン

### 二つの文脈

インラインの要素は `[` で始まり、`[` の直後の一文字で文脈が決まる。

- `[=` で始まれば**式文脈**である。中身は式の言語で書く。
- `[` の直後が識別子であれば**命令文脈**である。処理系への命令を書く。

文脈の判定は記号だけで決まり、どのコマンドが定義されているかには依存しない。
プラグインを追加しても、既存の原稿の構文解釈は変わらない。

### 式文脈

```
[= 1 + 2]
[= pi * r ** 2]
[= fib(10)]
[= values.price]
[= meta.title]
```

式文脈には、中置の演算子、リテラル、`f(x)` の形の関数呼び出し、名前空間を通した参照を書ける。
リテラルには、数、文字列、真偽値（`true` と `false`）、`nil`、配列（`[1, 2, 3]`）、連想配列（`{key: value, ...}`）がある。
`true`、`false`、`nil` は予約語である。
配列と連想配列の要素はカンマで区切る。
式文脈の中では `[` は配列の開始、`{` は連想配列の開始であり、命令文脈は書けない。

文字列リテラルは `"..."` で囲み、その中の `"` は `\"`、`\` は `\\` と書く。

数の型は、任意精度の整数と、倍精度の浮動小数点数の二つである。
ただし、整数の演算の結果は、絶対値が 2 の 4096 乗未満でなければならず、超えるとコンパイルエラー（G0286）とする（[docs/adr/0035](adr/0035-security-hardening.md)）。
演算子は `+`、`-`、`*`、`/`、`**`、`%` と比較演算子（`==`、`!=`、`<`、`<=`、`>`、`>=`）である。
比較演算子は真偽値を返す。
大小の比較は数どうしと文字列どうしに使え、文字列は Unicode のコードポイントの順で比べる。
整数と浮動小数点数を比べるときは、整数を浮動小数点数に変換する。
`/` は常に浮動小数点数を返し、整数の割り算は `div` 関数で行う。

組み込みの定数と関数は次のとおりである。

- 定数：`pi`、`e`
- 数学：`sqrt`、`floor`、`ceil`、`round(x, 桁数)`、`abs`、`min`、`max`
- 長さ：`len`（文字列と配列）
- 割り算：`div`
- 表示：`fixed`
- 文字列：`join(配列, 区切り)`。文字列の配列の要素を、区切りの文字列をはさんでつなぐ。空の配列は空の文字列になる（[docs/adr/0033](adr/0033-colophon-contributors-and-printings.md)）

三角関数、指数関数、対数関数などの超越関数は、v1 では持たない。
これらの結果は実行環境の数学ライブラリによって最後の桁が変わることがあり、決定性を保つ実装方法を v2 で決めるためである。
ユーザーが関数を定義する仕組みは持たず、それはプラグインの役割とする。

式の値のうち本文に埋め込めるのは、テキストに変換できる型（数と文字列）だけである。

### 数の規則

浮動小数点数の計算と表記は、実行する環境によらず同じ結果になるように定める。

浮動小数点数は IEEE 754 の倍精度で表し、丸めは最近接偶数丸めとする。
四則演算と `sqrt` の結果は、この規格によって一つに定まる。
十進数のリテラルは、最も近い倍精度の値に変換する。
整数と浮動小数点数の演算では、整数を浮動小数点数に変換する。

`**` の指数は整数に限り、浮動小数点数の指数はコンパイルエラーとする。
浮動小数点数の指数による累乗は、内部で超越関数を使うためである。
整数の指数による累乗は、決まった順序の掛け算で計算する。

結果が NaN か無限大になる演算（0 での割り算、負の数の平方根、オーバーフローなど）は、その位置でコンパイルエラーとする。
NaN と無限大は、式の値として存在しない。
負のゼロは正のゼロに正規化する。

`div` と `%` は整数にだけ使え、浮動小数点数に使うとコンパイルエラーとなる。
`div` は負の無限大の方向に切り捨て、`%` の結果の符号は割る数に合わせる。
このため、常に `a == div(a, b) * b + a % b` が成り立つ。
0 での割り算はコンパイルエラーとする。

`round(x, 桁数)` は、`x` を最短の十進表記に直してから、十進数として四捨五入する（端数は 0 から遠い方向に丸める）。
二進数の値をそのまま丸めると、`round(2.675, 2)` が 2.67 になるような、書き手の期待と異なる結果が生じるためである。
桁数を省いた `round(x)` と、`floor`、`ceil` は整数を返す。

`fixed(x, 桁数)` は、`round` と同じ規則で丸めた結果を、小数点以下の桁数をそろえた文字列として返す（`fixed(1.5, 2)` は「1.50」）。
`round` が返すのは数であり、末尾のゼロを保てないので、価格などの表示には `fixed` を使う。
`round` と `fixed` の桁数は 1000 までとし、超えるとコンパイルエラー（G0286）とする。

浮動小数点数を本文に埋め込むときは、次の表記を使う。

- 元の値に戻せる最短の十進数字の列を使う。
- 指数表記は使わず、常に位取りで書く（0.01 は「0.01」）。
- 整数値の浮動小数点数は小数点以下を付けない（`[= 10 / 2]` は「5」）。
- 負の符号は ASCII のハイフンマイナス `-` で書く。
- 桁区切りは付けない。
真偽値、配列、連想配列、`nil` を本文に直接埋め込むと型エラーになる。

予約された名前空間が二つある。

- `meta`：マニフェストのメタデータ。ファイル内評価（S0）の値であり、どこでも参照できる。書名などのほか、役割ごとの関係者の名前の配列 `meta.roles.<役割>`、現在の刷 `meta.printing`、刷の履歴 `meta.printings`、発行人 `meta.publisher_person` を持つ（[仕様書の「本文からの参照」](specifications.md#本文からの参照)）。
- `doc`：文書構造の値（章の数など）。文書構造（S1）の値であり、見出しの中では参照できない。

`meta` と `doc` は import の名前空間には使えない。

### 命令文脈

```
[name 位置引数... key=value...: 散文 | 散文...]
```

識別子の後に引数を並べ、`:` 以降に散文スロットを書く。
散文スロットは対応する `]` までであり、複数の散文スロットは `|` で区切る。
散文スロットの中には、ほかのインラインの要素を入れ子にできる。

引数は次の規則に従う。

- 引数は原子に限る。原子とは、リテラル、`key=value`、式文脈 `[= ...]`、入れ子の命令文脈である。命令文脈の引数には中置の演算子を書けない。
- 位置引数と `*[式]` をすべて書いてから、キーワード引数と `**[式]` を書く。順序が混ざると構文エラー（G0119）になる。二つの並びの中では、どの順に書いてもよい。
- 同じキーのキーワード引数を二度書くと、エラー（G0277）になる。
- 空白を含む値は `"..."` で囲む。その中の `"` は `\"` と書く。
- 可変長の引数は、位置引数の残りとして受け取る。
- `*[式]` は配列を位置引数に、`**[式]` は連想配列をキーワード引数に展開する。

存在しないコマンド名はコンパイルエラーになる。

### 文字スタイル

```
[style term: 決定性]
```

役割ごとのフォントより細かく書体を変えたい場合は、`style.toml` の `[character-styles.名前]` に文字スタイルを定義し、`[style 名前: ...]` で本文に適用する（[docs/adr/0005](adr/0005-character-and-paragraph-styles.md)）。
そのファイルでだけ使う文字スタイルは、ファイルの先頭の `@style-def character` でも定義できる（「ファイルの設定」の節を参照）。
`style.toml` にもそのファイルの `@style-def` にもない名前はエラーになる。

組み込みの文字スタイルは `strong`、`bold`、`italic`、`code`、`url` の五つである。
`bold` は合成の太字、`italic` は合成の斜体、`strong` は `bold` を基準にした文字スタイル、`code` は書体の役割 `code` で組む文字スタイル、`url` は参考文献の URL を組む文字スタイルである（[golem-doc ADR 0005](golem-doc/adr/0005-bibliography-fields.md)）。
`url` には別名がなく、原稿では `[style url: ...]` と書く。
利用者が組み込みと同じ名前の表を書くと、書いたキーだけが組み込みの定義を上書きする。

### 圏点

```
[kenten: 強調する語]
[kenten shape=circle: 強調する語]
```

圏点の形は `style.toml` の既定に従い、`shape` で個別に変えられる。
形は CSS の `text-emphasis-style` に合わせた次の十である（[golem-driver ADR 0019](golem-driver/adr/0019-pdf-kenten-shapes.md)）。
一覧にない形は G0239 になる。

| 形 | 字 | 名前 |
|---|---|---|
| `sesame` | ﹅（U+FE45） | ゴマ |
| `open-sesame` | ﹆（U+FE46） | 白ゴマ |
| `dot` | •（U+2022） | 小さい黒丸 |
| `open-dot` | ◦（U+25E6） | 小さい白丸 |
| `circle` | ●（U+25CF） | 黒丸 |
| `open-circle` | ○（U+25CB） | 白丸 |
| `double-circle` | ◉（U+25C9） | 蛇の目 |
| `open-double-circle` | ◎（U+25CE） | 二重丸 |
| `triangle` | ▲（U+25B2） | 黒三角 |
| `open-triangle` | △（U+25B3） | 白三角 |

`shape` を省くと、`style.toml` の `[composition]` の `kenten` の形になる（既定は `sesame`）。
約物（句読点、括弧など、Unicode の一般カテゴリ P の字）と区切り（空白など、Z の字）には、圏点の中でも圏点を付けない。
長音記号（ー）と踊り字（々）には付く。
圏点の中の欧文の語には、PDF では圏点を付けない。

PDF は、圏点の字を親文字の和文の書体で、親文字の半分の大きさで描く。
書体に圏点の字がなければ G0809 になり、PDF を書かない。
ルビの親文字の中の圏点と、圏点の中のルビは、PDF では圏点を描かず、お知らせ G0745 を出す。

### 色

```
[color accent: 色を付ける語]
```

最初の位置引数は `style.toml` で定義したスウォッチの名前である。
CMYK の値を直接書くことはできない。

### 縦中横

```
本当か[tcy: !?]
```

縦書きの中で、短い文字列を横向きのまま一字分の幅に組む。
数を縦中横にする場合は、`[number-text ...]` の `style=tcy` を使う。

### 強調

```
[strong: 強調する語]
[bold: 太字にする語]
[italic: 斜体にする語]
```

`[strong: ...]`、`[bold: ...]`、`[italic: ...]` は、組み込みの文字スタイル `strong`、`bold`、`italic` を付ける `[style 名前: ...]` の別名である（[docs/adr/0005](adr/0005-character-and-paragraph-styles.md)）。
`[strong: 語]` と `[style strong: 語]` は同じ意味になる。

`[strong: ...]` は意味の上での強調であり、太字で表すか斜体で表すかは `style.toml` の `[character-styles.strong]` で決まる。
見た目を直接指定したいときに限り、`[bold: ...]` と `[italic: ...]` を使う。
太字と斜体の書体は `[character-styles.bold]` と `[character-styles.italic]` の `font` で指定する。
指定がなければ、PDF では本文の書体から合成の太字と斜体で組む。
和文の文字も斜体を指定すれば傾く。
`font` の役割が和文のフォントを持たない場合は、和文の文字に合成の斜体をかけるので、字形がゆがむ（[golem-driver ADR 0004](golem-driver/adr/0004-pdf-emphasis-and-character-styles.md)）。

### コード

```
[code: manifest.toml]
```

`[code: ...]` は、組み込みの文字スタイル `code` を付ける `[style code: ...]` の別名であり、本文の中のファイル名、コマンド、パスに使う（[golem-driver ADR 0017](golem-driver/adr/0017-pdf-code-blocks.md)）。
中身は散文スロットなので、`]`、`|`、`[` は `\` でエスケープする。
PDF では、ハイフネーションとカーニングをかけず、行は空白と `/` の後でだけ改める。
`/` の後で改めてもハイフンは描かない。
HTML と EPUB では `<code>` の要素になる。
`style.toml` の文字スタイル `code` の `background` と `padding` で、本文の中のコードに背景の色と前後の余白を付けられる（[golem-driver ADR 0029](golem-driver/adr/0029-inline-code-background.md)）。

### ルビ

```
[ruby: 五月雨|さみだれ]
[ruby: 東/京|とう/きょう]
[ruby: お/父/さん|/とう/]
```

最初の散文スロットがルビを振る対象、二つ目のスロットが読みである。

- `/` を使わなければ、対象の全体に一つの読みを振るグループルビになる。
- `/` で対象と読みを同じ数のセグメントに区切ると、セグメントごとに読みを振るモノルビになる。セグメントの数が対象と読みで一致しない場合はコンパイルエラーとなる。対象を区切らずに読みだけを `/` で区切った場合も、数が一致しないのでコンパイルエラーとなる（[golem-eval ADR 0003](golem-eval/adr/0003-evaluation-diagnostic-codes.md)）。
- 読みのセグメントを空にすると、そのセグメントにはルビを振らない（部分ルビ）。

対象と読みを区切るのは、原稿に書いた `/` だけである（[golem-parser ADR 0010](golem-parser/adr/0010-ruby-slash-escape-and-table-cell-breaks.md)）。

```
[ruby: a\/b|えー]
[ruby: 漢字|かん\/じ]
```

- `\/` は区切りにならず、`/` という文字そのものになる。一つ目の例は、親文字「a/b」の全体に「えー」を振るグループルビである。
- 読みに `\/` を書くと、読みの文字の `/` になる。二つ目の例は、親文字「漢字」に読み「かん/じ」を振るグループルビである。
- 式の値の中の `/` も区切りにならない。`[ruby: [= "a/b"]|えー]` は、親文字「a/b」のグループルビである。
- 入れ子のコマンドの中の `/` も区切りにならない。`[ruby: [bold: 漢/字]|かんじ]` は一つのセグメントである。

ルビを振る対象には、圏点、色、式文脈など、ほかのインラインの要素を入れ子にできる。
ただし、ルビの中にルビを入れることはできない。
親文字の中の文字スタイルと色は親文字の字にだけ効き、読みには効かない（[golem-layout ADR 0011](golem-layout/adr/0011-ruby-base-character-styles.md)）。

### 数の表記

```
[number-text 10]
```

`[number-text ...]` は、表記を決めていない数を表す。
縦書きでは「十」「一〇」「縦中横の 10」のいずれか、横書きでは算用数字の「10」として出力される。
表記を決めるのは出力の形式ではなく、その文章が置かれる書字方向である。
縦書きでどの表記を使うかは、`style` 引数か `style.toml` の既定で決まる。

- `style=kanji`：位取りをする漢数字（十、百二十）
- `style=kanji-digits`：数字を一字ずつ漢数字にする（一〇、一二〇）
- `style=tcy`：算用数字の縦中横

横書きでは常に算用数字になるので、`style` 引数は縦書きでだけ意味を持つ。
`[number-text ...]` に渡せるのは整数だけであり、浮動小数点数を渡すとコンパイルエラーとなる。
`[number-text ...]` は散文スロットを取らず、`: ` の後に本文を書くとコンパイルエラーとなる（[golem-eval ADR 0003](golem-eval/adr/0003-evaluation-diagnostic-codes.md)）。

### アキ

```
第一章[aki 全角]吾輩は猫である
3[aki 四分]kg
```

`[aki 量]` は、その位置に固定の幅の空きを置く（[docs/adr/0019](adr/0019-aki-settings.md)）。
量は、アキの量の名前（`ベタ`、`全角`、`二分`、`三分`、`四分`、`五分`、`六分`、`八分`、`二分四分`）、`0.2zw` のような `zw` の小数、`25%` のような百分率、`1mm` や `2pt` のような絶対の寸法のどれかで書く。
`zw` は、その位置の文字の大きさを一字とする。
`[aki]` は散文スロットを取らない。
位置引数が一つでない場合、量を読めない場合、散文スロットがある場合はコンパイルエラーとなる。

`[aki]` の前後では改行しない。
`[aki]` を挟んだ二つの文字の間には、`style.toml` のアキ量のセットの空きを置かない。
改行してよい空きは、全角の空白で書く。

HTML と EPUB では、論理方向の余白を持つ空の `span`（`class="aki"`）で表し、前後に改行を避ける U+2060（WORD JOINER）を置く。
`zw` は `em`、絶対の寸法は `pt` で書く。
プレーンテキストでは、`zw` で書いた量の整数部の数だけ全角の空白を出し、1 に満たない量と絶対の寸法は何も出さない。

### 相互参照

```
[ref-number design]
[ref-title design]
```

`@label` で付けたラベルを指して、章などの番号と題を参照する。
ラベルは文書全体で一つの名前空間を持つので、ほかのファイルのラベルも参照できる。
存在しないラベルを参照するとコンパイルエラーとなる。
番号を持たない要素（`@nonumber` の見出しや段落など）を `[ref-number ...]` で参照した場合と、題を持たない要素（段落や表など）を `[ref-title ...]` で参照した場合も、コンパイルエラーとなる（[golem-doc ADR 0003](golem-doc/adr/0003-document-diagnostic-codes.md)）。
相互参照のコマンドは散文スロットを取らず、`: ` の後に本文を書くとコンパイルエラーとなる（[golem-eval ADR 0003](golem-eval/adr/0003-evaluation-diagnostic-codes.md)）。

### 脚注

```
本文[note: 注の本文。]。
```

注の本文はインラインの要素に限る。
番号は `style.toml` の `[notes]` の `numbering` の範囲（既定はマニフェストの章）ごとに 1 から振られる（[golem-driver ADR 0018](golem-driver/adr/0018-footnote-marks-and-numbers.md)）。
注を出力する位置（ページ下か章末か）は `style.toml` のスタイルで決まる。

### 傍注

```
本文[sidenote: 傍注の本文。]。
```

注の本文はインラインの要素に限る。
番号は脚注と別に、脚注と同じ範囲ごとに振られる。
PDF では版面の外の傍注欄に置かれ、ほかの媒体では段落の直後などに置かれる。
v1 では横組みでだけ使え、縦組みで使うとコンパイルエラーになる。
PDF では、`style.toml` に `[sidenotes]` がない場合と、脚注の本文や図版のキャプションの中に置いた場合もコンパイルエラーになる（[golem-driver ADR 0006](golem-driver/adr/0006-pdf-sidenotes.md)）。

### 索引

```
[index reading=くみはん: 組版]
[index reading=くみはん/わぶんくみはん: 組版/和文組版]
```

索引の印は、出現した位置には何も出力しない。
`reading` に読みを指定し、読みのない索引項目はコンパイルエラーとなる。
`/` で区切ると、主項目と副項目の二段の階層になる。
語の中の `\/` は段の区切りにならず、`/` という文字になる（[golem-parser ADR 0010](golem-parser/adr/0010-ruby-slash-escape-and-table-cell-breaks.md)）。
`[index reading=えー: a\/b]` は、語「a/b」の一段の項目である。
語を区切るのは原稿に書いた `/` だけであり、式の値の中の `/` は区切りにならない。
`reading` は引数なので、`\/` で `/` を書くことはできない。

### 引用

```
[cite knuth1981]
```

マニフェストで宣言した書誌データ（CSL-JSON）のキーで文献を引用する。
引用した文献は `@bibliography` の一覧に載る。
`[cite ...]` は散文スロットを取らず、`: ` の後に本文を書くとコンパイルエラーとなる（[golem-eval ADR 0003](golem-eval/adr/0003-evaluation-diagnostic-codes.md)）。

- `[!`：マクロのための記法。

## 扱わない記法

数式が必要な場合は、画像にして図版として入れる。
