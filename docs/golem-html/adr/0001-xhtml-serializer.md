# ADR 0001: XHTML と CSS の出力

ステータス: 採択

## 文脈

HTML と EPUB は並列のバックエンドではなく親子であり、EPUB は HTML の出力の上にパッケージングを加えた薄い層とする（specifications.md）。
EPUB の本文は XHTML でなければならないので、HTML の出力も XHTML として書き、EPUB と同じ本文をそのまま使えるようにする。
Web の出力では、行分割とシェイピングは閲覧者の側のエンジンが行い、Golem は意味と見た目の指定だけを出力する。

## 実装すること

### 入力と出力

```haskell
renderXhtml :: Style -> Doc.Book -> XhtmlSite

data XhtmlSite = XhtmlSite
  { sitePages  :: [(FilePath, ByteString)]   -- マニフェストのソースファイルごとに一つ
  , siteCss    :: ByteString
  , siteAssets :: [(FilePath, FilePath)]     -- 出力先、元のファイル（画像、フォント）
  }
```

- ソースファイルごとに一つの XHTML の文書を出力する。HTML のターゲットは、これに目次のページを加えて出力する。
- 文書は、XML として整形式であり、HTML として読んでも同じ意味になる形（polyglot）で書く。

### 要素の対応

| 意味論 IR | XHTML |
|---|---|
| 見出し | `h1` から `h3`。番号は style.toml の書式で作り、`span` に入れて題の前に置く |
| 段落 | `p` |
| リスト | `ul`、`ol` |
| 定義リスト | `dl`、`dt`、`dd` |
| 表 | `table`、`thead`、`tbody`。列の揃えはクラスで表す |
| コードブロック | `pre` と `code`。構文の色分けは skylighting のクラスで表す |
| 図版 | `figure`、`img`、`figcaption`。PDF の画像には `web` の代替画像を使う |
| 意味の強調、太字、斜体 | `strong`、`b`、`i` |
| ルビ | `ruby`、`rt`、`rp`。モノルビはセグメントごとに `rt` を置く |
| 圏点 | `span` と CSS の `text-emphasis` |
| 縦中横 | `span` と CSS の `text-combine-upright` |
| 色、文字スタイル | クラスを持つ `span` |
| 注の印 | 注へのリンク。注の本文はそのファイルの末尾にまとめ、本文へ戻るリンクを付ける |
| 傍注 | 段落の直後の `aside`。画面の幅が十分にあれば、CSS で本文の余白に配置する。本文側には番号の印を付ける |
| 章の番号と題への参照 | 参照先へのリンク |
| ページ番号への参照 | 参照先へのリンク。リンクの文字は参照先の見出しの題とする |
| ラベル | 参照される要素の `id`。値はラベルの名前とする |

### CSS

- style.toml から一つの CSS を生成する。使うのは、フォント、強調の表現、色、見出しの番号の書式、書字方向である。版面とマスターページは使わない。
- 縦書きは `writing-mode: vertical-rl` で表す。
- フォントは `@font-face` で指定し、style.toml のフォントのファイルを出力に複写する。
- 色は、スウォッチの CMYK を sRGB に近似して書く。v1 の近似は `R = 255 × (1 − C) × (1 − K)`（G と B も同様）とし、結果は整数に丸める。

### 決定性

- 属性の順序、空白、改行、文字のエスケープの規則を固定する。
- 生成の時刻や乱数による値（`id` など）を出力しない。`id` はラベルの名前か、文書の中の位置から決まる値とする。

## 実装しないこと

- EPUB のパッケージング。golem-epub の ADR で扱う。
- 生の CSS を書く仕組み。
- フォントのサブセット化と難読化。
- ICC プロファイルによる色の変換。

## テスト設計

- docs/markup.md の例を含む原稿の出力を golden テストで固定する。
- 出力が XML として整形式であることを、すべての golden テストで検査する。
- ルビ、圏点、縦中横、注、相互参照の出力を確かめる。
- 同じ入力から二回出力し、バイト列が一致することを確かめる。

## トレードオフ

CMYK から sRGB への近似を単純な式にすると、印刷の色と画面の色の差は ICC プロファイルによる変換より大きくなる。
画面の色は近似でよいと決めており、色の管理のライブラリへの依存を増やすより単純さを選ぶ。
差が問題になった場合は、ICC プロファイルによる変換を ADR で検討する。

フォントをサブセット化せずに複写するので、和文フォントを使うと出力が大きくなる。
サブセット化は PDF の経路で実装するので、その実装ができた段階で Web の経路にも使うことを検討する。
