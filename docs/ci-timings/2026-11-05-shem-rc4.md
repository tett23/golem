# 見た目の回帰テストの所要時間（2026-11-05、shem v0.1.0-rc4 に上げた前後）

shem を v0.1.0-rc3 から v0.1.0-rc4 に上げたプルリクエスト（[#552](https://github.com/tett23/golem/pull/552)、[ADR 0100](../adr/0100-raise-shem-to-v0-1-0-rc3-and-pre-release-bumps.md)）の、見た目の回帰テストの所要時間の記録である。
rc4 のリリースノートは、同じ入力に対して rc3 と同じ画素と、同じ PNG と PPM のバイトを出し、一つのスレッドでも複数のスレッドでも速くなったと書いている。
`check.sh` が shem を呼ぶ形（PDF を一つずつ、`--jobs` を渡さない）は変えていない。
単位は秒である。
2026-11-05 に作り、コミットした後は変更しない。

## CI

CI の秒数は、`gh run view <id> --json jobs` の `startedAt` と `completedAt` の差である（`scripts/ci/timings.sh` と同じ）。
「PDF の後」は、`build (ubuntu-24.04, outputs)` の `Upload the PDFs of the visual regression test` が終わってから `visual` が終わるまでの秒数である。
`visual` は PDF が上がるのを待つ（[ADR 0099](../adr/0099-visual-job-waits-only-for-visual-pdfs.md)）ので、shem の速さが実行の終わりに効くのはこの部分だけである。

## 手元

10 コアの Apple silicon の macOS（`getconf _NPROCESSORS_ONLN` が 10）で、#552 のコミットの PDF（17 の PDF、1,813 ページ）を使った。
shem は aarch64-apple-darwin の配布物である。
`check.sh` を 3 回ずつ動かした実時間（`/usr/bin/time -p`）は次のとおりである。

| shem | 1 回め | 2 回め | 3 回め |
|---|---|---|---|
| v0.1.0-rc3 | 3.71 | 3.67 | 3.66 |
| v0.1.0-rc4 | 2.40 | 2.32 | 2.40 |

同じマシンで、`scripts/visual/build.sh` は 20.03 秒、17.85 秒、17.03 秒だった。
`build.sh` は shem を使わないので、版上げで変わらない。

## 読み取れること

- CI の比べる手順は、rc3 の 6〜10 秒から rc4 の 4 秒に縮んだ。手元では 3.7 秒から 2.4 秒に縮んだ。
- `visual` のジョブ全体は、PDF を待つ手順（77 秒と 87 秒）がほとんどを占めるので、比べる手順の 4〜6 秒の短縮は全体の揺れに埋もれる。
- 実行の終わりに効くのは PDF の後の部分で、rc4 の 2 回（15 秒、14 秒）は rc3 の中央値（18 秒）より短いが、rc3 の範囲（11〜33 秒）の中にある。2 回では差を言い切れない。
- `outputs` の PDF を組む手順（41、42 秒）は shem と関係がない。
