# CI のジョブ wasm の所要時間（2026-11-08、[ADR 0199](../adr/0199-pdf-typesetting-as-wasm-reactor.md) の 7）

[ADR 0199](../adr/0199-pdf-typesetting-as-wasm-reactor.md) の 7 で `ci.yml` に足したジョブ `wasm` の所要時間の記録である。
CONTRIBUTING は、CI の時間を 5 分以内に保ち、最適化の前後の時間を `docs/ci-timings/` に記録するとしている。
2026-11-08 に作り、コミットした後は変更しない。

## 条件

プルリクエスト [#645](https://github.com/tett23/golem/pull/645) の二つの実行で、GitHub Actions の `ubuntu-24.04`（x86-64）のランナーで測った。
数字は `gh run view <id> --json jobs` の各ステップの始まりと終わり、またはジョブの中で `date +%s` で測った秒である。

- キャッシュなし：[42403425512](https://github.com/tett23/golem/actions/runs/42403425512)。ネイティブの `alex` と `happy`、ツールチェーンと wasm の cabal の store、`dist-wasm` のどれもキャッシュになかった。
- キャッシュあり：[42404927087](https://github.com/tett23/golem/actions/runs/42404927087)。三つのキャッシュがすべて当たり、Haskell のソースは前の実行から変わっていない。

## 結果

| ステップ | キャッシュなし | キャッシュあり |
|---|---|---|
| ネイティブの GHC の用意（`haskell-actions/setup`） | 143 | 0（使わない） |
| ネイティブの `alex` と `happy` | 17 | 1（キャッシュから戻す） |
| ツールチェーンの取得と展開（`fetch-ghc-wasm.sh`） | 102 | 30（キャッシュから戻す） |
| `wasm32-wasi-cabal update` | 19 | 0（キャッシュにある） |
| `golem.wasm` のビルド | 591 | 1 |
| キャッシュの保存（ツールチェーンと store、`dist-wasm`） | 18 | 0 |
| `run.mjs check`（kanikosen を三度組む） | 45 | 31 |
| `compare.sh` の七つの入力 | 26 | 19 |
| ジョブ全体 | 973 | 101 |

キャッシュなしの実行は、PDF と diagnostics の比べで失敗した（Node の警告が JSON に混ざった、`compare.sh` を直した）が、ビルドとキャッシュの保存までの時間は上のとおりである。
`golem.wasm` は 46,585,763 バイトである（cabal の設定で `executable-stripping: False`）。

golem-driver の `Golem.Driver.Explain.Embedded`（[ADR 0203](../adr/0203-generated-modules-instead-of-template-haskell-in-golem-driver.md) で生成したモジュール）は、wasm の GHC で約 11 秒、golem-driver のライブラリの全体で約 19 秒だった。
キャッシュなしのビルドの 591 秒のうち、ほとんどは Hackage のパッケージと golem のほかのパッケージである。
Haskell のソースを変えたプルリクエストでは、`dist-wasm` から変わったパッケージだけを組み直すので、ジョブの時間はこの二つのあいだになる。
