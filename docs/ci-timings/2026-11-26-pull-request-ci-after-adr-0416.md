# プルリクエストの CI の時間（2026-11-26、golem-driver のテストを分けた後の成功した `ci.yml` の 20 回）

[root ADR 0416](../adr/0416-shorten-the-build-of-the-pull-request-ci.md) の A1 が求める記録である。
0416 の実装（PR #1094、2026-11-23T04:03:07Z のマージ、[68095facc](https://github.com/tett23/golem/commit/68095facc6ac8ecad6d14cbf55b982fb793b3cb6)）より後の、成功したプルリクエストの `ci.yml` の時間を、[ADR 0392](../adr/0392-budget-the-pull-request-ci-at-five-minutes.md) の予算の 300 秒と比べた。
2026-11-26 に作り、コミットした後は変更しない。

## 条件

- 値は、`origin/main`（[3fc097e4c](https://github.com/tett23/golem/commit/3fc097e4c12e3050a3dc119d5169913c38061e24)）の作業ツリーで、2026-11-26 に `sh scripts/ci/ci-critical-path.sh` を一度走らせた出力である。
  このスクリプトは、`gh run list --workflow ci.yml --event pull_request --status success` の新しい順に、`build` を省かなかった実行を 20 回取る。
- 実行の時間は、ジョブの `needs` をたどった最も長い道の秒で、ランナーを待つ時間を含まない（`scripts/ci/ci-critical-path.sh` の冒頭の注記を参照）。
  `needs` は、測った時点の `.github/workflows/ci.yml` から読んだ。
- 作成の時刻、コミット、ブランチ、試行は、`gh api repos/tett23/golem/actions/runs/<id>` の `created_at`、`head_sha`、`head_branch`、`run_attempt` である。
  作成の時刻は、20 回すべてが PR #1094 のマージより後である。
- 20 回のうち 3 回は 2 回目の試行（`run_attempt` が 2）である。
  スクリプトが読むジョブの一覧の API は最後の試行のジョブを返すので、この 3 回の秒は 2 回目の試行のジョブから数えた。

## 読み方

中央値の 330 秒は、[ADR 0395](../adr/0395-bring-the-pull-request-ci-under-five-minutes.md) の後の記録（[2026-11-23-pull-request-ci-after-adr-0395.md](2026-11-23-pull-request-ci-after-adr-0395.md)）の 398.5 秒より 68.5 秒短い。
それでも、予算の 300 秒を 30 秒超える。
[root ADR 0416](../adr/0416-shorten-the-build-of-the-pull-request-ci.md) の A1 は予算を満たすことを求めないので、この記録で A1 を満たす。
予算を満たさないので、0416 の「測る」の手順により、臨界経路の脚を測り直し、次の手を新しい ADR で決める。

20 回のうち 300 秒以下は 3 回（276、285、289 秒）である。
500 秒を超えた 3 回（534、548、559 秒）の理由（ジョブのどこで時間がかかったか）は、この記録では調べていない（未確認）。
