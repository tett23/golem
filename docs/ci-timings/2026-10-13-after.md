# CI の所要時間（[ADR 0009](../adr/0009-ci-speed.md) の実装の後）

[ADR 0009](../adr/0009-ci-speed.md) の実装の後の、`.github/workflows/ci.yml` の所要時間の記録である。
実装の前の記録は [2026-10-13-before.md](2026-10-13-before.md) にある。
2026-10-13 に作り、コミットした後は変更しない。

## 対象の実行

キャッシュがすべて当たった最初の実行を使った。

| 実行の ID | 開始（UTC） | イベント | ブランチ | 結果 |
|---|---|---|---|---|
| 38334629827 | 2026-10-13T01:58:00Z | push | main | success |

この実行は、#26 のマージのコミット（`a589ab6`）の push である。
変えたのは `scripts/ci/` と `docs/` だけで、Haskell のコードは変えていない。
そのため `cabal build all` は、`dist-newstyle` のキャッシュからほとんど何もビルドせずに終わっている。
Haskell のコードを変える場合は、変えたパッケージとそれに依存するパッケージのビルドの時間が加わる。

キャッシュの鍵を変えた直後の実行は、キャッシュが一つも当たらない。
その例が #26 の実行（38332848933）で、build のジョブ全体は x86-64 で 21 分 32 秒、aarch64 で 17 分 21 秒だった。
キャッシュはブランチごとに分かれ、プルリクエストは `main` のキャッシュしか読めないので、`main` への最初の push が終わるまでは、どのプルリクエストもこの状態になる。

## 再現の手順

```sh
gh run view 38334629827 -R tett23/golem --json jobs -q . | sh scripts/ci/timings.sh
```

所要時間は、ジョブとステップの `startedAt` から `completedAt` までの秒数である。
skipped のステップは `-` と書く。
