# `verapdf` を臨界経路から外した後の CI の所要時間（2026-11-09、プルリクエストの 18 回の実行）

[ADR 0244](../adr/0244-take-verapdf-off-the-critical-path-of-ci.md) の 3 が求める記録である。
`verapdf` が `conformance-pdfs` を待つようにした変更（PR #752、マージのコミット e313e3b0、2026-11-08T23:23:10Z）の後の、プルリクエストの `ci.yml` の実行を数えた。
2026-11-09 に作り、コミットした後は変更しない。

## 条件

- 対象は、マージの後の 2026-11-08T23:27Z から 2026-11-09T04:30Z までに作られた `pull_request` の実行 41 回（成功 23、失敗 14、取り消し 4）のうち、結論が成功で、`build (ubuntu-24.04, tests-driver)` が省かれなかった 18 回である。文書だけの変更で `build` を省いた 5 回は、[2026-11-09 の記録](2026-11-09-ci-critical-path-and-download-failures.md)と同じく除いた。
- 各実行のジョブは `gh api repos/tett23/golem/actions/runs/<id>/jobs?per_page=100` で取った。
- 実行全体の秒は、その実行で最初に作られたジョブの `created_at` から、最後に終わったジョブの `completed_at` までである（前の記録と同じ方法）。
- 「最後に終わるジョブ」は、`ci` と `determinism`（どちらも `build` の全体を待って数秒で終わる）と、省かれたジョブを除いた中で、`completed_at` が最も遅いジョブである。
- 「`verapdf` の余裕」は、`verapdf` の `completed_at` から、最後に終わった `build` のランナーの `completed_at` を引いた秒である。負なら、`verapdf` は `build` より先に終わっている。
- 集計は手元の jq で行い、コミットしていない。

## 読み方

- `verapdf` は 18 回すべてで、最後に終わる `build` のランナーより 18 秒から 122 秒早く終わり、臨界経路にない。[ADR 0244](../adr/0244-take-verapdf-off-the-critical-path-of-ci.md) が確かめるとした「最後に終わるジョブが `build` のランナーになること」は、17 回で成り立つ。残る 1 回（42543382841）の `wasm` は、[ADR 0243](../adr/0243-retry-every-download-and-cache-the-archives-checked-by-sha-256.md) の実装で `fetch-ghc-wasm.sh` が変わり、wasm のキャッシュが外れた直後の実行である。
- 全体の秒の中央値は 358.5 秒で、[ADR 0244](../adr/0244-take-verapdf-off-the-critical-path-of-ci.md) が前の記録から見積もった 234 秒前後にはならなかった。前の記録の 118 回の中央値 298 秒（`verapdf` が臨界経路にあったとき）より長い。この 18 回は、rc4 の ADR の実装のプルリクエストが 5 時間に集中した期間のもので、`cabal build` が長い実行（660 秒、536 秒など）と、wasm のキャッシュが外れた実行（757 秒）を含む。前の記録の 40 時間の標本とは条件が違うので、見積もりとの差が `verapdf` の待ち方によるものではないことは、`verapdf` の余裕が全て負であることからわかる。
- 中央値が 300 秒を超えることについては、[ADR 0244](../adr/0244-take-verapdf-off-the-critical-path-of-ci.md) の「メンテナーが決めること」の 3 のとおり、変更のないパッケージのテストを省くことなどを別の ADR で扱う。
