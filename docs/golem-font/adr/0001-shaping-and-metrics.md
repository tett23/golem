# ADR 0001: シェイピングとメトリクス

ステータス: 採択

## 文脈

PDF の経路では、文字列をフォントのグリフの並びと位置に変換するシェイピングと、グリフの寸法の取得を Golem が行う。
シェイピングは HarfBuzz に、グリフの寸法と形状は FreeType に任せ、Haskell から FFI で呼ぶと決めている。
Web の経路では、シェイピングは閲覧者の側のエンジンが行うので、golem-font は PDF の経路だけが使う。

HarfBuzz と FreeType の版が変わると、グリフの配置が変わり、同じ入力から同じ出力が得られなくなる。
そのため、二つのライブラリは版を固定して Golem に同梱する。

## 実装すること

### 同梱とビルド

- HarfBuzz 14.6.0 と FreeType 2.14.3 のソースを golem-font のパッケージに同梱し、cabal の `c-sources` で静的にリンクする。システムにインストールされたライブラリは使わない。
- C のソースは、浮動小数点数の積和演算の融合を禁じる設定（`-ffp-contract=off`）でコンパイルする。アーキテクチャによって計算の結果が変わるのを防ぐためである。
- 版は README の表に記載し、版を上げるときは ADR を作成する。

### フォントの読み込み

- フォントは、`style.toml` が指すプロジェクトの中のファイルのバイト列から読み込む。ファイルのパスで FreeType に開かせない。
- OpenType（TrueType と CFF の輪郭）を扱う。可変フォントは v1 では既定のインスタンスだけを使う。
- フォントの OS/2 テーブルの `fsType` が埋め込みを禁じている場合（制限付きのライセンス）は、エラーとする。

### シェイピング

```haskell
shape
  :: Font
  -> ShapeRequest     -- テキスト、文字体系、言語、方向（横、縦）、OpenType の機能
  -> [ShapedGlyph]

data ShapedGlyph = ShapedGlyph
  { sgGlyphId :: !GlyphId
  , sgCluster :: !Int      -- 元のテキストの中の位置（ToUnicode の生成に使う）
  , sgAdvance :: !Sp
  , sgOffset  :: !(Sp, Sp)
  }
```

- HarfBuzz の拡大率は、フォントの em の単位（unitsPerEm）と等しくし、位置をフォントの単位の整数で受け取る。それを文字の大きさに応じて sp に変換する。変換は有理数で計算し、一度だけ最近接偶数丸めで整数にする。
- 縦組みでは、方向を縦にして、`vert` の機能を有効にする。

### メトリクス

グリフの外接矩形、フォントのアセンダーとディセンダー、縦組みのための縦の送りを、FreeType とフォントのテーブルから取得し、sp に変換して返す。

### FFI の閉じ込め

FFI は golem-font の中に閉じ込め、ほかのモジュールは Haskell の API だけを使う。
FFI の呼び出しは、純粋な関数として見えるように包み、例外を外に漏らさない。

## 実装しないこと

- サブセット化と PDF への埋め込み。[ADR 0002](0002-subsetting-and-embedding.md) で扱う。
- 可変フォントの軸の指定。
- 複雑な文字体系（アラビア文字、インド系の文字など）の検証。HarfBuzz は扱えるが、v1 の対象は和文と欧文に限る。
- Web の経路でのシェイピング。

## テスト設計

- 和文と欧文の代表的な文字列（合字、カーニング、縦書き用の字形を含む）のシェイピングの結果を golden テストで固定する。
- 同じ入力のシェイピングの結果が、x86-64 と aarch64 で一致することを確かめる。
- `fsType` が埋め込みを禁じるテスト用のフォントで、エラーになることを確かめる。
- 文字の大きさを変えたときの sp への変換が、丸めを一度しか行わないことを確かめる。
- テスト用のフォントは、ライセンスが再配布を許すものだけをリポジトリに置く。

## トレードオフ

C のライブラリを同梱して静的にリンクすると、Golem のビルドは重くなり、ライブラリの更新も ADR を経た手作業になる。
その代わり、利用者の環境のライブラリの版に出力が左右されなくなる。
