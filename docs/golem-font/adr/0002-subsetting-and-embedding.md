# ADR 0002: フォントのサブセット化と PDF への埋め込み

ステータス: 採択

## 文脈

PDF/X-4 は、使うすべてのフォントの埋め込みを要求する。
和文のフォントは数万のグリフを持ち、そのまま埋め込むと PDF が非常に大きくなるので、使ったグリフだけを抜き出すサブセット化を行う。
また、PDF から本文を正しく抽出し、検索できるように、グリフと文字の対応表（ToUnicode）を付ける。

サブセット化には、HarfBuzz の一部である hb-subset を使う。
Haskell からこれを使うバインディングは存在しないので、自前で FFI を書く。

## 実装すること

### サブセット化

- 文書の全体で使ったグリフの集合を、フォントごとに集める。
- hb-subset で、その集合だけを含むフォントを作る。グリフ番号は振り直さずに保つ（`retain-gids` の設定）。シェイピングの結果のグリフ番号を、PDF の内容でそのまま使うためである。
- サブセットのフォントのバイト列が、同じグリフの集合からは常に同じになることを、テストで保証する。

### PDF への埋め込み

- フォントは、CID を使う形式（Type 0 のフォントと CIDFont）で埋め込む。輪郭が CFF のフォントは `CIDFontType0` と `FontFile3`、TrueType のフォントは `CIDFontType2` と `FontFile2` とする。
- 文字のコードはグリフ番号そのもの（`Identity-H`、縦組みでは `Identity-V`）とする。
- サブセットのフォントの名前に付ける 6 文字の接頭辞（`ABCDEF+`）は、グリフの集合のハッシュから決める。乱数で決めると、同じ入力から同じ出力が得られなくなるためである。
- 縦組みのグリフの縦の送りを、CIDFont の `W2` と `DW2` に書く。

### ToUnicode

- シェイピングの結果のクラスタの情報から、グリフ番号と元の文字列の対応を作る。
- 合字のように一つのグリフが複数の文字に対応する場合は、その文字列全体に対応させる。
- 同じグリフが異なる文字に対応する場合は、文書の中で最初に現れた対応を使う。対応を一つに決めて、結果を決定的にするためである。

## 実装しないこと

- フォントの難読化と、Web の経路のためのサブセット化。
- Type 3 のフォントによる埋め込み。
- 埋め込みを禁じるライセンスのフォントの扱い（ADR 0001 でエラーにする）。

## テスト設計

- 同じグリフの集合から作ったサブセットのバイト列が、何度作っても一致することを確かめる。
- サブセットのフォントに、使ったグリフが含まれ、使わないグリフが含まれないことを確かめる。
- 埋め込んだ PDF から抽出したテキストが、元の文字列と一致することを確かめる（合字と縦組みを含む）。
- サブセットの名前の接頭辞が、グリフの集合のハッシュから決まり、毎回同じになることを確かめる。

## トレードオフ

グリフ番号を振り直さずにサブセット化すると、使わないグリフの番号の分だけ、フォントのテーブルに空の項目が残り、サブセットのフォントは少し大きくなる。
その代わり、シェイピングの結果と PDF の内容の間でグリフ番号を変換する必要がなく、変換の誤りが生じる余地がなくなる。
