# 診断のコード

この文書は、Golem が出す診断のコード（`G0101` など）を一つずつ説明する。
診断は、コードと一行のメッセージだけを出す。
コードが何を表し、どう直せばよいかを、ここで引けるようにする。
将来の `golem explain` は、この文書の各節をそのまま表示する前提で書いている（[仕様書の今後の実装項目](specifications.md)）。

各コードの節は、`## G0101` の見出しと、次の項目からなる。

- **重大度**：エラーか警告か。エラーが一つでもあれば、ビルドは失敗し、終了コードは 1 になる。
- **段階とモジュール**：コードを出す処理の段階と、それを実装するモジュール。
- **メッセージ**：表示する文言。引数を埋める部分は `<名前>` のように書く。
- **意味**：いつ出るか。
- **原因と直し方**：よくある原因と、直し方。
- **ADR**：そのコードを定めた ADR。番号を書いた ADR が見つからないコードは「ADR なし」とし、番号に触れているだけの ADR があれば併記する。

ソースで使っているコードがこの文書にすべて載っていることは、golem-cli のテスト（`modules/golem-cli/test/Main.hs`）が確かめる。

## 番号の区分

コードは `G` と 4 桁の数字からなる。
上 2 桁が、診断を出す段階を表す（[golem-syntax ADR 0001](golem-syntax/adr/0001-source-spans-and-diagnostics.md)）。
一度使った番号は、ほかの意味に使い回さない。

| 上 2 桁 | 段階 | 主なモジュール |
| --- | --- | --- |
| 01 | 構文（読み込みと解析） | golem-parser |
| 02 | 評価 | golem-eval（プラグインのコマンドは golem-driver） |
| 03 | プロジェクト（`manifest.toml`、`style.toml`、import） | golem-project、golem-driver、golem-eval |
| 04 | 文書の組み立て（ラベル、相互参照、目次） | golem-doc |
| 05 | lint | golem-lint |
| 06 | プラグイン | golem-plugin、golem-driver |
| 07 | レイアウト（版面、改ページ、傍注、表） | golem-layout-spec、golem-layout、golem-driver |
| 08 | 出力（フォント、出力インテント） | golem-driver |

重大度がプロファイルで変わるコードは `Golem.Syntax.Diagnostic.profileDependentCodes` にまとめてあり、dev では警告、prod ではエラーになる。
今は [G0310](#g0310) と [G0504](#g0504) の二つである。
[G0205](#g0205) は、prod でだけ出る警告である。

## 使っていない番号

次の番号は、ソースで使っていない。

- **廃止**：G0244。[docs/adr/0003](adr/0003-verse-line-breaks.md) が `@verse` の引数の誤りに定めたが、[docs/adr/0005](adr/0005-character-and-paragraph-styles.md) で使わなくなった。
- **廃止**：G0248。[docs/adr/0005](adr/0005-character-and-paragraph-styles.md) が廃止した `@verse` に定めたが、[golem-fmt ADR 0002](golem-fmt/adr/0002-remove-verse-migration.md) で使わなくなった。
- **定めたが未実装**：G0249 から G0254。[docs/adr/0014](adr/0014-in-file-settings.md) がファイルの中の設定（`@manifest` と `@style-def`）に定めた。この ADR を実装するまで、これらの診断は出ない。
- **空き**：G0104 から G0109、G0124 から G0128、G0601、G0703 から G0720、G0726 から G0731、G0736 から G0740。各区分の最後に使った番号より後も空いている。

廃止と未実装の番号にも、下に節を置く。

## G0101

- **重大度**：エラー
- **段階とモジュール**：構文（golem-parser の `Golem.Parser.Read`）
- **メッセージ**：`UTF-8 として不正なバイト列があります`
- **意味**：原稿のファイルに、UTF-8 として読めないバイト列がある。位置は最初の不正なバイトである。
- **原因と直し方**：Shift_JIS など、ほかの文字コードで保存したファイルで起きる。UTF-8 で保存し直す。
- **ADR**：ADR なし（[golem-syntax ADR 0001](golem-syntax/adr/0001-source-spans-and-diagnostics.md) がコードの例として挙げる）

## G0102

- **重大度**：エラー
- **段階とモジュール**：構文（golem-parser の `Golem.Parser.Read`）
- **メッセージ**：`ファイルの先頭に BOM があります。BOM を取り除いてください`
- **意味**：原稿のファイルが UTF-8 の BOM で始まる。
- **原因と直し方**：エディタが BOM 付きで保存している。BOM なしの UTF-8 で保存し直すか、`golem fmt` で取り除く。
- **ADR**：ADR なし

## G0103

- **重大度**：エラー
- **段階とモジュール**：構文（golem-parser の `Golem.Parser.Read`）
- **メッセージ**：`改行に CR が含まれています。改行は LF に限ります`
- **意味**：改行に CR（CRLF の改行を含む）がある。位置は最初の CR である。
- **原因と直し方**：Windows の改行で保存したファイルで起きる。`golem fmt` で LF に直す。
- **ADR**：ADR なし

## G0110

- **重大度**：エラー
- **段階とモジュール**：構文（golem-parser）

- **意味**：ブロックの文法のどれにも当てはまらない行がある。
- **原因と直し方**：ブロックの記法（見出し、箇条書き、表、ブロックコマンドなど）の書き誤りである。[記法](markup.md)と照らして直す。
- **ADR**：ADR なし（[golem-parser ADR 0007](golem-parser/adr/0007-grammar-label-safety.md) が既存のコードとして触れる）

## G0111

- **原因と直し方**：インデントは空白 2 個を単位とする。タブを空白に替え、深さを 2 の倍数にそろえる。
- **ADR**：ADR なし（[golem-parser ADR 0007](golem-parser/adr/0007-grammar-label-safety.md) が既存のコードとして触れる）
