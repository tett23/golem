# `-A64m` でリンクした `golem` の速さ（2026-11-09）

[docs/adr/0249](../adr/0249-link-golem-with-a-64-mb-allocation-area.md) の実装のプルリクエストで、`golem` を `-with-rtsopts=-N -A64m` でリンクする前と後の `golem build --target pdf` を測った記録である。
方法は [docs/benchmarks/2026-11-09-typesetting-speed-survey.md](2026-11-09-typesetting-speed-survey.md)（以下「調査」）の表 1 と表 2 にそろえた。
コミットした後は変更しない。

## 環境

- 計算機：調査と同じ Apple M1 Max（10 コア、性能コア 8 と効率コア 2）、メモリ 64GB、macOS 27.0。
- 変更前：`origin/main` のコミット `82861475` を新しい作業ツリーに取り出し、`cabal build exe:golem --disable-tests` でビルドしたもの。`-with-rtsopts` は `-N` である。
- 変更後：同じ作業ツリーで `modules/golem-cli/golem-cli.cabal` の `-with-rtsopts` だけを `-N -A64m` にしてリンクし直したもの。このプルリクエストの `golem` と同じ設定である。
- どちらも、`+RTS -s` を使うためだけに、作業ツリーの `cabal.project.local` に `package golem-cli` の `ghc-options: -rtsopts` を足した。製品のビルド設定には `-rtsopts` を入れていない。
- GHC 9.10.3、cabal 3.18.1.0、最適化は cabal の既定（`-O1`）。
- 入力：調査と同じ `manual/`、`manual-dev/`、`modules/golem-driver/test/fixtures/` の `kanikosen` と `pd/` の十冊。フォントも調査と同じものを置いた。`manual/common/build-info.gm` は `GOLEM_MANUAL_COMMIT=82861475` で書き、二つの `golem` で同じにした。

## 方法

一回ごとに `build/` を消し、`golem build --target pdf +RTS -s<ファイル> -RTS` を実行した。
壁時計はコマンドの前後の時刻の差、CPU 時間、世代 0 の GC の回数、最大常駐、「total memory in use」は `+RTS -s` の値である。
入力ごとに変更前と変更後を交互に一回ずつ走らせ、これを 5 周した。
交互に走らせたのは、同じ計算機で別のエージェントのビルドと計測が動いていて、負荷が時間とともに変わるからである。
130 回の計測の開始のときの load average（1 分）は 11.3 から 51.7、中央値は 15.2 だった。
調査のときより重い負荷で、壁時計の絶対値は調査の表 1 より長い。
そこで、変更前と変更後の比は、同じ周の二回の比を 5 周で中央値にしたもの（下の表の「短縮」）で読む。

出力は、`build/` の下のすべてのファイルの SHA-256 と標準出力と標準エラー出力をまとめたハッシュで比べた。
すべての入力の 10 回で、ハッシュは一つだった（変更前と変更後で一致する）。

- すべての入力で、壁時計は同じ周の比で 25% から 38% 短くなった。[ADR 0249](../adr/0249-link-golem-with-a-64-mb-allocation-area.md) のテスト設計の「20% 以上短い」を満たす。

- CPU 時間も 19% から 35% 減った。GC のたびの capability の同期が減ったためと見る。
- メモリは nursery の分だけ増えた。10 個の capability で 640MB の nursery になり、小さい入力では 130MiB 前後から 800MiB 前後に、マニュアルでは 1,956MiB から 2,343MiB になった。最大常駐（GC の後に生きているデータ）は大きくは変わらない（減った入力も、15MB ほど増えた入力もある）。
- 出力のバイト列と diagnostics は変わらなかった（[ADR 0249](../adr/0249-link-golem-with-a-64-mb-allocation-area.md) の I1）。

## 使ったコマンド

```sh
# 変更前と変更後のビルド（cabal.project.local に package golem-cli / ghc-options: -rtsopts）
cabal build exe:golem --disable-tests
# -with-rtsopts を変えても GHC はリンクし直さないので、実行ファイルの build ディレクトリを消してからビルドした
rm -rf dist-newstyle/build/aarch64-osx/ghc-9.10.3/golem-cli-0.1.0/x/golem
# 一回の計測（入力ごとに、変更前と変更後を交互に 5 周）
cd manual && rm -rf build && golem build --target pdf +RTS -s/path/rts.txt -RTS
```

## 限界

- 負荷を制御できず、壁時計の絶対値は調査より長い。比は交互の計測で負荷の影響を減らしたが、なくしてはいない。
- 計測のスクリプト（交互の実行と中央値の計算）は、この記録とともに置いていない。
- `-rtsopts` を付けた実行ファイルで測った。`-rtsopts` は RTS のオプションの受け付けだけを変え、GC の動きは変えない。
