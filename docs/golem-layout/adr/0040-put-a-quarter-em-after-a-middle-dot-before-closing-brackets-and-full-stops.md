# ADR 0040: 既定のアキ量のセットで、中点類の後ろの終わり括弧類と句読点の前に四分を置く

ステータス: 採択（未実装）

## 文脈

[golem-layout ADR 0039](0039-set-consecutive-opening-brackets-and-brackets-beside-middle-dots-as-jlreq.md) は、既定のアキ量のセット `gyomatsu-yakumono-hankaku` のすべての組を JLReq の付録 B の表 1 と照らし、三つの組を JLReq に合わせた。
照らしたときに見つかったほかの食い違いのうち、中点類の後ろの終わり括弧類と句読点（`・」`、`・。`）は、原因が別なので別の ADR で扱うことにした（0039 の「表 1 とのほかの食い違い」と「メンテナーが決めること」の 3）。
この ADR は、その組を扱う。

### 既定のセットの規則

既定のセットの規則は [`defaultAkiSet`](https://github.com/tett23/golem/blob/406ccc69f367cd32305c6162107a77a398e821ef/modules/golem-layout/src/Golem/Layout/Aki.hs#L78-L106) にある。
中点類（`m`）が前にある規則は、`(m, o, …)`、`(m, j <> w, …)`、`(m, m, …)` の三つである。
`p`（終わり括弧類と句点類と読点類）が後にある規則はない。
規則のない組の空きは `noAki`（0）なので、中点類の後ろの終わり括弧類と句読点のあいだは 0 になる。

0019 は、既定のセットの値を、それより前の `normalize` の組み方に合わせて決めた。
前の組み方を写した参照の実装は、テストの [`combined`](https://github.com/tett23/golem/blob/406ccc69f367cd32305c6162107a77a398e821ef/modules/golem-layout/test/Main.hs#L1653-L1658) にある。
`combined` は、後の字の前の空きが 0 のとき、後の字が終わり括弧類か句点類か読点類なら、前の字の後ろの空きを捨てていた。
この規則は、`」）` や `。」` の字間をベタ組にするためのものである（JLReq の 3.1.4 の①と⑥）。
同じ規則が中点類にも当たり、中点類の後ろの四分も捨てていた。
0019 の表は、この結果をそのまま写したので、`(m, p)` の規則がない。

0039 の三つの組は、二つの空きを足したために残すべきでない空きが残った組である。
この ADR の組は、捨てるべきでない空きを捨てた組であり、向きが逆である。

### 組んで確かめた結果

2026-11-09 に、origin/main（`406ccc69`）で golem を作り、横組み、10pt、Noto Serif JP の本で、次の段落を PDF に組んだ。
`Golem.Layout.Aki` は、0039 が測った `4b3ffcb4` から変わっていない。
表の「Golem」の列は、0039 と同じく、隣り合う二つの約物の箱のあいだのグルーの幅である（PDF の字の位置の差から、二つめの字の前にある箱の幅を引いた量）。
単位は em である。

| 段落 | 組 | Golem | JLReq |
| --- | --- | --- | --- |
| `漢・」漢` | `・」` | 0 | 0.25 |
| `漢・。漢` | `・。` | 0 | 0.25 |
| `漢・、漢` | `・、` | 0 | 0.25 |
| `漢：」漢` | `：」` | 0 | 0.25 |
| `漢・）。漢` | `・）` | 0 | 0.25 |
| `漢・）。漢` | `）。` | 0 | 0 |
| `漢「・」漢` | `「・` | 0.25 | 0.25 |
| `漢「・」漢` | `・」` | 0 | 0.25 |
| `漢・・漢` | `・・` | 0.5 | 0.5 |

`漢「・」漢` では、中点類の前に四分があり、後ろに空きがない。
中点類の字面は、前後の字のあいだの中央からずれる。

### JLReq の規定

JLReq の 3.1.2（句読点や，括弧類などの基本的な配置方法）は、中点類について「原則として前及び後ろを四分アキにする」と定める。
約物が連続する場合を定める 3.1.4 は、中点類の後ろに終わり括弧類や句読点が続く場合を挙げない。
付録 B の表 1 では、cl-05（中点類）の行の cl-02（終わり括弧類）、cl-06（句点類）、cl-07（読点類）の欄が、どれも「1/4 be」である。
JLReq の付録 B は、「be」を、空きの量を前の字の大きさで測ることとする。

cl-05 の行の line end の欄は注 4 で、行末の中点類の扱いである。
この ADR は行末を扱わない（「実装しないこと」）。

### HTML と EPUB

0039 は、Google Chrome 156.0.8078.80 の headless で同じ並びを描き、`・」` と `・。` の空きを 0.25 em と測った。
Chrome の既定は、すでに表 1 と同じ空きで組む。
PDF だけが表 1 と違う。

## 実装すること

### 1. 既定のセットの三つの組を変える

`defaultAkiSet` に、次の規則を足す。

| 前 | 後ろ | 今 | 変えた後 |
| --- | --- | --- | --- |
| `middle-dot` | `closing` | 0 | (0, 四分, 四分) |
| `middle-dot` | `full-stop` | 0 | (0, 四分, 四分) |
| `middle-dot` | `comma` | 0 | (0, 四分, 四分) |

ほかの組は変えない。
`gyomatsu-yakumono-zenkaku` は `defaultAkiSet` に行末の規則を足したセットなので、同じ三つの組が同じように変わる。

規則の書き方は、実装のプルリクエストで決めてよい。
たとえば、`(m, m, …)` の後に `(m, p, Aki 0 (1 / 4) (1 / 4))` を足す。

`zw` の基準の大きさ（0019 の「両方が約物なら、大きいほうの箱の大きさ」）は変えない。
四分の量は、二つの約物の箱の大きいほうで測る。

### 2. 0039 の上に積む

この ADR は、0039 を実装した後の `defaultAkiSet` を出発点とする。
0039 は `(p, m)` と `(m, o)` の値を変え、この ADR は `(m, p)` を足す。
同じ組を二つの ADR が変えることはない。
0039 の実装と同じ規則の表を書き換えるので、この ADR の実装は、0039 の実装がマージされた後の main から始める。

0039 の不変条件 B4 は、0039 の三つの組のほかのすべての組で、空きが 0039 の前の値と等しいことを求める。
この ADR の三つの組は、その「ほかの組」に入るので、この ADR を実装すると B4 は成り立たなくなる。
B4 の例外の組に、この ADR の三つの組を足す（この ADR の不変条件 A2）。
0039 は採択済みなので書き換えず、0039 のステータスの行からこの ADR を指す。

### 3. 行分割の項目

終わり括弧類と句点類と読点類は行頭禁則の字なので、この三つの組は、今も分割の候補でない。
今は、規則がないので、二つの箱のあいだに何も置かない（[`between`](https://github.com/tett23/golem/blob/406ccc69f367cd32305c6162107a77a398e821ef/modules/golem-layout/src/Golem/Layout/Japanese.hs#L1343-L1375) の `Just _ -> [Penalty 0 0 NoHyphen | not noBreak]`）。
変えた後は、`Penalty 0 infPenalty NoHyphen` と、幅が四分で、伸びが 0、縮みが四分のグルーを置く。
分割の位置は増えない。

### 4. 文書

- 仕様書の「アキ量のセット」の段落の、中点類の後ろの終わり括弧類と句読点の空きを、四分に改める。0039 の実装は、この空きを 0 と書く（0039 の「実装すること」の 3）。
- 仕様書のその段落に、この ADR へのリンクを足す。
- [docs/adr/0019](../../adr/0019-aki-settings.md) のステータスの行に、「既定のセットの中点類の後ろの終わり括弧類と句読点の空きは [golem-layout ADR 0040](0040-put-a-quarter-em-after-a-middle-dot-before-closing-brackets-and-full-stops.md)」を足す。
- 0039 のステータスの行に、「不変条件 B4 の例外の組に中点類の後ろの終わり括弧類と句読点を足したのは [golem-layout ADR 0040](0040-put-a-quarter-em-after-a-middle-dot-before-closing-brackets-and-full-stops.md)」を足す。
- 利用者のマニュアルは、隣り合う約物の値を書いていない（0039 の「実装すること」の 3）。マニュアルは変えない。

### 5. 出力の変化

中点類（`・`、`：`、`；`）の後ろに終わり括弧類か句読点が続く段落は、その字間が四分ぶん広がる。

`rg` で数えると、`manual/` には一つもなく、`manual-dev/` に二つある。
どちらも「中黒（・）」のように中点類を括弧で括った文であり（`manual-dev/part2/10-docs.gm` の 128 行目と `manual-dev/part2/15-manuals.gm` の 189 行目）、`・）` の字間が変わる。
`modules/golem-driver/test/fixtures/` の原稿には一つもない。
PDF の golden（`modules/golem-driver/test/golden/pdf-*.txt`）の原稿（`sample`、`complex-horizontal`、`complex-vertical`、`figures`）にもない。
golden は変わらない見込みである。
実装のプルリクエストで、golden、`scripts/visual/` の参照、二つのマニュアルと complex fixture の決定性のハッシュが変わるかを確かめ、説明に書く。

## 実装しないこと

- **行末の中点類**：表 1 の cl-05 の行の line end の欄（注 4）は、行末の中点類の扱いである。`gyomatsu-yakumono-hankaku` は行末の中点類の後ろを 0 とし、`gyomatsu-yakumono-zenkaku` は四分とする（0019）。この ADR は行末の規則を変えない。
- **測る大きさ**：表 1 の「1/4 be」は、前の字（中点類）の大きさで測る。Golem は二つの約物の箱の大きいほうで測る。0039 の「メンテナーが決めること」の 4 と同じく、この ADR では変えない。
- **和字間隔の前後の空き**：[golem-layout ADR 0041](0041-take-the-ideographic-space-out-of-japanese-characters-in-the-default-aki-set.md) で扱う。原因が別である。
- **利用者のセット**：`based-on` で既定のセットを引き継いだ利用者のセットは、引き継いだ規則が変わるので、同じ三つの組が変わる。利用者が `rules` でこの三つの組を書いていれば、その値が勝つ（0019 の「後に書いた規則が上書きする」）。
- **HTML と EPUB**：`style.css` を変えない。Chrome の既定は、すでに表 1 と同じ空きで組む。

## 不変条件

`d` を `defaultAkiSet`、`z` を `gyomatsu-yakumono-zenkaku` とする。
`d39` を、0039 を実装した後の `defaultAkiSet` とする。
`M`、`C`、`F`、`K` は、それぞれ `AkiChar MiddleDot`、`AkiChar Closing`、`AkiChar FullStop`、`AkiChar Comma` である。

- **A1**：`y` が `C`、`F`、`K` のどれでも、`akiBetween d M y == Aki 0 (1 / 4) (1 / 4)` である。
- **A2**：`(M, C)`、`(M, F)`、`(M, K)` 以外のすべての位置の組 `(x, y)`（行頭、段落の先頭、行末を含む）で、`akiBetween d x y == akiBetween d39 x y` である。
- **A3**：すべての位置の組 `(x, y)` で、`akiBetween z x y` は、`y` が行末なら今の `gyomatsu-yakumono-zenkaku` の値、そうでなければ `akiBetween d x y` である。
- **A4**：中点類の字 `a`（`・`、`：`、`；`）と、終わり括弧類か句点類か読点類の字 `b` を、和文の字のあいだに `a`、`b` の順に並べて組むと、`a` の箱と `b` の箱のあいだの項目は、`Penalty 0 infPenalty NoHyphen` と、幅が `a` と `b` の大きいほうの四分のグルーの二つだけである。
- **A5**：既定のセットを `based-on` にし、`rules` で `middle-dot` と `closing` の組を書いた利用者のセットでは、その組の空きは書いた値である。

## トレードオフ

既存の本の PDF の字詰めが変わる。
中点類の後ろに終わり括弧類や句読点が続く並びは、Golem のマニュアルと fixture にはほとんどない（「実装すること」の 5）。
既定のセットの名前は変えずに値を変えるので、同じ原稿を前の版と今の版で組むと違う PDF になる。

0039 と別の ADR にした。
0039 の三つの組は、`combined` が二つの空きを足したことが原因であり、この ADR の組は、`combined` が後の字が終わり括弧類か句読点のときに前の字の後ろの空きを捨てたことが原因である。
同じ表を変えるので、実装の順を決めておく必要がある（「実装すること」の 2）。

InDesign の「行末約物半角」の値とは照合していない。
メンテナーは、InDesign の振る舞いが分からないときは JLReq の記述を採ると決めた（2026-11-08）。
InDesign がこの組を 0 で組むなら、名前を合わせたセットが InDesign と違う組み方になる。

四分のグルーは縮む（最小 0）。
行の調整で詰めると、今と同じ 0 になる。
JLReq の 3.1.4 も、連続する約物のあいだの四分アキを、行の調整処理の詰める対象にしてよいとする。

## メンテナーが決めること

1. **三つの組を JLReq に合わせるか**：推奨は、合わせることである。表 1 は三つの組に四分を置き、3.1.2 も中点類の後ろを四分アキとする。InDesign の振る舞いは分からないので、2026-11-08 の決定により JLReq の記述を採る。Chrome の既定も、すでに四分で組む。
   - 退けた案は、0 のままとすることである。中点類の字面が前後の字のあいだの中央からずれ、PDF と HTML の差も残る。
2. **終わり括弧類と句点類と読点類をまとめて変えるか**：推奨は、まとめて変えることである。表 1 は三つの欄に同じ「1/4 be」を置き、Golem の原因も同じ一つの規則である。
   - 退けた案は、終わり括弧類だけを変えることである。同じ欄の値のうち一つだけを当てる理由がない。
3. **ADR を置く場所**：推奨は、0039 と同じく golem-layout の ADR とすることである。変えるのは golem-layout の既定の値だけで、`style.toml` の形も diagnostics も変わらない。
4. **実装の順**：推奨は、0039 の実装がマージされた後に、この ADR を実装することである。二つの ADR は同じ規則の表とテストを変える。0039 の B4 のテストの例外の組を、この ADR の実装が広げる。
   - 退けた案は、0039 の実装に、この ADR の組を含めることである。0039 は採択済みで、実装することの範囲が決まっている。

## 決めたことの記録

- **「メンテナーが決めること」のすべて**（2026-11-09、メンテナー）：どれも推奨のとおりとした。
