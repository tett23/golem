# ADR 0016: 三点リーダーの後の句点と、横線の二倍ダッシュの分割

ステータス: 採択

## 文脈

仕様書の「既知の不具合」に「三点リーダーの後の句点の行頭禁則」がある。
fixture の『牛山ホテル』（[docs/adr/0026](../../adr/0026-ten-public-domain-fixtures.md)）の 12 ページで、「……」の直後の「。」が行頭に置かれている、という報告である。
原因は確かめておらず、[docs/roadmap.md](../../roadmap.md) の「既知の不具合の修正」は、分離禁止文字と句点の間の改行の位置か、カーニングを止める処理と禁則の判定の順を疑っている。
報告のあと、行分割の最後の段で収まらない箱を次の行へ追い出す変更（PR #231）が入った。

### 再現の試み

今の `main` から作った golem（a2b6106e、PR #231 を含む）で、次の三つを調べた。
PDF の内容のストリームからグリフの位置を読み、ToUnicode の CMap で文字に戻し、行ごとの文字列にして確かめた。

- 『牛山ホテル』の fixture を組み、1514 行のどの行も、行頭禁則の文字（終わり括弧類、句点類、読点類、区切り約物、中点類、繰返し記号、長音記号、小書きの仮名）で始まらない。「……」の二字のあいだで分かれた行もない。
- 縦組みと横組み、ぶら下げ組の有無を組み合わせた小さなプロジェクトで、「……」の後に句点、終わり括弧、読点、疑問符、小書きの「ッ」のそれぞれを続けた並び（`……。`、`……」`、`……、`、`……？`、`……ッ`）を、行末の前後のすべての位置に置いて組んだ。どの組でも「。」などは「……」から離れず、行頭に来ない。
- 報告と同じ日（2026-10-16）に作った三つの golem でも『牛山ホテル』を組んだ。どれも行頭禁則の文字で始まる行はない。

この三つの golem の一つが組んだ 12 ページには、「金田」の台詞の二行めが「……。」だけの行がある。
報告は、この行の「……」に続く「。」を見て、句点が行頭に来たと読んだと考えられる。
行頭にあるのは「……」であり、「。」は「……」と同じ行の二字めにある。

### 規則の確認

JLReq の 3.1.7 は、行頭に置かない文字を、終わり括弧類（cl-02）、ハイフン類（cl-03）、区切り約物（cl-04）、中点類（cl-05）、句点類（cl-06）、読点類（cl-07）、繰返し記号（cl-09）、長音記号（cl-10）、小書きの仮名（cl-11）、割注終わり括弧類（cl-29）と定める。
分離禁止文字（cl-08）はこの中になく、「……」は行頭に置いてよい。
JLReq の 3.1.10 は、二倍ダッシュ（`——`）と三点リーダーの並び（`……`）のあいだで分割しないと定める。
小説の台詞が「……」で始まる行は珍しくなく、この組み方は JLReq に従っている。

### コードの確かめ

`Golem.Layout.Japanese` の `normalize` は、隣り合う二つの箱のあいだに改行の位置を置くかどうかを、前の箱の最後の字と後の箱の最初の字のクラスで決める。

- 後の字が行頭禁則（`lineStartProhibited`）なら、改行の位置を置かない。「…」と「。」のあいだは、句点類が行頭禁則なので改行できない。
- 前の字と後の字がどちらも分離禁止文字なら、改行の位置を置かない。「…」と「…」のあいだは改行できない。
- カーニング（`kernPairs`）は `normalize` の前に行うが、分離禁止文字と句点類を対象にしないので、箱の並びも改行の位置も変えない。
- 行分割の追い出し（`Golem.Layout.KnuthPlass` の `pushOut`）は、改行の位置の候補（`candidates`）からだけ行の終わりを選ぶ。改行の位置のない箇所で行を分けることはない。

注の印、索引の印、文字スタイルの境が「……」と「。」のあいだにあっても、印は前の箱に付き（注の印のあとは無限の罰点）、索引の印は箱を作らず、文字スタイルの境は箱の境にすぎないので、同じ規則で判定される。
報告された不具合は、今の `main` でも報告の時点の golem でも起きていない。

### 調べる途中で見つけた不具合

同じ小さなプロジェクトで、U+2015 HORIZONTAL BAR を二つ並べて句点を続けた `――。` を組むと、行末に U+2015 が一つ残り、次の行が `―。` で始まる組が四つあった。
`Golem.Layout.CharClass` の `charClass` は、分離禁止文字を `—…‥〳〴〵` に限り、U+2015 を漢字等（`Ideograph`）に分類する。
漢字等どうしのあいだには改行の位置が置かれるので、U+2015 の二倍ダッシュは二つに分かれうる。

JLReq の 3.1.10 は、二倍ダッシュの分割禁止を U+2014 EM DASH で定め、処理系によっては U+2015 HORIZONTAL BAR に同じ振る舞いを実装しているとも書く。
[golem-driver ADR 0015](../../golem-driver/adr/0015-vertical-dashes.md) が調べたとおり、全角のダッシュに U+2014 と U+2015 のどちらを使うかは、原稿の出どころ（JIS の対応表の流儀）で分かれる。
青空文庫から取った fixture は U+2015 を使い、『蟹工船』に 235 箇所、『牛山ホテル』に 31 箇所の `――` がある。
今の二冊では、たまたま `――` の途中で行が分かれていない。
同じ二倍ダッシュが、符号位置によって分かれたり分かれなかったりするのは、利用者には予測できない。

### メンテナーが決めたこと

- U+2015 の `――` は原稿に多く現れ、二字のあいだで分かれると利用者には壊れた組版に見えるので、この ADR（v0.1.0-rc3）で分離禁止文字にする。
- ほかの分離禁止文字と禁則の文字の見直しは、v2 の後半で扱う。

## 実装すること

### 三点リーダーの後の句点

組み方は変えない。
「……。」は、今のとおり「……」の前で改行してよく、「…」と「…」のあいだ、「…」と「。」のあいだでは改行しない。
回帰のテストを足して、仕様書の「既知の不具合」から項目を消す。

### U+2015 の文字のクラス（golem-layout）

`Golem.Layout.CharClass` の `charClass` で、U+2015 HORIZONTAL BAR を分離禁止文字（`Inseparable`）に加える。
JLReq の 3.1.10 の注が、処理系によっては U+2015 に U+2014 と同じ振る舞いを実装しているとする扱いに倣う。

```haskell
  | c `elem` ("—―…‥〳〴〵" :: String) = Inseparable
```

- これで、`――` のあいだは分割禁止になる（`normalize` の、前後がどちらも分離禁止文字の規則）。`――` の前では、今のとおり改行してよい。
- アキ量のセットの `inseparable` のクラスの規則も U+2015 にかかる。既定のセット（[docs/adr/0019](../../adr/0019-aki-settings.md)）では、漢字等と分離禁止文字は同じ規則の組（和文どうしの 0 から 0.1zw の空き、和欧間の空き）に入っているので、既定のセットの空きは変わらない。
- 和文のペアカーニング（`kernPairs`）は、分離禁止文字を対象にしないので、U+2015 の並びにカーニングをかけなくなる。仕様書は二倍ダッシュの間を詰めないと定めており（[golem-driver ADR 0020](../../golem-driver/adr/0020-glyph-positioning-and-dash-kerning.md)）、U+2015 もそれにそろう。
- 縦組みの字形と回転（[golem-driver ADR 0015](../../golem-driver/adr/0015-vertical-dashes.md)）は、UAX #50 の表で決まるので変わらない。
- 欧文の語に付くダッシュ（`textPieces` の `isJoiner`）は、今のとおり U+2014 などに限る。U+2015 は欧文の語に付けない。
- HTML、EPUB、プレーンテキストの出力は変わらない。

### ドキュメント

- 仕様書の「既知の不具合」から「三点リーダーの後の句点の行頭禁則」の項目を消す。
- 仕様書の和文のペアカーニングの段落にある分離禁止文字の一覧に `―`（U+2015）を加え、この ADR へのリンクを付ける。
- 仕様書の禁則の説明に、分離禁止文字（`—`、`―`、`…`、`‥`、`〳`、`〴`、`〵`）は行頭に置いてよく、分離禁止文字どうしのあいだでは分割しないことを、JLReq の 3.1.7 と 3.1.10 への言及とともに書く。
- [docs/roadmap.md](../../roadmap.md) の「既知の不具合の修正」から「三点リーダーの後の句点の行頭禁則」の項目を消す。
- [docs/roadmap.md](../../roadmap.md) の「v2 以降に回した事項」に、次の項目を加える（ロードマップはメインのセッションが改める）。U+2015 はこの ADR で扱うので、項目に含めない。
  - **分離禁止文字と禁則の見直し**：分離禁止文字と、行頭禁則と行末禁則の文字の一覧を見直す（この ADR）。v2 の後半に置く。
- 利用者のマニュアルの付録 I（`manual/appendices/i-known-issues.gm`）から「三点リーダーの後の句点が行頭に来る」の項目を消し、付録 H（`manual/appendices/h-roadmap.gm`）の直す不具合の一覧から同じ項目を消す。
- 利用者のマニュアルの付録 C（`manual/appendices/c-style.gm`）の `inseparable` の説明に、`―` も含むことを書く。

## 実装しないこと

- U+2015 のほかの分離禁止文字と禁則の文字の見直し。メンテナーの決定により、v2 の後半の「分離禁止文字と禁則の見直し」（[docs/roadmap.md](../../roadmap.md) に加える項目）で扱う。
- 「……」を行頭に置かない設定。JLReq は分離禁止文字を行頭禁則に含めず、行頭禁則を緩める設定（`kinsoku = "loose"`）とは別の軸になる。
- U+2E3A TWO-EM DASH と U+2E3B THREE-EM DASH のクラスの変更。どちらも一字で二倍、三倍の長さを持つので、字のあいだの分割の問題は起きない。
- 縦組みの U+2015 の字形の変更。[golem-driver ADR 0015](../../golem-driver/adr/0015-vertical-dashes.md) のとおりとする。

## テスト設計

実装の前に書く。
U+2015 のテストは、実装の前に失敗することを確かめる。
「……。」のテストは今の実装で通る回帰のテストであり、通ることを確かめてから残す。

### golem-layout（`modules/golem-layout/test/Main.hs`）

- `charClass '―'` が `Inseparable` である。`charClass '—'`、`charClass '…'` も `Inseparable` のままである。
- `defaultComposeEnv` の 10pt で、`"あ" × n <> "……。" <> "い" × 40` を `composeInlines` で項目にし、行長 38zw で `breakParagraph` にかける。n を 30 から 41 まで変えたどの場合も、どの行も `。` で始まらず、どの行も `…` 一字で終わらない。`ceKinsokuStrict` が真と偽、`ceVertical` が真と偽、`ceHanging` が真と偽のすべての組で確かめる。
- 同じ形で `"……」"`、`"……、"`、`"……？"` を確かめる。
- 同じ形で `"――。"`（U+2015 の二つ）を確かめ、どの行も `―` 一字で終わらず、`―` で始まる行は `――` で始まる。
- `"――"` の二つの箱のあいだに、無限の罰点のほかの改行の位置がない。
- 既定のアキ量のセットで、`漢―` と `―漢` の空き（グルーの幅、伸び、縮み）が、実装の前の `漢漢` と同じである。

### golem-driver（`modules/golem-driver/test/ParagraphSpec.hs`）

- 『蟹工船』の fixture のフォント（Noto Serif JP）を本文に使う、字詰め 38 字の縦組みの本で、`"あ" × n <> "……。" <> "い" × 40` の段落を n を変えて並べて組む。`lineTexts` で得たどの行も `。` で始まらない。
- 同じ本で `"あ" × n <> "――。" <> "い" × 40` の段落を n を 30 から 41 まで並べて組み、どの行も `―` 一字で終わらない。文脈の再現で、実装の前に n が 36 と 37 の段落で分かれた組である。

### 自動テストにしない確かめ方

- 『蟹工船』と『牛山ホテル』の fixture を組み、行頭禁則の文字で始まる行と、`―` 一字で終わる行がないことを、この ADR の再現と同じ方法で確かめる。
- 二冊の PDF の差が、U+2015 の前後の行に限られることを確かめる。

## トレードオフ

報告された不具合は再現しなかったので、三点リーダーの組み方は変えずに回帰のテストだけを足した。
原因を確かめずに「直した」と書くより、再現しないことと JLReq の規則を記録するほうが、同じ報告が繰り返されたときに読み返せる。
報告が見たものを、行頭の「……。」と推定したのは、報告の時点の golem の 12 ページにその行があり、ほかに候補がないからである。
推定が外れていた場合に備え、段落の中の位置を変えて行頭禁則を確かめるテストを残す。

U+2015 を分離禁止文字にすると、`――` の途中で改行できなくなり、行分割の候補が減る。
二字の箱が分けられないぶん、行末の調整が苦しくなる段落はありうるが、U+2014 の `——` と同じ条件になるだけである。
代わりに、U+2015 を単独で使う原稿（横線の記号として一字だけ置く場合）でも、前後の字のあいだの空きの規則が分離禁止文字のものになる。
既定のアキ量のセットでは漢字等と同じ空きなので、差が出るのは、利用者が `inseparable` と `ideograph` を別に定めたアキ量のセットに限られる。
