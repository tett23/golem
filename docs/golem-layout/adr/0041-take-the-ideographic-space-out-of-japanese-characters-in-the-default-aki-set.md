# ADR 0041: 既定のアキ量のセットで、和字間隔を和文の字の集まりから外し、JLReq の空きにする

ステータス: 採択（未実装）

## 文脈

[golem-layout ADR 0039](0039-set-consecutive-opening-brackets-and-brackets-beside-middle-dots-as-jlreq.md) は、既定のアキ量のセット `gyomatsu-yakumono-hankaku` のすべての組を JLReq の付録 B の表 1 と照らした。
照らしたときに見つかったほかの食い違いのうち、和字間隔（U+3000）の前後の括弧類（`」　`、`　「`）は、原因が別なので別の ADR で扱うことにした（0039 の「表 1 とのほかの食い違い」と「メンテナーが決めること」の 3）。
この ADR は、その原因を扱う。

### 既定のセットの規則

既定のセットの規則は [`defaultAkiSet`](https://github.com/tett23/golem/blob/406ccc69f367cd32305c6162107a77a398e821ef/modules/golem-layout/src/Golem/Layout/Aki.hs#L78-L106) にある。
U+3000 は、[`charClass`](https://github.com/tett23/golem/blob/406ccc69f367cd32305c6162107a77a398e821ef/modules/golem-layout/src/Golem/Layout/CharClass.hs#L38-L54) で和字間隔（`IdeographicSpace`、cl-14）に分けられる。
`defaultAkiSet` は、和字間隔を、漢字や仮名と同じ集まり `j` に含める（[90 行目](https://github.com/tett23/golem/blob/406ccc69f367cd32305c6162107a77a398e821ef/modules/golem-layout/src/Golem/Layout/Aki.hs#L90)）。
このため、`j` を名指す規則が、すべて和字間隔にも当たる。
[docs/adr/0019](../../adr/0019-aki-settings.md) の「組み込みのセット」の表も、`J` に `ideographic-space` を含める。
0019 の前の `normalize` も、和字間隔を、前後に空きを持たない和文の字として扱っていた。

和字間隔が前か後ろにある組を、表 1 の cl-14 の行と列と照らすと、次のとおりである。

### JLReq の規定

付録 B の表 1 は、cl-14（和字間隔）の行に、cl-05（中点類）の欄の「1/4 af」とルビの注 8 のほかの値を置かない。
cl-14 の列にも、cl-05、cl-06（句点類）、cl-07（読点類）の行の値と、ルビの付いた親文字（cl-22、cl-23）の行の注 8 のほかは値を置かない。
表 1 の凡例は、空欄をベタ組とする。

3.1.11（行の調整処理で字間を空ける処理を避ける箇所）は、「全角アキなどの和字間隔の前及び後ろ」を、行の調整で字間を空けるのを避ける箇所に挙げる。

3.1.5（行頭の始め括弧類の配置方法）は、段落の先頭の始め括弧類の置き方を三つ挙げる。
①は、段落の先頭の字下げを全角アキとし、始め括弧類の前に空きを入れない。
②は、段落の先頭の字下げを全角半とする。
③は、段落の先頭の字下げを二分とする。
JLReq は、括弧類の字幅はもともと半角であり、何も空き量を入れなければ①になると説明する。
和字間隔で字下げした段落の先頭の始め括弧類は、表 1 のとおりに組むと①になり、今の Golem は②で組む。

### 字下げと和字間隔

既定の段落スタイルは字下げをしない。
利用者のマニュアルは、段落の頭の一字下げを、原稿の行頭に和字間隔を書いて表せると案内する（`manual/chapters/04-manifest.gm` の 76 行目）。
`first-line-indent` で字下げする段落の先頭の始め括弧類には、`paragraph-start` の規則の二分が付き、②になる。
この ADR の後は、和字間隔で字下げした段落が①、`first-line-indent` で字下げした段落が②になり、二つの書き方で組み方が違う。

### HTML と EPUB

0039 は、Google Chrome 156.0.8078.80 の headless で同じ並びを描き、`」　` と `　「` の空きを 0 と測った。
Chrome の既定は、括弧類の組では、すでに表 1 と同じ空きで組む。
`　A` と `A　` は、Chrome で測っていない。

## 実装すること

### 1. 和字間隔を `j` から外し、表 1 の空きにする

`defaultAkiSet` の `j` から `IdeographicSpace` を除き、和字間隔の組の空きを次のようにする。

| 前 | 後ろ | 今 | 変えた後 |
| --- | --- | --- | --- |
| `closing` | `ideographic-space` | (0, 二分, 二分) | 0 |
| `ideographic-space` | `opening` | (0, 二分, 二分) | 0 |
| `ideographic-space` | `western` | (八分, 四分, 二分) | 0 |
| `western` | `ideographic-space` | (八分, 四分, 二分) | 0 |
| `ideographic-space` 以外の `J` | `ideographic-space` | (0, 0, 0.1zw) | 0 |
| `ideographic-space` | `kana`、`ideograph`、`ideographic-space`、`inseparable` | (0, 0, 0.1zw) | 0 |
| `full-stop`、`comma` | `ideographic-space` | (0, 二分, 二分) | (0, 二分, 二分) |
| `middle-dot` | `ideographic-space` | (0, 四分, 四分) | (0, 四分, 四分) |
| `ideographic-space` | `middle-dot` | (0, 四分, 四分) | (0, 四分, 四分) |

`J` は、0019 の表の `J`（`japanese` から `O`、`P`、`M` を除いたクラス）である。
最後の三行は値を変えない。
`j` から和字間隔を除くと、この三つの組は `(p, j <> w, …)`、`(m, j <> w, …)`、`(j <> w <> o, m, …)` に当たらなくなるので、同じ値の規則を足す。
ほかの組は変えない。
`gyomatsu-yakumono-zenkaku` は `defaultAkiSet` に行末の規則を足したセットなので、同じ組が同じように変わる。

規則の書き方は、実装のプルリクエストで決めてよい。
たとえば、`j` から `IdeographicSpace` を除き、`(chars [FullStop, Comma], s, Aki 0 (1 / 2) (1 / 2))`、`(m, s, Aki 0 (1 / 4) (1 / 4))`、`(s, m, Aki 0 (1 / 4) (1 / 4))` を足す（`s` は `chars [IdeographicSpace]`）。
`j` を名指すほかの規則（`(j, [Kana, Ideograph, IdeographicSpace, Inseparable], …)` の後ろの集まりも含む）からも和字間隔が外れ、表の「0」の組は規則のない組になる。

`zw` の基準の大きさは変えない。
和字間隔は約物でないので、句読点と中点類との組の空きは、その約物の大きさで測る。

### 2. 0039 と 0040 の上に積む

この ADR は、0039 と [golem-layout ADR 0040](0040-put-a-quarter-em-after-a-middle-dot-before-closing-brackets-and-full-stops.md) を実装した後の `defaultAkiSet` を出発点とする。
0039 は `(j <> w <> o, o, …)` の前の集まりから `o` を除き、この ADR は同じ規則の前の集まりから和字間隔を除く。
0040 は `(m, p, …)` を足し、和字間隔の組に触れない。
同じ組を二つの ADR が変えることはないが、同じ規則の行を書き換えるので、この ADR の実装は、0039 と 0040 の実装がマージされた後の main から始める。

0039 の不変条件 B4 は、0039 の三つの組のほかのすべての組で、空きが 0039 の前の値と等しいことを求める。
この ADR の組は、その「ほかの組」に入るので、この ADR を実装すると B4 は成り立たなくなる。
B4 の例外の組に、この ADR の組を足す（この ADR の不変条件 S5）。
0039 は採択済みなので書き換えず、0039 のステータスの行からこの ADR を指す。

### 3. 行分割の項目

この ADR で 0 になる組は、どれも行頭禁則にも行末禁則にも当たらず、分割の候補である。
今は、幅か伸びを持つグルーを置き、そこで分けられる。
変えた後は、規則のない組として、グルーの代わりに `Penalty 0 0 NoHyphen` を置く（[`between`](https://github.com/tett23/golem/blob/406ccc69f367cd32305c6162107a77a398e821ef/modules/golem-layout/src/Golem/Layout/Japanese.hs#L1343-L1375) の `Just _ -> [Penalty 0 0 NoHyphen | not noBreak]`）。
分割の位置は変わらない。
行の調整で伸ばせる位置は、和字間隔の前後のぶんだけ減る。

### 4. 文書

- 仕様書の「アキ量のセット」の段落に、和字間隔の空きを書く。和字間隔の前後は、句点類と読点類の後ろの二分と、中点類の前後の四分のほかは空けず、伸ばさない。終わり括弧類の後ろと始め括弧類の前の二分と、和欧間の空きも置かない。
- 仕様書のその段落に、この ADR へのリンクを足す。
- 仕様書の「字下げ」の段落（`first-line-indent` と原稿の先頭の全角の空白を併用しないこと）に、全角の空白で字下げした段落の先頭の始め括弧類は全角の空白の直後に置かれ、`first-line-indent` で字下げした段落では二分下がることを書く。
- [docs/adr/0019](../../adr/0019-aki-settings.md) のステータスの行に、「既定のセットの和字間隔の前後の空きは [golem-layout ADR 0041](0041-take-the-ideographic-space-out-of-japanese-characters-in-the-default-aki-set.md)」を足す。
- 0039 のステータスの行に、「不変条件 B4 の例外の組に和字間隔の組を足したのは [golem-layout ADR 0041](0041-take-the-ideographic-space-out-of-japanese-characters-in-the-default-aki-set.md)」を足す。
- 利用者のマニュアルの第 5 章の「本文の字下げ」の節に、全角の空白で字下げした段落と `first-line-indent` で字下げした段落とで、段落の先頭の始め括弧の位置が違うことを書く。付録 C の既定のセットの説明（和欧間は四分）は、和字間隔の前後を除くことを書き足す。マニュアルの変更は ADR を要しない（メンテナーの方針）が、実装のプルリクエストに含める。

## 実装しないこと

- **段落の先頭の始め括弧類の規則**：0039 と同じく、`paragraph-start` と `line-start` の規則を変えない。`first-line-indent` で字下げした段落は②のままである。
- **和字間隔で字下げした段落を、`first-line-indent` と同じに組むこと**：段落の先頭の和字間隔を字下げと見なして、続く始め括弧類に `paragraph-start` の規則を当てる案である。原稿の字と字の組で空きを決める今の仕組みに、段落の先頭からの位置という別の条件を足すことになる。
- **欧文間隔（U+0020）**：和文と欧文の語のあいだの語間の空白は、[docs/adr/0222](../../adr/0222-line-breaking-points-the-invariants-did-not-decide.md) が扱い、アキ量のセットの外にある。
- **和欧間のほかの組**：0039 の「文脈」のとおり、和文と欧文のあいだの空きは別の問いである。この ADR は、和字間隔と欧文の組だけを変える。
- **測る大きさ**：0039 の「メンテナーが決めること」の 4 と同じく、変えない。
- **利用者のセット**：`based-on` で既定のセットを引き継いだ利用者のセットは、引き継いだ規則が変わるので、同じ組が変わる。今の組み方に戻したい利用者は、`rules` で `ideographic-space` の組を書けば、その値が勝つ（0019 の「後に書いた規則が上書きする」）。
- **HTML と EPUB**：`style.css` を変えない。

## 不変条件

`d` を `defaultAkiSet`、`z` を `gyomatsu-yakumono-zenkaku` とする。
`d40` を、0039 と 0040 を実装した後の `defaultAkiSet` とする。
`S` は `AkiChar IdeographicSpace`、`O`、`C`、`F`、`K`、`M`、`W` は、それぞれ `AkiChar Opening`、`AkiChar Closing`、`AkiChar FullStop`、`AkiChar Comma`、`AkiChar MiddleDot`、`AkiChar Western` である。

- **S1**：`akiBetween d C S`、`akiBetween d S O`、`akiBetween d S W`、`akiBetween d W S` は、どれも `noAki` である。
- **S2**：`x` が `F`、`K`、`M` でない和文のクラスの字なら、`akiBetween d x S == noAki` である。`y` が `M` でない和文のクラスの字なら、`akiBetween d S y == noAki` である。
- **S3**：`akiBetween d F S == akiBetween d K S == Aki 0 (1 / 2) (1 / 2)` である。
- **S4**：`akiBetween d M S == akiBetween d S M == Aki 0 (1 / 4) (1 / 4)` である。
- **S5**：`S` を含まないすべての位置の組 `(x, y)`（行頭、段落の先頭、行末を含む）と、`S` と行頭、段落の先頭、行末の組で、`akiBetween d x y == akiBetween d40 x y` である。
- **S6**：すべての位置の組 `(x, y)` で、`akiBetween z x y` は、`y` が行末なら今の `gyomatsu-yakumono-zenkaku` の値、そうでなければ `akiBetween d x y` である。
- **S7**：和字間隔が k 個（k ≥ 1）続いた後に始め括弧類が続く段落を組むと、始め括弧類の箱の行頭からの位置は、k zw ちょうどである。和字間隔の箱の前後と、始め括弧類の箱の前に、グルーを置かない。
- **S8**：既定のセットを `based-on` にし、`rules` で `ideographic-space` と `opening` の組を書いた利用者のセットでは、その組の空きは書いた値である。

## トレードオフ

既存の本の PDF の字詰めが変わる。
変わる箇所は、0039 と 0040 より多い。
処理系が番号の後ろに和字間隔を置くので、番号が半角の数字で終わる見出しを持つ本は、原稿に和字間隔を書いていなくても変わる。
既定のセットの名前は変えずに値を変えるので、同じ原稿を前の版と今の版で組むと違う PDF になる。

和字間隔で字下げした段落の先頭の始め括弧類は、今の②から①に変わる。
`first-line-indent` で字下げした段落は②のままなので、同じ本の中で二つの書き方を混ぜると、段落の先頭の括弧の位置がそろわない。
①は JIS X 4051 が採り、②は今では採る例が少ないと JLReq は書く（3.1.5）。
②を保ちたい利用者は、`ideographic-space` と `opening` の組に二分を置く規則を自分のセットに書ける。

番号と題のあいだは、番号が数字で終わる見出しで 1.25 em から 1 em になり、番号が漢字で終わる見出し（`第1章　`）の 1 em とそろう。
[golem-html ADR 0002](../../golem-html/adr/0002-heading-number-spacing.md) は、番号と題のあいだの区切りを和字間隔と決め、その空きの量は決めていない。

一つの原因を一つの ADR で扱った。
括弧類の二つの組だけを直す案もあるが、和字間隔を `j` に含めたことが、括弧類の組、欧文との組、伸びのすべての原因である。
括弧類だけを直すと、和字間隔は、ある規則では和文の字として扱われ、ある規則では外されるという、どちらでもない扱いになる。

InDesign の「行末約物半角」の値とは照合していない。
メンテナーは、InDesign の振る舞いが分からないときは JLReq の記述を採ると決めた（2026-11-08）。
InDesign が和字間隔を漢字と同じに扱うなら、名前を合わせたセットが InDesign と違う組み方になる。

## メンテナーが決めること

1. **括弧類との組（`」　`、`　「`）を JLReq に合わせるか**：推奨は、合わせることである。表 1 は二つの組をベタ組とし、InDesign の振る舞いは分からないので、2026-11-08 の決定により JLReq の記述を採る。Chrome の既定も、すでに 0 で組む。
   - 退けた案は、今のままとすることである。和字間隔で字下げした段落の始め括弧類が②で組まれ、`）　（` のような並びで括弧と括弧のあいだが 2 em になる。
2. **欧文との組（`　A`、`A　`）を同じ ADR で JLReq に合わせるか**：推奨は、合わせることである。原因が括弧類の組と同じであり、表 1 も空欄である。番号が数字で終わる見出しのすべてが変わるが、番号と題のあいだが番号の書き方によらず 1 em になる。
   - 退けた案は、欧文との組を残し、括弧類との組だけを変えることである。和字間隔が規則によって和文の字だったりそうでなかったりする。番号と題のあいだも、番号の最後の字が数字か漢字かで違うままである。
3. **和字間隔の前後の伸び（0.1zw）をなくすか**：推奨は、なくすことである。3.1.11 は、和字間隔の前後を、行の調整で字間を空けるのを避ける箇所とする。原因も同じである。
   - 退けた案は、伸びを残すことである。和字間隔で字下げした行や、和字間隔を並べた詩の行で、行の調整が字下げの幅を広げる。
4. **字下げの二つの書き方で組み方が違うこと**：推奨は、違いを受け入れ、仕様書と利用者のマニュアルに書くことである。原稿の字と字の組で空きを決める仕組みのまま、表 1 に合わせられる。
   - 退けた案は、段落の先頭の和字間隔に続く始め括弧類に `paragraph-start` の規則を当てることである（「実装しないこと」）。字の組のほかに、段落の先頭からの位置を見ることになる。
5. **実装の順**：推奨は、0039 と 0040 の実装がマージされた後に、この ADR を実装することである。三つの ADR は同じ規則の表とテストを変える。
