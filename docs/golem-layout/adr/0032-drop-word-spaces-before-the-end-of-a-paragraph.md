# ADR 0032: 段落の終わりと強制改行の前の語間の空白を、行分割の前に捨てる

ステータス: 採択→コードの空白（T3 と「実装すること」の 1 のコードの空白の文）は [golem-layout ADR 0037](0037-drop-spaces-of-code-before-the-end-of-a-paragraph.md)

## 文脈

仕様書の「既知の不具合」に、「段落の終わりの語間の空白の前の行末禁則」がある。
[golem-layout ADR 0028](0028-kinsoku-across-spaces-and-explicit-hyphens.md) の実装（[#670](https://github.com/tett23/golem/pull/670)）が、毎晩の列挙（[docs/adr/0209](../../adr/0209-line-breaking-invariants-by-exhaustive-small-inputs.md)）で見つけ、テストの既知の不具合の一覧（[`lineBugs`](https://github.com/tett23/golem/blob/6380b99853307e4d4f3e35e8a448a84ce879412d/modules/golem-layout/test/LineBreakInvariantsSpec.hs#L558-L566)）に載せた。
除いた入力は、部品 2 個までで 0、3 個までで 576 である。
ロードマップの項目は、後に箱がない空白に行末禁則を当てるか、段落の終わりの空白を捨てるかを、ADR で決めるよう求めている。

### 後に箱がない空白は、禁則の判定を通らない

`normalize` は、語間の空白の前後の二つの箱の組で禁則を判定する（[`Japanese.hs`](https://github.com/tett23/golem/blob/6380b99853307e4d4f3e35e8a448a84ce879412d/modules/golem-layout/src/Golem/Layout/Japanese.hs#L1160-L1168)）。
後の箱は [`nextBox`](https://github.com/tett23/golem/blob/6380b99853307e4d4f3e35e8a448a84ce879412d/modules/golem-layout/src/Golem/Layout/Japanese.hs#L1182-L1185) で探し、段落の終わりでは見つからないので、判定をしない。
段落の項目の最後には、行の終わりの三つの項目（罰点 10000、`fil` のグルー、罰点 −10000、[`lineEnd`](https://github.com/tett23/golem/blob/6380b99853307e4d4f3e35e8a448a84ce879412d/modules/golem-layout/src/Golem/Layout/Japanese.hs#L430-L431)）が付く。
空白のグルーの前は箱なので、空白は分割の候補のままである（[`isBreak`](https://github.com/tett23/golem/blob/6380b99853307e4d4f3e35e8a448a84ce879412d/modules/golem-layout/src/Golem/Layout/KnuthPlass.hs#L299-L302)）。

### 禁則の文字がなくても、空の最後の行ができる

テストの送りの表（golem-layout のテストの `LineBreakEnum`）で、2 字の行に次の段落を組んで確かめた（2026-11-08、origin/main の 6380b998）。

| 段落 | 行 |
| --- | --- |
| `あ「「 ` | `あ「「`、空の行 |
| `ああ ` | `ああ`、空の行 |
| `ああ` | `ああ` |

`ああ ` は禁則の文字を含まないが、空の最後の行を作る。
空白で分けずに段落の終わりで分けると、空白の幅の分だけ行長を超えるので、最適な分け方が空白での分割になる。
行末禁則を当てても、この行は直らない。
既知の不具合の一覧が `あ「「 ` の形だけを数えているのは、L3（行末禁則）の違反だけを除いているからであり、空の最後の行を判定する述語がないからである。

### 段落の終わりの空白は、原稿に現れる

原稿の行末の空白は、構文解析で除かれる。
`golem inspect --as ir` で確かめると、`いい ` の段落は `Text "いい"` になる。
ところが、段落の最後に内容を描かないインラインのコマンドを置くと、その前の空白が残る。
`ああ [index reading=あ: あ]` の段落は、`Text "ああ "` と `IndexMark` になる。
英語の段落の `He left. [index reading=x: x]` も同じである。
強制改行の `\` の前の空白は無視するので（[docs/markup.md](../../markup.md) の「強制改行」）、強制改行の前に空白が残るのは、同じく内容を描かないコマンドを挟んだ場合である。

### TeX は、段落の終わりの空白を捨てる

TeX は、段落を行に分ける前に、段落の最後の項目がグルーなら、それを除く（tex.web の §816）。
LaTeX の `\\` も、前の空白を `\unskip` で除いてから行を改める。
どちらも、行の終わりに来る空白は行の幅にも分割の候補にも数えない。

## 実装すること

### 1. 段落の終わりと強制改行の前の語間の空白を捨てる

`normalize` の後、行の終わりの項目（段落の終わりと強制改行の `lineEnd`）の前にある語間の空白のグルーを除く。

- 除くのは、語間の空白のグルー（`normalize` の `wordSpace` に当たるもの）と、[golem-layout ADR 0028](0028-kinsoku-across-spaces-and-explicit-hyphens.md) がその前に置いた罰点 `Penalty 0 infPenalty NoHyphen` である。
- 空白と行の終わりのあいだに箱がなければ除く。あいだに箱でない項目（アンカー）があっても、箱がなければ除く。
- コードの空白（伸びないグルー、[golem-layout ADR 0017](0017-spaces-inside-inline-code.md)）は除かない。背景を塗るので、紙面に見える。
- 空白より後ろを指すアンカー（索引、リンクの終わりなど）は、除いた後の項目の位置に合わせる（[`alignPositions`](https://github.com/tett23/golem/blob/6380b99853307e4d4f3e35e8a448a84ce879412d/modules/golem-layout/src/Golem/Layout/Japanese.hs#L307-L310) と同じ扱い）。

原稿の字は変えない。
HTML、EPUB、プレーンテキストの出力は、今のとおり空白を書く。
変わるのは PDF の行分割の項目だけである。

### 2. テストの既知の不具合の一覧から消す

`lineBugs` から「段落の終わりの語間の空白の前の行末禁則」と `breaksAtTrailingSpace` を消す。
一覧は空になる。

### 3. 空の最後の行を判定する不変条件を足す

[docs/adr/0209](../../adr/0209-line-breaking-invariants-by-exhaustive-small-inputs.md) の不変条件に、T1（下の「不変条件」）を足し、述語にして列挙で判定する。
`ああ ` の形は L3 に当たらないので、述語を足さなければ列挙で見つからない。

### 4. 文書

- 仕様書の「行分割」の節に、「段落の終わりと強制改行の前の語間の空白は、行分割の前に捨てる。コードの空白は捨てない」と、この ADR へのリンクを足す。
- 仕様書の「既知の不具合」から、項目を消す。
- 「行分割」の節の、既知の不具合の一覧の文（「今の一覧には、…の一つがある」）を、一覧が空であることに改める。
- ロードマップの「不変条件のテストで見つかった行分割の不具合」の項目を消す。

### 5. 出力の変化

段落の終わりか強制改行の前に、内容を描かないコマンドを挟んで空白を書いた段落だけが変わる。
空の最後の行がなくなるほか、空白が最後の行に残っていた段落では、中央揃えと行末揃えの最後の行の位置が、空白の幅に応じて変わりうる（コードから読んだ推定で、PDF では確かめていない）。
実装のプルリクエストで、golden、`scripts/visual/` の参照、二つのマニュアルと complex fixture の決定性のハッシュが変わるかを確かめ、説明に書く。

## 実装しないこと

- **段落の始まりの空白**：段落の最初の空白のグルーの前には箱がないので、分割の候補にならない（`isBreak`）。行の始まりの幅に数えるかは、この ADR では変えない。
- **段落の中ほどの空白の連なり**：二つ続けた空白は、今のとおり一つにまとめる（[`textPiecesAt`](https://github.com/tett23/golem/blob/6380b99853307e4d4f3e35e8a448a84ce879412d/modules/golem-layout/src/Golem/Layout/Japanese.hs#L617)）。
- **空白を書いたことの diagnostic**：golem-lint の規則も、golem-syntax の diagnostic も足さない。空白は、コマンドを挟んだ書き方から自然に生じ、出力を壊さなくなる。
- **全角の空白（U+3000）**：和文の字の箱であり、語間の空白ではない。紙面に見える空きなので、捨てない。

## 不変条件

行の幅を W とする。
「行の終わり」は、段落の終わりと強制改行の `lineEnd` の項目とする。

- **T1**：最後の行と、強制改行で終わる行は、箱を一つ以上持つ。ただし、原稿が箱を一つも作らない段落（空の段落）と、強制改行の後に箱のない行は除く。
- **T2**：行の終わりの直前の項目は、語間の空白のグルーでない。行の終わりと、その前の最後の箱のあいだに、語間の空白のグルーはない。
- **T3**：コードの空白のグルーは、行の終わりの前でも残る。
- **T4**：行の終わりの前に語間の空白がない段落の項目は、この ADR の前と同じである。
- **T5**：プレーンテキスト、HTML、EPUB の出力は、この ADR の前と同じである。

境界の入力：

| 量 | 調べる値 |
| --- | --- |
| 空白の前の箱 | 和文の字、始め括弧類、欧文の語、注の印、ルビ |
| 空白と行の終わりのあいだ | なし、索引のアンカー、リンクの終わり |
| 行の終わり | 段落の終わり、強制改行 |
| 空白の種類 | 語間の空白、エスケープした空白（`\ `）、コードの空白、全角の空白 |
| 段落の揃え | 両端揃え、行頭揃え、中央揃え、行末揃え |
| 行の残りの幅 | 空白の前でちょうど終わる、空白の幅だけ足りない |

## テスト設計

テストを先に書き、今の実装で失敗することを確かめてから実装する。
テストの名前には、T1 から T5 の番号を入れる。

- **T1、T2**：`LineBreakingSpec` で、2 字の行に `ああ ` と `あ「「 ` を組み、行が一つで、空の行がないこと。今は空の行ができるので失敗する。`ああ ` の項目が `ああ` と行の終わりの項目だけであること。
- **T1**：述語を足し、段 2 までのすべての入力で違反がないこと。段 3 は毎晩の `enum.yml` で確かめる。既知の不具合の一覧を消した後、段 3 で今の実装が違反を返すことを確かめる。
- **T3**：`[code: a ]` を段落の最後に置き、コードの空白のグルーが残ること。
- **T4**：[golem-layout ADR 0028](0028-kinsoku-across-spaces-and-explicit-hyphens.md) の K1 から K7 のテストが、そのまま通ること。
- **T5**：golem-driver のテストで、`ああ [index reading=あ: あ]` の段落のプレーンテキストと HTML の出力が、空白を含むこと。PDF では、索引の項目のページが変わらないこと。
- 中央揃え：`ああ ` を中央揃えの段落で組み、行の位置が `ああ` と同じであること。

## トレードオフ

原稿の字を、PDF の行分割の項目からだけ除く。
「出力を黙って変えない」に当たるかを考えた。
除く空白は行の終わりで捨てられる位置にあり、両端揃えの段落では、除いても紙面の字の位置が変わらない（空の行がなくなるのを除く）。
中央揃えと行末揃えでは、空白が最後の行に残っていれば、行の位置が空白の幅の半分か全部だけ動きうる。
これは空白を行の幅に数えていた今の振る舞いの誤りであり、書き手が空白で位置をずらす意図を持って書く書き方ではない。

後に箱がない空白に行末禁則を当てる案は、`あ「「 ` の L3 の違反だけを直し、`ああ ` の空の行を残す。
空白の分割を禁じれば、空白の幅が行に残り、行長を超える行になる。
空白を除けば、どちらも直る。

## メンテナーが決めること

1. **段落の終わりの空白をどうするか**：推奨は、行分割の前に捨てることである。TeX と同じ扱いであり、禁則の文字のない `ああ ` の空の行も直る。
   - 退けた案の一つは、後に箱がない空白に行末禁則を当てることである。`ああ ` の空の行が残る（「文脈」の表）。
   - 二つめは、段落の終わりの空白の分割をつねに禁じることである。空白の幅が最後の行に残り、行長いっぱいの行が空白の分だけはみ出して G07105 になる。見えない空白で警告が出る。
   - 三つめは、構文解析か評価で、段落の終わりの空白を原稿から除くことである。HTML と EPUB の出力も変わり、インラインのコマンドの後に続く原稿（プラグインの出力など）でも同じ扱いを保つには、各所で除く必要がある。
2. **強制改行の前の空白も捨てるか**：推奨は、捨てることである。強制改行は段落の終わりと同じ行の終わりの項目を置く（[docs/adr/0016](../../adr/0016-hard-line-breaks.md)、`PForcedBreak` の `lineEnd`）ので、行の終わりの前の空白は段落の終わりと同じく空の行を作りうる。LaTeX の `\\` も前の空白を除く。
   - 退けた案は、段落の終わりだけにすることである。同じ項目の並びに、二つの扱いが残る。
3. **空の行を判定する不変条件を足すか**：推奨は、T1 を足すことである。今の述語は L3 の違反しか見ないので、`ああ ` の空の行を見逃してきた。
   - 退けた案は、述語を足さず、手で選んだ段落のテストだけで確かめることである。列挙が同じ形の別の入力を見つけられない。
