# ADR 0028: 禁則と分離禁止を、語間の空白と明示のハイフンの分割の候補をまたいで当てる

ステータス: 採択

## 文脈

[docs/adr/0209](../../adr/0209-line-breaking-invariants-by-exhaustive-small-inputs.md) の列挙は、行頭禁則、行末禁則、分離禁止（L2、L3、L4）を破る分割を二つの形で見つけた。
どちらも仕様書の「既知の不具合」に載り、テストの既知の不具合の一覧（[`lineBugs`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-layout/test/LineBreakInvariantsSpec.hs#L505-L531)）で除かれている。

- **語間の空白の隣の禁則と分離禁止**：2 字の行に `あ「 いい` を組むと、1 行めが `あ「` で終わる。`あ 〜` では 2 行めが `〜` で始まる。`… …` は二つの `…` のあいだで分かれる。除いた入力は、部品 2 個までで 432、3 個までで 64,114 である。
- **明示のハイフンの後の分割と両用の字の禁則**：`[lang en]` の区間に `…—…` を書き、前に `あ` を置いて 2 字の行で組むと、`—` と `…` のあいだで分かれる。`…—”` では 2 行めが `”` で始まる。除いた入力は、部品 3 個までで 448 である。

二つは別々の項目として載っているが、コードの原因は一つである。

### 禁則は、隣り合う二つの箱のあいだでしか調べていない

禁則の罰点は、[`normalize`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-layout/src/Golem/Layout/Japanese.hs#L1102-L1206) が置く。
`normalize` は項目を前から読み、直前の箱を状態として持ち、箱が来るたびに直前の箱との組で禁則を判定する（[`noBreak`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-layout/src/Golem/Layout/Japanese.hs#L1179-L1183)）。
ところが、箱でも `[aki]` でもない項目が来ると、状態を段落の始まり（`AtStart`）に戻す（[`Japanese.hs`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-layout/src/Golem/Layout/Japanese.hs#L1133)）。
次の箱は、前に箱がないものとして扱われ、禁則を調べない。

この「箱でない項目」に、分割の候補になる項目が二つある。

- **語間の空白**：`PSpace` のグルー（[`Japanese.hs`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-layout/src/Golem/Layout/Japanese.hs#L819-L823)）。Knuth と Plass の規則では、箱の直後のグルーは分割の候補である（[`isBreak`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-layout/src/Golem/Layout/KnuthPlass.hs#L291-L294)）。
- **明示のハイフンの罰点**：[`wordItems`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-layout/src/Golem/Layout/Japanese.hs#L1012-L1047) は、語をハイフンとダッシュの連なりの後で要素に分け（[`explicitParts`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-layout/src/Golem/Layout/Japanese.hs#L1052-L1066)）、要素のあいだに罰点 `explicit-hyphen-penalty`（既定 50）を置く。

どちらの候補でも、その前の字と後の字の組は禁則の判定を通らない。
`「` の後の空白で分ければ `「` が行末に残り、`—` の後の罰点で分ければ `”` が行頭に来る。

### 空白をまたぐ禁則は、JLReq がそのまま決める

JLReq の行頭禁則（3.1.7）と行末禁則（3.1.8）は、行の端に来る字を定める規則である。
語間の空白は、行で分けた位置では捨てられ、どちらの行にも残らない（[docs/adr/0209](../../adr/0209-line-breaking-invariants-by-exhaustive-small-inputs.md) の L10）。
そのため、`「` の後の空白で分けると、行の端の字は `「` になり、3.1.8 に反する。
空白を挟むかどうかは、行の端の字を変えない。
仕様書の「行頭禁則の文字の前と、始め括弧類の後ろでは改行しない」も、空白があるときを除いていない。

分離禁止（3.1.10）は事情が違う。
JLReq は、続けて並ぶ分離禁止文字のあいだで分けないと定める。
`… …` の二つの `…` は、あいだに空白があるので、続けて並んでいない。
読み手にも、一続きの記号ではなく、二つの記号に見える。
仕様書の「分離禁止文字どうしのあいだでは改行しない」と [docs/adr/0209](../../adr/0209-line-breaking-invariants-by-exhaustive-small-inputs.md) の L4 は、空白を挟む場合を区別していない。

### 明示のハイフンと両用の字の禁則は、仕様書が優先を書いていない

明示のハイフンの直後を分割の候補にする規則（[golem-layout ADR 0008](0008-explicit-hyphens.md)）は、候補の後の字を見ない。
一方、仕様書の「両用の文字」の節は、欧文の区間の両用の文字の隣での改行を、その字の和文の文字クラスの禁則に従わせる（[docs/adr/0187](../../adr/0187-inline-language-switch.md)）。
`—` は両用の文字で、和文の文字クラスは分離禁止文字、`”` は終わり括弧類である。
二つの規則は、`—` の直後で衝突する。

区間の外でも同じことが起きる。
区間の外の語の `”` は、`charClass` で終わり括弧類になる（[`CharClass.hs`](https://github.com/tett23/golem/blob/4c808d072df6918bf20ab57fd97eb7e75005f38c/modules/golem-layout/src/Golem/Layout/CharClass.hs#L75-L86)）。
`a—”` は `—` の後で分けられ、`”` が行頭に来る。

欧文の組版でも、閉じ引用符で行を始めることはない。
Golem の欧文の語は、引用符を語の箱に含めるので（仕様書の「行分割」の節）、引用符の前で分かれる経路は、この明示のハイフンの候補のほかにない。
明示のハイフンの規則が引用符の前の分割を意図していたとは読めない。

## 実装すること

### 1. `normalize` が、空白と明示のハイフンをまたいで直前の箱を持つ

`normalize` の状態に、語間の空白のグルーと明示のハイフンの罰点（`Penalty _ _ ExplicitHyphen`）をまたいだ直前の箱を持たせる。
ほかの項目（強制の改行、パターンの分綴の罰点、コードの空白）では、今のとおり段落の始まりに戻す。

次の箱が来たら、またいだ直前の箱との組で、禁則の部分だけを判定する。

- 行頭禁則：次の箱の最初の字のクラスが `lineStartProhibited`（`kinsoku` の strict と loose を今のとおり見る）。
- 行末禁則：直前の箱の最後の字のクラスが `lineEndProhibited`。
- 分離禁止：明示のハイフンをまたぐときに限り、二つの字がどちらも分離禁止文字。語間の空白をまたぐときは見ない（決めること 2）。

クラスは、今の `between` と同じく `breakClass` で引く。
欧文の区間の両用の字は、その字の和文の文字クラスで判定する。
欧文の語どうしを分けない規則（`bcExpandable` の二つの箱）は、またいだ組には当てない。
語間の空白で語を分けられなくなるからである。

### 2. 禁則に当たる候補を消す

判定が真なら、候補を消す。

- 語間の空白：グルーの直前に `Penalty 0 infPenalty NoHyphen` を置く。直前が罰点のグルーは分割の候補でなくなり（`isBreak`）、空白の幅と伸縮は変わらない。
- 明示のハイフン：罰点 `explicit-hyphen-penalty` を除く。二つの要素の箱は隣り合い、あいだで分けられなくなる。要素ごとのパターンの分綴（[docs/adr/0179](../../adr/0179-lines-ending-in-explicit-hyphens.md)）は、今のとおり要素ごとに当てる。

和欧間の空きとアキ量のセットの空きは、どちらの場合も足さない。
足すかどうかは、この ADR では変えない（空白を挟む和欧間は [docs/adr/0222](../../adr/0222-line-breaking-points-the-invariants-did-not-decide.md) で決める）。

### 3. テストの既知の不具合の一覧から二つを消す

`lineBugs` から「語間の空白の隣の禁則と分離禁止」と「明示のハイフンの後の分割と両用の字の禁則」の二つの項目と、`breaksAtSpace`、`breaksAtExplicitHyphen` を消す。
残るのは「字幅の伸縮の刻みで行長を超える行」（[golem-layout ADR 0029](0029-expansion-steps-never-overflow-the-line.md) で直す）だけである。

### 4. 不変条件の L4 の読み方

[docs/adr/0209](../../adr/0209-line-breaking-invariants-by-exhaustive-small-inputs.md) の L4 を、「隣り合う分離禁止文字どうしのあいだ（語の中の明示のハイフンの候補を含む）で行を分けない。語間の空白を挟んだ二つの分離禁止文字のあいだは分けてよい」と読む。
述語 `l4Inseparable` を、この読み方に改める。
採択したら、[docs/adr/0209](../../adr/0209-line-breaking-invariants-by-exhaustive-small-inputs.md) のステータスの行に「（L4 の読み方）は golem-layout ADR 0028」を足す。

### 5. 文書

- 仕様書の「行分割」の節の禁則の段落に、「行頭禁則と行末禁則は、語間の空白と、欧文の語の明示のハイフンの後の分割の候補にも当てる。分離禁止は、隣り合う字にだけ当てる」と、この ADR へのリンクを足す。
- 明示のハイフンの段落に、「候補の後の字が行頭禁則の文字なら、またはハイフンかダッシュと後の字がどちらも分離禁止文字なら、候補を置かない」を足す。
- 仕様書の「既知の不具合」から、二つの項目を消す。
- 「行分割」の節の、既知の不具合の一覧の文（「今の一覧には、…の三つがある」）を改める。
- ロードマップの「不変条件のテストで見つかった行分割の不具合」から、二つを消す。

### 6. 出力の変化

`「 ` や ` 」` のように、空白の隣に禁則の文字を置いた原稿だけが変わる。
実装のプルリクエストで、golden、`scripts/visual/` の参照、二つのマニュアルと complex fixture の決定性のハッシュが変わるかを確かめ、変われば説明に書く。
変わらなければ、変わらないことを書く。

## 実装しないこと

- **インラインのコードと URL の空白**：コードの空白（[golem-layout ADR 0017](0017-spaces-inside-inline-code.md)）と URL の改行（[golem-layout ADR 0018](0018-url-line-breaks.md)）は、それぞれの規則で分ける。[docs/adr/0209](../../adr/0209-line-breaking-invariants-by-exhaustive-small-inputs.md) の列挙の外にあり、ここでは変えない。
- **パターンの分綴の罰点をまたぐ禁則**：パターンの分綴は、前に 2 字、後に 3 字の欧文の字を残すので、両用の字の隣に候補が来ない。[docs/adr/0222](../../adr/0222-line-breaking-points-the-invariants-did-not-decide.md) で、パターンが欧文の字だけを見るようにした後も同じである。
- **空白をまたぐ和欧間の空き**：[docs/adr/0222](../../adr/0222-line-breaking-points-the-invariants-did-not-decide.md) で決める。
- **欧文の組版の規則（スペースを挟んだダッシュで行を始めない、など）**：和文の文字クラスの禁則のほかの規則は足さない。
- **禁則で分けられない字の並びが行長より長い場合**：はみ出す行のまま、[ADR 0210](../../adr/0210-warn-overfull-lines-in-build.md) の G07105 で知らせる。

## 不変条件

行の幅を W とする。
「またいだ組」は、語間の空白のグルー一つか、明示のハイフンの罰点一つだけを挟んで並ぶ二つの箱の、前の箱の最後の字と後の箱の最初の字の組とする。

- **K1**：またいだ組の後の字が行頭禁則の文字なら、そのあいだで行を分けない。ただし、行長に収まる分割がない行（L5 の例外）は除く。
- **K2**：またいだ組の前の字が始め括弧類なら、そのあいだで行を分けない。例外は K1 と同じである。
- **K3**：明示のハイフンの罰点をまたいだ組の二つの字がどちらも分離禁止文字なら、そのあいだで行を分けない。
- **K4**：語間の空白をまたいだ組の二つの字がどちらも分離禁止文字で、K1 と K2 に当たらないなら、空白は今のとおり分割の候補である。
- **K5**：禁則の判定は、欧文の区間の両用の字を、その字の和文の文字クラスで行う（[docs/adr/0187](../../adr/0187-inline-language-switch.md)）。
- **K6**：K1 から K3 に当たらない語間の空白と明示のハイフンの候補は、この ADR の前と同じ項目のままである。空白の幅と伸縮、明示のハイフンの罰点の値は変わらない。
- **K7**：消した候補の位置にも、和欧間の空きとアキ量のセットの空きを足さない。

境界の入力：

| 量 | 調べる値 |
| --- | --- |
| 挟む項目 | 語間の空白一つ、二つ続けて書いた空白（一つにまとめる）、明示のハイフンの罰点、パターンの分綴の罰点（変わらない） |
| 前の字のクラス | 始め括弧類、分離禁止文字、ハイフン類、欧文の字 |
| 後の字のクラス | 終わり括弧類、句点類、ハイフン類（`〜`）、長音記号（strict と loose）、分離禁止文字、欧文の字 |
| 区間の言語 | なし、`en`、`ja` |
| 行の残りの幅 | 候補の前でちょうど終わる、候補の前の字で一つ足りない |
| 禁則の字の続き | 1、W、W + 1（はみ出す行になる） |

## テスト設計

テストを先に書き、今の実装で失敗することを確かめてから実装する。
テストの名前には、K1 から K7 の番号を入れる。

- 列挙：実装すること 3 の二つの項目を `lineBugs` から消し、部品 2 個までのすべての入力のテストが、今の実装で L2、L3、L4 の違反を返して失敗することを確かめる。部品 3 個までは毎晩の `enum.yml` で確かめる。
- L4 の述語：`… …` を空白で分けた出力に違反を返さず、`[lang en: …—…]` を `—` の後で分けた出力に違反を返すこと（実装すること 4）。
- 手で選んだ段落（`LineBreakingSpec`）：文脈の最も小さい例の五つ（`あ「 いい`、`あ 〜`、`… …`、`…—…`、`…—”`）を 2 字の行で組み、K1 から K4 のとおりに分かれること。`… …` は二つの `…` のあいだで分かれてよいこと。
- K6：禁則に当たらない空白（`a b`）と明示のハイフン（`lime-tree`）の項目が、この ADR の前と同じであること。
- K5：区間の外、`en`、`ja` の区間のそれぞれで、`“ a` と `a ”` の分け方を確かめる。
- K7：消した空白の候補の前後で、項目のグルーが空白のグルー一つだけであること。

## トレードオフ

二つの既知の不具合を、一つの ADR で直す。
原因が `normalize` の状態の戻し方の一つであり、直す場所も一つだからである。
明示のハイフンの側には、優先を決める判断が一つ多くある（決めること 1）。
二つを別の ADR にすると、同じ状態の変更を二度に分けて書き、先に入れたほうの ADR が後のほうの候補を見ないことになる。

語間の空白で分けられなくなる位置が増えるので、空白の隣に禁則の文字を置いた行は、前より詰まるか空く。
そういう原稿は和文では少ないが、フランス語の区間の `« Bonjour »` は、`«` の後と `»` の前の空白で分けなくなる。
これはフランス語の組版の慣習（引用符の内側の空白で改行しない）にも合う。

分離禁止を空白の向こうに当てないので、`… …` は今のとおり分かれうる。
仕様書と L4 の文を読み方に合わせて改めることになる。

## メンテナーが決めること

1. **明示のハイフンの候補と、両用の字の禁則のどちらを優先するか**：推奨は、禁則を優先し、候補の後の字が行頭禁則の文字か、ハイフンかダッシュと後の字がどちらも分離禁止文字なら、候補を置かないことである。欧文の組版でも閉じ引用符で行を始めず、明示のハイフンの規則（[golem-layout ADR 0008](0008-explicit-hyphens.md)）が引用符の前の分割を意図したとは読めない。
   - 退けた案の一つは、明示のハイフンの候補を優先し、仕様書に例外として書くことである。区間の外でも `a—”` で `”` が行頭に来る。JLReq の 3.1.7 にも、欧文の組版の慣習にも反する。
   - 二つめは、`—` の後の候補だけを、両用の字の隣で置かないことである。`‐` と `–` の後の `”` も同じく行頭に来るので、`—` だけに限る理由がない。
2. **空白を挟んだ二つの分離禁止文字のあいだで分けるか**：推奨は、分けてよいとし、L4 と仕様書の文を「隣り合う分離禁止文字」に改めることである。JLReq の 3.1.10 は、続けて並ぶ分離禁止文字を一続きの記号として扱う規則であり、空白を挟んだ二つは一続きではない。
   - 退けた案は、空白の向こうにも分離禁止を当てることである。`… …` のように意図して空けた二つの記号を、一つの記号と同じに扱い、行の調整に使える位置を減らす。JLReq はこの場合を定めておらず、強める根拠がない。
3. **空白をまたぐ行頭禁則と行末禁則を当てるか**：推奨は、当てることである。空白は行で分けた位置で捨てられるので、行の端の字は禁則の文字になり、JLReq の 3.1.7 と 3.1.8 にそのまま反する。
   - 退けた案は、空白を書いた原稿は書き手が分割を許したものとし、仕様書に例外として書くことである。空白は字間の調整のために書かれることが多く、改行の許可を意味しない。黙って禁則を破る出力が残る。
4. **二つの既知の不具合を一つの ADR で直すか**：推奨は、一つで直すことである（「トレードオフ」）。
   - 退けた案は、仕様書の「既知の不具合」の項目ごとに ADR を分けることである。同じ状態の変更を二度書く。
