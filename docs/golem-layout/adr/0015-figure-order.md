# ADR 0015: 図版を原稿の順にページに置く

ステータス: 採択→回した図版の待ちは [golem-driver ADR 0034](../../golem-driver/adr/0034-fit-figures-to-column.md)

## 文脈

仕様書の「既知の不具合」に、図版の順序の入れ替わりがある。
ページに収まった図版が、それより前に次のページへ送られた図版より先に置かれる。
[golem-layout ADR 0003](0003-pagination-and-s2.md) は、収まらない図版を次のページの先頭に送り、送った図版より後の本文を図版の前に詰めてよいと定めたが、後の図版の扱いは定めていない。
[docs/roadmap.md](../../roadmap.md) の「既知の不具合の修正」は、これを v0.1.0-rc3 の項目にし、送った図版が待っているあいだは後の図版もその後に並べる直し方を案として挙げている。

図版には章ごとの図番号が原稿の順に振られる（仕様書の「図版」の節）。
順序が入れ替わると、「図 3-2」が「図 3-1」より前のページに出る。
本文の参照も原稿の順を前提に書かれるので、読み手には誤りに見える。

### 今の振る舞い

`Golem.Layout.Paginate` の `paginateIn` で、回り込ませない図版（`FFigure`）は、今の段の残りに収まればそこに置き、収まらなければ待ちの列（`sDeferred`）の末尾に加える。
待ちの列は、次の段に進むとき（`advance`）に `placeDeferred` が先頭から順に置く。
図版を置くかどうかの判定は、待ちの列が空かどうかを見ない。

回り込ませる図版（`FWrapped`）は待ちの列を使わない。
収まらなければ、脇の行とともに次の段に進む（[golem-layout ADR 0004](0004-wrapped-figures.md)）。
これも待ちの列を見ないので、待っている図版より先に置かれうる。

小さな例で確かめた（origin/main の e16ab1e、`cabal repl golem-layout`）。

```haskell
-- 一段、一ページ 5 行: 3 行の後に 3 行の図版 98、1 行の段落、1 行の図版 99
paginate 1 5 [FParagraph (lines' 0 3), FFigure 98 3 [] [], FParagraph (lines' 10 1), FFigure 99 1 [] []]
-- 1 ページ: SLine 0..2, SLine 10, SFigure 99
-- 2 ページ: SFigure 98

-- 二段組み: 図版 99 が 1 段め、図版 98 が 2 段めに置かれる
paginate 2 5 [...同じ流れ...]
-- 1 ページ 1 段め: SLine 0..2, SLine 10, SFigure 99
-- 1 ページ 2 段め: SFigure 98

-- 一段、一ページ 6 行: 4 行の図版 98 の後に、2 行の回り込みの図版 99
paginate 1 6 [FParagraph (lines' 0 3), FFigure 98 4 [] [], FWrapped 99 2 [] [] (lines' 10 2), FParagraph (lines' 20 1)]
-- 1 ページ: SLine 0..2, SWrapped 99, SLine 10, SLine 11, SLine 20
-- 2 ページ: SFigure 98
```

三つの例のどれでも、図版 99 が図版 98 より先に置かれる。

### ほかの組版システム

LaTeX の浮動体は、同じ種類（figure、table）の浮動体の順序を保つ。
先に書いた figure が置けずに待っているあいだは、後の figure も待つ（Lamport の LaTeX の手引きの浮動体の配置の規則による。記憶によるもので、節の番号は確かめていない）。
InDesign のアンカー付きオブジェクトは本文の流れに結び付いて動くので、順序は入れ替わらない。
ただし InDesign には、収まらない図版を後に送って本文を前に詰める仕組みがなく、送るなら本文も一緒に送る。
Golem の図版は、本文を前に詰める点で LaTeX の浮動体に近いので、順序についても LaTeX にそろえる。

### 回り込みの図版と段組み

回り込みの図版は脇の行と一体であり、待ちの列に入れて本文の後に回すことはできない。
順序を保つには、待っている図版があるあいだは、回り込みの図版を脇の行とともに、待っている図版の後に置くしかない。
収まらない回り込みの図版を次のページに送り、前のページの残りを空白にする扱いは、すでに仕様書の「図版」の節にある。
この ADR は、同じ送り方を、待っている図版がある場合にも使う。

段組みの版面（[docs/adr/0018](../../adr/0018-multi-column-layout.md)）では、送る先は次のページではなく次の段である。
図版の順序は、段をたどる順（ページの中の段の順、次にページの順）で数える。
段組みの版面では回り込みの図版を使えない（G0726）ので、段組みで考えるのは回り込ませない図版だけである。

### メンテナーが決めたこと

- 待っている図版があるときの回り込みの図版は、待っている図版の後に送る。今の段の残りは空白になる。順序の入れ替わりは、読み手が図番号と紙面の順を追えなくなるので、回り込みの図版にも例外を設けない。
- 図版の待ちの数に上限を設けない。LaTeX は待ちの浮動体が多すぎるとエラーにするが、Golem は待ちの列に上限を持たず、次の段の先頭から順に置き続ける。本文と図版が大きく離れても組める。問題が見つかれば、修正の ADR で上限を検討する。

## 実装すること

### 図版の順序の規則（golem-layout）

[golem-layout ADR 0003](0003-pagination-and-s2.md) の「図版」の規則に、次の規則を加える。

- 図版は、回り込みの有無にかかわらず、原稿の順に段に置く。送った図版より後の図版を、送った図版より前の段や、同じ段の前の位置に置かない。
- 送った図版より後の本文は、今までどおり図版の前に詰めてよい。

### 回り込ませない図版

`place` の `FFigure` の場合に、待ちの列が空でなければ、収まるかどうかにかかわらず待ちの列の末尾に加える場合を足す。

```haskell
FFigure i n labels marks
  | not (null (sDeferred st)) -> st {sDeferred = sDeferred st <> [f]}
  | n <= free st || isEmpty st -> putSlot st n (SFigure i) labels marks
  | otherwise -> st {sDeferred = sDeferred st <> [f]}
```

- 待ちの列は、今までどおり `advance` の `placeDeferred` が先頭から順に置き、置けない図版で止まる。止まった図版より後の図版を飛ばして置くことはないので、列の中の順序は保たれる。
- 待ちの列は本文の流れより先に置かれるので、次の段の先頭には、待っていた図版が原稿の順に並び、その後に本文が続く。

### 回り込ませる図版

`place` の `FWrapped` の場合に、待ちの列が空でなければ、待ちの列が空になるまで次の段に進んでから、今の規則で置く。

```haskell
FWrapped i n labels marks beside ->
  let st0 = flushFigures st   -- 待ちの列が空になるまで nextColumn
      ...                      -- 以下は今の規則を st0 に当てる
```

`flushFigures` は、`flushDeferred` と違い、続きの脚注（`sPendingNotes`）を待たない。
続きの脚注は待っている図版と並べて次の段に置けるので、待つ理由がないためである。
待ちの列の先頭の図版は、何も置いていない段（`isEmpty`）では必ず置かれる。
続きの脚注が段を使っている間は置けないことがあるが、続きの脚注は段を進むごとに減るので、`flushFigures` は有限の回数で終わる。

### 出力への影響

順序が入れ替わる配置があった本だけ、PDF の図版の位置と、それに続く改ページが変わる。
リポジトリの中で図版を持つ本は二つのマニュアル（`manual`、`manual-dev`）だけであり、golem-driver の fixture と決定性の検査の PDF の入力は図版を持たない。
二つのマニュアルは、決定性の検査（`scripts/determinism.sh`）の入力でもある。
今のマニュアルに入れ替わりがあるかは確かめていないので、実装の後にマニュアルを組み、図番号の順と PDF の図版の順が一致することを目で確かめる。
CI の `determinism` ジョブは二つのアーキテクチャの出力を比べるだけなので、出力が変わってもジョブの設定は変えない。

### ドキュメント

- 仕様書の「既知の不具合」から「図版の順序」の項目を消す。
- 仕様書の「図版」の節に、図版を原稿の順に置くこと、待っている図版があるあいだは後の図版も送ること、回り込みの図版は待っている図版の後に脇の行とともに置くことを書き足す。この ADR へのリンクを付ける。
- [docs/roadmap.md](../../roadmap.md) の「既知の不具合の修正」から「図版の順序」の項目を消す。
- 利用者のマニュアルの `manual/appendices/i-known-issues.gm` から「図版の順序が入れ替わる」の項目を消す。`manual/appendices/h-roadmap.gm` に同じ項目があれば消す。使い手のマニュアルで図版の送りを説明している箇所があれば、順序を保つことを書き足す。
- [golem-layout ADR 0003](0003-pagination-and-s2.md) のステータスの行に、図版の順序の規則をこの ADR で加えたことを、この ADR へのリンクで書き足す。
- [golem-layout ADR 0004](0004-wrapped-figures.md) のステータスの行に、待っている図版があるときの回り込みの図版の送りをこの ADR で定めたことを書き足す。

## 実装しないこと

- 表とコードブロックの順序。表とコードブロックは送らずに本文の流れの中で分けて置くので、入れ替わりが起きない。
- 図版を送る先の選択（ページの上、下、図版だけのページ）。LaTeX の `[htbp]` に当たる指定は持たない。待っていた図版は、今までどおり次の段の先頭に置く。
- 待ちの図版の数の上限（「メンテナーが決めたこと」）。
- 見出しと図版の先読み。見出しの直後に図版があり、その図版が待ちの列に入る場合、見出しの `keep` は図版の格子の数で判定されるが、図版は見出しの後に置かれない（「トレードオフ」）。

## テスト設計

実装の前に `modules/golem-layout/test/Main.hs` の図版のテストか `PaginateSpec.hs` に足し、今の実装で失敗することを確かめる。

- 一段、一ページ 5 行で、3 行の段落、3 行の図版 98、1 行の段落、1 行の図版 99 の順に置くと、1 ページは段落の 4 行で、2 ページは図版 98、図版 99 の順になる。今の実装では図版 99 が 1 ページに置かれるので失敗する。
- 同じ流れを二段組みで置くと、1 ページの 2 段めに図版 98、図版 99 の順で置かれる。
- 一段、一ページ 6 行で、3 行の段落、4 行の図版 98、脇に 2 行を持つ 2 行の回り込みの図版 99、1 行の段落の順に置くと、1 ページは段落の 3 行だけで、2 ページは図版 98、回り込みの図版 99 とその脇の 2 行の順になり、最後の 1 行は 3 ページに置かれる。
- 待ちの列の二つの図版が一つの段に収まらない場合に、先の図版、後の図版の順に別の段に置かれる（既存の「two figures sent on that do not fit one page together go to successive pages」がそのまま通る）。
- プロパティテスト：図版と回り込みの図版と段落を混ぜたランダムな流れで、`paginate` の出力の `SFigure` と `SWrapped` の id を段の順、段の中の位置の順に並べたものが、流れの中の順と一致する。段数は 1 と 2 で試す。
- プロパティテスト：同じ流れで、すべての図版とすべての行が、ちょうど一度ずつ出力に現れる（既存の不変条件のテストに図版を含める）。
- 改ページ（`FBreak`）の後に待っていた図版が置かれる既存のテストが、そのまま通る。

### 自動テストにしない確かめ方

- 二つのマニュアルを組み、各章の図番号の順と PDF の図版の順が一致することを目で確かめる。

## トレードオフ

待っている図版があるあいだは後の図版も送るので、収まるはずの図版が次のページに回り、図版と、それを参照する本文が離れることがある。
図番号の順と紙面の順の一致を優先した。
LaTeX も同じ選択をしている。

待っている図版があるときの回り込みの図版は、脇の行とともに次の段に送るので、今の段の残りが空白になる。
回り込みの図版と待っている図版が近くに続く原稿でだけ起きる。

見出しの直後で改ページしない規則は、見出しの次の図版の格子の数を先読みの量にする。
その図版が待ちの列に入る場合は、図版は見出しの後に置かれず、見出しの後には本文が続く。
先読みの量は図版の格子の数のままなので、見出しを必要以上に次の段に送ることがある。
先読みが段の状態（待ちの列）を見ない今の作りを保ち、この ADR では直さない。
