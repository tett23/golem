# ADR 0039: 既定のアキ量のセットで、続く始め括弧類の字間と、中点類と括弧類の字間を JLReq に合わせる

ステータス: 採択→不変条件 B4 の例外の組に中点類の後ろの終わり括弧類と句読点を足したのは [golem-layout ADR 0040](0040-put-a-quarter-em-after-a-middle-dot-before-closing-brackets-and-full-stops.md)、不変条件 B4 の例外の組に和字間隔の組を足したのは [golem-layout ADR 0041](0041-take-the-ideographic-space-out-of-japanese-characters-in-the-default-aki-set.md)

## 文脈

[docs/adr/0239](../../adr/0239-decide-the-conditions-of-the-outlined-figure-check-and-the-punctuation-of-figure-sources.md) を書くときに、既定のアキ量のセット `gyomatsu-yakumono-hankaku` が、続く二つの始め括弧類（`（「`）のあいだに二分を置くことが分かった。
JLReq は、この字間をベタ組とする。
0239 は、本文の組版の問いとして、これを別に扱うことにした（0239 の「実装しないこと」）。
この ADR は、その問いを扱う。
調べると、同じ形の食い違いがほかに二つの組にあった。

### 既定のセットの規則

Golem は、約物の字を半角の箱として置き（[`punctSpace`](https://github.com/tett23/golem/blob/4b3ffcb406d8edee9be3e6a5cd78667b564e3f4e/modules/golem-layout/src/Golem/Layout/Japanese.hs#L796-L807)）、字の間の空きをアキ量のセットの規則で決める。
既定のセットの規則は [`defaultAkiSet`](https://github.com/tett23/golem/blob/4b3ffcb406d8edee9be3e6a5cd78667b564e3f4e/modules/golem-layout/src/Golem/Layout/Aki.hs#L78-L106) にある。
規則の値は、[docs/adr/0019](../../adr/0019-aki-settings.md) の「組み込みのセット」の表のとおりである。
0019 は、この表を、それより前の `normalize` の組み方（約物の前後の空きを隣どうしで合わせる `combined`）と同じになるように決めた。
`combined` は、前の字の後ろの空きと後の字の前の空きのどちらかが 0 なら、もう一方をそのまま残し、中点類が関わる組では両方を足していた。

このため、次の三つの組で、JLReq がベタ組にする側の空きが残る。

- 規則 `(j <> w <> o, o, Aki 0 (1 / 2) (1 / 2))` は、前の字の集まりに始め括弧類（`o`）を含む。始め括弧類の後ろの始め括弧類にも、前に二分が付く。
- 規則 `(p, m, Aki 0 (3 / 4) (3 / 4))` は、終わり括弧類の後ろの二分と中点類の前の四分を足す。
- 規則 `(m, o, Aki 0 (3 / 4) (3 / 4))` は、中点類の後ろの四分と始め括弧類の前の二分を足す。

`p` は終わり括弧類と句点類と読点類をまとめたクラスの集まりである。
句点類と読点類の後ろの中点類は、JLReq でも二分四分なので（下の表の注 5）、食い違うのは終わり括弧類の後ろだけである。

### JLReq の規定

JLReq の 3.1.4（始め括弧類，終わり括弧類，読点類，句点類及び中点類が連続する場合の配置方法）は、次のように定める。

- 始め括弧類の後ろに始め括弧類が続くときは、その字間をベタ組とし、前の始め括弧類の前を原則として二分アキとする（図 69 の⑤）。
- 終わり括弧類の後ろに中点類が続くときは、後ろの中点類の前と後ろを原則として四分アキとする（図 69 の⑦）。終わり括弧類の後ろの二分は残らない。
- 中点類の後ろに始め括弧類が続くときは、前の中点類の後ろを原則として四分アキとする（図 69 の⑦）。始め括弧類の前の二分は残らない。

付録 B の表 1（文字間の空き量）も同じ値を持つ。
cl-01 の行の cl-01 の欄は空欄（ベタ組）、cl-02 の行の cl-05 の欄は「1/4 af」、cl-05 の行の cl-01 の欄は「1/4 be」である。
句点類と読点類の後ろの中点類（cl-06、cl-07 の行の cl-05 の欄）は注 5 で、句点類か読点類の二分と中点類の四分の和とする。
JLReq は、この節の規則を「それぞれの後ろ又は前を二分アキ……にし，全角の幅にすると空き量が目立ち，体裁がよくない」ためとする（図 70）。

### 表 1 とのほかの食い違い

既定のセットのすべての組を表 1 と照らすと、この ADR の三つの組のほかに、次の組が違った。
どれも原因が別であり、それぞれ別の ADR で扱う（「メンテナーが決めること」の 3）。

| 組 | Golem | 表 1 | 原因 |
| --- | --- | --- | --- |
| 中点類の後ろの終わり括弧類、句点類、読点類（`・」`、`・。`） | 0 | 四分（cl-05 の行、1/4 be） | 規則がない。中点類の後ろの四分を、後の字が `P` のとき置いていない |
| 終わり括弧類の後ろの和字間隔（`」　`） | 二分 | ベタ（cl-02 の行の cl-14 の欄が空欄） | 和字間隔を `j` に含め、`(p, j <> w, …)` が当たる |
| 和字間隔の後ろの始め括弧類（`　「`） | 二分 | ベタ（cl-14 の行の cl-01 の欄が空欄） | 和字間隔を `j` に含め、`(j <> w <> o, o, …)` が当たる |

和文と欧文のあいだ（cl-27 の行と列）は、表 1 がクラスごとに四分を置くか置かないかを分け、Golem は `j` と `w` のあいだに一律に (八分, 四分, 二分) を置く。
これは 0019 が InDesign の「行末約物半角」に合わせて決めた値であり、括弧類の組とは別の問いなので、ここでは照らさない。

0239 の「文脈」の表は、`）　` を「規定なし」とした。
表 1 の cl-02 の行の cl-14 の欄は空欄であり、表 1 の凡例は空欄をベタ組とする。
0239 は採択済みなので書き換えず、この記録だけを残す。

### HTML と EPUB

HTML と EPUB の `style.css` は、`text-spacing-trim` を書かない。
ブラウザーの既定の `normal` は、CSS Text Level 4 の 8.5.1 の規則で隣り合う約物の空きを詰める。
始め括弧類は、前の字が始め括弧類、中点類、和字間隔、同じ大きさ以上の終わり括弧類なら半角にする。
終わり括弧類は、後の字が終わり括弧類、中点類、和字間隔なら半角にする。

## 実装すること

### 1. 既定のセットの三つの組を変える

`defaultAkiSet` の規則を、次のように変える。

| 前 | 後ろ | 今 | 変えた後 |
| --- | --- | --- | --- |
| `opening` | `opening` | (0, 二分, 二分) | (0, 0, 0) |
| `closing` | `middle-dot` | (0, 二分四分, 二分四分) | (0, 四分, 四分) |
| `middle-dot` | `opening` | (0, 二分四分, 二分四分) | (0, 四分, 四分) |

ほかの組は変えない。
`full-stop` と `comma` の後ろの `middle-dot` は、二分四分のままである。
`gyomatsu-yakumono-zenkaku` は `defaultAkiSet` に行末の規則を足したセットなので、同じ三つの組が同じように変わる。

規則の書き方は、実装のプルリクエストで決めてよい。
たとえば、`(j <> w <> o, o, …)` の前の集まりから `o` を除き、`(m, o, …)` と `(p, m, …)` の後に、`(chars [Closing], m, Aki 0 (1 / 4) (1 / 4))` を足す。
`(o, o)` は規則のない組になり、`noAki` を引く。

`zw` の基準の大きさ（0019 の「両方が約物なら、大きいほうの箱の大きさ」）は変えない。
四分の量は、二つの約物の箱の大きいほうで測る。

### 2. 行分割の項目

`（「` は、行末禁則の字（始め括弧類）の後ろなので、今も分割の候補でない。
空きが `Aki 0 0 0` になると、`normalize` は分割できない位置に何も置かない（0019 の「組み方」）。
今は `Penalty 0 infPenalty NoHyphen` と幅二分のグルーを置いているので、二つの項目が消える。

`」・` と `・「` は、行頭禁則と行末禁則のどちらにも当たらない組であり、グルーの幅だけが変わる。
今のグルーは分割の候補なので、行末で分けたときにグルーが捨てられることも変わらない。

### 3. 文書

- 仕様書の「アキ量のセット」の段落（「隣り合う約物の空きは、終わり括弧類と始め括弧類の間が二分、中点類と括弧類や句読点の間が二分四分、中点類どうしが二分になる」）を、変えた後の値に改める。始め括弧類どうしはベタ、終わり括弧類と中点類のあいだと中点類と始め括弧類のあいだは四分、句読点と中点類のあいだは二分四分、中点類の後ろの終わり括弧類と句読点は 0 である。今の文は、中点類の後ろの終わり括弧類と句読点（0）と、始め括弧類の後ろの中点類（四分）でも、実装と合っていない。この ADR で一緒に直す。
- 仕様書のその段落に、この ADR へのリンクを足す。
- [docs/adr/0019](../../adr/0019-aki-settings.md) のステータスの行に、「既定のセットの始め括弧類どうし、終わり括弧類と中点類、中点類と始め括弧類の空きは [golem-layout ADR 0039](0039-set-consecutive-opening-brackets-and-brackets-beside-middle-dots-as-jlreq.md)」を足す。
- 利用者のマニュアルの第 5 章と付録 C は、既定のセットの値として和欧間と括弧類と句読点の二分だけを書き、隣り合う約物の値を書いていない。マニュアルは変えない。

### 4. 出力の変化

`（「` を含む段落は、その字間が二分ぶん詰まる。
利用者のマニュアルは、`（「[ref-title …]」）` の形で章の名前を引く文が多く（第 3 章と第 4 章の 20 行あまり）、それらの行の字詰めが変わる。
`」・` と `・「` を含む段落は、字間が二分ぶん詰まる。
`modules/golem-driver/test/fixtures/` の `pd/` と `kanikosen` の原稿に `・「` がある。

PDF の golden（`modules/golem-driver/test/golden/pdf-*.txt`）の原稿（`sample`、`complex-horizontal`、`complex-vertical`、`figures`）には、三つの組のどれもないことを `rg` で確かめた。
golden は変わらない見込みである。
実装のプルリクエストで、golden、`scripts/visual/` の参照、二つのマニュアルと complex fixture の決定性のハッシュが変わるかを確かめ、説明に書く。

## 実装しないこと

- **中点類の後ろの終わり括弧類と句読点（`・」`、`・。`）**：表 1 は四分を置き、Golem は 0 である。原因は規則がないことで、この ADR の三つの組（残すべきでない空きが残る）とは向きが逆である（「メンテナーが決めること」の 3）。
- **和字間隔の前後の括弧類（`」　`、`　「`）**：表 1 はベタ組とし、Golem は二分を置く。原因は和字間隔を `j` に含めたことで、段落の字下げに和字間隔を使う原稿の見た目にも関わる（「メンテナーが決めること」の 3）。
- **和文と欧文のあいだの空き**：「文脈」のとおり、別の問いである。
- **行頭の始め括弧類**：JLReq の 3.1.5 は、行頭の始め括弧類の置き方を何通りか挙げる。Golem は段落の先頭で二分、折り返した行頭で 0 とする（0019）。段落の先頭の `「（` は、`「` の前の二分と、`（` の前の 0 になる。この ADR は行頭の規則を変えない。
- **利用者のセット**：`based-on` で既定のセットを引き継いだ利用者のセットは、引き継いだ規則が変わるので、同じ三つの組が変わる。利用者が `rules` でこの三つの組を書いていれば、その値が勝つ（0019 の「後に書いた規則が上書きする」）。今の値に戻す設定の例は、仕様書には書かない。
- **HTML と EPUB**：`style.css` を変えない。Chrome の既定は、すでに表 1 と同じ空きで組む。

## 不変条件

`d` を `defaultAkiSet`、`z` を `gyomatsu-yakumono-zenkaku` とする。
`old` を、この ADR の前の `defaultAkiSet` の規則を写した参照のセット（テストに置く）とする。
`O`、`C`、`M` は、それぞれ `AkiChar Opening`、`AkiChar Closing`、`AkiChar MiddleDot` である。

- **B1**：`akiBetween d O O == Aki 0 0 0` である。
- **B2**：`akiBetween d C M == Aki 0 (1 / 4) (1 / 4)` である。
- **B3**：`akiBetween d M O == Aki 0 (1 / 4) (1 / 4)` である。
- **B4**：`(O, O)`、`(C, M)`、`(M, O)` 以外のすべての位置の組 `(x, y)`（行頭、段落の先頭、行末を含む）で、`akiBetween d x y == akiBetween old x y` である。
- **B5**：すべての位置の組 `(x, y)` で、`akiBetween z x y` は、`y` が行末なら今の `gyomatsu-yakumono-zenkaku` の値、そうでなければ `akiBetween d x y` である。
- **B6**：始め括弧類が k 個（k ≥ 2）続く並びを組むと、二つめ以降の始め括弧類の箱の直前に、グルーも罰則も置かない。最初の始め括弧類の前の空きは、その前の字との組の空き（段落の先頭なら `paragraph-start` の規則）のままである。
- **B7**：既定のセットを `based-on` にし、`rules` で `opening` と `opening` の組を書いた利用者のセットでは、その組の空きは書いた値である。

## テスト設計

テストを先に書き、今の実装で失敗することを確かめてから実装する。
テストの名前には、B1 から B7 の番号を入れる。

## トレードオフ

既存の本の PDF の字詰めが変わる。
`（「` は Golem のマニュアルに多く、その段落では改行の位置も変わりうる。
既定のセットの名前は変えずに値を変えるので、同じ原稿を前の版と今の版で組むと違う PDF になる。
アキ量のセットは 0019 で入れたばかりであり、既定の値を JLReq に寄せる変更は、0019 の値の決め方（今の組み方に合わせる）と、[golem-layout ADR 0002](0002-japanese-composition.md) の「隣り合う約物の空きを JLReq の表に従って詰める」の食い違いを、0002 の側に寄せて解くものである。

三つの組を一つの ADR にまとめた。
三つとも、JLReq の 3.1.4 の同じ節が定め、Golem の側の原因も同じ（0019 が `combined` の和の取り方をそのまま値にしたこと）だからである。
`・」` と和字間隔の組は、原因が違うので分けた。
分けたことで、既定のセットは、この ADR の後もまだ表 1 と三つの組で違う。

InDesign の「行末約物半角」の値とは照合していない。
0019 は、InDesign の同名のセットに名前と考え方を合わせたが、括弧類どうしの値は照合していない（0019 の「組み込みのセット」）。
InDesign の値が Golem の今の値と同じなら、名前を合わせたセットが InDesign と違う組み方になる。

## メンテナーが決めること

1. **三つの組を JLReq に合わせるか**：推奨は、合わせることである。0002 は「隣り合う約物の空きを JLReq の表に従って詰める」と決めており、今の値は 0019 が前の実装をそのまま写した結果である。HTML と EPUB を組む Chrome の既定も、すでに JLReq の値で組む。
   - 退けた案の一つは、既定のセットを今のままとし、JLReq に合わせたセットを三つめの組み込みのセットとして足すことである。既定の組み方が JLReq と違うまま残り、HTML と PDF の差も残る。
   - 二つめは、`（「` だけを直し、中点類の二つの組を残すことである。同じ節の規則のうち一つだけを当てる理由がない。
2. **ADR を置く場所**：推奨は、golem-layout の ADR とすることである。アキ量のセットの規則は `Golem.Layout.Aki` にあり、golem-layout が持つ。値の表を最初に決めたのは横断の [docs/adr/0019](../../adr/0019-aki-settings.md) なので、0019 のステータスの行からこの ADR を指す。
   - 退けた案は、`docs/adr/` に置くことである。変えるのは golem-layout の既定の値だけで、`style.toml` の形も diagnostics も変わらない。
3. **表 1 とのほかの食い違いをどう扱うか**：推奨は、`・」` と和字間隔の組を、それぞれ別の ADR として起こすことである。原因が別であり、和字間隔の組は、字下げに和字間隔を使う原稿の見た目に関わるので、別に決めたい。
   - 退けた案は、この ADR に含めることである。一つの ADR が三つの原因を扱うことになる。
4. **大きさの違う約物の組で測る大きさ**：推奨は、この ADR では変えないことである。表 1 の `be` と `af` は、空きを前と後のどちらの字の大きさで測るかを組ごとに決める。Golem は二つの約物の箱の大きいほうで測る（0019）。合わせるなら、すべての組の測り方を変えることになり、別の ADR にする。
