# ADR 0038: 行頭禁則と行末禁則を、本文の中のコードの空白をまたいで当てる

ステータス: 採択（未実装）

## 文脈

仕様書の「既知の不具合」に、「本文の中のコードの空白で、禁則に当たる位置でも改行する」がある。
[golem-layout ADR 0034](0034-line-breaks-between-japanese-characters-in-inline-code.md) の実装（[#713](https://github.com/tett23/golem/pull/713)）が、コードの並びの列挙で L2、L3、L4 の違反として見つけた（[docs/adr/0209](../../adr/0209-line-breaking-invariants-by-exhaustive-small-inputs.md)）。
テストの既知の不具合の一覧（[`codeLineBugs`](https://github.com/tett23/golem/blob/c638870fb9f5fb8a66d13308fef727a7e202de19/modules/golem-layout/test/LineBreakInvariantsSpec.hs#L715-L729)）の一つめの項目が、これを除く。
除いた入力は、部品 2 個までで 39、3 個までで 2703 である。

### 最も小さい例

2026-11-08 に、origin/main（`ec295f03`）の golem-layout のテストに一時のテストを足し、コードの並びの列挙と同じ送りで組んで確かめた（コミットしていない）。
列挙の送りでは、和文の字が 1 em、欧文の字が 1/2 em、コードの空白が 1/4 em である。

| 段落 | 行の幅 | 行 | 違反 |
| --- | --- | --- | --- |
| `あ[code: 「 a]` | 2 字 | `あ「`、`a` | L3（行末禁則） |
| `あ[code: a 」]` | 2 字 | `あa`、`」` | L2（行頭禁則） |
| `[code: 漢 。]` | 2 字 | `漢`、`。` | L2 |
| `[code: 「 漢]` | 2 字 | `「`、`漢` | L3 |
| `[code: … …]` | 2 字 | `…`、`…` | L4（分離禁止） |

どれも、空白の前か後の字の禁則を、空白での分割が破る。
同じ並びを本文に書けば、[golem-layout ADR 0028](0028-kinsoku-across-spaces-and-explicit-hyphens.md) の規則で、`… …` のほかは空白で改行しない。

### コードの空白は、0028 の判定を通らない

0028 は、語間の空白のグルーをまたいで直前の箱を持ち、後の箱との組で行頭禁則と行末禁則を判定する（[`normalize`](https://github.com/tett23/golem/blob/c638870fb9f5fb8a66d13308fef727a7e202de19/modules/golem-layout/src/Golem/Layout/Japanese.hs#L1247-L1255)）。
判定するのは、`wordSpace`（伸びるグルー）に当たるグルーだけである。
本文の中のコードの空白は、伸び縮みしないグルーなので（[golem-layout ADR 0017](0017-spaces-inside-inline-code.md)、[`Japanese.hs`](https://github.com/tett23/golem/blob/c638870fb9f5fb8a66d13308fef727a7e202de19/modules/golem-layout/src/Golem/Layout/Japanese.hs#L870-L875)）、判定を通らない。
0028 は、「実装しないこと」で、コードの空白を列挙の外にあるとして変えなかった。

0034 の前は、コードの和文は空白のあいだの一つの箱だったので、禁則の字が空白の隣に来ても、箱の端の字として同じように分けられた。
0034 が和文の字ごとの箱にして、列挙にコードの並びを足したので、違反が見つかった。

### `… …` は、述語の読み方の違いである

0028 の 4 は、L4 を「語間の空白を挟んだ二つの分離禁止文字のあいだは分けてよい」と読むことにした（0028 の K4）。
空白を挟んだ二つの `…` は、続けて並んでいないからである。
述語 [`l4Inseparable`](https://github.com/tett23/golem/blob/c638870fb9f5fb8a66d13308fef727a7e202de19/modules/golem-layout/test/LineBreakInvariants.hs#L184-L199) は、分けた位置の項目が本文の語間の空白のグルー（`latinSpace`）のときだけ、違反としない。
コードの空白は `latinSpace` と幅も伸び縮みも違うので、`[code: … …]` は違反になる。
組み方の誤りではなく、述語がコードの空白を空白として扱っていないことによる。

### JLReq と UAX #14

JLReq の行頭禁則（3.1.7）と行末禁則（3.1.8）は、行の端に来る字を定める。
0028 の「文脈」のとおり、空白は分けた位置で捨てられるので、空白を挟んでも行の端の字は変わらない。
JLReq には、コードの中の空白について定める節はない。
分離禁止（3.1.10）は、続けて並ぶ分離禁止文字のあいだを分けないと定める。

Unicode の行分割の規則（UAX #14、Revision 57）は、空白をまたぐ規則を持つ。
LB13 は、終わり括弧類（CL）の前で、空白の後でも分けないとする（`× CL`）。
`。` と `」` は CL である。
LB14 は、始め括弧類（OP）の後で、空白を挟んでも分けないとする（`OP SP* ×`）。
LB18 は、空白の後で分けてよいとし（`SP ÷`）、`…`（IN）の前で分けない LB22 より先に当たる。
UAX #14 の規則は、`「 a`、`a 」`、`漢 。` を分けず、`… …` を分ける。

### HTML

HTML と EPUB の `style.css` は、本文の中のコードに `white-space` も `word-break` も付けない（0034 の「文脈」）。
Google Chrome 156.0.8078.80 の headless で、`lang="ja"` の文書の 2 字の幅の段落に描いた。

| 段落 | 行 |
| --- | --- |
| `あ<code>「 a</code>` | `あ「 `、`a` |
| `あ<code>a 」</code>` | `あa `、`」` |
| `<code>漢 。</code>`（1.6 字の幅） | `漢 `、`。` |
| `あ<code>… …</code>` | `あ… `、`…` |
| `あ「 a`（コードでない） | `あ「 `、`a` |
| `あ漢 。`（コードでない） | `あ漢 `、`。` |

Chrome は、コードの中でも外でも、空白の後で改行した。
UAX #14 の LB13 と LB14 には従わなかった。
本文の PDF は、0028 で既にブラウザーと違う。

## 実装すること

### 1. コードの空白をまたいで、行頭禁則と行末禁則を当てる

`normalize` の、語間の空白をまたぐ禁則の判定（0028 の 1 と 2）を、本文の中のコードの空白のグルーにも当てる。

- 判定は 0028 と同じく、またいだ組の後の箱の最初の字が行頭禁則の字（`ceKinsokuStrict` による）か、前の箱の最後の字が行末禁則の字であることとする。字のクラスは `breakClass` と `startClass` で引く。欧文の区間の両用の字は、その字の和文の文字クラスで判定する。
- 分離禁止は、0028 の K4 と同じく、コードの空白をまたぐときは見ない。
- 判定が真なら、グルーの直前に `Penalty 0 infPenalty NoHyphen` を置く。グルーの幅は変えず、伸び縮みしないままである。
- 前の箱と後の箱の片方がコードの外の箱でも（`[code: a ]」`）、コードの空白をまたぐ組なら判定する。
- コードの空白は、`lkCode` の `PSpace` から作ったグルーとして見分ける（[golem-layout ADR 0037](0037-drop-spaces-of-code-before-the-end-of-a-paragraph.md) の 1 と同じ見分け方を使う）。

和欧間の空き、アキ量のセットの空き、改行の印は、どれも足さない。
空白で改行した行に印を描かないこと（0034 の C8）は変わらない。

### 2. L4 の述語を、コードの空白にも当てる

[docs/adr/0209](../../adr/0209-line-breaking-invariants-by-exhaustive-small-inputs.md) の L4 の 0028 の読み方（語間の空白を挟んだ二つの分離禁止文字のあいだは分けてよい）を、本文の中のコードの空白にも当てる。
述語 `l4Inseparable` は、分けた位置の項目がコードの空白のグルーのときも、違反としない。
コードの空白のグルーは、その段落のコードの書体の空白の送りから作り、形だけで見分けない。

### 3. テストの既知の不具合の一覧を空にする

`codeLineBugs` から、「本文の中のコードの空白で、禁則に当たる位置でも改行する」の項目と `atCodeSpace` を消す。
[golem-layout ADR 0037](0037-drop-spaces-of-code-before-the-end-of-a-paragraph.md) の後なので、一覧は空になる。
0037 の前に実装すると、段落の終わりの `[code: 「 ]` が L3 の違反として残る（後に箱がないので、またいだ組がない）。
この ADR は 0037 の後に実装する。

### 4. 文書

- 仕様書の「行分割」の節の禁則の段落（0028 の文）に、行頭禁則と行末禁則を本文の中のコードの空白にも当てることと、この ADR へのリンクを足す。
- 仕様書の文字スタイル `code` の段落の「空白の位置では今までどおり改行でき」に、後の字が行頭禁則の字か、前の字が行末禁則の字なら空白で改行しないことを足す。
- 仕様書の「既知の不具合」から、項目を消す。
- 「行分割」の節の、コードの並びの既知の不具合の文を、一覧が空であることに改める。

### 5. 出力の変化

本文の中のコードで、空白の隣に行頭禁則か行末禁則の字を置いた原稿だけが変わる。
`[code: 「 a]` のように、空白で改行できなくなった並びが行長より長ければ、行は送り出されるか、行長を超えて G07105 になる。
実装のプルリクエストで、golden、`scripts/visual/` の参照、二つのマニュアルと complex fixture の決定性のハッシュが変わるかを確かめ、説明に書く。

## 実装しないこと

- **ASCII の記号を約物のクラスで扱うこと**：0034 のとおり、`(`、`"`、`:` などは欧文の字（cl-27）のままとする。`( a` の空白では、今のとおり改行できる。
- **コードの空白をまたぐ分離禁止**：0028 の K4 と同じく、空白を挟んだ二つの分離禁止文字のあいだは分けてよい（「メンテナーが決めること」の 2）。
- **文字スタイル `url`**：[golem-layout ADR 0018](0018-url-line-breaks.md) のままとする。URL は空白を持たない。
- **コードブロック**：別の規則で折り返すので、変えない。
- **HTML と EPUB の `style.css`**：変えない（「メンテナーが決めること」の 3）。

## 不変条件

「コードの空白」は、`lkCode` の `PSpace` から作ったグルーとする。
「コードの空白をまたいだ組」は、コードの空白一つだけを挟んで並ぶ二つの箱の、前の箱の最後の字と後の箱の最初の字の組とする。

- **S1**：コードの空白をまたいだ組の後の字が行頭禁則の文字なら、そのあいだで行を分けない。ただし、行長に収まる分割がない行（L5 の例外）は除く。
- **S2**：コードの空白をまたいだ組の前の字が始め括弧類なら、そのあいだで行を分けない。例外は S1 と同じである。
- **S3**：コードの空白をまたいだ組の二つの字がどちらも分離禁止文字で、S1 と S2 に当たらないなら、空白は分割の候補である。
- **S4**：S1 と S2 に当たらないコードの空白は、この ADR の前と同じ項目のままである。グルーの幅は変わらず、伸び縮みしない。
- **S5**：消した候補の位置に、和欧間の空き、アキ量のセットの空き、改行の印を足さない。空白で分けた行の終わりには、印がない（0034 の C8）。
- **S6**：コードの空白をまたぐ禁則の判定は、欧文の区間の両用の字を、その字の和文の文字クラスで行う。

境界の入力：

| 量 | 調べる値 |
| --- | --- |
| 前の字のクラス | 始め括弧類（`「`）、分離禁止文字（`…`）、和文の字（`漢`）、欧文の字（`a`）、ASCII の `(` |
| 後の字のクラス | 終わり括弧類（`」`）、句点類（`。`）、読点類（`、`）、長音記号と小書きの仮名（strict と loose）、分離禁止文字、和文の字、欧文の字 |
| 空白の数 | 一つ、二つ続く（一つにまとめる） |
| またぐ組の位置 | どちらもコードの中、前だけコード（`[code: a ]」`）、後だけコード |
| 区間の言語 | なし、`en`（`…` と `“` が欧文の字）、`ja` |
| 行の残りの幅 | 空白の前でちょうど終わる、空白を含めて一つあふれる、禁則で候補がなく行長を超える |

## テスト設計

テストを先に書き、今の実装で失敗することを確かめてから実装する。
テストの名前には、S1 から S6 の番号を入れる。

- **S1**：`CodeJapaneseSpec` で、`[code: a 」]`、`[code: 漢 。]`、`[code: 漢 、]` の空白の前に罰点 10000 があること。今はないので失敗する。`[code: あ ー]` は、強い禁則で罰点 10000 があり、弱い禁則でないこと。
- **S2**：`[code: 「 a]`、`[code: 「 漢]` の空白の前に罰点 10000 があること。今はないので失敗する。
- **S1、S2**：「文脈」の表の四つの段落を 2 字の行で組み、`「` が行末に、`」` と `。` が行頭に来ないこと。今は来るので失敗する。
- **S3**：`[code: … …]` の空白が分割の候補のままであること。改めた `l4Inseparable` が、空白で分けた `[code: … …]` を違反としないこと。改める前の述語では違反になるので、述語のテストとして先に失敗させる。
- **S4、S5**：`[code: a b]`、`[code: 漢 a]`、`[code: ( a]` の項目が、この ADR の前と同じであること。空白で分けた行に印がないこと。
- **S6**：`[lang en: [code: “ あ]]` で、`“` の後の空白の前に罰点 10000 があること。
- 列挙：`codeLineBugs` から項目を消し、コードの並びの段 2 のすべての入力で L1 から L13、T1、C1 から C8 が成り立つこと。今は 39 の入力が違反するので失敗する。段 3 は毎晩の `enum.yml` で確かめる。
- [golem-layout ADR 0028](0028-kinsoku-across-spaces-and-explicit-hyphens.md) の K1 から K7 のテストが、そのまま通ること。

## トレードオフ

コードの空白で改行できる位置が減る。
`漢 。` のように、空白を挟んで禁則の字が並ぶコードは、行長より長ければ行長を超え、G07105 になる。
空白で分ければ収まる行を、はみ出させることになる。
それでも、本文と同じ並びで同じ禁則になり、`「` が行末に残る行は出なくなる。

ブラウザーとの差が広がる。
Chrome は、コードの中でも外でも、空白の後で禁則によらず改行した。
本文は 0028 で既にこの差を持ち、コードも同じ差を持つようになる。
UAX #14 の規則には、`「 a`、`a 」`、`漢 。`、`… …` のどれでも、この ADR の PDF のほうが近い。

コードの空白は、語間の空白と違って伸び縮みしない。
語間の空白と同じ判定に通すので、二つのグルーを見分ける判定が、`normalize` と述語の両方に要る。

## メンテナーが決めること

1. **コードの空白をまたいで禁則を当てるか**：推奨は、0028 と同じ行頭禁則と行末禁則を当てることである。JLReq の行頭禁則と行末禁則は行の端の字の規則であり、空白で分けても端の字は変わらない。0034 は、コードの中の和文の字のあいだに本文と同じ禁則を当てたので、空白の位置だけ禁則を外す理由がない。UAX #14 も、`× CL` と `OP SP* ×` で空白をまたいで分けない。
   - 退けた案の一つは、今のままとし、述語の側でコードの空白の分割を例外にすることである。`「` が行末に残る行を、仕様として認めることになる。
   - 二つめは、コードの空白をすべて分割の候補でなくすことである。空白のある長いコードが、どこでも改行できなくなる。
2. **空白を挟んだ二つの分離禁止文字をどうするか**：推奨は、0028 の K4 と同じく、分けてよいとし、L4 の述語をコードの空白にも当てることである。空白を挟んだ `…` は、続けて並んでいない。UAX #14 も `… …` を空白の後で分ける。
   - 退けた案は、コードの空白では分離禁止も当てることである。本文とコードで、同じ並びの扱いが分かれる。
3. **HTML と EPUB を合わせるか**：推奨は、変えないことである。本文の PDF と HTML の差（0028）と同じ差であり、コードだけを合わせる理由がない。合わせるなら、本文とコードの両方を一つの ADR で扱う。
   - 退けた案は、本文の中のコードの空白を `&nbsp;` に置き換えるなどして、HTML でも禁則を守ることである。禁則に当たらない空白でも改行できなくなるか、空白ごとに前後の字を調べて置き換えることになり、コピーした文字列も変わる。
