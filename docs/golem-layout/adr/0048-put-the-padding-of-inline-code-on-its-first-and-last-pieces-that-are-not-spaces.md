# ADR 0048: 本文の中のコードの余白を、空白でない最初と最後の部品に付ける

ステータス: 採択（未実装）

## 文脈

### 既知の不具合

[docs/specifications.md](../../specifications.md) の「既知の不具合」に、次の項目がある。

- **本文の中のコードの最初か最後に空白があると、その側の余白がなくなる**：文字スタイル `code` の `padding` は、コードの並びの最初と最後の部品に付ける。最後の部品が空白なら、余白を付ける先がない。`padding = 250` の `code` で、`[code: あ ]` の `あ` の後の余白と、前に空白を書いたコードの `あ` の前の余白が 0 になる。段落の終わりに限らず起きる。

[golem-layout ADR 0037](0037-drop-spaces-of-code-before-the-end-of-a-paragraph.md) の調べで見つかり、その「メンテナーが決めること」の 3 で、別の ADR で直すと決めた。
[docs/roadmap.md](../../roadmap.md) の v1.0.0 の「行分割と禁則」の「本文の中のコードの端の空白と余白」が、この不具合を指す。

### 今の余白の付け方

本文の中のコードの余白は、同じ背景と余白のコードの部品が続く並びごとに、最初の部品の前と最後の部品の後に付ける（[golem-driver ADR 0029](../../golem-driver/adr/0029-inline-code-background.md)、[`padCode`](https://github.com/tett23/golem/blob/9608953da3806ab63cb82abf091bfc1e04b76533/modules/golem-layout/src/Golem/Layout/Japanese.hs#L1327-L1365)）。
並びには、コードの文字列の部品（`PCode`）のほかに、空白（`PSpace`）、注の合印（`PMark`）、ルビ（`PRuby`）が入り、索引の印のような描かない部品は飛ばす。
`padCode` は並びの最初と最後の部品を選び、それが `PCode` か `PMark` なら余白を付ける。
空白は字を描かない部品なので、選ばれても余白を付けない。
そのため、端に空白を書いたコードは、その側の余白を失う。

背景は、行ごとに、同じ背景の箱の並びの最初の箱の始まりから最後の箱の終わりまでを塗る（[`codeBackgrounds`](https://github.com/tett23/golem/blob/9608953da3806ab63cb82abf091bfc1e04b76533/modules/golem-typeset/src/Golem/Typeset/Draw.hs#L869-L891)）。
空白は箱ではなくグルーなので、並びの端の空白は背景の外にある。
`[code: あ ]` は、背景が `あ` の字の終わりで切れ、その後に塗らない空白が続く。
余白のない背景が字に接する形は、余白を書いた書き手の意図と違う。

段落の終わりと強制改行の前のコードの空白は、行分割の前に捨てる（[golem-layout ADR 0037](0037-drop-spaces-of-code-before-the-end-of-a-paragraph.md)）。
捨てても、`padCode` はそれより前に余白の付け先を決めているので、余白は戻らない。

### HTML と EPUB

HTML と EPUB は、`<code>` に `padding-inline` を書く（[docs/specifications.md](../../specifications.md) の HTML の節）。
ブラウザーは、要素の中の空白も背景の内側に置き、余白をその外に取る。
端の空白の扱いは、今も PDF と HTML で違う。

## 実装すること

### 1. 余白を付ける部品

`padCode` が余白を付ける部品を、並びの最初と最後の部品から、空白でない最初と最後の部品に変える。
ここで「空白でない部品」は、空白（`PSpace`）と、今も飛ばしている描かない部品（`PAnchor`、`PShy`、`PRubyBreak`）のほかの部品とする。
選んだ部品が `PCode` か `PMark` なら、今のとおり余白を付ける。
`PRuby` なら、今のとおり余白を付けない（ルビの親文字の中のコードの余白は、この ADR では変えない）。

空白でない部品が一つもない並び（`[code:  ]`）は、今のとおり余白を付けない。
並びの区切り方（同じ背景と余白の部品が続く範囲）、余白の幅、余白とコードの字のあいだで改行しない規則は変えない。

端の空白は、今のとおりグルーとして残り、背景の外に置かれる。
`[code: あ ]` は、`あ` の前後に余白を持つ背景の後に、塗らない空白が続く形になる。

### 2. 変えないもの

- 端の空白の幅、伸び縮み、改行の位置の規則（[golem-layout ADR 0038](0038-kinsoku-across-spaces-of-inline-code.md)）。
- 段落の終わりと強制改行の前のコードの空白を捨てる規則（[golem-layout ADR 0037](0037-drop-spaces-of-code-before-the-end-of-a-paragraph.md)）。
- 背景を塗る範囲の規則（箱の並びの最初の箱の始まりから最後の箱の終わりまで）。
- HTML と EPUB の出力。

### 3. 文書

- [docs/specifications.md](../../specifications.md) の本文の中のコードの余白の段落の「一つの `[code: ...]` の最初の箱の前と最後の箱の後に」を、空白でない最初と最後の部品の前と後に付けると書き換え、端の空白は背景の外に置くこと、HTML と EPUB では端の空白が背景の内側に入ることを足し、この ADR へのリンクを付ける。
- 同じく「既知の不具合」から「本文の中のコードの最初か最後に空白があると、その側の余白がなくなる」を消す。
- [docs/roadmap.md](../../roadmap.md) の v1.0.0 の「行分割と禁則」から「**本文の中のコードの端の空白と余白**」の行を消す。
- [golem-layout ADR 0037](0037-drop-spaces-of-code-before-the-end-of-a-paragraph.md) のステータスの行に、「メンテナーが決めること」の 3 の不具合をこの ADR が直したことを書く。

### 4. 出力の変化

端に空白を書いた本文の中のコードを含む本だけが変わる。
コードの箱の幅が余白の分だけ広がるので、その段落の行の分け方が変わりうる。
実装のプルリクエストで、二つのマニュアル、golden、complex fixture の原稿から、端に空白を書いた `[code: ...]` を数え、PDF の変わったページを説明に書く。

## 実装しないこと

- **端の空白を背景の内側に入れること**：HTML と同じ形にするには、空白の外に余白を置き、空白を塗る必要がある。端の空白で改行すると、行頭か行末に余白だけの箱が残る（「メンテナーが決めること」の 1）。
- **端の空白を捨てること、報告すること**：書き手の書いた空白を変えず、diagnostic も出さない（「メンテナーが決めること」の 2）。
- **ルビの親文字にあるコードの余白**：`PRuby` の部品には今も余白を付けておらず、この不具合とは原因が別である。

## 不変条件

「並び」は、`padCode` が区切る、同じ背景と余白のコードの部品が続く範囲とする。
「字の部品」は、並びの部品のうち、空白（`PSpace`）でも描かない部品（`PAnchor`、`PShy`、`PRubyBreak`）でもない部品とする。
p は並びのコードの文字スタイルの `padding` とする。

- **D1 最初の字の部品の前の余白**：字の部品を持つ並びで、最初の字の部品が `PCode` か `PMark` なら、その前の余白は p である。並びのほかの部品の前の余白は 0 である。
- **D2 最後の字の部品の後の余白**：字の部品を持つ並びで、最後の字の部品が `PCode` か `PMark` なら、その後の余白は p である。並びのほかの部品の後の余白は 0 である。
- **D3 字の部品のない並び**：字の部品を持たない並びのどの部品も、余白を持たない。
- **D4 端に空白のない並び**：最初と最後の部品が字の部品である並びの項目は、この ADR の前と同じである。
- **D5 空白は変わらない**：端の空白のグルーの幅、伸び、縮みと、その前に置く罰点は、この ADR の前と同じである。
- **D6 背景の外の空白**：コードの並びの全体が一行にあるとき、背景の矩形は最初の字の部品の箱の始まりから最後の字の部品の箱の終わりまでであり、端の空白はその外にある。
- **D7 HTML と EPUB**：HTML と EPUB の出力のバイト列は、この ADR の前と同じである。

[ADR 0209](../../adr/0209-line-breaking-invariants-by-exhaustive-small-inputs.md) の L1 から L13、[golem-layout ADR 0032](0032-drop-word-spaces-before-the-end-of-a-paragraph.md) の T1、[golem-layout ADR 0034](0034-line-breaks-between-japanese-characters-in-inline-code.md) の C1 から C8、[golem-layout ADR 0045](0045-break-inline-code-after-hyphens-and-full-stops-to-avoid-loose-lines.md) の J1 から J7 は、余白が箱の幅に入るだけなので、そのまま成り立つ。
ただし、コードの並びの列挙の述語のうち、箱の幅を余白なしで数えるものがあれば、余白を足して数え直す。

境界の入力：

| 量 | 調べる値 |
| --- | --- |
| 端の空白 | なし、前だけ、後ろだけ、両方、二つ続く（`[code:   a]`） |
| 字の部品の数 | 0（空白だけ）、1、2 |
| 端の字の部品 | 和文の字、欧文の字、注の合印、ルビ |
| 位置 | 段落の始め、中ほど、終わり、強制改行の前 |
| `padding` | 0、既定（`0.25zw`）、既定より大きい値（`0.5zw`） |
| 改行 | 端の空白で改行する行の幅、しない行の幅 |
| 組方向 | 横組み、縦組み |

## テスト設計

テストを先に書き、今の実装で失敗することを確かめてから実装する。
テストの名前には、D1 から D7 の番号を入れる。

- **D1**：`あ[code:  漢]い` の `漢` の箱の前の余白が p であること。今は 0 なので失敗する。
- **D2**：`あ[code: 漢 ]い` の `漢` の箱の後の余白が p であること。今は 0 なので失敗する。段落の終わりの `あ[code: 漢 ]` も同じであること。
- **D3**：`あ[code:  ]い` のどの部品も余白を持たないこと。
- **D4**：`[code: a b]`、`[code: 漢]`、`[code: a/b]` の項目が、この ADR の前の実装と同じであること。
- **D5**：D1 と D2 の入力の空白のグルーと罰点が、この ADR の前の実装と同じであること。
- **D6**：golem-typeset のテストで、`[code: 漢 ]` を背景のある文字スタイルで組み、背景の矩形の終わりが `漢` の箱の終わり（余白を含む）にあり、空白のグルーの始まりがその後にあること。
- **D7**：D1 から D3 の入力の HTML と EPUB のバイト列が、この ADR の前と同じであること。
- **列挙**：コードの並びの列挙（[golem-layout ADR 0034](0034-line-breaks-between-japanese-characters-in-inline-code.md) の 5）は、部品に空白を含むので、端に空白のある並びを今も組んでいる。列挙の組み方の環境に `padding` の有無を足し、L1 から L13、T1、C1 から C8、J1 から J7、D1 から D5 がすべての入力で成り立つことを確かめる。プルリクエストの段の時間が範囲ごとの予算 10 秒（[ADR 0208](../../adr/0208-widen-lightweight-formal-methods.md) の 4）を超えるなら、`padding` のある環境は毎晩のジョブの段だけで足す。

## トレードオフ

PDF と HTML で、端の空白の位置が違ったまま残る。
PDF では空白が背景の外に、HTML では内側にある。
今も違うが、PDF の側の余白がなくなる形から、余白がある形に変わるので、見た目の差は小さくなる。

端の空白を書く書き手は少ないと見込むが、数えてはいない。
`[code: ls -l ]` のような書き方は、コマンドの後に空白が続くことを示したい書き手が使う可能性がある。
その空白は、紙面では背景の外の空きになり、コマンドの一部としては見えない。

## メンテナーが決めること

1. **余白を付ける部品**：推奨は、空白でない最初と最後の部品に付けることである。余白が字に付き、背景が余白を持つ形に戻る。行分割の項目の作り方（空白はグルー、余白は箱の幅）を変えずに済む。
   - 退けた案は、HTML と同じく端の空白を背景の内側に入れ、余白をその外に置くことである。空白のグルーの外に余白の箱を置くことになり、空白で改行すると余白だけの箱が行頭か行末に残る。これを避けるには、改行の位置ごとに余白の付け先を変える仕組みが要る。
2. **端の空白そのもの**：推奨は、空白を残し、diagnostic も出さないことである。原稿の字を変えない原則（[golem-layout ADR 0037](0037-drop-spaces-of-code-before-the-end-of-a-paragraph.md)）のとおりである。
   - 退けた案の一つは、端の空白を捨てることである。段落の途中の空白は語の区切りの役を持ち、捨てると前後の字がつながる。
   - もう一つは、端の空白に notice を出すことである。直す必要のない書き方を、すべての本で知らせることになる。

## 決めたことの記録

2026-11-10 に、tett23 がすべて推奨のとおりに決めた。

1. 余白は、推奨のとおり空白でない最初と最後の部品に付ける。
2. 端の空白は、推奨のとおり残し、diagnostic も出さない。
