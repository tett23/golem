# ADR 0013: 見出しの脚注がページに入らないときの改ページ

ステータス: 採択

## 文脈

仕様書の「既知の不具合」に、見出しの脚注の扱いがある。
見出しの行に付けた脚注の本文がページに入らないとき、見出しは元のページに残り、注の本文だけが次のページに送られる。
段落の行の場合は、注の印を含む行のほうが次のページに送られる。
[docs/roadmap.md](../../roadmap.md) の「既知の不具合の修正」は、これを v0.1.0-rc3 の項目にし、段落と同じく見出しを送る直し方を案として挙げている。

[golem-layout ADR 0003](0003-pagination-and-s2.md) の注の規則は、ページに行を一行置くたびに注の本文の高さを差し引き、入らなくなったら注の印を含む行を次のページに送ると定めている。
注の本文をページの途中で分けて次のページに続けるのは、一つの注の本文がページの下部に収まらない場合に限る。
見出しを一つのブロックとして置くことにした [golem-driver ADR 0003](../../golem-driver/adr/0003-pdf-heading-styles.md) は、見出しの注を「`putLine` と同じ規則で」置くと書いた。
ところが `putLine` は、行が収まるかどうかを判定せず、渡された行を置いて注の本文を分けるだけの関数である。
行を送るかどうかは、その前の `fitting` が、行と注の本文の全体が入るかで決めている。
見出しの側には `fitting` に当たる判定がないので、ADR の規則が見出しにだけ効いていない。

### 今の振る舞い

`Golem.Layout.Paginate` の `paginateIn` で、見出し（`FHeading`）は次の手順で置かれる。

1. `keep st (n + need)` で、見出しの格子の数 n と、後のブロックの先頭の必要量 `need` が段の残りに入るかを見る。入らなければ次の段に進む。
2. `n <= free st1 || isEmpty st1` で、見出しの格子の数だけが入るかを見る。
3. `putBlock` で見出しを置き、注の本文のうち入る分だけを置き、残りを `sPendingNotes` に積んで次のページに続ける。

どちらの判定も、見出しの注の本文の行と区切りの行を数えない。

小さな例で確かめた（origin/main の e16ab1e、`cabal repl golem-layout`）。
一ページ 8 行で、5 行の段落の後に、3 行の注を持つ一行の見出しと、2 行の段落を続けた。

```haskell
paginate 1 8 [FParagraph (lines' 0 5), FHeading 2 False 1 [LineBox 20 [NoteBody (nid 900) 3] [] []], FParagraph (lines' 30 2)]
-- 1 ページ: SLine 0..4, SHeading 20 1; 注 900 の 0 行めから 1 行
-- 2 ページ: SLine 30, SLine 31;         注 900 の 1 行めから 2 行
```

同じ位置に、3 行の注を持つ行で始まる段落を置くと、その行が次のページに送られ、注の本文は分かれない。

```haskell
paginate 1 8 [FParagraph (lines' 0 5), FParagraph [LineBox 20 [NoteBody (nid 900) 3] [] [], LineBox 21 [] [] []], FParagraph (lines' 30 2)]
-- 1 ページ: SLine 0..4
-- 2 ページ: SLine 20, SLine 21, SLine 30, SLine 31; 注 900 の 0 行めから 3 行
```

見出しの例では、注の本文が分かれるだけでなく、見出しの後の段落も次のページに送られている。
1 の判定は見出しと段落の最初の 2 行の 3 行が残りの 3 行に入ると見たが、見出しを置いた後に注の本文と区切りが残りを使い切ったので、段落が入らなかった。
見出しの直後で改ページしない規則（[golem-layout ADR 0003](0003-pagination-and-s2.md)）も、注を持つ見出しでは破れている。

### 見出しが続くときの改ページとの関係

草稿の [golem-driver ADR 0032](../../golem-driver/adr/0032-default-heading-styles.md)（既定の見出し）は、`nextNeed` の `FHeading` の値を、見出しの格子の数にその次のブロックの `nextNeed` を足した値に替える。
これは、見出しの前のブロックが見出しとその後をどれだけ先まで見るか（先読みの量）の変更である。
この ADR は、見出しそのものが今の段に入るか（見出しの必要量）の判定を変える。
二つの変更は `paginateIn` の別の箇所に効き、どちらを先に実装しても他方の期待値は変わらない。
ただし二つを合わせると、見出し、見出し、段落と続くときの最初の見出しの判定は、最初の見出しの注を数え、二つ目の見出しの注は数えない。
後のブロックの注を先読みで数えないのは、段落の行についての今の `nextNeed` と同じである（「実装しないこと」）。

### メンテナーが決めたこと

- 見出しの注の本文が、何も置いていない段の下部の全体にも入らない場合は、今と同じく空の段に見出しを置き、注の本文を分けて次の段に続ける。段落の行も、空の段では同じ扱いである。

## 実装すること

### 見出しの必要量（golem-layout）

見出しが今の段に置けるかを、見出しの格子の数に、見出しの行の注の本文の行と、その段で最初の注なら区切りの行を足した量で判定する。
段落の行を `fitting` で判定するのと同じ規則であり、注の本文が入らない見出しは、注とともに次の段に送る。

`paginateIn` の中に、見出しの必要量を求める関数を置く。

```haskell
-- 見出しの格子の数、見出しの行の注の本文、その段で最初の注なら区切り
headingNeed :: St -> Int -> [LineBox] -> Int
headingNeed st n ls =
  let noteLines = sum (map nbLines (concatMap lbNotes ls))
      sep = if sNoteLines st == 0 && noteLines > 0 then separator else 0
   in n + noteLines + sep
```

`place` の `FHeading` の場合を、次のように変える。

```haskell
FHeading _ recto n ls ->
  let st1 = if recto then parityStart odd st else keep st (headingNeed st n ls + need)
      st2 = if headingNeed st1 n ls <= free st1 || isEmpty st1 then st1 else nextColumn st1
   in putBlock st2 n ls
```

- `keep` の判定も見出しの必要量で行う。見出しの注の本文が残りを使って、見出しの後の段落が次の段に送られることを防ぐためである。
- 区切りの行の数は段の状態（`sNoteLines`）で変わるので、`keep` の後の段（`st1`）で数え直す。
- 空の段（`isEmpty`）では、今と同じく見出しを置き、`putBlock` で入らない注の本文を次の段に続ける。段落の行を空の段で一行は置くのと同じ扱いである。
- `putBlock` は変えない。注の本文が分かれるのは、空の段に置いた場合だけになる。
- 段組みの版面でも、送る先が次の段になるほかは同じである（[docs/adr/0018](../../adr/0018-multi-column-layout.md)）。

### ドキュメント

- 仕様書の「既知の不具合」から「見出しの脚注」の項目を消す。
- 仕様書の「脚注」の節に、注の本文が入らないときは注の印を含む行か見出しを次のページに送り、注の本文を分けて次のページに続けるのは、ページの先頭に置いても注の本文が収まらない場合に限ることを書き足す。この ADR と [golem-layout ADR 0003](0003-pagination-and-s2.md) へのリンクを付ける。
- [docs/roadmap.md](../../roadmap.md) の「既知の不具合の修正」から「見出しの脚注」の項目を消す。
- 利用者のマニュアルの `manual/appendices/i-known-issues.gm` から「見出しの注の本文だけが次のページに移る」の項目を消す。`manual/appendices/h-roadmap.gm` に同じ項目があれば消す。
- [golem-layout ADR 0003](0003-pagination-and-s2.md) のステータスの行に、見出しの注の扱いをこの ADR で定めたことを、この ADR へのリンクで書き足す。
- [golem-driver ADR 0003](../../golem-driver/adr/0003-pdf-heading-styles.md) のステータスの行に、見出しの注を置く規則（「`putLine` と同じ規則で」）をこの ADR で改めたことを書き足す。

## 実装しないこと

- 後のブロックの注の本文を先読みの量（`nextNeed`）に数えること。段落の行についても今は数えておらず、見出しの後の段落の最初の行の注が入らない場合は、その行が `fitting` で送られる。見出しだけが段の末尾に残る場合は残るが、段落の行と同じ規則の範囲の問題であり、この ADR では扱わない。
- 見出しが続くときの改ページ（[golem-driver ADR 0032](../../golem-driver/adr/0032-default-heading-styles.md) が扱う）。
- 定義リストの用語と表の見出しの行の注。用語の行は `placeLines` の `fitting` で判定されているので、この不具合はない。表の見出しの行の注は、この ADR の対象にしない。
- 傍注（[golem-layout ADR 0006](0006-sidenotes.md)）。傍注は本文の行を送らない。

## テスト設計

実装の前に `modules/golem-layout/test/PaginateSpec.hs` の `headingNoteTests` に足し、今の実装で失敗することを確かめる。
区切りの行の数は変わりうるので（[golem-driver ADR 0024](../../golem-driver/adr/0024-rule-spec-and-footnote-separator.md)）、区切りが 0 行でも 2 行でも結果が変わらない数で組む。

- 一ページ 8 行で、5 行の段落、3 行の注を持つ一行の見出し、2 行の段落の順に置くと、見出しと注の全体が 2 ページに置かれ、1 ページに注がない（`notesByPage ps == [(1, []), (2, [nid 900])]`）。2 ページの先頭が見出しで、続いて段落の 2 行が置かれる。今の実装では見出しが 1 ページに残るので失敗する。
- 一ページ 8 行で、5 行の段落、1 行の注を持つ一行の見出し、2 行の段落の順に置くと、見出しは 2 ページに送られる。見出しと注と区切りで残りの 3 行を使い、段落の最初の 2 行が入らないためである。今の実装では見出しだけが 1 ページの末尾に残るので失敗する。
- 一ページ 10 行で、2 行の段落、1 行の注を持つ一行の見出し、2 行の段落の順に置くと、見出しと注は 1 ページに置かれる（今の実装でも通る）。
- 一ページ 5 行で、6 行の注を持つ一行の見出しを空のページに置くと、見出しは 1 ページに置かれ、注の本文は 2 ページに続く（今の実装でも通る）。
- 2 段組みで、最初の例と同じ流れを置くと、見出しと注が 1 ページの 2 段めに置かれる。
- 段落の行の注の扱い（既存のテスト）が変わらないことを、既存のテストがそのまま通ることで確かめる。

## トレードオフ

見出しを送るので、送った見出しの前のページの末尾に、見出しと注の本文の分の空きが残る。
注の本文を分けて次のページに続ける今の振る舞いは、ページの末尾を埋めるが、見出しと注の本文が別のページに分かれ、見出しの直後で改ページしない規則も破る。
段落の行と同じ規則にそろえることを優先した。

注の多い見出しは、見出しの必要量が大きくなるので、送られやすくなる。
見出しに注を付けることは少なく、付けた場合も、注の本文が見出しと同じページにあるほうが読みやすい。
