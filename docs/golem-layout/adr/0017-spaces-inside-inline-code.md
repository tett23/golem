# ADR 0017: 本文の中のコードの空白を伸び縮みさせない

ステータス: 採択

## 文脈

二つのマニュアルの PDF を読み直したところ、本文の中のコード（文字スタイル `code`）の空白が、行によって大きく広がっていた。
開発者のマニュアルの `golem new DIR` が `golem   new   DIR` のように見え、`cabal build all` も同じように広がる。
利用者のマニュアルの付録 E では、定義の項目の語（G0276 の行）の中のコード `（language = "ja"）` の空白が広がる。
コードは等幅の書体で組み、空白の幅も字の幅と同じであることを前提に読まれる。
空白だけが広がると、原稿に空白が二つ以上あるように読めてしまう。

### 再現

今の `main` から作った golem（a2b6106e）で開発者のマニュアルを組み、22 ページの「プロジェクトの雛形」の節の最初の行の内容のストリームを読んだ。
行は `golem new DIR は、manifest.toml、style.toml、章のファイル、` である。

- コードの書体（Source Code Pro）の字の送りは 5.53pt（13Q の 0.6 倍）である。
- `golem` の `m` の終わりから `new` の `n` の始まりまでが 19.6pt あり、空白の送り 5.53pt の 3.5 倍に広がっていた。`new` と `DIR` のあいだも同じである。
- 同じ行の「章のファイル」も、字のあいだを空けて組まれている。この行は、次の `preflight.toml` が収まらないので追い出しで終わり（PR #231）、足りない幅を行の中のグルーで埋めている。

### 原因

`Golem.Layout.Japanese` の `codePieces` は、コードの中の空白を、本文の空白と同じ `PSpace` にする。
`itemsFor` は `PSpace` を、空白の送りを自然な幅とし、その半分を伸び、三分の一を縮みとするグルーにする。
一方、和文の字のあいだのグルーは、既定のアキ量のセット（[docs/adr/0019](../../adr/0019-aki-settings.md)）で、伸びが 0.1zw である。
コードの空白の伸び（0.3zw）は和文の字のあいだの三倍あり、行を両端揃えにするとき、伸びの比に応じてコードの空白が大きく広がる。
行の中にほかのグルーが少ないほど、コードの空白が受け持つ量は増える。

仕様書は、コードの空白について「空白（U+0020）は詰めずに残し」をコードブロックにだけ定め、本文の中のコードについては、改行してよい位置を空白と `/` の後に限るとだけ定める（[golem-driver ADR 0017](../../golem-driver/adr/0017-pdf-code-blocks.md)）。
本文の中のコードの空白の幅が伸び縮みするかどうかは、どの ADR も定めていない。
`codePieces` の注釈の「spaces as between words」が、今の振る舞いの唯一の記述である。

### 参照した組み方

- JLReq は、等幅の欧文の書体やコードの空白について定めていない。
- InDesign は、両端揃えで語間の空白を伸ばす量を段落の「ジャスティフィケーション」の設定で決め、書体が等幅かどうかで変えない。InDesign にはコードという文字の種類がないので、ここで倣える振る舞いはない。
- TeX は、語間の空白の伸びと縮みを、書体の fontdimen 3 と 4 から取る。等幅の書体 cmtt の fontdimen 3 と 4 は 0 であり、`\texttt` の中の空白は伸び縮みしない。そのうえで、空白の位置での改行はできる。LaTeX の `\verb` は、空白を改行しない空白にし、空白の数もそのまま残す。

## 実装すること

### コードの空白（golem-layout）

文字スタイル `code`（`lkCode` が真の見た目）の空白を、伸びも縮みもないグルーにする。

```haskell
  PSpace lk ->
    let sw = advance env lk ' '
     in if lkCode lk
          then [Glue (sw + tracking lk) 0 0] -- 本文の中のコードの空白は伸び縮みしない（golem-layout ADR 0017）
          else [Glue (sw + tracking lk) (sw `div` 2) (sw `div` 3)]
```

- 空白の幅は、今のとおりコードの書体の空白の送りにトラッキングを足した値とする。
- 空白の位置での改行は、今のとおりできる。グルーは箱の直後にあるので、行分割の候補になる。行末に来た空白は捨てる。
- 空白の並びを一つにまとめる今の扱い（`codePieces` の `T.dropWhile (== ' ')`）は変えない。HTML と EPUB の `<code>` も空白の並びを一つにまとめて表示するので、出力のあいだでそろう。
- 文字スタイル `url`（`lkUrl`）の空白は変えない。`url` の文字は周りの文字の書体のまま組むので、空白も本文の語間の空白として扱う。
- コードの背景と余白（[golem-driver ADR 0029](../../golem-driver/adr/0029-inline-code-background.md)）は変えない。

### 行の揃え方

コードの空白が伸びないぶん、行の不足は、行の中のほかのグルー（和文の字のあいだ、和欧間の空き、コードの外の語間の空白）が受け持つ。
伸びるグルーがない行、たとえばコードだけでできた行は、両端揃えにできない。
その行は今の行分割の最後の段（[golem-layout ADR 0001](0001-knuth-plass-line-breaking.md)、PR #231 の追い出し）で、自然な幅のまま行頭に寄せて組まれる。
行分割と行の配置の処理は変えない。

### ドキュメント

- 仕様書の、文字スタイル `code` の文字の改行の段落に、本文の中のコードの空白は、コードの書体の空白の送りの固定の幅で組み、両端揃えのために伸び縮みさせないことを書き、この ADR へのリンクを付ける。伸びるグルーのない行は行頭に寄せることも書く。
- 利用者のマニュアルの付録 C（`manual/appendices/c-style.gm`）の文字スタイル `code` の説明に、同じことを書く。

## 実装しないこと

- コードの外の空白（`[code: golem new DIR] は` の `]` と `は` のあいだの空白）。本文の語間の空白として、今のとおり伸び縮みする。和文とコードのあいだの空白を和欧間の空きとして扱うかは、この ADR では決めない。
- コードの中の空白の並びを、原稿の数のまま残すこと。HTML と EPUB の表示とそろえるため、今のとおり一つにまとめる。
- コードの中の空白で改行しないこと（LaTeX の `\verb`）。長いコマンドの例が行長を超えると、追い出しても収まらず、行があふれるからである。
- コードブロック。空白は既に固定の幅で組んでいる。
- コードの字のあいだを伸ばして両端揃えにすること。

## テスト設計

実装の前に書き、失敗することを確かめる。

### golem-layout（`modules/golem-layout/test/Main.hs`）

- `lkCode` が真の見た目の `golem new DIR` を `composeInlines` で項目にすると、二つの空白はどちらも伸びと縮みが 0 のグルーであり、幅は空白の送りとトラッキングの和である。
- `lkCode` が偽の見た目の `a b` の空白は、今のとおり伸びが送りの半分、縮みが三分の一のグルーである。
- `lkUrl` が真で `lkCode` が偽の見た目の空白も、今のとおり伸びと縮みを持つ。
- 和文の字とコードの `x y` を一行に収め、行長を自然な幅より長くした段落を組むと、`placeLine` の結果で、コードの空白の幅が自然な幅のままであり、行の不足は和文の字のあいだのグルーが受け持つ。
- コードの `a b c d` だけの段落を、自然な幅より長い行長で組むと、一行になり、空白の幅は自然な幅のままである（行頭に寄る）。
- 長いコード `a b c d e f g h` を、行長を一部の語だけが収まる長さにして組むと、空白の位置で改行し、各行の行末の空白は行に残らない。

### golem-driver（`modules/golem-driver/test/ParagraphSpec.hs`）

- 開発者のマニュアルの書体（Source Code Pro を `code` の役割の欧文の書体にする）で、22 ページの段落と同じ原稿（`[code: golem new DIR] は、[code: manifest.toml]、…`）を組む。最初の行の `golem` の最後の字の終わりから `new` の最初の字の始まりまでが、空白の送り（5.53pt）に等しい。

### 自動テストにしない確かめ方

- 二つのマニュアルを組み、開発者のマニュアルの 22 ページと利用者のマニュアルの付録 E の G0276 の行を PNG に描いて、コードの空白が一字分に見えることを確かめる。同じ行の和文の字のあいだがどれだけ広がるかも見る。

## トレードオフ

コードの空白を固定にすると、行の不足を受け持つグルーが減る。
コードを多く含む行では、和文の字のあいだがそのぶん広がる。
22 ページの行では、今は字のあいだとコードの空白の両方が広がっているが、変えたあとは字のあいだだけが広がる。
等幅の書体で、空白だけが字の三倍以上に広がると、空白の数を読み違えるおそれがあり、和文の字のあいだが少し広がるほうが害が小さいと判断した。

TeX の等幅の書体の空白も伸び縮みしないので、LaTeX で組んだ技術書と同じ見た目になる。
代わりに、コードだけでできた行は両端揃えにならず、行末がそろわない。
この行はもともと改行の位置が少なく、両端揃えにすると空白が大きく広がる行なので、行頭に寄せるほうを選んだ。
