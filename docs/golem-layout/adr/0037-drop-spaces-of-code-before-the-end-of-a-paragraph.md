# ADR 0037: 段落の終わりと強制改行の前の本文の中のコードの空白も、行分割の前に捨てる

ステータス: 採択（未実装）

## 文脈

仕様書の「既知の不具合」に、「段落の終わりの本文の中のコードの空白で改行し、箱のない最後の行を作る」がある。
[golem-layout ADR 0034](0034-line-breaks-between-japanese-characters-in-inline-code.md) の実装（[#713](https://github.com/tett23/golem/pull/713)）が、コードの並びの列挙で T1 の違反として見つけた（[golem-layout ADR 0032](0032-drop-word-spaces-before-the-end-of-a-paragraph.md) の T1：最後の行は箱を一つ以上持つ）。
テストの既知の不具合の一覧（[`codeLineBugs`](https://github.com/tett23/golem/blob/c638870fb9f5fb8a66d13308fef727a7e202de19/modules/golem-layout/test/LineBreakInvariantsSpec.hs#L715-L729)）の二つめの項目が、これを除く。
除いた入力は、部品 2 個までで 36、3 個までで 525 である。

### 最も小さい例

2026-11-08 に、origin/main（`ec295f03`）の golem-layout のテストに一時のテストを足し、コードの並びの列挙と同じ送りで組んで確かめた（コミットしていない）。
`あ` を前に置き、段落の終わりに `[code: 漢 ]` を置いて、2 字の行で組むと、次のようになる。

| 段落 | 行の幅 | 行 |
| --- | --- | --- |
| `あ[code: 漢 ]` | 2 字 | `あ漢`、箱のない行 |
| `ああ[code: 漢 ]` | 3 字 | `ああ漢`、箱のない行 |
| `あ[code: 。 ]` | 2 字 | `あ。`、箱のない行 |

列挙の送りでは、コードの空白は 1/4 em である。
`あ漢` で行はちょうど埋まり、空白を加えると行長を 1/4 em 超える。
空白は伸び縮みしないので、最適な分割は空白での分割になり、空白の後には段落の終わりの項目しか残らない。
[golem-layout ADR 0032](0032-drop-word-spaces-before-the-end-of-a-paragraph.md) の「文脈」の `ああ ` と同じ形である。

### 0032 は、コードの空白を残すと決めた

0032 は、段落の終わりと強制改行の前の語間の空白を、行分割の前に捨てた（[`trailingSpaces`](https://github.com/tett23/golem/blob/c638870fb9f5fb8a66d13308fef727a7e202de19/modules/golem-layout/src/Golem/Layout/Japanese.hs#L439-L466)）。
語間の空白は、伸びるグルー（`isWordSpace`）として見分ける。
コードの空白は伸び縮みしないグルーなので（[golem-layout ADR 0017](0017-spaces-inside-inline-code.md)、[`Japanese.hs`](https://github.com/tett23/golem/blob/c638870fb9f5fb8a66d13308fef727a7e202de19/modules/golem-layout/src/Golem/Layout/Japanese.hs#L870-L875)）、捨てない。
0032 は、その理由を「背景を塗るので、紙面に見える」とし、不変条件 T3（コードの空白のグルーは、行の終わりの前でも残る）と、テスト「T3: a space of code at the end stays」で固定した。
0032 の列挙は、コードの並びを持たなかったので、T1 の違反は見つからなかった。

### 最後の空白には、背景を塗らない

0032 の理由は、コードの最後の空白には当たらない。
本文の中のコードの背景は、行の中の同じスウォッチの箱の並びの、最初の箱の始まりから最後の箱の終わりまでに塗る（[`codeBackgrounds`](https://github.com/tett23/golem/blob/c638870fb9f5fb8a66d13308fef727a7e202de19/modules/golem-typeset/src/Golem/Typeset/Draw.hs#L690-L713)）。
箱のあいだの空白は塗るが、最後の箱の後のグルーは塗らない。
コードの最後の空白は、紙面では、背景の外の空きである。

あわせて、コードの最後か最初に空白があると、そのコードの後ろか前の余白（`padding`）がなくなることがわかった。
[`padCode`](https://github.com/tett23/golem/blob/c638870fb9f5fb8a66d13308fef727a7e202de19/modules/golem-layout/src/Golem/Layout/Japanese.hs#L1028-L1058) は、余白を、コードの並びの最初と最後の部品に付ける。
最後の部品が空白（`PSpace`）なら、余白を付ける先がない。
上と同じ一時のテストで、`padding = 250` の `code` に `あ `、` あ`、`あ` を組み、`あ` の箱の余白を読んだ。

| コード | `あ` の前の余白 | `あ` の後の余白 |
| --- | --- | --- |
| `[code: あ]` | 250 | 250 |
| `[code: あ ]` | 250 | 0 |
| `[code: ␣あ]`（前に空白） | 0 | 250 |

これは段落の終わりに限らない、別の原因の不具合である（「実装しないこと」）。

### TeX と HTML

TeX は、段落を行に分ける前に、段落の最後の項目がグルーなら除く（tex.web の §816）。
グルーの種類を問わない。

Google Chrome 156.0.8078.80 の headless で、`<p style="width: 2em">ああ<code>漢 </code></p>` を描くと、行は `ああ` と `漢 ` の二つで、箱のない行はできなかった。
`<p style="width: 2em">あ<code>漢 </code></p>` は一行だった。
ブラウザーは、行末の空白を行の幅に数えず、空白だけの行も作らない。

## 実装すること

### 1. 段落の終わりと強制改行の前のコードの空白を捨てる

`trailingSpaces` が捨てる項目に、本文の中のコードの空白のグルーを加える。

- 捨てる範囲は、語間の空白と同じく、行の終わりの項目（段落の終わりと強制改行の `lineEnd`）と、その前の最後の箱のあいだである。あいだに箱でない項目（アンカー）があっても、箱がなければ捨てる。
- コードの空白は、`lkCode` の `PSpace` から作ったグルーとして見分ける。グルーの形（伸びも縮みも 0）だけでは見分けない。アキ量のセットの空きにも、伸び縮みしないグルーがありうるからである。見分け方（`PSpace` の位置を覚える、グルーに印を持たせる、など）は、実装のプルリクエストで決める。
- アンカーの位置は、0032 と同じく、捨てた後の項目の位置に合わせる。

原稿の字は変えない。
HTML、EPUB、プレーンテキストの出力は、今のとおり空白を書く。
変わるのは PDF の行分割の項目だけである。

### 2. 0032 の T3 を改める

0032 の T3（コードの空白のグルーは、行の終わりの前でも残る）を、この ADR の B3 に改める。
テスト「T3: a space of code at the end stays」を、B3 のテストに置き換える。
[golem-layout ADR 0032](0032-drop-word-spaces-before-the-end-of-a-paragraph.md) のステータスの行を `採択→コードの空白（T3 と「実装すること」の 1 のコードの空白の文）は [golem-layout ADR 0037](0037-drop-spaces-of-code-before-the-end-of-a-paragraph.md)` にする。

### 3. テストの既知の不具合の一覧から消す

`codeLineBugs` から、「段落の終わりの本文の中のコードの空白で改行し、箱のない最後の行を作る」の項目を消す。
残るのは、「本文の中のコードの空白で、禁則に当たる位置でも改行する」だけである（[golem-layout ADR 0038](0038-kinsoku-across-spaces-of-inline-code.md) で直す）。

### 4. 文書

- 仕様書の「行分割」の節の「段落の終わりと強制改行の前の語間の空白は、行分割の前に捨てる」に、本文の中のコードの空白も捨てることと、この ADR へのリンクを足す。
- 仕様書の文字スタイル `code` の段落の「空白の位置では今までどおり改行でき、行末に来た空白は捨てる」に、段落の終わりと強制改行の前の空白も捨てることを足す。
- 仕様書の「既知の不具合」から、項目を消す。
- 「行分割」の節の、コードの並びの既知の不具合の文（「…の違反は、一覧で除き、除いた入力の数（部品 2 個までで 39 と 36、3 個までで 2703 と 525）を固定する」）を、残る一つの項目と、その数に改める。

### 5. 出力の変化

段落の終わりか強制改行の前に、最後に空白を書いた本文の中のコードを持つ段落だけが変わる。
箱のない最後の行がなくなるほか、中央揃えと行末揃えの最後の行の位置が、空白の幅に応じて変わりうる（0032 の「出力の変化」と同じく、コードから読んだ推定で、PDF では確かめていない）。
背景と余白の描き方は変わらない。
実装のプルリクエストで、golden、`scripts/visual/` の参照、二つのマニュアルと complex fixture の決定性のハッシュが変わるかを確かめ、説明に書く。

## 実装しないこと

- **コードの最初か最後の空白で余白がなくなること**：段落の終わりでなくても起きる、別の原因の不具合である（「文脈」）。仕様書の「既知の不具合」と docs/roadmap.md に足し、別の ADR で直す（「メンテナーが決めること」の 3）。
- **段落の始まりのコードの空白**：前に箱がないので、分割の候補にならない（0032 の「実装しないこと」と同じ）。
- **段落の中ほどのコードの空白**：[golem-layout ADR 0017](0017-spaces-inside-inline-code.md) のまま、伸び縮みしない分割の候補とする。禁則は [golem-layout ADR 0038](0038-kinsoku-across-spaces-of-inline-code.md) で扱う。
- **コードブロックの空白**：別の規則で折り返すので、変えない。
- **空白を書いたことの diagnostic**：0032 と同じく、足さない。

## 不変条件

「行の終わり」は、段落の終わりと強制改行の `lineEnd` の項目とする。
「コードの空白」は、`lkCode` の `PSpace` から作ったグルーとする。

- **B1**：最後の行と、強制改行で終わる行は、箱を一つ以上持つ（0032 の T1）。コードの最後の空白を持つ段落も、除かない。
- **B2**：行の終わりと、その前の最後の箱のあいだに、語間の空白のグルーもコードの空白のグルーもない。
- **B3**：行の終わりとのあいだに箱を挟むコードの空白のグルーは、この ADR の前と同じく残る（`[code: a b]` の空白など）。
- **B4**：行の終わりの前にコードの空白がない段落の項目は、この ADR の前と同じである。
- **B5**：プレーンテキスト、HTML、EPUB の出力は、この ADR の前と同じである。
- **B6**：伸び縮みしないグルーのうち、コードの空白でないものは、行の終わりの前でも残る。

境界の入力：

| 量 | 調べる値 |
| --- | --- |
| 空白の前の箱 | 和文の字（`漢`）、句点（`。`）、始め括弧類（`「`）、欧文の字（`a`） |
| 空白と行の終わりのあいだ | なし、索引のアンカー、コードの外の語間の空白（`[code: a ] `） |
| 行の終わり | 段落の終わり、強制改行 |
| 空白の数 | 一つ、二つ続く（一つにまとめる） |
| 段落の揃え | 両端揃え、行頭揃え、中央揃え、行末揃え |
| 行の残りの幅 | 空白の前でちょうど終わる、空白の幅だけ足りない、空白も入る |
| 空白の後 | 段落の終わり、コードの外の箱（`[code: 漢 ]い`、変わらない） |

## テスト設計

テストを先に書き、今の実装で失敗することを確かめてから実装する。
テストの名前には、B1 から B6 の番号を入れる。

- **B1、B2**：`LineBreakingSpec` で、2 字の行に、`あ` と段落の終わりの `[code: 漢 ]` を組み、行が `あ漢` の一つであること。今は箱のない行ができるので失敗する。`[code: 漢 ]` の項目が、`[code: 漢]` と同じであること。
- **B1、B2**：強制改行の前の `[code: 漢 ]` と、`[code: 漢 ]` の後に索引のアンカーを置いた段落で、同じであること。
- **B1**：`codeLineBugs` から項目を消し、コードの並びの段 2 のすべての入力で T1 の違反がないこと。今は 36 の入力が違反するので失敗する。段 3 は毎晩の `enum.yml` で確かめる。
- **B3**：`[code: a b]` の空白のグルーが残り、分割の候補であること。`[code: 漢 ]い` の空白が残ること。
- **B4**：0032 の T1、T2 のテストと、[golem-layout ADR 0017](0017-spaces-inside-inline-code.md) のテストが、そのまま通ること。
- **B5**：golem-driver のテストで、段落の終わりの `[code: 漢 ]` のプレーンテキストと HTML の出力が、空白を含むこと。
- **B6**：伸び縮みしないアキ量のセットの空きのグルーを、行の終わりの前に置いた項目の並びで、そのグルーが残ること。そうした空きを作る原稿がなければ、`trailingSpaces` に項目を手で渡して確かめる。
- 中央揃え：段落の終わりの `[code: 漢 ]` を中央揃えで組み、行の位置が `[code: 漢]` と同じであること。

## トレードオフ

0032 の T3 を改める。
0032 が空白を残した理由は、紙面に見えることだったが、最後の空白は背景の外にあり、紙面では空きとしてしか見えない。
残すと、空きのために箱のない行ができる。
捨てても、背景と余白の描き方は変わらない。

中央揃えと行末揃えでは、最後の行の位置が空白の幅だけ動きうる。
書き手がコードの最後の空白で位置をずらす意図を持つとは考えにくい。
ずらしたいなら、`[aki]` で書ける。

コードの空白を、グルーの形でなく作った部品で見分けるので、`trailingSpaces` が項目の並びのほかに知ることが増える。
形で見分ければ簡単だが、伸び縮みしない空きを、空白と取り違えるおそれがある。

## メンテナーが決めること

1. **段落の終わりのコードの空白をどうするか**：推奨は、語間の空白と同じく、行分割の前に捨てることである。TeX と同じ扱いで、ブラウザーも空白だけの行を作らない。0032 の残す理由（背景）は、最後の空白には当たらない。
   - 退けた案の一つは、空白を残し、その空白の分割を禁じる（前に罰点 10000 を置く）ことである。紙面に見えない空白の幅が行に残り、`あ漢` のように行がちょうど埋まる段落で、`漢` を次の行に送り出すか、行長を超えて G07105 になる。
   - 二つめは、今のままにし、既知の不具合として残すことである。箱のない行が紙面に残る。
2. **強制改行の前のコードの空白も捨てるか**：推奨は、捨てることである。0032 の「メンテナーが決めること」の 2 と同じく、強制改行は段落の終わりと同じ行の終わりの項目を置く。
   - 退けた案は、段落の終わりだけにすることである。同じ項目の並びに、二つの扱いが残る。
3. **コードの最初と最後の空白で余白がなくなる不具合をどう扱うか**：推奨は、この ADR では直さず、仕様書の「既知の不具合」と docs/roadmap.md に足して、別の ADR で直すことである。段落の終わりに限らず起き、原因（`padCode` が余白を付ける部品）も別である。
   - 退けた案は、この ADR で一緒に直すことである。一つの ADR に、原因の違う二つの修正が入る。
