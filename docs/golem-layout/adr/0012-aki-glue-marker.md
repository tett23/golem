# ADR 0012: `[aki]` の空きを箱で表す

ステータス: 採択

## 文脈

`[aki 量]` は、原稿の任意の位置に幅の決まった空きを置く（[docs/adr/0019](../../adr/0019-aki-settings.md)）。
`[aki]` の前後では行を分けず、`[aki]` を挟んだ二つの字の間にはアキ量のセットの空きを足さない。

`Golem.Layout.Japanese` の `itemsFor` は、`PAki` を次の二つの項目にする。

```haskell
PAki lk a -> ... [Penalty 0 infPenalty NoHyphen, Glue w 0 0]
```

`normalize` は、アキ量のセットの空きを足すときに `[aki]` の位置を見分ける必要がある。
今は、伸びも縮みもしない `Glue`（`Glue _ 0 0`）という形で見分けている。

```haskell
-- the glue of an [aki], after its penalty
Glue _ 0 0 -> x : go AfterAki first rest
```

`normalize` が形を調べるのは、`itemsFor` が作った項目だけである。
アキ量のセットの空きの `Glue` は、`normalize` が箱の前に足すもので、形を調べ直さない。
`itemsFor` が作る `Glue` は、`[aki]` のほかに、語間の空白（`PSpace`）と行の終わり（`lineEnd`）の `Glue` がある。
行の終わりの `Glue` は伸びを持つ。
語間の空白の `Glue` は、空白の送り `sw` に対して `Glue (sw + t) (sw/2) (sw/3)`（`t` はトラッキング）であり、`sw` が 0 でない限り伸び縮みする。
今の書体ではこの形は出ないが、空白の送りが 0 の書体を役割に指定すると、`Glue 0 0 0` が出る。
`normalize` はそれを `[aki]` と取り違え、次の箱を `[aki]` の後の箱として扱う（空白の後の箱に `AtStart` として付く空きが付かなくなる）。
仕様書の「v1 の実装で次の段階以降に回した項目」の「`[aki]` の空きの見分け方」である。

`Item` の三つの構成子（`Box`、`Glue`、`Penalty`）は Knuth と Plass の行分割の項目そのものであり、`Golem.Layout.KnuthPlass` は TeX との参照テスト（[ADR 0007](0007-knuth-plass-reference-test.md)）で確かめている。
`Glue` に印の欄を足すと、行分割の型と、それを作る 50 を超える箇所を変えることになる。
一方、`Box` の `BoxContent` には、行分割が読まない後段のための欄（`bcTag`）がすでにある。

`[aki]` の `[Penalty 0 infPenalty NoHyphen, Glue w 0 0]` は、行分割にとって幅 `w` の箱と同じ働きをする。
`Glue` が分割の位置になるのは直前の項目が箱のときだけなので、`Penalty` の後の `Glue` では分割しない。
`Penalty` は罰点が無限大なので、そこでも分割しない。
伸びも縮みもないので、行の調整にも加わらない。

## 実装すること

### `[aki]` を箱にする

`BoxKind` の最後に `KindAki` を加える。
既存の値の `fromEnum` を変えないため、最後に置く。

`itemsFor` は、`PAki` を幅 `w` の空の箱一つにする。

```haskell
PAki lk a -> [Box w (BoxContent "" False 0 0 (fromEnum KindAki) lk 0 0)]
```

- `w` の求め方は今と変えない（`zw` はその位置の文字の大きさで測る）。
- 前の `Penalty` は置かない。箱と箱の間には分割の位置がないので、前後で行を分けないことは今と同じである。

### `normalize`

- `Glue _ 0 0` の分岐を消す。すべての `Glue` は、`[aki]` でないほかの項目と同じく扱う。
- `KindAki` の箱は、前の箱との空きを求めずにそのまま置き、次の箱の前の状態を `AfterAki` にする。`first` の値は変えない。段落の先頭の `[aki]` の後の最初の字は、今と同じく段落の先頭の字として扱う。
- `KindAki` の箱には、行頭と行末の空き（`withEdges`）を付けない。
- `alignPositions` は、`KindAki` の箱も箱として数える。`normalize` が箱の前に項目を足さないので、位置の対応は今と同じく保たれる。

### 行頭と行末に来た `[aki]`

`[aki]` は前後で分割しないので、行頭か行末に来るのは、段落の先頭と末尾、強制改行（[docs/adr/0016](../../adr/0016-hard-line-breaks.md)）の前後に書いた場合だけである。
今は、行の最初と最後の箱は `[aki]` の隣の字であり、`KnuthPlass` はその字の行頭と行末の空き（`bcEdgeStart`、`bcEdgeEnd`）と突き出しを使う。
箱にすると、行の最初か最後の箱は `[aki]` の箱になり、隣の字の行頭と行末の空きは使わない。
`[aki]` を書いた位置の空きは書き手が決めたもの、という [docs/adr/0019](../../adr/0019-aki-settings.md) の扱いに合うので、この変化を受け入れる。

### 描画

golem-driver の `drawLineAt` は、`KindAki` の箱に何も描かない。
今の `_` の分岐が空の文字列を描かないので、分岐を足す必要はないが、意図を示すために `KindAki` の分岐を明示する。

### ドキュメント

- 仕様書の「v1 の実装で次の段階以降に回した項目」から「`[aki]` の空きの見分け方」の項目を消す。
- 仕様書に `[aki]` の行分割の項目の形を書いた箇所があれば、箱の形に直す。
- [docs/adr/0019](../../adr/0019-aki-settings.md) のステータスの行に、`[aki]` の項目の形をこの ADR で変えたことを、この ADR へのリンクで書き足す。
- マニュアルは変えない。行の中の結果は、行頭と行末に来た `[aki]` の場合を除いて変わらない。行頭と行末の扱いはマニュアルに書いていない。

## 実装しないこと

- `Glue` と `Penalty` に印の欄を足すこと。行分割の型と参照テストを変えずに済む方を選ぶ。
- `[aki]` の前後での分割を許す設定。
- 伸び縮みする `[aki]`。

## テスト設計

実装の前に書き、失敗することを確かめる。
`modules/golem-layout/test/Main.hs` に書く。

- `漢[aki 五分]A` の項目が、漢の箱、幅 `fs/5` の `KindAki` の箱、A の箱になり、和欧間の `Glue` も `Penalty` も含まない。[docs/adr/0019](../../adr/0019-aki-settings.md) のテスト設計の `[箱 漢, Penalty 0 inf, Glue (fs/5) 0 0, 箱 A]` の期待値を、この形に直す。
- 空白の送りを 0 にした測る関数（`ceAdvance` が空白に 0 を返す）の環境で `A 漢` を組むと、空白の `Glue 0 0 0` の後の漢の前で、`Glue` が `[aki]` として扱われない。今の実装では `Glue 0 0 0` を `[aki]` と取り違えるので、項目の列が `[aki]` の場合と同じになり、失敗する。期待値は、同じ環境で `[aki]` を含まない `A 漢` を、空白の送りを 0 より大きくして組んだ場合と、`Glue` の幅を除いて同じ項目の並びとする。
- `[aki 全角]` を段落の先頭に置いた段落で、最初の字が段落の先頭の字として扱われる（`leading` の空きが付かない）。今と同じ結果である。
- `」[aki 全角]` を段落の末尾に置いた段落で、行の最後の箱が `KindAki` の箱であり、行末の空きが `」` に付かない。
- `[aki]` を含む段落の行分割の結果（行の切れ目と各行の調整比）が、行頭と行末に `[aki]` がない場合に今と同じである。既存の `[aki]` のテストと、マニュアルの「空きを入れる」の節の例で確かめる。
- golem-driver の既存の PDF の golden テストのうち `[aki]` を含むものが変わらない。

## トレードオフ

`[aki]` を空の箱にしたので、行分割から見ると `[aki]` は字と同じ扱いになる。
空きを `Glue` で表す今の形のほうが意味に近いが、`Glue` の形で見分ける限り取り違えは避けられない。
箱の `bcTag` は描画のための欄だが、`normalize` が箱の種類で振る舞いを変えるのはルビ（`KindRuby`）と同じであり、新しい仕組みは要らない。

行頭と行末に来た `[aki]` で、隣の字の行頭と行末の空きを使わなくなる。
段落の先頭に `[aki]` を書いて始め括弧を置いた場合などで、見た目が変わる。
書き手が空きを書いた位置で、さらに組版の規則の空きを足し引きしないほうが、書いた量のとおりに組める。
