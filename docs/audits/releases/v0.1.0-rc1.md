# v0.1.0-rc1 の確かめの記録

[docs/adr/0008](../../adr/0008-first-release-verification.md) の手順で、最初のプレリリース v0.1.0-rc1 を確かめた記録です。
2026-10-13 に確かめ、同じ日に公開しました。

## 対象

- **タグ**：`v0.1.0-rc1`（軽量のタグ）
- **タグのコミット**：`8c537ce6c39076a8b879f5ca83c584c23999eba5`（[#46](https://github.com/tett23/golem/pull/46) のマージのコミット）
- **リリース**：https://github.com/tett23/golem/releases/tag/v0.1.0-rc1
- **タグの push で動いたワークフロー**：https://github.com/tett23/golem/actions/runs/38407274494（すべてのジョブが通った）

## 手順 2 と 3：workflow_dispatch の試し

`release/v0.1.0-rc1` のブランチで `workflow_dispatch` を 7 回走らせました。
失敗の原因を直す変更は、[ADR 0008](../../adr/0008-first-release-verification.md) の手順 3 のように別のプルリクエストにはせず、#46 のブランチに積みました。
どれもリリースの仕組み（`scripts/release/`）の不具合の修正で、仕様は変えていません。

この 7 回の中で、`release` のジョブが実行されず、リリースが作られないことを確かめました。

## 手順 4：main に含まれないタグ

使い捨てのブランチ `release-test/off-main` で `VERSION` を `0.1.0-test1` にしたコミットに `v0.1.0-test1` を付けて push しました（[38382867709](https://github.com/tett23/golem/actions/runs/38382867709)）。
`version` のジョブが `the tag v0.1.0-test1 is not on main` で失敗し、`build` 以降は実行されませんでした。
確かめたあと、残りのジョブを取り消し、タグとブランチを削除しました。

## 見つけた問題

- **`golem new` のメモリ**：雛形のフォントを取得する `golem new` の最大の常駐メモリが、macOS で約 2.27GB でした（`/usr/bin/time -l`）。`golem build` は約 220MB です。メモリが 2GB の Docker の中では、Linux の配布物の `golem new` が強制終了されました。CI のランナーはメモリが多く、`smoke` ジョブでは表に出ていませんでした。公開を止めず、リリースノートの既知の問題に書いて v0.1.0-rc2 で直すことにしました。
- **試しの失敗の修正の置き場所**：[ADR 0008](../../adr/0008-first-release-verification.md) の手順 3 は、失敗の修正を別のプルリクエストで `main` に入れると定めていますが、今回は #46 のブランチに積みました。修正がどれもリリースの仕組みの中に閉じていて、#46 と一緒に確かめるほうが早かったためです。
- **リリースノートの抜け**：AI のノートに三つのプルリクエストが載らず、`check-notes.sh` もそれを検出しませんでした。
