# ADR 0001: LSP サーバー

ステータス: 採択

## 文脈

v1 の LSP は、診断、定義への移動と参照の検索、ラベルの名前変更、補完、`[= ...]` の評価結果のホバー、整形、見出しのアウトラインを持つ（specifications.md）。
LSP は書きかけで構文エラーを含む原稿を常に扱うので、構文エラーから回復して木を作るパーサー（[golem-parser ADR 0002](../../golem-parser/adr/0002-parser-on-peg-hs.md)）が前提になる。
章ファイルは単独で検査できる単位であり、編集のたびに変わるのは、たいていそのファイルの S0 の結果と、S1 の見出しの索引だけである。

## 実装すること

### プロトコル

- LSP 3.17 に従い、Haskell の `lsp` パッケージで実装する。
- 位置の単位は、クライアントが対応していれば UTF-8 を、そうでなければ UTF-16 を交渉で選ぶ。変換は [golem-syntax ADR 0001](../../golem-syntax/adr/0001-source-spans-and-diagnostics.md) の関数を使う。
- 文書の同期は、全文の同期とする。

### ワークスペース

- `manifest.toml` のあるディレクトリをプロジェクトのルートとする。
- 編集中の内容は、ディスクのファイルより優先する。
- マニフェストから到達しないファイルは、構文解析と S0 だけを行い、S1 の診断を出さない。

### 再評価

- 文書が変わったら、そのファイルを構文解析し、S0 で評価し直す。
- S0 の結果のうち、見出し、ラベル、import される変数が変わった場合だけ、S1 と、影響を受けるほかのファイルを評価し直す。
- 連続した入力の途中で評価を繰り返さないよう、最後の変更から一定の時間を待ってから評価する。

### 機能

| 機能 | 内容 |
|---|---|
| 診断 | 構文エラー、コンパイルエラー、lint（[golem-lint ADR 0001](../../golem-lint/adr/0001-lint-rules.md)）。lint の重大度は dev のプロファイルで決める |
| 定義への移動 | `@import` のパス、名前空間を通した変数、ラベル |
| 参照の検索 | 変数とラベル。ラベルはファイルをまたいで検索する |
| 名前の変更 | ラベルの名前を、定義とすべての参照で一括して書き換える。新しい名前が既存のラベルと重なる場合は拒否する |
| 補完 | コマンドの名前（組み込みとプラグイン）、ラベルの名前、`@import` のパス、`style.toml` のスウォッチと文字スタイルの名前 |
| ホバー | `[= ...]` の評価結果。S1 で決まる値は S1 の結果を表示し、ページ番号のように S2 で決まる値はその旨を表示する |
| 整形 | [golem-fmt ADR 0001](../../golem-fmt/adr/0001-formatter.md) を呼ぶ |
| アウトライン | 見出しの階層 |

### プラグイン

プラグインのコマンドを含むファイルの評価には、プラグインのキャッシュを使う。
キャッシュにないプラグインは、`golem plugin fetch` を求める診断を出し、そのコマンドを含む部分だけを評価しない。
LSP はネットワークに接続しない。

### 起動

golem-cli に `golem lsp` を加え、標準入出力で LSP を話す。

## 実装しないこと

- 組版結果のプレビュー。
- 差分の同期とインクリメンタルな再解析。
- コードアクションのうち、名前の変更と lint の修正案の適用以外のもの。
- レイアウト（S2）とバックエンドの実行。

## テスト設計

- LSP のメッセージを送るテスト用のクライアントで、各機能の要求と応答を golden テストで固定する。
- 構文エラーを含むファイルで、エラーの箇所の外で補完と定義への移動が働くことを確かめる。
- ラベルの名前の変更が、ファイルをまたぐすべての参照を書き換え、重複する名前を拒否することを確かめる。
- 見出しを変えたときだけ、ほかのファイルの再評価が起きることを確かめる。
- UTF-8 と UTF-16 の位置の交渉で、日本語と 4 バイトの文字を含む行の位置が正しく変換されることを確かめる。

## トレードオフ

全文の同期を使うので、大きなファイルでは編集のたびに全文を送り直すことになる。
章ファイル単位の原稿は大きくなりにくく、差分の同期とインクリメンタルな再解析は、遅さが問題になってから扱う。
