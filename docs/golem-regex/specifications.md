# golem-regex 仕様書

golem-regex は、正規表現スタイル（[docs/adr/0015](../adr/0015-regex-styles.md)）の正規表現を解釈し、照合するパッケージである。
InDesign の正規表現の方言（Boost の Perl 互換）の部分集合を、Haskell で再実装している。
依存は `base`、`text`、`containers`、`array` だけであり、C のライブラリを使わない。

## API

モジュールは `Golem.Regex` 一つである。

```haskell
data Regex            -- コンパイルした正規表現。Eq と Show は元の文字列で比べる
data RegexError = RegexError
  { reOffset :: !Int, -- 正規表現の中の誤りの位置（文字の数、0 から）
    reMessage :: !Text
  }

compile :: Text -> Either RegexError Regex
matches :: Regex -> Text -> [(Int, Int)]
matchesCounting :: Regex -> Text -> ([(Int, Int)], Int)
programSize :: Regex -> Int
maxProgramSize :: Int  -- 10000
```

- `matches` は、重ならない一致の範囲 `[始まり, 終わり)` を、対象の文字の数で返す。
- `matchesCounting` は、`matches` と同じ結果と、照合の手順の数を返す。テストで手順の上限を確かめるためにある。
- `programSize` は、照合のプログラムの命令の数である。手順の上限の計算に使う。

## 方言

| 構文 | 意味 |
|---|---|
| 文字 | その文字に一致する |
| `\` と英数字でない文字 | その文字に一致する（`\.`、`\\`、`\[`、`\~` など） |
| `\t`、`\n` | タブ、行の区切り |
| `\xHH`、`\x{H...}` | 符号位置で書いた文字。`\xHH` は 16 進数の 2 桁、`\x{...}` は 1 桁から 8 桁で、サロゲートと U+10FFFF を超える値は誤り |
| `.` | `\n` を除く任意の一字 |
| `[...]`、`[^...]` | 文字クラス。範囲、文字クラスのエスケープ、POSIX の文字クラスを含められる。先頭（`^` の後）の `]` と、先頭か末尾の `-` は文字になる |
| `[:alpha:]`、`[:digit:]`、`[:alnum:]`、`[:upper:]`、`[:lower:]`、`[:space:]`、`[:punct:]` | 文字クラスの中の POSIX の文字クラス。一般カテゴリーの L、Nd、L か Nd、Lu、Ll、White_Space、P |
| `\d`、`\D` | 一般カテゴリー Nd とその補集合 |
| `\w`、`\W` | 一般カテゴリー L、M、Nd、Pc とその補集合 |
| `\s`、`\S` | White_Space とその補集合 |
| `\l`、`\u` | 一般カテゴリー Ll、Lu |
| `\p{名前}`、`\P{名前}` | 一般カテゴリー。一字の大分類、二字の分類、大分類の英語の名前（`Letter`、`Mark`、`Number`、`Punctuation`、`Symbol`、`Separator`、`Other`） |
| `*`、`+`、`?`、`{n}`、`{n,}`、`{n,m}` | 欲張りな量指定子 |
| `*?`、`+?`、`??`、`{n,}?`、`{n,m}?` | 怠惰な量指定子 |
| `\|`、`(...)`、`(?:...)` | 選択と群。`(...)` は捕獲しない |
| `^`、`$` | 対象の先頭と末尾 |
| `\b`、`\B` | `\w` による語の境界とその否定 |
| `(?=...)`、`(?!...)` | 先読み |
| `(?<=...)`、`(?<!...)` | 後読み。中身はどの経路でも同じ字数でなければならない |
| `\K` | そこまでの一致を一致の範囲から外す。先読みと後読みの中には書けない |
| `(?i)` | 正規表現の先頭にだけ書ける。大文字と小文字を区別しない |

- 量指定子の前に何もない場合、量指定子が続く場合（`a**`、`a{2}{3}`）は誤りとする。
- 量指定子の形にならない `{`（`a{x}`、`a{,3}`）と、`}` と `]` は文字とする。PCRE と Boost.Regex の扱いに合わせる。
- 繰り返しの回数は 65535 までとする。
- 量指定子は、先読み、後読み、`^`、`$`、`\b`、`\K` にも付けられる。
- `(?i)` は、文字、文字クラスの範囲と文字、POSIX の文字クラス、`\l`、`\u` に効く。文字を `Data.Char` の `toLower` と `toUpper` で写した字のどれかが一致すれば一致とする。否定の文字クラスは、写した後の一致を否定する。`\d`、`\w`、`\s`、`\p{...}` には効かない（PCRE2 の `\p{...}` の扱いに合わせる）。
- 文字の分類は GHC の base の `Data.Char` の `generalCategory` に従う。White_Space は U+0009 から U+000D、U+0020、U+0085、U+00A0、U+1680、U+2000 から U+200A、U+2028、U+2029、U+202F、U+205F、U+3000 の 25 字の表として持つ。

次の構文は誤りとし、黙って別の意味に読まない。

- 後方参照（`\1` から `\9`、`\k`）、名前付きの群（`(?<名前>...)`、`(?P...)`）、アトミックな群（`(?>...)`）、所有的な量指定子（`*+`、`++`、`?+`）、条件（`(?(...)...)`）、コメント（`(?#...)`）。
- 先頭でない `(?i)`、ほかのフラグ（`(?s)`、`(?m)`、`(?x)`、`(?-i)`、`(?i:...)`）。
- 表にない英数字のエスケープ（`\Q`、`\E`、`\X`、`\h`、`\v`、`\R`、`\A`、`\z`、`\Z`、`\G`、`\0` など）と、文字クラスの中の `\b`。
- 文字体系の名前の `\p{...}`（`\p{Han}` など）、表にない名前、`{}` のない `\pL`。
- 長さが一つに決まらない後読み。
- エスケープしない `~`（文字クラスの中を含む）。
- 空の正規表現、閉じていない括弧、対応する `(` のない `)`、閉じていない文字クラス、範囲の両端の逆転、範囲の端の文字クラス、`{n,m}` の `n > m`。
- 量指定子の展開を含めて、照合のプログラムが 10000 命令を超える正規表現。

## 照合の規則

- 対象の先頭から、最左優先（左の位置で、最初に成功した選択肢を採る）で一致を求める。
- 一致の終わりから次の照合を始める。一致が空なら、一致の範囲を返さず、次の照合を一字先から始める。
- `\K` があれば、成功した経路の上で最後に通った `\K` の位置を一致の始まりにする。始まりから終わりまでが空なら返さない。
- `^` と `$` は対象の先頭と末尾だけに一致し、`\n` の前後には一致しない。

## アルゴリズム

構文解析で正規表現を抽象構文木にし、方言の検査をここで行う。
コンパイルで、抽象構文木を命令の配列に写す。
命令は、一字の述語、分岐（欲張りと怠惰で試す順を変える）、移動、表明（`^`、`$`、`\b`、`\B`）、先読みと後読みの部分プログラム、`\K`、成功である。
`{n,m}` は展開し、後読みの部分プログラムには固定の長さを持たせる。

照合は、命令の番号と位置の組（pc, pos）を状態とする深さ優先のバックトラックで行う。
捕獲と後方参照がないので、ある状態から成功に至るかは、そこまでの経路によらない。

- 一度失敗した状態を集合に記録し、再び訪れたら直ちに失敗とする。この記録は開始位置をまたいで使い回す。
- 探している最中の状態を再び訪れた場合（空の繰り返しの輪）は、その枝を失敗とする。この失敗は、探している最中の祖先の状態に依存するので、祖先より上で照合が成功した場合は、その照合で記録した依存のある失敗を記録から消す。照合が失敗した場合は、祖先もすべて失敗しているので、記録はそのまま正しい。
- 先読みと後読みの結果は、（部分プログラム、位置）ごとに記録して使い回す。部分プログラムの照合では、成功に至った状態も記録する。部分プログラムで要るのは成功するかだけで、どこで終わるかは要らないためである。
- 後読みは、今の位置から固定の長さだけ戻った位置で部分プログラムを照合する。どの経路も同じ字数を進むので、成功すればちょうど今の位置で終わる。

失敗と成功の記録により、各状態を展開するのは高々一度であり、一つの照合の手順の数は、命令の数 P、対象の長さ N に対して O(P × N) に収まる。
`(a*)*b` のような正規表現でも、バックトラックの指数的な爆発は起こらない。
テストは、`(a*)*b`、`(a|aa)*c`、`(?=(a+))*b`、`(a+)+$x` を `a` の 10000 字に当てた手順の数が P × 10001 × 4 以下であることを確かめる。
照合の間のメモリは、訪れた状態の数に比例する。

## テスト

`test/Main.hs` は、方言の表の各行の一致する例と一致しない例、最左優先、空の一致、先読みと後読み、`\K`、誤りとその位置、手順の上限を確かめる。
`test/Suites.hs` は、PCRE2 の `testdata/testinput1`（BSD-3-Clause）と Boost.Regex の `test/regress` のテスト（BSL-1.0）から、部分集合の構文だけを含む例を写したものである。
各例に出典のファイルと行を添え、ライセンスの表示をファイルの先頭に置く。
期待する一致の範囲は、Golem の照合の規則（空の一致を返さない）で Perl 5.34 を使って求め、Boost.Regex の例では、その最初の一致がテストのファイルの記録と同じことを確かめた。
