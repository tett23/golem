# ADR 0003: プラグインの診断のコード（G06002 から G06010）

ステータス: 採択

## 文脈

プラグインの診断は、golem-driver の `Golem.Driver.Plugins` の `loadPlugins` と、golem-plugin の `Golem.Plugin.Lock` の `parseLock` が出す。
使っているコードは G06002 から G06010 の九つである。
[golem-plugin ADR 0001](0001-wasm-host-and-abi.md) と [golem-plugin ADR 0002](0002-distribution-and-lock.md) は、どの場合をエラーにするかを定めたが、コードの番号、メッセージ、位置は定めていない。
[docs/diagnostics.md](../../diagnostics.md) では、九つとも「ADR なし」になっている。

この ADR は、九つのコードの条件、重大度、メッセージ、位置を、今の実装に合わせて定める。
あわせて、実装を読んで見つけた次の問題に結論を出す。

**`plugins.lock` の構文の誤りの位置**：`parseLock` は、`plugins.lock` の TOML の誤りを G06002 として返す。
このとき `decodeStrict` に渡す `FileId` は `manifest.toml` のものなので、診断は `plugins.lock` の中のバイト位置を `manifest.toml` の位置として指す。
表示される行と桁は、誤りのある行とは無関係である。
また、「`plugins.lock` にないプラグイン」と「`plugins.lock` が読めない」という、直し方の違う二つの条件が一つのコードに入っている。

**URL の食い違い**：`manifest.toml` のプラグインの `url` が、`plugins.lock` の同じ名前の項目の `url` と違う場合も、G06002 の `plugins.lock にないプラグインです` になる。
直し方（`golem plugin lock`）は同じだが、名前は `plugins.lock` にあるので、書き手はメッセージと `plugins.lock` の中身の食い違いに迷う。

**G06008 の重複と G06007 の誤った案内**：`overrides` に、プラグインが提供せず、上書きもできない名前を書くと、同じ一つの宣言に G06008 が二つ出る。
また、プラグインが上書きできない組み込みのコマンド（`note` など）と同じ名前のコマンドを提供すると、G06007 は「overrides で宣言してください」と案内するが、宣言すると G06008 になる。

**G06009 のメッセージと位置**：コマンドの実行の失敗は、メッセージが理由だけで、どのプラグインのどのコマンドが失敗したかを書かない。
フィルタの実行の失敗は、`manifest.toml` の先頭を指し、どのファイルに適用して失敗したかが位置から分からない。

**G06010 の二つの条件**：フィルタの設定が、宣言されていないプラグインを指す場合と、宣言したプラグインが提供していないフィルタを指す場合が、同じメッセージ `宣言されていないプラグインかフィルタです` になる。

**読み込みの失敗の後の G02022**：プラグインの読み込みが失敗すると、`evaluateProjectWith` はプラグインなしで評価を続ける。
そのプラグインのコマンドを使う箇所は、すべて G02022（`未知のコマンドです`）になり、本当の原因（G06002 から G06008、G06010）が多数の G02022 に埋もれる。

## 実装すること

### 既存の振る舞いの追認

九つのコードは、どれも重大度がエラーであり、プロファイルによって変わらない。
`manifest.toml` にプラグインの宣言もフィルタの設定もなければ、どのコードも出ない。
ビルド、`golem check`、LSP は、どれも `evaluateProjectWith` から `loadPlugins` を呼ぶので、同じ診断を出す。

検査は次の三段で行い、段の中では見つけた誤りをすべて報告し、誤りのある段の後の段は行わない。

1. `plugins.lock` を読む。ファイルがなければ、空の `plugins.lock` として扱う。
2. `manifest.toml` で宣言したプラグインを、名前の順に一つずつ、キャッシュから読み込む（G06002 から G06005）。
3. 読み込んだすべてのプラグインについて、コマンドとフィルタの名前を検査する（G06006 から G06008、G06010）。

G06009 は、検査を通った後の評価の中で出る。

| コード | 条件 | メッセージ | 位置 |
| --- | --- | --- | --- |
| G06002 | 宣言したプラグインの名前が `plugins.lock` にないか、`plugins.lock` の項目の `url` が宣言の `url` と違う。 | `plugins.lock にないプラグインです。golem plugin lock を実行してください: <名前>` | `manifest.toml` の先頭 |
| G06003 | `plugins.lock` の項目のハッシュを名前とする配布物が、キャッシュにない。 | `キャッシュにないプラグインです。golem plugin fetch を実行してください: <名前>` | `manifest.toml` の先頭 |
| G06004 | キャッシュにある配布物の SHA-256 が、`plugins.lock` の項目のハッシュと一致しない。 | `キャッシュの配布物のハッシュが plugins.lock と一致しません: <名前>` | `manifest.toml` の先頭 |
| G06005 | 配布物を wasm のモジュールとして読み込めない。コンパイルの失敗、import の要求、ABI の版の違い、必要な関数の欠け、起動の失敗、`golem_describe` の不正な出力を含む。 | `<名前>: <理由>`。理由は `describePluginError` の文言 | `manifest.toml` の先頭 |
| G06006 | 二つ以上のプラグインが、同じ名前のコマンドを提供する。コマンドの名前ごとに一つ出す。 | 下の「変更」で改める | `manifest.toml` の先頭 |
| G06007 | プラグインが組み込みのコマンドと同じ名前のコマンドを提供し、そのプラグインの `overrides` にその名前がない。 | 下の「変更」で改める | `manifest.toml` の先頭 |
| G06008 | プラグインの `overrides` に、そのプラグインが提供していないコマンドか、上書きできる組み込みのコマンド（golem-eval の `overridableCommands`）でない名前がある。 | 下の「変更」で改める | `manifest.toml` の先頭 |
| G06009 | プラグインのコマンドかフィルタの実行が失敗した。命令数の上限、メモリの上限を含むトラップ、不正な出力を含む。 | 下の「変更」で改める | 下の「変更」で改める |
| G06010 | `[[filters]]` の項目が、宣言されていないプラグインか、プラグインが提供していないフィルタを指す。 | 下の「変更」で改める | `manifest.toml` の先頭 |

`manifest.toml` の先頭は、`mkSpan <manifest.toml の FileId> 0 0` である。
`Manifest` はプラグインの宣言の位置を持たないので、宣言の行は指さない。
メッセージに名前を書くことで、書き手は宣言を見つけられる。

`describePluginError` の文言は次のとおりで、G06005 と G06009 が共有する。

- **CompileFailed**：`プラグインを読み込めません: <詳細>`
- **HasImports**：`プラグインが import を要求しています: <import の一覧>`
- **AbiMismatch**：`プラグインの ABI の版が異なります: <版>`
- **MissingExport**：`プラグインが関数を公開していません: <関数>`
- **OutOfFuel**：`プラグインの実行が命令数の上限を超えました`
- **Trapped**：`プラグインの実行が失敗しました（メモリの上限を超えた場合を含む）: <詳細>`
- **InstantiateFailed**：`プラグインを起動できません: <詳細>`
- **BadOutput**：`プラグインの出力が不正です: <詳細>`

### 変更

**G06011 を新設し、`plugins.lock` の構文の誤りを G06002 から分ける**：`plugins.lock` が TOML として読めないか、項目の形（`url` と `sha256` の文字列）に合わない場合を、G06011 とする。
重大度はエラー、メッセージは今の `decodeStrict` の文言のままとする。
`plugins.lock` を、`manifest.toml` や `style.toml` と同じく診断の表示に使うファイルとして `FileId` を割り当て、`parseLock` にその `FileId` を渡す。
位置は、TOML の誤りの位置（`plugins.lock` の中）を指す。
`plugins.lock` は処理系が書くファイルなので、直し方は「`plugins.lock` を消して `golem plugin lock` を実行する」になり、G06002 とは違う。
プラグインの区分（06）の、最後に使った G06010 の次の番号を当てる。

**G06002 の URL の食い違いのメッセージ**：コードは G06002 のままとし、`url` が違う場合のメッセージを `plugins.lock の URL が manifest.toml と違います。golem plugin lock を実行してください: <名前>` にする。
直し方が同じなので、コードは分けない。

**G06006 のメッセージ**：`複数のプラグインが同じコマンドを提供しています: <コマンド>（<プラグイン>、<プラグイン>）` とし、提供するプラグインを名前の順に並べる。

**G06007 の二つの場合**：組み込みのコマンドが上書きできる（`overridableCommands` にある）場合は、今のメッセージ `組み込みのコマンドと衝突しています（overrides で宣言してください）: <プラグイン>.<コマンド>` のままとする。
上書きできない場合は、`上書きできない組み込みのコマンドと衝突しています: <プラグイン>.<コマンド>` とし、宣言を案内しない。
どちらも「宣言のない衝突」という一つの条件なので、コードは分けない。

**G06008 を宣言ごとに一つにする**：`overrides` の一つの名前について、G06008 を高々一つ出す。
プラグインがその名前のコマンドを提供していなければ `プラグインが提供していないコマンドを overrides に書いています: <プラグイン>.<コマンド>` とし、提供していて上書きできる組み込みのコマンドでなければ `上書きできる組み込みのコマンドではありません: <プラグイン>.<コマンド>` とする。
二つ目の文言は、組み込みでない名前と、上書きできない組み込みのコマンドの両方を説明する。

**G06009 のメッセージと位置**：コマンドの実行の失敗は、メッセージを `<プラグイン>.<コマンド>: <理由>` とし、位置は今のままコマンドを呼んだ箇所とする。
フィルタの実行の失敗は、メッセージを今のまま `<プラグイン>.<フィルタ>: <理由>` とし、位置をフィルタを適用したファイルの先頭（`mkSpan <そのファイルの FileId> 0 0`）に改める。
失敗はそのファイルの内容に依存するので、ファイルを指すほうが書き手の手がかりになる。

**G06010 のメッセージを二つに分ける**：プラグインが宣言されていなければ `宣言されていないプラグインです: <プラグイン>（フィルタ <プラグイン>.<フィルタ>）` とし、宣言したプラグインがそのフィルタを提供していなければ `プラグインが提供していないフィルタです: <プラグイン>.<フィルタ>` とする。
直し方はどちらも `[[filters]]` の項目を直すことなので、コードは分けない。

**読み込みの失敗の後は G02022 を出さない**：`loadPlugins` が誤りを返したときは、評価（S0）で未知のコマンド（G02022）を報告しない。
G02022 になるはずだったコマンドは、今と同じく何も出力しない。
読み込みに失敗したプラグインが提供するはずのコマンドの名前は、読み込めないので分からない。
そのため、未知のコマンドの報告を止めるのは、プラグインの誤りがあるときに限る。
プラグインの宣言がなく、プラグインの誤りもないときの G02022 は変えない。

[docs/diagnostics.md](../../diagnostics.md) の G06002 から G06010 の節を改め、G06011 の節を足し、各節の「ADR」の項にこの ADR を書く。

## 実装しないこと

- `manifest.toml` の中のプラグインの宣言の位置を `Manifest` に持たせ、G06002 から G06008、G06010 の位置を宣言の行にすること。`manifest.toml` の位置の保持は、ほかの G03 のコードにも関わるので、別の ADR で扱う。
- G06005 と G06009 を、`describePluginError` の種類ごとのコードに分けること。理由の文言が種類を示し、直し方（プラグインの作者に報告する）は同じである。
- G06006 と G06007 が同じコマンドについて同時に出る場合（二つのプラグインが、宣言なしに同じ組み込みのコマンドを提供する場合）の整理。どちらも直すべき誤りである。
- プラグインが返す診断（[golem-plugin ADR 0001](0001-wasm-host-and-abi.md) の応答の診断の列）のコード。

## テスト設計

今のテストの状況は次のとおりである（`modules/golem-driver/test/Main.hs` の `pluginTests`）。

- G06002：`plugins.lock` を空にすると G06002 になることを、コードだけで確かめている。
- G06003：キャッシュがないと G06003 になることを、コードだけで確かめている。
- G06008：提供していないコマンドを `overrides` に書くと G06008 になることを、コードだけで確かめている。
- G06009：不正な応答を返すコマンドが G06009 を含むことを確かめている。
- G06004、G06005、G06006、G06007、G06010 にはテストがない。

`pluginTests` に次のテストを足し、コード、メッセージ、位置（`diagSpan` の `FileId`）を確かめる。
二つ以上のプラグインを使うテストのために、`withPluginProject` を、名前と wat のファイルの組の一覧を受け取る形に広げる。
組み込みのコマンドと同じ名前を提供するテスト用のプラグインとして、`modules/golem-plugin/test/plugins/builtin-names.wat`（コマンド `ruby` と `note` を提供する）を足す。
フィルタの実行の失敗を確かめるために、`loop.wat` に倣って、フィルタ `spin` を提供し `golem_invoke` で止まらない `modules/golem-plugin/test/plugins/loop-filter.wat` を足す。

- G06002：`plugins.lock` から項目を消すと `plugins.lock にないプラグインです` になり、`url` を書き換えると `plugins.lock の URL が manifest.toml と違います` になること（変更）。どちらも `manifest.toml` の先頭を指すこと。
- G06003：既存のテストに、メッセージと位置の確認を足す。
- G06004：キャッシュの配布物の 1 バイトを書き換えると G06004 になること。
- G06005：import を要求する `imports.wat` を宣言すると G06005 になり、メッセージが `<名前>: プラグインが import を要求しています` で始まること。
- G06006：`identity.wat` を二つの名前で宣言すると、`broken` について G06006 が一つ出て、メッセージに二つのプラグインの名前が名前の順に並ぶこと（変更）。
- G06007：`builtin-names.wat` を `overrides` なしで宣言すると、`ruby` について宣言を案内する文言の G06007 が、`note` について上書きできないことを示す文言の G06007 が出ること（変更）。
- G06008：`overrides = ["ruby"]` の `identity.wat` で、提供していない旨の G06008 が一つだけ出ること。`overrides = ["xyz"]` でも G06008 が一つだけ出ること（変更）。`builtin-names.wat` に `overrides = ["note"]` を書くと、上書きできない旨の G06008 が出ること（変更）。
- G06009：不正な応答のテストで、メッセージが `identity.broken: ` で始まり、位置がコマンドを呼んだ箇所であること（変更）。命令数の上限を超えるフィルタで、位置がフィルタを適用したファイルの先頭であること（変更）。
- G06010：宣言していないプラグインを指す `[[filters]]` と、`identity.wat` の提供しないフィルタを指す `[[filters]]` で、それぞれの文言の G06010 が出ること（変更）。
- G06011：`plugins.lock` を TOML として不正な内容にすると G06011 になり、位置の `FileId` が `plugins.lock` のものであり、`BuildResult` の `brSources` に `plugins.lock` があること（新設）。
- G02022：`plugins.lock` を空にした状態で、原稿にプラグインのコマンド `[broken: x]` を書くと、診断が G06002 だけであること（変更）。プラグインの宣言のない原稿で未知のコマンドが G02022 になることは、golem-eval の既存のテストが確かめる。

変更の分は、テストを先に足して失敗させてから実装する。
`modules/golem-cli/test/Main.hs` の、ソースのコードがすべて [docs/diagnostics.md](../../diagnostics.md) に載っていることの検査が、G06011 の節の追加を確かめる。

## トレードオフ

G06002 から G06008、G06010 の位置を `manifest.toml` の先頭のままにする。
宣言の行を指すほうが親切だが、そのためには `Manifest` に位置を持たせる必要があり、プラグインの外の変更が大きい。
メッセージにプラグインの名前を書いているので、書き手は宣言を見つけられる。

読み込みの失敗の後に G02022 を止めると、プラグインと関係のない本当の未知のコマンド（綴りの誤りなど）も、プラグインの誤りを直すまで報告されない。
プラグインの誤りを直した後のビルドで報告されるので、失われるのは一回分の報告である。
多数の G02022 で本当の原因が埋もれることのほうが、書き手の手間は大きい。
