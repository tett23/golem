# ADR 0001: wasm のホストと ABI

ステータス: 採択→`golem_dealloc` は [docs/adr/0031](../../adr/0031-adr-code-mismatches.md)

## 文脈

プラグインは wasm のモジュールとして実装し、コマンドとフィルタの二種類がある（specifications.md）。
wasm を選んだ根拠の一つは、決定性と隔離をホストの側で強制できることである。
この根拠は、ホストがプラグインに何を渡し、何を渡さないかの設定によって初めて成り立つ。
この ADR は、wasm のランタイム、ホストの設定、呼び出し規約、出力の検証を定める。

Haskell には成熟した wasm のランタイムがないので、wasmtime の C API を FFI で呼ぶ。
HarfBuzz、FreeType に続く、版を固定する C のライブラリになる。

## 実装すること

### ランタイム

- wasmtime の C API を FFI で使う。版は 49.0.2 に固定し、README の固定しているネイティブライブラリの表に記載する。版を上げるときは ADR を作成する。
- FFI は golem-plugin の中に閉じ込め、ほかのモジュールは golem-plugin の Haskell の API だけを使う。

### 決定性と隔離のための設定

- プラグインに import を一切渡さない。WASI も渡さない。プラグインは時計、乱数、ファイル、ネットワーク、環境変数に触れられない。プラグインのモジュールが import を要求する場合は、読み込みの時点でエラーとする。
- スレッドを無効にする。
- 浮動小数点数の NaN を正規化する（wasmtime の NaN の正規化の設定）。
- 結果が実装によって変わりうる命令（relaxed SIMD）を無効にする。
- 一回の呼び出しで実行できる命令の数に上限（wasmtime の fuel）を設け、メモリの量にも上限を設ける。上限を超えた場合はコンパイルエラーとする。命令の数で数えるので、上限を超えるかどうかも決定的である。
- 呼び出しごとに新しいインスタンスを作り、呼び出しの間で状態を持ち越させない。呼び出しの順序が結果に影響しないので、ファイルを並列に評価できる。

### 呼び出し規約

プラグインのモジュールは次の関数を公開する。

- `golem_abi_version() -> u32`：ABI の版。処理系の版と一致しなければ、読み込みの時点でエラーとする。
- `golem_alloc(len: u32) -> u32` と `golem_dealloc(ptr: u32, len: u32)`：ホストがプラグインのメモリに入力を書くための領域を管理する。
- `golem_describe() -> u64`：プラグインが提供するコマンドとフィルタの名前の一覧を、CBOR で返す。戻り値の上位 32 ビットが位置、下位 32 ビットが長さである。
- `golem_invoke(ptr: u32, len: u32) -> u64`：CBOR の要求を受け取り、CBOR の応答の位置と長さを同じ形で返す。

### 要求と応答

要求と応答の CBOR のスキーマは、意味論 IR の CDDL（[golem-doc ADR 0001](../../golem-doc/adr/0001-semantic-ir-in-cddl.md)）と同じファイルに定義する。

- コマンドの要求：コマンドの名前、評価済みの引数、散文スロット（意味論 IR のインラインの列）、呼び出しの位置。
- フィルタの要求：フィルタの名前、ファイル一つ分の意味論 IR。
- 応答：出力の断片（コマンドならインラインの列、フィルタならファイル一つ分の文書）と、診断の列。

### 出力の検証

応答を受け取るたびに、次を検査する。

- CDDL のスキーマと、[golem-doc ADR 0001](../../golem-doc/adr/0001-semantic-ir-in-cddl.md) の意味論上の不変条件。
- 出力の `DeferredExpr` は、要求に含まれていたものと同一でなければならない。プラグインが新しく作ることはできない。
- 出力のノードのソース位置は、呼び出しの位置か、要求に含まれていたノードの位置でなければならない。プラグインが作ったノードには、呼び出しの位置を付ける。
- 違反はコンパイルエラーとし、黙って修正したり該当の部分を捨てたりはしない。

### 名前の衝突

`golem_describe` で得たコマンドの名前が別のプラグインのコマンドと衝突した場合は、プロジェクトの読み込みの時点でエラーとする。
組み込みのコマンドとの衝突は、マニフェストで上書きを宣言した場合に限って許し、上書きできるコマンドの範囲は [golem-eval ADR 0002](../../golem-eval/adr/0002-file-evaluation.md) に従う。
宣言のない衝突はエラーとする。

## 実装しないこと

- プラグインの取得とロックファイル。[ADR 0002](0002-distribution-and-lock.md) で扱う。
- プラグインがチャネルの中身や S1、S2 の値を読む機能。
- プラグインを書くための SDK。最初の SDK（Rust）は別のリポジトリで扱う。
- Component Model と WIT による ABI。

## テスト設計

- import を要求するモジュール、ABI の版が異なるモジュールが、読み込みの時点でエラーになることを確かめる。
- 無限ループするプラグインが命令数の上限でエラーになり、同じ入力で毎回同じ位置で止まることを確かめる。
- 大量のメモリを確保するプラグインが、メモリの上限でエラーになることを確かめる。
- NaN を作って返すプラグインの出力が、実行のたびに同じバイト列になることを確かめる。
- 不正な CBOR、スキーマに合わない出力、ルビを入れ子にした出力、新しい `DeferredExpr` を含む出力、範囲外のソース位置を含む出力が、それぞれエラーになることを確かめる。
- 同じプラグインを並列に呼んだ結果が、逐次に呼んだ結果と一致することを確かめる。
- テスト用のプラグインは、wat（wasm のテキスト形式）で書いてリポジトリに置く。

## トレードオフ

WASI を渡さないので、プラグインは標準の入出力やファイルを使うライブラリをそのままでは使えない。
総ルビの辞書のような資産は、wasm のモジュールに埋め込む必要がある。
その代わり、プラグインが入力の外から値を持ち込む経路は存在しなくなる。

呼び出しごとにインスタンスを作ると、辞書の初期化のような重い処理を毎回繰り返すことになる。
状態を持ち越させると呼び出しの順序が結果に影響しうるので、速度より決定性を優先する。
遅さが問題になった場合は、初期化済みのメモリの複製（スナップショット）を ADR で検討する。
