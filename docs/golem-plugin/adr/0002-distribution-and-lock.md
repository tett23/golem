# ADR 0002: プラグインの取得とロックファイル

ステータス: 採択

## 文脈

v1 では、プラグインの配布機構（レジストリや版の解決）を持たず、マニフェストに配布物の URL を直接書く（specifications.md）。
使うプラグインは人がマニフェストに宣言し、配布物のハッシュは処理系が `plugins.lock` に書き出す。
同じ入力から同じ出力を得るには、プラグインのバイト列まで入力の一部として固定する必要がある。

## 実装すること

### マニフェストでの宣言

```toml
[plugins.furigana]
url = "https://github.com/example/golem-furigana/releases/download/v1.0.0/furigana.wasm"

[[filters]]
plugin = "furigana"
filter = "total-ruby"
files = ["chapters/01.gm", "chapters/02.gm"]
```

- `[plugins.<名前>]` の `url` は HTTPS に限る。
- プラグインが組み込みのコマンドを上書きする場合は、`overrides = ["ruby"]` のように上書きするコマンドの名前を列挙する。列挙した名前をプラグインが提供していない場合はエラーとする。
- フィルタの適用は `[[filters]]` で宣言し、宣言の順に適用する。

### ロックファイル

```toml
[plugins.furigana]
url = "https://github.com/example/golem-furigana/releases/download/v1.0.0/furigana.wasm"
sha256 = "..."
```

- `plugins.lock` は TOML とし、プラグインの名前の順に並べる。
- 処理系だけが書き、手で編集しない。リポジトリにコミットする。

### キャッシュ

- 取得した配布物は、SHA-256 のハッシュを名前にして、ユーザーのキャッシュのディレクトリ（XDG の規則に従う）に置く。
- ビルドはキャッシュからだけ読み、ネットワークに接続しない。キャッシュにない場合は、`golem plugin fetch` を求めるエラーとする。

### コマンド

- `golem plugin fetch`：`plugins.lock` のとおりに配布物を取得し、ハッシュを検証してキャッシュに置く。ハッシュが一致しなければエラーとし、キャッシュに置かない。
- `golem plugin lock`：マニフェストの宣言に従って配布物を取得し、ハッシュを `plugins.lock` に書く。マニフェストから消えたプラグインは `plugins.lock` からも消す。
- `plugins.lock` にないプラグインがマニフェストにある場合、ビルドは `golem plugin lock` を求めるエラーとする。
- 同じ URL の中身がロックファイルのハッシュと異なっていた場合は、`fetch` もビルドもエラーとする。

### 通信

- HTTPS のリダイレクトには従う（GitHub のリリースは別のホストにリダイレクトする）。HTTPS から HTTP へのリダイレクトはエラーとする。
- 取得したバイト列は、ハッシュを検証するまでプラグインとして扱わない。

## 実装しないこと

- 版の範囲の宣言と解決、レジストリ。配布機構を作る段階で扱う。
- 配布されたバイナリがどのソースから作られたかの検証。
- キャッシュの削除と整理のコマンド。

## テスト設計

- ローカルの HTTPS のテスト用サーバーから取得し、`plugins.lock` が期待した内容になることを golden テストで固定する。
- サーバーの配布物を差し替えた後に `fetch` とビルドがエラーになることを確かめる。
- キャッシュがあればネットワークなしでビルドできること、キャッシュがなければエラーになることを確かめる。
- HTTP の URL と、HTTP へのリダイレクトがエラーになることを確かめる。
- マニフェストからプラグインを消して `lock` を実行すると、`plugins.lock` からも消えることを確かめる。

## トレードオフ

URL を直接書く方式では、プラグインの新しい版に移るときに、利用者が URL を書き換えて `golem plugin lock` を実行する必要がある。
版の解決の仕組みがない分の手間であり、配布機構を作るまでは受け入れる。

v1 は配布元を信用することになるが、ハッシュの固定によって、一度確認した配布物が黙って差し替えられることはない。
