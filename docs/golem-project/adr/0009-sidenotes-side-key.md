# ADR 0009: `[sidenotes]` の `side` は `"outside"` だけを受け付けるキーとして残す

ステータス: 採択（未実装）

## 文脈

`style.toml` の `[sidenotes]` の `side` について、文書と実装が食い違っている。

- [ADR 0002](0002-style-toml.md) は、読む節の一覧に「`[sidenotes]`：傍注欄の側（`side`）、幅、版面との間隔、フォント、文字の大きさ、本文側の印」と書く。`side` の値は定めていない。
- [golem-driver ADR 0011](../../golem-driver/adr/0011-sidenote-font.md) は、`[sidenotes]` の `font` と `size` を廃止し、「`[sidenotes]` には傍注欄の幾何（`width`、`gap`）と印（`marker`）だけを残す」とした。`side` には触れていない。
- 仕様書の `style.toml` の例（752 行）は `side = "outside"` を持つ。一方、傍注の節（2377 行）は「`[sidenotes]` には、ほかに本文側の印（`marker`）だけを書く」と書き、`side` を挙げない。
- 使い手のマニュアル（`manual/appendices/c-style.gm` の `[sidenotes]` の表）は、`side` を傍注欄を置く側とし、今は `"outside"`（小口の側）だけを書けると説明している。
- `Golem.Project.Style` の `SidenoteStyle` の読み込み（1413 行）は、`enumKey "side" ["outside"]` で `side` を読み、値を捨てる。`"outside"` のほかの値は G0306（`side に使えない値です: <値>（outside のどれか）`）とする。`SidenoteStyle` は `side` の欄を持たない。

傍注欄は、[golem-layout-spec ADR 0001](../../golem-layout-spec/adr/0001-page-geometry.md) のとおり、いつも版面の外の小口の側に置かれる。
奇数ページと偶数ページで、傍注欄の左右は小口の側に合わせて入れ替わる。
つまり、受け付ける唯一の値 `"outside"` は、実際の置き方と一致している。

レビュー（`.claude/reviews/2026-10-20-adr-spec-review.md` の A-14）が、この食い違いを挙げた。
残すなら仕様書に書き、なくすなら ADR が要る。

### 「黙って変えない」との関係

Golem は、書き手の指定を黙って読み捨てて出力を変えることをしない。
今の `side` の扱いは、受け付ける値が実際の置き方と一致する一つだけなので、読み捨てても書き手の意図と出力は食い違わない。
意図と違う値（たとえば `"inside"`）は G0306 になる。
したがって、今の実装は「黙って変える」にあたらない。
問題は、文書のあいだで `side` があるかないかが食い違っていることだけである。

## 実装すること

### 規則

`[sidenotes]` の `side` を、省略できるキーとして残す。

- 値は `"outside"`（小口の側）だけを受け付け、既定も `"outside"` とする。
- `side` を書いても書かなくても、傍注欄の位置は同じである。
- `"outside"` のほかの値と、文字列でない値は G0306 とする（今のとおり）。

`side` をキーとして残すのは、小口の側のほかの置き方を後から足せるようにするためである。
メンテナーは、ページの天の余白に注を置く縦組みの本（頭注）を、ありうる組み方として示した。
縦組みの本で、注を版面の上の余白に置く形は、今の傍注欄（横組みの版面の小口の側）とは位置も向きも違うが、本文の脇の余白に注を置くという点では同じ種類の指定である。
こうした置き方を足すときは、`side` に値（たとえば頭注にあたる値）を足し、値ごとの置き方、縦組みの版面での傍注欄の禁止（G0701）との関係、柱やノンブルとの重なりの検査を別の ADR で決める。
今受け付ける値は `"outside"` だけである。

### コード

`Golem.Project.Style` は、すでにこの規則で動いているので変えない。

### 文書

- 仕様書の傍注の節（2377 行）の「`[sidenotes]` には、ほかに本文側の印（`marker`）だけを書く」を、「ほかに、本文側の印（`marker`）と、傍注欄を置く側（`side`）を書く。`side` は `"outside"`（小口の側）だけを書け、既定も `"outside"` である」と改め、この ADR へリンクする。
- 仕様書の `style.toml` の例（752 行）は `side = "outside"` のまま残す。
- 使い手のマニュアル（`manual/appendices/c-style.gm` の `[sidenotes]` の表）はすでにこの規則のとおりなので変えない。

### ステータスの行

- [golem-driver ADR 0011](../../golem-driver/adr/0011-sidenote-font.md)：「採択→（`[sidenotes]` に残すキーへの `side` の追加）は [golem-project ADR 0009](0009-sidenotes-side-key.md)」とする。
- [ADR 0002](0002-style-toml.md)：今のステータスの行に、「`[sidenotes]` の `side` の値は ADR 0009」を足す。

## 実装しないこと

- `SidenoteStyle` に `side` の欄を加えること。値が一つしかないうちは、欄を持っても使う箇所がない。二つめの値を足す ADR で加える。
- `"outside"` のほかの値（ノドの側、左右の固定、頭注など）。どれも、値ごとの置き方を決める ADR を待つ。
- `side` を廃止すること（「トレードオフ」）。
- G0306 を原因ごとに分けること。G0306 は、TOML として読めないこと、未知のキー、列挙の外の値、範囲の外の値をまとめて報告しており、違う原因に一つのコードを使わないという diagnostic の原則に照らすと分ける余地がある。`side` の値の誤りは、ほかの列挙のキーの値の誤りと同じ原因なので、分けるときもそれらと同じコードにする。分けること自体は、G0306 のすべての原因に関わるので別の ADR で扱う。

## テスト設計

実装はすでにこの規則で動いているので、テストを先に書いて、今の実装で通ることを確かめる。
決定を記録する ADR なので、テストが失敗する段階はない。

既存のテスト（golem-project の `test/Main.hs` 1018 行の付近）は、`side = "outside"` を書いた `style.toml` が読めることだけを確かめている。
同じファイルに次を加える。

- `[sidenotes]` に `side = "outside"` を書いた `style.toml` と、書かない `style.toml` が、同じ `SidenoteStyle` になる。
- `side = "inside"` は G0306 で、メッセージが `side に使えない値です: inside（outside のどれか）` である。
- `side = 1`（文字列でない値）は G0306 である。

## トレードオフ

- 効果のないキーを残すと、書き手は書く意味のない行を書くことになる。一方、廃止すると、今 `side = "outside"` を書いている `style.toml`（仕様書の例と、それを写したプロジェクト）が G0306 で読めなくなり、書き換えが要る。値が実際の置き方と一致していて、書き手の意図と出力が食い違わないので、残すほうを採る。
- 残すと、将来ノドの側の傍注欄や縦組みの頭注を足すときに、新しいキーを設けずに値を足すだけで済む。広い型と狭い実装の組で、型の側を先に決めておく扱いである。
