# ADR 0001: マニフェストの読み込みと import のグラフ

ステータス: 採択→読み込みの失敗の型は [ADR 0006](0006-project-diagnostic-codes.md)

## 文脈

一冊の本は、`manifest.toml` と、そこから到達するソースファイルから成る。
内容の合成（どの章をどの順で並べるか）はマニフェストに書き、ソースファイルは `@import` で変数の定義だけを取り込む。
golem-project は、マニフェストを読み、ビルドに使うファイルの集合とその依存関係を決めるモジュールである。

ここで決まるファイルの集合と順序は、決定性の入力の定義そのものである。
同じファイルを別の書き方で参照したときに別物と扱うと、循環の検出漏れや二重評価が起きる。

`style.toml` の読み込みは、レイアウト IR と合わせて別の ADR で扱う。

## 実装すること

### マニフェストのスキーマ

`manifest.toml` の次の節を読む。

- `[metadata]`：書名、読み、著者、言語、日付、版、発行者、本の識別子 `id`（必須）。
- 章の配列：ファイルのパス、またはファイルとマスターページの組（`{ file = "...", master = "body" }`）。入れ子の配列で章をファイルに分けられる。
- `[targets.*]`：生成する出力ターゲットと、ターゲットごとの識別子（ISBN）。
- プラグインの宣言：配布物の URL と、適用するフィルタの指定。
- 書誌データ（CSL-JSON）のファイル。

未知のキーはエラーとする。
TOML の日付は時刻とタイムゾーンを含まない日付として読む。

### ファイルの同一性

- パスは、プロジェクトルートからの正規化パスに直す。`.` と `..` を解決し、シンボリックリンクを実体に解決する。
- プロジェクトルートの外を指すパス、絶対パス、URL はエラーとする。
- 大文字と小文字だけが異なるパスで同じファイルを参照した場合はエラーとする。大文字と小文字を区別しないファイルシステムでも、区別するファイルシステムでも、同じ結果にするためである。
- 正規化したパスに、[ADR golem-syntax 0001](../../golem-syntax/adr/0001-source-spans-and-diagnostics.md) の `FileId` を割り当てる。

### import のグラフ

- 各ソースファイルの `@import` を集め、ファイルを頂点、import を辺とするグラフを作る。
- 評価の前に循環を検出する。循環があればコンパイルエラーとし、循環の全経路と各 `@import` の位置を診断の関連位置に載せる。自分自身の import は長さ 1 の循環とする。
- 評価の順序は、このグラフのトポロジカル順序とする。同順位のファイルは、マニフェストの章の順と、ファイルを初めて参照した順で並べる。
- 複数のファイルが同じファイルを import した場合、そのファイルは一度だけ評価し、結果を共有する。

### インターフェース

```haskell
data Project = Project
  { projectRoot     :: !FilePath
  , projectFiles    :: !FileTable
  , projectChapters :: ![ChapterEntry]   -- マニフェストの順
  , projectImports  :: !ImportGraph
  , projectManifest :: !Manifest
  }

loadProject :: FilePath -> IO (Either [Diagnostic] Project)
```

ファイルの読み込みは、マニフェストと `@import` から到達するファイルだけに限り、ディレクトリの内容を列挙しない。

## 実装しないこと

- `style.toml` の読み込み。
- プラグインの取得とロックファイルの更新。golem-plugin の ADR で扱う。
- 変数の評価そのもの。golem-eval が行う。
- ファイルの変更の監視とインクリメンタルな再読み込み。LSP の ADR で扱う。

## テスト設計

- 正規化：`./a.gm`、`x/../a.gm`、シンボリックリンク経由のパスが同じ `FileId` になることを確かめる。
- 大文字と小文字だけが異なる参照がエラーになることを確かめる。
- ルートの外、絶対パス、URL の参照がエラーになることを確かめる。
- 循環：長さ 1、2、3 の循環と、循環を含まないひし形の依存を用意し、循環だけが検出され、診断に全経路が載ることを確かめる。
- ひし形の依存で、共通のファイルが一度だけ評価されることを、評価の回数を数えて確かめる。
- マニフェストの未知のキー、`id` の欠落がエラーになることを確かめる。
- 同じプロジェクトを何度読んでも、`FileId` の割り当てとファイルの順序が同じになることを確かめる。

## トレードオフ

大文字と小文字だけが異なる参照をエラーにすると、大文字と小文字を区別するファイルシステムで、本当に別のファイルとして二つを置くことはできなくなる。
環境によって結果が変わるより、どの環境でも同じエラーになるほうを選ぶ。

シンボリックリンクを実体に解決するため、リンクの先がプロジェクトルートの外にある場合もエラーになる。
外部のファイルをリンクで持ち込む使い方はできなくなるが、入力の範囲をプロジェクトの中に閉じる決定性の規則を優先する。
