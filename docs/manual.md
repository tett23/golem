# はじめに

本を一冊作るには、原稿を書くだけでは足りません。
判型と版面を決め、書体を選び、ルビや注を入れ、校正のたびに組み直します。
組版のソフトウェアでこの作業をすると、同じ原稿から同じ紙面が出てくるかどうかは、操作した人の手元の状態に左右されます。

Golem は、この作業をテキストとコマンドで行う組版システムです。
原稿は `.gm` のファイルに、本の構成は `manifest.toml` に、紙面の体裁は `style.toml` に書きます。
`golem build` を実行すると、同じ版の Golem は、同じ入力から、いつでも、どの機械でも、中身が一バイトも違わない同じ PDF を作ります。

## Golem でできること

Golem は、一つの原稿から次の四つの形式を作ります。

- 印刷所への入稿を想定した PDF（PDF/X-4）
- 電子書籍の EPUB
- Web で読む HTML
- ブログなどに転載するプレーンテキスト

PDF は、日本語の組版の規則（禁則、ルビ、圏点、約物の空き）に従って組みます。
縦組みと横組みの両方を扱い、欧文の行分割とハイフネーションも行います。

原稿も設定もテキストなので、Git で版を管理できます。
変更の差分はそのまま紙面の差分になり、誰がいつ何を直したかが履歴に残ります。
同じ入力から常に同じ出力が得られるので、原稿を変えるたびに自動で組み直す仕組み（CI）を用意して、前の版と比べて崩れたページだけを見つけることもできます。

## このマニュアルについて

このマニュアルは、Golem 自身で組んでいます。
リリースに付いている PDF と HTML は、リポジトリの `manual/` にある原稿を `golem build` で組んだものです。
手元の PDF の紙面が、そのまま Golem の組版の見本になります。

各節では、その節で説明する機能を、その節の中で実際に使っています。
振り仮名の節には振り仮名が、注の節には注が、表の節には表が組まれています。
同じ内容を Markdown で書いたものが、リポジトリの `docs/manual.md` にあります。

はじめて使う場合は、次の「インストールと最初の一冊」で一冊組んでみてください。
そのあとは、やりたいことに合わせて、必要な章を引いてください。

# インストールと最初の一冊

## 配布物を取得する

Golem の実行ファイルは、[GitHub Releases](https://github.com/tett23/golem/releases) で配布しています。
使う機械に合うアーカイブを選んでください。

| プラットフォーム | 対象 |
|---|---|
| `x86_64-linux` | Linux（x86-64） |
| `aarch64-linux` | Linux（aarch64） |
| `aarch64-macos` | macOS 14 以降（Apple Silicon） |

アーカイブの名前は、版のタグとプラットフォームを並べた `golem-v0.1.0-x86_64-linux.tar.gz` のような形です。

Windows では、WSL2 の上で Linux のアーカイブを使います。

アーカイブと `SHA256SUMS` を取得し、ファイルが壊れていないかを確かめてから展開します。
`SHA256SUMS` には、各ファイルの中身から計算した値（ハッシュ）が書いてあり、手元で計算した値と合えば、ファイルは正しく取得できています。
次の例は、x86-64 の Linux で版 `v0.1.0` を入れる場合です。

```sh
TAG=v0.1.0
URL=https://github.com/tett23/golem/releases/download/$TAG
DIR=golem-$TAG-x86_64-linux
curl -LO "$URL/$DIR.tar.gz"
curl -LO "$URL/SHA256SUMS"
sha256sum --ignore-missing -c SHA256SUMS
tar -xzf "$DIR.tar.gz"
install -m 755 "$DIR/golem" ~/.local/bin/
golem --version
```

macOS では、`sha256sum` の代わりに `shasum -a 256 --ignore-missing -c SHA256SUMS` を使います。
ブラウザで取得したアーカイブから取り出した `golem` は、初回の起動を macOS に止められます。
その場合は、`xattr -d com.apple.quarantine golem` を実行してから起動してください。

`golem --version` が版を表示すれば、インストールは終わりです。

## プロジェクトを作る

本を一冊作るには、まずプロジェクトを作ります。
プロジェクトは、一冊の本の原稿と設定をまとめたディレクトリです。

```sh
golem new mybook
```

このコマンドは `mybook` というディレクトリを作り、次のファイルを置きます。

- `manifest.toml`：本の構成（章の順、書名、出力の設定）。第 4 章で説明します。
- `style.toml`：紙面の体裁（判型、版面、書体）。第 5 章で説明します。
- `chapters/01.gm`：最初の章の原稿
- `fonts/`：本文の書体（Noto Serif JP）と、そのライセンスの文書
- `.gitignore`：組んだ結果を置く `build/` を Git の管理から外す設定

書体は、配布元から版を固定して取得し、ファイルが壊れていないかを確かめてから置きます。
このためネットワークに接続します。
接続できない環境では `golem new --no-fonts mybook` とし、表示されたファイルを手で `fonts/` に置いてください。

作られるのは、A6 判の縦組みの本です。
英語の本を作るときは、`--language en` を付けます。

```sh
golem new --language en mybook
```

こちらは、ペーパーバックの判型の横組みで、欧文の書体（Source Serif 4）を使う本になります。

## 組んで確かめる

プロジェクトのディレクトリに移って、`golem build` を実行します。

```sh
cd mybook
golem build
```

組んだ結果は `build/` に入ります。

- `build/pdf/`：PDF
- `build/html/`：HTML（`index.xhtml` から読み始めます）
- `build/epub/book.epub`：EPUB
- `build/text/`：プレーンテキスト

`golem build` は、何も指定しなければ四つの形式をすべて作ります。
一つの形式だけを作るときは、`golem build --target pdf` のように `--target` で選びます。
`--target` は何度でも書けます。

PDF を開くと、「第一章　はじめに」という見出しと「本文。」という一行が、縦組みで組まれています。
これが `chapters/01.gm` の中身です。

![golem new で作ったプロジェクトをそのまま組んだ PDF の最初のページ](../manual/images/new-project.png)

## 原稿を書き足す

`chapters/01.gm` をテキストエディタで開き、本文を書き足します。

```
# はじめに

吾輩は猫である。
名前はまだ無い。

どこで生れたかとんと見当がつかぬ。
```

空行で区切ったまとまりが一つの段落になります。
段落の中の改行は、組んだ結果には現れません。
一文ごとに改行して書いておくと、Git の差分が文の単位になり、校正の跡を追いやすくなります。

章を増やすときは、`chapters/02.gm` のようにファイルを作り、`manifest.toml` の `chapters` に加えます。

```toml
chapters = ["chapters/01.gm", "chapters/02.gm"]
```

並べた順に章が続きます。
もう一度 `golem build` を実行すれば、二つの章を含む本ができます。

# 原稿の記法

原稿は、拡張子が `.gm` のテキストのファイルに書きます。
文字コードは UTF-8 で保存します。
UTF-8 は、いまのテキストエディタの多くが標準で使う文字コードです。
改行の文字は、Windows の CRLF ではなく LF にします。

Golem の記法は二つの層に分かれます。
行頭の記号（`#`、`-`、`@` など）は、見出しやリストのような、行のまとまり（ブロック）を表します。
行頭の `@` で始まる行は、ブロックコマンドと呼ぶ指定の行です。
角括弧（`[ ... ]`）は、ルビや注のように段落の中に置く要素を表します。
Markdown を書いたことがあれば、ブロックの書き方はほぼ同じです。
段落の中の装飾は、Markdown の `**` や `_` の代わりに、すべて角括弧で書きます。

この章では、記法を使い方の順に説明します。
書き方を一つずつ引くには、巻末の付録A「記法のリファレンス」を使ってください。

## 段落と改行

空行で区切った行のまとまりが、一つの段落になります。

```
吾輩は猫である。
名前はまだ無い。

どこで生れたかとんと見当がつかぬ。
```

一つめの段落の二行は、「吾輩は猫である。名前はまだ無い。」と一続きに組まれます。
段落の中の改行は文字を生まず、前後は空白なしでつながります。

欧文では、この規則に注意が要ります。
単語の間で改行すると、二つの単語が空白なしにつながってしまいます。
欧文の語句は改行で分けず、一行に書いてください。
`golem lint` は、改行の前後がどちらも欧文の文字である箇所を誤りとして報告します。

行分けをそのまま残したい詩や歌詞には、後で説明する段落スタイル `verse` を使います。

段落を分けずに、その位置で行だけを改めたいときは、行の末尾に `\` を書きます（強制改行）。
住所や署名、手紙の結びのような段落に使います。

```
〒100-0001\
東京都千代田区千代田1-1\
山田太郎様
```

この三行は、一つの段落の中の三つの行として組まれます。
強制改行の後の行は同じ段落の続きなので、段落の一行目の字下げは掛かりません。

`\` は行の最後の文字にしてください。
`\` の後に空白があると、強制改行になりません。
`\` の次の行には、同じ段落の続きを書きます。
段落の最後の行や、見出し、表のセル、角括弧の中では、行末の `\` は誤りとして報告されます。
本文の `\` を行末に置くときは、`\\` と書きます。

和文の原稿には、一行を一つの段落として書く書き方もあります。
`manifest.toml` の `[source]` に `paragraph-separator = "line"` と書くと、改行ひとつで段落を区切る書き方になります（「プロジェクトの設定」の章の「原稿の読み方」）。

## 見出し

行頭の `#` の数が、見出しの階層を表します。
使える階層は三つです。

```
# 章の見出し
## 節の見出し
### 項の見出し
```

番号は自動で振られます。
「第 1 章」とするか「1.」とするかは、`style.toml` で決めます（「スタイルの設定」の章の「見出しの体裁」）。
原稿の見出しには、番号を書かないでください。

見出しの直前の行にブロックコマンドを書くと、見出しの扱いを変えられます。

```
@nonumber
@notoc
# まえがき
```

- `@nonumber`：番号を振りません。番号も数えません。
- `@notoc`：目次に載せません。
- `@toc-title 短い題`：目次に載せる題を、見出しより短くします。
- `@number 5`：この見出しの番号を 5 にします。後の見出しは 6 から数えます。

このマニュアルの「目次」と巻末の「参考文献」「索引」は、`@nonumber` で番号を外しています。

## 箇条書きと番号付きリスト

行頭の `-` と空白で、箇条書きの項目を書きます。
入れ子にするときは、空白二つで字下げします。

```
- 印刷用の PDF
- 画面で読むもの
  - EPUB
  - HTML
```

組むと、次のようになります。

- 印刷用の PDF
- 画面で読むもの
  - EPUB
  - HTML

番号付きのリストは、行頭を `+` にします。

```
+ 原稿を書く
+ golem build で組む
+ PDF を確かめる
```

組むと、次のようになります。

1. 原稿を書く
2. golem build で組む
3. PDF を確かめる

番号は 1 から自動で振られます。
項目を入れ替えても、番号を書き直す必要はありません。
途中の番号から始めるときは、項目の直前の行に `@number 4` のように書きます。

## 定義リスト

用語と説明の組は、定義リストで書きます。
行頭の `=` と空白で用語を書き、次の行から空白二つで字下げして説明を書きます。

```
= 版面
  ページの中で本文を組む領域。
= ノンブル
  ページ番号。
```

組むと、用語の行の次に、字下げした説明の行が続きます。

- **版面**：ページの中で本文を組む領域。
- **ノンブル**：ページ番号。

`=` の行を続けて書くと、それらの用語が一つの説明を共有します。
`=:` の行は、直前の用語のまま、二つめの説明を始めます。

## 強調と圏点

段落の中の装飾は、角括弧の中に名前とコロンを書き、その後に対象の文字を書きます。

```
[strong: 強調する語]
[kenten: 圏点を打つ語]
```

- `[strong: ...]`：意味の上での強調です。このマニュアルでは**太いゴシック体**で表しています。
- `[bold: ...]`：太字にします。
- `[italic: ...]`：斜体にします。
- `[kenten: ...]`：文字の上（縦組みでは右）に圏点を打ちます。

PDF と HTML の版では、この位置の段落で、二つの語にそれぞれ圏点と色を付けて見せています。

強調をどの書体で表すかは、`style.toml` の文字スタイルで決めます（「スタイルの設定」の章の「段落スタイルと文字スタイル」）。
原稿には「強調する」ことだけを書き、「ゴシック体にする」とは書かないのが基本です。
後で体裁を変えたくなったときに、原稿に手を入れずに済みます。

文字に色を付けるときは、`style.toml` で名前を付けた色（スウォッチ）を指定します。

```
[color accent: 色を付ける語]
```

自分で定義した文字スタイルは、`[style 名前: ...]` で使います。
このマニュアルでは、コマンドやファイルの名前を、文字スタイル `code` で色を付けて組んでいます。

縦組みの本では、`[tcy: !?]` のように書くと、短い文字列を横に並べて一字分の幅に組みます（縦中横）。

## 振り仮名（ルビ）

振り仮名は `[ruby: 親文字|読み]` で付けます。

```
[ruby: 五月雨|さみだれ]
[ruby: 東/京|とう/きょう]
[ruby: 振/り/仮/名|ふ//が/な]
```

- 一つめのように `/` を使わないと、親文字の全体に読みを付けるグループルビになります。熟字訓に使います。
- 二つめのように `/` で区切ると、区切りごとに読みを付けるモノルビになります。親文字と読みの区切りの数は同じにします。親文字を区切らずに読みだけを `/` で区切っても、エラーになります。
- 三つめのように読みの区切りを空にすると、その文字には読みを付けません。送り仮名を含む語に使います。

組むと、五月雨（さみだれ）、東京（とうきょう）、振り仮名（ふりがな）のようになります。
この節の見出しの「振り仮名」にも、三つめの書き方で読みを付けています。

読みが親文字より長いときは、前後の仮名に読みを少しかけて、親文字の字間が空きすぎないようにします。
かけ方は `style.toml` で変えられます（「スタイルの設定」の章の「行分割と和文組版」）。

## 数と式

本文に計算の結果を埋め込むときは、`[= 式]` と書きます。

```
@set price = 1800

税込みで[= price * 110 / 100]円です。
```

`@set` で変数を定義し、`[= ...]` の中で使います。
`@set` は行頭に書くブロックコマンドで、前後を空行で区切ります。
上の例は「税込みで 1980 円です。」と組まれます。
PDF と HTML の版では、この文の金額も、原稿では式で書いています。

式には、四則演算（`+`、`-`、`*`、`/`）、べき乗（`**`）、剰余（`%`）と、次の関数を使えます。

- `round(x, 桁数)`：四捨五入します。`round(2.675, 2)` は 2.68 です。
- `fixed(x, 桁数)`：小数点以下の桁をそろえた文字列にします。`fixed(1.5, 2)` は 1.50 です。価格の表示に使います。
- `floor`、`ceil`、`abs`、`min`、`max`、`sqrt`、`len`、`div`（整数の割り算）

小数の計算は、どの機械で組んでも同じ結果になるように決めています。

マニフェストに書いた本の情報は、`meta` で参照できます。
奥付のように、書名や発行日を本文に並べるページで使います。

```
[= meta.title]
[= meta.date]
```

使える名前は `title`、`date`、`id`、`language` と、マニフェストに書いた場合の `edition`、`publisher`、`title_reading` です。
`[= doc.chapters.count]` は、本の章の数になります。
このマニュアルの書名は「Golem マニュアル」、発行日は 2026-10-13 で、9 の章からなります。

数を書くときは、`[number-text 10]` という書き方もあります。
横組みでは「10」と組み、縦組みでは「十」や「一〇」のような漢数字か、縦中横の「10」で組みます。
縦組みでどの表記にするかは、`[number-text 10 style=kanji]` のように個別に選ぶか、`style.toml` の `[numbers]` で決めます。

## 空きを入れる

二つの文字のあいだに決まった幅の空きを入れるときは、`[aki 量]` と書きます。

```
第一章[aki 全角]吾輩は猫である
3[aki 四分]kg
```

組むと、第一章　吾輩は猫である、3 kg のようになります。
量は、`ベタ`、`全角`、`二分`、`三分`、`四分`、`五分`、`六分`、`八分`、`二分四分` のような名前か、全角を 1 とする `0.2zw` のような小数か、`25%` のような百分率か、`1mm` のような寸法で書きます。
名前と小数と百分率は、その位置の文字の大きさを全角とします。

`[aki]` の前後では行を分けません。
数と単位のあいだや、姓と名のあいだのように、行を分けたくない位置に使います。
行を分けてよい空きは、全角の空白で書きます。
`[aki]` を置いた位置には、「字間の空き」で決める空きを足しません。

HTML と EPUB では同じ幅の余白になります。
プレーンテキストでは、全角の何倍かの整数の部分だけ全角の空白を出し、全角に満たない空きと寸法で書いた空きは出しません。

## 変数をファイルで共有する

定価や版のように、いくつもの章で使う値は、一つのファイルにまとめて取り込めます。

```
@set price = 1800
@set edition = "第2版"
```

このファイルを `common/values.gm` とすると、章の原稿からは次のように使います。

```
@import common/values.gm as values

本書は[= values.edition]です。
```

`@import` で取り込めるのは、`@set` で定義した変数だけです。
取り込んだ変数は、`as` で付けた名前を前に付けて参照します。
取り込むファイルは、章として `manifest.toml` に並べる必要はありません。
このマニュアルも、版面の字数と行数を `common/values.gm` に書いて取り込み、ここで「一行 32 字、一ページ 29 行」と組んでいます。

## 注

段落の中に `[note: 注の本文]` と書くと、その位置に注の番号が付き、本文はページの下（脚注）に組まれます。

```
本文の文。[note: 注の本文です。]
```

注の本文には、段落の中の要素（ルビや強調）を使えます。
段落を分けることはできません。
注の番号は、ファイルごとに 1 から振ります。
注をページの下ではなく章の終わりにまとめるときは、`style.toml` の `[notes]` で指定します。
この段落の終わりにも、注を一つ付けています。[^note]

[^note]: この注は、ページの下に組まれています。HTML では章の終わりにまとめて置き、本文の番号と相互にリンクします。

横組みの本では、本文の脇の余白に置く傍注も使えます。

```
本文の語。[sidenote: 傍注の本文です。]
```

PDF では、傍注は版面の外の傍注欄に、注の印のある行と同じ高さで組まれます。
出典は脚注に、用語の補足は傍注に、という使い分けができます。
傍注を使うには、`style.toml` に傍注欄の設定（`[sidenotes]`）が要ります（「スタイルの設定」の章の「注と図の設定」）。
傍注は縦組みでは使えません。

## 表

行頭の `|` で始まる行で、表を書きます。

```
| 形式 | 用途 | 同じ出力の保証 |
|:---|:---|:---:|
| PDF | 印刷 | あり |
| HTML | 画面 | あり |
| EPUB | 電子書籍 | なし |
| テキスト | 転載 | あり |
```

一行目が見出しの行で、二行目の区切りの行で本体と分けます。
区切りの行の `:` の位置で、列の揃えを決めます。
`:---` は左寄せ、`:---:` は中央、`---:` は右寄せです。
上の例を組むと、次のようになります。

| 形式 | 用途 | 同じ出力の保証 |
|:---|:---|:---:|
| PDF | 印刷 | あり |
| HTML | 画面 | あり |
| EPUB | 電子書籍 | なし |
| テキスト | 転載 | あり |

セルの中には、段落の中の要素だけを書けます。
セルの結合はできません。

データが CSV のファイルにあるときは、`@table src=data/sizes.csv` のように書くと、そのファイルから表を作ります。
CSV の一行目が見出しの行になります。
次の表は、このマニュアルの原稿にある CSV のファイルから作っています。

| 判型 | 寸法 |
|---|---|
| A4 | 210mm × 297mm |
| A5 | 148mm × 210mm |
| A6 | 105mm × 148mm |
| B5 | 182mm × 257mm |
| B6 | 128mm × 182mm |
| 四六判 | 127mm × 188mm |
| 菊判 | 150mm × 220mm |
| 新書判 | 103mm × 182mm |
| mass-market | 4.25in × 6.875in |

PDF では、表は本文の行に合わせて組み、ページをまたぐ表は次のページの先頭に見出しの行を繰り返します。

## コードと外部のファイル

プログラムや設定のように、書いたとおりに組みたいテキストは、コードブロックにします。
行頭の三つのバッククォート（```` ``` ````）の行から、次の三つのバッククォートの行までがコードブロックです。

````
```toml
[page]
size = "A5"
```
````

最初の行に言語の名前（`toml` など）を書くと、HTML では構文に応じて色分けします。
コードブロックの中では、角括弧もコメントも解釈しません。

コードブロックは、組み込みの段落スタイル `code` で組みます。
PDF では、行頭と行の途中の空白をそのまま残し、タブは空白二つ分ごとの位置まで進めます。
両端揃えにせず、語をハイフンで分けず、和文と欧文のあいだも空けません。
版面に収まらない長い行は折り返し、続きを元の行の字下げより空白二つ分深い位置から始めます。
折り返したときは、お知らせ G0730 で知らせます。
書体は「スタイルの設定」の章の「書体」で、大きさと背景の色は付録C の段落スタイル `code` で決めます。

本文の中のファイル名やコマンドは、`[code: manifest.toml]` のように `[code: ...]` で書きます。
PDF では、語の途中で分けず、行は空白と `/` の後でだけ改めます。

ファイルの中身をそのまま載せるときは、`@listing` を使います。

```
@listing style.toml lines=1-5
```

`lines` で行の範囲を選べます。
省けば、ファイルの全体を載せます。
このマニュアルの「スタイルの設定」の章に載せた `style.toml` は、この書き方で、マニュアル自身の設定ファイルから取り込んでいます。

## 図版

図版は `@figure` で置きます。

```
@label fig-new
@figure images/new-project.png alt="golem new で作った本の例"
  golem new で作った本の最初のページ。
```

最初の引数が画像のファイルで、`alt` が代替テキストです。
代替テキストは、画面を読み上げる環境で画像の代わりに読まれるので、省くことはできません。
`@figure` の次の行から、空白二つで字下げして書いたのがキャプションです。

画像の形式は PNG、JPEG、PDF です。
PDF の画像は HTML と EPUB では表示できないので、`web=images/arch.png` のように画面用の画像も指定します。

画像のパスは、プロジェクトのディレクトリからの相対パスで書きます。
`@table` と `@listing` のファイルも同じです。
絶対パス、URL、プロジェクトの外を指すパスは使えず、エラー（G0260）になります。

図の番号は、章ごとに「図 2-1」のように振ります。
書式は `style.toml` の `[figures]` で変えられます。

`wrap=end width=12zw` を加えると、図版を版面の端に寄せ、本文を図版の脇に回り込ませます。
`wrap=start` なら行の始まりの側（横組みでは左）、`wrap=end` なら終わりの側（右）に寄せます。
回り込みには幅（`width`）の指定が要ります。
回り込みは PDF だけで行い、HTML と EPUB では通常の図版として置きます。
段組みの版面では、回り込みは使えません。
「インストールと最初の一冊」の章の図は、この書き方で置いています。

## 相互参照

本の中のほかの箇所を指すときは、指される側に `@label` で名前を付け、指す側でその名前を使います。

```
@label markup
# 原稿の記法

第[ref-number markup]章「[ref-title markup]」を見てください。
```

- `[ref-number 名前]`：章や節、図の番号になります。
- `[ref-title 名前]`：章や節の題になります。
- `[ref-page 名前]`：PDF では、その箇所のページ番号になります。

たとえば、この章は第 3 章「原稿の記法」です。
`[ref-page ...]` は、HTML と EPUB ではページがないので、指す箇所の題へのリンクになります。

章の題を直しても、ラベルを変えなければ参照は壊れません。
存在しないラベルを指すと、エラーになります。
番号を持たない要素（`@nonumber` の見出しや段落など）を `[ref-number ...]` で指したり、題を持たない要素（段落や表など）を `[ref-title ...]` で指したりしても、エラーになります。
相互参照のコマンドには、`: ` の後の本文を書けません。
ラベルの名前は本の全体で共通なので、ほかのファイルのラベルも指せます。
同じ名前のラベルを二つ付けることはできません。

## 目次と索引と参考文献

目次は、置きたい位置に `@toc` を書くと作られます。

```
@nonumber
@notoc
# 目次

@toc depth=2
```

`depth` で、目次に載せる見出しの階層を選びます。
PDF の目次には、見出しの題と、リーダー（点線）とページ番号を組みます。
HTML と EPUB の目次は、見出しへのリンクの一覧になります。
`@toc` は本に一つだけ置けます。

索引の項目は、本文の中に `[index reading=読み: 語]` で印を付けます。

```
[index reading=はんめん: 版面]
[index reading=るび/ぐるーぷるび: ルビ/グループルビ]
```

印は紙面には何も出しません。
`@index` を書いた位置に、読みの順に並べた索引が組まれ、PDF ではページ番号が付きます。
`/` で区切ると、主項目と副項目の二段になります。
読みを省くとエラーになります。
並べ方は、日本語の文字列の照合の規格 JIS X 4061 [1] に基づいています。

参考文献は、文献のデータを CSL-JSON の形式のファイルに書き、`manifest.toml` の `bibliography` に並べます（「プロジェクトの設定」の章）。
CSL-JSON は、多くの文献管理のソフトウェアが書き出せる形式です。
本文では `[cite キー]` で引用し、`@bibliography` を書いた位置に、引用した文献だけの一覧が組まれます。
引用の位置には、一覧の中の番号が「[1]」のように入ります。
たとえば、日本語の組版の規則は JLReq [2] にまとめられています。

このマニュアルの目次、巻末の索引と参考文献は、この節の書き方で作っています。

## 段落スタイルと韻文

段落の体裁を変えるときは、段落スタイルを付けます。
段落スタイルは `style.toml` で定義し（「スタイルの設定」の章）、原稿では段落の直前の行に `@style 名前` と書きます。

```
@style memo
この段落だけが memo の体裁になります。
```

> この段落には、マニュアルの `style.toml` で定義した段落スタイル `memo` を付けています。
> 小さめのゴシック体で、二字下げて組んでいます。

いくつもの段落に同じ段落スタイルを付けるときは、`@style 名前` の次の行から、空白二つで字下げして段落を並べます。

組み込みの段落スタイル `verse` は、段落の中の改行をそのまま行の区切りにします。
詩や歌詞、戯曲の台詞のように、行分けに意味がある文章に使います。

```
@style verse
  古池や
  蛙飛びこむ
  水の音
```

組むと、次のようになります。

```
古池や
蛙飛びこむ
水の音
```

空行で区切ると、連を分けられます。
行が長くて折り返すときは、折り返した部分を二字下げて組みます。
`verse` の段落では、行末の `\` は改行と同じ意味になり、次の行も新しい一行として組まれます。

## 改ページ

原稿の好きな位置でページを改めるときは、その位置に `@page-break` と書きます。
扉の後や、前付けの項目の間などに使います。

```
はじめにの最後の段落。

@page-break

次のページから始まる段落。
```

- `@page-break`：次のページから続けます。
- `@page-break recto`：次の奇数ページから続けます（改丁）。間の偶数ページは白ページになります。
- `@page-break verso`：次の偶数ページから続けます。
- `@column-break`：次の段から続けます（改段）。最後の段にいるときは、次のページの最初の段から続けます。一段組みの版面では `@page-break` と同じです。

`@page-break` を二つ続けると、白ページが一ページできます。
白ページには、柱もノンブルも入りません。
`@page-break recto` は、すでに空の奇数ページにいるときは何もしません。
本の最後に書いた改ページは無視されます。

ラベルを付けた見出しの前で改めるときは、`@label` と同じまとまりに書けます。

```
@page-break recto
@label appendix
# 付録
```

改ページは、リストの項目や図版のキャプションの中には書けません。
HTML と EPUB では、改ページの後の段落や見出しが次のページから始まるように CSS を書きます。
プレーンテキストには何も出力しません。

## コメントとエスケープ

`%%` と `%%` で囲んだ部分は、コメントとして出力されません。

```
本文。%% 出典を確かめる %%
```

`%%=` で始めると、校正のためのコメントになります。
校正のためのコメントは、ふだん組むときは紙面に出ますが、出荷する本として組むとき（`--profile prod`）に残っていると警告になります（「検査とエラー」の章の「書きかけと出荷」）。
コメントは空行を越えられません。

記法に使う文字を本文の文字として書くときは、前にバックスラッシュ `\` を置きます。

- 本文の `[` は `\[` と書きます。
- 段落を `#`、`-`、`+`、`=`、`@`、`|` で始めるときは、その文字の前に `\` を置きます。
- 本文の `%%` は `\%%` と書きます。
- 角括弧の中の `]` と `|` は `\]`、`\|` と書きます。
- `\` 自身は `\\` と書きます。

`%` が一つだけなら、そのまま書けます。
「50%」のような本文は、エスケープしなくても消えません。

# プロジェクトの設定

`manifest.toml` は、一冊の本の構成を書くファイル（マニフェスト）です。
どのファイルをどの順に並べるか、書名や著者は何か、どの形式に何を書き込むかをここに書きます。
書き方は、TOML という設定ファイルの形式です。
書けるキーの一覧は、付録B「manifest.toml のリファレンス」にあります。
`manifest.toml` と `style.toml` も、原稿と同じく文字コードは UTF-8、改行は LF とし、BOM を付けません。
BOM や CR があると、原稿と同じエラー（G0102、G0103）が出ます。

このマニュアル自身の `manifest.toml` は、次のとおりです。

```toml

  "chapters/01-introduction.gm",
  "chapters/02-first-book.gm",
  "chapters/03-markup.gm",
  "chapters/04-manifest.gm",
  "chapters/05-style.gm",
  "chapters/06-output.gm",
  "chapters/07-check.gm",
  "chapters/08-editor.gm",
  "chapters/09-plugins.gm",
  "appendices/a-markup.gm",
  "appendices/b-manifest.gm",
  "appendices/c-style.gm",
  "appendices/d-errors.gm",
  "back.gm",
]

[metadata]

知らないキーを書くとエラーになります。
キーの綴りを誤ったまま気づかずに組んでしまうことはありません。

## 章を並べる

`chapters` に、原稿のファイルを本の順に並べます。
パスはプロジェクトのディレクトリから書きます。

一つの章をいくつかのファイルに分けて書くときは、配列を入れ子にします。

```toml
chapters = [
  "front.gm",
  ["chapters/03-a.gm", "chapters/03-b.gm"],
]
```

ファイルを分けても、見出しの番号や図の番号は本の全体で続きます。
脚注の番号は、ファイルごとに 1 から振り直します。

一つの原稿のファイルが、別の原稿のファイルの中身を取り込むことはできません。
章の構成は、`manifest.toml` の `chapters` だけで決まります。

## 原稿の読み方

`[source]` には、原稿の読み方を書きます。
今は、段落の区切り方を選ぶ `paragraph-separator` だけがあります。

```toml
[source]
paragraph-separator = "line"
```

- `"blank-line"`：空行で段落を区切ります。段落の中の改行は文字を生みません。書かなければこちらになります。
- `"line"`：改行ひとつで段落を区切ります。一行が一つの段落になります。

`"line"` は、青空文庫の形式のように、一行を一つの段落として書く和文の原稿に向いています。

```
　吾輩は猫である。
　名前はまだ無い。
```

この二行は、二つの段落になります。
行頭の全角の空白は本文に残るので、段落の頭の一字下げをそのまま書けます。
空行は無視され、いくつ続けても空きにはなりません。
見出しやリストは、空行を挟まずに段落の直後の行に書けます。
一つの段落は一行で書きます。
段落の途中で改行して折り返す書き方はありません。

`@style verse` の段落では、`"line"` でも改行は行の区切りになり、連は空行で区切ります。
属性の形で `@style verse` を付けると、直後の一行ではなく、次の空行までの行がまとめて一つの連になります。

章ごとに区切り方を変えるときは、`chapters` の項目に書きます。

```toml
chapters = [
  "chapters/01.gm",
  { file = "en/02.gm", paragraph-separator = "blank-line" },
]
```

章の項目に書いた値は、`[source]` の値より優先します。
`@import` でだけ取り込むファイルには、`[source]` の値が効きます。

ファイルの先頭に `@manifest paragraph-separator=line` と書くと、そのファイルの区切り方を、そのファイルの中で決められます。
ファイルの中に書いた値は、章の項目と `[source]` の値より優先します。
ファイルを別の本に移しても、区切り方が一緒に付いていきます。
`@manifest` で変えられるのは `[source]` の設定だけで、書名などを書くとエラーになります。

`"blank-line"` と `"line"` のほかの値を書くと、エラーになります。

## 本の情報を書く

`[metadata]` に、書名や著者などの本の情報を書きます。
ここに書いた値は、PDF、EPUB、HTML のそれぞれの形式で決まった場所に書き込まれます。

- `id`：本の識別子です。`golem new` が一度だけ作ります。後から変えないでください。
- `title`：書名です。
- `title-reading`：書名の読みです。電子書店での並べ替えに使われます。
- `language`：本の言語です。日本語なら `"ja"`、英語なら `"en"` です。
- `date`：発行日です。PDF の作成日などは、組んだ日時ではなく、この日付から作ります。版を改めるときに書き換えます。
- `edition`：版です。
- `publisher`：発行者です。

著者などの関係者は、`[[metadata.creators]]` を人数分並べて書きます。

```toml
[[metadata.creators]]
name = "夏目 漱石"
reading = "なつめ そうせき"
role = "aut"
```

`role` には、著者なら `"aut"`、編者なら `"edt"`、訳者なら `"trl"` のように、EPUB と同じ役割の符号を書きます。

## 出力の設定

`[targets.<形式>]` には、形式ごとの設定を書きます。
少なくとも一つの形式を書いておく必要があります。

```toml
[targets.pdf]
isbn = "978-4-xxxx-xxxx-x"

[targets.epub]
isbn = "978-4-yyyy-yyyy-y"

[targets.html]

[targets.text]
variants = ["horizontal"]
```

- 紙の本と電子書籍では ISBN が違うので、ISBN は形式ごとに書きます。
- `[targets.text]` の `variants` で、プレーンテキストを縦書き用（`"vertical"`）と横書き用（`"horizontal"`）のどちらで作るかを選びます。省けば両方を作ります。

`golem build` は、`--target` を指定しなければ、ここに書いていない形式も含めて四つの形式をすべて作ります。
このマニュアルは PDF と HTML だけを使うので、`golem build --target pdf --target html` で組んでいます。

## 参考文献のデータ

`bibliography` には、文献のデータを書いた CSL-JSON のファイルを並べます。

```toml
bibliography = ["references.json"]
```

CSL-JSON は、文献を一件ずつ JSON のオブジェクトにした配列です。
このマニュアルの参考文献のデータは、次のように始まります。

```json
[
  {
    "id": "jlreq",
    "type": "report",
    "title": "日本語組版処理の要件",
    "publisher": "W3C",
    "issued": {"date-parts": [[2020]]},
    "URL": "https://www.w3.org/TR/jlreq/"
  },
```

本文では、`id` の値を使って `[cite jlreq]` のように引用します（「原稿の記法」の章の「目次と索引と参考文献」）。
一覧には、著者（`author` の `family` と `given`）、題（`title`）、発行者（`publisher`）、発行の年（`issued`）を、この順に並べて組みます。

# スタイルの設定

`style.toml` は、紙面の体裁を書くファイルです。
判型、版面、書体、見出しの大きさ、注の置き方のように、原稿の外で決めることはすべてここに書きます。
原稿に体裁を書かないので、同じ原稿を別の判型や別の書体で組み直すときも、変えるのは `style.toml` だけです。

この章の例の多くは、このマニュアル自身の `style.toml` から取り込んでいます。
`manifest.toml` と同じく、知らないキーを書くとエラーになります。
書ける表とキーの一覧は、付録C「style.toml のリファレンス」にあります。

## 判型と版面

紙面の大きさと、本文を組む領域（版面）は、`[page]` と `[page.grid]` で決めます。

```toml
[page]
size = "A5"
binding = "left"
writing-mode = "horizontal"

# 本文 13Q、行送り 22H、一行 32 字、29 行。
# 字数は 35 字から 32 字に減らした。
# 小口側の余白に傍注欄（幅 6zw と間隔 1zw）を取り、
# 仕上がりの端までの余裕も残すため。
[page.grid]
font-size = "13Q"
characters = 32
lines = 29
line-pitch = "22H"
position = { top = "22mm", gutter = "14mm" }
```

`[page]` には、紙面そのものを書きます。

- `size`：判型です。`"A4"`、`"A5"`、`"A6"`、`"B5"`、`"B6"`、`"四六判"`、`"菊判"`、`"新書判"`、`"mass-market"`（ペーパーバック）から選びます。寸法は「原稿の記法」の章の「表」に載せています。表にない判型は、`size = { width = "148mm", height = "210mm" }` のように幅と高さで書きます。
- `binding`：綴じる側です。縦組みの本は右綴じ（`"right"`）、横組みの本は左綴じ（`"left"`）が普通です。
- `writing-mode`：縦組み（`"vertical"`）か横組み（`"horizontal"`）かです。
- `bleed`：塗り足しの幅です（「出力」の章の「入稿用の PDF」）。

版面は、日本語の組版の流儀にならい、文字の大きさと字数と行数で決めます。
余白は、版面をページのどこに置くかで決まります。

- `font-size`：本文の文字の大きさです。
- `characters`：一行の字数です。
- `lines`：一ページの行数です。
- `line-pitch`：行送り（ある行から次の行までの距離）です。
- `position`：版面の位置です。`top` は天（ページの上端）から、`gutter` はノド（綴じる側の端）からの距離です。
- `columns`：段数です。省略すると 1 段になります。
- `column-gap`：段と段のあいだの空き（段間）です。`columns` が 2 以上なら必ず書きます。

寸法は、`mm`、`pt`、`Q`（級）、`H`（歯）、`zw`（全角一字分）の単位を付けて書きます。
1Q と 1H は、どちらも 0.25mm です。

版面がページに収まらない値を書くと、エラーになります。
字数か行数を減らすか、`position` を変えてください。

`columns` を 2 以上にすると、PDF の版面は段組みになります。
`characters` は一段の字数、`lines` は一段の行数です。
本文は、横組みでは左の段から右の段へ、縦組みでは上の段から下の段へ流れ、最後の段の次は次のページに進みます。
見出し、図版、表、索引も、段の中に一段の幅で組まれます。
索引だけは、`[index]` で版面と異なる段数にできます（「索引の段組み」の節）。
脚注は、注の印のある段の下に入ります。
章の終わりでは、後ろの段が空いたまま残ることがあります。
段組みの版面では、傍注欄（`[sidenotes]`）と図版の回り込み（`wrap`）は使えず、エラーになります。
HTML と EPUB は、段組みにしません。

## 書体

書体は、役割ごとに `[fonts.<役割>]` で指定します。
役割の名前は自由に付けられますが、`body` が本文の書体になります。

```toml
[fonts.body]
ja = "fonts/NotoSerifJP-Regular.otf"
latin = "fonts/SourceSerif4-Regular.otf"

[fonts.heading]
ja = "fonts/NotoSansJP-Bold.otf"
latin = "fonts/SourceSans3-Bold.otf"

[fonts.code]
ja = "fonts/NotoSansJP-Regular.otf"
latin = "fonts/SourceCodePro-Regular.otf"
```

`ja` に和文の書体を、`latin` に欧文の書体を書きます。
和文と欧文で別の書体を組み合わせるのは、日本語の組版の普通のやり方です。
このマニュアルは、本文を Noto Serif JP と Source Serif 4 で、見出しを Noto Sans JP と Source Sans 3 の太字で組んでいます。
どれも SIL Open Font License 1.1 で配布されている書体です。

コードの書体は、役割 `code` で指定します。
コードブロックと `[code: ...]` は、この役割の書体で組みます。
`[fonts.code]` がなければ本文の書体で組み、お知らせ G0808 で知らせます。
このマニュアルは、コードを Source Code Pro と Noto Sans JP で組んでいます。
どちらも SIL Open Font License 1.1 で配布されている書体です。

書体のファイルは、プロジェクトの中に置きます。
Golem は、機械にインストールされている書体を探しません。
機械ごとに入っている書体が違うと、同じ原稿から同じ紙面が得られなくなるからです。

OpenType の機能は、`features = ["palt"]` のように役割ごとに指定できます。
`palt` は、和文の約物や仮名を詰めて組む機能です。

縦組みの本では、書体の縦書き用の字形（OpenType の `vert`）を使います。
縦書き用の字形を持たないダッシュ（——）などの記号は、PDF では横組みの字形を 90 度回して、縦の線として組みます。
HTML と EPUB では、ブラウザーやリーダーが同じように記号を回して表示します。

PDF には、使った文字だけを含む形で書体を埋め込みます。
ライセンスで埋め込みを禁じている書体を使うと、エラーになります。
HTML と EPUB には、書体のファイルを同梱します。

原稿の漢字の後に異体字セレクタ（IVS）を書くと、PDF ではその字形で組みます。
書体がその異体字を持たない場合は、もとの字の字形になります。
PDF から文字を検索したり複写したりすると、異体字はもとの字として扱われます。
HTML、EPUB、プレーンテキストには異体字セレクタをそのまま書き、字形の選択は閲覧する環境の書体に任せます。

## 本文の字下げ

段落の始まりを一字下げるには、`[paragraph-styles.body]` に `first-line-indent` を書きます。

```toml
[paragraph-styles.body]
first-line-indent = "1zw"
```

既定では字下げしません。
字下げを指定したら、原稿の段落の先頭に全角の空白を書かないでください。
全角の空白と字下げが重なり、二字下がります。

`indent` を書くと、段落のすべての行を字下げします。
`first-line-indent` に負の値を書くと、最初の行だけが前に出るぶら下げになります。
箇条書きの項目、表、見出し、注の本文には、字下げは効きません。

## リストの印と番号

PDF のリストは、項目の印を行の始まりに出し、項目の二行目以降を本文の始まりにそろえます。
入れ子のリストは、外の項目の本文の始まりから下がります。
番号付きのリストは、横組みの本では `1.`、縦組みの本では `一、` の形の番号になります。

印の字形と番号の書式は、`[lists]` で入れ子の深さごとに変えられます。

```toml
[lists]
bullets = ["・", "◦"]
numbers = ["{n}.", "({a})"]
gap = "0.5zw"
```

`bullets` は箇条書きの印、`numbers` は番号の書式で、一段目のリストに最初の要素を、二段目に二つ目の要素を使います。
入れ子が配列より深いときは、最後の要素を使い続けます。
番号の書式には、番号を表す差し込みをちょうど一つ書きます。
差し込みは `{n}`（本の数の表記）、`{1}`（算用数字）、`{一}`（漢数字）、`{①}`（丸数字）、`{a}` と `{A}`（ラテン文字）、`{i}` と `{I}`（ローマ数字）、`{ア}` と `{イ}`（片仮名のアイウエオ順とイロハ順）です。
差し込みでない波括弧は、`{{` と `}}` のように重ねて書きます。
`gap` は印と本文の間の空きで、書かなければ印の最後の文字から決まります。

`[lists]` は HTML、EPUB、プレーンテキストにも効きます。
丸数字のように表せる番号に限りのある書式で、表せない番号の項目があると、エラーになります。

## 段落スタイルと文字スタイル

段落の体裁は段落スタイルに、文字の体裁は文字スタイルにまとめます。
考え方は、Adobe InDesign の段落スタイルと文字スタイルと同じです。

```toml
[character-styles.bold]
font = "heading"

[character-styles.code]
color = "code"

[paragraph-styles.body]
first-line-indent = "1zw"

[paragraph-styles.memo]
font = "heading"
size = "11Q"
indent = "2zw"

[paragraph-styles.caption]
size = "11Q"

[paragraph-styles.sidenote]
size = "10Q"
```

文字スタイル（`[character-styles.<名前>]`）に書けるキーは次のとおりです。

- `font`：書体の役割です。
- `size`：文字の大きさです。
- `color`：色の名前（スウォッチ）です。
- `synthetic-bold`、`synthetic-italic`：書体の輪郭を太らせた太字と、傾けた斜体です。
- `based-on`：引き継ぐ文字スタイルです。

`bold`、`italic`、`strong` の三つは、はじめから定義されています。
同じ名前で書くと、書いたキーだけが置き換わります。
このマニュアルは、`bold` の書体を見出しの太いゴシック体にしています。
`strong` は `bold` を引き継ぐので、`[strong: ...]` も同じ書体で組まれます。

段落スタイル（`[paragraph-styles.<名前>]`）に書けるキーは次のとおりです。

- `font`、`size`：書体の役割と文字の大きさです。大きさは本文の文字の大きさまでです。
- `indent`、`first-line-indent`：字下げです。
- `space-between`：同じ段落スタイルの段落が続くときに、あいだに空ける行の数です。
- `line-breaks`：`"keep"` にすると、段落の中の改行を行の区切りにします。
- `based-on`：引き継ぐ段落スタイルです。省くと `body` を引き継ぎます。

はじめから定義されている段落スタイルは、`body`（本文）、`verse`（韻文）、`caption`（図のキャプション）、`sidenote`（傍注の本文）の四つです。
段落スタイルを付けない段落は `body` で組みます。

行送りは、段落スタイルでは変えられません。
本文を行の格子にそろえて組むので、段落ごとに行送りが変わると、見開きの左右で行の位置がずれるからです。

## 文字の送り

文字スタイルと段落スタイルには、文字の送りを決める四つのキーも書けます。
`[paragraph-styles.body]` に書くと、本の全体の既定になります。
文字スタイルで書かなかったキーは、外側の文字の値のままです。

- `kerning`：カーニング（字の組ごとの字間の調整）の方式です。`"metrics"`（既定）は、フォントのペアカーニングの情報で字間を調整します。`"japanese-equal-width"` は欧文だけを調整し、和文は全角の送りのまま組みます。`"none"` は調整しません。
- `tracking`：文字ごとに足す空きです。文字の大きさの 1/1000 を単位に、-1000 から 10000 までの整数で書きます。負の値は字間を詰めます。
- `proportional-metrics`：`true` にすると、和文を字面に合わせた送り（プロポーショナルメトリクス）で組みます。括弧類と句読点は全角のまま組みます。
- `baseline-shift`：文字を、横組みでは上へ、縦組みでは右へずらす量です。`"1pt"` や `"-0.25zw"` のように書きます。行の位置は変わりません。

```toml
[paragraph-styles.body]
kerning = "japanese-equal-width"

[character-styles.tight]
tracking = -50
```

和文のフォントがカーニングの情報を持っていると、既定の `metrics` では和文の字間が字の組ごとに変わり、字送りの格子からずれる行が出ます。
格子にそろえたい本文は、`[paragraph-styles.body]` に `kerning = "japanese-equal-width"` と書いてください。
約物（括弧類、句読点、中点類）を含む字の組には、和文のカーニングをかけません。
トラッキングの空きは、行の最後の文字の後ろには入りません。
オプティカルカーニング（`kerning = "optical"`）は、まだ使えません。
書くと G0321 のエラーになります。

HTML と EPUB では、CSS の `font-kerning`、`letter-spacing`、`font-feature-settings`、`vertical-align` で表します。
CSS では和文と欧文で別のカーニングを指定できないので、`japanese-equal-width` は欧文のカーニングを保ちます。

## ファイルの中のスタイル

一つの章でだけ使う段落スタイルと文字スタイルは、その章のファイルの先頭に `@style-def` で書けます。
ファイルの中で定義したスタイルは、そのファイルにだけ効きます。

```
@style-def paragraph letter indent=2zw first-line-indent=0zw
@style-def character sender font=heading

@style letter
拝啓[style sender: 浅川]殿
```

最初の語は種類で、`paragraph`（段落スタイル）か `character`（文字スタイル）です。
次の語がスタイルの名前で、その後に `style.toml` と同じキーを `キー=値` の形で並べます。
値は `2zw` や `keep` のように引用符なしで書けます。
`true` と `false` は真偽値に、数字だけの語は整数になります。
一つのスタイルは一行で定義します。

`style.toml` にある名前を書くと、そのファイルの中でだけ、書いたキーが置き換わります。
たとえば `@style-def paragraph body indent=1zw` は、その章の本文の字下げだけを変えます。
`body` を引き継ぐ段落スタイルの字下げも、その章の中では一緒に変わります。

`@style-def` は、ファイルの最初に置きます。
前に置けるのは、コメントと空行だけです。
`@import` で取り込んだファイルの `@style-def` は、取り込んだ側では使えません。

> この段落には、この章のファイルの先頭で定義した段落スタイル `example` を付けています。
> `memo` を引き継ぎ、最初の行だけをもう一字下げています。

## 正規表現スタイル

段落スタイルには、正規表現に一致した文字に文字スタイルを当てる設定を書けます。
InDesign の正規表現スタイル（GREP スタイル）と同じ考え方です。
数字だけを欧文の書体にする、「第 N 章」の N だけを太字にする、といった体裁を、原稿に `[style ...]` を書かずに付けられます。

```toml
[paragraph-styles.body]
regex-styles = [
  { pattern = '[0-9０-９]+', style = "latin-digits" },
  { pattern = '(?<=第)[0-9]+(?=章)', style = "bold" },
]
```

`regex-styles` には、`pattern`（正規表現）と `style`（文字スタイルの名前）の組を並べます。
正規表現は `'...'` で囲むと、`\` をそのまま書けます。
同じ文字に二つの組が一致した場合は、後の組が勝ちます。
原稿で手で付けた文字スタイルは、正規表現スタイルより優先されます。

`regex-styles` は `based-on` で引き継がれます。
引き継いだ段落スタイルで `regex-styles = []` と書くと、引き継がなくなります。
見出し、表、脚注の本文には当たりません。
図のキャプションには `caption` の、傍注の本文には `sidenote` の `regex-styles` が当たります。

使える正規表現は、InDesign の正規表現の主なものです。
`\d` は全角の数字にも、`\w` は漢字と仮名にも、`\s` は全角の空白にも一致します。
後方参照、`\p{Han}` のような文字体系の指定、長さの決まらない後読み、InDesign の `~` で始まる記号は使えず、エラー（G0315）になります。
和文の文字の範囲は `[\x{4E00}-\x{9FFF}]` のように符号位置で書きます。
縦中横と `[number-text ...]` の数は一字として扱うので、`[0-9]+` はその中の数字には一致しません。

一つの章でだけ使う正規表現スタイルは、`@style-def regex` で書けます。

```
@style-def regex body pattern="\\d+" style=bold
```

二つ目の語が組を足す段落スタイルの名前で、一行が一つの組です。
文字列の中では `\` を `\\` と書きます。

> この段落には、数字だけを太字にする正規表現スタイルを、この章のファイルの先頭で付けています。
> 2026 年 10 月 14 日、１２３ページ。

## 見出しの体裁

見出しの書体と番号は、階層ごとに `[headings.<階層>]` で決めます。

```toml
[headings.1]
font = "heading"
size = "20Q"
number = "第{n}章"
page-break = "recto"

[headings.2]
font = "heading"
size = "15Q"
number = "{1}.{n}"

[headings.3]
font = "heading"
number = "{1}.{2}.{n}"
```

- `font`、`size`：書体の役割と文字の大きさです。
- `number`：番号の書式です。`{n}` がその階層の番号、`{n:kanji}` が漢数字の番号、`{1}` と `{2}` が上の階層の番号になります。縦組みの本なら `"第{n:kanji}章"` で「第三章」のように組めます。
- `page-break`：`"recto"` にすると、その見出しを奇数ページから始めます。

本文より大きい見出しも、行の格子からずらさずに置きます。
見出しは、その大きさを収める行数を占め、その中の中央に組まれます。

## 柱とノンブル

柱（ページの余白に置く章の題）とノンブル（ページ番号）は、`[masters.body]` で置きます。

```toml
[masters.body]
folio = { position = "bottom-outside", format = "{n}" }

[masters.body.running-head]
position = "top-outside"
content = "heading.1.short"
```

`position` には、`"top-outside"`、`"top-center"`、`"top-inside"`、`"bottom-outside"`、`"bottom-center"`、`"bottom-inside"` のどれかを書きます。
`top` と `bottom` は天と地の余白、`outside` は小口の側、`inside` はノドの側です。
`content` は、柱に出す内容です。
`"heading.1.short"` なら、そのページの章の題が入ります。
`@toc-title` で短い題を付けた見出しは、短い題が入ります。
`format` は、ノンブルの書式です。
このマニュアルのように、柱を天の小口側に、ノンブルを地の小口側に置くのが普通です。

柱の内容には、次の値を書けます。
`<階層>` は見出しの階層の数です。

- `"heading.<階層>.short"`：その階層の見出しの題です。ページの中で始まった最初の見出しを使い、なければその前から続く見出しを使います。
- `"heading.<階層>.numbered"`：番号と題を全角の空白でつないだものです（「第3章　原稿の記法」など）。
- `"heading.<階層>.short.last"`、`"heading.<階層>.numbered.last"`：ページの中で始まった最後の見出しを使います。辞書の柱のような使い方です。
- `"title"`：`manifest.toml` の書名です。
- `"none"`：柱を出しません。

左右のページで柱を変えるときは、`content` の代わりに `even`（偶数ページ）と `odd`（奇数ページ）の両方を書きます。

```toml
[masters.body.running-head]
position = "top-outside"
even = "title"
odd = "heading.1.numbered"
```

章の始まりのページ（`page-break = "recto"` の見出しのあるページ）と白ページには、柱を出しません。
章ごとに別のマスターページを使うときは、`manifest.toml` の章の項目に `{ file = "front.gm", master = "front" }` のように `master` を書きます。
`master` のない章は `[masters.body]` を使います。
目次のページなどで柱を消したいときは、`running-head` のないマスターページを指定します。
見出しの `[headings.<階層>]` には `running-head` を書けません。

## 注と図の設定

注、傍注、図番号、目次の体裁は、それぞれの表で決めます。

```toml
[notes]
placement = "page-foot"

[sidenotes]
width = "6zw"
gap = "1zw"

[figures]
number = "図{chapter}-{n}"

[toc]
leader = "dots"
```

- `[notes]` の `placement`：脚注をページの下に置くか（`"page-foot"`）、章の終わりにまとめるか（`"chapter-end"`）です。既定はページの下です。
- `[sidenotes]`：傍注欄を、小口側の余白に設けます。`width` が傍注欄の幅、`gap` が版面とのあいだの空きです。`marker` で本文側の印を、番号（`"number"`）、「※」（`"symbol"`）、なし（`"none"`）から選べます。
- `[figures]` の `number`：図番号の書式です。`{chapter}` が章の番号、`{n}` が章の中の図の番号です。`wrap-gap` で、回り込みの図版と本文のあいだの空きを決めます。
- `[toc]` の `leader`：目次のリーダーを点線（`"dots"`）にするか、なし（`"none"`）にするかです。

傍注欄の幅は、傍注を使うなら必ず決めてください。
`[sidenotes]` がないまま傍注を使うと、PDF を組むときにエラーになります。
このマニュアルは、傍注欄を取るために一行の字数を減らしています。
傍注欄は小口側の余白の中に収まる必要があるからです。

## 索引の段組み

索引は短い語とページ番号の並びなので、本文と同じ行長で組むと、行の後半が空いたままになります。
`[index]` を書くと、PDF の索引だけを版面と異なる段数で組めます。

```toml
[index]
columns = 2
column-gap = "2zw"
```

- `columns`：索引を組む段数です。1 以上の整数で書きます。書かなければ、版面の段数で組みます。
- `column-gap`：索引の段と段のあいだの空きです。書かなければ、`[page.grid]` の `column-gap` を使います。

索引の段の幅は、版面の幅から段間を引き、`columns` の数で等しく分けたものです。
傍注欄は版面の幅に含めません。
索引の行は、本文と同じ行の位置に並びます。
索引の段の幅が本文の文字の 8 字分に満たないと、エラーになります。
`columns` を減らすか、`column-gap` を狭めてください。

一段組みの版面では、`@index` の位置から、そのページの残りの行を段に分けて索引を組みます。
`# 索引` のような見出しは、一段の幅のまま索引の段の上に置かれます。
二段以上の版面では、次のページの最初から索引を組みます。
索引の後の内容は、次のページから版面の段組みに戻ります。
HTML と EPUB は、索引を段組みにしません。
このマニュアルの索引は、二段で組んでいます。

## 色

色は、名前を付けて `[color.swatches]` に定義します。

```toml
[color.swatches]
accent = { cmyk = [0, 80, 100, 0] }
code = { cmyk = [90, 50, 0, 20] }
```

値は、CMYK の各色の網点の割合（0 から 100）です。
原稿や文字スタイルからは、この名前で色を指します。
原稿に CMYK の値を直接書くことはできません。
印刷を前提に色を決め、HTML と EPUB では、その色に近い画面の色で表示します。

印刷所から印刷の色の条件を記したファイル（ICC プロファイル）を指定されたら、`[color]` の `intent` にそのファイルを書きます。

```toml
[color]
intent = "icc/JapanColor2001Coated.icc"
```

## 行分割と和文組版

行の分け方と、和文の組み方の細部は、`[composition]` で変えられます。
何も書かなければ、日本語組版処理の要件（JLReq）が一般的な処理として示す組み方になります。

```toml
[composition]
hanging-punctuation = true
```

- `kinsoku`：禁則の強さです。`"strict"`（既定）は、小書きの仮名（ぁ、っ、ゃ など）と長音記号も行頭に置きません。`"loose"` は、それらの行頭を許します。
- `hanging-punctuation`：`true` にすると、行末の句読点を版面の外に出すことを許します（ぶら下げ組）。このマニュアルはぶら下げ組で組んでいます。
- `tolerance`、`pretolerance`、`emergency-stretch`：欧文の段落を行に分けるときの、語間の伸び縮みの許容度です。既定値は TeX と同じ 200、100、0 です。どうしても行に分けられないときは、行が版面からはみ出し、警告が出ます。

ルビの配置は `[composition.ruby]` で変えます。

```toml
[composition.ruby]
mono-align = "center"
group-align = "1:2:1"
overhang = "0.5zw"
overhang-onto = "kana"
```

- `mono-align`：モノルビの読みが親文字より短いときに、中央に置くか（`"center"`）、始まりにそろえるか（`"start"`）です。
- `group-align`：グループルビの読みの配置です。`"1:2:1"` は字のあいだに等しい空きを入れ、両端にその半分を置きます。
- `overhang`：読みが親文字より長いときに、隣の文字にかけてよい量です。
- `overhang-onto`：`"kana"` なら仮名にだけかけ、`"none"` ならかけません。

縦組みの本で `[number-text ...]` の数をどう組むかは、`[numbers]` の `vertical` で決めます。
`"kanji"`（十、百二十）、`"kanji-digits"`（一〇、一二〇）、`"tcy"`（縦中横の算用数字）から選べます。

## 字間の空き

和文の文字のあいだの空きの量は、アキ量のセットで決めます。
InDesign の文字組みアキ量設定に当たる設定で、和文と欧文のあいだ（和欧間）、括弧や句読点の前後のような文字の組み合わせごとに、空きの最小、最適、最大を持ちます。
何も書かなければ、組み込みのセット `gyomatsu-yakumono-hankaku`（行末約物半角）で組みます。
和欧間は四分、括弧と句読点は半角の字面に二分の空き、行末の括弧と句読点は半角です。
行末の括弧と句読点の後ろにも二分を残す `gyomatsu-yakumono-zenkaku`（行末約物全角）も組み込みで持っています。

セットを変えるには、`[aki-sets.名前]` にセットを定義し、段落スタイルの `aki-set` で選びます。

```toml
[aki-sets.wide-waou]
based-on = "gyomatsu-yakumono-hankaku"

[[aki-sets.wide-waou.rules]]
before = "japanese"
after = "western"
optimum = "三分"
minimum = "四分"
maximum = "二分"

[[aki-sets.wide-waou.rules]]
before = "western"
after = "japanese"
optimum = "三分"
minimum = "四分"
maximum = "二分"

[paragraph-styles.body]
aki-set = "wide-waou"
```

- `based-on`：基準にするセットです。書かなければ `gyomatsu-yakumono-hankaku` です。
- `rules`：基準のセットに足す規則です。後に書いた規則が、同じ組み合わせの前の規則を上書きします。
- `before` と `after`：前と後ろの文字のクラスです。`kana`（仮名）、`ideograph`（漢字）、`opening`（始め括弧）、`closing`（終わり括弧）、`full-stop`（句点）、`comma`（読点）、`middle-dot`（中点）、`western`（欧文）、欧文のほかすべての `japanese` などを書き、配列で並べることもできます。`before` には段落の先頭の `paragraph-start` と行頭の `line-start`、`after` には行末の `line-end` も書けます。
- `optimum`、`minimum`、`maximum`：空きの最適、最小、最大です。最小と最大を書かなければ最適と同じになり、伸び縮みしません。

量は `"四分"` のような名前か、`"0.25zw"` か、`"25%"` で書きます。
段落スタイルは `body` からセットを引き継ぐので、`body` で選べば本の全体が変わります。
引用だけ組み方を変えるときは、その段落スタイルの `aki-set` だけを書きます。
組み込みのセットと同じ名前のセットは定義できません。
値を変えたいときは、`based-on` で引き継いだ別の名前のセットを作ります。

アキ量のセットは PDF にだけ効きます。
HTML と EPUB は、ブラウザーの組み方で組みます。

# 出力

Golem は、一つの原稿から PDF、HTML、EPUB、プレーンテキストの四つを作ります。
四つの形式は、見た目までは同じになりません。
本文、見出し、注、図版といった中身はどの形式でも同じで、ページ番号や柱のようにページがあって初めて決まるものは、形式ごとに表し方が変わります。

## PDF

```sh
golem build --target pdf
```

PDF は `build/pdf/` に書かれます。
ファイルの名前は、`manifest.toml` の `id` から作ります。

PDF は、印刷用の規格 PDF/X-4 に合わせて書きます。
書体は、使った文字だけを含む形で埋め込みます。
写真などの画像は、色を変換せず、画像の色の情報（ICC プロファイル）を付けたまま埋め込みます。
色の情報のない RGB の画像は、sRGB の画像として扱います。

PDF/X-4 に合っているかは Golem 自身でも確かめていますが、印刷所に入稿する前には、Acrobat などのプリフライトの機能で確認してください。

## 入稿用の PDF

日本の印刷所に入稿する PDF には、塗り足しとトンボを付けます。
塗り足しは、仕上がりの寸法の外側に設ける領域で、断裁がずれても紙の端に白い筋が出ないようにするためのものです。
トンボは、断裁の位置を示すために、仕上がりの寸法の外側に描く線です。

塗り足しの幅は、`style.toml` の `[page]` に書きます。
日本の印刷所では 3mm が多く使われます。

```toml
[page]
size = "A6"
binding = "right"
writing-mode = "vertical"
bleed = "3mm"
```

トンボは、`golem build` の `--marks` で付けます。

```sh
golem build --target pdf --marks japanese
```

- `--marks japanese`：日本式のトンボ（仕上がりの線と塗り足しの線の二重）を付けます。
- `--marks western`：欧文の一重のトンボを付けます。
- `--marks none`：トンボを付けません。既定はこれです。

日本式のトンボは、塗り足しの幅を二本の線の間隔で示すので、`bleed` を書いていないとエラーになります。
画面で読むための PDF と入稿用の PDF は、同じ原稿から `--marks` を変えて作り分けます。

![golem new で作った本に、塗り足しと日本式のトンボを付けたページ](../manual/images/crop-marks.png)

この図は、`golem new` で作った本に `bleed = "3mm"` を書き、`--marks japanese` を付けて組んだページです。

## HTML

```sh
golem build --target html
```

HTML は `build/html/` に、原稿のファイルごとに一つずつ書かれます。
`index.xhtml` が入り口です。
書体のファイルとスタイルシートも同じディレクトリに置くので、ディレクトリごと Web サーバーに置けば、そのまま読めます。

HTML は、画面の幅に合わせて文章を流し込む形式なので、版面、柱、ノンブルはありません。
`style.toml` からは、書体、文字スタイル、段落スタイル、色、番号の書式を使います。
脚注は章の終わりにまとめ、本文の番号と相互にリンクします。
傍注は、画面が広ければ余白に、狭ければ段落の直後に置きます。
コードブロックは、言語の名前を書いていれば構文に応じて色分けします。

HTML の見た目を、スタイルシートを直接書いて変える方法はありません。
見た目は `style.toml` で決め、PDF と同じ設定から作ります。

## EPUB

```sh
golem build --target epub
```

EPUB は `build/epub/book.epub` に書かれます。
脚注は、電子書籍の端末でポップアップとして表示される形で書きます。
傍注は、段落の直後に置きます。
本の識別子には、`[targets.epub]` に電子版の ISBN を書いていればそれを、なければ `manifest.toml` の `id` を使います。

## プレーンテキスト

```sh
golem build --target text
```

プレーンテキストは、ブログなどに文章を転載するための形式です。
`build/text/vertical/` に縦書き用、`build/text/horizontal/` に横書き用のテキストを、原稿のファイルごとに書きます。
二つの違いは数の書き方です。
`[number-text 10]` は、縦書き用では「十」、横書き用では「10」になります。

ルビは「組版（くみはん）」のように親文字の後に括弧で書き、注は章の終わりにまとめます。
索引は出力しません。

## 同じ原稿から同じ出力

Golem は、同じ入力から、いつでも中身が一バイトも違わない同じファイルを出力します。
入力とは、原稿、`manifest.toml`、`style.toml`、画像、書体のファイル、プラグイン、`--marks` と `--profile` の指定、それに Golem 自身の版です。

組んだ日時は、出力に入りません。
PDF の作成日などには、`manifest.toml` の `date` を書き込みます。
組むたびに日時が変わると、紙面が同じでも PDF のファイルの中身が変わってしまうからです。

この性質があると、原稿や設定を変えたときに、変わったページだけを見つけられます。
原稿を変えるたびに自動で組み直す仕組み（CI）で毎回組み、前の版の PDF とページの画像を比べれば、崩れたページだけが差分として残ります。

同じ出力を保証しているのは、PDF、HTML、プレーンテキストです。
EPUB は、中にまとめるファイルの記録の仕方をまだ決めていないので、同じ中身になることを保証していません。
Golem の版を上げると、同じ原稿からでも出力は変わることがあります。

# 検査とエラー

原稿や設定に誤りがあると、Golem はエラーや警告を出します。
どちらも、誤りの場所と、何が誤りかを示すメッセージです。
この章では、その読み方と、出力を作らずに原稿を検査する方法を説明します。

## エラーと警告の読み方

コマンドの名前を誤ると、次のエラーが出ます。

```
chapters/01.gm:3:2: error[G0222]: 未知のコマンドです: rubi
  | [rubi: 東京|とうきょう]
```

一行目は、左から次のように読みます。

- `chapters/01.gm:3:2`：ファイルと、行と、その行の何文字めかです。
- `error`：重大度です。`error`（エラー）、`warning`（警告）、`notice`（お知らせ）のどれかです。お知らせは、この章の「お知らせ」の節で説明します。
- `G0222`：エラーと警告のコードです。版が変わっても同じ誤りには同じコードが付くので、検索や記録に使えます。コードごとの意味と直し方は、付録D にまとめています。
- その後が、誤りの説明です。

二行目は、誤りのある行の中身です。
この例では、ルビのコマンドの名前 `ruby` を `rubi` と書いています。
`[ruby: 東京|とうきょう]` と直せば、エラーは消えます。

エラーが一つでもあると、`golem build` はその形式の出力を書きません。
警告だけなら出力を書きます。
スクリプトから成否を確かめるときは、コマンドの終了コードを見ます。
エラーがあれば 1、警告とお知らせだけなら 0、コマンドの使い方を誤ったときは 2 です。

`--format json` を付けると、エラーと警告を、プログラムで読みやすい JSON の形式で出力します。
ほかのツールに読ませるときに使います。

```sh
golem check --format json
```

## エラーのコードを調べる

`golem explain` にコードを渡すと、そのコードの意味、主な原因、直し方を表示します。
コードは小文字で書いてもかまいません。

```sh
golem explain G0222
```

コードを省くと、すべてのコードを題とともに一行ずつ表示します。
使わなくなったコードには、題の後に「（廃止）」が付きます。

エラーや警告を出したときは、最後に「`コードの説明は golem explain <コード> で表示できます（例: golem explain G0222）`」の一行を加えて、このコマンドを案内します。

同じ説明は、Golem のリポジトリの `docs/diagnostics.md` でも読めます。
プラグインが出すエラーと警告のコードは、プラグインの文書を参照してください。

## お知らせ

Golem は、誤りではないものの、知っておいたほうがよいことをお知らせとして伝えます。
たとえば、自動で振られる番号と同じ番号を `@number` に書くと、次のお知らせが出ます。

```
a.gm:5:1: notice[G0407]: @number 1 は自動で振られる番号と同じです
  | @number 1
```

重大度は `notice` です。
お知らせは直さなくてもかまいません。
出力は変わらず、終了コードにも影響しません。
エラーと警告の後に、まとめて表示します。

お知らせには、ファイルの中でスタイルを上書きしたこと、`style.toml` がないので既定の体裁で組むこと、効果のない書き方、今後の版で使えなくなる書き方（廃止予定）などがあります。
一覧は付録D の「お知らせ」の節にあります。
廃止予定のお知らせは、版を上げたときに書き方の変更を知る手がかりになるので、読んで書き換えておくことをお勧めします。

決まったお知らせを出さないようにするには、`manifest.toml` の `[diagnostics]` の `silence-notices` にコードを並べます。

```toml
[diagnostics]
silence-notices = ["G0262", "G0407"]
```

ここに並べたお知らせは、`golem build`、`golem check`、`golem lint` と、エディタ（LSP）のどれにも出なくなります。
並べられるのはお知らせのコードだけです。
エラーや警告のコードを書くと、エラー（G0324）になります。
エラーと警告は止められないので、原因を直してください。

一度の実行に限ってすべてのお知らせを出さないようにするには、`--no-notices` を付けます。
`golem build`、`golem check`、`golem lint` で使えます。

```sh
golem build --no-notices
```

## 出力を作らずに検査する

`golem check` は、PDF や HTML を書かずに、原稿と設定を検査します。

```sh
golem check
```

記法の誤り、存在しないラベルへの参照、`style.toml` の誤り、書体のファイルの有無などを確かめます。
PDF を作る設定なら、版面が判型に収まるか、段落スタイルの字下げが行を残すか、本文の書体を設定してあるかも確かめます。
組むよりも早く終わるので、原稿を書いている途中の確認に向いています。

## 誤りやすい書き方を探す（lint）

`golem lint` は、記法としては正しくても、ほぼ確実に誤りである書き方を探します。

```sh
golem lint
```

見つけるのは次のものです。

- 段落の中の改行の前後がどちらも欧文の文字である箇所。単語が空白なしにつながってしまいます。改行ひとつで段落を区切る書き方（`paragraph-separator = "line"`）では、段落の区切りの改行は対象になりません。
- 使われていない `@set` の変数と `@import`。
- どこからも参照されていない `@label`。

lint の規則は、変えることも止めることもできません。
誰が見ても誤りと言えるものだけを規則にしているからです。
全角と半角の使い分けのような表記の揺れは、lint の対象にしていません。
表記をそろえるには、校正のためのツールを併せて使ってください。

## 整形

`golem fmt` は、原稿の書き方を整えます。

```sh
golem fmt
```

整えるのは、コマンドの中の空白、ブロックコマンドの書き方、リストの字下げ、空行の数、行末の空白、エスケープの書き方です。
本文の改行の位置は変えません。
整形の前と後で、組んだ結果は変わりません。

`golem fmt --check` は、ファイルを書き換えずに、整形が必要なファイルの名前を表示します。
自動の検査（CI）で、整形していない原稿が入っていないかを確かめるのに使います。

## 書きかけと出荷

`golem build`、`golem check`、`golem lint` では、`--profile` で、原稿を書きかけとして扱うか、出荷する本として扱うかを選べます。
この選択をプロファイルと呼びます。

- `dev`：書きかけの原稿として扱います。既定はこれです。
- `prod`：出荷する本として扱います。

`prod` では、いくつかの警告がエラーになり、出力が止まります。
たとえば、参照されていないラベルは、`dev` では警告、`prod` ではエラーです。
校正のためのコメント（`%%= ... %%`）は、`dev` では紙面に出て、`prod` に残っていると警告になります。
書体のファイルが見つからないとき、HTML と EPUB は `dev` では書体を同梱せずに出力し、`prod` ではエラーになります。

印刷所に渡す PDF や、公開する HTML は、`--profile prod` で組んでください。

よく出るエラーと警告を、次の表にまとめます。
すべてのコードの一覧は、付録D にあります。

| G0215 | モノルビの対象と読みのセグメントの数が一致しません | 親文字と読みの `/` の数をそろえます |

# エディタと LSP

Golem には、エディタに Golem の原稿のための機能を足す部品が入っています。
この部品は、多くのエディタが対応している LSP（Language Server Protocol）という共通の取り決めに従っています。
LSP に対応したエディタに設定すると、原稿を書きながら誤りを確かめ、ラベルや変数をたどれます。

## エディタでできること

- エラーと警告：保存を待たずに、`golem check` と `golem lint` と同じエラーと警告を、誤りの箇所に表示します。エラーと警告のコードは、そのコードの説明へのリンクになります。
- 定義への移動と参照の検索：ラベル、変数、`@import` のファイルをたどれます。ラベルは章をまたいで引けます。
- 名前の変更：ラベルの名前を変えると、ほかの章の参照も一度に書き換えます。
- 補完：コマンドの名前、ラベル、`@import` のパスを補います。
- 式の値の表示：`[= ...]` にカーソルを合わせると、計算の結果を表示します。
- 整形：`golem fmt` と同じ整形をします。
- アウトライン：見出しの一覧を表示します。

組んだ紙面のプレビューは、LSP の範囲に入っていません。
紙面は `golem build` で組んで確かめてください。
エディタの中では書体のファイルを読まないので、書体を置く前でも原稿のエラーは表示されます。

## エディタに設定する

この部品は、`golem lsp` というコマンドです。
起動するのは人ではなくエディタで、エディタはこのコマンドの入出力を通してやりとりします。
エディタには、拡張子が `.gm` のファイルを開いたときにこのコマンドを起動し、`manifest.toml` のあるディレクトリをプロジェクトのディレクトリとして扱うように設定します。

Neovim（0.11 以降）では、たとえば次のように設定します。

```lua
vim.filetype.add({ extension = { gm = "golem" } })
vim.lsp.config("golem", {
  cmd = { "golem", "lsp" },
  filetypes = { "golem" },
  root_markers = { "manifest.toml" },
})
vim.lsp.enable("golem")
```

ほかのエディタでも、起動するコマンド（`golem lsp`）と、対象のファイル（`.gm`）と、プロジェクトのディレクトリの目印（`manifest.toml`）の三つを設定すれば使えます。

# プラグイン

Golem の組み込みのコマンドでは足りないとき、プラグインで機能を加えられます。
たとえば、本文のすべての漢字に辞書で振り仮名を付ける処理は、Golem には組み込まれていません。
こうした処理を、プラグインとして配布されたものを取り込んで使います。

## プラグインでできること

プラグインには二つの種類があります。

- コマンド：`[furigana: ...]` のように、原稿から角括弧で呼び出します。組み込みのコマンドと同じように、段落の中に要素を返します。
- フィルタ：原稿のファイル一つ分の中身を受け取り、書き換えて返します。本文の全体を対象にする処理に使います。

プラグインは、どの機械でも同じように動く WebAssembly（wasm）という形式のファイルで配布されます。

## プラグインを使う

使うプラグインは、`manifest.toml` の `[plugins.<名前>]` に、配布物の URL を書いて宣言します。

```toml
[plugins.furigana]
url = "https://example.com/furigana/v1.0.0/furigana.wasm"
```

URL は HTTPS に限ります。
版を固定した URL（リリースごとの配布物の URL など）を書いてください。

宣言したら、`golem plugin lock` を実行します。

```sh
golem plugin lock
```

このコマンドは、配布物を取得し、その中身から計算した値（ハッシュ）をプロジェクトの `plugins.lock` に書き込みます。
ハッシュは、ファイルの中身が一バイトでも変わると変わる値です。
`plugins.lock` は手で編集せず、原稿と一緒に Git に入れます。
同じ URL の中身が後から差し替えられても、ハッシュが合わなければエラーにして、知らないプラグインを動かさないためです。

取得した配布物は、利用者ごとの置き場所（キャッシュ、`~/.cache/golem/plugins` など）に置きます。
`golem build` はキャッシュからだけ読み、ネットワークには接続しません。
別の機械でプロジェクトを取り出したときは、`golem plugin fetch` で `plugins.lock` のとおりに配布物を取得してから組みます。

```sh
golem plugin fetch
golem build
```

プラグインを読み込めないときは、`plugins.lock` やキャッシュの問題を示すエラーだけを出します。
そのプラグインのコマンドを使った箇所は、未知のコマンドとして報告しません。
`plugins.lock` が壊れて読めないときは、`plugins.lock` を消してから `golem plugin lock` を実行し直してください。

## 組み込みのコマンドを置き換える

プラグインは、ルビや強調のような見た目に関わる組み込みのコマンドを置き換えられます。
置き換えるときは、`overrides` に置き換えるコマンドの名前を書きます。

```toml
[plugins.furigana]
url = "https://example.com/furigana/v1.0.0/furigana.wasm"
overrides = ["ruby"]
```

書いていない名前は置き換わりません。
目次、注、索引、相互参照のように、本の構造に関わるコマンドは置き換えられません。

## フィルタを適用する

フィルタは、`[[filters]]` で、どのプラグインのどのフィルタを、どのファイルに適用するかを書きます。

```toml
[[filters]]
plugin = "furigana"
filter = "total-ruby"
files = ["chapters/01.gm", "chapters/02.gm"]
```

`[[filters]]` を複数書くと、書いた順に適用します。

## プラグインを安全に動かすしくみ

プラグインは、外から取り込んだプログラムです。
Golem は、プラグインに、ファイル、ネットワーク、時計、乱数を渡しません。
プラグインは、渡された原稿の一部を受け取って結果を返すことしかできません。
このため、プラグインを使っても、同じ入力から同じ出力が得られる性質は崩れません。

プラグインが返した結果は、Golem が検査してから使います。
形の正しくない結果は、エラーになります。

# 付録A 記法のリファレンス

この付録は、原稿の記法を一つずつ引けるように並べたものです。
使い方の流れは「原稿の記法」の章で説明しています。
ここでは、それぞれの書き方と、引数、短い例、注意を並べます。

## ファイルの決まり

- **拡張子**：原稿のファイルの名前は `.gm` で終えます。
- **文字コード**：UTF-8 で保存します。UTF-8 は、いまのテキストエディタの多くが標準で使う文字コードです。Shift_JIS などで保存したファイルは、エラーになります。
- **BOM**：ファイルの先頭に BOM（文字コードを示すために先頭に付ける数バイトの目印）を付けないでください。BOM のあるファイルはエラーになります。`golem fmt` で取り除けます。
- **改行**：改行の文字は LF にします。Windows で使われる CRLF の改行を含むファイルはエラーになります。`golem fmt` で LF に直せます。
- **字下げ**：行頭の字下げは、半角の空白二つを単位にします。タブは使えません。
- **空白**：行末の半角の空白は無視します。全角の空白は、どこにあっても本文の文字として残ります。行末などに半角の空白を残したいときは、`\ ` のように前にバックスラッシュを置きます。
- **異体字**：Golem は文字を置き換えません。CJK 互換漢字のような異体字も、書いたとおりに組みます。漢字の後に異体字セレクタ（IVS）を書くと、PDF ではその字形で組みます。書体がその字形を持たなければ、もとの字の字形になります。

## ブロックの記法

行頭の記号で、そのまとまり（ブロック）の種類が決まります。
ブロックどうしは空行で区切ります。

- **段落**：記号で始まらない行のまとまりです。空行までが一つの段落になります。段落の中の改行は文字を生まず、前後は空白なしでつながります。`manifest.toml` の `[source]` に `paragraph-separator = "line"` と書くと、一行が一つの段落になります（付録B）。
- **行末の `\`**：段落を分けずに、その位置で行を改めます（強制改行）。`\` は行の最後の文字にし、次の行に同じ段落の続きを書きます。見出し、表のセル、角括弧の中には書けません。
- **`# 題`、`## 題`、`### 題`**：見出しです。`#` の数が階層で、三つまで使えます。番号は書かず、`style.toml` の `[headings]` の書式で自動で振ります。見出しの中では、`doc` を使う式と相互参照は使えません。
- **`- 項目`**：箇条書きの項目です。空白二つで字下げすると入れ子になります。項目の中に、字下げした段落やリストを続けられます。
- **`+ 項目`**：番号付きのリストの項目です。番号は 1 から自動で振ります。途中の番号から始めるときは、最初の項目の直前の行に `@number 4` と書きます。
- **`= 用語`**：定義リストの用語です。次の行から空白二つで字下げして説明を書きます。説明には段落、リスト、コードブロックを置けます。`=` の行を続けると、それらの用語が一つの説明を共有します。`=:` の行は、直前の用語のまま二つめの説明を始めます。
- **`| セル | セル |`**：表の行です。一行目が見出しの行、二行目が `|---|` の形の区切りの行です。区切りの行の `:` で、列を左寄せ（`:---`）、中央（`:---:`）、右寄せ（`---:`）にします。どの行も `|` で始めて `|` で終え、セルの数を見出しの行にそろえます。
- **```` ``` ````**：コードブロックの始まりと終わりの行です。始まりの行に言語の名前（`toml` など）を書くと、HTML で構文に応じて色分けします。中ではコマンド、コメント、エスケープを解釈しません。
- **`@名前`**：ブロックコマンドです。行頭の `@` に続けてコマンドの名前を書き、空白で区切って引数を並べます。次の節で一つずつ説明します。

```
# 見出し

段落の一行目。
段落の二行目。

- 箇条書き
  - 入れ子の項目

= 用語
  説明の段落。
```

## ブロックコマンド

ブロックコマンドは、行頭の `@` で始まる一行の指定です。
引数の書き方は、段落の中のコマンドと同じです（この付録の「段落の中のコマンド」）。

- **`@set 名前 = 式`**：変数を定義します。式の書き方は、この付録の「式」のとおりです。同じファイルで同じ名前を二度定義すると、エラーになります。`doc`、`meta`、`true`、`false`、`nil` は名前に使えません。例：`@set price = 1800`
- **`@import パス as 名前`**：別のファイルの `@set` の変数を、名前を付けて取り込みます。取り込んだ変数は `名前.変数` で参照します。`as` と名前は省けません。パスはプロジェクトのディレクトリからの相対パスで書きます。例：`@import common/values.gm as values`
- **`@toc depth=N`**：その位置に目次を組みます。`depth` は目次に載せる見出しの階層で、1 から 3 です。省くと 2 になります。本に一つだけ置けます。
- **`@index`**：その位置に索引を組みます。
- **`@bibliography`**：その位置に、引用した文献の一覧を組みます。
- **`@figure 画像 alt="…"`**：図版を置きます。次の行から空白二つで字下げして、キャプションを書きます。キーワードの引数は次のとおりです。
  - `alt`：代替テキストです。省けません。
  - `web`：PDF の画像を使うときの、HTML と EPUB のための PNG か JPEG の画像です。PDF の画像では省けません。
  - `wrap`：`start` か `end` を書くと、図版を版面の端に寄せ、本文を脇に回り込ませます。PDF だけで効きます。
  - `width`：回り込ませる図版の幅です。`wrap` を書くときは省けません。
- **`@table src=ファイル`**：CSV のファイルから表を作ります。一行目が見出しの行になります。各行のセルの数をそろえます。
- **`@listing ファイル lines=N-M`**：ファイルの中身をコードブロックとして載せます。ファイルは最初の引数に書きます。`src=` でも書けますが、廃止予定なので、お知らせ（G0265）が出ます。`lines` で載せる行の範囲を選べ、省くとファイルの全体を載せます。
- **`@style 名前`**：段落に段落スタイルを付けます。インデントのない次の行に段落を書くと、その段落一つに付きます。次の行から空白二つで字下げして段落を並べると、それらの段落のすべてに付きます。字下げした本体には段落だけを置けます。
- **`@page-break`**：次のページから続けます（改ページ）。`@page-break recto` は次の奇数ページから（改丁）、`@page-break verso` は次の偶数ページから続けます。リストの項目や図版のキャプションの中には書けません。
- **`@column-break`**：段組みの版面で、次の段から続けます（改段）。一段組みの版面では `@page-break` と同じです。
- **`@manifest キー=値`**：そのファイルにだけ効く原稿の読み方を書きます。書けるのは `manifest.toml` の `[source]` のキー（`paragraph-separator`）だけです。例：`@manifest paragraph-separator=line`
- **`@style-def 種類 名前 キー=値…`**：そのファイルにだけ効くスタイルを定義します。種類は `paragraph`（段落スタイル）、`character`（文字スタイル）、`regex`（正規表現スタイル）のどれかです。キーは `style.toml` と同じで、値は `2zw` や `keep` のように引用符なしで書けます。`style.toml` にある名前を書くと、そのファイルの中でだけ、書いたキーが置き換わります。`regex` では、二つ目の語に組を足す段落スタイルの名前を、キーに `pattern` と `style` を書きます。

`@manifest` と `@style-def` は、ファイルの最初に置きます。
前に置けるのは、コメントと空行だけです。
一つのスタイルは一行で定義します。

```
@manifest paragraph-separator=line
@style-def paragraph letter based-on=body indent=2zw
@style-def regex body pattern="\\d+" style=bold
```

`@figure`、`@table`、`@listing` が指すファイルも、プロジェクトのディレクトリからの相対パスで書きます。
絶対パス、URL、プロジェクトの外を指すパスは使えません。

## 見出しやブロックに付ける指定

次のブロックコマンドは、直後のブロックに付く指定（属性）です。
対象のブロックの直前の行に書き、あいだに空行を入れません。
いくつも重ねて書けますが、同じ指定を二度は書けません。

- **`@label 名前`**：ブロックにラベルを付けます。相互参照で、この名前を使います。名前には、英小文字、数字、`-`、`_` を使えます。本の全体で同じ名前は一度しか使えません。見出し、図版、段落などに付けられます。
- **`@nonumber`**：見出しに番号を振りません。この見出しは番号を数えません。
- **`@notoc`**：見出しを目次に載せません。
- **`@toc-title 短い題`**：目次に載せる題を、見出しの題と別にします。
- **`@number N`**：見出しの番号を `N` にします。後の見出しは `N` から続けて数えます。番号付きのリストの最初の項目に付けると、リストを `N` から始めます。
- **`@style 名前`**：上の節の `@style` です。段落にだけ付けられます。

```
@label preface
@nonumber
@notoc
# まえがき
```

## 段落の中のコマンド

段落の中のコマンドは、角括弧で囲んで書きます。
形は次のとおりです。

```
[名前 位置引数 キー=値: 本文 | 本文]
```

- コマンドの名前の後に、空白で区切って引数を並べます。名前のすぐ後に置く引数が位置引数、`キー=値` の形が名前付きの引数（エラーのメッセージではキーワード引数）です。位置引数を先に、名前付きの引数を後に書きます。
- 空白を含む値は `"…"` で囲みます。中の `"` は `\"` と書きます。
- 引数の値に `[= 式]` を書くと、式の値を渡せます。
- `:` の後が、コマンドがかかる本文です。エラーのメッセージでは、この部分を「散文スロット」と呼びます。ルビのように本文を二つ取るコマンドでは、`|` で区切ります。
- 本文の中には、ほかのコマンドを入れられます。

組み込みのコマンドは次のとおりです。

- **`[strong: 語]`**：意味の上での強調です。見た目は `style.toml` の文字スタイル `strong` で決まります。
- **`[bold: 語]`**、**`[italic: 語]`**：太字と斜体です。文字スタイル `bold` と `italic` を付けます。
- **`[style 名前: 語]`**：`style.toml` で定義した文字スタイルを付けます。`[strong: 語]` は `[style strong: 語]` と同じ意味です。
- **`[color 名前: 語]`**：`style.toml` の `[color.swatches]` で名前を付けた色を付けます。
- **`[kenten: 語]`**：圏点を打ちます。`shape=` で形を選べます。形は `sesame`（ゴマ）、`open-sesame`（白ゴマ）、`dot`（小さい黒丸）、`open-dot`（小さい白丸）、`circle`（大きい黒丸）、`open-circle`（大きい白丸）のどれかで、省くと `style.toml` の `[composition]` の `kenten` になります。今の版では、形の指定は HTML と EPUB でだけ効き、PDF では常にゴマで組みます。
- **`[tcy: 文字]`**：縦組みで、短い文字列を横に並べて一字分の幅に組みます（縦中横）。中には文字だけを書けます。
- **`[ruby: 親文字|読み]`**：ルビを振ります。`/` を使わなければグループルビ、親文字と読みを同じ数の `/` で区切ればモノルビです。読みの区切りを空にすると、その文字には読みを振りません。読みには文字だけを書けます。ルビの中にルビは入れられません。今の版では、親文字と読みに `/` という文字そのものは書けません。
- **`[number-text 数]`**：書き方を決めていない数です。横組みでは算用数字に、縦組みでは `style=` か `style.toml` の `[numbers]` で選んだ表記になります。`style=` には `kanji`（十）、`kanji-digits`（一〇）、`tcy`（縦中横の 10）を書けます。整数だけを渡せます。
- **`[note: 注の本文]`**：脚注です。注の本文には段落の中の要素だけを書けます。番号はファイルごとに 1 から振ります。
- **`[sidenote: 傍注の本文]`**：傍注です。横組みの本でだけ使えます。PDF では `style.toml` に `[sidenotes]` が要り、脚注の本文と図版のキャプションの中には置けません。
- **`[aki 量]`**：その位置に、決まった幅の空きを入れます。量は `全角`、`二分`、`三分`、`四分`、`五分`、`六分`、`八分`、`二分四分`、`ベタ` のような名前か、`0.2zw`、`25%`、`1mm` のように書きます。`[aki]` の前後では行を分けません。本文は取りません。
- **`[ref-number ラベル]`**：ラベルを付けた章、節、図の番号になります。番号のない見出しや段落を指すとエラーになります。
- **`[ref-title ラベル]`**：ラベルを付けた見出しの題か、図版の代替テキストになります。段落や表のような題のない箇所を指すとエラーになります。
- **`[ref-page ラベル]`**：PDF では、ラベルを付けた箇所のページ番号になります。HTML と EPUB では、その箇所へのリンクになります。相互参照の三つのコマンドには、`:` の後の本文を書けません。
- **`[index reading=読み: 語]`**：索引の項目の印です。紙面には何も出しません。`reading` は省けません。`語/副項目` と `よみ/ふくこうもく` のように `/` で区切ると、二段の項目になります。語と読みには文字だけを書けます。
- **`[cite キー]`**：文献を引用します。キーは、`manifest.toml` の `bibliography` に並べたファイルの `id` です。

プラグインのコマンドも、同じ形で呼び出します（「プラグイン」の章）。

```
[ruby: 東/京|とう/きょう]の[kenten shape=dot: 下町]。[note: 注]
図[ref-number fig-new]は[ref-page fig-new]ページにあります。
```

PDF と HTML の版では、この例の一行めのうち、ルビと圏点を次の段落で実際に組んでいます。

> 東京（とうきょう）の下町。

## 式

`[= 式]` と書くと、式の値を本文に埋め込みます。
本文に埋め込めるのは、数と文字列の値です。

- **数**：`1800`、`-3`、`2.5` のように書きます。整数と小数を区別し、整数はいくら大きくても正確に計算します。
- **文字列**：`"第2版"` のように `"` で囲みます。中の `"` は `\"`、`\` は `\\` と書きます。
- **真偽値と空の値**：正しいか誤りかを表す真偽値の `true` と `false`、値がないことを表す `nil` です。本文には埋め込めません。
- **配列と連想配列**：値の並び（配列）は `[1, 2, 3]`、名前と値の組の集まり（連想配列）は `{price: 1800, tax: 10}` のように書きます。本文には埋め込めません。
- **名前**：`@set` の変数は名前で、`@import` で取り込んだ変数は `名前.変数` で参照します。`pi` と `e` は円周率と自然対数の底です。
- **本の情報**：`meta.title`、`meta.date`、`meta.id`、`meta.language` と、書いてあれば `meta.edition`、`meta.publisher`、`meta.title_reading` で、`manifest.toml` の `[metadata]` の値を参照します。
- **本の構成**：`doc.chapters.count` は本の章の数です。見出しの中では使えません。
- **演算子**：`+`、`-`、`*`、`/`、`**`（べき乗）、`%`（剰余）と、比べる演算子の `==`、`!=`、`<`、`<=`、`>`、`>=` です。比べた結果は真偽値です。文字列どうしも比べられます。丸括弧で計算の順を変えられます。
- **関数**：`round(x, 桁数)`（四捨五入）、`fixed(x, 桁数)`（小数点以下の桁をそろえた文字列）、`floor`（切り捨て）、`ceil`（切り上げ）、`abs`（絶対値）、`min`、`max`、`sqrt`（平方根）、`len`（文字列の字数か配列の要素の数）、`div(a, b)`（整数の割り算）です。

計算の規則は、どの機械で組んでも同じ結果になるように決めています。

- `/` の結果は常に小数です。整数の割り算には `div` を使います。`div` と `%` は整数にだけ使えます。
- `**` の指数は整数に限ります。
- 0 で割る計算や、負の数の平方根はエラーになります。
- `round` は十進数として四捨五入します。`round(2.675, 2)` は 2.68 です。`round(x)`、`floor`、`ceil` は整数を返します。
- 小数を本文に埋め込むときは、指数を使わず位取りで書き、桁区切りを付けません。整数になる小数は小数点を付けません（`[= 10 / 2]` は「5」）。

```
@set price = 1800

税込み[= fixed(price * 1.1, 0)]円、全[= doc.chapters.count]章。
```

PDF と HTML の版では、この例も次の段落で実際に組んでいます。

> 税込みで1980円、本書は全9章です。

## コメントとエスケープ

- **`%% … %%`**：コメントです。出力されません。空行を越えられません。
- **`%%= … %%`**：校正のためのコメントです。`--profile dev` では紙面に出て、`--profile prod` では出力から落とし、残っていると警告になります。
- **`\`**：後ろの一文字を、記法の文字ではなく本文の文字にします。

バックスラッシュが要るのは、次の文字です。

- 本文の `[`（`\[`）。
- 角括弧の中の本文の `]` と `|`（`\]`、`\|`）。
- 段落の行頭の `#`、`-`、`+`、`=`、`@`、`|`（`\#` など）。
- 本文の `%%`（`\%%`）。
- `\` そのもの（`\\`）。行末の `\` は強制改行になるので、本文の `\` を行末に置くときも `\\` と書きます。
- 行末に残したい半角の空白（`\ `）。

`%` が一つだけなら、そのまま書けます。

`[!` で始まる書き方は、将来のために取ってあり、今は使えません。

# 付録B manifest.toml のリファレンス

この付録は、`manifest.toml` に書けるキーをすべて並べたものです。
書き方の流れは「プロジェクトの設定」の章で説明しています。
ここに載せていないキーを書くと、エラーになります。

表の説明の括弧の中には、値の種類と、省けないキー（必須）を示します。
値の種類は、次のように呼びます。

- **文字列**：`"…"` で囲んだ値です。
- **日付**：`2026-10-13` のように、引用符を付けずに書く日付です。
- **配列**：`[ … ]` で囲んで、カンマで区切った値の並びです。
- **表**：`[名前]` の見出しで始める、キーのまとまりです。

## 全体

ファイルの先頭（どの `[ ]` の見出しよりも前）に書くキーと、ファイルの中の表です。

| キー | 意味 |
|:---|:---|
| `chapters` | 原稿のファイルを本の順に並べます（配列、必須）。 |
| `bibliography` | 文献のデータ（CSL-JSON）のファイルです（文字列の配列）。省くと文献を引用できません。 |
| `[metadata]` | 書名などの本の情報です（表、必須）。 |
| `[targets]` | 出力の形式ごとの設定です。 |
| `[plugins.名前]` | 使うプラグインの宣言です（表）。 |
| `[[filters]]` | フィルタのプラグインを当てるファイルです（表の並び）。 |
| `[source]` | 原稿の読み方です（表）。 |

`chapters` の要素には、ファイルのパスを書きます。
パスはプロジェクトのディレクトリからの相対パスで、プロジェクトの外や、`/` で始まる絶対パス、URL は書けません。
要素を配列にすると、いくつかのファイルを一つの章として続けて組みます。
要素を `{ file = "chapters/02.gm", paragraph-separator = "blank-line" }` のような表にすると、その章だけ原稿の読み方を変えられます。
表に書けるのは、`file`（必須）と、`[source]` と同じキーと、`master` です。
`master` には、その章で使う `style.toml` のマスターページの名前を書きます（付録C の `[masters.名前]`）。
書かなければ `body` のマスターページを使います。
同じファイルを、読み方を変えて二度並べることはできません。

```toml
chapters = [
  "front.gm",
  ["chapters/01-a.gm", "chapters/01-b.gm"],
  "back.gm",
]
```

## `[metadata]`

本の情報です。
ここに書いた値は、PDF、EPUB、HTML の決まった場所に書き込まれ、原稿からは `[= meta.title]` のように参照できます。

| キー | 意味 |
|:---|:---|
| `id` | 本の識別子です（文字列、必須）。`golem new` が `urn:uuid:` で始まる値を作ります。一度決めたら変えません。PDF のファイルの名前にも使います。 |
| `title` | 書名です（文字列、必須）。 |
| `title-reading` | 書名の読みです（文字列）。電子書店での並べ替えに使われます。 |
| `language` | 本の言語です（文字列、必須）。日本語は `"ja"`、英語は `"en"` です。 |
| `date` | 発行日です（日付、必須）。PDF の作成日などに書き込みます。 |
| `edition` | 版です（文字列）。 |
| `publisher` | 発行者です（文字列）。 |
| `[[metadata.creators]]` | 著者などの関係者です（表の並び）。一人ごとに一つ書きます。 |

`[[metadata.creators]]` のキーは次のとおりです。

| キー | 意味 |
|:---|:---|
| `name` | 名前です（文字列、必須）。 |
| `reading` | 名前の読みです（文字列）。 |
| `role` | 役割の符号です（文字列、必須）。著者は `"aut"`、編者は `"edt"`、訳者は `"trl"` のように、EPUB と同じ符号を書きます。 |

## `[targets]`

出力の形式ごとの設定です。
形式の表は中身が空でもかまいません。
`[targets]` を書くときは、少なくとも一つの形式を置きます。

| キー | 意味 |
|:---|:---|
| `[targets.pdf]` | PDF の設定です。`isbn` に紙の本の ISBN を書けます。 |
| `[targets.epub]` | EPUB の設定です。`isbn` に電子版の ISBN を書けます。書けば EPUB の識別子に使います。 |
| `[targets.html]` | HTML の設定です。書けるキーはありません。 |
| `[targets.text]` | プレーンテキストの設定です。`variants` に `"vertical"`（縦書き用）と `"horizontal"`（横書き用）の一方か両方を並べます。省くと両方を作ります。 |

`golem build` は、`--target` を指定しなければ、この表にかかわらず四つの形式をすべて作ります。

## `[source]`

原稿の読み方です。
章の項目に同じキーを書くと、その章ではそちらが優先します。
原稿のファイルの先頭に `@manifest paragraph-separator=line` と書くと、そのファイルではそれがいちばん優先します（付録A の「ブロックコマンド」）。
`@import` でだけ取り込むファイルには、`[source]` の値が効きます。

| キー | 意味 |
|:---|:---|
| `paragraph-separator` | 段落の区切り方です（文字列）。`"blank-line"` は空行で段落を区切り、`"line"` は改行ひとつで区切って一行を一つの段落にします。省くと `"blank-line"` です。 |

## `[diagnostics]`

診断の扱いです。

| キー | 意味 |
|:---|:---|
| `silence-notices` | 出さないお知らせのコードです（文字列の配列）。お知らせのコードだけを書けます（「検査とエラー」の章の「お知らせ」）。省くと、すべてのお知らせを出します。 |

## `[plugins.名前]`

使うプラグインを、名前を付けて宣言します。
名前は、原稿や `[[filters]]` からプラグインを指すのに使います。

| キー | 意味 |
|:---|:---|
| `url` | 配布物の URL です（文字列、必須）。`https://` で始め、版を固定した URL を書きます。 |
| `overrides` | このプラグインで置き換える組み込みのコマンドの名前です（文字列の配列）。 |

`overrides` に書けるのは、`strong`、`bold`、`italic`、`ruby`、`kenten`、`color`、`style`、`tcy`、`number-text` です。

## `[[filters]]`

フィルタを当てるファイルを、当てる順に書きます。

| キー | 意味 |
|:---|:---|
| `plugin` | `[plugins.名前]` で宣言したプラグインの名前です（文字列、必須）。 |
| `filter` | そのプラグインのフィルタの名前です（文字列、必須）。 |
| `files` | フィルタを当てる原稿のファイルです（文字列の配列、必須）。 |

# 付録C style.toml のリファレンス

この付録は、`style.toml` に書ける表とキーをすべて並べたものです。
書き方の流れは「スタイルの設定」の章で説明しています。
ここに載せていないキーを書くと、エラーになります。
表の「既定」の欄と、説明の中の「既定は」は、キーを省いたときの値です。
「なし」は、省いてもよく、省くとその機能を使わないことを表します。

## 寸法と番号の書式

| 単位 | 意味 |
|:---|:---|
| `mm` | ミリメートルです。 |
| `pt` | ポイントです。1in の 72 分の 1 です。 |
| `Q` | 級です。0.25mm です。文字の大きさに使います。 |
| `H` | 歯です。0.25mm です。行送りに使います。 |
| `zw` | 全角一字分です。その場所の文字の大きさを一字とします。 |

| 差し込み | 意味 |
|:---|:---|
| `{n}` | その見出しや図の番号、ノンブルではページ番号です。 |

## `[page]`

判型と組み方向です。
PDF を作るには必須です。
HTML と EPUB は `writing-mode` だけを使います。

| キー | 既定 | 意味 |
|:---|:---|:---|
| `size` | （必須） | 判型です。`"A4"`、`"A5"`、`"A6"`、`"B5"`、`"B6"`、`"四六判"`、`"菊判"`、`"新書判"`、`"mass-market"` のどれかか、`{ width = "148mm", height = "210mm" }` のように幅と高さで書きます。幅と高さに `zw` は使えません。 |
| `binding` | `"left"` | 綴じる側です。`"right"`（右綴じ）か `"left"`（左綴じ）です。 |
| `writing-mode` | `"horizontal"` | `"vertical"`（縦組み）か `"horizontal"`（横組み）です。 |
| `bleed` | `"0mm"` | 塗り足しの幅です。`zw` は使えません。 |

## `[page.grid]`

版面です。
PDF を作るには必須です。
`columns` と `column-gap` のほかのキーも必須です。

| キー | 意味 |
|:---|:---|
| `font-size` | 本文の文字の大きさです。`zw` は使えません。 |
| `characters` | 一行の字数です。段組みでは一段の字数です。 |
| `lines` | 一ページの行数です。段組みでは一段の行数です。 |
| `columns` | 段数です。省くと 1 段です。2 以上にすると段組みになり、傍注と図版の回り込みは使えなくなります。 |
| `column-gap` | 段と段のあいだの空き（段間）です。`columns` が 2 以上なら必須です。 |
| `line-pitch` | 行送りです。文字の大きさ以上にします。 |
| `position` | 版面の位置です。`{ top = "22mm", gutter = "14mm" }` のように、天からの距離（`top`）とノドからの距離（`gutter`）を書きます。 |

## `[fonts.役割]`

書体を、役割の名前を付けて指定します。
役割の名前は自由ですが、`body` は本文の書体で、PDF を作るには必須です。
書体のファイルはプロジェクトの中に置き、プロジェクトのディレクトリからの相対パスで書きます。

| キー | 意味 |
|:---|:---|
| `ja` | 和文の書体のファイルです。 |
| `latin` | 欧文の書体のファイルです。 |
| `features` | OpenType の機能の名前の配列です。たとえば `["palt"]` で、和文の約物や仮名を詰めて組みます。省くと、書体の標準の機能だけを使います。 |

## `[character-styles.名前]`

文字スタイルです。
名前は英小文字で始め、英小文字、数字、`-` だけで付けます。
`bold`、`italic`、`strong`、`code` ははじめから定義されていて、同じ名前で書くと、書いたキーだけが置き換わります。

| キー | 既定 | 意味 |
|:---|:---|:---|
| `based-on` | なし | 引き継ぐ文字スタイルの名前です。書かなかったキーは、引き継いだスタイルの値になります。 |
| `font` | なし | 書体の役割の名前です。その役割が持つ側（和文か欧文）の文字だけを、その書体で組みます。 |
| `size` | なし | 文字の大きさです。PDF でだけ効きます。 |
| `color` | なし | `[color.swatches]` で付けた色の名前です。 |
| `synthetic-bold` | `false` | `true` にすると、書体の輪郭を太らせて太字にします。 |
| `synthetic-italic` | `false` | `true` にすると、字形を傾けて斜体にします。 |

文字の送りを決める次の四つのキーも書けます。
文字スタイルで書かなかったキーは、外側の文字の値のままです。

| キー | 既定 | 意味 |
|:---|:---|:---|
| `kerning` | `"metrics"` | カーニング（字の組ごとの字間の調整）の方式です。`"metrics"` は書体のペアカーニングの情報で調整し、`japanese-equal-width` は欧文だけを調整し、`"none"` は調整しません。`"optical"` はまだ使えません。 |
| `tracking` | `0` | 文字ごとに足す空きです。文字の大きさの 1000 分の 1 を単位に、-1000 から 10000 までの整数で書きます。 |
| `proportional-metrics` | `false` | `true` にすると、和文を字面に合わせた送りで組みます。 |
| `baseline-shift` | `"0pt"` | 文字を、横組みでは上へ、縦組みでは右へずらす量です。`"-0.25zw"` のように負の値も書けます。 |

組み込みの文字スタイルは、`bold` が `synthetic-bold = true`、`italic` が `synthetic-italic = true`、`strong` が `based-on = "bold"`、`code` が `font = "code"` です。
`code` と、`based-on` で `code` を引き継ぐ文字スタイルの文字は、PDF で語の途中で分けず、空白と `/` の後でだけ行を改めます。

## `[paragraph-styles.名前]`

段落スタイルです。
名前の付け方は文字スタイルと同じです。
`body`、`verse`、`caption`、`sidenote`、`code` ははじめから定義されていて、同じ名前で書くと、書いたキーだけが置き換わります。

| キー | 意味 |
|:---|:---|
| `based-on` | 引き継ぐ段落スタイルの名前です。`body` には書けません。既定は `"body"` です。 |
| `font` | 書体の役割の名前です。 |
| `size` | 文字の大きさです。本文の文字の大きさまでにします。 |
| `indent` | すべての行の始まりの字下げです。既定は `"0zw"` です。 |
| `first-line-indent` | 最初の行に `indent` へ加える字下げです。負の値はぶら下げになります。`indent` との和は 0 以上にします。既定は `"0zw"` です。 |
| `line-breaks` | `"keep"` にすると、段落の中の改行を行の区切りにします。既定は `"join"` です。 |
| `space-between` | 同じ段落スタイルの段落が続くときに、あいだに空ける行の数です。既定は `0` です。 |
| `aki-set` | 字間の空きを決めるアキ量のセットの名前です。`[aki-sets.名前]` で定義したものか、組み込みのセットを書きます。書かなければ `body` と同じセットです。 |
| `regex-styles` | 正規表現に一致した文字に文字スタイルを当てる組の配列です。`{ pattern = '[0-9]+', style = "bold" }` のように書きます。既定は `[]` です。 |

段落スタイルには、文字スタイルと同じ `kerning`、`tracking`、`proportional-metrics`、`baseline-shift` も書けます。
`[paragraph-styles.body]` に書くと、本の全体の既定になります。
`aki-set` は `body` から引き継ぐので、`body` に書けば本の全体が変わります。
`body` で書かなければ、組み込みのセット `gyomatsu-yakumono-hankaku` になります。

`regex-styles` の組は、`pattern`（正規表現）と `style`（文字スタイルの名前）を持ちます。
同じ文字に二つの組が一致したときは、後の組が勝ちます。
原稿で付けた文字スタイルは、正規表現スタイルより優先されます。
正規表現は `'…'` で囲むと、`\` をそのまま書けます。
後方参照、`\p{Han}` のような文字の種類の指定、長さの決まらない後読みは使えません。

組み込みの段落スタイルの値は次のとおりです。

- `body`：本文です。ほかの段落スタイルの既定の引き継ぎ先です。
- `verse`：韻文です。`line-breaks = "keep"`、`space-between = 1`、`indent = "2zw"`、`first-line-indent = "-2zw"` です。
- `caption`：図版のキャプションです。キャプションには `font` と `size` だけが効きます。
- `sidenote`：傍注の本文です。傍注には `font` と `size` だけが効きます。
- `code`：コードブロックです。`font = "code"`、`padding = "0.5zw"` です。

段落スタイル `code` に書けるキーは、次の四つだけです。
`based-on` は書けず、ほかの段落スタイルの `based-on` にも書けません。
原稿の `@style code` もエラーです。

| キー | 既定 | 意味 |
|:---|:---|:---|
| `font` | `"code"` | 書体の役割の名前です。 |
| `size` | 本文の大きさ | 文字の大きさです。本文の文字の大きさまでにします。 |
| `background` | なし | 背景の色の名前です。`[color.swatches]` で付けた名前を書きます。書かなければ背景を塗りません。 |
| `padding` | `"0.5zw"` | 背景の内側の余白です。`zw` はコードの文字の大きさを一字とします。上下と左右に同じ量を取ります。 |

コードブロックは、行と上下の余白を収める行数を占め、その中の中央に組みます。
後の本文は、行の格子からずれません。
`background` と `padding` は、`code` のほかの段落スタイルには書けません。

## `[aki-sets.名前]`

和文の字間の空き（アキ）の量を、文字の組み合わせごとに決めるセットです。
InDesign の文字組みアキ量設定に当たります。
段落スタイルの `aki-set` で選びます。
PDF でだけ効きます。

組み込みのセットは二つあります。
`gyomatsu-yakumono-hankaku`（行末約物半角）が既定で、和欧間は四分、括弧と句読点は二分の空きを持ち、行末の括弧と句読点は半角にします。
`gyomatsu-yakumono-zenkaku`（行末約物全角）は、行末の括弧と句読点の後ろにも二分を残します。
組み込みのセットと同じ名前のセットは定義できません。

| キー | 意味 |
|:---|:---|
| `based-on` | 基準にするセットの名前です。書かなければ `gyomatsu-yakumono-hankaku` です。 |
| `rules` | 基準のセットに足す規則の配列です。後に書いた規則が、同じ組み合わせの前の規則を上書きします。既定は `[]` です。 |

規則には、次のキーを書きます。

| キー | 意味 |
|:---|:---|
| `before` | 前の文字のクラスです（必須）。クラスの名前か、その配列で書きます。 |
| `after` | 後ろの文字のクラスです（必須）。書き方は `before` と同じです。 |
| `optimum` | 空きの最適の量です（必須）。 |
| `minimum` | 空きの最小の量です。省くと `optimum` と同じです。 |
| `maximum` | 空きの最大の量です。省くと `optimum` と同じです。 |

量は、`"四分"` のような名前（`ベタ`、`全角`、`二分`、`三分`、`四分`、`五分`、`六分`、`八分`、`二分四分`）か、`"0.25zw"` か、`"25%"` で書きます。
`minimum`、`optimum`、`maximum` の順に小さくない値にします。

クラスの名前は次のとおりです。

- `opening`：始め括弧類です。
- `closing`：終わり括弧類です。
- `hyphen`：ハイフン類です。
- `dividing`：区切り約物（？や！）です。
- `middle-dot`：中点類です。
- `full-stop`：句点類です。
- `comma`：読点類です。
- `inseparable`：分離禁止文字（…や‥）です。
- `iteration`：繰返し記号です。
- `prolonged-sound`：長音記号です。
- `small-kana`：小書きの仮名です。
- `ideographic-space`：全角の空白です。
- `kana`：平仮名と片仮名です。
- `ideograph`：漢字などです。
- `western`：欧文です。
- `japanese`：欧文のほかのすべてです。
- `paragraph-start`、`line-start`：段落の最初と、行頭です。`before` にだけ書けます。
- `line-end`：行末です。`after` にだけ書けます。

## `[masters.名前]`

柱とノンブルを置くマスターページです。
PDF でだけ効きます。
章は `body` という名前のマスターページを使い、`manifest.toml` の章の項目の `master` で別のものを選べます。

| キー | 意味 |
|:---|:---|
| `running-head` | 柱です。`{ position = "top-outside", content = "heading.1.short" }` のように、位置と内容を書きます。左右のページで変えるときは、`content` の代わりに `even`（偶数ページ）と `odd`（奇数ページ）の両方を書きます。書かなければ柱を組みません。 |
| `folio` | ノンブルです。`{ position = "bottom-outside", format = "{n}" }` のように、位置と書式を書きます。書かなければノンブルを組みません。 |

位置には、`"top-outside"`、`"top-center"`、`"top-inside"`、`"bottom-outside"`、`"bottom-center"`、`"bottom-inside"` のどれかを書きます。
`top` は天、`bottom` は地、`outside` は小口の側、`inside` はノドの側、`center` は中央です。

柱の内容には、次のどれかを書きます。
`<階層>` には見出しの階層の数を書きます。

- `"heading.<階層>.short"`：その階層の見出しの題です。`@toc-title` があれば、その短い題です。ページの中で始まった最初の見出しを使い、なければ前から続く見出しを使います。
- `"heading.<階層>.numbered"`：番号と題を並べたものです（「第3章　原稿の記法」など）。
- `"heading.<階層>.short.last"`、`"heading.<階層>.numbered.last"`：ページの中で始まった最後の見出しを使います。
- `"title"`：書名です。
- `"none"`：柱を出しません。

章の始まりのページと白ページには、柱を出しません。

# 付録D エラーと警告の一覧

この付録は、Golem が出すエラーと警告を、コードの順ではなく、原因の種類ごとにまとめたものです。
各項目は、コード、表示されるメッセージ、意味と直し方の順に並べています。
メッセージの `…` の部分には、名前やファイルのパスが入ります。
エラーと警告の読み方は「検査とエラー」の章で説明しています。
同じ説明は、`golem explain G0215` のように、コマンドでも表示できます。

ほとんどはエラーで、一つでもあれば出力を書きません。
警告になるものは、項目の中にそう書いています。
G0310 と G0504 は、`--profile dev` では警告、`--profile prod` ではエラーです。
お知らせは最後の節にまとめています。
この付録にない番号は、今の版の Golem では出ません。

## ファイルの文字コードと改行

- **G0101 `UTF-8 として不正なバイト列があります`**：原稿のファイル、`manifest.toml`、`style.toml` のどれかが UTF-8 で保存されていません。Shift_JIS などで保存したファイルで起きます。テキストエディタで文字コードに UTF-8 を選んで保存し直してください。
- **G0102 `ファイルの先頭に BOM があります。BOM を取り除いてください`**：ファイルの先頭に BOM（文字コードを示す目印）が付いています。BOM なしの UTF-8 で保存し直すか、`golem fmt` を実行してください。
- **G0103 `改行に CR が含まれています。改行は LF に限ります`**：Windows の形式の改行（CRLF）で保存されています。`golem fmt` を実行すると直ります。

## 原稿の書き方（行頭の記号と字下げ）

- **G0110 `このブロックを解釈できません`**：行頭の記号で始まる行が、どの書き方にも当てはまりません。付録A の「ブロックの記法」と見比べてください。本文の段落を `#` や `-` で始めたいときは、`\#` のように前に `\` を置きます。
- **G0111 `インデントが不正です（タブ、またはブロックの深さより多い空白）`**：行頭の字下げにタブがあるか、半角の空白が多すぎます。字下げは半角の空白二つを単位にしてください。
- **G0112 `見出しの階層は 3 までです`**：`####` 以上の見出しがあります。見出しは `###` までにしてください。
- **G0113 `用語のない =: があります`**：定義リストの `=:` の前に、`= 用語` の行がありません。
- **G0114 `表の 2 行目は区切りの行でなければなりません`**：表の見出しの行の次に、`|---|---|` の形の区切りの行を書いてください。
- **G0115 `表のセルの数が見出しの行と一致しません`**：表の行のセルの数が、見出しの行と違います。空のセルも `| |` と書き、`|` の数をそろえてください。
- **G0123 `表の行は | で始まり | で終わります`**：表の行の両端に `|` を書いてください。
- **G0116 `コードブロックが閉じていません`**：```` ``` ```` で始めたコードブロックに、終わりの ```` ``` ```` の行がありません。
- **G0122 `解釈できない入力が残っています`**：前にある書き間違いに引きずられて出ることが多いエラーです。先に出たほかのエラーから直してください。
- **G0129 `構文エラー（…）`**：ほかのコードに当てはまらない書き間違いです。示された位置の書き方を、付録A と見比べてください。
- **G0124 `行末の \ は段落の中の強制改行です。次の行に段落の続きが要ります。本文の \ は \\ と書きます`**：行末の `\`（強制改行）の次の行が、同じ段落の続きではありません。段落の最後の行の `\` を消してください。見出し、定義リストの用語、表のセルには強制改行を書けません。
- **G0257 `強制改行の前後に文字がありません`**：強制改行で、中身のない行ができます。`\` だけの行と、その前の `\` を消してください。行のあいだの空きは、強制改行では作れません。

## 角括弧とコマンドの書き方

- **G0117 `ここに閉じ括弧 ] が必要です`**：`[` に対応する `]` がありません。`]` を書き忘れているか、本文の `]` で早く閉じています。本文の `]` は `\]` と書きます。
- **G0121 `[ の後にはコマンド名か = が必要です。本文の [ は \[ と書きます`**：本文に `[` を書くときは、`\[` と書いてください。
- **G0118 `コメントが段落の中で閉じていません`**：`%%` で始めたコメントを、同じ段落の中で `%%` で閉じてください。本文に `%%` を書くときは `\%%` とします。
- **G0119 `キーワード引数の後に位置引数があります`**：コマンドの引数で、`キー=値` の後に、名前の付かない引数があります。名前の付かない引数を先に並べてください。
- **G0222 `未知のコマンドです: …`**：その名前のコマンドがありません。綴りを確かめてください。プラグインのコマンドなら、`manifest.toml` にプラグインを宣言してください。
- **G0238 `… には散文スロットが一つ必要です`**、**`… は散文スロットを取りません`** など：コマンドの `:` の後の本文（散文スロット）の数が違います。ルビは `[ruby: 親文字|読み]` のように、`|` で区切って二つ書きます。相互参照のコマンドには `:` の後の本文を書けません。
- **G0256 `強制改行は段落の中にだけ書けます。コマンドの中では使えません`**：角括弧の中で行末に `\` を書いています。行をまたいで斜体などを続けたいときは、行ごとにコマンドを閉じて開き直し、`\` を角括弧の外に書いてください。
- **G0255 `aki には量を一つ書きます`** など：`[aki 量]` の書き方が違います。`[aki 四分]`、`[aki 0.2zw]`、`[aki 25%]`、`[aki 1mm]` のように、量を一つだけ書いてください。
- **G0215 `モノルビの対象と読みのセグメントの数が一致しません`**：`/` で区切ったルビの、親文字の区切りと読みの区切りの数が違います。親文字を区切らずに読みだけを区切った場合も出ます。`[ruby: 東/京|とう/きょう]` のように、`/` の数をそろえてください。
- **G0216 `ルビの中にルビは入れられません`**：ルビの親文字の中に、別のルビがあります。
- **G0243 `ルビの読みは地の文に限ります`**：ルビの読みに、コマンドが入っています。読みには文字だけを書いてください。
- **G0239 `未知の圏点の形です: …`**：`[kenten ...]` の `shape` の値が違います。付録A の形の名前から選んでください。
- **G0240 `縦中横の中身は地の文に限ります`**：`[tcy: ...]` の中に、コマンドが入っています。文字だけを書いてください。
- **G0217 `style.toml にないスウォッチです: …`**、**`color にはスウォッチの名前を一つ書きます`**：`[color ...]` の色の名前が、`style.toml` の `[color.swatches]` にありません。色を定義するか、名前の綴りを直してください。
- **G0218 `定義されていない文字スタイルです: …`**、**`style には文字スタイルの名前を一つ書きます`**：`[style ...]` の文字スタイルが定義されていません。`style.toml` に `[character-styles.名前]` を書くか、ファイルの先頭に `@style-def character` で定義するか、名前の綴りを直してください。
- **G0219 `number-text に渡せるのは整数だけです`** など：`[number-text ...]` の引数が違います。整数を一つ渡し、`style` には `kanji`、`kanji-digits`、`tcy` のどれかを書いてください。
- **G0220 `索引には reading が必要です`**：`[index reading=読み: 語]` のように、読みを書いてください。
- **G0241 `索引の語は地の文に限ります`**：索引の語に、コマンドが入っています。文字だけを書いてください。
- **G0242 `索引の語と読みの段の数が不正です`**：`/` で区切った索引の段が三つ以上あるか、語と読みで `/` の数が違うか、空の段があります。段は二つまでにし、語と読みの `/` の数をそろえてください。
- **G0221 `書誌データにないキーです: …`**：`[cite ...]` のキーが、文献のデータにありません。データの `id` と綴りを見比べてください。
- **G0214 `見出しの中では相互参照を使えません`**、**`見出しの中では doc を参照できません`**：見出しの中に、`[ref-number ...]` などの相互参照か、`doc` を使う式があります。見出しの外の本文に移してください。

## 式と変数

- **G0120 `式を解釈できません`**：`[= ...]` の中の式の書き方が違います。演算子や括弧の対応を確かめてください。
- **G0201** 型の誤りのメッセージ：式で、使えない種類の値を計算しています。たとえば文字列と数を足しているか、小数に `div` や `%` を使っています。値の種類をそろえてください。
- **G0202 `未定義の名前 … です`**、**`未定義の名前空間 … です`**：定義していない変数か、取り込んでいない名前を使っています。`@set` と `@import` を書いたか、綴りが合っているかを確かめてください。
- **G0203 `0 で割っています`**：割る数が 0 になる計算です。
- **G0204 `結果が NaN か無限大になる演算です`**、**`負の数の平方根です`**：計算の結果が数になりません。値の範囲を確かめてください。
- **G0206 `** の指数は整数に限ります`**：`**` の右に小数を書いています。指数は整数にしてください。平方根には `sqrt` を使います。
- **G0207 `… の引数が不正です`**：関数に渡した引数の数か種類が違います。
- **G0261 `未定義の関数 … です`**：その名前の関数はありません。使える関数は付録A の「式」にあります。
- **G0208 `… は本文に埋め込めません`**：配列や真偽値のように、本文に埋め込めない値です。埋め込めるのは数と文字列です。
- **G0223 `予約語は変数の名前に使えません: …`**、**`予約語は名前空間に使えません: …`**：`doc`、`meta`、`true`、`false`、`nil` は、変数や `@import` の名前に使えません。
- **G0224 `変数を二度定義しています: …`**：同じファイルで、同じ名前の変数を二度 `@set` しています。
- **G0309 `@import は「@import パス as 名前空間」の形で書きます`**：`@import common/values.gm as values` のように書いてください。
- **G0305 `import が循環しています: …`**：`@import` でファイルどうしが互いを取り込んでいます。共通の変数を別のファイルに移してください。

## ブロックコマンドと属性

- **G0209 `未知のブロックコマンドです: @…`**：その名前のブロックコマンドがありません。綴りを確かめてください。
- **G0210 `属性の後にブロックがありません`**：`@label` や `@nonumber` などの次の行に、対象のブロックがありません。あいだの空行を消すか、対象を書いてください。
- **G0211 `属性のまとまりに属性でないコマンドがあります`**：続けて書いた指定の行に、`@toc` のような指定でないコマンドが混ざっています。あいだに空行を入れてください。
- **G0212 `同じ属性を二度書いています`**：一つのブロックに、同じ指定を二度付けています。
- **G0213 `@… はこのブロックには付けられません`**：その種類のブロックに付けられない指定です。たとえば `@notoc` は見出しに、`@style` は段落にだけ付けられます。図版のキャプションの見た目は、`style.toml` の `[paragraph-styles.caption]` で決めます。
- **G0225 `@toc の depth は 1 から 3 の整数です`**：`depth` を 1 から 3 の整数にしてください。
- **G0226 `@label にはラベルの名前を一つ書きます`**、**`参照にはラベルの名前を一つ書きます`**：ラベルの名前は、英小文字、数字、`-`、`_` で一つだけ書きます。
- **G0227 `@number には整数を一つ書きます`**：`@number 5` のように、整数を一つ書いてください。
- **G0228 `図版には alt の代替テキストが必要です`**：`@figure` に `alt="…"` を書いてください。
- **G0229 `PDF の図版には web の代替画像が必要です`**：PDF の画像を使うときは、`web=` で HTML と EPUB のための PNG か JPEG の画像を指定してください。
- **G0230 `wrap は start か end です: …`**：`wrap=start` か `wrap=end` にしてください。
- **G0231 `回り込む図版には width が必要です`**：`wrap` を書いた図版に、`width=` で幅を書いてください。
- **G0232 `@figure には画像のパスを一つ書きます`**：`@figure` の後に、画像のパスを一つだけ書いてください。
- **G0233 `ファイルがありません: …`**：`@figure`、`@table`、`@listing` が指すファイルがありません。パスはプロジェクトのディレクトリから書きます。綴りと置き場所を確かめてください。
- **G0234 `@table には src が必要です`**：`src=` で CSV のファイルを指定してください。
- **G0235 `CSV が空です`**、**`CSV の行ごとのセルの数が一致しません`**：CSV のファイルの各行の列の数を、一行目にそろえてください。
- **G0236 `@listing にはファイルのパスが必要です`**：最初の引数に、載せるファイルのパスを書いてください。
- **G0237 `lines の範囲が不正です: …`**：`lines=3-10` のように、1 からファイルの行数までの範囲を書いてください。
- **G0245 `@style の本体には段落だけを置けます。段落は空行で区切ります`**：字下げした `@style` の本体に、箇条書きなどの段落でないものがあります。
- **G0246 `@style の本体に段落がありません`**：本体の段落を、`@style` の行より空白二つ深く字下げして書いてください。
- **G0247 `定義されていない段落スタイルです: …`**：`style.toml` に `[paragraph-styles.名前]` を書くか、ファイルの先頭に `@style-def paragraph` で定義するか、名前の綴りを直してください。
- **G0266 `code はコードブロックの段落スタイルです。コードは ``` か @listing で書きます`**：`@style code` は書けません。コードは ```` ``` ```` で囲むか `@listing` で載せ、本文の中のコードは `[code: ...]` で書いてください。
- **G0258 `@page-break の引数は recto か verso です`** など：`@page-break` には何も書かないか、`recto` か `verso` を一つだけ書きます。`@column-break` は引数を取りません。次の行を字下げしているなら、字下げをやめてください。
- **G0259 `@page-break と @column-break は文書の最上位にだけ置けます`**：リストの項目や図版のキャプションの中に改ページを書いています。字下げをやめて、リストや図版の前か後ろに書いてください。
- **G0260 `絶対パスは使えません: …`** など：`@figure`、`@table`、`@listing` のパスが、絶対パス、URL、プロジェクトの外のどれかを指しています。ファイルをプロジェクトの中に置き、そこからの相対パスで書いてください。

## ファイルの中の設定（`@manifest` と `@style-def`）

- **G0249 `@manifest と @style-def はファイルの最初に置きます`**：`@manifest` と `@style-def` をファイルの先頭に集めてください。前に置けるのは、コメントと空行だけです。
- **G0250 `ファイルの中で上書きできない設定です: …`**：`@manifest` で変えられるのは `paragraph-separator` だけです。書名などは `manifest.toml` に書いてください。
- **G0251 `paragraph-separator は "blank-line" か "line" です: …`**：`@manifest` の値を `blank-line` か `line` にしてください。
- **G0252 `@style-def には種類（character、paragraph、regex）と名前を書きます`** など：`@manifest` か `@style-def` の書き方が違います。メッセージの示す形に直してください。値は語か文字列で書き、一つのスタイルは一行で定義します。
- **G0253 `同じ名前のスタイルを二度定義しています: …`**：同じファイルで、同じ種類の同じ名前を二度 `@style-def` しています。一行にまとめてください。

## ラベルと参照と目次

- **G0401 `ラベルが重複しています: …`**：同じラベルを二か所に付けています。どちらかの名前を変えてください。
- **G0403 `存在しないラベルへの参照です: …`**：参照の名前と、`@label` の名前を見比べてください。
- **G0405 `番号を持たない要素への参照です: …`**：`@nonumber` の見出しや段落のような、番号のない箇所を `[ref-number ...]` で指しています。題を出すなら `[ref-title ...]` を使ってください。
- **G0406 `題を持たない要素への参照です: …`**：段落や表のような、題のない箇所を `[ref-title ...]` で指しています。題があるのは見出しと図版だけです。ページを出すなら `[ref-page ...]` を使ってください。
- **G0402 `@toc は文書に一つだけ置けます`**：`@toc` を一つにしてください。
- **G0404 `章の外にある図版には、章番号を使う図番号を振れません。…`**：図番号の書式に `{chapter}` があるのに、番号を持つ章の見出しより前に図版があります。図版を章の中に移すか、書式から `{chapter}` を外してください。
- **G0721 `ページ番号の参照が収束しません: …`**：ページ番号を入れると組み方が変わり、それでまたページ番号が変わる、という繰り返しが止まりません。示された参照の近くの文言を少し変えてください。

## 誤りやすい書き方（lint）

`golem lint` と `golem check` が見つけるものです。

- **G0501 `改行の前後が欧文なので、単語が空白なしにつながります。一行で書いてください`**：欧文の単語のあいだで改行しています。欧文の文は一行に書いてください。行分けを残したい詩などには、段落スタイル `verse` を付けます。
- **G0502 `使われていない変数です: …`**：`@set` の変数がどこからも使われていません。消すか、使ってください。
- **G0503 `使われていない import です: …`**：`@import` した名前が使われていません。
- **G0504 `参照されていないラベルです: …`**：`--profile dev` では警告、`--profile prod` ではエラーです。参照を書くか、`@label` を消してください。
- **G0205 `校正用のコメントが残っています`**：`--profile prod` でだけ出る警告です。校正の済んだ `%%= … %%` を消してください。

## プロジェクトの設定（manifest.toml）

- **G0301 `TOML の誤りです: …`**、**`出力ターゲットが一つもありません`** など：`manifest.toml` の書き方が違います。`@style-def` の値の誤りも、このコードになります。キーの綴りと値の種類を、付録B と見比べてください。`[targets]` を書くときは、形式を一つ以上置きます。`paragraph-separator` には `"blank-line"` か `"line"` を書きます。同じファイルを、読み方を変えて `chapters` に二度並べることもできません。
- **G0316 `manifest.toml がありません`**：プロジェクトのディレクトリで `golem` を実行しているかを確かめてください。新しいプロジェクトは `golem new` で作ります。
- **G0302 `ファイルがありません: …`**：`chapters` や `@import` のパスの綴りと、ファイルの置き場所を確かめてください。
- **G0303 `絶対パスは使えません: …`**、**`URL は使えません: …`**、**`プロジェクトルートの外を指しています: …`**：ファイルはプロジェクトのディレクトリの中に置き、そこからの相対パスで書いてください。
- **G0304 `大文字と小文字だけが異なるパスです: …`**：大文字と小文字だけが違う二つのパスを使っています。機械によって同じファイルと見なされるかどうかが変わるので、綴りをそろえてください。
- **G0307 `style.toml にないマスターページです: …`**：`manifest.toml` の章に書いたマスターページの名前が、`style.toml` の `[masters]` にありません。
- **G0324 `抑制できるのはお知らせのコードだけです: …`** など：`[diagnostics]` の `silence-notices` に、お知らせでないコードを書いています。エラーと警告は止められないので、そのコードを消して原因を直してください。コードは大文字の `G` と 4 桁の数字で書きます。

## スタイルの設定（style.toml）

- **G0306** `style.toml` の誤り：`style.toml` の書き方が違います。キーの綴り、値の種類、単位、選べる値を、付録C と見比べてください。今の版では、知らないキーのメッセージは英語です。廃止した `[emphasis]`、`[verse]` などを書いたときは、書き換え先がメッセージに出ます。
- **G0317 `未知の判型です: …`** など：`[page]` の `size` が違います。表の名前を書くか、`{ width = "148mm", height = "210mm" }` のように幅と高さで書いてください。
- **G0308 `style.toml にないフォントの役割です: …`**：見出しやスタイルの `font` に書いた役割が、`[fonts]` にありません。
- **G0311 `段落スタイルの文字の大きさが版面の文字の大きさを超えます: …`**：段落スタイルの `size` を、`[page.grid]` の `font-size` 以下にしてください。
- **G0312 `段落の最初の行が版面の外に出ます。indent と first-line-indent の和を 0 以上にしてください: …`**：ぶら下げの分だけ `indent` を大きくしてください。
- **G0313 `style.toml のスタイルの参照が不正です: …`**：`based-on` の先のスタイルがないか、引き継ぎが輪になっているか、`body` に `based-on` があるか、文字スタイルの `color` の色が定義されていないか、`regex-styles` の文字スタイルがありません。
- **G0314 `柱の内容が正しくありません: …`**：`[masters.名前]` の `running-head` には、`content = "heading.1.short"` のように内容を一つ書くか、`even` と `odd` の両方を書いてください。書ける内容は付録C にあります。
- **G0318 `未知の位置です: …`**：柱かノンブルの `position` を、`top-outside` などの六つのどれかにしてください。
- **G0319 `[headings.… ] の running-head は廃止しました。…`**：見出しの `running-head` の行を消し、柱に出す見出しは `[masters.名前]` の `running-head` の `content` で選んでください。
- **G0315 `正規表現を解釈できません: …`**：`regex-styles` か `@style-def regex` の `pattern` に、使えない書き方があります。示された位置を直してください。文字の `~` は `\~` と書き、和文の文字の範囲は `[\x{4E00}-\x{9FFF}]` のように書きます。`@style-def regex` の文字列の中では、`\` を `\\` と書きます。
- **G0320 `アキの量の指定が正しくありません: …`**：`[aki-sets]` の規則か、寸法の欄の値が違います。量は `"四分"`、`"0.25zw"`、`"25%"` のように書き、`minimum`、`optimum`、`maximum` の順に小さくない値にしてください。`indent` のような寸法の欄には、`"四分"` や `"25%"` ではなく `"0.5zw"` のような寸法を書きます。
- **G0321 `… の値が正しくありません: …`**：`kerning`、`tracking`、`proportional-metrics`、`baseline-shift` の値が違います。`kerning = "optical"` はまだ使えないので、`"metrics"` にしてください。
- **G0322 `[lists] の … が正しくありません: …`**：`[lists]` の `bullets`、`numbers`、`gap` の値が違います。`numbers` の書式には、番号の差し込みをちょうど一つ書いてください。

## 紙面に収まらないとき

PDF を組むときに出るエラーです。

- **G0701 `版面がページからはみ出しています`** など：`[page]` と `[page.grid]` の値で版面を決められません。字数、行数、文字の大きさ、`position` を判型に収まる値にしてください。`[page]` や `[page.grid]` がないときと、縦組みや段組みの版面に傍注欄を設けたときも、このコードが出ます。
- **G0702 `日本式のトンボには塗り足しが要ります。style.toml の [page] に bleed を書いてください`**：`--marks japanese` を使うときは、`bleed = "3mm"` のように塗り足しを書いてください。
- **G0724 `見出しが版面に入りません（…）`**：見出しが一ページに収まりません。見出しを短くするか、`[headings]` の `size` を小さくしてください。
- **G0725 `段落スタイルの字下げが大きすぎます。…`**：字下げの後に、一行の長さが文字八つ分も残りません。段落スタイルの `indent` と `first-line-indent` を小さくしてください。
- **G0727 `リストの入れ子が深く、項目の本文の行長が足りません。…`**：リストの入れ子を浅くするか、`[lists]` の印を短くするか、`gap` を小さくしてください。
- **G0729 `リストの番号 … は、書式 … で表せません`**：丸数字（50 まで）のように表せる数に限りのある書式で、それを超える番号の項目があります。項目を減らすか、算用数字の書式に替えてください。
- **G0722 `回り込む図版の幅が不正です。…`**：回り込ませる図版の `width` を寸法で書き、脇に本文の文字が八つ以上入る幅にしてください。
- **G0723 `回り込む図版の除外領域が一ページの行数を超えます（…）`**：回り込ませた図版とキャプションが一ページに収まりません。図版を小さくするか、キャプションを短くしてください。
- **G0728 `回り込む図版の脇で、字下げを引くと行が残りません`**：図版の `width` を小さくするか、その段落の字下げを小さくしてください。
- **G0726 `段組みの版面では図版を回り込ませられません。…`**：図版の `wrap` を外すか、`[page.grid]` の `columns` を 1 にしてください。
- **G0732 `縦組みの版面では傍注を使えません。脚注に替えてください`**：縦組みの本では、傍注の代わりに脚注（`[note: ...]`）を使ってください。
- **G0734 `傍注欄（style.toml の [sidenotes]）のない版面では傍注を使えません`**：`style.toml` に `[sidenotes]` を書いてください。
- **G0735 `PDF では、脚注の本文と図版のキャプションの中に傍注を置けません`**：傍注を本文の段落に移してください。
- **G0733 `傍注が傍注欄より高く、収まりません`**、**`このページの傍注が傍注欄に収まりません`**：傍注を短くするか、そのページの傍注を減らしてください。
- **G0741 `表の列の最小の幅の合計（…）が使える幅（…）に収まりません`**：表の列を減らすか、長い語を短くしてください。
- **G0742 `表の … 行目が見出しの行とともに一ページに収まりません`**：表の行の途中では改ページしないので、その行のセルの文を短くしてください。
- **G0743 `コードブロックの行長が足りません`**、**`コードブロックの一行が一ページに収まりません`**：段落スタイル `code` の `padding` か `size` を小さくするか、コードブロックをリストの浅いところに移してください。

## 書体と色のファイル

- **G0807 `style.toml に本文のフォントがありません。[fonts.body] を書いてください`** など：PDF を作るのに、本文の書体が設定されていません。`style.toml` に `[fonts.body]` を書き、`ja` か `latin` に書体のファイルを書いてください。
- **G0802 `フォントのファイルがありません: …`** など：PDF を組むのに要る書体のファイルがありません。`style.toml` の `[fonts]` のパスにファイルを置いてください。`golem new --no-fonts` で作ったプロジェクトは、書体を置くまでこのエラーが出ます。
- **G0310 `フォントのファイルがないので、HTML と EPUB に同梱しません: …`**：`--profile dev` では警告で、書体を同梱せずに HTML と EPUB を書きます。`--profile prod` ではエラーです。
- **G0803 `フォントを読み込めません: …`**：書体のファイルが壊れているか、OpenType の書体ではありません。
- **G0804 `ライセンスが埋め込みを禁じているフォントです（…）: …`**：書体のライセンスが、PDF への埋め込みを許していません。埋め込みを許す書体に替えてください。
- **G0805 `PostScript 名が同じ異なるフォントがあります: …`**：同じ書体の別の版のファイルを混ぜています。どちらかのファイルにそろえてください。
- **G0806 `出力インテントの ICC プロファイルがありません: …`**：`[color]` の `intent` に書いたファイルがありません。

## プラグイン

- **G0602 `plugins.lock にないプラグインです。golem plugin lock を実行してください: …`**、**`plugins.lock の URL が manifest.toml と違います。golem plugin lock を実行してください: …`**：プラグインを宣言したり URL を変えたりした後に、`golem plugin lock` を実行してください。
- **G0611** `plugins.lock` の誤り：`plugins.lock` が読めません。手で編集したか、Git のマージで衝突が残っています。`plugins.lock` を消してから `golem plugin lock` を実行し直してください。
- **G0603 `キャッシュにないプラグインです。golem plugin fetch を実行してください: …`**：この機械にはまだプラグインの配布物がありません。`golem plugin fetch` を実行してください。
- **G0604 `キャッシュの配布物のハッシュが plugins.lock と一致しません: …`**：手元の配布物が、記録したものと違います。キャッシュのファイルを消して `golem plugin fetch` をやり直し、配布物が差し替えられていないかを確かめてください。
- **G0605**、**G0609** プラグインの誤り：プラグインを読み込めないか、実行が失敗しました。メッセージを添えて、プラグインの作者に知らせてください。
- **G0606 `複数のプラグインが同じコマンドを提供しています: …`**：どちらかのプラグインを外してください。
- **G0607 `組み込みのコマンドと衝突しています（overrides で宣言してください）: …`**、**`上書きできない組み込みのコマンドと衝突しています: …`**：組み込みのコマンドを置き換えるなら、`overrides` にその名前を書いてください。置き換えられないコマンドと同じ名前なら、プラグインの作者に知らせてください。
- **G0608 `上書きできる組み込みのコマンドではありません: …`**、**`プラグインが提供していないコマンドを overrides に書いています: …`**：`overrides` に、置き換えられないコマンドか、そのプラグインにないコマンドを書いています。
- **G0610 `宣言されていないプラグインです: …`**、**`プラグインが提供していないフィルタです: …`**：`[[filters]]` の `plugin` と `filter` の名前を確かめてください。

## お知らせ

お知らせは誤りではなく、出力を止めません。
`manifest.toml` の `[diagnostics]` の `silence-notices` にコードを並べると、そのお知らせを出さなくなります。
`--no-notices` を付けると、その実行ではすべてのお知らせを出しません。

- **G0262 `ファイルの中の定義が段落スタイルの … を上書きしています`** など：ファイルの先頭の `@style-def` が、`style.toml` か組み込みのスタイルと同じ名前のスタイルを定義しています。その章だけ体裁を変えるための使い方なら、そのままでかまいません。新しいスタイルのつもりなら、別の名前を付け、`based-on` で元のスタイルを継いでください。
- **G0263 `数の縦中横は [number-text … style=tcy] でも書けます`**：`[tcy: …]` の中身が数字だけです。数なら `[number-text 10 style=tcy]` のように書くと、縦組みと横組みのそれぞれに合った表記で出ます。
- **G0264 `行頭のエスケープした空白は無視されます。字下げには全角の空白を使います`**：`verse` のように改行をそのまま残す段落で、行の頭の空白の前にバックスラッシュを付けています。行頭の空白は捨てられます。字下げには全角の空白を使ってください。
- **G0265 `@listing の src= は廃止予定です。パスを最初の引数に書きます`**：`@listing src=src/Main.hs` は `@listing src/Main.hs` と書き換えてください。今の版では同じ内容を取り込みますが、今後の版では使えなくなります。
- **G0323 `style.toml がないので、既定の体裁で組みます`**：プロジェクトのディレクトリに `style.toml` がありません。既定の体裁でよければ、そのままでかまいません。
- **G0407 `@number … は自動で振られる番号と同じです`**：見出しやリストの項目の `@number` が、書かなくても振られる番号と同じです。項目を入れ替えたときに番号が固定されてしまうので、消してください。
- **G0408 `本の最後の改ページは効果がありません`**：本の最後のファイルの終わりにある `@page-break` と `@column-break` は捨てられます。白ページは作られないので、消してください。
- **G0730 `コードの行を折り返しました（… 行）`**：コードブロックの行が版面に収まらず、折り返して組みました。行を短く書き直すか、段落スタイル `code` の `size` を小さくしてください。`@listing` で取り込むファイルのように直せないときは、そのままでかまいません。
- **G0808 `コードの書体の役割 code がないので、本文の書体で組みます`**：本にコードがあるのに、`style.toml` に `[fonts.code]` がありません。等幅の書体で組みたければ `[fonts.code]` を書いてください。本文の書体のままでよければ、そのままでかまいません。
